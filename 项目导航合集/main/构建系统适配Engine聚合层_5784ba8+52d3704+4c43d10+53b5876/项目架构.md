## 二、项目总览与设计理念

### 2.1 一句话定位

白银纪元是一个**分层游戏引擎项目**：底层 `Engine/EngineCore` 提供基础能力（事件、对象、空间分区、碰撞、工具集），
`Engine/EngineSystem` 在其上提供游戏机制（实体、属性、效应），`Engine` 聚合层把二者合并为「一个引擎面」，
`Application/Test` 承载单元测试与交互式用例选择，`Application/Game` 为最终游戏本体（当前尚无源码）。

### 2.2 目录结构（五个可构建层 / 四个独立仓库）

```
白银纪元/（顶层仓库，只统辖目录，不跟踪下层内容）
├── Engine/                              ← 聚合层（随顶层入库，非独立仓库、不产出库）
│   ├── EngineCore/      独立仓库（分支 main → 远端 sliverera/engine）  ← 基础能力层（最底层）
│   └── EngineSystem/    独立仓库（分支 main → 远端 sliverera/system）  ← 游戏机制层（依赖 EngineCore）
└── Application/
    ├── Test/            独立仓库（分支 test → 远端 sliverera/test）    ← 唯一可执行文件产地（依赖 Engine 聚合面）
    └── Game/            独立仓库（分支 main → 远端 sliverera/game）    ← 游戏本体（当前无源码）
```

- `Engine/EngineCore`、`Engine/EngineSystem`、`Application/Test`、`Application/Game` 各自是**独立 git 仓库**，顶层仓库只记录其目录指针、不跟踪各层内容；因此下层有提交时顶层仓库通常不会有新提交。**`Engine` 目录本身没有嵌套 `.git`**，故随顶层入库。
- 远端统一为 `https://github.com/yuxingyuzhong/SilverEra.git`，各层以独立分支推送（`engine` / `system` / `test` / `game`）。
- 顶层 `main` 分支仅作为「代码合并线」：其新提交只由远端其余四分支合并产生；本地不拉取远程 main 分支代码，只拉取其余四个分支的代码。

### 2.3 三条核心设计原则

1. **层间一律链接「已构建的静态库」，绝不回退编译下层源码**。`EngineCore` 产出 `EngineCore.lib`、`EngineSystem` 产出 `EngineSystem.lib`、`Engine` 聚合层**不产出库**（只把两个子层的对外面摊平为 `BYJY_ENGINE_*`）、`Test` 产出唯一可执行文件 `EngineTests.exe`、`Game` 产出 `GameCore.lib`（当前无源码未产出）。层与层的交接通过 `cmake/对外接口.cmake` 自描述 + `cmake/接入下层.cmake` 的 `byjy_jieru_xiaceng()` 建立 IMPORTED 静态库目标完成。
2. **事件驱动为模块间协作的枢纽**。`EngineCore` 的碰撞代理器、`EngineSystem` 的实体管理器、效应管理器、属性槽分发器、工具层的配置加载器，都以「事件终端（Event_Terminal）→ 事件中转器（Event_Broker）」的订阅/发布机制互相通信。模块之间不直接调用对方接口（除层级内的直接调用外），而是通过事件解耦。
3. **全部对外公共头文件经由统一预编译头收敛**。`Engine/EngineCore/common/前置头文件包含.h` 集中包含标准库、nlohmann::json、GLFW 等；`EngineCore` 各模块头文件一律 `#include "Engine/EngineCore/common/前置头文件包含.h"` 起步；`EngineSystem` 亦然（用自身的 `Engine/EngineSystem/common/前置头文件包含.h`）。模块内通过「局部命名空间使用.h」展开 `using` 别名，保持源码整洁。

### 2.4 技术底座

- 语言标准：C++20（`CMAKE_CXX_STANDARD 20`，禁用扩展）。
- 构建系统：CMake（≥3.20，`GLOB_RECURSE CONFIGURE_DEPENDS` 自动发现源文件 + **目录级** `CMAKE_CONFIGURE_DEPENDS` 登记源根）+ Ninja 生成器 + MSVC 编译器（Windows 平台）；`CMAKE_EXPORT_COMPILE_COMMANDS ON` 产出 `compile_commands.json`。
- **构建入口（本版次起）**：顶层**没有** `CMakeLists.txt`／`CMakeSettings.json`；五个层各自独立配置与构建，顺序为 `Engine/EngineCore → Engine/EngineSystem → Engine → Application/Game / Application/Test`。
- 第三方库：`nlohmann::json`（JSON 解析）、`bullet3`（碰撞检测）、`glfw`（窗口/输入）、`googletest`（单元测试）、`Dear ImGui + glad`（测试选择器图形界面）、`Sol2 + Lua`（`EngineSystem` 脚本，`EngineCore` 未引用）。前序版次已移除 `EngineCore/external/glm`。
- **包含规则（本版次起）**：项目内部一切跨层包含写「项目根相对全路径」（`Engine/EngineCore/...`、`Engine/EngineSystem/...`、`Application/Test/...`）；各层自身的编译包含根统一收敛为项目根，第三方头保持原样（`<nlohmann/json.hpp>`、`<GLFW/glfw3.h>`、`<sol/sol.hpp>`、bullet3 等）。
- 编码约定：源文件统一 UTF-8（MSVC `/utf-8`）；中文路径在 `std::filesystem` 中经 `u8string` 转换工具（`string_to_path` / `path_to_string`）处理。

## 八、模块间交互关系

### 8.1 层间构建契约（编译期交互）

```
EngineCore.lib ──▶ EngineSystem.lib ──▶ Engine（聚合层，无产物）──▶ Application/Test（EngineTests.exe）
                                                            └────▶ Application/Game（GameCore.lib，条件产出）

Engine/EngineCore/cmake/对外接口.cmake        BYJY_ENGINE_CORE_*（OUT_INC 首项 = 项目根）
Engine/EngineSystem/cmake/对外接口.cmake      BYJY_ENGINE_SYSTEM_*（并入 EngineCore 对外面）
Engine/cmake/对外接口.cmake                   BYJY_ENGINE_*（OUT_LIB = EngineSystem;EngineCore 的摊平面）

```

- **对外面自描述**：每层 `cmake/对外接口.cmake` 声明本层对外变量：
  - `BYJY_<P>_OUT_LIB`（静态库名**列表**，分号分隔）、`BYJY_<P>_OUT_LIBDIR`（与 `OUT_LIB` 一一对应的「该库所在层目录」，可选，缺省=本层目录）、`BYJY_<P>_OUT_INC`（包含目录）、`BYJY_<P>_OUT_DEF`（编译定义）、`BYJY_<P>_OUT_LINK`（第三方库文件）、`BYJY_<P>_OUT_SYS`（系统库）。
  - `EngineSystem` 对外面 = 本层自有面 + `include(../EngineCore/cmake/对外接口.cmake)` 并入 `EngineCore` 对外面；`Engine` 聚合层的对外面 = 直接摊平 `EngineSystem` 与 `EngineCore` 两面（`OUT_LIB = "EngineSystem;EngineCore"`），**不产出 `Engine.lib`**；因此「接入 Engine 一层」即同时取得两个子层的公共路径与两个库。
- **接入函数**：`byjy_jieru_xiaceng(<对外接口文件> <变量前缀> <覆盖库路径变量>)`（**EngineSystem / Engine / Test / Game 四份逐字节相同**）读取下层对外接口 → **逐库**定位已构建静态库（① 覆盖变量优先且须与库数等长 → ② 自动探测 `<该库所在层目录>/out/build/*/lib/<库名>.lib` 取最新 → ③ 硬失败）→ 建立 `IMPORTED STATIC GLOBAL` 目标并挂载 INTERFACE 属性。**任何情况下都不回退编译下层源码**。
- **对外头快照**：`导出头快照.cmake` 把各层**自有头**（`common`、`src`）镜像到 `<本层构建目录>/include`（第三方头以外对面上单独的绝对路径条目出现，不经快照）。消费层用 `byjy_tou_kuaizhao_gen(<结果变量> <导入目标>)` 由导入目标反推下层快照根，并把**快照根作为自身包含目录**列出、**排在项目根之前** —— MSVC 下目标自身的 `-I` 恒早于导入目标传递的 `/external:I`，若把项目根交给导入目标传递，项目根反而排到快照之前、快照会被源码树旁路。`EngineCore` 导出 `EngineCoreIncludeSnapshot`，`EngineSystem` 导出 `EngineSystemIncludeSnapshot`，`Test` / `Game` 把两个快照根并列在前 ⇒ **头与 `.lib` 同版次**。
- **增删文件同步（本版次）**：各层在 `file(GLOB_RECURSE ... CONFIGURE_DEPENDS)` 之后，把每个被 GLOB 的**源根目录**登记进 `set_property(DIRECTORY APPEND PROPERTY CMAKE_CONFIGURE_DEPENDS ...)`。目录 mtime 变化（增删文件）被 ninja 记为 `build.ninja` 的依赖，构建前自动重跑配置并重扫 GLOB，VS 目录视图随之刷新（不再需手动「重新生成缓存」）。
- **IDE 索引**：各层 `CMakeLists.txt` 递归收集 `.h/.hpp` 并纳入对应目标（仅供 IDE 与生成系统建索引，**不参与编译**），并开启 `set(CMAKE_EXPORT_COMPILE_COMMANDS ON)`（Ninja 生成器默认不产出 `compile_commands.json`）。
- **唯一可执行**：宿主机制取消后，可执行文件只在 `Application/Test` 产生（`EngineTests.exe`）。

### 8.2 事件驱动协作（运行期交互）

整个项目的模块间通信以「事件终端 → 事件中转器」为核心：

```
事件发送方（如 Config_Loader / Collision_Proxy）
        │  build() 构造事件
        │  send(evt, acl_key) 发送
        ▼
   事件终端 Event_Terminal（持有者权限校验：acl_key）
        │  将事件送入 事件中转器 的接收入口（attach 时注册）
        ▼
   事件中转器 Event_Broker（订阅/发布中枢）
        │  按 category/tag 匹配订阅者；定向发送按 target_object 直投
        ▼
   事件订阅方（如 Collision_Proxy / Entity_Manager / Effect_Manager / Prop_Distributor）
        │  event_process() 按 category/tag 分派处理
```

- **接入链路**：订阅方 `attach()` → 注册事件接收入口 → 提交 `needed_events` 订阅清单 → 事件中转器据此建立分类/标签订阅表。
- **事件结构**：`Event{ sender_object, target_object, category, tag, config }`，其中 `target_object` 非空时走定向直投；`config` 为 nlohmann::json 载荷。
- **权限机制**：`Event_Terminal::acl_key_gen()` 生成唯一密钥，`send`/`interact`/`query`/`clear` 全部校验密钥，「密钥未生成即锁定」。
- **典型协作示例（碰撞检测结果分发）**：
  1. `Config_Loader` 收到可信根/路由/配置事件后读路由文件与配置 → 发 `Config/Load` 事件（`target_object="Collision_Proxy"`）；
  2. `Collision_Proxy::event_process()` 收到后 `config_apply()` 建空间/建碰撞体/配几何；
  3. 游戏逻辑调用 `region_detect()` → `Collision_Region::detect()` 执行扫掠+离散检测 → `event_publish("DetectResult", ...)` 广播碰撞对；
  4. 订阅 `Collision/DetectResult` 的模块（如Game 层将来的逻辑）消费碰撞对。

### 8.3 EngineCore 层模块间直接调用关系

除事件外，EngineCore 层内部还存在直接调用链（见「模块架构/」各文件）：

- `Collision_Proxy` → 持有 `std::unordered_map<string, unique_ptr<Collision_Region>>`，直接调用 `Collision_Region` 全部接口；
- `Collision_Region` → 使用 `Collider`（直接成员）、`Number_Allocator`（编号分配）、`Mesh_Loader`（网格加载）、`engine::detail::field_check / path_check`（配置校验）、`Log`（日志）、`Collision_Backend`（bullet3 世界）；
- `Quadtree_Manager` → 持有 `Quadtree<T>`（按根节点管理），通过 `tree_expand_approve` 回调链联动 `Quadtree` 的扩大；
- `Object_Pool` → 使用 `Number_Allocator`（双分配器）与 `binary_search`（排序模式查找）；
- `Event_Terminal` → 使用 `Random_Generator`（密钥生成）、`Terminal_Interface`（接口注册表）。

## 十二、工程约定与注意事项（跨模块通用）

1. **命名约定**：类名首字母大写（`Collision_Proxy`）；struct/union/enum 同样单词首字母大写（`Event`、`Event_Identity`、`Tree_State`、`Effect_Group`）；变量/函数全小写 + 下划线分隔（`region_build`、`acl_key`）；文件名中文（`碰撞代理器.h`）。历史遗留的小写自定义类型名已于前序版次（自定义类型命名整改 `2eda1d5` + `3268ce8` + `77ab24e`）统一为首字母大写。
2. **注释约定**：中文注释；<3 行用 `//`（无空格），≥3 行用 `/**/`；换行注释；函数头注释翻译函数名。
3. **错误处理约定**：模块接口普遍返回 `bool`/`std::optional`，失败时 `logger.warn`/`logger.error` 记录并返回失败标记，不抛异常到上层（内部使用 try/catch 收敛第三方库异常）；日志一律经 `logger` 实例调用（`Log::info(...)` 已不再可用）。
4. **内存约定**：能 `new(nothrow)` 就 `new(nothrow)`（部分模块以 `memory_malloc` 包装）；`Collider` 的网格与形状按成员声明逆序析构保证依赖关系。
5. **行尾约定**：EngineCore 仓库对部分文件存在自动行尾归一（`autocrlf`），涉及这些文件时注意 CRLF/LF。
6. **工具链坑位**：`.bat` 被 cmd 按 GBK 解析（含中文会乱码），改用 bash 通道；`ctest` 不在 Git Bash PATH 中，需绝对路径；`.hpp` 上 `apply_patch` 易失败，用 `str_replace`/`sed` 更稳。
7. **git 推送**：EngineCore 本地分支 `main` 与上游 `engine` 名字不一致，`git push` 会被 `push.default=simple` 拦下，必须显式 `git push sliverera main:engine`（EngineSystem `main:system`，Game `main:game`，Test `test:test` 同名）。<br>**注意**：`Engine/` 与 `Application/` 目录内只有四个子层各自的 `.git`，顶层仓库不收录含自身 `.git` 的子目录源码，因此顶层 `main` 只记录目录指针（本版次起顶层不再做源码快照）。
8. **构建环境约定**：配置阶段必须处于 **UTF-8 代码页**（否则头文件依赖不进 ninja 依赖库、改头不重编）；**`chcp 65001` 必须在 `Enter-VsDevShell` 之后执行**（顺序颠倒不生效）；`TMP`/`TEMP` 须指向**纯 ASCII** 路径（含中文会使 cl 只要带调试信息就报 `D8050 未能将命令行放入调试记录中`）；测试须在 `Application/Test` 目录下运行（`Path_Check_Test` 的相对路径基准依赖工作目录）；`ctest`/`ninja` 走绝对路径。
9. **层间契约与包含规则（本版次起）**：任何新增/改动的跨层 `#include` 一律写项目根相对全路径（`Engine/EngineCore/...`、`Engine/EngineSystem/...`、`Application/Test/...`）；层间**只链接已构建静态库**，定位不到即硬失败，**绝不回退编译下层源码**；改层间契约变量（`OUT_LIB`/`OUT_LIBDIR`/`OUT_INC`/`OUT_DEF`/`OUT_LINK`/`OUT_SYS`）必须同步四个 `接入下层.cmake` 副本（须逐字节相同）。
