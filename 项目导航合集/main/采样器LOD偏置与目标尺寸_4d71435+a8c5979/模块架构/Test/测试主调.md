## 二、模块功能介绍

### 2.1 模块定位

「测试主调」位于测试层源码目录 `Application/Test/src/主调/`，是测试层可执行文件 `EngineTests.exe` 的**进程入口与交互逻辑**。它把「选哪些用例跑」与「怎么跑、跑完停不停」这条控制流，收拢进一个 `main()` 的四步分流，并把可复用的**纯逻辑**（反射选择模型、控制台输入解析、停住判定）抽成独立编译单元。

按职责可再分为两簇：

- **控制流簇（进程入口）**：`主程序.cpp` 提供 `main` 与停住判定的实现，负责参数摘取、googletest 初始化、四条路径分流、过滤串落地与收尾等待。
- **选择与辅助簇（可复用逻辑）**：`测试选择模型`（反射建树 + 勾选态 + 过滤串生成 + 控制台输入解析）、`控制台选择菜单`（无图形环境时的文本回退入口）、`退出等待判定.h`（判定声明）、`引擎日志屏蔽`（把引擎日志分流到文件）。

一句话概括：**本模块是测试层 `EngineTests.exe` 的「进程入口 + 控制台/自动化调度中枢」，它决定「本次跑哪些用例、以何种交互形态、跑完是否停住、引擎日志落向何处」。**

### 2.2 职责边界与解决的问题

「测试主调」解决的问题可归纳为六点：

1. **提供全工程唯一进程入口**。本层是全项目唯一产出可执行文件的层，`main` 由本层 `主程序.cpp` 提供（**不链接** googletest 自带的 `GTest::gtest_main`），`EngineTests.exe` 既是单元测试入口，也是整套工程的启动项。
2. **把自定义开关与 googletest 原生参数分开**。命令行里的 `--selector=` 是本层自定义开关，不能原样交给 googletest（否则会被判为未知 flag）；本模块在进入 googletest 之前先把它摘出，其余参数原样保留并重建 `argv`。
3. **用反射替代人工维护用例名单**。`Test_Selection_Model` 从 googletest 单例反射枚举「已注册的套件 → 用例」，运行时建立两层选择树；新增用例**自动可见**，无需改主调代码、无需维护名单文件。
4. **把勾选结果落成 googletest 原生过滤串**。选择结果经三态压缩生成 `--gtest_filter` 串，供 `GTEST_FLAG(filter)` 使用；运行前打印该串与可复跑的 `--gtest_filter=` 命令，做到「所见即所测」。
5. **提供控制台回退入口**。图形环境不可用（或无控制台窗口的重定向/CI）时，用编号菜单让用户按套件粒度勾选，作为图形界面的降级形态。
6. **区分「交互运行」与「自动化运行」的收尾行为**。交互运行跑完停住等待按键（避免控制台一闪而过看不到结果），自动化运行（透传 / `off`）跑完即走（避免 CI 被挂住）；这一判定抽成 `需要等待退出` 独立函数，可被用例直接验证。
7. **把引擎日志从标准输出分离**。测试运行期间引擎日志改落日志文件，避免与 googletest 的输出交织在同一位置导致结果不可读。

### 2.3 在整体架构中的位置

测试主调处于测试层可执行文件的顶部：向下依赖 googletest（反射与执行）与引擎核心层工具（日志系统、引擎环境、路径字符串转换）；横向把「图形界面」簇当作可选调用方（默认路径），并在其失败时降级回控制台菜单。

```
                    ┌─────────────────────────────────────────────────────┐
                    │                  EngineTests.exe                     │
                    │  ┌───────────────────────────────────────────────┐   │
                    │  │            main()（主程序.cpp）                │   │
                    │  │  ① 摘参数 → ② InitGoogleTest → ③ 四步分流 →    │   │
                    │  │  ④ 过滤串落地 → RUN_ALL_TESTS → ⑤ 收尾等待     │   │
                    │  └───┬───────────────┬──────────────┬────────────┘   │
                    │      │               │              │                │
                    │      ▼               ▼              ▼                │
                    │  测试选择模型      控制台选择菜单   图形操作界面        │
                    │ （反射/过滤串）    （编号菜单）     （见 图形界面.md）   │
                    │      │               │              │                │
                    │      └───────┬───────┴──────────────┘                │
                    │              ▼                                       │
                    │      退出等待判定 / 引擎日志屏蔽                       │
                    └───────┬──────────────────────────┬───────────────────┘
                            │ 反射 / 过滤 / 执行         │ 日志分流 / 环境
                     ┌──────▼───────┐          ┌───────▼────────┐
                     │  googletest  │          │ 引擎核心层工具  │
                     │ (GTest::gtest)│          │ 日志系统/Engine_Env│
                     └──────────────┘          └────────────────┘
```

- **向上**：无可上层；本模块即进程顶。
- **向下**：googletest（`GTest::gtest`，反射 `UnitTest` 单例、`TestSuite`/`TestInfo`、`InitGoogleTest`、`GTEST_FLAG(filter)`、`RUN_ALL_TESTS`）；引擎核心层工具（`日志系统运行包.h` 的 `logger`、`Engine_Env::exe_dir_get()`、`Detail/路径字符串转换.h` 的 `string_to_path`/`path_to_string`）。
- **横向**：图形界面簇（`图形操作界面.h` 等）为默认路径的协作方；控制台菜单为其降级替代。二者共用同一 `Test_Selection_Model`。

| 相邻部分 | 归属 | 分界 |

### 2.5 生命周期（进程级）

本模块无类实例、无构造/析构语义，生命周期即**进程生命周期**：

```
main() 进入
  → SetConsoleOutputCP/SetConsoleCP(UTF-8)
  → 日志屏蔽_开启()               ← 引擎日志改落文件
  → 摘 --selector= / 重建 argv
  → InitGoogleTest()
  → 四步分流（透传 / off / console / window）
  → RUN_ALL_TESTS()               ← 执行选中用例
  → 日志屏蔽_落盘()               ← 每条 return 路径都调用
  → [交互路径] 等待用户关闭窗口()
  → return 退出码
进程退出
```

- 日志屏蔽是**进程级开启、按 return 路径落盘**：`日志屏蔽_开启()` 幂等（重复调用不重复绑定），`日志屏蔽_落盘()` 把缓冲写出并刷新。
- 引擎日志屏蔽.h 特别约定：**日志系统用例自身要验证「未绑定即走控制台」**，故其夹具须成对使用 `日志屏蔽_关闭()` / `日志屏蔽_开启()`；本模块不做自动配对，配对责任在用例夹具（见 §3.6）。

## 三、模块公开接口介绍

本章列出「控制台侧主调」**对外可见的类型与函数**。先厘清两层可见性：

- **层内可见（同一可执行文件/同层其它编译单元、用例）**：本模块全部公开接口均属此层。它们分别编入两个目标——`TestLauncher`（静态库：`测试选择模型` + `控制台选择菜单`）与 `EngineTests`（可执行文件：`主程序` + `引擎日志屏蔽`）。用例目标 `EngineTestObjects` 同时链接 `TestLauncher` 与 `EngineCore/EngineSystem/RendererCore/GTest::gtest`，因此用例可直接 include `Application/Test/src/主调/测试选择模型.h` 与 `src/主调/退出等待判定.h`。

### 3.2 进程入口 `main`

- **签名**：`int main(int argc, char** argv)`
- **声明与实现**：`Application/Test/src/主调/主程序.cpp`（本层唯一 `main`）。
- **参数**：`argc`/`argv` —— 原始命令行。`argv[0]` 做空指针兜底（为空则取字面量 `"EngineTests"`）。
- **返回值**：`int` —— 透传 `RUN_ALL_TESTS()` 的退出码（0 全过 / 非 0 有失败），供 CI 判级；图形界面会话正常结束时返回 `0`。
- **行为要点**（详见 §6、§7）：
  1. 切换控制台代码页为 UTF-8（`SetConsoleOutputCP(CP_UTF8)`、`SetConsoleCP(CP_UTF8)`），保证中文用例名可读。
  2. `引擎日志屏蔽_开启()` 把引擎日志分流到日志文件。
  3. 参数摘取循环：摘出 `--selector=`（记「显式选择器」）、标记是否出现 `--gtest_*`（记「命令行带过滤」），其余原样保留；重建 `argv`。
  4. `InitGoogleTest(&参数个数, 参数指针.data())`。
  5. 四步分流：① 未显式指定选择器且带 `--gtest_*` → 原样透传；② `--selector=off` → 不开窗全跑；③ `--selector=console` → 控制台菜单；④ 默认 / `--selector=window` / 未知值 → 图形界面，失败降级控制台菜单。
  6. 每条执行路径在 `RUN_ALL_TESTS()` 后调用 `引擎日志屏蔽_落盘()`；交互路径再按 `需要等待退出(...)` 决定是否 `等待用户关闭窗口()`。

- `suite_check_set` / `case_check_set` / `suite_expand_set`：写勾选态与展开态；**越界一律忽略（空操作）**。
- `all_check` / `all_clear` / `check_invert`：批量全选 / 全清 / 反选。
- `filter_string_build`：按三态压缩规则生成过滤串（见 §6.4）。

### 3.4 `engine::控制台选择菜单_运行`

- **签名**：`void engine::控制台选择菜单_运行(Test_Selection_Model& 模型, std::string& 过滤串)`
- **声明**：`Application/Test/src/主调/控制台选择菜单.h`；**实现**：`控制台选择菜单.cpp`。
- **参数**：

| 参数 | 类型 | 含义 | 约束 |
| --- | --- | --- | --- |
| `模型` | `Test_Selection_Model&` | 已 `suite_tree_build()` 的选择模型；菜单把勾选结果写回该模型 | 须已建树，否则列表为空 |
| `过滤串` | `std::string&` | 出参：选择结果对应的 `--gtest_filter` 串 | 由函数写入 |

- **返回值**：无（结果经 `过滤串` 出参）。
- **行为要点**：
  1. 打印标题与逐条编号列表：`N) 套件名（M 个用例）`。
  2. 提示输入形如 `1,3-5` 或 `all`；**直接回车表示全跑**。
  3. 最多接受 **3 次**非法输入，其后兜底全跑。
  4. 输入流结束（管道 / 重定向）或空输入 → 按「全选」处理（`all_check()` + 生成过滤串）。
  5. 解析成功 → 把勾选表逐条写入模型（`suite_check_set`）并生成过滤串。
- **说明**：控制台菜单按**套件粒度**勾选（整组或全不选），不暴露用例粒度。

### 3.5 `engine::需要等待退出`

- **签名**：`bool engine::需要等待退出(const std::string& 选择模式, bool 命令行带过滤, bool 显式选择器)`
- **声明**：`Application/Test/src/主调/退出等待判定.h`；**实现**：`主程序.cpp`（`namespace engine` 内，非匿名命名空间，故用例可链接同名符号）。
- **参数**：

| 参数 | 类型 | 含义 |
| --- | --- | --- |
| `选择模式` | `const std::string&` | `--selector=` 的取值：`window` / `console` / `off` / 未知值 |
| `命令行带过滤` | `bool` | 命令行是否出现 `--gtest_*` 参数 |
| `显式选择器` | `bool` | 命令行是否**显式**写了 `--selector=` |

- **返回值**：`bool` —— 真表示「跑完停住等待按键」，假表示「跑完立即返回」。
- **行为要点**：实现为两个早退 `return false` + 一个兜底 `return true`。判定表见 §6.6。
- **设计要点**：头文件**只放声明**，实现置于可执行文件 `主程序.cpp`；用例直接链接可执行文件的同名符号，以保证「用例验证的判定」与「主程序实际使用的判定」是**同一份逻辑**（`退出暂停判定测试` 覆盖全参数组合）。

### 3.6 引擎日志屏蔽四函数

**声明位置**：`Application/Test/src/主调/引擎日志屏蔽.h`；**实现**：`引擎日志屏蔽.cpp`。

| 函数 | 签名 | 作用 |
| --- | --- | --- |
| `日志屏蔽_开启` | `void 日志屏蔽_开启(void)` | 把日志根节点 `""` 绑定到屏蔽用日志文件；全部调用处的日志沿父链继承该流，不再落到控制台。**幂等**（`屏蔽已开启` 为真即直接返回） |
| `日志屏蔽_关闭` | `void 日志屏蔽_关闭(void)` | 清除根节点绑定（`logger.stream_clear("")`）并清除日志根目录设置（`logger.root_clear()`），使引擎日志回落到控制台；同步把 `屏蔽已开启` 置假，以便后续重新绑定 |

- **用法约定**（头注释明确）：主程序在进入测试前调用 `日志屏蔽_开启()`；**日志系统用例自身要验证「未绑定即走控制台」**，故须成对使用 `日志屏蔽_关闭()` / `日志屏蔽_开启()`（见 `日志系统测试.cpp` 夹具）。

## 六、模块设计/实现细节

### 6.1 四步分流的总设计

`main()` 的核心是**四步分流**，其优先级顺序由源码的 `if` 排列决定：

```
① 未显式指定选择器 且 带 --gtest_*   → 透传：不建模型、不开窗，直接 RUN_ALL_TESTS()
② --selector=off                     → 不开窗、不建模型，直接全量 RUN_ALL_TESTS()
③ --selector=console                 → 建模型 → 控制台菜单 → 跑一轮 → 等待 → 返回
④ 默认 / --selector=window / 未知值   → 图形操作界面（常驻，界面驱动多轮）
                                        │ 窗口创建失败（无图形环境）
                                        └→ 打印提示 → 退控制台菜单 → 跑一轮 → 等待 → 返回
```

- 判定式实现为 `if ((命令行带过滤 && !显式选择器) || 选择模式 == "off")` —— 把 ① 与 ② 合并为同一「自动化」分支（都跑完即走）。
- **显式 `--selector=` 优先于「带 gtest 参数即透传」的约定**：`--selector=console --gtest_filter=...` 会走控制台菜单（`显式选择器` 为真，① 不成立），菜单结果**覆盖**命令行过滤串。
- `console` 与 `window` 两分支均会跑测试；`window` 的界面**会话结束即返回，不再二次执行测试**（界面内已跑过多轮）。源码注释明确此点。

### 6.2 参数摘取与 `argv` 重建

1. 遍历 `argv[1..argc-1]`：
   - 若 `参数.rfind("--selector=", 0) == 0`：`选择模式 = 参数.substr(strlen("--selector="))`、`显式选择器 = true`，**不保留**（否则 gtest 报未知 flag）。
   - 否则若 `参数.rfind("--gtest_", 0) == 0`：置 `命令行带过滤 = true`，并**原样保留**。
   - 其余参数原样保留。
2. 保留列表首项为 `argv[0]`（空指针兜底为 `"EngineTests"`）。
3. 重建：`std::vector<char*> 参数指针` 逐项 `push_back(文本.data())`，末尾补 `nullptr`；`参数个数 = 保留列表长度`。
- **设计要点**：`--selector=` 的取值同时被 `选择模式` 与 `显式选择器` 记录；`--gtest_*` 参数**不解析、不改写**，原样交给 googletest，保证其对 `--gtest_filter` / `--gtest_list_tests` 等原生 flag 的完整支持。

### 6.3 `InitGoogleTest` 的时机约束

源码注释与 `测试选择模型.h` 头注释均指出：`InitGoogleTest()` 必须在**建立选择模型之前**完成，因为 `suite_tree_build()` 依赖 googletest 已解析参数并完成用例注册的单例状态。故顺序固定为：

```
摘参数 → InitGoogleTest() → [分流] → 建模型（仅 ③④ 路径）→ RUN_ALL_TESTS()
```

- 自动化分支（① ②）**不建模型**（省去反射开销），直接 `RUN_ALL_TESTS()`。

### 6.4 过滤串三态压缩

`filter_string_build()` 把选择树的勾选态压成 googletest 原生过滤串，规则为三态：

| 勾选态 | 过滤串片段 | 说明 |
| --- | --- | --- |
| **全不选**（已选用例数 = 0） | 整串直接为 `"*"` | 与 gtest 的 `"*"` 通配语义一致，即**全跑**——「全不选」被有意解释为「不过滤」，而非「一条都不跑」 |
| **某套件整组全选** | `套件.*` | 压缩为前缀通配 |
| **某套件部分勾选** | 逐条列 `套件.用例` | 每条一个片段 |

- 各片段以 `':'` 连接（gtest 过滤串的「或」分隔符）。整组未勾选的套件被 `continue` 跳过。
- **边界**：用例名/套件名若含 `:`、`*`、`?` 等过滤串特殊字符，直接拼接会导致过滤串断裂；当前依赖命名规范规避（见 §6.10、附录 C 的 TEST-01 之外该点属「已知边界」，源码与 README 均已记录，不另标待确认）。

### 6.5 控制台输入解析规则

`解析控制台选择` 的完整规则：

1. 先把 `勾选表` 置为「长度 = 套件数、全假」。
2. 去首尾空白（` \t\r\n`）；全空白判**非法**。
3. `all` / `ALL` / `a` / `*` → 全选（全真），返回真。
4. 否则按 `','` 切段，逐段处理：
   - **空段**（如 `1,,3`、`1,`）判非法；
   - 含 `'-'` → 区间 `a-b`：左右必须都是数字、左值 ≥ 1、**右值 ≥ 左值**（不得颠倒如 `5-2`）、右值 ≤ 套件数；区间展开为连续勾选；
   - 不含 `'-'` → 单编号：必须为数字、1 ≤ 编号 ≤ 套件数，否则非法。
5. 任一段非法 → 整个输入判非法（返回假），`勾选表` 保持全假。
6. 编号一律 `-1` 后作为下标写入 `勾选表`（**编号从 1 开始**）。

- **控制台菜单的粒度**：菜单把 `勾选表` 逐条 `suite_check_set(i, 勾选表[i])`，故一次输入把每个套件整体置为全选或全不选；**不提供用例粒度**（用例粒度是图形界面专属，见 §2.4）。【待确认：TEST-03】

### 6.6 退出等待判定表

`需要等待退出(选择模式, 命令行带过滤, 显式选择器)` 的判定表（实现为两个早退 `return false` + 兜底 `return true`）：

| 选择模式 | 命令行带过滤 | 显式选择器 | 结果 | 场景 |
| --- | --- | --- | --- | --- |
| 任意 | 是 | 否 | **不停** | `--gtest_*` 透传（自动化，ctest 逐用例形态） |
| `off` | 任意 | 任意 | **不停** | ctest 退化 / 一键全量回归 |
| `window` | 否 | 否 | 停 | 默认双击运行 |
| `window` / `console` | 否 | 是 | 停 | 显式指定选择器 |
| `window` / `console` | 是 | 是 | 停 | 显式选择器优先于透传约定 |
| 未知模式 / 空串 | 否 | 任意 | 停 | 兜底：宁可多等一次，也不要控制台一闪而过 |

- 实现顺序即判定优先级：先判「透传（带过滤且未显式）」，再判「`off`」，其余兜底为停。
- **大小写敏感**：仅小写 `off` 被视为关闭；`OFF` 按未知模式处理（仍停）。
- 停的**动作**在 `等待用户关闭窗口()`（`主程序.cpp` 文件内部工具，见 §4.1）；无控制台窗口时该动作自身直接跳过。

### 6.7 引擎日志屏蔽与「中文路径」

`引擎日志屏蔽` 的目标：测试运行期间引擎日志从控制台分离，避免与 googletest 输出交织。做法是利用日志系统的**路径节点绑定机制**：

1. `屏蔽日志路径获取()`：`Engine_Env::exe_dir_get() / detail::string_to_path("out/引擎运行日志.txt")`。【待确认：TEST-02】
   - **为何必须经 `string_to_path`**：相对路径含中文（`引擎运行日志.txt`），若直接以 `const char*` 参与 `filesystem::path` 拼接，C++ 的 `std::filesystem::path` 会按系统本地码页（Windows 下 GBK/UTF-16LE）解读 UTF-8 字节，生成乱码文件名；`string_to_path` 负责 UTF-8 字节与 `filesystem::path` 互转。
2. 创建父目录（`create_directories`，带 `std::error_code` 容错）。
3. 以 `std::ios::out | std::ios::trunc` 打开文件流（`new(std::nothrow)`，**禁用异常**；每次运行覆盖旧日志）；分配失败或打开失败则**放弃屏蔽**（日志继续留在控制台，不阻断测试）。
4. `logger.root_set("")`（日志根目录设为整个项目，使输出流绑定获准）→ `logger.stream_bind("", 日志流)`；绑定成功才置 `屏蔽已开启 = true`。
5. 收尾：`日志屏蔽_落盘()` 调 `logger.stream_flush()` 把缓冲写出。

- **关闭**：`logger.stream_clear("")` + `logger.root_clear()` + `屏蔽已开启 = false`，使日志回落控制台兜底输出目标。日志系统用例夹具据此临时关闭屏蔽、用例结束再恢复。

### 6.8 无参数启动进入退出暂停（已验证坑位）

**无参数运行 `EngineTests.exe` 会进入「交互运行 + 退出暂停」**，这是本层一个**有意为之、且已被用例固化**的行为：

- 无参数 → 默认选择模式 `window`；图形界面不可用时降级控制台菜单；两条交互路径在跑完测试后都会 `等待用户关闭窗口()`（阻塞等任意键）。
- 因此**以脚本无参调用会被挂住**。规避方式是走自动化路径：命令行带 `--gtest_*`（且不显式写 `--selector=`）或显式 `--selector=off`——两者 `需要等待退出` 均返回假，跑完立即返回退出码。
- ctest 的退化注册正是用 `--selector=off`（见 §6.9），以免无参数的 `ctest` 阻塞在图形窗口上。
- 该行为有专门用例在案：`退出暂停判定测试`（8 个用例，覆盖默认/显式窗口/显式控制台/关闭选择器/透传/显式优先/未知模式/空串/大小写敏感/全参数组合），与 `需要等待退出` 的实现在同一份逻辑上验证（§3.5）。

### 6.9 `EngineTests.exe` 的工作目录与参数约定

| 约定 | 值 | 依据与后果 |
| --- | --- | --- |
| 可执行文件落点 | **层根目录** `Application/Test/EngineTests.exe`（与 `assets/` 同级） | `set_target_properties(EngineTests ... RUNTIME_OUTPUT_DIRECTORY "${PROJECT_ROOT_DIR}")`；`Engine_Env` 以「可执行文件所在目录」为基准解析资源路径，是**硬性要求**——产物若改到 `out/` 下，资源路径会全盘错位 |

| 资产目录 | `assets/`（指向 `Application/Game/assets` 的**目录联接**） | 保持资产单一真源；联接已入 `.gitignore`，克隆本层不会自带 `assets/` |
| 着色器目录 | 层根 `shaders/`（配置期从渲染层着色器目录拷贝） | 渲染层以 SPIR-V 运行期加载着色器；本层渲染用例需要它 |
| 屏蔽日志落点 | `层根/out/引擎运行日志.txt` | 相对可执行文件目录（`Engine_Env::exe_dir_get()`）；见 §6.7 与附录 C TEST-02 |

**参数一览**（据源码 `main` 与 README §9.3 核实）：

| 命令 | 行为 | 开窗 | 停住 |
| --- | --- | --- | --- |
| `EngineTests.exe` | 默认 `window`；窗口不可用降级控制台菜单 | 是 | 是 |

### 6.10 与 README 的口径差异与已知边界

- **README 部分描述与本版次源码不符**：README（第 2、6.4、6.5、7.3、9.3 等节）仍描述「图形选择窗口（GLFW + OpenGL3 + glad，文件 `图形选择窗口.h`/`.cpp`）」，而本版次源码为「图形操作界面 + 测试界面 + 测试运行器 + 测试运行记录 + gtest输出镜像（SDL3 + Vulkan + ImGui）」；构建脚本 `CMakeLists.txt` 亦以 SDL3/Vulkan 为准（`imgui_impl_sdl3.cpp`/`imgui_impl_vulkan.cpp`，不再用 glfw/opengl3 与 glad）。本控制台侧文档**一律以源码为准**【待确认：TEST-01】（详情见附录 C）。

  - 控制台无用例粒度勾选（§6.5、附录 C TEST-03）；
  - 无参数启动挂住（已由自动化开关规避，§6.8）。

### 6.11 易错点与编码约定

| 易错点 | 说明与规避 |
| --- | --- |
| `--selector=` 未摘出 | 若原样传给 gtest，会被判未知 flag 而报错；必须摘出且不进入保留参数（§6.2） |
| `InitGoogleTest` 时机 | 必须在建模型/反射取值之前完成（§6.3） |
| `argv` 重建后未补 `nullptr` | `char**` 需以 `nullptr` 结尾；源码在 `参数指针.push_back(nullptr)` |
| `argv[i]` 空指针 | 逐项以 `(argv[i] != nullptr) ? argv[i] : ""` 兜底；`argv[0]` 兜底为 `"EngineTests"` |
| 中文路径直接拼 `filesystem::path` | 必须经 `detail::string_to_path`（§6.7） |
| 日志屏蔽与用例夹具配对 | 日志系统用例须 `日志屏蔽_关闭()` / `日志屏蔽_开启()` 成对使用，否则隐藏「未绑定即走控制台」的验证（§3.6） |
| 内存分配抛异常 | 文件流用 `new(std::nothrow)`（依编码约束禁用异常） |
| 中文源码编译 | 各目标带 `/utf-8`（源码、中文 include 路径、中文用例名都依赖它） |
| 停住判定与停住动作混淆 | 判定 `需要等待退出`（可被用例覆盖）与动作 `等待用户关闭窗口`（阻塞等待）职责分离（§4.1） |

**编码约定**：注释为中文，`//` 短注释换行书写、`//` 后不留空格，三行及以上用 `/* */`；文件名/类名/用例名用中文；英文标识符单词间 `_`、首字母不大写（类名首字母大写）；`if`/`for` 单语句不加代码块；内存分配禁用异常、改 `std::nothrow`。

## 七、模块运行链路详例

本章以「调用方 → 模块 → 被调方」的时序描述典型链路。调用方即操作系统/命令行；`main` 是本模块的入口。

### 7.1 主流程一：透传 / `off`（自动化）

1. `main` 进入：`SetConsoleOutputCP(CP_UTF8)` + `SetConsoleCP(CP_UTF8)`；`engine::日志屏蔽_开启()`。
2. 参数摘取：无 `--selector=`，但出现 `--gtest_*`（→ `命令行带过滤 = true`）**或** `--selector=off`（→ `选择模式 = "off"`）。
3. `InitGoogleTest(&参数个数, 参数指针.data())` 原样解析 gtest 参数。
4. 判定 `(命令行带过滤 && !显式选择器) || 选择模式 == "off"` 成立 → 进入自动化分支。
5. `const int 透传结果 = RUN_ALL_TESTS();` → `engine::日志屏蔽_落盘();` → `return 透传结果;`（**不建模型、不开窗、不等按键**）。
6. **异常/边界**：若同时给了 `--gtest_*` 与显式 `--selector=console`，则 ① 不成立，走 §7.2 控制台路径（显式选择器优先）。

### 7.2 主流程二：`console`（控制台菜单）

1. `日志屏蔽_开启()`；摘出 `--selector=console`（`选择模式 = "console"`、`显式选择器 = true`）；`InitGoogleTest`。
2. 建模型：`engine::Test_Selection_Model 模型; 模型.suite_tree_build();`（反射枚举 27 套件 / 625 用例，默认全勾选）。
3. `engine::控制台选择菜单_运行(模型, 过滤串)`（子流程见 §7.4）。
4. 打印 `[测试选择] 过滤串：<过滤串>` 与 `[测试选择] 可用 --gtest_filter=<过滤串> 复跑同一批用例。`
5. `::testing::GTEST_FLAG(filter) = 过滤串;` → `const int 测试结果 = RUN_ALL_TESTS();` → `engine::日志屏蔽_落盘();`
6. 若 `engine::需要等待退出("console", 命令行带过滤, 显式选择器)` 为真 → `等待用户关闭窗口()`（停住等按键）；`return 测试结果;`。
7. **异常/边界**：非法输入 3 次后兜底全跑（过滤串为 `"*"`）；输入流结束或空输入按全选处理。

### 7.3 主流程三：`window`（图形界面，含降级）

1. `日志屏蔽_开启()`；未见 `--selector=`（默认 `选择模式 = "window"`、`显式选择器 = false`）或显式 `--selector=window`；`InitGoogleTest`；建模型。
2. `if (!engine::图形操作界面_运行(模型))`（**图形界面内部见同层 `图形界面.md`**）：
   - **返回真**（界面会话正常结束）→ `engine::日志屏蔽_落盘(); return 0;`（界面内已驱动多轮测试，**不再二次执行**）。
   - **返回假**（窗口创建失败，无图形环境）→ 打印 `[测试选择] 图形窗口不可用，改用控制台菜单。`
3. 降级路径：`控制台选择菜单_运行(模型, 过滤串)` → 打印过滤串 → `GTEST_FLAG(filter) = 过滤串` → `RUN_ALL_TESTS()` → `日志屏蔽_落盘()`。
4. 若 `需要等待退出("window", 命令行带过滤, 显式选择器)` 为真（默认双击运行为真）→ `等待用户关闭窗口()`；`return 测试结果;`。
5. **异常/边界**：未知选择模式（`--selector=xxx`）走本分支同一 `else`（默认 window），窗口失败再退控制台菜单；退出等待判定对未知模式兜底为「停住」。

### 7.4 子流程：控制台菜单一次交互

1. 取 `模型.suite_table_get()`；打印标题 `===== 白银纪元 · 测试模块选择（控制台）=====` 与逐条 `N) 套件名（M 个用例）`。
2. 提示输入；循环最多 3 次：
   - `std::getline(std::cin, 输入)` 失败（管道/重定向）→ `all_check()` + `filter_string_build()` + 打印「未读到输入，按全选处理。」→ 返回；
   - 全空白输入 → 全选处理并返回；
   - `解析控制台选择(输入, 套件数, 勾选表)` 失败 → 提示重试（`continue`）；
   - 成功 → 逐条 `模型.suite_check_set(i, 勾选表[i])` → `过滤串 = 模型.filter_string_build()` → 打印「已生成过滤串：…」→ 返回。
3. 3 次非法后兜底：`all_check()` + `filter_string_build()`。

```
输入 "1,3-5"（套件数≥5）
   → 解析控制台选择 → 勾选表 = {1:√,2:×,3:√,4:√,5:√,6:×,…}
   → 逐条 suite_check_set
   → filter_string_build：套件1 若整组全选→"套件1.*"；套件3/4/5 视其勾选态压缩/逐条
   → 过滤串（':' 连接）
```

### 7.5 子流程：引擎日志屏蔽的开启与落盘

1. `日志屏蔽_开启()`：`屏蔽已开启` 为真即返回（幂等）；否则取路径 → 建父目录 → `new(std::nothrow) ofstream(路径, out|trunc)` → 失败则放弃屏蔽 → 否则 `logger.root_set("")` + `logger.stream_bind("", 日志流)` 成功则 `屏蔽已开启 = true`。
2. 测试运行期间，引擎侧 `logger` 的日志沿根节点父链继承该文件流，不再落控制台。
3. 每条 `RUN_ALL_TESTS()` 之后、`return` 之前调用 `日志屏蔽_落盘()`（`logger.stream_flush()`），确保缓冲写出。
4. 日志系统用例夹具（另属 `工具集.md` 的日志系统部分）会成对 `日志屏蔽_关闭()` / `日志屏蔽_开启()`，以验证「未绑定即走控制台」。

### 7.6 关键边界分支汇总表

| 场景 | 触发点 | 处理 | 结果 |
| --- | --- | --- | --- |
| 带 `--gtest_*` 且未显式选择器 | 透传判定 | 直接 `RUN_ALL_TESTS` | 不建模型、不开窗、不停 |
| `--selector=off` | 分流判定 | 同上 | 不停（ctest 路径） |
| `--selector=console` + `--gtest_filter=...` | 透传判定不成立 | 走控制台菜单，菜单结果覆盖命令行过滤串 | 走 ③ 路径、停 |
| `--selector=xxx`（未知） | 落 `else`（默认 window） | 图形界面；失败再退控制台菜单 | 停 |
| 图形窗口创建失败 | `图形操作界面_运行` 返回假 | 打印提示 → 控制台菜单 → 跑一轮 | 降级成功 |
| 图形界面会话正常结束 | `图形操作界面_运行` 返回真 | 落盘后 `return 0` | 不二次执行 |
| 控制台空输入 / 输入流结束 | `控制台选择菜单_运行` | `all_check()` 全选 | 过滤串 `"*"` |
| 控制台非法输入 ≥ 3 次 | 菜单循环 | 兜底全跑 | 过滤串 `"*"` |
| 控制台编号越界 / 空段 / 区间颠倒 | `解析控制台选择` | 判非法，勾选表重置全假 | 菜单提示重试 |
| 全部用例未勾选 | `filter_string_build` | 退化为 `"*"` | 等价全跑 |
| 无控制台窗口 | `等待用户关闭窗口` | `GetConsoleWindow() == nullptr` 直接返回 | 不挂住 |
| 日志文件打开失败 | `日志屏蔽_开启` | 放弃屏蔽 | 日志留控制台，测试继续 |
| 无参数启动 | 默认 window + 停住判定为真 | 跑完 `等待用户关闭窗口()` | 交互挂住（§6.8 坑位） |

- **TEST-01（README 与源码口径不一致）**
  - 问题：`Application/Test/README.md` 第 2、6.4、6.5、7.3、9.3 等节仍描述图形选择窗口为「GLFW + OpenGL3 + glad」、文件为 `图形选择窗口.h`/`.cpp`；而本版次源码为「图形操作界面 + 测试界面 + 测试运行器 + 测试运行记录 + gtest输出镜像」，构建脚本用 SDL3 + Vulkan + ImGui（`imgui_impl_sdl3.cpp`/`imgui_impl_vulkan.cpp`），无 glfw/opengl3/glad。README 第七章的目标表与目录树也与当前 `CMakeLists.txt`（`TestLauncher`/`EngineTests` 源文件构成）不符。
  - 推断：README 未随「图形界面重构为经渲染层 UI 通道（SDL3+Vulkan）」同步更新；本文以源码为准。是否需回写 README 待用户裁定。

- **TEST-02（屏蔽日志落点的口径差异）**
  - 问题：`引擎日志屏蔽.cpp` 注释称该相对路径「落在构建产物区 `out/`，不污染层根」；但可执行文件经 `RUNTIME_OUTPUT_DIRECTORY` 落在**层根**，`Engine_Env::exe_dir_get()` 以可执行文件目录为基准，故实际落点为 `Application/Test/out/引擎运行日志.txt`——此 `out/` 与构建目录 `out/build/x64-Debug/` 并非同一目录（前者是层根下的产物区）。
  - 推断：注释中的「构建产物区 `out/`」应指**层根下的 `out/`**（与生成源文件清单位置同一区域），而非 CMake 构建树；该口径是否与团队约定一致待确认。

- **TEST-03（控制台菜单的粒度取舍）**
  - 问题：`Test_Selection_Model` 本身支持用例粒度（`case_check_set`），但 `控制台选择菜单_运行` 只把选择结果按套件整体写入（`suite_check_set`），不暴露用例粒度入口。
  - 推断：控制台菜单定位为「无图形环境的回退入口」，精细的用例级勾选交由图形界面；此取舍源码未显式说明，属设计意图待确认。
