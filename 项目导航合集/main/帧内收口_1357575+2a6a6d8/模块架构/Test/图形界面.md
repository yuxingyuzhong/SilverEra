## 二、模块功能介绍

### 2.1 模块定位

「图形界面」位于测试层主调目录 `Application/Test/src/主调/`，是测试层**默认的交互入口**（`--selector=window` 或未指定选择器时走此分支），把「测试选择 → 运行 → 结果查看」组织成**一个常驻窗口内的即时模式界面**。它由四个部分协作构成：

1. **图形操作界面**（`图形操作界面.h/.cpp`）：会话级外壳——初始化渲染层与两条 ImGui 后端、接线绘制与事件回调、跑主循环、收尾清理；对外只暴露一个入口 `图形操作界面_运行(Test_Selection_Model&)`。
2. **测试界面**（`测试界面.h/.cpp`）：每帧把「选择树 / 运行控制 / 结果表 / gtest 输出镜像 / 轮次历史 / 引擎日志」绘制到窗口内；取运行器的只读快照、把用户的运行/停止/清空/退出动作下发给运行器。
3. **测试运行器**（`测试运行器.h/.cpp`）：把 gtest 的执行从界面线程移出——**工作线程**串行执行一轮 `RUN_ALL_TESTS()`，**界面线程**只经快照接口读取进度与结果，二者不冻结、不互锁（除必要的短临界区）。
4. **gtest 输出镜像**（`gtest输出镜像.h/.cpp`，数据结构见 `测试运行记录.h`）：一个 `::testing::TestEventListener` 监听器，每用例结果与输出行都被采集进带锁的容器，供界面滚动显示与结果表引用。

一句话概括：**本模块是「用一扇常驻图形窗口驱动多轮 gtest 运行」的界面与会话编排——渲染层出窗口与 Vulkan 设备，ImGui 出界面，工作线程出测试执行，镜像出可被界面安全读取的结果。**

### 2.2 职责边界与解决的问题

1. **有图形环境时以窗口为默认入口，无图形环境安全降级**。`图形操作界面_运行` 在渲染器初始化失败、UI 通道不可用、任一 ImGui 后端初始化失败时返回 `false`，主程序据此退到控制台菜单（§7.1）。字体探测失败不构成失败——界面仍可运行（中文显示为方块，仅影响观感）。
2. **常驻窗口驱动「多轮」测试**，取代「建窗 → 勾选 → 跑一轮 → 关窗」的一次性流程。窗口不因一轮测试结束而关闭；用户可反复点「运行选中」「重跑失败」，每轮结果与输出累积保留（§6.7）。
3. **把 gtest 执行从界面线程剥离**。若在界面帧回调里直接跑 `RUN_ALL_TESTS()`，一轮测试期间窗口不响应、无法中途查看进度、无法停止。故本模块让**工作线程**跑测试、**界面线程**只读快照；界面侧读取一律经带锁/原子的快照接口，二者无需冻结（§6.4）。
4. **让「默认打印器」退出控制台、改由界面镜像**。gtest 默认把进度与结果打到控制台；与引擎日志交织会不可读。本模块在界面模式下把镜像监听器 `Append` 进 gtest 监听器列表并 `Release` 默认打印器，由镜像按 gtest 控制台同风格格式化输出行，供界面显示（§6.6）。
5. **引擎日志分流**。测试期间引擎日志经 `引擎日志屏蔽` 落到文件（`out/引擎运行日志.txt`），不落入控制台；界面底部「引擎日志（尾部）」折叠栏按帧读取该文件尾部（§6.9）。
6. **复用渲染层已建的窗口与 Vulkan 设备**。界面不自建 SDL 窗口、不自建设备，而是经 `Renderer::ui_channel()` 取 `Ui_Channel_Context` 的通道信息（§6.1），把 ImGui 的 Vulkan 后端与 SDL3 后端绑到渲染层同一窗口与设备上。

### 2.3 在整体架构中的位置

图形界面处于测试层层内主调部分，向上由 `main()`（`主程序.cpp`）调用、向下依赖主调层的选择模型、运行器、界面绘制、日志屏蔽，并经测试层对外面横向依赖渲染层（`RendererCore`）与引擎核心层（`EngineCore`）：

```
                 main()（src/主调/主程序.cpp）
                    │  默认 / --selector=window
                    ▼
        ┌───────────────────────────────────────────────┐
        │            图形操作界面_运行                    │
        │  Renderer.init → ui_channel() → ImGui 两条后端  │
        │  draw_callback_set / event_callback_set         │
        │  while (frame_render()) { ... }                 │
        └───────┬───────────────────────────┬────────────┘
                │ 每帧绘制回调               │ 事件转发回调
                ▼                           ▼
     ┌───────────────────────┐   ┌───────────────────────────┐
     │ 测试界面_绘制           │   │ ImGui_ImplSDL3_ProcessEvent│
     │ 读快照 / 下发请求       │   └───────────────────────────┘
     └───────┬───────────────┘
             ▼
     ┌───────────────────────┐        ┌──────────────────────────┐
     │ Test_Runner          │───────▶│ Gtest_Output_Mirror        │
     │ 工作线程 RUN_ALL_TESTS│  写    │ TestEventListener 覆写      │
     └───────────────────────┘        └──────────────────────────┘
             │ 只读快照（progress/rounds/cases/output）
             ▼
     ┌───────────────────────┐   ┌───────────────┐   ┌──────────────┐
     │ Test_Selection_Model  │   │ 引擎日志屏蔽    │   │ Renderer 门面 │
     │ 反射建树 / 过滤串      │   │ 读日志文件尾部  │   │ Ui_Channel    │
     └───────────────────────┘   └───────────────┘   └──────────────┘
```

- **向上**：调用方唯一——`main()` 在建立 `Test_Selection_Model` 后调用 `图形操作界面_运行(模型)`；返回值 `false` 触发降级。
- **向下（层内）**：`测试界面` 依赖 `测试运行器` 读快照、下发请求，并用 `测试选择模型` 的勾选态与过滤串；`测试运行器` 依赖 `gtest输出镜像`；`测试界面` 与 `测试运行器` 共用 `测试运行记录.h` 的数据结构。
- **横向（跨层）**：经测试层对外面依赖渲染层 `RendererCore`（`Renderer` 门面与 `Ui_Channel_Context`）与引擎核心层 `EngineCore`（日志系统、引擎环境、路径字符串转换）。
- **第三方**：Dear ImGui 核心与两条后端（`imgui_impl_sdl3`、`imgui_impl_vulkan`）以源码副本落在 `Application/Test/external/Dear_ImGui/`，由 `TestGui` 静态库编译（§附录 A）。

### 2.4 与相邻对象的职责分界

| 相邻对象 | 分界 |
| --- | --- |
| 渲染层 UI 通道（`Ui_Channel_Context`，归属「Renderer/UI通道」） | 通道**只出窗口/设备/时机/事件转发口**，不代管 ImGui；本模块在 `init` 之后取 `通道->info_get()` 初始化后端，注册绘制与事件回调，会话结束前 `*_clear()` 解接线。见 §6.1。 |
| 渲染层门面（`Renderer`，归属「Renderer/门面」） | 门面**创建并拥有**窗口、设备、交换链与帧链路；本模块只 `init` / `frame_render` / `close_requested` / `shutdown` 四个门面调用，不触碰渲染层内部对象。 |
| 测试选择模型（`Test_Selection_Model`） | 纯逻辑的套件/用例树与勾选态；**图形界面与控制台菜单共用同一模型**。图形模式额外支持用例粒度勾选与套件展开态（§6.8）。 |
| 控制台选择菜单（`控制台选择菜单.h/.cpp`） | 图形不可用时的回退入口，按**套件粒度**勾选；本模块不调用它，只由 `main()` 在降级分支调用。 |
| gtest（`googletest`） | 提供反射（建树）与 `RUN_ALL_TESTS`；本模块经镜像接管其输出、经 `GTEST_FLAG` 设过滤串。 |
| 引擎日志屏蔽（`引擎日志屏蔽`） | 提供日志文件路径与落盘；本模块只读其路径取日志尾部，**不负责**分流开关（由 `main()` 在进测试前开启）。 |
| 渲染层帧模块（归属「Renderer/帧」） | 只按 `Frame_Ui_Callback` 类型在场景通道内调用本模块的绘制回调，不持有、不代管本模块。 |

### 2.5 生命周期与调用约定

**会话级（`图形操作界面_运行`）**：

```
渲染器.init(config) → 取 UI 通道（info_get）→ ImGui::CreateContext
   → ImGui_ImplSDL3_InitForVulkan → ImGui_ImplVulkan_Init → 加载中文字体
   → 运行器.ui_install() → 注册绘制/事件回调
   → while (frame_render()) { 界面驱动多轮测试 }
   → 解接线（clear 两个回调）→ 运行器.shutdown() → ImGui 关闭 → 渲染器.shutdown()
```

- 任一前置失败（渲染器 init / 通道无效 / SDL3 后端 / Vulkan 后端）立即逆序清理并返回 `false`；字体加载失败仅告警。
- 主循环每帧只推进渲染层帧链路；退出条件为「窗口请求关闭」或「界面按钮置退出请求」。

**对象级**：

- `Test_Runner`：`default` 构造不安装镜像、不起线程；`ui_install` 幂等；`request_run` 首次起线程、运行中再请求则排队；`request_stop` 只清排队；`shutdown` 停止并 `join` 工作线程；析构兜底 `shutdown`。**不可拷贝、不可移动**。
- `Gtest_Output_Mirror`：`default` 构造；`final` 类（不可继承）；全部采集接口持内部 `mutable std::mutex`（读接口为 `const`），进度用两个 `std::atomic<int>`；**线程安全**——可被工作线程写、界面线程读。
- `测试界面_绘制` 的跨帧状态为**函数内 `static`**（搜索缓冲、选中行、只看失败、自动滚动、日志行），随会话存活；同一进程内多次调用共享这份界面态（非按会话隔离，多实例/多次调用共用同一份）。

### 3.2 `图形操作界面_运行`

- **声明**：`Application/Test/src/主调/图形操作界面.h`；**实现**：`图形操作界面.cpp`。
- **签名**：`bool 图形操作界面_运行(Test_Selection_Model& 模型)`。
- **参数**：`模型` —— 已建树的测试选择模型（按引用，界面直接读写其勾选态与展开态）。
- **返回值**：`true` 表示界面会话正常结束（用户关闭窗口或点「退出界面」）；`false` 表示窗口创建/初始化失败（无图形环境），调用方应退到控制台菜单。
- **行为要点**（详见 §7.1／§7.5）：
  1. 以固定配置 `init` 渲染器（`width=1280`、`height=800`、标题、`frame_overlap=2`、`vsync=true`、`hidden=false`）；失败返回 `false`。
  2. 取 `通道 = 渲染器.ui_channel()`；`通道 == nullptr || !通道->valid()` 时 `shutdown` 并返回 `false`。
  3. 建 ImGui 上下文、应用蓝色主题、`ImGui_ImplSDL3_InitForVulkan(通道信息.window)`、按通道信息填 `ImGui_ImplVulkan_InitInfo` 并 `ImGui_ImplVulkan_Init`；任一后端失败即逆序清理并返回 `false`。
  4. 加载中文字体（失败仅 `printf` 告警）。
  5. `运行器.ui_install()`；注册 `通道->draw_callback_set(ui_绘制回调, &上下文)` 与 `通道->event_callback_set(ui_事件回调, nullptr)`。
  6. `while (渲染器.frame_render())` 主循环，`close_requested() || 上下文.退出请求` 时 `break`。
  7. 逆序清理：`event_callback_clear` → `draw_callback_clear` → `运行器.shutdown()` → `ImGui_ImplVulkan_Shutdown` → `ImGui_ImplSDL3_Shutdown` → `ImGui::DestroyContext` → `渲染器.shutdown()`；返回 `true`。

### 3.4 `Test_Runner` 类

**声明**：`Application/Test/src/主调/测试运行器.h`；**实现**：`测试运行器.cpp`。

类头注释（原文要点）：界面模式（`ui_install` 后）——由本类把 `Gtest_Output_Mirror` 接入 gtest 监听器并释放默认打印器（控制台不再重复输出）；「运行」请求以过滤串入队，工作线程串行执行一轮 `RUN_ALL_TESTS`；界面线程仅经进度/快照接口读取，不触碰 gtest 状态。无头模式——不安装镜像、不启动线程，行为与 gtest 原生一致。停止语义——不再排队下一轮，当前轮跑完即结束（gtest 无中途取消能力）。

**逐条要点**：

- **`~Test_Runner`**：函数体仅 `shutdown()`——停止并 `join`；即便从未 `ui_install` 亦安全。
- **`ui_install`**：`installed` 为真则直接返回（幂等）；否则置真、`listeners().Append(&mirror)`、取 `default_result_printer()` 并 `listeners().Release(default_printer)` 后**立即 `delete`**（`Release` 只移交所有权，不析构），避免泄漏。
- **`ui_uninstall`**：从 gtest 监听器列表**摘除镜像**（`Release`/移除，镜像为本类成员、不析构），避免对象销毁后监听器列表持有悬垂指针；随后复位 `installed`。
- **`request_run` 线程生命周期**：若上一轮 `worker` 仍 `joinable`，先 `join()` 再创建新线程，避免直接重赋触发 `std::terminate`。
- **`request_run(filter)`**：先持 `mtx` 写 `pending_filter = filter; queued = true;`；随后**仅当** `state == Idle` 时置 `Running` 并起工作线程 `worker = std::thread([this]{ worker_main(); })`。运行中再次请求只更新排队（覆盖前一个未执行请求）；重赋前若旧 `worker` 仍 `joinable` 则先 `join()`，不会触发 `std::terminate`。
- **`request_stop`**：持 `mtx` 清 `queued = false; pending_filter.clear();`——当前轮跑完后工作线程见无排队即自行退出。
- **`clear_results`**：转调 `mirror.results_clear()`。
- **`shutdown`**：`request_stop()` 后若 `worker.joinable()` 则 `join()`（正在跑一轮时会等待其完成）。
- **`is_running`**：`state.load() == Running`。
- **`last_exit_code`**：返回 `exit_code`（上一轮 `RUN_ALL_TESTS()` 返回值）；`exit_code` / `state` 均为 `std::atomic<int>`，跨线程读写无数据竞争。界面当前未使用它。
- **四个快照**：全部转调 `mirror` 的同名方法（持有镜像内部锁做拷贝），保证界面线程读时不与工作线程写竞争。见 §6.4。

**逐条要点**：

- **`round_begin`**：持锁 `cases.clear()`、`completed_cases=0`、`total_cases=0`、`current_case = Case_Result{}`、`in_case = false`；**保留** `rounds` 与 `output`（供多轮展示）。由运行器在每轮 `RUN_ALL_TESTS()` 之前调用。
- **`round_end`**：持锁汇总本轮 `cases` 的通过/失败/跳过与总数，并累加各用例 `elapsed_ms` 得本轮耗时，`round = rounds.size()+1` 后 `push_back` 入 `rounds`；由运行器在 `RUN_ALL_TESTS()` 之后调用。
- **`results_clear`**：持锁清 `cases`/`rounds`/`output` 并复位两个进度原子量（界面「清空结果」按钮）。
- **`progress_get`**：直接读两个原子量（不加锁）。
- **快照三件**：持锁做**限量拷贝**——`cases_snapshot` 取末尾 `max_count` 条、`output_tail` 取末尾 `max_count` 条、`rounds_snapshot` 全量拷贝。
- **`OnTestIterationStart`**：`total_cases = unit_test.total_test_count()`；持锁镜像开场行 `"[==========] Running N tests from M test suites."`（level 0）。
- **`OnTestSuiteStart` / `OnTestSuiteEnd`**：各镜像一行 `"[----------] 套件名"`（level 0）。
- **`OnTestStart`**：持锁开启新用例——`current_case = Case_Result{}`、填 `suite`/`name`、`in_case = true`，镜像 `"[ RUN      ] 套件.用例"`（level 1）。
- **`OnTestPartResult`**：**仅失败项**输出（通过项不输出，与默认打印器一致）；持锁追加 `"文件:行号: Failure\n消息"`（level 3）。
- **`OnTestEnd`**：持锁收尾——取 `result`，`elapsed_ms = result->elapsed_time()`；状态判定顺序为**先跳过、再失败、否则通过**；失败时逐条收集各失败 `TestPartResult` 的 `"文件:行号: 摘要"` 入 `failures`；`cases.push_back(current_case)`、`++completed_cases`、`in_case = false`；随后按状态镜像 `"[       OK ]"` / `"[  SKIPPED ]"` / `"[  FAILED  ]"`（level 2/4/3，附 ` (X ms)`）。
- **`OnTestIterationEnd`**：镜像轮末统计——`"[==========] … ran."`、`"[  PASSED  ] … tests."`（level 2）、失败数 > 0 时 `"[  FAILED  ] … tests."`（level 3）；通过数由 `total - failed - skipped` 推算。
- 其余覆写（`OnTestProgramStart`、两组 Environments、`OnTestProgramEnd`）为空体。
- **`line_append(text, level)`**：`output.push_back(Output_Line{text, level})`，随后 `while (output.size() > output_cap) output.erase(output.begin())`——`output_cap` 环形裁剪。见 §4.2。`cases` 亦按 `cases_cap`（=10000）裁剪，避免长时间连跑导致内存无界增长。
- **`case_name_get`**：返回 `test_suite_name() + "." + name()`。见 §4.3。

### 4.1 `Test_Runner::worker_main`（private，实现 `测试运行器.cpp`）

- **签名**：`void worker_main(void)`。
- **作用**：工作线程入口——串行执行排队的一轮或多轮 `RUN_ALL_TESTS()`，直到无排队任务。
- **关键行为**（循环体）：
  1. 持 `mtx`：若 `!queued` 则 `state = Idle` 并 `return`（线程结束）；否则取 `filter = pending_filter`、清空 `pending_filter` 与 `queued`。
  2. 设置本轮 gtest 参数（**仅工作线程改动这些 flag**）：`GTEST_FLAG(filter) = filter`、`GTEST_FLAG(repeat) = 1`、`GTEST_FLAG(break_on_failure) = false`。
  3. `mirror.round_begin()` → `exit_code = RUN_ALL_TESTS()` → `mirror.round_end()`。
  4. 回到第 1 步。
- **语义**：以「排队布尔量 + 过滤串」驱动多轮；停止由队列清空自然收敛（不中断当前轮）。

### 4.2 `Gtest_Output_Mirror::line_append`（private，实现 `gtest输出镜像.cpp`）

- **签名**：`void line_append(const std::string& text, int level)`。
- **作用**：向 `output` 追加一条输出行并做环形裁剪。
- **关键行为**：`output.push_back(Output_Line{text, level})`；随后 `while (output.size() > output_cap) output.erase(output.begin())`（保留最新 `output_cap` 条）。**调用者须已持 `mtx`**（头注释明确此约定）。

### 4.3 `Gtest_Output_Mirror::case_name_get`（private，实现 `gtest输出镜像.cpp`）

- **签名**：`std::string case_name_get(const ::testing::TestInfo& test_info) const`。
- **作用**：拼接 `套件.用例` 形式的完整用例名（供开场/收尾行）。
- **关键行为**：`return std::string(test_info.test_suite_name()) + "." + test_info.name();`（`const` 且只读形参，无锁）。

## 六、模块设计/实现细节

### 6.1 与渲染层 UI 通道的接线

**取通道**：渲染器 `init` 成功后，`通道 = 渲染器.ui_channel()`；必须 `通道 != nullptr && 通道->valid()`，否则 `渲染器.shutdown()` 并返回失败。随后 `const Ui_Channel_Info& 通道信息 = 通道->info_get();`（const 引用，见「Renderer/UI通道」§6.3 的自引用约束——通道信息不可按值转存再用）。

**初始化两条 ImGui 后端**：

1. `IMGUI_CHECKVERSION(); ImGui::CreateContext();` 取 `io`，置 `io.ConfigFlags |= ImGuiConfigFlags_NavEnableKeyboard`、`io.IniFilename = nullptr`（不写 `imgui.ini`，保持工作区整洁）；`应用蓝色主题()`。
2. **平台后端**：`ImGui_ImplSDL3_InitForVulkan(通道信息.window)`——绑定**渲染层自建**的 `SDL_Window*`，使 ImGui 的输入与光标管理落到同一窗口。
3. **渲染后端**：`ImGui_ImplVulkan_InitInfo 后端信息{}`，逐字段映射（§6.2 表），`ImGui_ImplVulkan_Init(&后端信息)`。

**填装映射**（对齐「Renderer/UI通道」§3.2）：

| `ImGui_ImplVulkan_InitInfo` 字段 | 取值来源（`Ui_Channel_Info`） |
| --- | --- |
| `ApiVersion` | `通道信息.api_version` |
| `Instance` / `PhysicalDevice` / `Device` | `通道信息.instance` / `physical_device` / `device` |
| `QueueFamily` / `Queue` | `通道信息.graphics_family` / `graphics_queue` |
| `DescriptorPoolSize` | `描述符池规模`（常量 64；交由后端自建内部描述符池） |
| `MinImageCount` / `ImageCount` | `通道信息.min_image_count` / `image_count` |
| `UseDynamicRendering` | `通道信息.use_dynamic_rendering` |
| `PipelineInfoMain.PipelineRenderingCreateInfo` | `通道信息.pipeline_rendering`（按值赋给该成员；其 `pColorAttachmentFormats` 仍指渲染层通道的 `color_format`，见「Renderer/UI通道」§6.3） |
| `window`（平台后端形参） | `通道信息.window` |

**接线**：`上下文`（栈上 `Ui_会话上下文`）填 `模型`/`运行器`；`通道->draw_callback_set(ui_绘制回调, &上下文)`；`通道->event_callback_set(ui_事件回调, nullptr)`。**解接线**在清理阶段先做：`通道->event_callback_clear(); 通道->draw_callback_clear();`。

**关键时序约束**：ImGui 后端 `Shutdown` **必须早于** `渲染器.shutdown()`——否则后端可能在渲染层设备/交换链销毁后仍持有其句柄。本模块清理顺序（§7.5）满足此约束。

### 6.2 每帧绘制时机与 ImGui 帧序

`ui_绘制回调` 由**渲染层帧链路**在「场景动态渲染通道仍开启、`vkCmdEndRendering` 之前」调用（详见「Renderer/帧」§6.14 与「Renderer/UI通道」§6.5）。回调内帧序：

```
ImGui_ImplVulkan_NewFrame()   // 渲染后端：字体图集纹理更新等
ImGui_ImplSDL3_NewFrame()     // 平台后端：鼠标/键盘/光标状态
ImGui::NewFrame()             // 开启本帧 ImGui 帧
绘制蓝色渐变背景()             // 背景绘制列表
ImGui::Begin(面板窗口) → 测试界面_绘制(...) → ImGui::End()
ImGui::Render()               // 结束帧、产出绘制数据
ImGui_ImplVulkan_RenderDrawData(ImGui::GetDrawData(), 命令缓冲)
```

**绘制落点**：`ImGui_ImplVulkan_RenderDrawData` **直接画在本帧已开启的动态渲染通道内**（与场景共用同一颜色/深度附件），**不自开渲染通道**；`ImGui_ImplVulkan_InitInfo::PipelineInfoMain.PipelineRenderingCreateInfo` 与本通道附件格式相容是前提（§6.1）。

**帧序说明**：本模块按「SDL3 平台后端 NewFrame → Vulkan 渲染后端 NewFrame → `ImGui::NewFrame()`」，与 Dear ImGui 官方示例的推荐次序一致。

**面板铺满视口**：`ImGui::SetNextWindowPos(视口->WorkPos)` + `ImGui::SetNextWindowSize(视口->WorkSize)` + `Begin("##测试操作界面", nullptr, ImGuiWindowFlags_NoDecoration | NoMove | NoSavedSettings)`——无标题、不可移动、不写窗口设置。

### 6.3 平台事件转发

渲染层平台的事件泵（`Platform_Context::events_pump`）先经事件转发出口把每个原始 `SDL_Event` 逐事件送出（渲染层只转发、不解释输入）；渲染器门面已把该出口桥接到 UI 通道的 `event_dispatch`；本模块注册的 `ui_事件回调` 再转调 `ImGui_ImplSDL3_ProcessEvent(事件)`，把键鼠/文本输入交给 ImGui 平台后端消费。因此：

- **事件队列保持单点轮询**（由渲染层 `SDL_PollEvent` 循环统一取出），本模块不再轮询。
- 注册时序**非对称**：平台→通道的桥接由渲染器在 `init` 内无条件挂上；本模块的 `ui_事件回调` 在 `init` **之后**注册——「桥接已挂、回调未注册」窗口期内的 `event_dispatch` 为空操作（见「Renderer/UI通道」§6.6）。

### 6.4 线程模型与只读快照

| 项 | 工作线程（`worker_main`） | 界面线程（渲染主线程） |
| --- | --- | --- |
| 职责 | 串行跑一轮或多轮 `RUN_ALL_TESTS()` | 每帧推进 `frame_render` 与界面绘制 |
| 触碰 gtest 状态 | 是（`GTEST_FLAG`、`RUN_ALL_TESTS`） | **否**（只读快照） |
| 写 `Gtest_Output_Mirror` 容器 | 经 gtest 回调写入（持 `mtx`） | 否 |
| 写 `Test_Runner::state` | 置 `Idle` 于出口 | 置 `Running` 于 `request_run` |
| 写 `pending_filter`/`queued` | 取用后清空（持 `mtx`） | `request_run`/`request_stop` 登记（持 `mtx`） |
| 读快照 | — | 经 `progress_get`/`rounds_snapshot`/`cases_snapshot`/`output_tail` |

**为什么「不冻结」**：界面线程读取一律经**短临界区拷贝**（快照接口持镜像锁做限量拷贝后即释放），故工作线程长时间跑测试时界面仍可逐帧刷新进度与已出结果；工作线程不会因界面绘制而长时间阻塞。

**原子与锁的分工**：进度（`completed_cases`/`total_cases`）用 `std::atomic<int>` 无锁读；结果/轮次/输出三容器用 `mutable std::mutex` 保护（读接口为 `const`）。`Test_Runner::state` 为 `std::atomic<int>`。`Test_Runner::exit_code` 为 `std::atomic<int>`，跨线程读写无数据竞争。

**一致性**：`cases_snapshot`/`output_tail` 取**末尾** `max_count` 条——注释说明「当前轮新结果在尾部」，界面按追加顺序展示。

### 6.5 运行/停止/退出语义

- **运行（`request_run`）**：登记 `pending_filter`（**覆盖式**——运行中多次点击只保留最后一次过滤串）、`queued = true`；若空闲则起工作线程。界面侧「运行选中」传 `model.filter_string_build()`（全不选时该模型返回 `"*"`，即全跑）；「重跑失败」传当前快照的失败过滤串（§4.5）。
- **停止（`request_stop`）**：清空排队（`queued = false`、`pending_filter.clear()`）。**当前轮跑完即止**——gtest 无中途取消能力（类头注释）；工作线程在轮末回到循环时见 `!queued` 即置 Idle 并结束，「停止」按钮在非运行时禁用（`BeginDisabled(!runner.is_running())`）。
- **排队语义**：类头注释「运行中再次请求则排队，跑完当前轮后执行」——`worker_main` 每轮结束回到循环、若 `queued` 为真即取用下一轮；故「运行中点击运行」＝「追加一轮（覆盖过滤串）」，而非并发。
- **退出（界面）**：「退出界面」按钮置 `exit_requested = true`；主循环检 `渲染器.close_requested() || 上下文.退出请求` 即 `break`。窗口被直接关闭（`close_requested`）同样退出。
- **`clear_results`**：清空全部结果/轮次/输出并复位进度（界面同时把「选中结果」重置为 -1）。

### 6.6 gtest 监听器接管与默认打印器释放

`ui_install`（仅界面模式调用，幂等）：

```
if (installed) return;
installed = true;
::testing::UnitTest::GetInstance()->listeners().Append(&mirror);          // 接入镜像
default_printer = ::testing::UnitTest::GetInstance()->listeners().default_result_printer();
if (default_printer != nullptr)
    ::testing::UnitTest::GetInstance()->listeners().Release(default_printer); // 释放默认打印器
```

**设计含义**：

1. `Append(&mirror)` 把镜像加入监听器列表，于是**每次 gtest 事件**（用例开始/断言/用例结束/套件开始结束/轮次开始结束等）都会回调镜像——这是结果采集与输出镜像的数据入口。
2. `Release` 把默认打印器从 gtest 所有权中**移出**，使其不再把进度/结果打到控制台——避免与「镜像到界面」重复输出、也避免与引擎日志交织。无头/控制台模式**不调用** `ui_install`，因此行为与 gtest 原生一致（默认打印器照常输出）。
3. **`Release` 后立即 `delete`**：`Release` 只把所有权交回调用者，实现随后 `delete default_printer`，无泄漏。
4. **镜像在卸载时摘除**：`ui_uninstall` 从 gtest 监听器列表移除镜像（`Release` 不析构，镜像为成员），避免 `Test_Runner` 析构后列表持有悬垂指针。

### 6.7 测试运行记录与容量

- **轮次保留策略**：`round_begin` 只清 `cases` 与进度，**保留** `rounds`（历史）与 `output`（滚动输出）。故界面可显示「多轮历史」横条与持续累积的输出镜像；`results_clear` 才将三者一并清空。
- **轮次汇总耗时**：`Round_Summary::elapsed_ms` 在 `round_end` 中累加各用例 `elapsed_ms`，界面「第N轮 … ms」显示真实耗时。
- **输出环形裁剪**：`output` 上限 `output_cap = 2000`，超出丢最旧（`line_append`）；界面另以 `输出上限 = 400` 只取尾部 400 行显示。
- **用例结果裁剪**：`cases` 由 `round_begin` 按轮清空；`OnTestEnd` 追加后按 `cases_cap = 10000` 丢弃最旧，避免连跑导致内存无界增长；界面另以 `结果上限 = 400` 只取尾部 400 条显示。
- **级别**：`Output_Line.level` 取值语义见 §5.3.3；界面据 `level` 着色（3 红 / 2 绿 / 4 黄 / 0 淡蓝 / 其余近白），当前实现产出的级别为 {0,1,2,3,4}，`5 信息` 无产出点。

### 6.8 图形操作界面与测试界面的职责划分及选择模型用法

**职责划分**：

| 职责 | 归属 |
| --- | --- |
| 渲染器/ImGui 初始化、接线、主循环、清理 | 图形操作界面 |
| 每帧 ImGui 帧序、背景、面板窗口 | 图形操作界面（回调内）／测试界面（面板内容） |
| 选择树绘制与交互、运行控制、结果表、输出镜像、轮次历史、引擎日志 | 测试界面 |
| 测试执行、排队、停止、结果采集 | 测试运行器 + 输出镜像 |

一句话：**图形操作界面管「会话与帧」，测试界面管「面板内容与交互」，运行器管「执行与状态」**；测试界面不含任何 Shell/渲染调用，全部经运行器与模型接口。

**选择模型在图形模式下的用法**（`测试界面_绘制` 左列「##选择区」）：

- **工具条**：`全选`→`model.all_check()`、`清空`→`model.all_clear()`、`反选`→`model.check_invert()`；搜索框 `InputTextWithHint("##搜索", ...)` 写 `搜索缓冲`；`已选 %zu / %zu` 用 `model.checked_case_count()` / `model.case_count()`。
- **套件节点**：遍历 `model.suite_table_get()`；`可选：关键词` 时对「套件名命中」或「任一用例名命中」者显示，否则整组隐藏（隐藏项勾选态保留）；套件级复选框用 `model.suite_all_checked(序号)` 读、`model.suite_check_set(序号, 勾选)` 写；展开态由 `model.suite_expanded(序号)` 读、`ImGui::SetNextItemOpen(..., ImGuiCond_Always)` 同步、`model.suite_expand_set(...)` 回写（**展开态由模型持有**，避免每帧复位）；节点标签含「（已选/总数）」计数。
- **用例复选**：`model.case_check_set(套件序号, 用例序号, 勾选)`；`PushID` 以套件/用例序号隔离控件 ID。
- **过滤串**：运行/重跑按钮生成过滤串——「运行选中」用 `model.filter_string_build()`（整套件全选压缩为 `套件.*`、部分勾选逐条列、全不选用 `"*"`）；「重跑失败」用 `失败过滤串生成(用例表)`（§4.5）。

> 图形模式**额外能力**（相对控制台菜单）：用例粒度勾选、套件展开态、搜索过滤、只看失败、点击行看失败详情。控制台菜单只支持套件粒度编号勾选（归属「测试选择模型/控制台选择菜单」）。

**右列「##结果区」**：`只看失败` 开关 + 三列表格（用例 / 状态 / 耗时，`ScrollY`），行可选中以展开失败详情（`选中用例.failures` 逐条 `TextWrapped`）；下方为 gtest 输出镜像滚动区（`自动滚动` 复选框、级别着色、`SetScrollHereY(1.0f)`）。

**底部**：轮次历史横条（无轮次时 `TextDisabled("尚未运行任何一轮测试")`）；`引擎日志（尾部）`折叠栏——**仅展开时**每帧 `引擎日志刷新(日志行)`（§4.5）并显示尾部（`日志上限 = 300`）。

### 6.9 引擎日志与中文字体

- **引擎日志**：`main()` 在进入测试前调用 `引擎日志屏蔽_开启()`，把引擎日志从控制台分流到 `out/引擎运行日志.txt`（相对可执行文件目录）；界面折叠栏按需读取该文件尾部。界面**不负责**分流开关与落盘（由 `main()` 在结束前 `引擎日志屏蔽_落盘()`）。
- **中文字体**：候选链逐平台给出（§4.4）；**先判文件存在**再加载，避免 ImGui 逐个打印加载失败日志；合并「中文全范围 + ♪/•/…/✓」四字形；命中即用，全部失败时回退默认字体（界面仍可运行，中文显示为方块）。字体像素大小 `19.0f`。
- **主题**：蓝色主题（§4.4），窗口底全透明以便背景渐变透出。

### 6.10 易错点清单

| 易错点 | 说明与规避 |
| --- | --- |
| 工作线程重赋 `worker` 的 joinable 语义 | `request_run` 在 `state==Idle` 且需要新起线程时，**先 `join` 旧 `worker`（若 joinable）**再赋值，故「跑完后再点运行」不会触发 `std::terminate`。 |
| 通道信息不可按值转存 | `Ui_Channel_Info` 的 `pipeline_rendering.pColorAttachmentFormats` 自引用其 `color_format`（「Renderer/UI通道」§6.3）；本模块只以 `const Ui_Channel_Info&` 使用。 |
| ImGui 关闭须早于渲染器关闭 | 清理顺序固定为「解接线 → 停运行器 → ImGui 关闭 → 渲染器关闭」（§7.5）；颠倒会使后端持有已销毁句柄。 |
| 回调内不得再开渲染通道 | `ui_绘制回调` 在场景动态渲染通道内被调用，`ImGui_ImplVulkan_RenderDrawData` 直接画在该通道内，**不得**再 `vkCmdBeginRendering`。 |
| 停止不是取消 | `request_stop` 只清排队；**当前轮会完整跑完**（gtest 无中途取消能力）。 |
| 排队请求被覆盖 | `request_run` 以 `pending_filter = filter` 覆盖式登记；连续多次请求只保留最后一次过滤串。 |
| 界面必须在面板窗口内调用 | `测试界面_绘制` 的控件须有有效 ImGui 窗口才可放置与命中；`ui_绘制回调` 已 `Begin`/`End` 包住它。 |
| 展开态须由模型持有 | 用 `SetNextItemOpen(..., ImGuiCond_Always)` 每帧同步模型态；直接依赖 ImGui 内部态会每帧复位。 |
| 日志读取在渲染线程 | 折叠栏展开时每帧读日志文件（IO）；收起时不读。 |
| 过滤串特殊字符 | 用例/套件名若含 `:`、`*`、`?` 等 gtest 过滤串特殊字符，拼接会断裂；当前依赖命名规范规避（属已知边界，「测试选择模型」侧）。 |

## 七、模块运行链路详例

调用方在测试层内为 `main()`（`主程序.cpp`）；渲染层侧回调由帧链路与平台事件泵触发。

### 7.1 初始化链路

1. **`main()`**：`--selector=window`（或默认）分支下，先 `模型.suite_tree_build()`，再 `图形操作界面_运行(模型)`。
2. **渲染器初始化**：填 `Renderer_Config{width=1280, height=800, title="白银纪元 · 测试操作界面", frame_overlap=2, vsync=true, hidden=false}`；`渲染器.init(配置)`。失败（`false`）→ 返回 `false`（调用方退控制台菜单）。
3. **取 UI 通道**：`通道 = 渲染器.ui_channel()`；`通道 == nullptr || !通道->valid()` → `渲染器.shutdown()`、返回 `false`。
4. **ImGui 初始化**：`IMGUI_CHECKVERSION` → `CreateContext` → 置 `io` 标志与 `IniFilename=nullptr` → `应用蓝色主题()`。
5. **平台后端**：`ImGui_ImplSDL3_InitForVulkan(通道信息.window)`；失败 → `ImGui::DestroyContext()` + `渲染器.shutdown()`、返回 `false`。
6. **渲染后端**：填 `ImGui_ImplVulkan_InitInfo`（映射见 §6.1 表）→ `ImGui_ImplVulkan_Init(&后端信息)`；失败 → `ImGui_ImplSDL3_Shutdown()` + `ImGui::DestroyContext()` + `渲染器.shutdown()`、返回 `false`。
7. **字体**：`加载中文字体(19.0f)`；失败仅 `printf` 告警。
8. **运行器安装**：`运行器.ui_install()`（接管监听器、释放默认打印器，§6.6）。
9. **接线**：填 `上下文`（模型/运行器）；`通道->draw_callback_set(ui_绘制回调, &上下文)`、`通道->event_callback_set(ui_事件回调, nullptr)`。
10. 进入主循环（§7.2）。

### 7.2 每帧渲染链路

1. **`main` 线程**：`while (渲染器.frame_render())` 每次迭代推进一帧。
2. **帧链路（渲染层）**：泵事件 → 取图像 → 录制命令。**事件阶段**：`events_pump` 逐事件转发 → `ui_事件回调` → `ImGui_ImplSDL3_ProcessEvent`（§6.3）。**录制阶段**：`command_record` 在场景通道内、`vkCmdEndRendering` 之前调用 `ui_绘制回调(命令缓冲, &上下文)`。
3. **UI 帧**（`ui_绘制回调`）：`ImGui_ImplVulkan_NewFrame` → `ImGui_ImplSDL3_NewFrame` → `ImGui::NewFrame` → `绘制蓝色渐变背景` → `Begin("##测试操作界面", ...)` → `测试界面_绘制(运行器, 模型, 上下文.退出请求)` → `End` → `ImGui::Render` → `ImGui_ImplVulkan_RenderDrawData(draw_data, 命令缓冲)`。
4. **`测试界面_绘制`**：取四份快照（cases / rounds / output / progress）→ 顶部控制与进度 → 左列选择树（读写模型）→ 右列结果表与输出镜像 → 底部轮次历史与引擎日志。用户动作（运行/重跑/清空/停止/退出、勾选、搜索、展开）在此落地。
5. **主循环收尾**：`if (渲染器.close_requested() || 上下文.退出请求) break;`。

### 7.3 一次运行（一轮 `RUN_ALL_TESTS`）

1. **界面线程**：用户点「运行选中」→ `runner.request_run(model.filter_string_build())`（或「重跑失败」→ 失败过滤串）。
2. **`request_run`**：持 `mtx` 写 `pending_filter`、`queued = true`；若 `state == Idle` → `state = Running`、起 `worker` 线程。
3. **工作线程 `worker_main`**：
   a. 持 `mtx`：有排队则取 `filter`、清 `pending_filter`/`queued`；无排队则 `state = Idle` 并结束。
   b. 设 `GTEST_FLAG(filter) = filter`、`repeat = 1`、`break_on_failure = false`。
   c. `mirror.round_begin()`（清本轮 `cases` 与进度）。
   d. `exit_code = RUN_ALL_TESTS()`——gtest 逐用例触发镜像回调：`OnTestStart`（开用例 + `[ RUN ]`）、`OnTestPartResult`（失败断言行）、`OnTestEnd`（收状态/耗时/失败消息 + `[ OK ]`/`[ FAILED ]`/`[ SKIPPED ]`、`++completed_cases`）、套件/轮次起止行等；镜像持锁写容器。
   e. `mirror.round_end()`（汇总入 `rounds`）。
   f. 回到 a。
4. **界面线程（并行）**：每帧读快照，实时刷新进度条、结果表、输出镜像。
5. 一轮结束（无排队）后工作线程置 `state = Idle` 并结束；界面「运行选中」重新可用（再次请求时会先 `join` 旧线程再起新线程）。

### 7.4 请求停止链路

1. **界面线程**：在运行中点「停止」（`BeginDisabled(!runner.is_running())` 允许）→ `runner.request_stop()`。
2. **`request_stop`**：持 `mtx` 清 `queued = false`、`pending_filter.clear()`（**不打断当前轮**）。
3. **工作线程**：当前轮 `RUN_ALL_TESTS()` 跑完后 `round_end()`、回到循环、持 `mtx` 见 `!queued` → `state = Idle`、结束。
4. **结果**：`is_running()` 变假，「停止」按钮转禁用；已完成的轮结果与输出保留在快照中。

### 7.5 退出与清理链路

1. **退出触发**：界面「退出界面」置 `上下文.退出请求 = true`；或用户直接关闭窗口（渲染层 `close_requested()` 为真）。主循环 `break`。
2. **清理（固定顺序）**：
   a. `通道->event_callback_clear();`（停止事件转发到本模块）；
   b. `通道->draw_callback_clear();`（停止每帧绘制回调）；
   c. `运行器.shutdown();`（`request_stop` + `join` 工作线程；若正在跑一轮则等待其完成）；
   d. `ImGui_ImplVulkan_Shutdown(); ImGui_ImplSDL3_Shutdown(); ImGui::DestroyContext();`
   e. `渲染器.shutdown();`
3. **返回** `true` 给 `main()`；`main()` 随后 `引擎日志屏蔽_落盘()` 并结束（**不再**二次执行测试）。

### 7.6 关键边界分支汇总表

| 场景 | 触发点 | 处理 | 结果 |
| --- | --- | --- | --- |
| 渲染器 `init` 失败 | `图形操作界面_运行` 第 2 步 | 直接返回 `false` | 调用方退控制台菜单 |
| UI 通道为空中/无效 | 第 3 步 | `渲染器.shutdown()` 后返回 `false` | 同上 |
| SDL3 后端初始化失败 | 第 5 步 | 销毁上下文 + `渲染器.shutdown()` | 返回 `false` |
| Vulkan 后端初始化失败 | 第 6 步 | 逆序关后端 + 销毁上下文 + `渲染器.shutdown()` | 返回 `false` |
| 中文字体全失败 | 第 7 步 | `printf` 告警 | 界面仍运行（中文方块），返回路径不受影响 |
| 运行中再次点运行 | `request_run` | 覆盖 `pending_filter`、`queued = true` | 当前轮后追加一轮 |
| 空闲态再次点运行 | `request_run` | 先 `join` 旧 `worker`（若 joinable），再起新线程 | 正常追加一轮 |
| 点「停止」 | `request_stop` | 清排队，不中断当前轮 | 当前轮跑完即止 |
| 无失败却点「重跑失败」 | 界面 `BeginDisabled(!有失败)` | 按钮禁用 | 不产生请求 |
| 全不选后点「运行选中」 | `filter_string_build()` 返回 `"*"` | 全跑 | 与 gtest `"*"` 语义一致 |
| 日志文件不存在 | `引擎日志刷新` | 打开失败即返回 | 日志栏空白 |
| 界面请求退出 / 窗口关闭 | 主循环条件 | `break` | 进入清理 |
| 清理时正在跑一轮 | `运行器.shutdown()` | `join` 等待其完成 | 不丢结果、不悬垂写 |
| 无头/控制台模式 | 不调用 `ui_install` | 不装镜像、不起线程 | 行为与 gtest 原生一致 |
