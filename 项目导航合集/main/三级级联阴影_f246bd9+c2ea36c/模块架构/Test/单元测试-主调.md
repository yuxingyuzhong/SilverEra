## 二、模块功能介绍

### 2.1 模块定位

「单元测试-主调」编译单元是 `Application/Test/src/单元测试/主调/` 下的 2 份用例源文件所属的那部分用例集合。它们随整层唯一的用例目标 `EngineTestObjects`（OBJECT 库）一并编译，由可执行目标 `EngineTests` 收编执行（见 `Test/构建与源文件清单.md`）。

一句话概括：**本单元是「主调纯逻辑的验收集合」——只针对主调中两块可脱离窗口/控制台独立验证的纯逻辑编写用例：反射选择模型 `engine::Test_Selection_Model`（建树、勾选态、过滤串、控制台输入解析）与停住判定 `engine::需要等待退出`；而主调的进程入口、控制台菜单、图形界面、日志屏蔽等**非纯逻辑**部分不在本单元覆盖范围。**

### 2.2 职责边界与文档分界

| 对象 | 分界 |
| --- | --- |
| 本单元（主调子树 2 文件） | 只写**用例正文**：各 `TEST_F` 的覆盖意图、断言与边界、被取用的主调接口与跨目标符号来源、运行前提。 |
| `Test/测试主调.md` | 写主调**本体**的实现（`主程序.cpp` 四步分流、`测试选择模型` 建树/勾选/过滤串、`控制台选择菜单` 编号菜单、`需要等待退出`、`引擎日志屏蔽`）。本单元只从**被验证面**出发断言其对外行为，不重述其内部实现。 |

### 3.1 用例的「公开面」

本单元**无对外头，也不被层外调用**。它「对外生效」的唯一产物是 googletest 的**静态注册**：每条 `TEST_F(夹具类名, 中文用例名)` 把「套件名 = 夹具类名 + 用例名」登记进 gtest 注册表，从而可经 `::testing::UnitTest` 反射枚举、可按 `--gtest_filter` 选取。因此本文的「公开接口」指**用例向 gtest 注册表暴露的选取面**，即 3.2 的「套件→用例」两级清单。

### 3.4 跨目标符号取得契约

本单元两个套件的被测实现**分别由不同目标提供**，故「用例如何取到被测实现」是理解本单元的关键（符号依赖总表另见 `Test/测试对象与夹具.md` §6.7）：

| 套件 | 被取符号 | 声明处 | 实现处（归属目标） | 用例取得方式 |
| --- | --- | --- | --- | --- |
| `测试选择模型测试` | `engine::Test_Selection_Model`、`engine::解析控制台选择` | `src/主调/测试选择模型.h` | `src/主调/测试选择模型.cpp`（编入 `TestLauncher` 静态库） | 用例 `#include "src/主调/测试选择模型.h"`；`EngineTestObjects` 经 `target_link_libraries(... TestLauncher)` 链接该库，且 `TestLauncher` 以 `PUBLIC` 传递「项目根 + 本层根」包含路径，故本层根相对包含 `src/主调/...` 可解析并链接到 `TestLauncher.lib` 内唯一实现副本 |
| `退出暂停判定测试` | `engine::需要等待退出` | `src/主调/退出等待判定.h`（**只放声明**） | `src/主调/主程序.cpp` 的 `namespace engine`（**非匿名命名空间**；编入 `EngineTests` 可执行目标） | 用例 `#include "src/主调/退出等待判定.h"`；实现与本用例 `.obj` 同处 `EngineTests` 一个可执行内，故链接期直接解析同名符号 |

- **为何 `需要等待退出` 的实现要放在可执行里**：头注释明确「用例直接链接可执行文件的同名符号，以保证『用例验证的判定』与『主程序实际使用的判定』是**同一份逻辑**」（详见 `Test/测试主调.md` §3.5）。代价是本目标单链接时该符号不可解析，须由 `EngineTests` 补齐。
- **包含口径**：两文件均以**本层根相对**路径包含主调头（`"src/主调/测试选择模型.h"`、`"src/主调/退出等待判定.h"`），`#include <gtest/gtest.h>` 置于文件最前（`测试选择模型测试.cpp` 第 2 行、`退出暂停判定测试.cpp` 第 2 行）。
- **无源码回退**：两套件均链接**已构建好的** `TestLauncher`/`EngineTests` 中的实现，不内联被测逻辑、不提供替身（stub）。

## 四、模块私有方法介绍

本章列出本单元内**仅在各自编译单元可见的内部函数**（4.1）与夹具形态（4.2）。夹具类型本身的形态与归属见 `Test/测试对象与夹具.md`。

### 4.1 文件级 `static` 辅助函数

仅 `测试选择模型测试.cpp` 含文件级 `static` 辅助（`退出暂停判定测试.cpp` 无辅助函数）：

| 文件 | 函数 | 签名 | 作用与关键行为 |
| --- | --- | --- | --- |
| `测试选择模型测试.cpp` | `查找套件` | `static bool 查找套件(const engine::Test_Selection_Model& 模型, const std::string& 名称, std::size_t& 序号)` | 取 `模型.suite_table_get()` 逐条比较 `name`；命中即写回下标 `序号` 并返回真，否则返回假 |
| 同上 | `找多用例套件` | `static bool 找多用例套件(const engine::Test_Selection_Model& 模型, std::size_t& 序号)` | 取套件表，返回**首个 `case_list.size() >= 2`** 的套件下标；无此套件返回假。供「逐条列出」「半选态」等需多用例套件样本的分支使用 |

> 二者为纯只读查找，不缓存、不改变模型态；被 `树中包含当前套件`、`半选态判定`、`整组取消后无半选`、`过滤串整套件压缩`、`过滤串单用例逐条列出`、`重复选择幂等` 六例取用（另 `过滤串多套件拼接`、`按前缀筛选多套件拼接` 用内联循环找样本，不复用此辅助）。

### 4.2 夹具形态

| 夹具（套件名） | 文件 | 形态 | 钩子 | 暴露面 |
| --- | --- | --- | --- | --- |
| `测试选择模型测试` | `测试选择模型测试.cpp` | 空夹具（中文类名），`class ... : public ::testing::Test {}` 类体为空 | 无 `SetUp`/`TearDown` | 无成员；用例体自行构造 `engine::Test_Selection_Model` 与勾选表 |

## 六、模块设计/实现细节

本章按用例面逐组写清覆盖意图与断言要点，是本文的核心。每份文件的夹具与辅助已在 §四/§五 说明，本节不重述。

### 6.1 反射建树与默认态（`测试选择模型测试.cpp`）

**覆盖意图**：验证 `suite_tree_build` 经 googletest 反射枚举得到的树与反射报告**计数一致**、默认全勾选、且能查到本用例所在套件；并验证套件展开态的读写。

| 用例 | 动作 | 断言要点 |
| --- | --- | --- |
| `反射建树套件数一致` | 构造模型 → `suite_tree_build()` | `suite_count() == UnitTest::GetInstance()->total_test_suite_count()` |
| `反射建树用例总数一致` | 同上 | `case_count()` 等于**逐套件 `GetTestSuite(i)->total_test_count()` 求和**（非直接用 `UnitTest::total_test_count()`；基准选取见 `【待确认：TEST-61】`）；`GetTestSuite(i)` 为空指针则跳过 |
| `默认全部勾选` | 同上 | `checked_case_count() == case_count()`；且每个套件 `suite_all_checked(i)` 为真 |
| `树中包含当前套件` | 同上 | `查找套件(模型, "测试选择模型测试", 序号)` 返回真 |
| `套件展开态读写一致` | 同上 | 默认 `suite_expanded(0)` 为假；`suite_expand_set(0, true)` 后读回真；再 `suite_expand_set(0, false)` 后读回假 |

- **建树数据源**：`suite_tree_build` 遍历 `UnitTest` 单例的套件与用例（见 `Test/测试主调.md` §3.3），故用例的期望值亦取自**同一反射单例**——即模型与期望共用同一份运行期注册表，用例只验证「模型正确搬运了反射数据」（含空指针防御跳过），并不验证注册表内容本身。
- **禁用用例是否纳入**：`suite_tree_build` 按 `TestSuite::total_test_count()`/`GetTestInfo()` 枚举（含以 `GTEST_DISABLE_` / `DISABLED_` 前缀禁用的用例），而 `RUN_ALL_TESTS` 实际只跑未禁用者；「选择树是否应有意图入禁用用例」源码与用例均未涉及，见 `【待确认：TEST-62】`。

### 6.2 勾选态、半选、批量与越界（`测试选择模型测试.cpp`）

**覆盖意图**：验证套件「全选 / 半选 / 全不选」三态、批量全选·清空·反选、越界索引的「查询为假、设置为空操作」、以及重复设置的幂等。

| 用例 | 动作 | 断言要点 |
| --- | --- | --- |
| `半选态判定` | 取多用例套件 → `case_check_set(序号, 0, false)` | `suite_all_checked` 假、`suite_half_checked` 真 |
| `整组取消后无半选` | `suite_check_set(序号, false)` | `suite_all_checked` 假、`suite_half_checked` 假 |
| `批量勾选操作` | `all_clear()` → `all_check()` → `check_invert()` | 清空后 `checked_case_count()==0`；全选后 `==case_count()`；反选后 `==0` |
| `空选择集反选后全部勾选` | `all_clear()` → `check_invert()` | `checked_case_count()==case_count()`；每个套件 `suite_all_checked` 真 |
| `重复选择幂等` | 同用例连续 `case_check_set(序号,0,true)` 两次；同套件连续 `suite_check_set(序号,true)` 两次 | 单用例重复后 `checked_case_count()==1` 且半选；整组重复后 `checked_case_count()==该套件用例数` 且全选 |
| `越界索引操作被忽略` | 取 `越界套件 = suite_count()`、`越界用例 = case_count()+1` | 三个越界查询（`suite_all_checked`/`suite_half_checked`/`suite_expanded`）均假；四个越界设置（`suite_check_set`/`suite_expand_set`/`case_check_set(越界套件,…)`/`case_check_set(0,越界用例,…)`）以 `EXPECT_NO_THROW` 包裹；操作前后 `checked_case_count()` 不变 |
| `清空后再全选恢复` | `all_clear()` → `all_check()` | 全选后 `checked_case_count()==case_count()`；每个**非空**套件 `suite_all_checked` 真（空套件 `continue` 跳过） |
| `全不选无半选态` | `all_clear()` | `checked_case_count()==0`；每个套件 `suite_all_checked` 与 `suite_half_checked` 均假 |

- **半选定义的边界**：`suite_half_checked` 在源码中要求 `0 < 已选 < 用例数`（见 `Test/测试主调.md` §3.3）；本节的「整组取消后无半选」与「全不选无半选态」即验证其两端边界（0 与全选都不算半选）。
- **越界口径**：源码对所有越界一律「查询返回假、设置直接 `return` 空操作」（另见 §三 3.3 各成员）；「越界索引操作被忽略」是**本单元唯一以 `EXPECT_NO_THROW` 断言「不崩溃」**的用例。
- `清空后再全选恢复` 对空套件显式跳过，隐含「模型可能存在空 `case_list` 套件」的前提；「空套件不应参与全选/半选判定」为源码口径（`Test/测试主调.md` §5.3）。

### 6.3 过滤串三态压缩（`测试选择模型测试.cpp`）

**覆盖意图**：验证 `filter_string_build` 的**三态压缩规则**——全不选 → `"*"`（视为全跑）、整组全选 → `套件.*`、部分勾选 → 逐条 `套件.用例`，多片段以 `':'` 连接（规则另见 `Test/测试主调.md` §6.4）。

| 用例 | 动作 | 断言要点 |
| --- | --- | --- |
| `过滤串全不选视为全跑` | `all_clear()` | `filter_string_build()=="*"` |
| `过滤串整套件压缩` | `all_clear()` → `suite_check_set(本套件, true)` | 结果 `=="测试选择模型测试.*"`（**中文套件名**参与拼接） |
| `过滤串单用例逐条列出` | 取多用例套件 → 记 `case_list[0].name` → `all_clear()` → `case_check_set(序号,0,true)` | 结果 `== 套件名 + "." + 用例名`（不加通配） |
| `过滤串多套件拼接` | 内联循环取前两个多用例套件 `甲`/`乙`，各 `case_check_set(样本,0,true)` | 结果 `== 甲.甲首:乙.乙首`（两段以 `':'` 连接） |
| `按前缀筛选多套件拼接` | `ASSERT suite_count()>=2`、前两套件 `case_list` 非空；`all_clear()` → `suite_check_set(0,true)`、`suite_check_set(1,true)` | 结果 `== 套件0名.*:套件1名.*` |

- **「全不选 = 全跑」是本模块最易误读的语义**：源码以 `checked_case_count()==0` 时直接返回 `"*"`，与 gtest 通配语义一致（`Test/测试主调.md` §6.4）。
- **样本取用依赖运行期注册表**：`过滤串整套件压缩` 与 `过滤串单用例逐条列出` 以「本用例所在套件」或「首个多用例套件」为样本；`过滤串多套件拼接`、`按前缀筛选多套件拼接` 则要求「至少两个套件且各有 ≥2 用例」，源码以 `ASSERT_TRUE`/`ASSERT_LT`/`ASSERT_GE` 兜底该前提（不满足即中断该用例）。
- **特殊字符边界**：若套件名/用例名含 `:`、`*`、`?` 等 gtest 过滤串特殊字符，直接拼接会断裂；当前依赖命名规范规避（属已知边界，见 `Test/测试主调.md` §6.4，本文不另标）。

### 6.4 控制台输入解析（`测试选择模型测试.cpp`）

**覆盖意图**：验证自由函数 `解析控制台选择` 对全选关键词、单编号、区间、混合分隔的接受，以及对非法输入（非数字、空段、区间颠倒、全空白、越界、超长数字）的拒绝与「勾选表重置为全假」的副作用。

| 用例 | 输入与套件数 | 断言要点 |
| --- | --- | --- |
| `控制台解析全选` | `"all"`、4 | 返回真；勾选表长度 4 且全真 |
| `控制台解析编号与区间` | `"1,3-5"`、6 | 返回真；勾选表 `{T,F,T,T,T,F}`（编号从 1 起，区间连续展开） |
| `控制台解析非法文本` | `"abc"`(3)、`"1,,3"`(3)、`"5-2"`(6)、`"   "`(3) | 四者均返回假（非数字 / 空段 / 区间颠倒 / 全空白） |
| `控制台解析越界编号` | `"0"`(3)、`"4"`(3)、`"2-9"`(3) | 三者均返回假（编号下界 1、上界 套件数 3） |
| `非法筛选输入重置勾选表` | 预填 `勾选表(3,true)`；依次 `"abc"`(3)、`"1,,3"`(3)、`"9999999"`(3) | 每次返回假；每次勾选表长度归位为 3；每次勾选表**被重置为全假**；`"9999999"` 命中内部防御阈值（>1000000）判非法 |
| `选择结果与输入一一对应` | `"2,4"`(5)、`"3,3"`(4)、`"4"`(4) | `"2,4"`→`{F,T,F,T,F}`；重复编号 `"3,3"`→`{F,F,T,F}`（不产生额外勾选）；`"4"` 命中末位（`勾选表[3]` 真） |

- **接受形态**：`all` / `ALL` / `a` / `*`（全选）、单编号 `3`、区间 `3-5`、逗号混合 `1,3-5`；编号**从 1 开始**，下标 = 编号 − 1（规则细节见 `Test/测试主调.md` §6.5）。
- **失败副作用**：任一段非法即整串判非法且勾选表保持/重置为全假；`非法筛选输入重置勾选表` 专门验证该副作用（传入预填全真的表，断言失败后转为全假）。
- **「全空白判非法」与菜单层的处置相反**：`解析控制台选择("   ")` 返回假（本单元 `控制台解析非法文本` 直接断言），而 `控制台选择菜单_运行` 对全空白输入**先拦截为「全选」**再调用解析函数，故经菜单路径时该用例的输入永不触达解析函数；该分层是否有意，见 `【待确认：TEST-63】`。
- **超长数字**：`"9999999"` 命中 `数字解析` 的内部上限 `1000000`（防溢出）；用例只验证「远超阈值即判非法」，未覆盖恰好等于阈值的边界，见 `【待确认：TEST-64】`。

### 6.5 退出等待判定（`退出暂停判定测试.cpp`）

**覆盖意图**：验证 `需要等待退出` 的**判定表全组合**——以「命令行带过滤」「显式选择器」「选择模式」三参构成，覆盖透传（带过滤且未显式）、`off` 关闭、显式选择器优先、未知模式兜底、大小写敏感与空模式串（判定表另见 `Test/测试主调.md` §6.6）。

| 用例 | 参数（模式, 带过滤, 显式） | 期望 |
| --- | --- | --- |
| `默认模式需要等待` | `("window", false, false)` | 真 |
| `显式窗口模式需要等待` | `("window", false, true)` | 真 |
| `显式控制台模式需要等待` | `("console", false, true)` | 真 |
| `关闭选择器不等待` | `("off", false, false)`、`("off", false, true)` | 二者均假 |
| `过滤串透传不等待` | `("window"/"console"/"off", true, false)` | 三者均假 |
| `显式选择器优先于透传` | `("window"/"console", true, true)` | 二者均真 |
| `显式选择器关闭且带过滤串不等待` | `("off", true, true)` | 假 |
| `未知模式需要等待` | `("未知模式", false, true)` | 真 |
| `未知模式带过滤串透传不等待` | `("未知模式", true, false)` | 假 |
| `未知模式显式选择仍等待` | `("未知模式", true, true)`、`("未知模式", false, true)` | 二者均真 |
| `空模式串按未知模式兜底` | `("", false, false)`、`("", false, true)`、`("", true, false)` | 真、真、假 |
| `模式大小写敏感` | `("OFF", false, true)`、`("OFF", true, false)` | 真、假（仅小写 `off` 视为关闭） |
| `重复调用判定结果幂等` | 同参数重复调用 | 两次结果相等（`EXPECT_EQ`） |
| `全参数组合与判定表一致` | 模式集合 `{window, console, off, 未知模式, ""}` × 带过滤 `{0,1}` × 显式 `{0,1}` | 期望 `= !(透传 || 关闭)`，其中 `透传 = 带过滤 && !显式`、`关闭 = (模式=="off")` |

- **判定优先级**：实现为两个早退 `return false` + 兜底 `return true`——先判透传（带过滤且未显式）、再判 `off`、其余兜底为停；用例逐条与该顺序对齐（见 `Test/测试主调.md` §6.6）。
- **全参数组合的期望基准**：末例的期望值 `!(透传 || 关闭)` 与被测实现的布尔表达式**同构**（实现的两个早退条件正是 `透传`、`关闭`），即该用例以「实现表达式」充当判定表，无法独立兜住实现变更；这是否为有意的「判定表固化」，见 `【待确认：TEST-65】`。
- **判定与动作分离**：本单元只验证**判定**（要不要停），不验证停的**动作**（`等待用户关闭窗口`，会阻塞等按键、无控制台窗口时直接返回，属 `主程序.cpp` 文件内部工具）——动作部分不可脱环境测试，故无对应用例。

### 6.6 断言口径与容错汇总

| 维度 | 结论 |
| --- | --- |
| 软/硬断言 | 查询类与拒绝类一律 `EXPECT_*`（软断言，可继续观察后续）；前置样本用 `ASSERT_TRUE`/`ASSERT_GE`/`ASSERT_LT`（如 `找多用例套件`、`suite_count()>=2`），样本缺失即中断该用例 |
| 不崩溃断言 | `越界索引操作被忽略` 以 `EXPECT_NO_THROW` 包裹四个越界设置调用（本单元唯一） |
| 精确字符断言 | 过滤串用例以 `EXPECT_EQ` 与**拼出的期望串**逐符号比对（含中文套件名与 `':'`、`"*"`） |
| 布尔表断言 | 控制台解析用例以 `EXPECT_EQ(勾选表, 期望向量)` 或逐元素循环断言 |
| 幂等断言 | `重复选择幂等`、`重复调用判定结果幂等` 以重复调用 + `EXPECT_EQ` 比对 |
| 容错 | 不抛异常、不写文件、不动全局态；无需任何环境清理 |

### 6.7 运行前提与环境依赖

| 维度 | 结论 |
| --- | --- |
| 是否需 GPU/窗口 | **否**——两套件均不建窗口、不触渲染层 |
| 是否需文件/网络 | **否**——不写临时文件、不读外部资源 |
| 是否触全局态 | **否**——不调用 `engine::logger` 或 `引擎日志屏蔽_*`（与 `Log_Test` 夹具相反） |

| 易错点 | 说明与规避 |
| --- | --- |
| 误以为「全不选 = 一条不跑」 | `filter_string_build` 在全不选时返回 `"*"`，语义为**全跑**（§6.3） |

## 七、模块运行链路详例

调用方为 `EngineTests` 的 gtest 执行器；本单元无外部调用者。

### 7.1 单个用例生命周期（以建树类用例为例）

1. gtest 命中一条 `TEST_F(测试选择模型测试, ...)` → **构造空夹具实例**（无钩子、无成员）。
2. 用例体：`engine::Test_Selection_Model 模型;`（栈上构造，`suite_table_` 为空）→ `模型.suite_tree_build()`。
3. `suite_tree_build` 取 `UnitTest::GetInstance()`，遍历反射套件/用例填 `suite_table_`（默认全勾选，空指针跳过）。
4. 用例体 `EXPECT_*` 断言计数/态（或调 `查找套件`/`找多用例套件` 取样本后再操作）。
5. 无 `TearDown`；析构夹具、析构模型（`std::vector` 成员随之释放），进入下一条用例。

### 7.2 过滤串生成链路（`测试选择模型测试`）

1. 建树 → `all_clear()`（或按需勾选）→ 调 `suite_check_set`/`case_check_set` 设定勾选态。
2. `filter_string_build()`：若 `checked_case_count()==0` 直接返回 `"*"`；否则逐套件统计已选数，整组全选推 `套件.*`、部分勾选逐条推 `套件.用例`、未选跳过；最后以 `':'` 连接。
3. 用例 `EXPECT_EQ(filter_string_build(), 期望串)`（期望串由套件名 + `"."` + 用例名（或 `".*"`）按同规则就地拼出）。

### 7.3 控制台解析链路（`测试选择模型测试`）

1. 用例准备 `std::vector<bool> 勾选表`（可预填全真以观察重置副作用）。
2. `解析控制台选择(输入, 套件数, 勾选表)`：先 `assign(套件数, false)` → 去首尾空白（全空白即返假）→ 判全选关键词 → 否则按 `','` 切段，逐段判区间/单编号、校验下界 1 与上界套件数、命中即置位。
3. 合法即返真（勾选表按下标置位）；非法即返假（勾选表已被重置为全假）。
4. 用例以 `EXPECT_TRUE/EXPECT_FALSE` + `EXPECT_EQ(勾选表, 期望)` 断言。

### 7.4 退出等待判定链路（`退出暂停判定测试`）

1. 用例直接以三参调用 `engine::需要等待退出`（符号解析自同一可执行内的 `主程序.cpp` 实现）。
2. 函数执行：`if (命令行带过滤 && !显式选择器) return false;` → `if (选择模式 == "off") return false;` → `return true;`。
3. 用例 `EXPECT_TRUE/EXPECT_FALSE/EXPECT_EQ` 断言；全参数组合末例以双层循环遍历 5×2×2 组合，逐组与 `!(透传 || 关闭)` 比对。

### 7.5 边界分支汇总表

| 场景 | 触发点 | 处理 | 结果 |
| --- | --- | --- | --- |
| 全不选后生成过滤串 | `filter_string_build` | 返回 `"*"` | 全跑（§6.3） |
| 某套件恰好全选 | `filter_string_build` | 压缩为 `套件.*` | 前缀通配（§6.3） |
| 越界套件/用例查询 | `suite_all_checked` 等 | 返回假 | 断言为假（§6.2） |
| 越界套件/用例设置 | `suite_check_set` 等 | 直接 `return`（空操作） | `EXPECT_NO_THROW`；勾选总数不变（§6.2） |
| 整组取消 | `suite_check_set(…, false)` | 全不选 | 全选与半选均假（§6.2） |
| 解析输入为空段/非数字/区间颠倒 | `解析控制台选择` | 判非法、勾选表重置全假 | 用例断言假（§6.4） |
| 解析输入编号越界 | 同上 | 判非法 | 用例断言假（§6.4） |
| 解析输入全空白 | 同上 | 判非法（菜单层会先拦截为全选） | 用例断言假（§6.4、TEST-63） |
| 解析输入超长数字 | `数字解析` 上限 1000000 | 判非法 | 用例断言假（§6.4、TEST-64） |
| 带过滤且未显式选择器 | `需要等待退出` 首早退 | 返回假 | 不等待（§6.5） |
| 选择模式为 `off` | 第二早退 | 返回假 | 不等待（§6.5） |
| 未知模式 / 空模式串 | 兜底 | 返回真 | 等待（§6.5） |
| `OFF` 大写 | 不等于 `off` | 按未知模式兜底 | 等待（§6.5） |
| 显式选择器 + 带过滤 | 首早退不成立 | 落兜底 | 等待（§6.5） |
