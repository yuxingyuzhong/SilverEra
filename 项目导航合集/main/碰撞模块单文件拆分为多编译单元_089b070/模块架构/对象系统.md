## 一、模块功能（该模块做什么，解决什么问题，在引擎中的定位）

### 1.1 模块定位

对象系统（Object System）是「白银纪元」游戏引擎引擎层（`engine` 命名空间）的**核心对象管理基础设施**。它位于 `引擎层\src\core\object\` 目录下，为引擎内部各模块提供一套**统一的对象生命周期管理机制**：对象 ID 的分配与回收、对象有效性标记、按 ID 快速索引查找、按任意投影字段排序后二分查找，以及对象批量卸载与整体清空。

在引擎的分层结构中，对象系统属于 `core`（核心层）的组成部分，其依赖方向遵循"核心层可依赖工具层、不可依赖业务模块"的原则：

- **上游依赖（被对象系统依赖）**：工具层（`src\tools\`）的数值分配器 `Number_Allocator`（用于 ID 与索引的分配回收）、二分查找算法 `binary_search`（用于排序模式的对象定位）、日志系统 `Log`（用于错误/警告输出）、标准库容器（`std::vector`、`std::unordered_map`、`std::optional`、`std::function`）与标准库算法（`std::ranges::sort` 等）。
- **下游消费方（依赖对象系统）**：碰撞模块的碰撞空间（Collision_Space）与碰撞体对象（Collision_Object 等）均派生自 `engine::Object`，由 `Object_Pool` 统一管理；未来任何需要"ID 化对象 + 快速查找"的模块（渲染、逻辑实体、音频源等）都可复用。

### 1.2 解决的核心问题

在没有对象系统的情况下，模块各自管理对象会产生以下问题：

1. **ID 重复与浪费**：手动分配对象 ID 容易重复或漏回收，导致查找错乱。
2. **查找性能不可控**：线性扫描 `std::vector` 找对象，在对象数量较大时性能差；且无法同时满足"按 ID 快速命中"与"按业务字段排序遍历"两种诉求。
3. **无效对象残留**：对象被销毁后若仅标记删除而不回收，容器中堆积"幽灵对象"，遍历时需反复判空。
4. **回收语义不统一**：每个模块各自实现一套"复用槽位"逻辑，代码重复且易错。

对象系统通过两层设计解决上述问题：

- **`Object`（对象基类）**：定义所有可被对象池管理的对象的公共基座——对象 ID（`object_ID`）与合法性标记（`is_valid`），并提供 `ID_set` / `valid_set` / `ID` / `valid` 四个访问器。任何要进对象池的类型必须派生自 `Object`（模板约束强制）。
- **`Object_Pool<T, Key>`（对象池模板）**：以 `std::vector<T>` 为物理存储，配合两个 `Number_Allocator`（ID 分配器、索引分配器）实现槽位复用；内部通过一个 **union 双模式设计**在同一块存储上切换两种索引策略：
  - **稳定模式（默认）**：用 `std::unordered_map<uint64_t, uint64_t>` 建立"对象 ID → 容器索引"映射，`find` 为 O(1) 查表；对象在容器中的物理顺序稳定（不因增删而移动其他对象）。
  - **排序模式**：用户通过 `sort_order_set` 指定投影字段与升降序后，对象按投影值有序排列，`find` 退化为 O(log n) 二分查找；非法（已卸载）对象被统一挪到容器前端，`min_valid_index` 记录有效区索引起点，避免二分查找区间混入无效对象。

### 1.3 与其他核心模块的协同

- **数值分配器 `Number_Allocator`（`src\tools\Number_Allocator\数值分配器.h`）**：对象池持有两个分配器实例——`ID_allocator` 负责对象 ID 的分配与回收，`index_allocator` 负责容器索引槽位的分配与回收。`ID_allocator.set(1)` 在构造函数中执行，**预留 ID 0 作为"非法/无效实体"专用 ID**（`unload` 时对象 ID 会被重置为 0，见 4.6）。`build` 从 `index_allocator.get()` 取槽位、从 `ID_allocator.get()` 取 ID；`unload` 分别 `recycle` 两者。
- **二分查找 `binary_search`（`src\tools\Auxi_Algorithm\二分查找.h`）**：排序模式下 `find` 调用 `engine::binary_search(begin + min_valid_index, end, key, less/greater, projector)`，该算法返回**相对于传入 `first` 的相对索引**，失败返回 -1；对象池据此换算全局迭代器（`begin + min_valid_index + index`）。
- **日志系统 `Log`（`src\tools\Logging\日志系统.h`）**：排序模式下用非整型 `Key` 在未排序池中查找时输出 `Log::error("Object_Pool::当前对象池未排序\n无法使用ID以外字段查找目标对象")`；`unload` 目标不存在时输出 `Log::warn("Object_Pool::目标对象不存在")`。

### 1.4 设计要点总览（本版次 089b070）

1. **模板约束**：`template <typename T, typename Key = uint64_t> requires std::is_base_of_v<Object, T>`——编译期强制 T 派生自 `Object`，保证 `ID()` / `valid()` / `ID_set()` / `valid_set()` 四个接口可用。
2. **union 双模式**：稳定模式（`unordered_map` 索引）与排序模式（投影 + 二分查找）共享同一块存储，通过 `is_sorted` 布尔标记分派；union 成员含非平凡类型，构造/析构/切换模式均使用 **placement new 与显式析构**管理生命周期（见 4.1）。
3. **min_valid_index 机制**：排序模式下，容器前端连续存放无效（已卸载）对象，`std::optional<uint64_t> min_valid_index` 记录第一个有效对象的下标；排序、查找、卸载均以它为界（见 4.4）。
4. **卸载回收语义**：`unload` 回收对象 ID 与索引槽位，并把对象 `ID_set(0)` + `valid_set(false)`；稳定模式下同步擦除索引映射，排序模式下将无效对象与前端元素交换并推进 `min_valid_index`（见 4.6）。
5. **显式实例化**：`Object_Pool/core/对象池实例化.cpp` 中 `template class Object_Pool<Object>;` 为基类类型显式实例化，供需要"通用对象池"的场景直接链接（见 4.8）。

## 二、模块提供接口（完整公开接口清单）

> 说明：以下接口签名全部摘自 089b070 版次源码（`引擎层\src\core\object\` 目录），方法名、参数类型、返回值、const 修饰与源码严格一致。参数名仅作语义说明。

### 2.1 `Object` 类（`Object\对象.h`）

`engine::Object` 是对象池管理的公共基类，源码如下：

```cpp
namespace engine
{
	//对象
	class Object
	{
	protected:
		//对象ID
		uint64_t object_ID = 0;
		//合法标记
		bool is_valid = false;
	public:
		//ID设置
		void ID_set(const uint64_t& ID)
		{
			//设置对象ID
			this->object_ID = ID;
		}
		//对象有效性设置
		void valid_set(bool valid)
		{
			this->is_valid = valid;
		}
		//ID获取
		uint64_t ID(void) const
		{
			return this->object_ID;
		}
		//对象有效性获取
		bool valid(void)
		{
			return is_valid;
		}
	};
}
```

#### 2.1.1 成员字段语义

| 成员 | 类型 | 初始值 | 语义 |
| --- | --- | --- | --- |
| `object_ID` | `uint64_t` | `0` | 对象唯一 ID。默认 0；由对象池 `build` 时经 `ID_allocator.get()` 分配；`unload` 时回收并重置为 0（非法 ID 约定）。受 `protected` 保护，仅派生类可直接访问。 |
| `is_valid` | `bool` | `false` | 合法性标记。默认 false（构造出的裸对象无效）；`build` 成功后被 `valid_set(true)`；`unload` 后被 `valid_set(false)`。 |

#### 2.1.2 公开方法逐一说明

- **`void ID_set(const uint64_t& ID)`**：
  - 参数 `ID`：要写入的对象 ID。
  - 返回值：无。
  - 行为：将 `object_ID` 置为传入值。对象池内部在 `build`（分配新 ID）与 `unload`（重置为 0）时调用；外部模块一般不直接调用，以免破坏 ID 唯一性。

- **`void valid_set(bool valid)`**：
  - 参数 `valid`：合法性布尔值。
  - 返回值：无。
  - 行为：将 `is_valid` 置为传入值。对象池在 `build` 后置 true、`unload` 后置 false；外部模块可在自定义业务逻辑中按需标记。

- **`uint64_t ID(void) const`**：
  - 参数：无。
  - 返回值：当前对象 ID（`object_ID`）。
  - 行为：常量访问器，供对象池索引映射、排序投影（如按 ID 排序）、外部查询使用。**const 修饰**，可对 const 对象调用。

- **`bool valid(void)`**：
  - 参数：无。
  - 返回值：当前合法性标记（`is_valid`）。
  - 行为：查询对象是否有效。注意：**该方法未加 const 修饰**（与 `ID()` 不同），const 对象上不可调用 `valid()`；对象池在排序模式的初始化扫描（4.4）中调用它区分有效/无效对象。

### 2.2 `Object_Pool<T, Key>` 模板（`Object_Pool\对象池.h`）

模板声明与公开接口骨架（与源码严格一致）：

```cpp
namespace engine
{
	//对象池 —— 模板需从对象中派生
	template <typename T, typename Key = uint64_t>
		requires std::is_base_of_v<Object, T>
	class Object_Pool
	{
	private:
		//ID分配器
		Number_Allocator ID_allocator;
		//索引分配器
		Number_Allocator index_allocator;

		//对象集合
		std::vector<T> objects;
		//对象池排序标记
		bool is_sorted = false;
		//对象池管理信息
		union
		{
			//对象索引映射
			std::unordered_map<uint64_t, uint64_t> object_index_map;
			//排序定位信息
			struct
			{
				//投影字段
				std::function<Key(const T&)> projector;  
				//比较方式(默认降序)
				bool is_greater;
				//有效索引起点
				std::optional<uint64_t> min_valid_index;
			};
		};

	public:
		//构造函数
		Object_Pool();
		//析构函数
		~Object_Pool();
		//对象排列方式设置
		template <typename Projection>
		void sort_order_set(bool greater, Projection proj);
		//对象排列方式重置
		void sort_order_reset(void);
		//对象查找
		typename std::vector<T>::iterator find(const Key& key);
		//对象添加
		uint64_t build(void);
		//对象卸载 —— 单对象重载
		void unload(const Key& key);
		//对象卸载 —— 多对象重载
		void unload(const std::vector<Key>& keys);
		//对象清除
		void clear(void);
		//全部对象获取
		std::vector<T>& data(void);
		//超尾迭代器获取
		typename std::vector<T>::iterator end(void);
	};
}
```

**模板参数**：
- `T`：对象类型，**必须派生自 `engine::Object`**（`requires std::is_base_of_v<Object, T>` 编译期约束，不满足则编译失败）。
- `Key`：查找键类型，默认 `uint64_t`（即对象 ID）。`Key` 可以是任意类型（如 `std::string` 业务字段），但**只有整型 `Key` 才能在稳定模式下用 ID 映射查找**；非整型 `Key` 必须先进入排序模式（见 4.5）。

#### 2.2.1 `Object_Pool()` —— 构造函数

- 签名：`Object_Pool();`
- 参数：无。
- 返回值：无。
- 行为：
  1. 以 **placement new** 在 union 的 `object_index_map` 槽位上默认构造 `std::unordered_map<uint64_t, uint64_t>()`（进入稳定模式）。
  2. 调用 `ID_allocator.set(1)`：**预留 ID 0 为非法实体 ID**，使 `build` 分配到的第一个 ID 从 1 开始，0 永远保留给"已卸载/无效"对象使用。

#### 2.2.2 `~Object_Pool()` —— 析构函数

- 签名：`~Object_Pool();`
- 参数：无。
- 返回值：无。
- 行为：根据 `is_sorted` 分派析构 union 中的活跃成员，避免非平凡类型析构遗漏：
  - `is_sorted == false`（稳定模式）：显式调用 `object_index_map.~unordered_map()`。
  - `is_sorted == true`（排序模式）：显式调用 `projector.~function()`。
  - 注意：排序模式下 `is_greater`（bool）与 `min_valid_index`（`std::optional<uint64_t>`）未显式析构。`is_greater` 是平凡类型无需析构；`min_valid_index` 作为 struct 成员会随 struct 生命周期自动析构（union 的析构由最外层 `objects` 等成员驱动时，struct 成员的析构由编译器按常规规则处理——这是当前实现的既有细节）。

#### 2.2.3 `sort_order_set` —— 对象排列方式设置

- 签名：`template <typename Projection> void sort_order_set(bool greater, Projection proj);`
- 参数：
  - `greater`：比较方式标记，`true` 表示降序，`false` 表示升序（源码注释称"默认降序"，但实际以传入值为准）。
  - `proj`：投影函数/可调用对象，类型 `Projection`，签名须满足 `Key(const T&)`（如 `[](const T& o){ return o.ID(); }`），被包装进 `std::function<Key(const T&)> projector`。
- 返回值：无。
- 行为（完整流程）：
  1. **首次进入排序模式**（`is_sorted == false`）：置 `is_sorted = true`；显式析构 union 中的 `object_index_map`；以 placement new 依次构造 `projector`（包装 `proj`）、`is_greater`（初值 false）、`min_valid_index`（初值无值）。
  2. **重复调用**（`is_sorted == true`）：仅更新 `projector = proj`（`is_greater` 与 `min_valid_index` 保留）。
  3. **计算有效索引起点**（仅当 `min_valid_index` 无值）：
     - 先按 ID **升序** `std::ranges::sort(objects, std::ranges::less(), [](const T& o){ return o.ID(); })`——注意此时按 ID 排，目的不是业务序，而是**把无效对象（`valid()==false`）集中到容器前端**（无效对象 ID 已被重置为 0，ID 最小）。
     - 从头扫描 `objects`，找到第一个 `valid()` 为 true 的下标记为 `min_valid_index`；扫描途中所有无效下标调用 `index_allocator.recycle(filter_index)` **回收为可用索引槽位**。
     - 若整个容器无有效对象，`min_valid_index = objects.size()`（有效区为空）。
  4. **记录比较方式**：`is_greater = greater;`
  5. **按投影重排有效区**：对 `[objects.begin() + min_valid_index, objects.end())` 区间，按 `proj` 做 `std::ranges::sort`（`is_greater` 为 false 用 `std::ranges::less()`，否则用 `std::ranges::greater()`）。无效对象保持在区间外的前端，不参与业务排序。

#### 2.2.4 `sort_order_reset` —— 对象排列方式重置

- 签名：`void sort_order_reset(void);`
- 参数：无。
- 返回值：无。
- 行为：
  1. 若当前已是稳定模式（`is_sorted == false`）：直接返回，不做任何事（幂等）。
  2. 若当前是排序模式：显式析构 `projector`（`projector.~function()`）与 `min_valid_index`（`min_valid_index.~optional()`）；以 placement new 重新构造空 `object_index_map`；遍历 `objects`，把所有 `valid()` 的对象按 `{ ID(), index }` 插入映射；置 `is_sorted = false`，回到稳定模式。

#### 2.2.5 `find` —— 对象查找

- 签名：`typename std::vector<T>::iterator find(const Key& key);`
- 参数：`key`：查找键。整型 `Key` 时通常是对象 ID；非整型 `Key` 时为投影字段值。
- 返回值：命中返回指向目标对象的迭代器；未命中返回 `end()`（超尾迭代器）。
- 行为（`if constexpr` 编译期分派，两套逻辑）：
  - **`Key` 为整型**（`std::is_integral_v<Key>` 为 true）：
    - 稳定模式：`object_index_map.find(key)`，命中返回 `objects.begin() + it->second`，未命中返回 `objects.end()`。O(1)。
    - 排序模式：以 `min_valid_index` 为起点调用 `binary_search(objects.begin() + min_valid_index.value(), objects.end(), key, std::ranges::less()/greater(), projector)`；返回的相对索引 ≥ 0 时换算为 `objects.begin() + min_valid_index.value() + index`，否则 `objects.end()`。O(log n)。
  - **`Key` 非整型**：
    - 稳定模式：`Log::error("Object_Pool::当前对象池未排序\n无法使用ID以外字段查找目标对象")` 并返回 `objects.end()`（**禁止未排序按非 ID 字段查找**）。
    - 排序模式：与整型 Key 的排序分支相同，用 `projector` 投影后二分。

#### 2.2.6 `build` —— 对象添加

- 签名：`uint64_t build(void);`
- 参数：无。
- 返回值：新对象的对象 ID（`uint64_t`）；ID 由 `ID_allocator.get()` 分配，稳定模式下首个 ID 为 1（因构造时 `set(1)`）。
- 行为（完整流程）：
  1. `uint64_t index = index_allocator.get();`——取一个可用索引槽位（优先复用回收槽，否则新分配递增下标）。
  2. 若 `index >= objects.size()`：`objects.push_back({})` 扩容（T 需默认构造）。
  3. 若处于排序模式且 `index == min_valid_index.value() - 1`：`min_valid_index.value()--`（新对象插入到有效区前端边界时，有效区起点前移一位，覆盖被回收的前端无效槽）。
  4. `auto& new_object = objects[index]; new_object = T{};`——**整体重置**，避免复用槽位上的旧数据残留。
  5. `new_object.ID_set(ID_allocator.get());`——分配新 ID。
  6. `new_object.valid_set(true);`——标记有效。
  7. 稳定模式：`object_index_map.insert({ new_object.ID(), index });`。
  8. 排序模式：对有效区 `[begin + min_valid_index, end)` 按当前投影/比较方式重新 `std::ranges::sort`，维持有序性。
  9. 返回 `new_object.ID()`。

#### 2.2.7 `unload` —— 对象卸载（单对象重载）

- 签名：`void unload(const Key& key);`
- 参数：`key`：要卸载对象的查找键（通常为对象 ID）。
- 返回值：无（void；目标不存在时仅打警告）。
- 行为（完整流程）：
  1. `auto it = find(key);`——按当前模式查找。
  2. 若 `it == objects.end()`：`Log::warn("Object_Pool::目标对象不存在");` 直接返回。
  3. 否则：
     - `uint64_t target_index = it - objects.begin();`——记录容器下标。
     - `uint64_t ID = it->ID();`——记录待回收 ID。
     - `ID_allocator.recycle(ID);`——**回收对象 ID**（后续 `build` 可复用该 ID）。
     - `it->ID_set(0);`——**将对象 ID 重置为 0**（非法实体 ID，配合构造时的 `set(1)` 预留约定）。
     - `objects[target_index].valid_set(false);`——标记无效。
     - 稳定模式：`object_index_map.erase(ID);`（擦除 ID→索引映射）；`index_allocator.recycle(target_index);`（回收索引槽位）。
     - 排序模式：`std::swap(objects[min_valid_index.value()], objects[target_index]);`（把刚卸载的无效对象与有效区前端元素交换，使无效对象回到前端连续区）；`index_allocator.recycle(min_valid_index.value());`（回收前端槽位）；`min_valid_index.value()++;`（有效区起点后移一位）。

#### 2.2.8 `unload` —— 对象卸载（多对象重载）

- 签名：`void unload(const std::vector<Key>& keys);`
- 参数：`keys`：待卸载对象的键集合。
- 返回值：无。
- 行为：顺序遍历 `keys`，逐个调用单对象重载 `unload(key)`。注意：批量卸载会多次触发排序模式的 `swap` 与重排，性能敏感场景需评估；且键集合中重复键第二次会命中"目标对象不存在"警告分支。

#### 2.2.9 `clear` —— 对象清除

- 签名：`void clear(void);`
- 参数：无。
- 返回值：无。
- 行为：
  1. `objects.clear();`——清空全部对象。
  2. `ID_allocator.reset();`——ID 分配器重置（`next_number = 0`，清空回收集合）。
  3. `index_allocator.reset();`——索引分配器重置。
  4. 稳定模式：`object_index_map.clear();`。
  5. 排序模式：`projector = {};`（清空投影）；`is_greater = false;`；`min_valid_index = 0;`（**直接赋 0 而非 reset**，optional 变为有值 0）。
  - 注意：`clear` 后对象池仍保持当前模式（`is_sorted` 不变）；排序模式下 `min_valid_index` 有值 0，而 `objects.size()` 为 0，二者一致（空有效区）。

#### 2.2.10 `data` —— 全部对象获取

- 签名：`std::vector<T>& data(void);`
- 参数：无。
- 返回值：内部对象容器的**非 const 引用**（`std::vector<T>&`）。
- 行为：直接暴露底层容器。调用方可通过它遍历/修改全部对象（含无效对象）。注意：**直接修改容器（如 push_back/erase/sort）会破坏对象池的索引一致性**，正常业务应只用 `build` / `unload` / `find`；`data` 主要用于只读遍历或外部接管场景。

#### 2.2.11 `end` —— 超尾迭代器获取

- 签名：`typename std::vector<T>::iterator end(void);`
- 参数：无。
- 返回值：`objects.end()`。
- 行为：与 `find` 的"未命中返回 end()"约定配合，供范围 for / `std::find` 等使用。注意返回的是 `iterator` 而非 `const_iterator`。

### 2.3 依赖工具接口（对象系统依赖的 `src\tools\` 模块，简要）

对象系统自身接口已在上文列全，此处仅列出其直接依赖的工具接口，供理解协作（完整说明见各自模块文档）：

- **`Number_Allocator`**（`src\tools\Number_Allocator\数值分配器.h`）：
  - `void set(const uint64_t& min_allocate_number);`——设置分配起点（对象池用 `set(1)` 预留 ID 0）。
  - `uint64_t get(void);`——取一个可用数值：优先弹回收集合末尾（LIFO），否则返回 `next_number++`。
  - `bool recycle(const uint64_t& recycle_number);`——回收数值：先二分查重（重复则 `Log::warn` 并返回 false），再 push_back + 排序。
  - `void recycle(const std::vector<uint64_t>&);`——批量回收。
  - `void reset(void);`——重置分配器。
- **`binary_search`**（`src\tools\Auxi_Algorithm\二分查找.h`）：
  - `template<typename RandomIt, typename T, typename Compare, typename Projection = std::identity> int binary_search(RandomIt first, RandomIt last, const T& target, const Compare& comp, Projection proj = {});`——在 `[first, last)` 上二分查找 `target`（用 `comp` 比较、`proj` 投影），返回**相对于 `first` 的索引**，失败返回 -1。

### 3.4 union 双模式设计（内部架构核心）

`Object_Pool` 内部使用一个**匿名 union** 在同一块存储上承载两种互斥的索引策略：

```cpp
union
{
    std::unordered_map<uint64_t, uint64_t> object_index_map;   // 稳定模式索引
    struct                                                  // 排序模式定位信息
    {
        std::function<Key(const T&)> projector;
        bool is_greater;
        std::optional<uint64_t> min_valid_index;
    };
};
```

设计要点：

1. **空间复用**：两种策略不会同时使用，union 使对象池只占其中较大者（排序模式 struct）的空间，节省一个 `unordered_map` 常驻内存。
2. **模式互斥**：`is_sorted` 布尔标记决定当前活跃成员——`false` 用 `object_index_map`，`true` 用 struct 三字段。
3. **非平凡类型管理**：`std::unordered_map`、`std::function`、`std::optional` 均是非平凡类型，直接对 union 成员赋值/读取会造成生命周期错乱，因此源码在所有模式切换点使用 **placement new（`new (&member) Type(...)`）构造、显式析构（`member.~Type()`）销毁**：
   - 构造函数：`new (&object_index_map) std::unordered_map<uint64_t, uint64_t>();`
   - 析构函数：按 `is_sorted` 显式析构 `object_index_map` 或 `projector`。
   - `sort_order_set`（稳定→排序）：`object_index_map.~unordered_map();` → `new (&projector) std::function<Key(const T&)>(proj); new (&is_greater) bool(false); new (&min_valid_index) std::optional<uint64_t>();`
   - `sort_order_reset`（排序→稳定）：`projector.~function(); min_valid_index.~optional();` → `new (&object_index_map) std::unordered_map<uint64_t, uint64_t>();`
4. **排序模式 struct 内部三字段分工**：
   - `projector`：把对象映射为查找/排序键（如 `[](const T& o){ return o.ID(); }` 或业务字段投影）。
   - `is_greater`：排序方向（true 降序 / false 升序），`find` 时决定二分比较器。
   - `min_valid_index`：有效区起点；排序、二分、卸载全部以它为界（详见 4.4）。

### 3.5 设计分层

- **第 0 层（工具层 `src\tools\`）**：`Number_Allocator`、`binary_search`、`Log`——无业务语义的通用工具。
- **第 1 层（核心层 `src\core\object\`）**：`Object` 基类 + `Object_Pool` 模板——只依赖工具层与标准库，不依赖任何业务模块。
- **第 2 层（业务模块，如碰撞模块）**：派生 `Object` 的碰撞对象类型 + 实例化 `Object_Pool`，通过 `build` / `find` / `unload` 管理对象。

依赖方向单向向下，符合核心层不反向依赖业务层的分层纪律。

## 四、模块设计/实现细节（关键算法流程、边界情况处理、设计决策及其原因、权限机制、订阅/发布机制细节、与其它模块的协作细节、易踩坑点）

### 4.1 稳定模式（unordered_map 索引）详解

**适用场景**：对象数量中等、增删频繁、查找以对象 ID 为主、且需要对象在容器中的物理顺序稳定（例如遍历顺序与创建顺序一致）。

**数据结构**：`std::unordered_map<uint64_t, uint64_t> object_index_map`，键为对象 ID，值为 `objects` 容器下标。

**关键流程**：

- `build`：`index = index_allocator.get()` → 必要时 `push_back` → `objects[index] = T{}` → `ID_set(ID_allocator.get())` → `valid_set(true)` → `object_index_map.insert({ ID, index })`。
- `find`：`object_index_map.find(key)` → 命中返回 `objects.begin() + it->second`。
- `unload`：`ID_allocator.recycle(ID)` → `ID_set(0)` → `valid_set(false)` → `object_index_map.erase(ID)` → `index_allocator.recycle(target_index)`。

**优点**：查找 O(1)；卸载不移动其他对象（物理顺序稳定）；槽位复用（`index_allocator` 回收 + 再分配），`std::vector` 不会无限膨胀。

**代价**：`unordered_map` 有哈希表内存开销；**对象物理顺序与 ID 顺序无关**（复用槽位导致新对象占据旧对象位置）；无法按业务字段范围查询。

**边界情况**：
- `find` 未命中返回 `end()`，调用方需判等。
- 卸载后立刻 `build`：`index_allocator.get()` 优先返回刚回收的末尾槽（LIFO），新对象会顶替刚卸载对象的位置，映射同步更新，语义正确。

### 4.2 排序模式（二分查找）详解

**适用场景**：对象数量大、需要按业务字段（如排序键）快速定位、或需要按序遍历对象（如渲染排序）。

**数据结构**：struct 三字段（`projector` / `is_greater` / `min_valid_index`），有效区 `[min_valid_index, objects.size())` 内对象按 `projector` 投影值有序（升/降由 `is_greater` 决定）。

**关键流程**：

- 进入排序模式（`sort_order_set` 首次调用）：
  1. 析构 `object_index_map`，placement new 构造三字段。
  2. 按 ID 升序对**全部**对象排序（把无效对象 ID=0 集中到前端）。
  3. 扫描定位第一个有效对象下标 → `min_valid_index`；途中无效下标全部 `index_allocator.recycle`。
  4. 对有效区按 `proj` 排序（less/greater）。
- `build`：复用/新分配索引 → 若 `index == min_valid_index - 1` 则 `min_valid_index--` → 重置对象、分配 ID、置有效 → 对有效区重排序。
- `find`：`binary_search(begin + min_valid_index, end, key, comp, projector)` → 相对索引 ≥ 0 则换算为全局迭代器。
- `unload`：找到目标 → 回收 ID、`ID_set(0)`、`valid_set(false)` → `swap(objects[min_valid_index], objects[target_index])` → 回收前端索引 → `min_valid_index++`。

**优点**：查找 O(log n)；支持任意投影字段（整型/非整型 Key）；按序遍历天然有序。

**代价**：每次 `build` 后需重排序（O(n log n)），高频增删场景性能退化；`find` 依赖投影值唯一性（投影值重复时二分命中任意一个，语义不保证）；非整型 Key 在稳定模式下不可查找。

**边界情况**：
- 有效区为空（`min_valid_index == objects.size()`）：二分区间为空，`binary_search` 返回 -1，`find` 返回 `end()`，正确。
- 投影值重复：二分可能命中任意重复元素；如需全部命中需用 `range_binary_search`（对象池未使用）。
- 排序模式 `build` 时 `index == min_valid_index.value() - 1` 的判断：`min_valid_index` 为 0 时 `0 - 1` 下溢为 `UINT64_MAX`，而 `index` 恒小于 `objects.size()`，不会相等，判断安全（不会误触发）。

### 4.3 `is_sorted` 与模式切换的不变量

对象池通过 `is_sorted` 维护以下**不变量**（重开发时务必保持）：

| 模式 | `is_sorted` | 活跃 union 成员 | 不变量 |
| --- | --- | --- | --- |
| 稳定模式 | false | `object_index_map` | 映射键 = 全部有效对象 ID；映射值 = 对象在 `objects` 中的下标；`objects` 中无效对象位置任意 |
| 排序模式 | true | struct 三字段 | `[0, min_valid_index)` 全为无效对象；`[min_valid_index, size)` 全为有效对象且按投影有序；`index_allocator` 已回收 `[0, min_valid_index)` 全部下标 |

模式切换必须同时维护两端不变量：

- `sort_order_set`（稳定→排序）：先按 ID 升序排全容器（保证无效对象前端聚集）→ 扫描回收无效下标 → 确定 `min_valid_index` → 重排有效区。
- `sort_order_reset`（排序→稳定）：析构排序字段 → 重建映射（只插入有效对象）→ 置回稳定模式。

### 4.4 `min_valid_index` 机制（排序模式核心）

**作用**：排序模式下唯一标记"有效对象区间起点"的字段，同时服务四个操作：

1. **排序边界**：`sort_order_set` / `build` 后的 `std::ranges::sort` 只作用于 `[begin + min_valid_index, end)`，无效对象（前端区）不参与业务排序。
2. **查找边界**：`find` 的二分区间从 `begin + min_valid_index` 开始，避免把无效对象（其投影字段可能是残留旧值）纳入二分，保证有序性假设成立。
3. **卸载回收**：`unload` 把目标对象与 `objects[min_valid_index]` 交换，回收的是 `min_valid_index` 槽位，然后 `min_valid_index++`——无效区整体"右扩一格"。
4. **构建前移**：`build` 时若分配的索引恰好是有效区前端（`index == min_valid_index - 1`，即回收槽顶替了刚卸载的前端槽），则 `min_valid_index--`——有效区"左缩一格"，保持"新对象进入有效区"的正确性。

**初始化时机**：仅在 `sort_order_set` 首次调用且 `min_valid_index` 无值时计算一次；此后 `build` / `unload` 以增量方式维护，不再全量重扫。

**为什么用 `std::optional`**：区分"尚未初始化"（无值，需要全量扫描建立）与"已初始化"（有值，增量维护）。`sort_order_reset` 会析构它，再次 `sort_order_set` 时重新计算。

**潜在注意点**：`clear()` 后排序模式 `min_valid_index = 0`（有值），若之后不再调用 `sort_order_set` 而直接 `build`，`build` 的 `index == min_valid_index - 1` 判断在 `min_valid_index == 0` 时不会误触发（见 4.2 边界），随后重排序区间 `[0, size)` 正确。行为自洽。

### 4.5 `find` 的编译期分派（`if constexpr`）

`find` 用 `if constexpr (std::is_integral_v<Key>)` 在编译期分流，避免运行时开销：

- **整型 Key**（默认 `uint64_t`）：
  - 稳定模式：走 `unordered_map` 查表。
  - 排序模式：走二分。
- **非整型 Key**（如 `std::string`）：
  - 稳定模式：**直接报错拒绝**——`Log::error("Object_Pool::当前对象池未排序\n无法使用ID以外字段查找目标对象")` 并返回 `end()`。设计原因：稳定模式的映射键固定为 `uint64_t`（对象 ID），无法用非整型键查表；与其静默返回错误结果，不如明确报错。
  - 排序模式：走二分（投影函数输出非整型键）。

**易踩坑**：使用非整型 `Key`（如 `Key = std::string`）时，若忘记先调用 `sort_order_set`，`find` 不会崩溃但会打 ERROR 日志并返回 `end()`，业务可能静默丢失对象——排查时注意看日志。

### 4.6 卸载回收语义（unload 的三重清理 + ID 归零约定）

`unload` 的语义比"删除"更精细，共执行**三重清理**：

1. **ID 回收**：`ID_allocator.recycle(ID)`——对象 ID 归还分配器，后续 `build` 可复用（ID 复用！）。
2. **ID 归零**：`it->ID_set(0)`——对象自身 ID 置 0。
3. **索引回收**：
   - 稳定模式：`object_index_map.erase(ID)`（映射清除）+ `index_allocator.recycle(target_index)`（槽位归还）。
   - 排序模式：`swap` 到前端 + `index_allocator.recycle(min_valid_index)` + `min_valid_index++`。

**ID 归零（`ID_set(0)`）的设计动机**：

- 构造时 `ID_allocator.set(1)` 预留 0，保证 **0 永远是"非法/无 ID"哨兵**；
- 卸载后对象仍留在 `objects` 容器中（仅标记无效），其 ID 若保持旧值会造成"容器内有已回收 ID 的对象"，一旦被 `data()` 遍历或误查找会产生歧义；
- 归零后，排序模式按 ID 升序排序时无效对象（ID=0）自然沉到容器前端，与 `min_valid_index` 机制无缝配合（见 4.1/4.2 中 `sort_order_set` 的初始扫描）。

**ID 复用风险提示**：`ID_allocator.recycle` 允许 ID 复用。若业务代码长期持有旧对象 ID 并在对象卸载后再次 `find`，可能命中**新对象**（同 ID）。对象池语义是"ID 即时回收复用"，业务需自行保证"ID 使用期"（build 之后、unload 之前）不重叠，或用 `valid()` 复核。

### 4.7 `build` 的槽位复用与数据重置

`build` 的槽位来源分两种：

1. **回收槽**：`index_allocator.get()` 优先返回 `recycle_numbers` 末尾（LIFO）——最近卸载的索引最先复用。
2. **新槽**：`next_number++`——追加到 `objects` 尾部（`push_back`）。

无论哪种来源，`build` 都执行 `new_object = T{}` **整体重置**（默认构造赋值），确保复用槽位上不残留上一个对象的字段值（如旧的 `object_ID`、业务数据）。这是"槽位复用安全"的关键一步，重开发时不可省略。

### 4.8 显式实例化（对象池实例化.cpp）

```cpp
#include "../对象池.h"

namespace engine
{
	//对象池实例化
	template class Object_Pool<Object>;
}
```

- 作用：为 `Object_Pool<Object>`（模板参数 T = 基类 `Object`）生成显式实例化符号，任何包含 `对象池.h` 的翻译单元引用 `Object_Pool<Object>` 时直接链接该符号，**避免多翻译单元重复实例化带来的编译时间与二进制膨胀**。
- 注意：显式实例化只覆盖 `Object_Pool<Object>` 这一特化；业务模块的 `Object_Pool<Collision_XX>` 仍在使用点隐式实例化。

### 4.9 与 `Number_Allocator` 的协作细节

- **双分配器职责分离**：`ID_allocator` 管"逻辑 ID"，`index_allocator` 管"物理槽位"，二者独立回收、独立增长。逻辑 ID 与物理索引**不保证相等**（ID 从 1 起、索引从 0 起；ID 由回收 LIFO 复用，索引同样），业务切不可假设"第 n 个对象的 ID 是 n"。
- **回收查重**：`Number_Allocator::recycle` 内部用 `binary_search` 查重，重复回收会 `Log::warn("Number_Pool::待回收数值已被回收!!!")` 并返回 false。对象池的 `unload` 对同一 ID 只会回收一次（`find` 命中后），正常流程不会触发该警告；但多对象 `unload` 传入重复键时，第二次 `find` 失败走"目标对象不存在"分支，也不会触发重复回收。
- **`set(1)` 的时序**：构造函数中 `ID_allocator.set(1)` 必须在任何 `build` 之前执行（构造函数体内完成，天然满足）。

### 4.10 与 `binary_search` 的协作细节

- 对象池排序模式 `find` 使用**迭代器区间重载**：`binary_search(objects.begin() + min_valid_index.value(), objects.end(), key, std::ranges::less(), projector)`。
- 该重载返回**相对 `first`（即 `begin + min_valid_index`）的索引**，因此对象池换算全局迭代器时必须 `objects.begin() + min_valid_index.value() + index`——**不可漏加 `min_valid_index`**，否则定位错误（这是重开发时最容易犯的偏移错误，源码已正确实现）。
- 比较器与投影一致性：`sort_order_set` 用 `proj` 排序，`find` 用 `projector` 二分，二者必须等价（`projector` 就是 `proj` 的 `std::function` 包装），否则二分结果无定义。

### 4.11 与 `Log` 的协作细节

对象池共两处日志（均为既有实现）：

| 位置 | 级别 | 内容 | 触发条件 |
| --- | --- | --- | --- |
| `find`（非整型 Key + 稳定模式） | `Log::error` | `Object_Pool::当前对象池未排序\n无法使用ID以外字段查找目标对象` | 未排序时按非 ID 字段查找 |
| `unload`（目标不存在） | `Log::warn` | `Object_Pool::目标对象不存在` | 卸载不存在的对象 |

设计决策：`find` 用 `error` 级别（编程错误类，应被开发者看见）、`unload` 用 `warn` 级别（业务可预期的未命中）。重开发时保持该分级。

### 4.12 边界情况与易踩坑点汇总

| 编号 | 场景 | 行为 | 踩坑提示 |
| --- | --- | --- | --- |
| E1 | `find` 未命中 | 返回 `end()` | 调用方必须判 `it != pool.end()` 再解引用 |
| E2 | `unload` 不存在的对象 | `Log::warn`，静默返回 | 不会崩溃；批量卸载重复键会触发多次警告 |
| E3 | 非整型 Key 稳定模式 `find` | ERROR 日志 + 返回 `end()` | 必须先 `sort_order_set` 才能按非 ID 字段查找 |
| E4 | 排序模式 `build` 高频调用 | 每次全有效区重排序 O(n log n) | 高频增删场景建议稳定模式 |
| E5 | ID 复用 | `unload` 后 ID 可被新 `build` 复用 | 长期持有旧 ID 再 `find` 会命中新对象，用 `valid()` 复核 |
| E6 | `data()` 返回非 const 引用 | 直接修改容器破坏索引一致性 | 只读遍历用 `data()`；增删一律走 `build`/`unload` |
| E7 | 投影值重复 | 排序模式 `find` 二分命中任意重复元素 | 需要"所有同键对象"时自行遍历有效区 |
| E8 | `min_valid_index` 为 0 时 `build` 的 `-1` 判断 | `0 - 1` 下溢为 `UINT64_MAX`，与任何合法 `index` 不相等 | 不会误触发，安全 |
| E9 | `clear` 后模式保留 | 稳定模式清映射、排序模式 `min_valid_index=0` | 清空后 `is_sorted` 不变，需按原模式使用 |
| E10 | `Object` 未派生（编译期） | `requires std::is_base_of_v<Object, T>` 不满足 | 编译错误，明确提示 |
| E11 | `T` 需默认构造 | `objects.push_back({})`、`new_object = T{}` | 自定义类型必须提供默认构造函数 |
| E12 | 排序模式 `find` 要求投影值唯一有序 | 二分依赖严格有序区间 | 投影函数必须是稳定的纯函数 |
| E13 | union 生命周期管理 | 模式切换必须 placement new / 显式析构 | 直接赋值 union 成员是未定义行为 |
| E14 | `sort_order_set` 非首次调用只更新 `projector` | `min_valid_index` 不重算 | 首次调用后对象有效性布局由 `build`/`unload` 增量维护 |

## 五、模块运行链路（从构建/初始化到一次典型操作的完整调用时序；与其他模块的协作关系）

### 5.1 总体协作拓扑

```
业务模块（如碰撞模块）
    │
    │ 构造：Object_Pool<Collision_XX> pool;  （默认稳定模式；ID_allocator.set(1) 预留 ID 0）
    │
    ├─ build() ───────────────────────────────────────────────► 对象池
    │     · index_allocator.get()           ──► Number_Allocator（取槽位）
    │     · objects.push_back / 重置 T{}
    │     · ID_set(ID_allocator.get())      ──► Number_Allocator（取 ID，首个为 1）
    │     · valid_set(true)
    │     · 稳定：object_index_map.insert；排序：std::ranges::sort
    │     └─► 返回对象 ID
    │
    ├─ find(id) ──────────────────────────────────────────────► 对象池
    │     · 稳定：object_index_map.find（O(1)）
    │     · 排序：binary_search（O(log n)，相对索引 + min_valid_index 换算）
    │     └─► 迭代器 / end()
    │
    ├─ unload(id) ────────────────────────────────────────────► 对象池
    │     · ID_allocator.recycle(ID)        ──► Number_Allocator（回收 ID）
    │     · ID_set(0) + valid_set(false)
    │     · 稳定：映射 erase + index_allocator.recycle
    │     · 排序：swap 前端 + recycle + min_valid_index++
    │
    ├─ sort_order_set(greater, proj) ─────────────────────────► 对象池
    │     · 首次：析构映射 → placement new 三字段 → 按 ID 升序
    │     ·       扫描回收无效索引 → min_valid_index → 重排有效区
    │
    ├─ sort_order_reset() ────────────────────────────────────► 对象池
    │     · 析构排序字段 → placement new 映射 → 重建索引 → 稳定模式
    │
    ├─ clear() ───────────────────────────────────────────────► 对象池
    │     · objects.clear + 双分配器 reset + 按模式清索引
    │
    └─ data() / end() ────────────────────────────────────────► 对象池（只读遍历）
```

### 5.2 链路一：稳定模式完整生命周期（默认路径）

```
① 构造
   Object_Pool<Object> pool;
   └─ Object_Pool::Object_Pool()
       ├─ new (&object_index_map) unordered_map<...>()   // 进入稳定模式
       └─ ID_allocator.set(1);                           // 预留 ID 0

② 连续添加
   id1 = pool.build();   // index=0 → push_back → ID=1 → map{1:0}
   id2 = pool.build();   // index=1 → push_back → ID=2 → map{2:1}
   id3 = pool.build();   // index=2 → push_back → ID=3 → map{3:2}
   // objects = [obj(id=1), obj(id=2), obj(id=3)]

③ 查找
   auto it = pool.find(id2);     // map.find(2) → {2:1} → begin()+1
   // *it 即对象 id=2

④ 卸载（回收语义）
   pool.unload(id2);
   // ID_allocator.recycle(2)   → ID 2 可复用
   // it->ID_set(0); valid_set(false)
   // object_index_map.erase(2)
   // index_allocator.recycle(1) → 索引 1 可复用
   // objects = [obj(id=1, valid), obj(id=0, invalid), obj(id=3, valid)]

⑤ 再添加（槽位复用）
   id4 = pool.build();
   // index_allocator.get() → 回收栈 LIFO 取 1
   // index(1) < size(3) → 不 push_back，直接复用槽位
   // objects[1] = T{}（重置）→ ID_allocator.get() → 2（复用 id2 的 ID！）
   // map.insert({2, 1})
   // objects = [obj(1,valid), obj(2,valid), obj(3,valid)]

⑥ 清空
   pool.clear();
   // objects 清空、双分配器 reset、map.clear()
```

**要点**：⑤中可清楚看到 **ID 复用**（新对象拿到 2 号 ID）与**索引复用**（占据 1 号槽位）——重开发时务必理解这两条复用通道是独立的。

### 5.3 链路二：排序模式完整生命周期

```
① 构造（稳定模式）并添加若干对象
   Object_Pool<Object, uint64_t> pool;      // 稳定模式
   pool.build(); pool.build(); pool.build();

② 切换到排序模式
   pool.sort_order_set(false, [](const Object& o){ return o.ID(); });
   // is_sorted=true；析构 map；构造 projector/is_greater/min_valid_index
   // 按 ID 升序排全容器（此刻全有效，min_valid_index 扫描得 0）
   // 有效区 [0,3) 按 ID 升序
   // 全部 ID 回收 index_allocator.recycle 无触发（无无效对象）

③ 排序模式查找
   auto it = pool.find(2);
   // binary_search(begin+0, end, 2, less, projector) → 相对索引 1
   // 返回 begin + 0 + 1

④ 排序模式卸载
   pool.unload(1);     // 卸载 ID=1 的对象（假设在位置 0）
   // find(1) → 位置 0；ID_allocator.recycle(1)；ID_set(0)；valid_set(false)
   // swap(objects[min_valid_index=0], objects[0]) → 原地
   // index_allocator.recycle(0)；min_valid_index++ → 1
   // objects = [obj(0,invalid), obj(2,valid), obj(3,valid)]

⑤ 排序模式再查找
   auto it2 = pool.find(2);
   // binary_search(begin+1, end, 2, less, projector) → 相对索引 0
   // 返回 begin + 1 + 0 → 正确命中（无效对象被排除在二分区间外）

⑥ 排序模式添加
   id4 = pool.build();
   // index_allocator.get() → 回收栈取 0
   // index(0) == min_valid_index(1) - 1 → min_valid_index-- → 0
   // objects[0] = T{} → ID_allocator.get() → 1（复用）→ valid_set(true)
   // 有效区 [0,3) 重排序
   // objects = [obj(1,valid), obj(2,valid), obj(3,valid)]

⑦ 重置回稳定模式
   pool.sort_order_reset();
   // 析构 projector/min_valid_index；placement new map
   // 遍历有效对象重建映射 {1:0, 2:1, 3:2}
   // is_sorted = false
```

**要点**：⑤展示 `min_valid_index` 如何保证二分区间纯净；④→⑥展示卸载/构建如何增量维护有效区边界。

### 5.4 链路三：`data()` 遍历与外部消费

```
auto& objects = pool.data();
for (auto& obj : objects)      // 含无效对象（valid()==false）
{
    if (!obj.valid()) continue;    // 业务需自行跳过无效对象
    // 处理有效对象
}
```

**要点**：`data()` 暴露的是原始容器（含已卸载的无效对象），业务遍历时**必须用 `valid()` 过滤**；排序模式下无效对象集中在前端，可结合 `min_valid_index` 语义只遍历有效区（但该字段是私有的，业务侧只能通过 `valid()` 判断）。

## 七、本版次相关与遗留事项

### 7.1 本版次（089b070）改动情况

**本模块（对象系统）在 089b070 版次无源码改动**。本版次聚焦"碰撞模块单文件拆分为多编译单元"，对象系统作为碰撞模块的对象管理基础设施被引用，其自身源码（`Object` 基类四接口、`Object_Pool` union 双模式、`对象池实例化.cpp` 显式实例化）保持 fa8459a 版次以来的既有状态。

### 7.2 源码中的已知注意事项与潜在缺陷（供后续版本关注）

1. **排序模式 `build` 后全有效区重排序**：每次 `build` 都对有效区 `std::ranges::sort`（O(n log n)）。批量添加对象（循环 `build` N 次）总复杂度 O(N·n log n)。**建议**：增加"批量构建后统一重排"接口，或将重排序推迟到首次 `find`/`data` 前（惰性排序）。
2. **`data()` 返回非 const 引用**：外部可直接修改容器破坏索引一致性，无防护。**建议**：提供 `const std::vector<T>& data() const` 重载，或文档约束只读使用。
3. **排序模式 `find` 对重复投影值只命中一个**：投影字段不唯一时二分命中任意重复元素。**建议**：文档明确约束"排序键需唯一"，或改用 `range_binary_search` 支持多命中。
4. **union 析构不完整**：析构函数只显式析构 `object_index_map` 或 `projector`，排序模式下 `min_valid_index`（`std::optional`）未显式析构（依赖 struct 自动析构路径）。当前编译器行为正确，但依赖未明示的生命周期规则，重开发时建议显式析构三字段以保证可移植性。
5. **`clear` 后排序模式 `min_valid_index = 0` 直接赋值**：若后续 `build` 前对象池处于排序模式且无有效对象，`min_valid_index` 为有值 0；再次 `sort_order_set` 因 `has_value()` 为真不会重算有效区。当前语义自洽（空容器时 0 == size），但若 `clear` 与 `build` 交错使用需留意。
6. **`unload` 后对象仍占容器空间**：无效对象留在 `objects` 中（仅标记），`objects` 容量只增不减（除非 `clear`）。长期高频增删会使容器中堆积无效对象。**建议**：提供"紧凑化"接口（如 `shrink`：剔除无效对象并重建索引）。
7. **多对象 `unload` 的重复键**：批量卸载传入重复键时，第二个键触发"目标对象不存在"警告（无害但噪音）。**建议**：批量接口内部去重。
8. **非整型 Key 稳定模式查找返回 `end()` 而非编译错误**：运行时才报错。**建议**：可考虑用概念（concept）约束"整型 Key 才允许稳定模式查找"，将错误前移到编译期。

### 7.3 接口变更建议汇总（备忘）

- `Object_Pool` 增加批量 `build`（多次添加后统一重排）。
- `Object_Pool` 增加 `const` 版本 `data()`。
- `Object_Pool` 增加 `shrink`/`compact` 紧凑化接口。
- `find` 对重复投影值提供多命中语义（`range_binary_search`）。
- 显式析构排序模式 union 三字段，增强可移植性。

### A.2 `sort_order_set`（第 63–115 行）

```cpp
template <typename Projection>
void sort_order_set(bool greater, Projection proj)
{
    //若当前未记录排序方式
    if(!is_sorted)
    {
        //设置对象序列易变
        is_sorted = true;
        //析构对象索引映射
        object_index_map.~unordered_map();
        //分配内存并记录投影字段
        new (&projector) std::function<Key(const T&)>(proj);
        new (&is_greater) bool(false);
        new (&min_valid_index) std::optional<uint64_t>();
    }
    else
        projector = proj;

    //若未记录有效索引起点
    if (!min_valid_index.has_value())
    {
        //升序排序使非法记录移动到序列前端
        std::ranges::sort(objects, std::ranges::less(), [](const T& o) { return o.ID(); });
        //获取有效索引起点
        for (int filter_index = 0; filter_index < objects.size(); filter_index++)
        {
            //若当前对象索引有效
            if (objects[filter_index].valid())
            {
                min_valid_index = filter_index;
                break;
            }
            else
                //回收无效索引
                index_allocator.recycle(filter_index);
        }

        //若未获得有效索引起点
        if (!min_valid_index.has_value())
            min_valid_index = objects.size();
    }

    //记录排序方式
    is_greater = greater;
    //重排序对象
    if (!is_greater)
        std::ranges::sort(objects.begin() + min_valid_index.value(), objects.end(),
            std::ranges::less(), proj);
    else
        std::ranges::sort(objects.begin() + min_valid_index.value(), objects.end(),
            std::ranges::greater(), proj);
}
```

关键点：首次切换时按 **ID 升序**排全容器（把 ID=0 的无效对象沉底到前端）→ 扫描确定 `min_valid_index` 并回收无效索引 → 按投影重排有效区。`std::ranges::less()` 无参数形式用于按 ID 排序（投影到 `o.ID()`）。

### A.5 `build`（第 205–242 行）

```cpp
uint64_t build(void)
{
    //分配新对象索引
    uint64_t index = index_allocator.get();
    //若索引越界
    if (index >= objects.size())
        objects.push_back({});

    //若为排序模式且索引位于有效区边界
    if(is_sorted && index == min_valid_index.value() - 1)
        min_valid_index.value()--;

    //获取新对象
    auto& new_object = objects[index];
    //重置该对象避免数据残留
    new_object = T{};
    //分配对象ID
    new_object.ID_set(ID_allocator.get());
    //设置记录有效
    new_object.valid_set(true);
    //若序列稳定则记录索引映射
    if(!is_sorted)
        object_index_map.insert({ new_object.ID(), index });
    else
    {
        //重排序对象
        if (!is_greater)
            std::ranges::sort(objects.begin() + min_valid_index.value(), objects.end(),
                std::ranges::less(), projector);
        else
            std::ranges::sort(objects.begin() + min_valid_index.value(), objects.end(),
                std::ranges::greater(), projector);
    }

    //返回对象ID
    return new_object.ID();
}
```

关键点：`new_object = T{}` 重置防残留；排序模式下 `index == min_valid_index - 1` 时有效区前移；稳定模式插入映射、排序模式重排有效区。

### A.6 `unload`（第 243–285 行）

```cpp
void unload(const Key& key)
{
    auto it = find(key);
    if (it != objects.end())
    {
        uint64_t target_index = it - objects.begin();
        uint64_t ID = it->ID();
        //回收目标对象ID
        ID_allocator.recycle(ID);
        //设置预留无效ID
        it->ID_set(0);
        //设置目标对象记录不合法
        objects[target_index].valid_set(false);
        if(!is_sorted)
        {
            //取消目标对象索引映射
            object_index_map.erase(ID);
            //回收目标对象索引
            index_allocator.recycle(target_index);
        }
        else
        {
            //将无效对象移动至容器前端
            std::swap(objects[min_valid_index.value()], objects[target_index]);
            //回收目标对象索引
            index_allocator.recycle(min_valid_index.value());
            //更新有效索引起点
            min_valid_index.value()++;
        }
    }
    else
    {
        Log::warn("Object_Pool::目标对象不存在");
        return;
    }
}
```

关键点：**ID 回收 + ID 归零（`ID_set(0)`）+ 无效标记**；稳定模式擦映射回收槽；排序模式 swap 到前端、回收前端槽、`min_valid_index++`。

## 附录 C：`Number_Allocator` 协作源码走读（数值分配器.h，79 行）

```cpp
namespace engine
{
	class Number_Allocator
	{
	private:
		uint64_t next_number = 0;
		std::vector<uint64_t> recycle_numbers;
	public:
		void set(const uint64_t& min_allocate_number)
		{
			next_number = min_allocate_number;
		}
		uint64_t get(void)
		{
			uint64_t index;
			if (!recycle_numbers.empty())
			{
				index = recycle_numbers.back();
				recycle_numbers.pop_back();
			}
			else
				index = next_number++;
			return index;
		}
		bool recycle(const uint64_t& recycle_number)
		{
			int index = binary_search(recycle_numbers, recycle_number, std::ranges::less());
			if(index >= 0)
			{
				Log::warn("Number_Pool::待回收数值已被回收!!!");
				return false;
			}
			else
			{
				recycle_numbers.push_back(recycle_number);
				std::ranges::sort(recycle_numbers);
				return true;
			}
		}
		void recycle(const std::vector<uint64_t>& recycle_numbers)
		{
			for (auto number : recycle_numbers)
				recycle(number);
		}
		void reset(void)
		{
			next_number = 0;
			recycle_numbers.clear();
		}
	};
}
```

要点：`get` 优先 LIFO 复用回收值；`recycle` 先二分查重（重复则 warn 拒绝）再插入排序——**回收集合始终有序**，为查重二分提供前提。对象池持有两个独立实例（ID/索引），互不干扰。
