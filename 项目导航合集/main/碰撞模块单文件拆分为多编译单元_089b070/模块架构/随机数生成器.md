## 一、模块功能

### 1.1 模块定位

「随机数生成器」（`Random_Generator`）是引擎层 `src/tools/` 工具集中一个**高质量伪随机数设施**。它以 PCG（Permuted Congruential Generator，置换同余生成器）算法家族中的 **PCG32** 为核心引擎，对外提供两种随机数产出形态：

1. **无参调用 `operator()()`**：生成一个覆盖 `int64_t` 全范围的 64 位随机整数；
2. **区间调用 `operator()(min, max)`**：生成闭区间 `[min, max]` 内的均匀随机整数（**无偏**，拒绝采样法实现）。

PCG 是 Melissa E. O'Neill 于 2014 年提出的现代伪随机算法，在统计质量（通过 BigCrush 测试套件）、速度与代码量之间取得了极佳平衡；相比 C 库 `rand()`（线性同余、低位质量差）与 `std::mt19937`（梅森旋转，状态 2.5KB、预热慢），PCG32 仅需 **16 字节状态**（`state` + `inc` 两个 `uint64_t`），输出经过异或位移（xorshift）与旋转（rotate）两级置换，低位随机性显著改善，特别适合需要「小而快且足够随机」的引擎内嵌场景。

本模块位于引擎层目录 `引擎层/src/tools/Random/`，由两份文件构成：

- `随机数生成器.h` —— 公共头文件，声明 `pcg32` 状态结构体、私有方法、公开接口；
- `随机数生成器.cpp` —— 全部实现（PCG 核心位运算、种子初始化、64 位组合、拒绝采样区间）。

### 1.2 解决的核心问题

引擎中需要随机数的场景包括：

1. **密钥/标识生成**：事件系统的访问控制密钥（`acl_key`）需要「不可预测」的 64 位随机值，防止攻击者猜出密钥绕过权限检查——这是本模块**当前唯一实际消费方**（`Event_Terminal`）；
2. **游戏逻辑随机**：掉落、暴击、AI 行为分支、粒子初始速度等（预留能力）；
3. **确定性复现**：显式种子构造（`Random_Generator(seed)`）保证「同一种子 → 同一序列」，便于测试与回放——这是游戏引擎随机系统的硬性需求。

`std::rand()` 无法满足上述需求（可预测、质量差、无种子复现保证）；`std::mt19937` 状态庞大且预热开销高。本模块以 40 行左右的紧凑实现同时提供：高质量位输出、64 位全范围、无偏闭区间采样、显式/自动双种子路径。

### 1.3 功能要点一览

| 能力 | 说明 |
| --- | --- |
| PCG32 核心 | 16 字节状态（`state`/`inc`），乘法同余 + xorshift + rotate 三步输出置换 |
| 无参随机 | `operator()()` 组合两次 PCG32 输出为 64 位，覆盖 `int64_t` 全范围 |
| 区间随机 | `operator()(min, max)` 拒绝采样法，闭区间 `[min, max]` 均匀无偏 |
| 显式种子 | `Random_Generator(uint64_t seed_out)` / `pcg32_seed_init(uint64_t)` 确定性复现 |
| 自动种子 | 默认构造 / `pcg32_seed_init()` 组合「高精度时钟 + Unix 时间 + 静态计数器」 |
| 参数自适应 | `min > max` 自动交换；全范围区间特判；单值区间直接返回 |
| 种子合法性 | `inc` 强制置奇（`(seed << 1) | 1`），保证全周期 2^64 状态遍历 |

### 1.4 非目标（明确不做的事）

- **不做密码学安全随机**：PCG32 的状态可从输出反推（仅 64 位状态熵），不应用于密钥学意义上的安全场景；`acl_key` 的使用场景是「访问控制混淆」，非密码学防线；
- **不做浮点随机**：未提供 `[0,1)` 浮点产出（调用方可自行 `operator()()` 换算）；
- **不做分布变换**：无正态/指数等分布适配器，仅均匀整数；
- **不做多线程安全**：`g_pcg32` 状态为实例成员，非线程安全；
- **不做序列持久化**：不提供状态保存/恢复接口（但显式种子可复现整条序列）。

### 2.1 类：`engine::Random_Generator`

```cpp
namespace engine
{
	class Random_Generator
	{
		// PCG32 状态结构体
		struct pcg32
		{
			uint64_t state = 0;
			uint64_t inc = 0;
		} g_pcg32;

		uint64_t seed = 0;

		// 底层原始 32 位随机数生成（PCG32 核心）
		uint32_t pcg32_random_raw();

		// 生成 [min, max] 范围内的 64 位随机数（无偏）
		int64_t pcg64_random_range(int64_t min, int64_t max);

	public:
		// 生成一个 int64_t 全范围随机数
		int64_t operator()();

		// 生成 [min, max] 范围内的 int64_t 随机数（包含两端）
		int64_t operator()(int64_t min, int64_t max);

		// 构造函数
		Random_Generator(void) ;
		explicit Random_Generator(uint64_t seed_out);

		// 种子初始化
		void pcg32_seed_init(uint64_t seed_out);
		void pcg32_seed_init();
	};

```

注意：源码中 `uint64_t seed = 0;` 成员变量**已声明但从未被读取**（种子只经 `pcg32_seed_init` 写入 `g_pcg32.inc`，`seed` 成员本身是遗留冗余），阅读与重开发时注意区分，勿依赖该成员（详见 §4.6 易踩坑点）。

### 2.2 接口逐条说明

#### `Random_Generator(void)` —— 默认构造

| 项目 | 说明 |
| --- | --- |
| 参数 | 无 |
| 行为 | 调用无参 `pcg32_seed_init()`：以「高精度时钟纳秒 ⊕ Unix 时间 ⊕ 自增计数器」组合出自动种子并完成初始化。不同实例/不同时刻构造，序列几乎必然不同 |

#### `explicit Random_Generator(uint64_t seed_out)` —— 显式种子构造

| 项目 | 说明 |
| --- | --- |
| 参数 | `seed_out`：用户提供的种子值（任意 `uint64_t`，0 亦合法——`inc` 置奇逻辑保证 0 种子也能正常运转） |
| 行为 | 调用 `pcg32_seed_init(seed_out)`，建立确定性序列：同一 `seed_out` 构造的实例产出完全相同的随机序列 |

`explicit` 关键字：禁止隐式转换（`Random_Generator r = 12345;` 非法），要求显式 `Random_Generator r(12345);`，避免无意的隐式构造。

#### `void pcg32_seed_init(uint64_t seed_out)` —— 显式种子初始化

```cpp
void Random_Generator::pcg32_seed_init(uint64_t seed_out)
{
    g_pcg32.state = 0;
    g_pcg32.inc = (seed_out << 1u) | 1u;
    (void)pcg32_random_raw();   // 预热一次
}
```

| 项目 | 说明 |
| --- | --- |
| 参数 | `seed_out`：种子值 |
| 返回值 | 无 |
| 行为 | ① `state` 归零；② `inc = (seed << 1) | 1`（左移一位再置最低位为 1，保证 `inc` 恒为奇数）；③ 调用一次 `pcg32_random_raw()` **预热**（丢弃首次输出） |

设计要点：

- **`inc` 置奇**：PCG 要求增量 `inc` 为奇数才能保证 LCG 全周期（`2^64` 状态不重不漏地遍历）。`(seed << 1) | 1` 把任意种子映射为奇数；
- **预热**：PCG 官方推荐的初始化规范——置零状态后首次输出质量差，丢弃一次即可让状态充分「搅拌」。`(void)` 显式忽略返回值。

#### `void pcg32_seed_init()` —— 自动种子初始化

```cpp
void Random_Generator::pcg32_seed_init()
{
    static uint64_t counter = 0;
    auto now = std::chrono::high_resolution_clock::now();
    auto ns = std::chrono::duration_cast<std::chrono::nanoseconds>(now.time_since_epoch()).count();
    uint64_t seed = static_cast<uint64_t>(ns) ^ static_cast<uint64_t>(std::time(nullptr)) ^ (++counter);
    g_pcg32.state = 0;
    g_pcg32.inc = (seed << 1u) | 1u;
    (void)pcg32_random_raw();
}
```

| 项目 | 说明 |
| --- | --- |
| 参数 | 无 |
| 返回值 | 无 |
| 行为 | 组合三路熵源生成种子：① `high_resolution_clock` 的 epoch 纳秒计数（纳秒级时间戳，分辨率高、变化快）；② `std::time(nullptr)` 的 Unix 秒数（跨进程/跨天维度差异）；③ `static uint64_t counter` 函数级静态计数器（**每次调用自增**，保证同一纳秒内连续构造的多个实例种子也互异）。三者按位异或后走与显式种子相同的初始化路径（置奇 + 预热） |

设计要点：

- **三路熵源互补**：仅用时钟，同一时钟 tick 内构造的实例会拿到相同种子；仅用时间戳，两台同步时钟的机器会拿到相同种子；计数器负责打破「同时刻同纳秒」的重合。三者异或后，重复概率在工程上趋近于零；
- **`counter` 是函数级 `static`**：生命周期跨实例、跨调用，进程内单调递增——即使 `high_resolution_clock` 分辨率低到两次 `now()` 返回相同值，`++counter` 仍保证种子不同。

#### `uint32_t pcg32_random_raw()` —— PCG32 核心（私有）

```cpp
uint32_t Random_Generator::pcg32_random_raw()
{
    uint64_t old_state = g_pcg32.state;
    g_pcg32.state = old_state * 6364136223846793005ULL + g_pcg32.inc;
    uint32_t xorshifted = (uint32_t)(((old_state >> 18u) ^ old_state) >> 27u);
    uint32_t rot = (uint32_t)(old_state >> 59u);
    return (xorshifted >> rot) | (xorshifted << ((-(int)rot) & 31));
}
```

| 项目 | 说明 |
| --- | --- |
| 参数 | 无 |
| 返回值 | 32 位无符号伪随机数 |
| 行为 | 三步标准 PCG 输出函数（O'Neill 论文中的 XSH-RR 变体）：<br>① **状态推进**（LCG）：`state = state * 6364136223846793005ULL + inc`——以 PCG 官方常数 6364136223846793005ULL 做乘法同余，`inc` 为奇数保证全周期；<br>② **异或位移**（xorshift）：`xorshifted = ((old_state >> 18) ^ old_state) >> 27`——取**旧状态**（推进前）做右移 18、自异或、右移 27，得到 32 位中间值；<br>③ **随机旋转**（rotate）：`rot = old_state >> 59` 取旧状态最高 5 位作旋转量，`(xorshifted >> rot) | (xorshifted << ((-rot) & 31))` 循环右移 |

关键实现细节：

- **使用 `old_state`（推进前的状态）做输出**：先推进、后用旧值置换——PCG 的标准做法，避免「新状态直接泄露」；
- **旋转量来自最高 5 位**：`old_state >> 59` 提取 `[63:59]` 5 位，取值范围 0~31，正好覆盖 32 位移位模数；`(-(int)rot) & 31` 把旋转量规范到 `[0, 31]` 区间（C++ 右移负数/移位≥位宽是未定义行为，此掩码规避）；
- **乘法常数** `6364136223846793005ULL` 是 PCG 论文与参考实现（pcg-c 库）的标准 LCG 乘数（即 2^64 模下的一个原根乘数）。

#### `int64_t operator()()` —— 64 位全范围随机

```cpp
int64_t Random_Generator::operator()()
{
    uint64_t high = pcg32_random_raw();
    uint64_t low = pcg32_random_raw();
    return static_cast<int64_t>((high << 32) | low);
}
```

| 项目 | 说明 |
| --- | --- |
| 参数 | 无 |
| 返回值 | `int64_t` 全范围随机整数（位模式覆盖全部 2^64 个值，按有符号解释为 `[-2^63, 2^63-1]`） |
| 行为 | 连续两次 `pcg32_random_raw()` 取高 32 位与低 32 位，`(high << 32) | low` 拼成 64 位，再 `static_cast<int64_t>` 按有符号位模式解释 |

注意：`high << 32` 中 `high` 是 `uint64_t`，左移 32 位安全（无符号移位不溢出）；`static_cast<int64_t>` 是**位模式重解释**（实现定义但所有主流平台为二进制补码），不改变任何位。

#### `int64_t operator()(int64_t min, int64_t max)` —— 闭区间随机（公有）

```cpp
int64_t Random_Generator::operator()(int64_t min, int64_t max)
{
    return pcg64_random_range(min, max);
}
```

| 项目 | 说明 |
| --- | --- |
| 参数 | `min`/`max`：闭区间端点，**允许 `min > max`**（内部自动交换） |
| 返回值 | `[min, max]` 内均匀随机整数（含两端） |
| 行为 | 直接委托私有 `pcg64_random_range` |

#### `int64_t pcg64_random_range(int64_t min, int64_t max)` —— 无偏区间随机（私有）

```cpp
int64_t Random_Generator::pcg64_random_range(int64_t min, int64_t max)
{
    if (min > max) {
        int64_t tmp = min;
        min = max;
        max = tmp;
    }

    uint64_t range = static_cast<uint64_t>(max - min) + 1ULL;
    if (range == 0) {  // 处理整个 int64_t 范围的情况
        // 直接生成完整 64 位随机数并返回（概率极低，但无偏）
        return operator()();
    }
    if (range == 1) return min;

    // 拒绝采样法（范围可能接近 2^64，需要用 128 位辅助）
    uint64_t limit = UINT64_MAX - UINT64_MAX % range;
    uint64_t r;
    do {
        r = static_cast<uint64_t>(operator()());
    } while (r >= limit);
    return min + static_cast<int64_t>(r % range);
}
```

| 项目 | 说明 |
| --- | --- |
| 参数 | `min`/`max`：闭区间端点（可乱序） |
| 返回值 | `[min, max]` 内均匀随机整数 |
| 行为 | ① 乱序端点交换；② 计算区间宽度 `range = (max - min) + 1`（`uint64_t` 无符号数学，`max - min` 的负数差经 `static_cast<uint64_t>` 变成补码大数，配合 `+1` 正确处理**跨零大区间**）；③ **`range == 0` 特判**：当区间恰好覆盖全部 `2^64` 个值（`max - min == UINT64_MAX`）时，`range` 回绕为 0，此时直接返回 `operator()()` 的全范围随机（无偏且恒在区间内）；④ **`range == 1` 特判**：单值区间直接返回 `min`；⑤ 一般情形走**拒绝采样**：`limit = UINT64_MAX - UINT64_MAX % range`（`2^64` 以下的最大「range 的整数倍」），循环生成 `r` 直到 `r < limit`，返回 `min + r % range` |

无偏性原理（为什么拒绝采样）：

- 朴素 `r % range` 有偏：`UINT64_MAX + 1 = 2^64` 不能被 `range` 整除时，`r % range` 的低 `2^64 % range` 个余数出现的概率略高于其余余数；
- 拒绝采样法把采样空间裁剪到 `limit`（`2^64` 之下最大的 `range` 倍数），只接受 `< limit` 的样本——被拒样本占比 `(2^64 - limit) / 2^64 < range / 2^64`，区间越大拒绝率越高，但每个接受的样本在 `[0, limit)` 内均匀，故 `r % range` 严格无偏；
- 源码注释提到「需要用 128 位辅助」指算法思路（计算 `UINT64_MAX % range` 需要 64 位模 64 位，实际源码用 `UINT64_MAX - UINT64_MAX % range` 一次求余完成，无需真 128 位）。

## 四、模块设计/实现细节

### 4.1 PCG32 算法逐步拆解（重开发必读）

以一次 `pcg32_random_raw()` 为例，追踪 `state = 42, inc = 7` 的完整变换：

```
① 状态推进（LCG）
   old_state = 42
   state = 42 * 6364136223846793005ULL + 7
         = 267238986968033110077...（64 位截断）

② 异或位移（XSH）
   x = (old_state >> 18) ^ old_state          ← 高 46 位与低 46 位异或
   xorshifted = x >> 27                        ← 取 32 位
   （等价于把旧状态 64 位的高熵压缩进低 32 位）

③ 随机旋转（RR）
   rot = old_state >> 59                       ← 取最高 5 位 (0~31)
   out = (xorshifted >> rot) | (xorshifted << ((-rot) & 31))
   （循环右移 rot 位；(-rot) & 31 规范化移位量，避免 UB）
```

输出统计特性：PCG32 通过 BigCrush（TestU01 套件最强测试），32 位输出的每个位都近似独立均匀；其低位质量远优于传统 LCG（`rand()`），旋转步骤专门修复了「低位周期短」的 LCG 通病。

### 4.2 种子初始化两条路径对比

| 路径 | 入口 | 种子来源 | 确定性 | 典型场景 |
| --- | --- | --- | --- | --- |
| 显式 | `pcg32_seed_init(seed)` / `Random_Generator(seed)` | 调用方传入 | **完全确定**：同种子同序列 | 测试、回放、需要可复现的关卡随机 |
| 自动 | `pcg32_seed_init()` / 默认构造 | 时钟纳秒 ⊕ Unix 时间 ⊕ 静态计数器 | 不可复现（每次不同） | 生产运行、密钥类随机 |

两条路径汇合于同一初始化内核：`state = 0; inc = (seed << 1) | 1; 预热一次`。

### 4.3 拒绝采样的边界特判深度分析

`pcg64_random_range` 的三个分支对应三种区间宽度形态：

| 区间宽度 `range` | 触发条件 | 处理 | 无偏性 |
| --- | --- | --- | --- |
| `range == 0`（回绕） | `max - min == UINT64_MAX`，即区间覆盖全部 `2^64` 个 `int64_t` 值（如 `min = INT64_MIN, max = INT64_MAX`） | 直接 `return operator()()` | 全范围均匀，天然无偏 |
| `range == 1` | `max == min` 单点区间 | `return min` | 恒等，无随机 |
| 一般 `range`（2~2^64-1） | 其余全部 | 拒绝采样 `r % range` | 严格无偏（拒绝率 < `range / 2^64`） |

细节验证：

- `uint64_t range = static_cast<uint64_t>(max - min) + 1ULL;`：`max - min` 在有符号下可能溢出（如 `INT64_MAX - INT64_MIN`），但 C++ 无符号转换先于运算生效？——**不**：`max - min` 先按 `int64_t` 求值，跨全范围时已溢出（UB 风险，见 §4.6 踩坑 5）。工程上调用方通常传 `(min, max)` 为「语义区间」而非「数学全宽」，该溢出仅在全范围场景出现，而全范围场景恰被 `range == 0` 分支兜底（溢出后的差在无符号下表现为 `0xFFFF...F`，`+1` 后为 0）；
- `limit = UINT64_MAX - UINT64_MAX % range`：当 `range` 恰好整除 `2^64` 时 `limit = UINT64_MAX`，拒绝率 0，退化为朴素 `%`（此时朴素法本就无偏）；
- 返回 `min + static_cast<int64_t>(r % range)`：`r % range < range ≤ 2^64 - 1`，`min + 余数` 在有符号下是否溢出？当 `range` 接近 `2^64` 时 `r % range` 可达 `2^64 - 1`，`min` 为负时 `min + (2^64-1)` 可能越界——但此时区间本身几乎覆盖全范围，`min + (r % range)` 在数学上仍落在 `[min, max]` 内，只有 `range == 0` 分支（全范围）走 `operator()()` 绕开此问题。实际可溢出组合需要 `min` 接近 `INT64_MIN` 且 `range` 接近 `2^64`，即区间几乎全宽——极端情形下存在实现层面的未定义风险，但工程调用模式（小区间）完全安全。

### 4.4 设计决策及原因

1. **为什么选 PCG32 而非 `std::mt19937`**：引擎工具模块追求「小、快、够好」。PCG32 状态仅 16 字节（mt19937 为 2.5KB），单次输出约 2-3 个周期指令（mt19937 需 624 词状态表 + 分发表重整），且 PCG 通过全部统计测试。对 `acl_key` 这类「每终端一次」的调用，PCG 完全够用。
2. **为什么 64 位用「两次 32 位拼接」而非单独 64 位算法**：复用已实现的 PCG32 核心，无需引入 PCG64（另一组乘数常数）。拼接法的两个 32 位输出来自**连续两次状态推进**，统计上独立，组合后 64 位分布均匀。
3. **为什么区间采样用拒绝法而非取模**：无偏性是本模块的显式承诺（头文件注释明确写「无偏」）。取模法在 `range` 不整除 `2^64` 时引入可测量的偏置（对游戏概率系统，0.1% 的偏置可能被玩家察觉或导致测试断言失败）。拒绝法以「平均不到 2 次采样」的代价换取严格均匀。
4. **为什么自动种子用三路熵源异或**：任何单一熵源都有退化场景（时钟 tick 内重复、跨进程同时间戳），异或组合把各熵源的弱点互相掩盖，且无熵源聚合的理论陷阱（异或对部分碰撞天然免疫）。
5. **为什么 `inc` 必须置奇**：LCG 全周期定理要求「增量与模数互质」，模 `2^64` 下等价于 `inc` 为奇数。`(seed << 1) | 1` 一行同时完成「任意种子 → 合法增量」的映射。

### 4.5 与其它模块的协作

#### 与 `Event_Terminal`（事件终端，`src/core/event/Event_Terminal/事件终端.h`）

当前引擎中**唯一的实际消费方**。`Event_Terminal` 持有 `Random_Generator key_generator{};`（默认构造 → 自动种子）作为权限密钥生成器：

```cpp
class Event_Terminal
{
private:
	//权限密钥
	std::optional<int64_t> acl_key;
	//密钥生成器
	Random_Generator key_generator{};
	...
public:
	//权限密钥生成
	int64_t acl_key_gen(void);
	...
};
```

`acl_key_gen` 的实现（`core/事件终端.cpp`）：

```cpp
int64_t Event_Terminal::acl_key_gen(void)
{
	if (!acl_key.has_value())
	{
		for (;;)
		{
			acl_key = key_generator();          // 无参 operator()()
			if (acl_key != 0)                    // 0 被排除（无效密钥哨兵）
				return acl_key.value();
		}
	}
	else
		return 0;                                // 已生成过，返回 0 表示拒绝
}
```

协作要点：

- 密钥 = `key_generator()` 无参调用的 `int64_t` 全范围值，**排除 0**（0 被事件系统用作「无权限/未生成」哨兵）；
- `for(;;)` 无限循环重试：因为 `operator()()` 有 `2^-64` 的概率产出 0，循环保证最终拿到非零密钥；
- 该密钥随后用于 `attach`/`interact`/`send`/`query`/`clear` 的权限校验（`this->acl_key != acl_key → 拒绝`）；
- 安全性定位：PCG32 的 64 位输出空间巨大（暴力尝试 2^63 次平均），对「防止误触/防内部越权」足够；若需对抗专业逆向，应换密码学 RNG（本模块明确不提供）。

#### 潜在协作方（预留）

- 游戏逻辑层：掉落/暴击/随机种子生成；
- 测试系统：显式种子复现随机场景。

### 4.6 易踩坑点（重开发速查）

1. **`seed` 成员是死代码**：`uint64_t seed = 0;` 从未被读写。重开发时建议删除或真正利用它（如记录当前种子便于复现），但**删除会改变类布局**（成员顺序 `pcg32` → `seed`），若涉及二进制兼容需谨慎；
2. **`pcg32_random_raw` 的旋转移位**：`(-(int)rot) & 31` 的 `& 31` 是**必需的**——`rot` 可为 0，`-0 = 0` 合法；但若不加掩码，`rot` 在 `xorshifted << (-(int)rot)` 中可能产生移位 ≥ 32 或负数，触发未定义行为；
3. **`high << 32` 只在 `uint64_t` 下安全**：`high` 必须是 64 位无符号，若误用 32 位类型，左移 32 位直接 UB；
4. **`static_cast<int64_t>` 是有符号位模式重解释**：结果可能是负数——`operator()()` 的「全范围」指位模式全覆盖，不是「非负」。需要非负随机数时用 `operator()(0, INT64_MAX)` 或自行掩码高位；
5. **`max - min` 的有符号溢出**：`pcg64_random_range` 中 `max - min` 在「全宽区间」场景溢出（UB 理论风险），依赖 `range == 0` 分支兜底；**调用方应避免**传「数学全宽」组合（如 `INT64_MIN, INT64_MAX`），改用默认 `operator()()` 表达全范围意图；
6. **非线程安全**：`g_pcg32` 状态读写无保护，多线程共享同一实例会破坏序列且数据竞争；每个线程应持独立实例（或加锁）；
7. **自动种子不可复现**：调试随机 bug 时若需要复现，改用显式种子构造并记录种子值；
8. **预热不可省**：省略 `pcg32_random_raw()` 预热会导致前几个输出与 `state` 相关性过强（尤其 `state=0` 起步时），统计质量打折。

## 五、模块运行链路

### 5.1 事件终端密钥生成完整链路

```
【初始化】Event_Terminal 构造
  ① key_generator{}（默认构造 Random_Generator）
       └─ pcg32_seed_init()
             ├─ ns = high_resolution_clock 纳秒
             ├─ t  = std::time(nullptr)
             ├─ seed = ns ^ t ^ (++counter)
             ├─ state = 0; inc = (seed<<1)|1
             └─ 预热 1 次

【密钥生成】Event_Terminal::acl_key_gen()
  ① for(;;)
       ├─ key_generator()                          ← operator()()
       │     ├─ high = pcg32_random_raw()          ← LCG推进 + XSH + RR
       │     ├─ low  = pcg32_random_raw()
       │     └─ return (int64_t)((high<<32)|low)
       ├─ 结果 == 0 ? ──是──► 继续循环（重试）
       └─ 结果 != 0 ? ──► acl_key = 结果; return 结果

【权限校验】Event_Terminal::attach/interact/send/query/clear
  ① 比对调用方传入 acl_key 与内部 acl_key
  ② 匹配 → 放行；不匹配 → 拒绝（返回 false）
```

### 5.2 区间随机典型链路（游戏逻辑示例，预留）

```
Random_Generator rng(20260926);        // 显式种子，可复现
int32_t gold = rng(10, 50);            // 掉落金币 [10,50]
double  crit  = rng(0, 1000) / 1000.0; // 千分级暴击率
```

内部路径：`operator()(min,max)` → `pcg64_random_range` →（乱序交换）→（宽度特判）→ 拒绝采样循环 → `min + r % range`。

### 5.3 依赖方向汇总

```
Event_Terminal（core/event）
        │  持有 Random_Generator 实例
        │  调用 operator()() 生成 acl_key
        ▼
Random_Generator（tools/Random）
        ├── 内部：g_pcg32（state/inc）、pcg32_random_raw、pcg64_random_range
        ├── 依赖：std::chrono::high_resolution_clock（自动种子）
        ├── 依赖：std::time（自动种子）
        └── 依赖：common/前置头文件包含.h（标准库头）
```

结论：`Random_Generator` 是**自包含的基础工具模块**，仅依赖标准库；与引擎唯一耦合点是 `Event_Terminal` 的密钥生成。重开发时保持四个公开方法签名与 PCG 常数不变，即可无缝替换实现。
