## 一、模块功能（该模块做什么，解决什么问题，服务谁）

### 1.1 模块定位

四叉树（Quadtree）是「白银纪元」游戏引擎引擎层**空间分区体系**中的核心基础容器。它位于 `引擎层\src\core\spatial\partition\Quadtree\` 目录，为引擎提供"**以区块（chunk）为单位管理二维空间数据**"的能力。

在引擎的空间体系分层中，四叉树处于"最内层的格子管理器"位置：

```
碰撞模块（Collision_Proxy 等业务层）
        │  调用
        ▼
┌─────────────────────────────────┐
│  Quadtree_Manager（四叉树管理器）  │  ← 管理 N 棵四叉树的"调度层"
└─────────────────────────────────┘
        │  调用
        ▼
┌─────────────────────────────────┐
│     Quadtree（四叉树，本模块）      │  ← 管理单个方形区域的"容器层"
└─────────────────────────────────┘
        │  依赖
        ▼
┌─────────────────────────────────┐
│  坐标类型（Point2i/l/d, Rect2i/l/d）│  ← 公共基础类型
└─────────────────────────────────┘
```

四叉树**本身不负责多棵树之间的调度、合并、去重**——那是 `Quadtree_Manager` 的职责；四叉树**只负责"一棵树"内部的区块寻址、范围检索、树自身扩大与销毁**。

### 1.2 解决的核心问题

四叉树解决以下问题：

1. **大世界区块化管理**：将一片"方形区域"按 4 叉递归均分，直到最小区块单元（`block_size`，默认 16）大小。区域中任意坐标点都能在 O(log₄(size/block_size)) 级数内定位到唯一区块（`block_seek`）。
2. **单点/范围快速检索**：既能查询"某坐标所属区块"（`block_seek`），也能查询"与某矩形范围相交的所有区块"（`range_seek`），后者通过显式栈迭代实现，避免深递归导致栈溢出。
3. **树可原地扩大**：当查询坐标超出当前树管辖范围时，四叉树支持"**原地扩大**"（`tree_expand`），把当前根节点下挂的子节点整体下沉一层，使树的边长翻倍（`size *= 2`），从而动态覆盖更大的区域——这是"世界可以无限扩张"的基础。
4. **扩大权限受控**：四叉树不擅自扩大，而是通过 `std::function<bool(Point2d root, Point2l target)> callback` 回调，向"上级管理对象"（即 Quadtree_Manager）申请扩大权限；上级批准后四叉树才执行扩大，从而在多棵树并存的场景下避免树之间相互重叠/冲突。
5. **与坐标类型解耦**：树的内部几何运算全部走 64 位整数（`Point2l`/`Rect2l`），对外暴露的区块中心坐标则回落到 `Point2d`（double）。这样既保证边长可配置到 `INT_MAX` 以上不溢出（前序版次 fa8459a 的 64 位化成果），又保持与上层浮点坐标接口的兼容。

### 1.3 服务谁

- **直接服务对象**：`Quadtree_Manager`（四叉树管理器）。管理器持有若干棵 `Quadtree`，负责创建、卸载、合并、扩大决策；四叉树把"扩大权限"通过回调上交给管理器裁决。
- **间接服务对象**：碰撞模块等业务层。业务层只与 `Quadtree_Manager` 打交道，通过管理器的 `seek`/`seek(范围)` 间接触达四叉树的 `block_seek`/`range_seek`。
- **底层依赖**：坐标类型（`引擎层/src/core/spatial/common/core/坐标类型.h`）提供的 `Point2i/Point2l/Point2d` 与 `Rect2i/Rect2l/Rect2d`；预编译头 `common/前置头文件包含.h` 提供的标准库与 `std::format` 等。

### 1.4 本版次（089b070）要点总览

1. **64 位尺寸层契约**（承前序版次 fa8459a）：`recur_record::node_range` 使用 `Rect2l`（int64 矩形）；回调 `callback` 的目标坐标使用 `Point2l`（int64 点）；`recur_direct_calcu` 以双精度求节点中点避免单精度损失；`child_node_range_calcu` 采用 `left + (right - left) / 2` 形式避免负数向零截断；`target_range_format` 的取模按 64 位整数进行并做了负数安全处理。
2. **Node 联合体双活成员**：`Node` 是联合体，`ptr_child[4]`（中间节点）与 `leaf`（叶子数据，类型 `T`）复用同一内存；构造时按 `Node_type` 用 placement new 激活对应成员。
3. **range_seek 用显式栈迭代而非递归**：采用 `std::vector<recur_record>` 作为模拟栈 + `std::vector<int> recur_path` 记录当前路径，主循环驱动遍历，规避深递归风险。
4. **block_seek 的可行性分析三态（0/1/2）**：`point_seekable_analyse` 返回 0（不可行，终止）/ 1（可能可行，继续扩大尝试）/ 2（可行，直接寻址）。
5. **既有编译器告警**：`point_seekable_analyse` 存在历史遗留的 warning C4715（非所有路径返回值），本版次未消除，属于既有已知项（详见 §4.2.7）。

### 2.2 构造与析构

```cpp
Quadtree(const uint64_t& size = 256, const Point2d& root = { 0.5,0.5 });
~Quadtree(void);
```

**构造行为**：将传入的 `size` 写入 `state.size`，`root` 写入 `state.root`。其余状态字段使用默认值：`max_size = 2^63 = 9223372036854775808`（`树状态下限`字段默认），`block_size = 16`。**注意**：构造时并不分配任何节点内存，`root` 联合体以默认 `MIDDLE` 模式构造（`ptr_child` 四槽位置空），整棵树是"空壳"，直到第一次 `block_seek`（stable 模式）或 `tree_expand` 才真正分配子节点。

**析构行为**：先调用 `recur_level_calcu` 求出树的总递归级数 `max_level`，然后以根节点 `root` 为起点，对 `NW/NE/SW/SE` 四个方向依次调用 `child_node_recur`（取得子节点指针，stable=false 不分配）+ `unload(1, max_level, ptr_next)` 递归释放子树，最后回到根节点（根节点本身是类内联合体成员，无需 delete）。注意根节点内部如果激活的是 `leaf`（理论上根恒为 MIDDLE，此处为健壮性考虑）不会额外释放，因为 `~Node()` 为空实现。

### 2.3 设置类接口

```cpp
void set_block_size(const uint64_t& size);
void set_max_size(const uint64_t& size);
void set_callback_manage(const std::function<bool(Point2d root, Point2l target)>& cb);
```

- `set_block_size(const uint64_t& size)`：**参数** `size` 为最小区块单元边长。**行为**：写入 `state.block_size`。区块尺寸影响递归级数（`recur_level_calcu` 的循环终止条件 `tree_size / 2 >= block_size`）与 `target_range_format` 的网格对齐步长。
- `set_max_size(const uint64_t& size)`：**参数** `size` 为四叉树边长上限。**行为**：写入 `state.max_size`。当 `state.size >= state.max_size` 时，`point_seekable_analyse` 判定"不可再扩大"，从而限制树的最大扩张幅度。
- `set_callback_manage(const std::function<bool(Point2d root, Point2l target)>& cb)`：**参数** `cb` 为扩大权限回调，签名 `bool(Point2d root, Point2l target)`：`root` 为当前树根节点坐标（double），`target` 为待纳入目标坐标（int64）。**行为**：注册到成员 `callback`。**返回值语义**：回调返回 `true` 表示上级批准扩大，返回 `false` 表示拒绝；若回调为空（未注册），四叉树在 `state.size < state.max_size` 时自行扩大（无权限管控）。

### 2.4 查询类接口

```cpp
void block_seek(tree_chunk_data<T>*& receiver, const Point2l& target, bool stable);
void range_seek(std::vector<tree_chunk_data<T>*>& receiver, const Rect2l& target_range, bool stable);
```

- `block_seek(tree_chunk_data<T>*& receiver, const Point2l& target, bool stable)`：
  - **receiver**：输出参数（引用），调用前可为 `nullptr`；查询成功后被指向一个 `tree_chunk_data<T>`（若原为空则内部 `new` 一个）。
  - **target**：待查询坐标，`Point2l`（int64），来自上层范围推导，按 64 位接收。
  - **stable**：稳定模式开关。`stable==true` 时，查询过程中缺失的节点会即时分配（`child_node_recur` 中 `new`），保证查询结果必定存在；`stable==false` 时不分配，若路径上节点缺失则返回（receiver 保持原值）。
  - **行为**：先做可行性分析（`point_seekable_analyse` 三态循环，可能触发扩大），再沿单一路径逐级下钻 `recur_level_max` 次，最终把 `receiver->ptr_data` 指向最小区块节点的 `leaf`，并把 `receiver->node` 置为区块中心（由 64 位范围求中点的 double 坐标）。
- `range_seek(std::vector<tree_chunk_data<T>*>& receiver, const Rect2l& target_range, bool stable)`：
  - **receiver**：输出参数，调用方传入空 vector，函数向其中 `push_back` 每个命中的 `tree_chunk_data<T>*`（函数内部 new）。
  - **target_range**：待查询矩形范围，`Rect2l`（int64）。
  - **stable**：稳定模式。`true` 时缺失节点即时分配；`false` 时只返回已存在节点。
  - **行为**：先 `target_range_format` 格式化目标范围，再 `range_seekable_analyse` 分析并可能扩大树，然后用显式栈迭代遍历所有与"可查询范围"相交的叶子区块，逐个创建 `tree_chunk_data<T>` 并 push 进 receiver。
  - **注意**：range_seek 可能产生 **重复区块**（相邻多次查询边界重叠时，同一坐标的区块可能被重复创建/返回）——去重是上层 `Quadtree_Manager` 的职责（其用 `target_excel` 布尔表去重）。

### 2.5 读取与扩大接口

```cpp
const tree_state& tree_state_get(void);
bool tree_expand(void);
```

- `tree_state_get(void)`：**返回** `const tree_state&`，即成员 `state` 的常引用。调用方可通过它读取 `root / size / max_size / block_size` 四项。
- `tree_expand(void)`：**返回** `bool`，扩大成功返回 `true`，内存分配失败返回 `false`。**行为**：原地扩大——分配 4 个新的 `MIDDLE` 节点，把原根节点 4 个槽位（`NW/NE/SW/SE`）指向的子树分别挂到新节点的"反方向槽位"（`NW→SE、NE→SW、SW→NE、SE→NW`），再把 4 个新节点挂到根节点，最后 `state.size *= 2`。此操作不改变根坐标、不重建数据，属于 O(1) 时间复杂度的"向上加一层"。

### 2.6 公开底层计算工具（供 Quadtree_Manager 跨对象调用）

这三个函数声明在类定义的 `public:` 段（注释"———— 底层计算工具 ————"之下），**设计意图是暴露给 `Quadtree_Manager` 复用的几何工具**：

```cpp
void manage_range_calcu(Rect2l& receiver, const Point2d& root, const uint64_t tree_size);
void target_range_format(Rect2l& target_range, const Point2d& root, const uint64_t block_size);
Point2d seekable_range_calcu(const Rect2l& target_range, Rect2l& seekable_range);
```

- `manage_range_calcu(Rect2l& receiver, const Point2d& root, const uint64_t tree_size)`：
  - **receiver**：输出参数，接收计算出的管理范围（int64 矩形）。
  - **root**：树根坐标（double，允许小数，默认 0.5,0.5 消除根节点中心偏移）。
  - **tree_size**：树边长（可来自 `state.size` 或其他树的 `tree_record::size`）。
  - **行为**：`half_span = tree_size / 2 - 1`；`left = root.X - 0.5 - half_span`、`right = root.X + 0.5 + half_span`、`down = root.Y - 0.5 - half_span`、`up = root.Y + 0.5 + half_span`（先 `static_cast<int64_t>` 截断根坐标偏移，再以 64 位整数运算，避免边长超过 INT_MAX 时溢出）。
- `target_range_format(Rect2l& target_range, const Point2d& root, const uint64_t block_size)`：
  - **target_range**：输入输出参数，原地被修改为对齐后的范围。
  - **行为**：以 `root` 的 ±0.5 网格原点为基准，将四条边界向 `block_size` 网格对齐：左/下边界向下取整对齐、右/上边界向上取整对齐，保证格式化后的范围**严格包含**内部完整区块。内部使用负数安全取模 lambda：`auto mod = [](int64_t a, int64_t b) { int64_t r = a % b; return r < 0 ? r + b : r; };`。`block_size == 0` 时直接 return（防止除零）。
- `seekable_range_calcu(const Rect2l& target_range, Rect2l& seekable_range)`：
  - **target_range**：目标范围（输入）。
  - **seekable_range**：输入输出参数，初始为树的管理范围，函数将其裁剪为目标范围与树范围的交集。
  - **返回** `Point2d`：扩大标记 `coord_register`。若目标范围某侧越出树范围，则对应轴坐标被重置为树边界坐标（表示"这里超界了"）；若完全在树内，返回初始值 `state.root`（表示无需扩大）。上层通过判断"返回值 == state.root"决定是否触发扩大。

## 三、模块内部架构（内部数据结构、文件组织、设计分层）

### 3.1 内部数据结构

四叉树的内部数据结构集中在 `四叉树.h`（类内嵌套定义）与 `函数预声明.h`（模块级结构体）中。

#### 3.1.1 节点类型枚举 `Node_type`

```cpp
enum Node_type
{
    MIDDLE,   // 中间节点（拥有 4 个子节点槽位）
    LEAF      // 叶子节点（承载数据 T）
};
```

#### 3.1.2 节点信息联合体 `union Node`（双活成员）

```cpp
union Node
{
    // 构造：按模式激活对应成员
    Node(const Node_type& mode = MIDDLE)
    {
        if (mode == MIDDLE)
            new (&ptr_child) Node* [4]();   // 激活 ptr_child 数组并零初始化（placement new）
        else if (mode == LEAF)
            new (&leaf) T();                // 激活 leaf 并默认构造 T
    }
    ~Node() {}                              // 析构为空：T 的析构由上层 unload 显式调用

    Node* ptr_child[4];                     // 中间节点：4 个子节点指针（NW/NE/SW/SE）
    T leaf;                                 // 叶子节点：区块数据
}root;                                       // 类内唯一联合体实例，即"根节点"
```

**关键设计**：`Node` 是 C++ 联合体，`ptr_child[4]` 与 `leaf` 复用同一块内存——中间节点不携带数据、叶子节点不携带子指针，二者互斥。构造时通过 placement new 显式激活目标成员，避免未激活成员访问未定义行为。根节点 `root` 恒以 `MIDDLE` 模式构造（默认参数），析构为空实现（叶子 `T` 的析构由 `unload` 中 `ptr_now->leaf.~T()` 显式完成）。

#### 3.1.3 查找区域分布情况枚举 `range_relation`

```cpp
enum range_relation
{
    PART_IN,    // 部分相交
    NONE_IN     // 完全不相交
};
```

> 注意：该枚举在 `四叉树.h` 中定义，但 089b070 版次的 `range_relation_get` 实际直接返回 `bool`（true=相交，false=不相交），该枚举在当前版本未被查询路径引用，属历史保留定义。

#### 3.1.4 节点递归方向枚举 `recur_direct`

```cpp
enum recur_direct { NW, NE, SW, SE };
```

方向顺序与数组下标一致（`NW=0, NE=1, SW=2, SE=3`），`ptr_child[4]` 与遍历 `for (int recur_direct = 0; recur_direct <= SE; recur_direct++)` 均依赖该约定。**方向语义**：以树中心为原点，NW=左上、NE=右上、SW=左下、SE=右下。

#### 3.1.5 节点递归记录结构体 `recur_record`

```cpp
struct recur_record
{
    Node* node;             // 节点指针（待恢复的父节点）
    Rect2l node_range{};    // 节点范围（64 位矩形！范围边界由树边长推导，边长可配置到 INT_MAX 以上，故一律使用 64 位整数承载，避免溢出）
    int recur_level = 0;    // 递归级别
};
```

`recur_record` 是 `range_seek` 显式栈迭代的"栈帧"：当某层存在多个可递归子节点时，把"父节点指针 + 父范围 + 当前级别"压栈，遍历完当前分支后弹栈恢复，继续处理其余分支。

#### 3.1.6 四叉树状态记录 `tree_state`（定义于 `函数预声明.h`）

```cpp
struct tree_state
{
public:
    Point2d root = { 0.5,0.5 };              // 根节点坐标（小数坐标，避免根节点中心偏移）
    uint64_t size = 256;                     // 四叉树大小（当前边长）
    uint64_t max_size = 9223372036854775808; // 大小上限，初始化 2 的 63 次方
    uint64_t block_size = 16;                // 最小区块单元大小
};
```

- `root` 使用 `Point2d`（double），默认 `{0.5, 0.5}` 是为了"**消除根节点中心偏移**"——让树管理范围落在整数网格中心（配合 `manage_range_calcu` 中的 `root.X ± 0.5` 抵消）。
- `max_size` 默认 `2^63` 表示"几乎不限高"（单棵树边长理论上可扩大到 2^63 量级）。
- `block_size` 默认 16：区块单元越小，递归级数越多，定位越精细。

#### 3.1.7 区块数据通信结构体 `tree_chunk_data<T>`（定义于 `函数预声明.h`）

```cpp
template<typename T>
struct tree_chunk_data
{
    tree_chunk_data() {}
    tree_chunk_data(float x, float y, T* ptr)
    {
        node.X = x;
        node.Y = y;
        ptr_data = ptr;
    }
    ~tree_chunk_data() {}

    Point2d node = { 0.5f, 0.5f };  // 使用 0.5f 强调 float 类型
    T* ptr_data = nullptr;           // 指向区块数据的指针
};
```

这是四叉树查询结果的**通信载体**：`node` 为区块中心坐标（double，默认 0.5f 强调其初始浮点语义），`ptr_data` 指向 `Node::leaf` 数据。`Quadtree_Manager` 用它在树与树之间搬运数据（`copy` 回调的 `receiver/transmiter` 参数类型）。

#### 3.1.8 扩大权限回调 `callback`

```cpp
// 外界上级管理对象回调管理方法 ---- 四叉树扩大行为权限申请
// 目标坐标取自范围推导结果，同样按 64 位整数通报

```

成员 `callback` 类型为 `std::function<bool(const Point2d&, const Point2l&)>`。`root` 为请求扩大的树根坐标（double），`target` 为待纳入目标坐标（int64）。由 `set_callback_manage` 注册。在 `Quadtree_Manager::quadtree_build` 中注册的 lambda 转发到 `tree_expand_approve`，实现"上级裁决扩大"。

### 3.3 设计分层

四叉树内部可划分为四层职责：

1. **状态层**（`state` 成员 + `tree_state`）：集中保存树的几何元数据（根坐标、当前边长、上限、区块单元），所有几何计算以 `state` 为输入。
2. **几何计算层**（`导航与范围计算.hpp`）：纯函数式工具——级数计算、方向判定、子范围划分、管理范围推导、范围格式化、交集判断、可查询范围裁剪。不触碰节点内存，可被管理器跨对象复用。
3. **结构维护层**（`节点创建与树扩大.hpp` + `unload`）：节点分配（`child_node_recur`）、树原地扩大（`tree_expand`）、递归销毁（`unload`/析构）。
4. **查询编排层**（`区块信息检索.hpp`）：可行性分析（单点三态/范围循环扩大）+ 寻址主流程（`block_seek` 单路径下钻、`range_seek` 显式栈遍历）。

数据流方向固定为：**查询编排层 → 可行性分析 →（必要时）扩大权限回调 → 结构维护层分配节点 → 几何计算层算范围**。

## 四、模块设计/实现细节

### 4.1 64 位尺寸层契约（承前序版次 fa8459a）

前序版次 fa8459a 将四叉树链路的"尺寸层"整体 64 位化，本版次沿用。该契约的要点：

1. **所有范围/坐标的推导计算一律用 `Rect2l`/`Point2l`（int64）**：树边长 `state.size` 可配置到 `INT_MAX` 以上，若用 32 位整数承载范围边界必然溢出，因此 `recur_record::node_range`、`block_seek::target`、`range_seek::target_range`、`manage_range_calcu::receiver` 全部为 64 位类型。
2. **中点计算用双精度**：`recur_direct_calcu` 中 `node_coord.X = (node.left + node.right) / 2.0;`——节点范围边界已达 64 位，用双精度求中点避免单精度在小数位上的精度损失。`block_seek`/`range_seek` 记录区块中心坐标时同样先以 `(left+right)/2.0` 双精度求中点，再回落 `float`/`double`。
3. **子范围划分避免负数向零截断**：`child_node_range_calcu` 采用 `mid_x = parent_range.left + (parent_range.right - parent_range.left) / 2`（而非 `(left+right)/2`），因为 `right - left` 恒为正，避免负数情况下 `(left+right)/2` 向零截断导致的不对称分裂。
4. **回调目标坐标 64 位通报**：`callback` 签名 `bool(Point2d, Point2l)` 的 `target` 参数按 int64 传递，保证上级管理层（Quadtree_Manager）拿到完整坐标做扩大决策。
5. **取模负数安全**：`target_range_format` 的自定义 `mod` lambda 保证对负数的取模结果非负，避免范围格式化在负数坐标下错位。

### 4.2 关键算法流程

#### 4.2.1 递归级数计算 `recur_level_calcu`

```cpp
void Quadtree<T>::recur_level_calcu(int& address_series)
{
    for (uint64_t tree_size = state.size; (tree_size /= 2) >= state.block_size;)
        address_series++;
}
```

**算法**：从当前边长 `state.size` 开始，每次除以 2，直到商小于 `block_size`，计数累加。得到的是"从根节点向下递归到最小区块单元所需的步数"。例如 `size=256, block_size=16`：256→128→64→32→16（≥16 计数 4 次）→8（<16 停），级数=4，正好对应 256/16=16 个叶子区块的二分深度 log₂(16)=4。

> 注意：循环条件是"除完再比"，即 `tree_size` 先 `/2` 再与 `block_size` 比较。级数即"边长能容纳的 2 的幂次数"。

#### 4.2.2 递归方向计算 `recur_direct_calcu`

```cpp
void Quadtree<T>::recur_direct_calcu(const Point2l& target, const Rect2l& node, int& recur_direct)
{
    Point2d node_coord = {};
    node_coord.X = (node.left + node.right) / 2.0;
    node_coord.Y = (node.down + node.up) / 2.0;

    if (target.X < node_coord.X && target.Y > node_coord.Y)      recur_direct = NW;
    else if (target.X > node_coord.X && target.Y > node_coord.Y) recur_direct = NE;
    else if (target.X < node_coord.X && target.Y < node_coord.Y) recur_direct = SW;
    else if (target.X > node_coord.X && target.Y < node_coord.Y) recur_direct = SE;
}
```

**算法**：计算节点范围中点（双精度），比较目标坐标落在哪个象限。**边界情况**：注释明确指出"因节点坐标为浮点坐标，而查找坐标为整数坐标，因而不存在坐标相等情况"——target 是 int64，中点可能是 .5 尾数，因此 `target == node_coord` 不会发生，四个分支必有且仅有一个命中；若出现理论上的相等，四个分支均不命中，`recur_direct` 保持调用前的旧值（调用处通常已用 0 初始化，风险可控）。

#### 4.2.3 子节点范围计算 `child_node_range_calcu`

```cpp
void Quadtree<T>::child_node_range_calcu(const int& recur_direct, Rect2l& child_range,
    const Rect2l& parent_range)
{
    int64_t mid_x = parent_range.left + (parent_range.right - parent_range.left) / 2;
    int64_t mid_y = parent_range.down + (parent_range.up - parent_range.down) / 2;

    if (recur_direct == NW)
    {
        child_range.left  = parent_range.left;  child_range.right = mid_x;
        child_range.up    = parent_range.up;    child_range.down  = mid_y + 1;
    }
    else if (recur_direct == NE)
    {
        child_range.left  = mid_x + 1;          child_range.right = parent_range.right;
        child_range.up    = parent_range.up;    child_range.down  = mid_y + 1;
    }
    else if (recur_direct == SW)
    {
        child_range.left  = parent_range.left;  child_range.right = mid_x;
        child_range.up    = mid_y;              child_range.down  = parent_range.down;
    }
    else if (recur_direct == SE)
    {
        child_range.left  = mid_x + 1;          child_range.right = parent_range.right;
        child_range.up    = mid_y;              child_range.down  = parent_range.down;
    }
}
```

**算法**：按中分线把父范围四等分（**闭区间**约定）。NW=左上（`[left,mid_x]×[mid_y+1,up]`）、NE=右上、SW=左下、SE=右下。四个子范围恰好无缝且不重叠地拼满父范围。

> 边界注意：`mid_x + 1` 在 `right == left + 1`（即宽度为 2 的最小区块）时会得到 `left+1`，不会越界；但理论上若递归深度超过 `size/block_size` 的 2 的幂次（正常不会），子范围可能退化为空。工程上递归级数由 `recur_level_calcu` 精确控制，不会发生退化。

#### 4.2.4 管理范围计算 `manage_range_calcu`

```cpp
void Quadtree<T>::manage_range_calcu(Rect2l& receiver, const Point2d& root, const uint64_t tree_size)
{
    int64_t half_span = static_cast<int64_t>(tree_size / 2 - 1);
    receiver.left  = static_cast<int64_t>(root.X - 0.5) - half_span;
    receiver.right = static_cast<int64_t>(root.X + 0.5) + half_span;
    receiver.down  = static_cast<int64_t>(root.Y - 0.5) - half_span;
    receiver.up    = static_cast<int64_t>(root.Y + 0.5) + half_span;
}
```

**算法**：`half_span = size/2 - 1`。根坐标 `root` 的 `±0.5` 偏移先被抵消（因为根坐标是整数网格中心 +0.5），再加减半跨度。以默认 `root={0.5,0.5}, size=256` 为例：`half_span=127`，`left=0-127=-127`、`right=1+127=128`、`down=-127`、`up=128`，管理范围为 `[-127,128]×[-127,128]`，宽高各 256（闭区间含端点），恰好覆盖整数坐标网格。

**契约**：该函数可传入任意 `root` 与 `tree_size`（不限于本树），因此被 `Quadtree_Manager` 跨树调用（如 `quadtree_inclusion_seek` 用它计算每棵候选树边界、`new_tree_range_calcu` 用它计算新树初始范围）。

#### 4.2.5 待查询范围格式化 `target_range_format`

```cpp
void Quadtree<T>::target_range_format(Rect2l& target_range, const Point2d& root, const uint64_t block_size)
{
    if (block_size == 0)   // 区块尺寸非正防御（为零时取模抛除零异常）
        return;

    auto mod = [](int64_t a, int64_t b) { int64_t r = a % b; return r < 0 ? r + b : r; };
    int64_t size_unit = static_cast<int64_t>(block_size);

    int64_t left_rem = mod(target_range.left  - static_cast<int64_t>(root.X + 0.5), size_unit);
    target_range.left -= left_rem;                       // 左边界向下对齐

    int64_t right_rem = mod(target_range.right - static_cast<int64_t>(root.X - 0.5), size_unit);
    target_range.right += (right_rem == 0 ? 0 : size_unit - right_rem);  // 右边界向上对齐

    int64_t up_rem = mod(target_range.up - static_cast<int64_t>(root.Y - 0.5), size_unit);
    target_range.up += (up_rem == 0 ? 0 : size_unit - up_rem);           // 上边界向上对齐

    int64_t down_rem = mod(target_range.down - static_cast<int64_t>(root.Y + 0.5), size_unit);
    target_range.down -= down_rem;                       // 下边界向下对齐
}
```

**算法**：以 `root±0.5` 为网格原点，把范围四边对齐到 `block_size` 的整数倍网格。左/下取"floor 对齐"（向内收），右/上取"ceil 对齐"（向外扩），从而保证格式化后范围**严格包含**内部完整区块。负数安全取模 lambda 确保 `left_rem` 等非负。

**边界**：`block_size == 0` 直接返回（防止 `% 0` 崩溃）；`block_size` 非 2 的幂时仍能正确对齐（取模是对 `block_size` 而非 2 的幂）。

#### 4.2.6 范围关系判断 `range_relation_get` 与可查询范围 `seekable_range_calcu`

```cpp
bool Quadtree<T>::range_relation_get(const Rect2l& target_range, const Rect2l& node_range)
{
    // 无交集判断：目标整体在节点某一侧（左、右、下、上）
    if (t_right < n_left || t_left > n_right || t_up < n_down || t_down > n_up)
        return false;
    else
        return true;   // 剩余情况即为相交
}
```

闭区间矩形相交判定：只要"目标右 < 节点左 || 目标左 > 节点右 || 目标上 < 节点下 || 目标下 > 节点上"任一成立即不相交，否则相交（**含边界相切**）。

```cpp
Point2d Quadtree<T>::seekable_range_calcu(const Rect2l& target_range, Rect2l& seekable_range)
{
    Point2d coord_register = state.root;   // 是否申请扩大标记

    if (target_range.left  < seekable_range.left)  coord_register.X = seekable_range.left;
    else                                          seekable_range.left  = target_range.left;
    if (target_range.right > seekable_range.right) coord_register.X = seekable_range.right;
    else                                          seekable_range.right = target_range.right;
    if (target_range.up    > seekable_range.up)    coord_register.Y = seekable_range.up;
    else                                          seekable_range.up    = target_range.up;
    if (target_range.down  < seekable_range.down)  coord_register.Y = seekable_range.down;
    else                                          seekable_range.down  = target_range.down;

    return coord_register;
}
```

**算法**：逐边比较目标范围与可查询（树）范围：目标边在树内则把树边"缩小"为目标边（取交集）；目标边越出树边则保留树边并记录越界坐标到 `coord_register`。返回 `coord_register`：若等于 `state.root` 表示完全在树内（无需扩大）；否则其 X/Y 分量被置为越界处的树边界坐标（double，由 64 位边界推导）。

#### 4.2.7 单点查询可行性分析 `point_seekable_analyse`（三态 + 既有 C4715 告警）

```cpp
/* 函数逻辑：
          0，代表分析已经结束，查找不可行
          1，代表分析正在进行，查找可能可行
          2，代表分析已经结束，查找可行
*/
int Quadtree<T>::point_seekable_analyse(const Point2l& target)
{
    auto& root = state.root;
    Rect2l tree_range{};
    manage_range_calcu(tree_range, state.root, state.size);

    if (target.X < tree_range.left || target.X > tree_range.right
        || target.Y > tree_range.up || target.Y < tree_range.down)
    {
        if (state.size >= state.max_size)         // 已到上限：不可扩大
        {
            if (callback) callback(root, target); // 通报上级（仅通报，不申请）
            return 0;
        }
        else if (state.size < state.max_size)     // 未到上限：申请扩大
        {
            if (callback)
                if (!callback(root, target))      // 申请被拒
                    return 0;
            if (tree_expand())                    // 扩大成功
            {
                manage_range_calcu(tree_range, state.root, state.size);
                if (target 越出 新tree_range)     // 一次扩大仍不够
                    return 1;                     // 返回"继续尝试"
                else
                    return 2;                     // 已包含，可行
            }
            else
                return 0;                         // 扩大失败（内存不足）
        }
    }
    else
        return 2;                                 // 坐标已在树内，直接可行
}
```

**三态语义**：
- `2`：目标坐标已在树管理范围内，直接寻址可行；
- `1`：目标越界，且一次扩大后仍越界（超长距离），需 `block_seek` 外层循环继续尝试扩大；
- `0`：不可行终止——已到 `max_size` 上限、扩大申请被上层拒绝、或 `tree_expand` 内存分配失败。

**既有 warning C4715（非所有路径返回值）**：编译器对本函数报告 C4715 告警（"并非所有控件路径都能返回值"）。从源码逻辑上审视：外层 `if(越界)` 为真时，内层 `if(size>=max_size) / else if(size<max_size)` 对无符号 `uint64_t` 构成互补完备分支、均含返回语句；外层为假时返回 2——逻辑上所有路径皆有返回值。该告警源于历史版本遗留的分支结构（或编译器对复杂嵌套分支的路径分析保守），本版次**未消除**，属于既有已知项。重开发时若遇到编译告警 C4715，属预期现象，不影响运行语义；如需消除可补一个末尾 `return 0;` 兜底（但会改变"理论不可达路径"的可读性，需谨慎）。

#### 4.2.8 范围查询可行性分析 `range_seekable_analyse`

```cpp
void Quadtree<T>::range_seekable_analyse(const Rect2l& format_range, Rect2l& seekable_range)
{
    for (;;)
    {
        manage_range_calcu(seekable_range, state.root, state.size);   // 树当前管理范围
        Point2d expand_register = seekable_range_calcu(format_range, seekable_range);

        if (expand_register != state.root)          // 需要扩大
        {
            if (callback)
            {
                if (callback(state.root, point_to_l(expand_register)))
                {
                    if (!tree_expand()) break;      // 扩大失败
                }
                else break;                          // 申请被拒
            }
            else if (state.size < state.max_size)
            {
                if (!tree_expand()) break;
            }
            if (state.size >= state.max_size) break; // 已达上限
        }
        else
            break;                                   // 树已覆盖目标范围
    }
}
```

**算法**：死循环内反复：求树当前管理范围 → 求与目标范围的交集与扩大标记 → 若标记指示越界则（经回调批准或自行）扩大一次，重新计算；直到树范围完全覆盖目标（`expand_register == state.root`）或达上限/被拒/分配失败。循环结束时 `seekable_range` 即为"目标 ∩ 树范围"的有效可查询范围。

#### 4.2.9 单点区块查询主流程 `block_seek`

```cpp
void Quadtree<T>::block_seek(tree_chunk_data<T>*& receiver, const Point2l& target, bool stable)
{
    uint64_t max_size = state.max_size;
    int exam_time_max = 1;
    if (state.size <= 0) return;                       // 树尺寸为零防御
    for (; (max_size /= 2) / state.size > 1;)          // 最大检测次数 = 可扩大轮数
        exam_time_max++;

    for (int check_time = 0; check_time < exam_time_max; check_time++)
    {
        int next_step = point_seekable_analyse(target);
        if (next_step == 2) break;                     // 可行
        else if (next_step == 1) continue;             // 继续扩大
        else if (next_step == 0) return;               // 不可行，终止
    }

    int recur_level_max = 0;
    recur_level_calcu(recur_level_max);                // 寻址总级数

    Node* child_node = &root;
    Rect2l node_range{};
    manage_range_calcu(node_range, state.root, state.size);
    int recur_direct = 0;

    for (int recur_level_now = 0; recur_level_now < recur_level_max; recur_level_now++)
    {
        recur_direct_calcu(target, node_range, recur_direct);
        if (recur_level_now < recur_level_max - 1)
            child_node_recur(child_node, recur_direct, MIDDLE, stable);   // 中间节点
        else if (recur_level_now == recur_level_max - 1)
            child_node_recur(child_node, recur_direct, LEAF, stable);     // 叶子节点
        if (child_node == nullptr) return;             // 分配失败（非 stable）

        Rect2l old_range = node_range;
        child_node_range_calcu(recur_direct, node_range, old_range);      // 下钻范围
    }

    if (receiver == nullptr)                           // 分配结果载体
    {
        receiver = new(std::nothrow) tree_chunk_data<T>;
        if (receiver == nullptr) return;
    }
    receiver->ptr_data = &(child_node->leaf);
    receiver->node.X = static_cast<double>(node_range.left + node_range.right) / 2.0;
    receiver->node.Y = static_cast<double>(node_range.down + node_range.up) / 2.0;
}
```

**流程**：
1. **检测次数预算**：`exam_time_max` 由 `max_size` 连续除以 2 直至 `(max_size/2)/state.size <= 1` 计数得到，即"理想情况下树最多可扩大到最大"所需的轮数；循环末尾额外余量保证管理层知晓查询失败。
2. **可行性分析循环**：反复调用 `point_seekable_analyse`，遇 0 终止、1 继续、2 跳出。
3. **单路径下钻**：从根节点出发，每层用 `recur_direct_calcu` 定方向、`child_node_recur` 推进指针（中间层建 MIDDLE、最末层建 LEAF，仅 stable 分配）、`child_node_range_calcu` 收窄范围，共 `recur_level_max` 次。
4. **记录结果**：把最末层叶子节点的 `leaf` 地址写入 `receiver->ptr_data`，区块中心坐标取范围中点（双精度）写入 `receiver->node`。

#### 4.2.10 范围区块查询主流程 `range_seek`（显式栈迭代）

```cpp
void Quadtree<T>::range_seek(std::vector<tree_chunk_data<T>*>& receiver,
    const Rect2l& target_range, bool stable)
{
    Rect2l seekable_range{};
    Rect2l format_range = target_range;
    target_range_format(format_range, state.root, state.block_size);   // ① 格式化
    range_seekable_analyse(format_range, seekable_range);              // ② 扩大至可查

    int recur_level_max = 0;
    recur_level_calcu(recur_level_max);

    std::vector<recur_record> stack{};                 // ③ 模拟栈（显式迭代关键）
    std::vector<int> recur_path(recur_level_max, NW);  //    当前路径每层方向

    Node* parent_node = &root;
    Rect2l parent_range{};
    manage_range_calcu(parent_range, state.root, state.size);
    Rect2l child_range{};

    for (int recur_level_now = 0; recur_level_now < recur_level_max;)  // ④ 主循环
    {
        auto& recur_direct = recur_path[recur_level_now];
        int recursive_num = 0;
        bool is_direct_record = false;

        // ④a 在当前层统计与可查询范围相交的子节点数，记录首个方向
        for (int now_direct = recur_direct; now_direct <= SE; now_direct++)
        {
            child_node_range_calcu(now_direct, child_range, parent_range);
            if (range_relation_get(seekable_range, child_range)) {
                recursive_num++;
                if (is_direct_record == false) { recur_direct = now_direct; is_direct_record = true; }
            }
        }

        // ④b 若可递归子节点 >1 且非叶子层，压栈当前帧（后续回来处理其余分支）
        if (recursive_num > 1 && recur_level_now != recur_level_max - 1)
            recur_stack_operate(stack, parent_node, parent_range, recur_level_now, true);

        if (recur_level_now < recur_level_max - 1)     // ④c 中间层：进入首个子节点
        {
            bool is_pop_back = true;
            bool entered = child_node_recur(parent_node, recur_direct, MIDDLE, stable);
            if (entered) {
                Rect2l old_range = parent_range;
                child_node_range_calcu(recur_direct, parent_range, old_range);
                recur_level_now++;
                is_pop_back = false;
            }
            if (recursive_num > 1) { recur_direct++; if (entered) is_pop_back = false; }
            else recur_direct = NW;                    // 本层无剩余方向，重置

            if (is_pop_back == true && stack.size() == 0) break;        // 遍历结束
            else if (is_pop_back == true) recur_stack_operate(stack, parent_node, parent_range, recur_level_now, false);  // 弹栈回溯
        }
        else if (recur_level_now == recur_level_max - 1)   // ④d 叶子层：一次性取完本层全部命中叶子
        {
            for (; recur_direct <= SE; recur_direct++)
            {
                child_node_range_calcu(recur_direct, child_range, parent_range);
                if (!range_relation_get(seekable_range, child_range)) continue;

                Node* child_node = parent_node;
                if (!child_node_recur(child_node, recur_direct, LEAF, stable)) continue;
                auto* new_data = new(std::nothrow) tree_chunk_data<T>(
                    static_cast<float>((child_range.left + child_range.right) / 2.0),
                    static_cast<float>((child_range.up + child_range.down) / 2.0),
                    &child_node->leaf);
                if (new_data == nullptr) return;
                else receiver.push_back(new_data);
            }
            recur_direct = NW;
            if (stack.size() == 0) break;              // 栈空，结束
            else recur_stack_operate(stack, parent_node, parent_range, recur_level_now, false);
        }
    }
}
```

**显式栈迭代 vs 递归**：`range_seek` 用 `std::vector<recur_record> stack` 模拟调用栈 + `std::vector<int> recur_path` 记录每层当前方向，主循环驱动深度优先遍历。**不使用递归**，规避了"范围覆盖大量区块时递归深度过大导致栈溢出"的风险。栈帧保存"父节点指针 + 父范围 + 级别"，弹栈后从 `recur_path` 恢复的下一个方向继续。

**遍历语义**：每层先统计与可查询范围相交的子节点数并记录首个方向；若不止一个方向，说明本层还有未走的分支，压栈备忘；进入首个方向下钻；到达叶子层后一次性把该父节点下全部命中的叶子区块收集（`new` 出 `tree_chunk_data<T>` 填入中心坐标与 leaf 指针）；返回时弹栈恢复，继续处理备忘分支，直到栈空。

#### 4.2.11 树原地扩大 `tree_expand` 与子节点递归 `child_node_recur`

```cpp
bool Quadtree<T>::tree_expand(void)
{
    Node* ptr_NW_new = new(std::nothrow) Node(MIDDLE);
    Node* ptr_NE_new = new(std::nothrow) Node(MIDDLE);
    Node* ptr_SW_new = new(std::nothrow) Node(MIDDLE);
    Node* ptr_SE_new = new(std::nothrow) Node(MIDDLE);
    if (ptr_NW_new == nullptr || ptr_NE_new == nullptr || ptr_SW_new == nullptr || ptr_SE_new == nullptr)
    {
        delete ptr_NW_new; delete ptr_NE_new; delete ptr_SW_new; delete ptr_SE_new;  // 释放已分配
        return false;
    }
    // 原根节点直接管辖的子树下沉一层，方向反转
    ptr_NW_new->ptr_child[SE] = (*this).root.ptr_child[NW];
    ptr_NE_new->ptr_child[SW] = (*this).root.ptr_child[NE];
    ptr_SW_new->ptr_child[NE] = (*this).root.ptr_child[SW];
    ptr_SE_new->ptr_child[NW] = (*this).root.ptr_child[SE];
    // 新中间节点挂回根节点
    (*this).root.ptr_child[NW] = ptr_NW_new;
    (*this).root.ptr_child[NE] = ptr_NE_new;
    (*this).root.ptr_child[SW] = ptr_SW_new;
    (*this).root.ptr_child[SE] = ptr_SE_new;
    state.size *= 2;        // 边长翻倍
    return true;
}
```

**算法**：四叉树**原地扩大**——分配 4 个新 `MIDDLE` 节点，把原来根节点直接管辖的 4 棵子树挂到新节点的**反向方向**槽位（NW 子树 → 新 NW 节点的 SE 槽；NE→SW 槽；SW→NE 槽；SE→NW 槽），再把这 4 个新节点挂回根节点。由于树以中心为根、四个方向对称，把子树向"外圈"移动一层后，新树的管理范围恰好是原来的 2 倍边长，且原数据位置不变（几何上向右上/左上等方向外扩）。`state.size *= 2` 同步记录。

```cpp
bool Quadtree<T>::child_node_recur(Node*& this_node, const int& direct, const Node_type& type, bool stable)
{
    if (this_node->ptr_child[direct] == nullptr && stable == true)
        this_node->ptr_child[direct] = new(std::nothrow) Node(type);   // 仅稳定模式分配
    this_node = this_node->ptr_child[direct];                          // 推进指针
    if (this_node == nullptr) return false;
    else return true;
}
```

**行为**：沿 `direct` 方向推进 `this_node`（引用参数，调用处同步更新）；仅当 `stable==true` 且子节点为空时分配新节点（`std::nothrow` 防止抛异常）；返回是否成功推进。这是"stable 模式创建区块、非 stable 模式只读已存在区块"的核心开关。

#### 4.2.12 递归销毁 `unload`（析构辅助）

```cpp
void Quadtree<T>::unload(int now_level, const int& max_level, Node* ptr_now)
{
    if (ptr_now == nullptr) return;
    if (now_level == max_level)                    // 最末级：叶子
    {
        if constexpr (!std::is_pointer_v<T>)
            ptr_now->leaf.~T();                    // 显式析构 T（非指针类型）
        delete ptr_now;
        return;
    }
    Node_type type = MIDDLE;
    if (now_level == max_level - 1) type = LEAF;   // 下一级是叶子层
    Node* ptr_next = ptr_now;
    for (int recur_direct = 0; recur_direct <= SE; recur_direct++)
    {
        child_node_recur(ptr_next, recur_direct, type, false);
        unload(now_level + 1, max_level, ptr_next);
        ptr_next = ptr_now;                        // 还原
    }
    delete ptr_now;                                // 删除中间节点
}
```

**算法**：递归后序遍历释放。叶子层（`now_level == max_level`）先 `leaf.~T()` 显式析构数据（仅非指针 T），再 `delete` 节点；中间层递归 4 个子节点后 `delete` 自身。`child_node_recur` 在 stable=false 下不分配、仅取指针，空子节点由 `unload` 的 `nullptr` 检查兜底。

### 4.3 边界情况处理

| 边界场景 | 处理方式 | 源码位置 |
|---|---|---|
| `state.size == 0` | `block_seek` 开头 `if (state.size <= 0) return;` 直接返回 | 区块信息检索.hpp |
| `block_size == 0` | `target_range_format` 开头 `if (block_size == 0) return;`，避免 `%0` 除零 | 导航与范围计算.hpp |
| 目标坐标超出树且已到 `max_size` | `point_seekable_analyse` 通报回调后返回 0，`block_seek` 终止 | 区块信息检索.hpp |
| 扩大申请被拒/分配失败 | 返回 0 终止查询；`tree_expand` 失败时释放已分配的新节点 | 区块信息检索.hpp / 节点创建与树扩大.hpp |
| 节点分配失败（`std::nothrow`） | `child_node_recur` 返回 false → `block_seek`/`range_seek` 提前 return | 节点创建与树扩大.hpp |
| 坐标等于节点中点（理论上不发生） | `recur_direct_calcu` 四分支均不命中，`recur_direct` 保持旧值 | 导航与范围计算.hpp |
| 负数坐标 | 范围计算用 64 位有符号 + `left + (right-left)/2` 形式避免截断；`target_range_format` 用负数安全取模 | 导航与范围计算.hpp |
| 边长超过 INT_MAX | `recur_record::node_range`/`callback` target 用 int64；中点用 double | 全局（64 位契约） |
| 范围查询结果重复 | 不在此层去重，由上层 `Quadtree_Manager` 的 `target_excel` 布尔表负责 | 区块信息检索.hpp / 管理器 |
| `range_seek` 叶子层内存分配失败 | `new_data == nullptr` 时 `return`（提前终止，已收集结果保留） | 区块信息检索.hpp |

### 4.4 设计决策及原因

1. **为什么根坐标用 `Point2d` 而非整数**：源码注释明确"为避免根节点中心偏移现象，故采用小数坐标"。默认 `{0.5,0.5}` 让树管理范围正好铺在整数网格上，配合 `manage_range_calcu` 的 `±0.5` 抵消，确保"树范围边界恰为整数"，与整数坐标的目标查询自然对齐。
2. **为什么范围推导用 `Rect2l`/`Point2l`（int64）**：前序版次 fa8459a 将尺寸层 64 位化。树边长可配置到 `INT_MAX` 以上（默认上限 2^63），若用 32 位承载边界必然溢出；这是尺寸层契约的根基。
3. **为什么 `Node` 用联合体**：中间节点与叶子节点互斥，联合体使单个节点在"4 个子指针"与"1 个数据 T"之间复用内存，内存开销最小（一个节点 4 指针大小），避免每个节点同时携带数据与子指针的浪费。
4. **为什么 `range_seek` 用显式栈而非递归**：范围查询可能遍历大量区块，递归深度虽受级数限制，但"分支回退"若用函数递归会反复重建栈帧、且深世界下风险高；显式栈 + 方向数组让遍历状态可完全受控，也便于中途提前终止（内存分配失败时 return 不泄露）。
5. **为什么 `block_seek` 先做"可行性分析循环"再寻址**：查询坐标可能远在树外数倍距离，单次 `tree_expand` 只翻一倍边长；`exam_time_max` 保证循环次数足够把树扩大到覆盖目标，同时最后一次 0 返回值让管理层知晓失败。
6. **为什么 `tree_expand` 是"原地扩大"而非重建**：重建整棵树代价高（O(n) 数据搬迁）；原地扩大只分配 4 个新节点、O(1) 指针搬运，数据节点不动，性能最优。
7. **为什么 `tree_expand` 不直接执行而要回调申请**：四叉树在 `Quadtree_Manager` 中多棵并存，若各自无限扩大将互相重叠、浪费内存。把扩大决策上交给管理器（`tree_expand_approve`）统一裁决（是否与相邻树重叠、是否已达上限、是否改新建树），是"容器与管理器职责分离"的关键。

### 4.5 易踩坑点（重开发警示）

1. **`Node` 联合体的内存管理陷阱**：`~Node(){}` 为空，`T` 的析构必须由 `unload` 显式 `leaf.~T()` 触发；`new (&ptr_child) Node* [4]()` 是 placement new 激活 `ptr_child`，切勿对其 `delete`（它是类内成员）。`root` 本身是成员，不能 `delete`。
2. **`recur_direct_calcu` 的四分支不完备性**：若目标坐标与节点中点完全相等（理论上 target 为 int64、中点为 double，不会发生），四个分支都不命中，`recur_direct` 沿用旧值——调用处应确保初值合法（`block_seek` 中初值为 0=NW）。
3. **`stable=false` 的语义**：非稳定查询绝不分配节点，路径上任何缺失都会让 `block_seek`/`range_seek` 提前返回或跳过，结果可能"不完整"——这是管理器数据迁移（`qurdtree_merge`）中故意使用非稳定查询"只读已存在数据"的原因。
4. **`range_seek` 会重复返回区块**：不同树/不同子查询范围边界重叠时，同一 `tree_chunk_data` 可能被多次创建并 `push_back`，上层必须去重（管理器用 `target_excel` 表）。
5. **`tree_expand` 后旧指针失效**：扩大不搬动数据节点，但根节点槽位指向变化；若外部持有"扩大前的某节点指针"会指向新中间节点而非原数据，重开发时注意不要在扩大后缓存节点指针。
6. **`target_range_format` 对齐的方向性**：左/下"向下取整"、右/上"向上取整"，这是为了保证范围"严格包含内部区块"；若反方向对齐会导致边界区块缺失。
7. **`exam_time_max` 的计算边界**：`state.size <= 0` 时提前 return；`max_size/state.size` 的除法在 `state.size` 为 0 时崩溃，故先做尺寸防御。
8. **C4715 既有告警**：见 §4.2.7，属预期，勿因告警盲目改动分支结构。

### 4.6 与坐标类型 / 二分查找 / 日志系统的协作

- **坐标类型**（`引擎层/src/core/spatial/common/core/坐标类型.h`）：四叉树全面依赖该头文件提供的类型别名。`Point2l = Point2<int64_t>` 用于 target/范围推导；`Rect2l = Rect2<int64_t>` 用于所有范围；`Point2d = Point2<double>` 用于根坐标/中心坐标；`Rect2d` 用于范围（本模块主要用 `Rect2l`）。精度转换工具 `point_to_l(const Point2d&)`（`llround` 四舍五入到 int64）被 `range_seekable_analyse` 用于把扩大标记 double 坐标转为回调的 int64 目标坐标。`Point2` 的 `operator==` 对浮点走 ULP 比较（≤4 ULP），因此 `seekable_range_calcu` 返回的 `coord_register` 与 `state.root` 比较时能容忍微小浮点误差。
- **Quadtree_Manager**（`Quadtree_Manager/` 目录）：本模块的上游使用者。管理器通过公开的 `manage_range_calcu/target_range_format/seekable_range_calcu` 三个计算工具跨树复用；通过 `set_callback_manage` 注入 `tree_expand_approve` 回调；通过 `block_seek/range_seek/tree_expand` 完成数据迁移（合并时"非稳定范围查询读取旧树 → 稳定单点查询写入新树"）。
- **二分查找**（`引擎层/src/tools/Auxi_Algorithm/二分查找.h`）：四叉树本身不直接使用二分查找；但管理器 `quadtree_index_seek` 用 `range_binary_search` 在按 X 降序的 `X_sequence` 上定位根坐标相同的树。四叉树只需保证 `tree_expand` 后 `state.size` 正确即可供管理器索引。
- **日志系统**：四叉树本版次源码未直接调用日志输出（无 `LOG` 类调用），失败通过返回值（`bool`/三态 int/nullptr）向上传播，由管理器或上层记录。

## 五、模块运行链路（完整调用时序与协作关系）

### 5.1 单点查询链路 `block_seek`

```
Quadtree_Manager::seek(单点)
   │ ① Point2i 提升为 Point2l
   │ ② quadtree_inclusion_seek(seek_coord) 找到直属树
   ▼
Quadtree::block_seek(receiver, target, stable)
   │ ③ exam_time_max 检测次数预算（防 size<=0）
   │ ④ 循环 point_seekable_analyse(target)
   │        ├─ 返回 0 → return（终止）
   │        ├─ 返回 1 → continue（继续扩大）
   │        └─ 返回 2 → break（可行）
   │            └─ 内部：manage_range_calcu 求树范围
   │                 ├─ 越界 && size>=max_size → 通报 callback → return 0
   │                 ├─ 越界 && size<max_size → callback(root,target) 申请扩大
   │                 │      └─→ Quadtree_Manager::tree_expand_approve（见 5.3）
   │                 │      └─ 批准 → tree_expand() → 返回 1/2
   │                 └─ 未越界 → return 2
   │ ⑤ recur_level_calcu 求寻址级数
   │ ⑥ 循环 recur_level_max 次：
   │        recur_direct_calcu(target, node_range, direct)      ← 方向
   │        child_node_recur(child_node, direct, MIDDLE/LEAF, stable)  ← 推进/分配
   │        child_node_range_calcu(direct, node_range, old)     ← 收窄范围
   │ ⑦ receiver 赋值：ptr_data=&leaf，node=区块中心（64 位范围求中点）
```

### 5.2 范围查询链路 `range_seek`

```
Quadtree_Manager::seek(范围)
   │ ① 空序列则建基准树；取 front 树为基准
   │ ② target_range_format(seekable_range, root, block_size)    ← 网格对齐
   │ ③ 计算 want_col/want_row → total_num（乘法溢出防御）→ 分配 target_excel 布尔表
   │ ④ 循环 seek_time < total_num（未查区块才处理）：
   │        excel_element_to_coord(seekable_range, seek_time, target)  ← 索引→坐标
   │        quadtree_inclusion_seek(target) 找直属树（无树且 stable → 智能创建）
   │        ▼
   │        Quadtree::range_seek(buffer, seekable_range, stable)
   │            ├─ target_range_format + range_seekable_analyse（循环扩大）
   │            ├─ 显式栈 + recur_path 深度优先遍历
   │            ├─ 叶子层收集命中区块 → receiver.push_back(tree_chunk_data<T>*)
   │        ▼
   │        seekable_range_calcu 裁剪已查范围 → target_range_amend 标记已查区块
   │ ⑤ delete[] target_excel
```

### 5.3 树扩大回调链（四叉树 ↔ 管理器）

```
Quadtree（内部越界，需要扩大）
   │ callback(root, target)          （root=Point2d，target=Point2l 64 位）
   ▼
Quadtree_Manager::tree_expand_approve(root, target, internal=false)
   │ ① callback_tree_seek(root) 找到对应 tree_record
   │ ② quadtree_inclusion_seek(target) != nullptr → 已覆盖，return false（拒绝）
   │ ③ now_tree->size < max_tree_size？
   │      ├─ 是：矩形筛选扩大区域（2×size 范围）内有无其他树根节点
   │      │       └─ 无 → 临时 size*=2 → next_tree_seek 找相邻树
   │      │             ├─ 有相邻 → next_tree_verify 严格筛选重叠树
   │      │             │     ├─ 无重叠 → 确认扩大：size 恢复并 *2、更新 largest、
   │      │             │     │            internal 则 tree->tree_expand()、刷新缓存 → true
   │      │             │     └─ 有重叠 → size 恢复 → 走④
   │      │             └─ 无相邻 → 直接确认扩大（沿用临时 *2 结果）→ true
   │      └─ 否（或扩大不可行）：走④
   │ ④ 构建新树：new_tree_range_calcu 求新范围 → 新 root=范围中心
   │      → quadtree_build(new_root, min_tree_size) → 返回 false（拒绝扩大，改建新树）
   ▼
Quadtree 侧：回调返回 true → 自行 tree_expand()；返回 false → 查询终止/改道
```

**回调链要点**：当四叉树以 `internal=false`（默认）走回调路径时，`tree_expand_approve` 只做"决策 + 记录（size/largest/缓存）"，**实际的 `tree->tree_expand()` 由四叉树自己在 `point_seekable_analyse`/`range_seekable_analyse` 中执行**；仅当 `internal=true`（管理器 `qurdtree_build_smart` 直接调用）时，管理器才代为调用 `tree->tree_expand()`。

### 5.4 与其他模块的协作关系

- **与 Quadtree_Manager**：四叉树是"单棵树的容器"，管理器是"树的调度者"。创建（`quadtree_build` 内 `new Quadtree<T>(size, root)`）、参数下发（`set_max_size`/`set_block_size`/`set_callback_manage`）、查询转发（`block_seek`/`range_seek`）、数据迁移（合并时读旧树写新树）、销毁（`delete record->tree` → 触发四叉树析构递归释放）全部由管理器驱动。
- **与坐标类型**：见 §4.6。四叉树是坐标类型 64 位化的主要受益者与验证者。
- **与碰撞模块（业务层）**：业务层通过管理器间接使用四叉树，不直接持有 `Quadtree` 对象；四叉树的 `tree_chunk_data<T>` 载荷类型 T 在碰撞场景中通常为碰撞空间/碰撞体相关数据（工程默认实例化为 `int`）。
