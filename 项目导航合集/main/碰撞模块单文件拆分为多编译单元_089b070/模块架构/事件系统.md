## 一、模块功能（该模块做什么，解决什么问题，在引擎中的定位）

### 1.1 模块定位

事件系统（Event System）是「白银纪元」引擎层（`engine` 命名空间）的核心通信基础设施，位于 `引擎层\src\core\event\`，为引擎内部各模块（碰撞模块 `Collision_Proxy`、配置加载模块 `Config_Loader`，以及未来接入的渲染、逻辑、音频等模块）提供基于订阅-发布（Publish-Subscribe）模式的解耦通信机制。

事件系统属 `core`（核心层），依赖方向遵循"核心层可依赖工具层、不可依赖业务模块"：

- **上游依赖**：工具层随机数生成器 `Random_Generator`（生成权限密钥）、日志系统 `Log`、`nlohmann::json`（事件载荷 `config`）、标准库容器与智能指针。
- **下游消费方**：`Collision_Proxy`（订阅/发布碰撞事件）、`Config_Loader`（发布 `Config/Load`），以及任何需跨模块通信的组件。

### 1.2 解决的核心问题

模块间直接互调会产生四类问题：**强耦合**（须持有对方实例/接口引用，难以独立测试替换）、**扩展困难**（新增关心某类消息的模块需改动所有发送方）、**时序脆弱**（初始化顺序变化即可能踩空指针）、**权限失控**（任何组件都可随意调用任意模块接口）。

事件系统用三层设计解决：**`event`（事件结构体）** 是数据载体，含发起者、目标、大类、标签、载荷五个维度，配套 `std::hash` 特化以支持哈希容器；**`Event_Terminal`（事件终端）** 是每个模块持有的出口/入口对象，封装"构造、发送、接收、查阅、清空"，以 **ACL 密钥（`acl_key`）** 机制实现模块级权限隔离，内嵌 `Terminal_Interface` 注册表把终端操作挂钩到具体回调通道；**`Event_Broker`（事件中转器）** 是全局订阅-发布中心，维护"模块名 → 订阅者编号"（`mapping_set`）、"大类 → 标签 → 订阅者编号集合"（`acl_set`）、"订阅者编号 → 事件入口回调"（`event_entries`）。`send` 触发时事件经中转器按订阅关系分发；`receive` 则是从中转器接收被分发下来的事件。

### 1.3 与其他核心模块的协同

- **`Config_Loader`（`引擎层\src\tools\Config_Loader\`）**：构造时 `acl_key_gen()` 取密钥；`act()` 扫描路由文件后构造 `category="Config"`、`tag="Load"`、`target_object=模块名` 的事件，经 `send({evt}, acl_key)` 定向投递。
- **`Collision_Proxy`（`引擎层\src\core\spatial\collision\Collision_Proxy\`）**：`attach()` 先查 `ATTACH_HANDLER` 是否注册，再注册接收入口 `event_receiver_register`，列出 11 个待订阅事件（`Config/Load` 与 Collision 大类下 10 个标签），调 `attach(module_name, needed_events, acl_key)`；`event_process` 按 `category/tag` 分派；`event_publish` 经 `build(...)+send(...)` 发布结果事件（如 `ColliderBuildResult`）。

### 1.4 设计要点总览（本版次 089b070）

1. **权限模型**：`Event_Terminal` 维护 `std::optional<int64_t> acl_key`，**密钥未生成即锁定**——`attach` / `interact`（两重载）/ `send`（两重载）/ `query` / `clear` 六个受保护操作在 `acl_key` 无值时统一告警并拒绝（返回 `false` / `nullptr`）；密钥只能生成一次，重复生成返回 `0`。
2. **接口注册表**：`Terminal_Interface` 用 `std::vector<interface_ID> map` 记录已注册接口 ID，用一组 `std::unique_ptr<std::function<...>>` 持有回调；公开 `*_register` 方法统一走 `function_register` 模板完成"分配内存 → 写回调 → 记 ID"三步。
3. **订阅语义**：`Event_Broker::info_register` 中，每个 `event_acl` 行首（`tag` 为空）是"该大类全订阅"标记行；`receive` 分发时先收集"全订阅者 + 标签匹配订阅者"，再排除发起者本人。
4. **定向与广播**：`receive` 中若 `target_object` 非空且存在于 `mapping_set`，则定向投递（不经 acl 匹配）；否则按 acl 表广播。
5. **应答协议**：`process` 仅处理 `category=="Subscriber"` 且 `tag=="Check"/"Call"` 的事件，返回 `Subscriber/Response`；`Call` 在目标存在时额外把原事件转发给目标。

## 二、模块提供接口（完整公开接口清单）

> 说明：接口签名摘自 089b070 版次源码（`引擎层\src\core\event\`）；方法名、参数类型、返回值、`const` 修饰与源码一致；参数名仅作语义说明。

### 2.1 `event` 结构体（`Event\事件.h`）

`engine::event` 是 POD 风格数据结构，承载事件全部信息：

```cpp
namespace engine
{
    //事件
    struct event
    {
        event();                                                                    //默认构造
        event(const std::string& category, const std::string& tag);                  //大类 + 标签
        event(const std::string& sender_object, const std::string& target_object,
              const std::string& category, const std::string& tag);                  //发起者 + 目标 + 大类 + 标签
        event(const std::string& sender_object, const std::string& target_object,
              const std::string& category, const std::string& tag,
              const nlohmann::json& config);                                         //全量构造
        ~event();

        std::string sender_object{};   //事件发起者
        std::string target_object{};   //事件目标
        std::string category;          //事件大类
        std::string tag;               //类内标签
        nlohmann::json config;         //配置包

        bool operator==(const event& other) const;
    };
}
```

**成员字段语义**：

| 字段 | 类型 | 默认值 | 语义 |
| --- | --- | --- | --- |
| `sender_object` | `std::string` | 空串 | 事件发起者（模块名）。`receive` 用它排除发起者自身；`process` 要求非空，否则事件无法处理。 |
| `target_object` | `std::string` | 空串 | 事件目标（模块名）。非空且已注册时触发定向投递；`process` 要求非空。 |
| `category` | `std::string` | 空串 | 事件大类（`"Config"` / `"Collision"` / `"Subscriber"`）。空串会导致 `receive` 丢弃、`info_register` 跳过。 |
| `tag` | `std::string` | 空串 | 类内标签（`"Load"` / `"RegionBuild"` 等）。空串会导致 `receive` 丢弃。 |
| `config` | `nlohmann::json` | 默认 json（null） | 事件载荷，承载业务数据（配置内容、`region`、`collider_ID`、`active`、`object_existence` 等）。 |

**构造函数语义**：`event()` 全默认（四字符串空串、`config` 为 null，`Config_Loader` 用它构造后逐字段填充）；`event(category, tag)` 仅填大类与标签，用于"只关心订阅模式"的声明；`event(sender, target, category, tag)` 填四维（`Collision_Proxy::attach` 的订阅清单即用此四参构造，前后各留空）；全量构造额外填载荷。

**相等运算符 `operator==`**：判等维度是 **`category` + `tag` + `target_object` + `config`**。两点注意：(1) **不比较 `sender_object`**（发起者不同、其余四维相同即相等，此设计使哈希与判等对齐）；(2) **比较 `config`（json）**，`nlohmann::json` 的 `==` 为**结构化比较**（递归按键值比较，与序列化顺序无关，如 `{"a":1,"b":2}` 与 `{"b":2,"a":1}` 相等）。

#### 2.1.1 `std::hash<engine::event>` 特化

`事件.h` 在 `namespace std` 内特化了 `hash<engine::event>`，使 `event` 可放入 `std::unordered_map` / `std::unordered_set`。**哈希维度与 `operator==` 严格一致**（`category`、`tag`、`target_object`、`config`，`sender_object` 不参与）。实现要点：以 `std::hash<std::string>` 依次哈希 `category`（首值作种子）、`tag`、`target_object`，并把 `config.dump()` 得到的紧凑 JSON 字符串一并哈希，四值经 `engine::detail::hash_combine`（黄金比例常数 `0x9e3779b9` 的经典组合散列）合成 `size_t`。`dump()` 对同一 json 值输出确定（对象键按字典序），故相同 json 哈希一致；空 json（null）dump 为 `"null"`。**潜在风险（源码注释已标注）**：`operator()` 声明为 `noexcept`，但 `config.dump()` 在深度嵌套/内存不足/浮点为 NaN·Inf 且 `allow_nan_inf=false` 时会抛异常，一旦抛出即 `std::terminate`。

**使用前提**：`event` 不管理任何资源（纯数据），可安全拷贝/移动/入容器；引擎内事件**一律以 `std::shared_ptr<event>` 形式流转**（`build` 返回 `shared_ptr<event>`，`send`/`receive`/`process` 均以之为参数），保证多订阅者共享同一对象、避免拷贝开销。

### 2.2 `Event_Terminal`（事件终端，`Event_Terminal\事件终端.h`）

`engine::Event_Terminal` 是模块侧的事件操作对象。私有成员：`std::optional<int64_t> acl_key`、`Random_Generator key_generator{}`、`std::vector<std::shared_ptr<event>> event_set{}`、`Terminal_Interface terminal_interface`。公开接口如下：

| 接口签名 | 需密钥 | 失败返回 | 行为要点 |
| --- | --- | --- | --- |
| `int64_t acl_key_gen(void);` | — | `0` | 首次生成非零密钥并返回；已有密钥时返回 `0`（"已存在"）。 |
| `bool attach(const std::string& module_name, const std::vector<event>& needed_events, const int64_t& acl_key);` | 是 | `false` | 密钥校验后经 `attach_handler` 完成订阅登记；接收入口选择见 2.2.2。 |
| `bool interact(std::shared_ptr<event> evt, const int64_t& acl_key);` | 是 | `false` | 密钥校验 + `interface_check(EVENT_INTERACTOR)` 后调用 `event_interactor`。 |
| `bool interact(std::vector<std::shared_ptr<event>> events, const int64_t& acl_key);` | 是 | `false` | 优先多事件入口 `events_interactor`；退化时逐事件循环单事件入口；均未注册则失败。 |
| `std::shared_ptr<event> build(三处重载：空参 / 两参(category,tag) / 四参(sender,target,category,tag));` | 否 | 空 `shared_ptr` | `new(nothrow)` 构造后包装为 `shared_ptr`，纯构造接口。 |
| `bool send(std::shared_ptr<event> evt, const int64_t& acl_key);` | 是 | `false` | 密钥校验后经 `event_sender` 交给中转站（单事件通道）。 |
| `bool send(std::vector<std::shared_ptr<event>> events, const int64_t& acl_key);` | 是 | `false` | 同上，走 `events_sender`（多事件通道）。 |
| `void receive(std::shared_ptr<event> evt);` | 否 | — | 已注册 `event_receiver` 则实时转发；否则入本地 `event_set` 队列。 |
| `void receive(std::vector<std::shared_ptr<event>> events);` | 否 | — | 同上，对应 `events_receiver`；否则批量追加队列。 |
| `const std::vector<std::shared_ptr<event>>* query(const int64_t& acl_key);` | 是 | `nullptr` | 密钥匹配返回指向 `event_set` 的**常量指针**，否则 `nullptr`。 |
| `bool clear(const int64_t& acl_key);` | 是 | `false` | 密钥匹配清空 `event_set` 并返回 `true`。 |
| `Terminal_Interface* operator->(void);` | 否 | — | 返回内部 `Terminal_Interface*`，用于注册回调/查询接口状态。 |

特殊成员：`Event_Terminal()` / 析构 / 移动构造 / 移动赋值均 `= default`，**拷贝被隐式删除**（`Terminal_Interface` 含 `unique_ptr`），传递终端时应使用引用、指针或移动语义。

#### 2.2.1 密钥机制与锁定（关键）

`acl_key_gen()` 要点：`acl_key` 无值时进入无限循环 `acl_key = key_generator()`，直到生成的数**不为 0** 才返回（0 是"无效/未授权"哨兵，不允许作真实密钥）；已有值时直接返回 `0`。因此：

- 首次调用返回非零密钥；重复调用返回 `0` 表示"密钥已存在"，**密钥一旦生成不可变更、不可重置**（无公开重置接口，除非整体析构重建）。
- 默认构造的终端处于"未生成密钥"态，此时 `attach` / `interact` / `send` / `query` / `clear` **全部锁定**：命中 `!this->acl_key.has_value()` 时打印 `Log::warn("Event_Terminal::密钥未生成\n功能已锁定")` 并返回失败值（`false` / `nullptr`）。此为防御性设计：忘记 `acl_key_gen` 就操作终端时得到明确告警而非静默未定义行为。
- 密钥比对统一为 `this->acl_key == acl_key`；**密钥不匹配时静默返回失败**（不打日志，避免噪音）。
- 任何要操作终端的模块，构造时必须先调用本方法并保存密钥（如 `Config_Loader` 构造中的 `this->acl_key = event_terminal.acl_key_gen();`）。
- 密钥由 `Random_Generator`（PCG32）生成，默认以"高精度时钟纳秒 ^ 系统时间 ^ 计数器"混合为种子，故每次运行/每终端密钥序列不同；生成的是全范围 int64 随机数（含负数），这正是"非 0"重试的原因。密钥为 64 位、进程内明文存储，安全模型是"防误用"而非"防恶意攻击"。

#### 2.2.2 `attach` 与接收入口选择（关键）

`attach` 流程：密钥未生成 → 告警 `false`；密钥不匹配 → `false`；随后取 `terminal_interface` 引用，**若单事件接收入口 `event_receiver` 尚未注册，则用 lambda 包装 `this->receive(evt)` 作为接收入口，否则直接使用已注册的 `*Tinterface.event_receiver`**，最后调用 `(*Tinterface.attach_handler)(module_name, needed_events, it)` 完成接入并返回 `true`。

- **`attach` 自身不调用中转站任何方法**，真正完成订阅登记的是 `attach_handler` 指向的回调（典型为 `Event_Broker::info_register`）；此间接设计使 `Event_Terminal` 不直接依赖 `Event_Broker` 类型，两模块仅通过 `std::function` 桥接。
- **调用前提**：`attach_handler` 必须已注册（`interface_check(interface_ID::ATTACH_HANDLER)` 为真，`Collision_Proxy::attach` 会显式前置检查并输出 `Log::error`）；否则解引用空 `unique_ptr` 为未定义行为。
- **顺序语义**：若先 `attach` 后注册 `event_receiver`，中转站 `event_entries` 中保存的仍是包装 `receive` 的旧 lambda，之后新注册的实时回调**不会**自动更新——推荐"先注册 `event_receiver` 再 `attach`"。

#### 2.2.3 其余接口的易错点

- **`build`**：三处重载均 `new(nothrow)`，**分配失败返回空 `shared_ptr`**，调用方必须判空（`Collision_Proxy::event_publish` 的 `if (!evt)` 即为此）；`Config_Loader` 未走 `build`，而是直接 `new(nothrow) event()` 逐字段填充。
- **`send`**：只负责"把事件交给发送入口"，**不保证事件被消费**——若无模块订阅该 `category/tag`，事件被 `receive` 静默忽略；返回值仅表示"入口调用成功"。
- **`interact` vs `send`**：两者可绑定到同一 `Event_Broker::receive`，但注册入口不同（`event_sender` / `event_interactor`），**入口检查方式也不同**：`send` 直判 `terminal_interface.event_sender` 指针，`interact` 走 `interface_check`。
- **`receive`（无需密钥）**：作为被中转站调用的回调型入口，模块若希望"事件一到就立即处理"，可注册 `event_receiver_register`（如 `Collision_Proxy` 注册 `this->event_process`），此时事件不再积压队列。
- **`query`**：返回内部容器地址，生命周期由终端管理；`const` 约束禁止外部修改，密钥不匹配/未生成均返回 `nullptr`，调用方须判空后再解引用；典型用法为"每帧 `query` 遍历 + 处理后 `clear`"。

### 2.3 `Terminal_Interface`（终端接口，`Event_Terminal\终端接口.h`）

`engine::Terminal_Interface` 是 `Event_Terminal` 内部的**回调注册表**，把"终端应执行的动作"以 `std::function` 保存。声明 `friend class Event_Terminal;`，私有成员包括注册表 `std::vector<interface_ID> map{}` 与 7 个入口 `unique_ptr`（`attach_handler`、`event_interactor`、`events_interactor`、`event_sender`、`events_sender`、`event_receiver`、`events_receiver`）。

#### 2.3.1 `interface_ID` 枚举

```cpp
enum class interface_ID
{
    NONE,
    ATTACH_HANDLER, EVENT_INTERACTOR, EVENTS_INTERACTOR,
    EVENT_SENDOR, EVENTS_SENDOR, EVENT_RECEIVER, EVENTS_RECEIVER
};
```

| 枚举值 | 语义 | 对应成员 |
| --- | --- | --- |
| `NONE` | 空占位（`map` 中不会被写入） | — |
| `ATTACH_HANDLER` | 中转站接入入口 | `attach_handler` |
| `EVENT_INTERACTOR` / `EVENTS_INTERACTOR` | 中转站交互入口（单/多事件） | `event_interactor` / `events_interactor` |
| `EVENT_SENDOR` / `EVENTS_SENDOR` | 事件发送入口（单/多事件） | `event_sender` / `events_sender` |
| `EVENT_RECEIVER` / `EVENTS_RECEIVER` | 事件接收入口（单/多事件） | `event_receiver` / `events_receiver` |

枚举底层类型默认 `int`，取值依次为 0（`NONE`）~ 7（`EVENTS_RECEIVER`）。`function_register` 每注册一个入口就把对应枚举值 `push_back` 进 `map`，`interface_check` 遍历 `map` 查找，故该枚举是"接口是否注册"的判断依据。

#### 2.3.2 私有类型别名

| 别名 | 定义 | 语义 |
| --- | --- | --- |
| `needed_events` | `const std::vector<event>&` | 订阅事件清单（按引用传递避免拷贝）。 |
| `event_handler` | `std::function<void(std::shared_ptr<event> evt)>` | 单事件回调签名。 |
| `events_handler` | `std::function<void(std::vector<std::shared_ptr<event>>)>` | 多事件回调签名（**按值传 vector**，有拷贝开销）。 |
| `attch_handler` | `std::function<void(const std::string& name, needed_events events, event_handler receiver)>` | 接入回调签名：模块名 + 订阅清单 + 接收入口。 |

`attch_handler` 的三个参数与 `Event_Broker::info_register` 的 `module_name`/`needed_events`/`event_entry` **完全对应**，故可用 lambda 把 `info_register` 包装后注册为 `attach_handler`。

#### 2.3.3 模板私有工具：`memory_malloc` 与 `function_register`

```cpp
template <typename... Args>
bool memory_malloc(std::unique_ptr<std::function<void(Args ...)>>& target);
template <typename... Args>
bool function_register(interface_ID ID, std::unique_ptr<std::function<void(Args ...)>>& target,
    std::function<void(Args ...)> function);
```

- `memory_malloc`：以 `new(nothrow)` 为 `std::function` 分配堆内存并 `reset` 进 `unique_ptr`，返回指针是否非空；若已有旧对象，`reset` 先析构旧的。
- `function_register`：通用注册三步曲——分配内存 → 成功则写入回调 `*(target) = function` → 把接口 ID 压入 `map`。**重复注册同一接口会覆盖旧回调**，且 `map` 会重复累积相同 ID（`interface_check` 只查存在性，不受影响）。
- 两模板**定义在 `.cpp` 中**（`终端接口.cpp`），仅在**同一翻译单元内的公开方法**中实例化，属"模板定义放 cpp、同 TU 内实例化"的合法模式；private，外部无法直接调用。

#### 2.3.4 公开注册方法（7 个）

七个注册方法均一行委托 `function_register`，成功返回 `true`、分配失败返回 `false`：

| 方法 | 注册到成员 | `map` 记录 ID | 典型用途 |
| --- | --- | --- | --- |
| `bool attach_handler_register(attch_handler callback);` | `attach_handler` | `ATTACH_HANDLER` | 中转站持有者注册"接入动作"（内部调用 `info_register`）；**必须最先注册**。 |
| `bool event_interactor_register(event_handler callback);` | `event_interactor` | `EVENT_INTERACTOR` | 中转站持有者注册单事件交互动作（内部调用 `receive(shared_ptr<event>)`）。 |
| `bool events_interactor_register(events_handler callback);` | `events_interactor` | `EVENTS_INTERACTOR` | 中转站持有者注册多事件交互动作。 |
| `bool event_sender_register(event_handler callback);` | `event_sender` | `EVENT_SENDOR` | 中转站持有者注册单事件发送通道（**模块 `send` 依赖此通道**）。 |
| `bool event_sender_register(events_handler callback);` | `events_sender` | `EVENTS_SENDOR` | 中转站持有者注册多事件发送通道。 |
| `bool event_receiver_register(event_handler callback);` | `event_receiver` | `EVENT_RECEIVER` | 模块注册自己的单事件处理回调（如 `Collision_Proxy::event_process`）。 |
| `bool event_receiver_register(events_handler callback);` | `events_receiver` | `EVENTS_RECEIVER` | 模块注册自己的多事件处理回调。 |

`event_sender_register` 与 `event_receiver_register` 各有两个重载（单/多事件），方法名相同、仅参数类型不同（`event_handler` vs `events_handler`），C++ 依函数重载区分。

#### 2.3.5 `interface_check` —— 接口注入验证

签名 `bool interface_check(const interface_ID& ID);`。实现为线性遍历 `map` 比对 ID，`true` 表示该接口已注册。用途：`Event_Terminal::interact` 判断交互入口是否可用；`Collision_Proxy::attach` 检查 `ATTACH_HANDLER`；模块注册前自查。**注意**：该检查只反映"是否注册过"，不反映回调内容是否仍有效（回调捕获对象析构后的悬空问题需调用方自行保证生命周期）。

### 2.4 `Event_Broker`（事件中转器，`Event_Broker\事件中转器.h`）

`engine::Event_Broker` 是全局订阅-发布中心。私有嵌套结构体 `event_acl` 与三层表见 2.4.1 / 3.3.3；公开接口如下：

| 接口签名 | 返回值 | 职责 |
| --- | --- | --- |
| `void info_register(const std::string& module_name, const std::vector<event>& needed_events, std::function<void(std::shared_ptr<event>)> event_entry);` | `void` | 登记订阅者（模块名 → 编号）与入口回调，并按 `needed_events` 建立订阅关系。 |
| `void receive(std::shared_ptr<event> evt);` | `void` | 单事件定向/广播分发。 |
| `void receive(std::vector<std::shared_ptr<event>> event_set);` | `void` | 多事件分发（循环调用单事件重载）。 |
| `std::shared_ptr<event> process(std::shared_ptr<event> evt);` | 应答事件 / `nullptr` | Subscriber 协议应答（Check/Call）。 |
| `std::vector<std::shared_ptr<event>> process(std::vector<std::shared_ptr<event>> event_set);` | 应答集合 | 多事件应答（逐事件调用单事件重载）。 |

#### 2.4.1 私有嵌套结构体 `event_acl`

| 成员 | 类型 | 语义 |
| --- | --- | --- |
| `tag` | `std::string` | 该行对应的事件标签；**首行的 `tag` 为空串，表示"该大类全订阅"标记行**。 |
| `ID_set` | `std::vector<int32_t>` | 订阅该标签（或该大类全部）的订阅者编号集合，编号由 `mapping_set` 分配。 |

`receive` 中使用 `vector<uint16_t> acled_IDs` 收集授权订阅者，存在 **`int32_t` → `uint16_t` 类型收缩**的潜在风险，见 4.8。

#### 2.4.2 `info_register` —— 订阅者登记注册

1. **订阅者 ID 登记**：若 `module_name` 已在 `mapping_set`（二次注册），取回原 ID 并**覆盖** `event_entries[subscriber_ID]`；否则以 `mapping_set.size()` 作为新 ID（从 0 起递增），插入 `mapping_set` 与 `event_entries`。二次注册**只更新入口回调，不更新旧订阅关系**（`acl_set` 保持首次注册状态）。
2. **逐事件登记订阅**：遍历 `needed_events`：`evt.category.empty()` → `continue` 跳过（**`evt.tag.empty()` 不跳过**）；`acl_set` 无该分类 → 创建 `acl_set[category]` 并 `push_back({})` 一个**全订阅标记行**（空 `tag`）；遍历该分类各行，某行 `tag` 与事件 `tag` 相同 → 把 `subscriber_ID` 加入该行 `ID_set`（先 `ID_set.empty()` 直插，否则线性去重检查），全部未匹配 → `push_back({evt.tag, {subscriber_ID}})` 新建标签行。
- **全订阅登记语义**：声明 `event("", "", category, "")`（tag 为空）时，匹配循环在首行（全订阅行，`tag==""`）命中并 `break`，订阅者被登记为全订阅；**一旦命中全订阅行，同一分类下其他带标签的声明不会再单独登记**——故同一模块同时声明"全订阅 + 具体标签"时实际等同全订阅。标签匹配为字符串全等比较（大小写敏感）。

#### 2.4.3 `receive` —— 事件接收/分发（两处重载）

多事件重载即循环调用单事件重载；单事件逻辑：

1. 取 `sender_object`、`target_object` 引用。
2. **丢弃条件**：`category` 为空或 `acl_set` 中无该分类 → return；`tag` 为空 → return。
3. **定向投递**：若 `target_object` 非空且存在于 `mapping_set`，取目标 ID，调用 `event_entries[target_ID](evt)` 后 return（**不经过 acl 匹配**）。
4. **广播分发**：先经 `acled_IDs.insert(..., acl_row.front().ID_set ...)` 收集**全订阅者**（首行即全订阅行）；再从下标 1 起遍历标签行，`evt->tag == acl.tag` 时并入该行 `ID_set`；解析发送者 ID（`mapping_set.find(sender_object)`，不存在取 `-1`）；遍历 `acled_IDs`，**跳过发送者本人**后逐一 `event_entries[id](evt)`。

- **重复投递**：全订阅行与具体标签行可能含同一订阅者 ID，`acled_IDs` 出现重复 → 入口被调用两次。订阅方应避免"全订阅 + 同标签订阅"并存。
- **发送者排除**：`sender_ID = -1`（发送者未注册）时比较恒真，不跳过任何人；ID 从 0 起分配，正常情况下发送者在自身订阅集合中会被排除。
- **调用前提**：`receive` 通常被注册为 `event_sender` / `events_sender` / `event_interactor` / `events_interactor`，由 `send` / `interact` 触发，也可由中转站持有者直接调用。

#### 2.4.4 `process` —— 事件处理/应答（两处重载）

单事件行为：

1. `sender_object.empty()` → `Log::warn("Event_Broker::事件发送者未定义\n事件无法处理")`，返回 `nullptr`。
2. `target_object.empty()` → `Log::warn("Event_Broker::事件目标未定义\n事件无法处理")`，返回 `nullptr`。
3. `!mapping_set.count(sender_object)` → `Log::warn("Event_Broker::事件发送者不存在\n事件无法处理")`，返回 `nullptr`。
4. 仅处理 `category == "Subscriber"` 且 `tag == "Check" || tag == "Call"`：构造应答事件 `shared_ptr<event> response_event(new(nothrow)event("Subscriber","Response"));`，再 `mapping_set.find(target_object)`——不存在则 `config["object_existence"] = false`；存在则置 `true`，且当 `tag == "Call"` 时把**原事件转发给目标模块** `event_entries[it->second](evt)`，最后返回 `response_event`。
5. **其他 category/tag 组合：函数体走到末尾无显式 `return`，返回未定义值**（源码缺省路径未补 `return nullptr;`，触发编译告警 C4715，见 4.5 / 七）。

多事件重载把每个单事件结果（可能含 `nullptr` 或未定义值）`push_back` 进 `buffer` 返回，**返回值与入参一一对应**，调用方须逐元素判空。

- **Check 与 Call 差异仅在"是否转发原事件"**：`Check` 只探测不打扰目标；`Call` 询问 + 转发。应答事件由两参构造 `event("Subscriber","Response")` 生成（sender/target 为空，`config` 随后填充 `object_existence`）。
- **注意**：`process` 只检查 `sender_object` 是否在 `mapping_set`，**不再校验 `target_object` 是否注册**——目标存在性改由应答事件的 `config["object_existence"]` 承载（`Call` 仅在目标存在分支才转发）。

### 2.5 消费方视角接口汇总（非事件系统自身接口）

- **`Collision_Proxy`（`引擎层\src\core\spatial\collision\Collision_Proxy\`，实现见 `core\事件交互.cpp`）**：`void attach(void);`（接入并订阅）、`void event_process(std::shared_ptr<event> evt);`（分派处理）、`bool event_publish(const string& tag, const json& payload);`（发布结果事件）；文件内匿名命名空间辅助 `text_read`（字段须为字符串且非空）、`number_read`（字段须为整数）。
- **`Config_Loader`（`引擎层\src\tools\Config_Loader\`，实现见 `core\配置加载器.cpp`）**：构造中 `event_terminal.acl_key_gen()` 取密钥；`void act(void);` 扫描配置路由并发送 `Config/Load`。

依赖与组织要点：

- **`事件系统运行包.h`**：依次包含 `common/前置头文件包含.h`、`Event/事件.h`、`Event_Terminal/事件终端.h`。**未包含 `Event_Broker/事件中转器.h`**——`Event_Terminal` 通过 `std::function` 与中转站解耦；需用 `Event_Broker` 的代码应显式包含 `Event_Broker/事件中转器.h`。
- **两个 `局部命名空间使用.h`**：提供 `string` / `vector` / `nothrow` / `shared_ptr` / `function` 等局部 using 别名（终端侧多 `unique_ptr`，中转站侧多 `unordered_map`），供 `.cpp` 简化书写；这些 using 位于文件作用域会污染包含者命名空间，但仅被本模块 `.cpp` 包含，影响可控。
- **`.cpp`** 均以 `#include "../局部命名空间使用.h"` 开头，再按需引入 `src/tools/Logging/日志系统.h`（`事件终端.cpp`、`事件中转器.cpp` 需要，`终端接口.cpp` 不需要）。
- **`终端接口.h` 冗余包含了随机数生成器.h**（自身不用），对编译时间有轻微影响，无功能影响。

### 3.2 类关系（层次结构）

- **`event`（纯数据 + `operator==` / `std::hash`）**：唯一消息载体，以 `shared_ptr<event>` 在终端、中转站、消费方之间流转；广播时同一对象被多订阅者共享（引用计数增加），不复制载荷。
- **`Event_Terminal`（模块侧）──组合──▶ `Terminal_Interface`（回调注册表）**：终端持有成员 `terminal_interface`，经 `operator->` 暴露；`Terminal_Interface` 声明 `friend class Event_Terminal;` 允许终端直接访问其私有成员（如 `attach` 中读取 `Tinterface.event_receiver`）。
- **终端接口中的回调由「中转站持有者」注册**：`attach_handler → Event_Broker::info_register`；`event_sender` / `events_sender → Event_Broker::receive`；`event_receiver → 模块自身处理函数`。
- **`Event_Terminal` 与 `Event_Broker` 无类型依赖**：终端经 `Terminal_Interface` 中存储的 `std::function` 间接驱动中转站；中转站持有者负责把 `info_register` / `receive` 包装成 `attach_handler` / `event_sender` 等注册进终端接口。
- **`Event_Broker` 内部三层表**：`mapping_set`（模块名 → 订阅者编号）、`event_entries`（订阅者编号 → 事件入口回调）、`acl_set`（事件大类 → 订阅行表，首行为全订阅标记行）。

事件流：模块 → `Terminal.send` → `Broker.receive` → `event_entries[订阅者ID]` → `Terminal.receive` → `event_set` 队列 或 模块实时回调。

## 四、模块设计/实现细节（关键流程、边界条件、设计决策、踩坑点、注意事项）

### 4.1 ACL 权限模型：密钥未生成即锁定

**设计决策**：用 `std::optional<int64_t> acl_key` 的"有值/无值"天然表达"密钥已生成/未生成"两态：

- **未生成（无值）**：`attach`、`interact`（两重载）、`send`（两重载）、`query`、`clear` 六个受保护操作在入口检查 `!this->acl_key.has_value()`，命中则 `Log::warn("Event_Terminal::密钥未生成\n功能已锁定")` 并返回失败值（`false` / `nullptr`）。
- **已生成但未匹配**：`this->acl_key != acl_key` 时静默返回失败（不告警）。
- **重复生成**：`acl_key_gen` 在已有时返回 `0`；其内部循环保证真实密钥永不取 0，故 0 永远无法通过 `==` 校验。

**设计原因**：事件系统是跨模块公共通道，若不设权限，任何代码都能伪造模块名发送事件、冒充他人订阅。**局限**：密钥是"终端级"而非"调用级"权限（粗粒度）；以 `int64_t` 明文存储，若被日志/序列化泄漏则权限失效；其安全模型是"防误用"而非"防恶意攻击"。

### 4.2 终端接口注册表的设计

`Terminal_Interface` 把"终端要做的动作"抽象成 7 个可注册回调，配合 `map` 做能力检查，实现控制反转（IoC）：中转站持有者在启动阶段注册 `attach_handler` / `event_sender` / `event_interactor` 等；业务模块在接入阶段注册 `event_receiver`；终端方法执行时只检查"入口是否注册"再调用。踩坑点：

1. **`send` 与 `interact` 入口检查方式不一致**：`send` 直判 `terminal_interface.event_sender`（指针当前状态），`interact` 走 `interface_check`（查 `map` 历史记录）；仅在手动破坏内部状态（`map` 有记录而指针为空）时结果会不同。
2. **重复注册覆盖旧回调**：`function_register` 每次 `target.reset(new(nothrow)...)` 重建，旧回调被覆盖；`map` 中 ID 重复累积（不影响存在性判断，属轻微浪费）。
3. **内存分配失败处理**：`memory_malloc` 用 `new(nothrow)`，失败时 `function_register` 与注册方法均返回 `false`，调用方应检查返回值（如 `Collision_Proxy::attach` 检查 `event_receiver_register` 返回值并 `Log::error`）。

### 4.3 订阅表（`acl_set`）的"全订阅标记行"约定

`acl_set[category]` 是 `vector<event_acl>`，**下标 0（首元素）为特殊行**：`tag` 为空串，表示"订阅该大类的全部事件"，由 `info_register` 在分类首次创建时插入（`acl_set[evt.category].push_back({})`）。`receive` 分发时的合并逻辑：

```text
acled_IDs = 全订阅行.ID_set            // 所有"订阅整个大类"的模块
for 每个标签行 (从下标 1 起):
    若 evt.tag == 行.tag:
        acled_IDs += 行.ID_set         // 加"订阅该具体标签"的模块
for id in acled_IDs:
    若 id != sender_ID: 调用 event_entries[id](evt)
```

- **全订阅语义**：声明 `event("", "", "Collision", "")`（tag 为空）→ 在 `info_register` 匹配循环中于首行命中全订阅行，ID 进入全订阅行。但 `receive` 会直接丢弃 `tag` 为空的事件，故"全订阅"实际是"接收该分类下所有**带标签**的事件"。
- **一旦命中全订阅行即 `break`**：同一模块即使同时声明了带标签事件，也已被并入全订阅行，不会再单独登记具体标签行。

### 4.4 定向投递 vs 广播

`receive` 中定向投递优先于广播（判据：`target_object` 非空且 `mapping_set` 中存在）：

- `Config/Load` 正是利用定向投递：`Config_Loader` 填充 `evt->target_object = module`，`receive` 直接投给该模块，**不经过 acl 匹配**（目标模块即使未在 `needed_events` 声明 `Config/Load` 也能收到）。
- 若 `target_object` 非空但目标未注册 → 条件不成立，**退化为广播**（按 `category/tag` 匹配所有订阅者），即对未注册目标的定向事件不会静默丢弃，而是广播——调用方需注意这一"意外广播"语义。
- **定向投递不排除发送者**：即使发送者就是目标也会收到自己的事件（与广播路径的"排除自身"不同），两分支语义不对称。

### 4.5 Subscriber 应答协议（`process`）

`process` 实现轻量级"模块存在性探测/呼叫"协议，事件类型约定：

| 事件 | category | tag | 语义 | 应答 |
| --- | --- | --- | --- | --- |
| 探测 | `Subscriber` | `Check` | 询问目标模块是否存在 | `Subscriber/Response`，`config["object_existence"]` 布尔 |
| 呼叫 | `Subscriber` | `Call` | 询问目标是否存在，且要求转发 | 应答同上；目标存在时原事件被转发给目标入口 |

实现细节：应答事件由两参构造 `event("Subscriber","Response")` 生成（sender/target 为空），随后填充 `object_existence`；**Check 与 Call 的差异仅在"是否转发原事件"**（`if (evt->tag == "Call") event_entries[it->second](evt);`）。

- **缺陷**：`process` 对非 `Subscriber/Check|Call` 组合的事件**无兜底 return**，从函数末尾"掉出去"返回未定义值（非 void 函数到达末尾属未定义行为），多事件重载会把它 push 进 `buffer`，调用方判空时可能误判。建议补 `return nullptr;`（既有编译告警 C4715）。
- **调用前提**：`acl_set` 中需存在 `Subscriber` 分类，否则 `Check`/`Call` 事件在 `receive` 阶段即被丢弃、进不了 `process`；且应答需调用方显式调用 `process`，系统不自动串联。

### 4.6 哈希与判等的一致性

`std::hash<engine::event>` 与 `event::operator==` 维度完全对齐（`category`、`tag`、`target_object`、`config`），保证把 `event` 用作 `unordered_*` 键时满足"相等对象哈希值必相同"。踩坑点：

1. **`config.dump()` 在 `noexcept` 函数中可能抛异常**：config 含 NaN/Inf 时 `dump()` 抛 `type_error` → `std::terminate`。
2. **浮点载荷的哈希稳定性**：同一 json 值在同一进程内 `dump()` 一致，跨运行可能因浮点舍入不同（对单进程容器使用无碍）。
3. **`operator==` 不比较 `sender_object`**：若将来希望"全字段判等"，需注意此为有意设计（哈希同样忽略 sender）。

### 4.7 移动语义与不可拷贝性

- `Event_Terminal` 只提供默认移动构造/移动赋值，**拷贝被隐式删除**（`Terminal_Interface` 含 `unique_ptr`，`Random_Generator` 拷贝会复制 PRNG 状态）；每个终端应为唯一实体。引擎内 `Event_Terminal` 通常作为模块成员直接持有（如 `Collision_Proxy::event_terminal`、`Config_Loader::event_terminal`），移动语义主要用于容器重排等场景。
- **移动后源对象**变为"密钥丢失 + 队列清空 + 接口为空"的空壳（受保护操作全部因密钥未生成而锁定）。
- **移动对已接入中转站的影响**：若 `attach` 时未注册 `event_receiver`，中转站保存的是捕获旧终端 `this` 的 lambda，移动后回调指向失效地址（UB）；若已注册 `event_receiver`，回调捕获模块 `this`，与终端地址无关。结论：**终端应在 `attach` 前完成移动/就位，`attach` 后不应移动终端**；建议用 `unique_ptr` 或固定地址存储，避免容器重排。

### 4.8 `receive` 中的类型收缩风险

`acled_IDs` 声明为 `vector<uint16_t>`，而 `event_acl::ID_set` 为 `vector<int32_t>`；收集全订阅者时 `acled_IDs.insert(acled_IDs.end(), acl_row.front().ID_set.begin(), acl_row.front().ID_set.end())` 发生 `int32_t` → `uint16_t` 隐式收缩：订阅者编号 ≥ 65536 时截断，多个 ID 映射到同一值，导致误投、发送者排除失效等。当前引擎模块数远未达 65535，属潜在风险而非现役问题。

### 4.9 边界条件与异常路径汇总

| 编号 | 触发条件 | 系统行为 | 级别 |
| --- | --- | --- | --- |
| U1 | 未 `acl_key_gen` 就 `send`/`attach`/`interact`/`query`/`clear` | `Log::warn("密钥未生成")` + 返回失败 | 防御 |
| U2 | 密钥不匹配 | 静默返回失败 | 防御 |
| U3 | `acl_key_gen` 重复调用 | 返回 `0` | 语义约定 |
| U4 | `build` 内存分配失败 | 返回空 `shared_ptr` | 需调用方判空 |
| U5 | `send` 时发送入口未注册 | 返回 `false` | 需接线 |
| U6 | `send` 空指针事件 | 中转站 `receive` 解引用崩溃（`evt->category`） | 潜在崩溃 |
| U7/U8 | `receive` 收到 `category` 空/未注册分类、或 `tag` 空 | 丢弃（return） | 静默 |
| U9 | 定向目标未注册 | 退化为广播 | 语义注意 |
| U10 | 广播收集到重复订阅者 ID | 重复调用回调 | 潜在重复 |
| U11 | 订阅者数 > 65535 | `acled_IDs` 截断 | 潜在缺陷 |
| U12 | `process` 收到非 `Subscriber/Check\|Call` | 无 return，未定义返回值 | 缺陷（C4715） |
| U13 | `process` 收到空发送者/目标/未注册发送者 | warn + `nullptr` | 防御 |
| U14 | `process` 中 `response_event` 分配失败 | 解引用空指针 | 潜在崩溃 |
| U16 | `attach` 时 `attach_handler` 未注册 | 解引用空 `unique_ptr`（UB） | 调用前提 |
| U17 | 多线程并发操作 | 数据竞争 | 不支持 |
| U18 | config 含 NaN/Inf 且被哈希 | `dump()` 抛异常 → terminate | 潜在崩溃 |
| U19 | 模块析构后仍收到事件（回调悬空 `this`） | 未定义行为 | 生命周期约定 |

**修复优先级**：U6、U12、U14（可能崩溃/未定义行为）应优先处理，U11、U10、U16 次之。事件系统**不使用异常**，失败一律经返回值表达；`new(nothrow)` 规避分配异常（`json::dump()` 的异常风险已标注）。

### 4.11 事件协议约定（`category` / `tag` 一览）

事件系统本身不限定事件命名，现有消费方与内置协议形成了一套约定。089b070 版次实际出现的组合如下：

| category | tag | 发布方 | 载荷字段 | 投递方式 | 语义 |
| --- | --- | --- | --- | --- | --- |
| `Config` | `Load` | `Config_Loader` | 配置 JSON（任意结构） | 定向（`target_object` = 模块名） | 把配置内容投递给目标模块，由模块自行解析应用 |
| `Collision` | `RegionBuild` | `Collision_Proxy` | `region`（string） | 广播 | 构建碰撞空间 |
| `Collision` | `RegionUnload` | `Collision_Proxy` | `region`（string） | 广播 | 卸载碰撞空间 |
| `Collision` | `RegionState` | `Collision_Proxy` | `region`、`active`（bool） | 广播 | 设置空间活跃性 |
| `Collision` | `RegionBoundary` | `Collision_Proxy` | `path`（string） | 广播 | 设置空间边界配置 |
| `Collision` | `RegionDetect` | `Collision_Proxy` | `region`（string） | 广播 | 执行碰撞检测 |
| `Collision` | `ColliderBuild` | `Collision_Proxy` | `region`（string） | 广播 | 构建碰撞体（结果回告 `ColliderBuildResult`） |
| `Collision` | `ColliderUnload` | `Collision_Proxy` | `region`、`collider_ID`（uint64） | 广播 | 卸载碰撞体 |
| `Collision` | `ColliderTransfer` | `Collision_Proxy` | `region`、`collider_ID` | 广播 | 转移碰撞体 |
| `Collision` | `ColliderMirror` | `Collision_Proxy` | `region`、`collider_ID` | 广播 | 镜像碰撞体 |
| `Collision` | `ColliderSet` | `Collision_Proxy` | `region`、`collider_ID` + 其余配置 | 广播 | 碰撞体设置 |
| `Collision` | `ColliderBuildResult` | `Collision_Proxy`（回告） | `region`、`collider_ID` | 广播 | 碰撞体构建结果回告 |
| `Subscriber` | `Check` | 调用方 | 无 | 广播 | 探测目标模块是否存在，应答 `Subscriber/Response`（`config["object_existence"]`） |
| `Subscriber` | `Call` | 调用方 | 无 | 广播 | 探测 + 转发呼叫；目标存在时原事件转发给目标入口 |
| `Subscriber` | `Response` | `Event_Broker::process` | `object_existence`（bool） | 返回调用方 | Check/Call 的应答，由调用方消费 |

载荷读取约定（`事件交互.cpp` 内部辅助）：`text_read` 要求字段为字符串且非空，`number_read` 要求字段为整数；任一读取失败 → `Log::warn("Collision_Proxy::...事件缺少有效字段(...)")` 并跳过该事件。`RegionState` 的 `active` 直接校验 `is_boolean()` 后 `get<bool>()`。

## 五、模块运行链路（从初始化到典型操作的调用时序；与其他模块的协作关系）

### 5.1 总体协作拓扑

```
引擎初始化（中转站持有者）
    Event_Broker broker;  Event_Terminal terminal;
    terminal.attach_handler_register([&](name, events, receiver){ broker.info_register(name, events, receiver); });
    terminal.event_sender_register([&](shared_ptr<event> evt){ broker.receive(evt); });
    terminal.events_sender_register([&](vector<shared_ptr<event>> evts){ broker.receive(evts); });
        │
        ├── Config_Loader（发送 Config/Load，走 events_sender）──▶ Event_Broker
        └── Collision_Proxy（attach 订阅 11 个事件，走 attach_handler）──▶ Event_Broker
                                                                          │
        Event_Broker：acl_set / mapping_set / event_entries
          info_register → 建立订阅；receive → 定向/广播分发；process → Subscriber 应答
```

### 5.2 链路一：引擎初始化（中转站接线）

```
引擎入口
  ├─ 1. 构造 Event_Broker broker;                     // 三表为空
  ├─ 2. 构造 Event_Terminal terminal;                 // 密钥未生成（锁定态）
  ├─ 3. terminal.attach_handler_register(lambda1)     // lambda1 => broker.info_register
  │      → function_register(ATTACH_HANDLER, attach_handler, lambda1)
  │      → memory_malloc 分配 + 写入回调 + map.push_back(ATTACH_HANDLER)
  ├─ 4. terminal.event_sender_register(lambda2)       // lambda2 => broker.receive(单)
  │      → function_register(EVENT_SENDOR, event_sender, lambda2)
  ├─ 5. terminal.events_sender_register(lambda3)      // lambda3 => broker.receive(多)
  │      → function_register(EVENTS_SENDOR, events_sender, lambda3)
  └─ 6. （可选）event_interactor_register / events_interactor_register
          → 绑定 broker.receive 的单/多事件重载，供 interact 使用
```

初始化后 `terminal` 的发送/接入通道指向 `broker`，但尚无订阅者。引擎中应存在**唯一** `Event_Broker` 实例（源码未强制单例，多实例会导致订阅表分离、跨 Broker 事件收不到）。

### 5.3 链路二：模块接入订阅（`Collision_Proxy::attach`）

```
Collision_Proxy::attach()（源码：Collision_Proxy\core\事件交互.cpp）
  ├─ 1. 前置检查：event_terminal->interface_check(interface_ID::ATTACH_HANDLER)
  │      └─ 若 false：Log::error("事件中转站接入入口未注册，接入中止"); return;
  ├─ 2. 注册本模块事件接收入口（先注册，保证 attach 直达处理函数）：
  │      event_terminal->event_receiver_register(
  │          [this](shared_ptr<event> evt) { this->event_process(evt); })
  │      └─ 若 false：Log::error("事件接收入口注册失败，接入中止"); return;
  ├─ 3. 构造待订阅事件清单 needed_events（11 个，四参构造 event("","",cat,tag)）：
  │      Config/Load 与 Collision 大类的 RegionBuild/RegionUnload/RegionState/
  │      RegionBoundary/RegionDetect/ColliderBuild/ColliderUnload/ColliderTransfer/
  │      ColliderMirror/ColliderSet
  └─ 4. 接入：event_terminal.attach(module_name, needed_events, acl_key)
        ├─ 4.1 密钥检查（未生成 → warn + false）；4.2 密钥比对（不匹配 → false）
        ├─ 4.3 event_receiver 已注册（步骤2）→ 取 *Tinterface.event_receiver
        ├─ 4.4 (*attach_handler)(module_name, needed_events, receiver)
        │      └─ lambda1 → broker.info_register("Collision_Proxy", needed_events, receiver)
        │            ├─ mapping_set["Collision_Proxy"] = 0（首个订阅者）；event_entries[0] = receiver
        │            └─ acl_set["Config"] → [全订阅标记行, {tag:"Load", ID_set:[0]}]
        │               acl_set["Collision"] → 全订阅标记行 + 10 个标签行（各含 ID 0）
        └─ 4.5 返回 true；若 false → Log::error("事件中转站接入失败")
```

接入完成后 `Collision_Proxy` 已在 `broker` 中登记处理回调（`event_entries[0]`）、订阅关系与"模块名 ↔ 订阅者 ID 0"映射。**注意**：`attach` 未在自身方法内取得密钥，`acl_key` 须由外部初始化流程先 `acl_key_gen` 再赋值；`attach` 返回 `false` 时仅 `Log::error`、不中止（模块继续运行但收不到事件）。

### 5.4 链路三：配置加载与定向投递（`Config_Loader` 发送 `Config/Load`）

构造：`Config_Loader::Config_Loader()` 执行 `this->acl_key = event_terminal.acl_key_gen();`。

```
Config_Loader::act()（源码：Config_Loader\core\配置加载器.cpp）
  ├─ 扫描路由文件 → 校验数组 → 路径安全检查（assets/config 前缀、禁 ".."）
  ├─ 读取目标模块配置文件 config_data
  ├─ 构造事件：shared_ptr<event> evt(new(nothrow) event());    // 默认构造后逐字段填充
  │      evt->category = "Config"; evt->tag = "Load";
  │      evt->target_object = module; evt->config = config_data;
  └─ 发送：event_terminal.send({ evt }, acl_key)                // 花括号 = 多事件重载
        ├─ 密钥检查 → 密钥比对 → events_sender 已注册？
        │      └─ (*events_sender)({evt}) → lambda3 → broker.receive({evt})
        │             └─ 多事件重载循环 broker.receive(evt)
        │                    ├─ category="Config" 已注册、tag="Load" 非空 → 继续
        │                    ├─ target_object 非空且在 mapping_set → 定向投递
        │                    │      └─ event_entries[0](evt) → Collision_Proxy::event_process
        │                    │             └─ target==module_name → config_apply(evt->config)
        │                    └─（返回）
        ├─ 成功 → Log::info("已发送配置事件: {}", module)
        └─ 失败 → Log::info("未注册事件中转站依赖\n配置工作无法完成"); return;
```

- **事件构造**用 `new(nothrow) event()` 后逐字段填充（未走 `build`）；**发送用多事件重载** `send({evt}, acl_key)`，依赖 `events_sender` 通道注册（若引擎只注册单事件通道会失败）；`send` 返回 `false` 时 `act()` 立即 return，不再处理后续路由条目。
- **定向投递**使事件直达目标模块，不依赖目标是否订阅 `Config/Load`；`Collision_Proxy::event_process` 处理时校验 `target_object == module_name` 才 `config_apply`，非本模块的配置指令直接忽略。

### 5.5 链路四：事件发布回告与 Subscriber 探测协议

**（1）事件发布与回告**：`Collision_Proxy` 处理 `ColliderBuild` 等指令后，用 `event_publish` 把结果告知请求方：`event_terminal.build(module_name, "", "Collision", tag)` 构造事件 → `if (!evt)` 判空失败则 `Log::error("事件内存分配失败，发布中止")` → 写入 `evt->config = payload` → `event_terminal.send(evt, acl_key)`，失败则 `Log::warn("事件({})发送失败，事件发送通道不可用")`。

时序：`event_process` 的 `ColliderBuild` 分支调用 `collider_build(region)`（返回 `optional<uint64_t>`，失败则直接 return 不回告），成功则填充 `payload["region"]`、`payload["collider_ID"]` 并 `event_publish("ColliderBuildResult", payload)`。发布事件 `sender_object=module_name`、`target_object` 为空 → 走**广播**（`acled_IDs` = 全订阅行 + 匹配标签行，排除发送者）；`event_publish` 返回值仅反映"是否成功把事件送入发送通道"，不反映是否被订阅者接收。

**（2）Subscriber 探测协议（`process`）**：

```
调用方（模块 X）
  ├─ evt = terminal.build("X", "目标模块名", "Subscriber", "Check")   // 或 "Call"
  ├─ terminal.send(evt, acl_key) → broker.receive(evt)
  │    └─ 若 acl_set 无 "Subscriber" 分类，receive 直接丢弃（事件进不了 process）
  └─ 中转站持有者在收到应答前调用 broker.process(evt)：
       ├─ sender/target 非空且 sender 已注册 → 继续
       ├─ category=="Subscriber" && tag=="Check|Call" → 构造 Response 事件
       ├─ mapping_set.find(target_object)：
       │    ├─ 不存在 → response->config["object_existence"] = false
       │    └─ 存在 → 置 true；若 Call → event_entries[target_ID](evt) 转发原事件给目标
       └─ 返回 response_event（调用方据 object_existence 判断目标是否存在）
```

**注意**：`process` 不遍历 acl 表分发（分发是 `receive` 的职责），系统不自动串联二者，应答需显式调用 `process`。

### 5.6 与其他模块协作的注意事项

1. **接线顺序**：`info_register` 必须发生在 `receive` 之前（先订阅后发事件），否则事件因无订阅者被丢弃。引擎初始化顺序应为：中转站接线 → 各模块 `attach` → 各模块发送。
2. **通道注册完整性**：`Config_Loader` 依赖 `events_sender`（多事件通道），`Collision_Proxy` 依赖 `ATTACH_HANDLER`；接线时单/多发送通道都应在初始化阶段注册。
3. **模块名唯一性**：`mapping_set` 以模块名做键，同名注册会共享同一订阅者 ID 且后注册者覆盖事件入口，模块名应全局唯一。
4. **共享可变状态**：事件以 `shared_ptr` 流转，广播时被 N 个订阅者共享；若某订阅者修改 `evt->config`，其他订阅者会看到修改。当前订阅方均按只读约定处理，但代码层面无强制。
5. **生命周期**：模块应先于 `Event_Broker` 析构；`event_entries` 中捕获模块 `this` 的回调在模块析构后即悬空（当前版次无注销接口）。`event_set` 积压队列无上限，长期运行模块应周期性 `clear` 或注册处理回调。

## 七、本版次相关与遗留事项

### 7.1 本版次（089b070）改动情况

**本模块（事件系统）在 089b070 版次无改动**。本版次主题为"碰撞模块单文件拆分为多编译单元"，事件系统作为碰撞模块的通信依赖被引用，自身源码未变更（`事件.h` 的哈希特化注释风格、`Event_Broker` 三表结构、`Terminal_Interface` 注册表机制均保持既有状态）。消费方 `Collision_Proxy\core\事件交互.cpp` 是本版次拆分出的独立编译单元，承担碰撞模块与事件系统的全部交互（`attach`/`event_process`/`event_publish`）。

### 7.2 源码中的已知注意事项与潜在缺陷（供后续版本关注）

1. **`Event_Broker::process` 缺省路径无 `return`（既有告警 C4715，`事件中转器.cpp` 单事件重载函数末尾）**：非 `Subscriber/Check|Call` 事件会"掉落"函数尾返回未定义值；本版次及前序版次均未修复。**建议**末尾补 `return nullptr;`。
2. **`receive` 的 `acled_IDs` 类型收缩**：`uint16_t` 承接 `int32_t` 订阅者 ID，订阅者 ≥ 65536 时误投/漏投。**建议**改为 `vector<int32_t>`。
3. **广播重复投递**：模块同时全订阅某大类又订阅其具体标签时 `acled_IDs` 含重复 ID，事件被调用两次。**建议**收集后去重。
4. **哈希特化的 `noexcept` 与 `dump()` 抛异常冲突**（源码注释已自我标注）：config 含 NaN/Inf 时 `dump()` 抛异常 → `std::terminate`。**建议** `dump()` 加 try-catch 或配置 `allow_nan_inf`。
5. **`interface_check` 与指针直判不一致**：`send` 查指针、`interact` 查 `map`，两套判定并存。**建议**统一。
6. **`Terminal_Interface::map` 重复记录**：重复注册同一接口导致 `map` 冗余增长。**建议**注册前查重或改用集合。
7. **`attach` 接收入口时序**：若先 `attach` 后注册 `event_receiver`，中转站保存的是包装 `receive` 的旧 lambda，新回调不会自动更新（事件进入 `event_set` 积压而非实时处理）。`Collision_Proxy` 采用"先注册回调再 attach"规避；其他模块反序操作需注意。
8. **定向投递不排除发送者**：`receive` 定向分支直接投递，发送者即目标时会收到自己的事件；广播分支则排除，两分支语义不对称。
9. **多事件接口按值传 `vector<shared_ptr<event>>`**：`events_handler` 参数为拷贝（shared_ptr 浅拷贝 + vector 拷贝），批量较大时有开销（签名已定，改动需评估影响面）。
10. **`Config_Loader` 用 `send({evt}, acl_key)` 多事件重载**：实际只发一个事件，依赖 `events_sender` 通道注册；接线时单/多通道都应注册。
11. **`Collision_Proxy::attach` 未在自身方法内取得密钥**：`acl_key` 须由外部初始化流程先 `acl_key_gen` 再赋值，否则 `attach` 的密钥比对永远失败。
12. **事件处理回调的悬空捕获风险**：`event_receiver_register` 捕获 `this`（如 `Collision_Proxy` 的 lambda），模块在 `Event_Broker` 仍持有其入口时析构，再收到事件将调用悬空 `this`。当前版次无注销接口，**建议**后续补充 `unregister(module_name)`。
13. **`acl_key_gen` 仅能成功一次**：已持有密钥时返回 `0`，无法重新生成/轮换密钥；返回值 `0` 是"已存在"哨兵，与"生成失败"语义无法区分，调用方应约定"每个终端只调用一次"。
14. **密钥错误分支返回空结果**：`query` 在密钥不匹配时返回 `nullptr`（而非空集合指针），调用方须判空；`attach` 的密钥不匹配分支仅静默返回 `false`（不打日志），与"密钥未生成"分支的 `Log::warn` 行为不一致。
15. **`process` 不再校验 `target_object` 是否注册**：仅检查 `sender_object` 是否在 `mapping_set`，目标存在性改由 `Subscriber/Response` 的 `config["object_existence"]` 承载；`Call` 仅在目标存在分支转发，`process` 本身仍返回 `Response`（`object_existence=false`）。重开发时勿再假设 `process` 会拦截非法目标。
16. **行数校正（相对旧版本文档）**：本版次核算 `事件中转器.cpp` 为 235 行（旧记录 234）、两个 `局部命名空间使用.h` 各为 17 行（旧记录 18），故自身文件合计 950 行（旧记录 951）。其余文件行数与旧记录一致。
