## 一、模块功能（该模块做什么，解决什么问题，服务谁）

### 1.1 模块定位

测试层主调与选择器是「白银纪元」引擎**测试层**的"入口与交互中枢"。它位于 `测试层\src\主调\` 目录，由以下六个源文件组成：

| 文件 | 职责 |
|---|---|
| `主程序.cpp` | 提供全仓库唯一可执行文件 `EngineTests.exe` 的 `main()`，完成参数摘取、googletest 初始化、四种运行路径分流、过滤串落地与收尾等待 |
| `测试选择模型.h/.cpp` | 纯逻辑层：通过 googletest 反射枚举全部已注册套件与用例，建立两层选择树，维护勾选态，生成 `--gtest_filter` 过滤串，解析控制台编号输入 |
| `控制台选择菜单.h/.cpp` | 无图形环境（或用户显式指定）时的文本交互入口：打印编号列表、读取用户输入、把选择结果应用到模型 |
| `图形选择窗口.h/.cpp` | 默认交互入口：GLFW + OpenGL 3.3 + Dear ImGui 的树形勾选窗口，支持搜索过滤、批量勾选、Esc 全跑 |
| `退出等待判定.h` | 声明测试结束后"是否停住等待用户按键"的三参数判定函数（实现位于 `主程序.cpp`，用例可直接链接验证） |

### 1.2 解决的核心问题

1. **测试运行路径的多样性**：同一份 `EngineTests.exe` 要同时服务三种截然不同的调用场景——① CI/ctest 自动化（带 `--gtest_*` 参数透传，跑完即退）；② 一键全量回归（`--selector=off` 不开窗直接全跑）；③ 开发期交互选择（控制台编号菜单或图形勾选窗口）。`main()` 通过"自定义开关摘取 + 参数透传 + 四步分流"在一份入口里同时满足三种形态。
2. **测试选择的人机交互**：交互运行时用户往往只关心少数几个套件/用例。选择模型从 googletest 反射建立"套件 → 用例"两层树，图形窗口用复选框 + 树节点 + 搜索框呈现，控制台菜单用编号区间呈现；最终统一压缩成 googletest 原生过滤串执行。
3. **"过滤串"的生成正确性**：勾选状态（全选/半选/单条）必须翻译成合法的 `--gtest_filter` 语法——全不选退化为 `"*"`（与 gtest 语义一致，全跑）、整套件全选压缩为 `"套件.*"`、部分勾选逐条列出、多条以 `':'` 连接。这是"所见即所测"的关键。
4. **控制台中文可读性**：Windows 控制台默认代码页无法显示 UTF-8 中文用例名，`main()` 开头强制 `SetConsoleOutputCP(CP_UTF8)` / `SetConsoleCP(CP_UTF8)`。
5. **交互结束"停住"语义**：交互运行（窗口/控制台）测试跑完后若立即退出，控制台一闪而过看不到结果；自动化调用（透传/off）则必须跑完即走，否则 CI 会被挂住。`需要等待退出()` 三参数判定表精确区分两类场景，且实现与用例验证共用同一份符号，保证"测的"就是"用的"。
6. **图形环境缺失的优雅降级**：无 GLFW/OpenGL 环境（远程桌面、CI、无显卡容器）时窗口创建失败，自动打印提示并回退控制台菜单，不会崩溃、不会黑屏挂死。

### 1.3 服务谁

- **直接服务对象**：使用 `EngineTests.exe` 的开发者（交互选择）、CI 与 ctest（自动化回归）、需要验证测试层自身逻辑的单元测试（`测试选择模型测试`、`退出暂停判定测试`）。
- **被服务对象**：googletest 框架。主程序负责 `InitGoogleTest`、设置 `GTEST_FLAG(filter)`、调用 `RUN_ALL_TESTS()`，本模块是测试框架与本仓库 338 个用例之间的"总调度"。
- **底层依赖**：googletest（`GTest::gtest`，不含 `gtest_main`——`main` 由本模块提供）、引擎层 `EngineCore` 静态库（传递 GLFW 头文件与 `glfw3.lib`、系统库、JSON 等对外面）、`external/Dear_ImGui` 与 `external/glad`（图形窗口）、Windows API（`conio.h` 的 `_getch`、`windows.h` 的控制台函数）。

### 1.4 本版次（089b070）要点总览

1. **四步分流顺序固化**：① 未显式 `--selector` 且带 `--gtest_*` → 透传；② `--selector=off` → 不开窗全跑；③ `--selector=console` → 控制台菜单；④ 默认/`--selector=window` → ImGui 窗口（失败降级控制台菜单）。
2. **参数摘取与 argv 重建**：`--selector=` 前缀摘出选择模式并标记"显式选择器"；`--gtest_` 前缀只做标记不改参数；其余参数原样保留后重建 `char**` 交给 `InitGoogleTest`。
3. **过滤串三态压缩**：全不选→`"*"`、整套件全选→`"套件.*"`、部分→逐条 `':'` 连接。
4. **控制台解析防御**：编号从 1 开始、区间 `a-b`、`all/a/*` 全选、数字解析上限 1000000 防溢出、三次非法输入兜底全跑、输入流结束按全选。
5. **图形窗口主题与字体**：蓝色渐变三段色（深蓝→中蓝→亮蓝）背景 + 透明窗口底色透出渐变；中文字体七候选回退链（msyh/Deng/simhei/simsun/simkai）；搜索框按套件名/用例名过滤。
6. **退出等待三参数判定表**：`(命令行带过滤 && !显式选择器)` 或 `选择模式=="off"` → 不停；其余（含未知模式）→ 停住，宁可多等也不一闪而过。
7. **构建目标划分**：`TestLauncher`（纯逻辑，可被用例链接）、`TestGui`（ImGui+glad，只被主程序链接）、`EngineTests`（主程序 + 图形窗口 + 用例 obj），三者职责清晰、依赖单向。

### 2.2 主程序与退出等待判定

```cpp
// 主程序.cpp —— 文件内部工具（匿名命名空间，不对外）
void 等待用户关闭窗口();   // GetConsoleWindow 判空防挂住 + FlushConsoleInputBuffer + _getch

// 退出等待判定：声明在 退出等待判定.h，实现位于 主程序.cpp（同一份符号供用例链接验证）
namespace engine
{
    bool 需要等待退出(const std::string& 选择模式, bool 命令行带过滤, bool 显式选择器);
}
```

- **`需要等待退出(选择模式, 命令行带过滤, 显式选择器)`**：
  - `选择模式`：`"window"` / `"console"` / `"off"`（`main` 中摘取后的字符串，默认 `"window"`）。
  - `命令行带过滤`：命令行出现过任一 `--gtest_*` 前缀参数（视为自动化调用标记）。
  - `显式选择器`：命令行显式出现过 `--selector=`（显式指定优先于自动化约定）。
  - **返回值**：`true` = 测试结束后停住等待按键（交互运行）；`false` = 跑完立即返回（自动化）。
  - **判定表**（实现为两个早退 `return false` + 一个兜底 `return true`）：

    | 选择模式 | 命令行带过滤 | 显式选择器 | 判定结果 | 场景 |
    |---|---|---|---|---|
    | window | false | false | **true（停）** | 默认双击运行 |
    | window | false | true | **true（停）** | 显式 `--selector=window` |
    | window | true | false | **false（不停）** | `--gtest_filter=...` 透传（自动化） |
    | window | true | true | **true（停）** | 显式选择器 + 过滤串并存，选择器优先 |
    | console | false | true | **true（停）** | 显式 `--selector=console` |
    | console | true | false | **false（不停）** | 控制台模式 + gtest 参数透传（罕见） |
    | off | false | false | **false（不停）** | ctest 整体注册的调用形态 |
    | off | false | true | **false（不停）** | 显式 `--selector=off` 一键全量回归 |
    | off | true | true | **false（不停）** | `--selector=off --gtest_filter=...` |
    | 未知模式 | 任意 | true | **true（停）** | 兜底：宁可多等一次也不要一闪而过 |

  - **设计决策**：判定逻辑单独成函数放在 `主程序.cpp`（而非内联在 `main`），头文件 `退出等待判定.h` 只放声明，使 `退出暂停判定测试.cpp` 的 8 个用例可以直接链接可执行文件里的同名符号，保证"用例验证的判定"与"主程序实际使用的判定"是同一份代码，杜绝测试与实现分叉。

- **`等待用户关闭窗口()`**（文件内部工具，匿名命名空间）：
  1. `::GetConsoleWindow() == nullptr` → 直接 `return`（重定向/CI/无控制台窗口时无可等待对象，跳过以免挂住）；
  2. 打印 `[测试选择] 测试已结束，按任意键关闭窗口…`；
  3. `::FlushConsoleInputBuffer(::GetStdHandle(STD_INPUT_HANDLE))` 清掉选择阶段残留的按键，避免"确认"用的回车被这里立刻吃掉导致一闪而过；
  4. `::_getch()` 阻塞等待任意键。

### 2.3 测试选择模型（纯逻辑类，头文件 `测试选择模型.h`）

```cpp
namespace engine
{
    // 单个用例的选择条目
    struct 用例条目
    {
        std::string 名称;    // 用例名（不含套件前缀，来自 TestInfo::name()）
        bool 已勾选 = true;  // 用例是否被勾选（默认勾选）
    };

    // 单个套件的选择条目
    struct 套件条目
    {
        std::string 名称;              // 套件名（来自 TestSuite::name()）
        std::vector<用例条目> 用例表;  // 套件下的用例
        bool 已展开 = false;           // 界面上是否已展开用例列表（由模型持有，跨帧保持）
    };

    class 测试选择模型
    {
    public:
        void 建立套件树();                       // 反射建树（全部用例默认勾选）

        // —— 查询（const 只读）——
        const std::vector<套件条目>& 套件表() const;   // 套件表（只读引用）
        std::size_t 套件数() const;                   // 套件数量
        std::size_t 用例总数() const;                 // 用例总数（各套件用例数之和）
        std::size_t 已勾选用例数() const;             // 已勾选用例数
        bool 套件全选(std::size_t 套件序号) const;    // 套件是否全选（空套件/越界为 false）
        bool 套件半选(std::size_t 套件序号) const;    // 套件是否半选（部分勾选）
        bool 套件已展开(std::size_t 套件序号) const;  // 套件是否已展开（越界为 false）

        // —— 修改 ——
        void 设置套件勾选(std::size_t 套件序号, bool 勾选);            // 整组全选/全不选
        void 设置用例勾选(std::size_t 套件序号, std::size_t 用例序号, bool 勾选); // 单条
        void 设置套件展开(std::size_t 套件序号, bool 展开);            // 展开态
        void 全部勾选();                                              // 批量
        void 全部清空();
        void 反向勾选();

        // —— 输出 ——
        std::string 生成过滤串() const;  // 生成 --gtest_filter 过滤串

    private:
        std::vector<套件条目> 套件表_;  // 两层选择树
    };

    // 解析控制台选择输入：接受 "all"/"a"/"*" 或 "1,3-5"（编号从 1 开始）
    // 结果写入 勾选表（长度被重置为 套件数）；返回 false 表示输入非法
    bool 解析控制台选择(const std::string& 输入, std::size_t 套件数, std::vector<bool>& 勾选表);
}
```

**接口逐条语义说明**：

- **`建立套件树()`**：先 `套件表_.clear()`，取 `::testing::UnitTest::GetInstance()` 单例（用例在静态初始化期已注册完毕），遍历 `total_test_suite_count()` 个套件、每个套件 `total_test_count()` 个用例，把 `TestSuite::name()` / `TestInfo::name()` 拷入条目，默认全部 `已勾选=true`。反射返回空指针（防御性）时跳过该条。
- **`套件表()`**：返回内部 `套件表_` 的 const 引用，图形窗口/控制台菜单/用例直接只读遍历，零拷贝。
- **`套件数()` / `用例总数()` / `已勾选用例数()`**：前两者 O(1)/O(n) 计数；`已勾选用例数()` 遍历两层统计 `已勾选==true` 的条数。
- **`套件全选(序号)`**：越界或空套件一律 `false`；否则遍历用例表，任一未勾选即 `false`。
- **`套件半选(序号)`**：越界或空套件 `false`；统计已选数 `已选`，满足 `已选 > 0 && 已选 < 用例表.size()` 即为半选。
- **`套件已展开(序号)`**：越界 `false`，否则返回 `已展开` 标志。
- **`设置套件勾选(序号, 勾选)`**：越界忽略；整组 `用例.已勾选 = 勾选`。
- **`设置用例勾选(套件序号, 用例序号, 勾选)`**：任一越界忽略；单条写入。
- **`设置套件展开(序号, 展开)`**：越界忽略；写展开标志。
- **`全部勾选()` / `全部清空()` / `反向勾选()`**：对全树批量置 `true` / 置 `false` / 取反。
- **`生成过滤串()`**（核心输出，见 4.1 详述）：
  - 若 `已勾选用例数() == 0` → 返回 `"*"`（与 gtest 语义一致：全不选视为全跑）；
  - 否则逐套件统计 `已选`：`已选 == 0` 跳过；`已选 == 用例表.size()` 压缩为 `套件.名称 + ".*"`；其余逐条 `套件.名称 + "." + 用例.名称` 入片段表；
  - 片段之间以 `':'` 连接（首片段前不加）。
- **`解析控制台选择(输入, 套件数, 勾选表)`**（见 4.2 详述）：
  - 先把 `勾选表.assign(套件数, false)` 复位；
  - 去掉首尾空白（`find_first_not_of`/`find_last_not_of`，" \t\r\n"），全空白直接 `false`；
  - `all` / `ALL` / `a` / `*` → 全 `true`，返回成功；
  - 按 `','` 切段循环：空段非法；段含 `'-'` 按区间（左右必须是纯数字、右段不得再含 `-`、`1 <= 左值 <= 右值 <= 套件数`），否则按单编号（`1 <= 编号 <= 套件数`）；
  - 任一解析失败即整体返回 `false`（不部分生效，但勾选表已被 assign 复位）。

### 2.4 控制台选择菜单与图形选择窗口

```cpp
// 控制台选择菜单.h —— 无图形环境时的回退入口

    // 运行控制台选择菜单，过滤串写入 过滤串
    // 输入流结束或多次非法输入时按「全选」处理
    void 控制台选择菜单_运行(测试选择模型& 模型, std::string& 过滤串);
}

// 图形选择窗口.h —— GLFW + Dear ImGui 的临时选择界面
namespace engine
{
    // 运行图形选择窗口
    // 成功返回 true，过滤串写入 过滤串（按 Esc 或关闭窗口视为全跑，写入 "*"）
    // 窗口创建失败返回 false（调用方应退到控制台菜单）
    bool 图形选择窗口_运行(测试选择模型& 模型, std::string& 过滤串);

```

- **`控制台选择菜单_运行(模型, 过滤串)`**：打印编号列表 → 最多三次读取输入 → 解析/应用/生成过滤串；具体流程见 4.3。
- **`图形选择窗口_运行(模型, 过滤串)`**：GLFW 初始化 → 建窗 → glad 加载 → ImGui 初始化 → 蓝色主题 → 中文字体 → 主循环渲染选择树 → 清理；返回 `false` 仅发生在 GLFW 初始化失败、窗口创建失败或 glad 加载失败三处；具体流程见 4.4。

5. **TestGui 不编 `imgui_demo.cpp`**（示例窗口用不到）；opengl3 后端用自带 loader（`imgui_impl_opengl3_loader.h`），另编 `glad` 供窗口自身的 `glViewport`/`glClearColor`/`glClear` 调用使用。
6. **googletest 接入参数**：`INSTALL_GTEST OFF`、`BUILD_GMOCK OFF`、`gtest_force_shared_crt ON`（强制共享运行时库，避免与引擎层 CRT 设置冲突导致 LNK2038），`add_subdirectory(..., EXCLUDE_FROM_ALL)` 只在被测试目标依赖时才编译。
7. **ctest 注册分两路**（详见 4.5）：工程路径纯 ASCII → `gtest_discover_tests` 逐用例注册；含中文 → 整体注册一个用例 `EngineTests --selector=off`。

- 工程强制 C++20（`CMAKE_CXX_STANDARD 20`，`REQUIRED ON`，`EXTENSIONS OFF`），与引擎层一致。
- MSVC 下 `add_compile_options(/WX-)`（关闭警告即错误），各目标 `PRIVATE /MP /utf-8`。
- 层间契约由 `cmake/接入下层.cmake` 的 `byjy_jieru_xiaceng()` 统一实现（系统层/测试层/游戏层三份逐字节相同）：`BYJY_ENGINE_LIB_PATH` / `BYJY_SYSTEM_LIB_PATH` 覆盖变量非空则强制使用（文件不存在直接 FATAL_ERROR），留空则自动探测 `<下层>/out/build/*/lib/<库名>.lib` 取时间戳最新，都没有则 FATAL_ERROR 并提示先构建下层——**任何情况下不回退编译下层源码**。引擎层对外面（`BYJY_ENGINE_OUT_*`：包含目录 / 编译定义 / 链接库 / 系统库）已并入系统层对外面，因此 `EngineCore` 一个导入目标就带齐了 `common/` 预编译头、`src/` 头文件、`external/Json`、`external/glfw`（含 `GLFW_STATIC`、`glfw3.lib`、系统库）。

## 四、模块设计/实现细节

### 4.1 过滤串生成的三态压缩（测试选择模型::生成过滤串）

这是"所见即所测"的核心算法，逻辑如下（源码精确对应）：

```
已勾选用例数() == 0
   └─→ 返回 "*"                                  // 全不选 = 全跑（与 gtest "*" 语义一致）
逐套件统计 已选：
   已选 == 0                      → 跳过本套件
   已选 == 套件.用例表.size()      → 片段 = 套件名 + ".*"     // 整组压缩
   0 < 已选 < 用例表.size()       → 逐条 片段 = 套件名 + "." + 用例名
片段间以 ':' 连接（i != 0 时前置 ':'）
```

**设计决策与易踩坑点**：

1. **全不选返回 `"*"` 而非空串**：空过滤串在 gtest 里会"过滤掉一切"（跑 0 个用例），而用户清空勾选后点击"开始测试"的心理预期是"跑全部"（与 gtest `-` 前缀之外默认全跑语义一致）。`"*"` 是 gtest 官方通配符，表示匹配一切。
2. **整组压缩的收益**：22 个套件 × 平均 15 个用例，若不压缩过滤串可达数百段；压缩成 `套件.*` 后长度从百级降到十级，`--gtest_filter` 命令行可读性大幅提升，也降低命令行长度风险。
3. **半选必须逐条**：`套件.用例A:套件.用例B` 之间是"或"关系，逐条列出保证精确；不能用 `套件.用例*` 之类的近似（gtest 的 `*` 只匹配路径段，`套件.用例*` 会匹配 `套件.用例A`、`套件.用例B` 之外更多名字以"用例"开头的用例，语义不精确）。
4. **`':'` 是 gtest 过滤串的分隔符**：多个正模式之间是"或"；负模式（`-` 前缀）本模块未使用。
5. **用例名/套件名含特殊字符**：gtest 过滤串中 `*`、`?` 是通配符，`:` 是分隔符，`-` 是否定符。当前用例名/套件名均不含这些字符（由 TEST 宏命名规范保证），故直接拼接无需转义。**若未来出现含 `:` 的用例名，过滤串将断裂，这是已知边界**。
6. **生成过滤串是 const 方法**：只读遍历，不修改勾选态；窗口/菜单/用例（`测试选择模型测试.cpp` 的 5 个过滤串用例）都可安全调用。

### 4.2 控制台输入解析的防御链（解析控制台选择）

`数字解析`（匿名命名空间内部工具）是防御的第一道关：

```cpp
bool 数字解析(const std::string& 文本, long& 结果)
{
    if (文本.empty()) return false;              // 空串非法
    long 值 = 0;
    for (char 字符 : 文本)
    {
        if (字符 < '0' || 字符 > '9') return false;  // 非数字非法
        值 = 值 * 10 + (字符 - '0');
        if (值 > 1000000) return false;              // 防御上限：套件编号不可能达到该量级
    }
    结果 = 值;
    return true;
}
```

**易踩坑点**：`值 > 1000000` 的溢出防御在乘法累加**之后**判断——若输入是一长串 9，`值` 早已溢出 `long`（32 位下 21 亿即溢出）。不过 1000000 上限使 `值` 在达到上限前最多 7 位，`long` 远未溢出，判断位置安全。**若未来改大上限，需同步考虑累加溢出**（如改用 `if (值 > 1000000 / 10)` 预判）。

`解析控制台选择` 的完整解析流程：

```
1. 勾选表.assign(套件数, false)                     // 先整体复位
2. 去首尾空白（" \t\r\n"）；全空白 → false
3. 文本 ∈ {all, ALL, a, *} → 全 true，返回 true
4. 按 ',' 切段（std::string::find 循环）：
   ├─ 空段（"1,,3" 或尾逗号）→ false
   ├─ 段含 '-'：
   │    ├─ 左/右段任一为空 → false
   │    ├─ 右段再含 '-'（"1-2-3"）→ false
   │    ├─ 数字解析 左/右 失败 → false
   │    ├─ 左值 < 1 或 右值 < 左值 或 右值 > 套件数 → false
   │    └─ for 编号 = 左值..右值：勾选表[编号-1] = true
   └─ 单编号：
        ├─ 数字解析 失败 → false
        ├─ 编号 < 1 或 编号 > 套件数 → false
        └─ 勾选表[编号-1] = true
5. 全部段成功 → true
```

**设计决策**：① 编号从 **1** 开始（与打印列表的 `i+1` 对齐，符合人机习惯），内部换算 `编号-1`；② 区间 `a-b` 左闭右闭且必须 `左值 <= 右值`（`5-2` 判非法）；③ 越界即整体失败，不部分生效；④ 支持 `all`/`ALL`/`a`/`*` 四种全选写法（大小写各一 + 单字母 + 通配符），宽容用户输入习惯。

### 4.3 控制台选择菜单的运行流程

```
控制台选择菜单_运行(模型, 过滤串)
│
├─ 打印标题：===== 白银纪元 · 测试模块选择（控制台）=====
├─ for i in 0..套件数-1：打印 "  {i+1}) {套件名}（{用例数} 个用例）"
├─ 打印提示：请输入要测试的编号（如 1,3-5），或输入 all 全选；直接回车表示全跑：
│
└─ 循环最多 3 次（for 尝试 = 0; 尝试 < 3; ++尝试）：
   ├─ std::getline(std::cin, 输入) 失败（EOF/管道关闭）
   │    └─ 模型.全部勾选(); 过滤串 = 模型.生成过滤串();
   │       打印 "未读到输入，按全选处理。" → return
   ├─ 输入全空白（find_first_not_of == npos）
   │    └─ 模型.全部勾选(); 过滤串 = 模型.生成过滤串();
   │       打印 "空输入，按全选处理。" → return
   ├─ 解析控制台选择(输入, 套件数, 勾选表) 失败
   │    └─ 打印 "输入无法识别，请重新输入（如 1,3-5 或 all）：" → continue
   ├─ 成功：for i：模型.设置套件勾选(i, 勾选表[i])
   │        过滤串 = 模型.生成过滤串();
   │        打印 "已生成过滤串：{过滤串}" → return
└─ 三次全部非法：模型.全部勾选(); 过滤串 = 模型.生成过滤串();   // 兜底全跑
```

**边界情况处理**：
- **输入流结束（管道/重定向）**：`getline` 返回 false 时按全选处理——这是 ctest/脚本化调用控制台模式的兜底，避免死循环读 EOF。
- **空输入（直接回车）**：按全选处理，与菜单提示"直接回车表示全跑"一致。
- **三次非法输入**：`for` 循环耗尽后兜底全跑，不无限纠缠用户。
- **勾选应用**：控制台按"套件"粒度勾选（`设置套件勾选`），不支持控制台选择单个用例——用例粒度选择是图形窗口的专属能力。

### 4.4 图形选择窗口的实现细节

#### 4.4.1 初始化时序与失败降级

```
图形选择窗口_运行(模型, 过滤串)
├─ glfwInit() 失败 → return false                       // 交回主调退控制台
├─ glfwWindowHint：CONTEXT_VERSION_MAJOR=3, MINOR=3, OPENGL_CORE_PROFILE
├─ glfwCreateWindow(1120, 760, "白银纪元 · 测试模块选择") 失败
│    └─ glfwTerminate() → return false
├─ glfwMakeContextCurrent(窗口); glfwSwapInterval(1)     // 垂直同步
├─ gladLoadGL(glfwGetProcAddress) 失败
│    └─ glfwDestroyWindow(窗口); glfwTerminate() → return false
├─ IMGUI_CHECKVERSION(); ImGui::CreateContext()
├─ io.ConfigFlags |= ImGuiConfigFlags_NavEnableKeyboard  // 键盘导航（Esc/Enter）
├─ io.IniFilename = nullptr                              // 不写 imgui.ini，保持工作区整洁
├─ 应用蓝色主题()
├─ ImGui_ImplGlfw_InitForOpenGL(窗口, true)              // 安装输入回调
├─ ImGui_ImplOpenGL3_Init("#version 130")
├─ 加载中文字体(19.0f) 失败 → printf 警告（界面仍可运行，中文显示为方块）
├─ …… 主循环（见 4.4.4）……
└─ 清理：ImGui_ImplOpenGL3_Shutdown → ImGui_ImplGlfw_Shutdown
         → ImGui::DestroyContext → glfwDestroyWindow → glfwTerminate
   （若未点任何按钮即关窗：过滤串 = "*"，视为全跑）→ return true
```

**要点**：
- **GL 加载器顺序**：`#include <glad/gl.h>` 必须先于 GLFW 头文件，且 `#define GLFW_INCLUDE_NONE` 禁止 GLFW 自带 GL 头，避免与 glad 冲突（重复声明 GL 函数）。这是重开发时必须保留的 include 顺序。
- **`"#version 130"`**：ImGui 的 OpenGL3 后端着色器版本串，与 GLFW 请求的 3.3 核心上下文兼容（130 是 GLSL 1.30，对应 OpenGL 3.0+；ImGui 官方示例默认 `#version 130`）。
- **`IniFilename = nullptr`**：禁用 imgui.ini 持久化，避免在仓库目录产生脏文件。
- **三处失败点全部 `return false`**：主调据此打印"图形窗口不可用，改用控制台菜单"并走 `控制台选择菜单_运行`，完成降级。

#### 4.4.2 蓝色渐变主题（应用蓝色主题 + 绘制蓝色渐变背景）

**渐变三段色常量**（匿名命名空间）：

```cpp
const ImVec4 渐变顶端色(0.05f, 0.11f, 0.26f, 1.00f);  // 深蓝（窗口顶部）
const ImVec4 渐变中段色(0.12f, 0.28f, 0.55f, 1.00f);  // 中蓝（窗口中部）
const ImVec4 渐变底端色(0.26f, 0.52f, 0.85f, 1.00f);  // 亮蓝（窗口底部）
```

**应用蓝色主题**：修改 `ImGuiStyle::Colors` 各色板 + 样式圆角/内边距。**关键设计**：`ImGuiCol_WindowBg` 的 alpha 设为 **0.00（全透明）**——让背景绘制列表里的蓝色渐变透出来，否则窗口底色会盖住渐变。其余色板为蓝色系（ChildBg 半透明 0.55、Button 深蓝→hovered 亮蓝、CheckMark 浅蓝、TitleBg 中蓝等），样式为柔和圆角（WindowRounding=8.0f、FrameRounding=5.0f、GrabRounding=5.0f）与宽松内边距（WindowPadding=(12,12)、FramePadding=(8,5)、ItemSpacing=(8,6)）。

**绘制蓝色渐变背景**（每帧调用，在 `NewFrame` 之后、窗口渲染之前）：

```cpp
const ImGuiViewport* 视口 = ImGui::GetMainViewport();
const ImVec2 左上 = 视口->Pos;
const float 宽度 = 视口->Size.x;
const float 中点 = 视口->Size.y * 0.5f;
ImDrawList* 绘制列表 = ImGui::GetBackgroundDrawList();
// 上半段：顶端色（上）→ 中段色（下）
绘制列表->AddRectFilledMultiColor(左上, ImVec2(左上.x + 宽度, 左上.y + 中点),
    顶端色, 顶端色, 中段色, 中段色);
// 下半段：中段色（上）→ 底端色（下）
绘制列表->AddRectFilledMultiColor(ImVec2(左上.x, 左上.y + 中点),
    ImVec2(左上.x + 宽度, 左上.y + 视口->Size.y),
    中段色, 中段色, 底端色, 底端色);
```

**要点**：① **两段连续垂直渐变**通过两次 `AddRectFilledMultiColor` 在背景绘制列表（位于所有窗口之后，作为窗口底色）绘制；② 中点 = 视口高度一半，两段在中点处颜色衔接（上一段的下沿 = 下一段的上沿 = 中段色），视觉连续；③ 每帧重绘；④ 兜底清屏色 `glClearColor(渐变顶端色.x, ...)` 与渐变顶端一致，即使 ImGui 没画出来，GL 清屏也是深蓝色。

#### 4.4.4 主循环：搜索、选择树渲染、按钮

每帧流程：

```

→ 绘制蓝色渐变背景()
→ SetNextWindowPos(视口.WorkPos); SetNextWindowSize(视口.WorkSize)
→ Begin("##测试选择", nullptr, NoDecoration | NoMove | NoSavedSettings)   // 铺满视口的无标题面板
→   TextUnformatted("白银纪元 · 测试模块选择") + TextDisabled("（勾选要运行的模块或用例；Esc = 全跑）") + Separator
→   工具条：Button("全选")→全部勾选 / Button("清空")→全部清空 / Button("反选")→反向勾选
→          InputTextWithHint("##搜索", "搜索模块或用例名…", 搜索缓冲, 128) + "已选 %zu / %zu"
→   BeginChild("##选择树", ImVec2(0.0f, -44.0f), ImGuiChildFlags_Borders)

→     套件命中 = 含关键词(套件.名称, 关键词)
→     有用例命中 = 任一用例名命中关键词
→     if (!套件命中 && !有用例命中) continue                        // 整组隐藏
→     PushID(套件序号)
→     Checkbox("##套件勾选", &套件勾选) → 设置套件勾选(套件序号, 勾选后值)
→     节点标签 = 套件.名称 + "（" + 已选 + "/" + 总数 + "）"
→     SetNextItemOpen(模型.套件已展开(套件序号), ImGuiCond_Always)   // 展开态由模型持有，避免每帧复位
→     TreeNodeEx("##节点", OpenOnArrow | SpanAvailWidth, "%s", 节点标签)
→     if (展开 != 模型.套件已展开(套件序号)) 设置套件展开(套件序号, 展开)   // 同步回模型
→     if (展开) 逐用例：
→         if (!套件命中 && !含关键词(用例.名称)) continue             // 套件名未命中时按用例名过滤
→         PushID(用例序号); Checkbox(用例.名称, &用例勾选) → 设置用例勾选; PopID
→       TreePop()
→     PopID()
→   EndChild()
→   底部：Button("开始测试", (160,32)) || IsKeyPressed(Enter)
→            → 过滤串 = 模型.生成过滤串(); 已确认 = true
→         Button("取消（全跑）", (160,32)) || IsKeyPressed(Escape)
→            → 过滤串 = "*"; 已确认 = true
→         TextDisabled("复跑：EngineTests.exe --gtest_filter=<过滤串>")
→ End()
→ ImGui::Render()
→ glfwGetFramebufferSize → glViewport → glClearColor(顶端色) → glClear
→ ImGui_ImplOpenGL3_RenderDrawData → glfwSwapBuffers
→ if (已确认) break
```

**易踩坑点**：
1. **展开态必须由模型持有**：若用局部变量存展开态，每次 `TreeNodeEx` 后的点击会因下一帧重建而复位，用户无法保持展开。代码用 `SetNextItemOpen(模型.套件已展开(序号), ImGuiCond_Always)` 强制每帧按模型值设置，再检测返回值变化写回模型（`如果(展开 != 模型.套件已展开(序号)) 设置套件展开`）。
2. **PushID/PopID 成对**：套件用 `套件序号`、用例用 `用例序号` 作 ID，防止同名字段在 ImGui 的 ID 栈中冲突（多套件下 `##套件勾选`/`##节点` 重名必须有 ID 区分）。
3. **`ImGuiChildFlags_Borders`**：`BeginChild` 使用新版标志（ImGui 1.90+ 的 `ImGuiChildFlags`），高度 `-44.0f` 表示"底部留 44 像素"给按钮行。
4. **搜索过滤是"隐藏"而非"删除"**：隐藏的套件/用例只是不渲染，勾选态保留，避免搜索导致误改选择。
5. **Enter/Esc 快捷操作**：Enter = 开始测试（等同"开始测试"按钮），Esc = 取消全跑（等同"取消（全跑）"按钮），依赖 `NavEnableKeyboard`。
6. **关窗即全跑**：主循环因 `glfwWindowShouldClose` 退出且 `已确认==false` 时，过滤串置 `"*"`，与"取消"语义一致。
7. **渲染前 glViewport**：以 `glfwGetFramebufferSize`（物理像素）而非窗口尺寸设置视口，否则高分屏/缩放会拉伸。

### 4.5 main() 的参数摘取与四步分流（主程序.cpp）

**参数摘取循环**（第一步）：

```cpp
std::string 选择模式 = "window";
bool 显式选择器 = false;
std::vector<std::string> 保留参数文本;
保留参数文本.push_back((argv[0] != nullptr) ? argv[0] : "EngineTests");  // 兜底 argv[0]
bool 命令行带过滤 = false;
for (int i = 1; i < argc; ++i)
{
    const std::string 参数 = (argv[i] != nullptr) ? argv[i] : "";
    if (参数.rfind(选择器前缀, 0) == 0)              // "--selector=" 前缀命中
    {
        选择模式 = 参数.substr(std::strlen(选择器前缀));
        显式选择器 = true;
        continue;                                    // 不进入保留参数
    }
    if (参数.rfind("--gtest_", 0) == 0)
        命令行带过滤 = true;                          // 只做标记，参数保留
    保留参数文本.push_back(参数);
}
// 重建 argv：std::vector<char*> 参数指针 ← 各 string::data()，末尾 nullptr
int 参数个数 = static_cast<int>(保留参数文本.size());
```

**要点**：① `rfind(前缀, 0) == 0` 是"前缀匹配"惯用法（C++20 无 `starts_with` 时）；② `--selector=` 参数**不保留**给 gtest（否则 gtest 报未知 flag）；③ `--gtest_*` 参数**保留**给 gtest，同时打标记；④ `argv[0]` 兜底 `"EngineTests"` 防空指针；⑤ 选择模式取 `substr(strlen("--selector="))`，故 `--selector=off` → `"off"`、`--selector=console` → `"console"`、`--selector=window` → `"window"`，**未知值会落到 else 分支走图形窗口**（4.6 有说明）。

**四步分流时序**：

```
main(argc, argv)
│ 0. SetConsoleOutputCP(CP_UTF8); SetConsoleCP(CP_UTF8)      // 控制台切 UTF-8，中文用例名可读
│ 1. 参数摘取（如上）
│ 2. ::testing::InitGoogleTest(&参数个数, 参数指针.data())    // 必须在取反射前完成
│ 3. if ((命令行带过滤 && !显式选择器) || 选择模式 == "off")
│        return RUN_ALL_TESTS();                             // ① 透传 ② 全跑：不开窗
│ 4. engine::测试选择模型 模型; 模型.建立套件树();
│    if (选择模式 == "console")
│        engine::控制台选择菜单_运行(模型, 过滤串);            // ③ 控制台菜单
│    else if (!engine::图形选择窗口_运行(模型, 过滤串))         // ④ 默认/窗口
│    {
│        std::cout << "[测试选择] 图形窗口不可用，改用控制台菜单。" << std::endl;
│        engine::控制台选择菜单_运行(模型, 过滤串);            //    失败降级
│    }
│ 5. std::cout << "[测试选择] 过滤串：" << 过滤串 << std::endl;
│    std::cout << "[测试选择] 可用 --gtest_filter=" << 过滤串 << " 复跑同一批用例。" << std::endl;
│    ::testing::GTEST_FLAG(filter) = 过滤串;                  // 过滤串落地
│    const int 测试结果 = RUN_ALL_TESTS();
│    if (engine::需要等待退出(选择模式, 命令行带过滤, 显式选择器))
│        等待用户关闭窗口();                                   // 交互运行停住
│    return 测试结果;
```

**设计决策**：
1. **InitGoogleTest 必须在反射建树之前**：`建立套件树()` 读取 `UnitTest::GetInstance()` 的注册表，而 gtest 参数（如 `--gtest_filter` 影响 `total_test_count`？不，注册表在静态初始化期已建）——真正原因是 gtest 的 `InitGoogleTest` 会解析参数并可能 `exit`（如 `--gtest_help`），先初始化保证参数语义（尤其 `--gtest_list_tests`）正确。代码注释明示"必须在取反射前完成"。
2. **透传分支不开窗也不建模型**：`(命令行带过滤 && !显式选择器)` 或 `off` 直接 `RUN_ALL_TESTS()`——零开销、无交互、跑完即退，是 CI/ctest 的黄金路径。
3. **交互路径复用模型建树**：窗口/菜单共用 `模型`，选择结果统一走 `GTEST_FLAG(filter)` 落地，之后只调一次 `RUN_ALL_TESTS()`，无论选中多少用例都只跑一轮（gtest 过滤在框架内完成）。
4. **过滤串打印**：执行前打印实际过滤串 + 复跑命令，方便用户记录与复现。
5. **返回码透传**：`return 测试结果` 即 `RUN_ALL_TESTS()` 的退出码（0 = 全过，非 0 = 有失败），供 CI 判级。

**易踩坑点**：
- **`--selector` 与 `--gtest_*` 并存**：显式选择器优先于"带 gtest 参数即透传"的自动化约定——`--selector=console --gtest_filter=Timer_Test.*` 会走控制台菜单，菜单结果覆盖过滤串（此时命令行 `--gtest_filter` 已被 `GTEST_FLAG(filter)=过滤串` 覆盖）。退出等待也按"显式选择器优先"判定（见 2.2 判定表第 4 行）。
- **未知选择模式**：`--selector=xxx` 既不等于 `off` 也不等于 `console`，落在 `else` 分支走图形窗口；若图形窗口又创建失败则退控制台菜单。退出等待判定对未知模式兜底"停住"（宁可多等）。
- **`GetConsoleWindow` 判空**：重定向输出（`> log.txt`）或 CI 无控制台窗口时 `_getch` 会直接返回/无对象可等，提前 `return` 防挂住；`FlushConsoleInputBuffer` 清残留按键防"回车被立刻吃掉"。

1. **对 googletest**：本模块是框架的"宿主"——`main()` 负责 `InitGoogleTest` 与 `RUN_ALL_TESTS`，模型负责反射（`UnitTest::GetInstance()`），过滤串通过 `GTEST_FLAG(filter)` 交给框架执行。
2. **对用例**：`测试选择模型测试.cpp`（16 例）直接构造 `engine::测试选择模型` 验证反射建树/勾选态/过滤串/解析；`退出暂停判定测试.cpp`（8 例）链接可执行文件中的 `engine::需要等待退出` 符号验证全部参数组合——**用例即文档，回归即护城河**。
3. **对引擎/系统层**：本层只消费两层已构建好的静态库（`EngineCore`/`SystemCore` 导入目标），通过 `byjy_jieru_xiaceng()` 的覆盖变量或自动探测定位，任何情况下不回退编译下层源码。
4. **对构建系统**：`TestGui`（ImGui+glad）只被 `EngineTests` 链接；`TestLauncher`（纯逻辑）既被 `EngineTests` 链接也被用例目标链接；`EngineTestObjects` OBJECT 库保证 338 个 TEST 静态注册不被链接器丢弃。

### 5.4 重开发要点清单（快速上手）

1. **加新入口参数**：在 `main()` 参数摘取循环中仿照 `--selector=` 加前缀判断；注意"保留参数给 gtest、自定义开关自己消费"的分工。
2. **加新套件**：在 `src/单元测试/` 下新增 `*测试.cpp`，CMake 的 `file(GLOB_RECURSE ... CONFIGURE_DEPENDS)` 会自动收编进 `EngineTestObjects`；`--selector=off` 全跑与图形窗口自动可见新套件（反射驱动，无需改主调代码）。
3. **改过滤串生成**：`生成过滤串()` 的三态压缩是核心，改动后必须同步跑 `测试选择模型测试` 的 5 个过滤串用例。
4. **改退出等待语义**：只改 `主程序.cpp` 里的 `需要等待退出()` 实现（声明在 `.h`），8 个 `退出暂停判定测试` 用例自动覆盖全部参数组合。
5. **图形窗口回归**：无图形环境时 `图形选择窗口_运行` 返回 false 走控制台菜单，此降级路径可用 `--selector=window` 在 CI 上验证（窗口创建失败即触发）。
