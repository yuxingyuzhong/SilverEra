## 一、模块功能（该模块做什么，解决什么问题，服务谁）

### 1.1 模块定位

测试层单元测试体系是「白银纪元」引擎**测试层**的"用例仓库"。它位于 `测试层\src\单元测试\` 目录，由 **20 个 `*测试.cpp` 用例源文件**组成，通过 googletest（gtest）的 `TEST_F` 宏注册 **22 个测试套件、338 个测试用例**，覆盖引擎层（`EngineCore`）与系统层（`SystemCore`）两大下层的核心功能模块。

整个体系与主调模块（`src/主调/`，见《测试层主调与选择器.md》）协作：用例注册进 gtest 静态注册表 → 主程序的 `测试选择模型::建立套件树()` 反射枚举出套件树 → 用户经图形窗口/控制台菜单勾选 → 生成过滤串 → `RUN_ALL_TESTS()` 执行选中的用例。**用例即被测层的"可执行规格说明书"**。

### 1.2 解决的核心问题

1. **功能正确性的持续回归**：引擎/系统层的每个功能模块都有对应套件，从构造、读写、边界条件到错误路径全覆盖。`EngineTests.exe --selector=off` 一键全量回归 338 个用例，任何下层改动导致的回归都能被立即捕获。
2. **测试选择与精准复跑**：338 个用例全跑较慢（且含大量空间数据结构压力用例），开发期通过选择器按套件/用例粒度精准运行；`--gtest_filter=套件.用例` 可直接透传复跑。
3. **跨层被测覆盖**：用例直接 `#include "src/core/.../xxx.h"` 或 `#include "src/tools/.../xxx.h"`，链接已构建好的 `EngineCore`/`SystemCore` 静态库，验证的是**真实现**而非 mock。
4. **缺陷回归固化**：若干用例来源于历史缺陷修复（如四叉树 2^33 截断除零、坐标类型 ULP 比较、事件中转器行为语义变迁），把"曾经坏过的地方"固化为永久回归用例，防止复发。
5. **中文可读性**：套件名/用例名全中文（如 `测试选择模型测试`、`退出暂停判定测试`、`碰撞体编号自一起分配`），测试报告一眼可读，贴近项目团队习惯。

### 1.3 服务谁

- **直接服务对象**：`EngineTests.exe`（执行入口）、开发者（开发期选择复跑）、CI/ctest（自动化回归）。
- **被服务对象**：引擎层（事件系统/空间分区/碰撞/对象系统）与系统层（日志/校验/加载器/计时器/随机数/分配器/路径转换/引擎环境）的全部功能模块——每一个被测模块都是一个或多个套件。
- **底层依赖**：googletest（`GTest::gtest`，仅测试框架本体，不含 `gtest_main`）、引擎层 `EngineCore`、系统层 `SystemCore`（均为已构建静态库）、`TestLauncher` 静态库（`测试选择模型` 与 `控制台选择菜单`，供主调相关用例 include）、`nlohmann::json`（事件/碰撞用例构造载荷）、`Engine_Env`（临时文件写入相对可执行文件目录）。

### 3.3 构建集成（googletest 接入方式）

来自 `测试层/CMakeLists.txt` 第 4/4.5/5 节：

```cmake
# 4. googletest 以源码形式内嵌 external/googletest，EXCLUDE_FROM_ALL 接入
set(INSTALL_GTEST OFF CACHE BOOL "" FORCE)
set(BUILD_GMOCK OFF CACHE BOOL "" FORCE)
set(gtest_force_shared_crt ON CACHE BOOL "" FORCE)   # 强制共享 CRT，避免 LNK2038
add_subdirectory("${PROJECT_ROOT_DIR}/external/googletest"
    "${CMAKE_BINARY_DIR}/googletest" EXCLUDE_FROM_ALL)

# 用例源收集（GLOB_RECURSE + CONFIGURE_DEPENDS 自动收编新用例文件）
file(GLOB_RECURSE BYJY_TEST_SOURCES CONFIGURE_DEPENDS
    "${PROJECT_ROOT_DIR}/src/单元测试/*.cpp")

# 4.5 TestLauncher：测试选择模型 + 控制台选择菜单（纯逻辑，供用例 include）
add_library(TestLauncher STATIC ...测试选择模型.cpp 控制台选择菜单.cpp)
target_link_libraries(TestLauncher PUBLIC GTest::gtest)

# 4.5 EngineTestObjects OBJECT 库：编一次，EngineTests 取一份 .obj
add_library(EngineTestObjects OBJECT ${BYJY_TEST_SOURCES})
target_link_libraries(EngineTestObjects PUBLIC
    EngineCore SystemCore GTest::gtest TestLauncher)

# 5. EngineTests.exe（本层唯一可执行文件）
add_executable(EngineTests
    $<TARGET_OBJECTS:EngineTestObjects>
    "${PROJECT_ROOT_DIR}/src/主调/主程序.cpp"
    "${PROJECT_ROOT_DIR}/src/主调/图形选择窗口.cpp")
target_link_libraries(EngineTests PRIVATE
    EngineTestObjects EngineCore SystemCore GTest::gtest TestLauncher TestGui)
set_target_properties(EngineTests PROPERTIES
    RUNTIME_OUTPUT_DIRECTORY "${PROJECT_ROOT_DIR}")   # 产物 = 层根目录/EngineTests.exe
```

**接入要点**：

1. **EXCLUDE_FROM_ALL**：googletest 只在被 `EngineTests`/`TestLauncher` 依赖时才编译，不改变静态库的既有构建范围。
2. **gtest_force_shared_crt ON**：强制 googletest 与引擎层使用一致的运行时库（否则 MSVC 下 LNK2038 冲突）。
3. **不装 gmock、不装 gtest**：`BUILD_GMOCK OFF` + `INSTALL_GTEST OFF`；只消费 `GTest::gtest` 目标（不用 `GTest::gtest_main`，main 由主调提供）。
4. **EngineTestObjects 用 OBJECT 库而非 STATIC 库**（本层核心决策）：静态库里未被引用的 `.obj` 会被链接器丢弃，`TEST` 宏的静态注册（`UnitTest::AddTest` 注册到全局注册表）随之丢失，用例便**静默不跑**。OBJECT 库不打包，`EngineTests` 以 `$<TARGET_OBJECTS:EngineTestObjects>` 全量引用其 `.obj`，338 个用例全部保留注册。**改回 STATIC 库是本体系最危险的"优化"**。
5. **用例 include "src/主调/测试选择模型.h"**：`TestLauncher` 以 `PUBLIC` 暴露本层根目录包含路径（`target_include_directories(TestLauncher PUBLIC "${PROJECT_ROOT_DIR}")`），用例因此可用 `src/...` 相对工程根路径 include 主调头文件；引擎/系统层头文件路径由 `EngineCore`/`SystemCore` 的对外面传递（含 `src/` 头文件、`common/` 预编译头、`external/Json`、`external/glfw`）。
6. **编译选项**：MSVC 下 `/MP /utf-8` + `_CRT_SECURE_NO_WARNINGS`（保证中文源码与宽字符兼容）；其他编译器 `-Wall -Wextra -pedantic` + `_GNU_SOURCE`。

```cmake
if("${PROJECT_ROOT_DIR}" MATCHES "^[ -~]+$")     # 工程路径为纯 ASCII
    include(GoogleTest)
    gtest_discover_tests(EngineTests WORKING_DIRECTORY "${PROJECT_ROOT_DIR}")
else()                                            # 工程路径含非 ASCII 字符
    # 不开窗直接全跑：无参数的 ctest 不会阻塞在图形窗口上
    add_test(NAME EngineTests COMMAND EngineTests --selector=off
        WORKING_DIRECTORY "${PROJECT_ROOT_DIR}")
endif()
```

**原因**：`gtest_discover_tests` 会以 `--gtest_output=json:<文件>` 枚举用例，而 googletest 写该 JSON 报告文件时**按 ANSI 代码页解析路径**——工程路径含中文（本仓库 `D:\代码存储\...` 即含中文）时必然失败（`[FATAL] Unable to open file ...\cmake_test_discovery_*.json`），构建会被判失败。故纯 ASCII 路径启用逐用例注册，含中文则退化为**整体注册一个用例**（`--selector=off` 全量跑），并在 message 提示"请直接运行 EngineTests.exe --gtest_filter=xxx 筛选用例"。

### 4.2 测试模式与复用技巧（全体系通用）

1. **行为可观察断言**：当被测 API 不再提供直接查询时，改为观察可验证行为。例：`Event_Broker_Test` 中引擎层 e430610 移除 `target_object_check` 后，"注册状态"改为"登记后投递匹配事件应送达 1 次"（`注册后状态确认`），"未登记"改为"投递安静结束不崩溃"（`未注册状态确认失败`）。
2. **缺陷回归段落**：`Quadtree_Manager_Test` 文件末尾专设「缺陷回归（修复后启用）」段落，注释写明**历史缺陷、根因、修复语义**（如 `超大边长上限下区块检索次数正常` 详细记录了 2^33 截断为 0 → `width % father_block_size` 除零 SEH 0xC0000094 → 尺寸层 64 位化 + 早退防御），并明示"原先固化引擎缺陷并处于禁用状态的用例，缺陷修复后已转为正式回归用例，无遗留禁用用例"。**新增缺陷修复时，应照此把复现用例转正并保留根因注释**。
3. **临时文件生命周期**：需要文件输入的被测模块（`Mesh_Loader_Test`、碰撞的边界构建）都在用例内写临时文件（相对 `Engine_Env::exe_dir_get()` 拼接，文件路径含中文目录）、用例末尾删除（`std::filesystem::remove` + `std::error_code` 容错）。临时文件集中在 `src/单元测试/核心/`、`src/单元测试/工具/` 下（`.obj` 文本网格）。
4. **确定性测试数据**：随机数、计时器等非确定性模块通过"固定种子 + 性质断言"（如 `Random_Generator_Test` 断言区间覆盖、不重复，而非具体随机值）规避 flaky；计时器断言用"正间隔""多次读取不重置"这类稳定性质。
5. **断言强度分级**：`EXPECT_*`（失败继续）用于性质校验；`ASSERT_*`（失败即中止本用例）用于后续依赖的前置条件（如拿到 ID、取到结果对象后再断言其内容），避免空指针连锁崩溃。

### 4.3 易踩坑点（重开发必读）

1. **别把 EngineTestObjects 改回 STATIC 库**：`TEST` 宏的静态注册依赖 .obj 被链接，静态库未引用 .obj 会被丢弃 → 用例静默不跑（最隐蔽的失败）。
2. **别引入 `gtest_main`**：`main` 由主调 `主程序.cpp` 提供；若误链 `GTest::gtest_main` 会 main 重定义。
3. **`/utf-8` 编译选项不可去**：源码全中文（含中文用例名、中文路径 include、中文临时文件名），去掉后 MSVC 按本地代码页解析将产生乱码/编译错。
4. **临时文件必须清理**：`Mesh_Loader_Test`/碰撞测试写出的 `.obj` 若不删会污染仓库；用例内用 `std::error_code` 容错的 `remove`。
5. **捕获控制台输出的坑**（`Log_Test`）：**不用 gtest 的 `CaptureStdout`**——它在临时目录建 `.tmp` 文件，本机临时目录含中文时窄字符 `fopen` 解析失败会直接 FATAL 打断整个用例进程；改为自研 `Console_Capture`（`std::cout.rdbuf(buffer.rdbuf())` 接管标准输出缓冲区，析构还原），因为日志系统写的是 `std::cout` 对象本身。
6. **中文路径贯穿**：工程路径、临时文件路径、用例名全含中文；ctest 枚举、`gtest_discover_tests` 的 JSON 报告路径都受此影响（见 3.4），依赖外部工具时必须考虑 ANSI/UTF-8 代码页差异。
7. **浮点比较用工程语义**：`Coord_Type_Test` 验证的是 `Point2d` **4-ULP 容差相等**、正负零相等、NaN 一律不等、无穷精确比较——写新用例别用 `==` 裸比较浮点。
8. **跨套件命名冲突**：`Test_Object`（对象池/对象测试各自派生）等辅助类位于各自文件匿名/文件级作用域，若新增文件也派生同名类要留意链接冲突（文件级 `static`/匿名命名空间隔离）。
9. **反射依赖静态注册完成**：`测试选择模型::建立套件树()` 依赖 googletest 单例 `UnitTest::GetInstance()`——该单例的套件树在**静态初始化期**由 TEST 宏注册填充，因此用例运行时反射已就绪；若想"反射到本文件之外的新套件"，需保证新用例文件被编进 `EngineTestObjects` 且在 `InitGoogleTest` 后运行。
10. **禁用用例规范**：历史上有"缺陷未修 → 用 `DISABLED_` 前缀禁用 + 注释说明"的过渡做法（四叉树管理器缺陷回归段即源于此）；缺陷修复后必须转正，保持"0 DISABLED"基线。

### 5.3 与主调模块的协作关系

- **反射**：`测试选择模型::建立套件树()` 读取的正是本体系 TEST 宏注册的 `UnitTest` 单例——**用例数量/名称就是选择器呈现的套件树**，二者由 gtest 注册表天然同步，无需手工维护名单。
- **过滤串**：选择器生成的过滤串（`"*"` / `"套件.*"` / `"套件.用例:..."`）正是 gtest 执行本体系用例的筛选条件；`测试选择模型测试` 的 5 个过滤串用例直接验证这套生成逻辑。
- **退出等待**：`退出暂停判定测试` 的 8 个用例链接主程序中的 `需要等待退出` 实现，保证"交互停住/自动化不停"的判定与主程序实际行为一致。
- **本层自测**：主调模块（`src/主调/`）的用例与引擎/系统层用例编进同一 `EngineTestObjects`，`--selector=off` 全量回归时一并覆盖，形成"测试层自举"——测试系统自身的逻辑也被 338 用例中的 24 例（主调 2 套件）守护。

### 5.4 扩写新用例的完整操作步骤

1. **新建文件**：在 `src/单元测试/<主调|工具|核心>/` 下新建 `被测模块测试.cpp`，按 3.2 骨架写夹具与 `TEST_F`。
2. **自动收编**：`file(GLOB_RECURSE ... CONFIGURE_DEPENDS)` 使 CMake 重跑（`cmake --build` 触发 CONFIGURE_DEPENDS 检测）后自动把新文件编进 `EngineTestObjects`，无需改 CMakeLists（除非新套件需要额外链接库）。
3. **构建**：`cmake --build <测试层>/out/build/x64-Debug` → 重新生成 `测试层/EngineTests.exe`。
4. **运行**：`EngineTests.exe --gtest_filter=新套件.*` 或 `--selector=off` 全量回归。
5. **验证反射**：图形窗口/控制台菜单会自动出现新套件（反射驱动）。
6. **缺陷回归规范**：若用例对应历史缺陷，保留根因注释，禁止 `DISABLED_` 残留。
