## 1. 模块功能

### 1.1 模块是什么

「日志系统 Log」是引擎层 `src/tools/Logging/日志系统.h` 定义的一个**静态工具类**（含一个全局 `std::formatter<std::error_code>` 特化），为整个引擎提供统一、轻量、线程模型简单的日志输出能力：

| 能力 | 入口 | 说明 |
| --- | --- | --- |
| 四级别日志 | `Log::info` / `Log::warn` / `Log::error` / `Log::debug` | 静态模板函数，`std::format` 风格格式化（`{}` 占位符 + 类型安全的参数包） |
| 消息级别前缀 | 自动加 `[INFO]` / `[WARN]` / `[ERROR]` / `[DEBUG]` | 输出形如 `[INFO]消息内容` |
| 输出目标切换 | `stream_set(filename)` | 指定活跃文件输出流（后续日志写到该文件）；空串回落控制台 |
| 文件流自动管理 | `stream_charge`（内部） | 按文件名缓存 `std::ofstream`（惰性创建、复用、失败回落控制台） |
| 错误码格式化 | `std::formatter<std::error_code>` 特化 | 使 `Log::info("{}", ec)` 可直接输出 `[value] message` |
| 结尾换行 | 自动 `std::endl` | 每条日志独立一行，且刷新流缓冲 |

### 1.2 模块解决什么问题

- **日志输出分散问题**：引擎各模块（Data_Validator、Config_Loader、Engine_Env、Number_Allocator、Collision_Region 等）都需要输出运行信息/警告/错误。若各自 `std::cout << ...`，格式不统一、目标不可控、无法统一切换输出文件。
- **格式化安全性问题**：C 风格 `printf("%s", str)` 若误传非 POD 类型是未定义行为。`Log` 采用 C++20 `std::format`（编译期格式串校验 + 类型安全），杜绝格式化漏洞与类型误配。
- **日志目标单一问题**：开发期希望日志上控制台实时可见，运行期希望落盘归档。`stream_set` + 流缓存机制让"控制台 ↔ 文件"切换一行代码完成，且**按文件名缓存多个文件流**，允许不同阶段/模块把日志写到不同文件。
- **错误码可读性问题**：`std::error_code` 默认没有 `std::formatter` 特化（C++20 标准库不保证），直接 `std::format("{}", ec)` 编译失败。日志系统在文件尾部提供显式特化，使 `Log::info("{}", error_info)`（Data_Validator::error_out 正是这么用的）可编译且输出 `[值] 消息`。

### 1.3 模块服务谁

- **服务方（被调用方）**：引擎层全部需要日志的模块——Data_Validator（数据校验器）、Config_Loader（配置加载器）、Engine_Env（引擎环境）、Number_Allocator（数值分配器）、碰撞空间/碰撞代理器等；系统层业务模块（间接经上述模块或直接调用）。
- **调用方画像**：任何 `#include "src/tools/Logging/日志系统.h"` 的翻译单元，直接调用 `Log::xxx` 静态方法，无需实例化。
- **不服务**：不做日志分级过滤（无"仅输出 ERROR 以上"配置）、无时间戳、无线程安全保证（文档化限制，见 §4.5）、无异步落盘。

### 1.4 版本演变（重要背景）

- 本版次（089b070）之前的版本：日志系统曾提供**多个文件输出重载**（如带文件名参数的 `info/warn/error/debug` 重载或 `stream_set` 的多重载形式）。
- 本版次：**已删除全部文件输出重载**，收敛为：
  - 四个静态日志函数只接受 `std::format_string` + 参数包；
  - 输出目标统一由**非静态** `stream_set(const std::string& stream)` 指定（修改静态成员 `active_file_stream`）。
- 因此**当前所有日志函数本身没有"指定文件"的入口**；要改输出目标必须调用 `stream_set`。这一收敛简化了 API 面，但引入了"非静态方法修改静态状态"的用法约束（见 §4.6）。

## 2. 模块提供接口

### 2.1 `Log` 类全貌

```cpp
namespace engine
{
    //日志系统
    class Log
    {
    private:
        //输出流别名
        using Stream = std::shared_ptr<std::ostream>;
        //文件输出流别名
        using FileStream = std::shared_ptr<std::ofstream>;
        //日志别名
        using LogState = std::pair<Stream, std::string>;
    public:
        //文件输出流设置
        void stream_set(const std::string& stream);
        //信息输出
        template<typename... Args>
        static void info(std::format_string<Args...> fmt, Args&&... args);
        //警告输出
        template<typename... Args>
        static void warn(std::format_string<Args...> fmt, Args&&... args);
        //错误输出
        template<typename... Args>
        static void error(std::format_string<Args...> fmt, Args&&... args);
        //调试输出
        template<typename... Args>
        static void debug(std::format_string<Args...> fmt, Args&&... args);
    private:
        //输出流流控制
        static Stream stream_charge(const std::string& file_name);
        //日志构建
        template<typename... Args>
        static LogState log_build(const std::string& file_name,
            std::format_string<Args...> fmt, Args&&... args);
        //日志输出
        static void output(Stream stream, const std::string& output, const std::string& type);

        //活跃文件输出流
        inline static std::string active_file_stream{};
        //输出流集合
        inline static std::unordered_map<std::string, FileStream> streams;
    };
}
```

### 2.2 公开接口逐项说明

#### 2.2.1 `stream_set`

```cpp
void stream_set(const std::string& stream)
{
    //记录其为活跃输出流
    active_file_stream = stream;
}
```

| 项 | 说明 |
| --- | --- |
| 签名 | `void stream_set(const std::string& stream)`——**非静态成员函数** |
| 参数 `stream` | 目标文件名。**空串 `""` 表示回落控制台**；非空表示后续日志输出到该文件（文件由 `stream_charge` 惰性打开并缓存） |
| 行为 | 只做一件事：把参数复制进静态成员 `active_file_stream`。**不立即打开文件**（打开发生在下一次日志输出时，见 §4.3 惰性创建） |
| 用法约束 | 因函数非静态，必须通过实例调用：`engine::Log logger; logger.stream_set("log.txt");`。**不能** `Log::stream_set(...)`。而四个日志函数是静态的，可在任意处直接调用——这种"实例方法设置全局状态 + 静态方法消费"的模式是本版本刻意的设计简化 |
| 线程安全 | 无锁。并发调用 stream_set 与 info 会产生数据竞争（见 §4.5） |

#### 2.2.2 `info` / `warn` / `error` / `debug`

```cpp
template<typename... Args>
static void info(std::format_string<Args...> fmt, Args&&... args)
{
    //构建日志
    LogState buffer = log_build(active_file_stream, fmt, std::forward<Args>(args)...);
    //输出消息
    output(buffer.first, buffer.second, "INFO");
}

template<typename... Args>
static void warn(std::format_string<Args...> fmt, Args&&... args)
{
    LogState buffer = log_build(active_file_stream, fmt, std::forward<Args>(args)...);
    output(buffer.first, buffer.second, "WARN");
}

template<typename... Args>
static void error(std::format_string<Args...> fmt, Args&&... args)
{
    LogState buffer = log_build(active_file_stream, fmt, std::forward<Args>(args)...);
    output(buffer.first, buffer.second, "ERROR");
}

template<typename... Args>
static void debug(std::format_string<Args...> fmt, Args&&... args)
{
    LogState buffer = log_build(active_file_stream, fmt, std::forward<Args>(args)...);
    output(buffer.first, buffer.second, "DEBUG");
}
```

| 项 | 说明 |
| --- | --- |
| 模板参数 | `Args...`：格式化参数包。`std::format_string<Args...>` 是 C++20 的**受约束格式串类型**——传入的字面量在编译期被校验，`{}` 数量与参数数量/类型不匹配时**编译报错** |
| 参数 `fmt` | 格式串，如 `"Data_Validator::字段 {} 类型不匹配"`；占位符 `{}`（亦支持 `{:spec}` 格式规范） |
| 参数 `args` | 被格式化的值，以 `std::forward<Args>(args)...` 完美转发 |
| 返回值 | void |
| 行为 | ① `log_build` 用当前 `active_file_stream`（静态成员）调用 `stream_charge` 拿到目标输出流 `Stream`，同时 `std::format` 生成消息文本；② `output` 组装 `[级别]消息` 并写入流 + `std::endl` |
| 级别标签 | info→`[INFO]`、warn→`[WARN]`、error→`[ERROR]`、debug→`[DEBUG]`。**注意**：当前实现不做任何级别过滤，四者行为差异只有标签前缀不同 |
| 常见用法 | `Log::info("{}", field)`、`Log::info("错误路径如下: {}", file_path.string())`、`Log::warn("Data_Validator::未包含指定字段: {}", field)`、`Log::error("错误: {}", e.what())` |
| 支持的类型 | 任何满足 `std::formatter` 的类型：基本类型、`std::string`、`std::string_view`、`std::filesystem::path`（C++23 起）、`std::error_code`（依赖本文件特化）等 |
| 异常 | `std::format` 对运行期格式错误（如类型不匹配的 `{:d}`）可能抛 `std::format_error`；本实现未捕获，异常会传播给调用方 |

### 2.3 私有接口（内部机制）

#### 2.3.1 `stream_charge`（流控制核心）

```cpp
static Stream stream_charge(const std::string& file_name)
{
    Stream stream;                                    // 待返回的输出流

    //若未指定输出文件名
    if (file_name.empty())
        stream = std::shared_ptr<std::ostream>(&std::cout, [](std::ostream*) {});   // 控制台
    //若指定输出文件名
    else
    {
        //检查该文件名是否已创建流
        auto it = streams.find(file_name);
        //若流已经存在则指针指向该流
        if (it != streams.end())
            stream = it->second;                      // 命中缓存
        //若流不存在则创建新流
        else
        {
            stream.reset(new(std::nothrow) std::ofstream(file_name));   // 惰性打开
            if (!stream)                              // ① 内存分配失败
            {
                stream = std::shared_ptr<std::ostream>(&std::cout, [](std::ostream*) {});
                *stream << "[FATAL]" << "内存不足\n已切换至控制台输出\n";
            }
            else
            {
                FileStream filestream = std::static_pointer_cast<std::ofstream>(stream);
                if (filestream->is_open())            // ② 打开成功 → 入缓存
                    streams.insert({ file_name, filestream });
                else                                  // ③ 打开失败 → 回落控制台
                {
                    stream = std::shared_ptr<std::ostream>(&std::cout, [](std::ostream*) {});
                    *stream << "[ERROR]" << "文件打开失败\n已切换至控制台输出\n";
                }
            }
        }
    }
    return stream;
}
```

| 项 | 说明 |
| --- | --- |
| 空文件名 | 返回 `std::shared_ptr<std::ostream>(&std::cout, 空删除器)`——**共享所有权的控制台流**。删除器为空 lambda，防止 shared_ptr 析构时 delete 栈上的 `std::cout` |
| 缓存命中 | `streams`（`unordered_map<string, FileStream>`）以文件名为键；命中直接返回既有流，**不重复打开文件** |
| 惰性创建 | 首次遇到某文件名时 `new(std::nothrow) std::ofstream(file_name)`。**注意**：`std::ofstream` 的打开失败（如目录不存在、无权限）不抛异常，需 `is_open()` 检查 |
| 分配失败（[FATAL]） | `new(nothrow)` 返回 nullptr → 回落控制台并输出 `[FATAL]内存不足\n已切换至控制台输出\n`（**注意**：此处用 `<<` 直接写控制台，未走 `output` 的标准 `[级别]` 包装，且是裸 `\n` 非 endl） |
| 打开失败（[ERROR]） | `!is_open()` → 回落控制台并输出 `[ERROR]文件打开失败\n已切换至控制台输出\n` |
| 返回值 | `Stream` = `shared_ptr<std::ostream>`。文件流经 `static_pointer_cast<ofstream>` 判断 is_open 后，以 `shared_ptr<ofstream>`（FileStream）存入缓存；返回给日志函数的是基类 `shared_ptr<ostream>` 视图 |
| 缓存增长 | `streams` 只增不减（模块生命周期内），每次切换新文件名都会留下一个打开的文件流句柄。长时间运行且频繁切换文件名可能耗尽文件描述符（见 §4.6） |

#### 2.3.2 `log_build`（日志构建）

```cpp
template<typename... Args>
static LogState log_build(const std::string& file_name,
    std::format_string<Args...> fmt, Args&&... args)
{
    LogState buffer{};                                       // pair<Stream, string>
    buffer.first = stream_charge(file_name);                 // 解析输出流
    buffer.second = std::format(fmt, std::forward<Args>(args)...);  // 格式化正文
    return buffer;
}
```

| 项 | 说明 |
| --- | --- |
| `LogState` | `std::pair<Stream, std::string>`：first=输出流（shared_ptr），second=格式化后的消息正文 |
| 职责 | 把"解析流"与"格式化文本"两个步骤打包，四个日志函数共用 |
| 顺序 | 先 stream_charge 再 format。**若 format 抛异常**（format_error），流已解析但未输出，异常传播给调用方 |

#### 2.3.3 `output`（日志输出）

```cpp
static void output(Stream stream, const std::string& output, const std::string& type)
{
    const std::string msg_type = std::format("[{}]", type);   // 组装 [INFO] 等前缀
    *stream << msg_type << output << std::endl;                // 输出并刷新
}
```

| 项 | 说明 |
| --- | --- |
| 组装 | `[{}]` + 正文。**无空格分隔**：形如 `[INFO]消息正文` |
| 换行刷新 | `std::endl` = 写入 `\n` + `flush()`。每条日志都强制刷新，保证日志即时落盘/上屏（代价是频繁 flush 的 I/O 开销） |
| 流写入 | `*stream << ...` 重载链；对 `std::cout` 与文件流通用 |

#### 2.3.4 静态成员

```cpp
//活跃文件输出流
inline static std::string active_file_stream{};
//输出流集合
inline static std::unordered_map<std::string, FileStream> streams;
```

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `active_file_stream` | `std::string` | 当前活跃输出目标文件名。`{}` 初始化=空串=控制台。**非静态 stream_set 修改它，静态日志函数读取它** |
| `streams` | `unordered_map<string, FileStream>` | 文件名 → 已打开文件流的缓存表。`inline static`（C++17）保证头文件多处包含时定义唯一 |

### 2.4 `std::formatter<std::error_code>` 特化（全局命名空间）

```cpp
namespace std
{
    template <>
    struct std::formatter<std::error_code> {
        // 简单实现：忽略格式说明符，直接输出错误码值和消息
        constexpr auto parse(format_parse_context& ctx) {
            return ctx.begin();   // 接受任何格式，不做特殊解析
        }

        auto format(const std::error_code& ec, format_context& ctx) const {
            // 注意：message() 可能抛出 bad_alloc，这里简单处理
            return std::format_to(ctx.out(), "[{}] {}", ec.value(), ec.message());
        }
    };
}
```

| 项 | 说明 |
| --- | --- |
| 声明位置 | `namespace std` 内的**显式全特化**（`template <> struct std::formatter<std::error_code>`）——特化必须在使用前可见，故定义在 `日志系统.h` 末尾 |
| `parse` | 返回 `ctx.begin()`：接受任意格式说明符但不解析（`{}`、`{:>10}` 等一律忽略，实际仍按默认输出） |
| `format` | 输出 `[错误码值] 错误消息`，如 `[2] No such file or directory`。用 `std::format_to(ctx.out(), ...)` 写入输出迭代器 |
| 异常说明 | 源码注释明确指出 `message()` 可能抛 `bad_alloc`（构造 std::string），"这里简单处理"——即不捕获，由调用方承担 |
| 使用入口 | `Log::info("{}", error_code)`（Data_Validator::error_out 即此用法）；引擎任意 `std::format` 调用只要包含本头文件即获得该特化 |
| 生效范围 | **翻译单元级**：只有包含 `日志系统.h` 的 cpp 才看得到此特化；未包含该头文件而直接 `std::format("{}", ec)` 的翻译单元仍编译失败（或依赖标准库自带行为，C++23 前无此特化） |

## 3. 模块内部架构

### 3.1 文件组织

```
src/tools/Logging/
└── 日志系统.h          ← 唯一文件：类定义 + 静态成员 + std::formatter 特化（header-only）
```

- **无 .cpp、无局部命名空间使用.h**：日志系统是 header-only 模块。模板函数（info/warn/error/debug/log_build）必须内联在头文件；`stream_charge`/`output` 虽是普通函数但也在类体内定义（隐式 inline），避免 ODR 违规。
- `日志系统.h` include 依赖：仅 `common/前置头文件包含.h`（预编译头），提供 `<ostream>`、`<fstream>`、`<format>`、`<unordered_map>`、`<memory>`、`<string>`、`<system_error>` 等。

### 3.2 内部类型

| 别名 | 定义 | 用途 |
| --- | --- | --- |
| `Stream` | `std::shared_ptr<std::ostream>` | 日志写入目标（多态：cout 或文件流）的统一视图 |
| `FileStream` | `std::shared_ptr<std::ofstream>` | 文件流专用视图（用于 is_open 检查与缓存存储） |
| `LogState` | `std::pair<Stream, std::string>` | log_build 的返回载体：流 + 正文 |

### 3.3 数据流（一次日志输出）

```
Log::info("字段 {} 类型不匹配", field)
  │
  ├─ log_build(active_file_stream, fmt, args...)
  │     ├─ stream_charge(file_name)
  │     │     ├─ file_name 空 → shared_ptr<ostream>(&cout, 空删除器)     [控制台]
  │     │     └─ file_name 非空
  │     │           ├─ streams 命中 → 复用缓存流
  │     │           └─ 未命中 → new ofstream → is_open 判定
  │     │                 ├─ 成功 → streams.insert 缓存
  │     │                 └─ 失败/分配失败 → 回落控制台 + [FATAL]/[ERROR] 提示
  │     └─ std::format(fmt, args...) → 正文
  │
  └─ output(stream, 正文, "INFO")
        └─ *stream << "[INFO]" << 正文 << std::endl
```

### 3.4 控制台流与文件流的对比

| 维度 | 控制台（`std::cout`） | 文件流（`std::ofstream`） |
| --- | --- | --- |
| 创建方式 | `shared_ptr<ostream>(&std::cout, 空删除器)` | `new(nothrow) ofstream(file_name)` |
| 触发条件 | `active_file_stream` 为空串 / 文件打开失败回落 | `active_file_stream` 非空且首次使用该名 |
| 所有权 | 不拥有（删除器为空，不 delete cout） | 拥有（shared_ptr 删除 ofstream，关闭文件） |
| 缓存 | 不缓存（每次新建 shared_ptr 包装同一 cout） | 缓存于 `streams`，文件名→流一对一 |
| 刷新 | endl 每次刷新 | endl 每次刷新（文件即时落盘） |

## 4. 模块设计/实现细节

### 4.1 设计决策与理由

**决策 1：`std::format` 而非 printf/ostream 拼接**

- 编译期格式校验：`std::format_string<Args...>` 使 `Log::info("{} {}", 1)`（占位符与参数不匹配）在编译期报错。
- 类型安全：支持任意可格式化类型（含自定义特化），无 `%d`/`%s` 的 UB 风险。
- 与引擎 C++20 技术栈一致（预编译头已含 `<format>`；坐标类型、数据校验器、配置加载器均用 format）。

**决策 2：`active_file_stream` 单一活跃目标 + `streams` 多流缓存**

- 单一"活跃目标"简化调用面：日志函数无需携带目标参数。
- 多流缓存允许：切换 `stream_set("a.log")` 写若干条 → `stream_set("b.log")` 写若干条 → 再切回 `stream_set("a.log")` 时**复用已打开的 a.log 流**（文件句柄不重复打开、不截断）。
- 代价：缓存流永不关闭（模块级生命周期）。

**决策 3：失败回落控制台**

- 文件流打开失败（目录不存在/只读盘）或内存分配失败时，日志**绝不能静默丢失**——回落控制台并输出 `[ERROR]`/`[FATAL]` 说明。保证"日志链路永远可用"。
- 回落提示用 `<<` 裸写（无 output 包装），避免递归依赖（output 又依赖 stream_charge）。

**决策 4：`inline static` 成员**

- C++17 `inline` 静态成员变量在头文件定义，多翻译单元共享唯一实例，无 ODR 问题。header-only 可行。

**决策 5：`std::formatter<std::error_code>` 放日志系统.h 而非独立头**

- `error_code` 的格式化主要被日志使用（error_out 场景），放这里"随日志系统一起生效"，避免额外包含负担。特化后全引擎（只要包含本头）都可 `format("{}", ec)`。

### 4.2 消息格式与细节

- 完整输出：`[INFO]正文`、`[WARN]正文`、`[ERROR]正文`、`[DEBUG]正文`。
- **级别标签与正文之间无空格**（`"[{}]" << output`）。
- 每次输出以 `std::endl` 结尾：换行 + 立即 flush。若频繁打日志（每帧 debug），flush 开销显著；当前引擎日志量小，可接受。
- 模块命名习惯：各调用方在正文中自带模块前缀，如 `"Data_Validator::未包含指定字段: {}"`、`"Config_Loader::已发送配置事件: {}"`。Log 本身不追加调用方信息（无 source_location 自动定位）。

### 4.3 流生命周期与惰性打开

```
第一次 Log::info 使用文件名 "run.log"
  → stream_charge("run.log")
  → streams 无 "run.log"
  → new ofstream("run.log")（创建/截断文件，若已存在则清空重写）
  → is_open() → 成功 → streams["run.log"] = 流
  → 后续所有 "run.log" 日志复用该流（不截断、不重复打开）
```

**陷阱**：`std::ofstream(file_name)` 默认模式是 `ios::out | ios::trunc`——**每次进程启动第一次写某文件会覆盖已有内容**（非追加）。若需要追加模式（`std::ios::app`）当前实现不支持。

### 4.4 线程安全分析

- 日志函数无锁；`streams` 的 find/insert 并发访问是数据竞争；`active_file_stream` 的读写并发也是数据竞争；对同一 `std::cout`/同一 ofstream 的并发 `<<` 交错会混行。
- **当前引擎为单线程游戏循环架构**（未见多线程日志调用），故未加锁是合理的性能取舍。
- 重开发若引入多线程日志：需加互斥锁（或独立日志线程 + 队列）。这是已知扩展点。

### 4.5 `stream_set` 非静态 vs 日志函数静态（用法约束）

- 源码中 `stream_set` 是**非静态**成员（`void stream_set(const std::string& stream)`），而 `info/warn/error/debug` 是 **static**。
- 后果：必须写 `Log logger; logger.stream_set("x.log");` 才能设置目标；`Log::stream_set(...)` 编译失败。
- 静态日志函数读取的 `active_file_stream` 是**静态成员**——即"任何实例调用 stream_set 都修改全局状态，任何静态调用都消费该全局状态"。
- 这是一个轻微的设计不对称（非静态 setter + 静态 getter 语义），本版次刻意保留；重开发时可将 stream_set 改为 static 以统一（注意：任务描述明确"本版次前已删除全部文件输出重载改为非静态 stream_set"，即非静态是既定决策，改回 static 属于架构变更需慎重）。

### 4.6 易踩坑点汇总

1. **`stream_set` 必须经实例调用**（`Log::stream_set` 编译错误）。
2. **默认输出到控制台**：从未调用 stream_set 时 `active_file_stream` 为空串，所有日志进 stdout。
3. **文件覆盖非追加**：进程内首次写某文件会 trunc 覆盖旧内容；如需追加需自行改 `ofstream` 模式。
4. **切换目标只影响后续日志**：stream_set 不 flush/不关闭当前文件流（缓存保留）。
5. **缓存流永不关闭**：进程生命周期内打开过的文件流一直占句柄；频繁换文件名可能耗尽文件描述符。
6. **无级别过滤**：debug 与 error 一样输出，没有"发布版关闭 debug"机制；需要时在调用侧包 `#ifdef`。
7. **format 异常不捕获**：`std::format` 抛 `format_error` 时（如 `{:d}` 配字符串）异常直接传播；调用方注意格式串正确性（编译期已拦截大部分）。
8. **error_code 特化需包含本头**：未包含 `日志系统.h` 的翻译单元对 `format("{}", ec)` 无特化可用。
9. **线程不安全**：多线程并发日志会数据竞争/混行。
10. **`[FATAL]`/`[ERROR]` 回落提示格式特殊**：是 `<<` 裸写（非 `[级别]正文` 标准格式、无空格、`\n` 非 endl），排查日志时留意这两行格式与常规日志不同。
11. **不要 delete cout**：控制台流是"空删除器包装栈对象"，若误传默认删除器会导致析构时 delete std::cout → 崩溃。
12. **std::endl 刷新开销**：高频日志场景（如每帧 debug）会因频繁 flush 拖慢帧率；可改用 `\n` 定期 flush，但当前语义是"即时可见"，改动需权衡。

### 4.7 与其它模块的协作

| 协作方 | 协作内容 |
| --- | --- |
| `Data_Validator`（数据校验器） | `Log::warn`/`Log::info` 输出校验失败原因；`error_out` 用 `Log::info("{}", error_info)` 输出 error_code（依赖 formatter 特化） |
| `Config_Loader`（配置加载器） | 全流程日志：扫描结果、路由格式错误、字段缺失、恶意跳转、配置读取失败、事件发送结果（`Log::info`） |
| `Engine_Env`（引擎环境） | `Log::error("错误: {}", e.what())` 输出 exe 路径获取失败信息 |
| `Number_Allocator`（数值分配器） | `Log::warn("Number_Pool::待回收数值已被回收!!!")` |
| `Collision_Region` / `Collision_Proxy`（碰撞系统） | 碰撞空间构建、检测等环节的日志输出 |
| 全引擎任意模块 | 可 `#include "src/tools/Logging/日志系统.h"` 直接使用 |

### 4.8 与主流日志库的差异（定位说明）

| 能力 | 本 Log | spdlog 等专业库 |
| --- | --- | --- |
| 格式 | std::format（C++20） | fmt/std::format |
| 级别过滤 | 无 | sink/level 过滤 |
| 线程安全 | 无 | 有（多 sink 锁） |
| 异步 | 无（同步 + endl flush） | 可配置异步 |
| 滚动文件 | 无（单文件缓存） | 按大小/时间滚动 |
| 上下文 | 无（手动模块前缀） | source_location/logger 名 |
| 目标 | 引擎自研轻量设施 | 通用重型方案 |

本模块定位是"够用、零依赖、header-only"的引擎内部日志设施；重开发时保持轻量即可，不必引入外部库。

## 5. 模块运行链路

### 5.1 典型调用时序（配置加载场景示例）

```
[进程启动]
  ├─ engine::Log logger;                      // 构造实例（用于调用非静态 stream_set）
  ├─ logger.stream_set("engine.log");         // ① 设置活跃文件目标（惰性，未开文件）
  ├─ ... 业务初始化 ...
  │
  ├─ Config_Loader 构造 →（暂无日志）
  ├─ loader.act()
  │     ├─ content_scan 扫描失败？
  │     │     └─ Log::info("Config_Loader::未检测到任何路由文件")
  │     │           ├─ log_build("engine.log", fmt)
  │     │           │     ├─ stream_charge("engine.log")
  │     │           │     │     └─ 首次 → new ofstream("engine.log") → is_open → 缓存
  │     │           │     └─ std::format(...) → "Config_Loader::未检测到任何路由文件"
  │     │           └─ output(流, 正文, "INFO") → "[INFO]Config_Loader::未检测到任何路由文件"
  │     └─ ... 后续日志同路径 ...
  │
  ├─ logger.stream_set("");                    // ② 切回控制台（后续日志上屏）
  └─ 主循环运行（日志持续输出到控制台）
```

### 5.2 状态机：输出目标切换

```
               stream_set("") 
  [控制台] ◄──────────────────────────┐
     │                                │
     │ stream_set("a.log")            │ stream_set("b.log")
     ▼                                │
  [文件 a.log] ──── stream_set("b.log")──► [文件 b.log]
     ▲                                │
     └──────── stream_set("a.log") ────┘ （复用缓存流，不重建）
```

### 5.3 错误路径链路

```
日志输出时
  ├─ stream_charge 分配失败（new 返回 nullptr）
  │     └─ 回落控制台 → *cout << "[FATAL]内存不足\n已切换至控制台输出\n" → 本次日志正文被丢弃
  ├─ ofstream 打开失败（is_open()==false）
  │     └─ 回落控制台 → *cout << "[ERROR]文件打开失败\n已切换至控制台输出\n" → 本次日志正文被丢弃
  └─ std::format 抛 format_error
        └─ 异常传播（不回落、不捕获）→ 由调用方 try-catch 或终止
```

## 6. 重开发要点速查

| 步骤 | 必须做到 |
| --- | --- |
| 1 | 类名 `Log`，位于 `namespace engine`；私有别名 `Stream`/`FileStream`/`LogState` 与源码一致 |
| 2 | 四个静态模板日志函数签名 `template<typename... Args> static void xxx(std::format_string<Args...> fmt, Args&&... args)`，级别标签 INFO/WARN/ERROR/DEBUG |
| 3 | `stream_set` 保持**非静态**、只写 `active_file_stream`（本版次既定决策） |
| 4 | `stream_charge`：空串→cout（空删除器）；缓存命中→复用；未命中→`new(nothrow) ofstream`；分配失败/打开失败→回落控制台并输出 `[FATAL]`/`[ERROR]` 提示 |
| 5 | `log_build` 返回 `LogState`（流 + format 文本）；`output` 组装 `[级别]正文` + `std::endl` |
| 6 | 静态成员 `inline static std::string active_file_stream{}` 与 `inline static std::unordered_map<std::string, FileStream> streams;` |

| 8 | include 仅 `common/前置头文件包含.h`；header-only 无 cpp |
| 9 | 保持无锁单线程语义；若未来多线程需自行加锁（架构扩展点） |
| 10 | 保持 `ofstream` 默认 trunc 模式（不追加）与 endl 刷新语义，除非需求变更 |
