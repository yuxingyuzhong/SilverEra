## 二、项目总览与设计理念

### 2.1 一句话定位

白银纪元是一个**分层游戏引擎项目**：底层引擎提供基础能力（事件、对象、空间分区、碰撞、工具集），
中层系统层提供游戏机制（实体、属性、效应），测试层承载单元测试与交互式用例选择，游戏层为最终游戏本体（当前尚无源码）。

### 2.2 四层结构

```
白银纪元/（顶层仓库，只统辖目录，不跟踪下层内容）
├── 测试层/   独立仓库（分支 test  → 远端 sliverera/test）    ← 唯一可执行文件产地
├── 系统层/   独立仓库（分支 main  → 远端 sliverera/system）  ← 游戏机制层
├── 引擎层/   独立仓库（分支 main  → 远端 sliverera/engine）  ← 基础能力层（本版次改造战场）
└── 游戏层/   独立仓库（分支 main  → 远端 sliverera/game）    ← 游戏本体（当前无源码）
```

- 四层各自是**独立 git 仓库**，顶层仓库只记录四层目录指针，不跟踪各层内容；因此下层有提交时顶层仓库通常不会有新提交。
- 远端统一为 `https://github.com/yuxingyuzhong/SilverEra.git`，各层以独立分支推送（`engine` / `system` / `test` / `game`）。
- 顶层 `main` 分支仅作为「代码合并线」：其新提交只由远端其余四分支合并产生；本地不拉取远程 main 分支代码，只拉取其余四个分支的代码。

### 2.3 三条核心设计原则

1. **层间一律链接「已构建的静态库」，绝不回退编译下层源码**。引擎层产出 `EngineCore.lib`、系统层产出 `SystemCore.lib`、测试层产出唯一可执行文件 `EngineTests.exe`、游戏层产出 `GameCore.lib`（当前无源码未产出）。层与层的交接通过 `cmake/对外接口.cmake` 自描述 + `cmake/接入下层.cmake` 的 `byjy_jieru_xiaceng()` 建立 IMPORTED 静态库目标完成。
2. **事件驱动为模块间协作的枢纽**。引擎层的碰撞代理器、系统层的实体管理器、效应管理器、属性槽分发器、工具层的配置加载器，都以「事件终端（Event_Terminal）→ 事件中转器（Event_Broker）」的订阅/发布机制互相通信。模块之间不直接调用对方接口（除层级内的直接调用外），而是通过事件解耦。
3. **全部对外公共头文件经由统一预编译头收敛**。`common/前置头文件包含.h` 集中包含标准库、nlohmann::json、GLFW 等；各模块头文件一律 `#include "common/前置头文件包含.h"` 起步，模块内通过「局部命名空间使用.h」展开 `using` 别名，保持源码整洁。

### 2.4 技术底座

- 语言标准：C++20（`CMAKE_CXX_STANDARD 20`，禁用扩展）。
- 构建系统：CMake（≥3.20，使用 `CONFIGURE_DEPENDS` 自动发现源文件）+ Ninja 生成器 + MSVC 编译器（Windows 平台）。
- 第三方库：`nlohmann::json`（JSON 解析）、`bullet3`（碰撞检测）、`glfw`（窗口/输入）、`glm`（数学）、`googletest`（单元测试）、`Dear ImGui + glad`（测试选择器图形界面）、`Sol2 + Lua`（系统层脚本，当前引擎层未引用）。
- 编码约定：源文件统一 UTF-8（MSVC `/utf-8`）；中文路径在 `std::filesystem` 中经 `u8string` 转换工具（`string_to_path` / `path_to_string`）处理。

## 八、模块间交互关系

### 8.1 层间构建契约（编译期交互）

```
引擎层 EngineCore.lib  ←── 系统层 SystemCore.lib  ←── 测试层 EngineTests.exe
     │                          │                          │
     └── 对外接口.cmake          └── 对外接口.cmake          └── 接入两层
         BYJY_ENGINE_OUT_*          BYJY_SYSTEM_OUT_*            byjy_jieru_xiaceng()
```

- **对外面自描述**：每层 `cmake/对外接口.cmake` 声明本层对外变量：
  - `BYJY_<P>_OUT_LIB`（静态库文件名）、`BYJY_<P>_OUT_INC`（包含目录）、`BYJY_<P>_OUT_DEF`（编译定义）、`BYJY_<P>_OUT_LINK`（第三方库文件）、`BYJY_<P>_OUT_SYS`（系统库）。
  - 系统层的对外面 = 本层自有面 + `include(引擎层/对外接口.cmake)` 并入引擎层对外面；因此「接入系统层」即同时取得两层公共路径。
- **接入函数**：`byjy_jieru_xiaceng()`（三份逐字节相同）读取下层对外接口 → 定位已构建静态库（覆盖变量优先 → 自动探测最新 → 硬失败）→ 建立 `IMPORTED STATIC GLOBAL` 目标并挂载 INTERFACE 属性。**任何情况下都不回退编译下层源码**。
- **唯一可执行**：宿主机制取消后，可执行文件只在测试层产生（`EngineTests.exe`）。

### 8.2 事件驱动协作（运行期交互）

整个项目的模块间通信以「事件终端 → 事件中转器」为核心：

```
事件发送方（如 Config_Loader / Collision_Proxy）
        │  build() 构造事件
        │  send(evt, acl_key) 发送
        ▼
   事件终端 Event_Terminal（持有者权限校验：acl_key）
        │  将事件送入 事件中转器 的接收入口（attach 时注册）
        ▼
   事件中转器 Event_Broker（订阅/发布中枢）
        │  按 category/tag 匹配订阅者；定向发送按 target_object 直投
        ▼
   事件订阅方（如 Collision_Proxy / Entity_Manager / Effect_Manager / Prop_Distributor）
        │  event_process() 按 category/tag 分派处理
```

- **接入链路**：订阅方 `attach()` → 注册事件接收入口 → 提交 `needed_events` 订阅清单 → 事件中转器据此建立分类/标签订阅表。
- **事件结构**：`event{ sender_object, target_object, category, tag, config }`，其中 `target_object` 非空时走定向直投；`config` 为 nlohmann::json 载荷。
- **权限机制**：`Event_Terminal::acl_key_gen()` 生成唯一密钥，`send`/`interact`/`query`/`clear` 全部校验密钥，「密钥未生成即锁定」。
- **典型协作示例（碰撞检测结果分发）**：
  1. `Config_Loader::act()` 读取路由 → 发送 `Config/Load` 事件（`target_object="Collision_Proxy"`）；
  2. `Collision_Proxy::event_process()` 收到后 `config_apply()` 建空间/建碰撞体/配几何；
  3. 游戏逻辑调用 `region_detect()` → `Collision_Region::detect()` 执行扫掠+离散检测 → `event_publish("DetectResult", ...)` 广播碰撞对；
  4. 订阅 `Collision/DetectResult` 的模块（如游戏层将来的逻辑）消费碰撞对。

### 8.3 引擎层模块间直接调用关系

除事件外，引擎层内部还存在直接调用链（见「模块架构/」各文件）：

- `Collision_Proxy` → 持有 `std::unordered_map<string, unique_ptr<Collision_Region>>`，直接调用 `Collision_Region` 全部接口；
- `Collision_Region` → 使用 `Collider`（直接成员）、`Number_Allocator`（编号分配）、`Mesh_Loader`（网格加载）、`Data_Validator`（配置校验）、`Log`（日志）、`Collision_Backend`（bullet3 世界）；

- `Event_Terminal` → 使用 `Random_Generator`（密钥生成）、`Terminal_Interface`（接口注册表）。

## 十二、工程约定与注意事项（跨模块通用）

1. **命名约定**：类名首字母大写（`Collision_Proxy`）；struct/union/enum 首字母小写（`event`、`Collision_Result`、`interface_ID`）；变量/函数全小写 + 下划线分隔（`region_build`、`acl_key`）；文件名中文（`碰撞代理器.h`）。
2. **注释约定**：中文注释；<3 行用 `//`（无空格），≥3 行用 `/**/`；换行注释；函数头注释翻译函数名。
3. **错误处理约定**：模块接口普遍返回 `bool`/`std::optional`，失败时 `Log::warn`/`Log::error` 记录并返回失败标记，不抛异常到上层（内部使用 try/catch 收敛第三方库异常）。
4. **内存约定**：能 `new(nothrow)` 就 `new(nothrow)`（部分模块以 `memory_malloc` 包装）；`Collider` 的网格与形状按成员声明逆序析构保证依赖关系。
5. **行尾约定**：引擎层仓库对部分文件存在自动行尾归一（`autocrlf`），涉及这些文件时注意 CRLF/LF。
6. **工具链坑位**：`.bat` 被 cmd 按 GBK 解析（含中文会乱码），改用 bash 通道；`ctest` 不在 Git Bash PATH 中，需绝对路径；`.hpp` 上 `apply_patch` 易失败，用 `str_replace`/`sed` 更稳。
7. **git 推送**：引擎层本地分支 `main` 与上游 `engine` 名字不一致，`git push` 会被 `push.default=simple` 拦下，必须显式 `git push sliverera main:engine`（测试层 `test:test` 同名）。
