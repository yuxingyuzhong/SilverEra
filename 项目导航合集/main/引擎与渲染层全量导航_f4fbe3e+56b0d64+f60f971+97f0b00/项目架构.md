```

│   │   └── 对外接口.cmake                ← 本层对外导出接口
│   ├── EngineCore/                      ← 引擎核心层（独立 git 仓库）
│   └── EngineSystem/                    ← 引擎系统层（独立 git 仓库）
```

> 目录图中的 `.git/`、`.vs/`、`out/`、`CMakeSettings.json` 等构建/版本控制产物属工程附属物，不在架构描述范围内；各层 `out/` 为 CMake 生成目录（Debug/Release 双构建树）。

### 1.2 分层职责

项目采用**分层静态库**架构：每一层是一个可独立构建的 CMake 工程（含独立本地 git 仓库），通过**层间契约变量**向下层索取「库文件路径」与「头文件快照路径」，从而做到「每一层只依赖它声明的下层」，且上层不必构建下层源码即可链接。

| 层 | 目录 | 是否产出静态库 | 依赖 | 说明 |
| --- | --- | --- | --- | --- |
| 引擎聚合层 | `Engine/` | 否 | — | 只做聚合编排与对外接口；不产出库 |
| 引擎核心层 | `Engine/EngineCore/` | 是 | 仅外部库（bullet3、glfw、Json 等） | 引擎基础设施：工具、对象、事件、配置、空间 |
| 引擎系统层 | `Engine/EngineSystem/` | 是 | EngineCore | 引擎业务系统：实体、属性、效果 |
| 渲染层 | `Application/Renderer/` | 是 | EngineCore（＋外部库 SDL3、VMA、glm） | Vulkan 渲染，本版次新建并贯通至纹理采样 |
| 测试层 | `Application/Test/` | 是 | EngineCore、EngineSystem | 本轮不收录 |
| 游戏层 | `Application/Game/` | 是 | EngineCore、EngineSystem | 本轮不收录 |
| 编辑器层 | `Application/Editor/` | 是 | 顶层仓库 | 本轮不收录 |

### 2.2 EngineCore 模块功能

**工具集（`src/tools/`）** — 引擎的地基，被其余所有模块直接或间接使用。分七组：
- `Detail/`：细粒度纯工具——路径规范化与字符串转换（中文路径与 UTF-8/本地编码转换的关键）、文件/JSON 字段可用性校验、哈希混合、二分查找、标准库 `std::format` 特化。是「路径转换操作」的官方入口。
- `Engine_Env/`：引擎环境全局态，提供逻辑帧计数等运行期环境量（位移按逻辑帧节流依赖于此）。
- `Logging/`：日志系统运行包，拆为 `Log`（门面）／`Stream_Tree`（流节点树）／`Stream_Sink`（输出目标）／`Rule`（规则）／`Node_Cache`（节点缓存）五个类；经 `std::source_location` 捕获调用处路径，按路径公共前缀建链表树分流；对外以 `logger.` 实例语义调用。
- `Mesh_Loader/`：OBJ 网格文件加载工具（供上层消费）。
- `Number_Allocator/`：数值分配器，为对象池等提供索引/ID 的分配与回收。
- `Random_Generator/`：随机数生成器。
- `Timer/`：计时器，提供帧计时、逻辑帧计数与节流判据。

**对象系统（`src/core/object/`）** — 统一的「对象托管」基础设施。
- `Object/`：对象基类及其标识（ID）、有效性等公共概念。
- `Object_Pool/`：对象池，按「ID ↔ 槽位索引」双映射管理对象记录，支持构建、遍历（迭代器化）、卸载与回收；`build` 采用**按值形参 `T object = {}` ＋ `std::move`**，兼容默认构造且不要求可拷贝。

**事件系统（`src/core/event/`）** — 模块间的解耦通信总线。
- `Event/`：事件类型（含发送者、载荷与可哈希/可比较语义）。
- `Event_Broker/`：事件中转器，持有注册关系并在事件到达时向接收方分发。
- `Event_Terminal/`：**端口化**的事件终端——`终端端口.h` 定义端口，`事件终端.h` 定义终端；终端作为模块对外暴露的接线口，通过端口与中转器形成**依赖反转**接线，避免模块间直接互相持有。

**配置系统（`src/core/config/`）** — 运行期配置的加载、缓存与回写。
- `Config_Loader/`：配置加载器，拆为 `core/` 下六个编译单元——`配置加载`／`路由文件操作`／`路径与文件`／`脏标记`／`缓存清除`／`事件处理`；核心机制为**脏标记 ＋ 缓存副本回写**：加载后缓存副本，运行期改动置脏标记，再由回写路径写回磁盘；并响应事件契约（`Load`）触发二次加载。
- `Logging_Config_Bridge/`：日志配置桥接，把配置项翻译为日志系统规则，隔离「配置」与「日志」两模块的直接依赖。

**空间系统（`src/core/spatial/`）** — 空间划分与碰撞。
- `common/`：坐标类型（统一坐标表示）与依赖库封装（bullet3 等）。
- `partition/Quadtree/`：四叉树，节点所有权为 `std::shared_ptr<Node>` 的**递归 RAII**，子节点以固定数组槽访问，裸 `Node*` 仅作非持有观察者；提供构建、区块信息检索、范围/单点查询、树扩大、设置与交互；内部函数采用 `chunk_operate`／`leaf_recur` 等命名。
- `partition/Quadtree_Manager/`：四叉树管理器，管理多棵四叉树的智能创建、合并、扩大回调、相邻查找；对外 API 风格与四叉树本身一致；单点查询复用范围查询重载（把点格式化为坐标范围）。
- `collision/Collider/`：碰撞体定义。
- `collision/Collision_Proxy/`：碰撞代理器，负责位移管理（按逻辑帧节流，`frequency` 须整除帧率）、碰撞体配置与管理、碰撞响应、空间边界与配置、事件交互。
- `collision/Collision_Region/`：碰撞空间，负责形状构建、检测执行（按 `step_length` 分段推进）、碰撞体管理、空间与边界、跨越通知。

### 2.3 EngineSystem 模块功能

**系统层-实体（`src/entity/`）** — 实体是引擎业务对象的基本单位。
- `Entity/`：实体定义（标识、属性槽引用、配置等）。
- `Entity_Manager/`：实体管理器，拆为 `core/` 下四个编译单元——`实体处理`／`属性槽处理`／`配置处理`／`事件处理`；负责实体创建/销毁、属性槽分配、配置装载与事件接线。

**系统层-属性（`src/prop/`）** — 属性的存储与分发。
- `Prop/`：属性定义。
- `Prop_Distributor/`：属性槽分发器，以「托管方持有—分发器借指针」的关系工作，配套密钥握手校验，负责属性槽的分配/回收/访问。

**系统层-效果（`src/effect/`）** — 作用于实体的效果（如增益/减益）的注册与结算。
- `Effect/`：效应定义（含阶段 `act_phase`、优先级、载荷等）。
- `Effect_Manager/`：效应管理器，负责效应的注册、挂载与结算；效应组以 ID 组织并支持检索。

### 2.4 Renderer 模块功能

渲染层是本版次新建并贯通的层级，整体由**门面**收口、内部拆十子模块，自下而上形成「平台 → 设备 → 交换链 → 帧 → 管线 → 网格/纹理 → 场景 → 门面」的完整链路。

- **渲染层-设备**：Vulkan 实例创建（含校验层与调试回调）、物理设备打分选择、逻辑设备与队列创建；是**本层唯一的 `VkResult` 检查出口**所在模块（检查函数/宏定义于门面的 `core/结果检查.h`）。
- **渲染层-平台与表面**：经 SDL3 创建窗口、创建 Vulkan 表面（`VkSurfaceKHR` 与 SDL 窗口绑定）、事件泵收集窗口事件。
- **渲染层-交换链**：交换链查询（表面能力/格式/呈现模式/范围）、创建、重建；**深度附件随交换链一并管理**。
- **渲染层-帧**：帧槽（命令缓冲/图像可用信号量/渲染完成信号量/飞行围栏）创建与轮转、命令录制、提交呈现、延迟销毁；含 `slot_wait()` 写入前置等待与「先取图像、后重置围栏」的防死锁约定。
- **渲染层-内存与资源**：VMA 分配器（实现单元位于本模块 `core/VMA实现.cpp`）、缓冲创建、图像创建、一次性同步上传批次。
- **渲染层-着色器**：SPIR-V 字节码 → `VkShaderModule` 的创建与销毁（不含着色器阶段组装，后者在管线模块）。
- **渲染层-管线**：描述符布局、管线布局、图形管线创建；采用 Vulkan 1.3 动态渲染（无 renderPass），固定 set0=场景 UBO（顶点阶段）、set1=采样器（片元阶段）、推送常量顶点阶段。
- **渲染层-网格**：网格数据结构、网格加载、顶点/索引缓冲创建（经内存模块）。
- **渲染层-场景与相机**：相机参数与视图/投影矩阵计算，产出与着色器 set0 场景 UBO 对应的数据。
- **渲染层-门面**：`Renderer` 类以 PIMPL 收口，持有并编排十个子模块的初始化/销毁顺序，对外提供渲染层唯一入口；同时定义 `vk_result_check` 出口。

### 2.5 构建系统与层间契约

- 每层一个 CMake 工程，层与层之间通过 `cmake/接入下层.cmake` 定义的**契约变量**传递「下层库文件」与「下层头快照路径」。
- `接入下层.cmake` 在多层各有一份副本，必须**逐字节相同**；改动契约须同步全部副本。
- **聚合层**（`Engine/`、`Application/`）不产出库，只做聚合与对外接口导出。
- **源文件清单**：各层以 `file(GLOB_RECURSE ...)` 收集源码，并落成层根显式清单 `源文件列表*.cmake`，使 VS 文件视图中的改名/迁移可改写清单并自动触发重配。
- **目录级 `CMAKE_CONFIGURE_DEPENDS`**：把被 GLOB 的源根目录登记为配置依赖，解决「仅靠 `CONFIGURE_DEPENDS` 不足以让 VS 感知增删文件」的问题。
- **头快照**：引擎导出头快照供上层消费；头快照根须作为**消费层自身的包含目录**并排在项目根之前（MSVC 下目标自身 `-I` 恒早于导入目标传递的 `/external:I`，否则快照被源码树旁路）。
- **外部库**：置于各层 `external/`（与 `src/` 平级），以基于项目根相对路径引入；渲染层额外把 SDL3 源文件就地编入（`cmake/SDL3源文件列表.cmake`），VMA 亦就地编入。

## 三、模块间交互关系

### 3.1 层间依赖总图

```
                    ┌──────────────────────────────┐
                    │   Application/Renderer       │
                    │   （门面 + 十子模块）          │
                    └──────────────┬───────────────┘
                                   │ 只依赖 EngineCore
                                   ▼
┌──────────────────────────────────────────────────────┐
│                  Engine/EngineCore                    │
│  工具集 · 对象系统 · 事件系统 · 配置系统 · 空间系统      │
└──────────────────────────────────────────────────────┘
                                   ▲
                                   │ 依赖 EngineCore
                    ┌──────────────┴───────────────┐
                    │   Engine/EngineSystem        │
                    │   实体 · 属性 · 效果           │
                    └──────────────────────────────┘

   Application/Test（→EngineCore+EngineSystem）、
   Application/Game（→EngineCore+EngineSystem）、
   Application/Editor：本轮不收录，不在依赖图内展开
```

**关键结论**：渲染层**只接 EngineCore**，不接 EngineSystem——即「渲染层不感知实体/属性/效应等业务概念」，这是本版次渲染层分层设计的硬约束。

### 3.2 EngineCore 内部交互

- **工具集是共用地基**：对象池的槽位分配用 `Number_Allocator`；几乎所有模块的告警/信息输出用 `Logging`；所有涉及文件与中文路径的模块用 `Detail` 的路径工具；节流与帧计数用 `Timer` 与 `Engine_Env`；空间系统加载形状/网格数据用 `Mesh_Loader`。
- **对象系统是被托管者**：系统层与空间系统都通过对象池托管自身对象（实体、碰撞体、四叉树区块数据等），对象池以 ID 索引与迭代器对外服务。
- **事件系统是解耦总线**：配置加载器、实体管理器、碰撞代理器均通过事件终端/端口接入事件系统；事件系统自身不依赖上述任何模块，形成单向依赖。
- **配置系统与日志系统通过桥接解耦**：`Config_Loader` 不直接依赖 `Logging`，而定式经 `Logging_Config_Bridge` 转换，保证两模块可独立演进。
- **空间系统内部**：`Collision_Proxy` 组合 `Collision_Region`（空间）与 `Collider`（碰撞体），并借 `Quadtree_Manager`/`Quadtree` 做空间划分；位移与检测按逻辑帧与步长分段推进，跨越事件经事件系统外发。

### 3.3 EngineSystem 内部交互

- `Entity_Manager` 是系统层中枢：创建/销毁实体、为实体分配属性槽、装载配置、接入事件。
- `Prop_Distributor` 为实体提供属性槽的分配与访问；`Prop` 是属性的值/描述载体，二者为「托管方持有—分发器借指针」关系。
- `Effect_Manager` 管理效应并结算到实体；效应组按 ID 组织。
- 三者均建立在 EngineCore 的**对象池**之上，并经**事件系统**与外部交互；配置来自**配置系统**。

### 3.4 Renderer 内部交互

门面 `Renderer` 是唯一对外入口，内部按固定顺序编排：

```
Platform ──► Device ──► Swapchain ──► Frame
   │            │            │           │
   │            └──► Memory ─┴──► Pipeline ◄── Shader
   │                              ▲  ▲
   │                     Mesh ────┘  └──── Texture
   │                              │
   └──────────────► 事件泵          └──► Scene（相机 UBO）
```

- **平台与表面 → 设备**：表面（`VkSurfaceKHR`）由平台模块创建，设备模块在物理设备选择与逻辑设备创建时需表面能力（呈现队列族、扩展支持）。
- **设备 → 内存**：VMA 分配器绑定实例/物理设备/逻辑设备，是所有 GPU 资源分配的底座。
- **设备 ＋ 表面 → 交换链**：交换链按表面能力与呈现模式创建，并随窗口尺寸变化重建；深度附件与交换链同步生命周期。
- **交换链 → 帧**：帧模块按交换链图像数与飞行帧数建立帧槽，取图像/提交/呈现均与交换链交互；「先取图像、后重置围栏」的顺序约定是二者间的关键契约。
- **内存 → 网格/纹理/交换链深度**：三者都经内存模块创建图像/缓冲，并经上传批次完成 CPU→GPU 数据搬运。
- **着色器 → 管线**：管线消费着色器模块创建的各阶段 `VkShaderModule`；管线与交换链格式级耦合（尺寸解耦，靠动态视口/裁剪）。
- **场景 → 帧**：相机的视图/投影矩阵写入帧槽的场景 UBO，供顶点着色器读取。
- **门面统一收口**：`Renderer` 以 PIMPL 隐藏实现，初始化按依赖顺序、销毁按逆序，并把 `VkResult` 检查集中在唯一出口。

### 3.5 构建期交互

- 上层构建时先经 `接入下层.cmake` 找到下层的**库文件**与**头快照目录**；若下层不可构建，可改用工作站的**下层库快照**。
- 「头快照根前置」是保证「头与库同版次」的机制前提；「显式源文件清单 ＋ 目录级配置依赖」是保证 VS 增删文件自动重配的机制前提。
- 五个（含渲染层）`接入下层.cmake` 副本必须逐字节一致，否则同一契约在不同层行为不一致。

### 3.6 典型端到端链路（引擎启动 → 渲染一帧）

1. **引擎环境就绪**：`Engine_Env` 初始化；`Timer` 建立逻辑帧计数。
2. **日志就绪**：`Logging` 运行包建立流节点树与输出目标；随后经 `Logging_Config_Bridge` 从配置装载日志规则。
3. **配置加载**：`Config_Loader` 从磁盘加载配置（经 `Detail` 路径工具处理中文路径），缓存副本；后续配置变更置脏标记并回写。
4. **事件接线**：各模块以「端口」接入 `Event_Terminal`，由 `Event_Broker` 中转；配置加载器监听 `Load` 类事件以支持二次加载。
5. **系统层构建**：`Entity_Manager` 创建实体 → 经 `Prop_Distributor` 分配属性槽 → `Effect_Manager` 结算效应；对象实体托管于对象池。
6. **空间构建**：`Collision_Proxy` 建立 `Collision_Region` 与碰撞体，经 `Quadtree_Manager` 组织空间划分。
7. **渲染层初始化**（门面按序）：平台创建窗口与表面 → 设备创建实例/选择物理设备/建逻辑设备 → 内存建立 VMA → 交换链创建（含深度附件）→ 帧槽创建 → 着色器加载 SPIR-V → 管线创建 → 网格/纹理装载 → 场景相机就绪。
8. **帧循环**（每帧）：门面 `slot_wait()` 等待当前帧槽可用 → 相机矩阵写入该槽场景 UBO → 录制命令（绑定管线/描述符/顶点索引缓冲/纹理，动态渲染设定附件）→ 提交（等待图像可用信号量、置渲染完成信号量、置飞行围栏）→ 呈现。
9. **交换链异常**：取得过期/次优图像时触发交换链重建，随后回到第 8 步。
10. **销毁**：门面按初始化的逆序释放各子模块资源。
