## 一、模块功能

### 1.1 模块定位

「网格」模块位于渲染层源码目录 `Application/Renderer/src/render/Mesh/`，与内存与资源模块（`render/Memory/`）、纹理模块（`render/Texture/`）、交换链模块（`render/Swapchain/`）、管线模块（`render/Pipeline/`）、着色器模块（`render/Shader/`）等并列为渲染层的资源类模块。它把 Vulkan 中「**几何数据（顶点 + 索引）如何组织成一段可被图形管线绑定的 GPU 缓冲**」这一段工作，收敛进一个门面类 `engine::Mesh_Context`，并额外提供两个**过程式几何生成器**（三角形、轴对齐立方体），用于在尚无网格文件加载链路时快速产出可渲染的几何体。

模块对外只暴露「构建 → 创建网格 → 取用缓冲 → 销毁」四段式接口，外加两个静态生成函数；底层缓冲的创建、上传、销毁则全部委托给内存与资源模块（`engine::Memory_Context`），本模块自身**不直接调用任何 Vulkan / VMA 函数**。

模块内部只把职责拆成两个编译单元，全部放在 `core/` 下：

- `core/网格加载器.cpp`：两个**过程式生成器**的落地——`triangle_generate`（单三角形）与 `cube_generate`（轴对齐立方体）。文件名虽为「加载器」，但本编译单元**不含任何文件读取 / 解析逻辑**（见 4.8 节与待确认 R-MESH-01）。
- `core/网格缓冲.cpp`：`Mesh_Context` 的析构、`build`、`destroy`、`valid`、`mesh_create`、`mesh_destroy`、`mesh_record_get` 的落地，即顶点 / 索引缓冲的创建、上传、登记、查询与销毁全部在此完成。

一句话概括：**本模块是渲染层「把一段 CPU 端几何数据变成一对可回传、可绑定的 GPU 顶点 / 索引缓冲，并以稳定句柄管理其生命周期」的唯一入口，是渲染器门面和帧 / 录制链路渲染几何体时的前置依赖。**

### 1.2 职责边界与解决的问题

`Mesh_Context` 解决的问题可归纳为六点：

1. **把「几何数据」与「GPU 缓冲」解耦为两个清晰的数据层**。`网格数据.h` 中的 `engine::Vertex` 与 `engine::Mesh_Data` 是**纯 CPU 端、Vulkan-free** 的数据描述，负责承载顶点位置 / 纹理坐标与索引；`Mesh_Record`（`网格.h`）与实际的 `VkBuffer` / `VmaAllocation` 才是 GPU 端资源。生成器只产出 `Mesh_Data`，创建动作才把它翻译为 GPU 缓冲。这样上层可以在完全不接触 Vulkan 的前提下构造与生成几何数据。

2. **把顶点 / 索引缓冲的创建与上传打包为一次 `mesh_create`**。Vulkan 中创建一对设备本地缓冲并上传数据，需要「建缓冲 → 建索引缓冲 → 各建一次暂存 → 各提交一次拷贝 → 各销毁暂存」的冗长流程。本模块把它收敛为一次 `mesh_create(handle_out, data)`：内部经内存模块的 `buffer_create` 建出**设备本地、可作传输目标**的缓冲，再经 `upload_buffer` 一次性同步上传，成功后登记记录并回写句柄。

3. **用「句柄 + 记录数组」把 GPU 句柄的管理外化为稳定整数**。调用方不直接持有 `VkBuffer` / `VmaAllocation`，而是持有一个 `Mesh_Handle`（`uint64_t`）。句柄自 1 起、0 表无效，记录下标 = 句柄 − 1（经典「1-based 句柄 + 0-based 数组」约定）。这样上层业务只需存一个整数即可引用网格，避免了 Vulkan 句柄在业务层的渗透。

4. **在创建阶段做完整的前置校验与失败清理**。`mesh_create` 在真正创建缓冲前依次校验：内存模块是否就绪、顶点与索引是否均非空、全部索引是否落在顶点数范围内；任何一步失败都返回假并保持「无副作用」（不会留下半初始化资源）。创建过程中若索引缓冲建立或上传失败，会**先行归还已经建立的顶点缓冲**，保证失败不留泄漏。

5. **提供两个开箱即用的几何生成器**。在还没有网格文件加载链路的阶段，`triangle_generate`（单三角形，位于 XY 平面、逆时针绕序、UV 覆盖整块贴图）与 `cube_generate`（边长 `2*half_extent` 的轴对齐立方体，24 顶点 / 36 索引、逐面独立顶点以保证 UV）可直接产出一份可渲染的 `Mesh_Data`，省去手写顶点数组。

6. **把销毁口径统一回内存模块**。缓冲句柄由本模块记录持有，但销毁动作一律回到内存模块的 `buffer_destroy`（`mesh_destroy` 与 `destroy` 两条路径都如此），保证「用 VMA 创建、用 VMA 销毁」的单一口径，不出现资源生命周期管理的错配。

### 1.3 在整体架构中的位置

网格模块处于渲染层资源链的**中下层**：它**依赖**内存与资源模块（提供缓冲创建 / 上传 / 销毁），并依赖引擎核心层的日志系统（错误报告）；它**不依赖**任何 Vulkan / VMA 头，也不依赖渲染层的交换链、帧、管线、着色器等模块。

```
                ┌───────────────────────────────────────────────┐
                │              Renderer（渲染器门面）             │
                │   持有 Mesh_Context 成员，按依赖顺序编排        │
                └───────────────┬───────────────────────────────┘
                                │ mesh.build(memory)
                                ▼
        ┌───────────────────────────────────────────────────────────────┐
        │                    Mesh_Context（网格上下文）                  │
        │  Memory_Context* memory  /  std::vector<Mesh_Record> records  │
        └───┬──────────────────────────┬────────────────────┬──────────┘
     依赖│                     依赖    │              提供   │
            ▼                          ▼                    ▼
   ┌───────────────┐        ┌──────────────┐   ┌──────────────────────────┐
   │ 内存与资源模块  │        │ 日志系统     │   │ 顶点 / 索引缓冲句柄       │
   │ Memory_Context │        │ logger 全局  │   │ 与索引数（mesh_record_   │
   │ buffer_create  │        │ 全局实例     │   │ get 直出，供录制链路绑定）│
   │ upload_buffer  │        └──────────────┘   └──────────────────────────┘
   │ buffer_destroy │
   └────────────────┘
                                │
                                ▼ 提供 GPU 顶点 / 索引缓冲
        渲染器门面 / 帧与命令录制链路（绑定 VK_VERTEX_INPUT_BINDING /
        vkCmdBindVertexBuffers / vkCmdBindIndexBuffer）
```

- **向上**：调用方是渲染器门面（`render/Renderer/`）。门面在自身实现中**以成员方式持有** `Mesh_Context`（与 `Memory_Context memory;` 同处渲染器实现头），在内存模块就绪后调用 `mesh.build(memory)`，并用 `mesh_create` / `mesh_record_get` / `mesh_destroy` 管理网格。
- **向下**：依赖内存与资源模块（`buffer_create` / `upload_buffer` / `buffer_destroy`）、引擎核心层日志系统（`engine::logger`）。本模块**不**直接依赖 Vulkan / VMA，`Mesh_Context` 的 .cpp 通过包含 `Memory/内存上下文.h` 间接获得这些类型。
- **横向**：本模块不依赖任何同级资源模块；反之帧 / 命令录制链路通过 `mesh_record_get` 拿到缓冲句柄与索引数，用于绑定与绘制。

### 1.4 与相邻模块的职责分界

| 相邻模块 | 分界 |
| --- | --- |
| 内存与资源模块（`render/Memory/`） | 内存模块负责 VMA 分配器的建立、缓冲的创建 / 销毁、以及一次性同步上传。本模块以 `build(Memory_Context& memory)` 接收其**引用**（非拥有），借 `buffer_create` / `upload_buffer` 建出顶点与索引缓冲，并把 `Memory_Context*` 指针记为成员以便后续归还。缓冲句柄归本模块记录所有，销毁动作回到内存模块。 |
| 渲染器门面（`render/Renderer/`） | 门面负责**拥有** `Mesh_Context` 实例、编排 `build → mesh_create → 使用 → destroy` 的顺序，并在销毁时**先**让所有网格销毁、**再**销毁内存模块。本模块自身只保证「`destroy` 幂等、析构兜底、失败不留半初始化」。 |
| 帧 / 命令录制链路（同层，经门面间接） | 录制链路通过 `mesh_record_get` 取到 `VkBuffer vertex_buffer` / `VkBuffer index_buffer` / `uint32_t index_count`，自行调用 `vkCmdBindVertexBuffers` 与 `vkCmdBindIndexBuffer`（索引类型为 `VK_INDEX_TYPE_UINT32`）。本模块只提供句柄与索引数，不参与命令录制。 |
| 管线 / 着色器模块（`render/Pipeline/`、`render/Shader/`） | 顶点布局（stride 20 字节、location 0 为 `vec3`、location 1 为 `vec2`）是本模块与管线 / 着色器的**隐式契约**：本模块只保证 `Vertex` 的内存布局与注释一致，具体的 `VkVertexInputBindingDescription` / `VkVertexInputAttributeDescription` 由管线模块声明、由着色器消费；本模块不生成管线状态。生成器的绕序（逆时针）与管线 `frontFace = COUNTER_CLOCKWISE` / `cullMode = BACK` 自洽，但该管线约定由管线模块落实。 |
| 引擎核心层网格加载工具（`Engine/EngineCore/src/tools/Mesh_Loader/`） | 该工具提供 `Mesh_Loader::load_obj`（OBJ 文件解析）。**本模块当前未引用它**：本模块的「加载器」编译单元只做过程式生成，且全渲染层源码中除 `源文件列表.cmake` 的字面量外无任何对 `Mesh_Loader` 的引用。二者虽然都提供「网格数据」，但**同名不同定义**（详见 2.3、4.9 与待确认 R-MESH-01 / R-MESH-02）。 |
| 日志系统（`Engine/EngineCore/src/tools/Logging/`） | 本模块只把 `logger` 当作输出通道使用（`logger.error` / `logger.info`），不配置日志规则、不绑定输出流。 |

### 1.5 生命周期与所有权总览

`Mesh_Context` 的完整生命周期为：

```
构造（default，不创建任何网格）
   → build(Memory_Context& memory)
        └─ 校验 memory.valid() → 记录 memory 指针（不创建任何网格）
   → [使用：三角 / 立方体生成 → mesh_create（创建并上传缓冲）→ mesh_record_get（取用）→ mesh_destroy（可选，逐网格销毁）]
   → destroy()（幂等；归还全部网格缓冲 → 清空 records → memory = nullptr）
   → 析构（兜底再调用一次 destroy，保证网格缓冲不泄漏）
```

所有权约定（关键约定，务必按此理解）：

1. **内存模块引用归本模块记录，但所有权归门面**：`Mesh_Context::memory` 是一个 `Memory_Context*` 裸指针，指向门面持有的内存上下文；本模块只借用，不拥有、不销毁它。
2. **缓冲句柄归本模块记录所有**：`records` 中每条 `Mesh_Record` 保存一对 `(VkBuffer, VmaAllocation)`；调用方只持有 `Mesh_Handle`，不直接持有缓冲句柄。
3. **销毁动作一律回到内存模块**：`mesh_destroy` 与 `destroy` 都通过 `memory->buffer_destroy` 归还缓冲，本模块不手写 `vkDestroyBuffer`。
4. **内存模块须比本模块长寿**：由于本模块保存的是裸指针，`Mesh_Context::destroy`（或析构）必须在 `Memory_Context` 被销毁**之前**完成；否则 `destroy` 将解引用悬空指针。此约定由门面的编排顺序保证。
5. **网格数据（`Mesh_Data`）为值语义、按值传入**：`mesh_create` 接收 `const Mesh_Data&`，内部只读取其内容并拷贝进 GPU 缓冲，不保存该对象的引用；调用方可随即丢弃 `Mesh_Data`。

### 2.2 `engine::Vertex`（单顶点）

**声明位置**：`Application/Renderer/src/render/Mesh/网格数据.h`

```cpp
//顶点（位置 vec3 + 纹理坐标 vec2；步长 20 字节，与着色器顶点输入一致）
struct Vertex
{
    //位置（三维）
    float position[3];
    //纹理坐标（二维）
    float uv[2];
};
```

| 字段 | 类型 | 含义 | 约束 |
| --- | --- | --- | --- |
| `position` | `float[3]` | 顶点位置（x, y, z） | 无单位约定；生成器使用范围为 `[-half_extent, +half_extent]` 或 `[-0.5, 0.5]` |
| `uv` | `float[2]` | 纹理坐标（u, v） | 生成器使用 `[0, 1]`；无越界校验 |

- **内存布局**：五个 `float` 连续排列，`sizeof(Vertex) == 20` 字节，无填充。该步长被 `mesh_create` 用作顶点缓冲字节数的计算基数（`sizeof(Vertex) * vertices.size()`），并与着色器顶点输入（location 0 为 `vec3`、location 1 为 `vec2`）约定一致。
- **返回值 / 约束**：纯 POD 结构体，无成员函数、无构造析构；可被 `std::vector` 容纳与按值传递。
- **异常行为**：无。

### 2.3 `engine::Mesh_Data`（网格创建入参）

**声明位置**：`Application/Renderer/src/render/Mesh/网格数据.h`

```cpp
//网格数据（创建入参）
struct Mesh_Data
{
    //顶点集合
    std::vector<Vertex> vertices;
    //索引集合
    std::vector<uint32_t> indices;
};
```

| 字段 | 类型 | 含义 | 约束 |
| --- | --- | --- | --- |
| `vertices` | `std::vector<Vertex>` | 顶点集合（数组结构 AoS，与步长 20 一致） | `mesh_create` 要求非空 |
| `indices` | `std::vector<uint32_t>` | 索引集合（每 3 个构成一个三角面，指向 `vertices`） | `mesh_create` 要求非空；每个元素必须 `< vertices.size()` |

- **语义**：本结构体是**纯 CPU 端描述**，既不含 Vulkan 类型也不含句柄；它是「生成器 / 未来的文件加载」与「GPU 缓冲创建」之间的中立数据层。
- **按值传入约定**：`mesh_create` 以 `const Mesh_Data&` 接收，内部只读并拷贝进缓冲，不保存引用；调用方可在 `mesh_create` 返回后立即丢弃该对象。
- **索引宽度**：索引固定为 `uint32_t`（32 位），因此绑定索引缓冲时须使用 `VK_INDEX_TYPE_UINT32`（由录制链路落实）。
- **【待确认】**：引擎核心层工具 `Engine/EngineCore/src/tools/Mesh_Loader/网格加载器.h` 亦定义了**同名**的 `engine::Mesh_Data`，但其字段为 `std::vector<float> vertices`（按 x、y、z 依次平铺）＋ `std::vector<uint32_t> indices`，与本模块的 `std::vector<Vertex> vertices` **定义不同**。二者若同处一个翻译单元（TU）被包含将构成 ODR 冲突（同一命名空间内同名类型两处定义）。当前本模块不包含该工具头，故未触发冲突。【待确认】`<成因：两处同名类型是否为有意隔离（渲染层自持顶点描述）还是尚未整合的遗留；见 R-MESH-02>`

### 2.4 `engine::Mesh_Handle`（网格句柄）

**声明位置**：`Application/Renderer/src/render/Mesh/网格数据.h`

```cpp
//网格句柄（0 表示无效）
using Mesh_Handle = uint64_t;
```

| 项 | 说明 |
| --- | --- |
| 类型 | `uint64_t` |
| 取值 | `0` = 无效句柄；`>= 1` = 有效句柄，其对应记录下标 = `句柄 − 1` |
| 约束 | 由 `mesh_create` 出参回写；上层只应保存与回传，不应自行构造或做算术 |
| 编号特征 | 单调递增（每成功创建一条网格加一），已销毁的句柄槽**不复用**（见 4.3） |

- **返回值 / 约束**：`mesh_create` 失败时把出参置 `0`；`mesh_record_get` / `mesh_destroy` 对 `0` 与越界句柄一律视为无效。

### 2.5 `engine::Mesh_Record`（网格记录）

**声明位置**：`Application/Renderer/src/render/Mesh/网格.h`

```cpp

struct Mesh_Record
{
    //顶点缓冲
    VkBuffer vertex_buffer = VK_NULL_HANDLE;
    //顶点缓冲内存
    VmaAllocation vertex_allocation = VK_NULL_HANDLE;
    //索引缓冲
```

| 字段 | 类型 | 初值 | 含义 | 置无效时的复位值 |
| --- | --- | --- | --- | --- |
| `vertex_buffer` | `VkBuffer` | `VK_NULL_HANDLE` | 顶点缓冲句柄（设备本地） | `VK_NULL_HANDLE` |
| `vertex_allocation` | `VmaAllocation` | `VK_NULL_HANDLE` | 顶点缓冲的 VMA 分配（与 `vertex_buffer` 成对） | `VK_NULL_HANDLE` |
| `index_buffer` | `VkBuffer` | `VK_NULL_HANDLE` | 索引缓冲句柄（设备本地） | `VK_NULL_HANDLE` |

### 2.7 构造 / 析构 / 拷贝禁用

```cpp
//构造（不创建任何网格）
Mesh_Context(void) = default;
//析构（内部调用 destroy，保证网格不泄漏）
~Mesh_Context(void);
//不可拷贝、不可移动（持有 VMA 句柄）
Mesh_Context(const Mesh_Context&) = delete;
Mesh_Context& operator=(const Mesh_Context&) = delete;
```

- **构造**：默认构造，`memory = nullptr`、`records` 为空；**不创建任何网格、不要求内存模块就绪**（内存模块在 `build` 时才记录）。
- **析构**：定义在 `网格缓冲.cpp`，函数体仅一句 `destroy();`——即使调用方忘记显式 `destroy`，析构也会兜底归还全部缓冲。
- **拷贝禁用**：拷贝构造与拷贝赋值均 `= delete`；由于用户声明了拷贝构造函数（删除形式），编译器**不再隐式生成移动构造 / 移动赋值**，故本类客观上也「不可移动」，与头注释「不可拷贝、不可移动」一致。
- **约束**：因持有 `Memory_Context*` 与缓冲句柄，拷贝会带来双重释放风险，故必须禁用。
- **异常行为**：构造与析构均不抛异常。

### 2.9 `void destroy(void)`

**签名**：`void Mesh_Context::destroy(void)`
**实现位置**：`Application/Renderer/src/render/Mesh/core/网格缓冲.cpp`

```cpp
//销毁
void Mesh_Context::destroy(void)
{
    //若内存模块已记录
    if (memory != nullptr)
        //释放全部网格缓冲
        for (auto& record : records)
        {
            //归还顶点缓冲
            memory->buffer_destroy(record.vertex_buffer, record.vertex_allocation);
            //归还索引缓冲
            memory->buffer_destroy(record.index_buffer, record.index_allocation);
            //复位记录
            record.vertex_buffer = VK_NULL_HANDLE;
            record.vertex_allocation = VK_NULL_HANDLE;
            record.index_buffer = VK_NULL_HANDLE;
            record.index_allocation = VK_NULL_HANDLE;
            record.index_count = 0;
            record.valid = false;
        }

    //清空记录并复位
    records.clear();
    memory = nullptr;
}
```

| 项 | 说明 |
| --- | --- |
| 参数 | 无 |
| 返回值 | 无 |
| 行为 | 遍历全部记录，逐条把顶点 / 索引缓冲归还给内存模块（`buffer_destroy`），复位各字段；随后清空 `records`、把 `memory` 复位为 `nullptr` |
| 幂等性 | **幂等**：第二次调用时 `records` 已空、`memory` 为 `nullptr`，空转即返回 |
| 前置条件 | 应在内存模块 `destroy` **之前**调用（否则解引用悬空指针） |
| 边界 | 若 `memory == nullptr`（尚未 `build` 或已 `destroy`），跳过释放循环，但仍执行 `records.clear()` 与 `memory = nullptr` |
| 异常行为 | 不抛异常 |

### 2.11 `bool mesh_create(Mesh_Handle& handle_out, const Mesh_Data& data)`

**签名**：`bool Mesh_Context::mesh_create(Mesh_Handle& handle_out, const Mesh_Data& data)`
**实现位置**：`Application/Renderer/src/render/Mesh/core/网格缓冲.cpp`

这是本模块**最核心**的接口，完整实现如下：

```cpp
//创建网格
bool Mesh_Context::mesh_create(Mesh_Handle& handle_out, const Mesh_Data& data)
{
    //默认无有效句柄
    handle_out = 0;
    //前置：内存模块必须就绪
    if (memory == nullptr || !memory->valid())
    {
        logger.error("网格缓冲:: 内存上下文尚未构建，无法创建网格");
        return false;
    }
    //前置：顶点与索引均不得为空
    if (data.vertices.empty() || data.indices.empty())
    {
        logger.error("网格缓冲:: 顶点或索引为空，无法创建网格");
        return false;
    }
    //校验索引不越界
    for (uint32_t index : data.indices)
        //若索引越界
        if (index >= data.vertices.size())
        {
            logger.error("网格缓冲:: 索引 {} 越界（顶点数 {}）", index, static_cast<uint32_t>(data.vertices.size()));
            return false;
        }

    //顶点缓冲字节数
    VkDeviceSize vertex_bytes = sizeof(Vertex) * data.vertices.size();
    //创建顶点缓冲（设备本地，可作传输目标）
    VkBuffer vertex_buffer = VK_NULL_HANDLE;
    VmaAllocation vertex_allocation = VK_NULL_HANDLE;
    if (!memory->buffer_create(vertex_buffer, vertex_allocation, vertex_bytes,
        VK_BUFFER_USAGE_VERTEX_BUFFER_BIT | VK_BUFFER_USAGE_TRANSFER_DST_BIT, false))
        return false;
    //上传顶点数据
    if (!memory->upload_buffer(vertex_buffer, data.vertices.data(), vertex_bytes, 0))
    {
        memory->buffer_destroy(vertex_buffer, vertex_allocation);
        return false;
    }

    //索引缓冲字节数
    VkDeviceSize index_bytes = sizeof(uint32_t) * data.indices.size();
    //创建索引缓冲（设备本地，可作传输目标）
    VkBuffer index_buffer = VK_NULL_HANDLE;
    VmaAllocation index_allocation = VK_NULL_HANDLE;
    if (!memory->buffer_create(index_buffer, index_allocation, index_bytes,
        VK_BUFFER_USAGE_INDEX_BUFFER_BIT | VK_BUFFER_USAGE_TRANSFER_DST_BIT, false))
    {
        memory->buffer_destroy(vertex_buffer, vertex_allocation);
        return false;
    }
    //上传索引数据
    if (!memory->upload_buffer(index_buffer, data.indices.data(), index_bytes, 0))
    {
        memory->buffer_destroy(vertex_buffer, vertex_allocation);
        memory->buffer_destroy(index_buffer, index_allocation);
        return false;
    }

    //登记网格记录
    Mesh_Record record;
    record.vertex_buffer = vertex_buffer;
    record.vertex_allocation = vertex_allocation;
    record.index_buffer = index_buffer;
    record.index_allocation = index_allocation;
    record.index_count = static_cast<uint32_t>(data.indices.size());
    record.valid = true;
    records.push_back(record);

    //句柄自 1 起
    handle_out = static_cast<Mesh_Handle>(records.size());
    logger.info("网格缓冲:: 网格已建立（句柄 {}，顶点 {}，索引 {}）",
        handle_out, static_cast<uint32_t>(data.vertices.size()), record.index_count);
    return true;
}
```

| 项 | 说明 |
| --- | --- |
| 参数 `handle_out` | 出参，回写新网格句柄；**进入时先被置 0**，任何失败路径都保持 0 |
| 参数 `data` | 网格数据（顶点 + 索引），按 `const` 引用只读 |
| 返回值 | 真 = 创建并上传成功，`handle_out >= 1`；假 = 前置校验或任一步创建 / 上传失败 |
| 前置校验① | `memory != nullptr && memory->valid()`，否则记 `error` 返回假 |
| 前置校验② | `data.vertices` 与 `data.indices` 均非空，否则记 `error` 返回假 |
| 前置校验③ | 逐个索引校验 `index < vertices.size()`，越界即记 `error`（含越界索引值与顶点数）并返回假 |
| 缓冲规格（顶点） | usage = `VK_BUFFER_USAGE_VERTEX_BUFFER_BIT | VK_BUFFER_USAGE_TRANSFER_DST_BIT`；`host_visible = false`（设备本地，需上传）；size = `sizeof(Vertex) * vertices.size()` |
| 缓冲规格（索引） | usage = `VK_BUFFER_USAGE_INDEX_BUFFER_BIT | VK_BUFFER_USAGE_TRANSFER_DST_BIT`；`host_visible = false`；size = `sizeof(uint32_t) * indices.size()` |
| 上传 | 两条缓冲各经 `memory->upload_buffer(..., offset = 0)` 做一次性同步上传；返回时数据已就位 |
| 句柄分配 | `handle_out = records.size()`，即新记录下标 + 1（1-based） |
| 失败清理 | 顶点缓冲上传失败 → 归还顶点缓冲；索引缓冲创建失败 → 归还顶点缓冲；索引缓冲上传失败 → 归还顶点与索引缓冲。任一失败路径都**不留半初始化资源**，`records` 不被修改 |
| 日志 | 成功记 `info`（句柄 / 顶点数 / 索引数）；各失败分支记 `error` |
| 异常行为 | 不抛异常（内存分配由 `std::vector` / VMA 内部承担；本函数不显式 `new`） |

### 2.12 `void mesh_destroy(Mesh_Handle handle)`

**签名**：`void Mesh_Context::mesh_destroy(Mesh_Handle handle)`

```cpp
//销毁网格
void Mesh_Context::mesh_destroy(Mesh_Handle handle)
{
    //句柄为零或越界即视为无需销毁（销毁幂等）
    if (handle == 0 || handle > records.size())
        return;
    //获取目标记录
    Mesh_Record& record = records[handle - 1];
    //若记录已无效
    if (!record.valid)
        return;
    //内存模块就绪时归还缓冲
    if (memory != nullptr)
    {
        //归还顶点缓冲
        memory->buffer_destroy(record.vertex_buffer, record.vertex_allocation);
        //归还索引缓冲
        memory->buffer_destroy(record.index_buffer, record.index_allocation);
    }
    //复位记录
    record.vertex_buffer = VK_NULL_HANDLE;
    record.vertex_allocation = VK_NULL_HANDLE;
    record.index_buffer = VK_NULL_HANDLE;
    record.index_allocation = VK_NULL_HANDLE;
    record.index_count = 0;
    record.valid = false;
}
```

| 项 | 说明 |
| --- | --- |
| 参数 `handle` | 待销毁网格句柄 |
| 返回值 | 无 |
| 无效句柄 | `handle == 0` 或 `handle > records.size()` 直接返回（幂等） |
| 已销毁记录 | 记录 `valid == false` 时直接返回（重复销毁幂等） |
| 归还动作 | 经 `memory->buffer_destroy` 归还顶点与索引缓冲（仅当 `memory != nullptr`） |
| 复位 | 六个字段全部复位；`valid = false` |
| 槽位 | 记录**保留在数组中**（不 `erase`），仅置无效；相应句柄**不复用** |
| 异常行为 | 不抛异常 |

### 3.3 内部数据结构字段说明

本模块的数据结构分「CPU 端描述」与「GPU 端记录」两层：

**CPU 端（`网格数据.h`，Vulkan-free）**

- `Vertex`：`position[3]`（位置）+ `uv[2]`（纹理坐标）；详见 2.2。
- `Mesh_Data`：`vertices`（`vector<Vertex>`）+ `indices`（`vector<uint32_t>`）；详见 2.3。
- `Mesh_Handle = uint64_t`：1-based 句柄；详见 2.4。

**GPU 端记录（`网格.h`，含 Vulkan 句柄）**

- `Mesh_Record`：`vertex_buffer` / `vertex_allocation` / `index_buffer` / `index_allocation` / `index_count` / `valid` 六字段；详见 2.5。语义为「一条已成功创建且尚未销毁的网格：一对（缓冲 + 分配）＋ 索引数 ＋ 有效标志」。

**上下文（`网格.h`）**

- `Mesh_Context::memory`：借用的内存模块指针。
- `Mesh_Context::records`：`vector<Mesh_Record>`；下标与句柄的映射为「句柄 − 1」。数组只追加（`push_back`），永不删除元素；销毁只把元素置无效。

## 四、模块设计/实现细节

### 4.1 顶点布局与步长契约

- `Vertex` 为 `float[3] + float[2]` 连续排列，`sizeof(Vertex) == 20` 字节、无填充。`mesh_create` 以 `sizeof(Vertex) * vertices.size()` 计算顶点缓冲字节数，因此**任何对 `Vertex` 字段的增删都会改变缓冲步长**，必须同步通知管线 / 着色器模块（顶点输入布局）。
- 该 20 字节步长与着色器顶点输入约定（location 0 `vec3`、location 1 `vec2`）一致，但**该约定不在本模块源码内显式声明**，而是以注释「步长 20 字节，与着色器顶点输入一致」形式记录；实际的 `VkVertexInputBindingDescription` 由管线模块给出。
- `Mesh_Data` 的顶点以 `vector<Vertex>`（AoS）存储，天然保证连续内存，可被 `upload_buffer` 按字节直接拷贝。

### 4.2 设备本地缓冲 + 一次性上传策略

- 本模块创建的顶点 / 索引缓冲均为 `host_visible = false`（设备本地、专用内存），usage 各含 `TRANSFER_DST`，因此**必须**经 `memory->upload_buffer` 上传。这样 GPU 读取走设备本地内存，避免主机可见内存的性能损耗。
- 上传走内存模块的一次性同步上传（临时命令池 → 录制拷贝 → 提交 → 等待完成），**返回时数据已就位**，调用方无需同步。本模块为顶点与索引各做一次 `upload_buffer`（两次独立上传），而非合并批次。【待确认】`<成因：两条缓冲两次独立上传、各建一次临时命令池，是否存在合并为单批次以降低提交开销的优化意图，源码未说明；如确需可另立条目>`
- 之所以选择「由本模块自行建缓冲 + 上传」而非「直接建主机可见缓冲后写入」，是为了对齐内存模块的 `host_visible` 语义与资源口径：GPU 只读资源走设备本地，是本层的一致做法。

### 4.3 句柄分配与回收策略

- **1-based 句柄**：`handle_out = static_cast<Mesh_Handle>(records.size())`，即新记录下标 + 1。0 被保留为「无效」，避免「句柄为 0 却指向第 0 条记录」的歧义。
- **槽位不复用**：`mesh_destroy` 只把记录置 `valid = false`，**不**从 `records` 中删除；`mesh_create` 也只在末尾 `push_back`。因此句柄随创建次数**单调递增**，已销毁句柄**永不复用**。这带来两点后果：
  1. 上层若长期持有旧句柄，旧句柄不会「指向」新网格（安全，不会误用）；
  2. 反复「创建 → 销毁」会令 `records` 数组持续增长（每次创建占一格），长期运行下内存占用只增不减。
- 【待确认】`<槽位永不复用是否为有意设计（追求句柄稳定与防误用），长期运行下是否存在回收 / 复用计划；见 R-MESH-04>`
- **下标映射**：所有按句柄访问的路径（`mesh_destroy` / `mesh_record_get`）都先做 `handle == 0 || handle > records.size()` 的越界判定，再取 `records[handle - 1]`，最后验 `valid`。

### 4.4 错误处理与失败清理

- **错误表达方式**：全部通过「返回 `bool` + `engine::logger` 记日志」表达，**不使用异常**（符合项目「内存分配全面禁用异常」与渲染层统一的返回值检查口径）。`destroy` / `mesh_destroy` 这类无返回值操作用「幂等 + 静默返回」表达无效输入。
- **校验顺序**：`mesh_create` 依「内存就绪 → 数据非空 → 索引不越界 → 建缓冲」顺序校验，把廉价校验放在昂贵资源创建之前，避免无谓创建。
- **失败清理矩阵**：

| 失败点 | 已创建资源 | 清理动作 | 结果 |
| --- | --- | --- | --- |
| 内存未就绪 | 无 | 无 | 无副作用，句柄为 0 |
| 数据为空 | 无 | 无 | 无副作用，句柄为 0 |
| 索引越界 | 无 | 无 | 无副作用，句柄为 0 |
| 顶点缓冲创建失败 | 无 | 无 | `buffer_create` 内部失败，句柄为 0 |
| 顶点缓冲上传失败 | 顶点缓冲 | `buffer_destroy(顶点)` | 句柄为 0 |
| 索引缓冲创建失败 | 顶点缓冲 | `buffer_destroy(顶点)` | 句柄为 0 |
| 索引缓冲上传失败 | 顶点缓冲 + 索引缓冲 | `buffer_destroy(顶点)` + `buffer_destroy(索引)` | 句柄为 0 |
| 创建全部成功 | 顶点 + 索引 | 登记记录 | 句柄 = records.size()，返回真 |

- **不留半初始化**：任何失败路径下 `records` 均不被修改，`handle_out` 保持 0，不存在「句柄有效但缓冲不全」的状态。

### 4.5 生命周期与所有权

- **建成顺序**：`Memory_Context::build` → `Mesh_Context::build` → `mesh_create` … → `mesh_destroy`（可选） → `Mesh_Context::destroy` → `Memory_Context::destroy`。本模块必须在内存模块**之后**构建、在内存模块**之前**销毁。
- **析构兜底**：`~Mesh_Context` 调用 `destroy()`，即使上层漏调 `destroy`，只要 `memory` 指针仍有效，缓冲也会被归还。但这要求析构发生时 `Memory_Context` 仍存活——门面编排顺序（先销毁网格上下文、后销毁内存上下文）是前提。
- **所有权小结**：内存模块对象归门面；本模块只借用其指针。缓冲句柄归本模块 `records`；调用方只持有 `Mesh_Handle`。`Mesh_Data` 按值流动、即用即弃。
- **重复 `build` 风险**：见 2.8 与待确认 R-MESH-03——`build` 不做重入保护，二次 `build` 会覆盖 `memory` 指针并使旧记录失去归还目标。

### 4.6 线程 / 并发约定

- 本模块**未做任何互斥或原子保护**：`Mesh_Context` 的 `records` 与 `memory` 均为普通成员，`mesh_create`（`push_back`）与 `mesh_destroy` / `destroy`（就地修改）不可并发调用。
- 隐含约定：网格的创建 / 销毁 / 取用都发生在**同一（渲染）线程**，且发生在 GPU 使用该缓冲的帧完成之后（无延迟销毁机制）。当前源码无帧同步参与，若上层在 GPU 仍在读取某缓冲时调用 `mesh_destroy`，将造成 use-after-free——这属于调用方职责，本模块不校验。
- `triangle_generate` / `cube_generate` 是无共享状态的静态函数，可任意并发调用。

### 4.7 生成器的绕序与管线自洽

- `triangle_generate` 与 `cube_generate` 的顶点 / 索引均按**从外部观察的逆时针（CCW）**排列：三角形索引 `{0,1,2}` 在 XY 平面从 +Z 观察为逆时针；立方体每面 `0,1,2` 与 `2,3,0` 亦为从外部看的逆时针。
- 该绕序与管线 `frontFace = COUNTER_CLOCKWISE` / `cullMode = BACK`（背culling）自洽：正面朝外、背面被剔除。若管线模块改用顺时针正面，则生成器产出的几何将整面翻转、被剔空——这是二者之间的隐式契约。
- **立方体逐面重复顶点**：同一空间角点在相邻三面上各出现一次（共 24 而非 8 顶点），目的是让每面拥有独立 UV（否则共享顶点无法同时满足多面不同纹理坐标）。这是「UV 正确性」优先于「顶点去重」的取舍。

### 4.8 命名与文件职责的错位

- 编译单元 `core/网格加载器.cpp` 名为「加载器（loader）」，但**实际只含过程式生成**（triangle / cube），不含任何文件读取、ODR 解析或格式解析逻辑。
- 真正的「OBJ 文件加载」由引擎核心层工具 `Engine/EngineCore/src/tools/Mesh_Loader/网格加载器.h` 的 `Mesh_Loader::load_obj` 提供（含文件体量上限 64 MiB、顶点数上限 1e6、面索引解析、多边形扇形三角化）。
- 本模块**未引用**该工具：全渲染层源码中除 `Application/Renderer/源文件列表.cmake` 的字符字面量外，无任何 `Mesh_Loader` / `load_obj` 引用。
- 【待确认】`<成因：文件命名暗示「加载」职责，实际实现为「生成」；下层已有 OBJ 加载工具却未被接入，是否为阶段性安排（先过程式生成、后接入文件加载），见 R-MESH-01>`

### 4.9 与引擎核心层 `Mesh_Loader` 的同名类型问题

- 引擎核心层 `Mesh_Loader` 头定义的 `engine::Mesh_Data` 与本模块 `网格数据.h` 的 `engine::Mesh_Data` **同名不同定义**：前者 `std::vector<float> vertices`（按 x、y、z 平铺），后者 `std::vector<Vertex> vertices`。
- 若某个 TU 同时包含这两个头（例如未来把 `load_obj` 接入本模块时），将触发**同一命名空间内同名类型的重复定义（ODR 冲突）**，编译期报错。
- 因此「接入 OBJ 加载」并非简单包含头即可，需要设计数据桥接层（把 `vector<float>` 转成 `vector<Vertex>`）或统一 `Mesh_Data` 的定义位置。
- 【待确认】`<成因：两处同名类型是否为有意冗余、还是尚未整合的遗留；接入时的桥接方案与 `Mesh_Data` 归位，见 R-MESH-02>`

### 4.10 编码与风格约定

- **编码**：源码为 UTF-8（含中文注释与中文日志文本）；日志消息使用 `std::format` 风格占位符（`{}`），由日志系统格式化。
- **命名**：类名 `Mesh_Context` / `Mesh_Record` 各单词首字母大写；结构体 `Vertex` / `Mesh_Data` 亦然；成员变量与函数名小写下划线（`vertex_buffer`、`mesh_create`、`triangle_generate`），符合项目命名约束。文件名 `网格.h` / `网格数据.h` / `网格加载器.cpp` / `网格缓冲.cpp` 为中文文件名，符合「文件名默认中文」约束。
- **大括号与注释**：大括号换行、注释采用「换行注释」且不前置空格（如 `//归还顶点缓冲`），与项目风格约束一致。
- **不抛异常**：本模块无 `new`、无 `throw`、无 `try`；内存分配全部下沉给 `std::vector` 与 VMA。
- **无文件系统操作**：本模块不涉及路径转换 / 编码转换（`std::filesystem` 未使用）。
- **头文件包含口径**：所有头均以「项目根相对全路径」包含预编译头（如 `#include "Application/Renderer/common/前置头文件包含.h"`），两个 `.cpp` 用相对路径包含内部头（`#include "../局部命名空间使用.h"`）。

## 五、模块运行链路

本章以「调用方 → 模块 → 被调方」的时序描述典型链路。调用方统一指渲染器门面（`render/Renderer/`）或其转交的上层。

### 5.1 主流程一：构建网格上下文

```
调用方                           Mesh_Context                    Memory_Context
  │                                   │                               │
  ├─ mesh.build(memory) ─────────────►│                               │
  │                                   ├─ memory.valid()? ────────────►│
  │                                   │◄──── true/false ──────────────┤
  │                                   │                               │
  │                                   ├─[未就绪] logger.error(...)    │
  │                                   │◄── false ─────────────────────┤
  │                                   │                               │
  │                                   ├─[就绪] this->memory = &memory │
  │◄──── true ────────────────────────┤                               │
```

分步：

1. 调用方（门面）在内存模块成功 `build` 之后，持引用调用 `mesh.build(memory)`。
2. `Mesh_Context::build` 先查 `memory.valid()`：
   - 未就绪 → 记 `logger.error("网格上下文:: 内存上下文尚未构建，无法建立网格上下文")`，返回假；
   - 就绪 → 记录 `this->memory = &memory`，返回真。
3. 此时 `mesh.valid()` 转为真；但**没有任何网格被创建**。

### 5.2 主流程二：生成数据并创建网格

```
调用方                       Mesh_Context                Memory_Context
  │                              │                              │
  ├─ Mesh_Data d =               │                              │
  │   Mesh_Context::cube_generate(0.5f)  （纯 CPU，无需实例）   │
  ├─ mesh.mesh_create(h, d) ────►│                              │
  │                              ├─ memory==nullptr || !valid()? ──►│
  │                              ├─[否] vertices.empty()||indices.empty()? │
  │                              ├─[否] 逐索引越界校验          │
  │                              ├─ buffer_create(顶点,VB|TDST,false) ──►│
  │                              │◄──── (vb, va) ────────────────┤
  │                              ├─ upload_buffer(vb, 顶点数据) ───────►│
  │                              │◄──── true（数据已就位）────────┤
  │                              ├─ buffer_create(索引,IB|TDST,false) ──►│
  │                              │◄──── (ib, ia) ────────────────┤
  │                              ├─ upload_buffer(ib, 索引数据) ───────►│
  │                              │◄──── true ────────────────────┤
  │                              ├─ records.push_back(record)    │
  │                              ├─ handle_out = records.size()  │
  │                              ├─ logger.info("网格已建立 ...") │
  │◄──── true, h>=1 ─────────────┤                              │
```

分步：

1. 调用方调用静态生成器（如 `Mesh_Context::cube_generate(0.5f)`）得到 `Mesh_Data`（纯 CPU 操作，不需要 `Mesh_Context` 实例）。
2. 调用方以 `mesh.mesh_create(handle, data)` 请求创建：
   1. `handle` 先被置 0；
   2. 校验 `memory != nullptr && memory->valid()`；
   3. 校验 `vertices` / `indices` 非空；
   4. 逐索引校验 `index < vertices.size()`；
   5. 经 `memory->buffer_create` 建**设备本地、带 `TRANSFER_DST`** 的顶点缓冲；
   6. 经 `memory->upload_buffer` 一次性上传顶点数据；
   7. 同法建索引缓冲并上传；任一步失败按 4.4 的清理矩阵回收已建缓冲并返回假；
   8. 填 `Mesh_Record`（含 `index_count = indices.size()`、`valid = true`），`push_back`；
   9. `handle_out = records.size()`，记 `logger.info`，返回真。

### 5.3 主流程三：取用缓冲绘制

```
调用方                       Mesh_Context
  │                              │
  ├─ mesh_record_get(h, vb, ib, n) ──►│
  │                              ├─ h==0 || h>records.size()? → false
  │                              ├─ records[h-1].valid? → 否 → false
  │                              ├─ vb=record.vertex_buffer
  │                              ├─ ib=record.index_buffer
  │                              ├─ n =record.index_count
  │◄──── true, (vb, ib, n) ──────┤
  ├─ vkCmdBindVertexBuffers(vb, ...)         （调用方自行录制）
  ├─ vkCmdBindIndexBuffer(ib, VK_INDEX_TYPE_UINT32)
  └─ vkCmdDrawIndexed(n, ...)
```

分步：

1. 调用方以 `mesh_record_get(handle, vb, ib, n)` 取缓冲句柄与索引数；三出参先被重置为空值。
2. 句柄 0 / 越界 / 记录无效 → 返回假，出参保持空值（调用方应跳过该绘制）。
3. 有效 → 写出顶点缓冲、索引缓冲、索引数，返回真。
4. 调用方（录制链路）自行绑定顶点 / 索引缓冲并绘制；索引类型为 `VK_INDEX_TYPE_UINT32`。

### 5.4 主流程四：销毁单个网格

```
调用方                Mesh_Context                Memory_Context
  │                       │                              │
  ├─ mesh_destroy(h) ────►│                              │
  │                       ├─ h==0 || h>records.size()? → 返回（幂等）
  │                       ├─ records[h-1].valid? 否 → 返回（幂等）
  │                       ├─ buffer_destroy(顶点缓冲, 顶点分配) ──►│
  │                       ├─ buffer_destroy(索引缓冲, 索引分配) ──►│
  │                       ├─ 复位六字段，valid=false  │
  │◄──── （void）─────────┤                              │
```

分步：

1. 调用方以有效句柄调用 `mesh_destroy(handle)`。
2. 若句柄为 0 / 越界 / 记录已无效，静默返回（重复销毁安全）。
3. 否则经 `memory->buffer_destroy` 归还顶点与索引缓冲，随后复位该记录六字段并置 `valid = false`。
4. 该槽位保留在 `records` 中，句柄不复用。

### 5.5 主流程五：销毁上下文（含析构兜底）

```
调用方                Mesh_Context                Memory_Context
  │                       │                              │
  ├─ mesh.destroy() ─────►│                              │
  │                       ├─ memory != nullptr?          │
  │                       ├─[是] for each record:        │
  │                       │     buffer_destroy(顶点) ──►│
  │                       │     buffer_destroy(索引) ──►│
  │                       │     复位记录                 │
  │                       ├─ records.clear()             │
  │                       ├─ memory = nullptr            │
  │◄──── （void）─────────┤                              │
  ...（稍后若仍调用析构）
  ├─ ~Mesh_Context() ───►│─ destroy()（此时 records 空、memory 空，空转）
```

分步：

1. 调用方（门面）在**销毁内存模块之前**调用 `mesh.destroy()`。
2. `destroy` 遍历全部记录，逐条把顶点 / 索引缓冲归还内存模块并复位；再 `records.clear()`、`memory = nullptr`。
3. 二次调用 `destroy` 为空转（幂等）。
4. 析构 `~Mesh_Context` 再调一次 `destroy`，同样空转，保证不泄漏。

### 5.6 异常 / 边界分支汇总

| 场景 | 触发点 | 模块行为 | 调用方应如何应对 |
| --- | --- | --- | --- |
| 内存模块未就绪即构建 | `build` / `mesh_create` | 记 `error` 返回假 / 句柄置 0 | 先完成内存模块 `build`，再重试 |
| 顶点或索引为空 | `mesh_create` | 记 `error` 返回假 / 句柄置 0 | 检查生成的 `Mesh_Data` |
| 索引越界 | `mesh_create` | 记 `error`（含索引值与顶点数）返回假 | 修正几何数据 |
| 缓冲创建失败 | `mesh_create` | 返回假，回收已建缓冲 | 检查显存 / 内存模块状态 |
| 上传失败 | `mesh_create` | 返回假，回收已建缓冲 | 检查内存模块一次性上传路径 |
| 查询无效句柄 | `mesh_record_get` | 三出参置空，返回假 | 跳过该绘制 |
| 销毁无效 / 已销毁句柄 | `mesh_destroy` | 静默返回 | 无需处理（幂等） |
| 销毁后又查询 | `mesh_record_get` | 记录 `valid=false` → 返回假 | 跳过该绘制 |
| GPU 仍在使用时销毁 | `mesh_destroy` | **不校验**，直接归还缓冲 | 调用方须自行保证帧同步（本模块无延迟销毁） |
| 重复 `build` | `build` | 覆盖 `memory` 指针，旧记录失去归还目标 | 只 `build` 一次（见 R-MESH-03） |
| 重复 `destroy` | `destroy` | 空转（幂等） | 无需处理 |

### 5.7 未接入路径说明

- **文件加载路径未接入**：本模块当前**没有**「读取网格文件 → 解析 → 创建缓冲」的链路。`网格加载器.cpp` 只提供过程式生成；引擎核心层的 `Mesh_Loader::load_obj` 未被本模块引用（见 4.8 / 4.9）。因此「网格加载」在本模块的实际形态仅有「过程式生成」，OBJ 加载路径如未来接入，还需解决同名 `Mesh_Data` 冲突。
- **延迟销毁未接入**：本模块销毁缓冲时直接调用 `memory->buffer_destroy`，未经过帧模块的延迟销毁队列；若上层在 GPU 使用中销毁会造成悬空。是否应改走延迟销毁，属未来演进方向，当前源码未涉及。
