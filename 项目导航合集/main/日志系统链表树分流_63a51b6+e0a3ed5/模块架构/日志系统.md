## 1. 模块功能

### 1.1 模块是什么

「日志系统 Log」是引擎层 `src/tools/Logging/日志系统.h` 定义的一个**静态工具类**（含一个全局 `std::formatter<std::error_code>` 特化），为整个引擎提供统一、轻量、按调用来源分流的日志输出能力：

| 能力 | 入口 | 说明 |
| --- | --- | --- |
| 四级别日志 | `Log::info` / `Log::warn` / `Log::error` / `Log::debug` | 静态模板函数，`std::format` 风格格式化（`{}` 占位符 + 类型安全参数包）；**签名中不出现任何流参数** |
| 调用处自动捕获 | `Log::Format<Args...>` 包装类型的构造函数默认参数 `std::source_location place = std::source_location::current()` | 在**调用点**求值，自动取得调用处文件路径（无需调用方显式传参） |
| 消息级别前缀 | 自动加 `[INFO]` / `[WARN]` / `[ERROR]` / `[DEBUG]` | 输出形如 `[INFO]消息内容` |
| 链表树路由 | 私有 `Stream_Node` 树 + `node_ensure` / `group_resolve` | 按调用处路径的**公共前缀**建父子链表，节点粒度即路径公共前缀本身（不逐级建目录节点） |
| 流绑定 | `stream_bind(path, file_name)` / `stream_bind(path, stream)` | 把「路径前缀节点」绑定到文件输出流或外部流；目录前缀节点绑定后其后代继承 |
| 流清空 | `stream_clear(path)` | 清除某路径节点的自有流，该节点及其后代回落共享父节点输出流 |
| 多流全量输出 | 节点自有容器 `std::vector<Stream>` | 同一节点可绑多个流，打印时**全部流都写** |
| 目录继承（弱引用共享） | 节点 `shared_group`（`std::weak_ptr`） | 子节点未设自有流时，激活 weak_ptr 容器共享父节点输出流 |
| 单独流输出（强引用持有） | 节点 `own_group`（`std::shared_ptr`） | 子节点设了自有流时，激活 shared_ptr 容器单独输出，与父流互斥 |
| 无流兜底 | `group_console()` | 整条父链都未设文件流时，默认写 `std::cout` |
| 多线程保护 | `inline static std::mutex tree_mtx` | 建节点 / 设流 / 清流 / 输出全程单锁串行化（**无权限保护机制**，任何调用方均可设流） |
| 错误码格式化 | `std::formatter<std::error_code>` 特化 | 使 `Log::info("{}", ec)` 可直接输出 `[value] message` |
| 结尾换行 | 自动 `std::endl` | 每条日志独立一行，且刷新流缓冲 |

### 1.2 模块解决什么问题

- **日志输出分散问题**：引擎各模块（Data_Validator、Config_Loader、Engine_Env、Number_Allocator、Collision_Region/Proxy 等）都需要输出运行信息。若各自 `std::cout << ...`，格式不统一、目标不可控。
- **格式化安全性问题**：`std::format` 提供编译期格式串校验（`Format` 内部保留 `std::format_string<Args...>`），杜绝格式化漏洞与类型误配。
- **日志目标全局化问题（本版次核心动机）**：旧实现用「单一活跃文件名（`active_file_stream`）+ 哈希表 `streams` 缓存流」，改输出目标必须显式调用 `stream_set`，且**全局唯一活跃流**无法按来源区分输出。本版次改为：**日志方法只认调用处路径**，路径 → 链表树节点 → 生效流容器，自动分流；同一进程内不同文件/目录的日志可各自落盘，互不干扰。
- **调用处自动定位问题**：旧实现日志方法不携带调用信息来源。本版次用 `std::source_location` 默认参数在调用点自动捕获 `file_name()`，把「谁在打日志」变成路由键，**无需调用方改动任何一行业务代码**（四个日志方法的调用点写法完全不变）。
- **错误码可读性问题**：`std::error_code` 在 C++20 标准库无 `std::formatter` 特化，`std::format("{}", ec)` 编译失败。日志系统在文件尾部提供显式特化，输出 `[值] 消息`（Data_Validator::error_out 正是这么用的）。

### 1.3 模块服务谁

- **服务方（被调用方）**：引擎层全部需要日志的模块——Data_Validator、Config_Loader、Engine_Env、Number_Allocator、Collision_Region / Collision_Proxy / Collider 等；系统层业务模块（经上述模块间接或直接调用）。
- **调用方画像**：任何 `#include "src/tools/Logging/日志系统.h"` 的翻译单元，直接 `Log::xxx(...)` 静态调用，无需实例化、无需设置流（未设置即走控制台）。
- **不服务**：不做日志分级过滤（无「仅输出 ERROR 以上」）、无时间戳、无异步落盘、无自动滚动文件；级别差异仅前缀不同。

### 1.4 版本演变（重要背景）

- **2d5f704 及更早（旧实现）**：`active_file_stream`（单一活跃文件名字符串）+ `streams`（`unordered_map<string, shared_ptr<ofstream>>` 哈希流缓存）+ **非静态** `stream_set` + 私有 `stream_charge` / `log_build`。日志方法读全局活跃流，无法按来源分流；`stream_set` 还因非静态而必须经实例调用。
- **本版次（63a51b6）**：
  - **取消哈希流存储容器**（`streams` 删除），**取消活跃流全局态**（`active_file_stream` 删除），**取消非静态 `stream_set`**；
  - 日志方法签名不再出现流参数，函数体不再读取任何全局流状态——**方法完全不感知流设置**；
  - 新增 public `Stream` 别名、public 嵌套 `Format<Args...>` 包装类型；
  - 新增静态 `stream_bind`（两重载）与静态 `stream_clear`；
  - 内部新增 `Stream_Group` / `Stream_Group_Weak` / `Stream_Node` 与链表树算法；
  - 整树加锁，获得**多线程保护**（旧实现明确无锁）。
- 对外**调用点零改动**：全项目所有既有 `Log::info/warn/error/debug` 调用一行未改即编译通过并自动获得分流能力。

## 2. 模块提供接口

### 2.1 `Log` 类全貌

```cpp
namespace engine
{
    //日志系统
    class Log
    {
    public:
        //输出流别名
        using Stream = std::shared_ptr<std::ostream>;
        //日志格式串（携带调用处信息，并承担占位符与实参的编译期校验）
        template<typename... Args>
        class Format
        {
        public:
            //从字面量构造（默认参数在调用点求值，从而自动捕获调用处文件路径）
            template<typename Text>
            consteval Format(const Text& text, std::source_location place = std::source_location::current())
                : pattern(text), site(place) {}
            //格式串本体（编译期校验占位符与实参匹配）
            std::format_string<Args...> pattern;
            //调用处信息
            std::source_location site;
        };
    public:
        template<typename... Args> static void info (Format<std::type_identity_t<Args>...> fmt, Args&&... args);
        template<typename... Args> static void warn (Format<std::type_identity_t<Args>...> fmt, Args&&... args);
        template<typename... Args> static void error(Format<std::type_identity_t<Args>...> fmt, Args&&... args);
        template<typename... Args> static void debug(Format<std::type_identity_t<Args>...> fmt, Args&&... args);
        static bool stream_bind(const std::string& path, const std::string& file_name);
        static bool stream_bind(const std::string& path, const Stream& stream);
        static bool stream_clear(const std::string& path);
    private:
        using Stream_Group      = std::shared_ptr<std::vector<Stream>>;
        using Stream_Group_Weak = std::weak_ptr<std::vector<Stream>>;
        struct Stream_Node
        {
            std::string       key{};
            Stream_Node*      parent = nullptr;
            std::list<Stream_Node> children{};
            Stream_Group      own_group{};
            Stream_Group_Weak shared_group{};
        };
        static std::string path_normalize(const std::string& raw);
        static size_t      prefix_common(const std::string& left, const std::string& right);
        static Stream_Node& node_ensure(const std::string& key);
        static Stream_Node* node_find(const std::string& key);
        static Stream stream_console();
        static Stream_Group group_console();
        static Stream_Group group_create_console();
        static bool group_append(Stream_Node& node, const Stream& stream);
        static void group_shared_reset(Stream_Node& node);
        static Stream_Group group_resolve(Stream_Node& node);
        static void output(const char* file_name, const std::string& text, const std::string& type);

        inline static Stream_Node node_root{};
        inline static std::mutex  tree_mtx{};
    };

    //日志系统全局实例
    inline Log logger;
}
```

### 2.2 公开接口逐项说明

#### 2.2.1 `Format<Args...>`（调用处捕获载体，public 嵌套类）

```cpp
template<typename... Args>
class Format
{
public:
    template<typename Text>
    consteval Format(const Text& text, std::source_location place = std::source_location::current())
        : pattern(text), site(place) {}
    std::format_string<Args...> pattern;
    std::source_location site;
};
```

| 项 | 说明 |
| --- | --- |
| 存在意义 | **MSVC 下唯一可行的「变参包之后捕获调用处」手段**。直接在日志函数末尾追加 `std::source_location loc = std::source_location::current()`（置于变参包之后）会被 MSVC 拒绝：非末位变参包是**非推导上下文**，`Args` 推成空、实参被误配到 `source_location`（详见 §4.1）。改为「格式串先隐式转换为 `Format<Args...>`」，其构造函数默认参数即落在**调用点**（隐式转换点）求值，从而拿到正确的 `file_name()`。 |
| `consteval` 构造 | 强制编译期求值（配合格式串编译期校验）。 |
| `pattern` | `std::format_string<Args...>`，保留占位符与实参的**编译期匹配校验**（`{}` 数与类型不符即编译错误）。 |
| `site` | `std::source_location`，`file_name()` 即调用处所在**源文件路径**（`/utf-8` 下为 UTF-8 字节，实测中文路径字节正确）。 |
| 可见性 | **必须 public**：日志函数形参类型需被调用方可见才能完成隐式转换。 |
| 构造模板参数 `Text` | 允许任意字面量类型（`const char(&)[N]`），由 `std::format_string` 承担约束。 |

#### 2.2.2 `info` / `warn` / `error` / `debug`

```cpp
template<typename... Args>
static void info(Format<std::type_identity_t<Args>...> fmt, Args&&... args)
{
    //格式化正文并交由链表树路由输出（方法不感知任何流设置）
    output(fmt.site.file_name(), std::format(fmt.pattern, std::forward<Args>(args)...), "INFO");
}
// warn / error / debug 同构，仅级别串不同
```

| 项 | 说明 |
| --- | --- |
| 关键签名技巧 | 形参写作 `Format<std::type_identity_t<Args>...> fmt`：`std::type_identity_t` 把该参数变成**非推导上下文**，于是 `Args` 只由**末位变参包** `Args&&... args` 推导；若写 `Format<Args...> fmt` 则会「无法从 `const char[N]` 推导 `Format<Args...>`」而失败（实测）。 |
| 流参数 | **签名中没有任何流参数**，函数体也不读任何全局流状态 → 实现「流输出设置对日志输出方法屏蔽」。 |
| 路由键 | `fmt.site.file_name()`——调用处源文件路径（未经规范化，规范化在 `output` 内做）。 |
| 行为 | `std::format` 生成正文 → `output` 内构造 `[级别]正文` 并路由写出。 |
| 级别标签 | info→`[INFO]`、warn→`[WARN]`、error→`[ERROR]`、debug→`[DEBUG]`；**无级别过滤**。 |
| 调试点 | 调用方式与旧实现**逐字相同**（`Log::info("{}", x)`），故全项目既有调用零改动。 |
| 异常 | `std::format` 对运行期格式错误可能抛 `std::format_error`，未捕获，异常传播给调用方。 |

#### 2.2.3 `stream_bind(path, file_name)`（绑定文件流）

```cpp
static bool stream_bind(const std::string& path, const std::string& file_name)
{
    //整树加锁（多线程保护）
    std::lock_guard<std::mutex> lock(tree_mtx);
    //定位或创建路径节点
    Stream_Node& node = node_ensure(path_normalize(path));
    //若文件名为空则改为绑定控制台输出流
    if (file_name.empty())
        return group_append(node, stream_console());
    //分配文件输出流内存（禁用异常的分配形式）
    Stream stream(new(std::nothrow) std::ofstream(file_name));
    //若内存分配失败
    if (!stream)
    {
        *stream_console() << "[FATAL]" << "内存不足\n已切换至控制台输出\n" << std::endl;
        return false;
    }
    std::shared_ptr<std::ofstream> file_stream = std::static_pointer_cast<std::ofstream>(stream);
    //若文件打开失败
    if (!file_stream->is_open())
    {
        *stream_console() << "[ERROR]" << "文件打开失败\n已切换至控制台输出\n" << std::endl;
        return false;
    }
    return group_append(node, stream);
}
```

| 项 | 说明 |
| --- | --- |
| `path` | 目标路径（文件路径或目录路径均可）。**经 `path_normalize` 规范化**后作为树键；空串即**根节点**（绑定后全局未设自有流的调用处全部继承）。 |
| `path` 语义 | 传**目录路径**时绑定的是「该目录前缀节点」，其后代文件调用处**继承**该流（见 §4.4、试用例「目录节点绑定后后代继承」）。 |
| `file_name` | 目标日志文件名（相对当前工作目录）。**空串表示绑定控制台流**（`group_append(node, stream_console())`），即让该节点显式输出到 `std::cout`。 |
| 返回值 | 成功 `true`；内存分配失败、文件打开失败均 `false`（此时**不绑流**，仅向控制台提示）。 |
| 分配失败提示 | `[FATAL]内存不足\n已切换至控制台输出\n`（`<<` 裸写、非标准 `[级别]正文` 包装）。 |
| 打开失败提示 | `[ERROR]文件打开失败\n已切换至控制台输出\n`。 |
| 多流叠加 | 对同一路径**重复调用**即向该节点自有容器**追加**流（不会替换），全部流都会输出（见 §4.5）。 |
| 线程安全 | 整树 `tree_mtx` 加锁。 |

#### 2.2.4 `stream_bind(path, stream)`（绑定外部流）

```cpp
static bool stream_bind(const std::string& path, const Stream& stream)
{
    //若输出流为空则绑定失败
    if (!stream)
        return false;
    //整树加锁（多线程保护）
    std::lock_guard<std::mutex> lock(tree_mtx);
    //定位或创建路径节点并追加输出流
    return group_append(node_ensure(path_normalize(path)), stream);
}
```

| 项 | 说明 |
| --- | --- |
| 用途 | 把**任意 `std::ostream`**（内存流 `std::ostringstream`、自定义流等）绑定到路径节点，便于测试与自定义输出后端。 |
| 空流 | `!stream` 直接返回 `false`（不建节点）。 |
| 所有权 | 容器持有 `shared_ptr`，外部流存活由容器引用计数保证。 |

#### 2.2.5 `stream_clear(path)`（清空节点自有流）

```cpp
static bool stream_clear(const std::string& path)
{
    //整树加锁（多线程保护）
    std::lock_guard<std::mutex> lock(tree_mtx);
    //按规范化键查找节点（不新建）
    Stream_Node* node = node_find(path_normalize(path));
    //若节点不存在则清空失败
    if (!node)
        return false;
    //清除节点自有流容器，使该节点转为共享父节点输出流
    node->own_group.reset();
    //清除节点共享流容器缓存，下次输出时按父链重新解析
    node->shared_group.reset();
    return true;
}
```

| 项 | 说明 |
| --- | --- |
| 行为 | 把目标节点**自有容器释放**（`own_group.reset()`）并清掉共享缓存，使该节点由「单独流输出」回落为「继承父节点流」。 |
| **不删除节点** | 只清流、不删节点（节点保留在树上，避免 `std::list` 迭代器/元素地址失效；节点生命周期与进程同长）。 |
| 返回值 | 节点存在 `true`；节点不存在（含从未建立）`false`。根节点（`path=""`）恒存在，故清空根节点返回 `true`。 |
| 对后代的影响 | 后代若此前共享了本节点容器，`shared_group` 缓存为 `weak_ptr`：本节点容器释放后 `lock()` 失败 -> 自动沿父链重新解析（见 §4.3）。 |
| 线程安全 | 整树 `tree_mtx` 加锁。 |

### 2.3 私有接口（内部机制）

#### 2.3.1 数据结构

```cpp
//输出流容器别名（容器可存储多个输出流，打印日志时全部输出）
using Stream_Group = std::shared_ptr<std::vector<Stream>>;
//输出流容器弱引用别名（共享父节点输出流时使用，不持有容器）
using Stream_Group_Weak = std::weak_ptr<std::vector<Stream>>;

//流节点（链表树节点）
struct Stream_Node
{
    //节点路径键（规范化路径，恒以 '/' 结尾，保证前缀比较落在路径段边界）
    std::string key{};
    //父节点（链表 splice 不搬移元素，故元素地址稳定、指针始终有效）
    Stream_Node* parent = nullptr;
    //子节点链表
    std::list<Stream_Node> children{};
    //自有输出流容器（节点被单独设置输出流时激活）
    Stream_Group own_group{};
    //共享输出流容器（节点未设置单独输出流时激活，弱引用最近祖先的自有容器）
    Stream_Group_Weak shared_group{};
};
```

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `key` | `std::string` | 节点路径键。**恒以 `/` 结尾**（文件路径规范化后末尾补 `/`），使文件节点与目录节点共用同一套「路径段前缀」比较；节点键是**相对于父节点的剩余路径段**（不是全路径），故同一路径只有一个节点。 |
| `parent` | `Stream_Node*` | 父指针。用 `std::list` 存子节点 + `splice` 迁元素，**元素地址稳定**，指针永不失效（这是选 `std::list` 而非 `vector` 的根本原因）。 |
| `children` | `std::list<Stream_Node>` | 子节点链表。 |
| `own_group` | `shared_ptr<vector<Stream>>` | **自有容器**：该节点被设过流时激活；容器内所有流均输出（多流全量）。 |
| `shared_group` | `weak_ptr<vector<Stream>>` | **共享容器**：该节点未设自有流时激活，弱引用**最近祖先**的自有容器（不参与所有权，避免循环引用与延长生命周期）。 |
| 两个容器互斥 | — | 节点有 `own_group` 即单独流输出（不看父）；否则走 `shared_group`（继承父）。 |

#### 2.3.2 `path_normalize`（调用路径规范化）

```cpp
static std::string path_normalize(const std::string& raw)
{
    //统一路径分隔符
    std::string path = raw;
    for (char& ch : path)
        if (ch == '\\') ch = '/';
    //项目根目录名锚点（以其为界剥离出项目内相对路径）
    static const std::string anchor = "白银纪元/";
    const size_t anchor_pos = path.rfind(anchor);
    //若锚点存在则剥离锚点及其之前的部分
    if (anchor_pos != std::string::npos)
        path.erase(0, anchor_pos + anchor.size());
    //剥离开头的前导分隔符与 './' 片段
    for (;;)
    {
        if (!path.empty() && path.front() == '/') { path.erase(0, 1); continue; }
        if (path.compare(0, 2, "./") == 0)        { path.erase(0, 2); continue; }
        break;
    }
    //末尾补 '/'，使目录节点与文件节点共用同一套路径段前缀比较
    if (!path.empty() && path.back() != '/')
        path.push_back('/');
    return path;
}
```

| 步骤 | 作用 |
| --- | --- |
| ① 分隔符统一 | `\` → `/`（`__FILE__` 在 MSVC 下可为反斜杠）。 |
| ② 锚点剥离 | 以**项目根目录名 `白银纪元/`** 为锚（`rfind` 取最后一次出现），把绝对路径剥成**项目内相对路径**，保证同一文件在不同机器/不同盘符下路径键一致。**锚点不存在时原样使用**（如测试层独立构建路径）。 |
| ③ 去前导 | 去掉前导 `/` 与 `./`（防相对/绝对混用产生不同键）。 |
| ④ 末尾补 `/` | 使文件节点键与目录节点键形式一致，前缀比较落在**路径段边界**（避免 `abc` 误配 `abcd`）。 |

#### 2.3.3 `prefix_common`（路径段对齐的公共前缀）

```cpp
static size_t prefix_common(const std::string& left, const std::string& right)
{
    const size_t limit = left.size() < right.size() ? left.size() : right.size();
    size_t length = 0;
    while (length < limit && left[length] == right[length]) ++length;
    //回退到最近的 '/' 边界，保证公共部分以路径段为单位
    while (length > 0 && left[length - 1] != '/') --length;
    return length;
}
```

| 项 | 说明 |
| --- | --- |
| 语义 | 返回两键按**完整路径段**计的公共前缀长度（末尾必定落在 `/` 后）。 |
| 边界回退 | 逐字符求公共长度后，回退到最近的 `/`，避免把半个路径段当公共部分。 |
| 返回 0 | 无公共前缀（两路径各自独立成为根的子节点）。 |

#### 2.3.4 `node_ensure`（节点查找或创建——建树核心）

```cpp
static Stream_Node& node_ensure(const std::string& key)
{
    //空键即根节点
    if (key.empty())
        return node_root;
    Stream_Node* node = &node_root;
    std::string rest = key;
    for (;;)
    {
        //在当前子链表中寻找与剩余键存在公共前缀的子节点
        std::list<Stream_Node>::iterator match = node->children.end();
        for (auto it = node->children.begin(); it != node->children.end(); ++it)
            if (prefix_common(it->key, rest) > 0) { match = it; break; }
        //若不存在公共前缀的子节点则以剩余键新建
        if (match == node->children.end())
        {
            node->children.push_back(Stream_Node{});
            Stream_Node& created = node->children.back();
            created.key = rest;
            created.parent = node;
            return created;
        }
        const size_t length = prefix_common(match->key, rest);
        //若子节点键完整包含于剩余键则继续向下定位
        if (length == match->key.size())
        {
            rest.erase(0, length);
            if (rest.empty()) return *match;
            node = &(*match);
            continue;
        }
        //公共前缀短于子节点键：拆出中间节点承载公共前缀
        node->children.push_back(Stream_Node{});
        Stream_Node& middle = node->children.back();
        middle.key = match->key.substr(0, length);
        middle.parent = node;
        //把原子节点移入中间节点子链表（splice 不搬移元素，子节点地址与指针保持有效）
        middle.children.splice(middle.children.end(), node->children, match);
        middle.children.back().key.erase(0, length);
        middle.children.back().parent = &middle;
        rest.erase(0, length);
        if (rest.empty()) return middle;
        middle.children.push_back(Stream_Node{});
        Stream_Node& created = middle.children.back();
        created.key = rest;
        created.parent = &middle;
        return created;
    }
}
```

| 分支 | 触发条件 | 行为 |
| --- | --- | --- |
| 空键 | `key.empty()` | 直接返回根节点。 |
| 无公共前缀子节点 | 子链表中无 `prefix_common > 0` 的节点 | 以剩余键**新建**子节点（各自单独成为父节点的子节点）。 |
| 子节点键完整包含 | `length == match->key.size()` | 去掉公共前缀下降；剩余清空即命中；否则继续向下。 |
| **拆分中间节点** | 公共前缀短于子节点键 | 新建**中间节点**承载公共前缀，`splice` 把原子节点整体移入中间节点之下，再把原子节点键**截短**（去掉公共前缀）；随后按剩余键新建目标子节点。 |

**关键性质**：链表树**不逐级建目录节点**——节点粒度就是「已出现路径的公共前缀」。因此 `A/B/c.hpp` 与 `A/B/d.hpp` 共享的节点键是 `A/B/`（一个公共前缀节点），而不是 `A/` 与 `A/B/` 两级。这也是用例「目录节点后绑定按公共前缀归并」验证的行为。

#### 2.3.5 `node_find`（节点查找，不新建）

```cpp
static Stream_Node* node_find(const std::string& key)
{
    if (key.empty()) return &node_root;
    Stream_Node* node = &node_root;
    std::string rest = key;
    for (;;)
    {
        Stream_Node* match = nullptr;
        for (Stream_Node& child : node->children)
            if (prefix_common(child.key, rest) == child.key.size()) { match = &child; break; }
        if (!match) return nullptr;
        rest.erase(0, match->key.size());
        if (rest.empty()) return match;
        node = match;
    }
}
```

| 项 | 说明 |
| --- | --- |
| 用途 | `stream_clear` 用；只沿既有树定位，**不新建节点**。 |
| 失败 | 返回 `nullptr`（节点不存在）。 |

#### 2.3.6 控制台流与兜底容器

```cpp
static Stream stream_console()
{
    //控制台流仅需构造一次，以函数局部静态持有
    static Stream stream(&std::cout, [](std::ostream*) {});
    return stream;
}
static Stream_Group group_console()
{
    static Stream_Group group = group_create_console();
    return group;
}
static Stream_Group group_create_console()
{
    Stream_Group group(new(std::nothrow) std::vector<Stream>());
    if (!group) return group;
    group->push_back(stream_console());
    return group;
}
```

| 项 | 说明 |
| --- | --- |
| 空删除器 | `std::cout` 是栈/静态对象，**绝不能 delete**；用空 lambda 删除器包装为非拥有 `shared_ptr`。 |
| 兜底容器 | 整条父链都未设文件流时，`group_resolve` 返回该容器（仅含控制台流），保证日志链路永远可用。 |

#### 2.3.7 `group_append`（向节点自有容器追加流）

```cpp
static bool group_append(Stream_Node& node, const Stream& stream)
{
    //记录节点此前是否已有自有容器
    const bool owned = static_cast<bool>(node.own_group);
    //若节点自有容器尚未创建则创建
    if (!node.own_group)
        node.own_group = Stream_Group(new(std::nothrow) std::vector<Stream>());
    //若容器不存在则追加失败
    if (!node.own_group) return false;
    node.own_group->push_back(stream);
    //若节点此前无自有容器（本次由共享父流转为单独流输出）
    if (!owned)
        group_shared_reset(node);
    return true;
}
```

| 项 | 说明 |
| --- | --- |
| 追加语义 | 同一节点重复绑定即**追加**（多流全量输出）。 |
| 首次由「共享」转「自有」 | 若节点此前靠父流（无 `own_group`），本次新建容器后必须**刷新后代共享缓存**（`group_shared_reset`），否则后代仍拿着旧的 `weak_ptr` 指向祖父容器。 |
| 分配失败 | `new(nothrow)` 返回空 → 返回 `false`。 |

#### 2.3.8 `group_shared_reset`（后代共享缓存刷新）

```cpp
static void group_shared_reset(Stream_Node& node)
{
    //逐个处理子节点
    for (Stream_Node& child : node.children)
    {
        //清除子节点共享容器缓存
        child.shared_group.reset();
        //递归处理更下游的节点
        group_shared_reset(child);
    }
}
```

| 项 | 说明 |
| --- | --- |
| 用途 | 节点新设自有容器时，其后代须「改取本节点容器」；逐层清掉 `shared_group` 缓存，使下次输出按父链重新解析。 |
| 复杂度 | 与子树规模线性。绑定操作非高频，可接受。 |

#### 2.3.9 `group_resolve`（生效容器解析——分流核心）

```cpp
static Stream_Group group_resolve(Stream_Node& node)
{
    //若节点已设置自有输出流则单独流输出
    if (node.own_group) return node.own_group;
    //若共享容器缓存有效则共享父节点输出流
    if (Stream_Group shared = node.shared_group.lock()) return shared;
    //若存在父节点则向上取用并刷新共享容器缓存
    if (node.parent)
    {
        Stream_Group parent_group = group_resolve(*node.parent);
        node.shared_group = parent_group;
        return parent_group;
    }
    //根部兜底：未设置任何文件流时默认使用控制台
    return group_console();
}
```

| 优先序 | 条件 | 结果 |
| --- | --- | --- |
| ① 自有优先 | `own_group` 非空 | 返回自有容器（**单独流输出**，与父流完全无关——父流不生效） |
| ② 弱引用共享 | `shared_group.lock()` 成功 | 返回缓存的父容器（**共享父节点输出流**） |
| ③ 沿父链上溯 | 有父节点 | 递归解析父节点容器并写回缓存 |
| ④ 根部兜底 | 无父节点 | 返回 `group_console()`（控制台） |

**注意「最近祖先优先」**：若目录节点自己设了流，则它成为其后代解析到的最早自有容器，**根节点的流不会生效**（父链在第一个自有容器处即返回）。

#### 2.3.10 `output`（树路由输出）

```cpp
static void output(const char* file_name, const std::string& text, const std::string& type)
{
    //规范化调用处路径键
    const std::string key = path_normalize(file_name);
    //构造消息行
    const std::string msg = std::format("[{}]{}", type, text);
    //整树加锁：节点定位与多流写出串行化
    std::lock_guard<std::mutex> lock(tree_mtx);
    //定位或创建调用处节点
    Stream_Node& node = node_ensure(key);
    //取节点生效输出流容器
    Stream_Group group = group_resolve(node);
    //若容器不可用则直接写出到控制台
    if (!group || group->empty())
    {
        std::cout << msg << std::endl;
        return;
    }
    //逐个流输出（容器内所有流均输出日志信息）
    for (const Stream& stream : *group)
        //跳过空流
        if (stream) *stream << msg << std::endl;
}
```

| 项 | 说明 |
| --- | --- |
| 路由键 | 调用处 `file_name` 经 `path_normalize`（**首次调用某文件即自动建节点**）。 |
| 消息格式 | `[{}]{}`——**级别与正文之间无空格**。 |
| 多流输出 | 遍历容器，**所有流都写**（同一节点多流全量）。 |
| 空容器兜底 | `group` 为空或容器内无元素时直接写 `std::cout`（极端兜底，正常路径由 `group_console()` 保证非空）。 |
| 加锁范围 | 从 `node_ensure` 到写出结束全程持锁 → **输出行不会交错**（见 §4.6 多线程）。 |
| `std::endl` | 每条日志换行 + flush。 |

### 3.3 树结构示意（公共前缀合并）

```
                        [根 ""]
                        /     \
             [ "引擎层/src/tools/" ]      [ "测试层/src/单元测试/工具/日志系统测试.cpp/" ]
                    /         \
   [ "Logging/日志系统.h/" ]  [ "Engine_Env/引擎环境.h/" ]
```

- 每个节点下方画的曲线代表「该节点的子节点链表」中**存在**的路径段。
- 同一路径只会有一个节点：第二次出现「与既有节点有公共前缀」的路径时，`node_ensure` 会**复用**该公共前缀节点（必要时拆分中间节点），而不是新建重复节点。
- 叶子节点是文件（键以文件名结尾 + `/`），中间节点等价于目录前缀（键以 `/` 结尾）。

### 3.4 一次日志输出的完整数据流

```
Log::info("字段 {} 类型不匹配", field)

        ├─ path_normalize(file_name)              → 路径键（相对项目根、末尾补 '/'）

        ├─ lock(tree_mtx)                          → 多线程保护

        ├─ group_resolve(node)
        │     ├─ own_group 非空        → 返回自有容器（单独流）
        │     ├─ shared_group.lock()   → 共享父容器
        │     ├─ parent 存在           → 递归上溯 + 写缓存
        │     └─ 无父（根）            → group_console()（控制台）
        └─ for (stream : *group) *stream << msg << std::endl
```

## 4. 模块设计/实现细节

### 4.1 关键设计决策：为何用 `Format<Args...>` 包装类型

**问题**：需要「在不改调用点的前提下，自动取得调用处文件路径」。C++20 的惯用法是末尾加 `std::source_location loc = std::source_location::current()`。

**MSVC 实测结论（本版次阶段一专门验证）**：把 `std::source_location` 放在**变参包之后**的签名——

```cpp
template<typename... Args>
static void info(std::format_string<Args...> fmt, Args&&... args,
                 std::source_location loc = std::source_location::current());   // ✗ MSVC 拒绝
```

会失败：非末位变参包 `Args&&...` 是**非推导上下文**，`Args` 推导为空 → 所有实参都被拿去匹配 `loc`（`C2664/C2672`）。同理，自定义「尾置默认参数结构体」`Call_Site` 方案也不可行。

**采用的方案**：把格式串包一层 `Format<Args...>`，其**构造函数的默认参数**承担 `source_location::current()`：

```cpp
engine::Log::info("数值={}", 42);
//  "数值={}" 先隐式转换为 Format<int>，转换点在调用处，
//  故构造函数默认参数 source_location::current() 返回调用处（而非头文件内部）
```

签名写作 `Format<std::type_identity_t<Args>...>` 以**冻结**该形参的推导（`std::type_identity_t` 使其成为非推导上下文），`Args` 仅由末位变参包推导；`Format::pattern` 仍是 `std::format_string<Args...>`，**编译期占位符校验得以保留**。

实测验证：原型程序的 `file:line` 输出确为调用点行（而非头文件内部），中文路径 `__FILE__` 字节正确（`e4 b8 b4`＝「临」）。

### 4.2 回调处路径基准：剥离到项目根

- 绝对路径在不同机器/盘符/构建目录下不同，若直接作键则同一文件会分裂成多个节点。
- 故 `path_normalize` 以**项目根目录名 `白银纪元/`** 为锚（`rfind`，取最后一次出现，兼容嵌套同名目录）剥离为**项目内相对路径**。
- **锚点不存在时原样使用**：如测试层独立构建时 `__FILE__` 可能是相对路径或其它前缀，此时保留原样（用户定夺口径 ⑦.1）。
- 副作用：若项目目录被改名，路径键会随 `__FILE__` 变化——这是可接受的（键只要求「同进程内一致」）。

### 4.3 两个容器的「互斥存储」与 `weak_ptr` 语义

- 节点**同一时刻只有一种生效来源**：有 `own_group` → 单独流；无 → 走 `shared_group`（继承）。
- `shared_group` 用 **`weak_ptr`** 而非 `shared_ptr`：后代**不参与祖先容器的所有权**，从而：
  1. 不延长祖先容器生命周期（祖先 `stream_clear` 或节点销毁后自动失效）；
  2. **不产生循环引用**（若用 `shared_ptr`，父持有子链表、子又持有父容器，将互相捆死）。
- `weak_ptr::lock()` 失败即视为「缓存失效」，`group_resolve` 会顺父链重新解析并写回——因此**祖先改流/清流后，后代无需主动改缓存**，下次输出自动生效。
- `group_shared_reset` 是「祖先**新设**自有流」时的**主动失效**：因为此时 `weak_ptr` 仍可能指向**祖父**容器（旧目标）且尚未失效，必须显式清掉，否则后代仍输出到祖父流。

### 4.4 目录继承与「最近祖先优先」

- 绑定目录路径（如 `测试层/src/单元测试/工具`）后，规范化键为 `测试层/src/单元测试/工具/`；该目录下的文件调用处路径以它开头，`node_ensure` 会把文件节点挂到该目录节点（或以其为父）之下。
- 文件节点自身无 `own_group` → `group_resolve` 沿父链找到目录节点的 `own_group` → **继承**。
- **若中间某节点自己设了流**，则它在父链上更近，成为解析到的第一个自有容器 → 「最近祖先优先」，更远的根流不生效。

### 4.5 多流全量输出

- 节点容器的类型是 `std::vector<Stream>`，`group_append` 只做 `push_back`。
- `output` 遍历容器**逐流写出**，任一节点的所有流都收到同一条日志。
- 重复 `stream_bind` 同一路径即叠加；测试用例「同节点多流全量输出」断言两个文件都收到同一条日志。

### 4.6 多线程保护

- **粒度**：单把 `inline static std::mutex tree_mtx`，覆盖 `stream_bind`（两重载）、`stream_clear`、`output` 的全部树操作。
- **目的**：既保护链表树的并发读写（建节点/拆节点/写容器），也保证 `output` 的「定位 + 逐流写出」串行化，**同一容器内的多线程日志不会交错混行**。
- 测试用例「多线程并发输出不交错」：4 线程 × 100 条写内存流，断言总行数 400 且每行均以 `[INFO]并发标记 ` 完整开头。
- **无权限保护机制**（按任务要求）：任何调用方都可对任意路径设流/清流，不做权限校验；**只有多线程保护**。
- 性能说明：全局单锁意味着所有日志串行；当前引擎日志量小，可接受。

### 4.8 易踩坑点汇总

1. **`Format` 必须 public**：否则调用方无法完成隐式转换而编译失败。
2. **不能改成 `Format<Args...>` 形参**：必须写 `Format<std::type_identity_t<Args>...>`，否则推导失败。
3. **路径键末尾恒有 `/`**：手动构造路径键时须遵守（`path_normalize` 已处理）。
4. **锚点依赖目录名 `白银纪元`**：项目改名会导致路径键整体变化。
5. **`stream_clear` 不删节点**：只清流；节点留在树上（避免 `list` 元素地址失效）。
6. **清空根节点返回 `true`**：根节点恒存在。
7. **`stream_bind` 的文件名是相对当前工作目录**：进程 cwd 变化会影响落盘位置。
8. **`std::ofstream` 默认 trunc**：绑定时即打开并**截断**同名文件（非追加）。
9. **一个 `stream_bind` 一个流**：要「目录 + 文件」都输出须分别绑定；节点内是追加语义。
10. **无权限保护**：任何调用方都能改任意节点流（按设计要求）。
11. **`output` 全程持锁**：若某流写出极慢会阻塞全部日志。
12. **`std::endl` 每条刷新**：高频日志有 flush 开销。
13. **`[FATAL]`/`[ERROR]` 绑定失败提示格式特殊**：`<<` 裸写、无空格、`\n`。
14. **不要 delete cout**：控制台流是空删除器包装。
15. **format 异常不捕获**：`std::format_error` 直接传播。

## 5. 模块运行链路

### 5.1 典型调用时序（配置加载 + 分流场景）

```
[进程启动]
  ├─（可选）Log::stream_bind("引擎层/src/tools/Logging", "engine_tools.log");
  │       └─ 目录节点绑定 → 该目录下所有源文件的日志落 engine_tools.log
  ├─（可选）Log::stream_bind("引擎层/src/core/config", "engine_config.log");
  │
  ├─ Config_Loader 构造 → loader.act()
  │     ├─ content_scan 扫描失败？
  │     │     └─ Log::info("Config_Loader::未检测到任何路由文件")
  │     │           ├─ Format 构造：捕获 file_name()＝引擎层/src/core/config/Config_Loader/core/配置加载器.cpp
  │     │           ├─ output → path_normalize → node_ensure（自动建节点）
  │     │           ├─ group_resolve：无自有流 → 父链 → 命中 "引擎层/src/core/config/" 节点自有流
  │     │           └─ *stream << "[INFO]Config_Loader::未检测到任何路由文件" << endl
  │     └─ ... 后续日志同路径 ...
  │
  └─ 主循环运行（未绑流的模块默认输出控制台）
```

### 5.2 状态机：单节点输出来源切换

```
        stream_bind(path, "a.log")
  [继承父流/控制台] ───────────────────► [自有流 a.log]  （own_group 激活，shared_group 不用）
        ▲                                        │
        │  stream_clear(path)                    │ stream_bind(path, "b.log")
        └────────────────────────────────────────┘   （追加 → a.log 与 b.log 同时输出）
```

### 5.3 错误路径链路

```
stream_bind(path, file_name)
  ├─ new(nothrow) ofstream 失败（内存不足）
  │     └─ *cout << "[FATAL]内存不足\n已切换至控制台输出\n" << endl ; return false（不绑流）
  └─ is_open() 失败（目录不存在/无权限）
        └─ *cout << "[ERROR]文件打开失败\n已切换至控制台输出\n" << endl ; return false（不绑流）

Log::xxx(...)
  └─ std::format 抛 format_error
        └─ 异常传播（不回落、不捕获）
```

## 6. 重开发要点速查

| 步骤 | 必须做到 |
| --- | --- |
| 1 | 类名 `Log` 位于 `namespace engine`；public `using Stream = std::shared_ptr<std::ostream>` |
| 2 | public 嵌套 `template<typename... Args> class Format`，`consteval` 构造，`std::source_location place = std::source_location::current()` 默认参数；成员 `std::format_string<Args...> pattern` + `std::source_location site` |
| 3 | 四个日志方法签名 `template<typename... Args> static void xxx(Format<std::type_identity_t<Args>...> fmt, Args&&... args)`，函数体只调 `output(fmt.site.file_name(), std::format(...), "级别")` |
| 4 | `stream_bind(path, file_name)`：加锁 → `node_ensure(path_normalize(path))` → 空文件名绑控制台流；`new(nothrow) ofstream` 分配/打开失败各提示 `[FATAL]`/`[ERROR]` 并返回 false；成功 `group_append` |
| 5 | `stream_bind(path, stream)`：空流返回 false；加锁 → `group_append(node_ensure(...), stream)` |
| 6 | `stream_clear(path)`：加锁 → `node_find(path_normalize(path))`；不存在返回 false；否则 `own_group.reset()` + `shared_group.reset()` |
| 7 | `Stream_Node{key, parent, children(std::list), own_group(shared_ptr<vector<Stream>>), shared_group(weak_ptr<vector<Stream>>)}` |
| 8 | `path_normalize`：`\`→`/`；`rfind("白银纪元/")` 剥离；去前导 `/` 与 `./`；末尾补 `/` |
| 9 | `prefix_common`：逐字符公共长度后回退到最近 `/` 边界 |
| 10 | `node_ensure`：空键返回根；子链表找公共前缀；无则新建；子节点键被完整包含则下降；否则拆中间节点（`splice` 迁元素，保证地址稳定） |
| 11 | `node_find`：同构但只找不建，失败返回 `nullptr` |
| 12 | `group_resolve`：own → weak.lock() → 父递归 → `group_console()` |
| 13 | `group_append`：首次创建自有容器时调 `group_shared_reset` 刷新后代缓存 |
| 14 | `output`：`path_normalize` → 组 `[级别]正文` → 加锁 → `node_ensure` → `group_resolve` → 逐流 `<< msg << endl` |
| 15 | 静态成员 `inline static Stream_Node node_root{}` 与 `inline static std::mutex tree_mtx{}` |
| 16 | 文件尾 `namespace std` 内显式特化 `formatter<std::error_code>`（parse 返回 begin，format 输出 `[value] message`） |
| 17 | include 仅 `common/前置头文件包含.h`；header-only 无 cpp |
| 18 | 保留多线程单锁保护与「无权限保护」语义；保留 `ofstream` 默认 trunc 与 `endl` 刷新 |
