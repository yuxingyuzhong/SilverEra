## 1. 模块功能

### 1.1 模块是什么

「日志系统」是引擎层 `src/tools/Logging/` 目录下的一个 **header-only 模块**，由一个对外总头（运行包）与四个类头组成，为整个引擎提供统一、轻量、按调用来源分流的日志输出能力：

| 文件 | 角色 | 对外形态 |
| --- | --- | --- |
| `日志系统运行包.h` | 模块**对外总头**：预编译头 + `#include "Log/日志系统.h"` + `inline Log logger;` | 一行包含即得完整日志系统与全局 `logger` |
| `Log/日志系统.h` | **门面类 `Log`**：调用处捕获、消息行合成、对外转发 | `logger.info/warn/error/debug` |
| `Stream_Tree/流节点树.h` | **分流与存储核心 `Stream_Tree`**：按调用处路径公共前缀建链表树、节点定位、生效容器解析、整树落盘、日志行路由 | `log.stream_bind/stream_clear/stream_flush`（由 `Log` 转发） |
| `Stream_Sink/输出目标.h` | **线程安全输出目标 `Stream_Sink`**：内部互斥 + 内部缓冲，达阈值才落盘 | `write` / `flush`（内部使用） |
| `Node_Cache/节点缓存.h` | **调用点缓存 `Node_Cache<Node>`**：调用处文件指针 → 节点指针 | `cache_fetch` / `cache_store`（内部使用） |

has-a 关系（均为**值成员**，非指针/引用）：

```
Log ──has-a──► Stream_Tree ──has-a──► Node_Cache<Stream_Node>
                                └──aggregate(shared_ptr 容器)──► Stream_Sink
```

核心能力一览：

| 能力 | 入口 | 说明 |
| --- | --- | --- |
| 四级别日志 | `logger.info` / `logger.warn` / `logger.error` / `logger.debug` | 成员模板函数（**实例语义**），`std::format` 风格格式化（`{}` 占位符 + 类型安全参数包）；签名中不出现任何流参数 |
| 调用处自动捕获 | `Log::Format<Args...>` 包装类型的构造函数默认参数 `std::source_location place = std::source_location::current()` | 在**调用点**求值，自动取得调用处文件路径（调用方无需显式传参） |
| 消息级别前缀 | `Log::output` 合成 `[TYPE]正文\n` | 输出形如 `[INFO]正文`，行尾**恒为 `\n`**（不做强制刷新） |
| 链表树路由 | `Stream_Tree` 私有 `Stream_Node` 树 + `node_ensure` / `node_locate` / `group_resolve` | 按调用处路径的**公共前缀**建父子链表，节点粒度即路径公共前缀本身（不逐级建目录节点） |
| 流绑定 | `stream_bind(path, file_name)` / `stream_bind(path, stream)` | 把「路径前缀节点」绑定到文件输出目标或外部流；目录前缀节点绑定后其后代继承 |
| 流清空 | `stream_clear(path)` | 清除某路径节点的自有流，该节点及其后代回落共享父节点输出流 |
| 整树落盘 | `stream_flush()` | 收集整棵树全部输出目标（含控制台）后逐个 flush（**本版次新增**，阈值缓冲的必要配套） |
| 多流全量输出 | 节点自有容器 `std::vector<Sink>` | 同一节点可绑多个流，打印时**全部流都写** |
| 目录继承（弱引用共享） | 节点 `shared_group`（`weak_ptr`）+ `shared_epoch` | 子节点未设自有流时，按版本号校验后共享最近祖先的自有容器 |
| 单独流输出（强引用持有） | 节点 `own_group`（`shared_ptr`） | 子节点设了自有流时，激活 shared_ptr 容器单独输出，与父流互斥 |
| 无流兜底 | `group_console()` | 整条父链都未设文件流时，默认写 `std::cout`（以空删除器包装的非拥有流） |
| 调用点缓存 | `Node_Cache<Stream_Node>` + `node_locate` | 键取 `std::source_location::file_name()` 指针，命中即 **O(1) 直取节点、零路径规范化** |
| 并发保护 | 节点级锁 + 树结构锁 + 缓存锁（严格单向锁序） | **I/O 全程在锁外**（见 §4.3） |
| 错误码格式化 | `std::formatter<std::error_code>`（已迁至 `src/tools/Detail/标准库format特化.h`） | 使 `logger.info("{}", ec)` 可直接输出 `[值] 消息` |

### 1.2 模块解决什么问题

- **日志输出分散问题**：引擎各模块（Data_Validator、Config_Loader、Engine_Env、Number_Allocator、Collision_Region/Proxy 等）都需要输出运行信息。若各自 `std::cout << ...`，格式不统一、目标不可控。
- **格式化安全性问题**：`std::format` 提供编译期格式串校验（`Format` 内部保留 `std::format_string<Args...>`），杜绝格式化漏洞与类型误配。
- **日志目标全局化问题（63a51b6 引入）**：旧实现用「单一活跃文件名（`active_file_stream`）+ 哈希表 `streams` 缓存流」，改输出目标必须显式调用 `stream_set`，且全局唯一活跃流无法按来源区分输出。63a51b6 起改为：**日志方法只认调用处路径**，路径 → 链表树节点 → 生效流容器，自动分流。
- **单体类过载问题（本版次核心动机）**：63a51b6 的单头文件把「门面 / 树 / 输出目标 / 缓存」四类职责挤在一个类里（`Log` 既是门面又是树又是流管理）。本版次按「职责单一」拆为四个类，`Log` 退化为纯门面（转发），树与流设施各自独立成文件，便于单独演进与复用；对外以**运行包**一键获取，并保留全局实例 `logger`。
- **调用处自动定位问题**：用 `std::source_location` 默认参数在调用点自动捕获 `file_name()`，把「谁在打日志」变成路由键，**无需调用方改动任何一行业务代码**（除本版次由 `Log::` 静态调用改为 `logger.` 实例调用这一处全局文本替换）。
- **性能问题（63a51b6 引入、本版次保留）**：`std::endl` 每条强制刷新、每次输出都做完整路径规范化、整树一把锁、`group_shared_reset` 子树遍历，均被替换——统一 `"\n"`、调用点缓存、节点级锁、`tree_epoch` 版本号。
- **错误码可读性问题**：`std::error_code` 在 C++20 标准库无 `std::formatter` 特化，`std::format("{}", ec)` 编译失败。本版次起该特化集中在 `Detail/标准库format特化.h`（同批还补齐 `std::error_condition` 与 `std::filesystem::path`），日志门面改为包含该头，语义不变。

### 1.3 模块服务谁

- **服务方（被调用方）**：引擎层全部需要日志的模块——Data_Validator（`Detail/文件路径可用性校验.h`）、Config_Loader、Engine_Env、Number_Allocator、Collision_Region / Collision_Proxy / Collider、Mesh_Loader、Event_Terminal / Event_Broker 等；系统层业务模块（Entity/Prop/Effect 系列）经 `logger.` 直接调用。
- **调用方画像**：任何 `#include "src/tools/Logging/日志系统运行包.h"` 的翻译单元，直接 `logger.xxx(...)` 调用（`logger` 为运行包内 `inline Log logger;`），无需实例化、无需设置流（未设置即走控制台）。
- **不服务**：不做日志分级过滤（无「仅输出 ERROR 以上」）、无时间戳、无异步落盘、无自动滚动文件；级别差异仅前缀不同。

### 1.4 版本演变（重要背景）

- **2d5f704 及更早（旧实现）**：`active_file_stream`（单一活跃文件名字符串）+ `streams`（哈希流缓存）+ **非静态** `stream_set` + 私有 `stream_charge` / `log_build`。日志方法读全局活跃流，无法按来源分流。

## 2. 模块提供接口

### 2.1 `Log` 类全貌（门面，`Log/日志系统.h`，98 行）

```cpp
namespace engine
{
    //日志系统（门面：日志方法与流设置接口；流的分流与存储交由流节点链表树）
    class Log
    {
    public:
        //输出流别名（对外绑定接口沿用共享输出流形态）
        using Stream = Log_Stream;
        //日志格式串（携带调用处信息，并承担占位符与实参的编译期校验）
        template<typename... Args>
        class Format
        {
        public:
            //从字面量构造（默认参数在调用点求值，从而自动捕获调用处文件路径）
            template<typename Text>
            consteval Format(const Text& text, std::source_location place = std::source_location::current())
                : pattern(text), site(place){}
            //格式串本体（编译期校验占位符与实参匹配）
            std::format_string<Args...> pattern;
            //调用处信息
            std::source_location site;
        };
    public:
        template<typename... Args> void info (Format<std::type_identity_t<Args>...> fmt, Args&&... args);
        template<typename... Args> void warn (Format<std::type_identity_t<Args>...> fmt, Args&&... args);
        template<typename... Args> void error(Format<std::type_identity_t<Args>...> fmt, Args&&... args);
        template<typename... Args> void debug(Format<std::type_identity_t<Args>...> fmt, Args&&... args);

        bool stream_bind(const std::string& path, const std::string& file_name);
        bool stream_bind(const std::string& path, const Stream& stream);
        bool stream_clear(const std::string& path);
        void stream_flush();
    private:
        //日志行输出（合成「类型前缀 + 正文 + 换行」的消息行后按调用处路径路由）
        void output(const char* file_name, const char* type, const std::string& text);
        //流节点链表树（has-a：日志系统持有分流与存储设施）
        Stream_Tree stream_tree{};
    };
}
```

要点：

| 项 | 说明 |
| --- | --- |
| **实例语义** | 四个日志方法与四个流接口均为**非静态成员**（`Log` 已无任何静态成员），必须经实例调用；对外实例为运行包内的 `inline Log logger;`。这是本版次相对 63a51b6 的对外主要变化 |
| **`Log::Stream` 别名保留** | `using Stream = Log_Stream;`（`Log_Stream` 定义在 `Stream_Sink/输出目标.h`），故测试层 `engine::Log::Stream()` 无需改动 |
| **无静态调用** | 旧的 `Log::info(...)` 写法**不再可用**；全项目已替换为 `logger.info(...)`（`engine::Log::Stream` 这类嵌套类型引用不参与替换） |
| **转发** | 四个流接口一律 `return stream_tree.xxx(...)`，门面不持有任何树结构细节 |

### 2.2 `Format<Args...>`（调用处捕获载体，public 嵌套类）

```cpp
template<typename... Args>
class Format
{
public:
    template<typename Text>
    consteval Format(const Text& text, std::source_location place = std::source_location::current())
        : pattern(text), site(place) {}
    std::format_string<Args...> pattern;
    std::source_location site;
};
```

| 项 | 说明 |
| --- | --- |
| 存在意义 | **MSVC 下唯一可行的「变参包之后捕获调用处」手段**。直接在日志函数末尾追加 `std::source_location loc = std::source_location::current()`（置于变参包之后）会被 MSVC 拒绝：非末位变参包是**非推导上下文**，`Args` 推成空、实参被误配到 `source_location`（详见 §4.1）。改为「格式串先隐式转换为 `Format<Args...>`」，其构造函数默认参数即落在**调用点**（隐式转换点）求值，从而拿到正确的 `file_name()`。 |
| `consteval` 构造 | 强制编译期求值（配合格式串编译期校验）。 |
| `pattern` | `std::format_string<Args...>`，保留占位符与实参的**编译期匹配校验**。 |
| `site` | `std::source_location`，`file_name()` 即调用处所在**源文件路径**（`/utf-8` 下为 UTF-8 字节，实测中文路径字节正确）。 |
| 可见性 | **必须 public**：日志函数形参类型需被调用方可见才能完成隐式转换。 |
| 构造模板参数 `Text` | 允许任意字面量类型（`const char(&)[N]`），由 `std::format_string` 承担约束。 |

### 2.3 `info` / `warn` / `error` / `debug`（四个日志方法）

```cpp
template<typename... Args>
void info(Format<std::type_identity_t<Args>...> fmt, Args&&... args)
{
    //格式化正文并合成消息行交由链表树路由输出（方法不感知任何流设置）
    output(fmt.site.file_name(), "INFO", std::format(fmt.pattern, std::forward<Args>(args)...));
}
// warn / error / debug 同构，仅级别串不同
```

| 项 | 说明 |
| --- | --- |
| 关键签名技巧 | 形参写作 `Format<std::type_identity_t<Args>...> fmt`：`std::type_identity_t` 把该参数变成**非推导上下文**，于是 `Args` 只由**末位变参包** `Args&&... args` 推导；若写 `Format<Args...> fmt` 则会「无法从 `const char[N]` 推导 `Format<Args...>`」而失败（实测）。 |
| 流参数 | **签名中没有任何流参数**，函数体也不读任何全局流状态 → 实现「流输出设置对日志输出方法屏蔽」。 |
| 路由键 | `fmt.site.file_name()`——调用处源文件路径（未经规范化，规范化在 `Stream_Tree::node_locate` 内做且仅首次）。 |
| 行为 | `std::format` 生成正文 → `Log::output` 合成 `[级别]正文\n` → `stream_tree.stream_output(file_name, msg)`。 |
| 级别标签 | info→`[INFO]`、warn→`[WARN]`、error→`[ERROR]`、debug→`[DEBUG]`；**无级别过滤**。 |
| 调用写法 | `logger.info("{}", x)`（本版次已由 `Log::info` 全量替换为 `logger.info`）。 |
| 异常 | `std::format` 对运行期格式错误可能抛 `std::format_error`，未捕获，异常传播给调用方。 |

### 2.4 `stream_bind(path, file_name)`（转发：Stream_Tree 实现）

```cpp
bool stream_bind(const std::string& path, const std::string& file_name)
{
    //整树结构锁（建节点）
    std::lock_guard<std::mutex> lock(tree_mtx);
    //定位或创建路径节点
    Stream_Node& node = node_ensure(path_normalize(path));
    //若文件名为空则改为绑定控制台输出流
    if (file_name.empty())
    {
        //提示并回落控制台输出
        if (Sink console = sink_console())
            console->write("[FATAL]文件名为空\n已切换至控制台输出\n");
        return group_append(node, sink_console());
    }
    //分配文件输出流内存（禁用异常的分配形式）
    Log_Stream stream(new(std::nothrow) std::ofstream(file_name));
    //若内存分配失败
    if (!stream)
    {
        //提示并回落控制台输出
        if (Sink console = sink_console())
            console->write("[FATAL]内存不足\n已切换至控制台输出\n");
        return false;
    }
    //构造文件流指针
    std::shared_ptr<std::ofstream> file_stream = std::static_pointer_cast<std::ofstream>(stream);
    //若文件打开失败
    if (!file_stream->is_open())
    {
        //提示并回落控制台输出
        if (Sink console = sink_console())
            console->write("[ERROR]文件打开失败\n已切换至控制台输出\n");
        return false;
    }
    //以带缓冲的文件输出目标构造（禁用异常的分配形式）
    Sink sink(new(std::nothrow) Stream_Sink(stream, file_flush_size, true));
    //若输出目标分配失败
    if (!sink)
        return false;
    //把文件输出目标追加进节点自有容器
    return group_append(node, sink);
}
```

| 项 | 说明 |
| --- | --- |
| `path` | 目标路径（文件或目录均可）。经 `path_normalize`（转调 `detail::path_key_normalize`）规范化后作为树键；空串即**根节点**。 |
| `path` 语义 | 传**目录路径**时绑定的是「该目录前缀节点」，其后代文件调用处**继承**该流（见 §4.5）。 |
| `file_name` | 目标日志文件名（相对当前工作目录）。**空串提示 `[FATAL]文件名为空` 并绑定控制台流**。 |
| 返回值 | 成功 `true`；内存分配失败、文件打开失败、Sink 分配失败均 `false`（不绑流，仅向控制台提示）。 |
| 分配失败提示 | `[FATAL]内存不足\n已切换至控制台输出\n`（经控制台 Sink 的 `write`，非 `<<` 裸写）。 |
| 打开失败提示 | `[ERROR]文件打开失败\n已切换至控制台输出\n`。 |
| 输出目标构造 | `Stream_Sink(stream, file_flush_size /*4096*/, true /*落盘时刷新*/)`——文件目标按 4KB 阈值批量落盘。 |
| 多流叠加 | 对同一路径**重复调用**即向该节点自有容器**追加**输出目标（不会替换），全部都会输出。 |
| 线程安全 | 整树 `tree_mtx` 加锁；`group_append` 内部另持节点锁。 |

### 2.5 `stream_bind(path, stream)`（转发：绑定外部流）

```cpp
bool stream_bind(const std::string& path, const Log_Stream& stream)
{
    //若输出流为空则绑定失败
    if (!stream)
        return false;
    //整树结构锁（建节点）
    std::lock_guard<std::mutex> lock(tree_mtx);
    //以逐条落盘并刷新底层流的方式构造输出目标（保持外部流即时可读语义）
    Sink sink(new(std::nothrow) Stream_Sink(stream, 0, true));
    //若输出目标分配失败
    if (!sink)
        return false;
    //定位或创建路径节点并追加输出目标
    return group_append(node_ensure(path_normalize(path)), sink);
}
```

| 项 | 说明 |
| --- | --- |
| 用途 | 把**任意 `std::ostream`**（内存流 `std::ostringstream`、自定义流等）绑定到路径节点，便于测试与自定义输出后端。 |
| 空流 | `!stream` 直接返回 `false`（不建节点）。 |
| 输出目标构造 | `Stream_Sink(stream, 0 /*每次写出即落盘*/, true /*刷新底层流*/)`——保持外部流**逐条即时可读**语义（向后兼容）。 |
| 所有权 | `Stream_Sink::owner` 以 `shared_ptr` 共享所有权，外部流存活由引用计数保证（生命周期不短于 Sink）。 |

### 2.6 `stream_clear(path)`（转发：清空节点自有流）

```cpp
bool stream_clear(const std::string& path)
{
    //整树结构锁
    std::lock_guard<std::mutex> lock(tree_mtx);
    //按规范化键查找节点（不新建）
    Stream_Node* node = node_find(path_normalize(path));
    //若节点不存在则清空失败
    if (!node)
        return false;
    //清除节点自有容器与共享缓存
    {
        //持节点锁改写容器
        std::lock_guard<std::mutex> node_lock(node->node_mtx);
        //清除自有容器（转为共享父节点输出流）
        node->own_group.reset();
        //清除共享缓存（下次输出按父链重新解析）
        node->shared_group.reset();
        //清除缓存登记版本
        node->shared_epoch = 0;
    }
    //流设置变更，递增树版本号使既有共享缓存全部失效
    epoch_bump();
    return true;
}
```

| 项 | 说明 |
| --- | --- |
| 行为 | 把目标节点**自有容器释放**并清掉共享缓存，使该节点由「单独流输出」回落为「继承父节点流」。 |
| **不删除节点** | 只清流、不删节点（节点保留在树上，避免 `std::list` 迭代器/元素地址失效；节点生命周期与实例同长）。 |
| 返回值 | 节点存在 `true`；节点不存在（含从未建立）`false`。根节点（`path=""`）恒存在，故清空根节点返回 `true`。 |
| 版本号 | 清流后 `epoch_bump()`，使既有共享缓存自动过期（取代旧的 `group_shared_reset` 子树遍历）。 |
| 线程安全 | 整树 `tree_mtx` + 节点锁。 |

### 2.7 `stream_flush()`（转发：整树落盘，本版次新增）

```cpp
void stream_flush()
{
    //先在结构锁内收集全部输出目标（不在锁内做 I/O）
    std::vector<Sink> sinks;
    {
        //整树结构锁
        std::lock_guard<std::mutex> lock(tree_mtx);
        //递归收集整棵树的自有输出目标
        group_collect(node_root, sinks);
        //并入控制台输出目标
        if (Sink console = sink_console())
            sinks.emplace_back(console);
    }
    //逐个落盘（此时不持任何树锁，仅由各输出目标自锁）
    for (const Sink& sink : sinks)
    {
        //跳过空输出目标
        if (sink)
            sink->flush();
    }
}
```

| 项 | 说明 |
| --- | --- |
| 语义 | 把整棵树内所有输出目标的缓冲内容写出并刷新（含控制台）。 |
| 锁策略 | **锁内收集、锁外 I/O**：`group_collect` 递归整树（每级持节点锁、即取即放），释放 `tree_mtx` 后逐个 `flush()`。 |
| 命名 | 沿用既有 `stream_*` 族（动词后置）。 |
| 必要性 | 文件输出目标按 4KB 阈值落盘，**写后立即读文件必须调用本接口**（测试层 `log_read()` 已统一补 flush）；进程正常退出时由 `Stream_Sink` 析构落盘。 |

### 2.8 私有接口（`Stream_Tree` 内部机制）

#### 2.8.1 数据结构

```cpp
//输出目标别名（容器实际存储的输出目标）
using Sink = std::shared_ptr<Stream_Sink>;
//输出目标容器别名（容器可存储多个输出目标，打印日志时全部输出）
using Sink_Group = std::shared_ptr<std::vector<Sink>>;
//输出目标容器弱引用别名（共享父节点输出流时使用，不持有容器）
using Sink_Group_Weak = std::weak_ptr<std::vector<Sink>>;

//流节点（链表树节点）
struct Stream_Node
{
    //节点路径键（规范化路径，恒以 '/' 结尾，保证前缀比较落在路径段边界）
    std::string key{};
    //父节点（链表 splice 不搬移元素，故元素地址稳定、指针始终有效）
    Stream_Node* parent = nullptr;
    //子节点链表
    std::list<Stream_Node> children{};
    //自有输出流容器（节点被单独设置输出流时激活）
    Sink_Group own_group{};
    //共享输出流容器（节点未设置单独输出流时激活，弱引用最近祖先的自有容器）
    Sink_Group_Weak shared_group{};
    //共享容器的登记版本（与树版本号一致时该缓存才可信）
    uint64_t shared_epoch = 0;
    //节点互斥锁（保护本节点的容器、共享缓存与父指针）
    std::mutex node_mtx{};
};
```

| 成员 | 说明 |
| --- | --- |
| `key` | 节点路径键。**恒以 `/` 结尾**（文件路径规范化后末尾补 `/`），使文件节点与目录节点共用同一套「路径段前缀」比较；节点键是**相对于父节点的剩余路径段**（不是全路径），故同一路径只有一个节点。 |
| `parent` | 父指针。用 `std::list` 存子节点 + `splice` 迁元素，**元素地址稳定**，指针永不失效（这是选 `std::list` 而非 `vector` 的根本原因）。 |
| `children` | 子节点链表。`Stream_Node` 含 `std::mutex` 故**不可搬移**，全部新建点用 `emplace_back()`（不用 `push_back(Stream_Node{})`）。 |
| `own_group` | **自有容器**（元素为 `Sink`）：该节点被设过流时激活；容器内所有目标均输出（多流全量）。 |
| `shared_group` | **共享容器**：该节点未设自有流时激活，弱引用**最近祖先**的自有容器（不参与所有权，避免循环引用）。 |
| `shared_epoch` | 共享容器的登记版本号；仅当等于解析开始时的 `tree_epoch` 才可信。 |
| `node_mtx` | 节点级互斥锁：保护 `own_group` / `shared_group` / `shared_epoch` / `parent`。 |

`Stream_Tree` 成员区（均在实例上，非 static）：

| 成员 | 说明 |
| --- | --- |
| `node_cache` | `Node_Cache<Stream_Node>`，调用处文件指针 → 节点指针 的线程安全缓存。 |
| `file_flush_size` | `static constexpr size_t = 4096`，内部文件输出目标的落盘阈值。 |
| `tree_epoch` | `std::atomic<uint64_t>`，树版本号（结构或流设置变更时递增）。 |
| `node_root` | 空键根节点（`node_ensure("")` / `stream_bind("", ...)` 即绑根）。 |
| `tree_mtx` | **树结构锁**：覆盖建节点 / 清流 / 落盘收集，**不用于日志输出热路径**。 |

#### 2.8.3 `prefix_common`（路径段对齐的公共前缀）

```cpp
//路径段对齐的公共前缀长度（公共部分不足一个路径段时回退到最近的 '/' 边界）
size_t prefix_common(const std::string& left, const std::string& right)
{
    //求原始公共前缀长度
    const size_t limit = left.size() < right.size() ? left.size() : right.size();
    size_t length = 0;
    while (length < limit && left[length] == right[length])
        ++length;
    //回退到最近的 '/' 边界，保证公共部分以路径段为单位
    while (length > 0 && left[length - 1] != '/')
        --length;
    //返回对齐后的公共前缀长度
    return length;
}
```

| 项 | 说明 |
| --- | --- |
| 语义 | 返回两键按**完整路径段**计的公共前缀长度（末尾必定落在 `/` 后）。 |
| 边界回退 | 逐字符求公共长度后回退到最近的 `/`，避免把半个路径段当公共部分（防 `abc` 误配 `abcd`）。 |
| 返回 0 | 无公共前缀（两路径各自成为父节点的子节点）。 |

#### 2.8.4 `node_ensure`（节点查找或创建——建树核心）

```cpp
//节点查找或创建（按路径键自根向下定位，公共前缀即父节点）
Stream_Node& node_ensure(const std::string& key)
{
    //空键即根节点
    if (key.empty())
        return node_root;
    //自根节点开始定位
    Stream_Node* node = &node_root;
    //待定位的剩余键
    std::string rest = key;
    //逐层向下定位
    for (;;)
    {
        //在当前子链表中寻找与剩余键存在公共前缀的子节点
        std::list<Stream_Node>::iterator match = node->children.end();
        for (std::list<Stream_Node>::iterator it = node->children.begin(); it != node->children.end(); ++it)
            if (prefix_common(it->key, rest) > 0) { match = it; break; }
        //若不存在公共前缀的子节点则以剩余键新建
        if (match == node->children.end())
        {
            //在子链表末尾就地新建节点（list 追加不搬移既有元素，地址稳定）
            node->children.emplace_back();
            Stream_Node& created = node->children.back();
            created.key = rest;
            created.parent = node;
            return created;
        }
        const size_t length = prefix_common(match->key, rest);
        //若子节点键完整包含于剩余键则继续向下定位
        if (length == match->key.size())
        {
            rest.erase(0, length);
            if (rest.empty()) return *match;
            node = &(*match);
            continue;
        }
        //公共前缀短于子节点键：拆出中间节点承载公共前缀
        node->children.emplace_back();
        Stream_Node& middle = node->children.back();
        middle.key = match->key.substr(0, length);
        middle.parent = node;
        //把原子节点移入中间节点子链表（splice 不搬移元素，子节点地址与指针保持有效）
        middle.children.splice(middle.children.end(), node->children, match);
        {
            //持被搬移节点锁改写键与父指针（父指针会被输出路径并发读取）
            Stream_Node& moved = middle.children.back();
            std::lock_guard<std::mutex> moved_lock(moved.node_mtx);
            moved.key.erase(0, length);
            moved.parent = &middle;
        }
        rest.erase(0, length);
        if (rest.empty()) return middle;
        middle.children.emplace_back();
        Stream_Node& created = middle.children.back();
        created.key = rest;
        created.parent = &middle;
        return created;
    }
}
```

| 分支 | 触发条件 | 行为 |
| --- | --- | --- |
| 空键 | `key.empty()` | 直接返回根节点。 |
| 无公共前缀子节点 | 子链表中无 `prefix_common > 0` 的节点 | 以剩余键 `emplace_back` **新建**子节点。 |
| 子节点键完整包含 | `length == match->key.size()` | 去掉公共前缀下降；剩余清空即命中；否则继续向下。 |
| **拆分中间节点** | 公共前缀短于子节点键 | 新建**中间节点**承载公共前缀，`splice` 把原子节点整体移入中间节点之下，再把原子节点键**截短**；随后按剩余键新建目标子节点。 |

**关键性质**：链表树**不逐级建目录节点**——节点粒度就是「已出现路径的公共前缀」。因此 `A/B/c.hpp` 与 `A/B/d.hpp` 共享的节点键是 `A/B/`。**注意**：拆分时被搬移节点的 `key` 与 `parent` 在**其自身节点锁内**改写（输出路径会并发读取 `parent`）。

#### 2.8.5 `node_find`（节点查找，不新建）

```cpp
//节点查找（按路径键自根向下定位，不新建节点）
Stream_Node* node_find(const std::string& key)
{
    if (key.empty()) return &node_root;
    Stream_Node* node = &node_root;
    std::string rest = key;
    for (;;)
    {
        Stream_Node* match = nullptr;
        for (Stream_Node& child : node->children)
            if (prefix_common(child.key, rest) == child.key.size()) { match = &child; break; }
        if (!match) return nullptr;
        rest.erase(0, match->key.size());
        if (rest.empty()) return match;
        node = match;
    }
}
```

用途：`stream_clear` 用；只沿既有树定位，**不新建节点**，失败返回 `nullptr`。

#### 2.8.6 `node_locate`（调用点节点定位 —— 缓存 O(1)，本版次沿用）

```cpp
//调用点节点定位（命中调用点缓存则直接返回，未命中才规范化路径、建节点并登记）
Stream_Node* node_locate(const char* file_name)
{
    //先查调用点缓存
    Stream_Node* cached = node_cache.cache_fetch(file_name);
    //命中则直接返回（节点地址稳定，缓存长期有效）
    if (cached)
        return cached;
    //未命中：持结构锁规范化路径并定位或创建节点（规范化仅此一次）
    std::lock_guard<std::mutex> lock(tree_mtx);
    const std::string key = path_normalize(file_name);
    Stream_Node* node = &node_ensure(key);
    //结构可能新增节点，递增树版本号使既有共享缓存失效
    epoch_bump();
    //把调用点登记进缓存，后续输出直接命中
    node_cache.cache_store(file_name, node);
    return node;
}
```

| 项 | 说明 |
| --- | --- |
| 缓存键 | `std::source_location::file_name()` 返回的 `const char*` **指针**。同一 TU 同一静态字面量地址恒定，故可直接作键。 |
| 命中路径 | `cache_fetch` 持 `cache_mtx` 查表，命中即返回节点指针，**零路径规范化、零建节点**。 |
| 未命中路径 | 持 `tree_mtx` → `path_normalize` → `node_ensure` → `epoch_bump` → `cache_store`。同一调用处此后恒命中。 |
| 缓存有效性 | 节点由 `std::list` 承载且从不销毁（拆分只改 `key`/`parent`，元素不搬移），**节点地址永久稳定**。 |

#### 2.8.7 版本号（`tree_epoch` / `epoch_current` / `epoch_bump`）

```cpp
//当前树版本号
uint64_t epoch_current() const { return tree_epoch.load(); }
//递增树版本号（使既有共享缓存全部失效）
void epoch_bump() { tree_epoch.fetch_add(1); }
```

- `epoch_bump` 的三个触发点：`node_ensure` 引发结构变更（由 `node_locate` 调用）、`group_append` **首次新建自有容器**、`stream_clear`。
- 取代旧的 `group_shared_reset()` 子树遍历——既消除「父→子」反向锁序风险，又避免逐后代清缓存的 O(子树) 开销。

#### 2.8.8 控制台输出目标与兜底容器

```cpp
//控制台输出目标构建（以非拥有指针包装 std::cout，逐条落盘且不强制刷新底层流）
Sink sink_console_create()
{
    //以不持有 std::cout 生命周期的共享指针包装标准输出

    //以「每次写出即落盘、不刷新底层流」的方式构造控制台输出目标

}
Sink sink_console() { static Sink sink = sink_console_create(); return sink; }
Sink_Group group_create_console() { /* 分配容器并装入控制台目标，失败返回空容器 */ }
Sink_Group group_console() { static Sink_Group group = group_create_console(); return group; }
```

| 项 | 说明 |
| --- | --- |
| 空删除器 | `std::cout` 是栈/静态对象，**绝不能 delete**；用空 lambda 删除器包装为非拥有 `shared_ptr`。 |
| 环境矩阵 | 控制台 `flush_size=0 / flush_target=false`（逐条写出、不强制刷新）；外部流 `0 / true`；内部文件 `4096 / true`。 |
| 兜底容器 | 整条父链都未设文件流时，`group_resolve` / `stream_output` 返回该容器（仅含控制台目标），保证日志链路永远可用。 |

#### 2.8.9 `group_append`（向节点自有容器追加输出目标）

```cpp
//节点自有输出目标追加（必要时创建容器并递增树版本号）
bool group_append(Stream_Node& node, const Sink& sink)
{
    //记录本次是否新建了自有容器
    bool created = false;
    {
        //持节点锁改写容器
        std::lock_guard<std::mutex> lock(node.node_mtx);
        //若节点自有容器尚未创建则创建
        if (!node.own_group)
        {
            node.own_group = Sink_Group(new(std::nothrow) std::vector<Sink>());
            if (!node.own_group) return false;
            //标记本次新建了自有容器
            created = true;
        }
        //把输出目标追加进节点自有容器
        node.own_group->push_back(sink);
    }
    //若本次由共享父流转为单独流输出则递增树版本号，使既有共享缓存失效
    if (created)
        epoch_bump();
    return true;
}
```

| 项 | 说明 |
| --- | --- |
| 追加语义 | 同一节点重复绑定即**追加**（多流全量输出）。 |
| 首次由「共享」转「自有」 | 新建自有容器后 `epoch_bump()`，使全体共享缓存自动过期（取代旧的 `group_shared_reset`）。 |
| 锁 | 仅持该节点锁，不持树锁（`tree_mtx` 由调用方 `stream_bind` 持有 → 锁序 `tree_mtx` → 节点锁）。 |
| 分配失败 | `new(nothrow)` 返回空 → 返回 `false`。 |

#### 2.8.10 `group_resolve`（生效容器解析——分流核心）

```cpp
//节点生效输出目标容器解析（自有优先，其次未过期的共享缓存，最后沿父链向上）
Sink_Group group_resolve(Stream_Node& node)
{
    //记录解析开始时的树版本号（用于判定登记结果是否过期）
    const uint64_t epoch_begin = epoch_current();
    //起点快速路径：自有容器优先，其次未过期的共享缓存
    Stream_Node* parent = nullptr;
    {
        //持起点节点锁读取容器与缓存
        std::lock_guard<std::mutex> lock(node.node_mtx);
        if (node.own_group) return node.own_group;
        if (node.shared_epoch == epoch_begin)
            if (Sink_Group shared = node.shared_group.lock())
                return shared;
        //记录父节点以便继续向上解析
        parent = node.parent;
    }
    //沿父链向上解析（每级仅持一个节点锁，即取即放、不嵌套）
    Sink_Group found;
    Stream_Node* current = parent;
    while (current && !found) { /* 每级单锁：自有 → 版本号校验的共享 → 记父继续 */ }
    //全部祖先均未设置输出流则回落控制台容器
    if (!found) found = group_console();
    //把解析结果登记到起点节点的共享缓存（以开始版本号登记，期间结构变更即自动判过期）
    {
        std::lock_guard<std::mutex> lock(node.node_mtx);
        node.shared_group = found;
        node.shared_epoch = epoch_begin;
    }
    return found;
}
```

| 优先序 | 条件 | 结果 |
| --- | --- | --- |
| ① 自有优先 | `own_group` 非空 | 返回自有容器（**单独流输出**，父流不生效）——最常见路径，**仅一次原子自增**，无父链遍历 |
| ② 弱引用共享 | `shared_epoch == epoch_begin` 且 `shared_group.lock()` 成功 | 返回缓存的父容器（**共享父节点输出流**） |
| ③ 沿父链上溯 | 有父节点 | 逐级单锁解析父节点容器（每级都校验版本号） |
| ④ 根部兜底 | 无父节点 / 全链无自有容器 | 返回 `group_console()`（控制台） |

| 项 | 说明 |
| --- | --- |
| 返回值形态 | **仍按值返回 `Sink_Group`**：用户已指出返回 `const&` 需持锁至生命周期结束，等于回到「持锁做 I/O」；故保留一次 `shared_ptr` 拷贝（一次原子自增）。 |
| 弱一致性 | 解析结果以**开始版本号**登记；解析期间任何结构/流设置变更都会 `epoch_bump`，使该登记自动判过期，避免陈旧结果长期生效。 |
| 「最近祖先优先」 | 若目录节点自己设了流，则它成为其后代解析到的最早自有容器，**更远的根流不会生效**。 |

#### 2.8.11 `group_collect`（自有输出目标收集，供落盘）

```cpp
//自有输出目标收集（递归整棵树，供落盘使用）
void group_collect(Stream_Node& node, std::vector<Sink>& sinks)
{
    {
        //持节点锁读取自有容器
        std::lock_guard<std::mutex> lock(node.node_mtx);
        if (node.own_group)
            for (const Sink& sink : *node.own_group)
                sinks.emplace_back(sink);
    }
    //递归处理子节点
    for (Stream_Node& child : node.children)
        group_collect(child, sinks);
}
```

要点：沿**子链向下**递归，但仅在 `tree_mtx` 内调用；每级仅持一个节点锁（即取即放）。取代旧的 `group_shared_reset`（后者已删除）。

#### 2.8.12 `stream_output`（树路由输出 —— I/O 在锁外）

```cpp
//日志行路由输出（按调用处路径定位节点 → 锁内解析容器 → 解锁后逐流输出）
void stream_output(const char* file_name, const std::string& msg)
{
    //定位调用处节点（缓存命中则不做任何路径规范化）
    Stream_Node* node = node_locate(file_name);
    //解析生效输出目标容器（锁内完成，取到容器后即已解锁）
    Sink_Group group = node ? group_resolve(*node) : group_console();
    //若容器不可用则直接写控制台
    if (!group || group->empty())
    {
        if (Sink console = sink_console())
            console->write(msg);
        return;
    }
    //逐个输出目标写出（此时不持任何树锁，仅由各输出目标自锁）
    for (const Sink& sink : *group)
        if (sink)
            sink->write(msg);
}
```

| 项 | 说明 |
| --- | --- |
| 消息形态 | 由 `Log::output` 合成的 `[TYPE]正文\n`（本函数只做路由，不合成消息行——与旧实现的 `output` 不同）。 |
| 多流输出 | 遍历容器，**所有目标都写**（同一节点多流全量）。 |
| 空容器兜底 | 容器为空时直接写控制台（极端兜底，正常路径由 `group_console()` 保证非空）。 |
| 锁范围 | `node_locate` / `group_resolve` 内部各自加放锁；**逐流写出时不持任何树锁**，仅由各 `Stream_Sink` 自锁 → 不会长时间阻塞其它线程的日志调用。 |
| 行尾 | 消息恒以 `\n` 结尾；控制台目标逐条写出但不强制刷新；文件目标按 4KB 阈值批量落盘。 |

### 2.9 `Stream_Sink`（线程安全输出目标，`Stream_Sink/输出目标.h`，73 行）

```cpp
namespace engine
{
    //日志输出流别名（对外绑定接口沿用共享输出流形态）
    using Log_Stream = std::shared_ptr<std::ostream>;

    //线程安全输出目标（内部互斥 + 内部缓冲：单次写入原子完成，避免多线程交错；达阈值才落盘，减少系统调用）
    class Stream_Sink
    {
    public:
        //以输出流、落盘阈值与「落盘时是否刷新底层流」构造
        Stream_Sink(const Log_Stream& owner, size_t flush_size, bool flush_target)
            : owner(owner), flush_size(flush_size), flush_target(flush_target){}
        //禁用拷贝 / 禁用赋值
        Stream_Sink(const Stream_Sink&) = delete;
        Stream_Sink& operator=(const Stream_Sink&) = delete;
        //析构时落盘残余缓冲
        ~Stream_Sink() { flush(); }
        //写出文本（锁内整体入缓冲，缓冲达阈值即落盘）
        void write(const std::string& text);
        //把缓冲内容落盘（线程安全）
        void flush();
    private:
        //缓冲落盘（须已持锁）
        void flush_locked();
        Log_Stream owner{};        //目标输出流（共享所有权，生命周期不短于本对象）
        size_t flush_size = 0;     //落盘阈值（0 表示每次写出即落盘）
        bool flush_target = false; //落盘时是否刷新底层流
        std::string buffer{};      //内部缓冲
        std::mutex sink_mtx{};     //内部互斥（保护内部缓冲与目标流）
    };
}
```

| 项 | 说明 |
| --- | --- |
| 设计目的 | 落实「持锁做 I/O 不合规」：节点/树锁只负责「解析出容器」，真正的写出由 `Stream_Sink` 自锁完成，且**单次 `write()` 在锁内整体入缓冲**，保证多线程日志行不交错。 |
| 落盘策略 | 缓冲达 `flush_size` 才 `flush_locked`；`flush_target` 决定是否随后 `owner->flush()`。 |
| 生命周期 | `owner` 以 `shared_ptr` 共享所有权 → 输出流生命周期不短于 Sink（避免悬垂引用）。 |
| 拷贝/搬移 | 显式禁用拷贝与赋值；故只能以 `shared_ptr<Stream_Sink>` 进容器。 |
| `Log_Stream` 唯一定义 | 仅在本头定义一次，其余文件通过包含获得（`Log::Stream` ≡ `Log_Stream`）。 |

## 4. 模块设计/实现细节

### 4.1 关键设计决策：为何用 `Format<Args...>` 包装类型

**问题**：需要「在不改调用点的前提下，自动取得调用处文件路径」。C++20 的惯用法是末尾加 `std::source_location loc = std::source_location::current()`。

**MSVC 实测结论**：把 `std::source_location` 放在**变参包之后**的签名——

```cpp
template<typename... Args>
static void info(std::format_string<Args...> fmt, Args&&... args,
                 std::source_location loc = std::source_location::current());   // ✗ MSVC 拒绝
```

会失败：非末位变参包 `Args&&...` 是**非推导上下文**，`Args` 推导为空 → 所有实参都被拿去匹配 `loc`（`C2664/C2672`）。

**采用的方案**：把格式串包一层 `Format<Args...>`，其**构造函数的默认参数**承担 `source_location::current()`：

```cpp
logger.info("数值={}", 42);
//  "数值={}" 先隐式转换为 Format<int>，转换点在调用处，
//  故构造函数默认参数 source_location::current() 返回调用处（而非头文件内部）
```

签名写作 `Format<std::type_identity_t<Args>...>` 以**冻结**该形参的推导，`Args` 仅由末位变参包推导；`Format::pattern` 仍是 `std::format_string<Args...>`，**编译期占位符校验得以保留**。实测：`file:line` 输出确为调用点行，中文路径 `__FILE__` 字节正确。

### 4.2 多类拆分与 has-a 组合（本版次核心）

| 类 | 单一职责 | 对外接口 |
| --- | --- | --- |
| `Log` | 日志门面：调用处捕获、消息行合成、对外转发 | `info/warn/error/debug`、`stream_bind`×2、`stream_clear`、`stream_flush`、`Format`、`Stream` |
| `Stream_Tree` | 链表树建立与路径规范化、节点定位、生效容器解析、整树落盘、日志行路由 | `stream_bind`×2 / `stream_clear` / `stream_flush` / `stream_output` |
| `Stream_Sink` | 线程安全输出目标（内部互斥 + 缓冲，达阈值落盘） | `write` / `flush` |
| `Node_Cache<Node>` | 调用处文件指针 → 节点指针 的线程安全缓存 | `cache_fetch` / `cache_store` |

- **组合方式**：全部为**值成员**（非指针/引用），故 `Log`、`Stream_Tree` 均因内含互斥量而**不可拷贝**（`inline Log logger;` 无需拷贝，静态初始化即可）。
- **职责切分点**：`Log::output` 只做「消息行合成」，路由交给 `Stream_Tree::stream_output`（旧实现的 `output` 兼做合成与路由，本版次拆开）。
- **兼容性保持**：`Log::Stream` 仍在；`logger.xxx` 的调用形式与语义不变；并发/缓存机制（节点级锁、`tree_epoch`、调用点缓存、Sink 阈值缓冲）原样迁移，未改语义。

### 4.3 锁模型与严格单向锁序（I/O 全程在锁外）

| 锁 | 保护对象 | 使用场合 |
| --- | --- | --- |
| `tree_mtx`（`Stream_Tree`） | 树结构（`children`/`key`/`parent` 的创建与拆分） | 建节点 / 清流 / 落盘收集——**不在输出热路径** |
| `node.node_mtx`（每节点一把） | 单节点 `own_group` / `shared_group` / `shared_epoch` / `parent` | 解析与设流，**逐级获取、即取即放** |
| `Node_Cache::cache_mtx` | `node_cache` 缓存表 | 调用点缓存（顺序：`tree_mtx` → `cache_mtx`） |
| `Stream_Sink::sink_mtx` | 底层输出流与内部缓冲 | **在无任何树锁时**获取 |

**严格单向锁序**（绝不反向、绝不嵌套两个节点锁）：`tree_mtx` → 节点锁 → `cache_mtx`；`Stream_Sink::sink_mtx` 独立于树锁之外。

- `stream_output` 流程：`node_locate`（缓存 O(1)）→ `group_resolve`（节点锁内解析，**取到 `Sink_Group` 拷贝即已解锁**）→ 逐流写出（**不持任何树锁**）。
- 死锁论证：全局不存在「父节点锁 → 子节点锁」或「节点锁 → `tree_mtx`」的获取方向；`group_resolve` 只沿父链向上、每级单锁；`group_collect` 沿子链向下但仅在 `tree_mtx` 内、且每级单锁。
- **无权限保护机制**（按任务要求）：任何调用方都可对任意路径设流/清流，不做权限校验；**只有并发保护**。

### 4.4 并发语义与「弱一致性」

- 测试用例「多线程并发输出不交错」：4 线程 × 100 条写内存流，断言总行数 400 且每行均以 `[INFO]并发标记 ` 完整开头——由 `Stream_Sink::write` 的「锁内整体入缓冲」保证。
- 共享缓存为**弱一致性**：并发设流与输出交错时，个别输出可能沿用解析瞬间的旧容器（一次 `Sink_Group` 拷贝的生命周期内），属预期（无权限保护、允许短暂过渡）。
- `node_ensure` 拆分中间节点时，被搬移节点的 `parent`/`key` 在**其自身节点锁内**改写（输出路径会并发读取 `parent`）。

### 4.5 目录继承与「最近祖先优先」

- 绑定目录路径（如 `测试层/src/单元测试/工具`）后，规范化键为 `测试层/src/单元测试/工具/`；该目录下的文件调用处路径以它开头，`node_ensure` 会把文件节点挂到该目录节点（或以其为父）之下。
- 文件节点自身无 `own_group` → `group_resolve` 沿父链找到目录节点的 `own_group` → **继承**。
- **若中间某节点自己设了流**，则它在父链上更近，成为解析到的第一个自有容器 → 「最近祖先优先」，更远的根流不生效。
- `shared_group` 用 **`weak_ptr`** 而非 `shared_ptr`：后代**不参与祖先容器的所有权**，从而不延长祖先生命周期、**不产生循环引用**（父持有子链表、子又持有父容器）。

### 4.6 输出目标语义矩阵（缓冲与刷新）

| 用途 | `flush_size` | `flush_target` | 语义 |
| --- | --- | --- | --- |
| 控制台 | 0 | false | 逐条写出、**不强制刷新**（落实「取消 `std::endl` 强制刷新」） |
| 外部流（`stream_bind(path, Stream)`） | 0 | true | 逐条写出并刷新，保持既有外部流即时可读语义（向后兼容） |
| 内部文件（`stream_bind(path, file_name)`） | 4096 | true | 批量落盘（4KB 阈值），性能优先 |

- `std::endl` 全部去除：消息行统一为 `[TYPE]正文\n`；4 处旧的 `std::endl`（2 处绑定失败提示、1 处控制台兜底、1 处逐流写出）已清。
- 进程正常退出时由 `Stream_Sink` 析构落盘；**异常终止可能丢最后不足 4KB 的日志**（已知局限）。
- 写后立即读文件必须调用 `stream_flush()`（测试层 `log_read()` 已统一补 `engine::logger.stream_flush()`）。

### 4.8 易踩坑点汇总

1. **必须用 `logger.` 实例调用**：`Log::info(...)` / `logger.Stream()` 均**非法**（`Log::Stream` 是嵌套类型、`Log` 已无静态成员），替换时要保留 `engine::Log::Stream` 这一处嵌套类型引用。
2. **`Format` 必须 public**：否则调用方无法完成隐式转换而编译失败。
3. **不能改成 `Format<Args...>` 形参**：必须写 `Format<std::type_identity_t<Args>...>`，否则推导失败。
4. **路径键末尾恒有 `/`**：手动构造路径键时须遵守（`path_key_normalize` 已处理）。
5. **锚点依赖目录名 `白银纪元`**：锚点由日志侧传入，项目改名会导致路径键整体变化。
6. **`流节点树.h` 不得再包含 `引擎环境.h`**：否则 `流节点树.h → 路径操作工具.h → 引擎环境.h → 运行包 → 日志系统.h → 流节点树.h` 构成头文件循环。
7. **`Stream_Node` 不可搬移**：含 `std::mutex`，新建一律 `emplace_back()`，不得 `push_back(Stream_Node{})`。
8. **`stream_clear` 不删节点**：只清流；节点留在树上（避免 `list` 元素地址失效）。
9. **清空根节点返回 `true`**：根节点恒存在。
10. **`stream_bind` 的文件名是相对当前工作目录**：进程 cwd 变化会影响落盘位置。
11. **`std::ofstream` 默认 trunc**：绑定时即打开并**截断**同名文件（非追加）。
12. **一个 `stream_bind` 一个输出目标**：要「目录 + 文件」都输出须分别绑定；节点内是追加语义。
13. **写后立即读文件必须 `stream_flush()`**：文件目标按 4KB 阈值落盘。
14. **绑定失败提示格式特殊**：`[FATAL]`/`[ERROR]` 前缀 + `\n`（经控制台 Sink 的 `write`）。
15. **不要 delete cout**：控制台流是空删除器包装。
16. **format 异常不捕获**：`std::format_error` 直接传播。

## 5. 模块运行链路

### 5.1 典型调用时序（配置加载 + 分流场景）

```
[进程启动]
  ├─（可选）logger.stream_bind("引擎层/src/tools/Logging", "engine_tools.log");
  │       └─ 目录节点绑定 → 该目录下所有源文件的日志落 engine_tools.log
  ├─（可选）logger.stream_bind("引擎层/src/core/config", "engine_config.log");
  │
  ├─ Config_Loader 构造 → attach() → 事件驱动加载
  │     ├─ route_load 扫描失败？
  │     │     └─ logger.error("Config_Loader::未检测到任何路由文件")
  │     │           ├─ Format 构造：捕获 file_name()＝引擎层/src/core/config/Config_Loader/core/配置加载.cpp
  │     │           ├─ stream_output → node_locate（首次：path_key_normalize + node_ensure）
  │     │           ├─ group_resolve：无自有流 → 父链 → 命中 "引擎层/src/core/config/" 节点自有流
  │     │           └─ sink->write("[ERROR]Config_Loader::未检测到任何路由文件\n")
  │     └─ ... 后续日志同路径（缓存命中，O(1)）...
  │
  ├─ 写后读检查 → logger.stream_flush()
  └─ 主循环运行（未绑流的模块默认输出控制台）
```

### 5.2 状态机：单节点输出来源切换

```
        stream_bind(path, "a.log")
  [继承父流/控制台] ───────────────────► [自有流 a.log]  （own_group 激活，shared 缓存经 epoch 失效）
        ▲                                        │
        │  stream_clear(path)                    │ stream_bind(path, "b.log")
        └────────────────────────────────────────┘   （追加 → a.log 与 b.log 同时输出）
```

### 5.3 错误路径链路

```
stream_bind(path, file_name)
  ├─ file_name 为空 → 控制台 Sink write("[FATAL]文件名为空\n已切换至控制台输出\n")，绑控制台流（返回 true）
  ├─ new(nothrow) ofstream 失败（内存不足）
  │     └─ 控制台 Sink write("[FATAL]内存不足\n已切换至控制台输出\n") ; return false（不绑流）
  └─ is_open() 失败（目录不存在/无权限）
        └─ 控制台 Sink write("[ERROR]文件打开失败\n已切换至控制台输出\n") ; return false（不绑流）

logger.xxx(...)
  └─ std::format 抛 format_error → 异常传播（不回落、不捕获）
```
