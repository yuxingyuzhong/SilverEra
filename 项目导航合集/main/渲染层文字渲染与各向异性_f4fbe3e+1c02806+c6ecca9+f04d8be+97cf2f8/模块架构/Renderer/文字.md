## 二、模块功能介绍

### 2.1 模块定位

「文字」位于渲染层源码目录 `Application/Renderer/src/render/Text/`，是渲染层本轮新增的子模块，处于依赖链**较靠下**的位置：它**向下**依赖纹理模块（字形图集的上传与销毁）与内存模块（间接，经纹理模块）、外部库 `stb_truetype`；**向上**被门面调用。

一句话概括：**本模块把「一个 TrueType 字体文件 ＋ 一个字号」烘焙为「一张 RGBA8 字形图集 ＋ 每个 ASCII 可打印字符的像素度量」，再把「一个 UTF-8 字符串」按这些度量展开为一批像素坐标下的四边形网格几何；字形图集与几何分别经纹理模块、网格模块落地，本模块自身不持有任何 Vulkan 类型、不做任何绘制。**

要理解它的边界，抓住三点：

1. **度量在加载时一次烘焙**：`Font_Record` **不保留字体文件字节**——`font_load_file` 完成后，字符的图集 uv、相对文本原点的像素矩形、笔位推进量（`advance`）与基线偏移（`baseline`）全部固化在记录里，后续绘制不再触碰字体文件、不再做任何几何度量计算。
2. **几何只做「按度量铺四边形」**：`text_geometry_build` 只做 UTF-8 解码 ＋ 笔位推进 ＋ 逐可见字形写 4 顶点 6 索引，是**纯 CPU、无 Vulkan、无 stb** 的确定性变换。
3. **本模块不接触描述符、管线、命令缓冲**：文字管线的登记、图集纹理的绑定、「像素坐标 → NDC」矩阵的构造、绘制项的登记，全部落在**门面**（见同层 `门面.md` §3.4.32~3.4.34 与 §6.13）。

### 2.2 职责边界与解决的问题

`Font_Context` 解决的问题可归纳为四点：

1. **把「字体文件 → 可采样图集」这条链收敛成一个入口**。`font_load_file` 在内部完成「读取字节 → 定位字体头（TTC 取第 0 号）→ 初始化字形信息 → 按字号求缩放 → 求基线 → 逐 ASCII 码点光栅化 → 行式打包 → 写入 RGBA8 像素 → 经纹理模块上传」全部步骤，对外只返回一个句柄。

2. **把「字体文件字节」与「运行期绘制」解耦**。加载时即烘焙**全部度量**，记录因此可**脱离字体文件存活**；绘制路径不再依赖字体文件的存在，也不承担重复解析 / 重复光栅化的代价（代价是图集与度量为加载时快照，字号或字体变更须重新加载）。

3. **把「字符串 → 顶点」这条链收敛成一个静态入口**。`text_geometry_build` 输入「字体记录 ＋ UTF-8 字符串」，输出可直接交给网格模块的 `Mesh_Data`（顶点 ＋ 索引）；它把「码点解码、越界码点跳过、空白字符只推笔位、可见字形铺四边形」四件事一次做完，且**没有任何 Vulkan / 平台依赖**。

4. **为「字形图集的采样语义」提供明确口径**。图集固定为 RGBA8、**RGB 恒为白、A 为字形覆盖率、非字形区 A 为 0**，使片元着色器可以直接输出纹理色、由管线混合档承担半透明合成（见 §6.5）；同时字形在打包时**左右各留 1 像素间隔**，避免线性过滤下邻字渗色。

### 2.3 在整体架构中的位置

本模块处于渲染层依赖链中段，向下依赖纹理模块（与纹理模块背后的内存模块、设备模块），向上被门面调用：

```
        ┌──────────────────────────────────────────────────────────────┐
        │              engine::Renderer（门面，render/Renderer/）         │
        │   font_load_file / font_unload / text_draw                     │
        │   （text_draw：登记文字管线 → 取/建网格 → 绑图集 → 矩阵 → 绘制）│
        └───────────────┬──────────────────────────────┬─────────────────┘
                        │ Font_Context&（值成员）       │ Font_Context::text_geometry_build（静态）
                        ▼                              ▼
        ┌──────────────────────────────────────────────┴───────────────┐
        │                  engine::Font_Context（Text/字体.h）           │
        │   build / destroy / valid / font_load_file / font_destroy       │
        │   font_get / glyph_seek（静态）/ text_geometry_build（静态）    │
        └───────┬───────────────────────────────────────┬──────────────┘
                │ 图集图像经由 Texture_Context            │ 几何交由 Mesh_Context（门面转交）
                ▼                                        ▼
        ┌───────────────────────┐                ┌───────────────────────┐
        │ 纹理模块（Texture/）   │                │ 网格模块（Mesh/）      │
        │ texture_create_from_   │                │ mesh_create（顶点/索引  │
        │   memory / _destroy    │                │   共用缓冲上传）        │
        └───────────┬───────────┘                └───────────────────────┘
                    │ 图像/视图/采样器
                    ▼
        ┌───────────────────────┐
        │ 设备模块 / 内存模块     │
        └───────────────────────┘

        外部库：external/stb/stb_truetype.h（仅 core/字体加载.cpp 定义实现宏）
```

- **向上**：门面持有 `Font_Context font`（值成员），在 `init` ⑰ 调 `build`，在 `shutdown` 归还文本网格后调 `destroy`；`font_load_file` / `font_unload` / `text_draw` 分别转交 `Font_Context::font_load_file` / `font_destroy` /（`font_get` ＋ `text_geometry_build`）。
- **向下（层内）**：仅依赖**纹理模块**（`Texture_Context`，仅作引用入参）；对网格模块**无编译期依赖**（几何以 `Mesh_Data` 值返回，由门面交网格模块）。
- **向下（外部库）**：仅 `core/字体加载.cpp` 依赖 `stb_truetype`。

### 2.4 与相邻模块的职责分界

| 相邻对象 | 分界 |
| --- | --- |
| 纹理模块（`Texture/`，`Texture_Context`） | 纹理模块负责图像创建、上传、视图与采样器；本模块**只调用** `texture_create_from_memory`（上传字形图集）与 `texture_destroy`（归还图集），并**只作引用入参**（不持有其所有权）。图集的采样语义（过滤 / 寻址 / mip）由纹理模块的模块级共享采样器决定，**本模块不参与**。 |
| 网格模块（`Mesh/`，`Mesh_Context`） | 网格模块负责顶点 / 索引共用缓冲的创建与上传；本模块**不直接调用**它，而是产出 `Mesh_Data` 值，由门面在 `text_draw` 中转交 `mesh.mesh_create`。本模块**不含**网格模块的包含依赖。 |
| 门面（`Renderer/`，`Renderer`） | 门面负责：字体句柄的对外入口（`font_load_file` / `font_unload`）、文字管线懒登记（`文字.vert.spv` / `文字.frag.spv`，Alpha 混合档）、`(字体, 文本) → 网格` 缓存、字形图集绑定、**像素坐标 → NDC 仿射矩阵**构造、绘制项登记。本模块**不做**其中任何一环。 |
| 帧模块 / 管线模块 | 本模块**不接触**帧槽、命令缓冲、描述符集、图形管线；相关接线全在门面与帧模块。 |
| 外部库 `stb_truetype` | 字体解析与字形光栅化由该库承担（`stbtt_InitFont` / `stbtt_ScaleForPixelHeight` / `stbtt_GetFontVMetrics` / `stbtt_GetCodepointHMetrics` / `stbtt_GetCodepointBitmap` / `stbtt_FreeBitmap`）。**它只在 `core/字体加载.cpp` 中被消费**，且以警告抑制包裹包含（本层要求「零本层新增警告」，第三方库自身告警不属本层代码问题）。`core/文字几何.cpp` **不包含**本库。 |
| 引擎核心（`EngineCore`） | 经预编译头与日志系统（`logger`）间接依赖，与其余渲染子模块一致。 |

### 2.5 生命周期与状态机

`Font_Context` 的生命周期为四段式，`destroy` 幂等、析构兜底：

```
构造 Font_Context()                     ← 仅零值初始化，不加载任何字体
   → build(texture)                     ← 记录纹理模块（要求 texture.valid()）；此后 valid() 为真
   → font_load_file(handle, path, h)    ← 逐条加载字体并烘焙图集；句柄自 1 起、空槽复用
   → [使用] font_get / glyph_seek / text_geometry_build（静态）
   → font_destroy(handle)               ← 单条字体归还（含其图集纹理），槽位标记为空
   → destroy()                          ← 全部字体归还 ＋ 复位（幂等）
   → 析构 ~Font_Context()                ← 内部再调一次 destroy（兜底）
```

- 状态机仅两态：**未构建**与**已构建**。`valid()` 判据为 `texture != nullptr`（即 `build` 是否成功记录纹理模块）。
- `font_load_file` 要求 `valid()` 为真且 `pixel_height != 0`；任一前置不满足即记 `error` 并返回假，**句柄保持 0**。
- **失败不留半初始化记录**：加载过程中任一步失败（文件不可读 / 为空 / 解析失败 / 字形过宽 / 图集纹理创建失败），已光栅化位图逐一 `stbtt_FreeBitmap` 回收、图集纹理不创建，**不向 `records` 写入任何记录**。
- 句柄规则：**句柄自 1 起（0 表无效），下标 = 句柄 − 1，空槽复用**（优先复用第一个 `valid == false` 的槽，无空槽才 `push_back`）。
- `Font_Context` **不可拷贝、不可移动**（持有纹理模块引用与记录集合，拷贝构造与拷贝赋值均 `= delete`）。

### 3.2 对外类型一：`Font_Glyph`（字形度量）

```cpp
struct Font_Glyph
{
    // 图集 uv（左上 / 右下）
    float u0 = 0.0f;
    float v0 = 0.0f;
    float u1 = 0.0f;
    float v1 = 0.0f;
    // 像素矩形（x0 / y0 为左上，x1 / y1 为右下；相对文本原点）
    float x0 = 0.0f;
    float y0 = 0.0f;
    float x1 = 0.0f;
    float y1 = 0.0f;
    // 笔位推进（像素）
    float advance = 0.0f;
    // 字形是否有可见像素（空白字符为假，但仍携带 advance）
    bool has_ink = false;
};
```

逐字段说明：

| 字段 | 类型 | 含义 | 约束 / 备注 |
| --- | --- | --- | --- |
| `u0` / `v0` | `float` | 字形在图集中的 uv **左上**角 | 由「图集矩形 ÷ 图集尺寸」在加载时算出；`v` 以图集左上为 0、向下增大 |
| `u1` / `v1` | `float` | 字形在图集中的 uv **右下**角 | 同上；`u1 − u0 = 字形宽 / 图集宽`、`v1 − v0 = 字形高 / 图集高` |
| `x0` / `y0` | `float` | 相对**文本原点（左上角）**的像素矩形左上 | `x0` 为字形位图相对笔位的水平偏移；`y0 = 位图垂直偏移 + baseline` |
| `x1` / `y1` | `float` | 相对文本原点的像素矩形右下 | `x1 = x0 + 字形宽`、`y1 = y0 + 字形高` |
| `advance` | `float` | 笔位推进量（像素） | `= 字体原始 advance × scale`；**空白字符也携带**（用于推进笔位） |
| `has_ink` | `bool` | 是否有可见像素 | 空白字符（如空格）为假；为真且 `x1 > x0 && y1 > y0` 才产出四边形 |

> `Font_Glyph` 是**纯数据聚合体**：无成员函数、无构造逻辑（仅零值默认初始化）。它对本层内部公开，是因为门面与文字几何都需要读其字段；建议经 `Font_Context::glyph_seek`（只读指针）取用。

### 3.3 对外类型二：`Font_Record`（字体记录）

```cpp
struct Font_Record
{
    // 字号（字形像素高度）
    uint32_t pixel_height = 0;
    // 基线相对文本原点的像素偏移（= ascent × scale 取整，使 y = 0 为文本顶端）
    float baseline = 0.0f;
    // 字形图集纹理句柄（由纹理模块持有）
    uint64_t atlas_texture = 0;
    // 图集宽度（像素）
    uint32_t atlas_width = 0;
    // 图集高度（像素）
    uint32_t atlas_height = 0;
    // 字形度量（下标 = 码点 - FONT_CODEPOINT_FIRST）
    std::array<Font_Glyph, FONT_GLYPH_COUNT> glyphs{};
    // 记录是否有效
    bool valid = false;
};
```

逐字段说明：

| 字段 | 类型 | 含义 | 约束 / 备注 |
| --- | --- | --- | --- |
| `pixel_height` | `uint32_t` | 加载时请求的字号（字形像素高度） | `font_load_file` 要求为正；透传记录 |
| `baseline` | `float` | 基线相对文本原点的像素偏移 `= floor(ascent × scale + 0.5)` | 使 `y = 0` 对应文本顶端（而非基线）；文字几何用它把位图垂直偏移折算为「相对文本原点」 |
| `atlas_texture` | `uint64_t` | 字形图集纹理句柄 | 由**纹理模块**持有；记录只存句柄，归还时调 `texture_destroy` |
| `atlas_width` | `uint32_t` | 图集宽度（像素） | 固定为 `512`（见 §6.2） |
| `atlas_height` | `uint32_t` | 图集高度（像素） | 由打包结果算出，向上取整到 4 的倍数、且不小于 4 |
| `glyphs` | `std::array<Font_Glyph, 95>` | ASCII 可打印字符（码点 32..126）的度量表 | 下标 `= 码点 − 32`；`FONT_GLYPH_COUNT = 95` |
| `valid` | `bool` | 记录是否有效 | 空槽为 `false`；`font_get` / `font_destroy` 均以此为判据；`font_destroy` 后整条记录复位为 `Font_Record{}` |

> **本记录不保留字体文件字节**：字节仅在 `font_load_file` 期间存在（局部 `vector<uint8_t> bytes`），函数返回前用完即弃。度量与位图已在加载时烘焙完毕，故记录可脱离字体文件独立存活。
>
> `Font_Record` 同样为**纯数据聚合体**（无成员函数）。它对本层内部公开，供门面读取 `atlas_texture` 与把整条记录传给 `text_geometry_build`。

### 3.4 对外类型三：`Font_Context`（字体上下文）

```cpp
class Font_Context
{
public:
    Font_Context(void) = default;
    ~Font_Context(void);
    Font_Context(const Font_Context&) = delete;
    Font_Context& operator=(const Font_Context&) = delete;

    bool build(Texture_Context& texture);
    void destroy(void);
    bool valid(void) const;

    bool font_load_file(uint64_t& handle_out, const std::string& path, uint32_t pixel_height);
    void font_destroy(uint64_t handle);
    const Font_Record* font_get(uint64_t handle) const;

    static const Font_Glyph* glyph_seek(const Font_Record& record, uint32_t codepoint);
    static bool text_geometry_build(Mesh_Data& data_out, const Font_Record& record, const std::string& text);
private:
    // 纹理模块（字形图集上传 / 销毁）
    Texture_Context* texture = nullptr;
    // 字体记录集合（下标 = 句柄 - 1）
    std::vector<Font_Record> records;
};
```

类级约定（来自头文件注释与实现）：

- **生命周期**：`build → font_load_file → 使用 → destroy`；`destroy` 幂等；析构兜底调用 `destroy`。
- **句柄规则**：句柄自 1 起（0 表示无效），下标 = 句柄 − 1，**空槽复用**（与纹理模块的「单调递增不复用」取舍**不同**，见 §6.1）。
- **所有权**：持有纹理模块裸指针引用与字体记录集合，故不可拷贝、不可移动。
- **不持 Vulkan 类型**：本类**不出现任何 `Vk*` 类型**（图集纹理只以 `uint64_t` 句柄表达），是渲染层内少见的「零 Vulkan 头依赖」子模块。

### 3.5 接口逐条清单

#### （1）`Font_Context(void) = default`

- **功能**：构造，**不加载任何字体**。
- **行为**：`texture = nullptr`、`records` 为空；`valid()` 为假，任何加载 / 取用接口都会因前置检查失败而被拒。

#### （2）`~Font_Context(void)`

- **功能**：析构，内部调用 `destroy()`，**保证图集纹理不泄漏**。
- **约束**：即使未 `build` 或半构建，析构也安全（`destroy` 对空集合为空遍历、`texture` 为空时空转）。

#### （3）拷贝与赋值（`= delete`）

- **约束**：持有纹理模块引用与记录集合，**不可拷贝、不可移动**（未声明移动，故移动亦不可用）。

#### （4）`bool build(Texture_Context& texture)`

- **功能**：构建——**仅记录纹理模块**（供字形图集上传与销毁），不创建任何字体 / 纹理。
- **参数**：`texture`——纹理上下文引用。仅记录其地址（`Texture_Context*`），**不拷贝、不持有所有权**；调用方须保证该对象在本上下文整个使用期内存活。
- **返回值**：`bool`——记录成功返回真；前置不满足返回假。
- **前置**：`texture.valid()` 必须为真，否则记 `logger.error("字体:: 构建时纹理模块不可用")` 并返回假。
- **约定**：重复 `build` 会直接覆盖 `texture`（不清理既有 `records`），**约定「先 `destroy` 再 `build`」**，实现不做重入保护（与纹理模块 `Texture_Context::build` 同属隐式约定）。

#### （5）`void destroy(void)`

- **功能**：销毁——幂等，归还**全部**字体记录与其图集纹理。
- **行为**（按实现顺序）：
  1. 遍历 `records`：若 `texture != nullptr && record.atlas_texture != 0` 则 `texture->texture_destroy(record.atlas_texture)`；随后 `record = Font_Record{}` 复位整条记录；
  2. `records.clear()`；
  3. `texture = nullptr`。
- **幂等性**：清空后 `records` 为空、`texture` 为空，再调用进入空遍历、无副作用。
- **约束**：销毁后需重新 `build` 才能再次使用；本函数**不销毁** `Texture_Context` 本身（只持引用）。

#### （6）`bool valid(void) const`

- **返回值**：`texture != nullptr`（即 `build` 是否成功记录纹理模块）。

#### （7）`bool font_load_file(uint64_t& handle_out, const std::string& path, uint32_t pixel_height)`

- **功能**：从 TTF 文件加载字体并构建 ASCII 字形图集；成功写出句柄（≥ 1）。
- **参数**：`handle_out`（出参，进入即置 0）；`path`（字体文件路径，以二进制读取）；`pixel_height`（字号 / 字形像素高度，须为正）。
- **返回值**：`bool`——成功返回真并写出句柄；**文件不存在 / 不可读 / 为空 / 解析失败 / 字形过宽 / 图集纹理创建失败**均返回假，句柄保持 0，**不留半初始化记录**。
- **前置**：`valid()` 为真（否则 `error("字体:: 加载字体时模块尚未构建")`）；`pixel_height != 0`（否则 `error("字体:: 字号必须为正")`）。
- **行为要点（详见 §7.2）**：
  1. 以二进制方式打开并定位到末尾取长度（`ios::binary | ios::ate`）；文件不存在 / 空 / 读失败即返回假；
  2. `stbtt_GetFontOffsetForIndex(bytes.data(), 0)`（**TTC 等多字体重文件取第 0 号**）→ `stbtt_InitFont`；
  3. `scale = stbtt_ScaleForPixelHeight(info, pixel_height)`；`stbtt_GetFontVMetrics` 取 `ascent`，`baseline = floor(ascent × scale + 0.5)`；
  4. 逐码点 ASCII 32..126：`stbtt_GetCodepointHMetrics` 取 `advance`（`× scale` 写 `glyph.advance`）；`stbtt_GetCodepointBitmap` 取 1 通道位图——**空白字符无位图，仅保留 advance 后跳过**；字形过宽（宽 + 2 > 图集宽）即回收全部位图并返回假；
  5. **行式（shelf）打包**：图集宽固定 `512`，字形左右各留 1 像素间隔、放不下则换行且行距 +1，行高取该行最高字形；
  6. **图集高度** `= 末行 y + 行高 + 1`，向上取整到 4 的倍数、且不小于 4；
  7. 生成 RGBA8 像素：**RGB 恒 255、A 为覆盖率（零覆盖率跳过写入）、非字形区 A = 0**；
  8. 登记度量：`uv = 图集矩形 ÷ 图集尺寸`、`x0 = gx`、`y0 = gy + baseline`、`x1 = x0 + gw`、`y1 = y0 + gh`、`has_ink = true`；逐字形 `stbtt_FreeBitmap` 释放；
  9. `texture_create_from_memory(atlas_texture, pixels, atlas_width, atlas_height)` 上传（失败即返回假）；
  10. 填充记录并分配句柄：**优先复用第一个空槽**，无空槽才追加。
- **日志**：成功记 `info("字体:: 已加载 {}（字号 {}，图集 {}×{}，句柄 {}）")`。

#### （8）`void font_destroy(uint64_t handle)`

- **功能**：销毁单条字体（一并归还其图集纹理）。
- **约束/行为**：句柄无效（`handle == 0 || handle > records.size()`）直接返回；目标记录 `!valid` 亦直接返回（幂等）；否则 `texture->texture_destroy(record.atlas_texture)`（`texture` 非空且句柄非 0 时）后 `record = Font_Record{}`（**标记槽为空**，供后续 `font_load_file` 复用）。
- **日志**：记 `info("字体:: 已销毁（句柄 {}）")`。

#### （9）`const Font_Record* font_get(uint64_t handle) const`

- **功能**：取字体记录。
- **返回值**：句柄无效 / 目标记录 `!valid` 时返回 `nullptr`；否则返回 `&records[handle - 1]`（**只读指针**）。

#### （10）`static const Font_Glyph* glyph_seek(const Font_Record& record, uint32_t codepoint)`

- **功能**：按码点取字形度量。
- **返回值**：码点超出 `[FONT_CODEPOINT_FIRST, FONT_CODEPOINT_LAST]`（即 `[32, 126]`）时返回 `nullptr`；否则返回 `&record.glyphs[codepoint - 32]`。
- **用途**：`text_geometry_build` 内部据此判「是否支持该码点」，门面亦可用它做度量查询。

#### （11）`static bool text_geometry_build(Mesh_Data& data_out, const Font_Record& record, const std::string& text)`

- **功能**：生成字符串的文字几何，写入 `data_out`（顶层为 `Mesh_Data`：`vertices` ＋ `indices`）。
- **坐标系**：**像素坐标系，原点在文本左上角、Y 向下**；`position` 为像素坐标（`z = 0`），`uv` 为图集 uv（见 §6.6）。
- **返回值**：`bool`——至少产出一个可见字形返回真；**文本不含任何可见字形（空串 / 全空白 / 全为不支持码点）返回假且清空出参**。
- **行为要点（详见 §7.3）**：
  1. 进入即清空 `data_out.vertices` / `data_out.indices`（失败不留残几何）；
  2. `record.valid` 为假返回假；
  3. 循环：`utf8_decode` 取码点 → `glyph_seek` 取度量（**不支持码点跳过、不推笔位**）→ 若 `has_ink && x1 > x0 && y1 > y0` 则产出四边形 → 笔位 `pen_x += advance`；
  4. 四边形四角顺序为「左上 → 右上 → 右下 → 左下」，索引为 **`(0,2,1)` ＋ `(0,3,2)`**（见 §6.4）；
  5. 若始终无可见字形，清空出参并返回假。
- **注**：本接口**不涉及 Vulkan、不涉及 stb**，可视为纯函数式变换（仅依赖传入的记录）。

## 四、模块私有方法介绍

本模块类内**无私有成员函数**：`Font_Context` 的私有区仅有两条数据成员（纹理模块裸指针、字体记录集合），无任何私有成员函数。模块在 `core/文字几何.cpp` 的**匿名命名空间**内定义了一个自由函数 `utf8_decode`（UTF-8 单码点解码），它是模块内部实现细节，逐条如下。

### 4.1 `static bool utf8_decode(const std::string& text, size_t& offset, uint32_t& codepoint_out)`（`core/文字几何.cpp`，匿名命名空间）

- **签名**：`static bool utf8_decode(const std::string& text, size_t& offset, uint32_t& codepoint_out);`
- **功能**：自 `text[offset]` 起解出一个码点。
- **参数**：`text` 输入串；`offset` 读写位置（成功时推进、失败时按规则推进）；`codepoint_out` 出参码点。
- **返回**：解析成功返回真并推进 / 写出；失败返回假。
- **行为**：
  1. `offset >= text.size()` → 返回假（无剩余字节，**不推进**）；
  2. 首字节 `< 0x80` → 单字节 ASCII，推进 1、返回真；
  3. 首字节 `110xxxxx` / `1110xxxx` / `11110xxx` → 2 / 3 / 4 字节序列，取低位作码点累加起始值；
  4. **非法首字节**（含把续字节 `10xxxxxx` 当首字节）→ 推进 1、返回假；
  5. 后续字节数不足（`offset + continuation_count >= text.size()`，**尾部截断**）→ 推进 1、返回假；
  6. 逐续字节拼接，若某续字节不满足 `10xxxxxx`（**格式不符**）→ 推进 1、返回假；
  7. 全部通过 → 推进 `continuation_count + 1`、写出码点、返回真。
- **关键口径**：**失败一律「跳过 1 字节」而返回假，不中断整串**——调用方（`text_geometry_build`）据返回假直接 `continue`，从而对畸形 UTF-8 **容错**：坏字节被逐字节跳过，后续合法码点继续解码（见 §6.3）。
- **可见性**：匿名命名空间（内部链接），仅本编译单元可见。

> 注：本模块私有方法仅此一处自由函数；其余行为（句柄分配、空槽复用、失败回收）均直接写在公开方法体内，细节见 §6 与 §7。

## 六、模块设计/实现细节

### 6.1 关键设计取舍

#### 6.1.1 度量在加载时烘焙、记录不保留字体文件字节

加载时一次性完成解析、光栅化、打包与度量登记，`Font_Record` 因此**可脱离字体文件存活**，绘制路径零解析开销。代价：字号或字体变更须重新 `font_load_file`（图集与度量均为加载时快照），且**换字号必然重建整张图集**。取舍理由：文字渲染的图集与度量在运行期是**只读**的，重算是纯浪费；把「慢的一次性工作」放在加载期、把「快的逐帧工作」放在绘制期，符合常规字体后端做法。

#### 6.1.2 图集格式固定为 RGBA8（RGB 恒白、A 为覆盖率）

把字形覆盖率写进 **A 通道**、RGB 恒为白，使片元着色器可直接 `输出纹理色` 而不必做通道重排，且**半透明合成交给管线混合档**（见 §6.5）。概念上「单通道覆盖率图」也可行，但 RGBA8 与纹理模块既有的 `texture_create_from_memory`（固定 `VK_FORMAT_R8G8B8A8_SRGB`、4 字节 / 像素）**直接对齐**，无需为文字新增纹理格式分支。

#### 6.1.3 句柄「空槽复用」而非「单调递增不复用」

`font_destroy` 把记录复位为 `Font_Record{}`（`valid = false`）但不移除元素；`font_load_file` **优先复用第一个空槽**、无空槽才 `push_back`。这与同层纹理 / 网格模块的「句柄单调递增、永不复用」取舍**相反**（见《渲染层-纹理》§6.5）。取舍理由：字体是**低频、少数量**的资源（通常同一时刻只有 1~2 种字体），且重新加载同一字体是常见操作；复用空槽可使句柄数量与「同时存活字体数」一致，避免长跑下 `records` 无界增长。代价是句柄**不再稳定**：同一字体卸载后重新加载会得到**不同的句柄**（若空槽位置不同），调用方不得缓存旧句柄跨卸载使用。

#### 6.1.4 图集宽度固定 512

图集宽固定 `512` 使打包算法（行式 / shelf）与图集高度计算变成纯前缀式扫描，无需「寻找最小宽度」的箱装优化。代价是可能存在**行尾浪费**（一行放不下最后一个字形时换行，右侧留空），但对 ASCII 95 个字形、字号 16~48 的常见场景，宽度 512 的总高度仍在合理范围。字形过宽（`宽 + 2 > 512`）被显式拒绝（返回假），避免越界写图集。

### 6.2 关键算法：字形图集行式（shelf）打包

`core/字体加载.cpp` 的打包分两趟：

**第一趟**（逐码点）：取 advance（**无论有无位图都写**）；取 1 通道位图——空白字符（`mono == nullptr || 宽 <= 0 || 高 <= 0`）跳过、仅留 advance；字形过宽（`宽 + 2 > 512`）即回收已光栅化位图并整体失败。

**第二趟**（行式打包定位）：

```text
cursor_x = 0, cursor_y = 0, shelf_height = 0
for 每个待打包字形 item：
    若 cursor_x + item.width + 2 > 512：            // 本行放不下
        cursor_x = 0; cursor_y += shelf_height + 1;  // 换行，行距 +1
        shelf_height = 0
    item.atlas_x = cursor_x; item.atlas_y = cursor_y
    cursor_x += item.width + 2                        // 右侧留 1 像素 + 下个字形左侧 1 像素
    shelf_height = max(shelf_height, item.height)
atlas_height = 向上取整到 4 的倍数(cursor_y + shelf_height + 1)
atlas_height = max(atlas_height, 4)                  // 防御：至少 4 像素高
```

要点：

- **左右各留 1 像素间隔**：`cursor_x` 每次推进「字宽 + 2」，加上打包起点本身，使相邻字形在图集中**至少隔 2 像素**（左字形的右边界与右字形的左边界各让 1 像素），线性过滤采样时不会互相渗色。
- **行距 +1**：换行时 `cursor_y += shelf_height + 1`，行与行之间留 1 像素间隔，同理防渗色；图集高度再加 1，给末行底部留间隔。
- **向上取整到 4 的倍数**：图集高度对齐到 4 的倍数（`(h + 3) / 4 * 4`），是对上传路径的保守对齐（并非 Vulkan 强制要求，属实现保守取值）。
- **复杂度** `O(字形数)`，纯 CPU、无外部依赖（打包算法本身不依赖 stb）。
- **像素填充**：先把整张图集 RGBA 全部写为 `255,255,255,0`（RGB 恒白、A 透明），再把各字形位图的覆盖率**逐像素写入对应位置的 A 通道**（零覆盖率跳过写入，省去无谓写入）。

### 6.3 关键算法：UTF-8 解码

`core/文字几何.cpp` 的 `utf8_decode`（见 §4.1）实现 1~4 字节 UTF-8 解码，失败策略为「**跳过 1 字节**」。这条口径有两个直接后果：

1. **畸形串容错**：非法首字节、续字节格式不符、尾部截断都不会中断整串，坏字节被逐字节跳过，后续合法码点继续解码；因此「半个汉字」「错位字节」只会丢掉少量字形，不会使整串几何为空。
2. **不推进笔位（针对越界码点）**：解码成功后若码点超出 `[32,126]`（`glyph_seek` 返回 `nullptr`），**跳过该码点且不推进笔位**——见 §7.3。注意「不支持码点」与「解码失败」是两条不同分支，但**都不产出几何、也都不推进笔位**。

> **本模块的实际支持面**：仅 ASCII 可打印字符 32..126 被光栅化进图集；非 ASCII 码点（含中文）虽能被 `utf8_decode` 正确解码，但 `glyph_seek` 返回 `nullptr` 而被跳过，**不产出任何字形**（见附录 C 的 `R-TEXT-01`）。

### 6.4 关键实现结论一：文字四边形索引绕序

**结论**：文字四边形索引须用 **`(base+0, base+2, base+1)` ＋ `(base+0, base+3, base+2)`**（即「左上 → 右下 → 右上」＋「左上 → 左下 → 右下」），**与场景四边形的 `(0,1,2)` ＋ `(0,2,3)` 相反**。

**成因（务必与场景几何区分）**：

1. 文字顶点在**像素空间**（原点在文本左上角、Y 向下），而场景顶点在 NDC 空间（Y 向上）；
2. 门面在 `text_draw` 中构造的**像素→NDC 仿射矩阵不做 Y 翻转**（见 §6.6）：矩阵为 `m[0] = 2/W`、`m[5] = 2/H`、`m[10] = 1`、`m[12] = 2·pixel_x/W − 1`、`m[13] = 2·pixel_y/H − 1`、`m[15] = 1`，其 2×2 主块行列式 `= (2/W)·(2/H) > 0`；
3. 而 Vulkan 视口把 NDC `y` 映射为**向下递增的帧缓冲行号**，故「像素 Y 向下 ＋ 不翻转」的组合使屏幕空间映射的**定向为负**（相对场景的「NDC Y 向上 ＋ 不翻转」）。

**后果（实测）**：若文字沿用场景绕序 `(0,1,2)` / `(0,2,3)`，在「背面剔除」的默认状态下**文字的所有三角形都会被判为背面而剔除**，表现为**一个像素都不出现**。故必须采用与场景相反的绕序。

> 口径提醒：绕序与「坐标系翻转」是**成对**的约定，改其一必改其二。若将来改为「像素→NDC 矩阵翻转 Y」（`m[5] = −2/H`），则文字绕序应同时改回场景的 `(0,1,2)` / `(0,2,3)`。

### 6.5 关键实现结论二：片元不判 alpha 与管线混合档

**结论**：文字片元着色器（`assets/shaders/文字.frag`）**不判断 alpha 阈值、不做 discard**，直接输出纹理采样色；半透明合成依靠**管线 Alpha 混合档**完成（文字管线登记时即指定 `Blend_Mode::Alpha`，见 §7.6）。

**成因**：图集 RGB 恒为白、A 为覆盖率（见 §6.1.2）。若片元把「A 低于阈值」判为透明并 `discard`，则字形边缘的抗锯齿覆盖率会被整块丢弃，边缘出现硬锯齿；而**交给混合档**则使覆盖率直接作为混合因子参与 `src·A + dst·(1−A)`，边缘自然过渡，同时**保留字形内部的完整不透明度**。

**边界**：混合档是**管线级**属性。文字管线与默认场景管线共享同一管线布局与描述符集布局，仅「着色器对 ＋ 混合档」不同（见《渲染层-门面》§3.4.25）；文字项与场景项**共享同一实例缓冲与描述符集**（见附录 C 的 `R-TEXT-02` 相关备注与《渲染层-门面》§6.13）。

### 6.6 坐标系口径与像素→NDC 矩阵

**本模块产出的几何口径**（`text_geometry_build`）：

- 原点：**文本左上角**；Y 轴**向下**。
- 顶点 `position`：像素坐标（`z = 0`）。
- 单字形四角：`左上 = (pen_x + x0, y0)`、`右上 = (pen_x + x1, y0)`、`右下 = (pen_x + x1, y1)`、`左下 = (pen_x + x0, y1)`；`uv` 取该字形图集 uv（左上 `(u0,v0)` → 右上 `(u1,v0)` → 右下 `(u1,v1)` → 左下 `(u0,v1)`）。
- 笔位推进：每字形按 `advance` 前移 `pen_x`（**空白字符与不支持码点是否推进见 §6.3 / §7.3**）。

**门面侧的换算**（`text_draw`，非本模块，此处仅记口径以便理解几何的去向）：门面取交换链宽高 `W`、`H`，构造**列主序**仿射矩阵：

```text
m[0] = 2 / W, m[5] = 2 / H, m[10] = 1,
m[12] = 2 * pixel_x / W - 1, m[13] = 2 * pixel_y / H - 1, m[15] = 1
```

它把「像素 (px, py)」映射到 NDC，且**不做 Y 翻转**（成因与绕序对应见 §6.4）。故「像素 (x, y) 与屏幕帧缓冲行列一一对应」，`pixel_x` / `pixel_y` 即文本左上角在窗口内的像素位置。

### 6.7 内存所有权与销毁约定

| 资源 | 创建方 | 销毁方 | 依据 |
| --- | --- | --- | --- |
| `Texture_Context*`（引用） | 门面（值成员 `texture`） | 门面（`shutdown`） | 本模块只记录地址、**不拥有** |
| 字形图集纹理（`atlas_texture` 句柄） | 本模块经 `texture.texture_create_from_memory` | 本模块经 `texture.texture_destroy`（`font_destroy` / `destroy`） | 「创建与销毁同属一个模块」的推广：图集由本模块发起创建，亦由本模块发起归还 |
| `records` 中的 `Font_Record` | 本模块（`font_load_file` 写入 / 复用空槽） | 本模块（`font_destroy` / `destroy` 复位 / 清空） | 纯数据结构 |
| stb 位图（`unsigned char* mono`） | stb（`stbtt_GetCodepointBitmap`） | 本模块（`stbtt_FreeBitmap`，逐字形释放 / 失败回收） | stb 约定「调用方负责释放」 |

**关键约定**：

- 本模块**只销毁自己直接创建的对象**（图集纹理、位图）；`texture` 指向的对象由门面销毁。
- 加载失败路径必须**先回收再返回**：任一环节失败时，已光栅化位图逐一 `stbtt_FreeBitmap`、图集纹理**不创建**，且**不向 `records` 写入任何记录**（半初始化记录会破坏 `valid` 语义）。
- `destroy` / `font_destroy` 幂等：重复调用进入空遍历 / 早返回，无副作用。

### 6.8 线程 / 并发约定

本模块与渲染层其余子模块一致：**非线程安全**，`build` / `font_load_file` / `font_destroy` / `destroy` 与门面的文字绘制调用均须来自**同一线程**。本模块**未引入任何互斥量、原子量或同步原语**，成员均为普通标量与容器。`font_get` / `glyph_seek` 为只读查询，但本模块亦未承诺「可在其它线程安全读取」。

### 6.10 易错点清单

1. **`STB_TRUETYPE_IMPLEMENTATION` 只能定义一次**：本层唯一定义点为 `core/字体加载.cpp`；若在别处再定义会重复定义 stb 实现符号（链接冲突）。使用接口的文件只包含头、**不带**该宏。
2. **`core/文字几何.cpp` 不得包含 stb / 纹理头**：几何只消费「已烘焙度量」，引入 stb 会把第三方告警与实现体重带进来，也会破坏「几何与图集无关」的分层。
3. **文字绕序必须与场景相反**（见 §6.4）：沿用场景绕序会导致文字**全部被背面剔除**（一个像素不出现），是排查「文字明明登记了却看不见」的第一顺位检查点。
4. **像素→NDC 矩阵不做 Y 翻转**（见 §6.6）：`m[5] = 2/H`（正）而非 `−2/H`；与第 3 条成对，改其一必改其二。
5. **图集固定 `512` 宽、字形左右各留 1 像素**（见 §6.2）：改图集宽或间隔会同时影响 uv 与 `x0/x1` 的登记；间隔过小会在放大时出现邻字渗色。
6. **`baseline` 是「相对文本原点的像素偏移」而非「相对基线的偏移」**：`y0 = 位图垂直偏移 + baseline`，使 `y = 0` 对应文本顶端；写成「位图垂直偏移」会让文字整体上移 `baseline` 像素。
7. **含空白字符的串仍可能「无可见字形」**：空串、全空白、全为不支持码点都会使 `text_geometry_build` 返回假并清空出参；调用方（门面）必须据此拒绝登记绘制项。
8. **不支持码点既不产出几何、也不推进笔位**（见 §6.3 / §7.3）：若期望「用占位字形（豆腐块）代替」，当前实现**没有**该行为（见 `R-TEXT-01`）。
9. **`font_destroy` 后句柄可能被复用**（见 §6.1.3）：卸载后重新加载的字体**未必**拿到同一句柄；调用方不得跨卸载缓存旧句柄。同时门面侧还有一层「文本网格缓存」，须在 `font_unload` 中**一并归还**，否则网格会泄漏（见 §7.6）。
10. **重复 `build` 不清旧记录**：`build` 直接覆盖 `texture` 而不清理既有 `records`；约定「先 `destroy` 再 `build`」，实现不做重入保护（与纹理模块同）。
11. **图集高度对齐与最小高度对 uv 有影响**：`atlas_height` 向上取整到 4 的倍数且不小于 4，故 `v1` 的分母可能与「角落实际像素高度」不同；图集上传使用**对齐后**的高度，二者必须一致。

## 七、模块运行链路详例

本章以「调用方 → 本模块 → 被调方」时序描述典型链路，覆盖主流程与关键异常 / 边界分支。

### 7.1 链路一：构建字体上下文

1. **调用方（门面）** 在 `init` ⑰ 调 `Texture_Context` 已就绪后调用 `font.build(impl->texture)`。
2. **`build`** 前置检查：`texture.valid()` 为假 → `logger.error("字体:: 构建时纹理模块不可用")`，返回假。
3. 否则记 `texture = &texture`，`logger.info("字体:: 上下文构建完成")`，返回真。
4. 此后 `valid()` 为真，可接受 `font_load_file`。

### 7.2 链路二：从 TTF 加载字体（主流程）

1. **调用方** 调 `font_load_file(handle_out, path, pixel_height)`（经门面 `Renderer::font_load_file`，见《渲染层-门面》§3.4.32）。
2. **前置**：`handle_out = 0`；`!valid()` → `error` 返回假；`pixel_height == 0` → `error` 返回假。
3. **读文件**：`std::ifstream file(path, binary | ate)`；`!file` → `error("字体:: 打不开字体文件 {}")` 返回假；`byte_count <= 0` → `error("字体:: 字体文件为空 {}")` 返回假；`seekg(0)` 后整块读入 `vector<uint8_t> bytes`，读失败 → `error` 返回假；`file.close()`。
4. **定位字体头**：`stbtt_GetFontOffsetForIndex(bytes.data(), 0)`（TTC 取第 0 号）；`font_offset < 0 || !stbtt_InitFont(&info, bytes.data(), font_offset)` → `error("字体:: 字体解析失败 {}")` 返回假。
5. **求缩放与基线**：`scale = stbtt_ScaleForPixelHeight(info, pixel_height)`；`stbtt_GetFontVMetrics` 取 `ascent`/`descent`/`line_gap`；`baseline = floor(ascent × scale + 0.5)`。
6. **逐码点光栅化**（`codepoint = 32..126`）：
   - `stbtt_GetCodepointHMetrics` 取 `advance`，写 `glyph.advance = advance × scale`（**无论有无位图都写**）；
   - `stbtt_GetCodepointBitmap(info, 0.0f, scale, codepoint, &w, &h, &xo, &yo)`；
   - 空白 / 空位图（`mono == nullptr || w <= 0 || h <= 0`）→ `continue`（仅留 advance）；
   - 字形过宽（`w + 2 > 512`）→ `error("字体:: 字形 {} 过宽（{} 像素），超出图集宽度 {}")`，**回收本字形与全部已光栅化位图**后返回假；
   - 否则登记待打包项（码点、宽高、偏移、位图指针）。
7. **行式打包定位**（见 §6.2），算出各字形 `atlas_x` / `atlas_y` 与图集高度。
8. **构造图集像素**：`vector<uint8_t> pixels(512 × atlas_height × 4, 0)`，逐像素写 `RGB = 255, A = 0`；再逐字形把覆盖率写入 A 通道（零覆盖率跳过）、并登记该字形度量（`uv` / `x0` / `y0 = 偏移 + baseline` / `x1` / `y1` / `has_ink = true`）、随后 `stbtt_FreeBitmap(item.bitmap, nullptr)`。
9. **上传图集**：`texture->texture_create_from_memory(atlas_texture, pixels.data(), 512, atlas_height)`；失败 → `error("字体:: 字形图集纹理创建失败 {}")` 返回假。
10. **登记记录**：填 `pixel_height` / `baseline` / `atlas_texture` / `atlas_width` / `atlas_height` / `valid = true`。
11. **分配句柄**：扫描 `records` **复用第一个空槽**（写记录、`handle = index + 1`、`break`）；无空槽则 `push_back` 并 `handle = records.size()`。
12. 写出 `handle_out = handle`，记 `info("字体:: 已加载 {}（字号 {}，图集 {}×{}，句柄 {}）")`，返回真。

**异常 / 边界分支**：文件不存在 / 为空 / 读失败 / 解析失败 / 字形过宽 / 图集纹理创建失败 → 均返回假且句柄 0、无半初始化记录；空白字符不占图集空间、仅留 advance。

### 7.3 链路三：生成字符串文字几何

1. **调用方（门面 `text_draw`）** 取 `font_get(font)` 得 `const Font_Record*`，再调 `Font_Context::text_geometry_build(data, *record, text)`。
2. **进入**：清空 `data_out.vertices` / `data_out.indices`。
3. **前置**：`record.valid` 为假 → 返回假。
4. **循环**（`offset < text.size()`）：
   - **解码**：`utf8_decode(text, offset, codepoint)`；失败 → 已跳过 1 字节，`continue`；
   - **取度量**：`glyph_seek(record, codepoint)`；`nullptr`（码点越界）→ `continue`（**不推笔位**）；
   - **产出四边形**：若 `glyph.has_ink && x1 > x0 && y1 > y0` → 置 `any_ink = true`；按「左上 / 右上 / 右下 / 左下」写 4 顶点（`position = 像素坐标, z = 0`；`uv` = 图集 uv）；追加索引 `(base+0, base+2, base+1)` ＋ `(base+0, base+3, base+2)`；
   - **推进笔位**：`pen_x += glyph.advance`（**无论本字形是否有位图**——空白字符也推进）。
5. **收尾**：`!any_ink`（无任何可见字形）→ 清空出参并返回假；否则返回真。

**异常 / 边界分支**：空串 → 循环直接不执行 → 无可见字形 → 返回假；全空白 → 只推笔位、`any_ink` 恒假 → 返回假；畸形 UTF-8 → 逐字节跳过、其余码点继续；不支持码点 → 跳过且不推笔位。

### 7.4 链路四：单条字体销毁

1. **调用方（门面 `font_unload`）** 先清除该字体的**文本网格缓存**并归还网格（门面侧），再调 `font.font_destroy(handle)`。
2. **`font_destroy`**：句柄无效（`0` 或超界）→ 直接返回；目标记录 `!valid` → 直接返回（幂等）。
3. 否则：`texture != nullptr && atlas_texture != 0` → `texture->texture_destroy(atlas_texture)`；`record = Font_Record{}`（标记槽为空）。
4. 记 `info("字体:: 已销毁（句柄 {}）")`。

### 7.5 链路五：整体销毁

1. **调用方（门面 `shutdown`）** 在归还文本网格、销毁网格模块**之后**、销毁纹理模块**之前**调 `font.destroy()`。
2. **`destroy`**：遍历 `records`，逐条 `texture->texture_destroy(atlas_texture)`（`texture` 非空且句柄非 0 时）并 `record = Font_Record{}`；`records.clear()`；`texture = nullptr`。
3. **析构兜底**：`~Font_Context` 再调一次 `destroy`（此时集合已空、`texture` 已空，为无操作）。

### 7.6 与门面 / 网格 / 纹理 / 管线对接

本模块**不自行绘制**，其产出经门面接向网格、纹理与管线三模块（门面侧细节见《渲染层-门面》§6.13，此处只记交接点）：

1. **图集 → 纹理模块**：`font_load_file` 内 `texture_create_from_memory` 上传；销毁时 `texture_destroy` 归还。
2. **几何 → 网格模块**：门面 `text_draw` 调 `text_geometry_build` 得 `Mesh_Data`，随后 `mesh.mesh_create` 上传为网格，并以「(字体句柄, 文本) → 网格句柄」缓存（`Impl::text_meshes`）；`font_unload` 时按字体句柄**清除缓存并归还网格**。
3. **图集 → 管线描述符集**：门面 `text_draw` 以 `texture_bind_set(record->atlas_texture)` 把字形图集绑为「当前纹理」（覆盖此前纹理绑定），使 `set1` 采到图集。
4. **几何 → 管线管线**：门面懒登记 `pipeline_load("文字.vert.spv", "文字.frag.spv", Blend_Mode::Alpha)`，并以 `pipeline_bind_set(text_pipeline)` 激活；随后构造像素→NDC 矩阵、`mesh_draw(mesh, 矩阵)`。
