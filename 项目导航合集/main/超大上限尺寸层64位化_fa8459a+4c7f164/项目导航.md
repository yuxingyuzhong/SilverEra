## 一、一句话定位

上一版次在案的「超大边长上限下的整数除零」被彻底修掉了：不是加一道防御，而是把**四叉树的「尺寸与由尺寸推导的范围」这一层整体升到 64 位**，同时保持对外接口仍是 32 位，因此**上层调用方一行都不用改**。一句话记法：**要升的只是树自己算得出来的那几个量，不是世界坐标。**


- 四层各自是**独立 git 仓库**，顶层仓库不跟踪它们的内容；因此下层有提交时顶层仓库不会有新提交。
- 远端统一为 `https://github.com/yuxingyuzhong/SilverEra.git`。
- ⚠️ 引擎层本地分支名 `main`、上游分支名 `engine`，**名字不一致**，`git push` 会被 `push.default=simple` 拦下，必须写显式 refspec：`git push sliverera main:engine`。测试层本地与上游同名（`test`），`git push sliverera test:test`。
- ⚠️ 提交信息含中文时用 `git commit -F <UTF-8 消息文件>`；**消息文件里主题与正文之间必须留一个空行**，否则 `git log --format=%s` 会把整段正文当成主题（本版次踩过一次，`--amend` 修正）。

### 2.2 层间消费方式

- 引擎层不依赖任何上层，只被上层通过「源码 include ＋ 链接静态库」消费。
- 测试层构建时**链接已构建的引擎层产物**（`引擎层/out/build/x64-Debug/lib/EngineCore.lib`），不重编引擎源码——因此改引擎后必须先编引擎层，再编测试层。

## 三、上版次遗留缺陷的收口

### 3.1 上一版次记的是什么

上一版次导航把崩点记为 `Quadtree_Manager/core/区块信息检索.hpp` 的 `excel_element_to_coord`（查询范围宽度不足一个 `block_size` 时 `width` 为 0），并判断「彻底解决需架构层调整」，用例 `Quadtree_Manager_Test.DISABLED_超大边长上限下区块检索次数正常` 保持禁用。

### 3.2 实测钉死的真实崩点（本版次更正）

真实主崩点在 `Quadtree_Manager/core/四叉树智能创建.hpp` 的 `prepare_smart_create_params`：

```cpp
int father_block_size = settings.max_tree_size;        // 2^33 按模 2^32 截断 → 0
int width = recta_range.right - recta_range.left + 1;  // = 1
if (width % father_block_size != 0)                    // 1 % 0 → SEH 0xC0000094
```

用最小复现程序实测：

```
[probe] 2^33 stored into int = 0
[probe] about to compute 1 % 0
[INFO] run_exit=-1073741676          # 即 0xC0000094（整数除零 SEH）
```

`excel_element_to_coord` 是**同一类隐患**（宽高为 0 时的除法），不是本站；两者本版次都清掉了。

### 3.3 修复方式

1. **尺寸层整体 64 位化**（见第四节）——把 `father_block_size` 一类量提升到 `int64_t`，截断从源头消失。
2. **零尺寸防御三处**：`prepare_smart_create_params` 补 `father_block_size <= 0` 与 `max_block_num_total <= 0 || max_block_size <= 0` 早退；`excel_element_to_coord` 补 `block_size == 0` 与 `width <= 0` 早退；`target_range_format` 补 `block_size == 0` 早退（`target_range_amend` 的防御上一版次已有）。
3. **乘法溢出防御**：`range_seek` 的 `total_num` 提升到 int64 并做 `want_row > INT64_MAX / want_col` 检查，越界直接返回。
4. **用例转正**：`DISABLED_` 前缀移除，更名 `超大边长上限下区块检索次数正常`，并补一次稳定 `seek` 断言。

## 四、尺寸层 64 位化的分层契约（本版次主线）

### 4.1 判据（唯一）

| 层 | 类型 | 具体对象 |
| --- | --- | --- |
| **对外公开接口** | `Point2i` / `Rect2i`（**不变**） | `Quadtree_Manager::seek`（单点／范围）、`qurdtree_build_smart`、`set_max_size` / `set_min_size`、`coord_set` 等 |
| **模块内部** | `Point2l` / `Rect2l`（新增） | 树边界范围、由尺寸推导的坐标、待查询区块坐标、树间范围计算、`tree_cache.ranges` |
| **回调契约** | `Point2l` | `callback` / `set_callback_manage` 的 `target`（申请扩大的目标坐标，在超大树上会超 int） |

口诀：**能由「树尺寸」推导出来的坐标一律 64 位；来自外界的世界坐标保持 32 位。** 因此系统层、游戏层对本次契约变化零感知（两处对四叉树 API 零引用）。

## 五、坐标类型契约（`坐标类型.h`）

| 类型 / 函数 | 定义 | 用途 |
| --- | --- | --- |
| `Point2i` | `Point2<int>` | 对外世界坐标、调用方入参 |
| `Point2d` | `Point2<double>` | 浮点运算中间量 |
| `Point2l` | `Point2<int64_t>` | 尺寸层坐标（本版次新增） |
| `Rect2i` | `Rect2<int>` | 对外范围入参 |
| `Rect2l` | `Rect2<int64_t>` | 树边界范围、区块范围（本版次新增） |
| `point_to_int` | `static_cast<int>(std::lround(...))` | 浮点 → 32 位定点 |
| `point_to_l` | `static_cast<int64_t>(std::llround(...))` | 浮点 → 64 位定点（本版次新增，取整口径与 `point_to_int` 一致） |
| `point_to_double` | 直接提升 | 定点 → 浮点（本版次补 `Point2l` 重载） |

**注意**：`Point2<T>` **没有跨精度转换构造**（`Point2i` 不能隐式或显式构造出 `Point2l`），跨精度转换必须**逐分量**做（`p_long.X = static_cast<int64_t>(p_int.X)`）。本版次有一处测试代码因此编译失败（`error C2440`），已改为逐分量比对。

## 七、遗留与约定

1. **超大树上的范围查询仍不作为承诺**：本版次用例只覆盖「建树 ＋ 单点检索」。在 `2^33` 边长树上做覆盖式范围查询会真实分配巨量区块，受内存物理限制；代码已加零尺寸与乘法溢出防御（越界直接返回），但**该行为的正确性未验证**。需要时另立版次评估。
2. **世界坐标仍受 int 约束**：对外接口保持 `Point2i`（±2^31）。这是刻意的分层取舍；若将来需要超 int 世界坐标，需再做一轮对外契约升级。
3. **残留的 32 位类型均为保留项**：如 `coord_set` 的 `Point2i`（对外契约面），非隐患。
4. **既有告警仍在案（均非本版次引入）**：
   - `Quadtree/core/区块信息检索.hpp(72)` `warning C4715`：`point_seekable_analyse` 不是所有控件路径都返回值
   - `Event_Broker/core/事件中转器.cpp(221)` `warning C4715`
   - 构建日志中另有 `warning C4005`（宏重定义，12 次）与 `warning C4828`（源文件在 `/utf-8` 下的无效字符，2 次）
5. **行尾约定**：引擎层仓库对 `Collision_Proxy/碰撞代理器.h` 等文件存在自动行尾归一（`autocrlf`）；测试层三份用例文件工作区为 LF、入库按既有规则，无实质差异。
