## 二、模块功能介绍

### 2.1 模块定位

「门面」位于渲染层源码目录 `Application/Renderer/src/render/Renderer/`，是整个渲染层 `Application/Renderer/` 的**唯一对外门面（Facade）**。上层（`Application/Test`、`Application/Game`、`Application/Editor` 等）在使用渲染层时，只与一个类打交道——`engine::Renderer`——其余十二个渲染子模块（平台 / 设备 / 内存 / 交换链 / 帧 / 着色器 / 管线 / 网格 / 纹理 / 渲染目标 / 字体 / UI 通道）与场景相机模块，均被该门面在内部持有、编排，对外完全不出现。

一句话概括：**本模块把「一整套 Vulkan 渲染基础设施 + 十三个子模块」收拢为一个只有「初始化 → 每帧渲染 → 关闭」三段式生命周期的门面对象，让上层用最少的函数调用完成窗口渲染，同时用 PIMPL 把 SDL3 / Vulkan / VMA 全部关进 `.cpp`，使上层编译单元看不到任何第三方类型。**

### 2.2 职责边界与解决的问题

`Renderer` 解决的问题可归纳为七点：

1. **PIMPL 收口——把渲染层的第三方依赖挡在层外**。对外主头 `渲染器.h` 只前置声明 `class Impl;` 与 `class Ui_Channel_Context;` 并持有 `std::unique_ptr<Impl>`，实现体 `Renderer::Impl` 定义在私有头 `core/渲染器实现.h` 中，只被 `core/渲染器.cpp` 包含。这样 `Renderer` 的尺寸与 ABI 稳定，上层头文件传递 `Renderer` 时不会顺带吃进 `<vulkan/vulkan.h>`、`<SDL3/SDL.h>`、`<vk_mem_alloc.h>`。对外主头里唯一被引入的跨模块类型是与渲染无关的引擎语义类型 `Mesh_Data` / `Mesh_Handle` / `Vertex`（来自 `render/Mesh/网格数据.h`，Vulkan-free）；而需要 Vulkan / SDL3 类型的 UI 通道接入面被隔离在**另一个公共扩展头** `渲染器_UI通道.h` 中（见 §3.4.19 与 §6.1、§6.8）。

2. **编排十三个子模块的生命周期**。`Renderer::Impl` 以**值成员**方式持有 `Platform_Context`、`Device_Context`、`Memory_Context`、`Swapchain_Context`、`Frame_Context`、`Shader_Context`、`Pipeline_Context`、`Mesh_Context`、`Texture_Context`、`Render_Target_Context`、`Font_Context`、`Ui_Channel_Context` 十二个上下文对象与一个 `Camera`（场景模块），并在 `init` 中按严格依赖顺序逐阶段构建，在 `shutdown` 中严格逆序销毁。子模块之间**不互相持有**（唯一例外：交换链 / 帧 / 网格 / 纹理在构建时接收内存模块或交换链模块的**引用**参数），所有跨模块的句柄传递都经由门面中转，从而让「模块之间只存在经门面撮合的依赖」，避免模块互相缠绕。

3. **固化「实例 → 表面 → 设备」的两段式启动顺序**。设备模块因「呈现队列族查询需要表面已存在」而两段化（`build_instance` 先于 `surface_build`，`build_device` 后于 `surface_build`）。门面在 `init` 中精确编排了这一交叉顺序（见 §2.4 与 §七.1），这是本模块最核心的编排知识。

4. **提供「一帧一调用」的帧循环门面**。`Renderer::frame_render()` 把「泵窗口事件 → 处理尺寸变化/最小化 → 按帧槽写场景 UBO → 填装描述符集 → 取图像/录制/提交/呈现（并把 UI 绘制回调交给帧模块）→ 帧计数」整条链路封装为一次调用，上层无需理解帧槽轮转、同步栅栏或交换链重建。

5. **提供资源装载与相机控制的语义化入口**。`mesh_load` / `mesh_unload` / `mesh_draw`、`texture_load` / `texture_load_checkerboard` / `texture_unload` / `texture_bind_set`、`camera_position_set` / `camera_target_set` / `camera_fov_set` / `camera_near_far_set` 把网格、纹理、相机三类资源的操作收敛为门面方法，上层只需处理 `Mesh_Handle` / `uint64_t` 这类不透明句柄与普通数值。

6. **作为渲染层唯一的 `VkResult` 检查出口的承载者**。`core/结果检查.h` 提供 `vk_result_name_get` / `vk_result_acceptable` / `vk_result_check` 三个函数，是全渲染层「所有 Vulkan 调用的唯一检查出口」，用于避免「有的地方查、有的地方不查」。该头物理上归属本模块（渲染器），被层内各模块的实现文件统一包含并使用。

7. **为上层接入 ImGui Vulkan 后端提供 UI 通道接线点**。门面在 `init` 末尾构建 UI 通道，把渲染层的实例 / 物理设备 / 逻辑设备 / 图形队列族与队列 / SDL 窗口 / 交换链图像数 / 颜色与深度格式等口径一次性交给 UI 通道；并把事件泵收到的 SDL 事件桥接到 UI 通道（供上层平台后端处理键鼠与文本输入），每帧再把 UI 绘制回调传入帧模块（供上层在场景渲染 pass 内绘制 UI）。**门面只负责接线，不代管 UI**——UI 通道的内部实现（信息结构、回调存取、事件分发）属同层「UI 通道」模块，见同层 `UI通道.md`。

### 2.3 在整体架构中的位置

```
        │  EngineCore：logger（日志系统运行包.h） + 预编译头 + 构建/层间契约│
        └──────────────────────────────────────────────────────────────┘
```

- **向上**：调用方只看见 `engine::Renderer` 与 `engine::Renderer_Config`，构造后调 `init`，循环调 `frame_render`，结束调 `shutdown`（或依赖析构）；如需接入 ImGui，另包含扩展头 `渲染器_UI通道.h` 并经 `ui_channel()` 取通道句柄。
- **向下（层内）**：编排十二个渲染子模块 + 场景相机的构建与销毁；调用 `结果检查.h` 完成全部 `VkResult` 检查。
- **向下（跨层）**：仅依赖 `EngineCore`（日志系统、预编译头、构建系统契约），**不**依赖 `EngineSystem`。

### 2.5 生命周期与状态机

`Renderer` 的生命周期为三段式，`shutdown` 幂等、可重复调用，析构兜底：

```
构造 Renderer()                ← 仅 new(std::nothrow) Impl，不建任何 GPU 资源
   → init(config)             ← 19 阶段：平台→实例→表面→设备→内存→交换链→（钳制在途帧数）→帧→着色器→管线→UBO→纹理→网格→渲染目标→字体→相机→UI 通道（＋事件桥接）
   → [每帧] frame_render()     ← 泵事件→处理尺寸→写 UBO→填描述符→取图/录制/提交/呈现 或 离屏渲染到目标（附 UI 回调）→帧计数
              mesh_draw(...)   ← 登记待绘制项（下一帧 frame_render 消费）
              texture_bind_set / camera_* ← 任意时刻可调（须同一线程）
              pipeline_load / pipeline_unload / pipeline_bind_set ← 具名管线登记 / 卸载 / 选择（登记失败不留半截句柄）
              render_target_create / render_target_destroy   ← 离屏目标创建 / 销毁
              render_target_set / texture_bind_target         ← 本帧渲染到目标 / 把目标颜色绑为当前纹理（闭环）
              font_load_file / font_unload                    ← 字体加载 / 卸载（卸载一并清除该字体的文本网格缓存并归还网格）
              text_draw(...)                                  ← 在窗口像素坐标处登记文字绘制项（懒登记文字管线；空文本返回真但不登记）
              sampler_anisotropy_supported / sampler_max_anisotropy ← 采样器各向异性能力查询（转发设备模块）
              ui_channel()     ← 取 UI 通道句柄（供上层注册事件/绘制回调）
   → shutdown()               ← 严格逆序销毁；幂等，可重复调用
   → 析构 ~Renderer()         ← 内部再调一次 shutdown（此时多为无操作）
```

- 状态机仅两态：**未初始化**与**已初始化**。`valid()` 判据为 `impl != nullptr && impl->initialized`。
- `init` 中任一阶段失败即调用 `shutdown()` 做**逆序回退**，不留下「半初始化」状态，并返回 `false`。
- `init` 在**已初始化**时记 `warn` 并直接返回 `true`（忽略重复初始化，**不重载配置**）。
- `Renderer` 不可拷贝、不可移动（`= delete`），因其持有 GPU 资源与线程亲和。
- **非线程安全**：所有调用须来自同一线程（`渲染器.h` 类注释标「见 `§4.5`」，即设计文档《渲染层架构设计》的公共面/生命周期章节，属设计期产物、未纳入本轮导航收录范围）。

### 3.4 逐条接口说明

#### 3.4.1 `Renderer(void)`

- **功能**：构造，**不创建任何 GPU 资源**。
- **参数**：无。
- **返回值**：无。
- **约束/行为**：以 `impl(new(std::nothrow) Impl())` 分配实现体；全面禁用异常，用 `std::nothrow`。若分配失败，`impl` 为空，后续 `init` 会记 `error` 并返回 `false`，其余查询接口对空 `impl` 有兜底。

#### 3.4.2 `~Renderer(void)`

- **功能**：析构，内部调用 `shutdown()`，保证资源不泄漏。
- **约束**：即使从未 `init` 或半初始化，析构也安全（`shutdown` 逐对象销毁，子模块 `destroy` 幂等）。

#### 3.4.3 拷贝与赋值（`= delete`）

- **功能**：显式删除拷贝构造与拷贝赋值。
- **约束**：类持有 GPU 资源与线程亲和，**不可拷贝、不可移动**（未声明移动，故移动亦不可用）。

#### 3.4.4 `bool init(const Renderer_Config& config)`

- **功能**：初始化整个渲染层——按依赖顺序构建十三个子模块并完成场景 UBO、默认纹理、UI 通道与事件桥接的准备工作。
- **参数**：`config`——渲染层配置（见 3.2）。
- **返回值**：`bool`——全部阶段成功返回 `true`；任一阶段失败走 `shutdown()` 逆序回退并返回 `false`；已初始化时返回 `true`（记 `warn`）。
- **约束与异常行为**：
  - **前置校验**：`impl == nullptr` → `error` + `false`；`impl->initialized` 已真 → `warn` + `true`（忽略重复）；`config.width == 0 || config.height == 0` → `error` + `false`；`config.frame_overlap < 1 || > 3` → `error` + `false`。
  - **Release 强制关校验层**：`Renderer_Config effective = config;` 后 `#ifdef NDEBUG` 令 `effective.validation = false;`（引用 `K21`）。
  - **十九个构建阶段**（详见 §七.1）：①`platform.build` ②`platform.instance_extensions_get` ③`device.build_instance` ④`platform.surface_build` ⑤`device.build_device` ⑥`memory.build` ⑦`swapchain.build` ⑦.5 钳制在途帧数（取 `swapchain.image_available_count_get()`，超出则下调 `effective.frame_overlap` 并 `warn`，K13）⑧`frame.build` ⑨`shader.build`+`directory_set` ⑩两次 `shader.module_load` ⑪`pipeline.build` ⑫`pipeline.pipeline_build` ⑬每帧槽场景 UBO（`memory.buffer_create`+`buffer_write`+`pipeline.scene_bind`）⑭`texture.build`+默认白纹理+`pipeline.texture_bind`（每槽）⑮`mesh.build` ⑯`render_target.build`（设备 / 图形族 / 图形队列 / 内存）⑰`font.build`（记录纹理模块；**本轮新增**）⑱`camera.aspect_set` ⑲`ui_channel.build` + `platform.event_forward_set`（事件泵→UI 通道桥接）。
  - 任一步失败：记 `error`（含阶段描述）并 `shutdown()` 后返回 `false`。
  - 成功：`impl->config = effective; impl->initialized = true;` 记 `info`（含校验层开/关）。
- **备注**：交换链尺寸取 `platform.window_size_get`，若得 `0` 则回退配置值（HiDPI 场景）。

#### 3.4.5 `void shutdown(void)`

- **功能**：关闭并释放全部资源，严格逆序销毁，复位状态。
- **参数**：无。**返回值**：无。
- **约束/行为**（顺序不可颠倒，详见 §7.6）：
  1. `impl == nullptr` 直接返回；
  2. `frame.destroy()`（保证在途帧结束）；
  3. **文本网格归还**（**本轮新增**）：`impl->mesh.valid()` 时遍历 `impl->text_meshes` 逐条 `mesh.mesh_destroy(record.mesh)` 归还文本网格，随后 `text_meshes.clear()` 并复位 `text_pipeline = 0`——文本网格依赖网格模块，须先归还；
  4. `mesh.destroy()`（网格缓冲依赖内存，先于 `memory`）；
  5. **字体模块 destroy**（**本轮新增**）：`font.destroy()` 归还全部字形图集纹理——图集纹理依赖纹理模块，须先归还；
  6. `texture.destroy()`（纹理依赖设备与内存，先于两者）；
  7. `render_target.destroy()`（离屏目标依赖设备与内存，先于两者；随后 `active_target = 0`）；
  8. 若 `memory.valid()`，逐槽 `memory.buffer_destroy(scene_ubos[slot], scene_ubo_allocs[slot])` 归还场景 UBO；随后清空两容器、`default_texture = 0`；
  9. `pipeline.destroy()`（依赖设备与内存，先于两者）；
  10. 若 `vert_module` / `frag_module` 非空，先 `shader.module_destroy` 并置空（**须先于 `shader.destroy()`**）；
  11. `shader.destroy()` → `swapchain.destroy()`（连带销毁深度图像，须在管线之后）→ `memory.destroy()` → **`platform.event_forward_clear()` → `platform.destroy()` → `device.destroy()`**（**先平台后设备**：平台持有「借用」的实例句柄，`vkDestroySurfaceKHR` 要求实例仍在途，而设备销毁会连带 `vkDestroyInstance`，故设备须排在平台之后；桥接须在平台销毁前解除，以免平台回调指向已销毁对象）；
  12. 清空 `pending_items` 与 `pending_transforms`；`ui_channel.destroy()`（复位 UI 通道信息与回调）；`frame_count = 0`；`initialized = false`。
- **幂等**：可重复调用；第二次及以后各子模块 `destroy` 均为无操作，状态已复位。

#### 3.4.6 `bool valid(void) const`

- **功能**：查询是否已初始化。
- **返回值**：`impl != nullptr && impl->initialized`。

#### 3.4.7 `bool frame_render(uint8_t* readback_pixels = nullptr, uint32_t readback_capacity = 0, uint32_t* readback_width = nullptr, uint32_t* readback_height = nullptr)`（本版次扩展）

- **功能**：推进一帧（泵事件 → 取图像 → 录制 → 提交 → 呈现 → 计数）；`readback_pixels` 非空时**额外**把本帧最终颜色附件回读到该主机缓冲（RGBA8 紧排、逐行自上而下），并经 `readback_width` / `readback_height` 回填尺寸。
- **返回值**：`bool`——成功（含「窗口请求退出」「窗口最小化」两处提前返回）返回 `true`；未初始化或硬错误返回 `false`；**请求回读但本帧未产出像素**（挂起帧 / 交换链过期跳过渲染）亦返回 `false`。
- **回读参数**：四个新形参**全为默认参数**，既有调用 `frame_render()` 完全不受影响；`readback_capacity` 须不小于「宽 × 高 × 4」，否则帧模块报错返假且**本帧不渲染**（帧计数不推进）。
- **约束/行为**（详见 §七.2）：
  - 未初始化 → `false`；
  - ① `platform.events_pump()`；
  - ②③ 若 `platform.close_requested() || platform.minimized()` → **清空 `pending_items` 与 `pending_transforms`** 后返回 `true`（两种挂起情形合并判断：请求退出交调用方收敛；最小化挂起本帧、避免 0×0 交换链，引用 `K7`；连续挂起期间不再累积待绘制项）；
  - `platform.window_size_get`；若 `platform.resized_consume()`（**含 `window_size_set` 显式所置**）且尺寸非零 → `swapchain_rebuild_deferred(width, height)`（内部 `swapchain.rebuild(width, height, old)` ＋ `frame.deferred_push(entry, frame.in_flight_count_get() + 1)`；失败仅 `warn`，本帧继续），随后 `pipeline.pipeline_rebuild(swapchain.format_get(), swapchain.depth_format_get())`（格式未变时空操作；失败仅 `warn`），置 `rebuilt = true`（`K8`：每帧最多重建一次）；
  - 刷新 `camera.aspect_set`（取 `swapchain.extent_get`）；
  - 取 `slot = frame.slot_index_get()`；
  - `frame.slot_wait()`（**必须在写本帧槽 UBO 之前**，避免覆盖 GPU 仍在读的上一轮 UBO）；失败 → `error` + `false`；
  - `camera.view_proj_get` → `memory.buffer_write(scene_ubos[slot], ...)`；失败 → `error` + `false`；**本帧槽 `set0` 无需重写**（各帧槽 UBO 缓冲句柄自 `init` 起恒定、`set0` 已在 `init` 一次性写入，本轮已移除每帧 `pipeline.scene_bind` 调用）；
  - 遍历 `pending_items` 填装 `scene_set = pipeline.scene_set_get(slot)`、`sampler_set = pipeline.sampler_set_get(slot)`、`descriptor_set_count = 2`；
  - `frame.render(swapchain, pending_items.data(), size, rebuild_needed, clear_color, ui_channel.draw_callback_get(), readback_ptr)`；失败 → `error` + `false`；`clear_color = impl->clear_color`（**第九轮起为门面记录值**，初值 `{0.05, 0.05, 0.10, 1.0}`）；**本轮已有把 UI 绘制回调（未注册时为 `nullptr`）传入帧模块**，供其在场景 pass 结束后交还上层绘制 UI；末位 `readback_ptr` 为**本版次新增**（未请求回读时为 `nullptr`）；
  - **像素回读（本版次新增）**：进入 `frame.render` 前先复位 `*readback_width` / `*readback_height` 为 `0`；`readback_pixels != nullptr` 时组装 `Frame_Readback_Request`（`pixels` / `capacity` 取自入参）并把其地址作为末位实参；返回后若 `request.bytes == 0`（挂起帧或交换链过期跳过渲染）→ `error` + `false`（尺寸出参保持零），否则回填 `*readback_width` / `*readback_height`；入参为 `nullptr` 时整条回读路径不参与，行为与扩展前一致；
  - `pending_items.clear()` 与 `pending_transforms.clear()`（消费完毕，下一帧由 `mesh_draw` 重新登记）；若 `rebuild_needed && !rebuilt` 且尺寸非零 → `swapchain.rebuild` 后同法调 `pipeline.pipeline_rebuild(...)`（失败仅 `warn`）；
  - `++frame_count`；返回 `true`。

#### 3.4.8 `bool close_requested(void) const`

- **功能**：窗口是否请求退出。
- **返回值**：`bool`——`impl == nullptr` 时 `false`；否则 `platform.close_requested()`。

#### 3.4.9 `uint64_t frame_count(void) const`

- **功能**：已呈现帧数（调试与用例断言用）。
- **返回值**：`impl == nullptr` 时 `0`；否则 `impl->frame_count`（每成功 `frame_render` 自增）。

#### 3.4.10 `uint32_t extent_width(void) const` / `uint32_t extent_height(void) const`

- **功能**：当前交换链尺寸（窗口缩放后可能变化）。
- **返回值**：`impl == nullptr` 时 `0`；否则 `swapchain.extent_get().width` / `.height`。

#### 3.4.11 `bool mesh_load(Mesh_Handle& handle_out, const Mesh_Data& data)`

- **功能**：加载网格（顶点/索引共用缓冲上传至设备本地）。
- **参数**：`handle_out`——输出句柄；`data`——`Mesh_Data`（`Vertex` 集合 + 索引集合）。
- **返回值**：`bool`——成功 `true` 并写出句柄；失败 `false`，句柄保持无效（`0`）。
- **约束**：未初始化 → `error` + `false`；否则转 `mesh.mesh_create`。

#### 3.4.12 `void mesh_unload(Mesh_Handle handle)`

- **功能**：卸载网格。
- **参数**：`handle`——网格句柄。
- **约束**：未初始化直接返回；否则转 `mesh.mesh_destroy(handle)`。

#### 3.4.13 `bool mesh_draw(Mesh_Handle handle, const float* transform)`

- **功能**：登记一个待绘制项（实际绘制在下一帧 `frame_render` 时发生）；**同帧可多次调用以登记多个网格**，各网格持有各自模型矩阵。
- **参数**：`handle`——网格句柄；`transform`——列主序 16 浮点模型矩阵，**可为 `nullptr`** 表示单位矩阵。
- **返回值**：`bool`——成功 `true`；未初始化或句柄无效 `false`。
- **约束/行为**：
  - 未初始化 → `error` + `false`；
  - `mesh.mesh_record_get(handle, mesh_buffer, index_offset, index_count)` 取**共用缓冲、索引区字节偏移与索引数**；句柄无效 → `error` + `false`；
  - `impl->pending_transforms.emplace_back()` 追加一块独立的列主序 16 浮点存储（`std::deque<std::array<float,16>>`；`push_back` 不使既有元素地址失效，故同帧内各块地址稳定）；`transform == nullptr` 写单位矩阵，否则拷贝 16 浮点；
  - 组装 `Frame_Render_Item`：`pipeline`/`layout` 取自 `pipeline.pipeline_get()`/`layout_get()`（**`pipeline_get()` 本版次起返回当前激活管线**，故该项所挂管线取决于此前最近一次 `pipeline_bind_set`），`vertex_buffer = index_buffer = mesh_buffer`（**顶点与索引共用同一缓冲**）、`index_offset = index_offset`、`index_count = index_count`，`scene_set`/`sampler_set` 先置空、`descriptor_set_count = 0`（延迟到 `frame_render` 按本帧槽填装），`push_constants = 该块存储的 data()`、`push_constant_size = 64`；
  - `pending_items.push_back(item)`（**不再先 `clear()`**）——同帧可累积多个，直到 `frame_render` 消费后统一清空。

#### 3.4.14 `bool texture_load(uint64_t& handle_out, const uint8_t* pixels, uint32_t width, uint32_t height)`

- **功能**：纹理加载（RGBA8 紧排像素）。
- **参数**：`handle_out`；`pixels`（RGBA8 紧排）；`width` / `height`。
- **返回值**：`bool`——成功 `true` 并写出句柄；失败 `false`。
- **约束**：进入即 `handle_out = 0`；未初始化 → `error` + `false`（句柄保持 0）；否则转 `texture.texture_create_from_memory`。

#### 3.4.15 `bool texture_load_checkerboard(uint64_t& handle_out, uint32_t width, uint32_t height, uint32_t cell_size)`

- **功能**：程序生成棋盘格纹理。
- **参数**：`handle_out`；`width` / `height` / `cell_size`。
- **返回值**：`bool`——成功 `true` 并写出句柄；失败 `false`。
- **约束**：进入即 `handle_out = 0`；未初始化 → `error` + `false`；否则转 `texture.texture_create_checkerboard`。

#### 3.4.16 `void texture_unload(uint64_t handle)`

- **功能**：卸载纹理（转发纹理模块的 `texture_destroy`）。
- **参数**：`handle`——纹理句柄，无效则忽略。
- **返回值**：无。
- **约束/行为**：未初始化（`impl == nullptr || !impl->initialized`）直接返回；否则转 `impl->texture.texture_destroy(handle)`。
- **使用约束**：`texture_unload` 只销毁纹理资源、不自动改写各帧槽 `set1`；**绑定过该纹理的帧槽需由调用方重新 `texture_bind_set`** 指定新的绑定纹理。

#### 3.4.17 `void texture_bind_set(uint64_t texture_handle)`

- **功能**：设置当前绘制所用纹理（写所有帧槽 `set1`）。
- **参数**：`texture_handle`——纹理句柄，**传 `0` 或无效句柄则回落内置默认白纹理**。
- **约束/行为**：未初始化直接返回；目标 = `texture_handle == 0 ? impl->default_texture : texture_handle`；`texture_bind_get` 取视图/采样器，失败则回落 `default_texture`，仍失败记 `error` 返回；**对全部 `[0, config.frame_overlap)` 帧槽**调 `pipeline.texture_bind(slot, sampler, view)`——只把目标纹理写入各帧槽 `set1`（原 `current_texture` 成员已删除：纹理实际由描述符集 `set1` 与绘制项承载，该字段无消费点）。
- **注意**：该函数是**立即写描述符**，若此刻存在在途帧正在使用对应 `set1`，属跨帧争用。

#### 3.4.18 相机四个设置接口

- `void camera_position_set(float x, float y, float z)`——设置相机位置；未初始化直接返回；转 `camera.position_set`。
- `void camera_target_set(float x, float y, float z)`——设置注视点；转 `camera.target_set`。
- `void camera_fov_set(float radians)`——设置视场角（弧度）；转 `camera.fov_set`。
- `void camera_near_far_set(float near_plane, float far_plane)`——设置近远平面；转 `camera.near_far_set`。
- **共同约束**：均在未初始化时静默返回；`camera.up_set` / `camera.orbit` **未**对外暴露（门面不转发）。

#### 3.4.19 `Ui_Channel_Context* ui_channel(void)`（本轮新增）

- **功能**：返回渲染层持有的 UI 通道句柄，供上层接入 ImGui Vulkan 后端。
- **参数**：无。**返回值**：`Ui_Channel_Context*`——实现体已分配时返回 `&impl->ui_channel`；`impl == nullptr`（构造分配失败）时返回 `nullptr`。
- **约束/行为**：
  - 仅当实现体未分配（`impl == nullptr`）时返回空；其余情形（含尚未 `init` 或已 `shutdown`）均返回指向 `impl->ui_channel` 的指针，此时通道未必已构建，调用方应以 `Ui_Channel_Context::valid()` 佐判（与头注释「未初始化时返回空」的口径以**实现为准**）。
  - 返回非 `const` 指针，供上层注册事件/绘制回调（`draw_callback_set` / `event_callback_set`）。**门面不代管 UI**：UI 通道类型定义、内部字段与方法语义见同层 `UI通道.md`，本文不展开。
  - 使用前上层须自行包含公共扩展头 `渲染器_UI通道.h`（含 Vulkan / SDL3 类型，`渲染器.h` 本身不引入）。

#### 3.4.20 `bool readback_supported(void) const`（本版次新增）

- **功能**：查询本机交换链图像是否具备传输源用法，即像素回读是否可用。
- **参数**：无。**返回值**：`bool`——未初始化（`impl == nullptr || !impl->initialized`）时为 `false`；否则取 `impl->swapchain.color_transfer_src_get()`。
- **用途**：上层（含用例）据此决定是否请求回读，避免在能力缺失的驱动上做无谓调用并产生错误日志。

#### 3.4.21 `void blend_mode_set(Blend_Mode mode)`（本版次新增）

- **功能**：设置后续绘制所用混合档（`Blend_Mode::Opaque` / `Blend_Mode::Alpha`）；档位语义与管线侧实现见《渲染层-管线》§3.3.7。
- **参数**：`mode`——混合档；枚举 `Blend_Mode` 声明于管线模块共用头 `Application/Renderer/src/render/Pipeline/管线数据.h`（Vulkan-free），门面公共头已包含之，故**公共面仍零 Vulkan 类型**。
- **返回值**：无（`void`）。未初始化直接返回；**同档重复调用为空操作**。
- **档位作用域（本版次收敛）**：本方法**只作用于默认场景管线**（句柄 0）的混合档——转调 `pipeline.pipeline_default_blend_set(mode)`（内部先 `vkDeviceWaitIdle`，故**应在帧与帧之间调用**）。**具名管线的混合档在 `pipeline_load` 登记时确定、不受本方法影响**。
- **关键行为**：同档重复调用为空操作；异档时成功才更新 `Impl::blend_mode`，失败记 `logger.error("渲染器:: 混合档切换失败（保持已记录档位 {}）")` 并保持档位记录（此时图形管线可能已不可用：本帧仍会清屏与推进、仅绘制项跳过，**不改变帧循环时序**）。
- **与交换链重建的关系**：门面在两处「尺寸事件重建」路径改调**两参** `pipeline_rebuild(color, depth)`（按新格式重建**全部**已登记管线，各管线混合档保留），不再传 `blend_mode`；见 §6.6（易错点，见 §6.10）。

#### 3.4.22 `bool mesh_draw_instanced(Mesh_Handle handle, const float* transforms, uint32_t count)`（本版次新增）

- **功能**：实例化绘制——同一网格 × `count` 个模型矩阵**一次**绘制提交。
- **参数**：`handle` 网格句柄；`transforms` 为 `count` 个「列主序 16 浮点模型矩阵」的连续存储（共 `count × 16` 个浮点，可为 `nullptr` 表整批单位矩阵）；`count` 实例数。
- **返回值**：`bool`——未初始化 / `count == 0` / 句柄无效 / **本帧实例矩阵存储不足**均返回假，且**不登记任何绘制项**（不产生半截绘制）。
- **实现要点**：把整批矩阵追加进 `Impl::pending_instances`（本帧全部实例矩阵连续存放），并登记**一个**渲染项（`instance_count = count`、`instance_offset = 追加起点字节偏移`）；帧槽实例缓冲句柄在 `frame_render` 时统一填装。
- **容量**：每帧槽实例缓冲容量 = `Impl::instance_capacity`（**256 个矩阵**）；超限整体拒绝，不静默截断。
- **与 `mesh_draw` 的关系**：`mesh_draw` 现为「`count = 1` 的实例路径」（内部追加 1 个矩阵），管线已恒定声明实例属性，故二者共用同一条绘制路径。

#### 3.4.23 `bool texture_load_file(uint64_t& handle_out, const std::string& path)`（本版次新增）

- **功能**：从文件加载纹理（PNG / JPG / BMP 等经外部库 `stb_image` 解码为 RGBA8 后上传）。
- **参数**：`handle_out` 出参句柄；`path` 文件路径。
- **返回值**：`bool`——未初始化 / 文件不存在 / 文件为空 / 解码失败 → 假，句柄保持 0；成功 → 真并写出句柄。
- **实现要点**：转交纹理模块 `texture_create_from_file`（解码在 `core/纹理解码.cpp`，全层唯一 `STB_IMAGE_IMPLEMENTATION`）。

#### 3.4.24 `void texture_sampler_state_set(const Texture_Sampler_State& state)`（本版次新增）

- **功能**：设置纹理采样器状态（`Texture_Address_Mode` 寻址模式 ＋ `mip_filter` 是否启用 mip 过滤 ＋ **细节层级范围 `min_lod` / `max_lod`** ＋ **各向异性 `anisotropy` / `max_anisotropy`**）。
- **返回值**：无。未初始化静默返回；同状态重复调用为空操作。
- **关键行为（与描述符集的耦合；本轮起）**：采样器被**烘焙进各帧槽 `set1`**，故本方法在切换状态后**必须重写全部帧槽 `set1`**——实现上以 `Impl::bound_view`（**当前绑定视图**，纹理与渲染目标**共用该语义**；未绑过任何源时回落内置默认白纹理视图）为采样源，配合重建后的共享采样器重写 `set1`（不再按纹理句柄回落重绑，故不覆盖渲染目标绑定）。**调用应发生在帧与帧之间**。
- **类型落点**：`Texture_Sampler_State` / `Texture_Address_Mode` 声明于纹理模块共用头 `Application/Renderer/src/render/Texture/纹理数据.h`（Vulkan-free），门面公共头已包含之，故公共面仍零 Vulkan 类型。
- **本轮扩展——入参按设备能力归一（**本轮新增**）**：在转交纹理模块之前，门面先把入参按**设备能力**归一为 `Texture_Sampler_State effective`：① 若 `state.anisotropy` 为真而设备未启用 `samplerAnisotropy` 特性（`impl->device.anisotropy_enabled_get()` 为假），记 `logger.warn("渲染器:: 设备不支持采样器各向异性，本次请求已忽略")` 并令 `effective.anisotropy = false`、`effective.max_anisotropy = 1.0f`；② 启用时把倍数钳到 `[1, impl->device.max_anisotropy_get()]`（上限来自设备 `limits.maxSamplerAnisotropy`）。随后以**归一后**状态调 `impl->texture.sampler_state_set(effective)`——纹理模块对「同状态」的判据为**逐字段比较**（含 `min_lod` / `max_lod` / `anisotropy` / `max_anisotropy`），否则「只改各向异性」会被误判为空操作；随后**先 `impl->frame.frames_wait()` 收口全部在途帧**（避免销毁 / 重建仍被在途命令缓冲引用的旧采样器），再以 `{ 重建后的共享采样器, impl->bound_view（或默认白纹理视图） }` 重写全部帧槽 `set1`。设备能力口径见《渲染层-设备》§3.4 / §6.7。

#### 3.4.25 `bool pipeline_load(uint64_t& handle_out, const std::string& vert_shader, const std::string& frag_shader, Blend_Mode blend_mode = Blend_Mode::Opaque)`（本版次新增）

- **功能**：登记一条**具名图形管线**（以**文件名**给出两着色器）。
- **参数**：`handle_out`（出参，默认置 0；成功写出句柄 ≥ 1）；`vert_shader` / `frag_shader` 着色器文件名（相对着色器目录）；`blend_mode` 混合档（默认 `Opaque`）。
- **返回值**：`bool`——成功 `true`；未初始化 / 着色器加载失败 / 图形管线创建失败均 `false`，句柄保持 0，**且已加载的着色器模块被回收，不泄漏**。
- **关键行为**：① `shader.module_load(vert_module, vert_shader)` → ② `shader.module_load(frag_module, frag_shader)`（失败即回收 `vert_module`）→ ③ `pipeline.pipeline_register(handle, vert_module, frag_module, blend_mode)`（失败即回收两模块）→ ④ 把 `Extra_Pipeline_Record{handle, vert_module, frag_module}` 记入 `Impl::extra_pipelines`（**着色器模块所有权在门面**）。
- **语义范围**：具名管线与默认场景管线共享同一管线布局与描述符集布局，仅「着色器对 ＋ 混合档」不同；登记**不改变当前激活管线**。

#### 3.4.26 `void pipeline_unload(uint64_t handle)`（本版次新增）

- **功能**：卸载一条具名管线。
- **约束/行为**：未初始化直接返回；句柄 0（默认管线）直接返回；在 `Impl::extra_pipelines` 中查找目标：命中则 `pipeline.pipeline_release(handle)`（销毁图形管线）→ `shader.module_destroy(vert/frag)` 销毁两着色器模块 → `erase` 记录；**若卸载的正是当前所选（`bound_pipeline_request == handle`）则回落默认场景管线**（`bound_pipeline_request = 0` 且 `pipeline.pipeline_activate(0)`）。卸载后该句柄失效。

#### 3.4.27 `void pipeline_bind_set(uint64_t handle)`（本版次新增）

- **功能**：设置后续绘制所用图形管线（`0` = 默认场景管线）。
- **约束/行为**：未初始化直接返回；句柄非零且未登记（`!pipeline.pipeline_has(handle)`）则记 `logger.warn("渲染器:: 管线句柄 {} 未登记，回落默认场景管线")` 并把目标置 0；`pipeline.pipeline_activate(target)`（失败保持原激活不变）；成功记录 `Impl::bound_pipeline_request = target`。
- **关联**：`mesh_draw` / `mesh_draw_instanced` 取 `pipeline_get()`（当前激活管线），故**切换须在登记绘制项之前完成**。

#### 3.4.28 `bool render_target_create(uint64_t& handle_out, uint32_t width, uint32_t height)`（本版次新增）

- **功能**：创建离屏渲染目标（颜色 ＋ 深度；颜色可作纹理采样，内容可像素回读）。
- **参数**：`handle_out`（出参，默认 0）；`width` / `height` 目标尺寸。
- **返回值**：`bool`——未初始化 / 参数非法 / 资源创建失败均 `false`，句柄保持 0，不留半初始化资源。
- **实现**：转交 `render_target.target_create(handle_out, width, height, swapchain.format_get(), swapchain.depth_format_get())`（**颜色 / 深度格式取当前交换链格式**）。

#### 3.4.29 `void render_target_destroy(uint64_t handle)`（本版次新增）

- **功能**：销毁离屏渲染目标。
- **约束/行为**：未初始化直接返回；**若销毁的是当前设定的本帧渲染目标（`active_target == handle`）则先把 `active_target` 置 0（回落交换链路径）**，再转 `render_target.target_destroy(handle)`。

#### 3.4.30 `void render_target_set(uint64_t handle)`（本版次新增）

- **功能**：设置「本帧渲染到目标」——`0` = 渲染到交换链（默认）；否则本帧把场景渲染进该目标且**不呈现到窗口**。
- **约束/行为**：未初始化直接返回；句柄非零且未登记（`!render_target.target_valid(handle)`）则记 `logger.warn("渲染器:: 渲染目标句柄 {} 无效，回落交换链路径")` 并把 `active_target` 置 0；否则 `active_target = handle`。
- **语义**：离屏结果帧间恒处于可采样布局，可用 `texture_bind_target` 在后续帧采样合成（后处理闭环）；每帧调用 `frame_render` 时按三路互斥分派路径（`present_target` 优先，见 §7.2）。

#### 3.4.31 `void texture_bind_target(uint64_t handle)`（本版次新增）

- **功能**：把指定渲染目标的颜色视图绑定为「当前纹理」（供后续绘制采样）。
- **约束/行为**：未初始化直接返回；`render_target.target_get(handle, color_image, color_view, depth_view, extent)` 取目标颜色视图——**句柄无效则静默返回（保持原绑定不变）**；借内置默认白纹理取一次**共享采样器**（`texture.texture_bind_get(default_texture, ...)`，不可用则记 `error` 返回）；**记录 `bound_view = 目标颜色视图`（本轮起）**；**写满全部帧槽 `set1` 前先 `frame.frames_wait()`（本轮新增，收口在途帧）**；随后以「目标颜色视图 ＋ 该采样器」对**全部帧槽**调 `pipeline.texture_bind(slot, sampler, color_view)`。
- **对当前绑定视图的影响（本轮起；R-FACADE-06 结案）**：本方法以 `bound_view = 目标颜色视图` 记录「当前绑定视图」（与 `texture_bind_set` 共用该语义）；故事后调用 `texture_sampler_state_set` 会以 `{新采样器, bound_view}` 重写全部帧槽 `set1`，**不再按纹理句柄回落而覆盖目标绑定**（见 §6.10 易错点 18 / §6.15）。

#### 3.4.32 `bool font_load_file(uint64_t& handle_out, const std::string& path, uint32_t pixel_height)`（本轮新增）

- **功能**：从字体文件加载字体并构建 ASCII 字形图集（转交字体模块）。
- **参数**：`handle_out`（出参，进入即置 `0`）；`path`（字体文件路径）；`pixel_height`（字号 / 字形像素高度）。
- **返回值**：`bool`——未初始化（`impl == nullptr || !impl->initialized`）返回假并记 `error("渲染器:: 加载字体失败：尚未初始化")`，**句柄保持 0**；否则转 `impl->font.font_load_file(handle_out, path, pixel_height)`（其失败路径亦保持句柄 0）。
- **实现要点**：TTF 解析 / 字形光栅化 / 行式打包 / 图集纹理上传均在字体模块（见《渲染层-文字》§7.2）。

#### 3.4.33 `void font_unload(uint64_t handle)`（本轮新增）

- **功能**：卸载字体（一并清除其文本网格缓存并归还网格）。
- **约束/行为**：未初始化直接返回；**① 先清除该字体的文本网格缓存并归还网格**——遍历 `Impl::text_meshes`，凡 `record.font == handle` 者在 `impl->mesh.valid()` 时 `mesh.mesh_destroy(record.mesh)` 并从集合移除；**② 再**调 `impl->font.font_destroy(handle)`（归还字形图集纹理）。
- **顺序口径（不可颠倒）**：文本网格依赖网格模块、字形图集纹理依赖纹理模块，故须**先归还网格、再销毁字体**；否则会留下指向已销毁记录的网格缓存，或在网格模块销毁前使图集纹理失去归还点。

#### 3.4.34 `bool text_draw(uint64_t font, const std::string& text, float pixel_x, float pixel_y)`（本轮新增）

- **功能**：在窗口**像素坐标**处登记一段文字的绘制项（实际绘制在下一帧 `frame_render` 时发生）。
- **参数**：`font`（字体句柄）；`text`（UTF-8 文本）；`pixel_x` / `pixel_y`（**文本左上角**在窗口内的像素坐标；**原点窗口左上、Y 向下**）。
- **返回值**：`bool`——未初始化 / 字体句柄无效 / 文本无可见字形 / 交换链尺寸非法 → 假；**空文本返回真但不登记绘制项**；成功返回真。
- **实现流程**：① 取 `record = impl->font.font_get(font)`，为空即记 `error("渲染器:: 文字绘制失败：字体句柄 {} 无效")` 返回假；② `text.empty()` → 直接返回真（不登记绘制项）；③ **懒登记文字管线**：`Impl::text_pipeline == 0` 时调 `pipeline_load(handle, "文字.vert.spv", "文字.frag.spv", Blend_Mode::Alpha)`，失败记 `error("渲染器:: 文字管线登记失败")` 返回假，成功把句柄缓存于 `Impl::text_pipeline`（登记结果缓存，后续不再重建）；④ **取 / 建网格**：在 `Impl::text_meshes` 中按 `(font, text)` 命中则复用；未命中则 `Font_Context::text_geometry_build(data, *record, text)`（失败记 `error("渲染器:: 文字几何生成失败（文本无可见字形）")` 返回假）→ `mesh.mesh_create(mesh, data)`（失败记 `error("渲染器:: 文字网格创建失败")` 返回假）→ 以 `Impl::Text_Mesh_Record{font, text, mesh}` 记入缓存；⑤ `pipeline_bind_set(impl->text_pipeline)` ＋ `texture_bind_set(record->atlas_texture)`（**把字形图集绑为「当前纹理」**）；⑥ 取 `extent_width()` / `extent_height()`，任一 `<= 0` 记 `error("渲染器:: 文字绘制失败：交换链尺寸非法")` 返回假；⑦ 构造**像素→NDC 仿射矩阵（列主序、不做 Y 翻转）**：`m[0] = 2/W`、`m[5] = 2/H`、`m[10] = 1`、`m[12] = 2·pixel_x/W − 1`、`m[13] = 2·pixel_y/H − 1`、`m[15] = 1`；⑧ `mesh_draw(mesh, transform.data())` 登记绘制项并返回其结果。
- **关键口径**：矩阵**不做 Y 翻转**（主块行列式 > 0），与文字几何的「像素 Y 向下」口径配合，故文字四边形索引绕序与场景相反（见《渲染层-文字》§6.4 / §6.6）。
- **已知边界**：本方法会把字形图集绑为「当前纹理」，**覆盖此前纹理绑定**（若后续场景绘制未重新 `texture_bind_set`，将采到字形图集）；文字项与场景项**共享同一实例缓冲与描述符集**（见 §6.13 与附录 D 的 `R-FACADE-07`）。

#### 3.4.35 `bool sampler_anisotropy_supported(void) const`（本轮新增）

- **功能**：查询本机逻辑设备是否启用了采样器各向异性特性。
- **返回值**：`bool`——未初始化（`impl == nullptr || !impl->initialized`）时为 `false`；否则取 `impl->device.anisotropy_enabled_get()`（**转发设备模块**，见《渲染层-设备》§3.7）。

#### 3.4.36 `float sampler_max_anisotropy(void) const`（本轮新增）

- **功能**：查询采样器最大各向异性倍数（设备上限）。
- **返回值**：`float`——未初始化时为 `1.0`；否则取 `impl->device.max_anisotropy_get()`（**转发设备模块**；设备未启用该特性时按 `1.0`）。

#### 3.4.37 `void render_target_present_set(uint64_t handle)`（本轮新增）

- **功能**：设置「本帧渲染到目标并同帧后处理呈现到交换链」（同帧多 pass）——`0` 关闭（回到 `render_target_set` 决定的默认路径）；句柄有效时本帧把场景渲染进该目标，随即在**同一命令缓冲内**以该目标为纹理做一次全屏后处理 pass 直接呈现到窗口。
- **约束/行为**：未初始化直接返回；句柄非零且未登记（`!render_target.target_valid(handle)`）则记 `logger.warn("渲染器:: 渲染目标句柄 {} 无效，关闭同帧后处理呈现路径")` 并把 `present_target` 置 0；否则 `present_target = handle`。
- **优先级**：**优先于 `render_target_set` 生效**——`frame_render` 分派时先判 `present_target`（见 §7.2）。该路径**不经过 UI 回调**（见《渲染层-帧》§3.14）。
- **硬性要求**：**目标范围须与交换链范围一致**（后处理按帧缓冲坐标 1:1 取源），故通常以当前交换链尺寸创建目标（`render_target_create(handle, extent_width(), extent_height())`）。

#### 3.4.38 `bool window_size_set(uint32_t width, uint32_t height)`（本轮新增）

- **功能**：请求改变窗口客户区尺寸（像素），转交平台层（`impl->platform.window_size_set`）。
- **返回值**：`bool`——未初始化（`impl == nullptr || !impl->initialized`）返回假并记 `error("渲染器:: 窗口尺寸设置失败：尚未初始化")`；否则转交平台层，其返回值即为本函数返回值（窗口未创建 / 尺寸为零 / SDL 调用失败时为假）。
- **语义**：成功即由平台层置「交换链待重建」标志，**交换链重建在下一次 `frame_render` 内完成**（见 §7.2 与《渲染层-平台与表面》§3.17）。使「尺寸变化 → 交换链重建」可由上层驱动、可被用例构造。

#### 3.4.39 `bool material_load(Material_Handle& handle_out, const Material_Data& data)`（本轮新增）

- **功能**：登记材质（图形管线 ＋ 纹理 ＋ 混合档），写出材质句柄。
- **参数**：`handle_out` 出参，进入即置 0，成功写出句柄（≥ 1）；`data` 为 `Material_Data`（见《渲染层-管线》§3.5）。
- **返回值**：`bool`——未初始化 / 具名管线登记失败时返回假、句柄保持 0、**不留半初始化记录**。
- **行为（源码顺序）**：① `handle_out = 0`；② 未初始化 → `error` + 假；③ 组装 `Impl::Material_Record{pipeline = data.pipeline, texture = data.texture}`；④ **若 `pipeline == 0` 且 `blend != Opaque`（第九轮改为「按混合档缓存复用」）** → 以 `data.blend` 档位序为下标访问 `impl->blend_pipelines`（按需 `resize` 扩容缓存表）；该档**未登记**（`blend_pipelines[index] == 0`）时以默认场景着色器对（`场景.vert.spv` / `场景.frag.spv`）`pipeline_load` 登记一条具名管线并写入缓存，随后 `record.pipeline = impl->blend_pipelines[index]`——同档材质**共享**该具名管线（失败即 `error` + 假）；⑤ `record.valid = true`；⑥ **句柄分配：优先复用第一个空槽（`!valid`）**，无空槽则追加（下标 = 句柄 − 1，句柄自 1 起）；⑦ 记 `info` 并返回真。
- **三档语义**：`pipeline != 0` → 沿用该具名管线（`blend` 被忽略）；`pipeline == 0 && blend == Opaque` → 沿用句柄 0 默认场景管线；`pipeline == 0 && blend != Opaque` → 按该 blend 档从 `blend_pipelines` 缓存取（未登记则登记）一条具名管线并**共享**之（第九轮；此前为「各材质各自登记一条 + `owns_pipeline`」）。**管线所有权一律归门面**（见 §6.16）。

#### 3.4.40 `void material_unload(Material_Handle handle)`（本轮新增）

- **功能**：卸载材质（句柄无效则忽略，幂等）。
- **约束/行为**：未初始化直接返回；`handle == 0 || handle > materials.size()` 直接返回；记录已空（`!valid`）直接返回；**不再释放具名管线**（第九轮改动：管线所有权归门面；blend 档缓存管线随 `shutdown` 的 `extra_pipelines` 统一释放，故同档其它材质不受影响）；`record = Impl::Material_Record{}`（复位、标记槽为空）；记 `info`。

#### 3.4.41 `void material_bind_set(Material_Handle handle)`（本轮新增）

- **功能**：设置后续绘制所用材质——等价 `pipeline_bind_set(材质管线)` ＋ `texture_bind_set(材质纹理)`。
- **约束/行为**：未初始化直接返回；**句柄 0 或无效（越界 / 记录已空）** → 回落「默认场景管线 ＋ 内置默认白纹理」（无效句柄另记 `logger.warn("渲染器:: 材质句柄 {} 无效，回落默认管线与默认纹理")`）；有效则 `pipeline_bind_set(record.pipeline)` ＋ `texture_bind_set(record.texture)`（管线句柄未登记 / 纹理句柄无效时各自内部回落默认）。
- **时序要点**：与 §6.10 易错点 17 同理——须在登记绘制项**之前**调用，否则该项会挂上旧的管线 / 纹理绑定。

#### 3.4.42 `Frame_Stats frame_stats_get(void) const`（本轮新增）

- **功能**：取只读帧统计快照（`Frame_Stats`，定义于 `渲染器.h`，Vulkan-free）。
- **返回值**：`Frame_Stats`——未初始化（`impl == nullptr || !impl->initialized`）返回**全零**；否则 `frames = impl->frame_count`（与 `frame_count()` 同口径）、`frame_ms = frame.last_frame_ms_get()`、`draw_items = frame.total_draw_items_get()`、`instances = frame.total_instances_get()`、`gpu_frame_ms = frame.last_gpu_frame_ms_get()`（**第九轮新增**）。
- **口径**：`frame_ms` 为**主机侧**耗时、`gpu_frame_ms` 为 **GPU 侧**耗时（**第九轮新增**；二者**不同量**，设备不支持 GPU 时间戳时后者恒 0）；`draw_items` / `instances` 按登记项累计（见《渲染层-帧》§6.18 / §6.19 与 `R-FRAME-10` / `R-FRAME-11`）。

#### 3.4.43 `bool gpu_timestamp_supported(void) const`（第九轮新增）

- **功能**：查询本机逻辑设备与图形队列族是否支持 GPU 时间戳。
- **返回值**：`bool`——未初始化（`impl == nullptr || !impl->initialized`）时为 `false`；否则取 `impl->frame.gpu_timestamp_supported_get()`（**转发帧模块**，见《渲染层-帧》§3.17）。
- **口径**：为假时 `Frame_Stats.gpu_frame_ms` 恒 0（帧模块已优雅降级，不影响渲染）。

#### 3.4.44 `void scene_apply(const Scene_Data& scene)`（第九轮新增）

- **功能**：应用一份**场景描述**（`Scene_Data`：相机位置 / 注视点 / 视场角 / 近远平面 ＋ 清屏色）。
- **参数**：`scene`——`Scene_Data`（见《渲染层-场景与相机》§3.5）。
- **返回值**：无。
- **约束/行为（源码顺序）**：未初始化（`impl == nullptr || !impl->initialized`）**静默返回**；否则等价于依次调用相机四 setter（`position_set` / `target_set` / `fov_set` / `near_far_set`）＋ 把 `scene.clear_color[0..3]` 逐分量拷入 `impl->clear_color[4]`。
- **口径**：**无条件覆盖**五项、**不校验**取值范围（近远反序、负视场角等照单写入，由相机侧承受退化矩阵）；清屏色自**下一次 `frame_render`** 起生效（见 `R-FACADE-10`）。【待确认：R-FACADE-10】

#### 3.4.45 `void clear_color_set(const float color[4])`（第九轮新增）

- **功能**：设置渲染层清屏色（RGBA，分量取值 0..1）。
- **参数**：`color`——长度 ≥ 4 的 `float` 数组。
- **返回值**：无。
- **约束/行为**：未初始化（`impl == nullptr || !impl->initialized`）**或 `color == nullptr`** 时静默返回；否则逐分量拷入 `impl->clear_color[4]`，自下一次 `frame_render` 起生效。
- **归属**：清屏色由**门面**记录（`Impl::clear_color`，初值 `{0.05f, 0.05f, 0.10f, 1.0f}`），`frame_render` 三条渲染路径共用该值——取代此前的「帧链路内部固定字面量」（见 §6.16）。

### 3.5 层内共享的 `结果检查.h` 接口（本层唯一 `VkResult` 检查出口）

**声明/实现位置**：`Application/Renderer/src/render/Renderer/core/结果检查.h`（inline 函数，仅头文件；包含 `<vulkan/vulkan.h>` 与 `Engine/EngineCore/src/tools/Logging/日志系统运行包.h`）。
**形态**：**非宏**，而是 `namespace engine` 下的三个 `inline` 自由函数。

| 函数 | 签名 | 语义 |
| --- | --- | --- |
| 结果名 | `inline std::string vk_result_name_get(VkResult result)` | 把常见 `VkResult` 映射为可读名（`VK_SUCCESS` / `VK_SUBOPTIMAL_KHR` / `VK_ERROR_OUT_OF_DATE_KHR` 等约 22 个）；未收录码回退 `std::format("VkResult({})", static_cast<int32_t>(result))` |
| 可接受判定 | `inline bool vk_result_acceptable(VkResult result)` | 判据：`VK_ERROR_OUT_OF_DATE_KHR \|\| VK_SUBOPTIMAL_KHR \|\| VK_TIMEOUT` 返回 `true` |
| 硬错误检查 | `inline bool vk_result_check(VkResult result, const char* operation)` | **本层所有 Vulkan 调用的唯一检查出口**。`result == VK_SUCCESS` → `true`；可接受码 → `logger.debug` 后返回 `false`；硬错误 → `logger.error`（带 `operation` 与结果码名）后返回 `false` |

- **调用约定**：`operation` 是「调用点描述」字符串（如 `"vkCreateSwapchainKHR"`），用于日志定位。
- **重要语义（有意约定）**：`vk_result_check` 返回 `false` 同时覆盖「可接受码」与「硬错误」两种情形——**返回 `false` 并不等同于硬失败**。此「可接受码亦返回假」为**有意为之的调用约定**，要求调用方自行区分：调用点可据 `vk_result_acceptable(result)` 二次判定「是否为可继续的可接受码」（例如交换链相关的 `OUT_OF_DATE` / `SUBOPTIMAL` 应走重建分支而非中止）。本门面中，呈现路径（`frame.render` 内部的取图像/呈现）不检查返回值即属此约定下的「失败下帧再试」；交换链重建路径亦以「返回假 = 需要重建」为语义。
- **设计意图（注释原文义）**：避免「有的地方查、有的地方不查」；可接受码只记 `debug`（调用方自行分支处理，如交换链重建），硬错误记 `error`。

## 四、模块私有方法介绍

本模块类内**无私有成员函数**：`Renderer` 的私有区仅有一条数据成员（不完整类型前置声明 `class Impl;` 与 `std::unique_ptr<Impl> impl`），**没有任何私有成员函数**；实现体 `Renderer::Impl` 为**纯数据聚合**（十二个上下文值成员 + 相机 + 场景 UBO 容器 + 若干句柄/计数，**无成员函数**）。模块也**未**在匿名命名空间或私有作用域内定义额外自由函数——门面的全部行为都落在 `core/渲染器.cpp` 中对公开接口的实现里。

因而本节无「逐条私有函数」可列；与「私有方法」相关的内部实现以如下三处承载，其细节不在本节重述：

- **实现体 `Renderer::Impl`**（私有嵌套类，无成员函数）——其字段与生命周期编排见 §5.3 / §5.4。
- **门面公开方法体内的实现细节**（如 `init` 的阶段顺序与失败回退、`shutdown` 的逆序销毁、`frame_render` 的帧槽一致性处理）——见 §六。
- **`core/结果检查.h` 的三个 `inline` 自由函数** 属**层内共享的公开接口**（非本类私有），已在 §3.5 单列，其设计见 §6.4。

> 注：公共扩展头 `渲染器_UI通道.h` 定义的 `Ui_Channel_Context` 类方法属**同层「UI 通道」模块**的公开接口，不在本文「门面私有方法」范围内——见同层 `UI通道.md`。

>
> **`Text_Mesh_Record`（本轮新增）**：门面内定义的结构体 `{ uint64_t font; std::string text; Mesh_Handle mesh; }`（声明于 `core/渲染器实现.h`），记录一个 `(字体句柄, 文本)` 组合对应的网格句柄；**网格所有权在门面**（随 `font_unload` / `shutdown` 经 `mesh.mesh_destroy` 回收），用于避免逐帧重建文字几何。
>
> **`Material_Record`（本轮新增；第九轮改造）**：门面内定义的结构体 `{ uint64_t pipeline; uint64_t texture; bool valid; }`（声明于 `core/渲染器实现.h`）——记录一条材质的图形管线句柄、纹理句柄与有效标记（用于句柄空槽复用）；**第九轮删除 `owns_pipeline`**（非不透明档的具名管线改由 `blend_pipelines` 按档缓存并**共享**，所有权归门面）；**`materials` 下标 = 句柄 − 1**。
>
> **`blend_pipelines`（第九轮新增）**：`std::vector<uint64_t>`（声明于 `core/渲染器实现.h`），下标 = blend 档位序、`0` 表该档未登记；`material_load` 按档取（未登记则登记），管线随 `shutdown` 的 `extra_pipelines` 统一释放（材质卸载**不**释放）。

### 5.4 内部类型关系与调用关系

`Renderer` 是**单一门面类**，唯一内部类型是私有嵌套的 `Renderer::Impl`。二者关系与 `Impl` 内部的编排关系如下（`→` 表示「调用」）：

```
                            ┌──────────────────────────────┐
                            │        engine::Renderer        │
                            │  std::unique_ptr<Impl> impl     │
                            └───────────────┬────────────────┘
                                            │ has-a（PIMPL）
        ┌───────────────────────────────────┴────────────────────────────────┐
        │                         Renderer::Impl（实现体）                      │
        └───────────────────────────────────┬────────────────────────────────┘
                                            │ 值持有（composition）
   ┌────────┬────────┬────────┬────────┬────────┬────┴───┬────────┬────────┬────────┬────────┬────────┬────────┐
   ▼        ▼        ▼        ▼        ▼        ▼        ▼        ▼        ▼        ▼        ▼        ▼
platform device  memory  swapchain frame  shader  pipeline  mesh  texture render_target font  ui_channel camera

init 编排（跨模块引用传递，唯一「模块间依赖」经门面撮合）：
  swapchain.build(..., memory, ...)      ← 交换链引用内存（深度图像）
  swapchain.image_available_count_get()  ← 钳制 effective.frame_overlap（K13）
  frame.build(..., swapchain, ...)       ← 帧引用交换链（取图像/范围/信号量）
  mesh.build(memory)                     ← 网格引用内存（共用缓冲创建/上传）
  texture.build(memory, device)          ← 纹理引用内存与设备
  render_target.build(device, gfx_family, gfx_queue, memory)  ← ⑯ 渲染目标引用设备 / 图形队列 / 内存（本版次新增）
  font.build(texture)                    ← ⑰ 字体引用纹理模块（字形图集经纹理上传/销毁；本轮新增）
  ui_channel.build(instance, phys, device, gfx_family, gfx_queue,
                   window, frame_overlap, image_count, color, depth)  ← ⑲ 取设备/平台/交换链口径
  platform.event_forward_set(lambda, &ui_channel)  ← 事件泵 SDL 事件桥接至 UI 通道

frame_render 编排：
  platform.events_pump / close_requested / minimized / window_size_get / resized_consume
  swapchain.rebuild / pipeline.pipeline_rebuild / extent_get
  camera.view_proj_get / aspect_set
  frame.slot_index_get / slot_wait / render(..., ui_channel.draw_callback_get())
  或 render_to_target(target, ..., ui_channel.draw_callback_get())  ← 离屏路径（本版次新增）
  render_target.target_get(active_target, ...) / target_valid(active_target)  ← 取目标附件 / 句柄判活
  memory.buffer_write
  pipeline.scene_set_get / sampler_set_get / pipeline_get / layout_get
  （不再每帧调 pipeline.scene_bind：set0 于 init 一次性写入）

shutdown 编排（文字与 UI 通道相关）：
  mesh.mesh_destroy(text_meshes[].mesh)  ← 归还文本网格（须先于 mesh.destroy；本轮新增）
  font.destroy()                    ← 归还字形图集纹理（须先于 texture.destroy；本轮新增）
  platform.event_forward_clear()  ← 解除事件桥接（须先于 platform.destroy）
  ui_channel.destroy()            ← 复位 UI 通道信息与回调
```

**核心约束**：`Renderer::Impl` 的十三个成员（十二子模块 + 相机）以**值成员**声明，故其**构造顺序 = 声明顺序**、**析构顺序 = 声明逆序**；但真正的 GPU 资源创建/销毁顺序由 `init` / `shutdown` **手动**编排（不依赖 C++ 成员顺序），因为很多子模块的「资源创建」发生在 `build` 而非构造函数中，且存在交叉依赖（如设备两段化、交换链需内存、帧需交换链、UI 通道需设备/平台/交换链口径）。

### 5.5 `局部命名空间使用.h` 的做法说明

**内容（全文）**：

```cpp
#pragma once
#include "渲染器.h"

// ---------- 基本类型别名 ----------
using std::string;
using std::vector;
```

**做法**：`core/渲染器.cpp`（及 `core/UI通道.cpp`）先 `#include "src/render/Renderer/局部命名空间使用.h"`，从而在本模块实现文件内引入 `string`、`vector` 别名，实现代码一律不加命名空间前缀（如 `string renderer_version(...)`、`vector<const char*> instance_extensions;`）。对外主头 `渲染器.h` 保持干净（只出现 `std::string` / `std::unique_ptr` 等全名）。这是渲染层与引擎统一「局部命名空间使用」约定的落地。注意本模块的私有头**仅**再引入 `渲染器.h`，未额外引入 Vulkan / 标准库其它头——因为门面实现体所需的 Vulkan / SDL3 类型全部来自 `渲染器实现.h`、`渲染器_UI通道.h` 所包含的各子模块对外头与扩展头。

## 六、模块设计/实现细节

### 6.1 PIMPL 收口与公共面边界

**做法**：对外主头 `渲染器.h`：

```cpp
class Ui_Channel_Context;   // 前置声明（用于 ui_channel 返回值，主头保持零 Vulkan / SDL 类型）

class Renderer
{
public:
    // ...全部对外方法（含 Ui_Channel_Context* ui_channel(void);）...
private:
    // 实现体（把 SDL3 / Vulkan / VMA 全部关在 .cpp 里）
    class Impl;
    std::unique_ptr<Impl> impl;
};
```

实现体定义留在私有头 `core/渲染器实现.h`（`class Renderer::Impl`），只被 `core/渲染器.cpp` 包含。

**收益**：
1. **层外看不到第三方类型来自主头**：`Renderer` 只含一个不完整类型指针，上层因 include `渲染器.h` 不会吃进 `<vulkan/vulkan.h>` / `<SDL3/SDL.h>` / `<vk_mem_alloc.h>`。
2. **对外主头唯一暴露的跨模块类型是引擎语义类型**：`渲染器.h` 为 `mesh_load` 的签名而包含 `render/Mesh/网格数据.h`（`Vertex` / `Mesh_Data` / `Mesh_Handle`），该头是 **Vulkan-free** 的「公共面只暴露引擎语义类型」头。
3. **ABI/尺寸稳定**：`Renderer` 大小恒为「一个指针」，实现体增删字段不影响上层。
4. **所有权清晰**：`~Renderer` 内调 `shutdown`，`shutdown` 经 `impl` 逐对象销毁；`impl` 自身由 `unique_ptr` 自动回收。

**本轮公共面边界的扩展**：渲染层公共面在原有 `渲染器.h`（主公共头）与 `Mesh/网格数据.h`（Vulkan-free 语义类型）之外，**新增公共扩展头 `渲染器_UI通道.h`**——它含 Vulkan / SDL3 类型，**不并入** `渲染器.h`（主头仍保持零 Vulkan / SDL 类型），供上层（Test 层）接入 ImGui Vulkan 后端时**自行包含**；上层须先经「对外接口.cmake 的公共包含根」取得 Vulkan SDK 与 SDL3 公共头方可包含本扩展头。`渲染器实现.h`、`core/UI通道.cpp`、`结果检查.h` 及各模块私有头**均不进公共面**，故可合法暴露 Vulkan / SDL3 类型（依据其头注释「层外仍看不到 —— 见 cmake/对外接口.cmake 的私有包含根」）。「私有包含根」的构建实现见 `Application/Renderer/CMakeLists.txt` 的 PRIVATE 段，说明另见 `cmake/对外接口.cmake` 的「私有包含根」一节。

### 6.2 初始化顺序与依赖（`init` 十九阶段的设计依据）

`init` 的阶段顺序不是随意的，而是由 Vulkan 的强制依赖与原子的两段化设计共同决定：

1. **平台先于设备**：`platform.build` 创建窗口；`platform.instance_extensions_get` 提供「表面扩展」清单，实例创建需要它。
2. **实例先于表面**：`device.build_instance` 必须早于 `platform.surface_build`（`VkSurfaceKHR` 需 `VkInstance`）。
3. **表面先于设备**：`device.build_device(surface)` 需要表面来查询「呈现队列族」（`vkGetPhysicalDeviceSurfaceSupportKHR`）——这是设备两段化（Phase 5）的直接原因。
4. **设备先于内存**：`memory.build` 需要 `instance` / `physical_device` / `device` / 图形族与队列。
5. **内存先于交换链**：`swapchain.build(..., memory, ...)` 的深度图像依赖内存模块。
6. **交换链先于帧（含在途帧数钳制，K13）**：`frame.build(..., swapchain, ...)` 取交换链图像、范围与图像可用信号量；交换链构建后先钳制在途帧数——取 `swapchain.image_available_count_get()`，若 `effective.frame_overlap` 超之则下调并 `warn`（图像可用信号量属「每交换链图像」，帧模块按该池轮转取用；仅当在途帧数不超过信号量数时，「先等帧栅栏」才能保证被取用的信号量已在前一次被消费），再据此构建帧槽。
7. **设备先于着色器**：`shader.build(device)` 记录逻辑设备用于建立 `VkShaderModule`。
8. **着色器模块先于管线**：`pipeline.pipeline_build(vert_module, frag_module)` 需要两个 `VkShaderModule`。
9. **交换链先于管线配置**：`Pipeline_Config::color_format` / `depth_format` 取自交换链（`format_get` / `depth_format_get`）。
10. **管线先于场景 UBO 绑定**：⑬ 的 `pipeline.scene_bind` 需要管线基础设施（描述符布局/池/集）已在 ⑪ 建立。
11. **纹理先于默认纹理绑定**：⑭ 先生成默认白纹理，再 `pipeline.texture_bind` 写所有帧槽 `set1`，保证 `descriptor_set_count = 2` 时**不存在未写入的描述符集**（注释明示）。
12. **渲染目标先于相机与 UI（⑯，本版次新增）**：`render_target.build(device, graphics_family, graphics_queue, memory)` 需设备（⑤）、图形队列与内存（⑥）就绪，故置于网格（⑮）之后；本步只记录句柄与内存模块，目标本身按需创建。
13. **字体模块先于文字绘制（⑰，本轮新增）**：`font.build(texture)` 需**纹理模块**（⑭）就绪（字形图集经纹理模块上传 / 销毁）；本步只记录纹理模块，不加载任何字体、不创建任何纹理。
14. **相机宽高比**：⑱ 取当前交换链尺寸设 `camera.aspect_set`（⑰ 字体模块构建之后）。
15. **UI 通道最后构建（⑲）**：UI 通道的信息需要设备（实例/物理设备/逻辑设备/图形族与队列）、平台（窗口）、交换链（图像数/颜色格式/深度格式）与配置（`frame_overlap` 作 `min_image_count`）四方口径全部就绪，故置于所有子模块构建之后；随后立即把事件泵的 SDL 事件桥接到该通道（`platform.event_forward_set`，桥接不持有资源）。

**关键取舍 1——窗口尺寸回退**：交换链尺寸优先取 `platform.window_size_get`（HiDPI 下可能不同于配置），若得 `0` 则回退 `effective.width` / `height`。

**关键取舍 2——Release 强制关校验层**：`#ifdef NDEBUG` 令 `effective.validation = false`，由门面而非设备模块强制，保证 Release 构建「无论如何都不请求校验层」。

**关键取舍 3——场景 UBO 在「初始化」与「每帧」两处写**：⑬ 初始化时写一次初始视图 × 投影，保证首帧渲染前 UBO 内容合法；`frame_render` 每帧再写一次。

**关键取舍 4——UI 通道不代管 UI**：门面只在 ⑲ 构建通道口径并把事件泵桥接过去，绘制回调由上层另行注册（`ui_channel()->draw_callback_set`）；渲染层不 include imgui、不持有 ImGui 上下文（见 §6.8）。

### 6.3 销毁逆序（`shutdown` 的设计依据）

`shutdown` 严格采用「创建逆序 + 依赖先于被依赖销毁」：

| 顺序 | 操作 | 理由（依赖关系） |
| --- | --- | --- |
| 1 | `frame.destroy()` | 帧槽持有在途提交与栅栏，必须最先行，保证后续无在途使用 |
| 2 | 文本网格归还（`mesh.valid()` 时逐条 `mesh.mesh_destroy(text_meshes[].mesh)`，随后清空 `text_meshes` 并复位 `text_pipeline`） | **本轮新增**：文本网格依赖网格模块，须先于 `mesh.destroy()` 归还，否则网格资源泄漏 |
| 3 | `mesh.destroy()` | 网格缓冲由内存模块创建，须先于 `memory` 销毁 |
| 4 | `font.destroy()` | **本轮新增**：字体模块的图集纹理依赖纹理模块，须先归还，故排在 `texture.destroy()` 之前 |
| 5 | `texture.destroy()` | 纹理依赖设备与内存，须先于两者销毁 |
| 6 | `render_target.destroy()` | **本版次新增**：渲染目标依赖设备与内存，须先于两者销毁（门面在 `texture.destroy()` 之后调用，并把 `active_target` 置 0） |
| 7 | 逐槽 `memory.buffer_destroy` 归还场景 UBO 与实例缓冲 | 二者依赖内存模块，须先于 `memory` 销毁 |
| 8 | `pipeline.destroy()` | 管线依赖设备与内存，须先于两者销毁 |
| 9 | `shader.module_destroy(vert/frag)` ＋ 具名管线模块；**随后** `materials.clear()` ＋ `blend_pipelines.clear()` ＋ `bound_pipeline_request = 0`（**本轮新增 / 第九轮补 `blend_pipelines.clear()`**） | 着色器模块须先于 `shader` 上下文复位（`extra_pipelines` 内两模块先销毁再清空）；材质的具名管线（含 blend 档缓存）已随 `extra_pipelines` 释放，故材质记录与 blend 缓存仅需清空 |
| 10 | `shader.destroy()` | 复位着色器上下文 |
| 11 | `swapchain.destroy()` | 交换链销毁连带销毁深度图像，须排在管线之后 |
| 12 | `memory.destroy()` | 分配器销毁（其下资源须先归还；平台/设备仍在其后） |
| 13 | `platform.event_forward_clear()` | 解除事件泵到 UI 通道的桥接（平台销毁后不应再有回调指向 UI 通道） |
| 14 | `platform.destroy()` | 窗口/表面/视频子系统；平台持有「借用」的实例句柄，`vkDestroySurfaceKHR` 要求实例仍在途（**先平台后设备**） |
| 15 | `device.destroy()` | 逻辑设备/实例（销毁连带 `vkDestroyInstance`，故须排在平台之后） |
| 16 | 清空 `pending_items` 与 `pending_transforms`；`ui_channel.destroy()`；`frame_count=0`；`initialized=false` | 复位帧状态与 UI 通道（`ui_channel.destroy()` 仅清句柄与回调、不拥有资源） |

**幂等与半初始化安全**：各子模块 `destroy` 幂等，`shutdown` 可在「部分阶段已构建、部分未构建」时安全调用（这是 `init` 失败回退路径的依靠）。**注意**：`shutdown` 不重置 `impl->config`，`initialized` 已复位，故 `valid()` 正确反映未初始化。

### 6.4 结果检查出口设计（`结果检查.h`）

**为何集中**：注释明示目的是「避免有的地方查、有的地方不查」。全层每个 Vulkan 调用结束后统一调 `vk_result_check(result, "调用点")`，把「成功 / 可接受 / 硬错误」三分流。

**分流语义**：

- `VK_SUCCESS` → 返回 `true`；
- 可接受码（`VK_ERROR_OUT_OF_DATE_KHR` / `VK_SUBOPTIMAL_KHR` / `VK_TIMEOUT`） → `logger.debug`，返回 `false`；
- 其余 → `logger.error`（带 `operation` 与结果码名），返回 `false`。

**可读化**：`vk_result_name_get` 覆盖约 22 个常见码，未收录回退 `VkResult(数值)`。使用 `std::format`（C++20，来自预编译头）。

**形态选择**：采用 `inline` 函数的头文件实现（非宏）。相比宏，函数形态有类型检查、可调试、可被其它 inline 函数组合调用（`vk_result_check` 内部调用 `vk_result_acceptable` 与 `vk_result_name_get`），代价是需在头中包含 `<vulkan/vulkan.h>` 与日志头——故该头被定位为「层内共享的实现细节头」。

**调用约定风险**：返回值 `false` 不区分「可接受」与「硬错误」，见 §6.10 易错点 2。

### 6.5 帧循环的线程亲和与同步约定

- **线程亲和**：`Renderer` 全部方法要求来自**同一线程**（`渲染器.h` 注释「非线程安全」「见 §4.5」）。门面不做任何加锁。
- **帧槽同步（核心正确性点）**：`frame_render` 必须在写「本帧槽 UBO」**之前**调 `frame.slot_wait()`，否则可能覆盖 GPU 仍在读取的上一轮 UBO（真实竞态）。帧模块内部还会再等一次，届时栅栏已发出，`vkWaitForFences` 立即返回，无副作用。
- **帧槽一致性**：门面用 `frame.slot_index_get()` 取「与帧模块内部一致的」槽号来写 UBO 与取描述符集，保证「门面写的槽 = 帧模块本帧渲染用的槽」。
- **`set0` 不每帧重写（本轮变更）**：各帧槽场景 UBO 缓冲句柄自 `init` 起恒定不变，`set0` 已在 `init` 一次性写入；`frame_render` 仅用 `memory.buffer_write` 更新 UBO **内容**，不再调用 `pipeline.scene_bind` 重写描述符集——减少每帧描述符写入。（`frame_render` 中仅保留 `pipeline.scene_set_get` / `sampler_set_get` 用于为待绘制项填装描述符集句柄。）
- **交换链重建节流**：`K8`「每帧最多重建一次」——`rebuilt` 标志使「事件驱动的重建」与「帧链路要求（`rebuild_needed`）的重建」不会在同一帧重复发生。
- **最小化挂起**：`K7`——窗口最小化时直接返回 `true`，避免 0×0 交换链；`resized_consume` 后若尺寸为 `0` 也不重建。

### 6.6 交换链重建与窗口事件的决策归属

- **平台只置标志**：`platform.events_pump` 只置「退出 / 尺寸变化 / 最小化」标志，不做任何 Vulkan 操作；交换链是否重建、何时重建，由门面统一决策。
- **两条重建触发路径（本轮起统一走 `swapchain_rebuild_deferred`）**：
  1. 事件路径：`resized_consume()` 消费尺寸变化标志（**含 `window_size_set` 显式所置**，见 §3.4.38） → 尺寸非零则 `swapchain_rebuild_deferred(w, h)`（内部调 `swapchain.rebuild(w, h, old)` 并把旧资源压入帧模块延迟销毁队列，延迟 = 在途帧数 + 1），随后调 `pipeline.pipeline_rebuild(swapchain.format_get(), swapchain.depth_format_get())`（格式未变时空操作）；
  2. 呈现路径：`frame.render`（或 `render_to_target_present`）输出 `rebuild_needed`（过期 / 次优） → 若本帧尚未重建且尺寸非零则 `swapchain_rebuild_deferred(w, h)`，随后同法调 `pipeline.pipeline_rebuild`。
- **重建后重建管线**：交换链重建可能改变颜色/深度格式，故两条路径在重建后均调 `pipeline.pipeline_rebuild` 重建图形管线（见同层 `管线.md`）；管线未建或格式未变时为空操作。
- **失败仅告警**：两条路径的重建与 `pipeline_rebuild` 失败均只记 `warn`，本帧继续（呈现旧帧或空帧），不检查返回值——此为 `vk_result_check` 的「可接受码亦返回假」约定下的「失败下帧再试」语义（见 §3.5）。

### 6.7 内存与所有权约定

| 对象 | 创建方 | 销毁方 | 说明 |
| --- | --- | --- | --- |
| `Renderer::Impl` 实例 | 门面构造（`new(std::nothrow)`） | `unique_ptr`（析构 `Renderer` 时） | PIMPL 实体 |
| 十二子模块内部资源 | 各自子模块 | 各自子模块（经 `destroy`） | 门面只调 `destroy`，不直接持有其内部句柄 |
| 场景 UBO（`scene_ubos` / `scene_ubo_allocs`） | 门面经 `memory.buffer_create` | 门面经 `memory.buffer_destroy` | **门面是唯一持有者**；故须在 `memory.destroy()` 前归还 |
| `vert_module` / `frag_module` | 门面经 `shader.module_load` | 门面经 `shader.module_destroy` | 着色器模块生命周期由**门面**显式管理（须先于 `shader.destroy`） |
| `default_texture` | 门面经 `texture.texture_create_from_memory` | `texture.destroy`（随纹理上下文） | 门面只持句柄 |
| 用户网格句柄 | 门面经 `mesh.mesh_create` | 门面经 `mesh.mesh_destroy`（`mesh_unload`） | 句柄归还网格模块 |
| 用户纹理句柄 | 门面经 `texture.texture_create_*` | 门面经 `texture_unload` → `texture.texture_destroy` | 句柄归还纹理模块；`texture_unload` 只销毁纹理资源、不自动改写帧槽 `set1`，卸载后需调用方重新 `texture_bind_set` |
| UI 通道（`ui_channel`） | 门面经 `ui_channel.build`（仅填通道信息，**不创建 Vulkan / SDL 对象**） | 门面经 `ui_channel.destroy`（仅清句柄与回调） | 门面以**值成员**持有；UI 通道**不拥有任何 GPU / 窗口资源**，其信息均为渲染层各子模块资源的「借用/引用口径」；绘制/事件回调由上层注册、门面不持有其 user_data |

**关键约定**：门面**只销毁自己直接创建的对象**（场景 UBO、两个着色器模块）；子模块内部资源由子模块自己销毁；传入子模块的引用（`memory` / `swapchain` 为引用，`device` 句柄为值）不承担销毁责任；UI 通道只记录「口径」，其持有的实例/设备/窗口等句柄均属上述子模块所有，故 `ui_channel.destroy()` 不做任何 Vulkan 销毁。

### 6.8 UI 通道接线设计（本轮新增）

**定位**：门面为上层（Test 层）接入 ImGui Vulkan 后端提供一条**接线（wiring）通道**，但**不代管 UI**——不 include imgui、不持有 ImGui 上下文、不创建任何 UI 管线/描述符。

**公共扩展头隔离**：`渲染器_UI通道.h` 含 `<vulkan/vulkan.h>` 与 `<SDL3/SDL.h>`，**不并入**主公共头 `渲染器.h`；主头仅前置声明 `class Ui_Channel_Context;` 供 `ui_channel()` 返回值使用，保持零 Vulkan / SDL 类型（见 §6.1）。

**门面侧的三处接线点**（门面唯一与 UI 通道交互之处；通道内部实现见同层 `UI通道.md`）：

1. **初始化构建（`init` ⑰）**：调 `ui_channel.build(...)`，把设备（`instance_get` / `physical_device_get` / `device_get` / `graphics_family_get` / `graphics_queue_get`）、平台（`window_get`）、交换链（`image_count_get` / `format_get` / `depth_format_get`）与配置（`frame_overlap` 作 `min_image_count`）口径一并交出；随后 `platform.event_forward_set(lambda, &impl->ui_channel)` 把事件泵 SDL 事件桥接到通道（桥接 lambda 调 `ui_channel.event_dispatch(event)`，不持有资源）。
2. **每帧回调传入（`frame_render`）**：把 `ui_channel.draw_callback_get()`（未注册时为 `nullptr`）作为 `frame.render(...)` 的可选 UI 回调入参，由帧模块在场景渲染 pass 结束后交还上层绘制 UI。
3. **关闭复位（`shutdown`）**：`platform.event_forward_clear()` 解除桥接（须先于 `platform.destroy()`），随后 `ui_channel.destroy()` 复位通道信息与回调。

**门面不做的事**：不调用 `draw_callback_set` / `event_callback_set`（回调由上层经 `ui_channel()` 自行注册）；不读取 `info_get`；不解释 `Ui_Channel_Info` 字段（字段对齐 `ImGui_ImplVulkan_InitInfo`，读取与填装由上层完成）。

### 6.9 编码与风格约定

- **异常禁用**：`impl` 用 `new(std::nothrow)`；实现中不抛异常，失败一律「记日志 + 返回 `false` / 静默返回」。
- **命名**：类型 `Renderer` / `Renderer_Config` / `Ui_Channel_Context`；函数 `frame_render` / `mesh_load` / `texture_bind_set` / `camera_position_set` / `ui_channel` 等（小写 + `_` 分隔，动词后置或名词+动词）。
- **注释**：中文；短注释多行 `//`（`//` 后无空格）；三行以上用 `/* */`；采用换行注释；变量声明与条件分支前均有说明。
- **日志前缀**：统一 `"渲染器:: ..."`，便于过滤（UI 通道实现亦沿用该前缀）。
- **大括号**：Allman（另起一行）。
- **命名空间**：全部实现位于 `namespace engine`。
- **包含路径**：实现文件跨目录包含写本层根相对（`src/...`），头文件跨目录包含写项目根全路径（`Application/...`），同模块相邻头写裸文件名（见 §5.2）。

### 6.10 易错点清单

1. **PIMPL 头是「实现细节头」**：`core/渲染器实现.h` 含 Vulkan / SDL3 类型，**不得**进入公共面；一旦被上层 include 会破坏收口。同理 `渲染器_UI通道.h` 虽属公共扩展头，但含 Vulkan / SDL3 类型，只可由已具备公共包含根的上层按需包含，**不得并入** `渲染器.h`。
2. **`vk_result_check` 返回 `false` 不代表硬失败**（有意约定）：可接受码（`OUT_OF_DATE`/`SUBOPTIMAL`/`TIMEOUT`）同样返回 `false`；调用方若把 `false` 一律当中止会误伤可重建场景，应据 `vk_result_acceptable(result)` 二次判定。
3. **`frame_render` 中 `slot_wait` 的顺序**：必须在写本帧槽 UBO 之前；若挪到之后，会与 GPU 争用同一 UBO（真实竞态）。
4. **`set0` 不每帧重写**：本轮已移除 `frame_render` 内的 `pipeline.scene_bind`——各帧槽 `set0` 于 `init` 一次性写入、缓冲句柄恒定，每帧只用 `buffer_write` 更新内容；若把 `scene_bind` 搬回每帧，会造成多余描述符写入（且与「缓冲句柄不变」的前提重复）。
5. **`pending_items` 支持同帧多网格**：`mesh_draw` 逐次 `push_back`（不再先 `clear`），每次追加一块 `pending_transforms`；同帧可登记多个网格（各网格持有各自模型矩阵），`frame_render` 消费后统一清空。
6. **`pending_transforms` 的地址稳定性**：它是 `Impl` 的 `std::deque<std::array<float,16>>`，`push_back` 不使既有元素地址失效，`pending_items[].push_constants` 指向其中某块；该指针在下一帧 `frame_render` 消费前必须保持有效——故不能改成局部/临时容器，且必须用 `deque` 而非 `vector`。
7. **顶点 / 索引共用缓冲**：`mesh_record_get` 回写的是**同一缓冲句柄**（`vertex_buffer = index_buffer = mesh_buffer`）＋ `index_offset`（索引区字节偏移）＋ `index_count`；`Frame_Render_Item` 的 `index_offset` 必须逐项带入（共用缓冲时非零），否则索引读取会错位。
8. **`shutdown` 顺序不可改**：尤其「着色器模块先于 `shader.destroy`」「场景 UBO 先于 `memory.destroy`」「交换链销毁在管线之后」「**先平台后设备**（实例须在表面销毁时在途）」「**事件桥接先于 `platform.destroy` 解除**（`event_forward_clear` 须在平台销毁前，避免平台回调指向已销毁的 UI 通道）」五条。
9. **`init` 已初始化时忽略配置**：重复 `init` 返回 `true` 但**不重新应用**新配置；改配置需先 `shutdown` 再 `init`。
10. **`texture_bind_set` 是立即写描述符**：对全部帧槽写 `set1`，若存在在途帧使用对应槽，属跨帧争用。
11. **`shutdown` 与挂起分支清空待绘制项**：`shutdown` 与 `frame_render` 的挂起分支（请求退出 / 最小化，合并判断）均清空 `pending_items` 与 `pending_transforms`，避免连续挂起期间无限累积。
12. **纹理卸载后需重绑**：`texture_unload` 只销毁纹理资源，绑定过该纹理的帧槽需调用方重新 `texture_bind_set` 指定新纹理。
13. **交换链重建后须重建管线**：两条重建路径在 `swapchain.rebuild` 后均调 `pipeline.pipeline_rebuild`，否则格式变化会导致动态渲染附件格式失配（失败仅 `warn`，格式未变时空操作）。
14. **`ui_channel()` 的边界**：只对 `impl == nullptr` 返回空（构造分配失败），**不**按 `initialized` 判空；未初始化 / 已 shutdown 时返回非空但未必 `valid()` 的通道指针，调用方应自行佐判。且 `ui_channel()` 与 UI 回调注册均须与 `frame_render` **同线程**（渲染层非线程安全）。
15. **UI 通道回调时机**：绘制回调在**场景渲染 pass 内、`vkCmdEndRendering` 之前**由帧模块调用（与场景共用同一动态渲染通道），UI 管线须与本帧颜色/深度格式相容（通道 `build` 已把交换链格式交给上层）；回调未注册时帧链路为空操作（见同层 `帧.md` / `UI通道.md`）。
16. **切档只影响默认管线（本版次收敛）**：`blend_mode_set` 只重建默认场景管线（句柄 0）的混合档；具名管线的混合档在 `pipeline_load` 登记时确定、不受其影响。若期望具名管线也换档，须以新档重新 `pipeline_load`。
17. **切换管线须在登记绘制项之前**：`mesh_draw` / `mesh_draw_instanced` 取 `pipeline_get()`（当前激活管线），故 `pipeline_bind_set` 必须在登记该项**之前**完成，否则该项会挂上旧的激活管线。
18. **`texture_bind_target` 与采样器状态切换（**已解决 · R-FACADE-06**）**：本轮起门面以 **`bound_view`**（当前绑定视图）取代 `bound_texture_request`——`texture_bind_target` 记 `bound_view = 目标颜色视图`，`texture_sampler_state_set` 重建采样器后以 `{新采样器, bound_view}` 重写全部帧槽 `set1`，故**不再**按纹理句柄回落而**覆盖**渲染目标绑定。见 §3.4.31 / §6.15。
19. **离屏与交换链路径回读来源不同**：交换链路径回读交换链颜色附件、离屏路径回读**目标颜色附件**；`frame_render` 的回读交付逻辑两路共用（`request.bytes == 0` 判「未兑现」）。
20. **`render_target_destroy` 会回落交换链**：销毁当前 `active_target` 时门面会先把 `active_target` 置 0（回落交换链路径），避免后续帧引用已销毁目标。
21. **文字四边形索引绕序与场景相反（本轮新增）**：文字几何位于像素空间（Y 向下）且门面的像素→NDC 矩阵**不做 Y 翻转**，故绕序须为 `(0,2,1)` ＋ `(0,3,2)`；沿用场景的 `(0,1,2)` ＋ `(0,2,3)` 会使文字三角形全部被判背面剔除（表现为「一个像素都不出现」）。见《渲染层-文字》§6.4。
22. **`text_draw` 会覆盖「当前纹理」绑定（本轮新增）**：方法内 `texture_bind_set(record->atlas_texture)` 把字形图集绑为「当前纹理」，**覆盖此前纹理绑定**；其后若绘制场景项须重新 `texture_bind_set`。见 §3.4.34 与附录 D 的 `R-FACADE-07`。
23. **字体卸载须先归还文本网格（本轮新增）**：`font_unload` 必须**先**清除并归还该字体的文本网格缓存，**再** `font_destroy`；顺序颠倒会留下指向已销毁记录的网格缓存，或在网格模块销毁前使字体图集失去归还点。`shutdown` 同理（见 §6.3 顺序表）。
24. **运行时卸载须走 `detach` ＋ 延迟销毁（本版次第八轮新增）**：`mesh_unload` / `texture_unload` / `render_target_destroy` 已改为「`*_detach` 摘出 → 组装 `Deferred_Entry`（`memory_resources`）→ `frame.deferred_push(…, frame.in_flight_count_get() + 1)`」，**不得**再直接调子模块 `*_destroy`；`render_target_destroy` 另在摘出前回落 `active_target` / `present_target`（等于该句柄时置 0），`texture_unload` 另在摘出的视图等于 `bound_view` 时先 `texture_bind_set(0)`。
25. **修改长命对象前须 `frame.frames_wait()`（本版次第八轮新增）**：`texture_bind_set` / `texture_bind_target` 写满全部帧槽 `set1` 前、`texture_sampler_state_set` 重建共享采样器前、`pipeline_unload` 注销管线前均先收口**全部**在途帧；仅 `slot_wait`（只等本帧槽）**不足**（见 §6.15）。
26. **`material_bind_set` 的作用域与时机（本版次第八轮新增）**：它等价 `pipeline_bind_set` ＋ `texture_bind_set`，须在登记绘制项**之前**调用（与易错点 17 同理）；材质 `pipeline != 0` 时其 `blend` 被忽略；材质**不含采样器状态**（采样器仍由 `texture_sampler_state_set` 全局控制）。
27. **同 blend 档材质共享具名管线（第九轮新增）**：`material_load` 在 `pipeline == 0 && blend != Opaque` 时按档取 `blend_pipelines` 缓存（未登记则以默认场景着色器对建一条并写入缓存），同档 N 个材质**共享一条管线 ＋ 2 个着色器模块**（而非各登记一条 ＋ 2N 个模块）；`material_unload` **不**释放该管线，故卸载其一不影响同档其它材质。

### 6.11 像素回读的门面接线（本版次新增）

**归属判定**：回读缓冲与拷贝录制**不下沉到门面**——缓冲由帧模块持有（`Frame_Context::readback_buffer`），门面只做三件事：组装请求、传入实参、判读结果。故就**像素回读**而言 `Renderer::Impl` **未新增任何字段**（`Impl` 字段表见 5.3），公共面也**不出现任何 Vulkan 类型**（回读参数只有 `uint8_t*` 与 `uint32_t*`），符合「PIMPL 收口与公共面边界」（6.1）。（注：**本版次**另有 `render_target` / `active_target` / `extra_pipelines` / `bound_pipeline_request` 四个字段（见 §5.3 与 §6.12），**本轮**另有 `font` / `text_pipeline` / `text_meshes` 三个字段（见 §5.3 与 §6.13）。）

**接线三点**
1. **组装**：`readback_pixels != nullptr` 时构造栈上的 `Frame_Readback_Request{pixels, capacity}`，取其地址作为 `frame.render` 末位实参；否则传 `nullptr`。
2. **判读**：返回后以 `request.bytes == 0` 判定「回读未兑现」——挂起帧（请求退出 / 窗口最小化）与「取图像返回过期 / 次优而跳过渲染」都不会产出像素，此时报错返假并把尺寸出参保持为零，把「未回读到」与「回读值全零」区分开。
3. **查询**：`readback_supported()` 直通 `swapchain.color_transfer_src_get()`，作为上层的**前置能力判据**。

**与既有约定的一致性**
- `frame_render` 的回读参数**全为默认参数**，故既有 35 例渲染用例与 Test 层其余调用点零改动；这是「公共面可改」前提下仍保持调用方稳定的做法。
- 门面**不**在回读帧与非回读帧之间改变帧循环顺序：回读的同步代价（等本帧栅栏）只发生在**显式请求回读的帧**内，且位于帧模块内部（见 `帧.md` 6.15）。

### 6.12 离屏目标与具名管线的门面接线（本版次新增）

**归属判定**：门面把「具名管线的着色器模块所有权」与「离屏目标的句柄」都收在自己这里，向下的实际资源仍由子模块持有（管线模块持 `VkPipeline`、渲染目标模块持图像 / 视图）。

**四个新字段（见 §5.3）**
- `render_target`：渲染目标模块实例（设备 / 图形队列 / 内存），`init` ⑯ 构建、`shutdown` 销毁。
- `active_target`：本帧渲染目标句柄（0 = 交换链路径），由 `render_target_set` 更新。
- `extra_pipelines`：具名管线记录（句柄 → 两着色器模块），**着色器模块所有权在门面**。
- `bound_pipeline_request`：当前所选管线句柄（0 = 默认）。

**`frame_render` 的分派**：写场景 UBO / 实例缓冲、填装描述符集之后，按**三路互斥**分派——`present_target` 有效且后处理资源就绪 → `frame.render_to_target_present(...)`（同帧多 pass，**不过 UI 回调**）；否则 `active_target` 有效 → `frame.render_to_target(...)`（离屏路径，不呈现）；否则 → `frame.render(...)`（交换链路径）；句柄无效或前置不完整则逐级回落并告警。**各路共用同一回读交付逻辑**（`request.bytes == 0` 判「未兑现」）。

**已知取舍**：离屏路径本帧**不呈现到窗口**；离屏结果需经 `texture_bind_target` 把目标颜色视图绑入帧槽 `set1`、再以正常绘制采样显示（后处理闭环）。

### 6.13 文字渲染与各向异性的门面接线（本轮新增）

**归属判定**：门面把「字形图集与度量的产出」交给字体模块，把「文字管线 / 网格缓存 / 坐标矩阵 / 绘制登记」与「采样器状态的设备能力归一」收在自己这里。

**三个新字段（见 §5.3）**
- `font`：字体模块实例（记录纹理模块引用），`init` ⑰ 构建、`shutdown` 在 `mesh.destroy()` 后 / `texture.destroy()` 前销毁。
- `text_pipeline`：文字管线句柄（0 = 尚未登记），首次 `text_draw` 懒登记（`文字.vert.spv` ＋ `文字.frag.spv`、`Blend_Mode::Alpha`），登记结果缓存。
- `text_meshes`：`(字体句柄, 文本) → 网格句柄` 缓存（`Text_Mesh_Record`），避免逐帧重建几何。

**`text_draw` 的接线链（八步）**：见 §3.4.34。要点：字体句柄判活 → 空文本直接返回真 → 懒登记文字管线 → 命中 / 新建网格（几何经 `Font_Context::text_geometry_build`）→ `pipeline_bind_set(text_pipeline)` ＋ `texture_bind_set(图集纹理)` → 取交换链尺寸 → 构造像素→NDC 矩阵（**不做 Y 翻转**）→ `mesh_draw(网格, 矩阵)`。

**销毁口径**：文本网格依赖网格模块、字形图集纹理依赖纹理模块，故 `shutdown` 须「先归还文本网格（`frame.destroy` 之后）、再销毁网格模块、再销毁字体模块、再销毁纹理模块」；`font_unload` 同理（**先归网格、再销毁字体**）。见 §6.3 顺序表与 §6.10 易错点 23。

**各向异性归一**：`texture_sampler_state_set` 在转交纹理模块前按**设备能力**归一采样器状态（不支持则置假并告警、倍数钳到 `[1, 上限]`，见 §3.4.24）；设备能力来自 `device.anisotropy_enabled_get()` / `device.max_anisotropy_get()`（见《渲染层-设备》§3.7 / §6.7），并由门面 `sampler_anisotropy_supported()` / `sampler_max_anisotropy()` 对外暴露（§3.4.35 / §3.4.36）。

**已知边界**：① `text_draw` 会把字形图集绑为「当前纹理」，**覆盖此前纹理绑定**；② 文字项与场景项**共享同一实例缓冲与描述符集**——`Frame_Render_Item` 的 `instance_count` / `instance_offset` 与描述符集句柄由门面在 `frame_render` 时按本帧槽统一填装，故「各绘制项用各自的管线 / 图集 / 纹理绑定」这一区分须在**登记该项之前**完成（见 §6.10 易错点 17 / 22）。

### 6.14 同帧后处理与窗口尺寸入口的门面接线（本轮新增）

**三个新字段（见 §5.3）**：`present_target`（同帧后处理呈现目标句柄，0 = 关闭）、`post_pipeline`（后处理管线句柄）、`fullscreen_mesh`（全屏四边形网格句柄）。

**惰性资源方法（`core/渲染器.cpp`）**：
- `swapchain_rebuild_deferred(width, height)`：调 `swapchain.rebuild(width, height, old_resources)`，成功后把 `old_resources` 组装为 `Deferred_Entry` 并 `frame.deferred_push(entry, frame.in_flight_count_get() + 1)`（**延迟 = 在途帧数 + 1**）；失败返回假（旧链已回滚、仍可用）。两处重建触发路径均改用它（§6.6）。
- `post_resources_ensure()`：**惰性**——①加载 `后处理.vert.spv` / `后处理.frag.spv` 并 `pipeline.pipeline_register` 登记具名管线（不透明档），着色器模块随 `extra_pipelines` 一并销毁；②创建 NDC `-1..1` 全屏四边形网格（绕序 `(0,2,1)/(0,3,2)`），随网格模块销毁。

**两处着色器（本轮新增，`Application/Renderer/assets/shaders/`）**：
- `后处理.vert`：经**实例模型矩阵**输出全屏 NDC 坐标；**必须真正应用 `location 3..6` 的实例属性**（否则触发「顶点属性未使用」校验告警）——本 pass 恒传单位矩阵，故等价于直接输出顶点位置。
- `后处理.frag`：`texelFetch(source_image, clamp(ivec2(gl_FragCoord.xy), 0, size - 1), 0)` 按帧缓冲坐标 1:1 取源像素（与顶点朝向 / 纹理坐标无关）。

**门面接线要点**：`present_target` **优先于** `active_target` 生效；该路径**不经 UI 回调**；要求**目标范围与交换链范围一致**（§3.4.37 / 待确认项）。`shutdown` 复位 `present_target` / `post_pipeline` / `fullscreen_mesh`（全屏网格随网格模块销毁、后处理管线随管线模块销毁）。

### 6.15 资源销毁时序收口与材质数据化的门面接线（本轮新增）

**一、资源销毁时序收口**

- **三个卸载路径改「摘出 → 延迟销毁」**：
  - `mesh_unload`：`mesh.mesh_detach(handle, record)` 摘出网格缓冲（句柄无效 / 记录已空则返回）→ 组装 `Deferred_Entry`（`memory_resources` 填 `{buffer, buffer_allocation}`）→ `frame.deferred_push(entry, frame.in_flight_count_get() + 1)`；
  - `texture_unload`：`texture.texture_detach(handle, record)` 摘出图像 ＋ 视图 → 若摘出的 `record.view == bound_view` 则**先** `texture_bind_set(0)` 回落默认白纹理 → 填 `{image, image_allocation, view}` → 压入延迟队列；
  - `render_target_destroy`：**先**回落 `active_target` / `present_target`（等于该句柄时置 0）→ `render_target.target_detach(handle, record)` 摘出颜色与深度 → **各**填一条 `memory_resources` → 压入延迟队列。
- **`frames_wait` 收口点**：`texture_bind_set` / `texture_bind_target` 在「写满全部帧槽 `set1`」之前、`texture_sampler_state_set` 在「销毁并重建共享采样器」之前、`pipeline_unload` 在「注销图形管线」之前，均调 `frame.frames_wait()`——这些对象被**任一**帧槽的在途命令缓冲引用，必须等全部帧槽完成。
- **`bound_view`**：以「当前绑定视图」取代 `bound_texture_request`（纹理与渲染目标共用该语义）——`texture_bind_set` 解析出视图后记 `bound_view`；`texture_bind_target` 记 `bound_view = 目标颜色视图`；`texture_sampler_state_set` 重建采样器后以 `{新采样器, bound_view}` 重写全部帧槽 `set1`（不再按句柄回落重绑，故**不再覆盖渲染目标绑定**，**R-FACADE-06 结案**）。底层口径见《渲染层-帧》§6.18。
- **效果**：校验层全开全量实跑的校验消息由 **6 条降至 0 条**。

**二、材质与场景描述数据化**

- **公共语义头**：`渲染器.h` 新引入 `Pipeline/材质数据.h`（`Material_Handle` / `Material_Data`，Vulkan-free，见《渲染层-管线》§3.5）。
- **三方法**：`material_load`（`pipeline != 0` 沿用具名管线；`pipeline == 0 && Opaque` 用默认场景管线；`pipeline == 0 && 非 Opaque` 以默认场景着色器对登记具名管线并置 `owns_pipeline`；句柄空槽复用）/ `material_unload`（自有管线随卸载释放）/ `material_bind_set`（等价 `pipeline_bind_set` ＋ `texture_bind_set`）。逐条见 §3.4.39~§3.4.41。
- **Impl 新字段**：`materials`（`std::vector<Material_Record>`，下标 = 句柄 − 1）＋ 内部类型 `Material_Record`（见 §5.3）；`shutdown` 清空 `materials`。

**三、帧性能统计**

- **公共结构** `Frame_Stats`（`渲染器.h`，Vulkan-free）：`{ uint64_t frames; double frame_ms; uint64_t draw_items; uint64_t instances; }`。
- **只读查询** `frame_stats_get()`（§3.4.42）：`frames` 取门面 `impl->frame_count`，其余取帧模块三 getter；未初始化返回全零。**不引入 GPU 时间戳**。

### 6.16 GPU 耗时与场景描述的门面接线（第九轮新增）

**一、GPU 耗时（透传）**：`Frame_Stats` 新增 `double gpu_frame_ms`，由 `frame_stats_get()` 从帧模块 `last_gpu_frame_ms_get()` 取（见 §3.4.42）；新增公开只读 `gpu_timestamp_supported()`，转调帧模块 `gpu_timestamp_supported_get()`（见 §3.4.43）。门面**自身不度量 GPU 时间**——能力探测、帧槽查询池、时间戳写入与环形读回全在帧模块（见《渲染层-帧》§6.19）；设备不支持时 `gpu_frame_ms` 恒 0（优雅降级）。口径登记为待确认（`R-FACADE-10`，与帧模块 `R-FRAME-11` 同源）。

**二、场景描述数据化**：`渲染器.h` 新引入 Vulkan-free 公共头 `Scene/场景数据.h`（`Scene_Data`，见《渲染层-场景与相机》§3.5）；新增 `scene_apply`（等价相机四 setter ＋ 清屏色逐分量拷贝，见 §3.4.44）与 `clear_color_set`（见 §3.4.45）；`Renderer::Impl` 新增 `float clear_color[4]`（初值 `{0.05f, 0.05f, 0.10f, 1.0f}`，见 §5.3）。

**三、清屏色归属（本轮变化）**：此前 `frame_render` 内以**固定字面量** `const float clear_color[4] = { 0.05f, 0.05f, 0.10f, 1.0f };` 提供清屏色；**第九轮改为** `const float* clear_color = impl->clear_color;`——清屏色由**门面记录值**提供，且三条渲染路径（同帧多 pass / 离屏 / 交换链）**共用同一份**。故 `scene_apply` / `clear_color_set` 的改动自**下一次 `frame_render`** 起对全部路径生效。

**四、材质 blend 管线共享（本轮变化）**：非不透明档材质的具名管线由「各材质各自登记一条 ＋ `owns_pipeline`」改为「**按 blend 档缓存复用**」（`Impl::blend_pipelines`，见 §3.4.39 / §5.3）；`material_unload` **不**再释放具名管线（所有权归门面）；`shutdown` 在 `materials.clear()` 后增 `blend_pipelines.clear()`（管线已随 `extra_pipelines` 释放）。同 blend 的 N 个材质由「各登记一条管线 ＋ 2N 个着色器模块」变为「共享一条 ＋ 2 个模块」。

## 七、模块运行链路详例

本章以「调用方（上层）→ 门面 → 被调方（子模块 / Vulkan）」的时序描述典型链路，至少覆盖主流程与关键异常/边界分支。

### 7.1 初始化链路（`Renderer::init` 十九阶段）

**调用方**：上层；**入口**：`Renderer::init(config)`。

1. **`impl == nullptr`？** 是 → `logger.error("渲染器:: 实现体分配失败")`，返回 `false`。
2. **已初始化？** `impl->initialized` 真 → `logger.warn("渲染器:: 已初始化，忽略重复 init")`，返回 `true`。
3. **参数校验**：`width == 0 || height == 0` → `error` + `false`；`frame_overlap < 1 || > 3` → `error` + `false`。
4. **生效配置**：`effective = config`；`#ifdef NDEBUG` → `effective.validation = false`。
5. **① `platform.build(width, height, title, hidden)`**：创建视频子系统 + 窗口；失败 → `error("平台初始化失败")` + `shutdown()` + `false`。
6. **② `platform.instance_extensions_get(instance_extensions)`**：取表面扩展清单；失败 → `error` + `shutdown` + `false`。
7. **③ `device.build_instance(instance_extensions, effective.validation)`**：创建实例 + 调试信使；失败 → `error` + `shutdown` + `false`。
8. **④ `platform.surface_build(device.instance_get())`**：创建 `VkSurfaceKHR`（**须先于设备**）；失败 → `error` + `shutdown` + `false`。
9. **⑤ `device.build_device(platform.surface_get())`**：选物理设备 + 建逻辑设备（查询呈现队列族）；失败 → `error` + `shutdown` + `false`。
10. **⑥ `memory.build(instance, physical_device, device, graphics_family, graphics_queue)`**：建 VMA 分配器；失败 → `error` + `shutdown` + `false`。
11. **取窗口尺寸**：`platform.window_size_get(swapchain_width, swapchain_height)`；为 0 则回退 `effective.width` / `height`。
12. **⑦ `swapchain.build(physical_device, memory, device, surface, graphics_family, present_family, w, h, vsync)`**：建交换链 + 图像视图 + 深度图像；随后**钳制在途帧数**——取 `swapchain.image_available_count_get()`，若 `effective.frame_overlap` 超之则下调并 `warn`（K13）；失败 → `error` + `shutdown` + `false`。
13. **⑧ `frame.build(device, physical_device, graphics_family, graphics_queue, present_family, present_queue, swapchain, frame_overlap)`**：建帧槽；失败 → `error` + `shutdown` + `false`。
14. **⑨ `shader.build(device)` + `shader.directory_set(effective.shader_dir)`**：记录设备与目录；失败 → `error` + `shutdown` + `false`。
15. **⑩ `shader.module_load(vert_module, "场景.vert.spv")` 与 `module_load(frag_module, "场景.frag.spv")`**：加载两个着色器模块；任一失败 → `error` + `shutdown` + `false`。
16. **⑪ `pipeline.build(device, pipeline_config)`**（`color_format = swapchain.format_get()`、`depth_format = swapchain.depth_format_get()`、`frame_overlap = effective.frame_overlap`）：建描述符布局/管线布局/池/集；失败 → `error` + `shutdown` + `false`。
17. **⑫ `pipeline.pipeline_build(vert_module, frag_module)`**：建图形管线；失败 → `error` + `shutdown` + `false`。
18. **⑬ 逐帧槽建场景 UBO**（`slot ∈ [0, frame_overlap)`）：`memory.buffer_create(scene_ubos[slot], scene_ubo_allocs[slot], 64, VK_BUFFER_USAGE_UNIFORM_BUFFER_BIT, true)` → `camera.view_proj_get(view_proj)` → `memory.buffer_write(..., 64, 0)` → `pipeline.scene_bind(slot, scene_ubos[slot])`；任一步失败 → `error` + `shutdown` + `false`。
19. **⑭ `texture.build(memory, device)`**；生成 2×2 全白纹理 `texture_create_from_memory(default_texture, white_pixels, 2, 2)`；`texture_bind_get(default_texture, default_view, default_sampler)`；逐帧槽 `pipeline.texture_bind(slot, default_sampler, default_view)`；任一步失败 → `error` + `shutdown` + `false`。
20. **⑮ `mesh.build(memory)`**：记录内存模块；失败 → `error` + `shutdown` + `false`。
21. **⑯ `render_target.build(device, graphics_family, graphics_queue, memory)`**（本版次新增）：记录设备 / 图形族 / 图形队列与内存模块；失败 → `error("渲染目标模块初始化失败")` + `shutdown` + `false`。
22. **⑰ `font.build(impl->texture)`**（本轮新增）：记录纹理模块（字形图集经纹理模块上传 / 销毁）；失败 → `error("渲染器:: 字体模块初始化失败")` + `shutdown()` + `false`。
23. **⑱ `camera.aspect_set(extent.width / extent.height)`**：取 `swapchain.extent_get()`，尺寸非零才刷新。
24. **⑲ UI 通道 + 事件桥接**：`ui_channel.build(device.instance_get(), device.physical_device_get(), device.device_get(), device.graphics_family_get(), device.graphics_queue_get(), platform.window_get(), effective.frame_overlap, swapchain.image_count_get(), swapchain.format_get(), swapchain.depth_format_get())`；随后 `platform.event_forward_set(lambda, &impl->ui_channel)` 把事件泵 SDL 事件桥接到通道（lambda 调 `ui_channel.event_dispatch(event)`）。**该阶段不返回失败**（`build` 为填信息、桥接为空操作，均为无失败路径）。
25. **收尾**：`impl->config = effective; impl->initialized = true;`；`logger.info("渲染器:: 初始化完成（校验层 开/关）")`；返回 `true`。

### 7.2 帧渲染链路（`Renderer::frame_render`）

1. **未初始化守卫**：`impl == nullptr || !impl->initialized` → 返回 `false`。
2. **① 泵事件**：`platform.events_pump()`（只置标志）。
3. **②③ 挂起检查（合并判断）**：`platform.close_requested() || platform.minimized()` 为真 → **清空 `pending_items` 与 `pending_transforms`** 后返回 `true`（请求退出交通调用方收敛；最小化挂起本帧、避免 0×0 交换链（`K7`）；两情形合并，连续挂起期间不再累积待绘制项）。
4. **取尺寸**：`platform.window_size_get(width, height)`。
5. **④ 尺寸事件重建（本轮起走 `swapchain_rebuild_deferred`）**：`platform.resized_consume()`（**含 `window_size_set` 显式所置**）且尺寸非零 → `swapchain_rebuild_deferred(width, height)`（内部 `swapchain.rebuild(width, height, old)` ＋ `frame.deferred_push(entry, frame.in_flight_count_get() + 1)`；失败仅 `warn`），随后 `pipeline.pipeline_rebuild(swapchain.format_get(), swapchain.depth_format_get())`（格式未变时空操作，失败仅 `warn`）；`rebuilt = true`（`K8`）。
6. **刷新宽高比**：`swapchain.extent_get()` 尺寸有效 → `camera.aspect_set(...)`。
7. **⑤ 本帧槽准备**：`slot = frame.slot_index_get()`；`frame.slot_wait()`（**先等待**，失败 → `error` + `false`）。
8. **写场景 UBO**：`camera.view_proj_get(view_proj)` → `memory.buffer_write(scene_ubos[slot], scene_ubo_allocs[slot], view_proj, 64, 0)`；失败 → `error` + `false`。**（不再调 `pipeline.scene_bind`：本帧槽 `set0` 无需重写）**
9. **填装描述符集与实例缓冲**：遍历 `pending_items` 设 `scene_set = pipeline.scene_set_get(slot)`、`sampler_set = pipeline.sampler_set_get(slot)`、`descriptor_set_count = 2`，并把本帧槽实例缓冲句柄与偏移填入项（实例化路径）。**本轮新增前置**：若 `present_target != 0`，先 `post_resources_ensure()` 惰性确保后处理管线与全屏网格就绪，并向本帧实例存储**追加一个单位模型矩阵**作为后处理全屏四边形的实例来源（**须在实例缓冲写入之前**；实例存储已满或资源未就绪则 `warn` 并回落原路径）；另把离屏目标颜色写入各帧槽**后处理采样器集**（`pipeline.post_texture_bind`）。
10. **分派渲染路径（本轮改为三路互斥）**：
    - **① 同帧多 pass 后处理**（`present_target != 0` 且 `post_resources_ensure()` 就绪、`render_target.target_get(present_target, ...)` 与全屏网格均就绪）→ 组装 `post_item`（后处理管线 `pipeline.pipeline_by_handle_get(post_pipeline)`、布局、set0 `scene_set_get(slot)`、set1 `post_set_get(slot)`、全屏网格缓冲、实例 = 本帧槽实例缓冲 + 单位矩阵偏移）后调 `frame.render_to_target_present(swapchain, target, pending_items.data(), size, post_item, clear_color, rebuild_needed, readback_ptr)`（**同帧内完成目标 → 后处理 → 呈现**）；失败 → `error("同帧多 pass 后处理渲染失败")` + `false`；
    - **② 离屏路径**（`active_target != 0` 且 `render_target.target_get` 成功）→ 组装 `Frame_Render_Target` 调 `frame.render_to_target(target, pending_items.data(), size, clear_color, ui_channel.draw_callback_get(), readback_ptr)`（**不取交换链图像、不呈现**）；失败 → `error("离屏帧渲染失败")` + `false`；
    - **③ 交换链路径**（默认）→ `frame.render(swapchain, pending_items.data(), size, rebuild_needed, clear_color, ui_channel.draw_callback_get(), readback_ptr)`（`clear_color = impl->clear_color`，**第九轮起为门面记录值**，初值 `{0.05, 0.05, 0.10, 1.0}`）；失败 → `error("帧渲染失败")` + `false`。
    - 前置不完整（目标 / 全屏网格 / 后处理资源 / 实例存储）时逐级回落：①→②/③、②→③。
11. **消费清空**：`pending_items.clear()` 与 `pending_transforms.clear()`。
12. **回读交付（两路共用）**：`readback_ptr != nullptr` 且 `readback_request.bytes == 0` → `error("渲染器:: 本帧未产出像素，像素回读未兑现")` + `false`；否则回填 `*readback_width` / `*readback_height`。
13. **⑥ 呈现路径重建**：`rebuild_needed && !rebuilt` 且尺寸非零 → `swapchain_rebuild_deferred(width, height)` 后同法调 `pipeline.pipeline_rebuild(...)`（失败仅 `warn`）。
14. **计数**：`++frame_count`；返回 `true`。

### 7.3 资源装载与绘制登记链路

**网格加载**（`mesh_load`）：未初始化 → `error` + `false`；否则 `mesh.mesh_create(handle_out, data)`（顶点/索引**共用缓冲**上传至设备本地，句柄自 1 起，0 表无效）。

**网格卸载**（`mesh_unload`，本轮改造）：未初始化直接返回；`mesh.mesh_detach(handle, record)` 摘出记录（句柄无效 / 记录已空则返回）；把 `{record.buffer, record.allocation}` 组装进 `Deferred_Entry`（`memory_resources`）并 `frame.deferred_push(…, frame.in_flight_count_get() + 1)`——**不再**立即 `mesh_destroy`（由帧模块到期经内存模块归还，见 §6.15 与 《渲染层-帧》§7.7）。

**绘制登记**（`mesh_draw`）：
1. 未初始化 → `error` + `false`；
2. `mesh.mesh_record_get(handle, mesh_buffer, index_offset, index_count)`；句柄无效 → `error` + `false`；
3. `pending_transforms.emplace_back()` 追加一块存储，写入 `transform`（`nullptr` → 单位矩阵，否则拷贝 16 浮点）；
4. 组装 `Frame_Render_Item`（`pipeline`/`layout` 取自管线模块（**`pipeline_get()` 返回当前激活管线**），`vertex_buffer = index_buffer = mesh_buffer`、`index_offset` 逐项带入，描述符集延迟填装，`push_constants = 该块 data()`、`push_constant_size = 64`）；
5. `pending_items.push_back(item)`（**不再先 clear**）；同帧可多次调用登记多个网格，由下一个 `frame_render` 消费后统一清空。

**纹理加载**：`texture_load` / `texture_load_checkerboard` 进入即 `handle_out = 0`；未初始化 → `error` + `false`；否则转 `texture.texture_create_*`。

**纹理切换**（`texture_bind_set`）：未初始化直接返回；目标 = 句柄为 0 则默认白纹理，否则句柄；`texture_bind_get` 失败再回落默认白纹理（仍失败 → `error` 返回）；**记录 `bound_view = view`（本轮起）**；**先 `frame.frames_wait()` 收口全部在途帧（本轮新增）**；逐帧槽 `pipeline.texture_bind`（只写 `set1`，不再记录 `current_texture`）。

**纹理卸载**（`texture_unload`，本轮改造）：未初始化直接返回；`texture.texture_detach(handle, record)` 摘出记录（句柄无效 / 记录已空则返回）；**若摘出的 `record.view == bound_view` 则先 `texture_bind_set(0)` 回落内置默认白纹理**；把 `{image, image_allocation, view}` 组装进 `Deferred_Entry`（`memory_resources`）并 `frame.deferred_push(…, frame.in_flight_count_get() + 1)`——**不再**立即 `texture_destroy`。

**字体加载**（`font_load_file`，本轮新增）：进入即 `handle_out = 0`；未初始化 → `error` + `false`（句柄保持 0）；否则转 `font.font_load_file(handle_out, path, pixel_height)`。

**字体卸载**（`font_unload`，本轮新增）：未初始化直接返回；**① 先**清除该字体的文本网格缓存并归还网格（`mesh.valid()` 时逐条 `mesh.mesh_destroy` 后从 `text_meshes` 移除），**② 再**转 `font.font_destroy(handle)`。

**文字绘制登记**（`text_draw`，本轮新增）：见 §3.4.34，时序为「字体句柄判活 → 空文本早返 → 懒登记文字管线 → 命中 / 新建网格（几何经 `text_geometry_build`）→ `pipeline_bind_set(text_pipeline)` ＋ `texture_bind_set(图集纹理)` → 取交换链尺寸 → 像素→NDC 矩阵 → `mesh_draw(网格, 矩阵)` 登记」。空文本返回真但**不登记**；任一环节失败均**不登记**绘制项。

### 7.4 相机链路

- **设置**：`camera_position_set` / `camera_target_set` / `camera_fov_set` / `camera_near_far_set` 未初始化静默返回，否则转相机同名方法（`position_set` / `target_set` / `fov_set` / `near_far_set`）。
- **宽高比**：`init` ⑱ 与每次 `frame_render` 步骤 6 由门面刷新（**上层无法直接设 aspect**）。
- **每帧矩阵**：`frame_render` 步骤 8 调 `camera.view_proj_get(view_proj)` 写入本帧槽 UBO → 顶点着色器经 `set0` 读取。

### 7.5 UI 通道接线链路（本轮新增）

时序（上层 → 门面 → UI 通道/平台/帧模块）：

1. **init 完成后**：上层调 `Renderer::ui_channel()` 取通道句柄（须已包含扩展头 `渲染器_UI通道.h`）；以 `Ui_Channel_Context::valid()` 佐判可用性。
2. **上层填 ImGui**：上层读 `ui_channel()->info_get()`，把 `Ui_Channel_Info` 字段填进 `ImGui_ImplVulkan_InitInfo`（字段对齐），完成 `ImGui_ImplVulkan_Init` 等（**非渲染层职责**）。
3. **上层注册回调**：`ui_channel()->event_callback_set(fn, user_data)` 供平台后端（imgui_impl_sdl3）处理输入；`ui_channel()->draw_callback_set(fn, user_data)` 注册每帧绘制回调。
4. **每帧事件**：门面 `frame_render` ① 调 `platform.events_pump()`；平台在泵事件时经 `init` ⑲ 设置的 `event_forward_set` 桥接，把每个 SDL 事件交 `ui_channel.event_dispatch(event)` → 若上层已注册事件回调则转发（未注册为空操作）。
5. **每帧绘制**：门面 `frame_render` 步骤 10 调 `frame.render(..., ui_channel.draw_callback_get())`；帧模块在场景渲染 pass 内、`vkCmdEndRendering` 之前调用该回调（未注册时为空操作），上层在回调内调 `ImGui_ImplVulkan_RenderDrawData` 绘制 UI（与场景共用同一动态渲染通道）。
6. **shutdown**：门面先 `platform.event_forward_clear()` 解除桥接，再 `platform.destroy()`，最后 `ui_channel.destroy()` 复位通道信息与回调。

> UI 通道内部（信息结构字段、回调存取、事件分发）见同层 `UI通道.md`；帧侧的 UI 回调时机与动态渲染通道细节见同层 `帧.md`。

### 7.6 关闭链路（`Renderer::shutdown`）

见 §6.3 顺序表。要点：
- `impl == nullptr` 直接返回；
- 依次 `frame → 文本网格归还（本轮新增）→ mesh → font（本轮新增）→ texture → render_target（本版次新增）→ 场景 UBO 与实例缓冲归还（条件 `memory.valid()`）→ 管线 → 着色器模块（含具名管线两模块）→ shader → swapchain → memory → 解除事件桥接（`platform.event_forward_clear`）→ 平台 → 设备`（**先平台后设备**：平台持有「借用」的实例句柄，`vkDestroySurfaceKHR` 要求实例仍在途，而设备销毁会连带 `vkDestroyInstance`；桥接须在平台销毁前解除）；
- 复位 `default_texture` / `vert_module` / `frag_module` / `pending_items` / `pending_transforms` / `ui_channel`（`destroy()`）/ `frame_count` / `initialized`；**另**在着色器模块回收后 `materials.clear()` 与 `bound_pipeline_request` 复位（**本轮新增**：材质记录清空，其具名管线已随 `extra_pipelines` 释放）；**第九轮补** `blend_pipelines.clear()`（blend 档缓存管线亦已随 `extra_pipelines` 释放；材质卸载不释放具名管线）；
- 析构兜底：`~Renderer` 再调 `shutdown`，此时 `initialized` 假、各子模块已复位，为无操作。

### 7.7 关键异常与边界分支

| 分支 | 触发条件 | 门面行为 | 后续 |
| --- | --- | --- | --- |
| 构造分配失败 | `new(std::nothrow)` 返回空 | `impl == nullptr` | `init` → `error` + `false`；查询接口对空 `impl` 兜底；`ui_channel` 返回空 |
| `init` 已初始化 | `impl->initialized` 真 | `warn`，返回 `true`（不重载配置） | 调用方继续 |
| `init` 尺寸为零 | `width/height == 0` | `error` + `false`（**不 shutdown**，尚未建资源） | 调用方修正配置 |
| `init` 在途帧越界 | `frame_overlap ∉ [1,3]` | `error` + `false` | 同上 |
| `init` 任一阶段失败 | 子模块 `build`/`load` 返回假 | `error`（带阶段）+ `shutdown` 逆序回退 + `false` | 状态回到未初始化 |
| 窗口最小化 / 请求退出 | `platform.close_requested() || platform.minimized()` 真（合并判断） | 清空 `pending_items` 与 `pending_transforms` 后返回 `true`（挂起本帧 / 交调用方收敛） | 下一帧继续 / 调用方收敛循环 |
| 在途帧数超过图像可用信号量数 | `effective.frame_overlap > swapchain.image_available_count_get()` | `warn` 并下调至信号量数（K13） | 按下调后帧数构建帧槽 |
| UI 通道最小图像数不足 | `min_image_count < 2`（imgui 要求） | UI 通道内部记 `warn`（不影响 init 成功） | 调用方可把在途帧数设为 2/3 |
| 尺寸变化重建失败 | `swapchain.rebuild` 假 | `warn`，本帧继续（随后仍调 `pipeline_rebuild`） | 后续帧再试 |
| 交换链重建后格式变化 | 重建后 `format_get` / `depth_format_get` 变化 | 调 `pipeline.pipeline_rebuild` 重建图形管线（失败仅 `warn`；格式未变时空操作） | 本帧继续 |
| 帧槽等待失败 | `frame.slot_wait()` 假 | `error` + `false` | 调用方决定是否继续 |
| 场景 UBO 写失败 | `memory.buffer_write` 假 | `error` + `false` | 同上 |
| 帧渲染失败 | `frame.render` 假 | `error` + `false` | 同上 |
| 呈现路径要求重建 | `rebuild_needed` 真且本帧未重建 | 尺寸非零则 `swapchain.rebuild` 后调 `pipeline.pipeline_rebuild`（均不检查返回，失败仅 `warn`） | 下一帧继续 |
| 未初始化调用 `mesh_load`/`texture_load` 等 | `!initialized` | `error` + `false`（句柄保持 0） | —— |
| 未初始化调用 `camera_*`/`texture_bind_set`/`texture_unload` | `!initialized` | 静默返回 | —— |
| 无效网格句柄绘制 | `mesh.mesh_record_get` 假 | `error` + `false` | —— |
| `ui_channel()` 在未初始化/已关闭时调用 | `impl != nullptr` 但 `!initialized` | 返回非空指针（通道未必 `valid()`），**不**拒绝 | 调用方应以 `Ui_Channel_Context::valid()` 佐判 |
| 具名管线登记失败 | `pipeline_load` 任一步失败 | 回收已加载模块、记 `error` 返回 `false`、句柄保持 0 | 调用方处理 |
| 无效管线句柄选择 | `pipeline_bind_set` 收到未登记句柄 | `warn` 并回落默认场景管线（`bound_pipeline_request = 0`） | 该项绘制走默认管线 |
| 创建渲染目标失败 | `render_target.target_create` 假 | 记 `error` 返回 `false`、句柄保持 0（不留半初始化资源） | 调用方重试 |
| 无效渲染目标句柄设定 | `render_target_set` 收到未登记句柄 | `warn` 并回落交换链路径（`active_target = 0`） | 本帧走交换链路径 |
| 离屏帧渲染失败 | `frame.render_to_target` 假 | 记 `error("离屏帧渲染失败")` 返回 `false` | 调用方决定是否继续 |
| 未初始化加载字体 | `font_load_file` 且 `!initialized` | 记 `error("渲染器:: 加载字体失败：尚未初始化")` 返回 `false`（**句柄复位 0**） | 调用方先 `init` |
| 字体文件缺失 / 解析失败 | `font.font_load_file` 假 | 返回 `false`、句柄保持 0（不留半初始化记录） | 调用方换文件 / 字号 |
| 文字绘制字体句柄无效 | `font_get(font)` 返回空 | 记 `error("渲染器:: 文字绘制失败：字体句柄 {} 无效")` 返回 `false`、**不登记绘制项** | —— |
| 文字几何无可见字形 | `text_geometry_build` 假（空串 / 全空白 / 全为非 ASCII 码点） | 记 `error("渲染器:: 文字几何生成失败（文本无可见字形）")` 返回 `false`、不登记 | 调用方换文本 |
| 文字管线登记失败 | `pipeline_load("文字.vert.spv","文字.frag.spv",Alpha)` 假 | 记 `error("渲染器:: 文字管线登记失败")` 返回 `false`；`text_pipeline` 保持 0（下次 `text_draw` 重试） | 调用方检查着色器 |
| 文字绘制尺寸非法 | `extent_width()` / `extent_height()` `<= 0` | 记 `error("渲染器:: 文字绘制失败：交换链尺寸非法")` 返回 `false` | 调用方等尺寸有效 |
| 空文本绘制 | `text.empty()` | 返回 `true`，**不登记绘制项** | —— |
| 采样器各向异性请求但设备不支持 | `state.anisotropy` 真 且 `!device.anisotropy_enabled_get()` | `logger.warn("渲染器:: 设备不支持采样器各向异性，本次请求已忽略")`，状态被归一为关闭（倍数 1.0） | 采样器按关闭各向异性创建，其余状态照常 |
| 采样器各向异性倍数越界 | `state.max_anisotropy` 超设备上限 / 小于 1 | 门面钳到 `[1, 设备上限]` 后转纹理模块（**不报错**） | 采样器按钳后倍数创建 |

### 7.9 文字绘制链路（本轮新增）

时序（上层 → 门面 → 字体模块 / 网格模块 / 纹理模块 / 管线模块）：

1. **加载字体**：上层调 `Renderer::font_load_file(font, path, pixel_height)`；门面转 `font.font_load_file`（TTF 解析 → 字形光栅化 → 行式打包 → 图集纹理上传 → 登记度量，见《渲染层-文字》§7.2），成功写出句柄（≥ 1）。
2. **登记绘制**：上层调 `Renderer::text_draw(font, text, pixel_x, pixel_y)`；门面取 `font_get_mutable(font)` 判活 → 空文本直接返回真（**不登记**）→ **`font.glyphs_ensure(*record, text)` 惰性补烘非 ASCII 字形**（本轮起；见《渲染层-文字》§7.7）→ 懒登记文字管线（`pipeline_load("文字.vert.spv","文字.frag.spv", Blend_Mode::Alpha)`，缓存 `text_pipeline`）→ 按 `(font, text)` 命中 `text_meshes`，或 `text_geometry_build` ＋ `mesh_create` 新建并缓存 → `pipeline_bind_set(text_pipeline)` ＋ `texture_bind_set(atlas_texture)` → 构造像素→NDC 矩阵 → `mesh_draw(网格, 矩阵)` 登记一个绘制项。
3. **消费绘制**：下一次 `frame_render` 按本帧槽填装描述符集与实例缓冲后提交；文字片元直接输出图集纹理色（RGB 恒白、A 为覆盖率），边缘羽化由**管线 Alpha 混合档**完成（见《渲染层-文字》§6.5）。
4. **卸载**：上层调 `Renderer::font_unload(font)`；门面**先**清除该字体的文本网格缓存并归还网格，**再** `font_destroy`（归还字形图集纹理）。

**要点**：① 文字管线与图集纹理绑定须在 `mesh_draw` **之前**完成；② `text_draw` 覆盖「当前纹理」，其后绘制场景项须重新 `texture_bind_set`；③ 文字项与场景项共享同一实例缓冲与描述符集（见 §6.13）。

### 7.10 同帧多 pass 后处理链路（本轮新增）

时序（上层 → 门面 → 渲染目标模块 / 管线模块 / 网格模块 / 纹理模块 / 帧模块）：

1. **创建同尺寸目标**：上层调 `Renderer::render_target_create(target, extent_width(), extent_height())`（**目标须与交换链同尺寸**）。
2. **设定路径**：上层调 `Renderer::render_target_present_set(target)`（0 关闭）；门面校验句柄有效后 `impl->present_target = target`（**优先于 `render_target_set`**，见 §3.4.37）。
3. **登记场景**：上层按需 `mesh_draw` / `text_draw` 登记本帧场景项（将被渲染进目标）。
4. **每帧兑现**：`frame_render` 中，若 `present_target != 0`：`post_resources_ensure()` 惰性建后处理管线与全屏网格；向本帧实例存储追加单位矩阵；把目标颜色写入各帧槽**后处理采样器集**（`pipeline.post_texture_bind`）；组装 `post_item`（`pipeline_by_handle_get(post_pipeline)` / `layout_get()` / `scene_set_get(slot)` / `post_set_get(slot)` / 全屏网格 / 实例；后处理管线 + 布局）→ `frame.render_to_target_present(swapchain, target, pending_items, post_item, ...)`（**同帧两 pass**，见《渲染层-帧》§6.17）。
5. **回读 / 校验**：如需回读，回读来源为**交换链**颜色附件（后处理输出）。
6. **画面一致性**：后处理 pass 按帧缓冲坐标 1:1 取源，故与「同场景直接走交换链路径」的回读画面一致（用例验收项，见「单元测试-渲染」文档）。
7. **前置不完整回落**：目标 / 全屏网格 / 后处理资源 / 实例存储不满足时，逐级回落离屏路径或交换链路径（并 `warn`）。

**要点**：① 该路径**不经 UI 回调**；② 单位矩阵必须在实例缓冲写入**之前**追加，否则后处理四边形拿不到实例来源；③ 同帧多 pass 与离屏路径共用同一批帧槽与帧计数轮转。

### 7.11 资源卸载收口链路（本轮新增）

时序（上层 → 门面 → 子模块 / 帧模块）：

1. **卸载请求**：上层调 `mesh_unload(h)` / `texture_unload(h)` / `render_target_destroy(h)`；
2. **前置回落**：`render_target_destroy` 先把 `active_target` / `present_target`（等于 `h` 时）置 0；`texture_unload` 若目标视图等于 `bound_view` 则 `texture_bind_set(0)` 回落默认白纹理（**注意**：`texture_bind_set` 内部还会 `frames_wait`）；
3. **摘出**：门面调对应子模块的 `mesh_detach` / `texture_detach` / `target_detach`——摘出记录（写出到出参、原记录复位）但**不**归还资源；句柄无效 / 记录已空则直接返回；
4. **组装与压入**：把摘出的缓冲 / 图像 / 视图填入 `Deferred_Memory_Resource`（渲染目标为颜色与深度**各一条**），组装 `Deferred_Entry` 后调 `frame.deferred_push(entry, frame.in_flight_count_get() + 1)`（`release_frame = frame_count + 在途帧数 + 1`）；
5. **到期归还**：帧模块每帧末尾 `deferred_flush()` 检查，`release_frame <= frame_count` 时 `deferred_entry_release` 经内存模块 `buffer_destroy` / `image_view_destroy` / `image_destroy` 归还；
6. **写长命对象前收口**：`texture_bind_set` / `texture_bind_target`（写满 `set1` 前）、`texture_sampler_state_set`（重建共享采样器前）、`pipeline_unload`（注销管线前）均先 `frame.frames_wait()`。

**材质链**：上层调 `material_load`（登记；非不透明档按 blend 档**共享** `blend_pipelines` 中的具名管线）→ `material_bind_set`（登记绘制项**之前**）→ 绘制 → `material_unload`（**不**释放具名管线，其随 `shutdown` 的 `extra_pipelines` 释放）。

**口径**：见 §6.15 与《渲染层-帧》§7.7；本路径即「校验消息 6 → 0」的直接成因。

### C. 本模块在渲染层中的双重身份速记

| 身份 | 说明 |
| --- | --- |
| **对外门面** | 渲染层唯一对外类型 `engine::Renderer`；PIMPL 收口；上层只用 init / frame_render / shutdown 三段式（接入 ImGui 时另经公共扩展头取 UI 通道） |
| **内部编排者** | 值持有并编排十三个子模块（平台/设备/内存/交换链/帧/着色器/管线/网格/场景/纹理/渲染目标/字体/UI 通道）的构建与销毁顺序 |
| **句柄中转站** | 子模块之间的依赖（交换链←内存、帧←交换链、网格←内存、纹理←内存/设备、字体←纹理、UI 通道←设备/平台/交换链口径）均经门面在 `init` 中撮合，子模块之间不直接互相持有 |
| **全层检查出口承载者** | `core/结果检查.h` 是全渲染层 VkResult 检查的唯一出口 |
| **UI 接线点** | 门面只提供 `ui_channel()` 并做「构建 ⑲ / 事件桥接 / 每帧回调传入 / 关闭解除并复位」四处接线（UI 通道内部见同层 `UI通道.md`） |
| **文字接线点** | 门面把「文字管线懒登记 / `(字体, 文本)` 网格缓存 / 像素→NDC 矩阵 / 绘制登记」收在自己这里，字体模块只产图集与度量（见 §6.13 与《渲染层-文字》） |
| **材质接线点（本轮新增）** | 门面把材质登记 / 卸载 / 绑定（`material_load` / `material_unload` / `material_bind_set` ＋ `Material_Record`）收在自己这里；语义类型来自 Vulkan-free 公共头 `Pipeline/材质数据.h`（见 §6.15） |
| **资源卸载收口点（本轮新增）** | 门面运行时卸载网格 / 纹理 / 渲染目标改走「摘出 → `deferred_push` 延迟销毁」，并在写长命对象前 `frames_wait` 收口在途帧（见 §6.15） |
| **EngineCore 唯一接线点** | 渲染层只经预编译头与日志系统接 `EngineCore`，不接 `EngineSystem` 聚合面 |

### D. 本模块待确认条目索引

本模块条目（`R-FACADE-01~05`）此前已全部确证且已撤标；**本版次（第八轮）**新增见下。

- **R-FACADE-06（**已解决 · 版次 `cb766f1`**）**：`texture_bind_target` 与 `texture_sampler_state_set` 的绑定覆盖问题。本轮起门面以 **`bound_view`**（当前绑定视图）取代 `bound_texture_request`——`texture_bind_target` 记 `bound_view = 目标颜色视图`，采样器状态切换后以 `{新采样器, bound_view}` 重写全部帧槽 `set1`，故不再按纹理句柄回落而覆盖目标绑定。正文 §6.10 易错点 18 与 §3.4.31 已记为已解决、**撤除 `【待确认】` 标记**（口径见 §6.15 / §3.4.31）。
- **R-FACADE-07**：`text_draw` 会把字形图集绑为「当前纹理」（`texture_bind_set(record->atlas_texture)`），**覆盖此前纹理绑定**；且文字项与场景项**共享同一实例缓冲与描述符集**（各绘制项的管线 / 图集 / 纹理绑定须在登记该项**之前**完成，见 §6.13 与 §6.10 易错点 17 / 22）。以实现为准，登记待确认（是否应让门面在 `frame_render` 按项重绑纹理，而非依赖「登记前绑定」的隐式约定；以及共享实例缓冲下文字与场景混排的容量边界，待上层定夺）。
- **R-FACADE-08（本轮新增）**：同帧多 pass 后处理路径（`render_target_present_set` → `frame.render_to_target_present`）**要求目标范围与交换链范围一致**（后处理按帧缓冲坐标 1:1 取源），但门面与帧模块**均未校验该一致性**（仅依赖调用方契约），且该路径**不经 UI 回调**。以实现为准，登记待确认（是否应在门面设定时校验目标尺寸与交换链一致并告警，待上层定夺；对应帧模块 `R-FRAME-09`）。
- **R-FACADE-09（本版次第八轮新增）**：`Frame_Stats` / `frame_stats_get` 的口径为门面所定——`frames` 取门面 `impl->frame_count`（与 `frame_count()` 同口径），`frame_ms` / `draw_items` / `instances` 取自帧模块三 getter（**主机侧**墙钟耗时、按**登记项**累计，**不含 GPU 时间戳**）。是否应补 GPU 时间戳、或把绘制统计改为「仅计实际绘制项」，源码未定；以实现为准，登记待确认（对应帧模块 `R-FRAME-10`）。

- **R-FACADE-10（本版次第九轮新增）**：`gpu_frame_ms` / `gpu_timestamp_supported` 的**口径**为门面所定——二者均**透传帧模块**（`Frame_Stats.gpu_frame_ms` 取自 `last_gpu_frame_ms_get()`；`gpu_timestamp_supported()` 转调 `gpu_timestamp_supported_get()`），门面自身不度量，故其口径与前一轮 `R-FACADE-09`（`frame_ms` 主机侧）**同源但不同量**（GPU 侧）；`scene_apply` **无条件覆盖**相机五项 ＋ 清屏色、**不校验**取值范围（近远反序、负视场角、零长度位置向量等照单写入，由相机侧承受退化）。是否应校验 / 归一场景描述字段，源码未定；以实现为准，登记待确认（对应帧模块 `R-FRAME-11`）。
