# 渲染层-管线 · 模块架构

> 源码根相对路径：`Application/Renderer/src/render/Pipeline/`
> 本文覆盖 `Pipeline/` 下的对外头 `管线.h`（门面类型 `Pipeline_Context` 与配置结构 `Pipeline_Config`）、私有头 `局部命名空间使用.h`，以及 `core/` 下的四个编译单元：`管线.cpp`、`描述符布局.cpp`、`管线布局.cpp`、`图形管线.cpp`。**本版次新增**共用头 `管线数据.h`：Vulkan-free 的公共语义类型 `enum class Blend_Mode`（与门面公共头 `渲染器.h` 共用，故公共面仍零 Vulkan 类型）。
> 本模块的职责是「把图形管线（`VkPipeline`）及其全部前置基础设施——描述符集布局（`VkDescriptorSetLayout`）、管线布局（`VkPipelineLayout`）、描述符池（`VkDescriptorPool`）与按帧槽分配的描述符集——收拢为一个门面」，并提供「构建基础设施 → 构建图形管线 → 每帧写描述符 → 销毁」的极简接口。**本轮新增**共用头 `材质数据.h`：Vulkan-free 的材质公共语义类型 `Material_Handle` / `Material_Data`（由门面公共头 `渲染器.h` 引用；本模块只提供该语义头，不实现材质逻辑，见 §3.5 / 附录 B）。
> 本模块采用 Vulkan **动态渲染（Dynamic Rendering）**路线：图形管线创建时 `renderPass = VK_NULL_HANDLE`，颜色/深度附件格式经 `VkPipelineRenderingCreateInfo` 通过 `pNext` 链入，不创建任何 `VkRenderPass` 与 `VkFramebuffer`，与帧模块的 `vkCmdBeginRendering` / `vkCmdEndRendering` 配对使用。
> 记录依据为当前工作区源码，不包含任何旧版次导航信息。文中文件路径口径统一为：**头文件写项目根全路径**（`Application/Renderer/...`）；**实现文件（.cpp）的跨目录包含写本层根相对**（`src/render/...`，本层根 = `Application/Renderer/`）；**私有包含根 = 项目根 ＋ 本层根**。
> 本模块的全部 `VkResult` 检查走渲染层统一出口（实现文件包含口径 `src/render/Renderer/core/结果检查.h`）提供的 `vk_result_check`；该头物理上归属「渲染层-渲染器」模块，本文在需要处标注其归属。

## 二、模块功能介绍

### 2.1 模块定位

「管线」模块位于渲染层源码目录 `Application/Renderer/src/render/Pipeline/`，与着色器模块（`render/Shader/`）、网格模块（`render/Mesh/`）、纹理模块（`render/Texture/`）并列为渲染层「绘制侧」的中层模块之一。它把 Vulkan 中「图形管线创建」所需的**全部前置对象**（描述符集布局、管线布局、描述符池、每帧槽描述符集）与**图形管线本身**（`VkPipeline`）收拢进一个门面类 `Pipeline_Context`，对外只暴露「构建一次基础设施 + 构建一次图形管线 + 一组 getter + 每帧写描述符 + 销毁」的极简接口。

一句话概括：**本模块是渲染层「把着色器模块、顶点布局、固定功能状态、描述符资源约定固化为一个可绑定的图形管线」的唯一入口，是帧模块录制绘制命令时的核心依赖。**

### 2.2 职责边界与解决的问题

`Pipeline_Context` 解决的问题可归纳为**七点**：

1. **完成「描述符集布局」的固化**。Vulkan 要求着色器资源在管线创建前以「集合布局（set layout）」声明：本模块固定两个集合——`set 0` 为场景统一缓冲（`VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER`，顶点阶段可见），`set 1` 为组合图像采样器（`VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER`，片元阶段可见）。整套「binding / 类型 / 数量 / 阶段可见性」在本模块内一次性定死，调用方无需重复描述资源约定（见 `core/描述符布局.cpp`，逐条行为见 §四.2）。

2. **完成「管线布局」的固化**。管线布局串联「描述符集顺序（set0 → set1）」与「推送常量范围」。本模块固定：推送常量 `offset = 0`、`size = 112`（`0..63` 矩阵占位、`64..79` 文字颜色、`80..95` 后处理「源 / 宿尺寸」、`96..111` 后处理泛光参数），顶点 ＋ 片元阶段可见（**第十六 / 十七 / 二十一轮**）；描述符集顺序恒为 `{ scene_set_layout, sampler_set_layout }`（见 `core/管线布局.cpp`，逐条行为见 §四.3）。

3. **完成「描述符池与每帧槽描述符集」的分配**。为避免在途帧（in-flight frame）之间争夺同一描述符集，本模块按 `config.frame_overlap`（在途帧数）为**每个帧槽**各分配一个 `set 0`（场景 UBO）描述符集、一个 `set 1`（采样器）描述符集，以及 `POST_SET_PER_SLOT` 个后处理采样器描述符集（同 `set 1` 布局、独立分配），池容量按「`UNIFORM_BUFFER × frame_overlap` + `COMBINED_IMAGE_SAMPLER × frame_overlap × (1 + POST_SET_PER_SLOT)`」精确配置、`maxSets = frame_overlap × (2 + POST_SET_PER_SLOT)`（见 `core/管线.cpp` 的 `build`）。

4. **完成「图形管线」的创建**。本模块把着色器阶段、顶点输入、输入装配、视口/裁剪、光栅化、多重采样、深度/模板、颜色混合、动态状态与动态渲染信息一次性固化为 `VkGraphicsPipelineCreateInfo` 并调用 `vkCreateGraphicsPipelines`（见 `core/图形管线.cpp`，逐条行为见 §四.4，固定功能全量说明见 §六.4）。顶点布局与 `Mesh` 模块的 `Vertex` 结构严格对齐（步长 **32** 字节：位置 `vec3` @0、纹理坐标 `vec2` @12、法线 `vec3` @20），并由四条 `static_assert` 在编译期锚定字面量与 `Vertex` 真实布局一致。**本版次起**本模块由「单一管线」扩为「按句柄的管线工厂 / 缓存」：可登记多条**具名图形管线**（句柄自 1 起），并**全部共享同一管线布局与描述符集布局**，仅允许「着色器对 ＋ 混合档」不同（见 §3.3.14 与 §六.5）。而 `pipeline_rebuild` 使**全部**已登记管线可在交换链格式变化时按新格式重建（见 §六.5）。

5. **提供「每帧写描述符」的便捷入口**。本模块对外提供 `scene_bind(slot, ubo_buffer)`（把第 `slot` 帧槽的 `set 0` 指向某场景 UBO 缓冲）、`texture_bind(slot, sampler, view)`（把第 `slot` 帧槽的 `set 1 binding 0` 指向某采样器与图像视图）与 `shadow_bind(slot, sampler, view)`（**第五十二轮新增**，写 `set 1 binding 1` 的阴影图），使上层在「每帧槽资源（主机可见 UBO 按帧轮转）」与「长命资源（默认纹理一次写满全部帧槽）」两种场景下都能以单次调用完成描述符写入。

6. **提供幂等销毁与析构兜底**。本模块的 `destroy()` 严格按「图形管线 → 描述符池 → 管线布局 → 采样器集布局 → 场景集布局」的逆序释放，并清空容器与句柄，可重复调用（第二次及以后为无操作）；析构函数内部再调一次 `destroy()`，保证「显式销毁 + 析构」不重复释放、半初始化状态下也能安全回退。

7. **提供 Vulkan-free 的材质公共语义类型（本轮新增）**。本目录另定义共用头 `材质数据.h`（`Material_Handle` / `Material_Data`），与 `管线数据.h` 同构——只放渲染层公共面需要暴露的引擎语义类型（**不含** Vulkan / VMA / SDL3 / glm），由门面公共头 `渲染器.h` 引用，避免公共头为一个结构而引入含 Vulkan 类型的 `管线.h`（逐字段见 §3.5）。

### 2.3 在整体架构中的位置

管线模块处于渲染层依赖链的中层偏上：它**向下**依赖设备模块提供的逻辑设备句柄（`VkDevice`）、交换链模块提供的**颜色/深度附件格式**（经 `Pipeline_Config` 注入）、着色器模块提供的顶点/片元着色器模块句柄（`VkShaderModule`）、网格模块提供的顶点布局约定（`Vertex` 结构）、以及渲染层统一的 `VkResult` 检查出口与引擎日志系统；**向上**被「渲染层-渲染器」门面（`Renderer::Impl`）持有并驱动。

```
                ┌────────────────────────────────────────────────────────────┐
                │                  Renderer（渲染器门面）                      │
                │  init：⑪ pipeline.build(...) → ⑫ pipeline.pipeline_build(...)│
                │  render：pipeline.scene_bind / scene_set_get / sampler_set_get│
                │  mesh_draw：pipeline.pipeline_get / layout_get                │
                │  shutdown：pipeline.destroy()                                 │
                └───────────┬───────────────────────────────────┬────────────┘
                            │ 驱动（build / pipeline_build / bind / destroy）│
                            ▼                                               │
        ┌───────────────────────────────────────────────────────────────┐  │
        │                  Pipeline_Context（管线上下文）                 │  │
        │  scene_set_layout / sampler_set_layout / pipeline_layout        │  │
        │  descriptor_pool / scene_sets[] / sampler_sets[] / pipeline     │  │
        └───┬──────────────┬───────────────┬──────────────┬──────────────┘  │
            │依赖           │依赖            │依赖           │依赖             │
            ▼               ▼                ▼               ▼               │
    ┌─────────────┐ ┌─────────────┐ ┌──────────────┐ ┌──────────────┐      │
    │ 设备模块     │ │ 交换链模块   │ │ 着色器模块    │ │ 网格模块      │      │
    │ VkDevice    │ │ 颜色/深度格式│ │ VkShaderModule│ │ Vertex 布局  │      │
    └─────────────┘ └─────────────┘ └──────────────┘ └──────────────┘      │
                                                                            │
      提供：VkPipeline / VkPipelineLayout / VkDescriptorSet[slot]           │
                                                                            ▼
                                                          ┌──────────────────────────┐
                                                          │ 帧模块 Frame_Render_Item  │
                                                          │ 录制：绑管线 / 绑集 / 推常量│
                                                          │ vkCmdDrawIndexed          │
                                                          └──────────────────────────┘
```

- **向上**：调用方是「渲染层-渲染器」门面 `Renderer::Impl`。门面在 `init` 的 ⑪⑫ 步依次调用 `build` 与 `pipeline_build`；在 `render` 中调用 `scene_bind`、`scene_set_get`、`sampler_set_get` 把描述符集填入 `Frame_Render_Item`；在 `mesh_draw` 中调用 `pipeline_get` / `layout_get` 组装渲染项；在 `frame_render` 的两条交换链重建路径上调用 `pipeline_rebuild`，使图形管线随格式变化重建；在 `shutdown` 中调用 `destroy`。
- **向下**：依赖设备模块（`VkDevice`）、交换链模块（`format_get()` 提供颜色格式、`depth_format_get()` 提供深度格式）、着色器模块（`VkShaderModule`）、网格模块（`Vertex` 结构定义顶点步长与属性偏移）、渲染层 `结果检查.h`（`vk_result_check`）、引擎日志系统（`logger`）、Vulkan Loader（全部 `vk*` 调用）。
- **横向**：管线模块**不**持有设备/交换链/着色器/网格对象，只消费它们产出的裸句柄与常量，因此不产生与这些模块的直接编译期依赖边（唯一例外：`core/图形管线.cpp` 为取 `sizeof(Vertex)` 而包含 `src/render/Mesh/网格数据.h`）。

### 2.4 与相邻模块的职责分界

| 相邻模块 | 分界 |
| --- | --- |
| 设备模块（`render/Device/`，`Device_Context`） | 设备模块负责选物理设备、建逻辑设备、取队列；本模块**只消费**其 `device_get()` 返回的 `VkDevice` 句柄，用于创建/销毁全部 Vulkan 对象，不创建任何设备对象。 |
| 交换链模块（`render/Swapchain/`，`Swapchain_Context`） | 交换链模块负责选表面格式与深度格式；本模块**消费**其 `format_get()` 与 `depth_format_get()` 结果（由门面填入 `Pipeline_Config`），用在动态渲染信息的颜色/深度附件格式上；交换链重建后若格式变化，门面再以二者调用 `pipeline_rebuild` 重建管线。**本模块不创建交换链图像，也不创建渲染通道**——采用动态渲染，无 `VkRenderPass`。 |
| 着色器模块（`render/Shader/`，`Shader_Context`） | 着色器模块负责把 `.spv` 加载为 `VkShaderModule` 并管理其生命周期；本模块**消费**门面转交的 `vert_module` / `frag_module` 句柄，仅用于图形管线创建。**着色器模块的销毁责任归门面**（须先于着色器上下文复位），本模块不销毁传入的着色器模块。 |
| 网格模块（`render/Mesh/`，`Mesh_Context` / `Vertex`） | 网格模块定义顶点结构 `Vertex`（位置 `vec3` + 纹理坐标 `vec2` + 法线 `vec3`，步长 **32** 字节）；本模块的图形管线顶点输入状态**与之一一对应**（binding 0 步长 `sizeof(Vertex)`，属性 0 位置 `R32G32B32_SFLOAT` @0，属性 1 纹理坐标 `R32G32_SFLOAT` @12，属性 2 法线 `R32G32B32_SFLOAT` @20）。该对齐是**隐式契约**，其跨模块不变量由 `core/图形管线.cpp` 的四条 `static_assert` 在编译期锚定：`sizeof(Vertex) == 32`、`offsetof(Vertex, position) == 0`、`offsetof(Vertex, uv) == 12`、`offsetof(Vertex, normal) == 20`（`offsetof` 需 `#include <cstddef>`，因预编译头不含之，故本文件自行引入），使 binding 步长与属性偏移的字面量与 `Mesh::Vertex` 真实布局一致，两侧漂移即编译失败而非静默错配。 |
| 帧模块（`render/Frame/`，`Frame_Context`） | 帧模块负责每帧取图像、录制命令、提交与呈现。本模块**产出**其消费的三类裸句柄：`VkPipeline`、`VkPipelineLayout`、第 `slot` 帧槽的两个 `VkDescriptorSet`，由门面组装进 `Frame_Render_Item`（含 `push_constants` 与 `push_constant_size = 64`）。两者共同遵守「管线布局决定推送常量范围（顶点阶段 / offset 0 / 64 字节）」的约定。 |
| 纹理模块（`render/Texture/`，`Texture_Context`） | 纹理模块产出 `VkSampler` 与 `VkImageView`；本模块的 `texture_bind` **消费**它们写入 `set 1`。所有权归纹理模块，本模块不销毁采样器与视图。 |
| 「渲染层-渲染器」模块的 `结果检查.h` | 本模块的全部 `VkResult` 检查都调用该头提供的 `vk_result_check`；该头是渲染层内所有模块共用的唯一检查出口。 |
| 本层设计文档（含 §/K 编号） | 本模块源码注释未大量引用编号（仅 `管线.h` 头注释自述生命周期），故本文不涉及编号溯源。 |

### 2.5 生命周期

`Pipeline_Context` 与 `Pipeline_Config` 的完整生命周期为：

```
构造（default，不创建任何 Vulkan 对象）
   → build(device, config)                          ← 建描述符集布局 / 管线布局 / 描述符池 + 每帧槽描述符集
   → pipeline_build(vert, frag, blend_mode)          ← 登记 / 替换并**激活句柄 0 默认场景管线**（可重复调用）
   → pipeline_register(handle_out, vert, frag, blend) ← 登记**具名图形管线**（句柄自 1 起递增且稳定；不改变激活管线）
   → pipeline_activate(handle) / pipeline_has(handle) ← 切换 / 查询当前激活管线
   → pipeline_release(handle)                        ← 注销具名管线（句柄 0 忽略；不销毁着色器模块）
   → [交换链格式变化] pipeline_rebuild(color, depth)  ← 按新格式重建**全部**已登记管线（着色器对与各自混合档保留）
   → [上层切档] pipeline_default_blend_set(blend_mode) ← 只重建**句柄 0 默认管线**的混合档
   → [每帧] scene_bind(slot, ubo_buffer)            ← 写第 slot 帧槽 set0
            texture_bind(slot, sampler, view)        ← 写第 slot 帧槽 set1（或初始化时一次写满）
            scene_set_get(slot) / sampler_set_get(slot) ← 取句柄交给帧模块
            pipeline_get() / layout_get()            ← 取句柄交给帧模块（`pipeline_get` 返回**当前激活**条目）
   → destroy()                                      ← 幂等；逆序释放**全部**图形管线与基础设施并复位句柄
   → 析构（兜底再调用一次 destroy，保证资源不泄漏）
```

- 状态机只有两态：**未构建完成**与**构建完成**。`valid()` 的判据是「逻辑设备非空 **且** 场景集布局非空 **且** 采样器集布局非空」。
- `build` 内部任何一步失败都会调用 `destroy()` 回退已创建的部分资源，并返回 `false`；门面据此走 `shutdown()`。
- **图形管线统一由 `std::vector<Pipeline_Entry> pipelines` 承载**：句柄 0 恒为默认场景管线，具名管线句柄自 1 起递增且稳定不变；`next_handle` 记录下一个待分配句柄（初值 1），`active_handle` 记录当前激活句柄（初值 0 = 默认场景管线）。
- `pipeline_build` 需要 `valid()` 为真**且**两个着色器模块均非空；语义收敛为「**登记 / 替换并激活句柄 0 默认场景管线**」——若句柄 0 条目已存在则先销毁其图形管线再重建，并把 `active_handle` 置 0。
- `pipeline_register` 先按当前格式把图形管线建好（失败则整体拒绝、不登记任何条目），成功才登记条目并推进 `next_handle`；**不改变当前激活管线**。
- `pipeline_rebuild(color, depth)` 面向「交换链重建后格式变化」：**无任何条目**、或**两格式均未变**时为空操作；需重建时 `vkDeviceWaitIdle` 后逐条目按新格式重建（**着色器与各自混合档保留**）。门面在两条交换链重建路径调用（失败仅 `warn`）。
- `pipeline_default_blend_set(blend_mode)` 面向「上层切档」：只重建**句柄 0 默认管线**的混合档；无默认管线、或同档且管线有效时为空操作；重建前同样 `vkDeviceWaitIdle`。门面 `blend_mode_set` 调用（失败记 `error` 并保持档位记录）。
- **关键不变量**：全部图形管线（默认与具名）**共享同一 `VkPipelineLayout` 与描述符集布局**（`set 0` 场景 UBO / `set 1` 采样器），具名管线**只允许**「着色器对 ＋ 混合档」不同；着色器模块所有权一律在门面（本模块只借用、不销毁）。
- **场景 UBO 契约（第四十轮，432 字节）**：`mat4 view_proj`（0..63）＋ `vec4 light_common`（64..79；x = 环境光强度、y = 高光强度、z = 光泽度、w = 点光源数）＋ `vec4 light_dir`（80..95；xyz = 方向光方向、w = 强度，0 = 关闭）＋ `vec4 light_color`（96..111；rgb = 方向光颜色、**w = 距离衰减模式**）＋ `vec4 camera_pos`（112..127）＋ `vec4 point_pos_radius[4]`（128..191）＋ `vec4 point_color_intensity[4]`（192..255）＋ `vec4 point_spot_dir[4]`（256..319）＋ `vec4 point_spot_cone[4]`（320..383）＋ `vec4 fog_color_density`（384..399）＋ `vec4 fog_range`（400..415）＋ `vec4 ambient_color`（416..431；rgb = 环境光颜色）。`scene_bind` 的描述符 `range` 必须为 **432**，且 set0 的 `stageFlags` 必须含 **`VK_SHADER_STAGE_FRAGMENT_BIT`**。任一处按旧值保留，片元侧会静默读到 0（光照全黑或参数失效），校验层不一定报错。**std140 陷阱**：两个 `vec4[4]` 数组各自连续，故先排全部「方向 ＋ 标志」再排全部「内外锥余弦」，不可按槽交错。
- `destroy()` 可重复调用，第二次及以后为无操作；析构函数内部再调一次 `destroy()`，因此「显式销毁 + 析构」不重复释放。
- 类**不可拷贝、不可移动**（持有 Vulkan 句柄），以 `= delete` 显式删除拷贝构造与拷贝赋值；未声明移动，故移动亦不可用。

### 3.3 逐条接口说明

#### 3.3.1 `Pipeline_Context(void) = default`

- **功能**：默认构造，**不创建任何 Vulkan 对象**。
- **参数**：无。
- **返回值**：无。
- **约束**：全部成员以类内初始化器就位：`device = VK_NULL_HANDLE`、`config = Pipeline_Config{}`、各布局/池/管线句柄 `VK_NULL_HANDLE`、两个描述符集容器为空 `vector`。

#### 3.3.2 `~Pipeline_Context(void)`

- **功能**：析构，内部调用 `destroy()`，保证资源不泄漏。
- **参数**：无。
- **返回值**：无。
- **约束**：即使在部分构建（半初始化）状态下析构也安全，因 `destroy()` 逐句柄判空后再释放。

#### 3.3.3 拷贝与赋值（`= delete`）

- **功能**：显式删除拷贝构造与拷贝赋值。
- **约束**：类持有 Vulkan 句柄，**不可拷贝、不可移动**（未声明移动构造/移动赋值，故移动亦不可用）。

#### 3.3.4 `bool build(VkDevice device, const Pipeline_Config& config)`

- **功能**：构建管线基础设施——创建描述符集布局（`set 0` 场景 UBO / `set 1` 采样器）、创建管线布局（含推送常量范围）、创建描述符池并分配**每帧槽**描述符集。
- **参数**：
  - `device`：逻辑设备句柄（来自设备模块 `device_get()`）。为 `VK_NULL_HANDLE` 时报错并返回 `false`。
  - `config`：图形管线配置（拷贝存入 `this->config`）。`config.frame_overlap == 0` 时报错并返回 `false`。
- **返回值**：`bool`——全部步骤成功返回 `true`，任一步失败返回 `false`。
- **约束与异常行为**：
  - 前置校验：设备非空、`frame_overlap` 为正。二者任一不满足即记 `logger.error` 并 `return false`（**此时不调用 `destroy`**）。
  - 任一 Vulkan 调用失败（`descriptor_layouts_create` / `pipeline_layout_create` / `vkCreateDescriptorPool` / 两次 `vkAllocateDescriptorSets`），记 `logger.error`、调用 `destroy()` 回退后返回 `false`。
  - 成功时记 `logger.info`（打印在途帧数、颜色格式、深度格式的整型值）。
  - **重复调用**：本函数未在入口处先 `destroy()` 旧基础设施；若在已构建状态下再次调用，会以旧句柄被覆盖的方式泄漏旧对象。调用方应在构建前保证对象处于未构建态。

#### 3.3.5 `void destroy(void)`

- **功能**：销毁本模块创建的全部 Vulkan 对象（**全部已登记图形管线**与基础设施）并复位状态。
- **参数**：无。
- **返回值**：无。
- **约束与行为**：
  - 仅当 `device != VK_NULL_HANDLE` 时进入释放分支，释放顺序严格为：**遍历 `pipelines` 逐个 `vkDestroyPipeline(entry.pipeline)`** → `vkDestroyDescriptorPool(descriptor_pool)`（连带回收其分配的描述符集）→ `vkDestroyPipelineLayout(pipeline_layout)` → `vkDestroyDescriptorSetLayout(sampler_set_layout)` → `vkDestroyDescriptorSetLayout(scene_set_layout)`。每个 `vkDestroy*` 前均判空。
  - 释放后清空 `pipelines` / `scene_sets` / `sampler_sets`，把 `next_handle` 复位为 1、`active_handle` 复位为 0，并把 `descriptor_pool`、`pipeline_layout`、`sampler_set_layout`、`scene_set_layout`、`device` 复位为 `VK_NULL_HANDLE`，`config` 复位为默认 `Pipeline_Config{}`。（**着色器模块**存于各 `Pipeline_Entry`、所有权在门面，本模块只清空容器，不销毁模块本体。）
  - **幂等**：第二次及以后调用时 `device == VK_NULL_HANDLE`，直接跳过释放分支并复位（无操作语义）。
  - **无 `vkDeviceWaitIdle`**：本函数不做设备空闲等待，调用方须保证销毁时无在途帧仍在使用这些对象（门面在 `shutdown` 逆序编排中处理；`Frame_Context::destroy` 内部另有等待）。

#### 3.3.6 `bool valid(void) const`

- **功能**：查询是否已构建完成。
- **参数**：无。
- **返回值**：`bool`——判据为 `device != VK_NULL_HANDLE && scene_set_layout != VK_NULL_HANDLE && sampler_set_layout != VK_NULL_HANDLE`。
- **约束**：仅检查设备与两个集布局，**不检查** `pipeline_layout` / `descriptor_pool` / `pipeline` 是否创建成功（它们由 `build` 的成功路径保证）。

#### 3.3.7 `bool pipeline_build(VkShaderModule vert_module, VkShaderModule frag_module, Blend_Mode blend_mode = Blend_Mode::Opaque)`

- **功能**：**登记 / 替换并激活句柄 0「默认场景管线」**（本版次语义收敛，不再创建任意单一管线）。
- **参数**：
  - `vert_module`：顶点着色器模块句柄（来自着色器模块 `module_load`）。
  - `frag_module`：片元着色器模块句柄。
  - `blend_mode`：混合档——`Blend_Mode::Opaque` 关闭混合、直接写全通道；`Blend_Mode::Alpha` 启用源 alpha 混合 `src.rgb * src.a + dst.rgb * (1 - src.a)`，alpha 通道同源同参（`SRC_ALPHA` / `ONE_MINUS_SRC_ALPHA` / `ADD`）。默认 `Opaque`，故既有调用点无需改动。
- **返回值**：`bool`——成功 `true`，失败 `false`。
- **约束与异常行为**：
  - 前置：`valid()` 为真**且**两个着色器模块均非 `VK_NULL_HANDLE`。任一不满足即记 `logger.error("管线:: 图形管线构建前置不完整")` 并 `return false`（**此时不销毁已有管线**）。
  - 按句柄 0 查找条目（`entry_find(0)`）：不存在则 `push_back` 新建一条并把 `handle` 置 0。
  - 幂等重建：若该条目 `pipeline != VK_NULL_HANDLE`，先 `vkDestroyPipeline` 并置空，再重建。
  - 把 `vert_module` / `frag_module` 与 `blend_mode` 写入该条目，再转调 `entry_pipeline_create(entry)`（见 §四.4）；失败返回 `false`（该条目管线保持空）。
  - 成功后把 `active_handle` 置 0（激活默认管线），记 `logger.info`。
  - **不销毁传入的着色器模块**；模块生命周期归调用方（门面在 `shutdown` 中先销毁模块再复位着色器上下文）。着色器模块句柄写入该 `Pipeline_Entry`，供 `pipeline_rebuild` 按格式重建时复用；**模块所有权仍在调用方**。
  - **配套入口**：重建全部管线用 `pipeline_rebuild(VkFormat, VkFormat)`（§3.3.16），只切默认档用 `pipeline_default_blend_set(Blend_Mode)`（§3.3.17），二者协作详见 §六.5，签名见 §3.2 表。

#### 3.3.8 `VkPipeline pipeline_get(void) const`

- **功能**：获取**当前激活**图形管线句柄。
- **参数**：无。
- **返回值**：`VkPipeline`——按 `active_handle` 查找条目（`entry_find(active_handle)`）；条目存在则返回其 `pipeline`，否则返回 `VK_NULL_HANDLE`。
- **约束**：无副作用。门面在 `mesh_draw` / `mesh_draw_instanced` 中把它填入 `Frame_Render_Item::pipeline`，故**当前时刻激活的具名管线会被后续登记的绘制项采用**（换管线即由 `pipeline_activate` 经门面 `pipeline_bind_set` 切换）。

#### 3.3.9 `VkPipelineLayout layout_get(void) const`

- **功能**：获取管线布局句柄。
- **参数**：无。
- **返回值**：`VkPipelineLayout`——已创建则返回句柄，否则 `VK_NULL_HANDLE`。
- **约束**：帧模块在绑描述符集与推送常量时需要此句柄（`vkCmdBindDescriptorSets` / `vkCmdPushConstants` 的 `layout` 参数）。门面在 `mesh_draw` 中填入 `Frame_Render_Item::layout`。

#### 3.3.10 `VkDescriptorSet scene_set_get(uint32_t slot) const`

- **功能**：获取第 `slot` 帧槽的场景 UBO 描述符集（`set 0`）。
- **参数**：`slot`——帧槽索引。
- **返回值**：`VkDescriptorSet`——`slot < scene_sets.size()` 时返回对应集合；否则返回 `VK_NULL_HANDLE`（**越界不报错、不日志**，静默返回空句柄）。
- **约束**：`slot` 有效范围为 `[0, frame_overlap)`。门面在 `render` 中按本帧帧槽取值填入渲染项 `scene_set`。

#### 3.3.11 `VkDescriptorSet sampler_set_get(uint32_t slot) const`

- **功能**：获取第 `slot` 帧槽的采样器描述符集（`set 1`）。
- **参数**：`slot`——帧槽索引。
- **返回值**：`VkDescriptorSet`——`slot < sampler_sets.size()` 时返回对应集合；否则返回 `VK_NULL_HANDLE`。
- **约束**：`slot` 有效范围为 `[0, frame_overlap)`。门面在 `render` 中按本帧帧槽取值填入渲染项 `sampler_set`。

#### 3.3.12 `bool scene_bind(uint32_t slot, VkBuffer ubo_buffer)`

- **功能**：向第 `slot` 帧槽写场景 UBO（`set 0`），把该集合的 `binding 0` 指向指定缓冲。
- **参数**：
  - `slot`：帧槽索引。
  - `ubo_buffer`：场景 UBO 缓冲句柄（须以 `VK_BUFFER_USAGE_UNIFORM_BUFFER_BIT` 创建，主机可见）。
- **返回值**：`bool`——写入成功 `true`，参数不完整 `false`。
- **约束与异常行为**：
  - 前置：`device != VK_NULL_HANDLE`、`slot < scene_sets.size()`、`scene_sets[slot] != VK_NULL_HANDLE`、`ubo_buffer != VK_NULL_HANDLE`。任一不满足记 `logger.error("管线:: 场景 UBO 绑定参数不完整")` 并 `return false`。
  - 缓冲描述固定为 `offset = 0`、`range = 624`（**第五十二轮由 544 扩为 624**）。`range` 与门面 UBO 分配大小必须一致（本模块不推导布局，改 UBO 须同步改此处）。
  - 描述符写：`dstBinding = 0`、`dstArrayElement = 0`、`descriptorCount = 1`、`descriptorType = VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER`，调用 `vkUpdateDescriptorSets`。
  - **注意**：`vkUpdateDescriptorSets` 的返回值被忽略（该 API 无失败返回），故本函数在参数齐备时恒返回 `true`。
  - **同步约定**：若目标描述符集可能正被在途帧使用，调用方须自行保证不在使用期间改写（门面按帧槽分离，避免跨帧争用）。

#### 3.3.13 `bool texture_bind(uint32_t slot, VkSampler sampler, VkImageView view)`

- **功能**：向第 `slot` 帧槽写采样器（`set 1`），把该集合的 `binding 0` 指向指定采样器与图像视图。
- **参数**：
  - `slot`：帧槽索引。
  - `sampler`：采样器句柄（来自纹理模块）。
  - `view`：图像视图句柄（来自纹理模块）。
- **返回值**：`bool`——写入成功 `true`，参数不完整 `false`。
- **约束与异常行为**：
  - 前置：`device != VK_NULL_HANDLE`、`slot < sampler_sets.size()`、`sampler_sets[slot] != VK_NULL_HANDLE`、`sampler != VK_NULL_HANDLE`、`view != VK_NULL_HANDLE`。任一不满足记 `logger.error("管线:: 采样器绑定参数不完整")` 并 `return false`。
  - 图像描述：`imageLayout = VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL`——即采样器期望图像处于「着色器只读最优」布局；图像由纹理模块在创建后置于该布局。
  - 描述符写：`dstBinding = 0`、`dstArrayElement = 0`、`descriptorCount = 1`、`descriptorType = VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER`。
  - **第五十二轮收窄**：只写 `binding 0`（此前同时写 0 与 1）；`binding 1` 专用于阴影图，由 `shadow_bind` 一次性写入，纹理切换不再覆盖它。
  - **等价地**：`vkUpdateDescriptorSets` 返回值被忽略，参数齐备时恒返回 `true`。

#### 3.3.13A `bool shadow_bind(uint32_t slot, VkSampler sampler, VkImageView view)`（第五十二轮新增）

- **功能**：向第 `slot` 帧槽写**阴影图**（`set 1` 的 `binding 1`），把该集合的第二采样源指向阴影目标颜色视图。
- **参数**：`slot`、`sampler`、`view` 同 `texture_bind`。
- **返回值/约束**：前置条件与 `texture_bind` 相同（设备 / 集 / 采样器 / 视图非空、slot 合法）；不满足记 `logger.error("管线:: 阴影绑定参数不完整")` 返回假。
- **写入位置**：`dstBinding = 1`、`descriptorCount = 1`、`COMBINED_IMAGE_SAMPLER`、`SHADER_READ_ONLY_OPTIMAL`。
- **调用时机**：门面 `init` ⑳ 逐帧槽调用一次（阴影目标在生命周期内固定不变，无需每帧重写）。

#### 3.3.14 `bool pipeline_register(uint64_t& handle_out, VkShaderModule vert_module, VkShaderModule frag_module, Blend_Mode blend_mode = Blend_Mode::Opaque)`

- **功能**：登记一条**具名图形管线**（句柄自 1 起递增且稳定不变）。
- **参数**：`handle_out`（出参，默认置 0，成功写出具名句柄即 `next_handle`）；`vert_module` / `frag_module` / `blend_mode` 同 §3.3.7。
- **返回值**：`bool`——成功 `true`，失败 `false`。
- **约束与异常行为**：
  - `handle_out` 先置 0。
  - 前置：`valid()` 为真**且**两个着色器模块均非 `VK_NULL_HANDLE`；否则记 error 返回 `false`。
  - **先建后登记**：以 `next_handle` 构造临时条目并按当前 `config` 格式创建图形管线（`entry_pipeline_create`）；**失败则整体拒绝，不登记任何条目**、句柄保持 0（不给调用方留半截句柄）。
  - 成功把条目 `push_back` 进 `pipelines`、`++next_handle`、写出句柄，记 `logger.info`。
  - **不改变当前激活管线**：`active_handle` 保持不变。
  - **共享不变量**：具名管线与默认管线**共享同一管线布局与描述符集布局**，仅「着色器对 ＋ 混合档」不同（见 §六.5）。

#### 3.3.15 `bool pipeline_activate(uint64_t handle)`

- **功能**：切换当前激活管线。
- **参数**：`handle`——目标句柄（0 = 默认场景管线）。
- **返回值**：`bool`——`entry_find(handle) != nullptr` 时置 `active_handle = handle` 并返回 `true`；否则记 error 返回 `false` 且**保持激活不变**。
- **约束**：仅登记过的句柄可被激活；门面 `pipeline_bind_set` 在句柄无效时先行回落默认再调用本函数。

#### 3.3.16 `void pipeline_release(uint64_t handle)`

- **功能**：注销一条具名管线。
- **参数**：`handle`——目标句柄。
- **返回值**：无。
- **约束与异常行为**：
  - 句柄 0（默认管线）直接 `return`，**默认管线不可注销**。
  - 线性查找 `pipelines`：命中则销毁其图形管线（判空且 `device` 非空）、`erase` 条目；**若被注销者正是当前激活句柄则 `active_handle = 0`（回落默认）**；记 `logger.info`。
  - **不触碰着色器模块**——模块所有权在门面（门面在 `pipeline_unload` 中另行销毁）。
  - 未命中 → 无操作。

#### 3.3.17 `bool pipeline_rebuild(VkFormat color_format, VkFormat depth_format)`

- **功能**：按新颜色 / 深度格式重建**全部**已登记图形管线（**签名由三参变两参**：混合档不再由本函数处理）。
- **参数**：`color_format` / `depth_format`——新的附件格式（通常取交换链当前格式）。
- **返回值**：`bool`。
- **约束与异常行为**：
  - `pipelines.empty()`（无任何条目）→ 直接返回 `true`（无操作）。
  - 两格式与 `config` 中两格式均相同 → **空操作**返回 `true`（无等待、无重建开销）。
  - 需重建：记 info → `vkDeviceWaitIdle`（确保旧管线不再被在途帧引用）→ 更新 `config` 两格式 → **逐条目**销毁旧管线并 `entry_pipeline_create`（**着色器对与各自混合档保留**）；任一条目创建失败即返回 `false`。

#### 3.3.18 `bool pipeline_default_blend_set(Blend_Mode blend_mode)`

- **功能**：只重建**句柄 0 默认管线**的混合档（供门面 `blend_mode_set`）。
- **参数**：`blend_mode`——目标混合档。
- **返回值**：`bool`。
- **约束与异常行为**：
  - 无默认条目（`entry_find(0) == nullptr`）→ 空操作返回 `true`。
  - 同档且该条目管线有效 → 空操作返回 `true`。
  - 需切换：`vkDeviceWaitIdle` → 销毁旧管线 → `entry->blend_mode = blend_mode` → `entry_pipeline_create`；成功记 `logger.info`。**具名管线的混合档不受本函数影响**（各自在 `pipeline_load` 登记时确定）。

#### 3.3.19 `bool pipeline_has(uint64_t handle) const`

- **功能**：查询句柄是否已登记。
- **参数**：`handle`——目标句柄。
- **返回值**：`bool`——等价于 `entry_find(handle) != nullptr`（含句柄 0 是否已登记默认管线）。
- **约束**：无副作用；门面 `pipeline_bind_set` 用它判断具名句柄是否有效，无效则回落默认。

#### 3.3.20 `VkDescriptorSet post_set_get(uint32_t slot, uint32_t index = 0) const`（本轮新增；**第十轮改动：增 `index` 形参**）

- **功能**：获取第 `slot` 帧槽的**后处理采样器描述符集**（`set 1`）中的第 `index` 档。
- **参数**：`slot`——帧槽索引；`index`——后处理采样器集档位（**`index` = 级序 % 实际目标数**；下标 0 = 场景目标、1..3 = 额外中间目标），默认 `0`。
- **返回值**：`index < POST_SET_PER_SLOT` **且** `slot × POST_SET_PER_SLOT + index < post_sets.size()` 时返回对应集合，否则 `VK_NULL_HANDLE`（`index >= POST_SET_PER_SLOT` 或下标越界均**静默返回空**）。
- **约束**：与 `sampler_set_get` **同布局、独立分配**（`post_sets`，下标 = `slot × POST_SET_PER_SLOT + index`）。用途：链式后处理第 i 级的源为第 `i % 目标数` 个中间目标，故每帧槽需「目标数」个后处理集（上限 4）；后处理 pass 用 `post_set_get(slot, index)` 采样对应中间目标，与场景 pass 的 `sampler_set_get(slot)` **互不覆盖对方绑定**。
- **第十六轮补充（双源）**：set 1 布局含 **2 个 binding**——binding 0 = 该级源、binding 1 = 第二源（门面恒写目标组首项 `targets[0]`，即场景目标）。`post_texture_bind` 只写 binding 0；binding 1 由 `post_scene_bind` 写。单源片元不声明 binding 1，多出的描述符不影响其行为。**第五十二轮**：场景采样集（`sampler_sets`）的 binding 1 改由 `shadow_bind` 写阴影图——`texture_bind` 不再写 binding 1，故「当前纹理」与「阴影图」互不覆盖（同一 set 1 布局同时承载这两种用途）。

#### 3.3.21 `bool post_texture_bind(uint32_t slot, VkSampler sampler, VkImageView view, uint32_t index = 0)`（本轮新增；**第十轮改动：增 `index` 形参**）

- **功能**：向第 `slot` 帧槽的**第 `index` 档**后处理采样器集（`set 1`）写采样器（`binding 0`）。
- **参数**：`slot` / `sampler` / `view` 同 `texture_bind`；`index`——后处理采样器集档位（默认 `0`）。
- **返回值/约束**：实现先经 `post_set_get(slot, index)` 取目标集，再写 `set 1 binding 0`；与 `texture_bind` 同口径，`imageLayout = VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL`；参数不完整（含 `post_set_get` 返回空句柄）记 `logger.error("管线:: 后处理采样器绑定参数不完整")` 返回假。

#### 3.3.22 `VkPipeline pipeline_by_handle_get(uint64_t handle) const`（本轮新增）

- **功能**：按句柄取图形管线，**不改变当前激活管线**。
- **返回值**：`entry_find(handle)` 命中则返回其 `pipeline`，否则 `VK_NULL_HANDLE`。
- **用途**：门面组装后处理绘制项时按 `post_pipeline` 句柄取管线，避免 `pipeline_activate` 的副作用（不干扰后续默认管线绑定）。

#### 3.3.23 `engine::Pipeline_Context::POST_SET_PER_SLOT`（公开常量；第十轮新增；第十五轮 2 → 4）

- **声明**：`static constexpr uint32_t POST_SET_PER_SLOT = 4;`（`管线.h`）。
- **语义**：每帧槽的后处理采样器集（`set 1`）档数。链式后处理第 i 级的源 = 第 `i % 目标数` 个中间目标，故每帧槽需「目标数」个后处理集；**目标数上限即本常量（4）**：下标 0 恒为场景目标、1..3 为额外中间目标。
- **用途**：`post_sets` 长度 = `frame_overlap × POST_SET_PER_SLOT`；`post_set_get` / `post_texture_bind` 的 `index` 合法范围为 `[0, POST_SET_PER_SLOT)`；描述符池容量与 `maxSets` 按它扩容（见 §6.3）；门面按 `级序 % 实际目标数` 取档（**不是** `% POST_SET_PER_SLOT`）。

### 3.5 `engine::Material_Handle` / `engine::Material_Data`（材质公共语义类型，`材质数据.h`；本轮新增）

**声明位置**：`Application/Renderer/src/render/Pipeline/材质数据.h`（**Vulkan-free 公共语义头**，与 `管线数据.h`、`网格数据.h`、`纹理数据.h` 同构）。

| 类型 | 形态 | 语义 |
| --- | --- | --- |
| `Material_Handle` | `using Material_Handle = uint64_t;` | 材质句柄（`0` 表无效；自 1 起、**空槽复用**），由门面 `material_load` 分配 |
| `Material_Data` | `struct`（聚合类型，无成员函数） | 材质描述：图形管线 ＋ 纹理 ＋ 混合档（字段见下表） |

- **`Material_Data` 字段**：

| 字段 | 类型 | 默认值 | 含义 | 约束 |
| --- | --- | --- | --- | --- |
| `pipeline` | `uint64_t` | `0` | 图形管线句柄 | 非 `0` 时沿用该具名管线、`blend` 被忽略（混合档在 `pipeline_load` 登记时已确定）；为 `0` 时由门面按 `blend` 决定实际管线 |
| `texture` | `uint64_t` | `0` | 纹理句柄 | 为 `0` 时回落内置默认白纹理 |

- **不含采样器状态（关键约定）**：采样器为**纹理模块共享**并烘焙进各帧槽 `set1`，故材质**不携带采样器状态**；采样器状态仍由门面 `texture_sampler_state_set` 全局控制（依据头文件注释）。
- **消费方**：门面材质三方法（`material_load` / `material_unload` / `material_bind_set`）与 `Renderer::Impl::Material_Record`（见《渲染层-渲染器》§3.4.39~§3.4.41 / §5.3）。本模块**不实现**任何材质逻辑，只提供该公共语义头。

### 4.2 `bool descriptor_layouts_create(void)`（`core/描述符布局.cpp`）

- **功能**：创建两个描述符集布局。
- **返回值**：`bool`——两者均创建成功 `true`，任一失败 `false`。
- **约束与关键行为**：
  - `set 0`（`scene_set_layout`）：`binding = 0`、`VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER`、`descriptorCount = 1`、`stageFlags = VK_SHADER_STAGE_VERTEX_BIT`（场景 UBO 仅顶点阶段可见）。
  - `set 1`（`sampler_set_layout`）：`binding = 0`、`VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER`、`descriptorCount = 1`、`stageFlags = VK_SHADER_STAGE_FRAGMENT_BIT`（采样器仅片元阶段可见）。
  - 两次 `vkCreateDescriptorSetLayout` 均经 `vk_result_check` 检查；失败即 `return false`（**不清理已创建的前一个布局**，由 `build` 失败路径的 `destroy()` 兜底）。
  - 设计动机（为何两集合、为何用组合图像采样器）见 §六.1。

### 4.3 `bool pipeline_layout_create(void)`（`core/管线布局.cpp`）

- **功能**：创建管线布局。
- **返回值**：`bool`——成功 `true`，失败 `false`。
- **约束与关键行为**：
  - 描述符集顺序固定为栈数组 `{ scene_set_layout, sampler_set_layout }`（`setLayoutCount = 2`）。
  - 推送常量范围：`stageFlags = VK_SHADER_STAGE_VERTEX_BIT | VK_SHADER_STAGE_FRAGMENT_BIT`、`offset = 0`、`size = 112`（`0..63` 矩阵占位、`64..79` 文字颜色、`80..95` 后处理「源 / 宿尺寸」、`96..111` 后处理泛光参数〔`x` = 阈值、`y` = 软膝、`z` = 强度、`w` 保留〕；**第十七 / 二十一轮**）。
  - `vkCreatePipelineLayout` 经 `vk_result_check` 检查。
  - 设计动机（集顺序、推送常量用途）见 §六.2。

### 4.4 `bool graphics_pipeline_create(VkShaderModule vert_module, VkShaderModule frag_module, Blend_Mode blend_mode, VkPipeline& pipeline_out)`（`core/图形管线.cpp`）

- **功能**：创建图形管线。把着色器阶段、顶点输入、输入装配、视口/裁剪、光栅化、多重采样、深度/模板、颜色混合（**按 `blend_mode` 生成附件混合状态**）、动态状态与动态渲染信息一次性固化。
- **返回值**：`bool`——成功 `true` 并把结果写入 `pipeline_out`；失败 `false`（并把 `pipeline_out` 复位为 `VK_NULL_HANDLE`）。
- **约束与关键行为**：
  - **本版次增出参 `VkPipeline& pipeline_out`**：创建结果写入该出参，**不再写任何成员**；由调用者 `entry_pipeline_create` 写回对应 `Pipeline_Entry`。故同一条创建逻辑可服务于默认管线与任意具名管线。
  - 颜色 / 深度格式取自成员 `config`（**全管线共享**）；`pipeline_info.layout = pipeline_layout`（**全管线共享同一管线布局**）。
  - 顶点输入 binding 0 步长 `sizeof(Vertex)`，属性 0 位置 `R32G32B32_SFLOAT` @0、属性 1 纹理坐标 `R32G32_SFLOAT` @12；三条 `static_assert` 在文件顶部锚定字面量与 `Mesh::Vertex` 布局一致（见 §5.1 文件树与 §六.4.2）。
  - `vkCreateGraphicsPipelines` 的 `pipelineCache = VK_NULL_HANDLE`、`renderPass = VK_NULL_HANDLE`、`subpass = 0`、`basePipelineHandle = VK_NULL_HANDLE`、`basePipelineIndex = -1`（默认零初始化），经 `vk_result_check` 检查。
  - 全部固定功能状态逐项说明见 §六.4。

### 4.5 `Pipeline_Entry* entry_find(uint64_t handle)` / `const Pipeline_Entry* entry_find(uint64_t handle) const`（`core/管线.cpp`）

- **功能**：按句柄**线性查找**条目的可写 / 只读两重载（条目数量很小，无需哈希）。
- **返回值**：命中返回条目指针，未命中返回 `nullptr`。
- **用途**：`pipeline_build` / `pipeline_activate` / `pipeline_default_blend_set` / `pipeline_get` / `pipeline_has` 均经它定位条目；`pipeline_release` 因需 `erase` 而以迭代器另行遍历。

### 4.6 `bool entry_pipeline_create(Pipeline_Entry& entry)`（`core/管线.cpp`）

- **功能**：以当前 `config` 格式 ＋ 该条目自身的着色器对 / 混合档创建其图形管线。
- **返回值**：`bool`——成功 `true` 并把结果写回 `entry.pipeline`；失败 `false`（条目管线保持空）。
- **关键行为**：内部先取 `VkPipeline created = VK_NULL_HANDLE`，调用 `graphics_pipeline_create(entry.vert_module, entry.frag_module, entry.blend_mode, created)`，**成功才写回** `entry.pipeline`。由公开 `pipeline_build` / `pipeline_register` / `pipeline_rebuild` / `pipeline_default_blend_set` 四处共用。

### 5.3 内部数据结构字段说明

#### 5.3.1 `Pipeline_Config`（对外结构，逐字段）

- `VkFormat color_format = VK_FORMAT_UNDEFINED`：颜色附件格式，等于交换链表面格式。经 `VkPipelineRenderingCreateInfo::pColorAttachmentFormats` 链入图形管线创建信息。
- `VkFormat depth_format = VK_FORMAT_UNDEFINED`：深度附件格式，等于交换链选定的深度格式。经 `VkPipelineRenderingCreateInfo::depthAttachmentFormat` 链入。
- `uint32_t frame_overlap = 2`：在途帧数。决定描述符池容量与 `scene_sets` / `sampler_sets` / `post_sets` 的长度。默认 2 与门面默认配置一致。

#### 5.3.2 `Pipeline_Context` 私有成员（逐字段）

| 成员 | 类型 | 初值 | 说明 | 生命周期 |
| --- | --- | --- | --- | --- |
| `device` | `VkDevice` | `VK_NULL_HANDLE` | 逻辑设备句柄，用于本模块全部 Vulkan 调用 | `build` 记入；`destroy` 复位 |
| `config` | `Pipeline_Config` | `{}` | 配置副本 | `build` 记入；`destroy` 复位 |
| `scene_set_layout` | `VkDescriptorSetLayout` | `VK_NULL_HANDLE` | `set 0` 布局：场景 UBO | `descriptor_layouts_create` 创建；`destroy` 释放 |
| `sampler_set_layout` | `VkDescriptorSetLayout` | `VK_NULL_HANDLE` | `set 1` 布局：采样器 | `descriptor_layouts_create` 创建；`destroy` 释放 |
| `pipeline_layout` | `VkPipelineLayout` | `VK_NULL_HANDLE` | 管线布局（含推送常量范围） | `pipeline_layout_create` 创建；`destroy` 释放 |
| `descriptor_pool` | `VkDescriptorPool` | `VK_NULL_HANDLE` | 描述符池（容量按帧槽精确配置） | `build` 创建；`destroy` 释放（连带回收描述符集） |
| `scene_sets` | `std::vector<VkDescriptorSet>` | 空 | 场景 UBO 描述符集，长度 = `frame_overlap` | `build` 分配；`destroy` 清空 |
| `sampler_sets` | `std::vector<VkDescriptorSet>` | 空 | 采样器描述符集，长度 = `frame_overlap` | `build` 分配；`destroy` 清空 |
| `post_sets` | `std::vector<VkDescriptorSet>` | 空 | **后处理采样器描述符集**（与 `sampler_sets` 同布局、**独立分配**），长度 = `frame_overlap × POST_SET_PER_SLOT`，下标 = `slot × POST_SET_PER_SLOT + index` | `build` 分配；`destroy` 清空（**本轮新增**；**第十轮扩容**） |
| `pipelines` | `std::vector<Pipeline_Entry>` | 空 | **图形管线条目集合**（句柄 0 = 默认场景管线，其余为具名管线） | `pipeline_build` / `pipeline_register` 增改；`pipeline_release` 移除；`destroy` 逐个销毁并清空 |
| `next_handle` | `uint64_t` | `1` | 下一个待分配的具名管线句柄（自 1 起递增） | `pipeline_register` 递增；`destroy` 复位为 1 |
| `active_handle` | `uint64_t` | `0` | 当前激活管线句柄（0 = 默认场景管线） | `pipeline_build` 置 0；`pipeline_activate` 置目标；`pipeline_release` 回落 0；`destroy` 复位 |

#### 5.3.3 `Pipeline_Entry`（模块内部结构，声明于 `管线.h`）

| 字段 | 类型 | 初值 | 含义 |
| --- | --- | --- | --- |
| `handle` | `uint64_t` | 0 | 句柄（0 = 默认场景管线；≥ 1 = 具名管线） |

### 5.4 内部类型关系与调用关系

`Pipeline_Context` 是**单一门面类**，其私有成员函数与公开接口的调用关系如下（`→` 表示「调用」）：

```
                                     ┌───────────────────────────┐
                                     │      Pipeline_Context      │
                                     └───────────────────────────┘
私有：
  entry_find ─────────→ 线性查找 pipelines（可写 / 只读两重载）
  entry_pipeline_create ─→ graphics_pipeline_create(…, pipeline_out) ─→ vkCreateGraphicsPipelines
公开：
  build ──────┬─→ descriptor_layouts_create   (core/描述符布局.cpp)
              ├─→ pipeline_layout_create      (core/管线布局.cpp)
              ├─→ vkCreateDescriptorPool
              └─→ vkAllocateDescriptorSets (×2：scene / sampler)
  pipeline_build ─┬─→ entry_find(0)（无则新建条目）
                  ├─→ vkDestroyPipeline（该条目已存在时）
                  ├─→ 写条目 vert / frag / blend
                  ├─→ entry_pipeline_create → graphics_pipeline_create
                  └─→ active_handle = 0
  pipeline_register ─┬─→ 以 next_handle 构造条目并 entry_pipeline_create（失败即整体拒绝）
                     └─→ push_back + ++next_handle（不改 active_handle）
  pipeline_activate ──→ entry_find(handle)（命中才置 active_handle）
  pipeline_release ──┬─→ 销毁该条目管线 + erase
                     └─→ 若为激活句柄则 active_handle = 0
  pipeline_rebuild ─┬─→ pipelines 空 / 格式未变：直接返回真（空操作）
                    └─→ 格式变化：vkDeviceWaitIdle → 更新 config → 逐条目 entry_pipeline_create
  pipeline_default_blend_set ─┬─→ 无默认条目 / 同档：空操作
                              └─→ vkDeviceWaitIdle → 销毁旧管线 → 改 blend → entry_pipeline_create
  pipeline_has / pipeline_get ──→ entry_find（纯查询）
  destroy ────┬─→ 遍历 pipelines 逐个 vkDestroyPipeline
              ├─→ vkDestroyDescriptorPool
              ├─→ vkDestroyPipelineLayout
              ├─→ vkDestroyDescriptorSetLayout (sampler)
              └─→ vkDestroyDescriptorSetLayout (scene)
  scene_bind ─────→ vkUpdateDescriptorSets (set0 / binding0 / UNIFORM_BUFFER)
  texture_bind ───→ vkUpdateDescriptorSets (set1 / binding0 / COMBINED_IMAGE_SAMPLER)
  valid / layout_get / *_set_get ──→ 纯读取成员，无 Vulkan 调用
析构 ───────────────→ destroy
```

用文字描述对象依赖：每条 `Pipeline_Entry::pipeline` 依赖（共享）`pipeline_layout`（创建信息里的 `layout`）；`pipeline_layout` 依赖 `scene_set_layout` 与 `sampler_set_layout`（集顺序数组）；`scene_sets` / `sampler_sets` 依赖 `descriptor_pool` 与对应集布局；`descriptor_pool` 依赖 `device`。因此**创建顺序**必须是 `device → 集布局 → 管线布局 → 描述符池 → 描述符集 → 图形管线`，而**销毁顺序**必须严格逆序。本模块的 `build` 与 `destroy` 正是按此顺序编排（图形管线按条目逐个销毁，共享基础设施最后统一销毁）。

### 5.5 `局部命名空间使用.h` 的做法说明

**内容（全文）**：

```cpp
#pragma once
#include "管线.h"

// ---------- 基本类型别名 ----------
using std::string;
using std::vector;
```

**做法**：本模块的 `core/*.cpp` 一律先 `#include "src/render/Pipeline/局部命名空间使用.h"`（实现文件本层根相对包含口径），从而在**本模块实现文件内**引入 `string`、`vector` 等标准类型别名（本模块实际仅用到 `vector`，`string` 为各模块统一的别名清单条目）。此后实现代码**一律不加命名空间前缀**（如 `vector<VkDescriptorSetLayout> scene_layouts(...)`）。这是渲染层与引擎统一的「局部命名空间使用」约定的落地：对外头 `管线.h` 保持干净（只用 `std::vector` 全名），实现文件通过私有头把冗长前缀收拢到一处。

> 说明：本模块的公共结构体 `VkDescriptorSetLayout` 等 Vulkan 类型来自 `管线.h` 中的 `<vulkan/vulkan.h>`，不需要在私有头中额外引入。

## 六、模块设计/实现细节

### 6.1 描述符集布局设计（`core/描述符布局.cpp`）

本模块把「着色器资源约定」固化在两处集布局上，采用**两个独立集合**而非单集合多 binding，理由见 §6.2。

- **`set 0`（场景 UBO）**：`binding = 0`，`VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER`，`descriptorCount = 1`，`stageFlags = VK_SHADER_STAGE_VERTEX_BIT | VK_SHADER_STAGE_FRAGMENT_BIT`（**第二十九轮**增片元阶段）。语义：逐帧更新 `mat4 view_proj`（顶点变换）、光照公共块 ＋ 方向光 ＋ 相机位置 ＋ 两个点光源数组（片元多光源累加 ＋ Blinn-Phong）；**第五十二轮**尾部追加光源空间矩阵与阴影参数（UBO 总长 624）。
- **`set 1`（采样器）**：`binding = 0`，`VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER`，`descriptorCount = 1`，`stageFlags = VK_SHADER_STAGE_FRAGMENT_BIT`。语义：反照率贴图（采样器 + 图像视图合一），供片元着色器采样。**第五十二轮**：布局第二项 `binding = 1` 同为 `COMBINED_IMAGE_SAMPLER`，语义为**阴影图**（由 `shadow_bind` 写入，场景片元 `texelFetch` 解包深度）。

**「组合图像采样器」而非分离式**：使用 `COMBINED_IMAGE_SAMPLER` 意味着逻辑上一条 binding 同时携带 `VkSampler` 与 `VkImageView`，简化了「采样器与视图分别绑定」的复杂度（本项目贴图数量少，无采样器与图像复用需求）。

### 6.2 管线布局设计（`core/管线布局.cpp`）

- **集顺序固定**：`VkDescriptorSetLayout set_layouts[2] = { scene_set_layout, sampler_set_layout }`。这决定了着色器中 `set = 0` 是场景 UBO、`set = 1` 是采样器，与 `scene_bind` / `texture_bind` 写入的 `dstSet`（`scene_sets[slot]` / `sampler_sets[slot]`）一一对应。
- **推送常量范围**：`{ stageFlags = VERTEX | FRAGMENT, offset = 0, size = 112 }`。布局：`0..63` 矩阵（占位；场景矩阵由实例属性承载）、`64..79` 文字颜色、`80..95` 后处理「源 / 宿尺寸」（`x/y` = 源宽高，`z/w` = 宿宽高；**第十七轮**）、`96..111` 后处理泛光参数（**第二十一轮**）。文字绘制项推 80 字节（offset 0）、后处理各级推 **32** 字节（offset 80，尺寸 ＋ 泛光参数）、场景路径不推送。
- **为何拆两个集合而非一个**：出于**描述符集分层意图**（非仅为对称）。按「更新频率 + 可见阶段」拆集：`set 0` 承载**场景级**资源（每帧更新、`VK_SHADER_STAGE_VERTEX_BIT` 可见），`set 1` 承载**材质/纹理级**资源（较静态、`VK_SHADER_STAGE_FRAGMENT_BIT` 可见）。两集可**按集粒度**分别绑定与更新（如按帧槽预写 `set 0`、按材质切换 `set 1`），避免整集重写。此为按集合结构与 `stageFlags` 确证的结构/跨模块约定（源码未以注释写明动机）。

### 6.3 描述符池与每帧槽描述符集（`core/管线.cpp` 的 `build`）

- **池容量精确配置（第十轮改动）**：
  - `pool_sizes[0]`：`VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER`，`descriptorCount = frame_overlap`。
  - `pool_sizes[1]`：`VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER`，`descriptorCount = frame_overlap × (1 + POST_SET_PER_SLOT) × 2`（采样器集一份 ＋ 后处理集 `POST_SET_PER_SLOT` 份，再乘 set 1 的两个 binding；**第十六轮**）。
  - `pool_info.maxSets = frame_overlap × (2 + POST_SET_PER_SLOT)`；`poolSizeCount = 2`。
- **每帧槽分配**：以布局数组调用 `vkAllocateDescriptorSets` 依次分配 `scene_sets`（set 0，`frame_overlap` 个）、`sampler_sets`（set 1，`frame_overlap` 个）与 `post_sets`（set 1 同布局、**独立分配**，`frame_overlap × POST_SET_PER_SLOT` 个，下标 = `slot × POST_SET_PER_SLOT + index`）；分配结果直接写入各自 `.data()`。三次分配均经 `vk_result_check`，失败即 `destroy()` 回退。
- **设计意图**：为「在途帧」提供各自独立的描述符集，使第 N 帧写入 `set 0`（指向本帧槽 UBO）不会破坏第 N-1 帧仍在 GPU 上执行的绘制。这是「按帧槽轮转描述符集」的标准做法，配合门面按帧槽轮转主机可见 UBO 使用。
- **无 `FREE_DESCRIPTOR_SET` 标志**：池创建未加 `VK_DESCRIPTOR_POOL_CREATE_FREE_DESCRIPTOR_SET_BIT`，因为集合不单独释放，随池整体销毁（`destroy` 中先销毁池即回收全部集合）。这是「批量生命周期」下的合理取舍，节省了 `vkFreeDescriptorSets` 调用与潜在碎片。
- **分配失败回退**：三次 `vkAllocateDescriptorSets` 均经 `vk_result_check`；失败即 `destroy()` 回退。

### 6.4 图形管线创建的全部固定功能状态（`core/图形管线.cpp`）

该编译单元固化了图形管线的**全部可配置项**，逐项如下：

#### 6.4.1 着色器阶段

- 两个阶段：`stages[0]` 为 `VK_SHADER_STAGE_VERTEX_BIT`（`module = vert_module`），`stages[1]` 为 `VK_SHADER_STAGE_FRAGMENT_BIT`（`module = frag_module`）。
- 入口名固定为 `"main"`（`pName = "main"`），两阶段一致。
- 无几何/曲面细分阶段，`stageCount = 2`。

#### 6.4.2 顶点输入（与 `Mesh::Vertex` 对齐）

- **顶点绑定**：`binding = 0`、`stride = sizeof(Vertex)`（= 20）、`inputRate = VK_VERTEX_INPUT_RATE_VERTEX`（逐顶点）。
- **顶点属性**：
  - 属性 0（位置）：`location = 0`、`binding = 0`、`format = VK_FORMAT_R32G32B32_SFLOAT`（`vec3`）、`offset = 0`。
  - 属性 1（纹理坐标）：`location = 1`、`binding = 0`、`format = VK_FORMAT_R32G32_SFLOAT`（`vec2`）、`offset = 12`。
- **对齐含义**：`Vertex = { float position[3]; float uv[2]; }`，`sizeof = 20`；`position` 占 0..11 字节，`uv` 从 12 开始占 12..19 字节。`offset = 12` 正是 `uv` 的字节偏移。
- **硬编码与静态断言**：`stride = sizeof(Vertex)` 由编译器计算（结构变化会自动跟随），而**属性格式与偏移是字面量硬编码**（`R32G32B32_SFLOAT` / `R32G32_SFLOAT` / `0` / `12`），不会随 `Vertex` 字段调整自动跟随。为此本编译单元在文件顶部（`namespace engine` 内）设三条 `static_assert`，断言字面量与 `Mesh::Vertex` 实际布局一致：`sizeof(Vertex) == 20`、`offsetof(Vertex, position) == 0`、`offsetof(Vertex, uv) == 12`（`offsetof` 需 `#include <cstddef>`，因预编译头不含之，故本文件自行引入）。若 `Vertex` 改成 `vec4` 位置或调整字段顺序，将在**编译期**报错而非静默错配。

- `topology = VK_PRIMITIVE_TOPOLOGY_TRIANGLE_LIST`（三角形列表）。

#### 6.4.5 光栅化

- `depthClampEnable = VK_FALSE`（不启用深度钳制）。
- `rasterizerDiscardEnable = VK_FALSE`（不丢弃光栅化输出)。
- `polygonMode = VK_POLYGON_MODE_FILL`（填充模式）。
- `cullMode = VK_CULL_MODE_BACK_BIT`（背面剔除）。
- `frontFace = VK_FRONT_FACE_COUNTER_CLOCKWISE`（逆时针为正面）。
- `depthBiasEnable = VK_FALSE`（不启用深度偏移；不需要阴影贴图深度偏移）。

- **绕序配合**：正面为逆时针，注释指出「配合 cube_generate 绕序」。该绕序是**跨模块一致契约**：网格端 `Mesh/core/网格加载器.cpp` 的 `cube_generate` 按逆时针生成正面三角形，管线端 `rasterization.frontFace = VK_FRONT_FACE_COUNTER_CLOCKWISE` 且 `cullMode = VK_CULL_MODE_BACK_BIT`，二者构成「正面=逆时针、剔除背面」。约定为**隐式**（无共享常量/断言），任一端改变绕序都会表现为「物体消失 / 内外翻转」。

- `rasterizationSamples = VK_SAMPLE_COUNT_1_BIT`（关闭 MSAA）。

#### 6.4.7 深度/模板

- `depthWriteEnable = VK_TRUE`（开启深度写入）。

- `depthBoundsTestEnable = VK_FALSE`（不启用深度边界测试）。
- `stencilTestEnable = VK_FALSE`（不启用模板测试；`VkStencilOpState` 未填，默认零值）。

#### 6.4.8 颜色混合

- **附件混合状态**：`blendEnable = VK_FALSE`（不混合）；`colorWriteMask = R | G | B | A`（写全部通道）。
- **全局混合状态**：`logicOpEnable = VK_FALSE`；`attachmentCount = 1`；`pAttachments = &color_attachment`。

#### 6.4.9 动态渲染信息（关键：无 renderPass）

- 声明 `VkPipelineRenderingCreateInfo rendering_info`：
  - `sType = VK_STRUCTURE_TYPE_PIPELINE_RENDERING_CREATE_INFO`。
  - `colorAttachmentCount = 1`；`pColorAttachmentFormats = &config.color_format`。
  - `depthAttachmentFormat = config.depth_format`。
  - 未设 `stencilAttachmentFormat`（默认 `VK_FORMAT_UNDEFINED`，因模板测试关闭）。
- 该结构经 `pipeline_info.pNext = &rendering_info` 链入。
- `pipeline_info.renderPass = VK_NULL_HANDLE`——**不兼容任何渲染通道**，与帧模块的 `vkCmdBeginRendering` / `vkCmdEndRendering`（动态渲染）配对使用。
- **为何用动态渲染**：避免创建 `VkRenderPass` 与每交换链图像一张 `VkFramebuffer`，使管线与「具体帧缓冲」解耦——只需知道附件格式即可建管线，交换链重建（图像数量/尺寸变化）时无需重建渲染通道。代价是管线与附件格式仍是**格式级耦合**（见 §6.5）。
- **格式来源**：`config.color_format` / `config.depth_format` 由门面从交换链模块取回，因此管线创建**必须晚于交换链创建**（门面 `init` 顺序保证了这点）。

#### 6.4.10 动态状态

- `VkDynamicState dynamic_states[2] = { VK_DYNAMIC_STATE_VIEWPORT, VK_DYNAMIC_STATE_SCISSOR }`，`dynamicStateCount = 2`。
- **含义**：视口与裁剪矩形在命令录制时动态设置（帧模块 `vkCmdSetViewport` / `vkCmdSetScissor`），故管线创建时无需也不提供静态视口。这使得同一管线可复用于不同尺寸的窗口，交换链尺寸变化**无需重建管线**（尺寸维度解耦）。

#### 6.4.11 创建信息汇总

- `sType = VK_STRUCTURE_TYPE_GRAPHICS_PIPELINE_CREATE_INFO`；`pNext = &rendering_info`。
- `stageCount = 2`；`pStages = stages`。
- `pVertexInputState` / `pInputAssemblyState` / `pViewportState` / `pRasterizationState` / `pMultisampleState` / `pDepthStencilState` / `pColorBlendState` / `pDynamicState` 逐项指向上述局部结构。
- `layout = pipeline_layout`。
- `renderPass = VK_NULL_HANDLE`、`subpass = 0`（默认）、`basePipelineHandle = VK_NULL_HANDLE`（默认）、`basePipelineIndex = -1`（默认）。
- 调用 `vkCreateGraphicsPipelines(device, VK_NULL_HANDLE /*pipelineCache*/, 1, &pipeline_info, nullptr, &pipeline_out)`（**结果写入出参 `pipeline_out`**），经 `vk_result_check` 检查；失败把 `pipeline_out` 复位为 `VK_NULL_HANDLE` 并返回 `false`。

### 6.5 管线与交换链格式的耦合

- **格式级耦合**：图形管线的动态渲染信息要求颜色/深度附件格式在创建时确定，因此管线**绑定**了创建时刻的交换链颜色格式与深度格式。
- **尺寸级解耦**：视口与裁剪是动态状态，故窗口/交换链**尺寸**变化不要求重建管线。
- **格式变化的处理——`pipeline_rebuild`（签名由三参变两参）**：若交换链重建时**格式发生改变**（如 vsync 切换引起呈现模式/颜色格式变化），既有多条管线仍携带旧格式，与新的颜色/深度附件不匹配（属 Vulkan 校验错误）。本模块为此提供 `bool pipeline_rebuild(VkFormat color_format, VkFormat depth_format)`（public，`core/管线.cpp`）：
  - ① `pipelines.empty()`（无任何条目）→ 直接返回 `true`；
  - ② 两格式与 `config.color_format` / `config.depth_format` 均相同 → **空操作**直接返回 `true`（无等待、无重建开销）；
  - ③ 格式变化 → `logger.info` 记录新格式，`vkDeviceWaitIdle`（确保旧管线不再被在途帧引用）→ 更新 `config` 中两格式 → **逐条目**销毁旧管线并 `entry_pipeline_create`（**各条目着色器对与各自混合档保留**）。
  - **门面协作**：交换链重建后由门面 `src/render/Renderer/core/渲染器.cpp` 调用 `pipeline_rebuild(swapchain.format_get(), swapchain.depth_format_get())`——两条重建路径（`resized_consume` 与 `rebuild_needed` 分支）各一处，**失败仅记 `logger.warn` 并继续本帧**。
- **按句柄的管线工厂 / 缓存（本版次）**：本模块自本版次起持有 `std::vector<Pipeline_Entry> pipelines`，以句柄索引区分「句柄 0 默认场景管线」与「具名管线（≥ 1）」：
  - `pipeline_build` 只作用于句柄 0 并激活之；`pipeline_register` 以 `next_handle` 分配句柄、登记后**不改变激活管线**；`pipeline_activate` 切换激活；`pipeline_release` 注销具名管线（句柄 0 忽略），且被注销者恰为激活句柄时回落默认。
  - `pipeline_default_blend_set` 只重建句柄 0 的混合档；**具名管线的混合档在 `pipeline_load` 登记时确定、不受门面切档影响**。
- **全部图形管线共享同一 `VkPipelineLayout` 与描述符集布局**（`set 0` 场景 UBO / `set 1` 采样器）：具名管线**只允许**「着色器对 ＋ 混合档」不同；`layout_get()` 因此恒返回该唯一布局，帧模块可对任意渲染项统一按此布局绑集与推常量。
- **后处理具名管线（第十轮）**：门面以 `pipeline_load(handle, "后处理.vert.spv", "<frag>.spv")` 登记两条后处理具名管线——`assets/shaders/反色.frag`（一级 · 反色）与 `assets/shaders/亮度阈值.frag`（二级 · 二值化）；二者**顶点复用既有 `后处理.vert`**，与默认场景管线共享同一管线布局与描述符集布局。资产由 `assets/shaders/*.frag` 的 `GLOB CONFIGURE_DEPENDS` 自动纳编。

### 6.6 幂等与回退设计

- **`destroy` 幂等**：以 `device` 句柄为「是否已释放」的哨兵；释放后复位为 `VK_NULL_HANDLE`，二次调用直接走复位路径。
- **`build` 失败回退**：每一步失败调用 `destroy()`，把已创建的部分资源一并释放，避免半初始化泄漏。
- **`pipeline_build` 幂等重建**：句柄 0 条目已存在则先销毁其管线再建，支持「着色器热重载」；「格式变化」场景改由 `pipeline_rebuild` 驱动（见 §6.5），后者在重建前先 `vkDeviceWaitIdle`。
- **`pipeline_rebuild` 按需重建**：无条目或格式未变时为空操作（直接返回真），仅在格式变化时逐条目按记住的着色器模块与各自混合档重建，避免交换链重建时的无谓重建与等待。
- **`pipeline_register` 先建后登记**：先按格式创建图形管线，失败即整体拒绝、不登记任何条目（句柄保持 0），避免留下「半截句柄」。
- **`pipeline_default_blend_set` 只动默认**：无默认条目或同档时为空操作；仅重建句柄 0 的混合档，不波及具名管线。
- **析构兜底**：析构再调一次 `destroy()`，保证栈对象或异常路径下资源不泄漏。

- **命名**：类型名 `Pipeline_Context` / `Pipeline_Config`（各单词首字母大写，无分隔）；函数名 `pipeline_build` / `scene_bind` / `texture_bind` / `descriptor_layouts_create`（小写，单词间 `_` 分隔）；「动词后置」（`xxx_build`、`xxx_bind`、`xxx_create`、`scene_set_get`）。
- **注释**：中文；短注释用多行 `//`；三行以上用 `/* */`；`//` 后无空格；采用换行注释。
- **大括号**：另起一行（Allman 风格）。
- **命名空间**：实现位于 `namespace engine`；`局部命名空间使用.h` 收拢标准类型别名。

- **日志前缀**：统一 `"管线:: ..."`，便于过滤。

### 6.9 易错点清单

1. **重建路径须调用 `pipeline_rebuild`**：交换链格式变化后未重建管线会导致动态渲染附件格式失配（见 §6.5）；本版次其签名为两参（`color, depth`）且会重建**全部**已登记管线，门面当前已在两条交换链重建路径调用，未来新增重建路径时须同样调用。
2. **越界静默**：`scene_set_get` / `sampler_set_get` 越界返回 `VK_NULL_HANDLE` 而非报错，调用方若不判空会把空句柄填入渲染项；帧模块的 `vkCmdBindDescriptorSets` 绑定空集会触发校验错误。
3. **`range` 三处硬编码 64**：`管线.cpp::scene_bind`、门面 UBO 大小与推送块前 64 字节三处必须一致；推送常量总大小（80）另在 `管线布局.cpp` 与门面 `mesh_draw` 的写入长度两处一致（第十六轮）。
4. **`build` 重复调用不清理旧对象**：应先 `destroy` 再 `build`。
5. **顶点属性偏移硬编码**：`Vertex` 结构变更时属性 `offset` / `format` 不会自动跟随（见 §6.4.2）；现由三条 `static_assert` 兜底，编译期即可暴露。
6. **`vkUpdateDescriptorSets` 无返回**：两个 `bind` 函数在参数齐备时恒 `true`，不反映「集合是否被在途帧占用」等语义。
7. **销毁前须无在途使用**：本模块 `destroy` 不含设备空闲等待，须由调用方保证（`pipeline_rebuild` / `pipeline_default_blend_set` 在重建前已自带一次 `vkDeviceWaitIdle`）。
8. **切档只影响默认管线**：门面 `blend_mode_set` 现只重建句柄 0（`pipeline_default_blend_set`）；具名管线的混合档在 `pipeline_load` 时确定、不受其影响——若期望具名管线也换档，须以新档重新 `pipeline_load`。
9. **句柄 0 语义专用**：`pipeline_build` 恒作用于句柄 0，`pipeline_release` 忽略句柄 0；具名管线句柄（≥ 1）不可被当作默认管线使用。
10. **激活管线决定登记项所挂管线**：`pipeline_get()` 返回**当前激活**条目，故 `mesh_draw` / `mesh_draw_instanced` 取到的管线取决于调用前最近一次门面 `pipeline_bind_set`；切换须在登记绘制项**之前**完成。

> 1. 新增公开常量 `static constexpr uint32_t POST_SET_PER_SLOT = 2;`（`管线.h`）：每帧槽的后处理采样器集档数——链式后处理各级的源只可能是「偶/奇」两种中间目标之一，故每帧槽只需 2 个后处理集，与链长无关（见 §3.3.23）。
> 2. `post_set_get` **签名增 `index` 形参**：`VkDescriptorSet post_set_get(uint32_t slot) const` → `VkDescriptorSet post_set_get(uint32_t slot, uint32_t index = 0) const`；`index >= POST_SET_PER_SLOT` 或 `slot × POST_SET_PER_SLOT + index` 越界时返回 `VK_NULL_HANDLE`（见 §3.3.20）。
> 3. `post_texture_bind` **签名增 `index` 形参**：`bool post_texture_bind(uint32_t slot, VkSampler sampler, VkImageView view)` → `bool post_texture_bind(uint32_t slot, VkSampler sampler, VkImageView view, uint32_t index = 0)`；实现改为先经 `post_set_get(slot, index)` 取目标集再写 `set 1 binding 0`（见 §3.3.21）。
> 4. **描述符池容量改写**：`COMBINED_IMAGE_SAMPLER` 描述符数 `frame_overlap * 2` → `frame_overlap × (1 + POST_SET_PER_SLOT)`；`maxSets` `frame_overlap * 3` → `frame_overlap × (2 + POST_SET_PER_SLOT)`（见 §6.3、§7.1 与附录 A）。
> 5. **`post_sets` 扩容**：长度 `frame_overlap` → `frame_overlap × POST_SET_PER_SLOT`（一次 `vkAllocateDescriptorSets` 分配，布局仍为 `sampler_set_layout`），**下标 = `slot × POST_SET_PER_SLOT + index`**（见 §5.3.2 与 §6.3）。
> 6. **档位语义**：`index 0`（偶级源）在单级路径与链的第 0 级均绑定「场景目标颜色视图」；`index 1`（奇级源）仅在链长 ≥ 2 时绑定「ping-pong 第二目标颜色视图」。二者均由门面每帧写入全部帧槽（长命资源、值跨帧不变）。
> 7. **后处理管线按文件名登记**：本轮新增两条后处理片元着色器源文件 `Application/Renderer/assets/shaders/反色.frag`（一级 · 反色：`texelFetch` 取源后输出 `vec4(vec3(1.0) - source.rgb, 1.0)`）与 `Application/Renderer/assets/shaders/亮度阈值.frag`（二级 · 二值化：按 Rec.709 亮度 `dot(source, vec3(0.2126,0.7152,0.0722))` 以 0.5 阈值输出纯白 / 纯黑）；二者**顶点复用既有 `后处理.vert`**，由门面经既有 `pipeline_load(handle, "后处理.vert.spv", "<frag>.spv")` 登记为**具名管线**（与默认场景管线共享同一管线布局与描述符集布局）。资产由 `assets/shaders/*.frag` 的 `GLOB CONFIGURE_DEPENDS` 自动纳编。
> 8. 本轮管线侧改动为**纯扩容、向后兼容**（既有 `index` 缺省 0 的调用点行为不变），**不新增待确认编号**。

> **本版次增量（第二十一轮：推送常量扩至 112 字节，增泛光参数段）**
> 1. `pipeline_layout_create` 的 `push_range.size` 由 **96** 改为 **112**（`offset` 仍为 0、阶段仍为顶点 ＋ 片元）。新增第四段 `96..111`：`vec4` 泛光参数（`x` = 阈值、`y` = 软膝、`z` = 强度、`w` 保留），由门面 `bloom_param_set` 记录、帧模块在链路径随「源 / 宿尺寸」一并推送。

## 七、模块运行链路详例

本章以「调用方（门面）→ 本模块 → 被调方（Vulkan / 依赖模块）」的时序描述典型链路。

### 7.1 初始化链路（门面 `Renderer::init` 的 ⑪⑫ 步）

1. **门面准备配置**：`Pipeline_Config pipeline_config{}`，填 `color_format = swapchain.format_get()`、`depth_format = swapchain.depth_format_get()`、`frame_overlap = effective.frame_overlap`。
   - 调用方：`Renderer::Impl`（渲染器门面）。
   - 被调方：交换链模块（取格式）。
2. **门面调用 `pipeline.build(device.device_get(), pipeline_config)`**。
3. **本模块 `build` 前置校验**：
   - 若 `device == VK_NULL_HANDLE` → 记 error，返回 `false`（门面走 `shutdown`）。
   - 若 `config.frame_overlap == 0` → 记 error，返回 `false`。
4. **本模块 `build` 记录设备与配置**：`this->device = device; this->config = config;`。
5. **本模块 `build → descriptor_layouts_create`**（`core/描述符布局.cpp`，见 §四.2）：
   - 创建 `set 0`（场景 UBO，顶点阶段）→ `vkCreateDescriptorSetLayout`。
   - 创建 `set 1`（采样器，片元阶段）→ `vkCreateDescriptorSetLayout`。
   - 失败 → error + `destroy` + `false`。
6. **本模块 `build → pipeline_layout_create`**（`core/管线布局.cpp`，见 §四.3）：
   - 集顺序 `{ scene_set_layout, sampler_set_layout }`，推送常量 `{ 顶点阶段, 0, 64 }` → `vkCreatePipelineLayout`。
   - 失败 → error + `destroy` + `false`。
7. **本模块 `build` 创建描述符池**：`pool_sizes = { UNIFORM_BUFFER × frame_overlap, COMBINED_IMAGE_SAMPLER × frame_overlap × (1 + POST_SET_PER_SLOT) }`，`maxSets = frame_overlap × (2 + POST_SET_PER_SLOT)` → `vkCreateDescriptorPool`。失败 → error + `destroy` + `false`。
8. **本模块 `build` 分配场景集**：`scene_sets.resize(frame_overlap)`，布局数组全为 `scene_set_layout` → `vkAllocateDescriptorSets`。失败 → error + `destroy` + `false`。
9. **本模块 `build` 分配采样器集与后处理集**：`sampler_sets.resize(frame_overlap)` 与 `post_sets.resize(frame_overlap × POST_SET_PER_SLOT)`，布局数组分别全为 `sampler_set_layout` → 两次 `vkAllocateDescriptorSets`。失败 → error + `destroy` + `false`。
10. **本模块 `build` 记 info 并返回 `true`**：日志打印在途帧数、颜色格式、深度格式。
11. **门面（⑫）调用 `pipeline.pipeline_build(vert_module, frag_module)`**（模块已由着色器模块 `module_load` 加载 `场景.vert.spv` / `场景.frag.spv`）。
12. **本模块 `pipeline_build` 前置校验**：`valid()` 为真且两模块非空；否则 error + `false`。
13. **本模块 `pipeline_build`（登记 / 替换并激活句柄 0 默认管线）**：按 `entry_find(0)` 定位条目（无则新建并置 `handle = 0`）；若该条目已有管线先销毁；写入 `vert_module` / `frag_module` / `blend_mode`（供格式变化时重建复用）；转调 `entry_pipeline_create` → `graphics_pipeline_create(…, pipeline_out)`（见 §四.4 / §四.6）→ 组装全部固定功能状态 + 动态渲染信息 → `vkCreateGraphicsPipelines`；成功后 `active_handle = 0`。
14. **成功**记 info，返回 `true`；门面继续 ⑬（场景 UBO 创建与绑定）与 ⑭（默认纹理绑定到所有帧槽 set1）。门面若另行经 `pipeline_load` 登记具名管线，则走 `pipeline_register`（登记后不改变激活管线）。

### 7.2 场景 UBO 绑定与每帧填写链路

**初始化阶段（门面 ⑬，逐帧槽一次）**：

1. 门面为第 `slot` 帧槽创建 64 字节主机可见 UBO（内存模块 `buffer_create`），写入相机 `view × proj`（`buffer_write`）。
2. 门面调用 `pipeline.scene_bind(slot, scene_ubos[slot])`。
3. 本模块 `scene_bind` 校验参数 → 构造 `VkDescriptorBufferInfo{ buffer, 0, 64 }` → `vkUpdateDescriptorSets`（`dstSet = scene_sets[slot]`、`binding 0`）。
4. 返回 `true`。

**初始化阶段（门面 ⑭，默认纹理一次写满）**：

1. 门面取默认白纹理的 `VkImageView` / `VkSampler`（纹理模块 `texture_bind_get`）。
2. 对每个 `slot` 调用 `pipeline.texture_bind(slot, default_sampler, default_view)`。
3. 本模块 `texture_bind` 校验参数 → 构造 `VkDescriptorImageInfo{ sampler, view, SHADER_READ_ONLY_OPTIMAL }` → `vkUpdateDescriptorSets`（`dstSet = sampler_sets[slot]`、`binding 0`）。
4. 保证 `descriptor_set_count = 2` 时**不存在未写入的描述符集**（注释明示）。

**每帧阶段（门面 `Renderer::render`）**：

1. 门面计算本帧帧槽 `slot`，把整块场景 UBO（624 字节）写入 `scene_ubos[slot]`；`set 0` 已在 `init` 一次性写入，**每帧不再调用 `scene_bind`**。
2. **阴影 pass（第五十二轮）**：若阴影开启，门面在取主 pass 帧槽前用同一帧槽实例缓冲提交一次 `render_to_target`（阴影管线共享本模块的管线布局，推送常量 64 字节光源矩阵），随后 `frames_wait`。
3. 门面遍历 `pending_items`：`item.scene_set = pipeline.scene_set_get(slot)`、`item.sampler_set = pipeline.sampler_set_get(slot)`、`item.descriptor_set_count = 2`（阴影图已在 init 由 `shadow_bind` 写入该集的 binding 1）。
4. 门面把 `pending_items` 交给帧模块 `frame.render(...)`。

### 7.3 网格绘制登记链路（门面 `mesh_draw`）

1. 门面从网格模块取顶点/索引缓冲与索引数（`mesh_record_get`）。
2. 门面把模型矩阵（或单位矩阵）写入 `pending_transform[16]`（列主序，地址稳定）。
3. 门面组装 `Frame_Render_Item`：
   - `item.pipeline = pipeline.pipeline_get()`（**本版次返回当前激活条目的管线**，故此前须已按需调用门面 `pipeline_bind_set`）；
   - `item.layout = pipeline.layout_get()`；
   - `item.push_constants = pending_transform`；`item.push_constant_size = 64`；
   - 描述符集暂置空（数量 0），延迟到 `render` 按本帧槽填装。
4. 门面登记渲染项（长度 0 或 1）。

### 7.4 帧模块消费链路（跨模块，理解本模块接口价值所必需）

1. 帧模块 `命令录制` 开始动态渲染：`vkCmdBeginRendering`。
2. 设置动态视口/裁剪：`vkCmdSetViewport` / `vkCmdSetScissor`（因管线用动态状态）。
3. 逐渲染项：
   - `vkCmdBindPipeline(..., VK_PIPELINE_BIND_POINT_GRAPHICS, item.pipeline)`——绑定本模块产出的管线。
   - 若 `descriptor_set_count > 0`：`vkCmdBindDescriptorSets(..., item.layout, 0, count, {scene_set, sampler_set}, 0, nullptr)`——绑定本模块产出的管线布局与描述符集。
   - 若 `push_constants` 非空：`vkCmdPushConstants(cmd, item.layout, VK_SHADER_STAGE_VERTEX_BIT, 0, 64, push_constants)`——推送模型矩阵（范围与 `管线布局.cpp` 一致）。
   - `vkCmdBindVertexBuffers`（binding 0）/ `vkCmdBindIndexBuffer`（`UINT32`）。
   - `vkCmdDrawIndexed`。
4. `vkCmdEndRendering`。

> 该链路说明：**管线布局既是描述符集绑定的依据，也是推送常量推送的依据**；管线布局的 `set 0 → set 1` 顺序与 `vkCmdBindDescriptorSets` 的 `sets[2] = { scene_set, sampler_set }` 顺序一致；推送常量范围「顶点阶段 / 0 / 64」与帧模块的 `vkCmdPushConstants(..., VK_SHADER_STAGE_VERTEX_BIT, 0, push_constant_size, ...)` 一致。

### 7.5 关闭链路（门面 `Renderer::shutdown`）

严格逆序，与管线相关的一段为：

1. `frame.destroy()`（保证在途帧结束）。
2. `mesh.destroy()` / `texture.destroy()`。
3. 归还场景 UBO（`memory.buffer_destroy`，逐帧槽）。
4. **`pipeline.destroy()`**：
   - 逆序销毁：**遍历 `pipelines` 逐个 `vkDestroyPipeline`**（默认 ＋ 全部具名）→ `vkDestroyDescriptorPool` → `vkDestroyPipelineLayout` → `vkDestroyDescriptorSetLayout(sampler)` → `vkDestroyDescriptorSetLayout(scene)`。
   - 清空 `pipelines` / `scene_sets` / `sampler_sets`，复位 `next_handle = 1` / `active_handle = 0`、复位配置与设备（着色器模块存于条目、不在此销毁）。
5. 销毁着色器模块（`shader.module_destroy`，须先于 `shader.destroy()`）。
6. `swapchain.destroy()` → `memory.destroy()` → `device.destroy()` → `platform.destroy()`。

> 顺序要点：**管线销毁须先于设备销毁**（门面注释「管线依赖设备与内存，须先于两者销毁」）；**交换链销毁连带销毁深度图像，须排在管线之后**。析构兜底：`Pipeline_Context` 析构再调一次 `destroy`，此刻已复位，为无操作。

### 7.6 关键异常与边界分支

| 分支 | 触发条件 | 本模块行为 | 门面后续 |
| --- | --- | --- | --- |
| `build` 设备为空 | `device == VK_NULL_HANDLE` | 记 error，返回 `false`（不 `destroy`） | `shutdown` |
| `build` 在途帧为 0 | `config.frame_overlap == 0` | 记 error，返回 `false` | `shutdown` |
| 集布局创建失败 | `vkCreateDescriptorSetLayout` 非成功 | error + `destroy` + `false` | `shutdown` |
| 管线布局创建失败 | `vkCreatePipelineLayout` 非成功 | error + `destroy` + `false` | `shutdown` |
| 描述符池创建失败 | `vkCreateDescriptorPool` 非成功 | error + `destroy` + `false` | `shutdown` |
| 描述符集分配失败 | 两次 `vkAllocateDescriptorSets` 任一非成功 | error + `destroy` + `false` | `shutdown` |
| `pipeline_build` 前置不完整 | `!valid()` 或模块为空 | error + `false`（**不销毁已有条目**） | `shutdown` |
| 图形管线创建失败 | `vkCreateGraphicsPipelines` 非成功 | `pipeline_out = VK_NULL_HANDLE` + `false`（该条目管线保持空） | `shutdown` |
| `pipeline_register` 前置 / 创建失败 | 未初始化 / 模块空 / 创建失败 | 整体拒绝、句柄保持 0、`false`（**不登记任何条目**） | 门面 `pipeline_load` 回收模块并记 error |
| `pipeline_activate` 句柄未登记 | `entry_find(handle) == nullptr` | error + `false`（**保持激活不变**） | 门面 `pipeline_bind_set` 先行回落默认再激活 |
| `pipeline_release` 句柄 0 / 未命中 | `handle == 0` 或线性查找未命中 | 直接返回 / 无操作 | 门面 `pipeline_unload` 先行处理 |
| `pipeline_rebuild` 无条目 | `pipelines.empty()` | 直接返回 `true`（无操作） | 无 |
| `pipeline_rebuild` 格式未变 | 两格式与 `config` 相同 | 空操作返回 `true`（无等待） | 无 |
| `pipeline_rebuild` 格式变化 | 两格式之一与 `config` 不同 | info + `vkDeviceWaitIdle` + 更新 `config` + **逐条目**重建 | 失败仅记 `logger.warn`，本帧继续 |
| `pipeline_default_blend_set` 无默认 / 同档 | 无句柄 0 条目或同档且有效 | 空操作返回 `true` | 无 |
| `pipeline_default_blend_set` 需切换 | 档位不同 | `vkDeviceWaitIdle` + 销毁旧管线 + 改档 + 重建 | 失败在门面记 error 并保持档位记录 |
| `scene_bind` 参数不完整 | 设备/集/缓冲任一空或 slot 越界 | error + `false` | 门面记 error 并返回 `false`（本帧渲染失败） |
| `texture_bind` 参数不完整 | 设备/集/采样器/视图任一空或 slot 越界 | error + `false` | 门面记 error 并返回 `false` |
| `scene_set_get` / `sampler_set_get` 越界 | `slot >= size` | 静默返回 `VK_NULL_HANDLE` | 门面按契约只在有效范围内调用 |
