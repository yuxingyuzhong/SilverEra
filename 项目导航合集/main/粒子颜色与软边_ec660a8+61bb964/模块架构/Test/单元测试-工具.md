## 二、模块功能介绍

### 2.1 模块定位

「单元测试-工具」指 Test 层构建目标 `EngineTestObjects`（OBJECT 库）中来自 `src/单元测试/工具/` 子树的 12 份用例源文件。它们以 googletest 的 `TEST_F` 形式，对 `Engine/EngineCore` **工具组**（`src/tools/`）的各工具真实现做黑盒与边界验证。

它不产出、不暴露任何库接口，也不含夹具定义（夹具与测试对象的清单见 `Test/测试对象与夹具.md`）。其价值在于**承载用例正文**：每条 `TEST_F` 的覆盖意图、断言口径、输入样本与边界预期。

一句话概括：**本单元是「工具组的行为规格说明书」——把 EngineCore 工具组各工具的对外行为，逐条固化为可执行断言。**

### 2.2 职责边界与文档分界

| 对象 | 分界 |
| --- | --- |
| 本单元（`单元测试-工具.md`） | 只写 `src/单元测试/工具/` 12 份文件内的**用例正文**：套件名、被测工具接口、用例清单、覆盖行为与边界。 |
| `Test/测试对象与夹具.md` | 写**夹具与测试对象**（夹具类形态、生命周期、隔离、`Console_Capture`/`test_item` 等辅助类型、编译口径与依赖）。本文只引用其结论，不重述。 |
| 同层其余用例文档 | 写 `src/单元测试/` 其它子树（主调/核心/渲染）的用例正文；本文不涉及。 |
| `Engine/EngineCore` 工具组源码 | 是**被测实现**；其模块架构见 EnginCore 侧导航（`EngineCore/工具集.md`）。本文只说明「用例验证了它的哪些接口、哪些行为」。 |

| 形态 | 特征 | 本单元套件 |
| --- | --- | --- |

| 持有被测对象（值成员，天然隔离） | 用例体直接在成员上操作 | `Number_Allocator_Test`（`allocator`）、`Timer_Test`（`timer`） |
| 持输入样本 | 用例体取夹具的样本容器 | `Binary_Search_Test`（`ascending_set`/`duplicate_set`） |

### 2.5 用例命名与注释约定

- **套件名**：即夹具类名（本单元 12 个套件全为英文类名）；**用例名**一律中文短语，直陈该用例验证的行为或边界（如「游标为最大数值时首次分配回绕」）。
- **文件头**：每份文件以一行 `//` 注释总述覆盖范围（如「二分查找算法测试：覆盖命中、未命中、空区间……」）。
- **用例体注释**：中文、换行注释；变量声明、条件、调用前均有注释（沿用项目既有注释风格，见 `Test/测试对象与夹具.md` §5.5）。三行及以上注释用 `/* */`（本单元仅 `日志系统测试.cpp` 的 `Console_Capture` 类头使用块注释）。
- **注册口径**：`TEST_F(夹具类名, 用例名)` 静态注册进 gtest 注册表，套件名对用户可见（用于 `--gtest_filter`）。

## 三、模块公开接口介绍

### 3.1 「公开接口」在本单元的所指

本单元无对外头、无对层外可见的接口。本节的「公开接口」指**每条用例对外所验证的被测工具接口**及其覆盖到的**可观察行为**——即「用例清单 = 规格」。逐套件分节如下。

### 3.2 `Binary_Search_Test`

- **文件**：`工具/二分查找测试.cpp`　**夹具**：`Binary_Search_Test`（持输入；样本 `ascending_set{1,3,5,7,9,11}`、`duplicate_set{1,2,2,2,3,5}`）
- **被测接口**（`Engine/EngineCore/src/tools/Detail/二分查找.h`，均位于 `engine::detail`）：
  - `binary_search(容器&, 目标, 比较器[, 投影])` → `std::optional<uint64_t>`
  - `binary_search(起始迭代器, 终止迭代器, 目标, 比较器[, 投影])` → `std::optional<uint64_t>`
  - `range_binary_search(容器&, 目标, 比较器)` → `std::optional<std::pair<uint64_t, uint64_t>>`（等价元素**闭区间**）
- **用例（30 条）**：

| 组 | 用例 |
| --- | --- |
| 基本命中/未命中（11） | 命中中间元素、命中首元素、命中尾元素、未命中时返回空值、空隙目标返回空值、空区间返回空值、单元素容器命中、单元素容器未命中、目标小于首元素返回空值、目标大于尾元素返回空值、目标位于相邻元素之间 |
| 重复元素单点定位（1） | 重复元素返回等价下标 |
| 投影字段（3） | 按投影字段命中、按投影字段未命中、投影字段降序命中 |
| 迭代器/子区间（3） | 子区间查找索引相对起点、空容器迭代器重载返回空值、迭代器与容器重载结果一致 |
| 降序序列（1） | 降序序列查找 |
| 等价闭区间（11） | 重复元素返回闭区间、唯一元素返回单点区间、重复区间首元素、重复区间未命中、重复区间空序列、重复区间全序列等价、重复区间首部连续重复值、重复区间尾部连续重复值、单元素序列等价区间、重复区间中部连续重复值、降序序列重复区间 |

- **覆盖的核心行为与边界**：索引以**传入区间起点**为基准（子区间用例，`【待确认：TEST-47】`）；空区间/单元素/首尾界均不越界访问；比较器方向须与序列有序方向一致（`std::ranges::less` 配升序、`std::ranges::greater` 配降序）；投影重载以仿函数取排序键；`range_binary_search` 对唯一值退化为**单点闭区间**、对全等序列覆盖整段、未命中返回 `nullopt`。
- **辅助结构**：`struct test_item{uint64_t ID; int score;}`——承载投影字段（`score`），见 §4.3。

### 3.3 `Hash_Combine_Test`

- **文件**：`工具/哈希混合测试.cpp`　**夹具**：`Hash_Combine_Test`（静态辅助 `combine_once`）
- **被测接口**（`Detail/哈希混合.h`）：`engine::detail::hash_combine(size_t& seed, size_t value)`——按引用**就地改写** `seed`，声明为 `noexcept`。
- **用例（12 条）**：

| 组 | 用例 |
| --- | --- |
| 确定性（4） | 相同输入结果一致、重复混合结果稳定、零种子零输入确定、连续混合序列确定 |
| 改写性（2） | 混合就地改写种子、零值输入仍改写种子 |
| 敏感性（3） | 不同输入结果不同、不同种子结果不同、交换顺序结果不同 |
| 极值输入（2） | 最大值输入可复现、高位输入不崩溃 |
| 异常规格（1） | 混合函数不抛出 |

- **覆盖的核心行为与边界**：同种子同输入必同结果（可复现）；对种子有就地改写副作用；对输入值、种子值、混合**顺序**均敏感；零值输入亦改写非零种子；`SIZE_MAX` 与最高位（`1<<(位宽-1)`）输入不产生未定义行为；`noexcept` 由编译期判定。

### 3.4 `Field_Check_Test`

- **文件**：`工具/字段校验测试.cpp`　**夹具**：`Field_Check_Test`（静态辅助 `make_config`，构造 12 字段公共配置）
- **被测接口**（`Detail/json字段可用性校验.h`）：`engine::detail::field_check<T>(const nlohmann::json&, const std::string& key)`；`T` 覆盖 `bool / int / int64_t / uint32_t / double / float / std::string / std::vector<int> / nlohmann::json`。
- **语义**（据断言）：字段**存在性** + **严格类型匹配** + **非空**（三元合一）。
- **用例（30 条）**：

| 组 | 用例 |
| --- | --- |
| 布尔萃取（5） | 布尔真值通过、布尔假值通过、布尔字段为整数被拒、布尔字段不接受零值整数、布尔字段缺失被拒 |
| 整型萃取（6） | 整型正数通过、整型负数通过、整型字段为浮点被拒、整型字段为字符串被拒、整型字段为布尔被拒、整型字段缺失被拒 |
| 浮点萃取（5） | 浮点正数通过、浮点负数通过、浮点字段为整数被拒、浮点字段为字符串被拒、浮点字段缺失被拒 |
| 字符串萃取（4） | 非空字符串通过、空字符串被拒、字符串字段为数字被拒、字符串字段缺失被拒 |
| 容器萃取（7） | 非空数组通过、空数组被拒、非空对象通过、空对象被拒、容器字段为字符串被拒、数组元素类型不符被拒、容器字段缺失被拒 |
| 组合场景（3） | 嵌套对象内层字段可校验、空配置任意字段被拒、空字段名被拒 |

- **覆盖的核心行为与边界**：**类型严格不互通**（整↔浮、数↔串、串↔容器互斥）；布尔真假均为合法布尔，但整数 `0` 不被当作布尔假；字符串/容器空值被非空检查拦下；嵌套对象可先取出再单独校验其内层字段；空字段名被拒。

  - **重复回收拒绝**：靠内部集合（`mapping`，本单元题述之「黑名单」）拦截，同值二次 `recycle` 返回 `false`；`get` 命中后从集合移除，故可再次回收；`reset` 一并清空该记录。
  - **回绕边界**：游标等于类型最大值即判「耗尽」→ 告警并回绕到类型最小值，**最大值本身绝不外发**（见 `【待确认：TEST-41】`）。
  - **无归属校验**：从未 `get` 过的数值也可 `recycle`（见 `【待确认：TEST-42】`）。
  - **批量回收**：逐个调用单值重载，按调用顺序入池、重复项被忽略。
  - **模板泛型**：`uint8_t`（8 位回绕）、`int32_t`（可负起点）均可用。

## 六、模块设计/实现细节

### 6.1 用例只接已构建真实现

工具子树 12 文件一律 `#include "Engine/EngineCore/src/tools/..."`（项目根全路径）并链接 `EngineCore`——**无源码回退、无桩替身**，用例直接验证静态库中被测工具的真实现。故任何工具行为变更都会直接反映到这些用例上（这也是把「返回值的『是否改变』语义」「布尔分支修复」等以回归用例固化的前提，见 §6.7）。

### 6.2 钩子夹具的资源与全局态管理

仅 2 个工具套件带钩子，各自管一类外部状态：

| 套件 | 管理对象 | `SetUp` | `TearDown` |
| --- | --- | --- | --- |
| `Path_Check_Test` | 临时样本文件 | 写出非空常规文件 | 删除（`std::error_code` 容错） |
| `Log_Test` | 全局日志态 + 11 个探针文件 | 关屏蔽、设根目录、清许可表、清节点流、清探针 | 清节点流、清探针、清根目录与许可表、恢复屏蔽 |

- `engine::logger` 是全局单例，故 `Log_Test` 必须成对收放（见 §7.2）；其余 10 个套件不触碰全局态。
- `Path_Check_Test` 的「常规文件通过」用例依赖钩子写出的样本，故钩子缺一不可。

### 6.3 时间用例的弱断言策略

`Timer_Test` 涉及真实墙钟时间，无法精确断言，故采用「`sleep_for` + 单调/比较」的**弱断言**：

- 只断言方向与单调性：正间隔 `> Duration{}`、多次读取 `≥` 前次、重置后 `<` 重置前；单位换算才是精确值断言（`EXPECT_DOUBLE_EQ`/`EXPECT_EQ`）。
- `sleep` 时长取小（5~20 ms），兼顾稳定与运行开销。
- 该策略使用例在负载波动下仍稳定，但代价是**不能断言精确时长**——这是刻意的取舍。

### 6.4 随机与统计断言策略

`Random_Generator_Test` 对随机输出不做逐值断言，只做**统计性断言**：

- **可复现性**是全精确断言（同种子逐位比较），这是随机工具的核心契约。
- **均匀性/区间覆盖**是经验性断言（如 5000 次抽样覆盖 5 个取值、100 个全范围值去重后 `>90`），不保证每次运行的分布细节，仅验证「不会退化到不覆盖」。
- **闭区间约束**是范围断言（`≥low && ≤high`），对颠倒区间、负区间、极值区间均适用。

### 6.5 分配器回绕边界设计

`Number_Allocator_Test` 的回绕用例组专门固化 `get()` 的极值行为：

- 实现为「回收池为空且游标 `== max` 时判耗尽」→ 告警并令 `number = next_number = min`，即**回绕时把最小值发出去**；
- 由此推出**最大值本身永不被外发**（`set(UINT64_MAX)` 后首次 `get()` 直接得 `0`；`set(UINT64_MAX-1)` 先得 `max-1`、再回绕得 `0`）；
- 但**已回收**的最大值可由回收池原样取回（用例「回收最大数值后原样取回」），即「不外发」只约束游标路径、不约束回收路径。
- 该设计是否为刻意保留最大值作「耗尽哨兵」，见 `【待确认：TEST-41】`；与 `capacity()` 的溢出处理（工具集 TOOLS-03）配套。

### 6.6 路径用例的编码覆盖

`Path_String_Test`、`Path_Check_Test`、`Data_Validator_Test`、`Engine_Env_Test`、`Log_Test` 五套件统一覆盖**中文/UTF-8 路径**：

- 往返用例断言逐字节一致（单汉字 3 字节）；
- 「转换结果可用于文件系统查询」用例把 `path_to_string` 结果再转回路径并 `exists`，证明 UTF-8 文本可被 `std::filesystem` 接受；
- `Log_Test` 的探针日志文件名刻意用纯 ASCII，日志目录含中文（`log_test_dir()` 取自本文件所在中文路径），以验证「字符串路径经 `string_to_path` 兼容中文」。
- 该覆盖对应项目「文件编码约束」中「UTF-8 中文路径须经自有转换工具」的既有约定。

### 6.7 日志用例与规则修订的对应

`Log_Test` 的若干用例与新近日志规则修订一一对应（修订口径见 `EngineCore/工具集.md` TOOLS-04/TOOLS-05、`待答疑清单.md`）：

| 用例 | 对应口径 |
| --- | --- |
| 根目录未设置时绑定被拒绝 | 根目录门禁：未设根目录 → 拒绝绑定并告警 |
| 根目录之外日志被截断 | 调用处落在根目录之外 → 越界截断 |
| 文件与目录许可过滤 | 文件许可比目录许可更具体、优先生效 |
| 级别不可输出被截断 | `level_rule_set` 逐级开关 |
| 目录节点后绑定按公共前缀归并 | 路径键以根目录为锚点、树键恒以 `/` 结尾（TOOLS-05） |
| 清空不存在节点返回失败 | `stream_clear` 对不存在节点返回 `false` |
| 同节点多流全量输出 | 重复绑定为追加（多路同时输出），而非覆盖（TOOLS/CFG-05 核实） |

> `root_set`/`file_rule_set`/`dir_rule_set`/`level_rule_set` 的 `bool` 返回值语义（「本次设置是否改变」）在源码里由 `Log_Rules` 提供，本套件未直接断言其返回值，只断言由规则引起的输出差异。

### 6.8 网格解析的非法输入矩阵

`Mesh_Loader_Test` 的非法输入用例组构成一张**错误矩阵**，逐一钉死 `load_obj` 的拒绝条件：

| 非法点 | 样本 | 期望 |
| --- | --- | --- |
| 路径层 | 不存在文件 / 空路径 / 目录路径 | 失败（不进入解析或解析前置校验失败） |
| 拓扑层 | 只有顶点无面 / 空文件 | 失败，且**清空输出** |
| 索引层 | 面索引越界 / 零起始索引 / 负索引越界 | 失败 |
| 完整性层 | 顶点分量不足（缺 Z）/ 面顶点不足三个 | 失败 |

- 合法侧则覆盖：三角面、四边形扇化、三种斜杠写法、负索引、立方体计数、重复加载幂等。

### 6.9 易错点

| 易错点 | 说明与规避 |
| --- | --- |
| 用 gtest 自带 `CaptureStdout` | 其在含中文临时目录建 `.tmp`、窄字符 `fopen` 失败会 FATAL 打断进程；改用自研 `Console_Capture`（接 `std::cout` rdbuf） |
| 探针日志删除失败 | 须先 `stream_clear` 释放文件流再删（Windows 特有约束）；`log_remove_all` 在 `TearDown` 中于清流之后调用 |
| 日志读取读到空 | 文件输出按阈值批量落盘，读前须 `stream_flush()`（`log_read` 内已封装） |
| `absolute_path_get` 字面量歧义 | 传 `const char*` 会引发 C2668 重载歧义，须显式构造 `std::string` |
| 以精确值断言时间 | `Timer_Test` 只能弱断言（见 §6.3） |
| 以逐值断言随机数 | 仅可复现性可精确断言（见 §6.4） |
| 泄漏临时文件 | 网格/路径校验样本在用例末或 `TearDown` 删除（`std::error_code` 容错），日志探针已纳入 `.gitignore` |
| 单目标链接缺失符号 | `Log_Test` 依赖的 `日志屏蔽_开启/关闭` 实现不在本目标，须经 `EngineTests` 提供 |

## 七、模块运行链路详例

### 7.1 单用例生命周期

1. `EngineTests` 启动并 `InitGoogleTest()` 后，本子树的 `TEST_F` 已由静态注册填满 gtest 注册表；`--gtest_filter` 决定本轮命中的用例。
2. 对每条命中的 `TEST_F`：构造夹具实例（值成员就地构造，如 `Number_Allocator_Test::allocator`、`Timer_Test::timer`）。
3. 若夹具覆写 `SetUp` → 调用（`Log_Test`、`Path_Check_Test`）。
4. 执行用例体：构造/取用被测工具、调用辅助、`EXPECT_*`/`ASSERT_*` 断言。
5. 若覆写 `TearDown` → 调用（同名两夹具），归还外部资源与全局态。
6. 析构夹具，进入下一条用例；用例间无共享可变态（详见 `Test/测试对象与夹具.md` §7.1）。

### 7.2 `Log_Test` 全局态收放链路

1. `SetUp`：`日志屏蔽_关闭()` → `logger.root_set("")` → `logger.rule_clear()` → `logger.stream_clear(log_test_path())` → `logger.stream_clear(log_test_dir())` → `log_remove_all()`。
2. 用例体（三种典型链路）：
   - **控制台链路**：`Console_Capture` 接管 `std::cout` rdbuf → `logger.info/warn/error/debug(...)` → `capture.text()` 取回并断言 `[LEVEL]正文`。
   - **落盘链路**：`logger.stream_bind(路径, 文件名)` → 输出 → `log_read` 读回并断言。
   - **规则链路**：`root_set`/`level_rule_set`/`dir_rule_set`/`file_rule_set` 改变规则后再输出并观察截断/放行。
3. `TearDown`：清本文件路径/目录/根节点自有流 → `log_remove_all()` → `logger.root_clear()` + `logger.rule_clear()` → `日志屏蔽_开启()`。
4. 由此保证：本套件可观察「未绑定走控制台」的兜底行为，且不把全局态改动泄漏给其余套件。

### 7.3 日志「绑定→输出→回落」链路

以「目录节点后绑定按公共前缀归并」用例为例：

1. 先 `stream_bind(log_test_path(), child)`——树上只存在**文件路径节点**，输出落该节点自有流。
2. 后 `stream_bind(log_test_dir(), parent)`——与既存文件节点共享公共前缀，目录节点成为其**父节点**；此时文件节点自有流优先，输出仍落文件节点流。
3. `stream_clear(log_test_path())`——清空文件节点自有流后，输出**回落**到父（目录）节点流。
4. 每一步均以 `log_read(...).find(...)` 正向/反向断言（在哪个文件、不在哪个文件）。

### 7.4 临时文件链路

| 套件 | 基址 | 写出 | 读取/校验 | 清理 |

### 7.5 边界分支汇总表

| 场景 | 触发点 | 处理 | 结果 |
| --- | --- | --- | --- |

| 日志空输出流绑定 | 传入空 `Stream` | 拒绝 | 返回 `false` |
| 时间读取重置 | `elapsed(name, true)` | 重置原点 | 累计重新计次（TEST-43） |
