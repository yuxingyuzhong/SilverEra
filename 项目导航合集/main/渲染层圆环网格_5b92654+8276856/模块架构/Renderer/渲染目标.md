# 渲染层-渲染目标 · 模块架构

> 源码根相对路径：`Application/Renderer/src/render/RenderTarget/`
> 本文覆盖 `RenderTarget/` 下的对外头 `渲染目标.h`（门面类型 `Render_Target_Context` 与记录结构 `Render_Target_Record`）、私有头 `局部命名空间使用.h`，以及 `core/` 下的单一编译单元 `目标创建.cpp`。
> 本模块**本版次新增**，职责是「持有若干**离屏渲染目标**，负责其颜色 / 深度图像与视图的创建、销毁与一次性布局转换」。每个渲染目标 = 一张颜色图像（可作颜色附件 / 可被采样 / 可作传输源）＋ 一张深度图像（可作深度附件）＋ 两者的图像视图。
> 本模块沿用渲染层 Vulkan **动态渲染（Dynamic Rendering）**路线：目标只承载「图像 ＋ 视图」，不创建任何 `VkRenderPass` 与 `VkFramebuffer`；实际渲染由帧模块以 `vkCmdBeginRendering` / `vkCmdEndRendering` 完成（见「渲染层-帧」模块）。
> 记录依据为当前工作区源码，不包含任何旧版次导航信息。文中文件路径口径统一为：**头文件写项目根全路径**（`Application/Renderer/...`）；**实现文件（.cpp）的跨目录包含写本层根相对**（`src/render/...`，本层根 = `Application/Renderer/`）；**私有包含根 = 项目根 ＋ 本层根**。
> 本模块的 `VkResult` 检查与批处理错误一律走渲染层统一出口（实现文件包含口径 `src/render/Renderer/core/结果检查.h`）提供的 `vk_result_check`；该头物理上归属「渲染层-渲染器」模块。

## 二、模块功能介绍

### 2.1 模块定位

「渲染目标」模块位于渲染层源码目录 `Application/Renderer/src/render/RenderTarget/`，是渲染层「离屏渲染」能力的资源侧载体。它把 Vulkan 中「把一个渲染目标所必需的两张图像（颜色 + 深度）及其视图」收拢进一个门面类 `Render_Target_Context`，以**句柄**为单位对外提供「创建 / 销毁 / 取用」的极简接口。

一句话概括：**本模块是渲染层「离屏渲染目标」的唯一持有者与资源入口；它只负责目标的图像 / 视图生命周期与初始布局，目标的实际使用（渲染、采样、回读）交由帧模块与门面按句柄驱动。**

### 2.2 职责边界与解决的问题

`Render_Target_Context` 解决的问题可归纳为五点：

1. **完成「离屏目标的两图像 ＋ 两视图」的创建**。为每个目标创建一张颜色图像（用法 `COLOR_ATTACHMENT | SAMPLED | TRANSFER_SRC`）与一张深度图像（用法 `DEPTH_STENCIL_ATTACHMENT`），并各建一张 2D / 单层 / 单 mip 的图像视图（颜色视图 aspect = `COLOR_BIT`、深度视图 aspect = `DEPTH_BIT`）。整套「格式 / 用法 / 视图口径」在本模块内一次性定死，调用方无需重复描述（见 `core/目标创建.cpp`）。

2. **完成「创建时一次性布局转换」**。图像创建后的初始布局为 `VK_IMAGE_LAYOUT_UNDEFINED`，不可直接使用。本模块在创建完成后立刻执行一次布局转换（`target_transition`）：颜色 `UNDEFINED → SHADER_READ_ONLY_OPTIMAL`，深度 `UNDEFINED → DEPTH_ATTACHMENT_OPTIMAL`。此后**颜色在帧间恒处于可采样布局**、**深度恒处于深度附件布局**（见 §6.1 / §6.2），使得离屏结果可随时被当作纹理采样，也使得帧链路无需逐帧重建目标布局。

3. **提供「以句柄为单位的目标管理」**。本模块以 `uint64_t` 句柄索引目标（句柄自 1 起，0 表无效），把每个目标存于 `std::vector<Render_Target_Record> records`（下标 = 句柄 − 1）；创建时优先**复用第一个空槽**，否则追加；销毁时把记录整条复位为「空槽」。上层（门面）只需持有句柄即可创建 / 使用 / 销毁目标，无需接触图像句柄。

4. **提供「一次性转换资源」的复用池**。布局转换需要「命令池 ＋ 命令缓冲 ＋ 栅栏」三件套；本模块持有**一套**（`transient_pool` ＋ `transient_fence`），首次创建目标时惰性建立、此后跨多个目标复用（每次仅重置命令池 → 录制 → 提交 → 等待），避免逐目标创建 / 销毁命令池的开销（见 §6.5）。

5. **提供幂等销毁与析构兜底**。本模块的 `destroy()` 逐条归还渲染目标（跳过空槽），再逆序归还一次性栅栏与命令池，并复位句柄，可重复调用（第二次及以后为无操作）；析构函数内部再调一次 `destroy()`，保证「显式销毁 + 析构」不重复释放、半初始化状态下也能安全回退。

6. **提供「摘出而不销毁」的 `target_detach`（本轮新增）**。运行期销毁目标时，其颜色 / 深度图像可能仍被在途帧引用，不能立即归还；`target_detach` 把记录**整体摘出**（写出到出参、原记录复位为空槽）而**不**归还图像与视图，归还责任移交调用方——供门面组装帧模块延迟销毁条目（见 §3.3.9 与 §6.6）。

### 2.3 在整体架构中的位置

渲染目标模块处于渲染层依赖链的中层偏下：它**向下**依赖设备模块提供的逻辑设备句柄（`VkDevice`）与图形队列（`VkQueue`，用作一次性转换的提交目标）、内存模块（`Memory_Context`，图像 / 视图的创建与销毁）、以及渲染层统一的 `VkResult` 检查出口与引擎日志系统；**向上**被「渲染层-渲染器」门面（`Renderer::Impl`）持有并驱动，并通过门面把目标的颜色 / 深度视图交给帧模块的离屏渲染路径（`render_to_target`）使用。

```
                ┌────────────────────────────────────────────────────────────────┐
                │                  Renderer（渲染器门面）                        │
                │  init ⑯：render_target.build(device, family, queue, memory)     │
                │  render_target_create → target_create（颜色/深度格式取自交换链）│
                │  frame_render：active_target 非零 → frame.render_to_target(...) │
                │  texture_bind_target(target)：目标颜色视图 → 帧槽 set1           │
                │  shutdown：render_target.destroy()                              │
                └───────────┬───────────────────────────────────┬───────────────┘
                            │ 驱动（build / target_* / destroy）  │
                            ▼                                     │
        ┌───────────────────────────────────────────────────────────────┐  │
        │                  Render_Target_Context（渲染目标上下文）       │  │
        │  device / graphics_family / graphics_queue / memory             │  │
        │  transient_pool / transient_fence / records[]                   │  │
        └───┬──────────────┬───────────────┬──────────────┬──────────────┘  │
            │依赖           │依赖            │依赖           │依赖             │
            ▼               ▼                ▼               ▼               │
    ┌─────────────┐ ┌─────────────┐ ┌──────────────┐ ┌──────────────┐      │
    │ 设备模块     │ │ 设备队列     │ │ 内存模块      │ │ 渲染器门面    │      │
    │ VkDevice    │ │ VkQueue     │ │ image_create  │ │ 结果检查 / 日志│      │
    └─────────────┘ └─────────────┘ └──────────────┘ └──────────────┘      │
                                                                            │
      提供：VkImage / VkImageView（颜色 ＋ 深度）＋ VkExtent2D               │
                                                                            ▼
                                              ┌──────────────────────────────┐
                                              │ 帧模块 Frame_Render_Target    │
                                              │ command_record_target 录制    │
                                              └──────────────────────────────┘
```

- **向上**：调用方是「渲染层-渲染器」门面 `Renderer::Impl`。门面在 `init` 的 ⑯ 步调用 `build(device, graphics_family, graphics_queue, memory)`；在 `render_target_create` 中调用 `target_create(handle_out, width, height, swapchain.format_get(), swapchain.depth_format_get())`；在 `frame_render` 中读取 `target_get(...)` 组装 `Frame_Render_Target` 后再交帧模块 `render_to_target`；在 `texture_bind_target` 中读取目标颜色视图写入帧槽 `set 1`；在 `shutdown` 中调用 `destroy`。
- **向下**：依赖设备模块（`VkDevice` + 图形队列）、内存模块（`image_create` / `image_view_create` / `image_view_destroy` / `image_destroy`）、渲染层 `结果检查.h`（`vk_result_check`）、引擎日志系统（`logger`）、Vulkan Loader（`vkCreateCommandPool` / `vkAllocateCommandBuffers` / `vkCmdPipelineBarrier` / `vkQueueSubmit` / `vkWaitForFences` 等）。
- **横向**：本模块**不**持有设备 / 内存对象，只消费它们产出的裸句柄与内存模块实例引用（`Memory_Context* memory`）；故除内存模块（持其指针以调用图像 API）外，无其它模块的直接编译期依赖边。

### 2.4 与相邻模块的职责分界

| 相邻模块 | 分界 |
| --- | --- |
| 设备模块（`render/Device/`，`Device_Context`） | 设备模块负责选物理设备、建逻辑设备、取队列；本模块**只消费**其 `device_get()` / `graphics_family_get()` / `graphics_queue_get()` 结果，用于本模块全部 Vulkan 调用与一次性转换的提交，不创建任何设备对象。 |
| 内存模块（`render/Memory/`，`Memory_Context`） | 内存模块负责图像 / 视图的底层创建与销毁；本模块**消费**其 `image_create` / `image_view_create` / `image_view_destroy` / `image_destroy`，把「目标的两图像 ＋ 两视图」建在其上。**销毁一律回到内存模块**（本模块不直接调 `vmaDestroyImage` / `vkDestroyImageView`）。 |
| 帧模块（`render/Frame/`，`Frame_Context`） | 帧模块负责每帧录制与提交；本模块**产出**目标的颜色图像句柄、颜色视图、深度视图与范围，由门面组装成帧模块的 `Frame_Render_Target` 传入 `render_to_target`。**本模块不录制命令，也不渲染**——实际渲染由帧模块的动态渲染路径完成。 |
| 管线模块（`render/Pipeline/`，`Pipeline_Context`） | 二者无直接编译期依赖。间接协作：门面 `texture_bind_target` 把「目标颜色视图 ＋ 纹理模块共享采样器」写入各帧槽 `set 1`，使目标颜色被后续绘制按纹理采样——此路径经管线模块的 `texture_bind` 落地。 |
| 纹理模块（`render/Texture/`，`Texture_Context`） | 纹理模块持有共享采样器；门面 `texture_bind_target` 借纹理模块取一次采样器句柄，再与目标颜色视图一并写入帧槽 `set 1`。**本模块不引入纹理模块接口**。 |
| 「渲染层-渲染器」模块的 `结果检查.h` | 本模块的全部 `VkResult` 检查都调用该头提供的 `vk_result_check`；该头是渲染层内所有模块共用的唯一检查出口。 |
| 本层设计文档（含 §/K 编号） | 本模块源码注释未大量引用编号，故本文不涉及编号溯源。 |

### 2.5 生命周期

`Render_Target_Context` 与 `Render_Target_Record` 的完整生命周期为：

```
构造（default，不创建任何 Vulkan 对象）
   → build(device, graphics_family, graphics_queue, memory)  ← 记录设备 / 图形队列与内存模块
   → target_create(handle_out, width, height, color_format, depth_format) × N
        ← 惰性建一次性命令池 / 栅栏 → 建颜色图像 + 视图 + 深度图像 + 视图 → 一次性布局转换 → 登记并分配句柄
   → target_get(handle, ...) / target_valid(handle)           ← 取句柄对应目标的附件与范围
   → target_destroy(handle)                                   ← 归还该目标的图像 / 视图，记录复位为空槽
   → destroy()                                                ← 幂等；逐条归还目标，再归还一次性资源并复位
   → 析构（兜底再调用一次 destroy，保证资源不泄漏）
```

- 状态机只有两态：**未构建完成**与**构建完成**。`valid()` 的判据是「逻辑设备非空 **且** 内存模块指针非空」。
- `build` 前置校验：设备非空、图形队列非空、内存模块 `valid()` 为真，三者任一不满足即记 `logger.error` 并返回 `false`（**不创建任何资源**）。
- `target_create` 在前置校验（上下文有效、宽高非零、颜色 / 深度格式非 `UNDEFINED`）通过后，惰性确保一次性转换资源就绪，再逐环节创建资源并做初始布局转换；**任一环节失败即回收已创建资源**（视图 → 图像），不登记半初始化记录，句柄保持 0。
- `target_destroy` 幂等：句柄无效（0 / 越界）或目标已空时直接返回；命中则归还图像 / 视图并把整条记录复位为空槽（空槽可被后续 `target_create` 复用）。
- `destroy()` 可重复调用，第二次及以后为无操作；析构函数内部再调一次 `destroy()`，因此「显式销毁 + 析构」不会重复释放。
- 类**不可拷贝、不可移动**（持有 VMA 句柄与队列），以 `= delete` 显式删除拷贝构造与拷贝赋值；未声明移动，故移动亦不可用。

### 3.3 逐条接口说明

#### 3.3.1 `Render_Target_Context(void) = default`

- **功能**：默认构造，**不创建任何 Vulkan 对象**。
- **参数**：无。
- **返回值**：无。
- **约束**：全部成员以类内初始化器就位：`device = VK_NULL_HANDLE`、`graphics_family = 0`、`graphics_queue = VK_NULL_HANDLE`、`memory = nullptr`、`transient_pool` / `transient_fence = VK_NULL_HANDLE`、`records` 为空 `vector`。

#### 3.3.2 `~Render_Target_Context(void)`

- **功能**：析构，内部调用 `destroy()`，保证资源不泄漏。
- **参数**：无。
- **返回值**：无。
- **约束**：即使在部分构建（半初始化）状态下析构也安全，因 `destroy()` 逐句柄判空后再释放。

#### 3.3.3 拷贝与赋值（`= delete`）

- **功能**：显式删除拷贝构造与拷贝赋值。
- **约束**：类持有 Vulkan / VMA 句柄，**不可拷贝、不可移动**（未声明移动构造/移动赋值，故移动亦不可用）。

#### 3.3.4 `bool build(VkDevice device, uint32_t graphics_family, VkQueue graphics_queue, Memory_Context& memory)`

- **功能**：构建——记录逻辑设备、图形队列族索引、图形队列与内存模块。
- **参数**：
  - `device`：逻辑设备句柄（来自设备模块 `device_get()`）。为 `VK_NULL_HANDLE` 时报错并返回 `false`。
  - `graphics_family`：图形队列族索引（来自设备模块 `graphics_family_get()`），供一次性命令池的 `queueFamilyIndex` 使用。
  - `graphics_queue`：图形队列（来自设备模块 `graphics_queue_get()`），一次性布局转换的提交目标。为 `VK_NULL_HANDLE` 时报错并返回 `false`。
  - `memory`：内存模块引用（来自门面 `Impl`），图像 / 视图创建与销毁依赖它。`memory.valid()` 为假时报错并返回 `false`。
- **返回值**：`bool`——全部前置满足返回 `true`，否则 `false`。
- **约束与异常行为**：
  - 三者任一不满足即记 `logger.error("渲染目标:: 构建前置不完整（设备 / 队列 / 内存模块）")` 并 `return false`（**不创建任何资源**，也不调用 `destroy`）。
  - 成功记录 `this->device` / `this->graphics_family` / `this->graphics_queue` / `this->memory = &memory`，记 `logger.info`。
  - **本函数不创建一次性资源**：命令池 / 栅栏由 `target_create → transient_resources_ensure` 惰性建立。

#### 3.3.5 `void destroy(void)`

- **功能**：销毁本模块创建的全部 Vulkan / VMA 对象（全部渲染目标 ＋ 一次性命令池 / 栅栏）并复位状态。
- **参数**：无。
- **返回值**：无。
- **约束与行为**：
  - 遍历 `records`：**跳过空槽**（`valid == false`），对有效记录调用 `record_resources_destroy`（归还图像 / 视图），再把该记录整条复位为 `Render_Target_Record{}`；随后 `records.clear()`。
  - 仅当 `device != VK_NULL_HANDLE` 时进入一次性资源释放分支：先 `vkDestroyFence(transient_fence)`，再 `vkDestroyCommandPool(transient_pool, nullptr)`（顺序为先栅栏后命令池）。
  - 复位 `transient_fence` / `transient_pool` / `memory`(= nullptr) / `graphics_queue` / `device` / `graphics_family`(= 0)。
  - **幂等**：第二次及以后调用时无目标可回收、`device == VK_NULL_HANDLE`，直接走复位（无操作语义）。
  - **无 `vkDeviceWaitIdle`**：本函数不做设备空闲等待；调用方须保证销毁时无在途帧仍在使用这些目标（门面在 `shutdown` 逆序编排中处理：`frame.destroy()` 先于 `render_target.destroy()`）。

#### 3.3.6 `bool valid(void) const`

- **功能**：查询是否已构建完成。
- **参数**：无。
- **返回值**：`bool`——判据为 `device != VK_NULL_HANDLE && memory != nullptr`。
- **约束**：仅检查设备与内存模块指针，**不检查**一次性命令池 / 栅栏（它们惰性创建，与「是否已构建」无关）。

#### 3.3.7 `bool target_create(uint64_t& handle_out, uint32_t width, uint32_t height, VkFormat color_format, VkFormat depth_format)`

- **功能**：创建一个离屏渲染目标（颜色 ＋ 深度图像与两者视图），并执行创建时一次性布局转换。
- **参数**：
  - `handle_out`：出参，**默认置 0**；成功写出句柄（≥ 1），失败保持 0。
  - `width` / `height`：目标尺寸（像素）；为 0 视为非法。
  - `color_format`：颜色图像格式（门面取 `swapchain.format_get()`）；`VK_FORMAT_UNDEFINED` 视为非法。
  - `depth_format`：深度图像格式（门面取 `swapchain.depth_format_get()`）；`VK_FORMAT_UNDEFINED` 视为非法。
- **返回值**：`bool`——全部环节成功返回 `true`，任一失败返回 `false`。
- **约束与异常行为**：
  - 前置校验：上下文 `valid()` 为真、宽高非零、两格式非 `UNDEFINED`；任一不满足即记 `logger.error` 并 `return false`。
  - 随后 `transient_resources_ensure` 确保一次性命令池 / 栅栏就绪；失败 `return false`。
  - 创建顺序：① 颜色图像 `image_create(..., COLOR_ATTACHMENT | SAMPLED | TRANSFER_SRC)` → ② 颜色视图 `image_view_create(..., color_format, COLOR_BIT)` → ③ 深度图像 `image_create(..., DEPTH_STENCIL_ATTACHMENT)` → ④ 深度视图 `image_view_create(..., depth_format, DEPTH_BIT)` → ⑤ `target_transition` 一次性布局转换。
  - **失败即回收**：②③④⑤ 任一失败，均先 `record_resources_destroy(record)` 归还已创建资源（先深度视图 / 深度图像，再颜色视图 / 颜色图像），再返回 `false`；① 失败时图像 API 已把 `color_image` / `color_alloc` 复位空，无需额外回收。**故不存在半初始化记录**。
  - 成功后标记 `record.valid = true`，**分配句柄**：先线性扫描 `records` 找第一个 `valid == false` 的空槽并覆写（句柄 = 下标 + 1），无空槽则 `push_back`（句柄 = 新长度）。
  - 成功记 `logger.info("渲染目标:: 已创建（句柄 {}，{}×{}）")`。
  - **参数来源**：颜色 / 深度格式由门面从交换链模块取回，故目标创建须在交换链创建之后（门面 `init` 顺序保证）。

#### 3.3.8 `void target_destroy(uint64_t handle)`

- **功能**：销毁一个渲染目标。
- **参数**：`handle`——目标句柄。
- **返回值**：无。
- **约束与行为**：
  - 句柄无效（`handle == 0 || handle > records.size()`）直接 `return`（忽略）。
  - 取记录 `records[handle - 1]`；若已空（`!record.valid`）直接 `return`（幂等）。
  - 调用 `record_resources_destroy(record)` 归还图像 / 视图，再把整条记录复位为 `Render_Target_Record{}`（标记槽为空、可被复用）。
  - 成功记 `logger.info("渲染目标:: 已销毁（句柄 {}）")`。
  - **注意**：本函数**不重置 `extent` 的持久语义**——记录整条复位后 `extent` 归零，但目标已无效，`target_get` 对空槽返回假。

#### 3.3.9 `bool target_detach(uint64_t handle, Render_Target_Record& record_out)`（本轮新增）

- **功能**：把目标记录**整体摘出**（写出到 `record_out` 并把原记录复位为空槽）而**不**归还其颜色 / 深度图像与视图——归还责任移交调用方。
- **参数**：`handle` 目标句柄；`record_out` 出参，成功时写出被摘出的记录（颜色 / 深度图像 ＋ 内存 ＋ 视图 ＋ `extent`）。
- **返回值**：`bool`——句柄有效且目标非空返回 `true` 并写出记录；`handle == 0` / 越界 / 记录已空返回 `false`（**不写出任何资源**，`record_out` 保持入参状态）。
- **约束与行为（源码顺序）**：① 句柄无效或记录已空 → 返回假；② `record_out = record`（整体写出）；③ `record = Render_Target_Record{}`（整条复位为**空槽**，可被后续 `target_create` 复用）；④ **不**触碰一次性命令池 / 栅栏。
- **与 `target_destroy` 的分界**：`target_destroy` 经 `record_resources_destroy` 直接归还图像 / 视图；`target_detach` 只摘出、不归还（见 §7.3）。二者都把记录复位为空槽、句柄槽**可复用**；但对句柄无效 / 已空的情形 `target_detach` 以**返回值**表达成败，`target_destroy` 为 `void` 静默返回。
- **异常行为**：不抛异常。

#### 3.3.10 `bool target_get(uint64_t handle, VkImage& color_image_out, VkImageView& color_view_out, VkImageView& depth_view_out, VkExtent2D& extent_out) const`

- **功能**：取目标各附件与范围（供门面组装帧模块的 `Frame_Render_Target`）。
- **参数**：`handle`——目标句柄；四个出参依次为颜色图像、颜色视图、深度视图与范围。
- **返回值**：`bool`——句柄有效且目标非空返回 `true` 并写出四出参；否则返回 `false` 且**四个出参先复位为空 / 零**。
- **约束与行为**：
  - 出参先复位：`color_image_out` / `color_view_out` / `depth_view_out = VK_NULL_HANDLE`、`extent_out = { 0, 0 }`。
  - 句柄无效（0 / 越界）返回假；目标已空（`!valid`）返回假。
  - 恒为 `const` 方法，不改变本模块状态。

#### 3.3.11 `bool target_valid(uint64_t handle) const`

- **功能**：查询句柄是否有效。
- **参数**：`handle`——目标句柄。
- **返回值**：`bool`——`handle != 0 && handle <= records.size() && records[handle - 1].valid`；越界或空槽均返回假。
- **约束**：门面 `render_target_set` 用它判断句柄有效性，无效则回落交换链路径。

#### 3.3.12 `bool target_readback(uint64_t handle, uint8_t* pixels, uint32_t capacity, uint32_t* width_out, uint32_t* height_out)`（第二十六轮新增）

- **功能**：把目标颜色图像**同步读回**到主机缓冲（RGBA8 紧排、逐行自上而下、无行填充）。
- **参数**：`handle` 目标句柄；`pixels` 主机出参；`capacity` 字节容量（须 ≥ 宽×高×4）；`width_out` / `height_out` 可选尺寸出参。
- **返回值**：全流程成功返回真并写出尺寸；任一步失败返回假（尺寸出参保持 0）。
- **实现链路**：
  1. 校验有效性与容量（不足即 `error` 并返回假）；
  2. `transient_resources_ensure` 后创建主机可见暂存缓冲（`TRANSFER_DST`）；
  3. 一次性命令缓冲内做：`SHADER_READ_ONLY → TRANSFER_SRC` 屏障 → `vkCmdCopyImageToBuffer`（整幅、紧排）→ `TRANSFER_SRC → SHADER_READ_ONLY` 屏障；
  4. 复位栅栏 → 提交 → 等待 → `buffer_read` 读出像素 → 销毁暂存缓冲。
- **布局不变量**：读回前后颜色图像**均**为 `SHADER_READ_ONLY_OPTIMAL`，故不破坏「离屏目标可在后续帧继续采样」；`TRANSFER_SRC` 只存在于这段拷贝命令内。
- **同步约定**：调用方须先保证无在途帧引用该目标（门面 `render_target_readback` 已先 `frames_wait`）；本模块只用一次性命令池同步提交，不依赖帧槽。
- **限制**：只读颜色，不读深度（读深度见 §3.3.12B）；每次调用临时创建并销毁暂存缓冲；为同步接口，不宜逐帧调用。

#### 3.3.12A `bool target_readback_region(uint64_t handle, uint32_t x, uint32_t y, uint32_t region_width, uint32_t region_height, uint8_t* pixels, uint32_t capacity, uint32_t* width_out, uint32_t* height_out)`（第二十七轮新增）

- **功能**：读回颜色图像的**指定子矩形**（RGBA8 紧排，子区域逐行紧密排列）。
- **校验**：句柄有效、区域宽高非 0、且 `x + region_width ≤ extent.width`、`y + region_height ≤ extent.height`（用减法形式避免无符号下溢），越界整次拒绝并 `error`。
- **实现**：与整幅读回共用私有 `target_readback_impl(handle, x, y, region_w, region_h, …)`；`VkBufferImageCopy.imageOffset = {x, y, 0}`、`imageExtent = {region_w, region_h, 1}`，容量按区域计算，成功后回填**区域**尺寸。
- **契约不变**：布局往返后仍为 `SHADER_READ_ONLY_OPTIMAL`；同步接口（门面先 `frames_wait`）。

#### 3.3.12B `bool target_readback_depth(uint64_t handle, uint32_t* values, uint32_t capacity, uint32_t* width_out, uint32_t* height_out)`（第二十八轮新增）

- **功能**：把目标**深度图像**同步读回到主机（每像素 32 位原始值；`D32_SFLOAT` 下由调用方 `memcpy` 解释为 `float`）。
- **参数**：`handle` 目标句柄；`values` 主机出参（`uint32_t` 数组）；`capacity` **元素个数**（须 ≥ 宽×高；与颜色读回的「字节容量」口径不同）；`width_out` / `height_out` 可选尺寸出参。
- **返回值**：全流程成功返回真并写出尺寸；任一步失败返回假（尺寸出参清零）。
- **实现链路**：与颜色读回同构，但切面与布局不同——
  1. 校验有效性与容量（元素个数口径）；
  2. 创建主机可见暂存缓冲（`TRANSFER_DST`，大小为 宽×高×4）；
  3. `DEPTH_ATTACHMENT_OPTIMAL → TRANSFER_SRC_OPTIMAL`（`VK_IMAGE_ASPECT_DEPTH_BIT`；`srcStageMask = EARLY_FRAGMENT_TESTS | LATE_FRAGMENT_TESTS`，`dstStageMask = TRANSFER`）→ `vkCmdCopyImageToBuffer`（整幅）→ 反向屏障转回；
  4. 同步提交 → `buffer_read` → 销毁暂存缓冲。
- **前置条件**：深度图像在 `target_create` 时已声明 `VK_IMAGE_USAGE_TRANSFER_SRC_BIT`（第二十八轮加入；与颜色图像的 `TRANSFER_SRC` 同理）。
- **布局不变量**：读回前后深度图像均为 `DEPTH_ATTACHMENT_OPTIMAL`，后续帧渲染不受影响。
- **限制**：只读第 0 层（深度无 mip）；不做线性化与格式转换；同步接口。

### 4.2 `bool transient_resources_ensure(void)`（`core/目标创建.cpp`）

- **功能**：确保一次性命令池与完成栅栏就绪——首次调用创建，之后复用。
- **返回值**：`bool`——两者齐备返回 `true`，任一创建失败返回 `false`。
- **约束与关键行为**：
  - **快速路径**：若 `transient_pool != VK_NULL_HANDLE && transient_fence != VK_NULL_HANDLE`，直接返回 `true`（跨多个目标复用，无重复创建）。
  - 创建一次性命令池：`VkCommandPoolCreateInfo` 带 `VK_COMMAND_POOL_CREATE_TRANSIENT_BIT`、`queueFamilyIndex = graphics_family`；创建失败即把 `transient_pool` 置空返回假。
  - 创建完成栅栏：`VkFenceCreateInfo`（**未触发态**，因每次提交前先 `vkResetFences`）；创建失败即销毁刚建的命令池并把两者置空返回假。
  - `TRANSIENT` 标志提示驱动「命令缓冲短命、可快速复用」，与其「一次转换提交即弃」的用法相符。

### 4.3 `bool target_transition(VkImage color_image, VkImage depth_image)`（`core/目标创建.cpp`）

- **功能**：对新建目标执行**一次**布局转换：颜色 `UNDEFINED → SHADER_READ_ONLY_OPTIMAL`、深度 `UNDEFINED → DEPTH_ATTACHMENT_OPTIMAL`。
- **返回值**：`bool`——提交并等待完成返回 `true`，任一环节失败返回 `false`。
- **约束与关键行为**：
  - 重置命令池（`vkResetCommandPool`，连带回收上次分配的命令缓冲）→ 分配 1 个 `PRIMARY` 命令缓冲 → `vkBeginCommandBuffer`（`ONE_TIME_SUBMIT_BIT`）。
  - **颜色屏障**：`oldLayout = UNDEFINED`、`newLayout = SHADER_READ_ONLY_OPTIMAL`、`srcAccessMask = 0`、`dstAccessMask = SHADER_READ`、`subresourceRange = { COLOR_BIT, 0, 1, 0, 1 }`。
  - **深度屏障**：`oldLayout = UNDEFINED`、`newLayout = DEPTH_ATTACHMENT_OPTIMAL`、`srcAccessMask = 0`、`dstAccessMask = DEPTH_STENCIL_ATTACHMENT_WRITE`、`subresourceRange = { DEPTH_BIT, 0, 1, 0, 1 }`。
  - **一次提交两条屏障**：`vkCmdPipelineBarrier(cmd, srcStage = TOP_OF_PIPE, dstStage = FRAGMENT_SHADER | EARLY_FRAGMENT_TESTS | LATE_FRAGMENT_TESTS, ...)`（`dstStage` 取颜色「片元着色器」与深度「早 / 晚片元测试」两者并集）。
  - 结束录制 → `vkResetFences(transient_fence)` → `vkQueueSubmit(graphics_queue, ..., transient_fence)`（**不设信号量**，同步完成）→ `vkWaitForFences(..., VK_TRUE, UINT64_MAX)`。
  - 任一 `vk_result_check` 失败即返回 `false`（由 `target_create` 的失败路径回收图像 / 视图）。
  - 设计动机（为何一次性而非逐帧转换、为何该 dstStage 并集）见 §6.2。

### 4.4 `void record_resources_destroy(Render_Target_Record& record)`（`core/目标创建.cpp`）

- **功能**：归还单条记录的图像与视图（内存模块就绪时；**不触碰 `valid` 标记**）。
- **参数**：`record`——目标记录。
- **返回值**：无。
- **约束与关键行为**：
  - 仅当 `memory != nullptr` 时逐个归还，顺序为：深度视图 → 深度图像 → 颜色视图 → 颜色图像（各句柄判空后再归还；销毁一律经内存模块 `image_view_destroy` / `image_destroy`）。
  - 归还后把 `color_image` / `color_alloc` / `color_view` / `depth_image` / `depth_alloc` / `depth_view` 复位为 `VK_NULL_HANDLE`；**不改变 `extent`、不改变 `valid`**（由调用方决定是否整条复位）。

### 5.2 各编译单元职责

| 编译单元 | 职责 | 关键被调用 API |
| --- | --- | --- |
| `core/目标创建.cpp` | 记录设备 / 队列 / 内存模块；目标创建、销毁、**摘出（`target_detach`；本轮新增）**、取用、有效性查询；一次性转换资源的惰性建立与复用；创建时布局转换；图像 / 视图的归还 | `vkCreateCommandPool`、`vkAllocateCommandBuffers`、`vkCmdPipelineBarrier`、`vkQueueSubmit`、`vkWaitForFences`、内存模块 `image_create` / `image_view_create` / `image_view_destroy` / `image_destroy` |

### 5.3 内部数据结构字段说明

#### 5.3.1 `Render_Target_Record`（记录结构，逐字段）

- `VkImage color_image = VK_NULL_HANDLE`：颜色图像。经内存模块以 `COLOR_ATTACHMENT | SAMPLED | TRANSFER_SRC` 用法创建，创建后布局转换为 `SHADER_READ_ONLY_OPTIMAL`。
- `VmaAllocation color_alloc = VK_NULL_HANDLE`：颜色图像内存，归还时与 `color_image` 一并交给内存模块。
- `VkImageView color_view = VK_NULL_HANDLE`：颜色图像视图（2D / 单层 / 单 mip，aspect `COLOR_BIT`，格式 = `color_format`）。
- `VkImage depth_image = VK_NULL_HANDLE`：深度图像。经内存模块以 `DEPTH_STENCIL_ATTACHMENT` 用法创建，创建后布局转换为 `DEPTH_ATTACHMENT_OPTIMAL`。
- `VmaAllocation depth_alloc = VK_NULL_HANDLE`：深度图像内存。
- `VkImageView depth_view = VK_NULL_HANDLE`：深度图像视图（aspect `DEPTH_BIT`，格式 = `depth_format`）。
- `VkExtent2D extent = { 0, 0 }`：渲染目标范围，等于创建时的 `{ width, height }`；门面经 `target_get` 取出，供帧模块设置渲染区与视口 / 裁剪。
- `bool valid = false`：记录是否有效。`true` 才参与 `target_get` / `target_valid` / `target_destroy` 的实际语义；空槽（`false`）会被 `target_create` 优先复用。

#### 5.3.2 `Render_Target_Context` 私有成员（逐字段）

| 成员 | 类型 | 初值 | 说明 | 生命周期 |
| --- | --- | --- | --- | --- |
| `device` | `VkDevice` | `VK_NULL_HANDLE` | 逻辑设备句柄，用于本模块全部 Vulkan 调用 | `build` 记入；`destroy` 复位 |
| `graphics_family` | `uint32_t` | 0 | 图形队列族索引（一次性命令池的 `queueFamilyIndex`） | `build` 记入；`destroy` 复位为 0 |
| `graphics_queue` | `VkQueue` | `VK_NULL_HANDLE` | 图形队列（一次性布局转换的提交目标） | `build` 记入；`destroy` 复位 |
| `memory` | `Memory_Context*` | `nullptr` | 内存模块指针（图像 / 视图创建与销毁依赖它） | `build` 记入；`destroy` 复位为 `nullptr` |
| `transient_pool` | `VkCommandPool` | `VK_NULL_HANDLE` | 一次性命令池（布局转换用；跨多个目标复用） | `transient_resources_ensure` 创建；`destroy` 销毁 |
| `transient_fence` | `VkFence` | `VK_NULL_HANDLE` | 一次性完成栅栏（布局转换用；跨多个目标复用） | `transient_resources_ensure` 创建；`destroy` 销毁 |
| `records` | `std::vector<Render_Target_Record>` | 空 | 渲染目标记录集合（下标 = 句柄 − 1） | `target_create` 增改；`target_destroy` 复位槽位；`destroy` 清空 |

### 5.4 内部类型关系与调用关系

`Render_Target_Context` 是**单一门面类**，其私有成员函数与公开接口的调用关系如下（`→` 表示「调用」）：

```
                                     ┌────────────────────────────────┐
                                     │     Render_Target_Context        │
                                     └────────────────────────────────┘
私有：
  transient_resources_ensure ─→ vkCreateCommandPool / vkCreateFence（首次；之后复用）
  target_transition ─→ vkResetCommandPool / vkAllocateCommandBuffers / vkCmdPipelineBarrier ×1（两屏障）
                     / vkQueueSubmit / vkWaitForFences
  record_resources_destroy ─→ memory.image_view_destroy(×2) / memory.image_destroy(×2)
公开：
  build ──────→ 记录 device / graphics_family / graphics_queue / memory
  target_create ─┬─→ transient_resources_ensure
                 ├─→ memory.image_create（颜色）→ memory.image_view_create（颜色）
                 ├─→ memory.image_create（深度）→ memory.image_view_create（深度）
                 ├─→ target_transition
                 ├─→（失败路径）record_resources_destroy
                 └─→ 复用空槽 / push_back 并写出句柄
  target_destroy ─┬─→ record_resources_destroy
                  └─→ 记录整条复位（槽位置空）
  target_get / target_valid ──→ 纯读取 records（无 Vulkan 调用）
  destroy ────┬─→ 逐条 record_resources_destroy + 记录复位
              ├─→ records.clear()
              └─→ vkDestroyFence / vkDestroyCommandPool
析构 ───────────────→ destroy
```

用文字描述对象依赖：目标记录内的颜色 / 深度图像与视图**依赖内存模块**（创建 / 销毁均经它）；`target_transition` 依赖 `graphics_queue`（提交目标）与 `transient_pool` / `transient_fence`（录制与同步）；`transient_pool` 依赖 `device` 与 `graphics_family`。因此**创建顺序**必须是 `build（记录设备 / 队列 / 内存）→ transient_resources_ensure → 逐目标建图像与视图 → target_transition`，而**销毁顺序**必须为「先归还全部目标（图像 → 视图）→ 再归还一次性资源（栅栏 → 命令池）→ 最后复位句柄」。本模块的 `target_create` 与 `destroy` 正是按此顺序编排。

### 5.5 `局部命名空间使用.h` 的做法说明

**内容（全文）**：

```cpp
#pragma once
#include "渲染目标.h"

// ---------- 基本类型别名 ----------
using std::string;
using std::vector;
```

**做法**：本模块的 `core/目标创建.cpp` 先 `#include "src/render/RenderTarget/局部命名空间使用.h"`（实现文件本层根相对包含口径），从而在**本模块实现文件内**引入 `string`、`vector` 等标准类型别名（本模块实际仅用到 `vector`，`string` 为各模块统一的别名清单条目）。此后实现代码**一律不加命名空间前缀**（如 `for (std::size_t index = 0; index < records.size(); ++index)`）。这是渲染层与引擎统一的「局部命名空间使用」约定的落地：对外头 `渲染目标.h` 保持干净（只用 `std::vector` 全名），实现文件通过私有头把冗长前缀收拢到一处。

> 说明：本模块用到的 `VkImage` / `VkImageView` / `VmaAllocation` 等类型来自 `渲染目标.h` 中的 `<vulkan/vulkan.h>` 与 `<vk_mem_alloc.h>`，不需要在私有头中额外引入；`Memory_Context` 的完整定义由实现文件 `#include "src/render/Memory/内存上下文.h"` 引入（对外头仅前置声明 `class Memory_Context;`）。

## 六、模块设计/实现细节

### 6.1 目标图像的用法与布局不变量

- **颜色图像**：`VK_IMAGE_USAGE_COLOR_ATTACHMENT_BIT | VK_IMAGE_USAGE_SAMPLED_BIT | VK_IMAGE_USAGE_TRANSFER_SRC_BIT`。
  - 颜色附件：可作 `vkCmdBeginRendering` 的颜色附件（写）。
  - 采样：可被 `set 1` 的组合图像采样器采样（读）——即「离屏结果当纹理」。
  - 传输源：可作 `vkCmdCopyImageToBuffer` 的源（像素回读）。
- **深度图像**：`VK_IMAGE_USAGE_DEPTH_STENCIL_ATTACHMENT_BIT`——仅作深度附件。
- **布局不变量（务必牢记）**：
  - **颜色在帧间恒处于 `VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL`**。目标创建时已由 `target_transition` 转至此布局；帧模块的离屏路径在渲染前后负责「进入附件布局 / 退出回该布局」（见 §6.6）。故目标颜色**随时可被采样**，无需调用方另行转换。
  - **深度恒处于 `VK_IMAGE_LAYOUT_DEPTH_ATTACHMENT_OPTIMAL`**。创建时转至该布局，帧链路**不再逐帧转换**，仅以 `CLEAR`（深度 1.0、模板 0）清空后使用。
  - 该不变量是「目标可立即作纹理采样、亦可立即作附件渲染」这一双重用途的根基；破坏它（如在别处把颜色转到其它布局）会使帧链路屏障失配（属 Vulkan 校验错误）。
- 图像其它参数：由内存模块固定为 2D、`VK_IMAGE_TILING_OPTIMAL`、`SAMPLE_COUNT_1_BIT`、`SHARING_MODE_EXCLUSIVE`、`initialLayout = UNDEFINED`、mip 级数 1。

### 6.2 创建时一次性布局转换（`target_transition`）

- **为何需要**：图像创建后初始布局为 `UNDEFINED`，既不可作附件也不可采样。故创建后必须立即转一次布局，使目标进入「可采样（颜色）/ 可作深度附件（深度）」的稳定态。
- **为何一次性**：颜色在帧间恒保持可采样布局、深度恒保持深度附件布局，故**只需创建时转一次**；后续帧链路的 `command_record_target` 负责「进出」的局部转换（进入 `COLOR_ATTACHMENT_OPTIMAL` 渲染、退出回 `SHADER_READ_ONLY_OPTIMAL`），无需本模块再介入。
- **同步语义**：`srcStage = TOP_OF_PIPE`、`srcAccessMask = 0`——旧布局是 `UNDEFINED`，无需等待任何先前写入（丢弃旧内容）；`dstStage = FRAGMENT_SHADER | EARLY_FRAGMENT_TESTS | LATE_FRAGMENT_TESTS`——取「颜色将被片元着色器采样」与「深度将被早 / 晚片元测试读写」的并集，两条屏障共用同一 `dstStage`，故**一次 `vkCmdPipelineBarrier`**（传入两条 `VkImageMemoryBarrier` 的数组）即可。
- **提交同步**：提交到 `graphics_queue` 并以 `transient_fence` 作为完成信号，随后 `vkWaitForFences(...UINT64_MAX)` 阻塞等待——保证 `target_create` 返回时目标已处于稳定布局、可被立即使用。
- **资源复用**：命令池 / 栅栏在 `transient_resources_ensure` 中惰性建立并跨目标复用；每次转换仅「重置命令池 → 分配 → 录制 → 提交 → 等待」，不逐目标创建 / 销毁。（注：命令池带 `TRANSIENT` 标志，多次转换经 `vkResetCommandPool` 复用。）

### 6.3 句柄分配与空槽复用

- 句柄自 1 起（0 表无效）；`下标 = 句柄 − 1`。
- **分配策略**：`target_create` 成功后先线性扫描 `records`，取**第一个 `valid == false` 的空槽**覆写（句柄 = 下标 + 1）；若无空槽则 `push_back`（句柄 = 新长度）。
- **复用语义**：`target_destroy` 把命中记录整条复位为 `Render_Target_Record{}`（`valid = false` 的空槽），故其槽位会被后续 `target_create` 优先复用——这使句柄在「销毁—再创建」间可能**重复出现**（旧句柄在销毁后即失效，重新创建可能得到同一数值）。
- **稳定性**：一旦登记，句柄在目标存活期间稳定不变（`records` 不移动已有元素；只有 `push_back` 追加）。

### 6.4 失败路径与资源回收

`target_create` 的每一步失败都**就地回收已创建的资源**，不留半初始化记录：

| 失败环节 | 已创建资源 | 回收动作 |
| --- | --- | --- |
| 前进校验失败 | 无 | 直接返回 `false`，句柄保持 0 |
| `transient_resources_ensure` 失败 | （可能已建命令池或栅栏） | 该函数内部已自行处理半初始化（见 §4.2），返回 `false` |
| 颜色图像创建失败 | 无（图像 API 已把句柄 / 分配复位空） | 直接返回 `false` |
| 颜色视图创建失败 | 颜色图像 | `record_resources_destroy`（归还颜色图像） |
| 深度图像创建失败 | 颜色图像 + 颜色视图 | `record_resources_destroy`（归还颜色视图、颜色图像） |
| 深度视图创建失败 | 颜色图像 / 视图 + 深度图像 | `record_resources_destroy`（归还深度图像、颜色视图、颜色图像） |
| `target_transition` 失败 | 全部四资源 | `record_resources_destroy`（归还全部四资源） |

- `record_resources_destroy` 归还顺序为「深度视图 → 深度图像 → 颜色视图 → 颜色图像」，与创建顺序逆序。
- 句柄仅在各环节全部成功后才写出，故**失败时句柄恒为 0**。

### 6.5 一次性命令池与栅栏（`transient_resources_ensure`）

- **为何自持**：布局转换需要录制与同步，但目标创建是低频、无法依赖帧模块的命令池（帧命令池属「每帧槽」，语义不符且会打乱帧计数）。故本模块自持**一套**一次性资源。
- **复用**：`transient_pool` / `transient_fence` 首次创建后跨多个目标复用；此后每次转换仅 `vkResetCommandPool` 重置（连带回收上次分配的命令缓冲）再重新分配。
- **栅栏初态为未触发**：因每次提交前先 `vkResetFences`；若上次等待已完成，重置后栅栏回到未触发态，可安全用于下一次提交。
- **半初始化回退**：命令池建成但栅栏失败时，函数会销毁刚建的命令池并把两者复位空，避免泄漏。

### 6.6 与帧模块的协作（离屏渲染路径）

- 门面在 `frame_render` 中按 `active_target` 分派：非零且有效 → 取目标（`target_get`）组装 `Frame_Render_Target{ color_image, color_view, depth_view, extent }`，调用 `frame.render_to_target(...)`；否则走 `frame.render(...)`（交换链路径）。
- 帧模块 `command_record_target` 依据 §6.1 的布局不变量做局部转换：
  - 颜色进入时 **`SHADER_READ_ONLY_OPTIMAL` → `COLOR_ATTACHMENT_OPTIMAL`**（`srcStage = FRAGMENT_SHADER`、`srcAccess = SHADER_READ`），说明「上一帧结束后颜色被采样过」。
  - 动态渲染（渲染区 = 目标 `extent`，颜色 + 深度附件，均 `LOAD_OP_CLEAR`）→ 逐项绘制 → 可选 UI 回调 → `vkCmdEndRendering`。
  - 有回读：`COLOR_ATTACHMENT → TRANSFER_SRC`（拷贝）`→ SHADER_READ_ONLY`；无回读：`COLOR_ATTACHMENT → SHADER_READ_ONLY`。**两条路径均把颜色送回 `SHADER_READ_ONLY_OPTIMAL`**，维持不变量。
  - 深度进入时恒为 `DEPTH_ATTACHMENT_OPTIMAL`，故**不再转换**，仅以附件 `loadOp = CLEAR` 清空。
- 目标与交换链路径**共用同一批帧槽与帧计数轮转**，故二者可交替调用而不打乱在途帧同步。
- **已知取舍**：离屏路径本帧**不呈现到窗口**；离屏结果需经门面 `texture_bind_target` 把目标颜色视图绑入帧槽 `set 1`、再以正常绘制采样显示（即后处理闭环）。
- **运行时摘出（本轮新增）**：`target_detach` 把记录整体摘出而**不**归还图像 / 视图（见 §3.3.9）；门面据此把**颜色与深度各**组装一条 `Deferred_Entry::memory_resources` 压入帧模块延迟销毁队列，由帧模块在到期帧经内存模块 `image_view_destroy` / `image_destroy` 归还（见《渲染层-帧》§6.18）。

### 6.7 内存所有权约定

| 对象 | 创建方 | 销毁方 | 说明 |
| --- | --- | --- | --- |
| 颜色 / 深度 `VkImage` ＋ `VmaAllocation` | 本模块（经内存模块 `image_create`） | 本模块（经内存模块 `image_destroy`） | 私有资源，随目标 / `destroy` 归还 |
| 颜色 / 深度 `VkImageView` | 本模块（经内存模块 `image_view_create`） | 本模块（经内存模块 `image_view_destroy`） | 私有资源 |
| `VkCommandPool` / `VkFence`（一次性） | 本模块 | 本模块 `destroy` | 私有资源 |
| `VkDevice` | 设备模块 | 设备模块 | 本模块仅借用 |
| `VkQueue`（图形队列） | 设备模块 | 设备模块 | 本模块仅借用（一次性转换的提交目标） |
| `Memory_Context` | 门面（`Renderer::Impl`） | 门面 `shutdown`（须晚于 `render_target.destroy()`） | 本模块仅持**指针**，不拥有 |
| 目标内图像所属的 VMA 分配器 | 内存模块 | 内存模块 | 本模块仅经内存模块使用 |

**关键约定**：本模块**只销毁自己创建的对象**（目标图像 / 视图与一次性资源）；设备、队列、内存模块实例均不销毁。销毁图像 / 视图时**一律经内存模块**，不直接调用 `vmaDestroyImage` / `vkDestroyImageView`。

### 6.8 编码与风格约定

- **命名**：类型名 `Render_Target_Context` / `Render_Target_Record`（各单词首字母大写，无分隔）；函数名 `target_create` / `target_destroy` / `target_get` / `target_valid` / `transient_resources_ensure` / `record_resources_destroy`（小写，单词间 `_` 分隔）；「动词后置」（`target_create`、`target_get`）。
- **注释**：中文；短注释用多行 `//`；三行以上用 `/* */`；`//` 后无空格；采用换行注释。
- **大括号**：另起一行（Allman 风格）。
- **命名空间**：实现位于 `namespace engine`；`局部命名空间使用.h` 收拢标准类型别名。
- **异常禁用**：本模块不进行堆内存分配（`std::vector` 由标准库管理，无显式 `new`）；全部 Vulkan 调用的失败均以 `VkResult` 检查 + 返回 `false` 处理，不抛异常。
- **日志前缀**：统一 `"渲染目标:: ..."`，便于过滤。

### 6.9 易错点清单

1. **布局不变量须维持**：目标颜色恒为 `SHADER_READ_ONLY_OPTIMAL`、深度恒为 `DEPTH_ATTACHMENT_OPTIMAL`；若有代码把目标图像转到其它布局而不转回，帧链路屏障会失配（见 §6.1）。
2. **销毁一律经内存模块**：图像 / 视图的销毁必须调用 `memory->image_destroy` / `memory->image_view_destroy`；直接 `vmaDestroyImage` 会绕过内存模块的一致性约定。
3. **句柄可复用**：空槽会被 `target_create` 复用，故「销毁旧目标 → 创建新目标」可能得到同一句柄数值；据此判活须用 `target_valid` 而非单纯比较数值。
4. **失败无半初始化**：`target_create` 失败时句柄恒为 0，且已建资源已回收（见 §6.4）；调用方无需再清理。
5. **销毁前须无在途使用**：本模块 `destroy` / `target_destroy` 不含设备空闲等待，须由调用方保证（门面 `shutdown` 中 `frame.destroy()` 先行）。
6. **一次性资源不逐目标建**：命令池 / 栅栏只在首次 `target_create` 时建立并复用；`target_create` 内不做 `vkDeviceWaitIdle`（转换本身以栅栏同步完成，无需全局空闲）。

## 七、模块运行链路详例

本章以「调用方（门面）→ 本模块 → 被调方（内存模块 / Vulkan）」的时序描述典型链路。

### 7.1 初始化链路（门面 `Renderer::init` 的 ⑯ 步）

1. 门面在 ⑯ 步调用 `impl->render_target.build(impl->device.device_get(), impl->device.graphics_family_get(), impl->device.graphics_queue_get(), impl->memory)`。
2. 本模块 `build` 前置校验：设备 / 图形队列非空、`memory.valid()` 为真；否则记 error 返回 `false`（门面走 `shutdown`）。
3. 本模块 `build` 记录 `device` / `graphics_family` / `graphics_queue` / `memory = &memory`，记 `logger.info("渲染目标:: 上下文构建完成")`，返回 `true`。
4. 门面后续在该步之后顺延相机（⑰）与 UI 通道（⑱），本模块此时尚未创建任何目标（按需创建）。

### 7.2 创建目标链路（门面 `render_target_create`）

1. 门面 `render_target_create` 先 `handle_out = 0`；未初始化则记 error 返回 `false`。
2. 门面转交本模块：`target_create(handle_out, width, height, swapchain.format_get(), swapchain.depth_format_get())`。
3. 本模块 `target_create` 前置校验：`valid()`、宽高非零、两格式非 `UNDEFINED`；否则记 error 返回 `false`。
4. 本模块确保一次性资源：`transient_resources_ensure`（首次创建命令池 / 栅栏；失败返回 `false`）。
5. 本模块建颜色图像与视图：`memory->image_create(..., COLOR_ATTACHMENT|SAMPLED|TRANSFER_SRC)` → `memory->image_view_create(..., color_format, COLOR_BIT)`。
6. 本模块建深度图像与视图：`memory->image_create(..., DEPTH_STENCIL_ATTACHMENT)` → `memory->image_view_create(..., depth_format, DEPTH_BIT)`。
7. 本模块执行初始布局转换：`target_transition(color_image, depth_image)`（颜色 → `SHADER_READ_ONLY`、深度 → `DEPTH_ATTACHMENT`，一次提交 + 栅栏等待）。
8. 本模块标记 `record.valid = true`，复用空槽 / 追加并写出句柄，记 info，返回 `true`。
9. 门面把句柄透传给调用方（层外）。

### 7.3 销毁目标链路（门面 `render_target_destroy`）

1. 门面 `render_target_destroy`：若 `active_target == handle` 先把 `active_target` 置 0（回落交换链路径），再转交本模块 `target_destroy(handle)`。
2. 本模块 `target_destroy`：句柄无效或目标已空直接返回；命中则 `record_resources_destroy`（深度视图 → 深度图像 → 颜色视图 → 颜色图像），记录整条复位为空槽，记 info。

**补充（本轮新增）**：门面 `render_target_destroy` 现已改走**摘出路径**——先回落 `active_target` / `present_target`（若等于该句柄），再调 `target_detach(handle, record)` 摘出记录而**不**归还图像 / 视图；随后把颜色与深度（图像 ＋ 内存 ＋ 视图）**各**组装一条 `Deferred_Entry::memory_resources` 压入帧模块延迟销毁队列，由帧模块在「在途帧数 + 1」帧后经内存模块归还。`target_destroy` 仍保留，但门面运行期不再直接调用它。

### 7.4 帧模块消费链路（跨模块，理解本模块接口价值所必需）

1. 门面在 `frame_render` 分派离屏路径时，以 `active_target` 调 `target_get(handle, color_image, color_view, depth_view, extent)` 取出四出参。
2. 门面组装帧模块的 `Frame_Render_Target{ color_image, color_view, depth_view, extent }`，交 `frame.render_to_target(target, items, count, clear_color, ui_callback, readback)`。
3. 帧模块 `command_record_target` 按 §6.6 完成「进入附件布局 → 动态渲染（颜色 + 深度附件）→ 逐项绘制 → 结束渲染 → 回读到布局」。**此过程本模块不再参与**（仅提供图像 / 视图 / 范围）。
4. 若需把关「离线结果当纹理」，门面 `texture_bind_target(handle)` 会再取一次目标颜色视图（`target_get`）与纹理模块共享采样器写入各帧槽 `set 1`。

### 7.5 关闭链路（门面 `Renderer::shutdown`）

严格逆序，与渲染目标相关的一段为：

1. `frame.destroy()`（保证在途帧结束）。
2. `mesh.destroy()`。
3. `texture.destroy()`。
4. **`render_target.destroy()`**（门面在 `texture.destroy()` 之后调用）：
   - 逐条归还渲染目标（`record_resources_destroy` + 记录复位），`records.clear()`。
   - 归还一次性资源：`vkDestroyFence(transient_fence)` → `vkDestroyCommandPool(transient_pool)`。
   - 复位 `memory` / `graphics_queue` / `device` / `graphics_family`；门面同时把 `active_target` 置 0。
5. 归还场景 UBO 与实例缓冲（内存模块） → `pipeline.destroy()` → 着色器模块销毁 → `swapchain.destroy()` → `memory.destroy()` → `device.destroy()` → `platform.destroy()`。

> 顺序要点：**渲染目标销毁须先于内存模块销毁**（门面注释「渲染目标依赖设备与内存，须先于两者销毁」）；`frame.destroy()` 必须最先（保证目标不再被在途帧引用）。析构兜底：`Render_Target_Context` 析构再调一次 `destroy`，此刻已复位，为无操作。

### 7.6 关键异常与边界分支

| 分支 | 触发条件 | 本模块行为 | 门面后续 |
| --- | --- | --- | --- |
| `build` 前置不完整 | 设备 / 队列为空或内存模块未就绪 | 记 error，返回 `false`（不创建资源） | `shutdown` |
| `target_create` 参数非法 | 未构建 / 宽高为 0 / 格式 `UNDEFINED` | 记 error，返回 `false`、句柄保持 0 | 门面记 error 返回 `false` |
| 一次性资源建立失败 | `vkCreateCommandPool` / `vkCreateFence` 非成功 | 半初始化回退 + `false` | 门面返回 `false` |
| 颜色图像创建失败 | `image_create` 非成功 | 直接 `false`（图像 API 已复空句柄） | 门面返回 `false` |
| 颜色视图创建失败 | `image_view_create` 非成功 | `record_resources_destroy` + `false` | 门面返回 `false` |
| 深度图像创建失败 | `image_create` 非成功 | `record_resources_destroy` + `false` | 门面返回 `false` |
| 深度视图创建失败 | `image_view_create` 非成功 | `record_resources_destroy` + `false` | 门面返回 `false` |
| 初始布局转换失败 | 重置 / 分配 / 提交 / 等待任一非成功 | `record_resources_destroy` + `false` | 门面返回 `false` |
| `target_destroy` 句柄无效 / 已空 | `handle == 0`、越界或 `!valid` | 直接返回（幂等） | 无 |
| `target_get` / `target_valid` 句柄无效 | 越界或空槽 | 出参复位后返回 `false` | 门面回落交换链路径（`render_target_set` / `texture_bind_target`） |

### 7.7 调用方与被调方一览（链路总表）

| 阶段 | 调用方 | 本模块入口 | 被调方 |
| --- | --- | --- | --- |
| 建上下文 | 门面 `init` ⑯ | `build` | —— |
| 创建目标 | 门面 `render_target_create` | `target_create` | `transient_resources_ensure` / 内存模块 `image_create` / `image_view_create` / `target_transition` / Vulkan |
| 取目标附件 | 门面 `frame_render` / `texture_bind_target` | `target_get` | —— |
| 判断句柄 | 门面 `render_target_set` | `target_valid` | —— |
| 销毁目标 | 门面 `render_target_destroy` | `target_destroy` | `record_resources_destroy` / 内存模块 |
| 释放 | 门面 `shutdown` | `destroy` | `record_resources_destroy` / Vulkan `vkDestroy*` |

### 待确认条目

本模块为**本版次新增**，源码注释与实现一致，正文不保留任何「待确认」标记。以下为需上层留意的两处**设计取舍**（非缺陷，已确证，不占用 `R-*` 编号）：

- **无关目标销毁不等待在途帧**：`target_destroy` / `destroy` 不做 `vkDeviceWaitIdle`，依赖门面在 `shutdown` 中的逆序编排（`frame.destroy()` 先行）保证无在途使用；若上层在帧中途销毁目标，须自行同步。
- **离屏路径不呈现**：离屏渲染本帧不呈现到窗口，需经 `texture_bind_target` 后的正常绘制采样显示（后处理闭环）——此为设计取舍，见 §6.6。

如需将上述取舍登记为正式待确认项，请续用 `R-TARGET-xx` 编号（当前无 `R-TARGET-xx` 条目）。
