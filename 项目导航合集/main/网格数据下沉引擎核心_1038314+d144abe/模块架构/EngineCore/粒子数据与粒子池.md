# 粒子数据与粒子池（EngineCore；2026-11-03）

> 版次：EngineCore `294f549` / Renderer `28d045b` / Test `1e3c38e`
> 定位：从渲染层下沉出来的「粒子模拟语义」——图形 API-free 的数据布局、校验函数与 CPU 粒子池。
> 渲染层与系统层/应用层共用本模块的**类型**；模拟状态由应用层持有并由渲染层绑定绘制。

## 一、模块介绍

- 源码：`Engine/EngineCore/src/core/effect/`
  - `粒子数据.h`：`Particle_State`（32 字节）／`Emit_Shape`／`Force_Type`／`Particle_Force_Field`（40 字节）／`Particle_Emitter`／`Particle_Params`／容量与步长常量（`PARTICLE_STRIDE=32`、`PARTICLE_FORCE_STRIDE=40`、`PARTICLE_FORCE_MAX=8`、`PARTICLE_CAPACITY_DEFAULT=8192`、`PARTICLE_CAPACITY_MAX=1048576`、`PARTICLE_EMIT_COUNT_MAX=65536`）。
  - `core/粒子数据.cpp`：`particle_emitter_valid`／`particle_params_valid`（与旧渲染层实现逐字段同口径）。
  - `粒子系统.h`／`core/粒子系统.cpp`：`Particle_System`（容量、LIFO 回收栈、`spawn/recycle/clear`、CPU 参考 `step`（重力 → 力场 → 阻尼 → 积分 → 地面/球体碰撞 → 年龄 → 寿命回收）、`emit`（点/盒/球壳 ＋ LCG 确定性）。
- 迁移来源：`Application/Renderer/src/render/Particle/`（整目录删除），逻辑逐行移植，含力场（风场/引力点/涡流）与碰撞（地面钳位反弹摩擦、碰撞球推出回弹）分支。
- 层级位置：EngineCore 为最底层，供 EngineSystem / Renderer / Application 共用；渲染层不再包含任何模拟语义。

## 二、公开接口

| 接口 | 说明 |
| --- | --- |
| `Particle_System::capacity_set(capacity)` | 钳制 [1, 1048576]，重建状态/活跃数组与空闲栈（活跃清零） |
| `active_count_get()` | 池内活跃计数（CPU 路径口径） |
| `spawn(index_out)` / `recycle(index)` | LIFO 分配 / 回收（重复回收与越界返回假） |
| `step(params, dt)` | 固定步推进，返回死亡数 |
| `emit(emitter, budget)` | 按发射器与预算发射，返回实际发射数 |
| `data_get()` / `alive_get()` | 状态数组 / 活跃标记（各含 const 与可变重载；GPU 推进回读需可变） |
| `seed_set(seed)` | 确定性对照种子 |
| `particle_emitter_valid` / `particle_params_valid` | 参数校验（渲染层配置入口与系统层模拟共同使用） |

## 三、内部实现

- `particles_` 与 `alive_` 长度恒等于 `capacity_`；`free_indices_` 升序压栈、尾部弹出，回收即复用同一索引。
- `step` 的运算顺序与 GPU 推进着色器保持一致，便于逐粒子 1e-5 阈值对照。
- `emit` 用线性同余（`1664525 / 1013904223`）生成 `[0,1)` 与 `[-1,1]` 随机量；方向 = `normalize(direction + 0.3·随机)`。
- 默认构造函数不分配数组（空池），调用方须先 `capacity_set`；应用层 `Particle_Host` 构造时按渲染器缓冲容量初始化。

## 四、设计要点

- 数据类型在 EngineCore 而池也在 EngineCore：渲染层需要同一布局做 GPU 上传，但**不需要**模拟实现；两侧引用同一份头，避免重复定义（ODR）与跨层依赖倒置。
- 生命周期（死亡回收）在 CPU 路径由 `Particle_System::step` 完成；GPU 同步推进回读后由渲染层置活跃标记、由应用层负责空闲栈记账（`particle_source_bind` 的可变 `alive` 指针）。
- 统计（出生/死亡/耗时）不再由渲染层计算：应用层通过 `particle_stats_add` 上报名义计数，GPU 路径自身累加。

## 五、运行链路

```text
应用层（Test/Game）
  Particle_System 池 ── emit/step ──▶ 状态数组 + 活跃标记
        │
        ├─ particle_source_bind(states, alive, capacity) ─▶ 渲染层
        │         └─ particle_draw / particle_gpu_step / particle_gpu_draw ...
        └─ particle_stats_add(born, died) ─▶ 帧统计
```
