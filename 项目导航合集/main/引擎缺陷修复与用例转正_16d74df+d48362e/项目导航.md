## 二、项目与层级结构

### 2.1 四层关系

```
白银纪元/（顶层仓库，只统辖目录，不跟踪下层内容）
├── 测试层/   独立仓库（分支 test  → 远端 sliverera/test）    ← 本版次用例战场
├── 系统层/   独立仓库（分支 main  → 远端 sliverera/system）
├── 引擎层/   独立仓库（分支 main  → 远端 sliverera/engine）   ← 本版次修复战场
└── 游戏层/   独立仓库（分支 main  → 远端 sliverera/game）
```

- 四层各自是**独立 git 仓库**，顶层仓库不跟踪它们的内容；因此下层有提交时顶层仓库不会有新提交。
- 远端统一为 `https://github.com/yuxingyuzhong/SilverEra.git`。
- ⚠️ 引擎层本地分支名叫 `main`，上游分支名叫 `engine`，**名字不一致**，`git push` 会被 `push.default=simple` 拦下，必须写成显式 refspec：`git push sliverera HEAD:engine`。

### 2.2 层间消费方式

- 引擎层不依赖任何上层，只被上层通过「源码 include + 链接静态库」消费。
- 测试层构建时**链接已构建的引擎层产物**（`引擎层/out/build/x64-Debug/lib/EngineCore.lib`），不重编引擎源码——因此改引擎后必须先编引擎层，再编测试层。

### 2.3 构建口径与常见坑

```bash
# 引擎层 / 测试层均在同一套工具链下
call D:\ViusalStudioCommunity2026\VC\Auxiliary\Build\vcvars64.bat
D:\ViusalStudioCommunity2026\...\CMake\Ninja\ninja.exe -t clean   # 建议：头文件不在 build.ninja 依赖里，增量不可信
D:\ViusalStudioCommunity2026\...\CMake\Ninja\ninja.exe
```

- PATH 里没有 cmake / ninja，必须写全路径。
- **不先 `call vcvars64.bat` 就直接编**会报 `fatal error C1083: 无法打开包括文件 "stdio.h"`。
- 用 cmd 时，命令行若以引号开头，cmd 会剥掉行尾引号并报「文件名、目录名或卷标语法不正确」——可执行文件路径尽量不加引号。
- 测试层用例源由 `file(GLOB_RECURSE ... CONFIGURE_DEPENDS "${PROJECT_ROOT}/src/单元测试/*.cpp")` 收集，**新增用例文件不需要改 CMakeLists**，`ninja` 会自动重跑 CMake 纳入新文件。

## 五、遗留缺陷（尚在案）

**超大边长上限下的整数除零**——真实崩点在 `Quadtree_Manager/core/区块信息检索.hpp` 的 `excel_element_to_coord`：

```cpp
int width = (excel_range.right - excel_range.left + 1) / settings.block_size;
int row = element_ID / width;   // width 为 0 时抛 SEH 0xC0000094
int col = element_ID % width;
```

当格式化后的查询范围宽度不足一个 `block_size` 时 `width` 为 0，除法即抛 `SEH 0xC0000094`（整数除以零）。根因涉及 **`int` 型坐标表示无法承载 `INT_MAX` 以上的树尺寸**：`Rect2i` 各分量为 `int`，`manage_range_calcu` 按 `tree_size` 计算范围时会溢出，导致查询范围退化。触发条件是把边长上限配置到 `INT_MAX` 以上（如 `1ull << 33`）后建树——属非常规配置。

本版次提交 `16d74df` 为 `Quadtree/core/区块信息检索.hpp` 的 `block_seek` 补了 `state.size <= 0` 短路（修掉该函数自身的潜在除零点），但**不足以**让这条用例通过；彻底解决需架构层调整。

对应测试 `Quadtree_Manager_Test.DISABLED_超大边长上限下区块检索次数正常` 保持禁用，注释已写明上述崩点与根因；修复后去掉 `DISABLED_` 前缀即可转正。**这是当前 `测试层/src` 下唯一一条禁用用例。**

另有一处既有告警未处理：`Quadtree/core/区块信息检索.hpp(72)` 的 `warning C4715`（`point_seekable_analyse` 并非所有控件路径都返回值）。
