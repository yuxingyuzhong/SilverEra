## 一、模块功能（该模块做什么，解决什么问题，服务谁）

### 1.1 模块定位

四叉树管理器（Quadtree_Manager）是「白银纪元」游戏引擎引擎层**空间分区体系**的"调度中枢"。它位于 `引擎层\src\core\spatial\partition\Quadtree_Manager\` 目录，负责管理"若干棵四叉树"的**生命周期、查询路由、智能创建、扩大裁决、相邻关系判定、树合并与卸载**。

如果说 `Quadtree`（四叉树）是"单个方形区域的格子容器"，那么 `Quadtree_Manager` 就是"整个世界的树群调度器"：

```
业务层（碰撞模块 Collision_Proxy 等）
   │ 只与管理器打交道（不直接持有 Quadtree 对象）
   ▼
┌──────────────────────────────────────────────┐
│            Quadtree_Manager（本模块）           │
│  · 维护 X_sequence 树群（按根 X 降序）           │
│  · 高速缓存 tree_cache（LRU 前进位）             │
│  · 智能创建 / 扩大裁决 / 相邻查找 / 四树合并       │
└──────────────────────────────────────────────┘
   │ 持有 N 棵                     ▲ 回调（扩大权限申请）
   ▼                                │
┌──────────────────────────────────┴───────────┐
│  Quadtree<T> × N（每棵树管理一个方形区域）         │
└────────────────────────────────────────────────┘
   │ 依赖
   ▼
坐标类型（Point2i/l/d, Rect2i/l/d）· 二分查找 · 四叉树的数据结构
```

### 1.2 解决的核心问题

1. **大世界多树组织**：世界范围远超单棵四叉树的可配置上限（默认 `max_tree_size=65536`）时，把世界切分为多个方形区域，每个区域由一棵 `Quadtree` 管理。管理器持有树群 `X_sequence` 并保证按根节点 X 轴坐标降序排列，支持高效的归属树查找。
2. **查询路由**：业务层只调用管理器的 `seek`（单点/范围），管理器负责"这个坐标/范围属于哪棵树"的定位（`quadtree_inclusion_seek`），再把查询转发给具体树的 `block_seek`/`range_seek`。单点查询在树缺失时自动智能建树（`seek` 循环 + `qurdtree_build_smart`）。
3. **智能建树**：给定一组坐标点集（`qurdtree_build_smart`），管理器先求包围矩形、按最大树尺寸划分为"最大区块"，再对每个非空区块递归细分（`divide_single_father_block`），"中心聚集"的稠密点簇用更小的树承载、分散的点簇用大树承载，从而以最少棵树覆盖点集且保证点尽量远离区块边界。
4. **扩大裁决与去重叠**：多棵树并存时，若每棵都无限扩大将互相重叠。管理器通过 `tree_expand_approve` 回调统一裁决"扩大 or 新建树"：扩大前先做矩形筛选 + 相邻树查找 + 重叠筛选（`next_tree_seek` 链），只有不与任何现存树重叠才允许扩大；否则新建一棵 `min_tree_size` 的树覆盖目标。
5. **相邻关系判定**：`next_tree_seek`（矩形筛选 → 分类筛选 → 验证确认）是扩大裁决与合并收集的共同基础，回答"谁是我旁边的树"。
6. **四树合并**：`qurdtree_merge` 把"等大的四棵相邻树"合并为一棵边长翻倍的新树（收集候选 → 精确筛选 → 建新树 → 数据迁移 → 卸载旧树），防止树群碎片化。
7. **高速缓存**：`tree_cache`（records + ranges）缓存最近命中的树及其范围，命中时 LRU 前进位，减少重复的边界计算与线性扫描。
8. **数据迁移**：`callback_register` 注册数据拷贝回调，合并时用它在旧树区块与新树区块之间搬运 `T` 数据。

### 1.3 服务谁

- **直接服务对象**：业务层（碰撞模块等）。业务层通过管理器的 `seek`（单点/范围）完成"坐标 → 区块数据"与"矩形 → 区块数据集合"的查询；通过 `qurdtree_build_smart` 在给定点集上初始化世界树群；通过 `qurdtree_merge` 定期整理树群。
- **被服务对象**：`Quadtree` 本身。管理器通过 `set_callback_manage` 注入的 lambda 充当四叉树的"上级"，四叉树扩大前必须得到管理器的 `tree_expand_approve` 批准。
- **底层依赖**：四叉树模块（`Quadtree` 及其 `tree_state`/`tree_chunk_data`）、坐标类型（`坐标类型.h`）、二分查找工具（`引擎层/src/tools/Auxi_Algorithm/二分查找.h`）、预编译头。

### 1.4 本版次（089b070）要点总览

1. **X_sequence 按根节点 X 坐标降序**：所有树的 `tree_record*` 存入 `std::vector`，每次建树后 `std::ranges::sort`（`std::ranges::greater` 投影到 `root.X`）保证降序，从而支持 `quadtree_index_seek` 用 `range_binary_search` 快速定位同 X 区间。
2. **tree_cache 高速缓存（records + ranges，LRU 前进位）**：缓存条目为"树指针 + 树范围（Rect2l）"两数组并行；命中非首条时与前一跳 swap（前进位），实现简易 LRU；插入时若达上限 `max_cache_records` 则 `pop_back` 淘汰最旧条目。
3. **qurdtree_build_smart 四步流程**：① 包围矩形与最大区块参数计算（`prepare_smart_create_params`）→ ② 统计各最大区块内坐标数 → ③ 对非空区块递归细分（`divide_single_father_block`）→ ④ 统一 `quadtree_build` 建树。树群已存在时改走"逐点检查 → `tree_expand_approve` 自适应补建"。
4. **tree_expand_approve 的自适应建树/扩大决策**：回调里先查目标是否已被其他树覆盖、再判当前树是否可扩（上限、矩形筛选无其他树根、相邻树无重叠），可扩则扩、不可扩则 `new_tree_range_calcu` 计算新范围并 `quadtree_build` 新树。
5. **qurdtree_merge 四树合并**：收集（`quedtree_merge_collect` 按扩大级数分组 + 相邻树组合）→ 精确筛选（`quedtree_merge_filter` 穷举平均根坐标匹配 + 指针去重）→ 建新树（四根平均为新根、边长翻倍）→ 复制数据（旧树非稳定范围查询 → 新树稳定单点查询 + copy 回调）→ 卸载旧树（`quadtree_unload`）。
6. **prepare_smart_create_params 的 int64 化（前版次修复的 2^33 截断除零主崩点）**：`father_block_size` 此前按 32 位整数接收，超过 INT_MAX 的上限被截断为零，随后的取模与除法抛整数除零异常；本版次按 64 位整数接收并增加非正防御，主崩点已修复。
7. **range_seek 的 total_num 乘法溢出防御**：`want_col * want_row` 前先判 `want_row > INT64_MAX / want_col`，防溢出后再分配布尔表。
8. **excel_element_to_coord 零尺寸防御**：`block_size == 0` 或表宽 `width <= 0` 时返回原点 `Point2l{}`，避免除零。

### 2.2 构造与析构

```cpp
Quadtree_Manager();
~Quadtree_Manager();
```

- **构造**：空实现（类内成员自带默认值：`largest_tree_size=0`、`X_sequence` 空、`tree_cache` 空、`settings` 默认、`copy` 空）。**注意**：构造后树群为空，首次查询若为 stable 模式会自动建树。

### 2.3 设置类接口

```cpp
void callback_register(const std::function<void(tree_chunk_data<T>& receiver, tree_chunk_data<T>& transmiter)>& cb_1);
void set_block_size(const uint64_t& block_size);
void set_max_size(const uint64_t& max_size);
void set_min_size(const uint64_t& min_size);
void set_cache_state(bool enabled);
void set_cache_active_threshold(const uint64_t& threshold);
void set_max_cach_records(const uint64_t max_entries);
```

- `callback_register(...)`：**参数** `cb_1` 为数据迁移回调，签名 `void(tree_chunk_data<T>& receiver, tree_chunk_data<T>& transmiter)`——把 `transmiter` 的载荷数据复制到 `receiver`。**行为**：存入成员 `copy`。**注意**：`qurdtree_merge` 开头 `if (copy)` 判断——**未注册数据迁移回调则合并不会执行**。
- `set_block_size(const uint64_t& block_size)`：**行为**：写入 `settings.block_size`，并遍历 `X_sequence` 把每个 `tree->set_block_size` 下发给全部树（同步生效）。
- `set_max_size(const uint64_t& max_size)`：**行为**：写入 `settings.max_tree_size`，并遍历 `X_sequence` 把 `tree->set_max_size` 下发给全部树。
- `set_min_size(const uint64_t& min_size)`：**行为**：仅写入 `settings.min_tree_size`（不涉及现存树；它是"新建树的默认边长"，被 `tree_expand_approve` 的建树分支与 `new_tree_range_calcu` 使用）。
- `set_cache_state(bool enabled)`：写入 `settings.is_cache_enabled`。
- `set_cache_active_threshold(const uint64_t& threshold)`：写入 `settings.cache_active_threshold`（当树数量 ≥ 阈值时缓存才启用写入）。
- `set_max_cach_records(const uint64_t max_entries)`：写入 `settings.max_cache_records`（缓存条目上限，0 表示不写缓存）。

### 2.4 创建类接口

```cpp
void qurdtree_build_smart(const std::vector<Point2i>& coord_set);
```

- **coord_set**：参考坐标点集（int32 坐标）。**行为**：若树群为空走"四步智能建树"（详见 §4.2.5）；若树群已存在，则逐点检查是否被现有树覆盖，未覆盖则调用 `tree_expand_approve(tree_group.back()->root, exam_coord, true)`（internal=true）自适应扩大/建树。**注意**：该函数只创建树（分配树内存与记录），**不写入任何区块数据**；点集内的坐标仅在"划分树的位置与大小"上起作用。

### 2.5 查询类接口

```cpp
void seek(tree_chunk_data<T>*& reciver, const Point2i& target, bool stable);
void seek(std::vector<tree_chunk_data<T>*>& receiver, const Rect2i& target_range, bool stable);
```

- **单点重载** `seek(tree_chunk_data<T>*& reciver, const Point2i& target, bool stable)`：
  - **reciver**：输出参数，成功后被指向目标区块的 `tree_chunk_data<T>`。
  - **target**：目标坐标（int32，内部提升为 `Point2l`）。
  - **stable**：稳定模式。
  - **行为**：`for(;;)` 循环内——`quadtree_inclusion_seek` 找直属树 → 命中则 `tree->block_seek` → 若 `reciver != nullptr || stable == false` 退出；否则（stable 且未命中）`qurdtree_build_smart({target})` 建树后重试。即 **stable 单点查询保证"必有区块可查"（坐标需可表达为 int32 内）**。
- **范围重载** `seek(std::vector<tree_chunk_data<T>*>& receiver, const Rect2i& target_range, bool stable)`：
  - **receiver**：输出参数，收集命中区块指针。
  - **target_range**：目标矩形（int32）。
  - **stable**：稳定模式。
  - **行为**：详见 §4.2.8（excel 去重表驱动的"逐区块查询 + 树范围裁剪 + 标记已查"流程）。**注意**：`target_range` 的 left/down 会被提升为 `Rect2l` 参与格式化，因此支持超出 int32 的几何（但智能建树坐标需落回 int32，超出部分跳过）。

### 2.6 读取类接口

```cpp
const tree_manager_settings& settings_get(void);
const std::vector<tree_record<T>*>& records_get(void);
const uint64_t& largest_size_get(void);
```

- `settings_get(void)`：返回 `settings` 常引用（block_size / max_tree_size / min_tree_size / is_cache_enabled / cache_active_threshold / max_cache_records）。
- `records_get(void)`：返回 `X_sequence` 常引用（树群档案，按根 X 降序）。调用方可通过 `tree_record::root/size` 遍历世界树分布。
- `largest_size_get(void)`：返回 `largest_tree_size` 常引用（当前最大树的边长，用于 `next_tree_seek` 的矩形筛选半径）。

### 2.7 维护类接口

```cpp
void qurdtree_merge(void);
void cache_clear(void);
void clear(void);
void quadtree_unload(const std::vector<Point2d>& root_set);
```

- `qurdtree_merge(void)`：四树合并总函数（详见 §4.2.6）。仅当 `copy` 已注册时执行；执行期间临时禁用缓存（结束后恢复），流程为 collect → filter → 逐组合建新树/迁移数据/卸载旧树。
- `cache_clear(void)`：`tree_cache.records.clear(); tree_cache.ranges.clear();`。
- `clear(void)`：把 `X_sequence` 的全部索引（逆序）收集进 `index_set`，调用 `quadtree_unload(index_set)` 批量卸载。
- `quadtree_unload(const std::vector<Point2d>& root_set)`：按根坐标卸载指定树（每棵通过 `quadtree_index_seek` 求索引后走单树卸载流程：移出缓存 → delete tree → delete record → erase 序列）。

### 3.1 内部数据结构

#### 3.1.1 四叉树记录结构体 `tree_record<T>`（定义于 `函数预声明.h`）

```cpp
template<typename T>
struct tree_record
{
private:
    Quadtree<T>* tree = nullptr;   // 四叉树指针（私有，仅管理器可访问）
public:
    friend Quadtree_Manager<T>;    // 管理器友元：可读写 tree 成员
    Point2d root{ 0.5,0.5 };       // 根节点坐标（double）
    uint64_t size = 256;           // 四叉树大小（当前边长记录）
};
```

`tree_record` 是管理器的"树档案卡"：公开暴露 `root/size`（供相邻判定、合并计算、外部读取），私有持有 `tree` 指针（仅管理器通过友元访问）。`size` 与 `tree->state.size` 保持同步（建树时写入；扩大时管理器手动维护；卸载时删除）。

#### 3.1.2 管理器设置结构体 `tree_manager_settings`（定义于 `函数预声明.h`）

```cpp
struct tree_manager_settings
{
    uint64_t block_size = 16;             // 最小区块单元大小
    uint64_t max_tree_size = 65536;       // 四叉树大小上限
    uint64_t min_tree_size = 256;         // 四叉树大小下限（新建树默认边长）
    bool is_cache_enabled = true;         // 缓存启用状态
    uint64_t cache_active_threshold = 32; // 缓存启用阈值（树数量 ≥ 此值才写缓存）
    uint64_t max_cache_records = 16;      // 缓存条目上限
};
```

默认值语义：世界单树最大 65536；新建树最小 256；树数 ≥32 时启用缓存写入；缓存最多保留 16 条。

#### 3.1.3 数据成员（定义于 `四叉树管理器.h`）

```cpp
uint64_t largest_tree_size = 0;                       // 当前最大四叉树大小（全树群最大值）
std::vector<tree_record<T>*> X_sequence{};            // 四叉树序列（按根节点 X 轴坐标降序）
struct
{
    std::vector<tree_record<T>*> records{};           // 缓存记录（树指针）
    std::vector<Rect2l> ranges{};                     // 缓存范围（64 位矩形，与 records 并行）

tree_manager_settings settings;                        // 管理器设置
std::function<void(tree_chunk_data<T>& receiver, tree_chunk_data<T>& transmiter)> copy;  // 数据迁移方法
```

- **X_sequence**：树群主存储，`std::vector<tree_record<T>*>`。**排序不变量：按 `root.X` 降序**（`quadtree_build` 末尾 `std::ranges::sort(...greater...)` 维护）。该不变量支撑 `quadtree_index_seek` 的二分定位。
- **tree_cache**：匿名结构体成员，`records` 与 `ranges` 两数组**下标并行**（`records[i]` 的范围在 `ranges[i]`）。命中时做 LRU 前进位（与前一跳 swap），满额时淘汰尾部。
- **largest_tree_size**：全树群最大边长缓存，供 `next_tree_seek` 计算矩形筛选半径（`(tree->size + largest_tree_size)/2`）。
- **copy**：数据迁移回调，`qurdtree_merge` 的前置条件。

### 3.3 设计分层

管理器内部按职责分五层：

5. **底层依赖**：四叉树模块、坐标类型、二分查找。

数据流方向：**业务层查询 → 查询编排层 →（树群基础层定位树）→ 四叉树 block_seek/range_seek → 结果回传**；**四叉树扩大请求 → 扩大裁决层 → 相邻判定链 → 批准/新建树**。

## 四、模块设计/实现细节

### 4.1 64 位尺寸层契约（承前序版次 fa8459a）

与前序版次 fa8459a 的 64 位化一脉相承，管理器的所有几何推导同样以 64 位为基准：

1. **缓存范围用 `Rect2l`**：`tree_cache.ranges` 为 `std::vector<Rect2l>`，注释明确"范围边界由树边长推导，用 64 位整数承载"。
2. **回调目标坐标用 `Point2l`**：`tree_expand_approve(root, seek, internal)` 的 `seek` 为 int64 点；`quadtree_build` 注册回调时注释"申请坐标按 64 位整数传递，与四叉树内部坐标系一致"。
3. **相邻判定中的 64 位化**：`next_tree_seek` 的矩形筛选范围 `tree_range.left = static_cast<int64_t>(tree->root.X - (tree->size + largest_tree_size) / 2)`；`new_tree_range_calcu` 的偏移 `int64_t offset_x = static_cast<int64_t>(min_tree_size / 2)`——树边长已达 64 位量级，半径计算必须按 64 位有符号承接。
4. **智能创建参数 int64 化（主崩点修复）**：`prepare_smart_create_params` 的 `father_block_size` 用 `int64_t` 接收（源码注释原文：*"边长上限已达 64 位，故此处按 64 位整数接收。此前按 32 位整数接收时，超过 INT_MAX 的上限会被截断为零，随后的取模与除法即抛整数除零异常"*）——这是 fa8459a 修复的 **2^33 截断除零主崩点**：当 `max_tree_size` 超过 `2^31`（如 2^33）时，32 位 `int` 接收会截断为 0，后续 `width % father_block_size` 抛除零。本版次保留 int64 化并增加 `father_block_size <= 0` 非正防御。
5. **范围查询的 64 位计算**：`seek(范围)` 中 `want_col/want_row` 用 `int64_t` 计算、`excel_element_to_coord` 的行列推导用 `int64_t`、`target_range_amend` 的行列裁剪用 `int64_t`。
6. **取整语义**：`quadtree_index_seek`/`next_tree_classify`/`next_tree_seek` 中把 double 根坐标差值 `static_cast<int64_t>(std::abs(...))` 向下取整后再与 64 位边长比较（注释"根节点坐标为双精度，差值向下取整后放入 64 位整数"）。

### 4.2 关键算法流程

#### 4.2.1 归属树查找 `quadtree_inclusion_seek`（缓存优先 + LRU 前进位）

```cpp
tree_record<T>* Quadtree_Manager<T>::quadtree_inclusion_seek(const Point2l& target)
{
    // ① 缓存优先
    if (is_cache_enabled && records.size() > 0)
    {
        for (int seek_time = 0; seek_time < records.size(); seek_time++)
        {
            tree_range = ranges[seek_time];
            if (target.X >= tree_range.left && target.X <= tree_range.right &&
                target.Y >= tree_range.down && target.Y <= tree_range.up)
            {
                if (seek_time > 0)                    // LRU 前进位：与前一跳交换
                {
                    std::swap(now_tree, last_tree);
                    std::swap(ranges[seek_time], ranges[seek_time - 1]);
                    seek_time--;                      // 递减索引保证返回正确条目
                }
                return records[seek_time];
            }
        }
    }
    // ② 序列扫描（X_sequence 线性遍历 + manage_range_calcu 算边界）
    for (int seek_time = 0; seek_time < tree_group.size(); seek_time++)
    {
        ptr_tree->tree->manage_range_calcu(tree_range, ptr_tree->root, ptr_tree->size);
        if (目标在范围内)
        {
            // ③ 缓存写入条件：缓存启用 && 树数 >= cache_active_threshold && max_cache_records > 0
            if (is_cache_enabled && tree_group.size() >= cache_active_threshold)
            {
                if (max_cache_records > 0)
                {
                    if (records.size() >= max_cache_records) { records.pop_back(); ranges.pop_back(); }  // 淘汰最旧
                    records.push_back(tree_group[seek_time]);
                    ranges.push_back(tree_range);
                }
            }
            return tree_group[seek_time];
        }
    }
    return nullptr;    // 未找到（该坐标无树覆盖）
}
```

**要点**：缓存命中返回条目，且把命中条目向表头前移一位（swap）——多次访问的树逐渐靠前，实现简易 LRU；缓存满时 `pop_back` 淘汰尾部（最久未前进位的条目）。范围判断用闭区间 `>=/<=`。

#### 4.2.2 索引查找 `quadtree_index_seek`（二分）

```cpp
int64_t Quadtree_Manager<T>::quadtree_index_seek(const Point2d& root)
{
    // 在 X_sequence 上按 root.X 二分查找"等 X 区间"
    std::pair<int, int> range = range_binary_search(tree_group.begin(), tree_group.end(),
        root.X, std::ranges::greater(), [](auto* p) { return p->root.X; });
    if (range.first < 0 && range.second < 0)
        return -1;                                  // 无等 X 区间
    for (int begin = range.first, end = range.second; begin <= end; begin++)
        if (root == tree_group[begin]->root)        // 区间内线性比对完整坐标
            return begin;
    return -1;
}
```

**要点**：依赖 `X_sequence` 降序不变量；`range_binary_search`（二分查找.h 提供）返回等 X 的闭区间下标，再在区间内用 `Point2d` 的 `==`（ULP ≤4 容差比较）精确匹配 `root`。`Point2::operator==` 的浮点容差使"由 double 运算得到的根坐标"仍能精确命中。

#### 4.2.3 建树 `quadtree_build`（含回调注入与排序）

```cpp
void Quadtree_Manager<T>::quadtree_build(Point2d root, uint64_t tree_size)
{
    tree_record<T>* new_tree = new(std::nothrow) tree_record<T>;
    if (new_tree == nullptr) { delete new_tree; return; }
    new_tree->tree = new(std::nothrow) Quadtree<T>(tree_size, root);
    if (new_tree->tree == nullptr) { delete new_tree->tree; return; }

    new_tree->size = tree_size;
    new_tree->root = root;
    new_tree->tree->set_max_size(settings.max_tree_size);
    new_tree->tree->set_block_size(settings.block_size);
    // 回调注入：四叉树扩大请求转发给管理器裁决
    auto manage = [this](const Point2d& root, const Point2l& seek)->bool
        { return this->tree_expand_approve(root, seek); };
    new_tree->tree->set_callback_manage(manage);

    tree_group.push_back(new_tree);
    // 按根节点 X 坐标降序排序（维护 X_sequence 不变量）
    std::ranges::sort(tree_group.begin(), tree_group.end(),
        std::ranges::greater(), [](const tree_record<T>* node) { return node->root.X; });
}
```

**要点**：创建树的同时完成三件事——记录 `size/root` 到档案、把管理器的 `tree_expand_approve` 包装成 lambda 注入四叉树回调、维护 `X_sequence` 降序不变量。**注意**：`size` 与 `tree->state.size` 双轨记录，扩大时必须同步维护（见 `tree_expand_approve`）。

#### 4.2.4 卸载 `quadtree_unload`（两重载）

```cpp
void Quadtree_Manager<T>::quadtree_unload(std::vector<int64_t>& index_set)
{
    std::ranges::sort(index_set.begin(), index_set.end(), std::ranges::greater());  // 降序防索引失效
    for (int unload_time = 0; unload_time < index_set.size(); unload_time++)
    {
        if (index_set[unload_time] < 0) continue;      // 无效索引跳过
        auto& record = tree_group[index_set[unload_time]];
        // 若在缓存中则移出
        for (int seek_time = 0; seek_time < records.size(); seek_time++)
            if (records[seek_time] == record) { records.erase(records.begin() + seek_time); ranges.erase(ranges.begin() + seek_time); break; }
        if (record->tree != nullptr) { delete record->tree; record->tree = nullptr; }  // 析构四叉树（递归释放）
        delete record;                                  // 删除档案
        tree_group.erase(tree_group.begin() + index_set[unload_time]);                 // 移出序列
    }
}

void Quadtree_Manager<T>::quadtree_unload(const std::vector<Point2d>& root_set)
{
    for (int unload_time = 0; unload_time < root_set.size(); unload_time++)
    {
        int64_t index = quadtree_index_seek(root_set[unload_time]);   // 二分定位
        if (index < 0) continue;
        // ……与上面相同的"移缓存 → delete tree → delete record → erase"流程
    }
}
```

**要点**：`index_set` 版先降序排序索引，保证从尾部往前删、前序索引不失效；`root_set` 版逐个二分定位。卸载会同步清理缓存条目（指针匹配）。

#### 4.2.5 智能创建 `qurdtree_build_smart`（四步流程）

```cpp
void Quadtree_Manager<T>::qurdtree_build_smart(const std::vector<Point2i>& coord_set)
{
    if (coord_set.empty()) return;

    if (tree_group.size() == 0)                       // —— 树群为空：四步智能建树 ——
    {
        // ———— 第一步：准备包围矩形和最大区块参数 ————
        prepare_smart_create_params(coord_set, recta_range, max_block_num_total, max_block_size);
        if (max_block_num_total <= 0 || max_block_size <= 0) return;   // 参数非法防御

        // ———— 第二步：遍历点集统计各最大区块内坐标数 ————
        std::vector<int64_t> father_block_coord_count(max_block_num_total, 0);
        int64_t father_block_num_X = (recta_range.right - recta_range.left + 1) / max_block_size;
        for (time : coord_set)
        {
            col_index = (X - recta_range.left) / max_block_size;
            row_index = (recta_range.up - Y) / max_block_size;      // 行号从上往下
            index = row_index * father_block_num_X + col_index;
            father_block_coord_count[index]++;
        }

        // ———— 第三步：对可递归区块进行划分 ————
        for (find_index : [0, max_block_num_total))
        {
            if (father_block_coord_count[find_index] != 0)
            {
                // 闭区间边界：left += col*size; right = left+size-1; up -= row*size; down = up-size+1
                divide_single_father_block(coord_set, left, right, up, down,
                    max_block_size, count, root, tree_size);
            }
        }

        // ———— 第四步：统一创建所有四叉树 ————
        for (create_time : root.size())
            quadtree_build(root[create_time], tree_size[create_time]);
    }
    else                                              // —— 树群已存在：逐点补建 ——
    {
        for (exam_time : coord_set)
        {
            Point2l exam_coord{ coord_set[exam_time].X, coord_set[exam_time].Y };
            if (quadtree_inclusion_seek(exam_coord) == nullptr)   // 未被覆盖
                tree_expand_approve(tree_group.back()->root, exam_coord, true);  // internal=true 自适应
        }
    }
}
```

**第一步 `prepare_smart_create_params`（int64 化）**：
1. 求点集包围矩形（`recta_range`，四个边界取极值）。
2. `father_block_size = static_cast<int64_t>(settings.max_tree_size)`——**int64 接收，杜绝 2^33 截断为零**；`<= 0` 时 `father_block_num_all = 0` 返回。
3. 矩形宽/高向 `father_block_size` 对齐补齐（余数补到上/右边界）。
4. `father_block_num_all = (width/size) * (height/size)`——总最大区块数。

**第三步 `divide_single_father_block`（递归复制子集版）**：
1. `in_block` lambda 收集当前区块内的点（**复制子集**到 `local_points`）。
2. 空区块直接返回（不建树）。
3. `block_size == 256`（最小区块）：直接记录建树参数 `{中心, 256}` 返回。
4. 中心聚集检测：`limit = 0.375 * block_size`，所有点到中心距离 ≤ limit 才算"中心聚集"。
5. 非中心聚集 → 在当前区块建树（记录 `{中心, block_size}`）。
6. 中心聚集 → 四等分（`subs[4]` 闭区间），把点分入四子区；`nonempty==1` 则递归细分该子区块（`block_size/2`），否则在当前区块建树。

**设计动机**（源码注释）："先用一个初始矩形包裹住所有坐标点，然后将矩形分割为若干块最大四叉树所管理的矩形，之后不断子级分割，直至保证子区块尽可能小，且里面的点尽可能多，尽可能远离区块边界"——即**稠密点簇用小树精分、稀疏区域用大树粗盖**，减少树间边界冲突。

**树群已存在的分支**：对每个未被覆盖的点调用 `tree_expand_approve(tree_group.back()->root, coord, true)`。`tree_group.back()` 是根 X 最小的树（降序末尾）；internal=true 使批准扩大时管理器直接执行 `tree->tree_expand()`（否则等四叉树自己扩）。

#### 4.2.6 扩大裁决 `tree_expand_approve`（自适应建树/扩大决策）

```cpp
bool Quadtree_Manager<T>::tree_expand_approve(const Point2d& root, const Point2l& target, bool internal)
{
    // ① 定位发起树
    tree_record<T>* now_tree = callback_tree_seek(root);   // 按根坐标精确匹配
    if (now_tree == nullptr) return false;

    // ② 目标已被其他树覆盖 → 拒绝
    if (quadtree_inclusion_seek(target) != nullptr)
        return false;

    // ③ 当前树未达上限 → 扩大可行性分析
    else if (now_tree->size < settings.max_tree_size)
    {
        // 矩形筛选：以 now_tree 为中心、2×size 为边长，找范围内其他树根
        rectan_range = now_tree->root ± (now_tree->size + now_tree->size) / 2;
        rectangle_filter(ptr_rectan_tree, now_tree, rectan_range);

        if (ptr_rectan_tree.size() == 0)                  // 扩大区域内无其他树根
        {
            now_tree->size *= 2;                          // 临时放大（供相邻判定用）
            next_tree_seek(next_trees, now_tree);         // 找相邻树
            if (next_trees.size() > 0)
            {
                // 严格重叠筛选（coord_1 > coord_2 - 1 形式）
                next_tree_verify(ptr_overlap_tree, now_tree, next_trees, screen_method);
                now_tree->size /= 2;                      // 恢复
                if (ptr_overlap_tree.size() == 0)         // 无重叠 → 扩大可行
                {
                    now_tree->size *= 2;                  // 确认扩大（记录）
                    if (now_tree->size > largest_tree_size) largest_tree_size = now_tree->size;
                    if (internal == true) now_tree->tree->tree_expand();   // 内部调用代为扩大
                    刷新缓存中该树范围;                    // manage_range_calcu 重算
                    return true;
                }
            }
            else                                          // 无相邻树 → 扩大可行（沿用临时 *2）
            {
                if (now_tree->size > largest_tree_size) largest_tree_size = now_tree->size;
                if (internal == true) now_tree->tree->tree_expand();
                刷新缓存中该树范围;
                return true;
            }
        }
    }

    // ———— ④ 扩大不可行 → 构建新树 ————
    new_tree_range_calcu(now_tree, target, new_tree_range);   // 计算覆盖 target 的 min_size 范围
    new_root.X = (new_tree_range.left + new_tree_range.right) / 2.0;
    new_root.Y = (new_tree_range.up + new_tree_range.down) / 2.0;
    quadtree_build(new_root, settings.min_tree_size);         // 新建最小树
    return false;                                             // 返回拒绝（调用方据此终止扩大）
}
```

**自适应决策逻辑**（重要细节）：
- `internal` 参数区分两种调用来源：**回调路径**（internal=false，四叉树自己随后执行 `tree_expand`，管理器只记录 size/largest/缓存）与**内部路径**（internal=true，管理器直接执行 `tree->tree_expand()`）。
- **扩大可行条件**：目标未被覆盖 + 当前树未达上限 + 扩大区域内无其他树根 + 相邻树无重叠。全部满足才返回 true。
- **size 记录的临时放大/恢复**：`now_tree->size *= 2` 是**临时**操作，为的是让 `next_tree_seek` 以"扩大后的边长"计算矩形筛选半径；有相邻树时筛完重叠必须 `/2` 恢复；无重叠再 `*2` 确认；无相邻树分支直接沿用临时 `*2` 结果（等效确认）。**若中途重叠则恢复原值**，保证记录与真实树一致。
- 不可扩时**新建一棵 `min_tree_size` 的树**覆盖目标，返回 false（四叉树收到 false 后不再扩大）。

**`new_tree_range_calcu`（新树范围计算）**：
1. 以 `min_tree_size` 为边长、以 `now_tree->root` 为中心，用 `manage_range_calcu` 求初始范围。
2. 若 `now_tree->size != min_tree_size`（基准树不是最小树），按 target 相对 root 的方位把范围平移 `min_size/2`（靠近目标方向）。
3. 死循环：若左边界在目标右侧 → 整体左移 `min_size`；右边界在目标左侧 → 右移 `min_size`；上边界在目标下侧 → 上移；下边界在目标上侧 → 下移；直到范围包含 target。

#### 4.2.7 相邻树查找链 `next_tree_seek`（矩形 → 分类 → 验证）

```cpp
void Quadtree_Manager<T>::next_tree_seek(std::vector<tree_record<T>*>& receiver,
    const tree_record<T>* tree, const std::vector<tree_record<T>*>* tree_group)
{
    // ① 矩形筛选范围：以 tree 为中心，半径 = (tree->size + largest_tree_size) / 2
    tree_range = tree->root ± (tree->size + largest_tree_size) / 2;
    rectangle_filter(rectan_trees, tree, tree_range, tree_group);   // ② 矩形筛选
    if (rectan_trees.size() == 0) { receiver = rectan_trees; return; }
    candidate_tree_filter(receiver, tree, rectan_trees);            // ③ 分类 + 验证
}
```

- **`rectangle_filter`（矩形筛选）**：先在 `tree_group`（默认 `X_sequence`）中筛出"根 X 在 range 内且 root != tree->root"的树（X 轴筛选，利用降序可提前终止但实现为线性遍历）；再在候选内筛 Y 轴（`root.Y` 在 range 内）。两轴都满足才进 `receiver`。
- **`next_tree_classify`（分类筛选）**：对每个候选计算 `root_diff.X = |tree->root.X - candidate->root.X|`（double 差值向下取整为 int64）；若 `root_diff.X == (tree->size + candidate->size) / 2` 则 `filter_hits++`（**注意源码用 `==` 精确等于**，与注释"小于等于"不完全一致——由于根坐标差值的取整与边长半和的整数性，实际命中的场景两者等价，但重开发时需按 `==` 理解）；两轴各判一次。`hits==2`（对角线相邻）直接入 `receiver`；`hits==1`（同排相邻）进 `verify_candidate`。
- **`next_tree_verify`（验证确认，模板）**：对每个候选计算双方管理范围（`manage_range_calcu`），把边界提升为 double，用传入的 `Screen way(left1, left2, right2, left1)`（X 轴）与 `way(up1, down2, up2, down1)`（Y 轴）判定相交；**任一轴相交即相邻树**。`candidate_tree_filter` 传入的默认 lambda：`coord_1 >= coord_2 - 1 && coord_3 >= coord_4 - 1`——带 `-1` 的宽松判据会筛出**重叠树**（注释 PS：该逻辑会筛选重叠四叉树，目的为扩大回调管理进一步锁定重叠四叉树，故不需修改）；`tree_expand_approve` 中另传严格 lambda：`coord_1 > coord_2 - 1 && coord_3 > coord_4 - 1`（不含等号的重叠判据）筛出真正重叠的树。

#### 4.2.8 范围查询主流程 `seek(范围)`（excel 去重表）

```cpp
void Quadtree_Manager<T>::seek(std::vector<tree_chunk_data<T>*>& receiver,
    const Rect2i& target_range, bool stable)
{
    // ① 树群为空：stable 则建基准树（qurdtree_build_smart({left, down})），否则返回
    // ② 取基准树 = tree_group.front()（根 X 最大者）
    //    格式化：baseline_tree->target_range_format(seekable_range, root, block_size)
    // ③ 计算区块网格：
    int64_t want_col = (seekable_range.right - seekable_range.left + 1) / size_unit;
    int64_t want_row = (seekable_range.up - seekable_range.down + 1) / size_unit;
    if (want_col <= 0 || want_row <= 0) return;                       // 可查询范围非法防御
    if (want_row > INT64_MAX / want_col) return;                      // ★ 乘法溢出防御
    int64_t total_num = want_col * want_row;
    bool* target_excel = new(std::nothrow) bool[total_num]();         // 去重标记表（零初始化）
    if (target_excel == nullptr) return;

    // ④ 逐区块查询循环
    for (seek_time < total_num)
    {
        if (target_excel[seek_time] == false)                          // 未查询过的区块
        {
            excel_element_to_coord(seekable_range, seek_time, target); // 索引→坐标
            ptr_tree = quadtree_inclusion_seek(target);
            if (ptr_tree == nullptr && stable == true)
            {
                if (target.X/Y 超出 int32) continue;                   // 建档坐标需落回 32 位
                qurdtree_build_smart({ Point2i{target} });            // 智能补建
                ptr_tree = quadtree_inclusion_seek(target);
            }
            if (ptr_tree == nullptr) continue;                         // 非稳定或建树失败

            ptr_tree->tree->range_seek(buffer, seekable_range, stable);// 树内范围查询
            receiver.insert(receiver.end(), buffer.begin(), buffer.end());
            buffer.clear();
            ptr_tree->tree->manage_range_calcu(tree_range, ptr_tree->root, ptr_tree->size);
            ptr_tree->tree->seekable_range_calcu(seekable_range, tree_range);  // 裁剪已查范围
            target_range_amend(tree_range, target_excel, seekable_range);     // 标记已查区块
        }
    }
    delete[] target_excel;
}
```

**要点**：
- **excel 去重表**：`total_num` 个布尔位对应格式化后网格的每个区块；每棵树的查询只处理 `target_excel[i]==false` 的区块，查询后把该树实际覆盖范围（`tree_range ∩ seekable_range`）通过 `target_range_amend` 标记为 true，避免跨树重复查询同一坐标（但同一坐标可能被两棵树都返回——由树范围不重叠保证不重复）。
- **total_num 乘法溢出防御**：`want_row > INT64_MAX / want_col` 时提前返回，防止 `want_col * want_row` 溢出为负/异常后再分配。
- **智能补建坐标落回 int32**：`target.X < INT32_MIN || > INT32_MAX` 时 `continue` 跳过该区块（注释：超出范围说明该坐标不宜作为管理层建档依据）。
- **`excel_element_to_coord`（索引→坐标）**：`row = ID / width; col = ID % width; receiver.X = left + col*block_size; receiver.Y = up - row*block_size`。**零尺寸防御**：`block_size == 0` 或 `width <= 0` 时返回 `Point2l{}`（原点），防除零。
- **`target_range_amend`（标记已查）**：把"目标范围 ∩ 表范围"的行列区间（`X_start/X_end/Y_start/Y_end`，均含裁剪到表内）置 true；空指针、`block_size<=0`、表宽高非正、完全无交集时提前返回。

#### 4.2.9 单点查询主流程 `seek(单点)`

```cpp
void Quadtree_Manager<T>::seek(tree_chunk_data<T>*& receiver, const Point2i& target, bool stable)
{
    Point2l seek_coord{ target.X, target.Y };        // 提升 64 位
    for (;;)
    {
        tree_record = quadtree_inclusion_seek(seek_coord);
        if (tree_record != nullptr)
            tree_record->tree->block_seek(receiver, seek_coord, stable);
        if (receiver != nullptr || stable == false)
            break;                                    // 查询成功 / 非稳定终止
        else
            qurdtree_build_smart({ target });         // 稳定模式未命中 → 建树重试
    }
}
```

**要点**：`for(;;)` 死循环保证 stable 模式下"查到为止"；每轮失败就 `qurdtree_build_smart({target})`（单点集合智能创建，树群已存在时走 `tree_expand_approve` 补建）。**注意**：若 `target` 被判定不可建树（如管理器 `max_tree_size` 配置异常），可能死循环——实际由 `qurdtree_build_smart` 的参数防御与 `tree_expand_approve` 的 false 返回兜底，但 `seek(单点)` 本身无显式次数上限（重开发时注意）。

#### 4.2.10 四树合并 `qurdtree_merge`（收集 → 精确筛选 → 建新树 → 复制数据 → 卸载旧树）

```cpp
void Quadtree_Manager<T>::qurdtree_merge(void)
{
    if (copy)                                    // 前置条件：数据迁移回调已注册
    {
        // 合并期间临时禁用缓存（is_cache_operate 记录恢复标记）
        // ① 收集候选组合
        quedtree_merge_collect(classfied_tree);
        // ② 精确筛选组合
        quedtree_merge_filter(classfied_tree, varified_tree);

        // ③ 逐组合执行合并
        for (merge_time < varified_tree.size())
        {
            new_root = 四树 root 平均值;
            quadtree_build(new_root, tree_group.front()->size * 2);   // 建新树（边长翻倍）
            new_tree = X_sequence[quadtree_index_seek(new_root)];

            index_set.clear();
            for (seek_time < tree_group.size())     // 遍历 4 棵旧树
            {
                merged_tree_range = 旧树管理范围;
                index_set.push_back(quadtree_index_seek(旧树 root));
                buffer.clear();
                tree_group[seek_time]->tree->range_seek(buffer, merged_tree_range, false);  // ★ 非稳定读旧树
                for (copy_time < buffer.size())
                {
                    ptr_data = nullptr;
                    new_tree->tree->block_seek(ptr_data, point_to_l(buffer[copy_time]->node), true);  // ★ 稳定写新树
                    if (ptr_data) copy(*ptr_data, *buffer[copy_time]);   // 数据迁移回调
                }
            }
            quadtree_unload(index_set);             // 卸载 4 棵旧树
        }
        // 恢复缓存状态
    }
}
```

**`quedtree_merge_collect`（收集候选组合）**：
1. `max_expandable_size = largest_tree_size`；若等于上限则 `/2`（已达上限的树不能作为"扩大后的合并目标"）。
2. 计算最大可扩级数 `expand_level`（从 `max_expandable_size` 连续 /2 到 `min_tree_size` 计数）。
3. 遍历树群，把每棵 `size <= max_expandable_size` 的树按其"扩大级数"（`size` 连续 /2 到 `min_tree_size` 的次数）分组进 `level_tree_group[expand_level]`。
4. 每组数量 ≥4 才进入 `level_qualified_tree`（合并最少需要 4 棵同尺寸树）。
5. 组内逐树为中心：`next_tree_seek(next_trees, center_tree, &candidate_trees)`（限定组内找相邻）；相邻数 ≥3 时组合（`push_back(center)` + `swap(front, back)` 使中心树在表头）入 `receiver`。

**`quedtree_merge_filter`（精确筛选组合，穷举法）**：
1. 对每个候选组合（表头为中心树）：`used_trees`（`std::unordered_set<tree_record<T>*>`，**按指针去重**——本版次修改点）中已有中心树指针则跳过。
2. 以中心树为基准计算 4 个可能的新根坐标：`center_root ± size/2` 的四种组合。
3. 三索引游标（`indexs[0..2]`，带进位校准的递增组合）遍历其余树，计算 4 树平均根坐标；若与某个可能新根坐标相等（`Point2d` ULP 容差比较）且三索引对应树均未被使用，则记录组合（`buffer = {center, i0, i1, i2}`）并把 4 树指针插入 `used_trees`，结束该组合搜索。
4. **筛选条件**（源码注释）："若等大的四棵四叉树的根节点坐标平均数能够满足一种新四叉树根节点可能坐标，即为满足条件的四叉树组合"。

**合并正确性**：新树边长 = 旧树 ×2，新根 = 四根平均——四棵等大相邻树恰好拼成父象限，新树范围 = 四旧树范围并集；数据迁移用"非稳定范围查询旧树（只读已存在区块）+ 稳定单点查询新树（按旧区块中心坐标创建新区块）+ copy 回调搬数据"，最后按索引卸载旧树。

### 4.4 设计决策及原因

1. **为什么 `X_sequence` 按根 X 降序**：支持 `quadtree_index_seek` 用 `range_binary_search` 在 O(log n) 内定位"等 X 区间"，再在小区间内线性比对完整根坐标。降序而非升序是二分工具 `std::ranges::greater` 的配套选择；树群规模大时避免全量线性扫描。
2. **为什么缓存是"records + ranges 双数组 + LRU 前进位"**：`ranges` 缓存了 `manage_range_calcu` 的计算结果（树范围随扩大而变化，缓存失效时由 `tree_expand_approve` 刷新），命中时免去重复几何计算；前进位实现"最近访问靠前"，比完整 LRU 链表简单且缓存条目有限（默认 16）。
3. **为什么 `qurdtree_build_smart` 用"中心聚集"决定细分**：树越大，越界查询的扩大成本越高；把稠密点簇放进小树（精分）、稀疏区域用大树粗盖，在"树数量"与"单树覆盖精度"之间取平衡，同时让点远离边界减少扩大触发。
4. **为什么 `tree_expand_approve` 集"扩大裁决 + 新建树"于一身**：对四叉树而言只有一个回调入口（`callback(root, target)`），管理器在回调内统一决策"扩 or 建"，避免四叉树感知多树存在的复杂性；返回 true/false 即批准/拒绝，接口极简。
5. **为什么合并用"非稳定读 + 稳定写"**：读旧树用 `stable=false`（只读已存在区块，不因边界误差创建多余区块）；写新树用 `stable=true`（必须创建新区块承接数据）。读出的旧区块中心坐标 `point_to_l` 落回 int64 作为新树写入坐标，保证一一对应。
6. **为什么 `quedtree_merge_filter` 按指针去重**：源码注释"改为按指针去重"——根坐标 ULP 容差可能让不同树被判等，用指针（地址唯一）保证一棵树只参与一次合并。
7. **为什么合并期间临时禁用缓存**：合并会创建新树、卸载旧树，缓存条目大量失效；临时关闭缓存避免合并过程中缓存误命中已卸载树（悬垂指针）。
8. **为什么 `seek(范围)` 用布尔表而非集合去重**：区块网格是规则的 `want_col × want_row` 矩阵，索引即坐标，布尔表 O(1) 读写、O(total_num) 内存，比哈希集合更省且天然有序。

### 4.5 易踩坑点（重开发警示）

1. **`size` 双轨记录一致性**：`tree_record::size` 与 `tree->state.size` 必须同步。`tree_expand_approve` 中临时 `size *= 2`/`/= 2` 操作极易引入不一致——务必按"临时放大 → 判定 → 恢复/确认"的顺序执行，否则相邻判定与合并会基于错误边长。
2. **缓存悬垂指针**：任何卸载路径（`quadtree_unload` 两重载）都必须先按指针匹配清除 `tree_cache` 中的条目，否则缓存会返回已销毁的 `tree_record*`。合并期间禁用缓存也是为了规避此风险。
3. **`X_sequence` 排序不变量**：只有 `quadtree_build` 维护降序；若直接 `push_back` 后不排序，`quadtree_index_seek` 的二分会错乱。重开发新增"直接插入"路径时必须重新排序。
4. **`next_tree_classify` 的 `==` 判据**：源码用 `root_diff == (size+size)/2` 精确等于（非注释所述"小于等于"）。根坐标差值向下取整 + 边长半和是整数，两者相等是"恰好相邻"的判定；若改为 `<=` 会把重叠/分离树误判为相邻，破坏扩大裁决与合并收集。
5. **`tree_expand_approve` 的 internal 分支**：回调路径（internal=false）下管理器**不执行** `tree->tree_expand()`（四叉树自己扩）；内部路径（internal=true）必须显式调用。漏调会导致"记录 size 已扩大、实际树未扩大"。
6. **`seek(单点)` 的循环无显式上限**：stable 模式下依赖 `qurdtree_build_smart`/`tree_expand_approve` 的返回值兜底；若配置异常（如 `max_tree_size` 为 0 导致建树失败）可能死循环，重开发时建议增加次数保护。
7. **智能补建坐标的 int32 边界**：范围查询中超出 int32 的目标坐标被 `continue` 跳过，不建树——这是"64 位几何 + 32 位建档"的显式妥协，重开发时勿把 `Point2i{static_cast<int>(target.X)}` 之外的值传入（会溢出）。
8. **`divide_single_father_block` 的闭区间修正**：区块边界必须用"减 1"的闭区间公式（`right = left + size - 1; down = up - size + 1`），漏减会重叠相邻区块边界，导致同一坐标被两棵树覆盖。
9. **`max_expandable_size` 达上限除 2**：合并收集时若 `largest_tree_size == max_tree_size` 要 `/= 2`，否则把已达上限的树当作"可扩对象"会导致新树超过上限。
10. **合并数据迁移的区块中心取整**：旧区块中心 `buffer[i]->node`（double）经 `point_to_l`（llround）取整后作为新树写入坐标；若旧树范围边界不是整数网格对齐，取整误差可能让写入坐标偏移一个区块，需依赖四叉树 `block_seek` 的 64 位寻址正确性。

### 4.6 与坐标类型 / 二分查找 / 四叉树的协作

- **坐标类型**（`引擎层/src/core/spatial/common/core/坐标类型.h`）：管理器广泛使用 `Point2i`（对外查询入参、智能建树点集）、`Point2l`（内部几何、缓存范围、回调目标）、`Point2d`（根坐标、新根计算）、`Rect2l`（树范围、矩形筛选、excel 表范围）。`point_to_l` 把 double 根坐标/区块中心转 int64 用于跨层传递。`Point2::operator==` 的 ULP 容差（≤4）支撑 `quadtree_index_seek` 的根坐标匹配与 `quedtree_merge_filter` 的平均根坐标比对。
- **二分查找**（`引擎层/src/tools/Auxi_Algorithm/二分查找.h`）：`range_binary_search` 在降序 `X_sequence` 上按 `root.X` 返回等值闭区间 `{first, last}`，供 `quadtree_index_seek` 使用；配合 `std::ranges::greater` 比较器与投影 lambda `[](auto* p){ return p->root.X; }`。
- **四叉树模块**（`Quadtree/` 目录）：管理器通过 `Quadtree<T>` 的公开接口完成一切树内操作——`quadtree_build` 构造 + `set_max_size/set_block_size/set_callback_manage` 配置；`block_seek/range_seek` 查询；`manage_range_calcu/seekable_range_calcu/target_range_format` 几何工具；`tree_expand` 内部扩大。`tree_state`/`tree_chunk_data` 结构体被管理器直接引用（`tree_chunk_data<T>` 是 copy 回调参数、查询返回载体）。
- **日志系统**：管理器本版次源码未直接调用日志，失败通过返回值（nullptr/false/提前 return）逐层上报，由业务层决定是否记录。

## 五、模块运行链路（完整调用时序与协作关系）

### 5.1 单点查询链路 `seek(单点)`

```
业务层
  │ seek(receiver, Point2i target, stable)
  ▼
Quadtree_Manager::seek(单点)
  │ ① Point2i → Point2l 提升
  │ ② for(;;) {
  │      quadtree_inclusion_seek(seek_coord)
  │        ├─ 缓存命中（LRU 前进位）→ 返回 tree_record*
  │        ├─ 序列扫描命中（可写缓存）→ 返回 tree_record*
  │        └─ 未命中 → nullptr
  │      命中 → tree_record->tree->block_seek(receiver, seek_coord, stable)
  │      receiver != nullptr || !stable → break
  │      未命中且 stable → qurdtree_build_smart({target}) → 重试
  │    }
  ▼
Quadtree::block_seek（可行性分析三态 → 单路径下钻 → 填 receiver）
  ▲ callback(root, target)（越界扩大申请）
  └─→ Quadtree_Manager::tree_expand_approve（见 5.3）
```

### 5.2 范围查询链路 `seek(范围)`

```
业务层
  │ seek(receiver, Rect2i target_range, stable)
  ▼
Quadtree_Manager::seek(范围)
  │ ① 树群空 → stable 则建基准树（qurdtree_build_smart 单点）；非 stable 直接返回
  │ ② 基准树 target_range_format 格式化（网格对齐）
  │ ③ want_col/want_row/total_num（乘法溢出防御）→ 分配 target_excel 布尔表
  │ ④ 循环 seek_time < total_num（仅未标记区块）：
  │      excel_element_to_coord(索引 → 坐标)
  │      quadtree_inclusion_seek(target)（缓存/序列定位直属树）
  │        ├─ 未命中且 stable → int32 范围检查 → qurdtree_build_smart 补建 → 重定位
  │        └─ 仍未命中 → continue
  │      ▼
  │      Quadtree::range_seek(buffer, seekable_range, stable)
  │         ├─ target_range_format + range_seekable_analyse（循环扩大）
  │         └─ 显式栈遍历 → 收集命中区块 → receiver.insert(buffer)
  │      ▼
  │      manage_range_calcu(树范围) → seekable_range_calcu(裁剪)
  │      → target_range_amend(标记已查)
  │ ⑤ delete[] target_excel
```

### 5.3 扩大回调链 `tree_expand_approve`（自适应决策）

```
Quadtree（越界）→ callback(root, target)
  ▼
Quadtree_Manager::tree_expand_approve(root, target, internal)
  │ ① callback_tree_seek(root) 定位发起树
  │ ② quadtree_inclusion_seek(target) 已覆盖？→ return false（拒绝）
  │ ③ now_tree->size < max_tree_size？
  │      ├─ 是：rectangle_filter（2×size 矩形内有无其他树根）
  │      │     └─ 无：size*=2（临时）→ next_tree_seek（矩形→分类→验证）找相邻树
  │      │           ├─ 有相邻：next_tree_verify 严格重叠筛选 → size/=2
  │      │           │     ├─ 无重叠：size*=2 确认 → largest 更新
  │      │           │     │        → internal? tree->tree_expand()
  │      │           │     │        → 刷新缓存范围 → return true（批准）
  │      │           │     └─ 有重叠：return false 走④
  │      │           └─ 无相邻：沿用 size*2 → largest 更新
  │      │                    → internal? tree->tree_expand() → 刷新缓存 → return true
  │      └─ 否：走④
  │ ④ 扩大不可行 → new_tree_range_calcu(新范围) → 新 root=范围中心
  │      → quadtree_build(new_root, min_tree_size)（建新树并重排序）→ return false
  ▼
Quadtree 侧：true → 自行 tree_expand()；false → 终止查询/改道
```

### 5.4 智能建树链路 `qurdtree_build_smart`

```
业务层
  │ qurdtree_build_smart(coord_set)
  ▼
树群为空：
  │ ① prepare_smart_create_params（int64 化）
  │     包围矩形 → father_block_size(=max_tree_size, int64 防 2^33 截断) → 对齐 → 区块总数
  │ ② 遍历点集 → father_block_coord_count 各区块坐标计数
  │ ③ 逐非空区块：闭区间边界 → divide_single_father_block
  │       ├─ 空 → 返回
  │       ├─ size==256 → 记录建树参数
  │       ├─ 中心聚集（0.375×size）→ 四等分递归（nonempty==1 继续细分，否则建树）
  │       └─ 非中心聚集 → 记录建树参数
  │ ④ 统一 quadtree_build(root[i], tree_size[i]) × N
  ▼
树群已存在：
  │ 逐点 quadtree_inclusion_seek(exam_coord)
  │   未覆盖 → tree_expand_approve(tree_group.back()->root, coord, internal=true)
  │             ├─ 扩大可行 → 管理器代为 tree->tree_expand()
  │             └─ 不可行 → new_tree_range_calcu → quadtree_build 新树
```

### 5.5 四树合并链路 `qurdtree_merge`

```
业务层
  │ qurdtree_merge()（前置：copy 已注册；合并期间临时禁用缓存）
  ▼
  │ ① 收集：quedtree_merge_collect
  │      按扩大级数分组 → 每组 ≥4 棵 → 组内 next_tree_seek 找相邻
  │      → 相邻 ≥3 + 中心树 = 4 棵组合（中心树放表头）
  │ ② 精确筛选：quedtree_merge_filter
  │      穷举（中心树 + 三索引游标）→ 4 树平均根 == 可能新根坐标
  │      → used_trees 按指针去重 → 记录可合并组合
  │ ③ 执行合并（逐组合）：
  │      新 root = 四根平均；quadtree_build(new_root, size×2)
  │      逐旧树：manage_range_calcu → range_seek(buffer, 树范围, stable=false) 只读
  │        逐区块：block_seek(ptr, point_to_l(node), stable=true) 建新区块
  │                  → copy(*ptr, *buffer[i]) 数据迁移
  │      quadtree_unload(index_set) 卸载 4 棵旧树
  │ ④ 恢复缓存状态
```

### 5.6 与其他模块的协作关系

- **与 Quadtree**：管理器是四叉树的"唯一上级"。创建/配置/查询/销毁全部经由管理器；四叉树的扩大行为受管理器回调裁决。二者通过 `tree_record`（档案）、`tree_state`（状态）、`tree_chunk_data`（数据载体）、`callback`（扩大申请）四个纽带协作。
- **与坐标类型**：见 §4.6。管理器的 64 位化（缓存范围、回调目标、智能创建参数）是 fa8459a 尺寸层契约在调度层的延续。
- **与二分查找**：`quadtree_index_seek` 是管理器与 `range_binary_search` 的唯一衔接点，依赖 `X_sequence` 降序不变量。
- **与碰撞模块（业务层）**：业务层通过管理器的公开接口完成世界初始化（`qurdtree_build_smart` + 配置 setter）、动态查询（`seek` 两重载）、定期整理（`qurdtree_merge`）、动态移除（`quadtree_unload(root_set)`）。业务层不直接触碰 `Quadtree` 对象，管理器屏蔽了树群复杂度。
