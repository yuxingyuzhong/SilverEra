## 一、模块功能

碰撞系统是引擎层 `core/spatial/collision/` 下的一组**空间碰撞检测能力**，为上层提供「碰撞空间（世界）— 碰撞体（对象）— 碰撞代理器（门面）」三层结构，基于 **bullet3**（`external/bullet3`）物理库的碰撞检测子集（仅碰撞，不含动力学求解）实现。

### 1.1 解决的三个问题

1. **碰撞体建模**：把游戏/系统层的对象抽象为可参与碰撞检测的 `Collider`，支持六种几何形状（盒体 / 球体 / 胶囊 / 圆柱 / 圆锥 / OBJ 网格），且一个碰撞体可容纳**一组几何体**（各几何体带相对变换，共用同一碰撞对象与世界变换，故整体具有相同移动方向与速度）；位移向量由 `Collision/ColliderDisplacement` 事件提供、持续生效直至被新事件覆盖；另可配置检测方式（扫掠/离散）、豁免标记。
2. **碰撞世界管理**：把碰撞体按「碰撞空间（`Collision_Region`）」分组管理，每个空间有独立的 bullet3 碰撞世界后端（`Collision_Backend`）、独立的编号分配器与空间边界（静态网格），并维护逐碰撞体的**跨越状态**（完全在内 / 部分在内 / 完全在外）。
3. **对外统一门面、事件接入与三大应答链路**：`Collision_Proxy` 是模块对外的门面，统一管理多个碰撞空间、维护「碰撞体编号 → 归属空间」的全局映射，并将全部操作接入事件系统（订阅 `Config` / `Collision` 两分类 **13 条**指令）。除发布 `DetectResult` / `ColliderBuildResult` 结果事件外，还承担**碰撞响应流程**（发布 `ColliderCollision`、回收 `ColliderCollisionResponse` 回复并施加三种响应）与**跨越通知发布**（`RegionCrossNotice`）。

### 1.2 服务对象

- 引擎层内部：被 `碰撞系统运行包.h` 聚合导出；
- 上层消费方：系统层、测试层通过 `Collision_Proxy` 构建空间/碰撞体、执行检测、读取碰撞结果；
- 测试层：`碰撞测试.cpp` 直接构造 `Collision_Proxy` 验证全部接口（`Collision_Proxy_Test` 16 例、`Collision_Region_Test` 12 例、`Collider_Test` 2 例，碰撞三套件合计 30 例）。

### 1.3 设计要点定位

碰撞系统的骨架是「事件驱动的三方协作」：碰撞代理器既是事件订阅者（接收构建/设置/位移/响应指令），又是事件发布者（发布检测结果、碰撞事件、跨越通知）。碰撞体本身不感知位移来源，只保存**当前位移向量**与**作废标记**；位移的真实来源由代理器按编号保存为**位移事件**，并在每次检测开始时重新读取回写到碰撞体。检测流程本身**会修改**碰撞体位置（就地平移）与位移状态（作废），故 `region_detect` 是消费型调用。

## 二、模块提供接口

### 2.1 Collider（`Collider/碰撞体.h`）

```cpp
//碰撞检测方式
struct Detection_Mode
{
    bool is_swept_volume = false;   //扫掠检测标记
    uint32_t step_length = 0;       //离散检测步长
};

//几何体部件（碰撞体内一个带相对变换的几何体）
struct Geometry_Part
{
    std::unique_ptr<Triangle_Mesh> mesh;                     //网格接口（网格形状的数据源，先声明后析构）
    std::unique_ptr<Collision_Shape> shape;                  //几何形状（由部件持有）
    Transform local_transform = Transform::getIdentity();    //相对变换（该几何体在碰撞体内的位置关系）
};

//碰撞体
struct Collider
{
    uint64_t ID = 0;                                //编号
    Collision_Object object;                        //碰撞对象（bullet3，经依赖库封装别名）
    std::vector<Geometry_Part> parts;               //几何体部件集合（先声明后析构）
    std::unique_ptr<Collision_Shape> compound;      //复合形状（仅当部件数大于一时持有）
    Vector3 displacement_vector{0.0f,0.0f,0.0f};    //位移向量
    bool displacement_invalid = false;              //位移作废标记（碰撞响应判定停止运动时置位）
    Detection_Mode detection_mode;                  //检测方式
    uint64_t exemption_flag = 0;                    //豁免标记（同组豁免的碰撞对跳过）
    nlohmann::json geometry;                        //几何配置（供空间间镜像与转移复用）

    Collider();                                     //默认构造：object.setUserPointer(this)
    ~Collider() = default;
    Collider(const Collider&) = delete;             //禁止拷贝（object 加入 world 后不能搬移）
    Collider& operator=(const Collider&) = delete;
    Collider(Collider&& other) noexcept;            //移动构造：搬移数据 + 重挂自指针 + 清空源自指针
    Collider& operator=(Collider&& other) noexcept;
    Collision_Shape* mounted_shape(void) const;     //实际挂载的形状（多部件→复合；单部件→本体；无部件→空）
    static Collider* recover(const Collision_Object* obj);  //反查：从碰撞对象取回封装结构体
};
```

要点解释：
- **自指针机制**：`Collider` 构造时 `object.setUserPointer(this)`，bullet3 在检测回调/流形中给出碰撞对象地址，`Collider::recover()` 借 `getUserPointer()` 反查回碰撞体。移动后必须重新挂载（默认移动会把自指针指向被搬空的源对象），故移动构造/赋值显式重挂 `this` 并清空源对象自指针；`displacement_invalid` 随移动一并搬移。
- **几何体集合与挂载形状**：`parts` 保存全部几何体部件（各带 `local_transform`）；`mounted_shape()` 决定碰撞对象实际挂载的形状——多部件返回 `compound`（复合形状），单部件返回该部件形状本体，无部件返回空指针。**单部件不套复合形状**是刻意设计：既保住「凸包判断 + 扫掠检测」，也使旧单几何体配置的挂载对象与改动前逐字节等价。
- **析构顺序**：`parts` 先于 `compound` 声明，按成员声明逆序析构，故析构时复合形状先释放、部件后释放；而每个部件内 `mesh` 先于 `shape` 声明，析构时形状先释放、网格后释放——`btBvhTriangleMeshShape` 只持网格指针不接管所有权，网格必须与形状同生共死。

### 2.2 Collision_Region（`Collision_Region/碰撞空间.h`）

```cpp
//碰撞结果
struct Collision_Result
{
    uint64_t collider_A = 0;    //碰撞体A（归一化后较小者在前）
    uint64_t collider_B = 0;
};

//碰撞体相对碰撞空间的跨越状态
enum class cross_state { inside, crossing, outside };  //完全在内 / 部分在内（跨越边界）/ 完全在外

//跨越通知（碰撞体相对碰撞空间发生跨越状态转移）
struct Cross_Notice
{
    uint64_t collider_ID = 0;   //碰撞体编号
    std::string kind;           //通知类型（部分跨越 cross / 完全回归 return / 完全超出跨越 exit）
};

//碰撞空间
struct Collision_Region
{
private:
    std::string name;                                          //空间名
    bool is_active = false;                                    //活跃性
    Number_Allocator ID_allocator;                             //编号分配器（编号 0 预留给空间边界）
    Collider region_boundary;                                  //空间边界（静态网格）
    Collision_Backend backend{};                               //bullet3 后端
    std::unordered_map<uint64_t, Collider> mapping;            //碰撞体映射（按值持有）
    std::function<bool(uint64_t, Vector3&)> displacement_reader;  //位移事件读取回调（由代理器注入）
    std::unordered_map<uint64_t, cross_state> cross_states;    //逐碰撞体跨越状态记录
    std::vector<Cross_Notice> cross_notices;                   //本帧待发跨越通知

public:
    Collision_Region();
    explicit Collision_Region(const std::string& region_name);
    Collision_Region(const Collision_Region&) = delete;
    Collision_Region& operator=(const Collision_Region&) = delete;
    Collision_Region(Collision_Region&&) = default;
    Collision_Region& operator=(Collision_Region&&) = default;
    ~Collision_Region();                                       //析构前先把全部碰撞对象移出碰撞世界

    bool valid(void) const;                                    //后端有效性检查
    void state_set(bool active);                              //空间活跃性设置
    bool state_check() const;                                 //空间活跃性查看
    bool boundary_build(const std::string& mesh_path);        //边界构建（静态网格）
    void boundary_unload();                                   //边界卸载

    uint64_t collider_build(void);                            //碰撞体构建（分配编号）
    bool collider_unload(uint64_t collider_ID);               //碰撞体卸载
    bool collider_set(const uint64_t collider_ID, const Detection_Mode& vector);  //检测方式
    bool collider_set(const uint64_t collider_ID, const uint64_t& vector);        //豁免标记
    bool collider_set(nlohmann::json geometry_config);        //几何体设置（单几何体或几何体集合）
    bool collider_find(uint64_t collider_id) const;           //碰撞体查询
    std::vector<uint64_t> colliders(void);                    //碰撞体全量获取
    bool collider_adopt(uint64_t collider_ID);                //碰撞体接管（按指定编号登记，供空间间转移）
    nlohmann::json collider_geometry(uint64_t collider_ID) const;  //几何配置读取（不存在返回空 json）

    void displacement_reader_set(std::function<bool(uint64_t, Vector3&)> reader);  //位移事件读取回调注入
    bool collider_displacement_void(uint64_t collider_ID);                       //碰撞体位移作废（停止运动）
    bool collider_displacement_replace(uint64_t collider_ID, const Vector3& displacement);  //位移改写（继续运动且位移变化）

    std::optional<std::vector<Collision_Result>> detect(void);  //执行碰撞检测（位移重读+扫掠+离散+跨越判定）
    bool contains(uint64_t collider_ID) const;                //碰撞体包含性检测（是否已进入碰撞世界）
    std::vector<Cross_Notice> cross_notices_take(void);       //跨越通知取走（取出并清空本帧收集的通知）
};
```

要点解释：
- `detect()` 返回 `std::optional`：空间无效或未激活时返回 `std::nullopt`（空 optional 而非空 vector），调用方据此区分「未执行检测」与「执行了但无碰撞」。
- **位移通道单一化**：碰撞体位移向量**只能**由 `Collision/ColliderDisplacement` 事件提供并保存于代理器；空间经 `displacement_reader` 回调在每次检测时重读。空间不再提供任何直写位移的重载（旧 `collider_set(const uint64_t, const Vector3&)` 已移除）。
- **响应接口**：`collider_displacement_void` 置位 `displacement_invalid`（作废，检测时跳过该碰撞体的位移施加）；`collider_displacement_replace` 改写位移向量并解除作废。
- `collider_adopt()` 供空间间转移使用：按原编号在目标空间登记（编号冲突时失败，源空间尚未改动）。

### 2.3 Collision_Proxy（`Collision_Proxy/碰撞代理器.h`）

```cpp
class Collision_Proxy
{
private:
    inline static const std::string module_name = "Collision_Proxy";   //事件中转站登记名
    std::unordered_map<std::string, std::unique_ptr<Collision_Region>> regions;      //空间集合
    std::unordered_multimap<uint64_t, std::string> collider_mapping;                 //编号归属多重映射
    std::unordered_map<uint64_t, nlohmann::json> displacement_events;              //位移事件保存（按编号）
    std::unordered_map<uint64_t, nlohmann::json> collision_responses;              //碰撞响应回复信箱
public:
    Event_Terminal event_terminal;   //事件终端（对外暴露，供外部直接操作）
private:
    int64_t acl_key = 0;             //事件发送权限密钥
public:
    Collision_Proxy();               //构造：event_terminal.acl_key_gen() 生成权限密钥
    ~Collision_Proxy() = default;

    //---- 空间管理 ----
    bool region_build(const std::string& region);
    bool region_unload(const std::string& region);
    bool region_detect(const std::string& region);             //检测并发布结果
    bool region_boundary_set(const std::string& path);
    bool region_state_set(const std::string& region, bool active);

    //---- 碰撞体管理 ----
    std::optional<uint64_t> collider_build(const std::string& region);
    bool collider_unload(const uint64_t collider_ID, const std::string& region);
    bool collider_transfer(const uint64_t collider_ID, const std::string& region);
    bool collider_mirror(const uint64_t collider_ID, const std::string& region);
    bool collider_set(const uint64_t collider_ID, const Detection_Mode& vector);   //检测方式
    bool collider_set(const uint64_t collider_ID, const uint64_t& vector);         //豁免标记

    void attach(void);   //事件中转站接入（订阅 Config/Collision 两分类 13 条指令）
};
```

要点解释：
- **归属映射**：`collider_mapping` 记录「碰撞体编号 → 持有空间名称」；编号由各空间自行分配，**同一编号可被不同空间分别持有**（镜像场景），故用多重映射。`collider_set_*` 对所有持有该编号的空间生效（`collider_set_dispatch`）。
- **位移事件与响应信箱**：`displacement_events`（按编号保存最新位移事件 `config`）供空间经回调重读；`collision_responses`（按编号保存外部对 `ColliderCollision` 的回复）供检测流程回查。两者均为代理器本地状态。
- **事件接入**：`attach()` 需先经 `event_terminal->interface_check(ATTACH_HANDLER)` 确认事件中转站接入入口已注册；成功后注册事件接收入口，并提交 **13** 条订阅事件（详见文档五）。
- **事件结果回告与应答**：由于事件调用无法取得返回值，`ColliderBuild` 处理完成后以 `ColliderBuildResult` 事件回告新编号；`RegionDetect` 处理完成后先走碰撞响应流程、再发布 `RegionCrossNotice`、最后广播 `DetectResult`。

### 3.3 数据成员（三个类的核心状态）

**Collision_Proxy**：
- `inline static const std::string module_name = "Collision_Proxy";` —— 事件中转站登记名与事件发送者标识；
- `std::unordered_map<std::string, std::unique_ptr<Collision_Region>> regions;` —— 空间集合（按名索引，unique_ptr 持有）；
- `std::unordered_multimap<uint64_t, std::string> collider_mapping;` —— 编号归属多重映射；
- `std::unordered_map<uint64_t, nlohmann::json> displacement_events;` —— 位移事件保存（键＝编号，新事件覆盖旧事件）；
- `std::unordered_map<uint64_t, nlohmann::json> collision_responses;` —— 碰撞响应回复信箱；
- `Event_Terminal event_terminal;`（公开）与 `int64_t acl_key = 0;`（私有）。

**Collision_Region**：
- `std::string name;`（空间名）、`bool is_active = false;`（活跃性）；
- `Number_Allocator ID_allocator;`（编号分配器，编号 0 预留给空间边界）；
- `Collider region_boundary;`（空间边界，直接成员，静态网格形状）；
- `Collision_Backend backend{};`（bullet3 后端：config/dispatcher/broadphase/world）；
- `std::unordered_map<uint64_t, Collider> mapping;`（碰撞体映射，按值持有 Collider）；
- `std::function<bool(uint64_t, Vector3&)> displacement_reader;`（位移事件读取回调，由代理器注入）；
- `std::unordered_map<uint64_t, cross_state> cross_states;`（逐碰撞体跨越状态）；
- `std::vector<Cross_Notice> cross_notices;`（本帧待发跨越通知）。

**Collider**：见 2.1（ID / object / parts / compound / displacement_vector / displacement_invalid / detection_mode / exemption_flag / geometry）。

### 3.4 依赖库封装（`common/core/依赖库封装.h`）

```cpp
using Collision_Config     = btDefaultCollisionConfiguration;  //碰撞配置别名
using Collision_Dispatcher = btCollisionDispatcher;            //窄阶段检测调度器
using Collision_Interface  = btBroadphaseInterface;            //宽阶段检测接口
using Bvh_Tree             = btDbvtBroadphase;                 //BVH 宽阶段
```

## 四、模块设计/实现细节

### 4.1 位移向量的事件化与持续生效

位移向量不再由「通用设置指令里的一次性字段」提供，而是独立成群：

- **事件**：`Collision/ColliderDisplacement`，`config = { "collider_ID": <编号>, "region": <空间名，可选>, "displacement": [x,y,z] }`。字段名沿用既有事件约定；`region` 仅携带不参与路由，按编号分发到全部持有该编号的空间。
- **保存**：`displacement_register` 校验 `collider_ID` 与 `displacement`（三元数组）后写入 `displacement_events[collider_ID]`（同编号新事件覆盖旧事件），随即对持有该编号的空间施加 `collider_displacement_replace`——**新位移事件同时解除先前的位移作废**，恢复运动。
- **读取**：`region_build` 时由 `region_displacement_link` 向新建空间注入读取回调；空间每次 `detect()` 开头按编号重读事件并回写 `collider.displacement_vector`。读取失败（该编号尚无位移事件）则保留原向量。
- **持续生效**：位移**不再**在检测后清零；只要不被新事件覆盖，每次检测都会读取同一向量并继续推进。消费型语义被取消。
- **收口**：位移向量**只能**经此事件提供；`Collision/ColliderSet` 的 `displacement` 字段处理、`Collision_Proxy::collider_set(uint64_t, const Vector3&)`、`Collision_Region::collider_set(uint64_t, const Vector3&)` 两条旧直写通道均已移除。

### 4.2 碰撞体几何体集合

碰撞体由「单形状」改为「几何体集合」：一个碰撞体可容纳多个几何体，各几何体带**相对变换**，且共用同一个碰撞对象与同一个位移向量——故整体具有相同的移动方向与速度。

- **数据模型**：`Collider::parts`（`std::vector<Geometry_Part>`）；`Collider::compound`（`std::unique_ptr<Collision_Shape>`，仅当部件数大于一时持有 `btCompoundShape`，各部件形状作为其子形状）；`mounted_shape()` 返回实际挂载形状。
- **配置协议（向后兼容）**：`Collision/ColliderSet` 事件的 `config["geometry"]` 现有两种形态：
  - **对象形式（旧，不变）**：`config["geometry"]` 即单个几何体，`position` / `rotation` 写在几何对象内，作为该碰撞体的世界变换；
  - **数组形式（新）**：`config["geometry"]` 为几何体数组，每个元素描述一个几何体，元素内的 `position` / `rotation` 为**相对本体的局部变换**；碰撞体基准位置与基准朝向改由配置**顶层**的 `position` / `rotation`（可选）给出，缺省时沿用当前变换。
- **代理器侧包装**：`collider_config_apply` 以「是否为对象 / 数组」判定形态——数组形式写入 `geometries` 字段并合并顶层基准 `position` / `rotation`，其余形式视为未提供有效几何体。
- **空间侧构建**：`geometry_build` 统一处理单几何体形式与集合形式（集合形式判定为「含 `geometries` 数组字段」）；集合形式逐元素构建部件并读取相对 `position` / `rotation`，集合不可为空、元素须为对象；部件数 > 1 时分配复合形状并 `addChildShape(part.local_transform, part.shape.get())`。
- **镜像 / 转移**：`Collider::geometry` 留档的是完整配置（数组形式含 `geometries`），镜像与转移只需改写 `collider_ID` 后原样回放，无需特判几何体形态。

### 4.3 碰撞体配置与形状构建（`形状构建.cpp`）

- **形状类型**：`box`（half_extent 三元数组，各分量须 >0）、`sphere`（radius>0）、`capsule`（radius>0 且 height ≥ 2*radius，沿 Y 轴，bullet 第二参数为圆柱段长度 = height-2*radius）、`cylinder`（radius>0，沿 Y 轴以半长描述，`Vector3(r, h*0.5, r)`）、`cone`（radius>0、height>0，沿 Y 轴）、`mesh`（mesh_path）。
- **碰撞边距**：缺省 `margin = 0.04`（bullet 默认），显式指定时须 ≥0；`shape_receiver->setMargin()` 下发（盒体/圆柱/胶囊会自行修正隐式尺寸以保持总体尺寸不变）。
- **字段读取三件套**：`scalar_read`（浮点或整数皆可读入 double）、`vector_read`（三元数组，`field_check<std::vector<double>>` + 长度 3）、`quaternion_read`（四元数组，按 x/y/z/w 顺序 `setValue`）。
- **`geometry_build`**：见 4.2；单几何体形式下基准位置与朝向由调用方写入世界变换，部件相对变换保持单位变换。
- **网格形状**：`mesh_shape_build` 经 `Mesh_Loader::load_obj` 加载 → `memory_malloc<Triangle_Mesh>(true, true)`（32 位索引 + btVector3 顶点）→ 预分配容量 → `findOrAddVertex(v, false)`（关闭查重，按调用顺序追加，下标与网格数据一一对应）逐顶点写入 → `addTriangleIndices` 写索引 → `memory_malloc<Bvh_Triangle_Mesh>(mesh_receiver.get(), true, true)`（BVH 形状，数据源由调用方一并持有；分配失败时重置 mesh）。
- **`memory_malloc` 模板**：bullet 形状类经 `BT_DECLARE_ALIGNED_ALLOCATOR` 只声明抛异常形式的内存分配算子，无法 `new(nothrow)`；故统一包成 try/catch 返回 `bool` 的模板，失败 `Log::warn`。

### 4.4 碰撞检测流程（`检测执行.cpp`）

`Collision_Region::detect()` 的执行流程：

1. **前置**：`!valid() || !is_active` 时返回 `std::nullopt`；否则 `world->updateAabbs()` 刷新包围盒（挂入后尚未执行过检测时需要）。
2. **位移重读**：遍历 `mapping`，若已注入 `displacement_reader` 则按编号重读位移事件，命中则回写 `collider.displacement_vector`（取代旧版的「清零」）。
3. **扫掠阶段**（位移途中命中）：
   - 遍历 `mapping`，仅处理「启用扫掠检测 + **未作废**（`displacement_invalid` 为假）+ 位移向量非零」的碰撞体；
   - **逐部件扫掠**：遍历 `collider.parts`，对每个**已挂载且为凸包**的部件，以 `世界变换 ∘ local_transform` 为起点、加上位移向量为终点执行 `world->convexSweepTest`；非凸包部件跳过（与其行为约定一致）；
   - `Swept_Collector` 收集器**固定返回未命中分数 1.0f**，保证收集全部命中而非最近一次；跳过发起扫掠的碰撞对象自身；命中对象经 `Collider::recover()` 反查；**命中对象为空间边界时跳过**（空间边界不属于碰撞体）；同组豁免（exemption_flag 相等且非零）跳过；
   - 结果经 `pair_normalize` 归一化（较小编号在前）入 `pairs`。
4. **离散阶段**（就地平移后求交叉接触）：
   - 遍历 `mapping`，对「**未作废** + 位移非零」的碰撞体：`transform.setOrigin(origin + displacement)` 就地平移（**不清零位移向量**）；
   - `world->performDiscreteCollisionDetection()` → 遍历 `dispatcher->getManifolds()`，`getNumContacts() == 0` 跳过；两侧 `Collider::recover()` 反查；任一侧为空间边界时**登记 `boundary_contacts`（供跨越判定）并跳过碰撞对**；同组豁免跳过；归一化入 `pairs`。
5. **去重**：`pair_unique` 用 `std::set<std::pair<uint64_t,uint64_t>>` 保留首次出现的碰撞对。
6. **跨越判定**：`cross_state_update(boundary_contacts)` 在位置更新完毕后逐碰撞体判定并收集跨越通知（见 4.6）。

**注意**：检测会**实际修改**碰撞体位置（就地平移）——`region_detect` 是消费型调用；但位移向量本身不再因检测而清零，故未被新事件覆盖时会持续推进。

### 4.5 三种碰撞响应（事件应答，`碰撞响应.cpp`）

碰撞发生后向外界发布碰撞事件，由外界三选一响应；并按「发出 → 立即回查 → 未收到则搁置 → 其余碰撞体处理完毕后再查 → 仍未收到则重发 → 再查 → 仍无则日志报错并搁置」的时序处理响应缺失。

- **事件协议**：

| 方向 | tag | config |
| --- | --- | --- |
| 代理器 → 外界（发布） | `Collision/ColliderCollision` | `{ "region": <空间名>, "collider_ID": <编号>, "collisions": [ { "collider_A": <编号>, "collider_B": <编号> }, ... ] }` |
| 外界 → 代理器（回复） | `Collision/ColliderCollisionResponse` | `{ "collider_ID": <编号>, "response": "stop" \| "keep" \| "change", "displacement": [x,y,z]（仅 change 必需） }` |

- **发布粒度**：碰撞事件为**每个参与碰撞的碰撞体各发一条**（载荷含该碰撞体参与的全部碰撞对）。
- **回复信箱**：`ColliderCollisionResponse` 由事件接收入口存入代理器本地 `collision_responses`（按编号，新回复覆盖旧回复）；检测流程 `collision_protocol` 回查取值。因中转站分发是同步的，外部即时回发的回复会在 `event_publish` 返回前送达，故「立即回查」可命中。
- **响应时序**：第一轮逐个碰撞体发布并立即回查，命中即施加、未命中计入搁置集合；第二轮对其余碰撞体处理完后逐个回查搁置集合，命中即施加；仍未命中则**重发一次**并再次回查，命中即施加；仍无响应则 `Log::error("碰撞体(N)未收到碰撞响应，事件搁置处理")` 并搁置。重发为一次性，不循环重试。
- **响应语义（三种）**：

| 回复 | 施加方式 |
| --- | --- |
| `stop`（停止运动，位移向量作废） | 对持有该编号的空间调用 `collider_displacement_void` 置位 `displacement_invalid`；检测的扫掠与离散两处均跳过已作废碰撞体，故其自下一帧起不再推进 |
| `keep`（继续运动，位移向量保持） | 不施加任何改动，位移事件继续生效（沿用持续位移语义） |
| `change`（继续运动，位移向量变化） | 改写 `Collider::displacement_vector` 并解除作废，**同时改写代理器已保存的位移事件** `config["displacement"]`，使后续重读取得新向量 |

- **不作位置回退**：三种响应均作用于「位移向量」（作废 / 保持 / 变化）；`stop` 采用「自下一帧起不再推进」语义，不回退本帧已施加的位移。
- **`stop` 不删除位移事件**：仅置位作废标记，便于新位移事件到达时原位解除作废；作废期间检测重读事件仍会写入向量，但运动被 `displacement_invalid` 拦截。

### 4.6 三类跨越通知事件（`跨越通知.cpp`）

碰撞体相对某碰撞空间发生「首次部分跨越 / 完全回归 / 完全超出跨越」状态转移时，碰撞代理器向外界发布通知事件，供外界做碰撞体迁移到其余空间等操作。

- **三态状态机**：`enum class cross_state { inside, crossing, outside }`（完全在内 / 部分在内 / 完全在外）。每次 `detect()` 在**位置更新完毕**（离散平移 + `performDiscreteCollisionDetection` 之后）逐碰撞体判定：
  1. 该碰撞体与空间边界**存在接触**（离散流形两侧之一为 `region_boundary`）→ `crossing`；
  2. 无接触 → 取碰撞体**世界包围盒中心**为探针点，对空间边界做**射线奇偶**判定（交点数为奇数即在内）→ `inside` / `outside`。
- **转移命名**：与上一帧记录比对后，转移后为 `crossing` → `"cross"`（首次部分跨越，含由外直入）；`inside` → `"return"`（完全回归）；`outside` → `"exit"`（完全超出跨越）。**任意三态转移均发**（含「完全在内 ↔ 完全在外」直接跳变），仅转移发一次，稳态不重复。
- **首次仅建立基准**：首次判定（新挂载、转移入本空间、编号回收后再用）只记录状态、不发通知，故不会把「初始就位于空间外」误报为一次跨越。
- **射线奇偶实现**：用 `AllHits_Ray_Callback` 沿固定方向（`(1, 0.37, 0.19)` 归一化，三轴均非零以避免与面片共面漏检）自探针点射至「包围盒对角线两倍 + 1」处，统计命中对象为 `region_boundary.object` 的交点数。子弹库 `AllHitsRayResultCallback::addSingleResult` 返回不变的 `m_closestHitFraction`（初值 1.0），使后续三角面片不被分数剪枝，**全交点均被收集**，奇偶判定成立。
- **事件协议**：

| 方向 | tag | config |
| --- | --- | --- |
| 代理器 → 外界（发布） | `Collision/RegionCrossNotice` | `{ "region": <空间名>, "collider_ID": <编号>, "state": "cross" \| "return" \| "exit" }` |

- **发布时机**：`region_detect` 内，**碰撞响应流程之后、`DetectResult` 之前**（故 `DetectResult` 恒为该次检测的最后一条事件）；每个发生转移的碰撞体各发一条。
- **出站事件不订阅**：该事件为代理器自身的出站事件，若订阅则会自收自处理，故订阅清单不因其增加。
- **状态清理口径**：`collider_unload`（含 `collider_transfer` 的源空间卸载）立即抹除该编号的跨越状态记录；目标空间 `collider_adopt` 无该编号记录，下次检测按首次建立基准；`collider_mirror` 得到全新编号，无记录；`cross_state_update` 内兜底清理已不在 `mapping` 中的编号记录。
- **边界不参与碰撞对**：`region_boundary` 是 `Collider` 类型且已挂入碰撞世界，扫掠命中与离散流形两处反查对象为 `&region_boundary` 时均跳过碰撞对（否则会把编号 0 的边界碰撞体当作正常碰撞对并触发对编号 0 的碰撞响应等待），离散流形处同时登记该碰撞体与边界的接触供跨越判定使用。

### 4.7 碰撞空间生命周期（关键陷阱）

1. **构造**：`Collision_Region(name)` 记录名称，并 `region_boundary.ID = ID_allocator.get()` **预分配编号 0 恒保留给空间边界**。
2. **析构**：碰撞体与空间边界都直接持有碰撞对象（`Collision_Object`），而碰撞世界内部记录的是这些对象的**地址**；碰撞体映射先于碰撞世界析构，故 `~Collision_Region()` 必须先把全部碰撞对象移出碰撞世界（`world->removeCollisionObject`），否则碰撞世界析构时解引用已释放对象。
3. **移动陷阱**：`Collision_Region` 默认移动构造/赋值被保留，但**碰撞世界内部记录的是碰撞对象地址，而空间边界是直接成员**——向碰撞世界挂入边界后再按值搬移本结构体会留下悬空指针。`Collision_Proxy` 按 `unique_ptr` 搬移不受影响；确需按值搬移时须搬移后重新执行边界构建（`boundary_build`）。

### 4.8 代理器的转移 / 镜像语义

- **转移 `collider_transfer`**：查归属空间 → 取源空间几何配置 `collider_geometry` → 目标空间 `collider_adopt(collider_ID)`（原编号接管，冲突即中止）→ 源空间 `collider_unload`（失败则回滚目标空间接管）→ 更新归属映射 → 有几何配置时 `geometry["collider_ID"]=原编号` 后 `collider_set` 重建几何体。**无几何配置时仅转移编号登记**（占位碰撞体）。
- **镜像 `collider_mirror`**：取源几何配置 → 目标空间 `collider_build`（全新编号）→ 有几何配置时按新编号重建。源碰撞体保留，两空间各持一份。

### 4.9 配置驱动的空间/碰撞体构建（`空间边界与配置.cpp`）

`config_apply(config)` 处理 `Config/Load` 路由指令（`target_object == "Collision_Proxy"`）：
- 顶层须为 object 且含 `regions` 数组；
- 每个 region 配置：`region`（名称）→ `region_build` → 可选 `active`（活跃性）→ 可选 `boundary`（网格路径 → `boundary_build`）→ 可选 `colliders` 数组（逐个 `collider_build` + `collider_config_apply`）；
- `collider_config_apply` 支持 `geometry`（对象形式补 `collider_ID` 后 `collider_set`；数组形式包装为 `geometries` 并合并顶层 `position` / `rotation`）、`detection_mode`（`is_swept_volume` 布尔 + `step_length` 整数）、`exemption_flag`（整数）。位移向量**不再**由本指令提供（改由 `ColliderDisplacement` 事件）。

`region_boundary_set(path)` 读 JSON 数组，每条含 `region` + `mesh_path`，逐空间 `boundary_build`；全部成功才返回 true（部分失败记 `all_set=false` 并 `Log::warn`）。

### 4.10 事件接入与处理（`事件交互.cpp`）

`attach()` 的三步校验链：
1. `event_terminal->interface_check(interface_ID::ATTACH_HANDLER)`——事件中转站接入入口未注册则中止；
2. `event_terminal->event_receiver_register([this](shared_ptr<event> evt){ this->event_process(evt); })`——注册事件接收入口；
3. `event_terminal.attach(module_name, needed_events, acl_key)`——提交订阅清单并接入。

`needed_events` 订阅清单（**13 条**，全部 `sender/target` 置空、category/tag 成对）：
| category | tag |
| --- | --- |
| Config | Load |
| Collision | RegionBuild / RegionUnload / RegionState / RegionBoundary / RegionDetect |
| Collision | ColliderBuild / ColliderUnload / ColliderTransfer / ColliderMirror / ColliderSet |
| Collision | ColliderDisplacement / ColliderCollisionResponse |

`event_process(evt)` 分派：
- `Config/Load`：`evt->target_object != module_name` 时忽略（**定向指令**），否则 `config_apply`；
- `Collision/RegionBuild`：读 `region` → `region_build`（内部注入位移读取回调）；
- `Collision/RegionUnload`：读 `region` → `region_unload`；
- `Collision/RegionState`：读 `region` + `active` → `region_state_set`；
- `Collision/RegionBoundary`：读 `path` → `region_boundary_set`；
- `Collision/RegionDetect`：读 `region` → `region_detect`；
- `Collision/ColliderBuild`：读 `region` → `collider_build` → 发布 `ColliderBuildResult`（`region` + `collider_ID`）；
- `Collision/ColliderDisplacement`：`displacement_register(evt->config)`（保存位移事件并解除作废）；
- `Collision/ColliderCollisionResponse`：`collision_response_register(evt->config)`（登记回复信箱）；
- `Collision/ColliderUnload/Transfer/Mirror/Set`：读 `region` + `collider_ID` → 对应处理（Set 走 `collider_config_apply`）；
- 其余 category/tag：`Log::debug` 未识别。

`event_publish(tag, payload)`：`event_terminal.build(module_name, "", "Collision", tag)` → 写载荷 → `event_terminal.send(evt, acl_key)`（单事件通道）。发布事件：`DetectResult` / `ColliderBuildResult` / `ColliderCollision` / `RegionCrossNotice`。

## 五、模块运行链路

### 5.1 典型运行链路一：配置驱动初始化（事件接入）

```
Config_Loader::act()
  └─ send(Config/Load, target=Collision_Proxy, config={regions:[...]})
       └─ Event_Broker 定向投递（target_object 非空 → 直投 event_entries[Collision_Proxy]）
            └─ Collision_Proxy::event_process()
                 └─ config_apply(config)
                      ├─ region_build(每个 region)          → 构造 Collision_Region + 注入位移读取回调
                      ├─ region_state_set / boundary_build   → 空间边界静态网格
                      └─ collider_build + collider_config_apply
                           ├─ Collision_Region::collider_build()  → ID_allocator.get() 分配编号
                           └─ Collision_Region::collider_set(geometry) → geometry_build → addCollisionObject
```

### 5.2 典型运行链路二：位移事件 → 检测执行 → 结果分发

```
外部 send(Collision/ColliderDisplacement, {collider_ID, displacement})
  └─ Collision_Proxy::event_process → displacement_register
       ├─ displacement_events[ID] = config（新事件覆盖旧事件）
       └─ collider_set_dispatch(ID, collider_displacement_replace) → 解除作废、写入向量

游戏逻辑调用（直接或经事件）
  └─ Collision_Proxy::region_detect("scene")
       ├─ region_seek("scene") → Collision_Region*
       └─ target->detect()
            ├─ updateAabbs()
            ├─ 位移重读：displacement_reader(ID) → collider.displacement_vector
            ├─ 扫掠阶段：逐部件 convexSweepTest + Swept_Collector（跳过边界/作废）→ pairs
            ├─ 离散阶段：就地平移（跳过作废）+ performDiscreteCollisionDetection → pairs + boundary_contacts
            ├─ pair_unique → vector<Collision_Result>
            └─ cross_state_update(boundary_contacts) → cross_notices
       ├─ collision_protocol(region, results)      → 发布 ColliderCollision / 回收 ColliderCollisionResponse / 施加响应
       ├─ cross_notices_take() → 逐个 event_publish("RegionCrossNotice", {region, collider_ID, state})
       └─ event_publish("DetectResult", {region, results:[...]}) → 广播（恒为最后一条）
```

### 5.3 典型运行链路三：碰撞响应闭环

```
region_detect → detect() 得碰撞对
  └─ collision_protocol(region, pairs)
       ├─ 逐个碰撞体发布 ColliderCollision{region, collider_ID, collisions}
       │     └─ 外部即时回发 ColliderCollisionResponse{response:"stop"|"keep"|"change", ...}
       │           └─ 事件入口 → collision_response_register（存入回复信箱）
       ├─ 立即回查 collision_response_take → 命中则 collision_response_apply
       │     ├─ stop   → collider_displacement_void（置位作废）
       │     ├─ keep   → 无改动
       │     └─ change → 改写 displacement_events + collider_displacement_replace
       ├─ 未命中计入搁置；其余碰撞体处理完后第二轮回查
       └─ 仍未命中 → 重发一次 → 再回查 → 仍无则 Log::error 搁置
```

### 5.4 典型运行链路四：碰撞体转移 / 镜像

```
Collision_Proxy::collider_transfer(ID, "target")
  ├─ collider_owner_seek(ID, owner)          → 找到归属空间
  ├─ source->collider_geometry(ID)           → 取几何配置
  ├─ target->collider_adopt(ID)              → 原编号接管（冲突中止）
  ├─ source->collider_unload(ID)             → 失败则回滚 target 接管（并抹除源空间跨越状态）
  ├─ collider_mapping_unlink + link          → 更新归属映射
  └─ 有几何时 target->collider_set(geometry) → 重建几何体

Collision_Proxy::collider_mirror(ID, "target")
  ├─ source->collider_geometry(ID)           → 取几何配置
  ├─ collider_build("target")                → 全新编号 mirror_ID
  └─ 有几何时 target->collider_set(geometry with mirror_ID)
```

## 八、遗留与约定

1. **位移通道单一化已落地**：碰撞体位移向量只能由 `Collision/ColliderDisplacement` 事件提供，旧直写重载与 `ColliderSet` 的 `displacement` 字段已移除；`displacement_invalid` 与读取回调链路保留。
2. **响应作用于位移向量而非位置回退**：`stop` 为「自下一帧起不再推进」，本帧末碰撞体仍停在推进后位置（可能嵌入对方）。
3. **重发为一次性**：响应缺失时仅重发一次，不循环重试。
4. **跨越判定口径**：部分跨越按「与边界接触」判定，故「完全在外但贴靠外壁」记为 `crossing`；探针点取世界包围盒中心（多部件即复合形状包围盒中心），对细长/偏心几何体可能有偏差；`RegionCrossNotice` 不含转移前状态。
5. **网格部件不参与扫掠**（网格形状非凸包）；多部件碰撞体挂载复合形状，凸包扫掠已改为逐部件执行。
6. **运动步长检测仍未实现**：`Detection_Mode::step_length` 目前仅存储，扫掠为单段凸包扫掠。
7. 空间边界编号恒为 0（`ID_allocator` 预分配），对外应明确该约定。
8. `形状构建.cpp` 因承载 `geometry_build` 而增长（412 行），`memory_malloc` 为其与 `mesh_shape_build` 共用。
