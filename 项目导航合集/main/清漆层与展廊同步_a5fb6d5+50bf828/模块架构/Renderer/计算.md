## 1. 模块功能介绍

提供**与图形管线完全独立**的计算管线基础设施：自有描述符集布局（set 0 = 若干存储缓冲）、管线布局、计算管线、每帧槽描述符集、一次性提交辅助与调度封装。它是方向一（GPU 驱动渲染）与方向二（GPU 粒子）共用的地基，不承载任何业务（剔除 / Hi-Z / Cluster / 粒子各自在自己的模块里）。

## 2. 模块公开接口

| 接口 | 语义 |
| --- | --- |
| `bool build(VkPhysicalDevice, VkDevice, uint32_t graphics_family, VkQueue graphics_queue, const Compute_Config&)` | 探测队列族 COMPUTE 位；创建布局 / 池 / 每帧槽描述符集 / 一次性命令池与围栏。队列族不支持时返回真且 `supported()` 为假（初始化不失败） |
| `bool supported()` | 是否可用（队列族含 COMPUTE 位且构建完整） |
| `bool pipeline_register(uint64_t& handle, VkShaderModule)` | 登记计算管线（句柄自 1 起；入口固定 `main`；着色器模块所有权在调用方） |
| `bool pipeline_activate(uint64_t)` / `VkPipeline pipeline_get()` | 激活 / 取当前管线 |
| `uint32_t pipeline_count()` / `VkPipelineLayout layout_get()` | 计数与布局 |
| `VkDescriptorSet set_get(uint32_t slot)` | 帧槽描述符集 |
| `bool storage_bind(uint32_t slot, uint32_t binding, VkBuffer, VkDeviceSize offset, size)` | 写存储缓冲描述符（binding ∈ [0, storage_buffer_count)） |
| `bool slot_set(uint32_t)` / `uint32_t slot_get()` | 指定 / 读取调度使用的帧槽（默认 0） |
| `bool compute_dispatch(cb, handle, gx, gy, gz, const void* push = nullptr, uint32_t push_size = 0)` | 绑定管线与描述符集、写推送常量、下发工作项、累计计数 |
| `bool single_submit(const std::function<bool(VkCommandBuffer)>&)` | 一次性命令缓冲 + 围栏等待（5 s），供自检 / 回读 / 测试；**不得**用于常规帧 |
| `bool self_check_run(uint32_t magic, uint32_t& out)` | 内置健康检查：建 64 元素主机可见缓冲 → 绑 0 → 推魔数 → 调度 → 计算→主机屏障 → 回读首元素 |
| `uint64_t dispatch_count_get()` | 累计调度次数 |

门面（`渲染器.h`）：`compute_supported()`、`compute_health_check(magic, value_out)`。

## 3. 模块私有方法

- `descriptor_layout_create()`：set 0 的 `storage_buffer_count` 条 `STORAGE_BUFFER` 绑定（`COMPUTE` 阶段可见）。
- `pipeline_layout_create()`：绑定 set 0 ＋ 推送常量段（`COMPUTE`，长度 = `push_size` 128）。
- `compute_pipeline_create(module, out)`：`vkCreateComputePipelines`，入口 `main`，不启用管线缓存（后续轮次可接入）。
- `entry_find(handle)`：线性查找管线条目（条目数量极少，无需映射）。

## 4. 模块内部架构

```
Compute/
├── 计算数据.h        # Vulkan-free：Compute_Config / Compute_Stats
├── Compute.h        # Compute_Context（内部头，含 Vulkan 类型）
├── 局部命名空间使用.h
└── core/Compute.cpp # 生命周期 / 描述符 / 管线 / 提交 / 调度 / 自检
```

- **与图形管线的关系**：完全独立（自有 `VkDescriptorSetLayout` / `VkPipelineLayout` / `VkDescriptorPool` / 管线），**不共享** set 0（场景 UBO）与 set 1（材质采样）。理由见方向一规划 §2.2：图形侧增字段不会让计算布局失效。
- **推送常量**：与图形同尺寸 128 字节，复用既有偏移约定，避免两套偏移表。
- **帧槽**：每帧槽一条描述符集（`frame_overlap` 条），调度时绑定 `active_slot` 对应的集。

## 5. 模块设计 / 实现细节

1. **队列族**：复用图形队列族（Vulkan 1.3 桌面卡普遍同时具备 GRAPHICS/COMPUTE）。若不含 COMPUTE 位 → `supported_flag = false`，`build` 返回真，门面 `compute_supported()` 为假，全部 GPU 路径保持关闭。
2. **一次性提交**：`single_submit` 每次复位围栏与命令池、分配一条主命令缓冲、录制、提交、等待（5 秒超时）后释放命令缓冲；命令池与围栏由 `destroy` 统一销毁。
3. **可见性**：自检在调度后插入 `VkMemoryBarrier2`（`COMPUTE_SHADER/SHADER_WRITE` → `HOST/HOST_READ`），主机回读为 coherent 映射，无需 `vkInvalidateMappedMemoryRanges`。
4. **错误处理**：任一步失败即返回假；`destroy` 幂等；管线条目在 `destroy` 时逐条 `vkDestroyPipeline`。
5. **自检缓冲**：主机可见 + 一致（`HOST_VISIBLE | HOST_COHERENT`）的 64 × float storage buffer，前置清零以便验证「写入确实发生」；回读按 **float 位模式** 与推送 `magic` 比较（测试传入 `1.0f` / `3.14159265` 的位模式）。

## 6. 模块运行链路详例

`compute_health_check(0x3F800000)`：
1. 门面检查 `initialized` 与 `compute_supported()`；
2. `self_check_run` 建缓冲（256 B）→ 映射 → 清零 → `slot_set(0)` → `storage_bind(0,0,buffer,0,256)`；
3. 组推送 `{float magic = 1.0f, uint count = 64}`；
4. `single_submit`：`compute_dispatch(handle, 1,1,1, push)` → `vkCmdDispatch(1,1,1)`（64 线程 = 64 元素）→ 屏障 → 提交 → 围栏等待；
5. 回读 `mapped[0]` 的 float 位模式，与 `magic` 相等即成功；
6. 还原帧槽、解映射、释放内存与缓冲。

## 7. 待确认

- 【待确认：241-1】计算管线未接入 `VkPipelineCache`（图形侧已有缓存文件机制）；后续若要复用管线缓存，需与 `Pipeline_Context` 的缓存生命周期协调。
- 【待确认：241-2】`single_submit` 直接提交到图形队列，与常规帧的帧槽提交可能交错；当前仅用于初始化 / 测试，若后续用于运行时回读，需纳入帧同步。
