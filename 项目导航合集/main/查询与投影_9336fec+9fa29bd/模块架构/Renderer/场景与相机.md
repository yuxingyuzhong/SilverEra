# 场景与相机 · 模块架构

> 源码根相对路径：`Application/Renderer/src/render/Scene/`
> 本文覆盖本层 `Scene/` 目录下的全部三个源码文件：对外头 `相机.h`（对外类型 `Camera`）、模块内部头 `局部命名空间使用.h`、以及 `core/` 下的唯一编译单元 `相机.cpp`。
> 本模块的职责是「为渲染层提供一个可写视图矩阵与投影矩阵（透视 / 正交）的相机」，它把相机参数（位置 / 注视点 / 上方向 / 视场角 / 宽高比 / 近远平面 / 投影模式）收拢进一个极简的 `Camera` 类，并在被调用时把「视图 × 投影」矩阵按**列主序 16 浮点**形式写出，供上层（或测试）直接拷入场景 UBO。
> 记录依据为当前工作区源码（本版次 Renderer 代码哈希 `c644826`），不包含任何旧版次导航信息。文中所有路径均为相对源码根（`工作区`）的相对路径，不出现绝对路径。
> 本模块是渲染层内**体量最小**的模块：`Scene/` 目录下**没有** `Scene_Context` 之类的门面上下文类，`Camera` 是唯一对外类型，`相机.cpp` 是唯一编译单元。本文因此对接口逐条、字段逐项、矩阵推导分步、链路分步做了充分展开，以补足源码体量。
> 需要说明：`相机.cpp` 是渲染层内**唯一直接使用 `glm` 数学库的编译单元**（其头文件刻意不暴露任何 `glm` 类型，见 §五 与 §六）。
> **本版次（第九轮）新增**：本模块新增一个 **Vulkan-free 公共头** `Application/Renderer/src/render/Scene/场景数据.h`——定义聚合类型 `engine::Scene_Data`（相机位置 / 注视点 / 视场角 / 近远平面 ＋ 清屏色），由门面公共头 `渲染器.h` 引用；门面据此新增 `scene_apply`（等价相机四 setter ＋ 清屏色）与 `clear_color_set`，并把清屏色由「帧链路内部固定值」改为**门面记录值**（见 §2.7 / §3.5 / §5.1 与《渲染层-渲染器》§3.4.44 / §3.4.45 / §6.16）。
> **本版次（第十轮）新增**：本模块 `Camera` 的默认值**收敛为单一来源**——`Camera::Camera(void)` 由 `= default` 改为**显式定义**（函数体内取 `const Scene_Data defaults{};` 后逐项 `position_set` / `target_set` / `fov_set` / `near_far_set`），从而「默认机位 / 注视点 / 视场角 / 近远平面」**全部取自 `Scene_Data` 默认值**；私有成员 `position` / `target` / `fov` / `near_plane` / `far_plane` 的成员初始化器**已删除**（仅 `up`（`{0,1,0}`）与 `aspect`（`16/9`）因 `Scene_Data` 未涵盖而保留本层自有默认）；`Scene/局部命名空间使用.h` 增 `#include "场景数据.h"`。**处置结案 `R-SCENE-07`**（见 §3.2.1 / §5.3 / 附录），对外行为不变（默认机位仍在 +Z 3 单位、注视原点、视场角 60°、近远 0.1 / 100）。

## 二、模块功能介绍

### 2.1 模块定位

「渲染层-场景与相机」模块位于渲染层源码目录 `Application/Renderer/src/render/Scene/`，与渲染层的其它子模块（设备 `render/Device/`、交换链 `render/Swapchain/`、内存与资源 `render/Memory/`、网格 `render/Mesh/`、管线 `render/Pipeline/`、着色器 `render/Shader/`、纹理 `render/Texture/`、帧 `render/Frame/`、平台 `render/Platform/`、渲染器门面 `render/Renderer/`）并列，是渲染层「场景侧」的**唯一在场模块**。

本模块把「虚拟相机」这一概念收拢为单个类 `Camera`：它持有一组标量相机参数，对外只暴露「六个参数 setter ＋ 一个轨道旋转 ＋ 一个矩阵写出」的极简接口，不持有任何 Vulkan / SDL 句柄，也不参与资源生命周期管理。其核心产物是一个 **4×4 的「视图 × 投影」矩阵**（列主序 16 个 `float`），该矩阵正是场景着色器顶点阶段所需的「把世界坐标变换到裁剪空间」的常量。

一句话概括：**本模块是渲染层「世界坐标 → 裁剪空间」变换的唯一产生者；它用 `glm` 在实现内计算 `view` 与 `proj` 两个矩阵并预乘为 `view_proj`，按列主序输出，直接对应着色器 `set 0` 场景 UBO 中的 `mat4 view_proj` 字段。**

### 2.2 职责边界与解决的问题

`Camera` 解决的问题可归纳为五点：

1. **把「相机参数」与「矩阵计算」封装在一处**。上层若要产生一个观察矩阵，传统做法需要在调用现场自行构造 `lookAt` 与 `perspective`，散落的三角函数、宽高比、近远平面容易写错且难以统一约定（例如深度范围、Y 轴朝向）。本模块把这套计算固化在 `Camera::view_proj_get` 内，上层只需摆好参数、取一次矩阵。

2. **固定 Vulkan 的「深度零到一」约定**。Vulkan 的裁剪空间深度 `Z ∈ [0, 1]`（区别于 OpenGL 的 `[-1, 1]`）。本模块通过 `glm::perspective` 在 `GLM_FORCE_DEPTH_ZERO_TO_ONE` 宏下生成右手的零到一投影矩阵（`perspectiveRH_ZO`），把该约定固化在编译期，调用方无需重复处理（见 §6.3）。

3. **固定 Vulkan 的「NDC Y 轴向下」约定**。Vulkan 的标准化设备坐标中 Y 轴指向下方（与 OpenGL 相反）。本模块在生成投影矩阵后直接执行 `proj[1][1] *= -1.0f` 做一次 Y 翻转（源码注释记为「K1」），从而把右手 OpenGL 风格的投影修正为 Vulkan NDC 期望的朝向（见 §6.4）。

4. **预乘视图与投影，减少上层每帧乘法**。本模块对外只提供一个 `view_proj_get`，内部先把 `proj * view` 预乘好再输出（见 §6.5）。这样着色器与上层每帧只需处理「一个场景级矩阵 × 一个对象级模型矩阵」，降低了每次绘制时的矩阵乘法次数，也令场景 UBO 只需 64 字节。

5. **提供列主序、可直接落 UBO 的输出格式**。`view_proj_get` 输出的是 `glm` 内部的列主序 16 浮点，与 Vulkan 的场景 UBO `mat4 view_proj`（std140 布局）**逐字节一一对应**，中间不需要任何转置或重排（见 §6.6 与 §3.4）。

### 2.3 在整体架构中的位置

相机模块处在渲染层依赖链的**下游末端**：它**不向下依赖任何 Vulkan 对象**，只依赖 `glm` 数学库与标准库基础类型；**向上**被「渲染层-渲染器」门面（`Renderer::Impl`）持有，或被渲染层测试用例直接使用，用于每帧产生「视图 × 投影」矩阵并写入场景 UBO（`set 0`）。

```
        ┌──────────────────────────────────────────────────────────────┐
        │                  Renderer（渲染器门面） / 测试用例              │
        │   init：camera.position_set / target_set / fov_set ...         │
        │   resize：camera.aspect_set(宽/高)                             │
        │   render：camera.view_proj_get(buf[16]) → 写入场景 UBO         │
        │            pipeline.scene_bind(slot, ubo) → Frame_Render_Item  │
        └───────────┬───────────────────────────────────────┬──────────┘
                    │ 驱动（setter / orbit / view_proj_get）  │
                    ▼                                        │
        ┌───────────────────────────────────────────────┐   │
        │                 Camera（相机）                  │   │
        │  position[3] / target[3] / up[3]               │   │
        │  fov / aspect / near_plane / far_plane         │   │
        └───┬───────────────────────────────────────────┘   │
            │依赖（仅实现内，头文件不暴露）                     │
            ▼                                                 │
    ┌──────────────────────────────┐                          │
    │ external/glm（数学库）         │                          │
    │ glm::lookAt / glm::perspective│                          │
    │ glm::rotate / glm::value_ptr  │                          │
    └──────────────────────────────┘                          │
                                                              ▼
                                        ┌────────────────────────────────────┐
                                        │ 场景 UBO（set 0, binding 0）         │
                                        │ mat4 view_proj（64B, std140）        │
                                        │ 着色器：gl_Position =               │
                                        │   scene.view_proj * object.model * p │
                                        └────────────────────────────────────┘
```

- **向上**：调用方是「渲染层-渲染器」门面（`Application/Renderer/src/render/Renderer/`）与渲染层测试用例。门面在初始化阶段调用六个 setter 设定机位与投影参数；在窗口尺寸变化时调用 `aspect_set` 重新同步宽高比；每帧（或每次场景 UBO 更新时）调用 `view_proj_get` 取得矩阵并写入主机可见的场景 UBO 缓冲。
- **向下**：仅依赖项目内就地编入的 `glm`（`Application/Renderer/external/glm/`，版本 1.1.0）与经 `前置头文件包含.h` 传递而来的标准库基础类型（如 `uint32_t`）。**不依赖任何 Vulkan / SDL 头**，故 `相机.h` 可安全地位于渲染层内部且不引入第三方类型。
- **横向**：本模块与场景 UBO 的**布局契约**发生在「管线模块」的 `set 0` 描述符集布局与「着色器模块」的 `场景.vert` 之间；相机与它们之间**没有编译期依赖边**，只有「输出 16 浮点 = mat4」这一**隐式契约**（见 §3.4）。

### 2.4 与相邻模块的职责分界

| 相邻模块 / 组件 | 分界 |
| --- | --- |
| 渲染器门面（`render/Renderer/`，`Renderer::Impl`） | 门面负责持有 `Camera` 实例、设定参数、取得矩阵并写入场景 UBO。本模块**只提供**参数读写与矩阵计算，**不持有** UBO、不持有描述符集、不调用任何 `vk*` 函数，也不知道 UBO 的存在。矩阵「如何被用」完全由门面决定。**本版次第九轮**：门面另提供 `scene_apply`（把 `Scene_Data` 分派到本模块四个 setter）与 `clear_color_set`，并把清屏色由「帧链路内部固定值」改为**门面记录值**；本模块**仍不感知**清屏色与 `Scene_Data`（后者仅是本模块字段的数据载体，由门面消费）。 |
| 管线模块（`render/Pipeline/`，`Pipeline_Context`） | 管线模块把 `set 0` 固化为「场景 UBO（`VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER`，顶点阶段可见）」，并提供 `scene_bind(slot, ubo_buffer)` 把某缓冲绑到该集合。本模块产出的矩阵**恰好**是写入该缓冲的内容，但二者之间无编译期依赖，仅为**布局约定**（16 浮点 ↔ `mat4`）。 |
| 着色器模块（`render/Shader/`，`Shader_Context`）与着色器资源 | 顶点着色器 `Application/Renderer/assets/shaders/场景.vert` 声明 `layout(set = 0, binding = 0) uniform Scene_Buffer { mat4 view_proj; } scene;`。本模块的输出即该 `view_proj` 的值。二者共享 std140 布局约定。 |
| 帧模块（`render/Frame/`，`Frame_Context` / `Frame_Render_Item`） | 帧模块的渲染项 `Frame_Render_Item` 含 `scene_set`（场景 UBO 描述符集句柄）与 `push_constants` / `push_constant_size`。相机矩阵经门面写入 UBO、经 `scene_bind` 进入 `scene_set`；而「模型矩阵」经**推送常量**逐次绘制传入。相机**不产生**推送常量（那是模型矩阵的职责）。 |
| 网格模块（`render/Mesh/`，`Vertex`） | 网格模块定义顶点位置（`vec3`）与纹理坐标（`vec2`）。着色器把 `in_position` 依次乘 `view_proj` 与 `model` 得到裁剪坐标。相机与网格无直接关系，仅在着色器相乘处汇合。 |
| 交换链模块（`render/Swapchain/`） | 交换链提供颜色/深度格式与尺寸。相机**不**直接读交换链尺寸；`aspect` 须由门面在窗口/交换链尺寸变化时**手工**调用 `aspect_set` 同步。**已确证**：门面在 resize / 交换链重建路径上显式同步，共三处——`init` 的 ⑯ 段（取当前交换链尺寸设 `aspect`），以及 `frame_render` 的两条交换链重建路径（`resized_consume` 与 `rebuild_needed` 分支）之后各一次；覆盖初始化与两条重建路径，无遗漏（见 R-SCENE-02）。 |
| 纹理模块（`render/Texture/`） | 与相机无职责交叠（纹理属片元阶段的 `set 1` 采样器）。 |

### 2.5 生命周期与默认参数

`Camera` 的完整生命周期极为简单：

```
构造（Camera(void)，**第十轮起显式定义**：机位 / 注视点 / 视场角 / 近远平面取 `Scene_Data` 默认值，`up` / `aspect` 取本层自有默认）
   → [可选] position_set / target_set / up_set        ← 设定机位与朝向
   → [可选] fov_set / aspect_set / near_far_set       ← 设定透视投影参数
   → [可选] orbit(radians_delta)                       ← 演示用：绕上方向轨道旋转
   → view_proj_get(out16)                             ← 写出「视图 × 投影」（可反复调用）
   → 析构（默认，无资源需释放）
```

- 类**无显式析构**（无动态资源），构造为**显式定义**（第十轮起，见 §3.2.1），故可自由拷贝/赋值（属于「值语义」类型）。这与同层持有 Vulkan 句柄的门面类（普遍 `= delete` 拷贝）形成鲜明对比——本模块是纯值对象。
- 类内成员中仅 `up` / `aspect` 仍带**就地默认值**，其余五项（`position` / `target` / `fov` / `near_plane` / `far_plane`）的成员初始化器**已删除**（第十轮起改由构造体从 `Scene_Data` 取，见 §5.3）；因此默认构造后立即可调用 `view_proj_get`，得到「机位在 `+Z` 轴 3 单位处、注视原点、上方向 `+Y`、视场角 60°、宽高比 16:9、近 0.1、远 100」的标准机位矩阵。
- 状态机只有一态：**始终可用**。没有任何 `valid()` / `build()` / `destroy()` 之类的生命周期方法。
- 参数 setter **不做任何取值校验**（不校验 `fov > 0`、`near_plane > 0`、`near_plane < far_plane`、上方向与视线不平行等），非法参数会直接进入矩阵计算并可能产生退化矩阵（见 §6.9）。

### 2.6 「Scene」目录的现状说明

与其它渲染层子目录（皆含「对外头 `XXX.h` ＋ 多编译单元 `core/`」）不同，`Scene/` 目录在本版次**只包含相机一个功能**：

- 没有 `Scene_Context` / `场景上下文` 这类「场景门面」——即没有负责「收集渲染项、持有相机、持有光照/环境」的对象。
- 没有光照、投影相机（正交）、多相机管理等其它场景概念。
- `core/` 下只有 `相机.cpp` 一个编译单元。

因此，「渲染层-场景与相机」在本版次实质等价于「渲染层-相机」。本模块与「渲染层-渲染器」门面之间存在「谁持有相机、谁负责每帧把矩阵写进 UBO」的分工，从源码可见门面才是驱动方（`Scene/` 内不含任何 UBO/描述符逻辑）。

### 2.7 场景描述数据化（本版次第九轮新增）

本模块在本版次新增一个 **Vulkan-free 公共头** `场景数据.h`：定义聚合类型 `engine::Scene_Data`，把「相机参数（位置 / 注视点 / 视场角 / 近远平面）＋ 清屏色」收拢为一个**可整体提交的场景描述**，供上层以「数据驱动」方式一次性设置场景状态（替代逐项调用四个相机 setter ＋ 单独设清屏色）。该头与渲染层其它语义头（`网格数据.h` / `管线数据.h` / `纹理数据.h` / `材质数据.h`）**同构**——只放公共面需要暴露的引擎语义类型，**不含任何 Vulkan / VMA / SDL3 / glm 类型**，由门面公共头 `渲染器.h` 引用。

- **归属**：`Scene_Data` 是**纯数据聚合**（无成员函数），本模块**不消费**它——真正「应用」它的是门面（`scene_apply` 把其字段分别转给 `Camera` 的四个 setter 与门面自身的清屏色记录）。故本模块**仍无** `Scene_Context` 之类的场景门面（见 §2.6），`Camera` 仍是唯一对外类型；`Scene_Data` 只是与相机字段一一对应的数据载体。
- **默认值来源收敛（第十轮）**：`position = {0,0,3}`、`target = {0,0,0}`、`fov = 1.0472f`、`near_plane = 0.1f`、`far_plane = 100.0f`、`clear_color = {0.05,0.05,0.10,1.0}`；**第十轮起** `Camera` 默认构造改为**从本结构取**（见 §3.2.1 / §5.3），默认值**单一来源**、不再两处硬编码——`R-SCENE-07` **结案**（见附录）。
- **清屏色归属变化**：清屏色此前由帧链路内固定字面量提供，本版次改为由**门面记录**（`Renderer::Impl::clear_color[4]`），`frame_render` 三条渲染路径共用该值（详见《渲染层-渲染器》§6.16）；本模块只提供 `Scene_Data::clear_color` 这一数据字段。**第十轮起**门面 `scene_apply`（《渲染层-渲染器》§3.4.44）另新增**参数校验**、`clear_color_set`（§3.4.45）新增**分量钳制**——该二项属门面接线，详见《渲染层-渲染器》§3.4.44 / §3.4.45 / §6.17（同一事实只写一处，本文不重述细节）。
- **正交投影字段（第二十轮）**：`Scene_Data` 另含 `bool ortho = false`（默认透视）与 `float ortho_height = 2.0f`（正交垂直可见高度，世界单位）。`scene_apply` 将其转给 `Camera::ortho_set`；`ortho` 为真且高度非正时，整次场景描述被拒绝（见《渲染层-渲染器》§3.4.44）。
- **光照字段（第二十九轮）**：`Scene_Data` 另含 `float light_direction[3] = {0,0,-1}`（光传播方向）、`float light_color[3] = {1,1,1}`、`float light_intensity = 1.0f`、`float light_ambient = 0.0f`。`scene_apply` 统一转交门面 `light_set`（非法由后者整次拒绝）；默认值即**满照**，故应用默认 `Scene_Data` 的画面与引入光照前逐通道一致。本模块仍**不消费**光照字段（不属相机职责），仅作为数据载体。
- **投影分支（第二十轮）**：`Camera::view_proj_get` 内 `ortho == true` 时用 `glm::ortho(-half_w, half_w, -half_h, half_h, near, far)`（`half_h = ortho_height/2`、`half_w = half_h × aspect`），随后同样做 `proj[1][1] *= -1`（Vulkan Y 向下）；`false` 时沿用 `glm::perspective(fov, ...)`。两者共享同一视图矩阵与同一输出格式，故上层无需区分模式。
- **相机位置读取（第三十一轮）**：新增 `void position_get(float out[3]) const`，逐分量写出私有 `position`；门面每帧用它把相机世界位置写入场景 UBO（`camera_pos`，offset 112），供片元计算 Blinn-Phong 的视线方向 `V`。
- **点光源组与高光字段（第三十三轮）**：`Scene_Data` 另含 `uint32_t light_count`（0..4）、`float point_light_position[4][3]`、`point_light_color[4][3]`（默认白）、`point_light_radius[4]`（默认 5）、`point_light_intensity[4]`（默认 1）、`specular_intensity`（默认 0）与 `specular_shininess`（默认 16）。`scene_apply` 先按方向光重置（`light_set` 清空点光源），再逐条 `light_add_point`（单条非法只跳过该条并告警；`light_count > 4` 只登记前 4 盏），最后 `specular_set`。默认值下画面与引入点光源前一致。
- **聚光灯组字段（第三十五轮）**：`Scene_Data` 另含 `uint32_t spot_light_count`（0..4）、`float spot_light_position[4][3]`、`spot_light_direction[4][3]`（默认 -Z，光源 → 被照区域）、`spot_light_color[4][3]`（默认白）、`spot_light_radius[4]`（默认 5）、`spot_light_intensity[4]`（默认 1）、`spot_light_inner_deg[4]`（默认 15）与 `spot_light_outer_deg[4]`（默认 30）。`scene_apply` 在点光源组之后逐条 `light_add_spot`；两组共用 4 盏上限，超限或单条非法的只跳过该条。默认 0 盏，故本模块仍**不消费**灯光字段（仅数据载体）。
- **衰减模式字段（第三十七轮）**：`Scene_Data` 另含 `uint32_t attenuation_mode = 0`（0 = 线性、1 = 平方反比）。`scene_apply` 在末尾调用 `light_attenuation_set`；非法值由门面拒绝并告警，不影响同次应用的其余字段。
- **距离雾字段（第三十九轮）**：`Scene_Data` 另含 `float fog_color[3]`（默认深蓝黑）、`float fog_density`（默认 0 = 关闭）、`float fog_start`（默认 1）、`float fog_end`（默认 10）。`scene_apply` 末尾透传 `fog_set`；非法参数由门面整次忽略，不影响同次应用的其余字段。
- **环境光颜色字段（第四十一轮）**：`Scene_Data` 另含 `float ambient_color[3] = {1,1,1}`（默认白 = 与标量环境光等价）。`scene_apply` 在雾之后调用 `ambient_color_set`；非法分量由门面整次忽略。
- **半球环境光与补光字段（第四十七轮）**：`Scene_Data` 另含 `ambient_ground[3]` / `ambient_hemisphere` / `fill_direction[3]` / `fill_color[3]` / `fill_intensity`；`scene_apply` 依次调用 `ambient_ground_set` 与 `light_fill_set`（默认 `hemisphere = 0`、`fill_intensity = 0` 即关闭，画面与引入前逐字节一致）。
- **逐盏高光缩放字段（第四十九轮）**：`Light_Data` / `Scene_Data` 另含 `point_specular[4]` / `spot_specular[4]`（默认 `{1,1,1,1}`）；`scene_apply` 经 `light_add_point` / `light_add_spot` 末参透传；0 = 该灯不产生高光，1 = 跟随全局高光强度，取值 0..100。
- **方向光 / 补光高光缩放字段（第五十轮）**：`Light_Data` / `Scene_Data` 另含 `directional_specular` / `fill_specular`（默认 1，0..100）；`scene_apply` 经 `directional_specular_set` 与 `light_fill_set` 末参透传。
- **逐盏高光光泽度字段（第五十一轮）**：`Light_Data` / `Scene_Data` 另含 `point_shininess[4]` / `spot_shininess[4]`（默认 0 = 跟随全局，>0 为该灯自身光泽度 1..1000）；经两入口末参透传。
- **阴影字段（第五十二轮）**：`Light_Data` / `Scene_Data` 另含 `int shadow_enabled = 0`（0 = 关闭）与 `float shadow_bias = 0.003f`；`scene_apply` 在光照字段之后调用 `shadow_enable_set(light.shadow_enabled != 0)` 与 `shadow_bias_set(light.shadow_bias)`，扁平包装先把 `scene.shadow_enabled` / `scene.shadow_bias` 抄入 `Light_Data` 再转发。默认关闭即与引入前逐字节一致。
- **阴影软度与强度字段（第五十三轮）**：`Light_Data` / `Scene_Data` 另含 `float shadow_softness = 0.0f`（0 = 单点硬边、≥0.5 = 3×3 PCF）与 `float shadow_strength = 1.0f`（0 = 阴影无效、1 = 全遮蔽）；`scene_apply` 经 `shadow_softness_set` / `shadow_strength_set` 透传，扁平包装同步抄入 `Light_Data`。默认值与第五十二轮一致。
- **阴影分辨率字段（第五十四轮）**：`Light_Data` / `Scene_Data` 另含 `int shadow_resolution = 1024`（仅 512 / 1024 / 2048）；`scene_apply` 经 `shadow_resolution_set` 透传，扁平包装抄入 `Light_Data`；非法值由门面整次忽略。

### 3.2 逐接口说明

#### 3.2.1 `Camera(void)`（第十轮起为显式定义，不再 `= default`）

- **签名**：`Camera(void);`（**第十轮起显式定义**；此前为 `Camera(void) = default;`）
- **参数**：无。
- **返回值**：无。
- **行为**：函数体内先取 `const Scene_Data defaults{};`，再依次调用 `position_set(defaults.position[0..2])` / `target_set(defaults.target[0..2])` / `fov_set(defaults.fov)` / `near_far_set(defaults.near_plane, defaults.far_plane)`——即「默认机位 / 注视点 / 视场角 / 近远平面」**全部取自 `Scene_Data` 的默认值**；`up`（`{0,1,0}`）与 `aspect`（`16/9`）仍取**本层自有**类内默认（`Scene_Data` 未涵盖这两项）。
- **约束**：无。构造后对象立即可用，无需任何 `build`。
- **注意**：默认构造语义仍为「机位在 `+Z` 轴 3 单位处、注视世界原点」，对应一个「从正前方观察原点」的初始视角——**对外行为与收敛前一致**（视场角 60°、近远 0.1 / 100 均不变）。
- **设计含义**：默认值**收敛为 `Scene_Data` 单一来源**，消除「`Scene_Data` 默认值」与「`Camera` 私有默认值」两处硬编码的漂移风险，**处置结案 `R-SCENE-07`**（见 §2.7 / §5.3 与附录）。

#### 3.2.2 `void position_set(float x, float y, float z)`

- **签名**：`void position_set(float x, float y, float z);`
- **参数**：
  - `x`：相机位置的世界坐标 X 分量；
  - `y`：相机位置的世界坐标 Y 分量；
  - `z`：相机位置的世界坐标 Z 分量。
- **返回值**：无（`void`）。
- **行为**：把三个分量依次写入私有成员 `position[0..2]`（见 `core/相机.cpp`）。
- **约束**：不做任何校验；不检查与注视点是否重合（重合会导致 `lookAt` 的视线方向退化为零向量，见 §6.9）。
- **线程**：无同步保护；约定由单一调用方（门面）串行使用（见 §6.10）。

#### 3.2.3 `void target_set(float x, float y, float z)`

- **签名**：`void target_set(float x, float y, float z);`
- **参数**：
  - `x`：注视点的世界坐标 X 分量；
  - `y`：注视点的世界坐标 Y 分量；
  - `z`：注视点的世界坐标 Z 分量。
- **返回值**：无。
- **行为**：把三个分量依次写入私有成员 `target[0..2]`。
- **约束**：不做校验；`target` 与 `position` 相同会导致视图矩阵退化。

#### 3.2.4 `void up_set(float x, float y, float z)`

- **签名**：`void up_set(float x, float y, float z);`
- **参数**：
  - `x`：上方向向量的 X 分量；
  - `y`：上方向向量的 Y 分量；
  - `z`：上方向向量的 Z 分量。
- **返回值**：无。
- **行为**：把三个分量写入私有成员 `up[0..2]`。该向量同时被 `orbit` 用作旋转轴（见 §3.2.8）。
- **约束**：
  - 约定传入的是「大致朝上的方向」；`lookAt` 会自行正交化。`orbit` 现已**在内部对 `up` 归一化**（长度 `≤ 0` 时退化为默认上方向 `(0,1,0)`），故**不要求** `up` 为单位向量（见 §6.8）。
  - 若为零向量或与视线平行，`lookAt` 产生的右向量退化，视图矩阵非法——**注意**：此退化只发生在 `view_proj_get` 的 `lookAt`；`orbit` 的零长度 `up` 已被归一化分支兜底（见 §6.8）。

#### 3.2.5 `void fov_set(float radians)`

- **签名**：`void fov_set(float radians);`
- **参数**：`radians` —— **竖直**视场角，单位为**弧度**（非角度）。
- **返回值**：无。
- **行为**：写入私有成员 `fov`。
- **约束**：
  - 该值直接传给 `glm::perspective` 的 `fovy` 形参，故为竖直视场角。
  - 项目在编译期定义了 `GLM_FORCE_RADIANS`（`Application/Renderer/CMakeLists.txt`），`glm::perspective` 的 `fovy` 期望弧度，与本参数单位一致。
  - 不做校验；`fov ≤ 0` 或 `fov ≥ π` 会产生退化/错误投影（`tan` 项异常）。
  - 默认值 `1.0472f` 约等于 60°（`π/3 ≈ 1.0471976`）。

#### 3.2.6 `void aspect_set(float aspect)`

- **签名**：`void aspect_set(float aspect);`
- **参数**：`aspect` —— 宽高比，即「视口宽度 / 视口高度」。
- **返回值**：无。
- **行为**：写入私有成员 `aspect`（实现内以 `this->aspect = aspect;` 显式限定成员，避免与形参同名遮蔽）。
- **约束**：
  - 约定由调用方在窗口/交换链尺寸变化时**手工**同步为 `宽/高`；本模块**不**感知视口尺寸。
  - 不做校验；`aspect ≤ 0` 会产生退化投影（`glm::perspective` 内部还有 `assert`，在 Debug 下可能触发断言，见 §6.9）。
  - **已确证**：门面在 resize / 交换链重建路径上显式同步调用本接口，共三处——`init` 的 ⑯ 段、`frame_render` 的 `resized_consume` 与 `rebuild_needed` 两条重建路径之后各一次；覆盖初始化与两条重建路径，无遗漏（见 R-SCENE-02）。
  - 默认值 `16.0f / 9.0f`。

#### 3.2.7 `void near_far_set(float near_plane, float far_plane)`

- **签名**：`void near_far_set(float near_plane, float far_plane);`
- **参数**：
  - `near_plane`：近裁剪平面到相机的距离（沿视线方向，正值）；
  - `far_plane`：远裁剪平面到相机的距离（正值）。
- **返回值**：无。
- **行为**：分别写入私有成员 `near_plane`、`far_plane`（实现内以 `this->near_plane` / `this->far_plane` 显式限定成员）。
- **约束**：
  - 不做校验；约定 `0 < near_plane < far_plane`。若 `near_plane ≥ far_plane`，`glm::perspective` 产生退化矩阵；若 `near_plane ≤ 0`，矩阵无意义。
  - 两者共同决定投影矩阵的深度映射（`perspectiveRH_ZO` 的第 3、4 列，见 §6.3）。
  - 默认 `near = 0.1f`、`far = 100.0f`。

#### 3.2.8 `void orbit(float radians_delta)`

- **签名**：`void orbit(float radians_delta);`
- **参数**：`radians_delta` —— 绕「上方向」旋转的角度增量（弧度）。
- **返回值**：无。
- **行为**：以「位置相对注视点的偏移向量」为被旋转向量、以当前 `up`（**先取长度并归一化**：长度 `≤ 0` 时退化为默认上方向 `(0,1,0)`，否则 `up_axis /= up_length`）为旋转轴，用 `glm::rotate` 构造旋转并按 `rotation * offset` 旋转偏移，再把旋转后的偏移加回 `target` 得到**新的位置**，写回 `position[0..2]`。**注视点与上方向本身不变**。
- **约束**：
  - 语义为「相机围绕注视点在球面上滑动」，距离不变。
  - `up` 取自成员并在内部**归一化**后作为旋转轴：先取 `up_length = glm::length(up_axis)`，长度 `≤ 0` 时退化为默认上方向 `(0,1,0)`（避免除零），否则 `up_axis /= up_length`。`glm::rotate` 会按轴长度缩放角度，故必须归一化；归一化后实际旋转量只由 `radians_delta` 决定，**不再要求 `up` 为单位向量**。
  - 刷新的是位置；`view_proj_get` 下次调用时用更新后的位置重算视图矩阵。
  - 源码注释标注「供演示」，即该接口是演示/测试性质的便捷方法，非完整相机控制器（无 pitch/yaw/任意轴/自由飞行）。
  - **有意保持最小实现**：本版次为最小可用的演示相机（源码注释已标「供演示」），无扩展为完整控制器的源码依据；`orbit` 仅绕上方向旋转并改写位置，不处理鼠标/键盘输入（输入属平台层与上层业务）。后续是否扩展（平移、缩放、俯仰、输入绑定）取决于上层需求，当前明确保持最小实现（见 R-SCENE-04）。

#### 3.2.9 `void view_proj_get(float out[16]) const`

- **签名**：`void view_proj_get(float out[16]) const;`
- **参数**：`out` —— 长度 16 的 `float` 数组，作为输出缓冲区；**由调用方分配**，写入的是**列主序**的 `view_proj`。
- **返回值**：无（结果经 `out` 返回）。
- **行为**（详见 §6.2–§6.6）：
  1. 用 `glm::lookAt(position, target, up)` 构造**视图矩阵** `view`；
  2. 用 `glm::perspective(fov, aspect, near_plane, far_plane)` 构造**透视投影矩阵** `proj`（在 `GLM_FORCE_DEPTH_ZERO_TO_ONE` 下为 `perspectiveRH_ZO`）；
  3. 执行 `proj[1][1] *= -1.0f` 做 **Y 翻转**（Vulkan NDC Y 向下）；
  4. 计算 `view_proj = proj * view`（**投影左乘视图**）；
  5. 用 `glm::value_ptr(view_proj)` 取列主序内存首地址，循环 16 次拷贝到 `out[0..15]`。
- **约束**：
  - **常量语义**：`const` 成员函数，不修改对象状态（`orbit` 等修改须显式先调用）。
  - **缓冲区所有权**：`out` 由调用方提供，本函数不分配、不释放；长度必须 ≥ 16。
  - **不校验空指针（明确约定）**：`view_proj_get` 是纯值输出接口，无失败语义、不持有资源，故不设空指针/长度校验与返回码——此为「调用方保证缓冲区有效」的**明确约定**，可接受。调用方（门面）自持固定 16 元素缓冲；若需更强健壮性可加有限断言，但会与「无失败语义」的总风格不符，当前有意保持现状（见 R-SCENE-01）。
  - **输出为裸 `float` 数组**而非 `glm::mat4`：刻意保持头文件不暴露 `glm` 类型（见 §6.1）。
  - 无 `noexcept` 标注；实现内不含任何抛异常语句（`glm` 在纯数学路径上不抛），故实际不抛。

### 3.4 隐含契约：与着色器 `set 0` 场景 UBO 的逐字节对应

这是本模块对外最重要的**隐式契约**（无编译期依赖边，仅靠约定成立）：

| 相机侧 | 着色器侧（`assets/shaders/场景.vert`） | 布局 |
| --- | --- | --- |
| `view_proj_get` 输出 `out[16]`（列主序） | `layout(set = 0, binding = 0) uniform Scene_Buffer { mat4 view_proj; } scene;` | std140 |
| 16 × `float` = 64 字节 | `mat4` = 4 列 × `vec4` = 64 字节 | 无填充 |
| 起始偏移 0 | `view_proj` 偏移 0，对齐 16 | 一致 |

- **std140 对齐分析**：`mat4` 在 std140 下按「列向量 `vec4`」排布，每列 16 字节、整体 64 字节、起始需 16 字节对齐。因场景 UBO 只有这一个字段且位于偏移 0，**不存在填充或跨列对齐问题**；相机的 16 个 `float` 顺序（`m[0]` 列 0 的 x/y/z/w，`m[1]` 列 1 ……）与 std140 要求的列主序**完全一致**。
- **着色器使用方式**：`gl_Position = scene.view_proj * object.model * vec4(in_position, 1.0);`
  - `scene.view_proj` 即本模块输出；
  - `object.model` 为**对象推送常量**（`layout(push_constant) uniform Push_Object { mat4 model; }`，64 字节），**不属本模块**；
  - 因是列向量约定，`view_proj` 必须在模型矩阵**左侧**相乘，且 `view_proj = proj * view`（投影左乘视图）才正确（见 §6.5）。
- **管线侧对齐**：`Pipeline_Context` 的 `set 0` 为 `UNIFORM_BUFFER`（顶点阶段可见），推送常量范围 `offset = 0 / size = 64`（模型矩阵），与本契约一致。
- **契约形式（已确证）**：该「16 浮点 ↔ `mat4`」对应关系由「std140 布局 ＋ 列主序」两项约定成立，源码中**无** `static_assert` / 共享常量断言（见 R-SCENE-06）。原因是此契约跨「C++ 矩阵写法」与「GLSL std140 布局」两侧、涉及 GLSL 侧，无法用单一 `static_assert` 覆盖；可选的强化手段是在着色器头注释中显式声明「列主序、无填充」，或在 C++ 侧断言 `sizeof(float[16]) == 64` 作最低保障，当前有意保持约定式实现。

### 5.3 内部数据结构（`Camera` 私有字段）

`Camera` 无嵌套结构体、无内部类、无内部类型；数据即下列七个私有字段：

| 字段 | 类型 | 默认值 | 含义 | 备注 |
| --- | --- | --- | --- | --- |
| `position` | `float[3]` | 无成员初始化器；构造自 `Scene_Data.position`（`{0,0,3}`） | 相机世界坐标位置 | 供 `lookAt` 的 `eye`，供 `orbit` 读写 |
| `target` | `float[3]` | 无成员初始化器；构造自 `Scene_Data.target`（`{0,0,0}`） | 注视点（观察目标） | 供 `lookAt` 的 `center`，供 `orbit` 作为旋转中心 |
| `up` | `float[3]` | `{0.0f, 1.0f, 0.0f}`（本层自有；`Scene_Data` 未涵盖） | 上方向向量 | 供 `lookAt` 的 `up`，供 `orbit` 作为旋转轴 |

| `aspect` | `float` | `16.0f / 9.0f`（本层自有；`Scene_Data` 未涵盖） | 宽高比（宽/高） | 供 `glm::perspective` 的 `aspect` |

| `far_plane` | `float` | 无成员初始化器；构造自 `Scene_Data.far_plane`（`100.0f`） | 远平面距离 | 供 `glm::perspective` 的 `zFar` |

- **默认值来源（第十轮收敛）**：`position` / `target` / `fov` / `near_plane` / `far_plane` 五项的**成员初始化器已删除**，其默认值由 `Camera(void)` 显式定义体从 `const Scene_Data defaults{};` 逐项 `position_set` / `target_set` / `fov_set` / `near_far_set` 取（见 §3.2.1）；仅 `up` / `aspect` 因 `Scene_Data` 未涵盖而保留本层类内默认。默认值由此**只有 `Scene_Data` 一处硬编码**（`R-SCENE-07` 结案）。
- 全部为 `float`/`float[3]` **标量存储**，不缓存任何矩阵——即每个 `view_proj_get` 都**重新计算** `view`、`proj` 与乘积。这是「以参数真源为准、避免缓存失效」的取舍（见 §6.1）。
- 组合关系：
  - `position` / `target` / `up` 三个 `float[3]` 描述**相机外参**（机位与朝向），决定**视图矩阵**。
  - `fov` / `aspect` / `near_plane` / `far_plane` 四个 `float` 描述**相机内参**，决定**投影矩阵**。
  - 两类参数在 `view_proj_get` 内汇合：外参经 `lookAt`、内参经 `perspective`，最终乘积输出。
- **存储为标量而非矩阵的设计含义**：字段是「真源（source of truth）」，矩阵是「派生量」。每次调用 `view_proj_get` 都从标量重新推导矩阵，避免「改了参数忘了更新缓存矩阵」的失效问题。代价是每次调用都要重算三角函数与两次矩阵构造——对每帧一次的调用频率而言可忽略（见 §6.1）。

### 5.5 `局部命名空间使用.h` 的做法说明

渲染层各模块普遍在 `局部命名空间使用.h` 中集中 `using` 本模块用到的标准库/引擎类型，使 `.cpp` 内代码可省去命名空间前缀（对应《agent开发指南》的「局部命名空间使用」约定）。本模块的情况是：

- `局部命名空间使用.h` **无任何 `using` 声明**，仅 `#pragma once` ＋ `#include "相机.h"` ＋ **第十轮新增 `#include "场景数据.h"`** 并附注释（注释分「基本类型别名」小节，正文说明「相机实现仅使用 glm，无额外标准库类型需要引入」）。原因是相机实现只用到 `glm`（在 `.cpp` 内以 `<glm/...>` 全限定包含）与 `uint32_t`（由预编译头传递），**没有需要提取到模块别名的自定义类型**。
- 因此 `.cpp` 内直接写 `glm::vec3` / `glm::mat4` 等前缀，未做 `using` 简化；这符合本模块「依赖极少」的实际。
- 该文件仍保留，是为了与渲染层其它模块的目录结构保持一致（`.cpp` 统一以包含 `局部命名空间使用.h` 开头），便于机械套用「标准模块架构」。

## 六、模块设计/实现细节

### 6.1 相机模型的取舍：位置 / 注视点 / 上方向（而非欧拉角或四元数）

`Camera` 采用的相机表示是「**eye / center / up** 三点式」（即 `lookAt` 的入参形式），而不是常见的「位置 ＋ 欧拉角（pitch/yaw/roll）」或「位置 ＋ 四元数 ＋ 前向」。

- **设计意图**：这是渲染层「演示/最小可用」阶段的最省事模型——所有参数都能一对一映射到 `glm::lookAt` 的入参，矩阵推导零转换成本；上层的「要看向哪里」以「给一个注视点」表达，符合人类直觉。
- **代价**：无法直接表达滚转（roll，即绕视线自身的旋转，只能靠 `up` 间接控制）；自由飞行需要每帧自行改写 `target`；`orbit` 的旋转轴被 `up` 绑死（见 §6.8）。
- **真源为标量、矩阵为派生**：不缓存 `view`/`proj`/`view_proj`，每调用必重算。理由是「避免缓存失效」优于「省几次三角运算」——本模块的调用频率是「每帧一次」量级，重算成本可忽略。

### 6.2 视图矩阵推导（`glm::lookAt`）

`view_proj_get` 的第一步：

```cpp
glm::mat4 view = glm::lookAt(
    glm::vec3(position[0], position[1], position[2]),
    glm::vec3(target[0],   target[1],   target[2]),
    glm::vec3(up[0],       up[1],       up[2]));
```

- `glm::lookAt` 生成的是**右手坐标系**的视图矩阵（eye space 中相机看向 `-Z`）。
- 算法分步：
  1. `f = normalize(center - eye)`：前向（视线方向，指向注视点）；
  2. `s = normalize(cross(f, up))`：右向量（`f` 与 `up` 叉乘、归一化）——**注意叉乘方向为 `f × up`，`glm` 内部取 `s = normalize(cross(f, up))`**，此步隐含「正交化 `up`」的效果；
  3. `u = cross(s, f)`：真正的正交上向量（已与视线正交）；
  4. 平移部分为 `-dot(s, eye)`、`-dot(u, eye)`、`dot(f, eye)`；
  5. 视图矩阵为「旋转（行是 `s`、`u`、`-f`）＋ 平移」的组合（列主序存储）。
- **退化条件**：若 `center == eye`（视线为零向量），或 `up` 与视线平行（`cross(f, up)` 为零），则 `s` 归一化除零，视图矩阵非法。源码**不校验**这两点（见 §6.9）。
- **不要求 `up` 正交或单位**：`lookAt` 会经步骤 2、3 自行正交化，故传入任意非退化 `up` 均能得到合法正交基。

### 6.3 透视投影矩阵推导（`glm::perspective`，RH_ZO）

第二步：

```cpp
glm::mat4 proj = glm::perspective(fov, aspect, near_plane, far_plane);
```

- 因编译期定义了 `GLM_FORCE_DEPTH_ZERO_TO_ONE`（未定义 `GLM_FORCE_LEFT_HANDED`），`GLM_CONFIG_CLIP_CONTROL` 取 `RH_ZO`，故 `glm::perspective` 派发到 **`perspectiveRH_ZO`**（`external/glm/ext/matrix_clip_space.inl`）。
- 其生成矩阵（列主序）各元素为：

```text
perspectiveRH_ZO(fovy, aspect, zNear, zFar):
  tanHalfFovy = tan(fovy / 2)
  m[0][0] = 1 / (aspect * tanHalfFovy)     // 列0.x
  m[1][1] = 1 / tanHalfFovy                // 列1.y
  m[2][2] = zFar / (zNear - zFar)          // 列2.z
  m[2][3] = -1                             // 列2.w  （透视除法来源）
  m[3][2] = -(zFar * zNear) / (zFar - zNear) // 列3.z（深度平移）
  其余元素 = 0
```

- 逐项含义：
  - `m[0][0]`：水平缩放，等于 `1 / (aspect · tan(fovy/2))`，体现竖直视场角 `fovy` 与宽高比 `aspect` 的配合；
  - `m[1][1]`：竖直缩放，等于 `1 / tan(fovy/2)`；
  - `m[2][2]` / `m[3][2]`：深度映射，把 `[-near, -far]`（右手相机看向 `-Z`）映射到 `[0, 1]`（`ZO`）；
  - `m[2][3] = -1`：使 `w_clip = -z_eye`，产生透视除法。
- **退化条件**：`aspect ≈ 0`（`glm` 内置 `assert`）、`fovy` 取 0 或 π（`tan(0)=0` 或 `tan(π/2)` 无穷）、`near == far`（`zFar - zNear = 0`）。源码不校验。
- **单位一致性**：`fov_set` 写入的是弧度，`GLM_FORCE_RADIANS` 使 `glm` 期望弧度——契约一致。若调用方误传角度值（如 `60`），将得到极端视场角（`tan(30)` 而非 `tan(π/6)`）。

### 6.4 Y 翻转（Vulkan NDC Y 向下）

第三步（源码注释标记为「K1」）：

```cpp
proj[1][1] *= -1.0f;
```

- **原因**：OpenGL 与 Vulkan 的标准化设备坐标（NDC）Y 轴朝向相反——OpenGL 的 NDC Y 向上（`+1` 在屏幕顶部），Vulkan 的 NDC Y 向下（`+1` 在屏幕底部）。`glm` 沿 OpenGL 约定生成投影，故需把投影矩阵的 Y 缩放项取负，使最终 NDC 的 Y 朝下，符合 Vulkan。
- **只翻转 `m[1][1]`**：`m[1][1]` 是唯一影响 Y 的项（该行其余为 0），取负即整体上下翻转。
- **与「负视口高度」的替代关系（已确证）**：修正 Vulkan Y 朝向常见两种做法——(a) 翻转投影矩阵 `m[1][1]`；(b) 在 `VkViewport` 里用**负高度** `height = -h` 并相应下移 `y`。二者**择一即可，同时使用会抵消**。本模块采用做法 (a)；**已确证**命令录制侧采用**正高度视口**——`VkViewport` 高度取 `static_cast<float>(extent.height)`（正值），与 `proj[1][1] *= -1` 共同完成「GLM（Y 向上）→ Vulkan NDC（Y 向下）」的坐标对齐。视口正高度在帧/门面的命令录制处设置，本模块只负责矩阵翻转（见 R-SCENE-03）。
- **对深度的影响**：翻转只作用于 Y 行，不改变 `m[2][*]` 与 `m[3][*]`，故不影响深度映射与透视除法。

### 6.5 组合顺序：`view_proj = proj * view`

第四步：

```cpp
glm::mat4 view_proj = proj * view;
```

- **为什么是 `proj * view`**：`glm` 采用**列向量约定**（矩阵右乘列向量），即 `v_clip = M · v`。世界坐标到裁剪空间为 `clip = proj · (view · world) = (proj · view) · world`，故组合矩阵为 `proj * view`（先视图、后投影，写成乘法时投影在左）。
- **与着色器的对齐**：着色器写 `gl_Position = scene.view_proj * object.model * vec4(in_position, 1.0)`——`view_proj` 在 `model` 左侧，符合「先模型、再视图、后投影」的链式顺序。若误写成 `view * proj`，则平移/缩放顺序颠倒，画面错误。
- **预乘的收益**：上层与着色器每帧只做「`view_proj` × `model`」一次 4×4 乘法，而非「`view` × `model` 再 `proj` × …」两次。

### 6.6 列主序输出与 UBO 写入

第五步：

```cpp
const float* data = glm::value_ptr(view_proj);
for (uint32_t index = 0; index < 16; ++index)
    out[index] = data[index];
```

- `glm::value_ptr` 返回矩阵的**列主序**内存首地址（`glm::mat4` 内部即 `float[16]`，列主序，与 GLSL/Vulkan 一致）。循环逐元素拷贝到 `out`。
- **为什么是列主序**：GLSL/Vulkan 的 `mat4` 也按列主序解读；UBO 中的 64 字节直接落到 `mat4` 的 4 列（每列 `vec4`），顺序为 `m[0][0..3]`、`m[1][0..3]`、`m[2][0..3]`、`m[3][0..3]`。相机输出与此逐字节一致（见 §3.4）。
- **为什么用裸 `float[16]` 而不是返回 `glm::mat4`**：保持 `相机.h` 不暴露 `glm` 类型，从而避免把 `glm` 带进渲染层公共头的包含面。调用方拿到的是可直接 `memcpy` 进 UBO 映射内存的 64 字节。
- **无转置**：因输出与 GLSL 列主序一致，**不需要转置**；若某处强行转置会得到错误的矩阵（常见易错点，见 §6.9）。

### 6.7 与推送常量的分工

相机只负责**场景级常量**（`view_proj`，逐帧一次），而**对象级常量**（`model`，逐次绘制）由门面经**推送常量**传入：

| 常量 | 产生方 | 通道 | 更新频率 | 字节 |
| --- | --- | --- | --- | --- |
| `view_proj`（视图×投影） | **本模块** `Camera::view_proj_get` | 场景 UBO（`set 0`，`UNIFORM_BUFFER`） | 每帧 / 每场景 | 64 |
| `model`（模型矩阵） | 门面 / 调用方 | 推送常量（`push_constant`，顶点阶段，offset 0） | 每次绘制 | 64 |

- 分工理由：`view_proj` 对一帧内所有对象相同，放 UBO 便于一次上传、按帧槽轮转（避免每帧重建描述符集）；`model` 随对象变化，放推送常量避免为每个对象准备 UBO 与描述符集。
- 相机**不感知**推送常量，也不感知对象；它只产出场景级常量。

### 6.8 `orbit` 的实现细节与局限

```cpp
glm::vec3 offset(position[0]-target[0], position[1]-target[1], position[2]-target[2]);
glm::vec3 up_axis(up[0], up[1], up[2]);
float up_length = glm::length(up_axis);
if (up_length <= 0.0f)
    up_axis = glm::vec3(0.0f, 1.0f, 0.0f);
else
    up_axis /= up_length;
glm::mat4 rotation = glm::rotate(glm::mat4(1.0f), radians_delta, up_axis);
glm::vec3 rotated = glm::vec3(rotation * glm::vec4(offset, 0.0f));
position[0] = target[0] + rotated.x;
position[1] = target[1] + rotated.y;
position[2] = target[2] + rotated.z;
```

分步解读：

1. `offset = position - target`：位置相对注视点的偏移（相机在「以注视点为中心」的局部坐标下的位置）。
2. `up_axis = up` 后取 `up_length = glm::length(up_axis)`：旋转轴取自当前 `up`，**先归一化**——若 `up_length <= 0.0f` 则退化为默认上方向 `(0.0f, 1.0f, 0.0f)`（避免除零），否则 `up_axis /= up_length`。原因：`glm::rotate` 会按轴长度缩放角度，故必须归一化。
3. `glm::rotate(mat4(1), radians_delta, up_axis)`：绕 `up_axis` 旋转 `radians_delta` 弧度的 4×4 旋转矩阵。
4. `rotated = rotation * vec4(offset, 0)`：以 `w = 0` 让旋转**只作用于方向分量**（不含平移）。
5. `position = target + rotated`：把旋转后的偏移加回注视点，得到新的机位。

**关键性质与局限**：

- **距离不变**：|`rotated`| = |`offset`|，相机在过 `target`、垂直于 `up` 的平面上沿圆轨道滑动。
- **不改变 `target` 与 `up`**：只改位置，故「看向注视点」的关系保持。
- **`up` 已在内部归一化（本轮已修）**：原实现直接以 `up` 原值作旋转轴，而 `glm::rotate` 按轴长度缩放角度（按 `axis` 原样代入 Rodrigues 公式，轴长度成比例影响旋转量），若上层传入非单位 `up`，实际旋转角会偏离 `radians_delta`。本轮已在 `orbit` 内先取 `up_length = glm::length(up_axis)`，长度 `<= 0.0f` 时退化为默认上方向 `(0,1,0)`（避免除零），否则 `up_axis /= up_length` 归一化；归一化后旋转量只由 `radians_delta` 决定，**不再依赖「上层保证 `up` 为单位向量」的隐式约定**（见 R-SCENE-05）。
- **旋转轴绑死 `up`**：只能绕「上方向」水平环绕，无法绕其它轴；且当 `up` 与 `offset` 平行（相机正上/正下方看注视点）时该旋转退化（不改变位置）。
- **演示性质**：源码注释「供演示」，定位为便捷演示/测试方法，非完整相机控制器。

### 6.9 易错点汇总

| 易错点 | 现象 | 规避 |
| --- | --- | --- |
| 把 `view_proj` 当 `view` 或 `proj` 单独用 | 画面双重变换或缺失变换 | 注意本模块只提供组合矩阵；需要单独的 view/proj 时须自行扩展（本版无此接口） |
| 矩阵转置 | 画面完全错位 | 输出已是列主序，直接落 UBO，**勿转置** |
| `fov_set` 误传角度 | 视场角过大/过小 | `fov` 单位是**弧度**（`GLM_FORCE_RADIANS`） |
| `aspect` 未随窗口更新 | 画面拉伸 | 尺寸变化时手工调用 `aspect_set(宽/高)` |
| `up` 与视线平行或 `position == target` | 视图矩阵退化（NaN/除零） | 保证 `up` 不平行视线、位置与注视点不重合 |
| `near ≥ far` 或 `near ≤ 0` | 投影矩阵退化、深度错乱 | 保证 `0 < near < far` |
| `aspect ≤ 0` | 退化（Debug 下 `glm` 断言） | 保证 `aspect > 0` |
| 同时用负视口高度与 `m[1][1] *= -1` | Y 被翻转两次（画面上下颠倒） | 二者择一；本模块已翻转矩阵（见 §6.4） |
| `out` 传空指针 | 解引用崩溃 | 调用方保证缓冲区有效、长度 ≥ 16 |
| `orbit` 收到非单位 `up` | 旋转量偏离 `radians_delta` | 旋转前先取 `glm::length` 并按长度归一化（长度 ≤ 0 退化为 `(0,1,0)`）；已消除该隐患：旋转量只由 `delta` 决定（见 §6.8） |

### 6.10 线程 / 生命周期 / 内存所有权约定

- **线程**：`Camera` 无任何互斥/原子；全部成员函数均非线程安全。约定由渲染主线程串行调用（门面在渲染循环内单线程使用）。`view_proj_get` 是 `const`，可与其它 `const` 读取并发，但只要存在 `position_set` 等写操作，即须由调用方自行保证不发生数据竞争。
- **内存所有权**：`Camera` 不拥有任何堆内存、不持有句柄，是纯栈/值对象。`view_proj_get` 的 `out` 缓冲区由调用方拥有，本模块不分配、不释放、不缓存其地址。
- **生命周期**：默认构造 → 使用 → 默认析构；无 `build`/`destroy`，无 `valid`。可自由拷贝（值语义），拷贝即完整复制七个字段。
- **异常**：本模块实现内不含 `throw`、不捕获异常；矩阵计算路径不抛（`glm` 纯数学不抛；Debug 下的 `assert` 在失败时终止而非抛异常）。整个模块符合「渲染层禁用异常」的总体约束取向。

### 6.11 编码约定相关

## 七、模块运行链路详例

本章以「调用方 → 模块 → 被调方」的时序描述典型链路。调用方均为「渲染层-渲染器」门面（`Renderer::Impl`）或渲染层测试用例；被调方为 `glm` 数学库。

### 7.1 主链路 A：初始化设参（一次性）

```
调用方（门面 init）
  ① camera.position_set(0, 0, 3)          → Camera::position_set       → 写 position[3]
  ② camera.target_set(0, 0, 0)            → Camera::target_set         → 写 target[3]
  ③ camera.up_set(0, 1, 0)                → Camera::up_set             → 写 up[3]
  ④ camera.fov_set(1.0472f)               → Camera::fov_set            → 写 fov（弧度）
  ⑤ camera.near_far_set(0.1f, 100.0f)     → Camera::near_far_set       → 写 near/far
  ⑥ camera.aspect_set(宽/高)              → Camera::aspect_set         → 写 aspect
```

- 步骤 ①–③ 设定外参（机位/朝向），④–⑥ 设定内参（投影）。
- 全程无 `glm` 调用（仅赋值），无返回值，无校验。
- 若调用方跳过某些步骤，对应字段保持类内默认值。
- **本版次第九轮**：门面另提供 `scene_apply(Scene_Data)`，等价于上述 ①–⑤ 四项相机 setter ＋ 清屏色提交（一次性数据驱动接口）；其中 `Scene_Data::clear_color` **不属本模块**（由门面 `Impl::clear_color` 记录）——本模块只接收前五项进 `Camera`。**第十轮起**门面 `scene_apply` 在转交相机 setter **之前**先做参数校验（非法即整次拒绝，见《渲染层-渲染器》§3.4.44）。

### 7.2 主链路 B：每帧产生并上传 `view_proj`（核心链路）

```
调用方（门面 render / 场景更新）
  ① camera.view_proj_get(buf16)
       → Camera::view_proj_get(const)
            ├─ glm::lookAt(position, target, up)         → 视图矩阵 view
            ├─ glm::perspective(fov, aspect, near, far)  → 投影矩阵 proj（RH_ZO）
            ├─ proj[1][1] *= -1.0f                        → Vulkan NDC Y 翻转（K1）
            ├─ view_proj = proj * view                    → 组合（列向量约定）
            ├─ glm::value_ptr(view_proj)                  → 列主序首地址
            └─ 循环拷贝 16 个 float → buf16[0..15]
  ② 调用方把 buf16（64 字节）写入「本帧槽」的场景 UBO 映射内存
       （先 pipeline 前经 frame.slot_wait() 等待该槽栅栏，避免覆盖在途内容）
  ③ pipeline.scene_bind(slot, ubo_buffer)      → 把本帧槽 set0 指向该 UBO（若缓冲未变可省略）
  ④ 组装 Frame_Render_Item：
       scene_set        = pipeline.scene_set_get(slot)
       push_constants   = &model（对象模型矩阵）
       push_constant_size = 64
  ⑤ frame.render(swapchain, items, ..., clear_color)
       → 帧模块录制：vkCmdBindDescriptorSets(set0)、vkCmdPushConstants(model)、vkCmdDrawIndexed
            → 顶点着色器：gl_Position = scene.view_proj * object.model * vec4(pos, 1)
```

- **关键对接点**：步骤 ① 的输出 `buf16` 与着色器 `Scene_Buffer.view_proj` 是同一份 64 字节（§3.4）。
- **按帧槽轮转**：场景 UBO 通常按 `frame_overlap` 个帧槽各一份；调用方在写前经 `Frame_Context::slot_wait()` 与 `slot_index_get()` 取「本帧将用」的槽，保证与帧内部一致（`帧上下文.h` 注释明示该协作）。
- **相机与帧上下文无直接调用**：相机只被①调用一次；后续 ②–⑤ 均由门面完成，相机不再参与。

### 7.3 主链路 C：窗口尺寸变化同步宽高比

```
调用方（门面 resize / 交换链重建后）
  ① 取新视口宽 W、高 H
  ② camera.aspect_set(W / H)   → Camera::aspect_set → 写 aspect
  ③ 下次 view_proj_get 即用新 aspect 重算投影
```

- 本模块**不**自动感知尺寸，须调用方显式同步。**已确证**门面在 `init` 的 ⑯ 段与 `frame_render` 的两条交换链重建路径（`resized_consume` / `rebuild_needed`）后各调用一次 `aspect_set(W/H)`，无遗漏（见 R-SCENE-02）。
- 若忘记同步，投影仍用旧宽高比，画面拉伸。

### 7.4 交互链路 D：演示用轨道旋转

```
调用方（演示/测试循环，每帧给一个角度增量）
  ① camera.orbit(delta_radians)
       → Camera::orbit
            ├─ offset = position - target
            ├─ up_axis = up；length(up_axis) <= 0 → (0,1,0)，否则 up_axis /= length
            ├─ rotation = glm::rotate(mat4(1), delta, up_axis)
            ├─ rotated = rotation * vec4(offset, 0)
            └─ position = target + rotated        → 仅位置变化
  ② camera.view_proj_get(buf16)   → 用新位置重算视图矩阵
```

- 距离不变，注视点不变，相机会在过注视点的水平圆上环绕。
- 若同时想改变俯仰，需另行改写 `position`（本模块无此接口）。

### 7.5 边界 / 异常分支

| 分支场景 | 触发条件 | 本模块行为 | 后果 / 处理 |
| --- | --- | --- | --- |
| 视线退化 | `position == target` | `lookAt` 内部 `cross(f, up)` 可能为零，归一化除零 | 视图矩阵出现 NaN；调用方须避免 |
| `up` 平行视线 | `up ∥ (target-position)` | `cross(f, up) ≈ 0` | 同上；调用方须避免 |
| `aspect ≤ 0` | 误设宽高比 | `glm::perspective` 内部 `assert`（Debug 终止；Release 产生退化矩阵） | 调用方须保证 `aspect > 0` |
| `fov` 越界 | `fov ≤ 0` 或 `≥ π` | `tan` 项异常 | 投影错误；调用方须保证 `0 < fov < π` |
| `near ≥ far` 或 `near ≤ 0` | 误设平面 | `zFar/(zNear-zFar)` 异常 | 深度映射错误；调用方须保证 `0 < near < far` |
| `orbit` 的 `up` 非单位 | 上层传非单位 `up` | 旋转前先取 `glm::length(up_axis)` 并按长度归一化（长度 ≤ 0 退化为 `(0,1,0)`） | 已消除：旋转量只由 `delta` 决定（见 §6.8） |
| `orbit` 时 `up` 为**零向量** | 上层传零长度 `up` | 归一化分支将其退化为默认上方向 `(0,1,0)`（避免除零） | 旋转绕 `Y` 轴进行，不发生除零/NaN（见 §6.8） |
| `orbit` 时 `up ∥ offset` | 相机在注视点正上/正下方 | 旋转不改变位置（退化） | 演示效果异常；调用方须避免 |
| `out` 为空指针 | 误传 `nullptr` | 循环内解引用崩溃 | 属「调用方保证缓冲区有效」的**明确约定**：调用方须保证有效缓冲区（见 §3.2.9、R-SCENE-01） |
| `out` 长度 < 16 | 误传短缓冲区 | 越界写 | 调用方须保证长度 ≥ 16 |

### 7.6 链路小结

相机模块的运行链路高度线性、无分支复杂状态：**设参（A/C）→ 取矩阵（B/D 的第一步）→ 由门面上传 UBO 并经帧模块进入着色器**。相机的全部「外部世界交互」只发生在 `view_proj_get` 的输出缓冲区上；它与 Vulkan 之间没有任何直接调用，因而没有任何失败返回码，所有非法输入都以「产生错误矩阵」而非「报错」的形式呈现——这是本模块「极简、无校验」设计取向的直接体现（本模块条目本轮已全部确证，无遗留待确认项，见附录）。
