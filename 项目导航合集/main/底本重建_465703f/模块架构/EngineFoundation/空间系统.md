## 二、模块功能介绍

空间系统是 `EngineFoundation` 层内唯一提供“二维空间划分”的子系统，拓扑上位于最底层，除公共预编译头与 `src/detail/methods/二分查找.h` 外不依赖任何其它模块。它由三层组成：`坐标类型.h` 提供点与矩形的值语义；`Quadtree<T>` 提供单棵可原地扩容的正方形四叉树；`Quadtree_Manager<T>` 提供多棵四叉树拼合出的“无边界”覆盖。

该模块负责：以整数坐标把平面切成正方形区块，对区块提供“按点/按范围”的构建、查找、获取、卸载四类操作；以 `std::shared_ptr<T>` 作为叶区块载荷，把载荷所有权与树生命周期解耦；在目标超出当前树管理范围时按 2 的幂逐级扩容；在多树场景下维护树序列、覆盖补齐、相邻树查找、四棵树合并与单树卸载；按坐标集合自动划分并建树。

该模块不负责：实体本身的位置、速度、生命周期或对象池管理；精细几何相交（碰撞体判定）；跨线程同步；资源持久化；渲染可见性判定。它只做“闭区间矩形与正方形网格的划分与相交”，叶区块载荷的语义完全由使用方定义。

模块对外只承诺三条边界：第一，所有尺寸参数（树边长、区块单元、上下限）必须构成 2 的幂关系，否则设置接口返回 `false` 且不写状态；第二，坐标与范围一律采用闭区间，`up/down` 分别表示 Y 轴较大/较小一侧，范围形参顺序为“左、右、上、下”；第三，树的管理范围为“以根节点为中心、边长为 `size` 的正方形网格”，根节点默认取 `.5` 结尾的半整数以避免中心落在单元格边界上。

模块存在的理由是“无限平面 + 有限内存”。单棵树只能覆盖有限正方形，管理器用多棵树按网格拼合来覆盖任意大的区域；每棵树内部只沿实际访问过的路径物化节点，未被访问的区域不分配任何内存，因此树可以声明很大的边长而不付出等量内存。

对上层而言，空间系统的价值是“以区块为粒度做空间索引”：上层把实体编号写进区块载荷，查询时只取与目标矩形相交的区块载荷集合，从而把全体实体扫描降为区块扫描。快照内唯一在仓库内的上层消费者是应用层 `Application/Game/星屑弹幕/source/world/世界.h`，它以 `Quadtree_Manager<chunk_entities>` 维护敌人/投射物的空间索引；`Application/Test/tests/Foundation/src/核心/` 下的两个测试文件直接消费 `Quadtree<int>` 与 `Quadtree_Manager<int>`。

模块不含任何锁、原子量或线程局部状态，也不监听生命周期事件：树由管理器 `new`/`delete` 独占，叶载荷由 `shared_ptr` 引用计数管理；模块假定调用方在单线程内串行调用，且不在遍历期间销毁管理器。

## 三、模块公开接口

### 3.1 坐标与精度类型（`math/坐标类型.h`）

#### 3.1.1 `engine::detail::ulp_distance`

```cpp
inline uint64_t ulp_distance(double lhs, double rhs) noexcept;
```

语义：返回两个 `double` 在 IEEE-754 位模式上的距离。`lhs == rhs` 时返回 0；符号位不同时返回 `std::numeric_limits<uint64_t>::max()`；同号时把较小位模式的数交换到 `lhs_bits` 后返回 `rhs_bits - lhs_bits`。不抛出异常，无失败路径。该函数不做 NaN 特判，NaN 输入得到的是位模式差（非 0）。

#### 3.1.2 `engine::Point2<T>`

```cpp
template <typename T>
struct Point2
{
    T X = T{};
    T Y = T{};

    Point2() = default;
    Point2(T x, T y);

    bool operator==(const Point2& other) const noexcept;
    bool operator!=(const Point2& other) const noexcept;
    friend std::ostream& operator<<(std::ostream& os, const Point2& p);
};
```

语义与前置条件：

- `operator==`：当 `T` 为浮点类型时，任一坐标为 NaN 直接返回 `false`；任一坐标为无穷时退化为逐分量精确比较；其余情况要求两轴 ULP 距离均不超过 4 才返回 `true`。当 `T` 为整数类型时逐分量精确比较。该比较是“近似相等”，不是全序关系：它不满足传递性，不能用于排序或哈希键。
- `operator<<`：输出两行，格式为 `X轴坐标: {}\nY轴坐标: {}\n`，整点或半整数由 `std::format` 默认格式决定。

类型别名：`Point2i = Point2<int32_t>`、`Point2l = Point2<int64_t>`、`Point2d = Point2<double>`。

#### 3.1.3 `engine::Rect2<T>`

```cpp
template <typename T>
struct Rect2
{
    T left = T{};
    T right = T{};
    T up = T{};
    T down = T{};

    Rect2() = default;
    Rect2(T l, T r, T u, T d);

    bool operator==(const Rect2& other) const noexcept;
    bool operator!=(const Rect2& other) const noexcept;
    friend std::ostream& operator<<(std::ostream& os, const Rect2& r);
};
```

语义：

- 四成员表示闭区间 `[left,right] × [down,up]`，不是半开区间；`right` 与 `up` 是“可取到的最后一个整数”，因此宽度为 `right-left+1`。
- 构造形参顺序为“左、右、上、下”，与成员声明顺序 `left,right,up,down` 一致；`up` 声明在 `down` 之前。
- `operator==` 对四个边界逐分量精确比较，不使用 ULP 容差（与 `Point2` 的策略不同）。
- `operator<<` 输出四行：`左边界`、`右边界`、`上边界`、`下边界`。

类型别名：`Rect2i`、`Rect2l`、`Rect2d`。

#### 3.1.4 坐标精度转换

```cpp
inline Point2i point_to_int(const Point2d& p) noexcept;   // lround 后 static_cast<int>
inline Point2d point_to_double(const Point2i& p) noexcept;
inline Point2l point_to_l(const Point2d& p) noexcept;     // llround
inline Point2d point_to_double(const Point2l& p) noexcept;
```

语义：`point_to_int`/`point_to_l` 用 `std::lround`/`std::llround` 做“四舍五入、半数远离零”；两个 `point_to_double` 重载把整型坐标提升为 `double`。前置条件是值域落在目标类型内；越界时由 `static_cast` 截断，无失败返回。

### 3.2 树状态与区块返回结构（`Quadtree/数据结构.h`）

#### 3.2.1 `engine::Tree_State`

```cpp
struct Tree_State
{
public:
    Point2d root = { 0.5,0.5 };
    uint64_t size = 0;
    uint64_t max_size = 9223372036854775808; // 2^63
    uint64_t block_size = 0;
};
```

字段语义：

- `root`：树的管理范围中心，半整数坐标（默认 `0.5,0.5`），为 `range_align`/`rect_range_calcu` 的网格锚点。
- `size`：当前树边长（正方形范围的每边单元格数），默认 0，由 `Quadtree` 构造函数写入（其缺省为 256）。
- `max_size`：边长上限，默认 2^63，`tree_expand` 不得越过。
- `block_size`：最小区块单元边长，默认 0 表示“未配置”，任何区块操作都会退化。

三处 `size` 缺省值不一致（`Tree_State::size = 0`、`Quadtree` 构造缺省 256、`Tree_Record::size = 256`）【待确认：1】。

#### 3.2.2 `engine::Tree_Chunk_Data<T>`

```cpp
template<typename T>
struct Tree_Chunk_Data
{
    Tree_Chunk_Data() = default;
    Tree_Chunk_Data(double x, double y, std::shared_ptr<T> ptr);
    Tree_Chunk_Data(const Point2d& point, std::shared_ptr<T> ptr);
    ~Tree_Chunk_Data() = default;

    Point2d center = { 0.5,0.5 };
    std::shared_ptr<T> data = nullptr;
};
```

语义：`center` 是区块中心（闭区间中点，形如 `.5` 结尾），由树在每次查询时按几何范围推导后写入，不存储于叶节点；`data` 是叶载荷，可为空。两个带参构造分别接收“横纵坐标 + 载荷”与“中心点 + 载荷”，均对载荷做 `std::move`。该结构按值返回，拷贝即复制 `shared_ptr`（共享所有权）。

### 3.3 `engine::Quadtree<T>` 公开接口

```cpp
template<typename T>
class Quadtree
{
public:
    explicit Quadtree(const uint64_t& size = 256, const Point2d& root = { 0.5,0.5 });
    ~Quadtree(void) = default;

    // ---- 设置 ----
    bool set_block_size(const uint64_t& size);
    bool set_max_size(const uint64_t& size);
    void set_callback_manage(const std::function<bool(Point2d root, Point2l target)>& cb);

    // ---- 区块操作 ----
    void build(const Point2l& target, const std::shared_ptr<T>& data = nullptr);
    void build(const Rect2l& target_range);

    bool seek(const Point2l& target, Tree_Chunk_Data<T>& receiver);
    void seek(const Rect2l& target_range, std::vector<Tree_Chunk_Data<T>>& receiver);

    bool get(const Point2l& target, Tree_Chunk_Data<T>& receiver);
    void get(const Rect2l& target_range, std::vector<Tree_Chunk_Data<T>>& receiver);

    void unload(const Point2l& target);
    void unload(const Rect2l& target_range);

    const Tree_State& tree_state_get(void) const;
    bool tree_expand(void);

    // ---- 几何计算工具（管理器复用）----
    Rect2l chunk_range_calcu(const Point2l& target) const;
    Rect2l child_range_calcu(const int& quadrant, const Rect2l& parent_range) const;
    Point2d center_calcu(const Rect2l& range) const;
    Rect2l rect_range_calcu(const Point2d& root, const uint64_t& size) const;
    void range_align(Rect2l& target_range, const Point2d& root, const uint64_t& block_size) const;
    Point2d range_intersect(const Rect2l& target_range, Rect2l& reachable_range) const;
};
```

#### 3.3.1 构造与析构

`explicit Quadtree(const uint64_t& size = 256, const Point2d& root = {0.5,0.5})`：只把 `size` 与 `root` 写入 `state`，不校验 2 的幂，不设置 `block_size`。前置条件：使用前必须调用 `set_block_size` 成功，否则 `block_size` 为 0、递归级数为 0，全部区块操作无效果。构造后 `max_size` 取结构体缺省 2^63，`root` 取传入值。

`~Quadtree(void) = default`：析构会沿 `shared_ptr<Node>` 链递归释放已物化的节点，叶载荷的 `shared_ptr` 引用计数减一；未物化的空子树不占内存。析构不释放叶载荷对象本身（由其它持有者决定）。

#### 3.3.2 设置接口

`bool set_block_size(const uint64_t& size)`：成功返回 `true` 并写入 `state.block_size`。返回 `false` 的完整条件（按实现顺序）：`size == 0`、`size` 不是 2 的幂、`state.size == 0`、`state.size` 不是 2 的幂、`size >= state.size`、`state.size % size != 0`、`state.size/size` 不是 2 的幂。实现不检查树内是否已有物化叶子【待确认：2】：建叶后再改小区块单元，旧叶会停在浅层，后续下潜会被 `child_step` 的类型校验拒绝，旧数据不可达（可疑1）。

`bool set_max_size(const uint64_t& size)`：成功写入 `state.max_size`。返回 `false` 的条件：`size < state.size`、`size == 0`、`size` 不是 2 的幂、`state.size == 0`、`state.size` 不是 2 的幂、`size % state.size != 0`、`size/state.size` 不是 2 的幂。等价语义是：上限必须是当前边长的 2 的幂倍数。

`void set_callback_manage(const std::function<bool(Point2d root, Point2l target)>& cb)`：把回调写入成员 `callback`（成员类型为 `std::function<bool(const Point2d&, const Point2l&)>`，与形参类型等价）。回调在“目标越出当前管理范围且需要扩容”时被调用，第一参数为本树根坐标，第二参数为越界侧被夹到当前管理范围边界的 64 位坐标；返回 `true` 表示允许本次原地扩容。未注册回调时树按自身上限自行扩容。

#### 3.3.3 区块构建

`void build(const Point2l& target, const std::shared_ptr<T>& data = nullptr)`：把目标点折算为所属区块范围后进入构建模式。目标区块尚不存在时创建叶节点并挂载 `data`（`data` 为空时按叶节点默认构造创建载荷）；目标区块已存在时直接复用旧叶，传入的 `data` 不会被挂载【待确认：3】。无返回值，失败（例如 `block_size == 0`、越界且扩容被拒绝）表现为“没有发生任何构建”。

`void build(const Rect2l& target_range)`：对齐并遍历范围内每个区块，缺失即创建，载荷一律取默认构造值；没有挂载外部载荷的入口。

#### 3.3.4 区块查找

`bool seek(const Point2l& target, Tree_Chunk_Data<T>& receiver)`：只读模式，不创建节点、不扩容。命中已物化叶节点时把该叶的中心与载荷写入 `receiver` 并返回 `true`；未命中返回 `false` 且不修改 `receiver`。若叶子存在但载荷为空（分配失败），仍返回 `true`，此时 `receiver.data == nullptr`【待确认：4】。

`void seek(const Rect2l& target_range, std::vector<Tree_Chunk_Data<T>>& receiver)`：只读模式，把范围内所有已物化叶节点追加到 `receiver`（不先清空容器）。结果按递归象限顺序（NW、NE、SW、SE）深度优先产生，无重复。

#### 3.3.5 区块获取

`bool get(const Point2l& target, Tree_Chunk_Data<T>& receiver)`：创建模式。目标区块存在则返回其中心与载荷；不存在则沿路径物化中间节点与叶节点后返回。返回 `false` 仅有两种情况：容积为 0（`block_size == 0` 导致递归级数为 0）、或扩容后目标仍不可达。与 `seek` 相同，载荷分配失败时 `true` 且 `data == nullptr`。

`void get(const Rect2l& target_range, std::vector<Tree_Chunk_Data<T>>& receiver)`：对范围内每个未物化区块执行创建，并把全部区块中心与载荷追加到 `receiver`。该重载会物化范围内全部叶子，代价与“范围覆盖的区块数”成正比。

#### 3.3.6 区块卸载

`void unload(const Point2l& target)` / `void unload(const Rect2l& target_range)`：只读模式（不创建、不扩容），把范围内最深层叶节点整体 `reset`（释放该区块及其载荷引用）。不回退、不回收中间节点，因此树的空间骨架保留。无返回值，无告警。

#### 3.3.7 状态与扩容

`const Tree_State& tree_state_get(void) const`：返回内部 `state` 的常量引用，调用方可观察到后续 `size`/`block_size`/`max_size` 变化。

`bool tree_expand(void)`：原地扩容一次。返回 `false` 的条件：已设上限且 `state.size >= state.max_size`、根节点不是中间节点（`root.data.index() != 0`）、四个新中间节点中任一 `new(std::nothrow)` 失败。成功时在根节点与旧四个子节点之间插入一层新的中间节点，旧四个子树按“相反象限”下沉一级，`state.size` 翻倍，根坐标不变。旧叶节点的几何范围与中心坐标在扩容后保持不变。

#### 3.3.8 几何计算工具（公开）

这批函数在类中第二次 `public:` 区块中声明，注释标注“管理器复用”，但任何持有树对象的调用方都可使用。

`Rect2l chunk_range_calcu(const Point2l& target) const`：把点折叠为零尺寸矩形后调用 `range_align(..., state.root, state.block_size)`，返回该点所属区块的闭区间。`block_size == 0` 时 `range_align` 直接返回，结果是退化矩形 `[x,x]×[y,y]`。

`Rect2l child_range_calcu(const int& quadrant, const Rect2l& parent_range) const`：按象限切分父范围。内部计算 `mid_x = left + (right-left)/2`、`mid_y = down + (up-down)/2`（整数截断），四个象限为：NW `[left,mid_x]×[mid_y+1,up]`、NE `[mid_x+1,right]×[mid_y+1,up]`、SW `[left,mid_x]×[down,mid_y]`、SE `[mid_x+1,right]×[down,mid_y]`。传入非 0..3 的 `quadrant` 时返回零初始化的 `Rect2l`。`quadrant` 取自私有枚举 `Quadrant` 的整数值（`NW=0, NE=1, SW=2, SE=3`）【待确认：5】。

`Point2d center_calcu(const Rect2l& range) const`：返回闭区间中点，按 `left + (right-left)/2.0` 与 `down + (up-down)/2.0` 计算，用差值避免边界相加溢出，结果为 `.5` 结尾或整数。

`Rect2l rect_range_calcu(const Point2d& root, const uint64_t& size) const`：返回以 `root` 为中心、边长 `size` 的管理范围。实现取 `half_span = int64_t(size/2 - 1)`，四边界为 `int64_t(root.X-0.5)-half_span`、`int64_t(root.X+0.5)+half_span`、`int64_t(root.Y-0.5)-half_span`、`int64_t(root.Y+0.5)+half_span`。当 `root` 为半整数时，范围宽度恰为 `size`；整数根会出现有效中心偏移（分量 0 时还会少一格），见 §6.14【待确认：10】。不是 `state` 的成员函数，参数独立于对象状态。

`void range_align(Rect2l& target_range, const Point2d& root, const uint64_t& block_size) const`：把范围向外扩展到区块网格。`block_size == 0` 直接返回。取模使用“结果非负”的 `mod`，四个边界锚点为：左边 `int64_t(root.X+0.5)`、右边 `int64_t(root.X-0.5)`、上边 `int64_t(root.Y-0.5)`、下边 `int64_t(root.Y+0.5)`；左/下向下对齐，右/上向上对齐。

`Point2d range_intersect(const Rect2l& target_range, Rect2l& reachable_range) const`：把 `reachable_range` 收窄为与 `target_range` 的交集，同时返回“扩容标记点”。标记初值为 `state.root`；逐边界按“左、右、上、下”顺序处理：某条边界越出时，标记的对应分量改写为 `reachable_range` 的原边界值，且该侧不收缩 `reachable_range`；未越出时把该侧收缩到目标值。返回值与 `state.root` 相等表示“完全覆盖、无需扩容”。同一轴两侧都越界时后处理的一侧覆盖标记：X 轴右侧生效、Y 轴下侧生效。

### 3.4 树档案与管理器设置（`Quadtree_Manager/数据结构.h`）

#### 3.4.1 `engine::Tree_Record<T>`

```cpp
public:
```

#### 3.5.1 构造与析构

`Quadtree_Manager()`：空实现，所有成员按结构体缺省初始化（`largest_tree_size = 0`、`X_sequence` 空、缓存空、`settings` 取缺省值）。

`~Quadtree_Manager()`：调用 `clear()`，按索引倒序卸载全部树并释放档案与缓存。

#### 3.5.2 设置接口

`bool set_block_size(const uint64_t& block_size)`：成功写入 `settings.block_size`。`false` 条件：非 2 的幂或为 0、`block_size >= settings.min_tree_size`、`min_tree_size % block_size != 0`、`min_tree_size/block_size` 不是 2 的幂、`X_sequence` 非空（已有树时禁止改动区块单元）。调用方必须在建树前设置。

`bool set_max_size(const uint64_t& max_size)`：成功时写入 `settings.max_tree_size` 并对 `X_sequence` 中每棵树调用 `set_max_size`（返回值被忽略，因已先行校验）。`false` 条件：非 2 的幂或为 0、小于 `min_tree_size`、不是 `min_tree_size` 的整数倍、倍率不是 2 的幂，或任一现存树 `size > max_size`、`max_size % size != 0`、`max_size/size` 不是 2 的幂。

`bool set_min_size(const uint64_t& min_size)`：成功只写入 `settings.min_tree_size`；不会下发给任何树，也不会回填已存在且小于新下限的树。`false` 条件：非 2 的幂或为 0、`min_size <= settings.block_size`、不是 `block_size` 的整数倍、`min_size/block_size` 不是 2 的幂、大于 `settings.max_tree_size`。

`void set_cache_state(bool enabled)`：直接写 `settings.is_cache_enabled`，无校验。

`void set_cache_active_threshold(const uint64_t& threshold)`：直接写门槛值，无校验（0 表示任何非空序列都启用缓存写入）。

`void set_max_cache_records(const uint64_t max_entries)`：直接写条目上限，无校验（0 表示不写缓存）。

#### 3.5.3 智能建树

`void tree_build_smart(const std::vector<Point2l>& coord_set)`：空集合直接返回；`X_sequence` 为空时按整批坐标做首轮智能划分并建树；非空时对每个坐标调用私有 `ensure_tree`，确保其被某棵树覆盖（可能扩容、补建）。前置条件：`settings` 已配置为合法的 2 的幂关系，否则可能无法建树。无返回值，失败表现为“没有新增树或没有覆盖”。

#### 3.5.4 区块操作

`void build(const Point2l& target, const std::shared_ptr<T>& data = nullptr)`：先 `ensure_tree(target)` 确保目标被某棵树覆盖，再在该树执行 `Quadtree::build`。`ensure_tree` 失败（返回空）时不进行任何构建。载荷只在目标区块新建时挂载（见 §3.3.3）。

`void build(const Rect2l& target_range)`：进入管理器范围分派（构建模式）。空序列时若非只读会先建立基准树（只读模式直接返回）；随后补齐范围内覆盖，再逐树裁剪出交集范围并调用各树的 `build(region)`。范围构建不挂载载荷。

`bool seek(const Point2l& target, Tree_Chunk_Data<T>& receiver)`：用 `tree_inclusion_seek` 定位“范围完全包含该点”的树；找不到返回 `false`；找到则调用该树 `seek(target, receiver)`，语义同 §3.3.4（不建树、不建区块）。

`void seek(const Rect2l& target_range, std::vector<Tree_Chunk_Data<T>>& receiver)`：范围查找模式。空序列直接返回；不补齐覆盖、不扩容；对快照的每棵树裁剪交集并调用 `seek(region)`，把结果追加到 `receiver`。

`bool get(const Point2l& target, Tree_Chunk_Data<T>& receiver)`：先 `ensure_tree(target)`，失败返回 `false`，成功则在归属树执行 `get`（可创建区块）。

`void get(const Rect2l& target_range, std::vector<Tree_Chunk_Data<T>>& receiver)`：范围获取模式。空序列时先建基准树；先 `coverage_ensure` 补齐范围内覆盖，再逐树裁剪并 `get(region)`，结果追加到 `receiver`。会物化范围内全部区块。

`void unload(const Point2l& target)`：用 `tree_inclusion_seek` 定位归属树；找不到直接返回；找到则调用该树 `unload(target)`。

`void unload(const Rect2l& target_range)`：范围卸载模式。不建树、不补齐覆盖、不扩容；逐树裁剪交集并 `unload(region)`。

#### 3.5.5 读取接口

三项读取均返回内部成员的常量引用，引用随后续操作变化（不是快照）：

- `const Tree_Manager_Settings& settings_get(void) const`
- `const std::vector<Tree_Record<T>*>& records_get(void) const`（序列按根节点 X 降序；元素为裸指针，卸载后失效）
- `const uint64_t& largest_size_get(void) const`（当前序列中的最大边长；无树时为 0）

#### 3.5.6 维护接口

`void tree_merge(void)`：尝试把“同边长、根坐标构成 2×2 邻接关系”的四棵树合并为一棵双倍边长的树。合并期间临时关闭缓存（若原本启用），结束后恢复；先建新树，再把旧树全部叶区块的载荷以 `shared_ptr` 共享方式迁入新树，最后卸载旧树。无返回值；无可合并组合时序列不变。

`void cache_clear(void)`：清空高速缓存的记录表与范围表，不触碰树序列。

`void clear(void)`：按序列倒序卸载全部树，释放档案并清理缓存条目，最后把 `largest_tree_size` 归零。

`void tree_unload(const std::vector<Point2d>& root_set)`：按根坐标（`Point2d` 的 ULP 比较）逐个查索引，统一走私有 `unload_index`；不存在的根坐标被忽略。

### 3.6 节点结构与回调类型的可见性

`Quadtree<T>` 的节点类型 `Node`、节点种类 `Node_Kind`、区块操作模式 `Chunk_Mode`、递归方向 `Quadrant` 全部声明在类的 `private` 区，公开接口不暴露节点对象；对外只通过 `Tree_Chunk_Data<T>` 交出“中心 + 载荷”。节点结构的精确形态（`std::variant<四子指针数组, 叶载荷>`、两种索引的含义、叶子默认构造规则）见 §4.1，本节不重复。

管理器一侧的回调类型为 `std::function<bool(Point2d, Point2l)>`，注册入口见 §3.3.2；回调的调用时机、参数含义与返回约定见 §3.3.2 与 §6.10。管理器的私有 `Chunk_Mode` 与四叉树的同名枚举是两套独立类型，互不通用（各自只在所属类内使用）。

## 四、模块私有方法

### 4.1 `Quadtree<T>` 私有类型与私有方法

私有类型（`Quadtree/函数预声明.h`）：

| 名称 | 定义 | 语义 |
| --- | --- | --- |
| `enum class Node_Kind` | `Middle`、`Leaf` | 节点双态：中间节点持有四子指针，叶节点持有载荷 |
| `struct Node` | `std::variant<std::array<std::shared_ptr<Node>,4>, std::shared_ptr<T>> data` | 节点数据；索引 0 为中间态，索引 1 为叶态 |
| `enum class Chunk_Mode` | `Build`、`Seek`、`Get`、`Unload` | 区块操作模式 |
| `enum Quadrant` | `NW=0`、`NE=1`、`SW=2`、`SE=3` | 递归方向；非限定作用域枚举，以 `int` 传递 |

`Node` 的构造函数签名：

```cpp
explicit Node(Node_Kind kind = Node_Kind::Middle, std::shared_ptr<T> external_data = nullptr);
```

职责：`Middle` 时 `emplace<0>` 四个空 `shared_ptr`；`Leaf` 且有外部载荷时 `emplace<1>(std::move(external_data))`；`Leaf` 且无外部载荷时 `emplace<1>(std::shared_ptr<T>(new(std::nothrow) T()))`——分配失败会得到一个“叶态但载荷为空”的节点【待确认：6】。

私有方法（按调用链分组）：

```cpp
// 递归级数计算
int depth_calcu(void) const;

// 范围相交判定
bool range_overlap_check(const Rect2l& target_range, const Rect2l& node_range) const;

// 子节点推进
bool child_step(Node*& this_node, const int& quadrant, const Node_Kind& kind,
    bool read_only, const std::shared_ptr<T>& external_data = nullptr);

// 区块递归
void chunk_recur(Node* node, const Rect2l& node_range, const Rect2l& target_range,
    int now_level, const int& max_level, bool read_only,
    const Chunk_Mode& mode, std::vector<Tree_Chunk_Data<T>>& receiver,
    const std::shared_ptr<T>& data);

// 叶子槽操作
void leaf_slot_apply(Node* node, const Rect2l& node_range, const Rect2l& target_range,
    const Chunk_Mode& mode, bool read_only,
    std::vector<Tree_Chunk_Data<T>>& receiver,
    const std::shared_ptr<T>& data);

// 区块操作 —— 单区块重载
void chunk_dispatch(const Point2l& target, const Chunk_Mode& mode,
    std::vector<Tree_Chunk_Data<T>>& receiver,
    const std::shared_ptr<T>& data = nullptr);

// 区块操作 —— 范围重载
void chunk_dispatch(const Rect2l& target_range, const Chunk_Mode& mode,
    std::vector<Tree_Chunk_Data<T>>& receiver,
    const std::shared_ptr<T>& data = nullptr);

// 扩大可行性分析
void expand_analyse(const Rect2l& target_range, Rect2l& reachable_range, bool read_only);
```

职责与要点：

- `depth_calcu`：`block_size == 0` 返回 0；否则统计 `(size /= 2) >= block_size` 的循环次数，结果即“根到叶子的层数”。边长 256、区块 16 时为 4。
- `range_overlap_check`：闭区间判交。目标整体位于节点某一侧（右 < 左、左 > 右、上 < 下、下 > 上）时返回 `false`，其余返回 `true`（相接视为相交）。
- `child_step`：四步契约——(1) 当前节点必须是中间节点，否则 `false`；(2) 目标槽为空时，`read_only` 直接 `false`，否则 `new(std::nothrow) Node(kind, external_data)`，失败 `false`；(3) 目标子节点数据索引必须与 `kind` 相符（要求 Leaf 时索引须为 1，要求 Middle 时须为 0），否则 `false`；(4) 把 `this_node` 推进到子节点并返回 `true`。失败时 `this_node` 保持原值（引用只在成功路径末尾赋值）。
- `chunk_recur`：`now_level == max_level` 时调 `leaf_slot_apply` 并返回；否则遍历四象限，先算子范围、用 `range_overlap_check` 剪枝，再用 `child_step(..., Middle, read_only)` 下潜，失败即 `continue`；递归层数加一。该函数不做结果去重，依靠四象限划分保证叶唯一。
- `leaf_slot_apply`：取出父节点的四子槽，遍历四象限并剪枝；卸载模式下只把“存在且为叶”的槽 `reset`；其余模式下用 `child_step(..., Leaf, read_only, data)` 取/建叶，然后对 Seek/Get 记录 `center_calcu(child_range)` 与叶载荷。Get 也会建叶，因此该函数同时承担“创建 + 返回”【待确认：7】。
- `chunk_dispatch(Rect2l, ...)`：先按 `Seek`/`Unload` 推导 `read_only`；对目标范围 `range_align`；调 `expand_analyse` 得到 `reachable_range`；`depth_calcu() <= 0` 直接返回；用 `rect_range_calcu(state.root, state.size)` 取当前管理范围，以 `now_level = 1` 启动 `chunk_recur`。
- `chunk_dispatch(Point2l, ...)`：调 `chunk_range_calcu` 把点转成区块矩形，再转调范围重载。
- `expand_analyse`：循环体先按当前 `size` 计算管理范围，再 `range_intersect` 求交并取标记点；标记等于 `state.root` 或 `read_only` 时结束；有回调时“回调返回 `false` 即结束，否则调 `tree_expand()`，失败即结束”；无回调时“已达 `max_size` 即结束，否则 `tree_expand()`，失败即结束”；每轮末尾再检查一次上限。因此单次调用可连续扩容多级。

```cpp
// 候选树筛选
void candidate_filter(std::vector<Tree_Record<T>*>& receiver, const Tree_Record<T>* tree,
    const std::vector<Tree_Record<T>*>& candidate) const;
// 相邻四叉树查找总函数
void neighbor_seek(std::vector<Tree_Record<T>*>& receiver, const Tree_Record<T>* tree,
    const std::vector<Tree_Record<T>*>* tree_group = nullptr) const;
```

职责与要点：

- `tree_inclusion_seek`：先查缓存（若启用且非空）：逐条用缓存里的 `Rect2l` 做四边界包含判断；命中时把该条目与其前一条交换（每次前进一位）并返回。缓存未命中则线性扫描 `X_sequence`，每次现场用 `rect_range_calcu` 计算候选树范围，首个包含目标点的树获胜；若树数量达到 `cache_active_threshold` 且 `max_cache_records > 0`，在缓存满时 `pop_back` 掉尾条目再 `push_back` 新条目（新条目落在尾部，命中后再逐步前移）。未命中返回 `nullptr`。
- `tree_index_seek`：以 `root.X` 为键、序列降序为前提，调用 `detail::range_binary_search` 取“X 相等的闭区间”，再在该区间内用 `Point2` 的 ULP 比较找完整坐标；未命中返回 `std::nullopt`。
- `nearest_tree`：线性扫描 `X_sequence`，用“目标点到树的 `root`”的平方距离取最小；严格小于才替换，等距取先出现者。判据是“中心最近”，不是“范围最近”。
- `ensure_tree`：先 `tree_inclusion_seek`；空序列走 `tree_build_smart_first({target})`；非空序列最多循环 64 次：取最近树、记录“序列长度 + 最大边长”快照、调 `tree_expand_approve(最近树根, target, true)`，再重新查找；命中即返回；若一轮后序列长度与最大边长都没变化则提前结束。最终返回一次重新查找结果（可能为空）。
- `rect_filter`：两遍筛选。第一遍按 `root.X ∈ [range.left, range.right]` 且根坐标不等于主体树根，收集候选；第二遍再按 `root.Y ∈ [range.down, range.up]` 过滤，把结果追加到 `receiver`（不清空）。`tree_group` 为空时使用 `X_sequence`。
- `neighbor_classify`：对每个候选计算 `diff_x = |主体.root.X - 候选.root.X|`（截断为 `int64`）、`diff_y` 同理、`half_sum = (主体.size + 候选.size)/2`；`diff_x <= half_sum` 记一次命中，`diff_y <= half_sum` 再记一次；两次命中（含同尺寸正交邻居，其非跨越轴的差为 0）直接入 `receiver`；一次命中（仅一轴在阈值内）进入返回的“待确认”列表；零次命中丢弃。头文件注释把“两次命中”直接称对角相邻，与该判据的真实含义不符【待确认：12】。
- `neighbor_verify`：以两棵树的完整管理范围做闭区间“相接或重叠”判定；`way` 是四参谓词，X 轴传 `(right1, left2, right2, left1)`，Y 轴传 `(up1, down2, up2, down1)`；任一轴为真即入 `receiver`。两轴结果按“或”合并，因此 X 方向远离但 Y 重叠的候选也会被判相邻（可疑13）。`candidate_filter` 传入的谓词是 `coord_1 > coord_2 - 1 && coord_3 > coord_4 - 1`，即“闭区间有交集（含仅共边）”。
- `candidate_filter`：先 `neighbor_classify`，再对“一次命中”的候选做上面的重叠确认。
- `neighbor_seek`：先构造一个以主体根为中心、半宽 `(主体.size + largest_tree_size)/2` 的矩形（边长按 `int64` 截断），用 `rect_filter` 收集根落在该矩形内的其它树，再 `candidate_filter` 做最终判定。矩形范围偏大只影响性能，不影响正确性【待确认：8】。

### 4.3 扩容回调与新建树（`core/四叉树扩大回调管理.hpp`）

```cpp
// 回调管理四叉树查找
Tree_Record<T>* callback_tree_seek(const Point2d& root) const;
// 新四叉树管理范围计算
void new_tree_range_calcu(const Tree_Record<T>* primary_tree, const Point2l& target,
    Rect2l& new_tree) const;
// 扩大管理方法
bool tree_expand_approve(const Point2d& root, const Point2l& target, bool internal = false);
```

职责与要点：

- `callback_tree_seek`：线性扫 `X_sequence`，用 `Point2` 的 ULP 比较找根坐标一致的记录；找不到返回 `nullptr`。复杂度 O(树数)。
- `new_tree_range_calcu`：先取 `rect_range_calcu(primary.root, settings.min_tree_size)` 作为初始框；若 `primary.size != min_tree_size`，按目标相对根的方向把框整体平移“半格”（`±min_size/2`，X/Y 各自判断）；随后按 `min_size` 为步长循环滑动（左/右超界则整框左右移，上/下超界则整框上下移），直到框包含目标点。终止条件由“包含目标”保证；迭代次数与目标到初始框的距离成正比。
- `tree_expand_approve`：决策顺序如下。(1) `callback_tree_seek(root)`，找不到返回 `false`。(2) 若 `tree_inclusion_seek(target)` 已有归属树，直接返回 `false`（目标已被覆盖，无需扩容）。(3) 若当前树 `size < max_tree_size`：先算“翻倍后的管理范围”，用 `rect_filter` 检查范围内是否已有其它树的根，有则不可原地扩容；否则把 `record->size` 临时翻倍，用 `neighbor_seek` 找相邻树并用重叠谓词确认是否冲突，冲突则恢复原大小。可扩容时：`internal == true` 则由管理器直接调 `tree->tree_expand()`（失败则把 `record->size` 减半并返回 `false`），`internal == false` 则由调用方（树自身的 `expand_analyse`）执行扩容；成功后维护 `largest_tree_size`、刷新缓存中该树的范围并返回 `true`。(4) 原地扩容不可行时，用 `new_tree_range_calcu` 求新树框，与除自身外的所有树做 `range_clip` 重叠检查，任一重叠即返回 `false`；否则以框中心为新根、以 `min_tree_size` 为边长调用 `tree_build`，并返回 `false`（表示“请求方不要扩容，目标已交给新树”）。新建分支里 `tree_build` 的返回值未被检查。

### 4.4 建树、卸载与合并（`core/基础操作.hpp`、`core/四叉树合并.hpp`）

```cpp
// 四叉树创建
bool tree_build(Point2d root = {0.5,0.5}, uint64_t tree_size = 256);
// 卸载——序列索引重载
void unload_index(std::vector<uint64_t>& index_set);
// 卸载——根节点重载
void tree_unload(const std::vector<Point2d>& root_set);

// 合并：收集候选组合
void merge_collect(std::vector<std::vector<Tree_Record<T>*>>& receiver) const;
// 合并：精确筛选组合
void merge_filter(const std::vector<std::vector<Tree_Record<T>*>>& candidate,
    std::vector<std::vector<Tree_Record<T>*>>& receiver) const;
// 四叉树合并总函数
void tree_merge(void);
```

职责与要点：

- `tree_build`：先校验 `tree_size ∈ [min_tree_size, max_tree_size]` 且根坐标不重复（`tree_index_seek`）；`new(std::nothrow)` 分配档案与 `Quadtree`，任一失败即回滚已分配部分；写入 `size`/`root`；对新树下发 `set_max_size(settings.max_tree_size)` 与 `set_block_size(settings.block_size)`，任一失败即释放并返回 `false`；注册回调 lambda（捕获 `this`，转调 `tree_expand_approve(root, target)`，`internal` 取缺省 `false`）；把档案追加到 `X_sequence`，必要时抬高 `largest_tree_size`，最后按 `root.X` 降序整表排序。
- `unload_index`：对索引集合降序排序（保证擦除不使后续索引失效），逐个跳过越界与重复索引；从缓存中按“指针相等”删除对应条目（只删第一条匹配）；`delete` 树与档案；从 `X_sequence` 擦除；循环结束后按剩余树重算 `largest_tree_size`。
- `tree_unload`：把根坐标集合逐个转成索引集合，再统一 `unload_index`。
- `merge_collect`：把 `largest_tree_size` 作为“可扩容尺寸”基准（若已等于上限则取一半），按“每次减半直到不小于 `min_tree_size`”的级数把树分桶（桶 0 为最小级）；超过可扩容尺寸的树跳过；只保留元素数 ≥ 4 的桶；对桶内每棵树以“同桶集合”为候选调用 `neighbor_seek`，相邻树 ≥ 3 时把主体树补到组合首部（`push_back` 后与前位交换），写入 `receiver`。
- `merge_filter`：以组合首位为主体，`offset = size/2`，生成四个对角候选新根 `(root.X ± offset, root.Y ± offset)`；对组合内其余元素枚举三元组（`indices[1..3]`，升序、带进位），计算“主体 + 三元组”的根坐标平均值，用 `Point2d` 的 ULP 相等与候选新根匹配；匹配且四棵树未被 `used_trees` 占用时记录组合并把四棵加入占用集合。
- `tree_merge`：临时关闭缓存；`merge_collect` → `merge_filter`；对每个确认组合求四根平均作为新根、`front->size * 2` 作为新边长，`tree_build` 建新树（失败则跳过该组合）；用 `tree_index_seek(new_root)` 取新树档案；对四棵旧树逐棵 `seek` 出其全部叶区块，并以 `build(point_to_l(center), data)` 迁入新树（载荷 `shared_ptr` 共享）；收集旧树索引并 `unload_index`；恢复缓存开关。

### 4.5 智能创建（`core/四叉树智能创建.hpp`）

```cpp
// 计算初始包围矩形及最大区块划分参数
void smart_params_prepare(const std::vector<Point2l>& coord_set,
    Rect2l& rect_range, uint64_t& father_block_num_all,
    uint64_t& father_block_size) const;
// 单个最大区块的深度划分
void father_block_divide(const std::vector<Point2l>& coord_set,
    int64_t block_left, int64_t block_right, int64_t block_up, int64_t block_down,
    uint64_t block_size, std::vector<Point2d>& node_centers,
    std::vector<uint64_t>& tree_sizes) const;
// 空序列下的首轮智能创建
void tree_build_smart_first(const std::vector<Point2l>& coord_set);
// 四叉树智能创建主函数
void tree_build_smart(const std::vector<Point2l>& coord_set);
```

职责与要点：

- `smart_params_prepare`：以坐标集合的包围矩形为起点；`father_block_size = settings.max_tree_size`（为 0 时输出 0 并返回）；把包围矩形右边界向右补齐到父区块边长的整数倍、上边界向上补齐，得到 `father_block_num_X`、`father_block_num_Y`；校验乘积不溢出后输出总父区块数。包围矩形左/下边界保持原值，区块从真实最小坐标开始铺。
- `father_block_divide`：先在当前区块内筛出点集（每次递归都从头扫描 `coord_set`）；空集返回；算区块中心；`block_size <= min_tree_size` 时直接在中心建树并记录；否则判断“中心聚集”：所有点与中心在 X/Y 上的偏差都不超过 `0.375 * block_size`；不聚集就在当前区块建树，聚集则把点按“x 左半/右半、y 上半/下半”分到四个子区块；只有一个子区块非空时递归细分该子区块（边长减半），否则在当前区块建树。输出为一一对应的根坐标与边长列表。
- `tree_build_smart_first`：准备参数；按 `col = (X - left)/father_block_size`、`row = (up - Y)/father_block_size` 统计每个父区块的点数，并按 `row * father_block_num_X + col` 组装一维下标；逐个非空父区块调用 `father_block_divide`；最后按记录顺序逐棵 `tree_build`。
- `tree_build_smart`：空集合返回；序列为空走首轮建树；否则逐点 `ensure_tree`。

### 4.6 范围分派辅助（`core/区块信息检索.hpp`）

```cpp
// 范围裁剪
bool range_clip(const Rect2l& lhs, const Rect2l& rhs, Rect2l& receiver) const;
// 确保范围内每个区块都有四叉树覆盖
void coverage_ensure(const Rect2l& target_range);
// 区块查询/操作分派
void chunk_dispatch(const Rect2l& target_range, const Chunk_Mode& mode,
    std::vector<Tree_Chunk_Data<T>>& receiver);
```

职责与要点：

- `range_clip`：四边界取 `max(left)`、`min(right)`、`max(down)`、`min(up)`，返回交集是否有效（`left <= right && down <= up`）。
- `coverage_ensure`：序列为空时先以 `(target_range.left, target_range.down)` 为种子做首轮智能建树；以 `X_sequence.front()` 的根与 `block_size` 对齐目标范围；按 `width = (right-left+1)/block`、`height = (up-down+1)/block` 遍历网格，对每个单元格的四个角点各调一次 `ensure_tree`。目的是保证范围内每个网格单元的四角都有归属树，从而后续逐树裁剪不产生空缺。
- `chunk_dispatch`：`read_only = (Seek || Unload)`；空序列时只读直接返回、非只读先建基准树；`Build`/`Get` 先 `coverage_ensure`；随后以 `X_sequence.front()` 的网格对齐；把 `X_sequence` 拷贝成快照，逐棵树算管理范围、`range_clip` 出交集并跳过空交集，按模式调用树的 `build/seek/get/unload`，Seek/Get 的结果以移动迭代器并入 `receiver`。快照保证“遍历期间管理器新建/扩容树不会使迭代器失效”。

### 4.7 私有数据成员

`Quadtree<T>`：`Node root`（根，恒为中间节点，由默认构造创建）、`Tree_State state`、`std::function<bool(const Point2d&, const Point2l&)> callback`。

`Quadtree_Manager<T>`：`uint64_t largest_tree_size`、`std::vector<Tree_Record<T>*> X_sequence`（根 X 降序）、匿名结构体 `tree_cache { std::vector<Tree_Record<T>*> records; std::vector<Rect2l> ranges; }`、`Tree_Manager_Settings settings`。

## 五、模块内部架构

### 5.1 分片组织方式

本模块全部是模板，模板定义必须对使用方的翻译单元可见，因此不存在“声明与实现分离编译”的常规做法。这里采用“声明集中 + 实现分片 + 聚合头”的纯头文件式组织，具体为四层：

```
数据结构.h            自由结构（Tree_State / Tree_Chunk_Data / Tree_Record / Settings），含必要的类前向声明
      ↓
函数预声明.h          唯一的类声明（含私有内嵌类型与全部成员声明）
      ↓
core/*.hpp            每个 .hpp 只做“类外定义”分片，一律 #include "../函数预声明.h"
      ↓
四叉树.h / 四叉树管理器.h   聚合头：include 声明头 + 全部 core 分片，供使用方一次性引入
      ↓
core/*实例化.cpp       每个模块各一个、唯一被编译的非模板尾文件，写 template class X<int>;
```

两个模块的 `.hpp` 分片都不参与独立编译，它们是“按职责切开的实现头”。分片文件自身也写 `#pragma once`，因此即使被单独包含也不会重复展开；但正常使用路径一律经由聚合头。聚合头只做 include，不含任何代码。

关键推论：由于定义随头分发，任何使用方 TU 只要包含 `四叉树管理器.h`，就能自行实例化任意 `T`；库内 `四叉树管理器实例化.cpp` 只额外提供 `Quadtree_Manager<int>` 的符号。快照内应用层 `世界.h` 正是这样实例化 `Quadtree_Manager<chunk_entities>` 的，不需要库侧改动。

包含基准有两套，依据 `Engine/EngineFoundation/CMakeLists.txt` 的说明：头文件之间跨目录一律用“项目根相对”的 `Engine/EngineFoundation/...`，`.cpp` 文件跨目录用“本层根相对”的 `src/...`。快照中 `Quadtree_Manager/函数预声明.h` 对二分查找用了项目根相对写法，符合该约定；`Quadtree/函数预声明.h` 与两个 `数据结构.h` 对坐标类型用了 `../../math/坐标类型.h` 的相对写法，与该约定不完全一致，但因头快照镜像保持同样的相对层级而仍可解析【待确认：9】。

### 5.4 所有权与生命周期

```
Quadtree_Manager<T>（栈对象 / 使用方持有）
  ├─ settings : Tree_Manager_Settings（值）
  ├─ largest_tree_size（值）
  ├─ tree_cache.records → Tree_Record<T>*（非拥有，指向 X_sequence 元素）
  └─ X_sequence : vector<Tree_Record<T>*>（拥有）
        └─ Tree_Record<T>（new(nothrow) 分配）
              ├─ root / size（值，必须与树同步）
              └─ tree : Quadtree<T>*（new(nothrow) 分配，私有）
                    ├─ state（值）
                    ├─ callback（std::function，捕获管理器 this）
                    └─ root : Node（栈成员，值）
                          └─ shared_ptr<Node> 四子树（拥有）
                                ├─ Middle：array<shared_ptr<Node>,4>
                                └─ Leaf：shared_ptr<T>（拥有一份载荷强引用）
```

叶载荷 `shared_ptr<T>` 是强引用：树持有一份，查询结果 `Tree_Chunk_Data<T>` 复制时再持有一份；两者都释放后载荷销毁。模块内没有任何 `weak_ptr`，也没有“实体 ID 集合”以外的实体持有关系。载荷内容完全由使用方解释；快照内应用层用 `chunk_entities`（帧戳 + 敌人/投射物编号数组）实现“逐帧惰性清空”。

生命周期规则：管理器析构 → `clear()` → 逐棵树 `delete`；树析构 → `Node` 递归释放 → 叶载荷引用减一。查询结果的生命周期独立于树：即使树被卸载，已返回的 `Tree_Chunk_Data` 仍通过 `shared_ptr` 保活载荷，直到结果容器清空。

线程归属：全部对象无内部同步设施，归属调用线程；管理器不可在多个线程间共享调用。

### 5.5 数据流

单点写路径：坐标 → `chunk_range_calcu`（对齐到区块网格）→ `expand_analyse`（必要时扩容/请求管理器扩容）→ `chunk_recur`（按象限下潜、按需建中间节点）→ `leaf_slot_apply`（建/取叶）→ `Tree_Chunk_Data{center, data}`。

范围路径在管理器层多一层“切树”：目标矩形 → 以首树网格对齐 → 覆盖补齐（仅 Build/Get）→ 快照遍历所有树 → 逐树 `range_clip` → 调该树的范围重载 → 合并结果。

多树布局由“坐标系拼图”决定：每棵树是正方形，根为 `.5` 结尾，块边长为 2 的幂，因此同一棵树的网格边界与其管理范围边界严格重合；相邻树按 2 的幂尺寸规则拼接，边界处不重叠（闭区间相接）。

## 六、模块设计 / 实现细节

### 6.1 节点容量与细分阈值：没有容量，只有几何深度

四叉树不存在“节点容量上限”或“按占用数分裂”的机制。中间节点固定四个子槽，叶子固定一个 `shared_ptr<T>` 槽；是否细分完全由 `size` 与 `block_size` 决定：`depth_calcu` 给出层数 `log2(size/block_size)`，`chunk_recur` 严格下潜到该层才处理叶槽。因此同一条路径上的区块数量恒定，与写了多少数据无关；未访问路径零物化。这里的“阈值”只有两个：`block_size`（最小单元格，叶子的物理下限）与 `max_size`（整树扩容上限）。管理器层的“细分阈值”另有两处：智能建树的 `0.375 * block_size` 中心聚集判据（见 §4.5），以及合并要求的“同边长 ≥ 4 棵且根构成 2×2”。

由此带来的直接后果是：树的深度只与尺寸比有关，不随数据量增长；查询复杂度是 O(深度) 的路径下降，范围查询则是 O(相交区块数)；代价是稀疏数据也会为每个被访问的区块单独分配叶节点与载荷（即使载荷是默认构造的空对象）。

### 6.2 节点双态与按需物化

`Node` 用 `std::variant` 表达“中间/叶”双态，索引 0 存四子指针、索引 1 存载荷。根由 `Node()` 默认构造成中间节点，因此根永远是中间节点；叶只在最深层由 `leaf_slot_apply` → `child_step(..., Leaf, ...)` 创建。`child_step` 在推进前校验“当前节点必须中间态、目标槽状态须与期望一致”，这既防止只读查询把浅层叶改写成中间节点，也防止把已有叶数据丢弃。节点数组是固定的四个 `shared_ptr`，没有动态子列表，因此内存只沿真实访问路径增长。

### 6.3 几何语义：闭区间、Y 轴方向与半整数根

`Rect2l` 是闭区间，`right-left+1` 才是宽度；`up` 是 Y 轴较大值，`down` 是较小值。`child_range_calcu` 切出的四个子范围各占 `size/2` 个单元格，但边界归属不对称：X 轴左半闭合到 `mid_x`、右半从 `mid_x+1` 起；Y 轴北半从 `mid_y+1` 起、南半闭合到 `mid_y`。因此叶子的“东南”“西北”等象限在边界上是互斥的，不会出现同一整数坐标同时属于两个子范围。

根坐标默认 `.5` 结尾不是审美选择，而是网格契约：`rect_range_calcu` 用 `int64(root.X-0.5)-half_span` 与 `int64(root.X+0.5)+half_span`，只有根为半整数时两个锚点相差 1、范围宽度才恰为 `size`。`range_align` 同理会把区块网格锚定在整数上：以根 `127.5`、区块 16 为例，左边界满足 `≡0 (mod 16)`、右边界满足 `≡15 (mod 16)`，于是区块是 `[0,15]`、`[16,31]`……。管理器的建树函数（`new_tree_range_calcu`、`father_block_divide`、`tree_merge`）算出的中心必然是半整数（偶数边长范围的中点），因此在管理器内部该契约始终成立。若外部直接给 `Quadtree` 传整数根，有效中心会向 0 偏移半格，分量为 0 时范围还会少一格，详见 6.14【待确认：10】。

### 6.4 坐标比较：点用 ULP，矩形用精确

`Point2` 的相等是“近似相等”（浮点 4 ULP 容差、NaN 恒不等、Inf 精确），`Rect2` 的相等是精确比较。模块只在“根坐标同一性”上依赖 `Point2` 的容差比较：`tree_index_seek`、`callback_tree_seek`、`merge_filter` 的均值匹配、`tree_unload` 的根匹配。这样做的动机是均值除以 4 会引入浮点误差，若用精确比较，合法组合可能被判不等。代价是该比较不具传递性，不能作为容器键；序列查找只能退化为“先按 X 二分、再容差比较完整坐标”。

### 6.5 四模式语义矩阵

| 模式 | 触发入口 | 是否创建节点 | 是否可能扩容 | 是否写结果 | 备注 |
| --- | --- | --- | --- | --- | --- |
| Build | `build` | 是 | 是 | 否（单点重载可挂载载荷） | 已存在叶不替换载荷 |
| Seek | `seek` | 否 | 否 | 是 | 只读 |
| Get | `get` | 是 | 是 | 是 | 创建并返回；范围重载会物化整个范围 |
| Unload | `unload` | 否 | 否 | 否 | 只 reset 最深层叶 |

只读判定集中在两处：`chunk_dispatch(Rect2l)` 用 `mode == Seek || mode == Unload`，管理器 `chunk_dispatch` 同构。只读模式下 `child_step` 不分配、`expand_analyse` 立即退出，因此 `seek`/`unload` 是“零副作用”的（除缓存写入外）。

### 6.6 载荷挂载只发生在“新建叶”

`leaf_slot_apply` 通过 `child_step(this_node, quadrant, Node_Kind::Leaf, read_only, data)` 处理叶槽。若槽已有叶，`child_step` 只做状态校验并返回旧叶，`external_data` 被忽略。于是 `build(point, data)` 的语义是“若该区块不存在则建叶并挂载，否则保持原载荷”。要替换载荷必须先 `unload` 再 `build`（可疑2）。管理器 `build(point, data)` 与合并迁移都依赖这一点；后者依赖“新树是全新的、槽必为空”，因此能正确共享旧载荷。

### 6.7 nothrow 分配失败会留下“空载荷叶子”

`Node` 的叶分支写 `emplace<1>(std::shared_ptr<T>(new(std::nothrow) T()))`。当 `new` 返回空指针时，得到的 `shared_ptr` 是空的，但 `variant` 索引仍然是 1，节点会被判定为“叶已存在”。后续 `seek`/`get` 会在 `leaf_slot_apply` 里 `emplace_back(center, std::get<1>(...))`，返回 `true` 而 `data == nullptr`。调用方无法用 `data == nullptr` 区分“未建区块”和“分配失败”（快照内应用层正是用该判据跳过写入的）。这是模块内唯一一处“失败被记录为某种合法状态”的地方【待确认：6】（可疑3）。

### 6.8 扩容：在根与旧子之间插层，O(1) 完成

`tree_expand` 不做“整树重建”，而是分配四个新中间节点，作为根的新子节点，并把旧四个子树按相反象限塞进这四个新节点的对应槽：旧 NW → 新 NW.SE、旧 NE → 新 NE.SW、旧 SW → 新 SW.NE、旧 SE → 新 SE.NW。这样旧子树整体下沉一级、范围保持不变，`state.size *= 2`，根的几何中心不变。代价是四个节点的分配，收益是旧叶的范围与中心完全不动（测试 `扩大保留原有区块` 验证同一坐标扩容后仍指向同一载荷）。`tree_expand` 的失败条件是上限、根非中间态、任一分配失败。

### 6.9 扩容分析循环：只读不扩、无回调自扩、有回调仲裁

`expand_analyse` 是“越界 → 扩容”的唯一驱动点。循环每轮重新计算当前管理范围并求交：完全覆盖或只读则退出；有回调时先询问回调，回调拒绝即退出，回调同意才调 `tree_expand`；无回调时直接按 `max_size` 自扩；每轮末尾再查一次上限。因为循环存在，单次 `get`/`build` 可以连续翻倍多级直到容纳目标（快照内 `越界检索连续扩大直至容纳目标` 验证了这一点）。只读退出发生在“求交之后”，所以 `seek` 与 `unload` 的 `reachable_range` 被裁剪为目标与当前管理范围的交集。该函数在 `depth_calcu` 的零深度判断之前执行，因此 `block_size == 0` 的未配置树在越界 `build`/`get` 时仍可能先扩容、随后因深度 0 直接返回（可疑4）。

扩容被拒绝（回调拒绝或已达上限）时，`range_intersect` 可能把交集算成 `left > right` 或 `down > up` 的“反向矩形”，例如目标点整体位于树右侧时得到 `left=288, right=255`。该反向矩形不会被显式修正，而是由 `range_overlap_check` 的四侧比较自然判为“不相交”，于是整轮递归不产生任何叶，`get` 返回 `false`。内部节点也不会被创建：`chunk_recur` 先用 `range_overlap_check` 剪枝，不相交的象限根本不会进入 `child_step`。因此“越界且不可扩容”是零副作用失败。

### 6.10 管理器级联协议：回调只“批准”，扩容由树执行（internal 的两套路径）

管理器建树时给每棵树注册 lambda：`tree_expand_approve(root, target)`，`internal` 取缺省 `false`。于是树越界时链路是“树询问管理器 → 管理器做可行性检查并把 `record->size` 翻倍 → 树自己 `tree_expand()`”。管理器在这一步**不**执行扩容，它只在 `internal == true` 时才直接调 `tree->tree_expand()`（用于 `ensure_tree` 主动补覆盖，没有树侧调用者）。两条路径的返回值语义因此不同：`true` 表示“请调用方扩容”，`false` 表示“不要扩容”（拒绝，或已改由新建树承担）。这是本模块最容易误读的隐式契约【待确认：11】。

风险：`internal == false` 时管理器先把 `record->size` 翻倍，再等树执行 `tree_expand`；若树侧分配失败返回 `false`，管理器不会回滚 `record->size`，记录与树内 `state.size` 失配，后续 `tree_inclusion_seek` 会按偏大的范围认为该树覆盖了它实际覆盖不到的点（可疑5）。

### 6.11 多树布局：序列、直属定位、缓存

`X_sequence` 按 `root.X` 降序排列，`tree_index_seek` 依赖该序做范围二分。直属定位有两个来源：高速缓存（`records` + `ranges` 平行数组）与全序列线性扫描。缓存是“转置式”而非“移到队首”：命中条目只与前一条交换；新条目 `push_back` 到尾部（逻辑上是“最旧”位置）；缓存满时 `pop_back` 淘汰尾部。缓存写入有两个门槛：树数量 ≥ `cache_active_threshold`、`max_cache_records > 0`。缓存失效点覆盖了所有会改范围或删树的路径：扩容后刷新对应条目（`tree_expand_approve`）、卸载时按指针删除条目（`unload_index`）、合并期间临时关闭、`cache_clear` 全清。

直属判定的几何依据是“目标点落在某树的 `rect_range_calcu` 闭区间内”。管理器依靠“树间不重叠”的建树纪律（`expand_approve` 的重叠检查、`new_tree_range_calcu` 的重叠拒绝）让该判定基本唯一；一旦重叠，先出现在序列中的树获胜。

### 6.12 覆盖补齐与快照遍历

范围 `Build`/`Get` 前会 `coverage_ensure`：以首树网格对齐目标范围，逐网格单元对四个角点各 `ensure_tree` 一次。它保证“每个单元格的四角都有归属树”，从而逐树裁剪时不出现无主空洞；代价是 O(单元格数 × 定位成本)，对整树范围（16×16 单元）就是 1024 次 `ensure_tree`。分派阶段先拷贝 `X_sequence` 快照再遍历：树的 `build`/`get` 可能通过回调让管理器新建树，快照避免容器扩容导致迭代器失效；新建的树不在本轮遍历内，但因 `coverage_ensure` 已提前补齐，不影响本轮完整性。对齐基准取 `X_sequence.front()`（根 X 最大者，不等于最大树）；管理器自建树的根全为半整数且边长是区块的 2 的幂倍数，各树网格共享同一锚点，故实际不产生错位；若序列中混入不同锚点的树（例如外部直接构造的整数根树），逐树二次对齐可能出现多/少一格的边界差（可疑9，推测）。

### 6.13 相邻查找三级筛

`neighbor_seek` 的判据是“两棵树的闭区间矩形相接或重叠”，实现分三级：第一级用“以主体根为中心、半宽 `(size + largest_tree_size)/2`”的矩形按根坐标过滤；第二级逐轴判断“根坐标差 ≤ 两树边长之和的一半”：两轴都在阈值内直接入选（同尺寸的正交邻居因另一轴差为 0 也落在这一档），只有一轴在阈值内才进入待确认；第三级用完整矩形做闭区间交集确认，谓词为 `right1 > left2-1 && right2 > left1-1`（Y 轴同构：`up1 > down2-1 && up2 > down1-1`），但两轴结果以“或”合并——任一轴相交即判相邻。该“或”语义使“X 方向相距很远、Y 方向重叠”的候选也会被当成相邻（可疑13）。第一级范围用全局最大边长而非同组最大边长，框偏大但只增加候选数【待确认：8】；第三级保证“仅共边”也算相邻，这是合并 2×2 组合的必要条件。第二级的阈值恰为“两树相接时的中心距”，因此任何真正共边的两棵树都不会被第二级漏掉。

### 6.14 整数根坐标的中心偏移与缺口

`rect_range_calcu` 与 `range_align` 都靠 `int64(root.X ± 0.5)` 取锚点。根为半整数时两个截断值相差 1，范围宽度等于 `size`、中心与根一致；根分量为非零整数 `k` 时，`int64(k-0.5)` 与 `int64(k+0.5)` 分别取到 `k-1` 与 `k`（向量零截断），宽度仍为 `size`，但范围中心变成 `k-0.5`（`k>0`）或 `k+0.5`（`k<0`），即有效中心向 0 偏移半格；根分量恰为 0 时两个截断值都取到 0，左右锚点重合，管理范围宽度变成 `size-1` 格。管理器自建的根都是半整数，因此内部不受影响；外部直接构造 `Quadtree(size, {整数, 整数})` 会踩到中心偏移或缺口。快照内测试只读取该类根的状态、未在其上建区块，故未暴露【待确认：10】（可疑7）。

### 6.15 智能建树的划分规则与尺寸分布

首轮智能建树以 `max_tree_size` 为“父区块”边长，把包围矩形向右/向上补齐后铺网格；每个父区块独立递归：点集为空不建树；边长到 `min_tree_size` 必建树；点集不满足 `0.375 * block_size` 中心聚集则在当前边长建树；聚集且只落在一个子象限时递归缩小；聚集但分散到多个子象限时在当前边长建树。结果树的边长落在 `[min_tree_size, max_tree_size]`，且彼此不重叠（子区块按网格切分，父区块按补齐网格铺开）。`father_block_divide` 每次递归都从完整坐标集合重新筛选，复杂度与“点数 × 递归深度”成正比。

### 6.16 新树补位：半格校准与整格滑动

原地扩容不可行时，`new_tree_range_calcu` 以 `min_tree_size` 为边长、以基准树根为中心取初始框；若基准树不是最小尺寸，先把框沿目标方向平移半格（`min_size/2`，X/Y 各自判断），再按 `min_size` 整格滑动至包含目标。半格校准使新树框相对“以基准树根为中心的整格网格”错开半格；源码只记录了该步骤，未注明动机。整格滑动保证新框与基准树网格仍以 `min_size` 为步长对齐。新树根取框中心（必然是半整数），边长取 `min_tree_size`，建树前还要对全部其它树做一次闭区间重叠检查，任一重叠即放弃。

### 6.17 合并：分级、四元组合、载荷共享迁移

`tree_merge` 分三段。第一段按“边长减半到不小于 `min_tree_size` 的级数”分桶，只处理 ≥ 4 棵的桶，并要求组合内根构成 2×2（由均值匹配实现）。第二段为每棵主体树枚举组合内的三棵树，校验组合未被占用。第三段新建双倍边长树，把旧树全部叶区块的 `shared_ptr` 逐点迁入，再卸载旧树。载荷迁移是“共享所有权”，不复制对象，因此合并前后载荷地址不变（测试 `四棵相邻树合并后区块数据迁移` 验证）。

风险：`merge_filter` 只校验“四根均价等于某个对角偏移点”，不校验四棵树是否恰好铺满新树且互不重叠（可疑6）。一旦出现“平均值凑巧相等但实际不铺满”的组合，新树会有空洞；若四个旧树的叶落到新树同一叶槽，后写的数据会被 `build` 忽略（见 6.6），造成载荷丢失。`neighbor_verify` 的“任一轴相交即相邻”还会把 X 方向远离、Y 方向重叠的树混入候选（可疑13），进一步放大该风险。此外，新建双倍树时 `tree_build` 只检查根坐标是否重复，不再与其它现存树做范围重叠检查（可疑12）；`tree_build` 成功后若 `tree_index_seek` 取不到新树索引会 `continue`，留下已建但未迁移、未卸载的空树（可疑11，理论上仅在该容差查找失败时触发）。

### 6.18 卸载不回收骨架

`unload` 只把最深层叶槽 `reset`，中间节点全部保留；`unload_index` 是“整树回收”，会 `delete` 树与档案。因此单区块卸载不会降低树的深度或节点数：中间节点继续复用，但被卸载的叶节点及其载荷会被真正释放，下次构建同一区块时会重新分配叶节点与载荷（不会新增中间节点）。长期稀疏使用会保留大量空中间节点，模块不提供“压缩/回缩”接口。

### 6.19 设置项的相互约束

管理器把 `block_size < min_tree_size <= max_tree_size` 且三者两两为 2 的幂倍数作为不变量：`set_block_size` 用 `min_tree_size` 校验，`set_min_size` 用 `block_size` 与 `max_tree_size` 校验，`set_max_size` 用 `min_tree_size` 与现存树校验。`set_block_size` 额外要求序列为空；`set_max_size` 会把新上限下发给现存树；`set_min_size` 只改设置、不下发也不回填。于是“先抬高下限、后建树”会导致序列里同时存在小于新下限的旧树（可疑8），后续合并分级以新下限为基准，这些旧树会落到桶 0，与“真正的下限树”混在一起。

### 6.20 所有权、拷贝与析构

树与档案由管理器用裸指针独占，缓存只是弱语义的非拥有指针。`Quadtree` 与 `Quadtree_Manager` 都没有删除拷贝构造/赋值：拷贝一棵树会共享整套 `Node` 子树与指向原管理器的回调；拷贝一个管理器会得到两份指向同一批树与档案的 `X_sequence`，析构时双重释放（可疑10）。使用方需自行禁止拷贝（快照内应用层 `World` 已用 `= delete` 处理）。

### 6.21 失败处理与异常策略

全模块的内存分配一律 `new(std::nothrow)`，不使用异常；设置类接口用 `false` 表达拒绝；查询类接口用“空结果/空指针”表达失败；无日志、无告警。唯一可能抛出的是 `std::get<0>`/`std::get<1>` 的 `variant` 类型检查失败，但所有调用点都被 `child_step` 的类型校验保护，正常路径不会触发。除零风险点（`range_align` 的取模、`coverage_ensure` 的宽度/高度、`new_tree_range_calcu` 的步长）均有 `block_size == 0` / `<= 0` 的早退防御。

### 6.22 64 位化与溢出

坐标与范围统一用 `Point2l`/`Rect2l`（`int64`），树尺寸用 `uint64`；中间运算（半跨度、子范围中点、对齐取模、智能建树的宽高）都先转 `int64`，并用“差值求中点”避免左右边界相加溢出。`depth_calcu` 的返回值是 `int`，对 2^63 边长与最小 16 区块，层数为 59，仍在 `int` 范围。`rect_range_calcu` 的半跨度取 `size/2 - 1`（先减后转），避免 `size/2` 超界。

### 6.23 查询范围“先对齐、后裁剪”的副作用

`chunk_dispatch` 的顺序是“对齐 → 扩容分析 → 递归”，不是“裁剪 → 对齐”。因此一个完全落在树内、但边界未对齐的查询范围，向外对齐后可能越过树边界，从而触发一次扩容（或管理器补建树），即使原始范围与树完全相交。对于半整数根与 2 的幂区块，树的边界本身已对齐，管理器裁剪出来的交集边界与树网格重合，通常不会触发这种“对齐溢出”；直接使用 `Quadtree` 且查询范围贴边时则会。这是设计取舍：对齐优先保证“范围严格包含目标区块”，代价是贴边查询可能多扩一级。

### 6.24 载荷语义：强引用、无弱引用、实体以编号存于载荷

树只保存 `shared_ptr<T>`，不保存坐标、实体指针或实体编号。位置是“路径的隐式结果”，每次查询由 `center_calcu` 重新推导。全模块没有 `weak_ptr` 或“区块失效标记”，失效策略完全由载荷自身承担：快照内应用层用帧戳（`chunk_entities::stamp`）在写入时惰性清空、读取时只认本帧，从而避免每帧全量卸载。实体（敌人/投射物）以 `uint32_t` 编号存放在载荷的两个数组里，树不知道实体存在。这也是“为什么每帧重建索引不必清树”的根本原因：树只负责区块槽位，槽位内的数据由载荷协议自管理。

## 七、模块运行链路详例

以下数值均按“区块 16、树边长 256、根 `(127.5,127.5)`”前提计算（与快照内管理器测试的配置一致）。

### 7.1 链路一：管理器单点写入 + 取回（空序列首次建树）

调用：`Quadtree_Manager<int>`（`min_tree_size = max_tree_size = 256`、`block_size = 16`），执行 `build(Point2l(10,10), data)`。

1. `Quadtree_Manager<T>::build(Point2l, shared_ptr)`（`core/区块信息检索.hpp`）→ `ensure_tree(10,10)`。
2. `ensure_tree`（`core/基础操作.hpp`）→ `tree_inclusion_seek(10,10)`：缓存为空、`X_sequence` 为空 → 返回 `nullptr`。
3. 序列为空 → `tree_build_smart_first({(10,10)})`（`core/四叉树智能创建.hpp`）。
4. `smart_params_prepare`：包围矩形 `[10,10]×[10,10]`；`father_block_size = 256`；宽 `1` 补齐到 256（右边界 `10+255=265`，上边界同理）→ 父区块数 1。
5. `father_block_divide(block=[10,265]×[10,265], block_size=256)`：点集非空、中心 `(137.5,137.5)`；`block_size <= min_tree_size` 成立 → 记录根 `(137.5,137.5)`、边长 256。
6. 回到 `tree_build_smart_first` → `tree_build((137.5,137.5), 256)`（`core/基础操作.hpp`）：分配档案与树；`rect_range_calcu(137.5,256)` 得管理范围 `[10,265]×[10,265]`；下发 `max_size=256`、`block_size=16`；注册回调；插入序列并排序；`largest_tree_size = 256`。
7. `ensure_tree` 末尾再 `tree_inclusion_seek(10,10)`：`X_sequence` 只有 1 棵（未达缓存门槛 32），直接线性扫描；`[10,265]` 包含 `(10,10)` → 返回该记录。
8. `Quadtree_Manager::build` → `record->tree->build(10,10,data)`。
9. `Quadtree::build(Point2l, data)`（`core/区块信息检索.hpp`）→ `chunk_dispatch(10,10, Build, temp, data)` → `chunk_range_calcu(10,10)`（`core/导航与范围计算.hpp`）：点折叠为 `[10,10]`，按根 137.5、区块 16 对齐 → `[10,25]×[10,25]`（中心 `(17.5,17.5)`）。
10. `chunk_dispatch(Rect2l, Build, ...)`：`read_only=false`；再次对齐（不变）；`expand_analyse`：管理范围 `[10,265]` 完整覆盖目标，标记等于 `state.root`，不扩容，`reachable_range=[10,25]`；`depth_calcu = log2(256/16) = 4`；`tree_range=[10,265]`；`chunk_recur(root, ..., now_level=1, max_level=4)`。
11. `chunk_recur` 逐层下潜：根（256）中点 `(137,137)` → 目标只与 SW 子范围 `[10,137]×[10,137]` 相交 → `child_step(..., Middle, false)` 分配 SW 中间节点（level 2）；该节点中点 `(73,73)` → SW 子范围 `[10,73]×[10,73]`（level 3）；中点 `(41,41)` → SW 子范围 `[10,41]×[10,41]`（level 4）；由于 `now_level == max_level`，调用 `leaf_slot_apply`。
12. `leaf_slot_apply` 在 `[10,41]` 上遍历四槽：目标只与 SW 槽 `[10,25]×[10,25]` 相交 → `child_step(node, SW, Leaf, false, data)`：槽为空 → `new(nothrow) Node(Leaf, data)` → 挂载载荷；Build 模式不写结果。
13. 之后 `get(10,10)`：同一路径全部已物化，`leaf_slot_apply` 的 `child_step` 命中旧叶 → `emplace_back((17.5,17.5), data)` → `get` 返回 `true`，`receiver.center=(17.5,17.5)`、`receiver.data` 为同一 `shared_ptr`。
14. 若此时执行 `seek(10,10)`，同样命中并返回同一载荷；若执行 `seek(10,10)` 在步骤 9 之前（即未 build），因路径全空且只读不分配，`child_step` 在第一个中间层就失败，返回 `false`。

### 7.2 链路二：树扩大 + 节点细分（管理器级联，原地扩容分支）

前提：管理器 `min_tree_size=256`、`max_tree_size=512`、`block_size=16`；已有一棵树根 `(127.5,127.5)`、边长 256（管理范围 `[0,255]²`）；执行 `build(Point2l(300,300), data)`。

1. `Quadtree_Manager::build` → `ensure_tree(300,300)`：`tree_inclusion_seek` 未命中（`[0,255]` 不含 300）。
2. `ensure_tree` 非空分支：`nearest_tree` 取唯一树；记录快照（序列长度 1、`largest_tree_size=256`）；调 `tree_expand_approve((127.5,127.5), (300,300), internal=true)`。
3. `tree_expand_approve`（`core/四叉树扩大回调管理.hpp`）：
   - `callback_tree_seek(127.5,127.5)` 命中；
   - `tree_inclusion_seek(300,300)` 仍为 `nullptr`；
   - 当前 `size=256 < 512` → `expanded_range = rect_range_calcu(127.5,512) = [-128,383]²`；`rect_filter` 在序列中找不到其它树根 → 可扩容；
   - 把 `record->size` 临时置为 512；`neighbor_seek` 的半宽为 `(512+256)/2 = 384`，候选框 `[-256.5,511.5]²`；`rect_filter` 排除主体后为空 → 无相邻树冲突；
   - `internal=true` → 直接调 `now_tree->tree->tree_expand()`（`core/节点创建与树扩大.hpp`）：分配四个新中间节点，旧 `[0,255]` 四子树按相反象限下沉（旧 NW → 新 NW.SE 等），`state.size` 变为 512；
   - 维护 `largest_tree_size = 512`、刷新缓存中该树范围（本场景缓存为空）；返回 `true`。
4. 回到 `ensure_tree`：重新 `tree_inclusion_seek(300,300)`，该树管理范围已变为 `[-128,383]²` → 命中，返回记录；循环结束。
5. `record->tree->build(300,300,data)` → `chunk_dispatch`：`chunk_range_calcu(300,300)` 得 `[288,303]²`（中心 `(295.5,295.5)`）；`expand_analyse` 在新范围内无需扩容；`depth_calcu = log2(512/16) = 5`；`chunk_recur` 从根开始。
6. 下潜路径与范围：根 `[-128,383]`（中点 127）→ 目标在 NE：`[128,383]²`（中点 255）；→ NE：`[256,383]²`（中点 319）；→ 目标 300 ≤ 319 → SW：`[256,319]²`（中点 287）；→ 目标 300 > 287 → NE：`[288,319]²`（此时 `now_level == max_level = 5`）。
7. `leaf_slot_apply` 在 `[288,319]` 上遍历四槽：目标与 SW 槽 `[288,303]²` 相交 → `child_step(..., Leaf, false, data)` 新建叶并挂载载荷；叶中心 `(295.5,295.5)`。
8. 扩容对旧数据的影响：旧叶（如 `(10,10)` 所在 `[0,15]²`）在扩容后整体下沉一级，范围与中心不变；新树的深度比原来多一级，查询该旧叶要多下降一层，但语义一致。

### 7.3 链路三：原地扩容不可行时改建新树（级联第二部分）

前提改为 `max_tree_size=256`（已有一棵边长 256 的树，管理范围 `[0,255]²`），执行 `build(Point2l(300,300), data)`。

1. `ensure_tree` → `tree_expand_approve(root=(127.5,127.5), target=(300,300), internal=true)`。
2. 当前 `size == max_tree_size`（256 < 256 为假）→ 跳过原地扩容分支，进入新建树分支。
3. `new_tree_range_calcu`：初始框 `rect_range_calcu(127.5, min=256)` 因 `primary.size == min_tree_size` 不做半格校准 → `[0,255]²`；滑动：右边界 255 < 300 → 整框右移 256 → `[256,511]`；上边界 255 < 300 → 整框上移 256 → `[256,511]`；此时已包含目标。
4. 与其它树做 `range_clip`：`[256,511]²` 与主体 `[0,255]²` 无交集（`256 > 255`）→ 不重叠。
5. 新根取框中心 `(left+right)/2.0 = (256+511)/2 = 383.5`；边长取 `min_tree_size = 256`；`tree_build(383.5, 256)` 成功入列（`max_size=256` 满足），`largest_tree_size` 保持 256。
6. `tree_expand_approve` 返回 `false`（告知树侧“不要扩容”）。
7. `ensure_tree` 重新 `tree_inclusion_seek(300,300)`：新树 `[256,511]²` 包含目标 → 命中；随后 `record->tree->build(300,300,data)` 在新树上走 `depth = 4` 的路径，叶槽 `[288,303]²`，中心 `(295.5,295.5)`。
8. 结果：旧树保持 256，新树以最小尺寸补位；无扩容、无旧数据迁移。

若管理器配置为 `min_tree_size=128`、主体树边长 256（非最小），则步骤 3 会先做半格校准：初始框 `rect_range_calcu(127.5,128) = [64,191]²`，目标 `(300,300)` 在右/上侧 → 偏移 `+64, +64` → `[128,255]²`；再整格滑动 `+128` → `[256,383]²`；新根 `(319.5,319.5)`（与快照内测试 `越界查询按基准树校准新树位置` 期望一致）。

### 7.4 链路四：四棵树合并与载荷共享迁移

前提：`max_tree_size=256`、`min_tree_size=256`、`block_size=16`；`tree_build_smart({(0,0),(300,0),(0,300),(300,300)})` 建立 4 棵边长 256 的树，根分别为 `(127.5,127.5)`、`(383.5,127.5)`、`(127.5,383.5)`、`(383.5,383.5)`（包围矩形 `[0,511]²` 按 256 铺成 2×2 父区块）。

1. 对四个坐标各执行一次 `get`，每棵树物化一个叶并写入区分值；载荷地址记为 A、B、C、D。
2. `set_max_size(512)`：允许合并出双倍边长；现存 4 棵树均满足“512 ≥ 256 且为 256 的 2 的幂倍数”，下发新上限。
3. `tree_merge`（`core/四叉树合并.hpp`）：临时关闭缓存。
4. `merge_collect`：`largest_tree_size=256` 且不等于上限 512 → 可扩容尺寸取 256；按“减半直到不小于 `min_tree_size`”计算级数，`256/2=128` 已小于 256，故只建一个桶（桶 0）；四棵树边长 256 均不超过可扩容尺寸 → 全部入桶 0；桶内数量 4 ≥ 4 → 合格。
5. 对桶内每棵主体树 `neighbor_seek(主体, 同桶)`：矩形半宽 `(256+256)/2=256`，2×2 布局中其余 3 棵根都落在框内；分类阶段对同尺寸相邻树，两轴差值均为 0 或 256（正交邻居一轴 0、对角邻居两轴 256），均不大于 `half_sum = 256`，三棵全部按“两次命中”直接入选（不进入确认环节；头文件注释称“两次命中即对角”与此不符，见 §四 与待确认 12）→ 每个主体得到 3 棵相邻树 → 组合写入 `merge_collect` 结果（主体在首位）。
6. `merge_filter`：以首位为体，`offset=128`，四个候选新根为 `(255.5,255.5)`、`(255.5,-0.5)`、`(-0.5,255.5)`、`(-0.5,-0.5)`；枚举其余三棵（唯一三元组），四根均值 `(255.5,255.5)` 与首个候选相等 → 记录组合，四棵加入 `used_trees`；其余主体组合因占用冲突被跳过。
7. `tree_merge` 第三段：新根 `(255.5,255.5)`、新边长 512 → `tree_build` 成功，管理范围 `rect_range_calcu(255.5,512) = [0,511]²`；`tree_index_seek` 取到新树档案。
8. 逐棵旧树：算自身范围（如 `[0,255]²`），`seek(range, buffer)`（只读）取出该树全部叶区块（本例各 1 个），对每条 `build(point_to_l(center), chunk.data)` 迁入新树：新树是全新的，叶槽为空 → 载荷指针直接挂载，地址仍为 A/B/C/D。
9. 收集四棵旧树索引，`unload_index` 倒序删除：每删一棵先从缓存移除指针、`delete` 树与档案、从 `X_sequence` 擦除；结束后重算 `largest_tree_size=512`。
10. 恢复缓存开关。最终序列 1 棵树，四次 `get` 仍取回原载荷地址，数据内容不变。

### 7.5 链路五：范围查找与高速缓存转置（补充）

前提：序列已有 ≥ 32 棵树（达到 `cache_active_threshold`）、缓存启用、条目上限 16。

1. `seek(Rect2l, receiver)` → `chunk_dispatch(Seek)`：只读，不补齐覆盖；以首树网格对齐；快照遍历所有树。
2. 每棵树：`rect_range_calcu` + `range_clip` 出交集 → `Quadtree::seek(region, buffer)` → `expand_analyse(read_only=true)` 只把范围裁到交集、不扩容 → `chunk_recur` 只沿已物化路径下潜 → `leaf_slot_apply` 读模式不建叶 → 结果并入 `receiver`。
3. 单点 `seek(point)` 先走 `tree_inclusion_seek`：若目标命中缓存第 k 条（k>0），与第 k-1 条交换后返回（转置式近似 LRU）；若未命中则线性扫描序列，命中后把该树与当时范围 `push_back` 进缓存（满 16 条先 `pop_back`）。
4. 扩容/卸载会同步刷新或删除缓存条目，因此“缓存范围”始终与树记录一致（除 `internal=false` 扩容失败这一失配路径，见可疑5）。

## 附：待确认正文

1. `size` 三处缺省不一致：`Tree_State::size = 0`、`Quadtree` 构造缺省 `size = 256`、`Tree_Record::size = 256`。实现以构造实参为准；阅读结构体易误以为默认树可用。
2. `Quadtree::set_block_size` 只校验尺寸关系，不检查树内是否已有物化叶子。若在建叶后改小 `block_size`，旧叶会停在比新叶层更浅的位置，`child_step` 会拒绝下潜，旧数据不可达。管理器用“序列非空即拒绝”规避，四叉树公开接口无此保护。
3. `build` 与 `leaf_slot_apply` 的注释未说明“已存在叶时忽略传入载荷”；实现以旧叶为准，新 `data` 被丢弃。
4. `seek` 的返回值语义在注释中写作“命中返回 true”，但实现中“叶存在且载荷为空（分配失败）”也返回 `true`，此时 `receiver.data == nullptr`，调用方无法与“未命中”区分。
5. `Quadrant` 为非限定作用域枚举，`child_range_calcu` 以 `int` 接收；头文件未标注合法取值 0..3，越界时返回零初始化矩形而不报错。
6. `Node` 叶分支注释称“分配默认区块数据”，实现用 `new(std::nothrow)`，分配失败时仍 `emplace<1>` 一个空 `shared_ptr`，节点被判为叶但载荷为空。
7. `leaf_slot_apply` 注释只说 Seek/Get 记录结果；实现中 Get 同时承担“创建缺失叶”的职责，故范围 Get 会物化范围内全部叶子。
8. `neighbor_seek` 的注释称“矩形筛选范围”，实现用全局 `largest_tree_size` 而非同组最大边长计算半宽，候选框可能显著偏大（仅影响性能）。
9. 头文件包含基准不统一：`Quadtree_Manager/函数预声明.h` 对二分查找用项目根相对写法，而 `Quadtree/函数预声明.h` 与两个 `数据结构.h` 对坐标类型用 `../../` 相对写法。`CMakeLists.txt` 的说明要求头文件跨目录一律写项目根相对；相对写法在当前镜像层级下仍可解析。
10. `rect_range_calcu` / `range_align` 的注释称管理范围恰为 `size` 且对齐“严格包含内部区块”，但该保证以根坐标为半整数为前提；根分量为非零整数时有效中心偏移半格，分量为 0 时范围少一格。管理器自建根均为半整数，故内部不触发；直接构造整数根的树会触发。
11. `tree_expand_approve` 注释“若为内部调用则由管理器完成实体扩大”，未点明 `internal == false` 时管理器只做“批准 + 预改记录尺寸”，真正的 `tree_expand` 由树侧执行；两条路径的返回值语义也相反。
12. `neighbor_classify` 注释称“若命中两次则为对角相邻树”，但该判据只统计“两轴中心距都不超过半边长之和”，同尺寸的正交邻居非跨越轴差为 0，同样两次命中，故注释与实际语义不符（实现为准）。
