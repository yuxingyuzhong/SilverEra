# 单元测试-渲染（下）模块

本文件描述 `Application/Test/tests/Renderer` 目标中「渲染测试（下半区）」这一组用例文件的组织契约、被测接口、测试辅助设施与断言口径。全部事实来自快照 `465703f_20261108_084029` 内的 48 个源文件以及它们直接引用的渲染层公共头（`Engine/EngineRenderer/src/render/Renderer/渲染器.h` 等）。

## 二、模块功能介绍

本模块是渲染层测试中的「下半区」：48 个文件按被测功能域各自成册，统一通过 `engine::Renderer` 公共门面（`Engine/EngineRenderer/src/render/Renderer/渲染器.h`）驱动真实 Vulkan 设备，并对「隐藏窗口的交换链回读像素」或「离屏渲染目标的回读像素」做结构性断言。它负责回答四类问题：（一）渲染层某个开关/参数是否真正接入着色与管线（而非只改了门面字段）；（二）某个画面变化是否「只在该变的地方变」（例如阴影只压暗被遮挡区域、描边只改变轮廓、雾只作用于几何片元）；（三）同一语义在数据侧（`Light_Data` / `Scene_Data` / `Level_Data`）与门面侧（setter/getter）两条入口是否一致；（四）性能与资源口径（统计字段、字节数、缓存条目、耗时上限）是否仍成立。

它不负责：L1 纯无窗口接口用例（本模块内仅 `渲染着色器校验测试.cpp` 属于「无窗口、只测初始化失败」）；L3 可见窗口目视用例的判定标准（`渲染可见窗口测试.cpp` 只是把窗口开出来并连跑 120 帧，供人眼确认）；Vulkan 句柄、描述符集、屏障等实现细节的断言（所有断言都写在门面返回值、像素与 `Frame_Stats` 上）。同目标内的上半区文件（Alpha 覆盖、Cluster、MSAA、PCSS、HiZ、合批、后处理其余阶段、粒子数据/系统、纹理解码等）不在本模块范围内。

关键约束一：断言必须与「表面格式」无关。交换链颜色附件可能是 `B8G8R8A8` 或 `R8G8B8A8`，也可能是 sRGB 或非 sRGB；因此本模块大量使用「四通道排序后比对」「只取绿通道（下标 1）」「取 R/B 两者较大者作外通道」「alpha 恒取第 4 字节」等手法（见 `渲染混合测试.cpp` 的 `color_min`、`渲染外扩描边测试.cpp` 的 `red_count`、`渲染离屏目标测试.cpp` 的 `pixel_is_green`）。

关键约束二：容差按「链路级数」与「编码路径」分级。单级直通类恒等判定取 `≤2`；两级后处理链的恒等判定取 `CHAIN_TOLERANCE=4`（每级一次「附件编码 → 采样解码」取整）；逐字节判定（`std::memcmp` / `operator==` / `EXPECT_EQ(vector,vector)`）只用于「同渲染器、同输入、两次出帧」这类不引入新编码的场景（如阴影图复用、开关往返、方案 A/B 同帧对照）。

关键约束三：环境依赖必须可跳过。无回读能力、无字体、计算/Cluster/Hi-Z 不可用、无 GPU 时间戳时一律 `GTEST_SKIP()`；异步用例最多轮询 5 秒。跳过不是失败，但会让该用例「不产生证据」。

关键约束四：本模块的「公开接口」不是产品接口，而是测试契约：套件名、夹具名、辅助头、断言阈值都必须能被同目标内的其它文件复用与共编译。两条辅助头（`渲染场景测试辅助.h`、`渲染后处理链测试辅助.h`）在文件清单之外，但被本模块 30 余个文件包含，是事实上的「测试公共层」（见 §四）。

关键约束五：文件粒度受「单文件 ≤ 800 行」拆分约定约束。多个文件头部注释明确记录了拆分来源（`渲染雾测试.cpp` 由 `渲染场景效果测试.cpp` 第五十九轮拆出、`渲染阴影测试.cpp` 由 `渲染场景数据测试.cpp` 第五十七轮拆出、`渲染聚光阴影测试.cpp` 由 `渲染关卡测试.cpp` 第五百六十二轮迁出、`渲染纹理分级测试.cpp` 由 `渲染网格纹理测试.cpp` 第一百五十八/一百六十一轮拆出、`渲染聚光灯测试.cpp` 由 `渲染光照测试.cpp` 第五十八轮拆出、两条辅助头由第五十七/五十九轮拆分时抽出）。拆分留下的注释残片已在附录列为待确认项。

关键约束六：用例之间默认不共享渲染器实例。绝大多数用例在函数体内构造 `engine::Renderer` 并 `init`，作用域结束即析构；需要「同一场景两条路径对照」时，要么开两个独立渲染器（`渲染同帧后处理测试.cpp`、`渲染阴影口径一致性测试.cpp`、`渲染粒子测试.cpp` 的三路径对照），要么在同一渲染器内「同帧重登记 + 逐字节/容差比对」。资源句柄（网格、纹理、管线、目标、字体、材质）在用例末尾逐个卸载；卸载顺序多为「材质/目标/管线/字体/纹理/网格」。

## 三、模块公开接口（测试套件组织契约与被测接口）

### 3.1 套件组织契约

**构建目标与产物。** 本模块所有 `.cpp` 编入静态库 `TestRenderer`（`add_library(TestRenderer STATIC)`），薄入口 `TestRendererMain` 以 `$<LINK_LIBRARY:WHOLE_ARCHIVE,TestRenderer>` 整库收编，输出名 `TestRenderer.exe`，落在 Test 层根（`Application/Test/tests/Renderer/../..`），以便按可执行文件目录解析 `assets/` 与 `shaders/`。`CMakeLists.txt` 的注释明确：只测渲染层（含其依赖的 `EngineSystem` / `EngineFoundation` 面），依赖顺序 `Foundation → System → Renderer` 且按版本锁解析（`byjy_ceshi_yilai`），并记录本子工程使用的下层版本（`byjy_ceshi_jilu`）。

**源文件登记。** `CMakeLists.txt` 用 `file(GLOB_RECURSE ... "src/*.cpp")` 与 `src/*.h`、`src/*.hpp` 收集，再由 `byjy_source_list_sync` 生成并 include `源文件列表_TestRenderer.cmake`；该文件是这些文件「唯一加入点」（`target_sources(TestRenderer PRIVATE ...)` 逐条列出），`add_library` 不再传源文件列表，以保证 Visual Studio 的改名/迁移能改写引用并触发重新配置。头文件（两个辅助头）也以 `target_sources` 列出，只为 IDE 建索引、不参与编译。

**着色器供应。** 配置期从对应配置的 `EngineRenderer.lib` 同级或上两级目录寻找 `shaders/`，`file(COPY ... DESTINATION ${BYJY_TEST_ROOT})` 拷到 Test 层根；找不到只发 `WARNING`（`渲染用例需要它，请先构建渲染层`）。这解释了本模块大量 `pipeline_load(handle, "后处理.vert.spv", "xxx.frag.spv")` 与 `compute_pipeline_load(handle, "计算加一.comp.spv")` 的裸文件名写法：解析基准是 exe 目录下的 `shaders/`。

**外部依赖。** 仅 googletest：`INSTALL_GTEST OFF`、`BUILD_GMOCK OFF`、`gtest_force_shared_crt ON`，`add_subdirectory(${BYJY_TEST_ROOT}/external/googletest ... ## 四、模块私有方法（测试辅助设施）

本模块没有产品意义上的「私有实现」，所谓私有方法即测试辅助设施：两条公共辅助头（被本模块多数文件包含）、各文件匿名命名空间内的局部辅助，以及 gtest 的断言/诊断封装约定。

### 4.1 公共辅助头 `src/渲染场景测试辅助.h`

文件头注明「第五十七轮拆分；由原『渲染场景数据测试.cpp』抽出」，提供：隐藏窗口配置、像素读取与亮度、四边形 / 立方体网格构造、纹理构造、模型矩阵构造，以及所有场景渲染用例共用的夹具。匿名命名空间内的常量与函数如下（签名逐条）：

- `constexpr uint32_t WINDOW_WIDTH = 64;` / `constexpr uint32_t WINDOW_HEIGHT = 36;` —— 场景类用例的统一隐藏窗口尺寸。
- `engine::Renderer_Config hidden_config(void)` —— `width=64,height=36,hidden=true`；未设置 `msaa_samples` / `frame_overlap` / `vsync`，全部走 `Renderer_Config` 默认值。
- `uint32_t pixel_bytes(void)` —— `WINDOW_WIDTH * WINDOW_HEIGHT * 4`。
- `std::array<uint8_t,4> pixel_get(const std::vector<uint8_t>& pixels, uint32_t x, uint32_t y)` —— 行内偏移 `(y*WINDOW_WIDTH+x)*4`，取四字节。
- `std::string pixel_text(const std::array<uint8_t,4>&)` —— 失败诊断用的 `R/G/B/A` 文本。
- `uint8_t outer_max(const std::array<uint8_t,4>&)` —— 取 R 与 B 较大者（避开通道序；注释明确「本层包含链有 min/max 宏」）。
- `engine::Mesh_Data quad_data(void)` —— NDC 尺度 ±1、`z=0` 的四边形（默认相机在 +Z 3 单位处，故四角留清屏色）。
- `std::vector<uint8_t> solid_red(void)` / `solid_white(void)` / `solid_gray(void)` —— 2×2 RGBA8 纹理：(255,0,0)/(255,255,255)/(128,128,128)，alpha 255。
- `engine::Mesh_Data quad_data_with_normal(float nx, float ny, float nz)` —— 四顶点共用同一法线（第四顶点起 `{position, uv, normal}` 三字段）。
- `uint32_t center_brightness(const std::vector<uint8_t>& pixels)` —— 中心像素三通道均值。
- `engine::Mesh_Data cube_data(float half_extent)` —— 24 顶点 / 36 索引的逐面法线立方体（注释说明与网格模块 `cube_generate` 一致）。
- `std::array<float,16> rotation_y_matrix(float angle)` —— 绕 Y 轴旋转（列主序，`cos/sin`）。
- `std::array<float,16> full_screen_matrix(void)` —— x/y 各放大 4 倍，越过 NDC 边界即铺满全屏。
- `class Renderer_Scene_Test : public ::testing::Test {}` —— 空夹具，仅作套件名。

使用约束：辅助都在匿名命名空间（逐翻译单元内部链接），故各文件可各自定义尺寸与容差（如 `渲染混合测试.cpp` 自带 `WINDOW_WIDTH=64`、`CLEAR_TOLERANCE=4`），不会冲突。

### 4.2 公共辅助头 `src/渲染后处理链测试辅助.h`

文件头注明「第五十九轮拆分；由原『渲染后处理链测试.cpp』抽出」，提供隐藏窗口配置、像素读取、纹理与网格构造、后处理链夹具。除与 4.1 同名的 `hidden_config` / `pixel_bytes` / `pixel_get` / `pixel_text` / `quad_data` 外，独有内容：

- `constexpr uint32_t WINDOW_WIDTH = 64;` / `WINDOW_HEIGHT = 36;` —— 注释强调「目标与交换链同尺寸以满足后处理 1:1 取源」。
- `const char* const FONT_PATH = "C:\\Windows\\Fonts\\consola.ttf";` / `constexpr uint32_t FONT_PIXEL_HEIGHT = 16;` —— 文字兼容用例的字体入口。
- `constexpr int CHAIN_TOLERANCE = 4;` —— 「两级链画面与参考画面的最大允许逐通道差」；注释给出推理：每级经历一次「附件编码 → 采样解码」取整，两级累积故取 4；若只执行一级则画面整体反色（通道差可达 200 以上），故 4 仍具决定性。
- `constexpr int SATURATION_THRESHOLD = 250;` / `constexpr int DARK_THRESHOLD = 4;` —— 「纯黑/纯白」判定与「近黑」判定的通道阈值。
- `engine::Renderer_Config msaa_config(uint32_t samples)` —— 在 `hidden_config()` 基础上只改 `msaa_samples`（第一百九十一轮引入）。
- `void scene_register(engine::Renderer& renderer, engine::Mesh_Handle& handle_out)` —— `texture_bind_set(0)` 回落内置白纹理 + `mesh_load` 四边形 + `mesh_draw`。
- `uint64_t post_pipeline_register(engine::Renderer& renderer, const std::string& frag_shader)` —— 复用 `"后处理.vert.spv"` 作顶点、给定片元建管线，返回句柄（失败用 `EXPECT_TRUE` 而非 `ASSERT`）。
- `int max_channel_diff(const std::vector<uint8_t>& left, const std::vector<uint8_t>& right)` —— 全帧逐字节最大差（含 alpha）。
- `float luma_of(const std::array<uint8_t,4>&)` —— Rec.709 加权亮度。
- `uint32_t darkened_count(const std::vector<uint8_t>& tested, const std::vector<uint8_t>& reference, float threshold)` —— 统计「本帧比参考帧暗至少 threshold」的像素数。
- `uint32_t brightened_count(const std::vector<uint8_t>& tested, const std::vector<uint8_t>& reference, float threshold)` —— 相反方向（泛光/提亮类用例）。
- `class Renderer_Post_Chain_Test : public ::testing::Test {}`。

两条辅助头的共存约束：它们各自在匿名命名空间定义了同名常量与同名辅助函数，因此**同一翻译单元不能同时包含两者**（会重定义）。快照中 Path 上确实没有任何文件同时包含它们（场景类用前者，后处理链类用后者）。

### 4.3 各文件内的局部辅助（按职责分组）

**（1）配置构造组。** 每个文件自带 `hidden_config()` 变体，尺寸随用例：`64×36`（场景/后处理链/混合/实例化/像素回读/交换链重建/阴影/雾/粒子短场景）、`64×64`（粒子 billboard / 颜色曲线 / 分桶 / 混合档 / 离屏）、`128×64`（文字）、`128×96`（文字布局）、`320×180`（网格纹理、资源查询、UI、逐绘制项纹理、粒子三路径）、`128×72`（资产加载、聚光阴影关卡）、`512×288`（八盏聚光 512 档细节）、`1280×720` 与 `1920×1080`（性能基线）。变体还额外设置 `frame_overlap/vsync`（`渲染帧测试.cpp`）、`msaa_samples`（`渲染文字测试.cpp`、`渲染聚光阴影测试.cpp`、`渲染阴影诊断测试.cpp`）、`shader_dir`（`渲染着色器校验测试.cpp`）、`pipeline_cache_path`（`渲染缓存与阴影范围测试.cpp`）、`compute_enable`（`渲染计算测试.cpp`、`渲染粒子测试.cpp`）、`instance_capacity`（`渲染粒子测试.cpp`）、`hiz_enable`（`渲染粒子测试.cpp` 软粒子）、`render_threads`（`渲染阴影测试.cpp`）、`static_batching`（`渲染帧统计测试.cpp`）。

### 4.4 夹具与断言封装

- **夹具层面**只提供套件名，唯一有生命周期的是 `Renderer_Shader_Test::SetUp/TearDown`（`std::filesystem::remove_all` + `create_directories`，用 `std::error_code` 版本避免抛异常）。
- **断言选择**：`ASSERT_*` 只用于前置条件（`init`、回读能力、资源加载、句柄非零）；`EXPECT_*` 用于被测语义（单个失败不吞掉后续观测）。需要记录但不设阈值的量一律 `RecordProperty(key,value)`（键名如 `shadow_baseline`、`cascade_far_single`、`fog_luma_delta`、`budget_single`、`mask_blinn`、`exposure_base`、`instanced_upload_bytes`、`particle` 系列）。
- **跳过封装**：`GTEST_SKIP() <<` 附中文原因——回读能力、中文字体、计算/Cluster/Hi-Z、GPU 时间戳缺失、`BYJY_RUN_L3=0`、系统字体缺失；跳过即该用例不提供证据。
- **诊断输出**：大量 `std::cout << "[体积雾] 差异像素=..."` / `"[关卡] ..."` / `"[粒子基线] ..."`，把基线量级打到控制台；`ADD_FAILURE() << "第 i 帧推进失败"`（`渲染帧测试.cpp` 在循环内记失败而不中断）；`SUCCEED()`（`渲染深度描边测试.cpp` 的「未初始化设置无副作用」）。

```

      ▼
```

**生命周期与线程归属。** 除 `渲染阴影测试.cpp` 的 `render_threads=0/4` 对照与 `渲染资产加载测试.cpp` 的异步解析线程外，所有用例都在 gtest 的主线程上顺序执行；渲染器内部的 worker 线程只在 `frame_render` 期间存在（用例通过「4 线程与单线程逐字节一致」间接观测）。异步解析线程由 `asset_mesh_async_load` 建立、由 `asset_mesh_async_poll` 在主线程收割；用例不等价于「无条件成功」——不存在路径的轮询必须始终为假。

## 六、模块设计 / 实现细节

### 6.1 阈值与容差分级总表

| 判定类型 | 阈值 | 依据 |
| --- | --- | --- |
| 逐字节相等 | `==` / `memcmp` / `EXPECT_EQ(vector,vector)` | 同渲染器、同输入、同编码路径；任何差异都指向缺陷（开关往返、静止复用、批量提交、图集两态、分辨率往返、阴影图复读） |
| 单级恒等 | 通道差 `≤2` | 只需一次「全屏采样 → 附件编码」取整（强弱 0 与直通、卡通全关、非法参数不覆盖、越界区间拒绝） |
| 两级链恒等 | `CHAIN_TOLERANCE=4` | 每级 ±1 取整、两级累积（体积雾/光两级、四级链前两级） |
| 通道差计数 | 2 / 4 / 6 / 8 / 20 | 按「变化是否结构性」选取：软边扫掠（2）、体积光/雾（4/8）、聚光灯/关卡（6）、描边/分段（20） |
| 亮度门限 | 受光 ≥200/≥150；遮蔽 <60/<80；半强度 >100；暗部 ≤20/≤4 | 白纹理 + 满照接近 250，遮蔽接近清屏或黑，阈值留取整余量 |
| 亮度差 | `0.05` / `8.0` | Rec.709 luma 差，避免单通道波动主导（描边、卡通、SSAO） |
| 结构比例 | 压暗 `>30` 且 `<宽×高×2/5`；三路径可见差 `<5%`；软边蓝和 `<85%`；扫掠最宽档 `<40%` | 上界防整体变暗/变亮，下界防完全未生效 |
| 浮点近似 | `1e-5`（粒子逐粒子/力场/碰撞）、`1e-4`（预算/纹素/偏置/解析）、`1e-3`（相机往返） | CPU/GPU 同公式不同执行单元；解析解与离散积分的量级差 |
| 性能上限 | `<10/200/2000/5/1000/10000/200/5000 ms` | 防退化护栏；无时间戳时退化为「字段恒 0」断言 |

### 6.2 阈值的来源（逐条归因）

1. **清屏色双编码候选**：`渲染像素回读测试.cpp` / `渲染交换链重建测试.cpp` / `渲染文字测试.cpp` / `渲染中文字形测试.cpp` / `渲染逐绘制项纹理测试.cpp` 注释写明「清屏色 0.05/0.05/0.10/1.0；UNORM ≈ 13/13/26，sRGB ≈ 63/63/89」；故候选数组是两组常量，容差 4（文字/中文 6，UI 8）。判定先排序四通道再逐通道比对并要求 alpha ≥250，同时兼容 BGRA/RGBA 与两种传输函数。
2. **阴影「受光/遮蔽」阈值 200 / 60**：白纹理 2×2 + 方向光强度 1 + 环境光 0 时受光面接近饱和（约 250），阴影处只剩环境光/清屏；双级/三级情形把遮蔽上界放宽到 80（`渲染级联阴影测试.cpp`）。
3. **阴影强度半值**：`渲染阴影口径一致性测试.cpp` 把 8 位亮度按 `pow(x/255,2.2)` 解回线性再求比值，断言 `0.5±0.03`；注释明确「sRGB 下线性 0.5 会编码成约 0.737」。
4. **纹素世界尺寸**：`shadow_range_set(48,1,60)` + 边长 512 → `2×48/512 = 0.1875`；上限 0.05/0.02 的等效半径分别是 `12.8` 与 `5.12`，后者使 `z=-10` 遮挡面落到视锥外，从而以「中心亮度上升」间接证明覆盖面收缩。
5. **自动淡化建议 `4/分片边长`**：2 级、边长 1024 → 每片 512 → `4/512 = 0.0078125`，即实现侧「切换带 4 纹素」的换算。
6. **偏置自校准**：`0.010 × 参考跨度 / 实际跨度`；八盏同半径 9 → `0.010×9/8.9≈0.010112`（分母取 `radius-0.1`），两盏 26/9 → `0.010×9/25.9≈0.003475`，比值断言容差 5e-4。
7. **体积雾/光结构阈值**：差异像素 `>20`、亮度 `+2/+3/+5` 用于区分「全屏均匀提亮」与「局部生效」；`>20` 相对 64×36=2304 像素约 0.9%，足以排除取整噪声。
8. **指数平方雾区间 205..232**：注释给出推导——距离差 2、密度 0.3 → 因子 `1-exp(-(0.6)²)≈0.302`，线性亮度 `≈178`，sRGB 编码后约 218，故区间取 205..232。
9. **雾色/亮度比例**：`雾色亮于清屏色` 使「开启雾 → 亮度上升」，与「关闭雾 → 逐字节还原」形成双向判据；高度雾抬升片元 `exp(-1.5×0.8)≈0.301` → 提亮 `≥30`。
10. **文字度量**：宽度随字符数严格递增（不设具体像素，因字体/字号相关）；高度恒等于字号 16；缩进 30 像素允许 ±4；字距 6 像素 ×2 间隙 → 右端至少 +8。
11. **粒子逐粒子对照 1e-5**：CPU 与 GPU 使用同一组公式与步序，差异只来自浮点执行顺序；力场 `vx==2.0`/`px==1.1`（`0.5×2×1²` 加半步修正 0.1）用 1e-4。
12. **粒子资源字节公式**：`容量×STRIDE×2 + FORCE_MAX×FORCE_STRIDE + (8+ceil(容量/32)×4) + 容量×4 + 4 + 2×20`——双缓冲状态、力场 SSBO、位图头 + 每 32 粒子 4 字节、紧凑索引、4 字节计数、在途 2 帧 ×20 字节间接命令；以精确等式锁定。
13. **实例步长 112 / 80**：`渲染物体多材质测试.cpp` 断言 `2×112` 与 `200×112`；`渲染帧统计测试.cpp` 注释提到旧口径 80 字节/实例，两数字分属不同轮次。

### 6.3 受控场景构造方式

本模块不引入场景文件做像素用例（`渲染资产加载测试.cpp` 与 `渲染聚光阴影测试.cpp` 例外），而是用「最小几何 + 受控相机 + 受控光照」把待测效应压到单一变量上：

- **正对四边形（遮挡/受光基元）**：`quad_data_with_normal(0,0,-1)` 朝向 +Z 相机，默认相机在 `(0,0,3)`，四边形在 `z=0`（距 3）。这是阴影类用例的标准接收面。
- **遮挡面配方**：同一四边形 + 列主序矩阵 `diag(0.6,0.6,0.6)` 且 `translate z=-0.5`（阴影测试/软度/按需重绘），或 `z=-9`/`-9.5`/`-10`（阴影口径/稳定性/诊断/纹素钳制），或用 `translate(0,0,-5)`/`-20` 把整对几何移到远区（级联覆盖）。距离选择不是随意的：`0.5` 与 `1.0` 用来避开深度偏置带来的等效世界偏移（`渲染阴影纹素钳制测试.cpp` 注释明确「间距 1.0，避开深度偏置的等效世界偏移」）。
- **全屏接收面**：`full_screen_matrix()` 把 x/y 各放大 4 倍越过 NDC 边界，使画面被完全覆盖，用于「阴影口径一致性」（三模型同屏对照）与「离屏目标」。
- **聚光配方**：灯位于 `(0,2,3)` 朝 `(0,-1,0)`、半径 10、内 15°/外 30°，遮挡面 `0.6` 缩放置于 `z=-1`，接收面在原点；偏轴质量缩放用例把灯移到 `(2.5,1.5,3)`、遮挡板 `0.4` 缩放偏右上 `(0.6,0.4,1)`，注释解释「使阴影落在遮挡板屏幕投影之外（否则被遮挡板自身盖住而不可见）」——这是本模块最典型的「受控可见性」构造。
- **八盏聚光关卡**：`level` 文本固定 9 个 `place`、8 条 `light spot`（半径 9、内 20°/外 40°、强度 1），每盏照一块遮挡体；`level_bridge_draw` 恒返回 9 作为「对象数不变」的哨兵。
- **后处理最小场景**：64×36 的目标与交换链同尺寸（保证 1:1 取样），场景只有「一张覆盖视口中央的四边形 + 天空」；SSAO 需要深度断层，故加一张前移 0.5、缩放 0.45 的小四边形；软粒子需要遮挡物，故加一张 4×4 黑墙并前移到 `z=0.58`。
- **性能场景**：粒子 1920×1080 MSAA4 + 1 万粒子 + `instance_capacity=16384`；体积雾/光 1280×720 三档步数；八盏软度 1920×1080；资产解析 5 万三角形纯 CPU 解析。
- **对照帧的构造原则**：「只改一个变量」——同一渲染器内两次登记 + 三次出帧，或两个独立渲染器 + 各出一帧；对照帧必须与目标帧共享相机、清屏色、纹理与几何，只差被测参数。`渲染同帧后处理测试.cpp` 与 `渲染阴影口径一致性测试.cpp` 明确使用「两个独立渲染器」以避免上一帧状态泄漏。

### 6.4 像素级比对与统计

- **取样点**：中心（几乎所有亮度断言）、角 `(1,1)`/`(2,2)`/`(W-2,H-2)`（清屏/覆盖）、`(W/2+150,H/2)`（阴影外参考，320 宽）、`(41,9)`（聚光角点）、左 1/4 与右 3/4（逐绘制项纹理）、文本框矩形 `(26..90,24..45)`。
- **整帧统计函数**：`max_channel_diff`（含 alpha）、`differing_count/differing_pixels`（前三通道）、`darkened_count`/`brightened_count`（Rec.709 luma）、`average_luma`、`distinct_color_count`、`white_count(_rows)`、`red_count`/`red_run_left`、`ink_*`、`bright_pixels`、`region_brightness_range`、`blue_sum`（粒子软边）。
- **掩码比对**：`渲染阴影口径一致性测试.cpp` 先用「各自无阴影帧的中心亮度一半」作阈值把阴影帧二值化为掩码，再比较三模型掩码是否逐像素相等；这比直接比像素更能证明「同一阴影因子、不同光照模型」。
- **通道序无关**：所有颜色判定避免写死 R/G/B 下标（`outer_max`、`color_min`、四通道排序、只取绿通道），因为交换链可能是 BGRA；alpha 恒取第 4 字节。
- **传输函数无关**：清屏色用双候选；纯绿（0/255 端点）在 UNORM 与 sRGB 下编码一致；半透明叠加用区间 `[100,240]` 而非定值；阴影强度比显式做 `pow(2.2)` 反解（见 6.2 第 3 条）。
- **失败诊断**：`pixel_text` 输出 `R/G/B/A` 便于人工比对；`std::cout` 打印关键基线（粒子蓝和、关卡差异像素、体积雾亮度增量）；`RecordProperty` 把基线写进 gtest XML。

### 6.5 用例间资源复用与隔离

- **绘制项按帧消费**：`渲染后处理遮蔽测试.cpp` 的 `scene_two_layers` 注释「每帧重新登记，避免被上一帧消费」；`渲染阴影测试.cpp`/`渲染级联阴影测试.cpp` 每次出帧前都重新 `mesh_draw`。这是门面契约：登记队列在帧末清空。
- **阴影图复用**：静止帧签名不变时 `shadow_passes==0`、`shadow_reuses` 递增（`渲染阴影诊断测试.cpp`、`渲染阴影稳定性测试.cpp`、`渲染级联配置数据测试.cpp`）；任何输入（相机、模型矩阵、聚光位置、级联配置）变化都会使签名失配并重绘一次（`渲染阴影测试.cpp` 第三帧、`渲染聚光阴影测试.cpp` 移动第 7 盏）。复用的前提是**纹素对齐**：相机亚纹素位移 0.004 时阴影图逐字节不变（`渲染级联阴影测试.cpp`、`渲染阴影稳定性测试.cpp` 的 8 帧轨迹）。
- **聚光瓦片与图集的共存/回收**：独立瓦片按需创建（`spot_shadow_tile_targets≥1`），切到图集后独立瓦片目标被回收为 0、图集占 `4S×2S×4` 字节；切回独立瓦片再按需重建（`渲染阴影诊断测试.cpp`）。
- **文字网格缓存**：默认 64 条，LRU 淘汰；`text_cache_capacity_set` 立即缩容并可钳到 `[1,1024]`；被淘汰文本重画会重新计 miss 但仍能出墨（`渲染文字测试.cpp` 70 段用例）。
- **字体图集**：加载时只烘 ASCII，非 ASCII 在 `text_draw` 时惰性补烘并重建图集纹理；图集不足时扩容而不是跳过（`font_skipped_codepoints==0`，`渲染中文字形测试.cpp`）；同码点补烘只做一次（`渲染文字测试.cpp` 的 U+E000 用例）。
- **资产共享**：`asset_mesh_shared_load` / `asset_texture_shared_load` 按归一化路径（大小写不敏感）复用，同一资源多次加载得到同一句柄，`asset_cache_count()` 只加一次；释放按引用计数递减，归零才真正卸载并使句柄失效（`渲染资产加载测试.cpp`）。
- **粒子池**：关闭粒子不释放池内容（关态 `emit`/`active_count` 为 0，重开恢复既有活跃数）；常驻路径与 CPU 镜像是两套状态，关闭常驻后回到 CPU 镜像（`渲染粒子测试.cpp` 常驻发射/推进用例）。
- **用例隔离**：每个用例独立 `engine::Renderer`（脚本内构造、`init`、作用域结束析构）；只有需要「同场景两路径」时才开第二个渲染器。离屏后处理用例用两块目标做 ping-pong（`体积雾 → 反色`、四级链轮转两圈），避免自读自写。
- **临时文件隔离**：`out/test_tmp/render_shader_check`、`render_shader_missing`（`SetUp/TearDown` 清理）、`out/资产测试/`、`out/关卡测试/`（用例自建、覆盖写）、`out/测试管线缓存.bin`（首次前 `remove`）。

### 6.6 错误处理策略（测试侧）

- **先守卫后断言**：`init` 失败用 `ASSERT_TRUE`；能力缺失用 `GTEST_SKIP`；资源加载失败用 `ASSERT_TRUE`。设备不支持时用例为 skipped 而非 failed，避免 CI 噪声。
- **非法参数测试一律「两次观测」**：先读回配置不变，再出帧比对画面逐字节不变（例如 `shadow_range_set` 非法、`light_attenuation_set(2)`、`outline_set` 负宽、`fog_exp2_set` 越界、`particle_params_set` damping 2.0）。既验证「拒绝」也验证「拒绝无副作用」。
- **卸载语义**：重复卸载幂等（`mesh_unload`、`texture_unload`、`compute_pipeline_unload`、`render_target_destroy`、`spot_shadow_atlas_set` 同值不重建）；卸载后句柄绘制/读回应失败（`渲染网格纹理测试.cpp`、`渲染纹理分级测试.cpp`、`渲染像素回读测试.cpp`）。
- **越界下标**：统一用「超上限的槽位」探测（`spot_shadow_light_set(9)`、`spot_shadow_quality_set(9)`、`spot_shadow_priority_set(32)`、`spot_shadow_bias_scale_set(9)`），断言返回假且配置/画面不变。

### 6.7 已知坑与隐式约定

1. **`min`/`max` 宏污染**：多条用例注释写明「本层包含链存在 min/max 宏，`std::min({...})` / `std::max` 会被宏破坏（C2589）」，故 `color_min`、`outer_max`、`red_count`、`region_brightness_range` 全部手工比较；`渲染聚光逐盏阴影测试.cpp` 用了 `(std::max)(...)` 的括号写法规避。
2. **`ASSERT_*` 不能出现在有返回值的 lambda/函数里**：多处注释记录，故「返回像素/亮度」的辅助一律用 `EXPECT_*`，前置失败时返回空像素或 0，由上层断言暴露。
3. **中文路径与编码**：资产用例「写盘用宽字符路径、加载器入参用 UTF-8 窄字符串，两者都不做编码转换」；着色器校验的临时目录用纯 ASCII 命名，「避免中文路径在本地码页下的解析歧义」；管线缓存与纹理路径用 `std::filesystem::u8path`。
4. **交换链表面格式不定**：BGRA/RGBA、sRGB/UNORM 都可能，故立体断言全部通道序无关 + 容差；纯色判定（纯红/纯绿/纯蓝）用「通道排序 + 双阈值」。
5. **GPU 时间戳缺失**：所有耗时断言都分支——支持则断言非负/上限，不支持则断言字段恒 0 或 `-1`（`particle_gpu_ms` 约定为 `-1`）。
6. **计算/Cluster/HiZ 能力缺失**：用例跳过而不是降级；`compute_enable=false` 的用例是例外（断言 `compute_supported()==false` 但 `capabilities.compute` 仍为真）。
7. **L3 可见窗口默认运行**：`渲染可见窗口测试.cpp` 注释「默认运行（2026-10-24 用户确认两个用例可稳定通过后取消默认跳过）；如需在无人值守环境关闭，设置环境变量 `BYJY_RUN_L3=0`」。
8. **同帧重登记**：忘了重登记会表现为「画面与统计都不变」，多个用例专门断言第二帧的 `draw_items`/`shadow_passes` 以捕捉这类错误。
9. **后处理链装配顺序**：注释强调「链先于 `present_set` 设置」；两级/四级链须先建目标，再设链，再设逐级参数，最后登记场景。
10. **离屏尺寸与交换链一致**：软粒子用例注释「Hi-Z 按交换链范围构建，尺寸不一致时回调跳过」，故离屏目标取 64×36。

### 6.8 与本模块断言相关的口径风险（摘要，详见附录）

- 多个用例把「默认阴影分辨率为 1024」写进断言与字节数公式（`shadow_atlas_bytes == 1024×8×1024×4`、`shadow_resolution == 1024`），一旦默认档调整，这些断言需要同步（N8）。
- 「片元恰在雾结束处」类用例依赖雾插值的边界语义（`t=1` 完全遮蔽），实现若改为平滑端点需同步（`渲染雾测试.cpp`）。
- `渲染阴影口径一致性测试.cpp` 的 `pow(2.2)` 反解假设附件为 sRGB；非 sRGB 机器上该比值断言会偏离（N9）。
- `渲染粒子测试.cpp` 全部使用 `TEST` 且依赖枚举的整数值（`Emit_Shape`、`Force_Type`、`Blend_Mode` 的 `static_cast<uint32_t>`），若枚举重排会影响参数语义（N6）。
- 三个文件的注释残片与用例错位（N1/N2/N3）、体积光/雾辅助在出帧前卸载网格（N4）、`Renderer_Level_Test` 夹具跨文件依赖（N5）。

## 七、模块运行链路详例

### 7.1 链路 A：阴影/光照用例从场景构造到像素断言

以 `渲染阴影测试.cpp` 的 `方向光阴影生效` 为主线（这是本模块阴影类用例的母版，`渲染级联阴影测试.cpp`、`渲染阴影诊断测试.cpp`、`渲染阴影稳定性测试.cpp` 都是它的变体）：

1. **初始化**：`engine::Renderer renderer; ASSERT_TRUE(renderer.init(hidden_config()))`（64×36）；`if (!renderer.readback_supported()) GTEST_SKIP()`。
2. **资源准备**：`texture_load(texture, solid_white().data(), 2, 2)`；`mesh_load(receiver/occluder, quad_data_with_normal(0,0,-1))`；`texture_bind_set(texture)`。
3. **场景构造**：`Camera_Data camera{}`（默认 `(0,0,3)` 注视原点、fov 1.0472）；`Light_Data light{}` 且 `direction[2]=1.0`（光沿 +Z）、`intensity=1.0`、`ambient=0.0`；`Fog_Data fog{}`；`scene_apply(camera, light, fog)`。
4. **基线帧**：`mesh_draw(receiver, nullptr)` → `frame_render(pixels,size)` → `EXPECT_GE(center_brightness(pixels), 200)`；同时取中心右移 150 像素的 `baseline_edge`。
5. **关阴影对照**：`occluder_transform`（`0.6` 缩放 + `[14]=-0.5`）→ 遮挡面 + 接收面 → 出帧；`EXPECT_NEAR(unshadowed, baseline, 3)`（遮挡面在接收面之后，关阴影不应改变画面）。
6. **开阴影**：`shadow_enable_set(true)` → 同帧重登记两侧 → 出帧 → `EXPECT_LT(shadowed, 60)`、`EXPECT_NEAR(shadowed_edge, baseline_edge, 3)`（阴影外未被误遮蔽）。
7. **还原**：`shadow_enable_set(false)` → 重登记 + 出帧 → `EXPECT_NEAR(restored, baseline, 3)`。
8. **诊断落盘**：`RecordProperty` 写 6 个键；末尾 `mesh_unload` ×2、`texture_unload`。

同族变体的插入点：`渲染阴影测试.cpp` 的 `阴影强度生效` 在步骤 6 与 7 之间穿插 `shadow_strength_set(1.0/0.0/0.5/1.5)` 与 `shadow_softness_set(1.0)`；`按需重绘` 在步骤 6 后用 `shadow_pass_count()` 比对三帧；`渲染阴影诊断测试.cpp` 读 `Frame_Stats` 而非像素；`渲染阴影稳定性测试.cpp` 用 `shadow_readback` 取整张阴影图并逐字节比较；`渲染级联阴影测试.cpp` 在步骤 6 前调用 `shadow_cascade_set` 并把物体移到 `z=-5`/`-20`。

### 7.2 链路 B：后处理链用例从链装配到输出比对

以 `渲染后处理体积光测试.cpp` 的 `体积雾与体积光组合`（两级链 + 双目标）为主线：

1. **初始化与目标**：`engine::Renderer renderer; init(hidden_config())`（64×36）；`render_target_create(target0, extent_width(), extent_height())`、`render_target_create(target1, ...)`——两块目标都取交换链尺寸（1:1 取源）。
2. **管线与链装配**：`post_pipeline_register(renderer, "体积雾.frag.spv")`、`post_pipeline_register(renderer, "体积光.frag.spv")`（顶点统一 `"后处理.vert.spv"`）；`chain[2]={fog_pass, shaft_pass}`；`post_chain_set(chain, 2)`（**先设链**）。
3. **逐级参数**：`post_stage_vec4_set(0, fog_density, 0.0, 20.0, 1.0)`（密度/高度衰减/最大距离/步数缩放）；`post_stage_color4_set(0, r,g,b, 0.0)`（雾色 + 噪声强度）；`post_stage_vec4_set(1, shaft_strength, 0.9, 1.0, 0.9)`（强度/衰减/采样缩放/光源 uv y）；`post_stage_color_set(1, 暖白)`。
4. **呈现链**：`render_target_present_chain_set(targets, 2)`（`targets={target0,target1}`，两块目标 ping-pong）。
5. **场景登记**：`mesh_load(plane, quad_data())`、`mesh_draw(plane, nullptr)`、`mesh_unload(plane)`（**注意本用例在出帧前卸载网格，见附录 N4**）。
6. **出帧与回读**：`frame_render(pixels, pixel_bytes())`；`frame_stats_get().post_stages` 应等于 2。
7. **恒等对照**：另用一条「`后处理.frag.spv`（直通）+ 体积光 0」的两级链跑同一场景作为 `direct`，`max_channel_diff(direct, off) ≤ CHAIN_TOLERANCE(4)`。
8. **结构性判定**：`differing_pixels(off, on, 8) > 20`；`average_luma(on) > average_luma(off) + 2.0`；`RecordProperty("fog_shaft_changed_pixels", …)`、`("fog_shaft_identity_diff", …)`。
9. **收尾**：`pipeline_unload(fog_pass/shaft_pass)`、`render_target_destroy(target1/target0)`。

链路 B 的骨架可映射到：单级（`post_chain_set(&pass,1)` + `render_target_present_set`）、两级（双目标 + `present_chain_set`）、四级（双目标轮转两圈）。对照容差按级数取 2/4，差异计数阈值取 4（体积光/开关）或 8（雾/组合），亮度增量取 `+2/+3/+5`。链装配次序错会使 `post_stages` 与画面同时异常，故链用例几乎都显式断言 `post_stages`。

### 7.3 链路 C：数据侧用例（不出像素的「回读—比对」链）

以 `渲染级联配置数据测试.cpp` / `渲染级联淡化数据测试.cpp` / `渲染阴影纹素钳制测试.cpp` 的扁平入口为代表：

1. `init(hidden_config())` 后先调 `shadow_cascade_get(&count,&far,&split)` 或 `shadow_cascade_blend()`、`shadow_texel_max()`、`shadow_cascade_blend_auto()` 取初始值。
