## 二、模块功能介绍

**定位。** 本模块是 `EngineTests.exe` 的唯一入口与交互层。它不承载任何被测业务逻辑，而是把 googletest 在静态初始化期注册出来的「套件 / 用例」注册表，转成一棵可勾选的两层选择树；再按勾选结果把用例逐条喂给 googletest，执行结果经自定义监听器采集后镜像到图形界面或控制台。CMake 侧产物分工（见 `Application/Test/CMakeLists.txt`）：`TestLauncher` 静态库收编选择模型、层级状态、控制台菜单；`EngineTests` 可执行文件另编主程序、图形操作界面、测试界面、运行器、输出镜像；三个分层用例库与 `EngineTestObjects` 提供用例本身。

**负责的四段。** 第一段是「选」：`Test_Selection_Model` 用 `::testing::UnitTest::GetInstance()` 反射建树，维护套件 / 用例 / 层级三层勾选态，并向运行器提供 `std::vector<std::string>` 的「套件.用例」全名清单，向控制台路径提供 `--gtest_filter` 串。第二段是「跑」：`Test_Runner` 在调用线程按时间片逐条设置 `GTEST_FLAG(filter)` 并调用 `RUN_ALL_TESTS()`，因此每一轮实际是「N 次单用例迭代」而非一次全量迭代。第三段是「看」：`Gtest_Output_Mirror` 作为 `TestEventListener` 采集状态、耗时、失败摘要，并按 gtest 控制台风格生成带级别的输出行；`测试界面_绘制()` 每帧取快照渲染。第四段是「退」：`需要等待退出()` 决定控制台 / 回退路径跑完后是否停住等按键，图形路径则靠界面退出请求与窗口关闭收尾。

**不负责的边界。** 不实现任何测试断言、不实现被测模块；不解析 `assets/`、不构建工程；不直接操作 Vulkan / SDL3 句柄（全部经 `Renderer` 的 UI 通道转交）；不负责 ctest 的用例发现（由构建脚本用 `gtest_discover_tests` 或整体注册完成）；不负责分层的版本锁解析（构建期完成，本模块只做运行期「是否落后」的展示判定）。

**进程模型约束。** 快照内不存在任何子进程创建（无 `CreateProcess` / `_popen` / `std::system`），也不存在工作线程；测试执行在界面主线程上同步发生。原因写在 `测试运行器.h` 与 `图形操作界面.cpp`：渲染层用例会创建 SDL 窗口并逐帧抽取事件，SDL3 要求事件泵在主线程，若在非主线程执行会触发 `SDL_IsMainThread_REAL()` 断言。所谓「分片」只是把一轮拆成多次 `RUN_ALL_TESTS`，每次在 8 ms 预算后返回，让主循环照常渲染一帧。

**为什么要镜像而不是直接看控制台。** 图形模式下默认打印器被摘除并销毁（`Test_Runner::ui_install()`），控制台不再输出 gtest 结果；全部可读信息只存在于 `Gtest_Output_Mirror` 的 `output` / `cases` 容器与界面上。这保证了「窗口里看到的」与「gtest 语义」同源，同时也意味着镜像的格式化逻辑必须自行补齐被抑制的横幅（见 §六 D8）。

**为什么需要层级隔离。** 三个测试子工程各自链接「与自身同版次」的下层静态库，如果下层库已重建而某层测试库没重建，用旧库跑新头得到的结论会失真。`测试层级状态.cpp` 在运行期读取各子工程构建期写出的 `依赖版本.cmake`，与当前可用版本（版本锁优先，锁空读锚点头的 12 位哈希）比对；界面首帧把 `outdated` 的层级整层取消勾选并置顶提示。

**无头模式。** `--selector=off` 或「带 `--gtest_*` 且未显式指定 `--selector`」时，主程序不建模型、不建运行器、不装镜像，直接 `RUN_ALL_TESTS()`，行为与 gtest 原生一致；`ctest` 走的就是 `--selector=off`（`Application/Test/CMakeLists.txt` 的 `add_test`）。

## 三、模块公开接口

本节只列头文件中真实存在的声明。签名按源码原样抄录；语义与失败行为来自实现。

### 3.1 结果数据结构（`测试运行记录.h`）

```cpp
namespace engine
{
    enum class Case_Status
    {
        Passed = 0,   //通过
        Failed = 1,   //失败
        Skipped = 2   //跳过
    };

    struct Case_Result
    {
        std::string suite{};                 //所属套件名
        std::string name{};                  //用例名
        Case_Status status = Case_Status::Passed;
        int64_t elapsed_ms = 0;              //耗时（毫秒）
        std::vector<std::string> failures{}; //失败消息（逐条 TestPartResult 的摘要）
    };

    struct Round_Summary
    {
        int round = 0;        //轮次号（从 1 开始，= 已有轮次数 + 1）
        int total = 0;        //本轮采集到的用例数
        int passed = 0;
        int failed = 0;
        int skipped = 0;
        int64_t elapsed_ms = 0; //各用例 elapsed_ms 之和
    };

    struct Output_Line
    {
        std::string text{};
        int level = 0; //0 分隔/标题 1 运行 2 通过 3 失败 4 跳过 5 信息
    };
}
```

`Case_Result::failures` 每条形如 `"<file>:<line>: <summary>"`（`gtest输出镜像.cpp::OnTestEnd`），仅收集失败的 `TestPartResult`。`Output_Line::level` 的实际使用见下表（界面按级别着色，`测试界面.cpp`）。

| level | 生产者 | 典型文本 | 界面颜色 |
| --- | --- | --- | --- |
| 0 | `round_begin` / `round_end` / `OnTestStart` 套件横幅 | `[==========] Running N tests from M test suites.`、`[----------] <suite>` | 次要色 |
| 1 | `OnTestStart` | `[ RUN      ] <suite>.<case>` | 正文色 |
| 2 | `OnTestEnd` / `round_end` | `[       OK ] ...`、`[  PASSED  ] ...` | 成功色 |
| 3 | `OnTestPartResult` / `OnTestEnd` / `round_end` | `file:line: Failure`、`[  FAILED  ] ...` | 失败色 |
| 4 | `OnTestEnd` 跳过 / `round_end` 跳过 / `note_append` | `[  SKIPPED ] ...`、`[  WARN  ] 未匹配到用例：...` | 跳过色 |
| 5 | 保留（`note_append` 参数） | 无实际调用点 | 正文色 |

### 3.2 层级枚举与版本状态（`测试层级状态.h`）

```cpp
enum class Test_Layer : int
{
    Self = 0,        //本层自测（EngineTests 自身收编的用例）
    Foundation = 1,  //tests/Foundation
    System = 2,      //tests/System
    Renderer = 3,    //tests/Renderer
    Unknown = 4      //未识别来源（正常不应出现）
};

constexpr int test_layer_count = 4; //不含 Unknown

const char* test_layer_name(Test_Layer layer);

struct Layer_Version_State
{
    Test_Layer layer = Test_Layer::Unknown;
    bool outdated = false;       //落后或缺少构建记录
    bool record_missing = false; //该子工程尚未构建过
    std::vector<std::string> reasons; //逐条原因，界面直接展示
};

bool version_mismatch(const std::map<std::string, std::string>& recorded,
    const std::map<std::string, std::string>& current,
    std::vector<std::string>& reasons);

std::vector<Layer_Version_State> layer_version_states_get(void);
const char* current_config_name(void);
std::string project_root_path(void);
```

- `test_layer_name()`：`Self → "本层自测"`、`Foundation → "EngineFoundation 子工程"`、`System → "EngineSystem 子工程"`、`Renderer → "EngineRenderer 子工程"`、其余（含 `Unknown`）→ `"未识别层级"`。前置条件无；纯 switch。
- `version_mismatch()`：入参 `recorded` 为该层构建时记录的「层名 → 12 位哈希」，`current` 为当前可用版本。先 `reasons.clear()`；遍历 `current`，**跳过值为空的项**（无从判定）；`recorded` 缺失或值空 → 追加 `"<层名>：构建记录缺少该层版本"`；值相等 → 跳过；否则追加 `"<层名>：测试库用 <旧>，当前可用 <新>"`。返回 `!reasons.empty()`。纯函数，不触盘，单测直接调用。
- `layer_version_states_get()`：读盘。以可执行文件目录上溯两级为项目根，按 `current_config_name()`（`_DEBUG` 宏决定 `Debug` / `Release`）逐层读取 `<子工程>/out/build/x64-<配置>/依赖版本.cmake`；缺文件即 `outdated = true`、`record_missing = true`，原因 `"缺少构建记录：请先重建 <相对目录>"` 后直接产出该层状态；否则读 `BYJY_BUILD_AGAINST_<层>_<配置>` 与当前版本比对。固定返回 4 条（不含 `Unknown`），顺序与枚举 0..3 一致。任何文件读取失败都不抛出、不中断，按「待更新」处理。
- `current_config_name()`：`#if defined(_DEBUG)` → `"Debug"`，否则 `"Release"`。与可执行文件配置一致的前提是 CRT / 配置宏随构建传递。
- `project_root_path()`：`detail::exe_dir_get().parent_path().parent_path()` 转 UTF-8 文本。因 `EngineTests.exe` 被 CMake 输出到 `Application/Test` 根目录（`RUNTIME_OUTPUT_DIRECTORY "${PROJECT_ROOT_DIR}/$<0:>"`），上溯两级即项目根。快照内本模块没有调用点，`layer_version_states_get()` 自行重复同一推导。

### 3.3 选择条目与选择模型（`测试选择模型.h` / `.cpp`）

```cpp
struct Case_Entry
{
    std::string name;                        //用例名（不含套件前缀）
    bool checked = true;
    Test_Layer layer = Test_Layer::Unknown;  //来源子 CMake 层级
};

struct Suite_Entry
{
    std::string name;
    std::vector<Case_Entry> case_list;
    bool expanded = false;
    Test_Layer layer = Test_Layer::Unknown;  //取首个用例的来源
};

class Test_Selection_Model
{
public:
    void suite_tree_build();

    const std::vector<Suite_Entry>& suite_table_get() const;
    std::size_t suite_count() const;
    std::size_t case_count() const;
    std::size_t checked_case_count() const;
    bool suite_all_checked(std::size_t 套件序号) const;
    bool suite_half_checked(std::size_t 套件序号) const;
    bool suite_expanded(std::size_t 套件序号) const;

    void suite_check_set(std::size_t 套件序号, bool 勾选);
    void case_check_set(std::size_t 套件序号, std::size_t 用例序号, bool 勾选);
    void suite_expand_set(std::size_t 套件序号, bool 展开);
    void all_check();
    void all_clear();
    void check_invert();

    std::size_t layer_case_count(std::size_t 层级) const;
    std::size_t layer_checked_count(std::size_t 层级) const;
    bool layer_all_checked(std::size_t 层级) const;
    bool layer_half_checked(std::size_t 层级) const;
    void layer_check_set(std::size_t 层级, bool 勾选);
    void layer_check_only(std::size_t 层级);

    std::string filter_string_build() const;
    std::vector<std::string> selected_cases() const;

private:
    std::vector<Suite_Entry> suite_table_;
};

bool 解析控制台选择(const std::string& 输入, std::size_t 套件数, std::vector<bool>& 勾选表);
```

逐条语义：

| 接口 | 语义 / 前置条件 / 失败行为 |
| --- | --- |
| `suite_tree_build()` | 清空后重建。遍历 `UnitTest::total_test_suite_count()`；`GetTestSuite()` 为空的索引 `continue`；逐 `GetTestInfo()` 登记，`name/checked=true/layer=层级判定(file())`；`GetTestInfo()` 为空亦跳过；套件 `layer` 取 `case_list.front().layer`（空套件保持 `Unknown`）。必须在 `InitGoogleTest()` 之后调用，否则注册表尚未解析命令行、套件集合可能不完整。 |
| `suite_table_get()` | 返回内部 `const&`，调用方不得持有跨重建；界面 / 控制台只读。 |
| `suite_count()` / `case_count()` / `checked_case_count()` | `O(套件数)` / `O(用例数)` 现算，不缓存。空树全返回 0。 |
| `suite_all_checked(i)` | 越界或空套件返回 `false`；否则要求全部 `checked`。 |
| `suite_half_checked(i)` | 越界或空套件返回 `false`；否则 `0 < 已选 < 用例数`。 |
| `suite_expanded(i)` | 越界 `false`，否则读 `expanded`。 |
| `suite_check_set(i,b)` | 越界静默返回；否则整组用例置 `b`（空套件无效果）。 |
| `case_check_set(s,c,b)` | 两级越界均静默返回；否则只改该用例。 |
| `suite_expand_set(i,b)` | 越界静默返回；纯 UI 态，与勾选无关。 |
| `all_check()` / `all_clear()` / `check_invert()` | 全用例遍历置 `true` / `false` / 取反；空树无效果。 |
| `layer_case_count(L)` | `L > (std::size_t)Test_Layer::Unknown` 返回 0；否则累计 `套件.layer == L` 的全部用例数（**含 `Unknown` 层**）。头文件注释写「仅 0..test_layer_count-1 有效」，实现允许 0..4，以实现为准，见【待确认：1】。 |
| `layer_checked_count(L)` | 边界同上；累计该层已勾选数。 |
| `layer_all_checked(L)` | 该层用例数为 0 → `false`；否则已选 == 总数。 |
| `layer_half_checked(L)` | 该层用例数为 0 → `false`；否则 `0 < 已选 < 总数`。 |
| `layer_check_set(L,b)` | `L > Unknown` 静默返回；否则该层全部用例置 `b`。 |
| `layer_check_only(L)` | `L > Unknown` 静默返回；否则「属于该层的用例置 true，其余层全部置 false」。`Unknown` 层同样可被单独选中。 |
| `filter_string_build()` | 已勾选总数为 0 → 返回空串（**不退化为全跑**）；逐套件：已选 0 → 跳过；已选 == `case_list.size()` → 压成 `"套件.*"`；部分勾选 → 逐条 `"套件.用例"`；片段用 `':'` 连接。套件名 / 用例名不做转义，见【待确认：6】。 |
| `selected_cases()` | 按套件顺序展开已勾选项，元素为 `"套件.用例"`；全不选返回空 `vector`。运行器据此拒绝启动（`request_run` 返回 `false`）。 |
| `解析控制台选择(输入, 套件数, 勾选表)` | 先把 `勾选表.assign(套件数,false)`（**失败时也保持全假、长度已归位**）；去首尾 `" \t\r\n"`，全空白返回 `false`；`all` / `ALL` / `a` / `*` → 全真；按 `','` 切段，空段（含尾部逗号）返回 `false`；段内含 `'-'` 视为区间：两侧必须非空、右段不得再含 `'-'`、两侧纯十进制数字且 ≤ `1000000`、`左≥1`、`右≥左`、`右≤套件数`；单编号同规则；任一非法立即返回 `false`（已写入的真值不回滚，调用方按返回值丢弃）。成功返回 `true`。 |

补充：`数字解析()` 只接受 `'0'..'9'`，累计值超过 `1000000` 立即判非法（`测试选择模型.cpp` 匿名命名空间）。

| 接口 | 语义 / 前置条件 / 失败行为 |
| --- | --- |
| `ui_install()` | 幂等（`installed` 先置位）。把 `&mirror` `Append` 到 `UnitTest` 监听器列表；随后 `Release` 默认打印器并 `delete`（`Release` 转移所有权，不 delete 会泄漏）。安装后控制台不再有 gtest 输出，结果只进镜像。 |

| `poll_on_caller()` | 非阻塞；无线程。无排队任务且本轮未开始 → 置 `Idle` 后返回。详见 §六 D4 的三环节。 |
| `is_running()` / `last_exit_code()` | 读原子量；`Running` 含「排队等待」阶段；`exit_code` 在每轮开始清零、任一条失败置 1。 |
| `progress_get()` | 转调镜像，读本轮「已完成 / 计划总数」（原子量，未持锁）。 |
| `rounds_snapshot()` | 持锁整体拷贝轮次历史；无上限截断。 |
| `cases_snapshot(out, max)` | 持锁取**尾部**最多 `max` 条（当前轮新结果在尾部）。`begin_index = size > max ? size - max : 0`；`max` 为负时 `begin_index > size`，循环不进入，返回空结果。调用方应传正数。 |
| `output_tail(out, max)` | 同上，取输出缓冲尾部最多 `max` 行。 |

| 接口 | 语义 |
| --- | --- |
| `round_begin(total, suites)` | 持锁清 `cases`、进度归零、`total_cases = total`、`current_case` 复位、`in_case=false`、`last_suite` 清空、记 `round_suites` 与 `round_start_ms`；追加 level 0 行 `"[==========] Running <total> tests from <suites> test suites."`。由运行器在每轮取到清单后调用（非 gtest 回调）。 |
| `round_end()` | 持锁遍历 `cases` 累计 `total / passed / failed / skipped / elapsed_ms`（`elapsed_ms` 为用例耗时之和）；`round = rounds.size() + 1` 入历史；追加轮末四类行：`"[==========] <total> tests from <round_suites> test suites ran. | `note_append(text, level)` | 持锁追加一行；供运行器报告「过滤串未命中」。 |
| 读接口 | 持锁拷贝；`progress_get` 不持锁（原子量）。 |
| `OnTestProgramStart` / `OnEnvironmentsSetUp*` / `OnEnvironmentsTearDown*` / `OnTestProgramEnd` | 空实现，仅满足接口。 |
| `OnTestIterationStart` / `OnTestIterationEnd` | 空实现。分片下每次迭代只含一条用例，禁止打印迭代横幅，否则每条都刷 `Running 1 tests`。 |
| `OnTestSuiteStart` / `OnTestSuiteEnd` | 空实现。套件横幅改由 `OnTestStart` 在套件名变化时打一次；套件收尾行因无法给出真实耗时合计而不输出。 |
| `OnTestStart` | 持锁；套件名 != `last_suite` 时更新并追加 `"[----------] <suite>"`（level 0）；重置 `current_case` 填 `suite/name`、`in_case=true`；追加 `"[ RUN      ] <suite>.<case>"`（1）。 |
| `OnTestPartResult` | 仅处理 `failed()` 的断言；追加 `"<file>:<line>: Failure\n<message>"`（3）。通过项不输出，与默认打印器一致。 |
| `OnTestEnd` | 持锁；取 `test_info.result()`，`elapsed_ms = elapsed_time()`；状态判定顺序 **先 `Skipped()` 再 `Failed()`**，否则 `Passed`；失败时遍历 `total_part_count()` 收集失败 `summary()` 为 `"<file>:<line>: <summary>"`；`cases.push_back`，超过 `cases_cap` 从头部 `erase`；`++completed_cases`、`in_case=false`；追加 `[       OK ] / [  SKIPPED ] / [  FAILED  ] <名> (<ms> ms)`（2/4/3）。 |

### 3.6 控制台菜单（`控制台选择菜单.h` / `.cpp`）

行为：打印标题、逐套件编号（`i+1`、名称、用例数）与提示；最多 3 次尝试。`std::getline` 失败（管道 / 重定向 / EOF）或输入全空白 → `模型.all_check()`、`过滤串 = 模型.filter_string_build()` 并返回；解析失败 → 打印提示后重试；成功 → 逐套件 `suite_check_set(i, 勾选表[i])`，再生成过滤串并返回。3 次均失败 → 兜底 `all_check()`。前置条件：`模型.suite_tree_build()` 已调用（否则套件表为空、打印空列表、任何输入都越界非法，最终兜底全选得到空过滤串）。

### 3.10 退出等待判定（`退出等待判定.h`，实现于 `主程序.cpp`）

| 命令行带 `--gtest_*` | 显式 `--selector=` | 选择模式 | 返回 |
| --- | --- | --- | --- |
| 否 | 否 | 任意（默认 `window`） | `true` |
| 是 | 否 | 任意 | `false` |
| 否 | 是 | `off` | `false` |

线程归属：全部逻辑在进程主线程。`Test_Runner::mtx` 与镜像的 `mutable mtx` 是「接口级防御」，用于覆盖未来可能的多线程读取；实际写入 / 读取同线程。`state` / `exit_code` / `completed_cases` / `total_cases` 用 `std::atomic` 以避免读接口持锁。

### 5.4 数据所有权

- `Test_Selection_Model` 由 `main` 栈上持有，引用传给控制台菜单与图形界面；`suite_table_` 独占。

- 界面 `static` 变量（搜索串等）生命周期 = 进程，跨会话保留。

## 六、模块设计 / 实现细节

### D1 层级表示：四个层级、三套子工程 + 自身

`Test_Layer` 的 4 个有效层级与 `层级表()` 一一对应：`Self`（`Application/Test` 根，即 `src/单元测试/` 下自测用例）、`Foundation`、`System`、`Renderer`。层级不是人工标注，而是**按用例源文件路径反推**：`层级判定()` 把 `__FILE__` 规范化后匹配 `"/tests/foundation/"` 等片段，`src/单元测试/` 归 `Self`。这依赖两点：CMake 以绝对路径传 `__FILE__`；三个子工程目录名固定。任一不成立都会落 `Unknown`（界面有兜底分组，仍可运行）。

套件层级取「首个用例的层级」，隐含假设一个套件只出自一个编译单元；`测试选择模型测试.cpp::层级归类套件与用例一致` 用断言把该假设固化。若未来出现跨文件的同名套件，该假设会失效且不会报警（`EXPECT_EQ` 只在测试里跑）。

### D2 反射建树时机

`suite_tree_build()` 依赖 `UnitTest` 单例的注册表。注册发生在静态初始化期，但 `total_test_suite_count()` 的结果还受 `InitGoogleTest` 解析后的标志（如 `--gtest_filter` 不影响套件集合，但 `--gtest_list_tests` 会提前退出）影响。主程序固定顺序「InitGoogleTest → 注册锚 → 建树」，保证界面看到的是完整集合。任何在 `main` 之前调用 `suite_tree_build()` 的代码（例如静态对象构造）都可能看到空表。

### D3 勾选态是「唯一事实」，过滤串与清单是派生

模型只存 `checked`，不存「部分选择」的中间态：`suite_half_checked` / `layer_half_checked` 由计数现算。`filter_string_build()` 与 `selected_cases()` 是同一事实的两种投影：前者给「一次全跑」的控制台路径，后者给「逐条迭代」的界面路径。两者语义必须一致，但存在一处不一致风险：过滤串在「整组全选」时压成 `套件.*`，而清单永远是逐条全名；若运行器改用过滤串执行，`套件.*` 会匹配套件下**所有**用例（含未登记进模型的？实际上模型就是全量反射，因此集合相同）。当前运行器只用清单，过滤串仅供控制台与 `--gtest_filter` 复跑提示。

空选择的处理是刻意设计：`filter_string_build()` 返回空串而**不是** `"*"`，`request_run()` 对空清单返回 `false`，主程序控制台路径在空过滤串时会退化为 gtest 默认「全跑」。三条路径的空选择行为并不完全一致：界面显式拒绝；控制台菜单在非法 / 空输入时主动 `all_check()`；`--gtest_filter=`（用户显式传空）则由 gtest 解释。这是「不隐式全跑」与「交互便利」之间的取舍，见 §六 D14。

### D4 分片执行：三环节与 8 ms 预算

`poll_on_caller()` 每次调用最多走三环节（`测试运行器.cpp`）：

1. **取走排队**（仅当 `!round_active`）：加锁检查 `queued`，无则 `state=Idle` 直接返回；有则 `cases.swap(pending_cases)`、`queued=false`、`stop_requested=false`。空清单兜底置 `Idle`。随后加锁 `running_cases.swap(cases)`、`cursor=0`、`round_active=true`；按 `"套件.用例"` 首个 `'.'` 前缀去重统计套件数；`exit_code=0`；`mirror.round_begin(len, 套件数)`。
2. **时间片执行**：记录 `steady_clock` 起点；循环加锁读 `stop_requested || cursor >= size`，结束即 break，否则取 `running_cases[cursor]`；解锁后 `case_execute(全名)`；失败则 `exit_code=1`；加锁 `++cursor`；累计用时 ≥ 8 ms 即 break（**至少执行一条**，因为判断在循环尾部）。
3. **收尾判定**：再次加锁判 `stop_requested || cursor >= size`；未收尾直接返回（下一帧继续）。收尾则 `mirror.round_end()`，复位 `running_cases/cursor/round_active/stop_requested`，`state=Idle`。

设计要点：`RUN_ALL_TESTS()` 不能在持锁期间调用（gtest 回调会进镜像取同一把锁 → 死锁）。代码在取用例名后立即释放锁，正是为此。`case_execute` 自身也不持 `mtx`。

### D5 为什么按用例而不是按整轮

- 单条用例耗时可单独计量（`TestInfo::result()->elapsed_time()`）。
- 失败可单独回传并在结果表定位。
- 一轮中途可停止（停止语义为「跑完当前条」）。
- 界面在片间能刷新一帧，避免 Windows 判「未响应」。
代价：每条用例一次 `RUN_ALL_TESTS`。gtest 在单次迭代内对「有匹配用例」的套件执行一次套件级 `SetUpTestSuite` / `TearDownTestSuite`；单用例过滤下该套件每条用例都要各自起一次迭代，套件级夹具因此**每条用例各跑一次**，这是与「整轮一次迭代」最大的语义差异。镜像的 `OnTestSuiteStart/End` 因此被刻意留空（套件耗时无法汇总）。这一点对依赖套件级夹具复用状态的用例有影响，属于已知取舍但文档未标注。【待确认：8】

### D6 过滤串未转义

`case_execute` 直接 `GTEST_FLAG(filter) = case_name`。gtest 的过滤语法把 `:` 作正模式分隔、`-` 作排除、`*` 作通配；若套件或用例名含这些字符（gtest 允许 `TestName` 中除 `_` 外多数 ASCII，但参数化后缀常带 `/`），可能匹配到额外或零条用例。零条时有 `note_append` 告警兜底；多条时不会告警，结果会多跑。当前用例命名均为中文 + 下划线，风险未暴露。【待确认：6】

### D7 主线程约束

`图形操作界面.cpp` 主循环第一句就是 `运行器.poll_on_caller()`，之后才 `frame_stats_get()` 与 `frame_render()`。由于 `poll_on_caller` 同步执行最多 8 ms 的测试，`frame_render` 与 UI 回调发生在「片间」。这不仅满足 SDL3 主线程要求，也让渲染层用例（自带窗口 / 事件泵）与测试界面的 SDL 事件泵处于同一线程，避免两个窗口的事件循环竞争。

`测试运行器.h` 的注释与实现一致；`图形操作界面.h` 第 9 行写「测试运行器在工作线程内执行」，与实现矛盾，以实现为准。【待确认：2】

### D8 输出镜像如何补齐被抑制的横幅

默认打印器被销毁后，gtest 不再输出任何文本；镜像必须自行重建「控制台观感」。策略：

- 轮首规模由**运行器**显式给（`round_begin(len, 套件数)`），因为每次迭代只有 1 条，gtest 自带的 `[==========] Running 1 tests` 会被 `OnTestIterationStart` 抑制。
- 套件横幅改在 `OnTestStart` 按「套件名变化」打印，保证同一套件只打一次（分片下同一套件可能跨多个时间片）。
- 轮末统计由 `round_end()` 统一给出，`OnTestIterationEnd` 抑制。
- 套件收尾行不输出，因为一条用例一次迭代无法得到套件总耗时。

结果是镜像文本在「轮 / 套件 / 用例 / 断言」四级上与 gtest 控制台近似，但**轮末的 `total` 是采集到的用例数**，不是 `round_begin` 的计划数：若某条过滤串未命中，计划 N 条、实际追加 N-1 条，轮末仍打印 N-1（并有 WARN 行）。顶部进度条的 `total_cases` 则保持计划数，两者会出现 1 条差。属于已知观感差异。

### D9 缓冲上限与截断语义

| 容器 | 上限 | 溢出策略 | 后果 |
| --- | --- | --- | --- |
| `output` | 2000 行 | 丢最旧 | 长时间会话只保留尾部 |
| `cases` | 10000 条 | 丢最旧 | 单轮超过 1 万条时 `round_end` 的 `total/passed` 会偏小 |
| `rounds` | 无 | 只增 | 多轮回归会话缓慢增长（每轮一个 `Round_Summary`，数十字节） |
| 界面可见 | 400 行 / 400 条 | 取尾部 | 顶部「通过 / 失败 / 跳过」按 400 条快照统计，超过 400 条时计数偏小 |

界面计数偏小是可观察的：`测试界面_绘制()` 用 `runner.cases_snapshot(用例表, 结果上限)` 的结果累计 `通过数/失败数/跳过数`，而进度条用 `progress_get` 的计划完成数。用例总数超过 400 的大轮次会出现「进度 100% 但通过数只有 400」。见【待确认：7】。

### D10 日志桥接：根节点绑定而不是逐调用点重定向

`引擎日志屏蔽.cpp` 用日志系统的「路径节点 + 父链继承」机制：`logger.root_set("")` 把根目录设为整个项目（空串是合法值），`logger.stream_bind("", 日志流)` 把根节点绑到外部 `ofstream`。所有调用点的日志路径键都从根派生，沿父链命中根节点的流，不再落控制台兜底。相比逐文件 / 逐模块绑定，这种做法只改一处、无需知道调用点路径；代价是**全局唯一**：一旦开启，所有引擎日志（含被测用例的日志）都进同一文件，测试期间无法按套件分流。

落盘由 `stream_flush()` 统一完成；文件目标按 `file_flush_size = 4096` 批量写，故崩溃 / 提前返回时可能丢尾部缓冲。主程序在每条返回路径（透传、控制台、图形回退、图形正常结束）都调用了 `日志屏蔽_落盘()`，属于「宁可多刷一次」的保守策略。

路径含中文（`out/引擎运行日志.txt`）必须经 `detail::string_to_path`；`std::filesystem::path` 在 Windows 按本地码页解读 `const char*`，直接拼接会得到乱码文件名。界面读取时同样经 `string_to_path` 反向转换。

### D11 开启 / 关闭的成对契约

`日志屏蔽_关闭()` 不只是「停用」，还要 `root_clear()` 恢复「未设置根目录则禁止绑定」的门禁状态；否则后续 `stream_bind` 会因根目录仍为 `""` 而被允许，但状态标记已复位，出现「逻辑认为未屏蔽、实际仍在屏蔽」的错位。日志系统用例在夹具里成对调用（`tests/Foundation/src/工具/日志系统测试.cpp`），属于对本模块的隐式依赖：用例验证「未绑定 → 走控制台」时必须先关闭。

### D12 层级版本判定：记录缺失即待更新

`layer_version_states_get()` 把「`依赖版本.cmake` 不存在」直接判为 `outdated + record_missing`，理由是该文件由子工程配置期写出，缺失意味着该子工程从未构建或构建树被清理 —— 此时该层的 `Test<Layer>.lib` 也不存在，界面上的「待更新」提示实际上等价于「该层没有可跑用例」。这比「缺记录 → 跳过判定」更安全（不会拿旧库跑新头），但也意味着干净构建树首次打开界面会看到多条隔离提示。`Self` 的 `依赖版本.cmake` 由本层配置期写出（`Application/Test/CMakeLists.txt` 调 `byjy_banben_jilu("${CMAKE_BINARY_DIR}")`），本层构建过即存在。

`version_mismatch()` 跳过「当前版本为空」的项：锚点头读不到（例如下层未构建、路径布局不同）时不会误报。反过来，若 `recorded` 为空而 `current` 非空，会报「记录缺少该层版本」。

当前版本解析优先级为「版本锁值 → 构建树锚点」。锁非空时读 `Engine/版本锁.cmake` 的 `BYJY_LOCK_<层>_<配置>`，因为该值就是「重建该层会解析到的版本」；锁空时读 `<层>/out/build/x64-<配置>/include/Engine/<层>/版本锚点.h` 的 12 位哈希。锚点头注释行格式由 `Engine/EngineFoundation/cmake/生成版本锚点.cmake` 固定为 `//   哈希：<12 位>`，`锚点哈希读取()` 取标记后最多 12 位十六进制。【待确认：9】

### D13 界面默认隔离与「重新检测」

首帧（`层级状态已读 == false`）调用一次 `layer_version_states_get()`；若 `待更新已隔离 == false`，对每个 `outdated` 层执行 `model.layer_check_set(layer, false)`，然后置 `待更新已隔离 = true`。左栏顶部把 `outdated` 层分隔到「待更新层级（已默认隔离，重建后再跑）」区，并给出 `cmake --build <子工程>/out/build/x64-<配置>` 的提示；已同步层按枚举顺序分组；最后兜底 `Unknown`。

「重新检测」按钮把 `层级状态已读` 与 `待更新已隔离` 同时复位，下一帧重读并**再次整层取消勾选**。副作用：用户在旧状态下手工勾选的待更新层用例会被清掉，且如果下层已重建（`outdated` 消失），该层不会被重新勾选（保持用户此前的取消状态）——这与「重建后再跑」的提示不完全吻合。见【待确认：5】。

### D14 界面交互的隐式约定

- 套件复选框只有二态，半选态用文字计数 `（已选/总数）` 表达；`ImGui::Checkbox("##套件勾选")` 的初值取 `suite_all_checked`，半选时显示为未勾，点一下会整组置真。
- 右键菜单提供「只选此项（先 `all_clear`）」「全选此项」「清空此项」，以绕开二态复选框无法表达「只选一个」的问题。
- 「运行选中」与 `Enter` 完全等价（同一段代码复制两份）；空选择时写 `运行提示` 并在按钮下方以失败色显示。
- 「重跑失败」只在当前快照存在 `Failed` 时可用（`BeginDisabled(!有失败)`）；清单按快照顺序，最多 200 条。
- 「停止」只在 `is_running()` 时可用；停止不取消当前条。
- 「退出界面」与 `Esc` 都只置 `exit_requested = true`，由主循环下一帧检查后 break；`Esc` 用 `IsKeyPressed(ImGuiKey_Escape, false)` 只认按下沿。
- `ImGui::GetIO().WantTextInput` 为真时不响应 `Enter`，避免搜索框输入回车误触发运行。

### D15 快照拷贝而非共享

`Test_Runner` 的四个读接口都返回**值拷贝**（`rounds_snapshot` / `cases_snapshot` / `output_tail` / `progress_get`），界面每帧重新取。这样界面渲染不会长时间持锁，也不会因镜像容器的 `erase(begin)` 而迭代器失效。代价是每帧复制最多 400 条 `Case_Result`（每条含 `failures` 字符串向量），在 60 FPS 下是可见的堆分配开销；快照限量（400）正是为此。

### D16 初始化与清理顺序（图形路径）

初始化：`Renderer::init(配置)` → `ui_channel()` 校验 → `ImGui::CreateContext` + `ConfigFlags_NavEnableKeyboard` + `IniFilename = nullptr`（不写 `imgui.ini`）→ 主题 → `ImGui_ImplSDL3_InitForVulkan(通道信息.window)` → 填 `ImGui_ImplVulkan_InitInfo`（`DescriptorPoolSize = 64`，描述符池由后端自建）→ `ImGui_ImplVulkan_Init` → 字体 → 运行器 `ui_install()` → 设置绘制 / 事件回调 → `scene_apply(深蓝清屏色)`。

清理：`event_callback_clear()` → `draw_callback_clear()` → `运行器.shutdown()` → `渲染器.frame_wait_idle()` → `ImGui_ImplVulkan_Shutdown()` → `ImGui_ImplSDL3_Shutdown()` → `ImGui::DestroyContext()` → `渲染器.shutdown()`。`frame_wait_idle` 必须夹在后端销毁之前：ImGui 的 Vulkan 后端销毁时会释放自建描述符池 / 采样器 / 管线，若最后一帧命令缓冲仍在飞，校验层会报「资源仍在使用」。

任一初始化失败点的回滚顺序都与上述相反且只回收已成功步骤：SDL3 失败 → `DestroyContext` + `Renderer::shutdown`；Vulkan 后端失败 → `SDL3_Shutdown` + `DestroyContext` + `Renderer::shutdown`。

### D17 字体与主题

`加载中文字体()` 先构造字形范围（中文全范围 + 4 个符号），再按候选路径逐个「文件存在性检查 → `AddFontFromFileTTF`」。存在性检查前置是关键：ImGui 的 `AddFontFromFileTTF` 失败会向 `io` 的日志通道打印，逐个候选失败会刷屏。全部失败返回 `false`，界面继续运行（中文显示为方块），只打印一行警告。字体像素 19，界面内用 `PushFont(Fonts[0], 字号)` 做 17/19/21/28 的动态字号（依赖 ImGui 的「同字体不同字号」支持）。

主题分两层：`应用蓝色主题()` 改全局 `ImGuiStyle`；`测试界面.cpp` 的卡片样式用 `PushStyleColor/PushStyleVar` 局部覆盖。两者叠加的结果是「窗口底色全透明 + 背景绘制列表的渐变透出 + 卡片半透明深蓝」。

### D18 错误处理策略

- 不抛异常：文件流用 `error_code` 重载；内存分配用 `new(std::nothrow)`（`引擎日志屏蔽.cpp` 的 `ofstream`）；读接口不校验 `max_count` 负值。
- 失败即降级：日志屏蔽失败 → 日志留控制台；字体失败 → 方块中文；图形初始化失败 → 控制台菜单；过滤串未命中 → WARN 行；层级记录缺失 → 待更新提示。
- 越界即忽略：模型的所有 `set` 接口与查询接口对越界静默返回，不 `assert`、不抛（单测用 `EXPECT_NO_THROW` 固化）。
- 生命周期错误靠约定：镜像必须摘除；回调必须在栈对象销毁前清除。代码没有运行期保护（悬垂指针无法检测）。

### D19 退出码与「成功」的定义

`Test_Runner::last_exit_code()` 是「本轮是否有失败」的布尔化（0/1），由 `case_execute` 的返回值聚合；不是 gtest 的完整退出码。`main` 的返回值：透传 / `off` 路径返回 `RUN_ALL_TESTS()` 原值；`console` 路径返回该轮 `RUN_ALL_TESTS()`；图形路径固定返回 0（界面里跑了多少轮、是否失败都不影响进程退出码）。因此 `EngineTests --selector=window` 即使在界面里跑出失败，进程仍以 0 退出 —— 自动化不应使用 window 模式。

### D20 argv 重建的细节

主程序把每个参数复制进 `std::vector<std::string> 保留参数文本`，再取 `std::string::data()` 组成 `std::vector<char*>`，末尾补 `nullptr`，`参数个数 = 保留参数文本.size()`。因为 `vector<string>` 在循环中不再增长（`push_back` 在收集阶段完成，重建阶段只读），`data()` 指针稳定。`InitGoogleTest` 可能修改 `argv`（例如移除已识别标志），但 `std::string::data()` 可写（C++17 起非 const 版本），容量足够容纳标志重写。`--selector=` 被摘除后不进入 gtest，避免 gtest 报未知参数。

## 七、模块运行链路详例

### 7.1 启动 → 选择 → 运行 → 展示（图形路径）

1. **进程启动**（`主程序.cpp::main`）：`SetConsoleOutputCP(CP_UTF8)` / `SetConsoleCP(CP_UTF8)`；`engine::日志屏蔽_开启()` → `create_directories(<exe>/out)`、建 `ofstream(trunc)`、`logger.root_set("")`、`logger.stream_bind("", 日志流)`、`屏蔽已开启 = true`。
2. **参数分流**：循环 `argv[1..]`，命中 `--selector=` 则记 `选择模式` 与 `显式选择器 = true` 并跳过；命中 `--gtest_` 记 `命令行带过滤 = true` 但仍保留。重建 argv。
3. **gtest 初始化**：`::testing::InitGoogleTest(&参数个数, 参数指针.data())`；随后 `byjy_test_anchor_foundation/system/renderer()` 强制引用。
4. **建模型**：`engine::Test_Selection_Model 模型; 模型.suite_tree_build();` → 反射得到全部套件，逐用例按 `__FILE__` 归层，全部默认勾选。
5. **开界面**：`engine::图形操作界面_运行(模型)` → `Renderer_Config{1280×800, "白银纪元 · 测试操作界面", frame_overlap=2, instance_capacity=512, vsync=true, hidden=false}` → `Renderer::init` → `ui_channel()` → `ImGui` 上下文 / SDL3 后端 / Vulkan 后端 → 中文字体 → `Test_Runner 运行器; 运行器.ui_install()`（Append 镜像、Release + delete 默认打印器）→ `draw_callback_set(ui_绘制回调)` / `event_callback_set(ui_事件回调)` → `scene_apply(深蓝)`。
6. **选择**：进入主循环，`frame_render` 内回调 `ui_绘制回调` → `测试界面_绘制` → 首帧读 `layer_version_states_get()`，把 `outdated` 层整层取消勾选并置顶；用户勾选套件 / 用例、搜索、右键「只选此项」等只改 `模型.suite_table_`。
7. **下发运行**：点「运行选中」或 `Enter` → `runner.request_run(model.selected_cases())`；空清单返回 `false`，界面写提示；非空则 `pending_cases = 清单`、`queued = true`、`state = Running`。
8. **执行**：同一帧或下一帧主循环开头 `运行器.poll_on_caller()`：
   - 环节一取走清单，`mirror.round_begin(N, 套件数)` 写轮首横幅；
   - 环节二逐条 `case_execute`：`GTEST_FLAG(filter) = "套件.用例"`、`repeat = 1`、`break_on_failure = false` → `RUN_ALL_TESTS()` → 镜像 `OnTestStart`（套件横幅 + `[ RUN ]`）→ 断言失败时 `OnTestPartResult`（`file:line: Failure`）→ `OnTestEnd`（状态 / 耗时 / 失败摘要、`[ OK/FAILED ]`、`completed_cases++`）；累计 8 ms 后返回；
   - 环节三：清单跑完 → `mirror.round_end()` 写轮末统计并追加 `Round_Summary`；复位状态。
9. **展示**：下一帧 `测试界面_绘制` 调 `runner.cases_snapshot(…, 400)` / `rounds_snapshot` / `output_tail(…, 400)` / `progress_get`：顶部胶囊显示「运行中 / 空闲」与进度；中栏结果表按快照逐行画状态胶囊、用例名、耗时；右栏选中行详情（失败摘要）与轮次堆叠条；底部输出镜像按 level 着色并自动滚动；左栏套件状态点按快照聚合变红 / 绿。
10. **结束**：界面「退出界面」或窗口关闭 → `exit_requested` / `close_requested()` → break → 解接线 → `运行器.shutdown()`（`request_stop` + `Release(&mirror)`）→ `frame_wait_idle` → ImGui 后端与上下文销毁 → `Renderer::shutdown()` → 返回 `true` → `main` 调 `日志屏蔽_落盘()` → `return 0`。

### 7.2 启动 → 控制台选择 → 单轮运行 → 停窗（console 路径）

1. `main` 同上完成 UTF-8、日志屏蔽、`InitGoogleTest`、注册锚、`suite_tree_build()`。
2. `选择模式 == "console"` → `控制台选择菜单_运行(模型, 过滤串)`：打印编号表与提示；`std::getline` 读取；空 / EOF → `模型.all_check()` + `filter_string_build()`；非法输入最多 3 次；成功则 `解析控制台选择()` → 逐套件 `suite_check_set(i, 勾选表[i])` → `过滤串 = 模型.filter_string_build()`。
3. 打印「过滤串：…」「可用 `--gtest_filter=…` 复跑同一批用例。」
4. `::testing::GTEST_FLAG(filter) = 过滤串;` → `RUN_ALL_TESTS()`（**不安装镜像**，输出为 gtest 原生控制台格式）。
5. `日志屏蔽_落盘()`；`engine::需要等待退出("console", 命令行带过滤, 显式选择器)` → 默认 `true` → `等待用户关闭窗口()`：无控制台窗口直接返回；否则打印提示、`FlushConsoleInputBuffer`、`_getch()`。
6. `return 测试结果`（gtest 退出码）。

### 7.3 自动化透传（`--gtest_*` 或 `--selector=off`）

1. 参数循环记录 `命令行带过滤`；若同时出现 `--selector=` 则 `显式选择器 = true`（此时不再走透传，按显式模式走）。
2. `InitGoogleTest` 解析 `--gtest_filter` / `--gtest_repeat` 等；注册锚执行。
3. 条件 `(命令行带过滤 && !显式选择器) || 选择模式 == "off"` 成立 → `RUN_ALL_TESTS()`（gtest 原生输出，无镜像、无界面）→ `日志屏蔽_落盘()` → 直接返回退出码。
4. ctest 注册形态：路径非纯 ASCII 时 `add_test(NAME EngineTests COMMAND EngineTests --selector=off ...)`，落在本路径；纯 ASCII 时用 `gtest_discover_tests` 逐用例发现。

### 7.4 单个失败用例的输出回传（端到端）

1. 界面「运行选中」/ `Enter` → `request_run(selected_cases())`（非空）→ `pending_cases`、`queued`。
2. `poll_on_caller()` 环节一：`mirror.round_begin(N, S)` → `output` 追加 `[==========] Running N tests from S test suites.`（level 0），`total_cases = N`，`completed_cases = 0`，`round_start_ms` 记录。
3. 环节二对该失败用例：`case_execute("Suite.Case")` → `GTEST_FLAG(filter)`、`repeat`、`break_on_failure` 设置 → `RUN_ALL_TESTS()`。
4. gtest 回调链（同一线程、同步）：
   - `OnTestStart`：若套件名与 `last_suite` 不同 → `[----------] Suite`（0）；`current_case = {suite, name, Passed, 0, {}}`；`[ RUN      ] Suite.Case`（1）。
   - `OnTestPartResult`（失败断言）：`output += "<file>:<line>: Failure\n<message>"`（3）。
   - `OnTestEnd`：`elapsed_ms = result->elapsed_time()`；先 `Skipped()` 后 `Failed()` 判状态 → `Failed`；遍历 `total_part_count()` 收集失败摘要 `"<file>:<line>: <summary>"`；`cases.push_back(current_case)`；`completed_cases++`；`output += "[  FAILED  ] Suite.Case (<ms> ms)"`（3）。
5. `case_execute` 返回 `false` → 运行器 `exit_code = 1`；`cursor++`。
6. 环节三：清单跑完 → `mirror.round_end()`：统计 `failed >= 1`，追加 `[==========] N tests from S test suites ran. (墙钟 ms total)`、`[  PASSED  ] P tests.`、有跳过则 `[  SKIPPED ] ...`、`[  FAILED  ] F tests.` 并逐条列 `Suite.Case`（3）；`Round_Summary` 入 `rounds`。
7. 下一帧界面：`cases_snapshot` 把该用例放进结果表（`状态胶囊("失败", 失败色)`）；用户点该行 → `选中结果` = 快照下标 → 右栏「详情与历史」用 `选中用例.failures` 逐条以失败色显示；底部输出镜像按 level 3 着色显示断言原文与 `[ FAILED ]` 行。
8. 用户点「重跑失败」→ `失败用例清单生成(用例表)` 拼出 `"Suite.Case"`（上限 200）→ `request_run(...)` 重走 2–7。

### 7.5 退出时存在待决用例的判定

「待决」分三种状态：排队未取走（`queued=true, pending_cases` 非空）、本轮执行中（`round_active=true, cursor < size`）、已收到停止但当前条未跑完。链路上的处理：

1. **用户点「停止」** → `request_stop()`：加锁 `queued=false`、`pending_cases.clear()`、`stop_requested=true`。排队清单被**丢弃**（不是延后执行）；当前正在执行的用例继续跑完。
2. `case_execute` 返回后 `cursor++`；环节二下一轮循环重新加锁读 `已结束 = stop_requested || cursor >= size` → `true` → break。
3. 环节三再次判定 `收尾` 为 `true` → `mirror.round_end()`（把已跑完的用例汇总成一轮，`total` 为实际采集数）→ 清 `running_cases`、`cursor=0`、`round_active=false`、`stop_requested=false`、`state=Idle`。**未跑的待决用例不会产生结果行**，界面结果表只显示已跑部分。
4. **用户点「退出界面」/ 按 `Esc` / 关窗**：`exit_requested = true`（或 `渲染器.close_requested()`）→ 主循环 `break`。由于 `poll_on_caller` 是同步调用，此刻不可能有「正在跑」的用例；最多存在未取走的排队清单。
5. 清理阶段 `运行器.shutdown()` → `request_stop()` 再次清空排队并置 `stop_requested`（若之后有人误调 `poll_on_caller`，环节一会因 `!queued` 直接置 `Idle` 返回）；随后 `Release(&mirror)` 摘除监听器。
6. **停窗等待判定**只在控制台路径与「图形不可用回退」路径调用：`需要等待退出(选择模式, 命令行带过滤, 显式选择器)` 按 §3.10 的表返回。图形正常路径不等待 —— 窗口本身就是用户可见的输出载体，关窗即确认。自动化路径（带 `--gtest_*` 未显式指定 selector，或 `--selector=off`）一律不停，避免 CI / 重定向场景被 `_getch()` 挂住。

### 7.6 层级待更新隔离链路

1. 界面首帧：`层级状态已读 == false` → `层级状态 = layer_version_states_get()`：项目根 = `exe_dir` 上溯两级；配置 = `_DEBUG` ? `Debug` : `Release`；读 `Engine/版本锁.cmake` 文本；对 4 层分别读 `<相对目录>/out/build/x64-<配置>/依赖版本.cmake`，缺失即 `outdated + record_missing`；否则取 `BYJY_BUILD_AGAINST_*` 与当前版本（锁值优先，否则锚点头 12 位哈希）→ `version_mismatch()` 生成原因。
2. `待更新已隔离 == false` → 对每个 `outdated` 层 `model.layer_check_set(layer, false)`；置位。
3. 左栏：顶部渲染「待更新层级（已默认隔离，重建后再跑）」+ `cmake --build <子工程>/out/build/x64-<配置>` 提示 + 逐层 `层级分组绘制(..., &状态, true, ...)`（进度条用「待更新」红色胶囊 + 逐条原因）；分隔线后画「已同步层级」；最后兜底 `Unknown`。
4. 用户重建子工程后点「重新检测」→ `层级状态已读 = false; 待更新已隔离 = false;` → 下一帧重读；`outdated` 消失的层回到正常分组（但其勾选态仍是上次被清空的值）。
5. 运行不受层级隔离强制约束：用户仍可手工重新勾选待更新层并运行（界面只提示，不拦截）。
