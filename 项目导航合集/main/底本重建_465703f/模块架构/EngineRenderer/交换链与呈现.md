# 交换链与呈现模块

> 依据版次：EngineRenderer fb26686 ｜ 依据：冻结快照 465703f ｜ 更新：2026-11-08

本模块由两个并列的“呈现载体”子系统组成：`Swapchain/`（窗口交换链）与 `RenderTarget/`（离屏渲染目标）。两者都以 Vulkan 图像为最终载体，都以 `Memory_Context` 为图像内存来源，都以“构建 → 使用 → 销毁”为生命周期，但一个面向窗口表面、一个面向离屏合成。

## 二、模块功能介绍

本模块回答的问题是“渲染结果最终落在哪张图像上，以及这张图像由谁拥有、什么格式、配套什么附件与同步原语”。它只做“载体”的建立与维护，不做录制与提交。

`Swapchain_Context` 负责窗口呈现链的全部非管线资源：查询物理设备对表面的能力，选择格式/色彩空间、呈现模式、范围与图像数，创建 `VkSwapchainKHR`，取得驱动分配的交换链图像并为其建立 2D 颜色视图，创建“每交换链图像一个”的图像可用信号量与呈现完成信号量，再为每张交换链图像建立一张深度图像与一张（可选）MSAA 颜色/深度附件。它对外只暴露裸 Vulkan 句柄与只读查询，不暴露任何策略；唯一带参数的写接口是 `sample_count_set`（采样数）与 `rebuild`（重建）。

`Render_Target_Context` 负责离屏目标的全部非管线资源：按调用方给出的宽高、颜色格式、深度格式创建颜色图像（颜色附件 + 采样 + 传输源）、深度图像（深度附件 + 传输源 + 采样）、可选 MSAA 颜色/深度附件及各自的视图，并完成一次性的初始布局转换，使颜色进入 `VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL`、深度进入 `VK_IMAGE_LAYOUT_DEPTH_ATTACHMENT_OPTIMAL`。它以单调分配的 `uint64_t` 句柄标识目标（0 为无效，句柄 = 下标 + 1），并额外提供颜色/深度的同步读回、资源分离（`target_detach`）与采样数切换。

不负责的部分（边界）：

- 设备、队列族、表面创建、窗口尺寸与最小化状态：由设备模块与平台模块持有；本模块只接收已创建好的句柄。
- 图像内存的实际分配与回收、缓冲创建与映射：由 `Memory_Context` 持有与执行；本模块只调用其 `image_create` / `image_view_create` / `image_destroy` / `image_view_destroy` / `buffer_create` / `buffer_read` / `buffer_destroy`。
- 帧栅栏、命令缓冲、acquire/present 的调用、延迟销毁队列：由帧模块持有；交换链模块只提供“每交换链图像”的信号量，`vkAcquireNextImageKHR` / `vkQueuePresentKHR` 均由帧模块发起。
- 图形管线、描述符集、着色器：由管线/着色器模块持有；重建后是否需要重建管线由门面判断，本模块不通知。
- 布局不变量的逐帧维持：`Render_Target_Context` 只在创建时完成一次初始转换，帧间进入/退出附件布局由帧链路负责（见 §六）。

两类载体的区别与共用抽象（本模块存在的核心理由）：

| 维度 | 交换链（`Swapchain_Context`） | 离屏渲染目标（`Render_Target_Context`） |
| --- | --- | --- |
| 图像来源 | `vkCreateSwapchainKHR` 由驱动分配，模块只取得句柄 | `Memory_Context::image_create`（VMA 分配）自建 |
| 数量与标识 | 一组图像，按 `uint32_t` 索引；索引即 acquire 返回值 | 若干独立目标，按 1-based `uint64_t` 句柄标识 |
| 颜色格式 | 运行时查询并选择（`B8G8R8A8_SRGB` 优先，见 §六） | 调用方显式给出（门面传当前交换链格式） |
| 颜色用法 | `COLOR_ATTACHMENT` + `TRANSFER_SRC`（与表面能力求交），不含 `SAMPLED` | `COLOR_ATTACHMENT` + `SAMPLED` + `TRANSFER_SRC` |
| 颜色图像视图 | 2D、单层、单级、`ASPECT_COLOR`，创建时即建 | 同左 |
| 颜色常态布局 | 不设常态；呈现前由帧链路转为 `PRESENT_SRC_KHR` | `SHADER_READ_ONLY_OPTIMAL`（模块不变量） |
| 深度附件 | 每交换链图像一张；`DEPTH_STENCIL_ATTACHMENT` + `SAMPLED`；格式 D32→D32S8→D24S8 | 每目标一张；`DEPTH_STENCIL_ATTACHMENT` + `TRANSFER_SRC` + `SAMPLED` |
| 深度常态布局 | `DEPTH_ATTACHMENT_OPTIMAL`（创建后一次性转换） | 同左 |
| 深度视图 | 2D、`ASPECT_DEPTH`（不含模板方面） | 同左 |
| MSAA 颜色附件 | 每交换链图像一张，格式 = 交换链格式，仅 `COLOR_ATTACHMENT`；解析到交换链图像 | 每目标一张，格式 = 目标颜色格式，仅 `COLOR_ATTACHMENT`；解析到单采样颜色图像 |
| MSAA 深度附件 | 每交换链图像一张，`DEPTH_STENCIL_ATTACHMENT` + `SAMPLED`（供深度解析与 Hi-Z） | 每目标一张，仅 `DEPTH_STENCIL_ATTACHMENT` |
| 同步原语 | 每交换链图像各 1 个图像可用信号量与 1 个呈现完成信号量，随重建重建 | 无信号量、无长期栅栏；仅共享“一次性命令池 + 一次性栅栏”做阻塞式同步 |
| 呈现角色 | 参与 acquire 与 present，是最终呈现目标 | 不直接呈现；由帧链路作为附件写入、作为纹理采样，最后合成到交换链 |
| 尺寸来源 | 表面能力（`currentExtent` 或窗口宽高夹取） | 调用方显式宽高（允许与交换链尺寸不同，例如 SSAA/阴影图） |
| 交换/重建 | 窗口尺寸变化、表面过期/次优、MSAA 切换时重建；旧资源整体移交延迟销毁 | 不随窗口重建；仅由调用方创建/销毁，或采样数切换时原地重建 |
| 回读能力 | 模块不提供；帧模块利用 `TRANSFER_SRC` 用法自行回读颜色 | 模块提供颜色整幅/子区域、深度整幅/子区域同步读回 |

共用抽象：两者都以“构建一次上下文、按需创建载体、最后销毁”为生命周期；都以 `VkFormat` 作为跨模块格式契约（交换链由本模块决定、离屏目标由调用方沿用同一格式）；都以 2D 单层单级视图对外；都遵循“创建后一次性布局转换、此后由使用方维持布局”的分工；都在失败时通过返回值 + 日志报告，而不抛异常、不中途终止进程。

## 三、模块公开接口

本节只列头文件中真实存在的声明。命名空间均为 `engine`；`Memory_Context` 以 `class Memory_Context;` 前置声明，只作引用入参。

### 3.1 `Swapchain_Old_Resources`

重建时旧交换链及其附属资源的移交包，默认成员均为空。字段语义如下（字段类型为精确声明）：

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `swapchain` | `VkSwapchainKHR` | 旧交换链句柄；建新链时作为 `VkSwapchainCreateInfoKHR::oldSwapchain` 传入，之后由延迟销毁队列销毁。 |
| `images` | `std::vector<VkImage>` | 旧交换链图像句柄记录；**仅作索引记录，不单独销毁**（句柄由交换链持有）。 |
| `image_views` | `std::vector<VkImageView>` | 旧图像视图，需逐张销毁。 |
| `image_available_semaphores` | `std::vector<VkSemaphore>` | 旧图像可用信号量，每交换链图像一个。 |
| `render_finished_semaphores` | `std::vector<VkSemaphore>` | 旧呈现完成信号量，每交换链图像一个。 |
| `depth_images` | `std::vector<VkImage>` | 旧深度图像（每交换链图像一张）。 |
| `depth_allocations` | `std::vector<VmaAllocation>` | 旧深度图像内存，与 `depth_images` 成对。 |
| `depth_views` | `std::vector<VkImageView>` | 旧深度图像视图。 |
| `msaa_color_images` | `std::vector<VkImage>` | 旧 MSAA 颜色图像；未启用 MSAA 时为空。 |
| `msaa_color_allocations` | `std::vector<VmaAllocation>` | 旧 MSAA 颜色图像内存。 |
| `msaa_color_views` | `std::vector<VkImageView>` | 旧 MSAA 颜色视图。 |
| `msaa_depth_images` | `std::vector<VkImage>` | 旧 MSAA 深度图像；未启用时为空。 |
| `msaa_depth_allocations` | `std::vector<VmaAllocation>` | 旧 MSAA 深度图像内存。 |
| `msaa_depth_views` | `std::vector<VkImageView>` | 旧 MSAA 深度视图。 |

使用约定：该结构的所有权只在“移交”瞬间成立；调用方拿到非空结构后必须负责最终销毁（当前实现由帧模块的延迟销毁队列承担，见 §七）。

### 3.2 `Swapchain_Context`

生命周期与复制语义：

```cpp
Swapchain_Context(void) = default;          // 不创建任何 Vulkan 对象
~Swapchain_Context(void);                   // 内部调用 destroy()
Swapchain_Context(const Swapchain_Context&) = delete;
Swapchain_Context& operator=(const Swapchain_Context&) = delete;
```

未声明移动构造/移动赋值；因拷贝构造已删除，移动构造不会被隐式生成，故该类型实际不可移动，只能以引用或指针传递。

#### 3.2.1 生命周期与状态

```cpp
bool build(VkPhysicalDevice physical_device, Memory_Context& memory, VkDevice device, VkSurfaceKHR surface,
    uint32_t graphics_family, uint32_t present_family,
    uint32_t width, uint32_t height, bool vsync);
```

- 语义：记录设备/表面/队列族/垂直同步开关与内存模块引用，随后以 `oldSwapchain = VK_NULL_HANDLE` 调用 `swapchain_create`，一次性建立交换链、图像视图、两类信号量与深度（以及采样数大于 1 时的 MSAA 附件）。
- 前置条件：`physical_device`、`device`、`surface` 均非空；`memory.valid()` 为真（深度图像依赖内存模块）；`width`、`height` 均非 0。
- 失败/告警行为：三个句柄不完整 → `logger.error("交换链:: 构建设备句柄或表面不完整")` 并返回假；内存上下文未构建 → 错误日志并返回假；尺寸为 0 → `logger.warn("交换链:: 窗口尺寸为零，跳过交换链创建（K7）")` 并返回假；建链失败 → 错误日志后调用 `destroy()` 回收半成品并返回假。
- 隐式前置：`build` 未做“已构建则先销毁”的保护；同一对象连续 `build` 两次会覆盖成员并泄漏上一组资源（见 §附 待确认 6）。正确用法是 `build` 一次、`destroy` 后再次 `build`（初始化期切换 MSAA 的路径即 `destroy` 后 `build`）。

```cpp
void destroy(void);
```

- 语义：若已记录逻辑设备，先 `vkDeviceWaitIdle(device)`，再调用 `swapchain_resources_destroy()` 逆序释放信号量、深度与 MSAA 附件、图像视图、交换链本体，最后复位设备/表面/队列族/`vsync`/格式/深度格式/首次转换标志/范围。幂等：设备为空时只做状态复位。
- 注意：`sample_count` 与 `color_transfer_src` 不在 `destroy` 中复位；前者刻意保留以支持“先设采样数、再 destroy、再 build”的初始化路径，后者会在下次建链时重新确定。

```cpp
bool valid(void) const;
```

- 语义：`swapchain != VK_NULL_HANDLE && !images.empty()`。只检查交换链与图像，不校验深度/MSAA/信号量完整性。

```cpp
bool rebuild(uint32_t width, uint32_t height, Swapchain_Old_Resources& old_out);
```

- 语义：先保存依赖旧资源的派生状态（`format`、`depth_format`、`extent`、`depth_initialized`、`color_transfer_src`）；再把全部交换链侧资源“析出”到局部 `Swapchain_Old_Resources`（不销毁、不等设备空闲）；随后以旧交换链作为 `oldSwapchain` 建新链；成功后把旧资源整体移入 `old_out`（由调用方负责延迟销毁），失败则销毁半成品、把旧资源原样恢复、恢复派生状态并返回假。
- 前置条件：`device`、`surface` 已记录（即已 `build` 过）；`width`、`height` 非 0。
- 失败/告警行为：未构建 → 错误日志返回假；尺寸为 0 → 警告日志返回假（最小化不重建）；建链失败 → 错误日志 + 回滚 + 返回假，`old_out` 不被写出（保持调用方传入时的状态）。
- 关键副作用：重建成功时会重新查询表面能力，因此**格式、色彩空间、呈现模式、图像数、范围都可能变化**，模块只更新自身状态，不通知上层；上层需按新 `format_get()` / `depth_format_get()` 决定是否重建管线（门面确实这样做，见 §七）。

#### 3.2.2 图像与附件访问（全部只读，越界返回空句柄或 0）

```cpp
VkImage image_get(uint32_t index) const;                    // 交换链图像
VkImageView image_view_get(uint32_t index) const;           // 交换链图像视图
uint32_t image_count_get(void) const;                       // 交换链图像数
VkFormat format_get(void) const;                            // 表面颜色格式
VkExtent2D extent_get(void) const;                          // 交换链范围
VkSwapchainKHR handle_get(void) const;                      // 交换链句柄
VkSemaphore image_available_semaphore_get(uint32_t index) const;
uint32_t image_available_count_get(void) const;             // = 交换链图像数
VkSemaphore render_finished_semaphore_get(uint32_t index) const;
uint32_t render_finished_count_get(void) const;             // = 交换链图像数
VkImage depth_image_get(uint32_t index) const;
VkImageView depth_view_get(uint32_t index) const;
VkFormat depth_format_get(void) const;                      // 已选定的设备支持格式
bool color_transfer_src_get(void) const;                    // 交换链图像是否具备 TRANSFER_SRC
```

- 越界策略：所有按索引的获取在 `index >= 容器.size()` 时返回 `VK_NULL_HANDLE`，不打印日志；数量接口返回容器当前尺寸（未构建时为 0）。
- `color_transfer_src_get()` 的唯一意义是告知上层“交换链颜色可否作为传输源回读”；为假时上层应跳过像素回读，不影响正常呈现。

#### 3.2.3 MSAA 控制

```cpp
void sample_count_set(uint32_t count);      // 仅接受 2/4/8，其余按 1
uint32_t sample_count_get(void) const;
VkImage msaa_color_image_get(uint32_t index) const;
VkImageView msaa_color_view_get(uint32_t index) const;
VkImageView msaa_depth_view_get(uint32_t index) const;
VkImage msaa_depth_image_get(uint32_t index) const;
```

- `sample_count_set`：纯状态写入，不触发任何 Vulkan 调用；必须在 `build` / `rebuild` 之前调用才会生效。钳制规则：只有 2、4、8 被视为有效采样数，其余取值（含 1、3、6）一律置 1。
- 四个 MSAA 取值的越界或未启用（`sample_count == 1`）时返回 `VK_NULL_HANDLE`。
- 只暴露 MSAA 颜色图像/视图、MSAA 深度视图与 MSAA 深度图像，不暴露 MSAA 颜色内存与深度内存（内存只由交换链内部持有，用于重建析出与销毁）。
- `msaa_depth_image_get` 的用途（头注释）：场景 pass 结束时以“深度解析”把多重采样深度写入单采样深度图像，供 Hi-Z 生成读取。

### 3.3 `Render_Target_Record`

单个离屏目标的完整记录，默认成员均为空。字段与语义：

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `color_image` | `VkImage` | 单采样颜色图像。 |
| `color_alloc` | `VmaAllocation` | 颜色图像内存。 |
| `color_view` | `VkImageView` | 颜色图像视图（`ASPECT_COLOR`）。 |
| `depth_image` | `VkImage` | 单采样深度图像。 |
| `depth_alloc` | `VmaAllocation` | 深度图像内存。 |
| `depth_view` | `VkImageView` | 深度图像视图（`ASPECT_DEPTH`）。 |
| `msaa_color_image` / `msaa_color_alloc` / `msaa_color_view` | `VkImage` / `VmaAllocation` / `VkImageView` | MSAA 颜色附件；`sample_count <= 1` 时为空。 |
| `msaa_depth_image` / `msaa_depth_alloc` / `msaa_depth_view` | `VkImage` / `VmaAllocation` / `VkImageView` | MSAA 深度附件；未启用时为空。 |
| `color_format` | `VkFormat` | 创建时使用的颜色格式（采样数切换重建时复用）。 |
| `depth_format` | `VkFormat` | 创建时使用的深度格式（同上）。 |
| `sample_count` | `uint32_t` | 该目标实际采样数（1 = 关闭 MSAA）。 |
| `follow_sample_count` | `bool` | 是否跟随上下文默认采样数；假表示固定采样数（如阴影目标固定 1）。 |
| `extent` | `VkExtent2D` | 目标像素范围。 |
| `valid` | `bool` | 记录是否有效；假表示该槽为空。 |

该结构会被 `target_detach` 整份写出，因而“分离”是记录级的所有权转移。

### 3.4 `Render_Target_Context`

生命周期与复制语义：

```cpp
Render_Target_Context(void) = default;      // 不创建任何 Vulkan 对象
~Render_Target_Context(void);               // 内部调用 destroy()
Render_Target_Context(const Render_Target_Context&) = delete;
Render_Target_Context& operator=(const Render_Target_Context&) = delete;
```

同样不可移动（拷贝被删除后移动未隐式生成）。

```cpp
bool build(VkDevice device, uint32_t graphics_family, VkQueue graphics_queue, Memory_Context& memory);
```

- 语义：记录逻辑设备、图形队列族、图形队列（一次性转换的提交目标）与内存模块引用。
- 前置条件：`device`、`graphics_queue` 非空且 `memory.valid()` 为真。
- 失败行为：任一前置不满足 → `logger.error("渲染目标:: 构建前置不完整（设备 / 队列 / 内存模块）")`，返回假；成功时打印 info。
- 隐式前置：与交换链一致，未做重复 `build` 保护。

```cpp
void destroy(void);
bool valid(void) const;                     // device != VK_NULL_HANDLE && memory != nullptr
uint32_t target_count(void) const;          // 有效记录数（只读诊断）
```

- `destroy`：逐条销毁有效记录（先 MSAA、后深度再颜色的“视图→图像”顺序），清空 `records`，再销毁一次性栅栏与一次性命令池，最后复位设备/队列/队列族/内存指针。不调用 `vkDeviceWaitIdle`，依赖调用方已完成帧同步（门面在 `frame.destroy()` 之后调用，见 §七）。
- `target_count`：遍历 `records` 统计 `valid` 为真的条目，不改变任何状态。

#### 3.4.1 创建、销毁与分离

```cpp
bool target_create(uint64_t& handle_out, uint32_t width, uint32_t height,
    VkFormat color_format, VkFormat depth_format, uint32_t sample_count = 0);
```

- 语义：解析采样数（`sample_count == 0` 表示跟随上下文默认值并置 `follow_sample_count = true`；非 0 表示固定值并置假；随后把 1/2/4/8 之外的值钳为 1）；确保一次性命令池与栅栏就绪；创建颜色图像（`COLOR_ATTACHMENT | SAMPLED | TRANSFER_SRC`）与视图；创建深度图像（`DEPTH_STENCIL_ATTACHMENT | TRANSFER_SRC | SAMPLED`）与视图；创建可选 MSAA 颜色/深度附件；执行一次性初始布局转换；最后把记录放入第一个空槽（无空槽则追加），写出 `handle = 下标 + 1`。
- 前置条件：上下文 `valid()`；`width`、`height` 非 0；`color_format`、`depth_format` 均非 `VK_FORMAT_UNDEFINED`。
- 失败行为：参数不完整 → 错误日志、`handle_out = 0`、返回假；颜色/深度/视图/MSAA/转换任一步失败 → 错误日志、调用 `record_resources_destroy(record)` 归还已建资源、`handle_out` 保持 0；失败不会在 `records` 中留下半初始化条目（`record` 是局部变量）。
- 成功语义：句柄 ≥ 1；记录 `valid = true`；日志 `渲染目标:: 已创建（句柄 {}，{}×{}，采样数 {}）`。

```cpp
void target_destroy(uint64_t handle);
bool target_detach(uint64_t handle, Render_Target_Record& record_out);
bool target_valid(uint64_t handle) const;
```

- `target_destroy`：句柄为 0、越界或槽已空则直接返回（不打印）；否则归还该记录全部资源并把整条记录复位为空记录（槽变为可复用）。
- `target_detach`：句柄为 0、越界或槽已空则 `record_out` 置空并返回假；否则把记录**按值写出**（复制句柄，不销毁），随后把槽复位为空，返回真。所有权随之移交，调用方必须自行销毁。
- `target_valid`：`handle != 0 && handle <= records.size() && records[handle - 1].valid`。

#### 3.4.2 采样数切换

```cpp
bool sample_count_set(uint32_t count);
uint32_t sample_count_get(void) const;
```

- 语义：把 `count` 钳到 1/2/4/8（其他值按 1）；与当前上下文默认值相同则直接返回真；否则写入新值，并逐条重建 `valid && follow_sample_count` 的目标：保存宽高与格式 → 销毁旧资源（含 MSAA）→ 写入新采样数 → 重建颜色图像/视图、深度图像/视图、MSAA 附件 → 执行一次性初始布局转换 → 槽与句柄保持不变。固定采样数的目标被跳过。
- 失败行为：任一步失败会把该记录 `valid` 置假、回收已建资源并立即返回假；此时**已处理的目标处于新采样数，未处理的目标仍是旧值**，函数不做回滚（头注释要求调用方回退旧值重试；门面只打印警告，见 §附 待确认 5）。
- 隐式前置：`target_transition` 依赖一次性命令池已存在；只有在该上下文曾成功创建过目标时池才存在（`sample_count_set` 自身不调用 `transient_resources_ensure`）。

#### 3.4.3 查询

```cpp
bool target_get(uint64_t handle, VkImage& color_image_out, VkImageView& color_view_out,
    VkImageView& depth_view_out, VkExtent2D& extent_out) const;
bool target_extent_get(uint64_t handle, VkExtent2D& extent_out) const;
bool target_depth_get(uint64_t handle, VkImage& depth_image_out, VkImageView& depth_view_out) const;
bool target_msaa_get(uint64_t handle, VkImage& msaa_color_image_out, VkImageView& msaa_color_view_out,
    VkImageView& msaa_depth_view_out, uint32_t& sample_count_out) const;
bool target_msaa_depth_image_get(uint64_t handle, VkImage& msaa_depth_image_out) const;
```

- 全部为只读；句柄无效或槽已空时先把出参复位（空句柄 / `{0,0}` / 采样数 1）再返回假；成功时写出对应内容并返回真。
- `target_get` 不返回深度图像，只返回颜色图像、颜色视图、深度视图与范围；需要深度图像时用 `target_depth_get`。
- `target_depth_get` 的出参在无效时为空；头注释提示“采样前调用方须把深度转入 `SHADER_READ_ONLY_OPTIMAL`，用完转回 `DEPTH_ATTACHMENT_OPTIMAL`”。
- `target_msaa_get` 在关闭 MSAA 时返回真但图像/视图为空、采样数为 1；`target_msaa_depth_image_get` 在关闭 MSAA 时返回真但图像为空（调用方据此跳过深度解析）。

#### 3.4.4 读回

```cpp
bool target_readback(uint64_t handle, uint8_t* pixels, uint32_t capacity,
    uint32_t* width_out, uint32_t* height_out);
bool target_readback_region(uint64_t handle, uint32_t x, uint32_t y,
    uint32_t region_width, uint32_t region_height, uint8_t* pixels, uint32_t capacity,
    uint32_t* width_out, uint32_t* height_out);
bool target_readback_depth(uint64_t handle, uint32_t* values, uint32_t capacity,
    uint32_t* width_out, uint32_t* height_out);
bool target_readback_depth_region(uint64_t handle, uint32_t x, uint32_t y,
    uint32_t region_width, uint32_t region_height, uint32_t* values, uint32_t capacity,
    uint32_t* width_out, uint32_t* height_out);
```

- 颜色：`pixels` 为 RGBA8 紧排（逐行自上而下、无行填充），`capacity` 单位为**字节**，须不小于区域宽 × 高 × 4；读回后颜色图像仍回到 `SHADER_READ_ONLY_OPTIMAL`。
- 深度：`values` 为 32 位原始值，`capacity` 单位为**元素个数**，须不小于区域宽 × 高；读回后深度图像仍回到 `DEPTH_ATTACHMENT_OPTIMAL`。头注释假定深度格式为 `D32_SFLOAT`（按 float 解释），与 `target_create` 允许任意深度格式不一致（见 §附 待确认 3）。
- 子区域：`x` / `y` 为左上角，区域必须完整落在目标内（`x < width`、`y < height`、`region_width <= width - x`、`region_height <= height - y`）且宽高非 0，否则整次拒绝、尺寸出参归零。
- MSAA 目标：颜色读回可用（读的是已解析的单采样颜色图像，是否已解析由帧链路保证）；**深度读回直接拒绝**——MSAA 开启时实际深度写入多重采样附件，单采样深度未被写入。
- 前置条件（模块外）：调用方须保证无在途帧引用该目标；门面在读回前统一调用 `frame.frames_wait()`。
- 失败行为：句柄/出参/容量/边界任一不满足 → 错误日志（容量与越界会打印具体数值）并返回假；尺寸出参在失败时保持 0。实现内部使用一次性命令池 + 一次性栅栏做阻塞式提交与等待，不经帧模块。

### 5.2 所有权与生命周期

```
Swapchain_Context
├── [设备持有] swapchain ──► images（仅句柄记录，不销毁）
│                          ├─► image_views         （本模块销毁）
│                          ├─► image_available_semaphores（本模块销毁）
│                          └─► render_finished_semaphores（本模块销毁）
├── [VMA 持有] depth_images + depth_allocations ──► depth_views
└── [VMA 持有] msaa_color_images + msaa_color_allocations ──► msaa_color_views
             msaa_depth_images + msaa_depth_allocations ──► msaa_depth_views

Render_Target_Context
└── records[handle - 1]
    ├── [VMA] color_image + color_alloc ──► color_view
    ├── [VMA] depth_image + depth_alloc ──► depth_view
    ├── [VMA] msaa_color_image + alloc ──► msaa_color_view      （sample_count > 1）
    └── [VMA] msaa_depth_image + alloc ──► msaa_depth_view      （sample_count > 1）
```

- 交换链图像本体（`images`）由 `VkSwapchainKHR` 持有，模块只在重建析出时记录句柄，**任何路径都不对交换链图像调用销毁**；延迟销毁亦只销毁交换链本体。
- 视图与信号量由设备持有，模块负责成对销毁；深度与 MSAA 图像由 VMA 经 `Memory_Context` 持有，模块以“视图先于图像”的顺序归还。
- `Render_Target_Record` 的 1-based 句柄与向量下标绑定；`target_detach` 会把记录移出槽位，此后同一句柄若被新目标复用将指向新资源（见 §六 句柄复用）。
- 重建期间旧资源的所有权短暂转交给 `Swapchain_Old_Resources`，成功后转交帧模块延迟队列；失败则回到本对象。

### 5.3 创建/销毁顺序

创建（交换链）：`vkCreateSwapchainKHR` → `vkGetSwapchainImagesKHR` → 逐张 `vkCreateImageView` → 逐张 `vkCreateSemaphore`（图像可用、呈现完成各一）→ 深度图像/视图（`image_create` / `image_view_create`）→ MSAA 颜色/深度（采样数 > 1）→ 深度一次性布局转换。

销毁（交换链）：两类信号量 → 深度（视图→图像）→ MSAA（深度视图/图像 → 颜色视图/图像）→ 图像视图 → 交换链。

创建（离屏目标）：一次性池/栅栏 → 颜色图像/视图 → 深度图像/视图 → MSAA 附件 → 一次性布局转换 → 记录入槽。

销毁（离屏目标）：MSAA（深度 → 颜色）→ 深度（视图→图像）→ 颜色（视图→图像）→ 复位记录；上下文销毁时最后销毁栅栏与命令池。

### 5.4 线程与同步归属

- 两个上下文都没有内部锁；所有成员调用必须在同一渲染线程（或至少外部串行化）执行。
- 模块内部唯一的同步动作是“阻塞式等待”：交换链 `destroy()` 的 `vkDeviceWaitIdle`、深度/目标布局转换与读回的 `vkWaitForFences(UINT64_MAX)`。`rebuild` 刻意不含 `vkDeviceWaitIdle`。
- 每交换链图像的两个信号量归本模块；每帧槽的栅栏、命令池、命令缓冲归帧模块。由此形成跨模块约束：在途帧数不得超过图像可用信号量数量，否则“先等帧栅栏再取信号量”的复用前提不成立；门面在初始化时会把 `frame_overlap` 下调到 `image_available_count_get()`（见 §七）。
- 离屏目标无信号量；帧模块通过帧栅栏与 `frames_wait` 保证对目标图像的使用顺序；读回与采样数切换前门面会先 `frames_wait()`。

## 六、模块设计与实现细节

### 6.1 格式选择不硬编码，且允许降级

`format_select` 先查格式数量再查列表；仅一项且为 `UNDEFINED` 时按“任意格式皆可”直接取 `B8G8R8A8_SRGB` + `SRGB_NONLINEAR`。首选序列显式区分 sRGB 与 UNORM 两档，命中即保留驱动给出的 `colorSpace`；全部不匹配时兜底列表首项。这样在移动 GPU（常见 `R8G8B8A8_*`）与桌面 GPU（常见 `B8G8R8A8_*`）上都能取得可用格式，代价是“兜底首项”可能是低色深或非常规格式，模块不做进一步校验，交给上层管线按 `format_get()` 适配。

### 6.2 呈现模式只有 FIFO 与 MAILBOX

`present_mode_select` 在 `vsync == true` 时直接 FIFO；`vsync == false` 时才在支持列表中寻找 MAILBOX。不请求 IMMEDIATE（无撕裂保证且部分平台不可用）。查询失败或列表为空一律 FIFO，因为规范保证 FIFO 可用。由此可得两条约束：`vsync` 是“期望垂直同步”的语义，不是“必须用 FIFO”；关闭垂直同步但设备不支持 MAILBOX 时仍会落到 FIFO，实际仍受垂直同步限制，模块仅通过日志之外的方式不提示。

### 6.3 图像数量与范围

图像数请求 `minImageCount + 1`，并在 `maxImageCount > 0` 时钳到上限；`maxImageCount == 0` 视为无上限。`+1` 的意图是给驱动留一张周转余量，实际数量以 `vkGetSwapchainImagesKHR` 返回值为准（先查 count 再查句柄，最后再 `resize` 一次做防御性收敛）。

范围选择优先采信 `currentExtent`（Windows 上通常已由驱动给出客户区像素尺寸），仅在 `UINT32_MAX` 时使用调用方宽高并夹取到能力区间。因此“窗口尺寸”与“交换链范围”可能不一致：`build/rebuild` 传入的是窗口客户区尺寸，模块最终写入 `extent` 的是 `extent_select` 的结果。上层必须以 `extent_get()` 为准，门面据此刷新相机宽高比。

### 6.4 图像用法与回读能力降级

交换链用法 = `(COLOR_ATTACHMENT | TRANSFER_SRC) & supportedUsageFlags`。若颜色附件位不被支持则直接判为不可建链（错误日志返回假）；若传输源位不被支持则只告警，并把 `color_transfer_src` 置假，建链照常进行。上层据此跳过交换链像素回读，渲染路径不受影响。交换链颜色图像**不含 `SAMPLED`**，因此不能被着色器直接采样；若需要“把上一帧结果当纹理”，必须走离屏目标或额外拷贝。离屏目标颜色图像则显式包含 `SAMPLED`，因为后处理链要把它当纹理读。

### 6.5 共享模式与表面属性

图形队列族与呈现队列族相同用 `VK_SHARING_MODE_EXCLUSIVE`；不同则用 `CONCURRENT` 并把两个族索引写入 `queueFamilyIndexCount = 2`、`pQueueFamilyIndices = family_indices`（栈上数组，生命周期覆盖 `vkCreateSwapchainKHR` 调用）。本层不做队列族所有权转移，故不用 `EXCLUSIVE` + barrier 让渡。其余属性：`imageArrayLayers = 1`、`preTransform = capabilities.currentTransform`（不主动旋转）、`clipped = VK_TRUE`、合成模式由 `composite_alpha_select` 选择。

### 6.6 同步原语的归属与“每图像”语义

两类信号量都随交换链图像数分配，并与交换链一起重建（`swapchain_create` 内 `resize(actual_count)` 后逐张创建；析出/销毁/延迟释放都按同一集合处理）。

- 图像可用信号量：帧模块按 `acquire_cursor % image_available_count_get()` 轮转取用。
- 呈现完成信号量：按**交换链图像索引**取用（`render_finished_semaphore_get(image_index)`）。头注释给出安全性论证：同一信号量只会在同一张交换链图像被再次获取时复用，而那时上一次 present 必然已取走该信号量；帧栅栏只保证提交完成，不保证 present 已消费信号量，故不能按帧槽分配呈现完成信号量。

跨模块推论：在途帧数必须不超过图像可用信号量数量，门面在初始化末尾据此下调 `frame_overlap`。`swapchain_create` 建链后并不检查该约束，约束完全由上层维持。

### 6.7 深度模板附属：格式回退、仅用深度方面

深度格式按 `D32_SFLOAT` → `D32_SFLOAT_S8_UINT` → `D24_UNORM_S8_UINT` 依次检查 `optimalTilingFeatures` 是否含 `DEPTH_STENCIL_ATTACHMENT_BIT`，全部不可用则建链失败。三个候选中有两个带模板位，但本模块：

- 深度图像视图只取 `VK_IMAGE_ASPECT_DEPTH_BIT`，不含 `STENCIL`；
- 所有布局转换屏障的 `subresourceRange.aspectMask` 也只有 `DEPTH`；
- MSAA 深度同样只建 `ASPECT_DEPTH` 视图。

也就是说模板方面从未被使用、也未被显式布局转换。若将来启用模板测试，需要补模板方面的转换与视图（见 §附 待确认 4）。深度图像额外带 `SAMPLED` 用法（注释记为第二百五十六轮），用于 Hi-Z 的深度拷贝；交换链深度“每交换链图像一张”，随重建重建。

深度图像首次创建后执行一次 `depth_transition`（`UNDEFINED → DEPTH_ATTACHMENT_OPTIMAL`），此后帧间由帧链路以 `CLEAR` 复用，模块不再转换。该转换使用本模块自建的临时命令池 + 栅栏，不依赖帧模块，故 `build` 期间即可安全完成。

### 6.8 MSAA：采样数钳制、双份深度与切换路径

- 钳制：`sample_count_set` 只接受 2/4/8，其余一律 1；不查询设备 `sampleCounts`，设备能力校验由门面 `msaa_supported_max`（按颜色与深度格式的 `sampleCounts` 求交集）完成。
- 交换链侧附件：颜色（交换链格式，仅 `COLOR_ATTACHMENT`，作为解析源）与深度（深度格式，`DEPTH_STENCIL_ATTACHMENT | SAMPLED`，供深度解析与 Hi-Z）。**单采样深度仍然保留**，它是 MSAA 深度解析的目标（帧模块用 `msaa_depth_image_get` 写入解析结果，Hi-Z 读该图）。
- 离屏目标侧附件：颜色（目标颜色格式，仅 `COLOR_ATTACHMENT`）与深度（目标深度格式，仅 `DEPTH_STENCIL_ATTACHMENT`，不带 `SAMPLED`）；解析目标是记录里的单采样颜色图像，深度解析目标则是单采样深度图像（由帧链路执行，模块只提供句柄）。
- 初始化路径：门面先以采样数 1 建链（以便确定格式），再按设备能力择定采样数；若大于 1，则 `sample_count_set` → `destroy` → `build` 重建一次，属于一次性初始化开销。
- 运行时切换：门面先 `frames_wait`，再 `swapchain.sample_count_set(samples)` 并以**原尺寸**调用重建（尺寸不变也走重建，因为附件数量与采样状态变了），旧资源进延迟队列；随后 `render_target.sample_count_set(samples)` 原地重建“跟随默认采样数”的目标，再重建全部图形管线（采样数被烘焙进管线状态）。重建失败时门面把交换链采样数回退到旧值并中止，但已重建的离屏目标不回退（见 §附 待确认 5）。
- 交换链 MSAA 附件在 `msaa_resources_create` 末尾无条件调用 `depth_transition`；若单采样深度已在 `depth_resources_create` 中转换过，这里会以 `UNDEFINED` 旧布局再次转换（内容丢弃）。实现注释承认“单采样深度重复转入无害”，行为正确但重复劳动（见 §附 待确认 7）。

### 6.9 分级（mip）支持：本模块全部为单级

交换链与离屏目标的全部 `image_create` 调用都只传 `width/height/format/usage` 与（MSAA 时的）采样数，`mip_levels` 取 `Memory_Context::image_create` 默认值 1；`image_view_create` 亦取默认 `level_count = 1`、`base_mip_level = 0`。因此：

- 交换链图像与离屏颜色/深度图像都没有 mip 链，不存在逐级视图；
- 不存在 mip 生成（`vkCmdBlitImage` / 计算着色器降采样）路径；
- 需要多级的场景（Hi-Z 金字塔）由独立 Hi-Z 模块自建图像与逐级视图，不借用本模块的目标。

读回固定按 level 0 的完整子资源（`imageSubresource = {aspect, 0, 0, 1}`），与单级实现一致。

### 6.10 重建触发条件

交换链重建在快照内由门面三处触发：

1. **窗口尺寸变化**：`Renderer::render` 每帧调用 `platform.resized_consume()`；为真且宽高非 0 时调用 `swapchain_rebuild_deferred(width, height)`，并置本帧已重建标志。每帧最多重建一次（源码注释记为 K8）。
2. **表面失效或次优**：帧模块 `vkAcquireNextImageKHR` 返回 `VK_ERROR_OUT_OF_DATE_KHR` 或 `VK_SUBOPTIMAL_KHR` 时，不视为硬错误，而是置 `rebuild_needed_out = true`、跳过本帧录制与呈现并返回成功；门面在帧末若 `rebuild_needed && !rebuilt` 再调用一次 `swapchain_rebuild_deferred`。`VK_SUBOPTIMAL_KHR` 也触发重建，意味着“仍能呈现但已不理想”的状态会被主动纠正。
3. **MSAA 切换**：`Renderer::msaa_samples_set` 在 `frames_wait` 之后以当前 `extent` 调用同一重建入口，使 MSAA 附件按新采样数重建。

不触发的情况：窗口最小化 / 关闭请求时整帧挂起，`resized_consume` 即使为真也不重建；宽高为 0 时不重建（最小化防 0×0 建链，源码注释记为 K7）；首次建链走 `build` 而非 `rebuild`；初始化期切换 MSAA 走 `destroy` + `build`。

格式变更并非独立触发条件：每次重建都会重新 `format_select`，若驱动返回的首选格式变化，`format_get()` / `depth_format_get()` 随之变化，门面在重建后调用 `pipeline.pipeline_rebuild(...)` 让管线与新格式对齐（格式未变时该调用为空操作）。模块自身不检测、不通知格式变化。

### 6.11 无整帧停顿的重建与旧资源回收时序

重建不再 `vkDeviceWaitIdle`，而是把“可能仍被在途帧引用”的资源整体移交。精确时序：

1. `rebuild` 保存派生状态；
2. `swapchain_resources_extract(old)`：成员清零，`format` / `extent` / `color_transfer_src` / `depth_initialized` 复位；
3. `swapchain_create(w, h, old.swapchain)`：新链以旧链作 `oldSwapchain`，驱动可复用资源；
4. 成功：`old_out = std::move(old)`，返回真；
5. 门面 `swapchain_rebuild_deferred` 组装 `Deferred_Entry`，把 `old_out` 移入 `entry.resources`，调用 `frame.deferred_push(std::move(entry), frame.in_flight_count_get() + 1)`；
6. `deferred_push` 写入 `release_frame = frame_count + delay_frames`（当前帧号 + 在途帧数 + 1）；
7. 每个成功出帧路径在 `++frame_count` 之后调用 `deferred_flush()`，释放所有 `release_frame <= frame_count` 的条目；
8. 条目释放顺序：先经内存模块归还 `memory_resources`（若有），再归还旧深度视图/图像、旧 MSAA 深度视图/图像、旧 MSAA 颜色视图/图像，然后销毁旧图像视图、旧两类信号量，最后销毁旧交换链。旧 `images` 句柄不销毁（归交换链所有）。
9. 关闭期：帧模块 `destroy` 先 `vkDeviceWaitIdle`，再 `deferred_release_all()` 无条件释放全部残留条目，避免旧交换链附属资源（尤其深度图像与其内存）泄漏到内存模块销毁之后。

“在途帧数 + 1”的意义：当前帧可能已引用了旧交换链图像，且帧模块允许 `in_flight_count` 帧并行，故等到这些帧全部完成后再多留一帧余量。若帧循环停止（不再调用 `deferred_flush`），旧资源会一直驻留到关闭期，这是用内存峰值换“重建不卡顿”的取舍。

### 6.12 重建失败的回滚

`swapchain_create` 内部任一步失败时，可能已创建新交换链/视图/部分信号量/部分深度。`rebuild` 的处理是：

1. `swapchain_resources_destroy()` 清理半成品（含 `depth_resources_destroy` 与 `msaa_resources_destroy`）；
2. `swapchain_resources_restore(old)` 把旧资源移回成员；
3. 手工恢复 `format`、`depth_format`、`extent`、`depth_initialized`、`color_transfer_src`；
4. 返回假，`old_out` 不写出。

风险点：若新链已成功创建过（失败发生在后续取图像/建视图/建信号量/建附件阶段），旧链在 `vkCreateSwapchainKHR` 返回时即被驱动标记为退休（retired）。回滚后把退休链当作“仍可用”继续 acquire/present，与 Vulkan 规范语义存在冲突（见 §附 待确认 1）。当前实现把重建失败当作“本帧继续、下帧再试”，未再降级为“销毁重建”。

### 6.13 离屏目标的布局不变量

`Render_Target_Record` 头注释约定：颜色恒为 `SHADER_READ_ONLY_OPTIMAL`、深度恒为 `DEPTH_ATTACHMENT_OPTIMAL`。模块只在创建（含采样数重建）时用一次命令缓冲完成初始转换：

- 颜色：`UNDEFINED → SHADER_READ_ONLY`，`dstStage = FRAGMENT_SHADER`、`dstAccess = SHADER_READ`；
- 深度：`UNDEFINED → DEPTH_ATTACHMENT`，`dstStage = EARLY|LATE_FRAGMENT_TESTS`、`dstAccess = DEPTH_STENCIL_ATTACHMENT_WRITE`；
- MSAA 颜色：`UNDEFINED → COLOR_ATTACHMENT`，`dstAccess = COLOR_ATTACHMENT_WRITE`；
- MSAA 深度：`UNDEFINED → DEPTH_ATTACHMENT`。

四条屏障共用一次 `vkCmdPipelineBarrier`（`srcStage = TOP_OF_PIPE`，`dstStage` 取并集），一次提交等待完成。之后“作附件写入时进入附件布局、退出时回到常态布局”由帧链路负责；模块不校验、也不修复运行期布局。因此任何绕过帧链路直接写目标的外部代码都会破坏该不变量。

### 6.14 句柄分配、槽复用与池化边界

- 句柄 `uint64_t`，0 无效，`handle = 下标 + 1`；`target_create` 优先复用**第一个 `valid == false` 的槽**，无空槽才 `push_back`。
- `records` 只在 `destroy()` 时 `clear()`，`target_destroy` / `target_detach` 只把槽复位为空记录，向量不收缩。因此句柄值会被复用：先销毁句柄 3、再创建新目标，新目标可能再次得到句柄 3。外部若保留过期句柄，可能误指向新资源；模块不提供“句柄代际”校验（见 §六 6.15 与 §附 待确认 6）。
- 所谓“池化”仅指**句柄槽位复用**：每次创建仍完整分配新图像与新视图，模块不缓存、不复用图像对象，显存回收完全交给 VMA（`image_destroy`）。
- 门面的公开销毁入口 `Renderer::render_target_destroy` 不直接调用 `target_destroy`，而是 `target_detach` 摘出记录，再把颜色、深度、MSAA 颜色、MSAA 深度分别组装成 `Deferred_Memory_Resource`（图像 + 内存 + 视图），压入帧延迟队列；槽立即变为可复用，但显存释放推迟到在途帧用尽。这样既避免“销毁仍被在途命令缓冲/描述符集引用的图像”，又让句柄尽快可复用。门面内部仍有直接调用 `target_destroy` 的路径（SSAA 场景/解析目标重建时先销毁旧目标），这些路径依赖调用点自身的帧同步前提。关闭路径由 `Render_Target_Context::destroy`（在帧模块销毁之后、内存模块销毁之前）直接销毁全部记录。

### 6.15 一次性命令资源与同步风格

- 交换链侧没有跨调用复用的命令池：`depth_transition` 每次新建 `TRANSIENT` 池与栅栏，用完即销毁。
- 离屏目标侧复用一对 `transient_pool` + `transient_fence`（`transient_resources_ensure` 首次创建），每次操作先 `vkResetCommandPool(device, pool, 0)` 回收上次命令缓冲，再分配一条主命令缓冲；提交前 `vkResetFences`，提交后 `vkWaitForFences(UINT64_MAX)`。
- 两条路径都是“录制 → 提交到图形队列 → 阻塞等待”，不引入信号量、不依赖帧槽；因此它们可以在 `build` / `target_create` 期间同步完成，但也意味着在渲染线程上会引入一次 GPU 往返停顿（仅在创建/重建/读回等低频路径发生）。
- 失败传播：所有 Vulkan 调用经 `vk_result_check(结果, "模块:: 动作")` 统一判定并记录日志；不抛异常。部分失败不就地回滚，交由上层（`build` 的 `destroy`、`rebuild` 的回滚分支、`target_create` 的 `record_resources_destroy`）清理。

### 6.16 读回细节与性能取舍

- 颜色读回总是“整幅或子区域 → 主机可见暂存缓冲（`TRANSFER_DST`）→ `buffer_read` 拷贝 → 销毁缓冲”，每次调用新建暂存缓冲，不做缓冲池；容量校验单位为字节。
- 深度读回同样的暂存缓冲流程，但容量单位为元素个数（内部换算 `byte_size = value_count * 4`）；屏障只在 `DEPTH` 方面往返，`srcStage = LATE_FRAGMENT_TESTS`、`dstStage = TRANSFER`，回程 `TRANSFER → EARLY_FRAGMENT_TESTS`。
- 子区域读回使用 `bufferRowLength = 0`、`bufferImageHeight = 0`（紧排、无行填充），输出尺寸回填的是**区域尺寸**而非目标尺寸。
- MSAA 目标的颜色读回读到的是单采样颜色图像（若帧链路尚未解析则得到旧内容）；深度读回在 MSAA 下直接拒绝并打印错误，避免返回“清屏值”误导上层。
- 门面四个读回入口都先 `frame.frames_wait()`：读回是同步、跨帧的操作，必须等尽在途帧，否则会与仍在执行的写入或采样竞争。

### 6.17 错误处理策略汇总

| 场景 | 行为 |
| --- | --- |
| 前置句柄/内存缺失（`build`、`target_create`、`target_readback_depth_region`） | 错误日志 + 返回假，不创建任何对象。 |
| 尺寸为 0（`build` / `rebuild`） | 警告日志 + 返回假；最小化挂起由上层处理。 |
| 表面不支持颜色附件用法 | 错误日志 + 建链失败 + 返回假。 |
| 表面不支持传输源用法 | 警告日志 + 继续建链 + `color_transfer_src = false`。 |
| 无可用深度格式 | 错误日志 + 建链失败 + 返回假。 |
| 无可用表面格式 | 错误日志 + 返回假。 |
| 呈现模式查询失败 | 静默兜底 FIFO（不打印）。 |
| 句柄越界/槽已空（查询、销毁、分离） | 静默返回假或直接返回，不打印；出参先复位。 |
| 读回容量不足 / 子区域越界 | 错误日志 + 返回假（尺寸出参保持 0）。 |
| MSAA 下深度读回 | 错误日志 + 返回假。 |
| 采样数非 2/4/8 | 静默钳为 1，不告警。 |
| 重建失败 | 错误日志 + 回滚 + 返回假；门面只警告并继续本帧。 |

### 6.18 隐式约定（跨模块）

1. 调用 `build` 前必须已完成设备、平台表面、内存模块的构建；`build` 之后才能调用任何访问器。
2. 交换链 `sample_count_set` 必须在 `build` / `rebuild` 之前；重建不会自动沿用“上一次运行时设置的采样数”以外的变更。
3. `rebuild` 成功后必须读取新的 `format_get()` / `depth_format_get()` / `extent_get()`，并据此重建管线（门面已做）。
4. 交换链重建成功后，旧图像视图/信号量/深度/MSAA 资源不可再使用；它们已被移交，模块成员只指向新资源。
5. 离屏目标颜色格式必须与将要合成到的交换链格式兼容（门面直接传交换链格式）；模块不做兼容性校验。
6. 采样数切换、读回、运行时销毁目标前必须 `frames_wait`；模块内部不等待在途帧（`destroy` 也不等）。
7. 目标句柄会复用，外部不得在 `target_destroy` / `target_detach` 后继续使用旧句柄。
8. 模块输出的都是裸 Vulkan 句柄，不保证其生命周期超过本上下文；上下文销毁后句柄全部失效（延迟销毁中的旧资源除外，其所有权已移交）。

## 七、模块运行链路详例

### 7.1 链路一：交换链首次创建（Renderer 初始化）

调用方与逐步动作：

1. 平台模块已完成实例/表面/窗口创建；设备模块已完成物理设备与逻辑设备选择，暴露 `physical_device_get()`、`device_get()`、`graphics_family_get()`、`present_family_get()`。
2. `Renderer::initialize` 取窗口客户区尺寸：`platform.window_size_get(swapchain_width, swapchain_height)`；为 0 时回退配置宽高。
3. `swapchain.sample_count_set(1)`，保证首建不带 MSAA 附件（格式尚未确定，无法验证采样支持）。
4. `swapchain.build(physical_device, memory, device, surface, graphics_family, present_family, width, height, vsync)`
   - `Swapchain_Context::build` 校验句柄与 `memory.valid()`、宽高非 0，记录成员；
   - `swapchain_create(w, h, VK_NULL_HANDLE)`：
     - `capabilities_query` → `vkGetPhysicalDeviceSurfaceCapabilitiesKHR`；
     - `format_select` → 两段式 `vkGetPhysicalDeviceSurfaceFormatsKHR`，按首选序列选格式；
     - `present_mode_select(vsync)` → 两段式 `vkGetPhysicalDeviceSurfacePresentModesKHR`，FIFO/MAILBOX；
     - `extent_select(capabilities, w, h)` → `currentExtent` 或夹取；
     - 计算 `image_count = minImageCount + 1`（受 `maxImageCount` 限制）；
     - 用法求交、`color_transfer_src` 记录、合成模式与共享模式选择；
     - `vkCreateSwapchainKHR`；
     - `vkGetSwapchainImagesKHR`（两次：数量、句柄）→ `images`；
     - 逐张 `vkCreateImageView`（2D、单层、单级、`ASPECT_COLOR`）；
     - `image_available_semaphores` / `render_finished_semaphores` 各 `resize(actual_count)` 并逐张创建；
     - `depth_resources_create`：`depth_format_select` → 逐张 `memory->image_create`（`DEPTH_STENCIL_ATTACHMENT | SAMPLED`）与 `image_view_create`（`ASPECT_DEPTH`）→ 首次 `depth_transition`；
     - `msaa_resources_create`：采样数 1 时直接返回真。
5. `build` 成功后打印 info（图像数、范围）。
6. 门面择定 MSAA：`msaa_supported_max(physical_device, format_get(), depth_format_get(), requested)`；若 `chosen > 1`：`sample_count_set(chosen)` → `destroy()`（`vkDeviceWaitIdle` + 释放全部首建资源）→ 再次 `build(...)`（此时 `swapchain_create` 会多建 MSAA 颜色/深度附件，并在末尾再次执行深度转换）。`msaa_samples = sample_count_get()`。
7. 门面取 `image_available_count_get()`，若配置的 `frame_overlap` 超限则下调并告警。
8. `frame.build(swapchain, memory, frame_overlap)` 之后，帧模块按交换链图像数建立对应的帧槽与信号量使用策略。

结果：窗口上有一组可 acquire/present 的交换链图像；每张图像配有视图、1 个图像可用信号量、1 个呈现完成信号量、1 张深度图像（可选 1 套 MSAA 颜色/深度）；深度已完成初始布局转换。

### 7.2 链路二：交换链重建（含等待空闲与延迟销毁）

入口 A（窗口尺寸变化）：

1. `Renderer::render` 每帧读 `platform.window_size_get(width, height)`；
2. `platform.resized_consume()` 为真且宽高非 0 → `Impl::swapchain_rebuild_deferred(width, height)`；
3. 内部 `swapchain.rebuild(width, height, old_resources)`：
   - 校验 `device`/`surface`、宽高非 0；
   - 保存 `format` / `depth_format` / `extent` / `depth_initialized` / `color_transfer_src`；
   - `swapchain_resources_extract(old)`（不清 `depth_format`）；
   - `swapchain_create(w, h, old.swapchain)`：重查能力与格式/模式/范围，新链以旧链作 `oldSwapchain`；随后建新视图、新两类信号量、新深度、新 MSAA 附件；
   - 成功 → `old_out = std::move(old)`；失败 → `swapchain_resources_destroy()` + `swapchain_resources_restore(old)` + 手工恢复派生状态 + 返回假（`old_out` 不写出）；
4. 门面把 `old_resources` 移入 `Deferred_Entry`，`frame.deferred_push(std::move(entry), frame.in_flight_count_get() + 1)`；
5. 门面若 `hiz.valid()`，按新 `extent_get()` 与 `depth_format_get()` 调 `hiz.extent_set`；失败则 `hiz.destroy()` 并关闭 Hi-Z（不阻断出帧）；
6. 门面随后调 `pipeline.pipeline_rebuild(swapchain.format_get(), swapchain.depth_format_get(), msaa_samples)`；失败仅警告；
7. 门面刷新相机宽高比（`extent_get()`）；
8. 本帧继续渲染到新链；帧模块在本帧 `++frame_count` 后调用 `deferred_flush()`，若 `release_frame <= frame_count` 则释放旧资源（顺序见 §6.11）。

入口 B（表面过期/次优）：

1. 帧模块 `render`：`vkAcquireNextImageKHR(..., UINT64_MAX, image_available, VK_NULL_HANDLE, &image_index)`；
2. 返回 `VK_ERROR_OUT_OF_DATE_KHR` 或 `VK_SUBOPTIMAL_KHR` → `rebuild_needed_out = true`，跳过录制/提交/呈现，返回成功（本帧无输出）；
3. 门面在帧末若 `rebuild_needed && !rebuilt` → 同样进入 `swapchain_rebuild_deferred(width, height)`；
4. 之后的路径与入口 A 第 3 步起完全一致。

入口 C（MSAA 切换）：`frames_wait()` → `swapchain.sample_count_set(samples)` → 以当前 `extent` 调 `swapchain_rebuild_deferred` → `render_target.sample_count_set(samples)` → `pipeline.pipeline_rebuild`；重建失败则把交换链采样数回退并中止。

关键差异：整个重建路径**没有 `vkDeviceWaitIdle`**；只有 `destroy()`（关闭/初始化期重建）才等待设备空闲。旧资源销毁时间点由帧号判据决定，而不是重建时刻。

### 7.3 链路三：离屏渲染目标的创建与使用

创建：

1. 调用方 `Renderer::render_target_create(handle_out, width, height)`；
2. 门面校验 `impl != nullptr && initialized`，转交 `render_target.target_create(handle_out, width, height, swapchain.format_get(), swapchain.depth_format_get())`（第五参数省略，取默认 0 = 跟随上下文默认采样数）；
3. `Render_Target_Context::target_create`：
   - `handle_out = 0`；校验 `valid()`、宽高、两格式非 `UNDEFINED`；
   - `transient_resources_ensure()`（首次创建池与栅栏）；
   - 解析采样数：`follow_sample_count = (sample_count == 0)`，`record.sample_count = 0 ? 上下文默认值 : 传入值`，再钳到 1/2/4/8；
   - `memory->image_create(color, alloc, w, h, color_format, COLOR_ATTACHMENT|SAMPLED|TRANSFER_SRC)` → `image_view_create(color_view, ..., ASPECT_COLOR)`；
   - `memory->image_create(depth, alloc, w, h, depth_format, DEPTH_STENCIL_ATTACHMENT|TRANSFER_SRC|SAMPLED)` → `image_view_create(depth_view, ..., ASPECT_DEPTH)`；
   - `record_msaa_create`：采样数 > 1 时建 MSAA 颜色（仅 `COLOR_ATTACHMENT`）与 MSAA 深度（仅 `DEPTH_STENCIL_ATTACHMENT`）及视图；
   - `target_transition(record)`：一次命令缓冲完成颜色/深度（及 MSAA）初始转换，阻塞等待；
   - 写入第一个空槽或追加，`handle_out = 下标 + 1`，打印 info。
4. 任一步失败：错误日志 + `record_resources_destroy` + 返回假，句柄保持 0。

使用（同帧离屏 + 后处理呈现）：

1. 调用方通过 `Renderer::render_target_set(handle)` 或 `render_target_present_set` / `render_target_present_chain_set` 指定目标；
2. `Renderer::render` 在绘制项齐备后调 `render_target.target_get(present_target, color_image, color_view, depth_view, extent)` 与 `target_msaa_get(present_target, msaa_color_image, msaa_color_view, msaa_depth_view, sample_count)`；链式路径对 `present_extra` 中的每个中间目标同样调用这两组接口；若启用深度解析（`msaa_depth_resolve`）再调 `target_msaa_depth_image_get(present_target, msaa_depth_image)` 供帧模块把多重采样深度解析到单采样深度；景深等后处理阶段则经 `target_depth_get` 取深度图像与视图作为采样输入；
3. `frame.render_chain_present(swapchain, targets, ...)`：
   - `vkAcquireNextImageKHR` 取交换链图像与信号量；
   - 场景 pass 以目标颜色/深度（或 MSAA 附件）为渲染附件，退出时颜色转 `SHADER_READ_ONLY`；
   - 后处理 pass 以目标颜色视图（以及 `target_depth_get` 提供的深度视图，用于景深采样）为纹理输入；
   - 呈现 pass 写入交换链图像并 `vkQueuePresentKHR`；
4. 帧模块在提交后 `++frame_count` 并 `deferred_flush()`。

使用（读回）：

1. 调用方 `Renderer::render_target_readback*(handle, ...)`；
2. 门面先 `frame.frames_wait()`；
3. `target_readback` → `target_readback_impl`（整幅）或 `target_readback_region`（先做边界校验再转 `target_readback_impl`）；
4. `target_readback_impl`：建暂存缓冲 → 重置池/分配命令缓冲 → `SHADER_READ_ONLY → TRANSFER_SRC` → `vkCmdCopyImageToBuffer` → `TRANSFER_SRC → SHADER_READ_ONLY` → 提交等待 → `buffer_read` → 销毁暂存缓冲 → 回填区域尺寸；
5. 深度读回走 `target_readback_depth`（先 `target_extent_get` 得整幅）→ `target_readback_depth_region`（拒绝 MSAA、校验容量与边界）→ 同样的暂存缓冲流程，深度布局往返 `DEPTH_ATTACHMENT ↔ TRANSFER_SRC`。

销毁：

1. 调用方 `Renderer::render_target_destroy(handle)`；
2. 门面若该句柄是 `active_target` / `present_target` / `present_extra` 成员则先回落并清空引用；
3. `render_target.target_detach(handle, record)`：记录按值写出、槽立即复位；
4. 门面把颜色、深度、MSAA 颜色、MSAA 深度分别组装 `Deferred_Memory_Resource`，压入 `Deferred_Entry` 并 `frame.deferred_push`；
5. 后续某帧 `deferred_flush` 时经 `memory` 归还视图与图像/内存（见 §6.11 释放顺序）；
6. 关闭期：`frame.destroy()`（`vkDeviceWaitIdle` + `deferred_release_all`）→ `render_target.destroy()`（逐条直接归还剩余记录 + 销毁池/栅栏）→ `swapchain.destroy()` → `memory.destroy()`。

- **待确认 5**：`Render_Target_Context::sample_count_set` 在重建中途失败时把失败记录置 `valid = false` 并立即返回，已处理目标处于新采样数、未处理目标仍是旧值，且上下文默认 `sample_count` 已写成新值而不回滚；头注释要求调用方回退旧值重试，但门面 `Renderer::msaa_samples_set` 只打印警告后继续把 `impl->msaa_samples` 更新为新值。需要确认：门面失败路径是否应回退 `render_target.sample_count_set(previous)`，以及模块是否应提供“全或无”的重建语义。落点：`RenderTarget/渲染目标.h` 的 `sample_count_set` 注释、`RenderTarget/core/目标创建.cpp` 的 `sample_count_set`、`Renderer/core/渲染器.cpp` 的 `msaa_samples_set`。
- **待确认 6**：两个上下文的 `build` 都没有“已构建则先销毁”的保护。交换链重复 `build` 会直接覆盖 `swapchain`/`images`/信号量等成员，旧资源失去句柄而泄漏；`Swapchain_Context::destroy` 仍能释放新一组，但旧一组不可回收。`Render_Target_Context::build` 重复调用只覆盖设备/队列/内存指针，危害较小。同时 `target_create` 的空槽复用会让同一 `uint64_t` 句柄在销毁后指向新目标，模块无代际校验。需要确认：是否需要在 `build` 加“已构建返回假/先 `destroy`”的保护，以及句柄复用是否需要文档级约束（当前仅在 `Render_Target_Record`/`target_destroy` 注释中隐含）。落点：`Swapchain/core/交换链.cpp` 的 `build`、`RenderTarget/core/目标创建.cpp` 的 `build` 与 `target_create`。
