## 二、模块功能介绍

**帧模块（Frame）负责一帧的 Vulkan 侧落地。** 它按在途帧数持有帧槽（命令池、主命令缓冲、次级命令缓冲与其独占命令池、批量阴影缓冲、完成栅栏、两套时间戳查询池），负责「等栅栏 → 取图像 → 重置命令池 → 录制 → 提交 → 呈现 → 可选像素回读 → 推帧计数 → 冲刷延迟销毁」的完整闭包，并对外提供四类录制形态：交换链直通（`render`）、离屏单 pass（`render_to_target`）、阴影多目标单次提交（`render_to_targets_batch`）、场景目标＋N 级后处理同帧呈现（`render_chain_present`，`render_to_target_present` 为其单级薄封装）。帧模块还承担 GPU 时间戳的口径换算与环形读回、主机侧分段耗时统计、间接绘制命令的合并写入与延迟销毁队列。

**帧模块不负责交换链与内存本身。** 交换链图像、图像视图、深度/MSAA 附件以及「每交换链图像」的两类信号量归 `Swapchain_Context`；缓冲/图像的创建销毁归 `Memory_Context`；并行录制线程归 `Thread_Pool`；计算管线调度归 `Compute_Context`。帧模块只持有裸 Vulkan/VMA 句柄与指向上述对象的引用，不反向依赖它们的实现细节（`帧上下文.h` 只包含 `交换链.h`、`线程池.h` 与 Vulkan/VMA 头）。

**场景模块（Scene）负责把「中立场景描述」翻译成渲染层可消费的形态。** 其中 `场景数据.h` 只做转发（`Camera_Data` / `Light_Data` / `Fog_Data` / `Point_Light_State` / `Scene_Data` 的唯一定义在系统层），`光源数据.h` 提供与 Vulkan 无关的 80 字节 `Light_Record` 契约以及旧前向路径的 32 盏截断口径，`相机.h/.cpp` 提供视图×投影、屏幕互投影与 AABB 保守可见判定，`场景装配.h/.cpp` 负责关卡文本/场景清单 → 网格与材质资源创建 → 对象摆放表 → 逐段绘制登记，并在任一步失败时整体回退。

**Cluster 与 HiZ 是两条「CPU 参考 + GPU 落地」的双轨管线。** Cluster 的五个自由函数给出与计算着色器同口径的分簇计数/前缀和/偏移/列表写入实现，用于与 GPU 结果对数；HiZ 的 `遮挡测试.h` 给出与剔除着色器同口径的 CPU 遮挡判定，`HiZ.h/.cpp` 负责逐帧槽深度历史与 mip 金字塔的真实资源与生成录制。

**Particle 把粒子模拟状态的所有权留在渲染层。** `Particle_Host` 自持 `Particle_System` 池并在构造/容量变更/显式 `bind()` 时把状态数组交给渲染器；`粒子GPU推进.cpp` 实现常驻模式下的 GPU 发射与推进（活跃计数回读、环形写指针、前后缓冲交换、力场上传、死亡结算）。

**Input 负责把 SDL 事件收敛为「每帧一份不可变快照」。** `event_feed` 只累积待生效状态与边沿，`frame_advance` 一次性锁存为 `Input_Frame` 并清空单帧量，`frame_get` 返回引用供 UI 命中测试与渲染层内部消费；`输入快照.h` 保持零 SDL/Vulkan 类型，SDL3 只出现在公共扩展头 `输入聚合.h`。

**关键约束（对外职责边界）：** ① 帧槽数量严格等于 `frame_overlap`，与交换链图像数无关；② 录制路径的选择由调用方决定，帧模块不做策略判断，只在参数不完整时返回假并记日志；③ 所有 Vulkan 类型只出现在本模块内部头（`帧上下文.h`、`HiZ.h`）与实现文件，公共面（`相机.h`、`光源数据.h`、`簇划分.h`、`遮挡测试.h`、`输入快照.h`、`场景装配.h`）不含 Vulkan；④ 场景语义类型的唯一定义在系统层，渲染层的 `场景数据.h` 只是转发。

#### 3.1.5 `Frame_Render_Target`（渲染目标附件集合）

```cpp
struct Frame_Render_Target
{
    VkImage color_image = VK_NULL_HANDLE;       // 颜色图像（亦作解析目标与回读来源）
    VkImageView color_view = VK_NULL_HANDLE;    // 颜色视图
    VkImageView depth_view = VK_NULL_HANDLE;    // 深度视图（MSAA 时为单采样深度）
    VkImage depth_image = VK_NULL_HANDLE;       // 深度句柄（后处理深度类阶段转换用）
    VkImage msaa_color_image = VK_NULL_HANDLE;  // MSAA 颜色图像
    VkImageView msaa_color_view = VK_NULL_HANDLE;
    VkImageView msaa_depth_view = VK_NULL_HANDLE;
    VkImage msaa_depth_image = VK_NULL_HANDLE;  // MSAA 深度图像（开启深度解析时非空）
    uint32_t sample_count = 1;                  // 采样数
    VkFormat color_format = VK_FORMAT_UNDEFINED; // 供次级缓冲继承信息使用
    VkFormat depth_format = VK_FORMAT_UNDEFINED;
    VkExtent2D extent = { 0, 0 };               // 渲染范围
    VkRect2D viewport_rect = { { 0, 0 }, { 0, 0 } }; // 子视口（宽或高为 0 = 整幅）
    bool render_area_from_viewport = false;     // 为真时 renderArea 收缩到 viewport_rect
};
```

布局约定（实现按此假设）：颜色进入时须为 `VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL`，深度进入时恒为 `VK_IMAGE_LAYOUT_DEPTH_ATTACHMENT_OPTIMAL`。

#### 3.1.6 两个回调结构与回读请求

```cpp
struct Frame_Ui_Callback
{
    void (*fn)(VkCommandBuffer command_buffer, void* user_data) = nullptr;
    void* user_data = nullptr;
};

struct Frame_Post_Scene_Callback
{
    void (*fn)(VkCommandBuffer command_buffer, VkImage depth_image, VkImageView depth_view,

struct Frame_Readback_Request
{
    uint8_t* pixels = nullptr;      // 为空表示本帧不回读
    VkDeviceSize capacity = 0;      // 须不小于 宽 × 高 × 4
    uint32_t width = 0;             // 回填

    VkDeviceSize bytes = 0;         // 回填

```

`Frame_Ui_Callback::fn` 的调用位置：单采样时在场景动态渲染通道内、`vkCmdEndRendering` 之前；多采样时在解析完成后另起的单采样 UI 通道内；后处理链路径则在**末级后处理之后**的交换链图像 UI 通道内（详见 §6.1）。

### 5.2 所有权与借用关系

```
上层门面（Renderer / Impl，见 渲染器 模块文档）
   │  调用 render / render_to_target / render_to_targets_batch /
   │      render_to_target_present / render_chain_present / slot_wait / frames_wait
   ▼
Frame_Context
   ├─ owns ── std::vector<Frame_Slot> slots        数量严格 = frame_overlap
   │             ├─ command_pool ── command_buffer（PRIMARY，主线程独占）
   │             ├─ secondary_pools[i] ── secondary_buffers[i]（SECONDARY，第 i 段工作线程独占）
   │             ├─ batch_buffers[0..N-2]（PRIMARY，主线程，批量阴影第 1..N-1 段）
   │             ├─ in_flight_fence（每槽一个，主机等待/GPU 信号）
   │             ├─ timestamp_pool（4 查询）＋ timestamp_written
   │             ├─ shadow_timestamp_pool（2 查询）＋ shadow_timestamp_written
   │             └─ indirect_buffer / indirect_mapped / indirect_capacity（每槽一份）
   ├─ owns ── readback_buffer / readback_alloc / readback_size（单份，跨槽复用）
   ├─ owns ── deferred_entries（旧交换链与旧内存资源队列）
   ├─ borrows ── Swapchain_Context（图像/视图/深度/MSAA/每图像信号量）
   ├─ borrows ── Memory_Context（回读缓冲、延迟资源归还）
   ├─ borrows ── Thread_Pool（并行段录制）
   └─ borrows ── 调用方持有的 items / targets / post_items 数组（只读，批量阴影除外）
```

`Frame_Context` 对 `Swapchain_Context` / `Memory_Context` / `Thread_Pool` 只持引用或指针，不参与它们的创建与销毁顺序；`destroy()` 明确要求先于内存模块销毁完成（`readback_buffer_destroy` 与 `deferred_release_all` 都在 `destroy()` 内、且在 `memory` 指针被清空之前）。

`HiZ_Context` 与 `Frame_Context` 无直接引用关系：两者由门面分别持有，唯一交汇点是 `Frame_Post_Scene_Callback`（门面把 `hiz_post_scene_entry` 作为回调传入帧录制路径）。

### 5.3 帧槽资源生命周期图（帧槽 → 命令缓冲 → 提交/呈现 → 延迟销毁）

```
build()
  └─ frame_slot_create × frame_overlap
        ├─ vkCreateCommandPool（graphics_family）
        ├─ vkAllocateCommandBuffers(PRIMARY, 1)  → command_buffer
        ├─ vkCreateFence(SIGNALED)               → in_flight_fence
        └─ [能力可用时] 两个 VkQueryPool（4 / 2 查询）

   ┌─────────────────────────── 每帧（槽 k = frame_count % frame_overlap） ───────────────────────────┐
   │ 1  Frame_Slot& slot = slots[k]                                                                    │
   │ 2  slot_fence_wait(slot)         // 上一轮（第 N−overlap 帧）的提交已完成                          │
   │ 3  gpu_timestamp_read(slot)      // 上一轮 4 个时间戳此时可读（首轮因 timestamp_written 跳过）      │
   │ 4  [屏内] acquire_cursor → image_available；vkAcquireNextImageKHR                                  │
   │       ├─ 过期 / 次优 → rebuild_needed_out = true，直接返回（栅栏保持已发出）                       │
   │       └─ 成功 → ++acquire_cursor                                                                  │
   │ 5  vkResetFences（仅在 acquire 成功后；避免提前返回后下一帧死等）                                  │
   │ 6  frame_slot_pools_reset        // 主池 + 全部次级池；池内缓冲内容一并失效但句柄仍可用            │
   │ 7  [可选] readback_buffer_ensure(宽×高×4)                                                          │
   │ 8  parallel_plan(...)            // 段数 0 = 单线程；> 1 = 追加/复用次级池与次级缓冲               │
   │ 9  command_record*               // 录制进 slot.command_buffer（批量路径另用 batch_buffers）        │
   │10  vkQueueSubmit2(graphics_queue, …, slot.in_flight_fence)                                        │
   │       └─ [屏内] wait image_available@COLOR_ATTACHMENT_OUTPUT / signal render_finished@ALL_COMMANDS │
   │11  [屏内] vkQueuePresentKHR(present_queue, wait render_finished[image_index])                      │
   │12  [可选] readback_read → vkWaitForFences → memory->buffer_read                                    │
   │13  slot.timestamp_written = true（阴影路径为 shadow_timestamp_written）                            │
   │14  ++frame_count ; deferred_flush()                                                                │
   └──────────────────────────────────────────────────────────────────────────────────────────────────┘

destroy()
  └─ vkDeviceWaitIdle
       ├─ frame_slot_destroy × N（查询池 → 栅栏 → 主池（连带主缓冲）→ 次级池（连带次级缓冲））
       ├─ readback_buffer_destroy（经内存模块归还）
       └─ deferred_release_all（无视帧号，直接释放全部残留条目）
```

**同步原语归属（实现口径）：**

| 原语 | 归属粒度 | 数量 | 谁创建/销毁 |
| --- | --- | --- | --- |
| `in_flight_fence` | 每帧槽 | `frame_overlap` | 帧槽创建 / 帧槽销毁 |
| `image_available` 信号量 | 每交换链图像 | 交换链图像数 | 交换链模块（帧只按 `acquire_cursor % count` 取用） |
| `render_finished` 信号量 | 每交换链图像 | 交换链图像数 | 交换链模块（帧按 `image_index` 取用） |
| `command_pool` | 每帧槽（主） | `frame_overlap` | 帧槽创建 / 销毁 |
| `secondary_pools[i]` | 每段（次级） | 按需增长，≤ `parallel_max_segments` | `secondary_buffers_ensure` 追加；帧槽销毁统一回收 |
| 线程池任务 | 帧内一次性 | 无跨帧残留 | `Thread_Pool::ranges_run` 同步阻塞至全部块完成 |

**多帧并行录制的同步原语（实现事实）：** ① 主命令缓冲只由主线程录制（`command_record*` 全在主线程）；② 并行段由 `thread_pool->ranges_run(segment_count, 1, body)` 分派，每段由单一工作线程完整录制（`vkBeginCommandBuffer` → `vkCmdBeginRendering` → `items_record` → `vkEndCommandBuffer`），因此每段必须独占一个 `VkCommandPool`（`secondary_pools[i]`），否则校验层报 THREADING ERROR；③ 段间无共享写入：项区间按 `segment * item_count / segment_count` 均分，统计写入 `parallel_counts[segment]` 各自一格；④ 主线程在 `ranges_run` 返回后才 `vkCmdExecuteCommands`，故 GPU 执行顺序与单线程一致；⑤ 并行只在场景 pass 生效，`items_record` 的间接合并路径在 `active_secondary_count > 1` 时整体关闭（两者互斥）。

### 5.4 场景/Cluster/HiZ/Particle/Input 的架构位置

- **Scene**：`相机.h/.cpp` 是纯算法（无 Vulkan、无堆分配）；`光源数据.h` 是纯契约；`场景装配.h/.cpp` 是唯一触碰 `Renderer` 门面的文件（资源创建与绘制登记），因此它是「渲染层资源生命周期」与「系统层中立描述」之间的适配层。
- **Cluster**：`簇划分.h` 只依赖 `光源数据.h`，不依赖相机与 Vulkan；`core/簇划分.cpp` 内四个匿名命名空间小工具承载全部矩阵/索引细节。CPU 参考与 GPU 着色器共享同一套网格下标记法与覆盖口径（保守上界）。
- **HiZ**：`HiZ.h` 持 Vulkan/VMA 类型（层内实现细节头）；`遮挡测试.h` 完全 Vulkan-free。两者通过「金字塔级视图 + 采样器」在门面层汇合，`HiZ_Context` 自身不做遮挡判定。
- **Particle**：`粒子宿主.h` 内联全部逻辑，只依赖 `渲染器.h` 与 `粒子系统.h`；`粒子GPU推进.cpp` 直接访问 `Renderer::Impl` 私有字段（`renderer.impl->…`），是层内授权而非公共接口。
- **Input**：`输入快照.h` 是纯数据结构（含少量内联查询函数）；`输入聚合.h` 承担 SDL3 边界；实现被拆为「事件适配」与「帧锁存」两个 `.cpp`，前者只写待生效量，后者只做锁存与清空。

**6.1.1 `command_record`（交换链直通）**

```

2  [时间戳池非空] vkCmdResetQueryPool(0..3) + WriteTimestamp(TOP_OF_PIPE, 0)
3  indirect_command_sync（批内含 gpu_indirect 项才插屏障）
4  颜色屏障：UNDEFINED → COLOR_ATTACHMENT_OPTIMAL
     srcStage=COLOR_ATTACHMENT_OUTPUT / srcAccess=0（同步由 acquire 信号量承担）

     vkCmdBeginRendering → SetViewport / SetScissor → items_record

   否则
     颜色 → PRESENT_SRC（dstStage=BOTTOM_OF_PIPE, dstAccess=0）
11 [时间戳池] WriteTimestamp(BOTTOM_OF_PIPE, 3)
12 vkEndCommandBuffer
```

**6.1.3 `command_record_chain_present`（场景 ＋ N 级后处理）**

```
1  vkBeginCommandBuffer
2  [时间戳池] ResetQueryPool(0..3) + WriteTimestamp(TOP_OF_PIPE, 0)
3  indirect_command_sync（只扫场景 items）
4  场景目标颜色：SHADER_READ_ONLY → COLOR_ATTACHMENT
5  [MSAA] 场景 MSAA 颜色：UNDEFINED → COLOR_ATTACHMENT
6  [MSAA 深度解析就绪] 场景 MSAA 深度：UNDEFINED → DEPTH_ATTACHMENT
7  parallel 或单线程录制场景 pass（不出 UI：链路径传 nullptr）
8  WriteTimestamp(BOTTOM_OF_PIPE, 1)  → 场景结束
9  场景目标颜色：COLOR_ATTACHMENT → SHADER_READ_ONLY
10 [场景深度非空] 深度：DEPTH_ATTACHMENT → SHADER_READ_ONLY
11 逐级后处理（stage = 0..post_count-1）：
     a 宿布局转换：末级交换链 UNDEFINED → COLOR_ATTACHMENT；非末级中间目标 SHADER_READ_ONLY → COLOR_ATTACHMENT
     b [本级采样数 > 1] 宿 MSAA 颜色：UNDEFINED → COLOR_ATTACHMENT
     c 组装 16 个浮点的推送块：源宽/高、宿宽/高、post_params、post_color、post_extra
        push_constant_offset = 80；size = post_extra_enabled ? 64 : 48 字节
     d vkCmdBeginRendering（清屏）→ SetViewport/SetScissor（按宿范围）→ items_record(单级后处理项)
     e vkCmdEndRendering
     f [末级且给了 UI] ui_pass_record（交换链图像，UI 不吃后处理）
     g 末级：readback ? 颜色→TRANSFER_SRC→拷贝→PRESENT_SRC : 颜色→PRESENT_SRC
        非末级：宿颜色 → SHADER_READ_ONLY（供下一级采样）
12 WriteTimestamp(BOTTOM_OF_PIPE, 2) → 后处理结束
13 [场景深度非空] 深度：SHADER_READ_ONLY → DEPTH_ATTACHMENT（供下一帧重新挂载）
14 WriteTimestamp(BOTTOM_OF_PIPE, 3)
15 vkEndCommandBuffer
```

顺序上的三条硬约束：① `vkCmdResetQueryPool` 必须在任何渲染通道之外；② `post_scene` 回调必须在场景通道 `vkCmdEndRendering` 之后（它要在通道外做布局往返）；③ 像素回读的布局转换必须发生在所有颜色写入之后、呈现布局转换之前。

### 6.2 屏内 / 屏外通道拆分

| 维度 | `render`（屏内直通） | `render_to_target`（屏外单 pass） | `render_to_targets_batch`（屏外多 pass 阴影） | `render_chain_present` / `render_to_target_present`（屏内多 pass） |
| --- | --- | --- | --- | --- |
| 取交换链图像 | 是 | 否 | 否 | 是 |
| 呈现 | 是 | 否 | 否 | 是 |
| 提交方式 | `vkQueueSubmit2` + 两信号量 + 栅栏 | 仅栅栏 | 仅栅栏（一次提交全部段） | `vkQueueSubmit2` + 两信号量 + 栅栏 |
| 颜色进入布局 | `UNDEFINED` | `SHADER_READ_ONLY` | `SHADER_READ_ONLY` | 场景目标 `SHADER_READ_ONLY`；交换链 `UNDEFINED` |
| 颜色退出布局 | `PRESENT_SRC`（或经 `TRANSFER_SRC`） | `SHADER_READ_ONLY`（或经 `TRANSFER_SRC`） | 同左 | 中间目标 `SHADER_READ_ONLY`；交换链 `PRESENT_SRC` |
| 后处理 | 无（`last_post_stages = 0`） | 无（0） | 无（0） | 有（`post_count`） |
| UI 回调 | 支持（单采样在场景通道内、MSAA 在解析后单通道） | 支持（同左） | 不支持（恒传 `nullptr`） | 支持（末级后处理之后的交换链 UI 通道） |
| 像素回读来源 | 交换链颜色图像 | 目标颜色图像 | 不支持 | 最终交换链颜色图像 |
| 时间戳池 | 主 4 查询池 | `shadow_pass ? 阴影 2 查询池 : 主 4 查询池` | 阴影 2 查询池（首段起点 / 末段终点） | 主 4 查询池 |
| 间接绘制 | 可用（单线程时） | 可用（`shadow_pass` 强制关闭） | 恒关闭 | 可用（单线程时） |
| 并行场景录制 | 支持 | 支持 | 不适用（曲面为多段独立 pass） | 支持 |
| `items` 是否被改写 | 否 | 否 | 是（`push_constants` 被逐段覆盖） | 否 |

拆分理由（实现事实）：屏内路径必须处理「图像获取失败 → 不重置栅栏」与「呈现同步」，屏外路径不需要信号量；批量阴影路径共用同一帧槽命令池但需要多条 `PRIMARY` 缓冲与跨缓冲写后写屏障，故单独建模；链路径把场景与后处理放在同一命令缓冲内，以避免跨帧中间目标与额外的提交。

### 6.3 HiZ 遮挡剔除的接入点

**资源侧（本模块）：** `HiZ_Context` 逐帧槽各建一份 `R32_SFLOAT` 深度历史（`STORAGE | SAMPLED | TRANSFER_DST`，颜色面）与一张带完整 mip 链的金字塔（`STORAGE | SAMPLED`），另建 `mip` 逐级视图与完整链视图、一个最近邻 + 钳边 + 点 mip 采样器。级数 `level_count_from` 自 1 级逐级折半到 1×1 或 12 级。

**录制接入点：** `post_scene` 回调。三种录制路径的触发位置分别见 §6.1；门面把 `hiz_post_scene_entry` 作为 `Frame_Post_Scene_Callback::fn` 传入（快照中门面仅在 `hiz_enabled && hiz.valid()` 时挂接）。该回调收到「本次场景以单采样写出的深度图像与视图 + 范围」，因此：
- 单采样直接可用；
- 多采样时必须已开启深度解析（`msaa_depth_image` / `msaa_depth_view` 就绪），否则该路径不触发（`command_record` 的判定用 `msaa_depth_image`，`command_record_target` 用 `msaa_depth_view`，字段不一致见【待确认：7】）。

**`pyramid_generate` 的命令序列：** 场景深度 `DEPTH_ATTACHMENT → SHADER_READ_ONLY`（`LATE_FRAGMENT_TESTS/DEPTH_STENCIL_WRITE` → `COMPUTE/SHADER_READ`）→ 历史图像 `UNDEFINED → GENERAL`（存储写）→ 绑定采样器与历史存储 → 深度拷贝 compute 调度（8×8 工作组）→ `ComputeToCompute` 屏障 → 逐级：该级 mip `UNDEFINED → GENERAL`（存储写）、源为历史（第 0 级）或上一级视图、调度降采样 compute → `ComputeToCompute` 屏障 → 场景深度恢复 `DEPTH_ATTACHMENT` → 历史转为 `SHADER_READ_ONLY` → `history_valid = true`。末级仍生成（源码注释记录「曾尝试跳过末级导致采样上限级覆盖退化并误剔」）。

**消费侧（门面，非本模块）：** 剔除调度前判定「开关开启 + 资源有效 + `history_valid(last_hiz_slot)` + 完整链视图非空 + 采样器非空」，满足则把剔除参数 `hi_z = (宽, 高, 级数, 1)`、把计算帧槽切到最近生成槽并把金字塔全链视图 + 深度采样器绑到采样器位；首帧无历史自动跳过。CPU 参考 `hiz_occlusion_test` 与之同口径：覆盖纹素取**最大**远面深度、对象最近深度严格大于该值 + `HIZ_OCCLUSION_BIAS` 才剔除、矩形外扩 `HIZ_RECT_DILATE_PIXELS`、跨近平面一律可见。

**历史语义：** 每帧槽各一份历史 = 该槽上一次使用时的场景深度；双在途帧槽下约为两帧前。交换链重建 / 尺寸变化会重建全部槽并把 `history_valid` 清零。

### 6.4 簇（Cluster）前向光照的数据组织

**记录层：** `Light_Record` 固定 80 字节，四分量排布 `pos_radius`（x, y, z, radius）、`color_intensity`（r, g, b, intensity）、`direction`（x, y, z, 0）、`cone`（cos_inner, cos_outer, attenuation, specular），尾随 `shininess` / `type` / `flags`（bit0 = 有效）/ `reserved`。容量常量 `LIGHT_RECORD_CAPACITY = 1024`、`LIGHT_RECORD_BYTES = 80`、`LIGHT_LEGACY_MAX = 32`。`light_effective_count(light_count, cluster_enabled)`：关闭 Cluster 时截断到 32，开启时截断到 1024。

**网格层：** 默认 16 × 9 × 24 = 3456 簇；`cluster_grid_clamp` 各轴钳 1..64 并在总数 > 4096 时逐步收缩 z。x 为屏幕 X、y 为屏幕 Y、z 为近远平面间线性视图深度。线性下标 `(z * y + y) * x + x`。

**覆盖口径（CPU 参考，与 GPU 计数/列表着色器同口径）：**
1. 只处理 `flags & 1` 为真的记录；
2. 方向光对**全部簇**计数 / 写入索引；
3. 点光与聚光按包围球：球心投影到裁剪空间；`w > 1e-6` 时按 `dv = radius / (distance · tan(fov/2))`、`du = dv / aspect` 得到屏幕矩形，深度区间 `[distance − radius, distance + radius]`；
4. 跨近平面（`w ≤ 1e-6` 或 `z_low ≤ near`）退化为「整屏 + 全部深度」；
5. 屏幕矩形与视口、深度区间与近远平面完全不相交则跳过；
6. 索引范围下界取 `floor`、上界取 `ceil − 1`（保守包含边界簇）；
7. 索引统一 `index_floor` 钳到 `[0, axis − 1]`。

**分桶层（本模块的五个函数与 GPU 阶段的对应）：**

| 阶段 | 本模块 CPU 参考 | GPU 同名管线（资产着色器） | 输出 |
| --- | --- | --- | --- |
| 逐簇计数 | `cluster_counts_reference` | `Cluster计数.comp` | `counts[total]` |
| 块内前缀 | `cluster_prefix_block_scan`（块 256） | `Cluster块内扫描.comp` | `prefix[total]` + `block_totals[blocks]` |
| 块间扫描 | 由调用方组合使用 | `Cluster块间扫描.comp` | 块间偏移 |
| 块偏移合成 | 无独立函数（由块内 + 块间两步合成） | `Cluster块偏移合成.comp` | 全局包含式前缀 |
| 排他偏移 | `cluster_list_offsets` | 同上末段 / 主机侧 | `offsets[total]`（每簇写入起点） |
| 列表写入 | `cluster_list_reference` | `Cluster列表写入.comp` | `list[Σcounts]`（光源索引序列） |

消费方式（实现事实）：门面在构建簇数据时先把逐簇计数、排他偏移与列表写入主机侧或 GPU 缓冲，再把三者按帧槽写入 SSBO，随后场景 set0 绑定；`cluster_entries` 记录本次条目数、`cluster_light_count` 记录上传的光源记录数。前向着色器按片元的簇下标取 `offsets[c]` 与 `list[offsets[c] .. offsets[c+1])` 得到该簇的光源索引集合，再对 `LIGHT_RECORD_CAPACITY` 内的记录做前向光照。关闭 Cluster 时回到旧前向路径（最多 32 盏、按声明顺序）。

### 6.5 像素回读的唯一合法时机

**录制侧（唯一合法位置）：** 颜色附件的拷贝必须录在**同一命令缓冲内、所有颜色写入完成之后、呈现（或回到着色器可读）布局转换之前**。三条路径的具体位置见 §6.1 的第 10 / 12 / 11.g 步。因此可选时机只有三个：`command_record` 尾部、`command_record_target` 尾部、`command_record_chain_present` 的末级收尾。批量阴影入口明确不支持回读。

**主机侧（唯一合法位置）：** `readback_read` 内的 `vkWaitForFences(slot.in_flight_fence)` 之后、`memory->buffer_read` 之前。由于渲染与拷贝录在同一命令缓冲、提交同一栅栏，栅栏发出即表示像素已写入回读缓冲；提前读（提交前）读到的是上一轮内容或未定义内容，滞后读（跨帧复用缓冲）会被下一次录制覆盖。

**缓冲复用口径：** `Frame_Context` 只有**一份** `readback_buffer`（跨全部帧槽共享），依赖「`readback_read` 阻塞至本帧完成」这一事实保证下一帧录制不会改写尚未读走的内容。容量按「宽 × 高 × 4」增长式重建（已在容量足够时复用），交换链尺寸变化时由 `readback_buffer_ensure` 自动扩容。回读失败（目标为空、容量不足、交换链图像无 `TRANSFER_SRC` 用法、等待或读取失败）均返回假并记日志，且**不**回填 `width` / `height` / `bytes`。

### 6.6 输入帧锁存语义

**两级状态机：**
- 待生效层（`pending_*` / `keys_held` / `buttons_held`）：由 `event_feed` 写入。键按下置 `keys_held[code] = 1` 并入 `pending_pressed`；SDL 的 `key.repeat` 只入 `pending_repeat`（不改按住状态）；已按住时重复按下事件被忽略；抬起仅在确实按住时入 `pending_released` 并清 `keys_held`。鼠标键下标 = `button − 1`（SDL 从 1 起），越界忽略。指针位移 `xrel/yrel` 累加到 `pending_dx/dy`，滚轮累加到 `pending_wheel_x/y`，文本提交累加到 `pending_committed`，预编辑串覆盖 `pending_preedit` 并置 `pending_preedit_changed`。
- 当前帧层（`frame`）：由 `frame_advance` 一次性锁存。`frame.frame` 自增、`frame.dt = dt`；窗口尺寸「事件优先，其次入参（两者都为 0 时保持上一帧）」；`dpi_scale ≤ 0` 保持上一帧；`frame.key_down = keys_held`（整表拷贝）；三个边沿列表用 `std::move` 接管（源容器随后为空，故单帧语义天然成立）；位移/滚轮取待生效值后立刻清零；鼠标按住与边沿逐下标拷贝后清零；`committed` 用 `std::move`；`preedit` 仅在 `pending_preedit_changed` 时更新；`text.active = text_active`。

**单帧量 vs 跨帧量：** 边沿（`key_pressed/released/repeat`）、位移增量、滚轮增量、`committed` 都是单帧量，下帧 `frame_advance` 前若无人调用则不累积（键边沿会跨多次 `event_feed` 累积，但每次 `frame_advance` 后清空）；按住状态（`key_down`、`button_down`）、`preedit`、`text.active`、窗口尺寸、`dpi_scale`、`window_focused` 是跨帧量。

**例外（实现与注释口径不一致）：** `pointer.x/y`、`modifiers`、`window_focused` 在 `event_feed` 内直接写入当前帧，不等 `frame_advance`（见【待确认：4】）。

**文本输入启停：** `text_input_enable` 状态未变化时空操作；变化时更新 `text_active` 与 `frame.text.active`，仅在已绑定窗口时调用 `SDL_StartTextInput` / `SDL_StopTextInput`，关闭时清空预编辑串并置变化标记。`reset` 关闭文本输入并清空全部待生效量与按住状态、最后 `frame = Input_Frame{}`。

### 6.7 并行录制的实现细节

- 段数公式：`min(thread_count, parallel_max_segments, item_count / 16)`，并要求 `≥ 2` 且次级缓冲就绪；默认最小项数 32、最大段数 8。
- 每段是**完整**的动态渲染实例（`vkCmdBeginRendering` / 视口 / 裁剪 / 绘制 / `vkCmdEndRendering`），因此次级缓冲需要 `VkCommandBufferInheritanceRenderingInfo`（颜色附件格式、深度格式、`rasterizationSamples`）。
- 首段沿用入参附件（含 `loadOp`），其余段强制 `LOAD`；`resolveMode` / `resolveImageView` 只在末段保留，其余段清空 —— 保证解析只执行一次。
- 单采样时 UI 回调放在**末段**（与单线程位置一致）；多采样时不放在段内，改由主缓冲在解析后另起 `ui_pass_record`。
- 统计：`parallel_counts[segment] = items_record(...)`，主缓冲在 `vkCmdExecuteCommands` 后逐段汇总到 `frame_recorded`，并回填 `last_parallel_segments`。
- 间接绘制与并行互斥（`active_secondary_count <= 1` 才允许间接）；批量阴影路径不复用该实现（其「多段」是多次独立 pass，不是同 pass 分段）。

### 6.8 延迟销毁的时机与判据

- `deferred_push(entry, delay)` 记 `release_frame = frame_count + delay`；门面在所有快照调用点都取 `in_flight_count_get() + 1`，即「在途帧数 + 1」。
- 判据是 `release_frame <= frame_count` 才释放（`deferred_flush` 用 `if (it->release_frame > frame_count) { ++it; continue; }`）。由于帧计数每帧只加一、且每帧末都冲刷，实际等价于「条目至少存活 `delay` 帧」。
- 为什么需要延迟：交换链重建不再 `vkDeviceWaitIdle`，旧链、旧视图、旧信号量、旧深度/MSAA 可能仍被在途帧引用；延迟到在途帧用尽后才安全。
- 销毁期 `deferred_release_all` 无视帧号：`destroy()` 已先 `vkDeviceWaitIdle`，且这些资源必须早于内存模块销毁（尤其是旧深度图像与其内存）。
- 类型口径隐患：`release_frame` 为 `uint64_t`、`frame_count` 为 `uint32_t`，比较时后者被提升；`frame_count` 回绕（2^32 帧）后所有条目会被立即释放（见【待确认：8】）。

### 6.9 间接绘制合并（`items_record` 的间接分支）

启用条件（全部满足）：`indirect_mapped != nullptr`、`indirect_buffer != VK_NULL_HANDLE`、`indirect_capacity > 1`、`active_secondary_count <= 1`（非并行段）、批内所有项 `instance_input == true`。

合并条件（`indirect_items_mergeable`）：管线、布局、描述符集数量、`scene_set`、`sampler_set`、推送常量（偏移/长度/逐字节）、顶点缓冲、索引缓冲、索引偏移、索引数、实例缓冲全等，且下一项 `instance_offset` 恰好等于「上一段起始偏移 + 累计实例数 × 步长」（步长默认 80），即实例区严格连续。

写入方式：预扫描本批命令条数，若 `frame_indirect_commands + planned <= indirect_capacity` 才整体走间接（容量不足则整体回落逐项路径，不与逐项混用）；每一合并段绑定一次状态与缓冲（顶点缓冲的实例偏移恒 0，起点由命令的 `first_instance = instance_offset / stride` 表达），写一条 20 字节命令并 `vkCmdDrawIndexedIndirect`。统计口径与逐项路径一致：`counts.items += merged_items`、`counts.instances += merged_instances`。

### 6.10 GPU 时间戳口径

- 能力探测在 `build` 内一次完成：`timestampComputeAndGraphics == VK_TRUE`、`timestampPeriod > 0`、图形队列族 `timestampValidBits > 0`；任一不满足只降级（不建池、字段恒 0、记 warn）。
- 主池 4 查询：0 = `TOP_OF_PIPE`（帧始）、1 = `BOTTOM_OF_PIPE`（场景结束）、2 = `BOTTOM_OF_PIPE`（后处理结束）、3 = `BOTTOM_OF_PIPE`（帧末）。直通与离屏单 pass 把 1、2 写在同一位置，故后处理耗时恒 0。
- 读回时机：在该槽栅栏等待完成之后、本帧录制之前；由于是环形帧槽，第 N 帧读回的是第 N − `frame_overlap` 帧的结果；首轮 `*_written` 为假直接跳过。
- 换算：按 `timestampValidBits` 掩去高位后相减，`period = timestampPeriod / 1e6` 得毫秒；场景 = 1 − 0、后处理 = 2 − 1、总计 = 3 − 0。
- 阴影池 2 查询，由 `shadow_gpu_ms_read` 单独读回（须由调用方保证已等尽在途帧）；批量路径只在首段重置 + 写起点、末段写终点。
- 所有累计量只在确实读回时递增，故 `gpu_sample_count` 等于「已成功读回的帧数」。

### 6.11 错误处理与降级策略

- `vk_result_check(result, 标签)` 统一出口（`Renderer/core/结果检查.h`），失败即记日志并返回假；`Frame_Context` 的每个公开入口在参数不完整时先用 `logger.error` 给出具体原因（如「帧上下文或离屏目标尚未就绪」）。
- 交换链过期 / 次优视为**可恢复**：`render`、`render_chain_present` 的 acquire 阶段与 `submit_present` 的 present 阶段都只置 `rebuild_needed_out = true` 并返回真；`render_to_target*` 无此概念。
- 栅栏重置刻意放在 acquire 成功之后：提前返回时栅栏保持已发出，避免下一帧复用同槽时死等（源码注释明确记录该因果）。
- 时间戳、阴影时间戳、三级缓冲、间接路径全部采用「能力/资源不足即静默降级为既有行为」，不使构建或出帧失败。
- 批量阴影路径任一段失败返回假，调用方应回落到逐 pass 旧路径（头注释明确该契约）。
- `items_record` 跳过不完整项（管线/缓冲缺失、索引数或实例数为 0、需实例属性却无实例缓冲、`gpu_indirect` 却无命令缓冲），并让「实际绘制量」与「登记量」分开统计。
- `HiZ_Context::slots_destroy` 在内存模块已失效时只清句柄（避免访问已销毁的分配器）。
- `场景装配` 的失败一律整体回退（先卸载本次新建的材质与网格、清空 `scene_out`），保证「装载失败时既有场景状态不被改动」。

### 6.12 其他值得记录的隐式约定

- 交换链颜色进入布局为 `UNDEFINED` 且 `srcAccess = 0`：同步完全由 acquire 信号量承担（`K11`）；呈现收尾的 `dstStage = BOTTOM_OF_PIPE`、`dstAccess = 0`（`K12`）。
- 离屏目标颜色在帧间恒为 `SHADER_READ_ONLY`，故「目标 → 下一帧采样」可直接成立；深度在帧间恒为 `DEPTH_ATTACHMENT`，后处理链在采样后必须转回（否则下一帧挂载非法）。
- 子视口 `viewport_rect` 非空时只收缩视口与裁剪，默认不收缩 `renderArea`；`render_area_from_viewport` 为真时才把 `renderArea` 一起收缩（用于图集瓦片各自清屏）。级联分片依赖「首片整图清屏」，故默认关闭该开关。
- `clear_color == nullptr` 在离屏路径表示 `LOAD`（同一目标的后续分片）；交换链路径没有该分支（始终 `CLEAR`）。
- 后处理推送块固定 16 个浮点、`offset = 80`；`post_extra_enabled` 为假时只推前 12 个，保证 `maxPushConstantsSize` 较小的设备照常出帧。
- 链路径的后处理绘制项要求「实例缓冲与实例数非空」，即使全屏四边形也按实例化绘制。
- `Camera` 的 Vulkan 约定：投影深度 `[0,1]`、NDC Y 向下（`proj[1][1] *= -1`），因此 `project_to_screen` 的 `v` 直接按 `ndc.y * 0.5 + 0.5` 得到「左上原点、Y 向下」。
- `Camera::ortho_set` 对非正 `ortho_height` 直接忽略整次设置（不会把模式切成「正交但高度 0」）。
- `场景装配` 的资产目录一律取「输入路径最后一个 `/` 或 `\` 之前的部分」并直接前缀拼接（保留 UTF-8，不做规范化）。
- `Particle_Host` 析构不解绑，绘制前各入口会重新绑定；`active_count` 在非常驻模式按 `alive` 标记统计（因为 GPU 推进会直接改写标记，池计数器可能滞后）。
- `HiZ` 深度历史用 `R32_SFLOAT` 颜色面（`STORAGE | SAMPLED`），与场景深度格式仅作记录；`depth_format` 变化会触发 `extent_set` 重建。
- `HiZ` 每级生成前都把该 mip 以 `UNDEFINED → GENERAL` 转入（内容整幅覆盖，丢弃旧布局合法）；生成结束历史转 `SHADER_READ_ONLY`，供跨帧组合采样器读取（软粒子等）。
- `Input` 的键位编码与 `SDL_Scancode` 数值一致，故 512 容量上界覆盖 SDL3 扫描码范围；越界一律忽略（既不置按住也不记边沿）。

## 七、模块运行链路详例

### 7.1 链路一：一帧从录制到呈递（`render` 直通路径）

**调用方：** 上层门面（`Renderer`，见 渲染器 模块文档）在 `frame_render` 内组织渲染项后调用 `Frame_Context::render`。

**逐步：**

1. `render` 入口把 `rebuild_needed_out = false`、`frame_indirect_commands = 0`，校验 `valid()`、`swapchain.valid()`、交换链图像数与两类信号量数非零。
2. `Frame_Slot& slot = slots[frame_count % frame_overlap]`；从该槽装载间接上下文（`indirect_buffer` / `indirect_mapped` / `indirect_capacity`）。
3. `slot_fence_wait(slot)`：`vkGetFenceStatus` 快速路径；未完成才 `vkWaitForFences(VK_TRUE, UINT64_MAX)`。
4. `gpu_timestamp_read(slot)`：读上一轮 4 个查询（首轮因 `timestamp_written` 为假跳过）。
5. 取 `image_available = swapchain.image_available_semaphore_get(acquire_cursor % count)`；`vkAcquireNextImageKHR(UINT64_MAX, image_available, VK_NULL_HANDLE, &image_index)`。
   - 过期 / 次优 → `rebuild_needed_out = true`，`logger.debug` 后**返回真**（本帧不推进 `frame_count`，不重置栅栏）。
   - 成功 → `++acquire_cursor`。
6. `vkResetFences(1, &slot.in_flight_fence)`；`frame_slot_pools_reset`（主池 + 全部次级池）。
7. 若 `readback` 非空且 `pixels` 非空：校验交换链图像具备 `TRANSFER_SRC` 用法、`capacity ≥ 宽×高×4`，`readback_buffer_ensure(bytes)`，得到 `readback_target`。
8. `parallel_plan(slot, item_count, swapchain.format_get(), swapchain.depth_format_get(), swapchain.sample_count_get())`：命中条件时填 `active_secondary` / 段数 / 格式 / 采样数，`parallel_counts.assign(段数, {})`。
9. `command_record(slot.command_buffer, swapchain.image_get(image_index), swapchain.image_view_get(image_index), swapchain.depth_image_get(image_index), swapchain.depth_view_get(image_index), swapchain.extent_get(), items, item_count, clear_color, ui_callback, readback_target, slot.timestamp_pool, swapchain.msaa_*_get(image_index)…, swapchain.sample_count_get(), post_scene)`。
   - 命令序列见 §6.1.1。
   - 期间 `items_record` 可能走间接合并（写 `indirect_mapped` 中的 20 字节命令）或逐项 `vkCmdDrawIndexed`，并累计 `frame_recorded`。
   - `post_scene` 回调（HiZ 生成）在场景通道结束后执行。
10. 清空 `active_secondary` / `active_secondary_count`（并行上下文只对本帧有效）；记录 `last_host_record_ms`。
11. `render_finished = swapchain.render_finished_semaphore_get(image_index)`；`submit_present(slot, image_index, image_available, render_finished, swapchain, rebuild_needed_out, submit_ms, present_ms)`：
    - `vkQueueSubmit2`：等 `image_available`@COLOR_ATTACHMENT_OUTPUT、信号 `render_finished`@ALL_COMMANDS、完成栅栏 `slot.in_flight_fence`。
    - `vkQueuePresentKHR(present_queue, wait render_finished, image_index)`；过期/次优只置标志。
12. 回填 `last_host_submit_ms` / `last_host_present_ms` / `last_frame_ms`，累加三个 `total_host_*` 与 `total_frame_ms`。
13. `frame_stats_accumulate(items, item_count)`：登记量 + 实际绘制量。
14. `last_post_stages = 0`、`last_sample_count = swapchain.sample_count_get()`。
15. 若请求回读：`readback_read(slot, *readback, swapchain.extent_get())`（再次等栅栏 → `memory->buffer_read` → 回填三字段）。
16. `slot.timestamp_written = true`；`++frame_count`；`deferred_flush()`。

**结果与副作用：** 交换链图像完成一次颜色写入与呈现布局转换；槽栅栏被重新武装；间接命令缓冲被填充（若启用）；主机侧统计与 GPU 时间戳样本按环形口径推进；到期延迟销毁条目被释放。

### 7.2 链路二：HiZ 遮挡裁剪（跨帧两段式）

**阶段 A（第 N 帧，生成本帧深度金字塔）**

1. 门面 `hiz_enable_set(true)`：判 `hiz_capable && compute.supported()` 与 `R32_SFLOAT` 的 `STORAGE_IMAGE | SAMPLED_IMAGE` 特性；`hiz.compute_set(&compute)`；`hiz.build(device, memory, frame_overlap, 宽, 高, 交换链深度格式)`；懒加载 `HiZ深度拷贝.comp.spv` 与 `HiZ降采样.comp.spv` 两条管线。
2. 交换链重建时：`hiz.extent_set(新宽, 新高, 深度格式)` —— 完全一致则空操作，否则销毁并按原槽数重建（`history_valid` 归假）。
3. 门面在录制时把 `Frame_Post_Scene_Callback{ fn = hiz_post_scene_entry, user_data = impl }` 传给 `render` / `render_to_target` / `render_chain_present`。
4. 帧录制在场景通道 `vkCmdEndRendering` 之后调用该回调（`extent` 与 `hiz` 尺寸不一致时直接跳过）；`hiz_post_scene_entry` 取当前槽号并调 `pyramid_generate`：
   - `compute->slot_set(slot)`；
   - 场景深度 `DEPTH_ATTACHMENT → SHADER_READ_ONLY`；历史 `UNDEFINED → GENERAL`；绑定采样器与历史存储；
   - `compute_dispatch(深度拷贝管线, ceil(宽/8), ceil(高/8), 1)`；`ComputeToCompute` 屏障；
   - 逐级 `level`：目标 mip `UNDEFINED → GENERAL`、源（第 0 级 = 历史，其余 = 上一级视图）、`compute_dispatch(降采样管线, ceil(级宽/8), ceil(级高/8), 1)`、`ComputeToCompute` 屏障；
   - 场景深度恢复 `DEPTH_ATTACHMENT`；历史转 `SHADER_READ_ONLY`；
   - `history_valid(slot) = true`、`generation_total++`；门面记 `last_hiz_slot = slot`。
5. 帧结束，帧末 `deferred_flush()` 与本链路无关。

**阶段 B（第 N+1 帧，用上一轮金字塔做 GPU 剔除）**

1. 门面在提交渲染项前做实例级 GPU 压缩（`实例压缩.comp`）：先做 CPU 级视锥剔除并得到局部界，再准备四个计算缓冲（源矩阵 / 压缩输出 / 原子计数 / 剔除参数）。
2. 判定遮挡是否可用：`hiz_enabled && hiz.valid()` 且 `hiz.history_valid(last_hiz_slot)` 且 `hiz.pyramid_full_view(last_hiz_slot) != VK_NULL_HANDLE` 且 `hiz.depth_sampler_get() != VK_NULL_HANDLE`；首帧无历史即自动跳过（与关闭 HiZ 逐字节一致）。
3. 可用时：`params.hi_z = (hiz.width_get(), hiz.height_get(), hiz.level_count(), 1.0f)`；`compute.slot_set(last_hiz_slot)`；`compute.sampler_bind(last_hiz_slot, hiz.depth_sampler_get(), hiz.pyramid_full_view(last_hiz_slot))`。
4. `compute_dispatch(实例压缩管线, count, 本地尺寸 256, push = {view_proj, bounds_min, bounds_max, count})`，绑定 0..3 号缓冲（第 3 号为剔除参数）。
5. `compute_buffer_read(counter_handle, counters, 8, 0)`：`counters[0]` = 可见数、`counters[1]` = 遮挡剔除数；回写 `last_gpu_occluded`；随后回读压缩后的可见矩阵前缀。
6. 后续绘制只登记可见前缀。

**CPU 参考对照（本模块 `遮挡测试.h`）：** `hiz_screen_rect_build`（8 角点投影 → 屏幕包围盒 + 最小 z + 跨近平面标志）→ `hiz_level_for_rect`（按矩形尺寸取级，末两级不采样）→ `hiz_pyramid_level_get`（逐级紧排偏移定位）→ `hiz_occlusion_test`（覆盖纹素最大远面深度 + bias 比较）。`hiz_pyramid_downsample` 与 `HiZ降采样.comp` 同为「2×2 取最大、越界钳到末行/末列」。

**结果：** 完全位于已生成遮挡面之后的实例被剔除；因采用「最大远面深度 + 正 bias + 矩形外扩」，只会少剔、不会误剔。

### 7.3 链路三：簇光照分桶（CPU 参考与 GPU 落地）

1. 场景应用后，门面把相机 / 光照 / 雾写入内部状态并生成 `Light_Record` 数组（`LIGHT_RECORD_CAPACITY` 上限），`light_effective_count(count, cluster_enabled)` 决定参与数目。
2. 网格：`cluster_grid_set(x, y, z)` 经 `cluster_grid_clamp` 钳制（各轴 1..64、总数 ≤ 4096）；默认 16×9×24。
3. 组装 `Cluster_Input`：`camera.view_proj_get(view_proj)`、`camera.position_get(camera_position)`、`fov`（`fov_get`）、`aspect`（`aspect_effective_get`）、`near_plane` / `far_plane`（`clip_get`）。
4. 逐簇计数：
   - CPU：`cluster_counts_reference(counts, total, grid, lights, count, input)` → 方向光全簇 +1；点光/聚光按 §6.4 的保守覆盖区间累加。
   - GPU：上传光源记录与清零计数缓冲 → 每记录一线程调度 `Cluster计数.comp` → 回读逐簇计数（门面 `cluster_counts_gpu`）。
5. 前缀和：CPU `cluster_prefix_block_scan`（256 分块，包含式）或 `cluster_prefix_scan`（全量）；GPU 为 `Cluster块内扫描.comp` → `Cluster块间扫描.comp` → `Cluster块偏移合成.comp` 三段。
6. 排他偏移：`cluster_list_offsets(counts, total, offsets)` → `offsets[c]` = 前 c 簇计数之和，返回总条目数。
7. 列表写入：CPU `cluster_list_reference(list, capacity, offsets_io, counts, total, grid, lights, count, input)`，`offsets_io` 作为每簇写入游标被推进到簇末尾；GPU 为 `Cluster列表写入.comp`，每光源一线程。
8. 门面把 `counts` / `offsets` / `list` 写入当前帧槽 SSBO（与帧槽一一对应），并把光源记录 SSBO 一并上传；记录 `cluster_light_count`、`cluster_entries`、`cluster_gpu_bytes`。
9. 场景绘制时 set0 绑定上述 SSBO；前向着色器按片元簇下标 `(z*y + y)*x + x` 查 `offsets` 与 `list`，取该簇光源集合做光照。关闭 Cluster 时退回旧前向路径（最多 32 盏，按声明顺序）。

**失败与回退：** `capacity < 总簇数`、入参非法、`light_count == 0` 时 CPU 函数一律返回 0 且不写任何项；GPU 路径在计算不可用 / 容量不足 / 调度或回读失败时返回假，调用方应回退 CPU 参考或关闭 Cluster。

### 7.4 链路四：输入事件到帧快照

1. **事件泵（门面 / 上层）：** 每个 SDL 事件调 `Input_Aggregator::event_feed(&event)`（门面暴露 `input_aggregator()` 供上层直接喂入，多窗口或测试注入也走此入口）。
2. **待生效累积（`SDL事件适配.cpp`）：**
   - `SDL_EVENT_KEY_DOWN`：`scancode` 越界（≥ 512）忽略；刷新 `frame.modifiers`（左右合并）；`repeat` 为真只入 `pending_repeat`；已按住则忽略；否则 `keys_held[code] = 1` 并入 `pending_pressed`。
   - `SDL_EVENT_KEY_UP`：仅确已按住时清 `keys_held` 并入 `pending_released`。
   - `SDL_EVENT_MOUSE_MOTION`：直写 `frame.pointer.x/y`，`xrel/yrel` 累加到 `pending_dx/dy`。
   - `SDL_EVENT_MOUSE_BUTTON_DOWN/UP`：下标 = `button − 1`（越界忽略），直写 `frame.pointer.x/y`，按住用 `buttons_held` 去重，边沿入 `pending_button_pressed/released`。
   - `SDL_EVENT_MOUSE_WHEEL`：`pending_wheel_x/y` 累加。
   - `SDL_EVENT_TEXT_INPUT`：`pending_committed += text`；`SDL_EVENT_TEXT_EDITING`：覆盖 `pending_preedit` 并置变化标记。
   - `SDL_EVENT_WINDOW_FOCUS_GAINED/LOST`：直写 `frame.window_focused`。
   - `SDL_EVENT_WINDOW_RESIZED` / `SDL_EVENT_WINDOW_PIXEL_SIZE_CHANGED`：`data1/data2 > 0` 时记 `pending_window_*` 并置 `pending_window_valid`。
3. **帧推进（`帧锁存.cpp`）：** 上层每帧调 `frame_advance(dt, 宽, 高, dpi_scale)`：
   - `++frame.frame`、`frame.dt = dt`；
   - 窗口尺寸：`pending_window_valid` 优先并清标志；否则两入参都 > 0 时采用；否则保持上一帧；
   - `dpi_scale > 0` 才更新；
   - `frame.key_down = keys_held`；三个边沿列表 `std::move` 接管；位移/滚轮取待生效值后清零；鼠标三数组逐下标拷贝后清空待生效边沿；`frame.text.committed = std::move(pending_committed)`；`preedit` 仅在变化时更新；`frame.text.active = text_active`。
4. **消费：** 上层与 UI 命中测试通过 `frame_get()` 读同一份快照（`key_held` / `key_pressed_check` / `key_released_check` 均为只读内联）。
5. **侧副作用：** `text_input_enable` / `reset` 会直接改 `frame.text.active` 与待生效量；析构时若文本输入仍启用则 `SDL_StopTextInput`。

**语义结果：** 单帧边沿在两次 `frame_advance` 之间累积、锁存后清空；按住状态跨帧保持；指针位置、修饰键与焦点为「事件即时值」（见【待确认：4】），窗口尺寸为「事件优先、参数兜底」的两级锁存。
