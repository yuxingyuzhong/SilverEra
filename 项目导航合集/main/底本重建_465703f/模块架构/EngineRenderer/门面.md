## 二、模块功能介绍

`EngineRenderer` 门面的唯一职责是“编排整个渲染层”：它持有平台、设备、内存、交换链、帧、着色器、管线、计算、HiZ、Cluster、网格、纹理、字体、文字、UI、输入、渲染目标、线程池、相机等全部子模块实例，并按确定顺序创建、使用与销毁；外部只通过 `Renderer` 的公共方法访问渲染能力。

对外提供的能力面（全部为 Vulkan-free 签名）：

- 生命周期与帧驱动：`init` / `shutdown` / `frame_render` / `frame_wait_idle`；
- 资源装载与释放：程序化/OBJ 网格、内存/文件/棋盘/LUT/立方体纹理、材质与 MTL 材质库、具名图形管线、离屏渲染目标、TTF 字体；
- 绘制登记：`mesh_draw` / `mesh_draw_range` / `mesh_draw_sections` / `mesh_draw_instanced` / `text_draw*` / `particle_draw*`，登记后统一在下一帧消费；
- 场景与光照：相机参数、方向光/补光/点光/聚光、雾、环境光、PBR、卡通、描边；
- 阴影：方向光级联阴影、聚光灯阴影（单盏/多盏/图集）、PCSS、预算与逐盏参数；
- 后处理：同帧单级/多级链、离屏目标、SSAA、MSAA、LUT、逐级参数；
- GPU 路径：计算上下文、GPU 剔除/压缩、Hi-Z 遮挡、Cluster 光照、粒子 GPU 推进/绘制；
- 观测：`Frame_Stats`、`Renderer_Resource_Counts`、各项专项查询；
- UI 通道：`Ui_Channel_Context`（供 ImGui Vulkan 后端接入）与原生 `Ui_Context`。

不负责的边界：

- 不实现任何子模块内部逻辑（设备创建、交换链图像管理、命令录制、管线创建、网格/纹理存储分别归各子模块）；门面只做参数校验、状态记录、顺序编排与跨模块拼装。
- 不解析 UI 控件语义；原生 UI 的控件树与命中测试在 `Ui_Context`，GPU 绘制在 `Ui_Renderer`。
- 不推进粒子模拟；粒子状态数组由应用层持有，渲染层只上传并登记 billboard 绘制。
- 不暴露 Vulkan / VMA / SDL3 类型于主公共头；需要 Vulkan 句柄的上层能力放在 `渲染器_UI通道.h` 这类扩展头。

关键约束：

1. 非线程安全。所有公开 API 必须来自同一线程；内部工作线程只执行实例剔除、实例差异扫描与场景/阴影次级命令录制，不对外暴露（见 §5.4）。
2. `init` 任一环节失败即调用 `shutdown` 逆序回退，不留半初始化状态；`shutdown` 幂等，析构兜底。
3. 绘制登记是“下一帧生效”：`mesh_draw` 等只压入 `pending_items` / `pending_instances` / `pending_push_constants`，由下一次 `frame_render` 消费并清空。
4. 大量特性默认关闭或取恒等值，保证不调用时画面逐字节不变；这些默认值同时是回归基线。
5. 资源销毁普遍走“延迟队列”，延迟 = 在途帧数 + 1，避免在途命令缓冲仍引用资源。

### 3.16 接口契约的共性规则

以下规则横跨全部公开接口，单条接口表不再重复：

1. 未初始化时的行为分三档：`bool` 返回 false、`uint*` / `int` / `float` 返回默认值、`void` 静默返回；句柄类出参一律置 0。`ui_channel()` / `input_aggregator()` 是例外（只判 `impl`，见【待确认：4】）。
2. “整次拒绝”语义：一次调用内任一参数非法即不改变任何状态、不登记任何绘制项；已部分登记的场景仅 `mesh_draw_sections` 例外（已成功段不回滚，与 `mesh_draw` 既有语义一致）。
3. “同值空操作”语义：多数 setter 在钳制/归一后与当前值相同时直接返回，不重建资源、不置待重绘标志（如 `ssaa_factor_set`、`msaa_samples_set`、`blend_mode_set`、`spot_shadow_all_set`、`spot_shadow_light_set`、`pbr_roughness_absolute_set`、`shadow_texel_max_set`）。
4. “下一帧生效”：绘制登记、清屏色、文字颜色/描边、泛光/逐级参数、SSAA 倍率全部在下一次 `frame_render` 生效；阴影/聚光参数多数即时改字段，但阴影图内容要等下一次重绘。
5. “等尽在途帧”：凡是重写被在途命令缓冲引用的资源（纹理绑定、采样器状态、后处理集、阴影图改绑、图集切换、MSAA/阴影分辨率重建、渲染目标销毁、计算缓冲卸载、粒子容量变化）都先 `frames_wait` 或 `slot_wait`。
6. “延迟销毁”：交换链旧资源、网格缓冲、纹理图像、渲染目标四组图像、计算缓冲均进入 `frame.deferred_push`，延迟 = 在途帧数 + 1；只有管线/着色器模块在 `frames_wait` 后直接销毁。
7. “句柄自 1 起、0 无效”：网格/材质/纹理/管线/渲染目标/字体/LUT 使用 `uint64_t`；计算缓冲与计算管线使用独立句柄空间，同样自 1 起，槽不复用（卸载即移出列表）。
8. “观测量与累计量分离”：`last_*` 字段为最近一帧即时值，`*_total` / 无 `last` 前缀字段为自 init 累计；`frame_stats_reset` 只清累计，不清即时量。
9. “单位与坐标约定”：文本/相机投影使用窗口像素坐标、左上原点、Y 向下；深度读回为 32 位原始值（本层 `D32_SFLOAT` 按 float 解释）；像素读回一律 RGBA8 紧排、逐行自上而下、无行填充。
10. “阴影图深度为打包值”：阴影颜色附件为 RGBA8 UNORM，存非线性可视深度；空区域全 0；读回接口输出该打包颜色，不直接给浮点深度。

### 5.4 销毁顺序（`Renderer::shutdown`）

严格逆序，并允许半初始化状态（各子模块 `destroy` 幂等）：

```
thread_pool.threads_stop
→ 阴影管线 / 阴影目标 / 聚光图集 / 8 张聚光瓦片
→ 粒子四边形网格（先于 frame/mesh）
→ frame.destroy
→ ui_render.shutdown → ui.shutdown → input.reset → text.shutdown
→ mesh.destroy → font.destroy → texture.destroy → render_target.destroy
→ 复位路径/链/SSAA/MSAA/逐级参数/剔除/合批/材质吸附/光照/雾/环境光
→ 场景 UBO、实例缓冲、间接命令缓冲（memory 仍有效）
→ cluster_destroy / cluster_graphics_destroy
→ 管线缓存写回
→ 计算缓冲记录 → 计算管线条目 → 粒子 GPU 句柄复位 → Hi-Z destroy → compute.destroy
→ 自检模块 → pipeline.destroy → 场景着色器模块 → 具名管线模块 → materials/material_pipelines
→ shader.destroy → swapchain.destroy → memory.destroy
→ platform.event_forward_clear → platform.destroy → device.destroy
→ pending 清空 → ui_channel.destroy → frame_count=0 / initialized=false
```

关键顺序约束：

- `frame.destroy` 位于阴影/粒子资源之后、UI/网格/纹理/渲染目标与场景/实例/间接/Cluster 缓冲手动归还之前；它释放命令缓冲、栅栏与延迟队列，故后续归还的资源必须已无在途引用。
- `swapchain` 晚于 `pipeline`（管线引用交换链格式与采样数），`memory` 晚于所有缓冲/图像。
- `platform` 先于 `device`：平台持有“借用”的实例句柄，销毁表面要求实例仍在途；随后 `device.destroy` 连带销毁实例。

### 5.5 数据流

```
应用层
  │ mesh_draw / mesh_draw_sections / mesh_draw_instanced / text_draw / particle_draw
  ▼
门面登记区（Impl）
  ├─ pending_items        : Frame_Render_Item（管线/索引区/实例区/采样快照/阴影标记）
  ├─ pending_instances    : 28 浮点/实例（16 矩阵 + 4 PBR + 4 卡通 + 4 暗部色调）
  └─ pending_push_constants : deque<array<float,32>>（引用稳定，绘制项持指针）
  │ frame_render
  ▼
帧槽（slot = frame.slot_index_get()）
  ├─ scene_ubo[slot]      : 980 浮点，按 16 字节单元差异上传
  ├─ instance_buffer[slot]: 容量 × 112 字节，按实例差异上传（可并行）
  ├─ indirect_buffer[slot]: 4096 × 20 字节（可选）
  ├─ post sets[slot][i]   : 后处理每槽采样集（源/场景/深度/阴影/LUT）

  ├─ 后处理级（单级/链/SSAA，全屏四边形）
  ├─ UI 阶段（原生 UI + 外部回调）
  └─ 呈现（交换链或离屏）
```

### 5.6 线程归属

- 所有 Vulkan 对象创建、提交、呈现与描述符集写入都在调用 `frame_render` 的线程上完成。
- `render_threads > 0` 时 `Thread_Pool` 只承担三类纯 CPU 工作：实例级视锥剔除（写各自掩码槽）、实例缓冲差异扫描（写各自掩码槽）、实例缓存回写（写各自 28 浮点槽）；块间不重叠，结果与单线程逐字节一致。
- 帧模块另用同一线程池把场景/阴影绘制命令录制进次级命令缓冲，主命令缓冲以 `vkCmdExecuteCommands` 汇总；门面只把线程池指针交给帧模块（`frame.thread_pool_set`）。
- 工作线程不对外暴露；外部不得并发调用门面接口，也不得与门面共用同一队列自行提交。

### 5.7 四条渲染路径的优先级

| 优先级 | 条件 | 门面调用 | 结果 |
| --- | --- | --- | --- |
| 1 | `ssaa_factor > 1` 且 `present_target == 0` 且 `active_target == 0`，资源全部就绪 | `frame.render_chain_present(swapchain, targets[2], ...)` | 场景 → N 倍目标 → 降采样 → 默认后处理 → UI → 呈现 |
| 2 | `present_target != 0` 且后处理资源就绪 | `frame.render_chain_present(swapchain, targets, ...)` | 场景 → 目标组轮转 N 级后处理 → UI → 呈现 |
| 3 | `active_target != 0` | `frame.render_to_target(target, ...)` | 场景 → 离屏目标，不呈现 |
| 4 | 默认 | `frame.render(swapchain, ...)` | 取图像 → 场景 → UI → 呈现 |

路径互斥；任一前置失败只告警并回落下一路径，不改变帧计数节奏。

## 六、模块设计 / 实现细节

### 6.1 单文件巨型化的原因与拆分边界现状

`core/渲染器.cpp` 达 573 KB / 13432 行，是本项目体量最大的单文件。从代码结构看，巨型化源自“按轮次增量堆叠”的历史路径：

- 单函数 `frame_render` 占据 2242–4259 行（约 2017 行），把事件泵、输入锁存、UI 回调、交换链重建、光源矩阵、阴影 pass、UBO 组装与差异上传、实例缓冲差异上传、合批、描述符集填装、天空盒、SSAA/后处理/离屏/交换链四路分派、统计结算与回读交付全部串在一个函数内。
- 阴影相关代码在同一个文件里重复出现多轮：级联矩阵、聚光瓦片矩阵、瓦片槽位映射、图集、PCSS、逐盏质量缩放、批量提交，均由后续轮次直接插入既有函数（尤其 `frame_render` 与 `scene_apply`）。
- 资源装载、状态 setter、查询 getter 按“接口出现顺序”平铺，缺少按功能域的物理隔离；同一簇的代码（例如阴影）分散在 12136–13081 行与 `frame_render` 两处。
- 公共头 `渲染器.h` 达 2214 行，也呈现“接口按轮次追加”的痕迹；但公共头与实现头已分离，接口层尚可读。

现状的拆分边界：

1. 公共/实现隔离已完成：`渲染器.h` 零 Vulkan/SDL；`渲染器实现.h` 承载全部内部类型与状态，仅被 `.cpp` 包含。
2. `core/` 内已抽出 `结果检查.h` 与 `UI通道.cpp`，说明“可独立的小块”已有先例。
3. 未完成的边界：帧驱动、阴影、场景/光照、资源/材质/管线、后处理/渲染目标、计算/Cluster、粒子仍全部挤在 `渲染器.cpp`。

拆分建议（供用户拍板）：按功能域拆成 8 个 `.cpp`，保留一个“门面装配”主文件：

| 建议文件 | 承接内容 | 约行数 |
| --- | --- | --- |
| `core/渲染器.cpp` | 构造/析构、`init`、`shutdown`、窗口/尺寸/全屏、`valid`、`resource_counts`、UI 入口 | 约 1600 |
| `core/渲染器_帧驱动.cpp` | `frame_render`、帧统计、回读、`frame_wait_idle` | 约 2200 |
| `core/渲染器_阴影.cpp` | 阴影/聚光/图集/PCSS/级联/预算全部 setter/getter + `spot_shadow_tiles_ensure` / `atlas_apply` | 约 1600 |
| `core/渲染器_场景与光照.cpp` | 相机、`scene_apply` 两份、光源、雾、环境光、PBR/卡通/描边 | 约 2200 |
| `core/渲染器_资源.cpp` | 网格装载/更新、纹理、材质/MTL、管线登记/绑定 | 约 2200 |
| `core/渲染器_后处理.cpp` | 渲染目标、`post_chain`、逐级参数、LUT、SSAA/MSAA | 约 1300 |
| `core/渲染器_计算与簇.cpp` | 计算缓冲/管线/调度、GPU 剔除、Hi-Z、Cluster 原语 | 约 1800 |
| `core/渲染器_粒子与文字.cpp` | 粒子全部、字体/文字/文本缓存、输入/UI 查询入口 | 约 1600 |

拆分前提：`Renderer::Impl` 的单一定义保持不变（仍只在 `渲染器实现.h`），拆分只移动成员函数定义；匿名命名空间工具抽到 `core/渲染器工具.h` / `.cpp`。这样不改变 ABI、不改变持有关系，只降低单文件认知与编译负担。

### 6.2 公开接口与内部实现的隔离

- `Renderer` 是 pimpl：公共头只前置声明 `class Impl;` 与 `std::unique_ptr<Impl> impl`，不暴露任何内部字段。
- Vulkan/SDL/VMA 类型全部关在 `渲染器实现.h` 与 `.cpp`；公共头只使用 `uint64_t` 句柄（纹理/管线/材质/渲染目标/字体/LUT）与引擎语义类型（`Mesh_Handle`、`Material_Handle`、`Vertex`、`Mesh_Data`、`Texture_Sampler_State`、`Scene_Data` 等）。
- 需要 Vulkan/SDL 能力的上层接口（UI 通道）另立扩展头 `渲染器_UI通道.h`，由上层自行包含；主头保持零 Vulkan。
- `core/结果检查.h` 也属于“层内实现细节”：只被本层 `.cpp`/层内头包含，因此可以合法暴露 Vulkan 类型。
- 模板/静态工具（`instance_matrices_append`、`msaa_supported_max`、`batch_adjacent_items` 等）留在 `.cpp` 匿名命名空间或文件级 `static`，不进入任何头。

### 6.3 绘制登记与推送常量布局

- 每个绘制项 `Frame_Render_Item` 在登记时只填静态字段（管线、布局、顶点/索引缓冲、索引区、实例区、采样快照、阴影标记、透明标记），描述符集与实例缓冲句柄延迟到 `frame_render` 按本帧槽填装。
- 模型矩阵不再走推送常量，而是写入实例缓冲（每个实例 28 浮点 = 112 字节：0..15 矩阵、16..19 PBR、20..23 卡通、24..27 暗部色调）。
- 场景项恒推送 32 浮点（128 字节）推送块：0..15 单位矩阵占位、16..19 颜色（offset 64）、20..23 法线强度/粗糙度标志/Alpha 裁剪/UV 旋转（offset 80）、24..27 UV 缩放与偏移（offset 96）、28..31 清漆强度/粗糙度（offset 112）。文字路径复用 offset 80 为描边半宽与描边色、offset 96 恒等 UV。
- 后处理项不走上述场景块：`Frame_Render_Item` 额外带 `post_params[4]`（offset 96 泛光）、`post_color[4]`（offset 112 描边色）、`post_extra[4]`（offset 128 自定义），由帧模块按级推送；设备 `maxPushConstantsSize < 144` 时 `post_stage_extra_set` 被拒绝且该组保持全零。
- `pending_push_constants` 用 `std::deque<std::array<float,32>>` 保证元素引用稳定；绘制项持裸指针，直到 `frame_render` 消费后统一清空。

### 6.4 场景 UBO 与实例缓冲的按需上传

- 场景 UBO 固定 980 浮点（3920 字节），逐帧槽缓存上一轮全部浮点；按 4 浮点（16 字节，std140 vec4 对齐）为比较单元，把连续变化单元合并成段，仅对变化区间 `buffer_write`；首次访问该槽整块写入。上传字节计入 `scene_upload_bytes`。
- 实例缓冲以“一个实例 = 28 浮点 = 112 字节”为比较单元。差异扫描先用并行掩码（每实例只写自己的掩码槽），再单线程按掩码合并连续变化段写入；缓存回写同样按实例分块并行。上传字节计入 `instance_upload_bytes`。
- 阴影 pass 直接整块写当前槽实例缓冲，并显式把该槽的 `instance_block_cached` 置 0，迫使主 pass 复用该槽时重建缓存（否则会按旧缓存跳过必要更新）。
- 帧槽 UBO/实例缓冲的写入都在 `frame.slot_wait()` 之后，避免覆盖 GPU 仍在读取的上一轮内容。

### 6.5 静态合批的等价条件

`batch_adjacent_items` 只在“相邻”项之间合并，且要求：

- 推送常量大小/偏移一致，非零时逐字节一致；
- `post_params`、`post_color`、`post_extra` 逐字节一致；
- 实例缓冲相同且实例区首尾相接；
- 两项都带实例输入、都不是透明项；
- 管线、布局、顶点/索引缓冲、索引偏移/索引数完全一致；
- 阴影标记与采样数一致；
- 采样器与六张视图（反照率/法线/粗糙度/自发光/AO/金属度）一致。

合并只累加 `instance_count`，不重排顺序，因此绘制顺序、实例顺序与画面逐字节不变；收益通过 `drawn_items` 下降与 `merged_items` 观测。主 pass 与阴影分片共用该函数；阴影列表在分片循环外只合批一次。

### 6.6 后处理链与回退策略

- 单级默认路径：`present_target` 有效且 `post_chain` 为空，使用内置 `后处理.vert/frag` 管线（惰性登记）与全屏四边形，做一次全屏 pass 后呈现。
- 链路径：`post_chain` 1..8 级；目标组由 `render_target_present_chain_set` 给出 1..`PRESENT_TARGET_MAX` 个目标。第 i 级源 = `targets[i % count]`、非末级宿 = `targets[(i+1) % count]`；链长 ≥ 2 时目标数必须 ≥ 2，否则本帧回落单级路径。
- 每帧先 `post_sets_bind` 把目标视图组写入全部帧槽后处理集（签名未变时空操作），再组装每级绘制项；任一级管线在设置后被卸载/失效即整帧回落原路径。
- 后处理实例：向 `pending_instances` 追加一个单位矩阵实例（材质四浮点全零），全屏四边形以该实例为实例缓冲来源；若实例存储已满则回落。
- SSAA 与后处理/离屏互斥：`ssaa_factor > 1` 且两者皆未设置时才走；两级管线固定为“降采样 → 默认后处理”，目标按 `targets[级序 % 2]` 轮转（第 0 级 N 倍场景目标、第 1 级解析目标）。
- 后处理目标尺寸不要求等于交换链（自第十七轮放宽），仅要求每个目标尺寸非零；片元按“源/宿尺寸”推送做像素映射。
- LUT 绑定写入全部帧槽全部后处理集 binding 3；句柄 0 改写为 2×2 白纹理使查找级原样输出。

### 6.7 阴影预算与阴影路径

- 阴影目标颜色格式固定 `VK_FORMAT_R8G8B8A8_UNORM`（不用交换链 sRGB 格式，避免 sRGB 编解码破坏打包深度）；固定单采样，不随 MSAA 变化。
- 方向光级联：`cascade_count` 1/2/3；阴影图沿 X 切成 2/3 个方形片。单级以相机为中心、半径 `shadow_half_extent` 的包围球拟合；多级每片半径 = `split × far_scale^片序`，纹素对齐把光源空间裁剪平移吸附到纹素网格，Z 不吸附。`cascade_depth_span[3]` 供着色器把法线偏移换算为世界量。
- 聚光阴影：最多 8 个瓦片；`spot_shadow_all` 开启时优先“瓦片号 = 光源槽位”，可投影聚光超过 8 盏时按优先级降序取前 8 再按槽位升序分配；关闭时沿用 `spot_shadow_index` 单盏语义（写瓦片 0）。每瓦片透视矩阵由外锥角反解半锥角（钳 0.02..1.5 弧度）、远平面取衰减半径（≥0.2）。
- 图集：4×2 张 `shadow_size` 见方瓦片并入一张 4S×2S 目标，按瓦片号收缩视口与渲染区并逐片清屏；图集生效后销毁全部独立瓦片，`spot_shadow_tiles_ensure` 直接返回。
- 按需重绘：FNV-1a 签名混入三阶级联矩阵、8 份聚光矩阵、仅投影实例矩阵、投影项数、阴影图边长与级联数；签名一致且阴影图可用即整段复用（`shadow_reuses` 增长），否则重绘。
- 批量提交：`shadow_batch_submit` 且段数（方向光级联 + 有效聚光瓦片）> 1 时，先把每段目标/矩阵/清屏标志填入表，循环后一次 `render_to_targets_batch`；否则逐段 `render_to_target`。`shadow_submits` 记录实际提交次数。
- 预算：`scene_apply` 内按“方向光级联数 + 聚光瓦片数”折算单位数，`pixels_per_unit = bytes / (units × 4)`，整数平方根后向下取 256 倍数并钳 256..4096，再取不超过该值的最大受支持档（512/1024/2048），与请求分辨率取较小值。`shadow_budget_set` 只存预算，真正换算依赖本次 `scene_apply`。

### 6.8 重建编排

| 重建对象 | 触发 | 编排要点 | 失败处理 |
| --- | --- | --- | --- |
| 交换链 | 窗口 resize（`platform.resized_consume`）、帧链路 `rebuild_needed`、`window_size_set`、`msaa_samples_set` | `swapchain_rebuild_deferred` 把旧链及附属资源（图像视图/两类信号量/深度图像/内存/视图）移交延迟队列，延迟 = 在途帧数 + 1；随后按新格式重建图形管线；Hi-Z 跟随尺寸重建 | 失败回滚为旧链（`swapchain.rebuild` 内部），本帧继续；下一帧再试 |
| 图形管线 | 交换链格式/深度格式/采样数变化 | `pipeline.pipeline_rebuild(format, depth_format, sample_count)`；格式未变时空操作 | 仅告警，不中断帧 |
| MSAA | `msaa_samples_set` | 等尽在途帧 → 交换链采样数 + 重建 → 渲染目标 `sample_count_set` → 全部图形管线重建 → 当前绑定视图回落白纹理 → 更新配置 | 交换链重建失败则恢复原采样数并返回 |
| 阴影分辨率 | `shadow_resolution_set` | 等尽在途帧 → 建新阴影图与各瓦片 → 取新视图 → 逐帧槽改绑 → 全部成功后才销毁旧图并更新 `shadow_size`；图集按新边长重建 | 任一步失败销毁新资源并回绑旧图 |
| 聚光图集 | `spot_shadow_atlas_set` / `shadow_resolution_set` | 等尽在途帧 → 回收旧图集 → 请求开启则创建 4S×2S → 成功后回收独立瓦片 → 重写全部帧槽 binding 9 → 置待重绘 | 创建/查询失败回落独立瓦片，请求保留避免逐帧重试 |
| 渲染目标销毁 | `render_target_destroy` | 先从 `active_target` / `present_target` / `present_extra` 摘除；`render_target.target_detach` 摘出颜色/深度/MSAA 四组图像与视图，全部压入延迟队列 | 句柄无效直接返回 |
| SSAA 目标 | 倍率或输出尺寸变化 | 等尽在途帧 → 销毁旧目标 → 建 N 倍场景目标与输出尺寸解析目标；失败置 `ssaa_extent_failed` 防逐帧重试 | 本帧回落原路径 |
| Cluster 缓冲 | 簇数/列表容量增长 | 等尽在途帧 → 回收旧缓冲 → 逐槽重建 → 重写全部帧槽 binding 1..4 | 失败清零容量并告警 |

### 6.9 错误检查策略

- `结果检查.h` 是“唯一出口”约定：成功返回 true；`VK_ERROR_OUT_OF_DATE_KHR` / `VK_SUBOPTIMAL_KHR` / `VK_TIMEOUT` 记 debug 并返回 false，由调用方分支（例如交换链重建/本帧跳过）；其余记 error（带操作名与结果码名称）并返回 false。
- 门面自身大量使用“参数先校验、非法整次拒绝、状态不变”的策略；NaN 通过“取反比较”统一判非法（`!(x >= 0)`）。
- 初始化路径任一失败都调用 `shutdown`；由于各模块 `destroy` 幂等，半初始化状态可安全回收。
- 资源句柄约定：失败路径一律把出参句柄置 0；材质/网格句柄优先复用空槽。

### 6.10 默认值即回归基线

绝大多数特性遵循“默认关闭/恒等”的设计，以便不调用时画面与引入前逐字节一致：

- 阴影、聚光阴影、图集、PCSS、批量提交、Hi-Z、Cluster、GPU 剔除、间接绘制、天空盒、SSAA、MSAA 默认关闭/1；
- 泛光 0.6/0.1/1.0、阴影偏置 0.003、阴影软度 0、强度 1、聚光偏置 0.010；
- 卡通色阶 0、边缘光 0、暗部色调 (1,1,1)、卡通高光 0、描边 0；
- PBR 关闭、粗糙度缩放 1、金属度 0、能量修正关、绝对口径关；
- 清漆 0/0.15、逐物体色调白、自发光 0、UV 缩放 (1,1)/偏移 (0,0)/旋转 0、Alpha 裁剪 0；
- 雾密度 0、环境光白、半球混合 0、补光强度 0。
修改这些默认值等于改变基线画面，必须同步回归用例。

### 6.11 帧内不变量与顺序约束

以下不变量是维护 `frame_render` 时的“不得破坏”清单，均可在代码中找到对应判断或注释：

1. 槽等待先于槽写入：`slot_wait()` 必须在写 `scene_ubos[slot]` / `instance_buffers[slot]` 之前；帧模块内部还会再等一次，届时栅栏已发出，立即返回。
2. 阴影先于主 pass：阴影 pass 使用独立离屏提交并推进帧计数，必须在取主 pass帧槽之前完成；随后 `frames_wait()` 保证主 pass 采样时阴影图已写完。
3. 阴影实例缓冲独立性：阴影项来自 `pending_items` 的副本，必须显式设置 `instance_buffer = instance_buffers[shadow_slot]`；否则 binding 1（实例矩阵）为空，几何塌到原点、阴影图只剩一点（代码注释明确记录该坑）。
4. 阴影缓存失效：阴影 pass 直接整块写实例缓冲后，必须把 `instance_block_cached[shadow_slot]` 置 0；否则主 pass 复用该槽时会按旧缓存跳过更新。
5. 后处理实例先追加：后处理/SSAA/天空盒的单位实例必须在“实例缓冲写入”之前追加到 `pending_instances`，否则其字节偏移指向不存在的数据。
6. 实例容量前置校验：`mesh_draw_range` 检查 +1，`mesh_draw_instanced` 检查 +count，后处理/SSAA/天空盒各检查 +1；任一不足即拒绝或回落，绝不越界写。
7. 合批先于描述符填装：静态合批在 `pending_items` 完成全部登记之后、描述符集填装之前执行；合批只改 `instance_count`，不改变项顺序与实例区。
8. 描述符集填装先于路径分派：`item.instance_buffer` / `scene_set` / `sampler_set` 必须在调用 `frame.render*` 之前填好；逐项专属 set1 的写入前需 `frames_wait`。
9. 统计取用先于清空：`last_draw_items` / `last_instances` 必须在 `pending_items.clear()` 之前取用；`frame_merged_items` / `frame_culled_*` / `frame_cull_ms` 的转存也在清空前后保持同一顺序。
10. 主管线/格式一致：交换链格式或采样数变化后必须调用 `pipeline.pipeline_rebuild`；否则管线与附件格式不匹配，校验层报错。
11. 渲染目标句柄有效性：`render_target_set` / `render_target_present_set` 对未登记句柄回落默认路径；`render_target_destroy` 必须先摘除所有引用再延迟销毁。
12. 图集与独立瓦片互斥：图集实际生效时 `spot_shadow_tiles_ensure` 直接返回，独立瓦片在 `spot_shadow_atlas_apply` 成功后全部销毁；切回独立图时按需重新创建。
13. 阴影分辨率“先建后拆”：`shadow_resolution_set` 必须在新图与全部瓦片创建、逐槽改绑成功后才销毁旧图；任一步失败必须回绑旧图并销毁新资源。
14. 管线缓存时机：载入必须在创建任何图形管线之前；写回必须在 `pipeline.destroy` 之前。
15. 关闭幂等：`shutdown` 通过 `impl->initialized` 判断是否执行“已初始化段”；其余复位无条件执行，允许在 `init` 中途调用。

## 七、模块运行链路详例

### 7.1 初始化到首帧

调用方：

```cpp
Renderer renderer;
Renderer_Config config;
config.width = 1280; config.height = 720;
if (!renderer.init(config)) { /* 失败已逆序回退 */ }
// 装载资源、设置场景 …
renderer.frame_render();
```

逐步链路：

1. `Renderer::init(config)`
   - 校验 `width/height != 0`、`frame_overlap ∈ [1,3]`；Release 下 `validation = false`。
   - 依次装配 Platform → Device（实例）→ Platform（表面）→ Device（物理/逻辑设备）→ Memory。
   - `swapchain.build` 首次单采样；`msaa_supported_max` 探测后如请求 >1 则销毁并重建多采样交换链；`frame_overlap` 下调到图像可用信号量数。
   - 实例容量钳制、线程池启动、并行阈值下发 → `frame.build`。
   - 着色器加载、`pipeline.build`、默认场景管线、描边管线、计算上下文与能力探测。
   - 逐帧槽创建场景 UBO（写视图投影/光照/点光/聚光/雾/环境/补光/光泽度/高槽/阴影/PBR 初值）、绑定 set0、绑定 Cluster 占位、创建实例缓冲与可选间接命令缓冲。
   - 纹理模块创建 2×2 白纹理与 1×1×6 白立方体，写满全部帧槽 set1；网格、渲染目标、字体、文字宿主绑定、相机宽高比、UI 通道、事件桥接、原生 UI、UI 管线与 UI 渲染器。
   - 记录配置与开关，`initialized = true`；按配置启用 Hi-Z / Cluster；最后创建阴影目标、写各帧槽 binding 1、创建聚光瓦片 0。
   - 任一环节失败：`shutdown()` 逆序回收并返回 false。

2. 首次 `Renderer::frame_render()`
   - `platform.events_pump()` 把 SDL 事件喂入输入聚合器与 UI 通道；`input.frame_advance` 锁存本帧输入；`ui.frame_begin` 命中测试；按文本框焦点启停平台文本输入。
   - 组装 `Frame_Ui_Callback{ &Impl::ui_draw_entry, impl.get() }`。
   - 若 `close_requested()` 或 `minimized()`：清空 `pending_items` / `pending_instances`，返回 true。
   - 读取窗口尺寸；若 `resized_consume()` 且尺寸非零：`swapchain_rebuild_deferred` + `pipeline_rebuild`。
   - 刷新相机宽高比。
   - ⑤a 由方向光构造光源空间矩阵（单级或 2/3 级），写 `light_view_proj` / `light_view_proj_far` / `light_view_proj_far2`；聚光瓦片矩阵与槽位映射。
   - ⑤b 若阴影开启且有待投影项：算签名；签名不同则等 `slot_wait`、写实例缓冲、组装阴影项（阴影管线 + 光源矩阵推送）、按级联/瓦片 `render_to_target`（或批量提交），随后 `frames_wait`，记录签名与统计。
   - 取主 pass 帧槽 `slot`，`slot_wait`；Cluster 开启时上传光源记录与簇数据。
   - `text.frame_begin` 推进文字时钟；组装 980 浮点场景块（视图投影、光照、点光/聚光、雾、环境、补光、级联矩阵、阴影参数、PBR、卡通、天空盒、PCSS、Cluster、聚光阴影矩阵/跨度/映射/偏置/质量缩放）。
   - 按 16 字节单元差异上传场景 UBO。
   - 若设置同帧后处理/SSAA/天空盒：向实例存储追加单位矩阵实例并记录字节偏移。
   - 上传实例缓冲（首帧整块写入）。
   - 静态合批（默认开启）。
   - 为本帧绘制项填装 set0/set1 与实例缓冲句柄；逐项采样快照批量写入专属 set1。
   - 追加天空盒绘制项（如启用）。
   - 分派路径：SSAA / 同帧后处理链 / 离屏 / 交换链；`frame.render*` 内部取图像、录制、提交、呈现，UI 阶段回调最后执行。
   - 结算 `last_draw_items` / `last_instances` / 合批收益 / 剔除计数与耗时；清空登记区。
   - 若请求回读且帧模块未产出像素则返回 false；若 `rebuild_needed` 且本帧未重建则重建交换链与管线；`++frame_count`，返回 true。

首帧结束时：交换链完成首次呈现，阴影图（若开启）已生成，`Frame_Stats::frames = 1`。

### 7.2 一帧的完整驱动（装配 → 录制 → 提交 → 呈现）

以“阴影开启 + 单级后处理 + 原生 UI + 外部 ImGui”配置为例：

```
frame_render
 ├─ platform.events_pump → input.event_feed / ui_channel.event_dispatch
 ├─ input.frame_advance → ui.frame_begin → input.text_input_enable
 ├─ 最小化/关闭检查（挂起帧只清登记区）
 ├─ resize 检查 → swapchain_rebuild_deferred → pipeline_rebuild
 ├─ 光源空间矩阵（级联 1..3）+ 聚光瓦片矩阵/槽位映射
 ├─ 阴影 pass
 │   ├─ shadow_signature_build
 │   ├─ 相同 → shadow_reuses++，复用阴影图
 │   └─ 不同 → slot_wait → 写实例缓冲 → 阴影项(投影管线+光源矩阵)
 │              → 逐级联 render_to_target / 逐瓦片(独立图或图集子视口)
 │              → (批量提交开关) render_to_targets_batch
 │              → frames_wait → 记录 shadow_passes / shadow_submits / gpu_shadow_ms
 ├─ slot = frame.slot_index_get(); slot_wait
 ├─ Cluster：light_records 上传 + cluster_data_build + 簇缓冲上传（可选）
 ├─ scene_block[980] 组装 → 差异上传 → scene_upload_bytes += 实际字节
 ├─ 追加后处理/SSAA/天空盒单位实例
 ├─ instance_buffer 差异扫描（可并行）→ 分段上传 → instance_upload_bytes += 实际字节
 │   → 缓存回写（可并行）
 ├─ batch_adjacent_items（主 pass）
 ├─ 描述符集：pending_items 逐项设 set0/set1；采样快照批量写专属 set1
 ├─ 天空盒项（如启用）
 ├─ 路径分派
 │   ├─ frame.render_chain_present：场景 → 目标组轮转 N 级 → UI → 呈现
 │   ├─ frame.render_to_target：场景 → 离屏 → UI（不呈现）
 │   └─ frame.render：取图像 → 场景 → UI → 呈现
 │        场景退场回调 hiz_post_scene_entry（Hi-Z 开启时）
 ├─ 统计结算：last_draw_items/last_instances/merged/culled/cull_ms
 ├─ pending_items/pending_instances/pending_push_constants 清空
 ├─ 回读交付（请求时）
 ├─ rebuild_needed 且未重建 → 重建交换链与管线
 └─ ++frame_count
```

关键副作用：

- 每帧对帧槽资源的写都在 `slot_wait` 之后；阴影 pass 的提交在取主 pass 帧槽之前完成，并用 `frames_wait` 保证主 pass 采样安全。
- UI 阶段由帧模块在场景/后处理之后调用 `ui_draw_entry`；原生 UI 先画，外部 UI 后画，故外部 UI 在最上层。
- 统计在清空登记区之前取用，保证 `last_draw_items` / `last_instances` 与“实际交给录制的项”同源。

### 7.3 场景装载与资产接入

应用层典型序列：

```
// 1) 网格
Mesh_Handle mesh;
renderer.mesh_load_obj(mesh, "assets/场景.obj");        // OBJ 解析在 Asset 模块；按 usemtl 建分段
// 2) 材质（与 OBJ 的 usemtl 顺序对齐）
std::vector<Material_Handle> materials;
std::vector<std::string> names;
renderer.material_load_mtl(materials, "assets/场景.mtl", &names);
// 3) 纹理（MTL 已自动加载 map_Kd/map_Bump；也可手动 texture_load_file）
// 4) 相机与光照
Camera_Data camera; Light_Data light; Fog_Data fog;
renderer.scene_apply(camera, light, fog);
// 5) 逐物体绘制（分段材质 + 逐实例覆盖）
Material_Instance_Data inst{};
inst.模板 = materials[0];
inst.use_tint = true; inst.tint[0..3] = ...
renderer.mesh_draw_sections(mesh, transform, materials.data(), materials.size(), &inst);
// 6) 下一帧 frame_render 才实际绘制
```

链路上的门面动作：

1. `mesh_load_obj`：`obj_mesh_load` 解析出 `Mesh_File_Data`（顶点/索引/分段），再 `mesh.mesh_create(handle, data, sections)`；失败句柄 0。
2. `material_load_mtl`：解析为 `Mtl_Material` 列表；逐项构造 `Material_Data`（`tint_override = true`、`pbr_override = true`、粗糙度由 Ns 换算并钳 0.06..4、自发光取 Ke 亮度、`d < 0.999` 设 `alpha_cutoff = 0.5`），加载 `map_Kd` / `map_Bump` 为纹理；调用 `material_load`；任一失败回退本次已建材质与纹理。
3. `material_load`：字段级校验与归一；若未指定管线且需要非默认组合，按“混合档 × 8 组合”查表/登记共享管线；句柄优先复用空槽。
4. `scene_apply`：相机五项 + 光源选择/预算 + 逐条点光/聚光 + 阴影全套参数 + 雾/环境光/补光 + PBR/卡通/描边；相机非法整次拒绝。
5. `mesh_draw_sections`：若网格有分段，逐段 `material_bind_set(materials[slot])`、套用 `Material_Instance_Data`、`mesh_draw_range`；否则按材质数均分索引；结束后 `material_bind_set(0)`。
6. `mesh_draw_range`：取网格记录 → 区间校验 → 视锥剔除（可跳过登记）→ 追加 28 浮点实例 → 组装 `Frame_Render_Item` → 写推送块（颜色/法线/UV/清漆）→ `outline_item_push`（如开启）→ `pending_items.push_back`。
7. 下一次 `frame_render` 按 §7.2 消费。

注意：公共头中的 `Asset_Scene` / `Asset_Object` 目前没有门面入口消费（见【待确认：6】）；“装配”仍在应用层完成，渲染层只接收句柄与逐项绘制清单。

### 7.4 后处理链与阴影开关变更

后处理链变更（帧间调用）：

```
Post 管线：renderer.pipeline_load(h0, "泛光提取.vert.spv", "泛光提取.frag.spv");
          renderer.pipeline_load(h1, "泛光叠加.vert.spv", "泛光叠加.frag.spv");
目标组：  uint64_t targets[2];
          renderer.render_target_create(targets[0], w, h);
          renderer.render_target_create(targets[1], w, h);
          renderer.render_target_present_chain_set(targets, 2);
链：      renderer.post_chain_set(handles, 2);
逐级参数：renderer.post_stage_param_set(0, 0.8, 0.2, 1.2);
          renderer.post_stage_color_set(1, 0.1, 0.0, 0.0);
```

门面动作：

1. `render_target_create` 转交渲染目标模块；句柄 ≥1。
2. `render_target_present_chain_set`：`count=0` 清除；句柄空/超 `PRESENT_TARGET_MAX`/任一句柄未登记整组拒绝；成功写 `present_target = handles[0]`、`present_extra = handles[1..]`。
3. `post_chain_set`：级数 ≤8；任一句柄未登记整链拒绝；成功后清除全部逐级专设参数/颜色/extra（旧下标失效）。
4. 下一次 `frame_render`：`post_frame = true`；`present_extra` 非空且链长 ≥2 才走链路径；`post_mesh_ensure`；逐级 `pipeline_by_handle_get` 取管线；`post_sets_bind` 把目标视图组写入后处理集；组装每级全屏项（`post_params` / `post_color` / `post_extra`）；`frame.render_chain_present`。

阴影开关变更：

```
renderer.shadow_enable_set(true);          // 懒登记阴影管线（RGBA8 UNORM、单采样）
renderer.shadow_resolution_set(2048);      // 等尽在途帧 → 建新图/瓦片 → 改绑 → 销毁旧图
renderer.spot_shadow_all_set(true);        // 按槽位补齐瓦片 → shadow_pass_ready = false
renderer.spot_shadow_atlas_set(true);      // 4×2 图集 → 回收独立瓦片 → 重绑 binding 9
renderer.shadow_pcss_set(true, 24, 8);     // 仅着色器采样参数
renderer.shadow_batch_submit_set(true);    // 段数 >1 时一次提交
```

门面动作与失败回退：

- `shadow_enable_set(true)` 首次调用：加载 `阴影.vert/frag.spv`，按 `VK_FORMAT_R8G8B8A8_UNORM`、`cull_none = true`、单采样登记管线，记入 `extra_pipelines`；失败保持关闭。
- `shadow_resolution_set`：仅 512/1024/2048；等 `frames_wait`；建新阴影图 + 已存在的各聚光瓦片；取新视图；逐帧槽改绑 binding 1 与 binding 9；全部成功后才销毁旧目标；图集按新边长重建；`shadow_pass_ready = false`。
- `spot_shadow_all_set(true)`：按“槽位一一对应”或“聚光灯数量压缩”计算所需瓦片数，`spot_shadow_tiles_ensure`；`shadow_pass_ready = false`。
- `spot_shadow_atlas_set(true)`：`spot_shadow_atlas_apply` 等 `frames_wait`、回收旧图集、建 4S×2S、成功后销毁独立瓦片、逐帧槽写 binding 9 的 8 个元素；创建失败回落独立瓦片但保留请求。
- `shadow_batch_submit_set(true)`：只改标志；下一次阴影重绘按段数决定单次批量提交。

### 7.5 交换链重建与 MSAA 切换

### 7.7 失败与降级链路

门面在四个层级上处理失败，降级方向始终是“保持上一可用状态或回落既有路径”，而不是中断帧循环：

| 层级 | 典型入口 | 失败表现 | 降级结果 |
| --- | --- | --- | --- |
| 初始化 | `platform.build` / `device.build_*` / `memory.build` / `swapchain.build` / `frame.build` / `pipeline.build` / 纹理/网格/渲染目标/字体构建 | 返回 false | 立即 `shutdown()` 逆序回收；`init` 返回 false |
| 可选特性初始化 | 描边管线、计算上下文、自检管线、Hi-Z 生成管线、Cluster 光源缓冲 | 加载/创建失败 | 仅告警；对应特性保持关闭；主渲染路径不受影响 |
| 帧内资源 | UBO/实例/簇缓冲写入失败、阴影附件查询失败、后处理目标查询失败、管线失效 | 返回 false 或告警 | 资源写入失败让 `frame_render` 返回 false；附件/管线失败回落原路径 |
| 交换链与呈现 | `swapchain.rebuild` 失败、`rebuild_needed`、`VK_ERROR_OUT_OF_DATE_KHR` | 告警、返回 false 或置标志 | 保留旧链本帧继续；帧末再试；下次 `frame_render` 重建 |

典型过程：

1. `VK_ERROR_OUT_OF_DATE_KHR`：帧模块返回 `rebuild_needed = true`；门面在帧末调用 `swapchain_rebuild_deferred` + `pipeline_rebuild`；若尺寸为零则跳过，下一帧继续。
2. MSAA 重建失败：`swapchain.sample_count_set(previous)` 恢复采样数；`msaa_samples` 保持原值；本帧不改变其他状态。
3. 阴影分辨率切换失败：销毁新阴影图/新瓦片，旧图与旧绑定保持；`shadow_size` 不变。
4. 图集创建失败：`spot_shadow_atlas_target = 0`、`spot_shadow_atlas = false`，`spot_shadow_atlas_requested` 保留；独立瓦片继续工作。
5. Hi-Z 尺寸重建失败：`hiz.destroy()`、`hiz_enabled = false`；软粒子深度档位回落 0；主渲染不受影响。
6. 后处理链含已卸载管线：`items_ready = false`；本帧记录告警并回落交换链路径。
7. 渲染目标句柄失效：`render_target_set` / `render_target_present_set` 回落默认路径；`render_target_destroy` 摘除引用后延迟销毁。
8. 像素回读未兑现（挂起/过期/容量不足）：`readback_request.bytes == 0` 时记录 error 并返回 false；尺寸出参保持 0。
9. 初始化中途失败：已创建模块由 `shutdown` 幂等回收；`initialized` 仍为 false，后续 `valid()` 返回 false。

### 7.8 并行实例处理链路（`render_threads > 0`）

以一次大批量 `mesh_draw_instanced(count = 4096, transforms != nullptr)` 为例：

```
mesh_draw_instanced
 → mesh_record_get（索引区）
 → mesh_bounds_get（局部 AABB）
 → gpu_cull_enabled ?
     ├─ 是：gpu_instance_compact → 成功则压缩矩阵替换 transforms、更新 culled_instances
     └─ 否/失败：CPU 路径
 → CPU 路径
     ├─ instanced_cull_mask.assign(count, 0)
     ├─ count >= cull_parallel_min_instances && thread_pool.active()
     │    → thread_pool.ranges_run(count, 阈值, lambda)
     │        每块只写自己的 mask 槽（1 可见 / 0 剔除）
     │    → cull_parallel_dispatches 累加派发数
     ├─ 单线程压缩：按原顺序把可见矩阵写入 instanced_cull_scratch
     ├─ 全部不可见 → culled_items++（按一个绘制项计）→ 返回 true
     └─ 部分可见 → transforms/count 替换为可见子集
 → 容量校验（pending_instances.size() + count <= instance_capacity）
 → instance_matrices_append（写 28 浮点/实例）
 → 组装 Frame_Render_Item（instance_count = count）
 → 登记
frame_render
 → instance_block_cache 规模校验
 → 首访该槽：整块写入
 → 否则：
     ├─ instance_changed_mask.assign(instance_count, 0)
     ├─ instance_count >= instance_scan_parallel_min && thread_pool.active()
     │    → ranges_run 并行写各自掩码（与单线程逐字节一致）
     ├─ 单线程按掩码合并连续变化段 → buffer_write
     ├─ 缓存回写：并行按实例分块写各自 28 浮点槽
     └─ instance_block_count[slot] = instance_count；cached = 1
```

该链路的关键不变量：

- 并行只发生在“每实例独立槽”的写操作上；压缩/分段扫描等有顺序依赖的部分始终单线程。
- 并行阈值可运行期调整（`cull_parallel_min_instances_set` / `instance_scan_parallel_min_set`），只影响主机耗时，不影响剔除集合、实例顺序与画面。
- GPU 压缩失败会静默回落 CPU 路径；两条路径的视锥判定口径一致（GPU 用保守球判定，CPU 可见集是其子集）。
