## 二、模块功能介绍

本模块是 `EngineSystem` 层对「世界」的最小事实集合：把场景描述、关卡文本、场景清单、粒子状态与逻辑帧这几类与图形 API 无关的事实，集中成一组可被渲染层与上层应用单向消费的中立数据结构与纯函数。它不持有任何 GPU 句柄，也不包含任何平台窗口 / 交换链概念。

**负责的四件事**

1. **场景中立数据契约**：`场景数据.h` 定义相机、光照（方向光 / 环境光 / 点光 / 聚光 / 阴影 / PBR / 卡通描边 / 光源选择 / 级联 / PCSS / 预算）、雾、点光源查询快照、以及扁平兼容聚合 `Scene_Data`。这些类型在 2026-11-07 由渲染层迁入系统层，渲染层保留 `Engine/EngineRenderer/src/render/Scene/场景数据.h` 作为纯转发头，保证「类型唯一定义」只有系统层一处。
2. **关卡文本 ↔ 关卡数据的文本层职责**：`level_text_read` 把行式关卡文件解析为 `Level_Data`；`level_text_write` 按固定顺序写出；不做资产文件存在性校验、不建资源、不做场景应用。材质实例声明提供查 / 改 / 增 / 删四个纯表操作。
3. **场景清单文本解析**：`scene_manifest_parse` 读清单文件，`scene_manifest_parse_lines` 解析内存行集合（关卡文件内嵌的 `mesh` / `mtl` / `place` 段落即走此入口）。只做语法与「ID 是否被引用」的静态检查，不校验 OBJ / MTL 是否存在。
4. **粒子纯数据与 CPU 参考池**：`粒子数据.h` 固定 CPU 模拟与 GPU 缓冲共享的字段布局；`Particle_System` 提供容量管理、LIFO 分配回收、固定步 CPU 模拟（与 GPU 推进同公式同顺序）、确定性 LCG 发射。

**附带的一件小事**：`逻辑帧.h` 提供全局逻辑帧率与逻辑帧计数的加锁读写，供系统层各模块按帧取模决定作用时机。它是模块间的公共标量，不属于任何具体子系统。

**明确不负责**

- 不创建 / 销毁 GPU 资源，不调用 `mesh_load_obj` / `material_load_mtl`，不校验 OBJ / MTL 文件是否存在。
- 不执行 `scene_apply`（相机 / 光照 / 雾提交给渲染器），不实现装配顺序与失败回退；这些属于渲染层 `Engine/EngineRenderer/src/render/Scene/场景装配.h` 的 `level_bridge_load` / `scene_bundle_load` / `level_bridge_draw`。
- 不扫描目录、不枚举关卡、不维护「当前关卡」之类的会话状态；关卡选择由调用方传入路径决定。
- 不驱动主循环，不调用 `Logics::frame_tick`；何时推进逻辑帧由外部主循环约定。
- 不做异步 IO、不做缓存、不做资源热重载。

**依赖边界**

- 仅依赖 `EngineFoundation`：日志运行包、`detail::string_to_path`（UTF-8 字符串转 `std::filesystem::path`）、`detail::text_trim` / `detail::carriage_return_trim` / `detail::float_parse`、`detail::finite_check` / `detail::unit_interval_check`。
- 不反向被渲染层依赖；依赖方向为 `EngineFoundation -> EngineSystem -> EngineRenderer` 单向。
- 粒子状态数组通过裸指针导出（`data_get` / `alive_get`），渲染层据此上传 GPU 缓冲，本模块不感知缓冲格式。

**关键约束**

- 全部结构为纯数据（`std::string` / `std::vector` 除外），无虚函数、无句柄、无第三方类型。
- 文本读取采用「全有或全无」：任何失败都把输出清空（见 §六 6.1 的失败清空守卫）。
- 文本输入有硬上限：文件 2 MiB、资产行 20000、材质实例 256、点光 / 聚光各 8 盏（见 §六 6.2）。
- 浮点写出统一 `%.9g`，目标是 32 位浮点逐位往返一致（见 §六 6.3）。
- 粒子模拟固定步、固定运算顺序、固定 LCG，保证 CPU / GPU 逐粒子可对照（见 §六 6.4）。

## 三、模块公开接口

本节只写头文件中真实存在的声明；语义以 `.cpp` 实现为准。所有类型均位于命名空间 `engine`。字段名为中文的成员（`Level_Material::实例名` / `模板`）与英文成员混排，此处按源码原样记录。

### 3.1 Camera_Data

定义于 `Engine/EngineSystem/src/world/data/scene/Level/场景数据.h`。默认值与迁入前完全一致。

| 字段 | 类型 | 默认值 | 语义与取值 |
| --- | --- | --- | --- |
| `position` | `float[3]` | `{0.0f, 0.0f, 3.0f}` | 相机位置（世界坐标） |
| `target` | `float[3]` | `{0.0f, 0.0f, 0.0f}` | 相机注视点（世界坐标） |
| `fov` | `float` | `1.0472f` | 垂直视场角，单位弧度（默认约 60 度） |
| `near_plane` | `float` | `0.1f` | 近裁剪平面距离 |
| `far_plane` | `float` | `100.0f` | 远裁剪平面距离 |
| `ortho` | `bool` | `false` | 正交投影开关；假 = 透视 |
| `ortho_height` | `float` | `2.0f` | 正交投影的垂直可见高度（世界单位；仅 `ortho` 为真时生效） |
| `up` | `float[3]` | `{0.0f, 1.0f, 0.0f}` | 相机上方向（世界坐标；注释要求长度非零，view 矩阵内部按 glm 语义处理） |
| `aspect` | `float` | `0.0f` | 宽高比覆盖；0 = 跟随窗口，> 0 时固定该比例 |
| `clear_color` | `float[4]` | `{0.05f, 0.05f, 0.10f, 1.0f}` | 清屏色 RGBA，分量 0..1 |

约束：本结构自身不做合法性校验。`level_bridge_load`（渲染层）在使用前单独校验 `fov > 0 && fov < π && near_plane > 0 && far_plane > near_plane && (!ortho || ortho_height > 0)`，不通过则拒绝装载（见 §七 7.1）。

### 3.8 关卡文本语法

依据 `关卡文本.h` 的文档块与 `关卡文本.cpp` 的实际解析分支整理。整体为行式格式：`<段> <键> <值…>`；首 token 以 `#` 起首为注释，空行忽略。文件必须是 UTF-8，按二进制读取，行尾 `\r` 由 `carriage_return_trim` 去掉。

**整体约束**

- 文件非空且 ≤ 2 MiB（`MAX_FILE_BYTES = 2ull * 1024 * 1024`）。
- `version` 行必须为 `1`：解析器读整数后要求 `value == 1`，否则失败【待确认：6】。
- 未知段（任何不匹配 `level` / `version` / `camera` / `light` / `fog` / `material` / `mesh` / `mtl` / `place` 的首 token）一律失败。
- 未知键（`camera` / `light` / `fog` 下的键）一律失败。
- 文件中未出现 `version` 行时沿用默认 1。

**段：level**

```
level <名称>
```

取 `level` 之后整行剩余文本并去首尾空白；可以为空。名称内含换行会破坏写出，写出侧拒绝。

**段：version**

```
version 1
```

必须严格等于 1；`int_parse` 只接受可选负号加十进制数字串。

**段：camera**

逐行一个键。字段数必须精确（`floats_read` 读满后若还有多余 token 即失败）。

| 行 | 字段数 | 目标字段 |
| --- | --- | --- |
| `camera position x y z` | 3 浮点 | `camera.position` |
| `camera target x y z` | 3 浮点 | `camera.target` |
| `camera up x y z` | 3 浮点 | `camera.up` |
| `camera clear r g b a` | 4 浮点 | `camera.clear_color` |
| `camera fov v` | 1 浮点 | `camera.fov` |
| `camera near v` | 1 浮点 | `camera.near_plane` |
| `camera far v` | 1 浮点 | `camera.far_plane` |
| `camera ortho 0 或 1` | 1 整数 | `camera.ortho` |
| `camera ortho_height v` | 1 浮点 | `camera.ortho_height` |
| `camera aspect v` | 1 浮点 | `camera.aspect` |

| 行 | 字段数量与顺序 | 目标 |
| --- | --- | --- |

| `light color r g b` | 3 浮点 | `color` |

| `light specular intensity shininess` | 2 浮点 | `specular_intensity`、`specular_shininess` |

| `light fill_color r g b` | 3 浮点 | `fill_color` |

| 行 | 字段 | 目标 |
| --- | --- | --- |
| `fog color r g b` | 3 浮点 | `fog.color` |
| `fog density v` | 1 浮点 | `fog.density` |
| `fog range start end` | 2 浮点 | `fog.start`、`fog.end` |
| `fog mode n` | 1 整数 | `fog.mode` |
| `fog height_falloff v` | 1 浮点 | `fog.height_falloff` |

**段：material**

```
material <实例名> <模板材质名> [tint r g b a] [emissive v] [toon steps rim specular] [pbr roughness metallic] [clearcoat strength roughness]
```

- 实例名与模板材质名必填，均为无空白 token；实例名在同一关卡内不得重复（逐条线性比对，重复即整份失败）。
- 覆盖项顺序固定为 tint → emissive → toon → pbr → clearcoat；每个最多一次；后置项之后再出现前置项即失败。
- 数值范围：tint 四通道 0..1；emissive 0..1；toon 色阶 0..8、边缘光与高光 0..1；pbr 粗糙度 (0.05, 4]、金属度 0..1；clearcoat 强度 (0, 1]、粗糙度 0.03..1。
- 上限 256 条（`MAX_LEVEL_MATERIALS`）。

**段：mesh / mtl / place（资产声明）**

```
mesh  <网格ID> <OBJ 路径（余下整行，可含空格）>
mtl   <材质ID> <MTL 路径（余下整行，可含空格）>
place <网格ID> [材质ID] <x> <y> <z> <sx> <sy> <sz> [<rx> <ry> <rz>]
```

- `mesh` / `mtl`：ID 一个 token，路径取余下整行并去首尾空白；路径为空即失败。
- `place`：网格 ID 必填；材质 ID 可省略；其后至少还有一个 token；具体坐标 / 缩放 / 旋转字段由清单解析器在装配阶段严格校验。
- 读入时只做上述最少检查，整行去首尾空白后原样追加到 `asset_lines`；上限 20000 行（`MAX_ASSET_LINES`）。

**写出顺序**

`level_text_write` 固定按以下顺序落盘：

1. 注释行 `# 白银纪元 · 关卡文件（方向六；第四百二十九轮）`
2. `level` → `version`
3. 相机 10 行（position / target / up / fov / near / far / ortho / ortho_height / aspect / clear）
4. 光照按序：direction / color / intensity / ambient / specular（2 值）/ attenuation_mode / ambient_color / ambient_ground / ambient_hemisphere / fill_direction / fill_color / fill_intensity / specular_scale（2 值）/ shadow（5 值）/ spot_shadow（开关 ＋ 恒写 3 个质量值）/ spot_shadow_index / spot_shadow_all / spot_shadow_bias_auto / 非默认槽位的 spot_shadow_quality / 非零槽位的 spot_shadow_priority / pbr / toon / outline / 有效点光逐盏 / 有效聚光逐盏
5. 雾 5 行
6. 全部 `material` 行（先于资产行）
7. `asset_lines` 原样逐行

浮点统一 `%.9g`（`number_text`）；整数用十进制；`spot_shadow_quality` 只写软度或强度缩放不等于 1 的槽位；`spot_shadow_priority` 只写非 0 槽位。

**写出前校验（`level_write_validate`）**

- `version ≥ 1`（不要求等于 1）。
- 相机全部浮点有限（position / target / up / fov / near / far / ortho_height / aspect / clear_color）。
- 光照主要浮点有限（direction / color / intensity / ambient / specular 两项 / ambient_color / ambient_ground / ambient_hemisphere / fill_direction / fill_color / fill_intensity / directional_specular＋fill_specular / shadow_bias＋softness＋strength / pbr_roughness＋metallic / toon_rim / toon_shadow_tint / toon_specular / outline_width / outline_color）。
- 聚光阴影质量：bias 0..0.05、softness 0..1、strength 0..1；`spot_shadow_index` 0..7；`spot_shadow_all` / `spot_shadow_bias_auto` 为 0/1。
- 逐槽位软度缩放 0.25..4、强度缩放 0..1；32 个 `spot_shadow_priority` 全部有限。
- 有效点光 / 聚光槽位（受 `point_count` / `spot_count` 且不超过 8 限制）的位置、颜色、半径、强度、高光、光泽度有限。
- 雾：color / density / start＋end / height_falloff 有限。
- 每条材质：实例名与模板非空且不含空格 / 制表 / 回车 / 换行；启用的覆盖项数值有限且在各自范围内。

### 3.9 关卡文本与材质实例函数

均声明于 `关卡文本.h`，实现于 `core/关卡文本.cpp` 与 `core/关卡变换.cpp`。

#### bool level_text_read(const std::string& path, Level_Data& out)

把关卡文本读入 `out`。

- 前置：`path` 非空；文件可 `file_size` 且无错误；字节数非 0 且 ≤ 2 MiB；可打开。
- 失败行为：任一检查或解析分支失败均返回 `false`，并通过 `清空守卫` 把 `out` 重置为默认 `Level_Data()`；同时写 `logger.warn`，前缀为「关卡::」。
- 成功行为：`out` 为文件内容的完整映射；未出现的字段保留默认值；`asset_lines` 为原文行；`materials` 按出现顺序。
- 不做：资产存在性、相机合法性、材质模板是否存在、`place` 引用完整性。

#### bool level_text_write(const Level_Data& level, const std::string& path)

把关卡数据写成文本。

- 前置：`path` 非空；`level.name` 不含 `\n` / `\r`；`level_write_validate(level)` 通过。
- 副作用：先 `create_directories(parent_path())`（错误码被忽略），再以 `binary | trunc` 打开并覆盖写；写完 `flush` 并检查 `file.good()`。
- 失败行为：路径空、名称含换行、校验失败、打开失败、最终写入失败均返回 `false` 并写 warn；校验失败发生在打开文件之前，故不会破坏既有文件。
- 不做：不校验 `asset_lines` 是否可被清单解析器接受；不校验方向向量长度非零；不校验 `toon_steps ≤ 8`、`attenuation_mode` / `fog.mode` 取值范围。

#### bool level_material_find(const Level_Data& level, const std::string& name, Level_Material& out)

- 名称空 → `false`，`out` 保持入参原值。
- 按 `level.materials` 顺序取首个 `实例名 == name` 的项复制到 `out` 并返回 `true`；未找到返回 `false`。
- 纯查表，不建资源、不修改关卡、不写日志。

#### bool level_material_update(Level_Data& level, const std::string& name, const Level_Material& data)

- 名称空 → `false`，关卡不变。
- 定位首个同名项后整体替换；替换前把 `替换.实例名` 强制设为关卡内既有名称（即 `data.实例名` 被忽略）。
- 未找到 → `false`，关卡不变。
- 不做数值校验，写出前由 `level_text_write` 统一校验。

#### bool level_material_add(Level_Data& level, const Level_Material& data)

- `data.实例名` 为空 → `false`。
- 已达 256 条 → `false`。
- 已存在同名（线性扫描首个匹配）→ `false`。
- 否则追加到 `materials` 末尾并返回 `true`；保留 `data.实例名`。
- 不做数值校验。

#### bool level_material_remove(Level_Data& level, const std::string& name)

- 名称空 → `false`。
- 按顺序定位首个同名项并 `erase`，其余顺序不变；未找到 → `false`。
- 只改声明表，不回溯清理 `place` 行对已删实例的引用。

#### void level_transform_build(const float position[3], const float rotation_deg[3], const float scale[3], float out[16])

- 合成 `M = T · R · S`，列主序写出到 `out[0..15]`。
- 旋转为欧拉角、单位为度，顺序 X → Y → Z，即 `R = Rz · Ry · Rx`。
- 旋转全零时 `R` 退化为单位阵，输出为「对角缩放 ＋ 末列平移」。
- 无返回值、无失败路径、不校验输入；`out` 必须由调用方提供 16 个 float。
- 结果可直接传给渲染层 `mesh_draw` / `mesh_draw_sections` / `mesh_draw_range`。

### 3.10 Scene_Manifest 与解析入口

定义于 `场景清单.h`。纯文本行格式（UTF-8，一行一条，`#` 起首为注释）。路径相对清单文件所在目录。本模块只做文本解析，不建 GPU 资源。

#### Scene_Mesh_Ref

| 字段 | 类型 | 默认值 | 语义 |
| --- | --- | --- | --- |
| `id` | `std::string` | 空 | 网格 ID（清单内唯一） |
| `path` | `std::string` | 空 | OBJ 路径（相对清单目录，可含空格） |

#### Scene_Mtl_Ref

| 字段 | 类型 | 默认值 | 语义 |
| --- | --- | --- | --- |
| `id` | `std::string` | 空 | 材质 ID（清单内唯一） |
| `path` | `std::string` | 空 | MTL 路径（相对清单目录，可含空格） |

#### Scene_Place

| 字段 | 类型 | 默认值 | 语义 |
| --- | --- | --- | --- |
| `mesh_id` | `std::string` | 空 | 网格 ID（必须已在前文声明） |
| `material_id` | `std::string` | 空 | 材质 ID 或材质实例名；空串表示无材质 |
| `position` | `float[3]` | `{0,0,0}` | 位置（世界坐标） |
| `scale` | `float[3]` | `{1,1,1}` | 三轴缩放 |
| `rotation_deg` | `float[3]` | `{0,0,0}` | 欧拉角旋转（度；顺序 X → Y → Z，缺省全零 = 不旋转） |

#### Scene_Manifest

| 字段 | 类型 | 默认值 | 语义 |
| --- | --- | --- | --- |
| `meshes` | `std::vector<Scene_Mesh_Ref>` | 空 | 网格引用 |
| `materials` | `std::vector<Scene_Mtl_Ref>` | 空 | 材质库引用（注意与 `Level_Data::materials` 的材质实例是不同概念） |
| `places` | `std::vector<Scene_Place>` | 空 | 摆放记录 |

#### bool scene_manifest_parse(const std::string& path, Scene_Manifest& out, const std::vector<std::string>& 实例名表 = {})

- 前置：路径非空、文件可读、字节数非 0 且 ≤ 2 MiB、可打开。
- 逐行解析；空行与 `#` 注释跳过；未知指令、字段缺失、ID 重复、引用未知 ID 一律失败。
- 结束后要求至少一条 `place`，否则失败。
- 失败时通过 `清空守卫` 清空 `out`（`meshes` / `materials` / `places` 全清）并写「场景清单::」前缀 warn。
- `实例名表` 为关卡材质实例声明；`place` 的材质列命中实例名即视为合法，未命中再查 `materials` 中的材质库 ID。
- 只做静态检查，不校验 OBJ / MTL 文件是否存在。

#### bool scene_manifest_parse_lines(const std::vector<std::string>& lines, Scene_Manifest& out, const std::vector<std::string>& 实例名表 = {})

- 行内容与 `scene_manifest_parse` 完全同语法；供关卡装载复用（关卡文件里的资产段落不落成独立清单文件）。
- `lines` 为空 → `false` 并清空输出；逐行失败 → `false` 并清空；结束后同样要求至少一条 `place`。
- 不执行 `carriage_return_trim`（文件版会执行）；依赖 `text_trim` 去掉路径尾部 `\r`。

#### 清单行语法（实现即事实）

```
mesh  <ID> <路径>
mtl   <ID> <路径>
place <网格ID> [材质ID] <x> <y> <z> <sx> <sy> <sz> [<rx> <ry> <rz>]
```

- `mesh` / `mtl`：`id_and_path_read` 读一个 ID token，余下整行 `text_trim` 作为路径；路径空即失败；ID 重复即失败。
- `place`：
  - 读网格 ID；
  - 读下一个 token，若 `float_parse` 成功则视为 `position[0]`，材质 ID 留空；否则该 token 作为 `material_id`，随后必须能解析出 `position[0]`；
  - 再读 5 个浮点：`position[1]`、`position[2]`、`scale[0..2]`；
  - 若还有 token：必须正好再读 3 个浮点作为 `rotation_deg`，旋转之后不允许多余字段；
  - 网格 ID 必须在**此前已解析**的 `meshes` 中存在，否则失败；
  - 材质列非空时，必须在 `实例名表` 或**此前已解析**的 `materials` 中命中，否则失败；
  - `places` 数量上限 20000，超限失败。

### 3.11 粒子数据类型与常量

定义于 `粒子数据.h`，全部为 `engine` 命名空间下的纯数据。

#### Particle_State

单个粒子状态，32 字节（位置 12 ＋ 速度 12 ＋ 年龄 4 ＋ 寿命 4）。

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `position` | `float[3]` | 世界坐标位置 |
| `velocity` | `float[3]` | 每秒速度 |
| `age` | `float` | 已存活时间 |
| `lifetime` | `float` | 寿命；`age >= lifetime` 视为死亡 |

无默认成员初始化；由 `capacity_set` 的 `resize` 值初始化或由发射 / GPU 写入。

#### Emit_Shape

`enum class Emit_Shape : uint32_t`：`Point = 0`、`Box = 1`、`Sphere_Shell = 2`。越界值由 `particle_emitter_valid` 拒绝。

#### Force_Type

`enum class Force_Type : uint32_t`：`Attractor = 0`（引力 / 斥力点，按半径线性衰减）、`Vortex = 1`（绕轴涡流）、`Wind = 2`（恒定风向）。越界值由 `particle_params_valid` 拒绝。

#### Particle_Force_Field

40 字节，与 GPU std430 float 数组布局逐字段一致。

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `position` | `float[3]` | 力场中心 |
| `radius` | `float` | 作用半径（Wind 忽略） |
| `strength` | `float` | 强度，可负表示斥力 |
| `direction` | `float[3]` | 风方向 / 涡流轴（非 Attractor 时长度须非零，内部归一化） |
| `type` | `uint32_t` | `Force_Type` 的整数值 |
| `padding` | `float` | 对齐填充，未参与模拟 |

#### Particle_Emitter

64 字节。

| 字段 | 类型 | 默认 | 语义 |
| --- | --- | --- | --- |
| `position` | `float[3]` | 无默认 | 发射中心 |
| `extents` | `float[3]` | 无默认 | 盒半尺寸 / 球壳半径（点发射忽略；实现中球壳只用 `extents[0]`） |
| `direction` | `float[3]` | 无默认 | 主发射方向（长度须非零，内部归一化），与随机锥混合 |
| `speed_min` | `float` | 无默认 | 速度区间下界（≥ 0） |
| `speed_max` | `float` | 无默认 | 速度区间上界（≥ `speed_min`） |
| `lifetime_min` | `float` | 无默认 | 寿命下界（> 0） |
| `lifetime_max` | `float` | 无默认 | 寿命上界（≥ `lifetime_min`） |
| `shape` | `uint32_t` | 无默认 | `Emit_Shape` 的整数值 |
| `count` | `uint32_t` | 无默认 | 单帧发射数量（1..65536） |

| `sphere_radius` | `float` | 碰撞球半径；≤ 0 表示关闭 |

| `color_start` | `float[3]` | 新生端颜色 |
| `color_end` | `float[3]` | 衰老端颜色 |
| `color_enabled` | `uint32_t` | 颜色覆盖开关；非 0 时两端颜色各通道须在 0..1 |
| `edge_softness` | `float` | 软边宽度 0..1；0 = 内置 0.65 内半径 |
| `soft_depth_range` | `float` | 软粒子深度档位 0..1；0 = 关闭 |

### 3.12 粒子数值校验函数

#### bool particle_emitter_valid(const Particle_Emitter& emitter)

声明于 `粒子数据.h`，实现于 `core/粒子数据.cpp`。全部条件通过返回 `true`，任一不满足立即返回 `false`（无日志、无输出参数）：

- `shape <= static_cast<uint32_t>(Emit_Shape::Sphere_Shell)`，即只允许 0 / 1 / 2。
- `count != 0 && count <= PARTICLE_EMIT_COUNT_MAX`。
- `speed_min` 有限且 ≥ 0；`speed_max` 有限且 ≥ `speed_min`。
- `lifetime_min` 有限且 > 0；`lifetime_max` 有限且 ≥ `lifetime_min`。
- `position` / `extents` / `direction` 三组逐分量有限；`extents` 三分量均 ≥ 0。
- `direction` 长度平方 > `1e-12f`（点发射也要求方向合法，便于统一归一化）。

调用方语义：`emit` 在入口调用本函数，非法则直接返回 0（不发射、不消耗随机数），并保持既有发射器配置由调用方负责。

#### bool particle_params_valid(const Particle_Params& params)

- `gravity` 三分量、`floor_y` 有限。
- `damping` / `restitution` / `friction` 落在 [0, 1]。
- `sphere_center` 三分量有限；`sphere_radius` 有限且 ≥ 0。
- `color_enabled != 0` 时，`color_start` / `color_end` 六个分量落在 [0, 1]。
- `edge_softness` 落在 [0, 1]；`soft_depth_range` 落在 [0, 1]。
- `force_count <= PARTICLE_FORCE_MAX`；逐场：`type <= Wind`、位置与方向有限、`radius` 有限且 ≥ 0、`strength` 有限；非 Attractor 的场方向长度平方 > `1e-12f`。
- 不校验 `ground_enabled` / `color_enabled` 的取值域（任意非零即开启），不校验 `floor_y` 与球体 / 地面的几何一致性。

### 3.13 Particle_System

声明于 `粒子系统.h`，实现于 `core/粒子系统.cpp`。类自身无虚函数、无拷贝保护声明；持有三个 `std::vector` 与三个标量。

#### 公开成员

| 签名 | 语义 | 前置 / 失败行为 |
| --- | --- | --- |
| `void capacity_set(uint32_t capacity)` | 设置容量并重建池 | `capacity == 0` 钳到 1；`> PARTICLE_CAPACITY_MAX` 钳到 1048576。`particles_.resize(capacity_)`、`alive_.assign(capacity_, 0)`、重建 `free_indices_`（升序压入 0..capacity-1）、`active_count_ = 0`。收缩时超出容量的粒子数据被 `resize` 丢弃，所有存活标记清零；无日志、无返回值 |
| `uint32_t capacity_get(void) const` | 当前容量 | 直接返回 `capacity_`（默认 8192，但向量为空，见 §六 6.5） |
| `uint32_t active_count_get(void) const` | 当前活跃粒子数 | 返回 `active_count_`；仅由本类的 `spawn` / `recycle` 维护，GPU 直接改写 `alive_` 时不会同步 |
| `bool spawn(uint32_t& index_out)` | 分配一个池索引 | 回收栈空 → `false`（`index_out` 不变）；否则弹出栈顶，置 `alive_[index]=1`，`++active_count_`，返回 `true`。不初始化粒子状态内容 |
| `bool recycle(uint32_t index)` | 回收指定索引 | `index >= capacity_` → `false`；`alive_[index] == 0`（重复回收）→ `false`；否则置 0、压入回收栈、`--active_count_`，返回 `true` |
| `void clear(void)` | 清空全部粒子并复位回收栈（保留容量） | 置零 `alive_`、重建升序回收栈、`active_count_ = 0`；不清粒子状态内容，不重置随机种子 |
| `uint32_t step(const Particle_Params& params, float dt)` | 推进一个固定步，返回本步死亡数 | 遍历 `0..capacity_-1`，跳过非活跃；顺序见 §六 6.4；不校验 `params` / `dt`，`dt <= 0` 仍会累加年龄并可能回收 |
| `uint32_t emit(const Particle_Emitter& emitter, uint32_t budget)` | 发射，返回实际发射数 | 先 `particle_emitter_valid`，非法返回 0；`limit = min(emitter.count, budget)`；逐个 `spawn`，池满即 `break`；不校验 `budget` 上限 |
| `void seed_set(uint32_t seed)` | 重置随机种子 | 直接写 `rng_state_`；默认种子 12345 |
| `Particle_State* data_get(void)` | 粒子状态数组指针（长度 = 容量） | 返回 `particles_.data()`；容量未设置时可能为空指针 |
| `const Particle_State* data_get(void) const` | 同上，只读 | 同上 |
| `uint8_t* alive_get(void)` | 逐索引活跃标记（1 = 活跃，长度 = 容量） | 返回 `alive_.data()`；可能为空指针 |
| `const uint8_t* alive_get(void) const` | 同上，只读 | 同上 |

## 六、模块设计 / 实现细节

以下每条都落到具体文件 / 函数；接口签名见 §三，不在此重复。

### 6.1 关卡文本的失败原子性与语法容错

- **全有或全无**：`level_text_read` 在函数开头先 `level_reset(out)`，随后定义局部 `清空守卫 守卫{ out }`；任何 `return false` 路径都由守卫析构把 `out` 重置为默认值。成功路径最后置 `守卫.成功 = true`。`Scene_Manifest` 的两个解析入口使用同样的守卫模式（`场景清单解析.cpp`）。
- **宽容的空白与注释**：每行先 `carriage_return_trim` 去 `\r`，再 `istringstream >> tag`；取不到 tag 视为空行跳过；`tag[0] == '#'` 视为注释跳过。行内尾随空格被 token 化自然忽略。
- **严格的段与键**：`camera` / `light` / `fog` 下任何未列出的键立即失败并写 warn；首 token 不属于已知段也立即失败。即格式演进没有「忽略未知字段」的兼容策略，新增键必须改解析器。
- **字段数精确性不均**：`camera` / `fog` / `light outline` / `light specular_scale` 等经 `floats_read` 要求「不多不少」；而 `light shadow`、`light toon`、`light point`、`light spot`、`light pbr` 在 `floats_read_n` 之后未再检查尾部，多余 token 被静默丢弃（见【待确认：9】）。
- **数值词法**：所有浮点走 `detail::float_parse` —— `strtof` 且要求完整消费、结果 `isfinite`；因此 `inf` / `nan` / 尾随垃圾被拒绝，十六进制浮点会被 `strtof` 接受（实现未额外禁止）。整数走 `uint_parse` / `int_parse`，只认十进制数字（`int_parse` 允许一个前导 `-`），不接受 `+`、`0x`、前后空格。
- **体量与条数上限**：2 MiB 文件、20000 资产行、256 材质实例、8 点光、8 聚光；超限都返回 `false` 而非截断。
- **版本语义**：读侧 `version` 必须 `== 1`；写侧只要求 `>= 1`。两者不对称，见【待确认：6】。
- **部分解析后失败仍清空**：例如先读到若干 `camera` 行、再遇到非法 `light` 行，守卫会在返回时抹掉已读内容，调用方不会拿到半份关卡。

### 6.2 场景清单的解析顺序与引用完整性

- **单遍、即时校验**：`manifest_line_parse` 处理 `place` 时立刻在**已累积**的 `meshes` / `materials` 中查引用。因此 `mesh` / `mtl` 必须先于引用它们的 `place` 出现；前向引用会失败【待确认：13】。
- **材质列二义性处理**：`place` 的第二个 token 先尝试 `float_parse`；能解析为浮点即当成 `position[0]`（无材质），否则当成材质 ID。因此材质 ID 不能是纯数字形式，否则会被当作坐标。
- **旋转三元组要么全无要么全有**：读到一个额外 token 后必须连续读满 3 个浮点，再多任何 token 都失败。
- **引用校验的双表**：材质列先查 `实例名表`（来自 `Level_Data::materials`），未命中再查清单内 `materials`（MTL 库 ID）。两张表都未命中即失败。
- **仅静态检查**：不 `std::filesystem::exists` 检查 OBJ / MTL；不检查 `place.mesh_id` 对应的 OBJ 是否能加载。
- **重复 ID**：`mesh` / `mtl` 各自在插入前线性扫描已有项；重复即失败。`place` 不去重。
- **文件版 vs 内存行版**：文件版逐行 `carriage_return_trim`；内存行版不做，但因为 `>>` 与 `text_trim` 会处理尾部 `\r`，实际影响仅限极端行（例如路径中间含 `\r`）。
- **至少一条 place**：两个入口在解析完成后都检查 `out.places.empty()`；只有 `mesh` / `mtl` 的清单视为失败。

### 6.3 关卡文本往返一致性

- **浮点**：读写统一 `%.9g`。对 32 位 `float`，9 位有效十进制数字足以唯一还原，故 `level_text_read(level_text_write(x))` 的浮点字段应逐位一致（前提：写前校验通过且读取端支持全部写出的键）。
- **受支持字段子集**：写出器只覆盖具有文本键的字段（相机 10 项、光照基础项 / 阴影 / 聚光阴影 / PBR / 卡通 / 描边 / 有效光源、雾 5 项、材质实例全部覆盖项）。`Light_Data` 中无文本键的运行时调参不会落盘，包括 `light_select_mode` / `light_budget`、`spot_shadow_on`、`spot_shadow_bias_scale`、`spot_shadow_atlas`、`shadow_cascade_blend` / `shadow_cascade_count` / `shadow_cascade_far_scale` / `shadow_cascade_split`、`shadow_pcss` / `shadow_pcss_search` / `shadow_pcss_max`、`shadow_budget_bytes`、`exposure`、`shadow_texel_max`、`shadow_cascade_blend_auto`、`shadow_batch_submit`、`pbr_energy`、`pbr_roughness_absolute`。这些字段只能由运行时接口设置，关卡文本无法持久化【待确认：20】。
- **未写出的内容**：`Scene_Data` 扁平结构不参与关卡文本；`Point_Light_State` 不参与；`asset_lines` 原样写回，不做再解析。
- **可能破坏往返的典型情形**：
  1. `version > 1` 可写出但读不回（读侧只认 1）。
  2. `level.name` 的首尾空白在读取时被 `text_trim` 去掉，写出时原样输出，故带首尾空白的名称往返会变化。
  3. 调用方手工构造非法 `asset_lines` 时，写出器不校验，读回时 `level_text_read` 仍会接受（资产行只做最少检查），但后续 `scene_manifest_parse_lines` 会失败。
  4. 无文本键的 `Light_Data` 字段（见上一条）写出后不会落盘，读回时回到默认值，往返丢失。
- **写出的幂等性**：`spot_shadow_quality` / `spot_shadow_priority` 只在非默认时写行，默认值不产生文本，故「读 → 写 → 读」不增加行数。

### 6.4 粒子池的容量、分配与回收

- **LIFO 语义**：`capacity_set` 以升序 `push_back` 0..capacity-1，`spawn` 从 `back()` 弹出，因此首次分配顺序是 `capacity-1, capacity-2, ..., 0`；`recycle` 把索引 `push_back` 到尾部，下一次 `spawn` 立即复用它，符合头注释「回收后立即复用同一索引」。
- **容量收缩即清池**：`capacity_set` 无条件 `alive_.assign(capacity_, 0)` 与重建回收栈，并把 `active_count_` 归零；`particles_.resize` 收缩时丢弃尾部元素。头注释说「收缩时丢弃超出容量的粒子」，实现实际是「全部粒子标记失效」，语义上等价于清池。
- **默认构造不可发射**：`capacity_` 初值 8192，但 `particles_` / `alive_` / `free_indices_` 均为空；未调用 `capacity_set` 时 `spawn` 恒 `false`。渲染层 `Particle_Host` 构造时显式 `capacity_set` 后才可用（见【待确认：2】）。
- **`active_count_` 与 GPU 的分叉**：`active_count_` 只由 `spawn` / `recycle` 维护；若 GPU 推进着色器直接改写 `alive_` 标记，计数会与真实活跃数偏离。渲染层 `Particle_Host::active_count` 因此在非常驻模式下自行遍历 `alive_` 统计，而不是信任 `active_count_get()`。
- **状态内容不复位**：`spawn` 只置活跃标记，不清 `Particle_State`；`recycle` 也不清。复用槽位的旧位置 / 旧速度会短暂存在，直到发射或 GPU 写入覆盖；因此「刚 `spawn` 未填充」的槽位不是合法渲染数据。
- **`clear` 不重置随机状态**：`clear` 只重建活跃标记与回收栈，`rng_state_` 保留；若要确定性从头复现，需要再调 `seed_set`。
- **遍历成本**：`step` 每步遍历整个 `capacity_` 而非活跃列表，复杂度 O(容量)。容量 1048576 时即使只有一个活跃粒子也要走满一圈，这是「状态数组连续、GPU 同构」的取舍。
- **上限守护**：`capacity_set` 钳到 [1, 1048576]；`emit` 的 `limit` 取 `emitter.count` 与 `budget` 的较小值，而 `emitter.count` 已被校验 ≤ 65536；`budget` 本身无上限校验。

### 6.5 固定步模拟的运算顺序（与 GPU 对齐）

`Particle_System::step` 对每个活跃索引执行固定顺序（源码注释明确要求与 GPU 推进着色器同序，便于 1e-5 阈值逐粒子对照）：

1. `velocity[axis] += gravity[axis] * dt`（三轴）。
2. 逐力场按 `params.forces[0..force_count-1]` 顺序施加速度增量：
   - `Wind`：归一化 `direction` 后 `velocity += dir_unit * strength * dt`；方向长度 ≤ 1e-6 跳过；忽略 `radius`。
   - 其余类型先算 `relative = position - field.position`、`distance`；`distance ≤ 1e-6` 或 `distance >= radius` 跳过。
   - `Attractor`：`weight = 1 - distance / radius`；`velocity -= relative / distance * strength * weight * dt`（正 `strength` 指向中心）。
   - `Vortex`：`axis_unit = normalize(direction)`；`tangent = cross(axis_unit, relative)`；`tangent` 长度 ≤ 1e-6 跳过；`velocity += tangent_unit * strength * weight * dt`。
3. `velocity[axis] *= damping`（三轴，**每步**衰减，不随 `dt` 调整）。
4. `position[axis] += velocity[axis] * dt`（三轴）。
5. 地面碰撞（`ground_enabled != 0 && position.y < floor_y`）：`position.y = floor_y`；若 `velocity.y < 0` 则 `velocity.y = -velocity.y * restitution`；`velocity.x` / `velocity.z` 各乘 `(1 - friction)`。注意摩擦只作用于水平两轴，且反弹不乘 `damping`。
6. 球体碰撞（`sphere_radius > 0`）：`delta = position - sphere_center`，`distance`；仅当 `1e-6 < distance < sphere_radius`（粒子在球内）时：沿 `normal = delta / distance` 推出到球面；若法向速度 `normal_speed = dot(velocity, normal) < 0`，则 `normal_after = -normal_speed * restitution`，并把速度分解为「切向 × (1 - friction) ＋ 法向 × normal_after」。球外不处理；单步穿透（从球外直接跨到另一侧）不会推出。
7. `age += dt`；若 `age >= lifetime` 调用 `recycle(index)` 并 `++died`。

设计取舍：先重力、再力场、再阻尼、再积分，意味着同一子步内新增的重力 / 力场速度也会被 `damping` 衰减；`dt <= 0` 时位置不变但年龄仍累加，可能出现负步长下的「无位移死亡」。

### 6.6 逻辑帧的时序约定

- **唯一写入口径**：`frame_tick` 每逻辑帧由外部主循环调用一次，计数只增不减；模块自身不提供「每帧自动推进」的钩子，也不读取真实时间。
- **率的语义**：`logic_frames` 命名为「逻辑帧率」，但唯一的实际消费者（`Collision_Region` 的位移门控）把它当作「一个逻辑帧周期含有的帧数」：`interval = frame_rate / frequency`，再用 `frame_now - displacement_frame < interval` 判断是否到作用时机。因此 0 被当作「帧率不可用」，退化为每次都施加位移。
- **读取不是原子快照**：`frame_count_get()` 与 `logic_frames_get()` 分别加锁，调用方可能读到「率已更新、计数仍旧」的组合；没有联合读取 API。
- **回退允许但未约定**：`frame_count_set` 可写入任意值（包括小于当前值），与 `frame_tick` 注释的「只增不减」相矛盾；若被用来复位，消费者侧的 `frame_now - displacement_frame` 可能下溢（`uint64_t` 无符号减法回绕），导致门控行为异常【待确认：7】。
- **计数溢出**：`uint64_t` 递增，理论溢出点极远；未做回绕处理。

### 6.7 场景数据到运行时的装配关系

本模块只产出数据，装配全部在渲染层 `Engine/EngineRenderer/src/render/Scene/场景装配.cpp` 完成。实际映射为：

1. `level_bridge_load(renderer, level_out, scene_out, path, apply_scene)` 先清空 `level_out` / `scene_out`，再调用 `level_text_read(path, level_out)`；失败即返回。
2. 相机合法性由渲染层单独校验（`fov`、`near_plane`、`far_plane`、`ortho_height`），因为 `scene_apply` 返回 `void`、非法时静默拒绝，装配层需要显式失败。
3. 资产目录取 `path` 最后一个 `/` 或 `\` 之前的子串（保留分隔符），作为清单相对路径的基准目录。
4. `level_out.asset_lines` 非空时：由 `level_out.materials` 提取实例名表，调用 `scene_manifest_parse_lines(level_out.asset_lines, 清单, 实例名表)`；失败则清空 `level_out` 并返回。
5. 成功后渲染层按清单创建网格 / 材质、按 `place` 装配 `Asset_Scene`，失败整体回退。
6. `apply_scene` 为真时调用 `renderer.scene_apply(level_out.camera, level_out.light, level_out.fog)`；为假时只装配资产，不动全局相机 / 光照 / 雾（供展示层切换关卡）。
7. 绘制时 `level_bridge_draw` 逐对象用 `Scene_Place` 的 position / scale / rotation 调 `level_transform_build`，再 `mesh_draw_sections` 等。

关键推论：`asset_lines` 为空是合法的「空场景」（不调用清单解析）；`asset_lines` 非空但只有 `mesh` / `mtl` 没有 `place` 时，会因清单解析器「至少一条 place」的规则而失败。关卡文本与场景清单因此不是同一层语义：前者是容器，后者是资产布局。

### 6.8 关卡变换矩阵的实现约定

`level_transform_build`（`core/关卡变换.cpp`）按列主序直接写出 16 个 float：

- 角度换算 `degree_to_radian = 3.14159265f / 180.0f`；分别求 `cx/sx`、`cy/sy`、`cz/sz`。
- 旋转矩阵按 `R = Rz · Ry · Rx` 展开为 9 个 `r[row][col]`；源码注释用「先行后列记法」描述，写出的 `out` 是列主序（`out[0..2]` 为第 0 列，`out[12..14]` 为平移）。
- 缩放乘在旋转列上：`out[0..2] = R 第 0 列 * scale.x`，`out[4..6] = R 第 1 列 * scale.y`，`out[8..10] = R 第 2 列 * scale.z`；`out[3] = out[7] = out[11] = 0`；`out[15] = 1`。
- 退化情形：旋转全零 → `R = I`，输出即「对角缩放 ＋ 末列平移」，与既有手工构造一致。
- 不归一化 `scale`，不做剪切，不处理非有限值；调用方负责合法性。

### 6.9 跨成员指针读取布局（脆弱约定）

`level_write_validate` 多次以「首成员地址 ＋ 元素个数」的形式一次性校验相邻同类字段：

- `finite_many(&camera.fov, 1)`、`finite_many(&camera.near_plane, 1)` 等单成员调用安全。
- `finite_many(&light.specular_intensity, 2)` 假定 `specular_shininess` 紧随其后。
- `finite_many(&light.directional_specular, 2)` 假定 `fill_specular` 紧随其后。
- `finite_many(&light.shadow_bias, 3)` 假定 `shadow_bias` / `shadow_softness` / `shadow_strength` 三成员连续。
- `finite_many(&light.pbr_roughness, 2)` 假定 `pbr_metallic` 紧随其后。
- `finite_many(&fog.start, 2)` 假定 `fog.end` 紧随其后。
- `finite_many(light.directional_specular, 2)` 在源码中写作 `&light.directional_specular`。

当前布局下这些 float 成员确实相邻，功能正确；但这是「跨成员指针算术」，不是标准保证的数组访问。任何字段重排 / 插入都会静默改变校验覆盖面【待确认：4】。同理 `finite_many(&light.toon_rim, 1)` 等单成员调用不受影响。

### 6.10 材质实例表的线性实现

- `materials` 全程无序表，查找 / 去重 / 删除都是 O(n) 线性扫描；上限 256，最坏成本可接受。
- 读取时每插入一条材质都线性查重，故 256 条上限下最坏约 3.2 万次比较；`scene_manifest_parse` 的 `mesh` / `mtl` 查重是 20000 条上限下的 O(n²)，最坏约 2 亿次字符串比较，是本模块最明显的性能风险点（`场景清单解析.cpp`）。
- `level_material_update` 用「先复制 `data`、再强制写回既有名」的方式实现「名称以关卡内为准」；因此 `data.实例名` 与 `name` 不一致时不会改名。
- 删除不清理 `place` 引用：`level_material_remove` 只 `erase`，后续 `scene_manifest_parse_lines` 会把引用该实例的 `place` 判为「未知材质或实例」而整份失败。

### 6.11 粒子发射的确定性采样

`Particle_System::emit` 的随机序列（LCG，默认种子 12345）：

- 每个粒子按固定顺序消耗随机数：位置（`Box` = 3 次有符号采样；`Sphere_Shell` = 3 次有符号采样后归一化并乘 `extents[0]`；`Point` = 0 次）→ 速度扰动（3 次有符号采样）→ 速度大小（1 次单位采样）→ 寿命（1 次单位采样）。
- 速度方向 = `normalize(direction_unit + 0.3 * signed_vec)`；若长度 ≤ 1e-6 退化为 `direction_unit`。
- 速度大小 = `speed_min + unit * (speed_max - speed_min)`；寿命同理。
- 球壳采样若三次随机都接近 0 导致长度 ≤ 1e-6，退化为 `+Y` 方向（`shell = {0,1,0}`，长度置 1）。
- `emit` 先校验发射器，非法时**不消耗**随机数；池满时在 `spawn` 失败处 `break`，此后本帧不再消耗随机数。
- 发射不写入 `lifetime` 之外的状态；`age` 置 0，`lifetime` 按区间采样，位置 / 速度按形状与方向写满三分量。

因此「同一 `seed_set` ＋ 同一发射器 ＋ 同一预算 ＋ 同一池状态」得到逐字节一致的粒子状态；与 GPU 推进的对照依赖两侧使用同一 LCG 与同一采样顺序（本模块只保证 CPU 侧）。

### 6.12 边界与常量一致性

- `Particle_Data` 的 `PARTICLE_STRIDE = 32`、`PARTICLE_FORCE_STRIDE = 40` 只是常量；`粒子数据.h` 注释称「整体大小须与 GPU std430 布局一致（由静态断言守住）」，但该目录内没有任何 `static_assert`，编译期不会阻止结构体布局漂移【待确认：8】。
- `Particle_Params` 的实际大小 408 字节：`gravity 12 + damping 4 + floor_y 4 + restitution 4 + friction 4 + force_count 4 + forces 320 + sphere_center 12 + sphere_radius 4 + ground_enabled 4 + color_start 12 + color_end 12 + color_enabled 4 + edge_softness 4 + soft_depth_range 4`。
- `Particle_Emitter` 实际 64 字节；`Particle_Force_Field` 实际 40 字节（`12+4+4+12+4+4`）。
- `MAX_POINT_LIGHTS` / `MAX_SPOT_LIGHTS` 取 8，而 `Light_Data` 的数组容量是 32；关卡文本因此最多承载 8 盏点光与 8 盏聚光，结构体却可容纳 32【待确认：3】。`关卡文本.h` 的文档也称「光源超过 8 盏」失败。
- `Light_Data` / `Scene_Data` 的点光 / 聚光颜色与聚光方向数组只显式初始化前 4 项，第 5..32 项为 `(0,0,0)`；若上层把 `point_count` 提到 5 以上而未逐盏设色，会得到黑色光源【待确认：19】。

### 6.13 错误处理与日志策略

- 全部失败路径写 `logger.warn`，前缀固定：关卡文本为「关卡::」，清单为「场景清单::」；无 `error` / `throw`，无错误码返回。
- 数值校验函数（`particle_emitter_valid` / `particle_params_valid`）静默返回布尔，不写日志；由调用方决定是否记录。
- 文件系统错误用 `std::error_code` 而非异常（`file_size(file_path, code)`）；路径转换 `detail::string_to_path` 处理 UTF-8 → 本地路径。
- 写出时 `create_directories(parent_path(), code)` 的错误码被忽略；只有最终 `ofstream` 打开失败 / `good()` 为假才报错。
- 读取时先 `level_reset`，再用守卫兜底，保证调用方拿不到半份数据；这是本模块最重要的失败契约。

### 6.14 文件编码与路径

- 文本按 `std::ios::binary` 读写，避免 `\r\n` 的平台翻译；行尾 `\r` 由 `carriage_return_trim` 显式去掉。写出统一使用 `\n`。
- 路径参数为 `std::string`（约定 UTF-8），经 `detail::string_to_path` 转 `std::filesystem::path`；所有资产路径相对清单 / 关卡文件所在目录，由上层拼接。
- 关卡名允许中文（`std::string` 原样写入），只禁止换行；材质实例名 / 模板名在写出校验中禁止任何空白字符，以保证行式格式可逐列解析。
- 注释语言为中文；字段名中英混排是历史遗留（`Level_Material::实例名` / `模板`）。

### 6.15 头文件包含与转发

- `关卡数据.h` 直接 `#include "场景数据.h"`（同目录相对路径）；`关卡文本.h` → `关卡数据.h`；`局部命名空间使用.h` → `关卡文本.h`。因此任何 include 关卡文本的翻译单元都会拿到全部场景类型。
- `粒子系统.h` 以项目根相对路径 include `粒子数据.h`；`粒子数据.cpp` 与 `粒子系统.cpp` 用 `#include "src/world/..."` 相对实现目录的写法（与同模块其它 .cpp 的 `../局部命名空间使用.h` 风格不同）。
- 渲染层 `Engine/EngineRenderer/src/render/Scene/场景数据.h` 只做转发 include，不重复定义类型；`粒子宿主.h` 直接 include `粒子系统.h`。
- `逻辑帧.h` 只 include `Engine/EngineSystem/common/前置头文件包含.h`，依赖其间接提供的 `<mutex>` / `<cstdint>`；自身无线程池 / 时间库依赖。

### 6.16 性能取舍汇总

| 位置 | 取舍 | 量级 |
| --- | --- | --- |
| `Particle_System::step` | 遍历全容量而非活跃列表 | O(capacity) / 步；与 GPU 同构、状态数组连续 |
| `Particle_System::emit` | 每粒子多次 `sqrt`（方向 / 速度 / 球壳归一化） | 每粒子 2..3 次开方 |
| `scene_manifest_parse` | `mesh` / `mtl` 查重 O(n²) | 上限 20000，最坏约 2 亿次比较 |
| `level_text_read` | 每行一个 `istringstream` | 与文件行数同阶；无正则、无回溯 |
| `level_text_write` | 逐字段流式输出，无中间缓冲 | O(输出字节) |
| `level_material_*` | 线性查表 | 上限 256 |
| `Logics` | 每次读写一次 `mutex` | 常量开销；无读多写少优化 |

### 6.17 隐式约定与调用方义务

- `Particle_System` 必须先 `capacity_set` 才能发射；默认容量常量不代表已分配。
- 发射前须由调用方保证 `Particle_Emitter` 的 `direction` 非零，否则 `emit` 返回 0 且不写日志。
- `Particle_System::step` 假定 `params` 已由 `particle_params_valid` 校验；`step` 自身不做任何校验（`force_count > 8` 会让循环越界读取 `forces`，属未定义行为）。
- `Level_Data::asset_lines` 的合法性由清单解析器负责；`level_text_read` 的成功不保证可装配。
- `Scene_Manifest` 解析顺序敏感：`mesh` / `mtl` 必须位于引用它们的 `place` 之前。
- `Logics::logic_frames` 为 0 时消费方按「帧率不可用」处理；本模块不强制非零。
- `level_transform_build` 输出列主序，渲染层 `mesh_draw*` 直接消费；不可与行主序矩阵混用。

### 6.18 版本与兼容

- `Level_Data::version` 默认 1，注释声明「当前只接受 1」；解析器强制 `== 1`，写出器只要求 `>= 1`。
- 旧关卡文本可以缺少 `material` 段、`spot_shadow_quality` / `spot_shadow_priority` 等新键：缺失即保留默认值，属向后兼容读取。
- 新键的写出采用「默认值不落行」策略（仅 `spot_shadow_quality` / `spot_shadow_priority`），以保持旧文本体积与内容不变；但 `light spot_shadow` 行恒写三项质量值，旧读取方需能忽略尾部（注释如此声明）。
- `Scene_Data` 作为兼容聚合保留扁平字段，但与 `Light_Data` / `Fog_Data` 已出现字段漂移（缺 7 个聚光阴影字段）。

## 七、模块运行链路详例

### 7.1 链路一：关卡文本解析 → 场景数据构造 → 运行时装配

调用方（渲染层 `level_bridge_load`，`Engine/EngineRenderer/src/render/Scene/场景装配.cpp`）：

1. `level_bridge_load(renderer, level_out, scene_out, path, apply_scene)` 先把 `level_out` / `scene_out` 置默认值。
2. 调 `level_text_read(path, level_out)`：
   - `level_reset(out)` → `path.empty()` 检查 → `detail::string_to_path` → `std::filesystem::file_size`（`error_code`）→ 体量检查（非 0 且 ≤ 2 MiB）→ `ifstream(binary)`。
   - 建立 `清空守卫{ out }`。
   - 逐行 `getline` → `carriage_return_trim` → `istringstream >> tag` → 分派：
     - `level`：`getline` 取余下并 `text_trim` → `out.name`。
     - `version`：`int_field_read` 且必须为 1。
     - `camera` / `light` / `fog`：按键逐项写入 `out.camera` / `out.light` / `out.fog`；字段数不符、未知键、非有限值均 `return false`。
     - `material`：读实例名 / 模板 → 查重 → 逐覆盖项（顺序 tint → emissive → toon → pbr → clearcoat）→ 范围校验 → `out.materials.push_back`。
     - `mesh` / `mtl` / `place`：最少字段检查 → `out.asset_lines.push_back(text_trim(line))`。
     - 其它：warn 并 `return false`。
   - 成功后 `守卫.成功 = true`。
3. 渲染层校验 `level_out.camera` 的 `fov` / `near_plane` / `far_plane` / `ortho_height`；不合法则清空 `level_out` 并返回 `false`。
4. `level_out.asset_lines` 非空时：
   - 遍历 `level_out.materials` 收集 `实例名` → `实例名表`。
   - `scene_manifest_parse_lines(level_out.asset_lines, 清单, 实例名表)`（见 7.2 的行解析细节）。
   - 渲染层 `资产装配(renderer, 清单, 目录, level_out.materials, scene_out)`：按 `meshes` 加载 OBJ、按 `materials` 加载 MTL、按 `places` 填 `Asset_Scene.objects`（位置 / 缩放 / 旋转原样拷贝；材质列先查实例表再查 MTL 库）。
5. `apply_scene` 为真：`renderer.scene_apply(level_out.camera, level_out.light, level_out.fog)`——三组结构被渲染层消费为相机矩阵、光照 uniform、雾参数。为假则跳过。
6. 结果：`level_out` 保留完整关卡数据（供 UI / 调试回显），`scene_out` 持有已装配的资产句柄与对象表；任一阶段失败，`level_out` 与 `scene_out` 均为空，既有场景状态不变。

副作用与失败点：解析期不改全局状态；清空守卫保证失败无半成品；渲染层资源创建失败会整体回退（本模块不参与）。

### 7.2 链路二：场景清单加载 → 关卡选择 → 关卡装配

「关卡选择」在本模块里不是枚举或索引，而是「调用方选定一个路径」：

1. 独立清单路径：调用方调 `scene_bundle_load(renderer, scene_out, manifest_path)` → 内部 `scene_manifest_parse(manifest_path, 清单)`：
   - 路径 / 体量 / 打开检查 → `manifest_reset` → `清空守卫` →
   - 逐行 `carriage_return_trim` → `manifest_line_parse`：
     - `mesh`：`id_and_path_read` → 查重 → `meshes.push_back`；
     - `mtl`：同构 → `materials.push_back`；
     - `place`：读网格 ID → 探测下一 token（浮点则作 `position[0]`，否则作材质 ID）→ 读 5 个浮点 → 可选 3 个旋转 → 网格引用检查 → 材质引用检查（实例名表 / 已解析 MTL 表）→ 上限检查 → `places.push_back`；
     - 未知指令 / 字段缺失 / 引用未知 ID → `false`。
   - 结束后 `places` 为空 → `false`；否则 `守卫.成功 = true`。
2. 关卡内嵌清单：调用方选 `level_path` 调 `level_bridge_load`，由 `level_text_read` 得到 `Level_Data`，再把 `asset_lines` ＋ 实例名表交给 `scene_manifest_parse_lines`（行解析与上面完全同一函数）。
3. 装配：无论来源，`Scene_Manifest` 交给渲染层 `资产装配`；资产目录为「所选文件路径的父目录」，故同一份清单在不同目录下会解析到不同资产。
4. 绘制：`level_bridge_draw` 遍历 `Asset_Scene.objects`，对每个对象用 `position` / `scale` / `rotation_deg` 调 `level_transform_build` 得列主序矩阵，再按 `mesh` 与材质句柄逐段 `mesh_draw_sections`。

失败语义：任一清单解析失败都不会修改已装配场景（`scene_out` 由调用方先清空）；本模块只保证「失败时输出为空」，资源回退由渲染层负责。

### 7.3 链路三：粒子发射 → 推进 → 回收

调用方（渲染层 `Particle_Host`，`Engine/EngineRenderer/src/render/Particle/粒子宿主.h`）：

1. 构造：`Particle_Host::Particle_Host(Renderer&)` 读 `renderer.particle_capacity_get()`；若为 0 用 `PARTICLE_CAPACITY_DEFAULT`；调 `池.capacity_set(capacity)`（钳到 [1, 1048576]，重建回收栈），再 `renderer.particle_source_bind(池.data_get(), 池.alive_get(), 池.capacity_get())`。
2. 发射：`Particle_Host::emit(count)`：
   - `particle_enable_get()` 为假或 `count == 0` → 返回 0；
   - `池.emit(renderer.particle_emitter_get(), count)`：
     - `particle_emitter_valid(emitter)`：形状 / 数量 / 速度区间 / 寿命区间 / 半尺寸 / 方向长度 / 有限性；非法 → 0；
     - `limit = min(emitter.count, budget)`；
     - 逐粒子：`spawn(index)`（`free_indices_.back()` 弹出，`alive_[index]=1`）→ 按形状写位置 → 按 `direction_unit + 0.3·signed` 写速度 → 采样寿命 → `age=0`；
     - 池满 `spawn` 失败 → `break`，返回已发射数；
   - `渲染器.particle_stats_add(spawned, 0)` 上报出生数。
3. 推进：`Particle_Host::step(dt)`：
   - `particle_enable_get()` 为假 → 0；`!std::isfinite(dt) || dt <= 0` → 0；
   - `池.step(renderer.particle_params_get(), dt)`：
     - 遍历 `0..capacity-1`；跳过 `alive_[index]==0`；
     - 重力 → 力场（Wind / Attractor / Vortex，见 6.5）→ `damping` → 位置积分 → 地面 / 球体碰撞 → `age += dt`；
     - `age >= lifetime` → `recycle(index)`（`alive_=0`、压回回收栈、`active_count_--`）→ `died++`；
   - 返回 `died`；`渲染器.particle_stats_add(0, died)`。
4. 回收复用：下一次 `emit` 的 `spawn` 从回收栈尾部弹出刚刚回收的索引（LIFO），因此「死亡槽位」立刻被新生粒子复用。渲染层注释称 GPU 推进会直接改写 `alive_` 标记（`粒子宿主.h` 的 `active_count` 实现据此按标记统计），但 GPU 常驻链路使用自己的控制缓冲活跃计数（`粒子GPU推进.cpp` 的 `emit` / `step_resident` 读回控制缓冲），两条链路对「活跃」的记账口径并不完全一致【待确认：21】。
5. 绘制前：`Particle_Host::bind()` 或各入口重新 `particle_source_bind(...)`，把最新的 `data_get()` / `alive_get()` / `capacity_get()` 交给渲染器；渲染器只保存这三个指针与容量（`粒子宿主.h` 注释「渲染层只保存指针，不分配、不推进、不回收」），上传时按 32B 粒子步长（`PARTICLE_STRIDE` 约定）处理状态数组。
6. 查询：`Particle_Host::state_get(index, state)` 先检查 `index < capacity_get()` 与 `alive_get()[index] != 0`，再复制 `data_get()[index]`；`active_count()` 在非常驻模式下遍历 `alive_` 统计（因为 GPU 推进可能绕过 `active_count_`）。

副作用：本模块只改变池内数组与计数器；GPU 上传、统计展示、渲染开关（`particle_enable_get`）均属渲染层 / 应用层。

### 7.4 链路四：材质实例声明增改 → 写出 → 读回

1. `level_text_read(path, level)` 得到 `materials`。
2. `level_material_add(level, data)`：
   - `data.实例名` 空 → `false`；`materials.size() >= 256` → `false`；线性查重同名 → `false`；否则 `push_back(data)`。
3. `level_material_update(level, name, data)`：
   - 名称空 → `false`；线性定位首个同名项 → 复制 `data` 并把 `实例名` 强制写回既有名 → 赋值；未找到 → `false`。
4. `level_text_write(level, path)`：
   - 校验名称无换行、`version >= 1`、全部浮点有限、材质范围合法；失败不落盘。
   - 按固定顺序输出；材质行先于资产行；浮点 `%.9g`；启用的覆盖项才输出。
5. 再次 `level_text_read(path, level2)`：
   - `material` 行解析：实例名 / 模板 → 查重 → 覆盖项按固定顺序解析并范围校验 → 追加；
   - 结果 `level2.materials` 与写出前一致（顺序保持）。
6. `level_material_find(level2, name, out)` 验证查表；`level_material_remove(level2, name)` 删除首个匹配项，其余顺序不变。

失败点：`level_text_write` 的材质校验比 `level_material_add` / `level_material_update` 更严格（后者不做数值校验），因此先增改、后写出时错误会延迟到写出阶段暴露；删除材质不会清理 `place` 引用，读回后清单解析可能因「未知材质或实例」失败。
