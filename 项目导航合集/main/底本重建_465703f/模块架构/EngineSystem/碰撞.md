## 二、模块功能介绍

碰撞模块是 EngineSystem 层内的独立子系统，把“谁拥有碰撞几何、谁负责空间检测、谁消费碰撞结果”拆成三层，并把 Bullet 的全部类型与生命周期收拢在 `backend/` 内。模块只使用 `btCollisionWorld`，不引入 `btDiscreteDynamicsWorld`、刚体、约束或冲量求解；它回答“本帧哪些碰撞对发生了接触、接触点/法线/穿透深度/扫掠比例是什么”，不做物理响应。

三层职责：

- Collider（`Collider/`）：单个碰撞体的前端描述。只保留编号、运动通道（周期总量、本帧施加量、作用频率、生效帧）、检测方式、豁免标记与几何配置留档；碰撞对象、子部件形状全部由 `Collider_Backend` 持有。该层不出现任何 Bullet 类型。
- Collision_Proxy（`Collision_Proxy/`）：模块对外唯一投递口与事件入口。持有全部碰撞空间、按编号登记的空间归属、运动事件 JSON 表、简略结果事件开关；所有外部指令（空间构建、碰撞体构建/卸载/转移/镜像/设置、运动投递、跨越查询）都从 `event_process` 进入，所有对外通知（构建结果、跨越通知、跨越查询结果、简略结果）都从 `event_publish` 发出。同步 API（`region_detect`）是检测的唯一触发方式。
- Collision_Region（`Collision_Region/`）：一个碰撞空间内的检测执行者。持有编号分配器、碰撞体映射、活跃标志、空间边界、跨越状态与待发通知；负责按逻辑帧门控运动、组织移动体清单、调用后端执行扫掠与离散检测、做跨越判定。它不裁决碰撞结果，也不持有响应策略。
- backend（三个 `backend/` 目录）：Bullet 边界层。`Collider_Backend` 把“碰撞对象 + 部件形状 + 暂存区”封装在堆上实现体；`Region_Backend` 把“配置/调度器/宽阶段/碰撞世界”封装在堆上实现体；`Proxy_Backend` 不接触 Bullet，只做空间集合与编号归属编排。

对外职责边界：

- 模块不决定碰撞后物体应如何运动，也不提供“碰撞响应协议”。外部只能通过运动事件驱动碰撞体，通过 `region_detect` 同步取回碰撞详情或订阅 `DetectResult`。
- 模块不做碰撞分组/层过滤，只提供“同组豁免”与“同碰撞体子部件忽略对”两条最简规则。
- 模块不负责几何资源生命周期。网格通过 `Mesh_Loader::load_obj` 只读加载，网格数据由 `Geometry_Part` 与形状共同持有，模块不缓存文件、不做热重载。
- 模块不提供父子层级、质量、重力或时间步积分；运动完全由外部通过运动事件驱动。
- 跨越通知是单向事件，不接受应答；外部收到后可再发其他 `Collision` 事件完成回控，但没有与该通知关联的请求编号或回执。

第三方封闭策略：Bullet 头文件只允许出现在 `Collider/backend/`、`Collision_Region/backend/` 与 `Common/数学转换.h` 三处。前端公共面（`碰撞体.h`、`碰撞空间.h`、`代理后端.h`、`碰撞代理器.h`、`碰撞系统运行包.h`）均不出现 Bullet 类型。

关键约束：

- 多空间并存：一个进程可同时存在多个命名碰撞空间；空间之间可通过“同编号接管（转移）”与“新编号复制（镜像）”搬运碰撞体；编号由各空间自行分配，同一编号在不同空间内可重复存在，代理后端的归属映射是多重映射。
- 事件驱动解耦：外部只认识事件类别 `Collision` 与标签/字段名，不认识任何 C++ 类型；运动投递与跨越查询都是 JSON 载荷。
- 失败不抛出：除 `memory_malloc` 内部为 Bullet 形状构造包了 `try/catch`、`boundary_config_read` 为 JSON 解析包了 `try/catch` 外，模块对外一律返回 `false` / `nullopt` / 空集合并写日志。
- 单线程假设：模块内部所有容器（空间表、映射、运动表、跨越状态）均无锁；调用方必须在同一逻辑线程内串行调用事件入口与 `region_detect`。

### 3.1 Common/几何类型.h

```cpp
using Scalar = float;

class Vector3
{
public:
    Vector3() = default;
    Vector3(Scalar x_value, Scalar y_value, Scalar z_value);
    void setValue(Scalar x_value, Scalar y_value, Scalar z_value);
    Scalar x(void) const;  Scalar y(void) const;  Scalar z(void) const;
    Scalar getX(void) const;  Scalar getY(void) const;  Scalar getZ(void) const;
    Scalar length2(void) const;
    Scalar length(void) const;
    Vector3 normalized(void) const;
    Vector3 operator+(const Vector3& other) const;
    Vector3 operator-(const Vector3& other) const;
    Vector3 operator*(Scalar factor) const;
    Vector3 operator/(Scalar factor) const;
    Vector3& operator+=(const Vector3& other);
};

class Quaternion
{
public:
    Quaternion() = default;                              // 单位四元数
    Quaternion(Scalar x, Scalar y, Scalar z, Scalar w);
    void setValue(Scalar x, Scalar y, Scalar z, Scalar w);
    Scalar x(void) const;  Scalar y(void) const;
    Scalar z(void) const;  Scalar w(void) const;
    Quaternion operator*(const Quaternion& other) const; // Hamilton 积
    Vector3 rotate(const Vector3& vector) const;
    bool identity_check(Scalar epsilon = 1e-6f) const;
    Scalar length2(void) const;
    Quaternion normalized(void) const;
    bool axis_angle_get(Vector3& axis, Scalar& angle) const;
    static Quaternion from_axis_angle(const Vector3& axis, Scalar angle);
};

class Transform
{
public:
    Transform() = default;                               // 单位变换
    static Transform getIdentity(void);
    void setOrigin(const Vector3& origin_value);
    Vector3& getOrigin(void);
    const Vector3& getOrigin(void) const;
    void setRotation(const Quaternion& rotation_value);
    Quaternion& getRotation(void);
    const Quaternion& getRotation(void) const;
    Transform operator*(const Transform& other) const;   // 先 other 后自身
};
```

- `Scalar` 固定为 `float`，与 Bullet 默认标量口径一致。
- `identity_check` 以 `|w| >= 1 - epsilon` 判定单位四元数，`q` 与 `-q` 视为同一旋转。
- `Transform::operator*` 与 Bullet 一致：旋转复合 `rotation * other.rotation`，平移复合 `rotation.rotate(other.origin) + origin`。
- 类型刻意不提供点积、叉积、比较运算；叉积只在 `Quaternion::rotate` 的私有静态函数中使用。

### 3.3 Common/运动类型.h

```cpp
struct Motion
{
    Vector3 translation{ 0.0f, 0.0f, 0.0f };
    Quaternion rotation{};
    bool empty(void) const;
    Motion operator/(Scalar factor) const;
};

struct Part_Motion
{
    uint16_t part = 0;
    Motion motion;
};

struct Motion_Event
{
    Motion body;
    std::vector<Part_Motion> parts;
};
```

- `Motion` 表示一个运动周期内的总量（平移 + 旋转增量，绕自身原点）。
- `empty` 判定为“平移长度平方不大于零且旋转为单位四元数”。
- `operator/` 按因数均分：平移直接除，旋转取轴角后把角度除以因数再重建四元数；因数为零返回空运动。

### 3.4 Common/碰撞数据类型.h

```cpp
struct Collision_Result
{
    uint64_t collider_A = 0;
    uint64_t collider_B = 0;
    uint16_t part_A = 0xFFFF;    // 0xFFFF 表示无子部件信息
    uint16_t part_B = 0xFFFF;
};

struct Collision_Contact
{
    uint16_t part_A = 0xFFFF;
    uint16_t part_B = 0xFFFF;
    Vector3 point{ 0.0f, 0.0f, 0.0f };    // 两侧世界接触位置的中点
    Vector3 normal{ 0.0f, 0.0f, 0.0f };   // 由碰撞体 B 指向碰撞体 A
    Scalar depth = 0.0f;                  // 穿透深度，分离时钳零
    Scalar fraction = 1.0f;               // 扫掠命中比例，离散检测恒为一
};

struct Collision_Detail
{
    uint64_t collider_A = 0;
    uint64_t collider_B = 0;
    std::vector<Collision_Contact> contacts;
};

enum class Cross_State { inside, crossing, outside };

struct Cross_Notice
{
    uint64_t collider_ID = 0;
    std::string kind;                              // "cross" / "return" / "exit"
    Cross_State previous = Cross_State::outside;   // 转移前状态
    Vector3 position{ 0.0f, 0.0f, 0.0f };          // 判定时世界包围盒中心
    uint64_t frame = 0;                            // 判定时逻辑帧号
    uint64_t sequence = 0;                         // 本空间内单调递增序号
};

struct Cross_State_Entry
{
    uint64_t collider_ID = 0;
    Cross_State state = Cross_State::outside;
    bool known = false;                            // 假表示尚未建立基准或无几何
};

inline const char* cross_state_text(Cross_State state);   // inside / crossing / outside
```

- `Collision_Result` 与 `Collision_Detail` 的 A/B 编号均由 `pair_normalize` 归一化：较小编号恒为 A、较大编号恒为 B。
- `normal` 方向约定为“B 指向 A”；扫掠与离散两条路径都按同一规则翻转。
- `depth` 只由离散检测填充（取 `-m_distance1` 的正部），扫掠检测恒为 0；`fraction` 只由扫掠填充，离散恒为 1。
- `crossing` 不再“接触即判”：接触时用九探针，只有内外混合才判 `crossing`，见 §六.9。

### 3.5 Common/碰撞事件.h

事件类别 `collision_event::category = "Collision"`。配置入口使用事件系统协议 `event_protocol::config = "Config"` 与 `event_protocol::load = "Load"`。

外部 → 本模块（`Collision_Proxy::event_process` 消费）：

| 标签常量 | 字符串 | 必需载荷 | 可选载荷 | 语义 |
| --- | --- | --- | --- | --- |
| `region_build` | `RegionBuild` | `region` | 无 | 新建命名碰撞空间 |
| `region_unload` | `RegionUnload` | `region` | 无 | 卸载空间并注销其全部编号归属 |
| `region_state` | `RegionState` | `region`、`active`(bool) | 无 | 设置空间活跃性；未激活时检测直接返回空 |
| `region_boundary` | `RegionBoundary` | `path` | 无 | 读取边界配置文件并批量设置各空间边界 |
| `region_event_output` | `RegionEventOutput` | `region`、`enabled`(bool) | 无 | 设置该空间是否发布 `DetectResult` |
| `collider_build` | `ColliderBuild` | `region` | 无 | 在空间内新建碰撞体，结果以 `ColliderBuildResult` 回告 |
| `collider_unload` | `ColliderUnload` | `region`、`collider_ID` | 无 | 卸载碰撞体 |
| `collider_transfer` | `ColliderTransfer` | `region`、`collider_ID` | 无 | 把原空间同编号碰撞体接管到 `region` |
| `collider_mirror` | `ColliderMirror` | `region`、`collider_ID` | 无 | 在 `region` 内以新编号复制源碰撞体 |
| `collider_set` | `ColliderSet` | `region`、`collider_ID` | `geometry`、`detection_mode`、`exemption_flag` | 逐项应用碰撞体配置 |
| `collider_motion` | `ColliderMotion` | `collider_ID` | `motion`、`parts`、`frequency` | 登记运动事件（同编号覆盖旧事件） |
| `region_cross_state_query` | `RegionCrossStateQuery` | `region` | `collider_ID`、`request_ID` | 查询当前跨越状态快照 |

本模块 → 外部（发送者为 `"Collision_Proxy"`、接收者为空串）：

| 标签常量 | 字符串 | 载荷字段 | 触发时机 |
| --- | --- | --- | --- |
| `collider_build_result` | `ColliderBuildResult` | `region`、`collider_ID` | 事件驱动的构建成功后回告编号 |
| `region_cross_notice` | `RegionCrossNotice` | `region`、`collider_ID`、`state`、`previous_state`、`position`、`frame`、`sequence` | 检测后取走跨越通知，逐条发布 |
| `region_cross_state_result` | `RegionCrossStateResult` | `region`、`found`、`request_ID`、`states` | 处理查询后同步发布 |
| `detect_result` | `DetectResult` | `region`、`frame`、`results` | 该空间结果开关为真时每帧发布 |

### 4.2 Collider/backend/core/几何装配.cpp

文件内匿名命名空间：

- `memory_malloc<Object_Type>(receiver, args...)`：Bullet 形状类只声明了抛异常形式的分配算子，此处用 `try/catch` 包成失败返回。
- `mesh_shape_build(mesh_path, shape_receiver, mesh_receiver)`：`Mesh_Loader::load_obj` → `btTriangleMesh(true, true)` → `btBvhTriangleMeshShape(mesh, true, true)`；顶点按顺序写入（关闭查重）保证索引一一对应。
- `shape_build(config, shape_receiver, mesh_receiver)`：支持 `box`（`half_extent` 三正分量）、`sphere`（`radius > 0`）、`capsule`（`radius > 0`、`height > 0`、`height >= 2 * radius`，圆柱段长 `height - 2r`）、`cylinder`（半长 `(r, height/2, r)`）、`cone`（沿 Y 轴）、`mesh`（`mesh_path`）；未知类型拒绝。碰撞边距 `margin` 缺省 0.04、可选且非负，统一 `setMargin`。
- `part_ID_assign(parts, used)`：先收集显式编号并去重；缺省编号从 0 起取未占用最小值；编号上限 `0xFFFE`。
- `geometry_assemble(config, parts_receiver, ignored_receiver)`：`geometries` 数组形式逐项构建部件，支持 `part_ID`、`position`、`rotation`；单对象形式视作单部件，基准位姿由调用方写入根变换；再分配编号、解析 `part_ignore`（二元数组、编号存在、禁自忽略），最后为每个部件分配 `Geometry_Part_Object` 并挂载形状。
- `parts_refresh(impl)`：`world = root_transform * part.local_transform`，写世界变换与身份标签。
- `parts_index_rebuild(impl)`：重建 `part_ID → 下标` 映射。

成员实现：

- 构造：`impl.reset(new(nothrow) Impl())`。
- 析构：若 `impl->owner` 非空则 `owner->object_detach(*this)`。
- 移动构造/赋值：只搬移 `impl`；移动赋值前若自身仍挂载则先摘除。
- `tag_set`：写编号与边界标记并 `parts_refresh`；`tag_ID` / `boundary_check` 为空时分别返回 0 / false。
- `exemption_flag_set/get`：读写实现体字段。
- `part_ignore_set`：校验两侧部件存在，写入归一化键集合。
- `geometry_build`：装配到暂存区；失败清空暂存并置 `pending_valid = false`，成功写 `pending_parts` / `pending_part_ignored` / `pending_transform` / `pending_valid`。
- `geometry_mount`：无有效暂存返回 false；否则释放旧几何、搬移暂存、写根变换、重建编号映射、刷新世界变换。
- `geometry_clear`：清空当前与暂存。
- `geometry_mounted`：`parts` 非空且首部件形状非空。
- `part_count` / `part_exists`：按 `parts.size()` 与 `part_index` 查询。
- `world_transform_set`：写根变换并刷新；`world_transform_get` 为空时返回单位变换。
- `origin_advance`：根变换平移累加后刷新。
- `aabb_get`：逐部件 `shape->getAabb(worldTransform)` 求并集；空几何返回零值。
- `static_flag_set`：逐部件写入 `CF_STATIC_OBJECT` 或 0。
- 内部访问器：`impl_get` 直接解引用实现体；`object_get` 返回首部件对象（无空检查，见【待确认：2】）。

### 4.3 Collider/backend/core/运动推进.cpp

- `motion_advance(motion)`：实现体或几何缺失返回 false；先 `root.rotation = root.rotation * motion.rotation`（绕自身原点），再 `root.origin += motion.translation`（按世界轴），最后刷新全部子部件世界变换。
- `part_motion_advance(part_ID, motion)`：部件不存在告警返回 false；单部件时退化为 `motion_advance`；多部件时只更新目标部件的 `local_transform`（先旋转后按局部轴平移），再刷新该部件世界变换。

### 4.4 Collision_Proxy/backend/core/碰撞体编排.cpp

- `collider_build`：查空间；`target->collider_build()` 取编号；`collider_mapping_link`。
- `collider_unload`：查空间；`target->collider_unload` 成功后 `collider_mapping_unlink`。
- `collider_transfer`：查目标空间、编号归属与源空间；取源几何配置；目标 `collider_adopt`（编号冲突则中止）；源 `collider_unload`（失败回滚目标接管）；更新归属；无几何则只转移编号；有几何则按原编号重建。
- `collider_mirror`：查归属与源空间；取几何配置；目标构建新编号；无几何则得到占位体；有几何则按新编号重建。
- `collider_set_dispatch`：取该编号的全部归属项，逐个空间施加 setter，任一成功即返回 true。

### 4.5 Collision_Proxy/backend/core/空间编排.cpp

- `region_build`：重名拒绝；`regions[region].reset(new(nothrow) Collision_Region(region))`；分配失败报错；构建成功后注入 `motion_reader`。
- `region_unload`：查空间；对其全部编号 `collider_mapping_unlink`；擦除空间。
- `region_detect`：查空间；`target->detect_detail()`；`nullopt` 时告警返回 false；否则移出详情。
- `region_state_set`：查空间后写活跃标志。
- `region_seek`：按名称查空间，缺失返回空指针。
- `region_colliders`：转发空间编号集合。
- `collider_owner_seek`：取该编号的首个归属项。
- `collider_mapping_link` / `collider_mapping_unlink`：多重映射的登记与按空间注销。

### 4.6 Collision_Proxy/core/空间管理.cpp

- 构造：`acl_key = event_terminal.key().value()`；`backend.motion_reader_bind` 绑定本代理器的 `motion_seek`。
- `region_build` / `region_state_set`：纯转发后端。
- `region_unload`：先后端卸载，成功后 `event_output.erase(region)`。
- `region_detect` 编排：
  1. `backend.region_detect(region, details)`，失败返回 `nullopt`；
  2. 从详情抽取 `Collision_Result` 数组并按子部件对去重；
  3. `backend.region_seek` 取空间，`cross_notices_take` 逐条发布 `RegionCrossNotice`（`region` / `collider_ID` / `state` / `previous_state` / `position` / `frame` / `sequence`）；
  4. 空间结果事件开关为真时构造 `DetectResult`（`region` / `frame` / `results`）并发布；
  5. 返回详情。
- `region_event_output_set/get`：空间不存在告警返回 false；未登记默认 true。
- 跨越通知只在检测成功时取走；空间停用与边界重建会主动清空队列与基准。

### 4.7 Collision_Proxy/core/空间边界与配置.cpp

- `region_boundary_set(path)`：`boundary_config_read` 读取数组；逐项读 `region` 与 `mesh_path`；查空间；`target->boundary_build(mesh_path)`；任一失败置 `all_set = false` 但成功项已生效，不回滚。
- `config_apply(config)`：校验对象且 `regions` 为数组；逐空间读 `region` 并 `region_build`；可选 `active`、`event_output`、`boundary`；若含 `colliders` 数组，则逐项 `collider_build` 后 `collider_config_apply`。
- `boundary_config_read(path)`：路径可读性检查 → 整文件读取 → `json::parse`（`try/catch`）→ 必须为数组。

### 4.8 Collision_Proxy/core/碰撞体管理.cpp

- `collider_build` / `collider_unload` / `collider_transfer` / `collider_mirror`：纯转发 `Proxy_Backend`。
- `collider_set(Detection_Mode)` / `collider_set(uint64_t)`：经 `collider_set_dispatch` 对所有持有该编号的空间施加设置。

### 4.9 Collision_Proxy/core/碰撞体配置.cpp

`collider_config_apply(region, collider_ID, config)`：

1. `geometry` 为对象：视作单个几何体，写入 `collider_ID` 后交 `collider_set`；
2. `geometry` 为数组：收容为 `geometries`，把配置顶层的 `position` / `rotation` 搬到几何配置顶层；
3. 几何设置成功后，过滤该编号已登记部件运动中编号已不存在的条目；
4. `detection_mode`：读 `is_swept_volume`（布尔）与 `step_length`（整数）；步长归零时清除“含旋转或部件运动”的运动登记；
5. `exemption_flag`：读整数后交 `collider_set`。

### 4.10 Collision_Proxy/core/运动管理.cpp

- `motion_read(config, receiver)`：`translation` 与 `rotation` 均可选；四元数须长度非零并单位化；缺省为零平移 + 单位旋转。
- `parts_read(config, receiver)`：逐项读 `part`（须小于 `0xFFFF`）与该部件运动；同一下标后者覆盖前者。
- `motion_register(config)`：
  1. 读 `collider_ID`；
  2. 读可选 `motion` 与可选 `parts`，至少提供一个；
  3. 经 `collider_set_dispatch` 读该碰撞体的 `step_length`；
  4. 含旋转或部件运动时 `step_length` 必须非零，否则拒绝；
  5. 逐个校验部件编号存在；
  6. 读可选 `frequency`，必须整除逻辑帧率，否则告警并按 0（每次检测全量施加）处理；
  7. `motion_events[collider_ID] = config`（同编号覆盖），并 `collider_frequency_set` 下发频率、重新起算生效计时。
- `motion_seek(collider_ID, receiver)`：查表；解析 `motion` 与 `parts` 为 `Motion_Event`；无登记返回 false。

### 4.11 Collision_Proxy/core/事件交互.cpp

- `aabbs_refresh`：`world->updateAabbs()`。
- `object_contains`：`inner.owner == this` 且 `parts` 非空。
- `swept_collect`：
  1. `valid()` 检查；
  2. 逐移动体跳过空后端、零平移、含旋转或含部件运动者；
  3. 段数归一化，单段位移 `translation / step_count`；
  4. 取移动体根变换与实现体；
  5. 逐部件只处理形状非空、`isConvex()` 且对象非空的部件；
  6. 起点变换 = `root_transform * part.local_transform`；
  7. 逐段：终点 = 起点平移 `segment`；`convexSweepTest(part.shape, from, to, collector, m_allowedCcdPenetration)`；
  8. 对每个命中：反查子部件，失败跳过；`is_boundary` 时把 `move.ID` 推入 `boundary_contacts` 并跳过；否则做豁免与忽略对判定，归一化对，填接触点、法线、`depth = 0`、`fraction`，并入详情；
  9. 段末把起点推进到终点。
- `discrete_run`：
  1. `valid()` 检查；
  2. 扫描全部移动体取最大段数（至少 1）；
  3. 外层逐段：内层逐移动体，段数耗尽者跳过；否则 `motion_advance(body_step / step_count)` 与逐部件 `part_motion_advance(part, motion / step_count)`；
  4. `performDiscreteCollisionDetection()`；
  5. 遍历流形，跳过零接触；
  6. 反查两侧子部件，失败跳过；
  7. 任一侧 `is_boundary`：把另一侧编号推入 `boundary_contacts`，跳过该对；
  8. 归一化对；逐接触点取两侧世界位置中点、`m_normalWorldOnB` 作法线；若归一化 B 是流形第一侧则法线取反；`depth = max(-m_distance1, 0)`；`fraction = 1`；并入详情。
- `point_inside`：
  1. 边界未挂载返回 false；
  2. 取边界包围盒；
  3. 固定探针方向 `(1, 0.37, 0.19)` 归一化；
  4. 射线终点 = 探针点 + 方向 ×（包围盒对角线长度 × 2 + 1）；
  5. `AllHitsRayResultCallback` + `rayTest`；
  6. 只统计命中边界首部件对象的交点；
  7. 交点数为奇数返回 true。

### 4.15 Collision_Region/core/检测执行.cpp

### 5.2 所有权与生命周期

- 代理器拥有全部 `Collision_Region`；空间拥有自己的 `Region_Backend` 与全部 `Collider`；`Collider` 拥有 `Collider_Backend`；后端实现体拥有 `Geometry_Part`，部件拥有 `btCollisionObject` 与形状，形状只引用部件持有的 `btTriangleMesh`。
- `Region_Backend::attached` 只保存非拥有指针，用于析构时统一摘除；`Collider_Backend_Impl::owner` 是反向非拥有指针。
- 空间边界是 `Region_Backend` 内嵌的 `Collider_Backend`，不进入 `mapping`，固定编号 0。
- 代理器析构 → 空间析构 → 空间 `mapping` 先于 `backend` 析构 → `Collider_Backend` 析构时仍能通过 `owner` 摘除对象；最后 `Region_Backend` 析构再兜底清理 `attached` 与边界。

### 5.3 数据流动方向

- 外部 → 代理器：事件（构建、设置、运动、查询）→ 代理器更新运动表/空间/碰撞体。
- 代理器 → 空间：同步调用 `detect_detail`；空间在检测开头通过注入回调反查最新运动事件。
- 空间 → 后端：`swept_collect` / `discrete_run`；后端输出详情与边界编号。
- 空间 → 代理器：检测详情、跨越通知；代理器再发布为事件或同步返回。

### 5.4 线程归属

模块内部所有容器无锁；`Logics` 只保护帧计数与帧率。所有事件入口与 `region_detect` 必须在同一逻辑线程串行调用。

### 5.5 依赖方向

`Collision_Proxy` → `Collision_Region` → `Collider` → `Common`；`Proxy_Backend` 不接触 Bullet；`Region_Backend` 与 `Collider_Backend` 是唯一的 Bullet 边界。

## 六、模块设计 / 实现细节

### 6.1 Bullet 封闭的具体做法

- Bullet 头只出现在两个 `backend/` 与 `Common/数学转换.h`。
- 公共句柄全部 PIMPL：`Collider_Backend` 与 `Region_Backend` 只暴露自有类型与 `uint64_t`。
- 回调反查通过 `btCollisionObject::setUserPointer(Geometry_Part_Object*)` 完成；`Geometry_Part_Object` 堆分配保证地址稳定。

### 6.2 扫掠路径与离散分段的选取条件

- 扫掠清单只收“启用 `is_swept_volume`、纯平移（旋转为单位四元数）、无部件运动”的移动体。
- 扫掠只处理 `isConvex()` 部件；网格部件不参与扫掠（见【待确认：5】）。
- 所有移动体（包括扫掠体）都进入离散清单；扫掠在前、离散在后，离散负责真正推进位置。

### 6.3 分段调度与步数语义

- 步数取 `detection_mode.step_length`，0 视作 1。
- 扫掠按段推进每段 `translation / step_count`；离散先取所有移动体的最大段数，逐段推进，段数耗尽的移动体不再移动，然后执行一次离散检测。
- 运动事件含旋转或部件运动时必须显式提供非零步长，否则登记被拒。

### 6.4 频率门控的算术

- `frequency` 表示一个逻辑帧周期内运动生效的次数，必须是逻辑帧率的因数。
- 生效帧本帧运动量 = 周期总量 / `frequency`；非生效帧为零运动且不重读外部更新。
- `frequency == 0` 或帧率不可用时退化为旧行为：每次检测重读事件并施加全量运动。
- `motion_register` 中非法频率（为零、帧率不可用、不整除）降级为 0；`collider_frequency_set` 会重置 `motion_frame` 并清零本帧运动量，因此新配置至少等待一个间隔。

### 6.5 变换施加顺序

- 子部件世界变换 = 根变换 ∘ 部件局部变换（先部件后世界）。
- 整体运动：先绕根原点旋转，再按世界轴平移，随后刷新全部部件。
- 部件运动：在碰撞体局部空间内绕部件原点旋转，再按局部轴平移；单部件碰撞体退化为整体运动。

### 6.6 几何重建时的状态清理

- `geometry_build` 只写暂存区，失败不破坏当前几何。
- `geometry_mount` 才替换当前几何并刷新世界变换。
- 代理器在几何设置成功后过滤已失效的部件运动登记；区域在几何设置成功后把该编号标脏，强制跨越判定重算（瞬移不作为真实跨越的基准跳过）。

### 6.7 运动事件信箱

- 代理器用 `unordered_map<uint64_t, nlohmann::json>` 保存运动事件，同编号新事件覆盖旧事件，不存在队列。
- 事件只在生效帧被 `motion_seek` 重读并解析；撤销事件后，空间在下次重读时把运动清空。
- 频率与生效计时保存在空间内的 `Collider` 上，不在代理器；因此同一编号被多个空间持有时，各空间独立计时。

### 6.8 空间边界与编号 0

- 边界不是 `Collider`，而是 `Region_Backend` 内嵌的 `Collider_Backend`；固定 `tag_set(0, true)`，不进入 `mapping`。
- 边界恒为静态对象、恒置于世界原点、几何为单个 `mesh` 部件。
- 边界在检测中有三种角色：
  1. 离散：任一侧 `is_boundary` 时，把另一侧编号推入 `boundary_contacts`，该对不进入详情；
  2. 扫掠：命中边界时把移动体编号推入 `boundary_contacts`（路径穿越），不生成碰撞对；
  3. 射线：`point_inside` 用 `rayTest` 统计与边界首部件的交点奇偶性（见【待确认：4】）。
- 边界重建会清空跨越状态、脏标记与通知；`boundary_unload` 不清，等下次重建统一清空。
- 编号 0 由空间构造时预占，业务编号从 1 开始。

### 6.9 跨态机

- 状态集合 `inside` / `crossing` / `outside`。未接触时用包围盒中心射线奇偶；接触时用中心 + 八顶点九探针，内外混合才判 `crossing`。因此“空间内贴墙/站地形”不再误判。
- 未移动、未穿越、未标脏且已有基准的碰撞体直接沿用旧状态。
- 首次观察只建立基准，不产生通知。
- 通知类型按状态迁移命名：首次进入 `crossing` 记 `cross`，进入 `inside` 记 `return`，进入 `outside` 记 `exit`；稳态停留在 `crossing` 不重复发 `cross`。
- 扫掠穿越时：最终为 `outside` 则同帧先 `cross` 后 `exit`；最终为 `inside` 则至少发 `cross`（旧状态在外再补 `return`）。因此同帧可能两条通知。
- 通知携带 `previous_state`、`position`、`frame`、`sequence`；`DetectResult` 携带同一 `frame`。
- 未挂载几何不参与判定；卸载时主动抹除状态与脏标记；边界未挂载时整个函数返回，已有状态保留，待重建时统一清空。

### 6.10 豁免过滤

- 宽阶段 `Region_Overlap_Filter` 在窄阶段之前过滤：
  - 同一碰撞体：按对称子部件忽略对过滤；
  - 不同碰撞体：两侧 `exemption_flag` 均非零且相等则过滤；
  - 无法反查身份的对象（边界等）直接放行。
- 豁免标记变更后，区域会摘除并重新挂载该碰撞体，强制重建宽阶段配对。
- 过滤只影响普通碰撞对，不影响边界接触与跨越判定。

### 6.11 网格生命周期

- `Geometry_Part` 中 `mesh` 声明在 `shape` 之前，析构逆序释放：形状先释放、网格后释放；BVH 形状只持有网格指针，因此该顺序是正确性硬约束。
- `mesh_shape_build` 在形状分配失败时主动释放网格，避免孤儿数据。
- 顶点写入关闭查重，保证 `Mesh_Data` 下标与 `btTriangleMesh` 下标一一对应。
- 网格路径由配置直接给出，模块不做规范化或存在性预检；`Mesh_Loader` 失败即装配失败。

### 6.12 错误处理策略

- 对外失败一律 `false` / `nullopt` / 空集合 + 日志。
- 仅两处 `try/catch`：Bullet 形状构造的 `memory_malloc`、边界配置 JSON 解析。
- 事件发送失败只告警，已取走的跨越通知不会重试，见【待确认：7】。

### 6.13 分配与移动语义

- 自有对象统一 `new(std::nothrow)`；Bullet 形状因分配算子限制而包 `try/catch`。
- `Collider` / `Collider_Backend` / `Region_Backend` / `Collision_Region` 的移动只搬移堆句柄，实现体与碰撞对象地址不变。
- `Region_Backend` 移动赋值会释放旧实现体；旧世界内的对象不会走本类析构摘除逻辑，调用方需保证移动时旧空间已不再使用。

### 6.14 性能取舍

- 宽阶段 BVH 负责空间剔除；窄阶段只在每段推进后执行一次。
- 扫掠只覆盖纯平移凸形移动体；旋转与部件运动走离散多段。
- 跨越判定对未移动碰撞体不重算；接触碰撞体最多 9 次射线，非接触移动体 1 次。
- 每帧 `updateAabbs` 由 Bullet 的 `m_forceUpdateAllAabbs` 语义更新全部对象。
- 运动事件在生效帧重新解析 JSON，配置复杂时有解析开销。

### 6.15 已知脆弱点

- 碰撞体分配失败时 `collider_build` 会解引用空后端，见【待确认：1】。
- `Collider_Backend_Access::object_get` 不检查空部件，见【待确认：2】。
- 九探针使用世界包围盒顶点，旋转盒体或球形碰撞体在凹角处可能误判，见【待确认：3】。
- `point_inside` 只统计边界首部件对象，多部件边界不支持，见【待确认：4】。
- 网格对网格（凹-凹）在 Bullet 中无窄阶段算法，网格碰撞体之间不会产生流形；网格部件也不参与扫掠，见【待确认：5】。
- 所有碰撞对象默认 `CF_STATIC_OBJECT`，Debug 构建下 Bullet 会打印 static-static 警告；模块不提供运动学/动力学语义，见【待确认：6】。
- 跨越通知先出队再发布，发送失败即丢失，见【待确认：7】。
- 跨越查询的同步语义依赖事件中转站的同步派发，见【待确认：8】。

## 七、模块运行链路详例

### 7.1 链路一：投递运动事件 → 检测 → 发布通知与结果

1. 外部发送 `Collision/ColliderMotion`，载荷包含 `collider_ID`，可选 `motion`、`parts`、`frequency`。
2. 代理器 `motion_register` 校验编号、运动通道、步长、部件编号与频率；通过后写入 `motion_events[ID]`，并 `collider_frequency_set` 下发频率与计时。
3. 外部调用 `region_detect(region)`；代理器转 `Proxy_Backend::region_detect`；空间 `detect_detail`：
   - `aabbs_refresh`；
   - 频率门控决定本帧是否重读运动事件；
   - 组织 `all_moves` / `swept_moves` 与 `moved_IDs`；
   - `swept_collect` 收集碰撞详情与边界穿越编号；
   - `discrete_run` 逐段推进位置、执行离散检测、收集接触与边界接触编号；
   - `cross_state_update` 判定跨越并生成通知。
4. 代理器抽取碰撞对，发布 `RegionCrossNotice`（如有），再按开关发布 `DetectResult`，最后返回检测详情。

### 7.2 链路二：碰撞体注册与几何装配

1. 外部发送 `ColliderBuild`；代理器在目标空间 `collider_build` 分配编号并登记归属，发布 `ColliderBuildResult`。
2. 外部发送 `ColliderSet`，携带 `geometry`（对象或数组）。
3. 代理器 `collider_config_apply` 归一化几何形式；若为数组，把顶层 `position` / `rotation` 搬入几何配置。
4. 空间 `collider_set(json)`：
   - 以当前世界变换为基准，可选位姿覆盖；
   - `geometry_build` 解析形状（盒/球/胶囊/圆柱/圆锥/网格）、分配部件编号、解析忽略对、分配子部件对象；
   - 摘除旧几何、`geometry_mount` 替换、留档几何、重新挂载；
   - 标记跨越状态脏。
5. 代理器过滤已失效的部件运动登记。

### 7.3 链路三：空间边界变更与跨越重置

1. 外部发送 `RegionBoundary`，载荷为边界配置文件路径。
2. 代理器读取 JSON 数组，逐项取 `region` 与 `mesh_path`，调用空间 `boundary_build`。
3. 后端构造 `type = mesh` 配置，加载 OBJ，构建 `btBvhTriangleMeshShape`，摘除旧边界、挂载新几何、置静态标志、写入编号 0 与边界标记、加入世界。
4. 构建成功后，空间清空跨越状态、脏标记与待发通知；下一次检测重新建立基准，不产生跨越通知。

### 7.4 链路四：跨越状态查询

1. 外部发送 `Collision/RegionCrossStateQuery`，载荷含 `region`，可选 `collider_ID` 与 `request_ID`。
2. 代理器 `event_process` 读取字段，`backend.region_seek` 找空间。
3. 空间 `cross_state_snapshot` 输出 `mapping` 中每个碰撞体的状态与 `known` 标记。
4. 代理器构造 `RegionCrossStateResult`（`region` / `found` / `request_ID` / `states`）并发布；事件中转站同步派发，请求方在发送返回前收到结果。

## 附：待确认正文

【待确认：1】`Collision_Region::collider_build` 在 `Collider` 构造分配后端失败（`new(nothrow)` 返回空）后仍调用 `collider.backend->tag_set(...)`，会解引用空指针；当前没有失败保护。

【待确认：2】`Collider_Backend_Access::object_get` 直接返回 `parts.front().object->object`，不检查 `parts` 是否为空；当前只由 `point_inside` 在 `boundary_mounted` 为真后调用，暂不会触发，但属于隐式前提。

【待确认：3】跨越判定在接触时使用世界包围盒中心与八顶点作探针。旋转盒体的包围盒会大于实际形状，球形碰撞体在凹角处也可能出现顶点落在边界外的情况，从而把“完全在内”误判为 `crossing`。当前接受该近似。

【待确认：4】`point_inside` 只统计与边界“首个子部件对象”的交点；边界由 `boundary_build` 固定构造为单部件网格，因此当前成立；若未来允许边界为多部件几何，需改为统计全部边界部件对象。

【待确认：5】Bullet 的窄阶段不支持凹形对凹形：`btBvhTriangleMeshShape` 与 `btBvhTriangleMeshShape` 之间不会生成流形。碰撞体可配置 `type = mesh`，因此网格碰撞体与边界网格、其他网格碰撞体之间不会产生碰撞对；同时扫掠路径只处理 `isConvex()` 部件，网格部件不参与扫掠。

【待确认：6】`btCollisionObject` 默认碰撞标志为 `CF_STATIC_OBJECT`，模块只对边界显式设置静态标志，未对普通碰撞体设置动态或运动学标志；Debug 构建下 Bullet 会对 static-static 配对打印警告。模块只做检测，不依赖该标志求解运动，但接入方若改用动力学世界需自行调整。

【待确认：7】`region_detect` 先 `cross_notices_take` 再逐条 `event_publish`；若事件通道不可用，通知已从队列移除，只会记录告警，不会重试或保留。

【待确认：8】`RegionCrossStateQuery` 的“发送即得结果”依赖 `Event_Broker::receive` 同步调用订阅者回调；若事件系统未来改为异步入队，查询会退化为异步请求/应答。另，中转站不向发送者自身回投事件，请求方不能与 `Collision_Proxy` 同名。
