## 二、模块功能介绍

### 2.1 模块定位

「单元测试-渲染」编译单元是 `Application/Test/src/单元测试/渲染/` 下的 **24 份**用例源文件所属的那部分用例集合。它们随整层唯一的用例目标 `EngineTestObjects`（OBJECT 库）一并编译，由可执行目标 `EngineTests` 收编执行（见 `Test/构建与源文件清单.md`）。

一句话概括：**本单元是「渲染层公共面的验收集合」——只按 `Application/Renderer/src/render/Renderer/渲染器.h` 这一个公共头编写用例，验证渲染器门面的初始化/销毁、帧推进、相机设置、网格与纹理的创建与读回、着色器输入的校验，而完全不触碰 Vulkan / SDL / VMA 等底层类型。**

### 2.2 职责边界与文档分界

| 对象 | 分界 |
| --- | --- |
| 本单元（渲染子树 24 文件） | 只写**用例正文**：各 `TEST_F` 的覆盖意图、断言与边界、运行前提与环境门控、外部产物依赖。 |
| `Test/测试对象与夹具.md` | 写夹具类（本单元 25 个夹具）、匿名命名空间辅助的**类型层面**（形态与归属）、生命周期与隔离、编译口径与依赖。本单元不重述夹具定义，只说明用例「站在什么夹具上」。 |
| `Test/构建与源文件清单.md` | 写构建清单与三/四目标的完整关系。本单元仅在 2.3 说明与 `EngineTestObjects` 直接相关的构建事实。 |
| `Renderer/门面.md` 等渲染层文档 | 写渲染层**内部实现**（设备/交换链/帧/网格/纹理/着色器/相机）。本单元只从公共面出发断言其对外行为，不回证内部机制。 |
| `Test/单元测试-主调.md`、`-工具.md`、`-核心.md` | 写其余三棵子树的用例正文；与本文无重叠。 |

### 2.3 在 Test 层与依赖链中的位置

```
                        ┌──────────────────────── EngineTests.exe（可执行） ───────────────────────┐
                        │  main（src/主调/主程序.cpp）                                            │
                        │  $<TARGET_OBJECTS:EngineTestObjects>  ← 本单元（渲染用例 .obj 之一部）  │
                        └───────────────┬───────────────────────────────────┬─────────────────────┘
                                        │ 链接                                │ 链接
                        ┌───────────────▼──────────────┐          ┌───────────▼──────────────┐
                        │ RendererCore.lib（渲染层公共面）│          │ EngineCore / EngineSystem │
                        │ 头：渲染器.h（Vulkan-free）     │          │ GTest::gtest / TestLauncher│
                        └──────────────────────────────┘          └──────────────────────────┘
                                        ▲
                            运行期还需：真实 Vulkan 设备 / 显示环境（L2/L3 及隐藏窗口用例）
                                        +
                            exe 旁 shaders/ 目录（渲染层着色器，CMake 配置期拷自渲染层构建目录）
```

- 本单元链接项与包含口径同整层用例目标：`EngineCore`、`EngineSystem`、`RendererCore`、`GTest::gtest`、`TestLauncher`；编译选项 MSVC `/MP /utf-8`（见 `Test/测试对象与夹具.md`）。
- 渲染 24 文件在 `源文件列表_EngineTestObjects.cmake` 中列于末段（`src/单元测试/渲染/渲染初始化测试.cpp` 等 24 条），随 `file(GLOB_RECURSE ... CONFIGURE_DEPENDS)` 自动收编。
- **本单元不引入任何 Vulkan / SDL 头**：编译脚本注释明确「渲染层公共头不暴露 SDL / Vulkan / VMA 类型，本层按公共面编写用例即可，无需、也不应引入 Vulkan 头」。

## 三、模块公开接口介绍

### 3.1 用例的「公开面」

本单元**无对外头，也不被层外调用**。它「对外生效」的唯一产物是 googletest 的**静态注册**：每条 `TEST_F(夹具类名, 中文用例名)` 把「套件名 = 夹具类名 + 用例名」登记进 gtest 注册表，从而可经 `::testing::UnitTest` 反射枚举、可按 `--gtest_filter` 选取。因此本文的「公开接口」指**用例向 gtest 注册表暴露的选取面**，即 3.2 的「套件→用例」两级清单，加上 3.4 的 `BYJY_RUN_L3` 门控契约。

### 3.4 环境变量门控契约

- `BYJY_RUN_L3`：仅 `渲染可见窗口测试.cpp` 读取（`std::getenv`）。**未设**、为空串或为 `"0"` 即视为关闭，两条 L3 用例随即 `GTEST_SKIP()` 跳过；仅当显式给出且非 `"0"` 时执行可见窗口。
- 复跑方式（源码文件头给出）：`set BYJY_RUN_L3=1 && EngineTests.exe --gtest_filter=Renderer_Visible_Test.*`。
- **不存在 `BYJY_RUN_L2` / `BYJY_RUN_L1` 门控**：L2、L1 用例默认执行，无环境开关（全仓仅见 `BYJY_RUN_L3` 一处）。L2 用例因此会对无 GPU/无显示环境的机器直接失败（非跳过），见 §六 6.7。

### 6.1 渲染初始化测试（`渲染初始化测试.cpp`，L1）

**覆盖意图**：从门面侧验证「生命周期状态机」（未初始化 → 已初始化 → 已销毁，`shutdown` 幂等、可重初始化）、非法配置的拒绝、隐藏窗口的正常初始化与查询面零值/非零值口径。

| 用例 | 前置 | 断言要点 | 需 GPU/窗口 |
| --- | --- | --- | --- |
| `版本查询非空` | 无 | `renderer_version()` 返回非空串 | 否 |
| `默认构造未初始化` | 仅构造 `Renderer` | `valid()==false`；`frame_count()==0`；`extent_width()==0`、`extent_height()==0`；`frame_render()==false`；`close_requested()==false` | 否 |
| `宽度为零被拒绝` | `hidden_config(0,180)` | `init(...)==false`；`valid()==false` | 推断否（配置校验阶段拒绝） |
| `高度为零被拒绝` | `hidden_config(320,0)` | 同上 | 推断否 |
| `在途帧数为零被拒绝` | `frame_overlap=0` | 同上 | 推断否 |
| `在途帧数越界被拒绝` | `frame_overlap=4` | 同上 | 推断否（上界来源见 `【待确认：TEST-52】`） |
| `隐藏窗口初始化与幂等关闭` | `hidden_config()` | `init` 真 → `valid` 真 → `extent_width/height>0` → `close_requested` 假 → `shutdown` 后 `valid` 假 → 二次 `shutdown` 幂等 → 关闭后**重新 `init`** 真 | **是** |
| `重复初始化幂等` | `hidden_config()` | 首次 `init` 真；已初始化状态下再 `init` 仍返回真且 `valid` 保持真 | **是** |

- 容错/断言口径：初始化失败类用 `EXPECT_FALSE`（软断言，可继续观察后续断言）；「隐藏窗口初始化与幂等关闭」对两次 `init` 用 `ASSERT_TRUE` 并在失败时附中文提示（后续断言依赖 init 成功）。
- 「重复初始化幂等」的期望是**返回真且不破坏已初始化状态**（源码注释明确「不破坏已初始化状态」）。

### 6.6 渲染网格纹理测试（`渲染网格纹理测试.cpp`，L2，两夹具）

**覆盖意图**：网格面与纹理面各一组用例，验证「未初始化守卫、创建/绘制/卸载的成功与拒绝路径、句柄有效性、句柄回落默认、幂等卸载、多资源并存」。

网格组（夹具 `Renderer_Mesh_Test`）：

| 用例 | 动作 | 断言要点 |
| --- | --- | --- |
| `未初始化加载网格失败` | 未 `init`，`handle=0` | `mesh_load(handle, tri)==false`；`handle==0` |
| `加载三角形并绘制` | `init` → `mesh_load` | `handle!=0`；`mesh_draw(handle,nullptr)==true`；`frame_render()==true`；末 `mesh_unload` |
| `同帧绘制两个网格` | `init` → 两次 `mesh_load` → 同一帧两次 `mesh_draw` | 两次 `mesh_draw` 均真；单次 `frame_render` 一并提供；末两次 `mesh_unload` |
| `绘制无效句柄失败` | `init` → `mesh_draw(12345u,nullptr)` | `==false` |
| `卸载后绘制失败` | `init` → `mesh_load` → `mesh_unload` → 再 `mesh_draw` → 再 `mesh_unload` | 卸载后绘制假；重复卸载不报错 |

纹理组（夹具 `Renderer_Texture_Test`）：

| 用例 | 动作 | 断言要点 |
| --- | --- | --- |
| `未初始化加载纹理失败` | 未 `init`，4×4 全零像素，`handle=9999` | `texture_load(...)==false`；`handle==0`（被复位；见 `【待确认：TEST-54】`） |

| `棋盘格纹理绑定跑帧` | `init` → `texture_load_checkerboard(handle,64,64,8)` → `texture_bind_set` | `handle!=0`；`frame_render()==true`；末 `texture_unload` |
| `绑定无效句柄回落默认` | `init` → `texture_bind_set(0)` | `frame_render()==true`（回落内置默认白纹理，不报错） |

| `纹理读回与输入一致`（**第二十七轮补**） | `init` → 2×2 四色纹理 → `texture_readback` | 16 字节与输入逐字节一致；尺寸 2×2；容量 15 → 假且尺寸归 0；句柄 9999 / 卸载后 → 假 |

- 需真实 GPU/窗口：**13 例中前 11 例（除两个未初始化守卫）需要**（均先 `init` 隐藏窗口）；两个「未初始化」守卫例不需要。

### 6.7 运行前提、跳过与容错汇总

| 维度 | 结论 |
| --- | --- |
| 需真实 GPU + 显示环境的用例 | L2 全部（帧 5 / 相机前 4 / 网格纹理前 10 / **回读后 4**）、初始化 3 例（隐藏窗口 init）、L3 可见窗口 2 例 |
| 推断不需 GPU 的用例 | 初始化的 5 个拒绝/查询例（版本查询、默认未初始化、四个非法配置中的查询类）、着色器校验 4 例（失败路径）、相机末例、网格纹理两个未初始化守卫 |
| 跳过机制 | ① L3 两条用例：`l3_enabled()` 为假即 `GTEST_SKIP`；② 回读用例在 `readback_supported()` 为假（交换链图像不含传输源用法）时 `GTEST_SKIP`（含本版次第十轮新增的后处理链用例）；③ **本版次第十轮**：GPU 耗时用例**取消跳过**，改为按 `gpu_timestamp_supported()` 能力分支断言；另有文字 / 文字布局 / 中文字形用例在系统字体缺失时按文件局部跳过（文字布局内五例另需回读能力，缺失时同样局部跳过）；其余无跳过 |
| 无 GPU 机器上的行为 | L2 与隐藏窗口用例会**失败**（非跳过），如 `init` 返回假即 `ASSERT_TRUE` 中断 |
| 容错策略 | 初始化/加载用 `ASSERT_*`（成功前置）；拒绝/守卫用 `EXPECT_*`（软断言）；帧推进失败用 `ADD_FAILURE` 汇总不中断；文件系统操作用 `std::error_code` 容错 |
| 提前收敛 | 可见窗口两例在循环内判 `close_requested()` 后 `break`，避免用户关窗后继续硬跑 |

### 6.10 渲染像素回读测试（`渲染像素回读测试.cpp`，L2；本版次新增）

**目的**：给渲染层补上**像素级断言**能力——此前所有渲染用例只能断言「跑帧成功 / 句柄有效」，无法验证「画出来的像素对不对」。本文件是渲染层 `frame_render` 回读接口（见 `Renderer/门面.md` 3.4.7 / 3.4.20 与 `Renderer/帧.md` 6.15）的验收用例，也是后续图形特性（实例化、混合、多材质、离屏与后处理、文字渲染、纹理解码、mipmap）的断言模板。

**夹具**：`Renderer_Readback_Test`（1 个）。**文件内匿名命名空间辅助**：`hidden_config()`（64×36 隐藏窗口）、`pixel_bytes()`、`pixel_get()`、`pixel_sorted()`、`pixel_is_clear()`、`pixel_text()`、`quad_data()`（覆盖视口中央的四边形，UV 0..1）、`distinct_color_count()`。

| 用例 | 步骤与断言 |
| --- | --- |
| `未初始化回读失败` | 未 `init` 即调 `frame_render(pixels, size, &w, &h)` → `EXPECT_FALSE`；`readback_supported()` → `EXPECT_FALSE` |
| `容量不足被拒且不推进帧` | `init` 后以 16 字节目标请求回读 → `EXPECT_FALSE`；`frame_count()==0`、尺寸出参为 `0` |
| `回读清屏色正确` | 无障碍缓存单帧 → 尺寸回填 64×36；左上 / 右下 / 中心三点均为清屏色，且**三点颜色完全一致**（清屏为纯填充） |
| `白纹理四边形中心覆盖角落留空` | 绑默认白纹理 + 加载四边形并 `mesh_draw` → 中心像素四通道 ≥ 250；左上角仍为清屏色（几何 / 投影 / 深度路径真实生效） |
| `棋盘格纹理回读呈现多色调` | 绑 64×64 棋盘格（格 8）+ 四边形 → 去重颜色数 ≥ 3；且存在四通道最小值 ≥ 60 的像素（纹理亮色 vs 清屏色） |

**格式无关性（本版次踩坑口径）**：清屏色 `0.05/0.05/0.10` 在**非 sRGB（UNORM）**附件下编码为 ≈`13/13/26`，在 **sRGB** 附件下经传输函数编码为 ≈`63/63/89`。故 `pixel_is_clear()` 用 `CLEAR_CANDIDATES = {{13,13,26},{63,63,89}}` **双候选 + 容差 ±4 + 通道排序**比对，并对 alpha 单列校验 `≥ 250`；通道序（BGRA / RGBA）与附件传输函数差异均被吸收，**断言与表面格式解耦**。棋盘格用例同理不用「与清屏色取色比对」，改用**去重颜色计数**（非 sRGB 附件下深色 0x40 线性化后约为 130，与清屏色高通道 26 相差大，但 UNORM 路径下浅色 0xC0 ≈ 134，故以计数与亮度阈值判定）。

**能力缺失时**：`容量不足被拒且不推进帧` 之后的 4 例在 `readback_supported()` 为假时 `GTEST_SKIP`（不掩盖失败，仅适配不含 `TRANSFER_SRC` 的极端驱动）。

**实测结果（本版次）**：`BYJY_RUN_L3=1` 下本套件 5/5 通过；连同既有 35 例，渲染层共 **40/40 通过**；全量（排除四叉树两套件）**590/590 通过**。

### 6.11 渲染混合态测试（`渲染混合测试.cpp`，L2；本版次新增）

**目的**：验收渲染层**可配置混合档**（`Renderer::blend_mode_set`，见《渲染层-门面》§3.4.21 与《渲染层-管线》§3.3.7）：同一「半透明白纹理 + 覆盖视口中央的四边形」在两条档位下应给出**可区分的像素结果**，从而证混合真实生效且可往返。

| 用例 | 断言 |
| --- | --- |
| `不透明档忽略源alpha` | 中心**颜色三通道 ≥ 250**（实白）＋**alpha 第 4 字节 ∈ [120,136]**（源 alpha=128 原样写出，证未混合）；角落为清屏色 |
| `alpha档产生半透明叠加` | 中心**颜色三通道 ∈ [100,240]**（严格介于清屏色与纹理白之间）＋混合后 alpha ∈ [180,205]（≈0.75→191）；角落为清屏色 |
| `切回不透明档后恢复实白` | 混合帧中心 ≤ 240 → `blend_mode_set(Opaque)` 后次帧中心颜色三通道 ≥ 250（档位往返成立） |

**断言口径（本版次两条关键踩坑）**
1. **颜色三通道与 alpha 分离**：不透明档下写出的 alpha = 源 alpha（128）而非 255，故**不能**用「四通道最小值 / 最大值」判定颜色；本文件用 `color_min()` 只看前三通道，alpha 一律直接取**下标 3**（BGRA 与 RGBA 下 alpha 均恒为第 4 字节）。
2. **`std::min({...})` 在本层不可用**：本层包含链存在 `min` 宏（Windows 头），`std::min({a,b,c})` 会被宏展开，产生 `C2589: "(": "::" 右边的非法标记` 及连锁语法错误；改用显式比较（本文件 `color_min()` 即如此实现）。

**格式无关性**：混合在 sRGB 附件下于**线性空间**进行（写入时编码回 sRGB），故半透明期望值随附件传输函数不同（sRGB 附件 ≈ `192/192/196`、非 sRGB ≈ `134/134/141`），用例用**区间**判定而非定值。

**实测结果（本版次）**：`BYJY_RUN_L3=1` 下本套件 3/3 通过；渲染层共 **43/43 通过**；全量（排除四叉树两套件）**593/593 通过**。

**断言格式无关**：绿判定只看**绿通道**（RGBA / BGRA 下恒为第 2 字节，下标 1）；红判定用「R 与 B 通道取较大者」（外通道）避开本层包含链的 `min/max` 宏与 `std::max`。两种端点色（0 与 1）在 UNORM 与 sRGB 附件下编码一致，故判定不随附件传输函数变化。

### 6.17 渲染文字测试（`渲染文字测试.cpp`，L2；本轮新增，第十二轮补 2 例）

**目的**：验收 `Renderer::font_load_file` / `font_unload` / `text_draw` 与跳过码点计数 `font_skipped_codepoints`（见《渲染层-门面》§3.4.32~3.4.34 与《渲染层-文字》）。

**夹具**：`Renderer_Text_Test`（空夹具）。窗口 128×64 隐藏窗口；字号 `FONT_PIXEL_HEIGHT = 16`；字体取自系统 `C:\Windows\Fonts\consola.ttf`（**本机不存在时该用例 `GTEST_SKIP`**）。

**断言口径**：一律「格式无关」——以「是否近似清屏色」判定墨迹（双编码候选 ＋ 容差 ＋ 通道排序；alpha 恒取第 4 字节）；`ink_count(矩形)` 统计指定矩形内的非清屏色像素数。

| 用例 | 步骤与断言 |
| --- | --- |
| `未初始化加载字体失败` | 未 `init` 即 `font_load_file(font, path, 16)` → **假**；**句柄须被复位为 0**（入参初值 `12345`） |
| `字体文件缺失加载失败` | `init` 后加载不存在路径 → 假、句柄 0；随后 `frame_render` 仍成功（**字体加载失败不破坏帧循环**） |
| `文本在指定位置产生非背景像素` | 在 `(4,4)` 画 `"AB"` → 回读：全窗口墨迹 > 0、**上半区**墨迹 > 0（文本位置相符）、右下角一带墨迹 == 0；随后 `font_unload(font)` 再 `text_draw` 同句柄 → **假**（句柄失效） |
| `不同文本产生不同像素分布` | 两帧分别画 `"III"` 与 `"WWW"`（同位置同字号）→ 两帧在 `(0,0)-(64,24)` 内均 > 0 墨迹，且**宽字形墨迹显著多于窄字形**（证明确实按文本光栅化而非固定图样） |
| `空文本与无效句柄行为` | 无效句柄 `99999` → `text_draw` 假；加载字体后空文本 `""` → **真（返回真但不登记绘制项）**；帧仍正常推进；收尾 `font_unload` |
| `纯ASCII不产生跳过计数`（本版次第十二轮补） | 未 `init` 时 `font_skipped_codepoints(1u) == 0`；加载字体（字号 16）后读回 == 0；`text_draw(font, "AB C1", 4, 4)` 后仍 == 0（**含空格，空白字符不计入**）；重复绘制仍 == 0；无效句柄 `99999` 读回 == 0；收尾 `font_unload` |
| `不支持码点计入跳过计数`（本版次第十二轮补） | 加载后初始 == 0；构造文本 `"A"` ＋ U+E000（UTF-8 字节 `EE 80 80`，源码写作 `"\xEE\x80\x80"`）＋ `"B"`，`text_draw` 返回**真**（ASCII 部分仍有墨迹）、`font_skipped_codepoints(font) == 1`；重复绘制同一文本仍 == 1（**同一码点不重复计数**）；改画 `"AB"` 仍 == 1；`font_unload` 后读回 == 0 |
| `文字颜色着色生效`（本版次第十六轮补） | 默认白帧：全窗口最亮像素（三分量和最大）三通道差 ≤ **6**；`text_color_set({1,0,0,1})` 后重绘同文本：同指标 ≥ **100** 且最大通道 ≥ **200**（着色生效；**通道序无关**，只比最大与最小通道之差）；`RecordProperty` 记录红帧最大 / 最小通道 |
| `文字透明度生效`（本版次第二十轮补） | 白字 alpha=1 与 alpha=0.5 两帧：半透明帧最亮像素亮度 **<** 不透明帧，且 **>** 背景亮度 + 30（介于两者之间；`RecordProperty` 记录两帧亮度） |

**跳过与环境门控**：五例依赖系统字体（`font_available()` 假即 `GTEST_SKIP`，含第十二轮新增两例）；两例依赖像素回读（`readback_supported()` 假即 `GTEST_SKIP`）；未初始化 / 文件缺失两例无需 GPU 能力（但需可 `init`）；`纯ASCII不产生跳过计数` 的「未初始化读 0」断言在字体检查之前执行，故该断言在所有环境都会实跑（随后才可能跳过）。

**跳过码点计数口径（第十二轮）**：`font_skipped_codepoints` 按字体句柄读取，自 `font_load_file` 起累计、`font_unload` 后读回归 0；只统计「字体不含 / 无法烘焙」的码点，且**每码点至多计一次**（首次失败以「0 推进的空度量」登记，重复绘制不再累加）；空白字符不计数；未初始化与无效 / 已卸载句柄恒返回 0。用例只钉住「相对增量」与「重复不增」，不断言失败原因或图集容量（属渲染层内部）。

**易错点**：断言「墨迹」而非「具体字形像素」，故对附件传输函数与通道顺序不敏感；`"III"` / `"WWW"` 的墨迹量对比依赖同一字体同字号（若换字体该对比未必成立，见 `【待确认：TEST-60】`）；新增两例的「跳过计数」依赖所选字体确实不含 U+E000（私有区码点），若换字体后该码点被覆盖，则 `不支持码点计入跳过计数` 会失败而非跳过（同属 `TEST-60` 的字体硬编码耦合）。

| `各向异性能力可查询` | `init` 后 `sampler_max_anisotropy() >= 1.0f`；**未启用该特性时必须恰为 `1.0f`**；以 `RecordProperty` 记录本机取值（便于人工核对，通常为 16） |
| `各向异性与细节层级设置后仍可正常绘制` | 三帧各绑棋盘格纹理（`texture_load_checkerboard(32,32,4)`）画覆盖视口中央的四边形：①「各向异性（倍数 = `sampler_max_anisotropy()`）＋ 启用 mip 过滤」；②「显式 `min_lod = max_lod = 0`（只看第 0 级）并**重复设置同状态**（走空操作路径）」；③「切回默认档（不采样 mip）」——每帧中心像素**非清屏色**、角落为清屏色；三帧后 `frame_count() == 3` |

| `各向异性开关产生像素级差异`（本版次第十三轮补；**诊断口径**） | 自建**垂直条纹**纹理（256×256、条宽 2 像素，`stripes_vertical_black_white`：沿 u 变化、沿 v 恒定）× 绕 Y 轴 60° 的四边形（模型矩阵按列主序填 `[0]=0.5`、`[2]=-0.866`、`[5]=1`、`[8]=0.866`、`[10]=0.5`、`[15]=1`，使屏幕 x 方向被压缩）→ 各向异性关（倍数 1）与开（设备上限）各出一帧：**硬断言只有**「两帧均正常出图（中心非清屏色）」＋ `frame_count() == 2`；差异经 `RecordProperty("anisotropy_pixel_diff", …)` **记录而不强制 > 0**，同时记录 `anisotropy_supported` / `anisotropy_max`；不因设备不支持各向异性而跳过。本机实测差异 = **0**（两帧逐字节相同） |

### 6.24 渲染 GPU 耗时测试（`渲染GPU耗时测试.cpp`，L2；本版次第九轮新增，第十二轮补 1 例）

**目的**：验收 GPU 时间戳耗时统计——门面 `gpu_timestamp_supported()` 与 `Frame_Stats.gpu_frame_ms`（见《渲染层-门面》§3.4.42 / §3.4.43 与《渲染层-帧》§6.19）。**本版次第十轮**：后两例由「不支持即跳过」改写为「**不跳过、按能力分支断言**」（处置 `TEST-68`），支持 / 不支持两分支均可构造、均实跑。**本版次第十二轮**：补一例「两级后处理链路径」的 GPU 耗时旁证（处置 `R-FRAME-11` 的链路径口径）。

**夹具**：`Renderer_Gpu_Test`（空夹具）。窗口 64×36 隐藏窗口。

| 用例 | 步骤与断言 |
| --- | --- |
| `未初始化不支持GPU时间戳` | 仅构造 `Renderer`（未 `init`）：`gpu_timestamp_supported() == false`；`frame_stats_get().gpu_frame_ms == 0.0` |
| `绘制帧GPU耗时随能力分支断言` | `init` 后登记三角形绘制项并连续渲染 **4 帧**：支持分支断言 `gpu_frame_ms > 0` 且 `gpu_samples == 2`（= 帧数 − 在途帧数 2）；不支持分支断言 `gpu_frame_ms == gpu_total_ms == 0` 且 `gpu_samples == 0`；两分支均另断言绘制项 / 实例计数恒为 4（**不跳过**） |
| `空帧GPU耗时随能力分支断言` | 同上前提但不登记绘制项（仅清屏）：支持分支断言 `gpu_frame_ms > 0` 且 `gpu_samples == 2`；不支持分支三字段恒 0（**不跳过**） |
| `两级链GPU耗时随能力分支断言`（本版次第十二轮补） | `init` → 建 `scene_target` / `second_target`（均 `extent_width` × `extent_height`）→ 登记两条后处理管线（`后处理.vert.spv` ＋ `反色.frag.spv` / `亮度阈值.frag.spv`）→ `post_chain_set(chain, 2)` → `render_target_present_set(scene_target)` ＋ `render_target_present_secondary_set(second_target)` → 三角形网格连画 **4 帧**（每帧 `mesh_draw` ＋ `frame_render()`）：断言 `frames == 4`、`draw_items == 12`、`instances == 12`（每帧 1 个场景项 ＋ 2 级后处理项）、`drawn_items == draw_items`；支持时 `gpu_frame_ms > 0` 且 `gpu_samples == 2`（符合「帧数 − 在途帧数」），不支持时三字段恒 0（**不跳过**） |

**帧数口径**：GPU 时间戳结果在「同一帧槽**下一次**使用」时才被读回（帧槽环形读回，滞后 = 在途帧数；默认在途帧数 2），故用例须渲染**不少于「在途帧数 + 1」帧**（此处取 4）方能读到首轮结果。

**链路径旁证口径（第十二轮）**：本用例**不比较**「两级 ≥ 一级」的耗时大小（换机 / 驱动波动会假失败），只钉住「链路径确实产生 GPU 样本」与「链路径绘制统计口径」；多 pass 覆盖由「终点时间戳位于收尾转换之后」的源码口径保证（见《渲染层-帧》§6.19），用例本身不做时序断言。

**能力分支（不跳过）**：按能力分支断言的三例（`绘制帧GPU耗时…` 与 `空帧GPU耗时…` 两例处置 `TEST-68`，第十二轮补的两级链一例同口径）均**不** `GTEST_SKIP`，无论设备是否支持 GPU 时间戳都各自实跑并断言；需真实 GPU 与隐藏窗口（L2）。

**断言口径**：格式无关——像素判定只看通道字节与阈值（`SATURATION_THRESHOLD` / `DARK_THRESHOLD`），不假定具体通道序与附件传输函数；两级恒等以「与交换链参考路径逐通道差 ≤ 4」判定。**本版次第十二轮补**：`post_chain_count` / `post_chain_get` 为**只读诊断**入口——未初始化、空链、出参为空一律返回 0；`post_chain_get` 按容量截断并返回实际写入数（`min(链级数, 容量)`）；级序为「当前链」顺序，管线卸载造成的摘除会**压缩级序**（不复用原下标），故读回值只保证与当前链一致。**本版次第十四轮补（预设相对断言口径）**：预设的像素效果**不硬编码具体边界坐标与绝对通道值**——灰度只断言「三通道趋同（两两差 ≤ 2）＋ 亮度区间（中心 ≥ 200、角落 > 4）」；描边以**同场景同目标的灰度帧**为参考，断言「比参考暗 ≥ 40 的像素数 > 0」且中心亮度下降 ≤ 20（`luma_of` 按 Rec.709 求亮度，与通道序、附件传输函数无关；`darkened_count` 逐像素比对两帧）；色调映射只断言高光被压到 **200–246** 这一确定区间并保持 r ≈ g；串联只断言「仍去色（r ≈ b）且中心仍亮」。`RecordProperty` 记录 `edge_darkened_pixels` / `tone_mapped_center` 供跨机复核。**本版次第十五轮补**：①「三级链」以「中心三通道趋同」证明第 3 级真实执行，暗部断言用**端点**（≤ 4，不依赖曲线数值）；②「模糊参与」用**两帧必有像素差**（`> 0`）判定，不量化模糊强度；③「目标组不足回落」以「中心未被反色 ＋ 角落未被阈值化为白」判定回落生效；④对比度 / 饱和度均为**端点方向断言**；饱和度按 **通道差绝对值**（本机回读通道序为 BGR，`[2]−[0]` 会是负值），避免通道序耦合。

**能力依赖**：依赖像素回读（`readback_supported()` 假即 `GTEST_SKIP`；`未初始化设置无副作用` 与 `链计数与级序可读` 两例无需回读；第十四 / 十五轮补的 9 例均需回读）。

**链写法（本版次事实）**：用例经 `pipeline_load` 登记具名后处理管线，以「**目标组**（`render_target_create` N 次 ＋ `render_target_present_chain_set(handles, N)`）＋ `post_chain_set`」构成链路径；第 i 级源 = `targets[i % N]`、非末级宿 = `targets[(i+1) % N]`，各级采样集下标 = `级序 % N`。级数上限为 `POST_CHAIN_MAX_STAGES = 8`（超限整链拒绝）、目标数上限 4（`POST_SET_PER_SLOT`）、链只存管线句柄（失效句柄由门面在 `pipeline_unload` 时摘除并压缩级序）、`render_to_target_present` 已是 `render_chain_present` 的单级特例薄封装（两条路径共用一套录制实现）等取舍见清单 `R-FRAME-12`；「目标范围须与交换链一致」与容差 4 的口径见 `【待确认：TEST-70】`（**第十二轮已结案**：两条复核点已固化进本用例文件头注释，原文保留于附录 D）。第十四 / 十五轮的后处理预设（`灰度` / `描边` / `色调映射` / `亮部提取` / `模糊` / `对比度` / `饱和度`）同样经 `pipeline_load` 登记后由 `post_chain_set` 组装，未新增门面接口；`render_target_present_secondary_set` 已在第十五轮删除。

### 6.27 渲染文字布局测试（`渲染文字布局测试.cpp`，L2；本版次第十三轮新增，第十四轮补 2 例）

**目的**：验收文字布局能力——单行度量 `text_measure`（宽度按字形推进累加且**不含尾随空白**、高度恒为字体像素高度）与按布局绘制 `text_draw_layout`（显式 `'\n'` 换行、`max_width` 逐字符断行、按行对齐、行距取 `line_height`；**第十四轮**另验收 `tracking` 字距与 `first_line_indent` 首行缩进）。接口语义以 `Application/Renderer/src/render/Renderer/渲染器.h` 的注释与 `Application/Renderer/src/render/Text/文字布局数据.h`（`Text_Layout` / `Text_Align`）为准；被验证接口清单见 §3.3。

**夹具**：`Renderer_Text_Layout_Test`（空夹具）。窗口 128×96 隐藏窗口（高度留出多行空间）；字号 `FONT_PIXEL_HEIGHT = 16`；字体取自系统 `C:\Windows\Fonts\consola.ttf`（本机不存在时依赖字体的用例 `GTEST_SKIP`）。

**断言口径**：与既有文字用例一致——以「是否近似清屏色」判定墨迹（双编码候选 ＋ 容差 6 ＋ 通道排序；alpha 恒取第 4 字节）；`ink_in_band(y0, y1)` 统计纵向区间墨迹数、`ink_total()` 统计全文墨迹数、`ink_horizontal_extent(min, max)` 取墨迹水平范围（无墨迹时均为 0）；第十四轮另加 `band_horizontal_extent(y0, y1, min, max)` 按行高区间求墨迹水平范围，`first_line_extent` / `second_line_extent` 为其 `[0, 16)` / `[16, 32)` 两行区间的薄封装。坐标口径为像素坐标、原点在窗口左上、Y 向下。

| 用例 | 步骤与断言 |
| --- | --- |
| `未初始化守卫` | 未 `init`：`text_measure(1u, "AB", &w, &h)` **假**且两出参归零；`text_measure(1u, "AB", nullptr, nullptr)` **假且不崩溃**（出参可为空）；`text_draw_layout(1u, "AB", 0, 0, Text_Layout{})` **假** |
| `度量宽度随字符数单调` | `init` ＋ `font_load_file(font, FONT_PATH, 16)`：`"I"` / `"II"` / `"III"` 的宽度**严格递增**且均 > 0；`"I"` 的度量高度 == 16（恒为字号）；`"I   "` 与 `"I"` **等宽**（尾随空白不计）；无效句柄 `99999` 返回假 |
| `空文本度量为零` | `init` ＋ 加载字体：`""` 与 `"   "` 均返回**假**且宽、高出参归零（无可见字形即失败） |
| `显式换行产生两行墨迹` | `text_draw_layout(font, "I\nI", 4, 0, Text_Layout{})` 后回读：第 1 行区间 `[0,16)` 与第 2 行区间 `[16,32)` 均有墨迹、第 3 行区间 `[32,48)` **无**墨迹（仅两行） |
| `窄宽度逐字换行` | 先以 `text_measure(font, "I", …)` 取**单字形宽度**作 `max_width`，再 `text_draw_layout(font, "III", 4, 0, layout)`：前三行区间各有墨迹、第 4 行区间无墨迹（每行恰好一个字形） |
| `右对齐使墨迹靠右` | `max_width = 100`、`align = Text_Align::Right` 绘制 `"I"` → 墨迹水平范围**起点 ≥ 60**；同一文本改为 `Text_Align::Left` 再出一帧 → 起点 **≤ 20**（**兼作网格缓存键回归护栏**：缓存键为（字体, 文本, 布局三项），漏项会导致第二帧仍画在右侧） |
| `字距增大使墨迹右移`（本版次第十四轮补） | 同一字体与文本 `"III"`（原点 `(4,0)`）：`tracking = 6` 帧的墨迹右端 > 无字距帧右端 **+ 8**；左端**不变**（字距不改变起始笔位；兼作缓存键含 `tracking` 的回归护栏） |
| `首行缩进只影响首行`（本版次第十四轮补） | 文本 `"I\nI"`（原点 `(0,0)`）：`first_line_indent = 30` 帧的首行左端相对无缩进帧右移 **26–34**（±4 容差）；第二行左端与无缩进帧**完全一致**（缩进只作用于首行） |

**能力依赖与跳过**：`未初始化守卫` 不需 GPU/窗口；其余七例先 `init`（需真实 GPU 与隐藏窗口）。字体检查在前、`readback_supported()` 检查在后——`度量宽度随字符数单调` / `空文本度量为零` 只需字体，`显式换行产生两行墨迹` / `窄宽度逐字换行` / `右对齐使墨迹靠右` / `字距增大使墨迹右移` / `首行缩进只影响首行` 另需回读能力（缺失即 `GTEST_SKIP`）。故无字体的机器上本文件 1 例实跑、7 例跳过。

**易错点**：
- 「空 / 全空白文本」按**失败**（返回假、出参归零）处理，与 `text_draw` 的「空文本返回真但不登记绘制项」（§6.17）**语义不同**，两者不可类推。
- 右对齐断言依赖 `max_width = 100` 与窗口宽 128 的组合；改窗口宽、字号或字体后 60 / 20 两阈值需重估。
- `text_measure` 是**无字距基线**（不含 `tracking`），`tracking` 只影响 `text_draw_layout` 的行宽 / 换行 / 对齐；故字距用例只以绘制后的墨迹水平范围判定，不用度量宽度换算。
- `first_line_indent` 只作用于首行且不计入换行判据 / 行宽；右对齐 / 居中时首行会整体右移，可能超出 `max_width`（缩进用例固定左对齐，未覆盖该组合）。
- 网格缓存键为（字体, 文本, 布局）：同一文本换对齐必须重建网格——左 / 右两帧的墨迹位置对比即该键完整性的回归护栏。

## 七、模块运行链路详例

### 7.1 初始化/销毁链路（L1，`Renderer_Init_Test`）

1. `Renderer renderer;` —— 构造不创建任何 GPU 资源（公共头注释）。
2. 拒绝路径：`renderer.init(hidden_config(0,180))` → 配置校验失败 → 返回假，`valid()` 仍假，无窗口建立。
3. 正常路径：`renderer.init(hidden_config())` → 建隐藏窗口/表面/交换链/管线/加载 `shaders` → 真，`valid()` 真，`extent_*()>0`。
4. `renderer.shutdown()` → 逆序释放 → `valid()` 假；二次 `shutdown()` 幂等。
5. 关闭后可 `renderer.init(...)` 再次成功；析构时隐含 `shutdown`。

### 7.2 帧推进链路（L2，`Renderer_Frame_Test`）

1. `renderer.init(hidden_config(frame_overlap, vsync))`。
2. 循环 `renderer.frame_render()`：泵事件 → 取图像 → 录制 → 提交 → 呈现；成功帧数自增。
3. 断言 `frame_count()==成功帧数==60`。
4. `shutdown()` 后再 `frame_render()` → 返回假（未初始化守卫）。

### 7.3 网格与纹理链路（L2，`Renderer_Mesh_Test` / `Renderer_Texture_Test`）

1. `init` 后 `mesh_load(handle, triangle_data())` —— 顶点/索引上传至设备本地，句柄写回（`handle!=0`）。
2. `mesh_draw(handle, nullptr)` —— 只**登记**待绘制项（`nullptr` = 单位模型矩阵）；同一帧可多次登记。
3. `frame_render()` —— 消费该帧全部待绘制项。
4. 纹理链：`texture_load`/`texture_load_checkerboard` 取得句柄 → `texture_bind_set` → `frame_render`；`texture_bind_set(0)` 或卸载后句柄回落默认白纹理。
5. 收尾 `mesh_unload` / `texture_unload`；重复卸载幂等。

### 7.4 着色器校验失败链路（L1，`Renderer_Shader_Test`）

1. `SetUp`：`remove_all` 两目录 → `create_directories(shader_probe_dir)`。
2. 用例体：`write_bytes(probe_dir/场景.vert.spv, 伪造字节)`（或指向 `missing_dir` 不写文件）。
3. `renderer.init(shader_config(dir))` → 加载并校验着色器 → 命中「目录缺失 / 空文件 / 长度非 4 倍 / 魔数不符」之一 → 返回假；`valid()` 假。
4. `TearDown`：`remove_all` 两目录，清除伪造样本。

### 7.5 可见窗口目视链路（L3，`Renderer_Visible_Test`）

1. `if (!l3_enabled()) GTEST_SKIP()` —— 未设 `BYJY_RUN_L3` 即跳过，不弹窗。
2. `init(visible_config())` —— 建 640×360 可见窗口。
3. 循环 ≤120 帧 `frame_render()`（第二例另叠加 `mesh_draw`）；期间可人工观察清屏色/三角形/棋盘格。
4. 用户关窗 → `close_requested()` 真 → `break` 提前收敛；末 `frame_count()>0`。

### 7.6 边界分支汇总表

| 场景 | 触发点 | 处理 | 结果 |
| --- | --- | --- | --- |
| 非法配置 | `init` 前置校验 | 直接返回假 | 拒绝类用例通过 |
| 未初始化调用 | `frame_render`/`mesh_load`/`texture_load` | 门面守卫 | 返回假，句柄保持/复位 0 |
| 未初始化设置相机 | 相机 setter | 安全无操作 | `valid()` 仍假（不崩溃） |
| 着色器异常 | `init` 加载着色器 | 加载失败即失败 | `init` 假 |
| 可见窗口未获授权 | `l3_enabled()` 假 | `GTEST_SKIP` | 用例跳过、不弹窗 |
| 用户关窗 | 循环内 `close_requested()` | `break` | 提前收敛 |
| 无效/已卸载句柄 | `mesh_draw` / `texture_bind_set` | 绘制失败 / 回落默认白纹理 | 断言假 / 帧仍成功 |
| 重复关闭或卸载 | `shutdown` / `mesh_unload` / `texture_unload` | 幂等 | 不报错 |
| GPU 时间戳不支持 | `gpu_timestamp_supported()` 假 | 用例按能力分支断言（**不跳过**） | 断言三字段恒 0（优雅降级，见 §6.24） |
| 未初始化应用场景 / 设清屏色 | `scene_apply` / `clear_color_set` 且未 `init` | 静默返回 | `valid()` 仍假，不崩溃 |
| 非法后处理链句柄 / 第二目标缺失 | `post_chain_set` 句柄未登记 / 链长 ≥ 2 未设第二目标 | 整链拒绝 / 门面告警并回落单级默认 | 返回假、保持原链 / 帧仍成功（见 §6.26） |
| 非法场景描述 / 越界清屏色 | `scene_apply` 参数非法 / `clear_color_set` 分量越界 | 整次拒绝 / 钳制到 `[0,1]` | 保持原相机与清屏色 / 饱和（见 §6.25） |
