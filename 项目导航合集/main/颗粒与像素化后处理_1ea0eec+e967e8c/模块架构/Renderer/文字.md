> 源码根相对路径：`Application/Renderer/src/render/Text/`
> 本文覆盖 `Application/Renderer/src/render/Text/` 下的：对外头 `字体.h`（字形度量 `Font_Glyph`、字体记录 `Font_Record`、字体上下文 `Font_Context`）、对外语义头 `文字布局数据.h`（行内对齐 `Text_Align`、布局参数 `Text_Layout`，**Vulkan-free**）、私有头 `局部命名空间使用.h`，以及 `core/` 下的两个编译单元：`字体加载.cpp`（TTF 解析 ＋ 字形光栅化 ＋ 图集打包 ＋ 纹理上传）、`文字几何.cpp`（UTF-8 解码 ＋ 文字度量 ＋ 文字四边形几何生成）。

> 记录依据为当前工作区源码，不包含任何旧版次导航信息；文中所有路径均为相对源码根（`工作区`）的相对路径。正文中的推断处标注 `【待确认：R-TEXT-nn】`，详情集中文末附录 C。
> **本轮新增（第十二轮：跳过码点诊断计数）**：`Font_Record` 新增 `uint64_t skipped_codepoints = 0`（按码点去重、只增不减、跨多次绘制累加、字体销毁时随记录复位）；`Font_Context` 新增只读 `uint64_t font_skipped_codepoints_get(uint64_t handle) const`（句柄无效返回 0）。`core/字体加载.cpp` 的 `glyphs_ensure` 在**三处**递增该计数：①**本轮新增的前置判据**——`stbtt_FindGlyphIndex(&info, codepoint) == 0`（字体不含该码点；空白字符位图为空但 `FindGlyphIndex != 0`，故不误计）；②原有「字形过宽」分支；③原有「图集高度不足」分支。`font_destroy` / `destroy` 经 `record = Font_Record{}` 归零，**无新增代码**。`R-TEXT-01` **第十二轮结案**（详见 §6.11 / 附录 C）。

## 二、模块功能介绍

### 2.1 模块定位

「文字」位于渲染层源码目录 `Application/Renderer/src/render/Text/`，是渲染层本轮新增的子模块，处于依赖链**较靠下**的位置：它**向下**依赖纹理模块（字形图集的上传与销毁）与内存模块（间接，经纹理模块）、外部库 `stb_truetype`；**向上**被门面调用。

一句话概括：**本模块把「一个 TrueType 字体文件 ＋ 一个字号」烘焙为「一张 RGBA8 字形图集 ＋ 各字符的像素度量（加载期烘焙 ASCII，其余码点在绘制时惰性补烘）」，再把「一个 UTF-8 字符串」按这些度量展开为一批像素坐标下的四边形网格几何；字形图集与几何分别经纹理模块、网格模块落地，本模块自身不持有任何 Vulkan 类型、不做任何绘制。**

要理解它的边界，抓住三点：

1. **度量在加载时烘焙 ASCII、其余码点在绘制时惰性补烘（本轮改动）**：`font_load_file` 完成后，ASCII 字形的图集 uv、相对文本原点的像素矩形、笔位推进量（`advance`）与基线偏移（`baseline`）全部固化在记录里；`Font_Record` **保留字体文件字节与图集像素缓冲**，供非 ASCII 码点（如中文）在首次绘制时经 `glyphs_ensure` 按需光栅化补烘。绘制期对已烘焙字形不再触碰字体文件、不再重做度量计算。
2. **几何只做「按度量铺四边形」**：`text_layout_build` 只做 UTF-8 解码 ＋ 切行 ＋ 行内对齐 ＋ 字距与首行缩进 ＋ 笔位推进 ＋ 逐可见字形写 4 顶点 6 索引，是**纯 CPU、无 Vulkan、无 stb** 的确定性变换；`text_geometry_build` 是它的「默认布局（单行 / 左对齐 / 不换行 / 零字距 / 零缩进）」薄封装（第十三轮，见 §6.12）。
3. **本模块不接触描述符、管线、命令缓冲**：文字管线的登记、图集纹理的绑定、「像素坐标 → NDC」矩阵的构造、绘制项的登记，全部落在**门面**（见同层 `门面.md` §3.4.32~3.4.34 与 §6.13）。

### 2.2 职责边界与解决的问题

`Font_Context` 解决的问题可归纳为四点：

1. **把「字体文件 → 可采样图集」这条链收敛成一个入口**。`font_load_file` 在内部完成「读取字节 → 定位字体头（TTC 取第 0 号）→ 初始化字形信息 → 按字号求缩放 → 求基线 → 逐 ASCII 码点光栅化 → 行式打包 → 写入 RGBA8 像素 → 经纹理模块上传」全部步骤，对外只返回一个句柄。

2. **把「加载期烘焙」与「运行期惰性补烘」结合（本轮改动）**。加载时烘焙 ASCII 32..126 的全部度量；其余码点在绘制时经 `glyphs_ensure` 按需光栅化并追加进同一图集（为此记录保留字体文件字节，运行期以 `stbtt_InitFont` 重新定位字形头，**无需重新读盘**）。绘制路径对**已烘焙**字形不再重复解析 / 光栅化（代价是 `baseline` / `scale` 为加载时快照，字号变更须重新加载）。

3. **把「字符串 → 顶点」这条链收敛成一个静态入口**。`text_geometry_build` 输入「字体记录 ＋ UTF-8 字符串」，输出可直接交给网格模块的 `Mesh_Data`（顶点 ＋ 索引）；它把「码点解码、越界码点跳过、空白字符只推笔位、可见字形铺四边形」四件事一次做完，且**没有任何 Vulkan / 平台依赖**。

4. **为「字形图集的采样语义」提供明确口径**。图集固定为 RGBA8、**RGB 恒为白、A 为字形覆盖率、非字形区 A 为 0**，使片元着色器可以直接输出纹理色、由管线混合档承担半透明合成（见 §6.5）；同时字形在打包时**左右各留 1 像素间隔**，避免线性过滤下邻字渗色。

### 2.3 在整体架构中的位置

本模块处于渲染层依赖链中段，向下依赖纹理模块（与纹理模块背后的内存模块、设备模块），向上被门面调用：

```
        ┌──────────────────────────────────────────────────────────────┐
        │              engine::Renderer（门面，render/Renderer/）         │
        │   font_load_file / font_unload / text_draw                     │
        │   （text_draw：登记文字管线 → 取/建网格 → 绑图集 → 矩阵 → 绘制）│
        └───────────────┬──────────────────────────────┬─────────────────┘
                        │ Font_Context&（值成员）       │ Font_Context::text_geometry_build（静态）
                        ▼                              ▼
        ┌──────────────────────────────────────────────┴───────────────┐
        │                  engine::Font_Context（Text/字体.h）           │
        │   build / destroy / valid / font_load_file / font_destroy       │
        │   font_get / glyph_seek（静态）/ text_geometry_build（静态）    │
        └───────┬───────────────────────────────────────┬──────────────┘
                │ 图集图像经由 Texture_Context            │ 几何交由 Mesh_Context（门面转交）
                ▼                                        ▼
        ┌───────────────────────┐                ┌───────────────────────┐
        │ 纹理模块（Texture/）   │                │ 网格模块（Mesh/）      │
        │ texture_create_from_   │                │ mesh_create（顶点/索引  │
        │   memory / _destroy    │                │   共用缓冲上传）        │
        └───────────┬───────────┘                └───────────────────────┘
                    │ 图像/视图/采样器
                    ▼
        ┌───────────────────────┐
        │ 设备模块 / 内存模块     │
        └───────────────────────┘

        外部库：external/stb/stb_truetype.h（仅 core/字体加载.cpp 定义实现宏）
```

- **向上**：门面持有 `Font_Context font`（值成员），在 `init` ⑰ 调 `build`，在 `shutdown` 归还文本网格后调 `destroy`；`font_load_file` / `font_unload` / `text_draw` 分别转交 `Font_Context::font_load_file` / `font_destroy` /（`font_get` ＋ `text_geometry_build`）。
- **向下（层内）**：仅依赖**纹理模块**（`Texture_Context`，仅作引用入参）；对网格模块**无编译期依赖**（几何以 `Mesh_Data` 值返回，由门面交网格模块）。
- **向下（外部库）**：仅 `core/字体加载.cpp` 依赖 `stb_truetype`。

### 2.4 与相邻模块的职责分界

| 相邻对象 | 分界 |
| --- | --- |
| 纹理模块（`Texture/`，`Texture_Context`） | 纹理模块负责图像创建、上传、视图与采样器；本模块**只调用** `texture_create_from_memory`（上传字形图集）与 `texture_destroy`（归还图集），并**只作引用入参**（不持有其所有权）。图集的采样语义（过滤 / 寻址 / mip）由纹理模块的模块级共享采样器决定，**本模块不参与**。 |
| 网格模块（`Mesh/`，`Mesh_Context`） | 网格模块负责顶点 / 索引共用缓冲的创建与上传；本模块**不直接调用**它，而是产出 `Mesh_Data` 值，由门面在 `text_draw` 中转交 `mesh.mesh_create`。本模块**不含**网格模块的包含依赖。 |
| 门面（`Renderer/`，`Renderer`） | 门面负责：字体句柄的对外入口（`font_load_file` / `font_unload`）、文字管线懒登记（`文字.vert.spv` / `文字.frag.spv`，Alpha 混合档）、`(字体, 文本, 布局) → 网格` 缓存、字形图集绑定、**像素坐标 → NDC 仿射矩阵**构造、绘制项登记。本模块**不做**其中任何一环。 |
| 帧模块 / 管线模块 | 本模块**不接触**帧槽、命令缓冲、描述符集、图形管线；相关接线全在门面与帧模块。 |
| 外部库 `stb_truetype` | 字体解析与字形光栅化由该库承担（`stbtt_InitFont` / `stbtt_ScaleForPixelHeight` / `stbtt_GetFontVMetrics` / `stbtt_GetCodepointHMetrics` / `stbtt_GetCodepointBitmap` / `stbtt_FreeBitmap`）。**它只在 `core/字体加载.cpp` 中被消费**，且以警告抑制包裹包含（本层要求「零本层新增警告」，第三方库自身告警不属本层代码问题）。`core/文字几何.cpp` **不包含**本库。 |
| 引擎核心（`EngineCore`） | 经预编译头与日志系统（`logger`）间接依赖，与其余渲染子模块一致。 |

### 2.5 生命周期与状态机

`Font_Context` 的生命周期为四段式，`destroy` 幂等、析构兜底：

```
构造 Font_Context()                     ← 仅零值初始化，不加载任何字体
   → build(texture)                     ← 记录纹理模块（要求 texture.valid()）；此后 valid() 为真
   → font_load_file(handle, path, h)    ← 逐条加载字体并烘焙图集；句柄自 1 起、空槽复用
   → [使用] font_get / glyph_seek / text_geometry_build（静态）
   → font_destroy(handle)               ← 单条字体归还（含其图集纹理），槽位标记为空
   → destroy()                          ← 全部字体归还 ＋ 复位（幂等）
   → 析构 ~Font_Context()                ← 内部再调一次 destroy（兜底）
```

- 状态机仅两态：**未构建**与**已构建**。`valid()` 判据为 `texture != nullptr`（即 `build` 是否成功记录纹理模块）。
- `font_load_file` 要求 `valid()` 为真且 `pixel_height != 0`；任一前置不满足即记 `error` 并返回假，**句柄保持 0**。
- **失败不留半初始化记录**：加载过程中任一步失败（文件不可读 / 为空 / 解析失败 / 字形过宽 / 图集纹理创建失败），已光栅化位图逐一 `stbtt_FreeBitmap` 回收、图集纹理不创建，**不向 `records` 写入任何记录**。
- 句柄规则：**句柄自 1 起（0 表无效），下标 = 句柄 − 1，空槽复用**（优先复用第一个 `valid == false` 的槽，无空槽才 `push_back`）。
- `Font_Context` **不可拷贝、不可移动**（持有纹理模块引用与记录集合，拷贝构造与拷贝赋值均 `= delete`）。

- **私有头**：`Application/Renderer/src/render/Text/局部命名空间使用.h`，仅 `#include "字体.h"` ＋ `using std::string; using std::vector;`（见 §5.3）。
- **命名空间口径**：本模块对外头把类声明与结构声明均放在 `namespace engine` 中展开；因对外只暴露 `Font_Context` 与两个数据聚合结构，天然处于命名空间 / 类作用域内，无需额外前缀。

### 3.2 对外类型一：`Font_Glyph`（字形度量）

```cpp
struct Font_Glyph
{
    // 图集 uv（左上 / 右下）
    float u0 = 0.0f;
    float v0 = 0.0f;
    float u1 = 0.0f;
    float v1 = 0.0f;
    // 像素矩形（x0 / y0 为左上，x1 / y1 为右下；相对文本原点）
    float x0 = 0.0f;
    float y0 = 0.0f;
    float x1 = 0.0f;
    float y1 = 0.0f;
    // 笔位推进（像素）
    float advance = 0.0f;
    // 字形是否有可见像素（空白字符为假，但仍携带 advance）
    bool has_ink = false;
};
```

逐字段说明：

| 字段 | 类型 | 含义 | 约束 / 备注 |
| --- | --- | --- | --- |
| `u0` / `v0` | `float` | 字形在图集中的 uv **左上**角 | 由「图集矩形 ÷ 图集尺寸」在加载时算出；`v` 以图集左上为 0、向下增大 |
| `u1` / `v1` | `float` | 字形在图集中的 uv **右下**角 | 同上；`u1 − u0 = 字形宽 / 图集宽`、`v1 − v0 = 字形高 / 图集高` |
| `x0` / `y0` | `float` | 相对**文本原点（左上角）**的像素矩形左上 | `x0` 为字形位图相对笔位的水平偏移；`y0 = 位图垂直偏移 + baseline` |
| `x1` / `y1` | `float` | 相对文本原点的像素矩形右下 | `x1 = x0 + 字形宽`、`y1 = y0 + 字形高` |
| `advance` | `float` | 笔位推进量（像素） | `= 字体原始 advance × scale`；**空白字符也携带**（用于推进笔位） |
| `has_ink` | `bool` | 是否有可见像素 | 空白字符（如空格）为假；为真且 `x1 > x0 && y1 > y0` 才产出四边形 |

> `Font_Glyph` 是**纯数据聚合体**：无成员函数、无构造逻辑（仅零值默认初始化）。它对本层内部公开，是因为门面与文字几何都需要读其字段；建议经 `Font_Context::glyph_seek`（只读指针）取用。

### 3.3 对外类型二：`Font_Record`（字体记录；本轮改造）

```cpp
struct Font_Record
{
    // 字号（字形像素高度）
    uint32_t pixel_height = 0;
    // 基线相对文本原点的像素偏移（= ascent × scale 取整）
    float baseline = 0.0f;
    // 字形图集纹理句柄（由纹理模块持有；惰性追加字形时会重建为更新后的图集）
    uint64_t atlas_texture = 0;
    // 图集宽度（像素；一经确定不再变化，故已烘焙字形的 uv 恒稳定）
    uint32_t atlas_width = 0;
    // 图集高度（像素；同理不变）
    uint32_t atlas_height = 0;
    // 字形度量（码点 → 度量；惰性追加）
    std::unordered_map<uint32_t, Font_Glyph> glyphs;
    // 字体文件字节（保留以供惰性光栅化新码点）
    std::vector<uint8_t> font_bytes;
    // 图集像素（RGBA8 紧排；惰性追加字形时原地改写对应区域）
    std::vector<uint8_t> atlas_pixels;
    // 图集打包游标（行式打包）
    uint32_t cursor_x = 0;
    uint32_t cursor_y = 0;
    uint32_t shelf_height = 0;
    // 已退役的旧图集纹理（图集重建时产生；字体销毁时统一归还）
    std::vector<uint64_t> retired_atlas_textures;
    // 累计被跳过的码点数（补烘阶段判定为无法呈现；按码点去重）
    uint64_t skipped_codepoints = 0;
    // 记录是否有效
    bool valid = false;
};
```

逐字段说明：

| 字段 | 类型 | 含义 | 约束 / 备注 |
| --- | --- | --- | --- |
| `pixel_height` | `uint32_t` | 加载时请求的字号（字形像素高度） | `font_load_file` 要求为正；透传记录 |
| `baseline` | `float` | 基线相对文本原点的像素偏移 `= floor(ascent × scale + 0.5)` | 使 `y = 0` 对应文本顶端；文字几何用它把位图垂直偏移折算为「相对文本原点」 |
| `atlas_texture` | `uint64_t` | 字形图集纹理句柄 | 由**纹理模块**持有；惰性补烘时**重建**为新图集（旧句柄移入 `retired_atlas_textures`） |
| `atlas_width` | `uint32_t` | 图集宽度（像素） | 固定为 `512`（见 §6.2） |
| `atlas_height` | `uint32_t` | 图集高度（像素） | 加载时按「ASCII 占用高度 × 2、下限 256、向 4 对齐」确定，**此后不再变化** |
| `glyphs` | `std::unordered_map<uint32_t, Font_Glyph>` | 码点 → 字形度量（**本轮改动**：由 `std::array<Font_Glyph, 95>`「下标 = 码点 − 32」改为按码点哈希表） | 惰性补烘按需插入；未烘焙码点 `find` 不命中 |
| `font_bytes` | `std::vector<uint8_t>` | 字体文件字节（**本轮新增**：保留以供惰性补烘重新 `stbtt_InitFont`） | 加载时整块保留；空则无法惰性补烘 |
| `atlas_pixels` | `std::vector<uint8_t>` | 图集像素（RGBA8 紧排；**本轮新增**） | 惰性追加字形时**原地改写**对应区域；图集重建时据此重新上传 |
| `cursor_x` / `cursor_y` / `shelf_height` | `uint32_t` | 图集行式打包游标（**本轮新增**） | 加载结束时记录，供惰性补烘继续打包 |
| `retired_atlas_textures` | `std::vector<uint64_t>` | 已退役的旧图集纹理句柄（**本轮新增**） | 图集重建时旧句柄入列；**不可立即销毁**（可能仍被在途帧描述符集引用），在 `font_destroy` / `destroy` 统一归还 |
| `skipped_codepoints` | `uint64_t` | 累计被跳过的码点数（**第十二轮新增**） | 只统计补烘阶段判定「无法呈现」的码点（字体不含该码点 / 字形过宽 / 图集空间不足）；按码点去重（同一码点至多计一次）、只增不减、跨多次绘制累加；UTF-8 解码失败的字节不计；`font_destroy` / `destroy` 随记录复位（见 §6.11） |
| `valid` | `bool` | 记录是否有效 | 空槽为 `false`；`font_get` / `font_destroy` 均以此为判据；`font_destroy` 后整条记录复位为 `Font_Record{}` |

> **本轮改动要点**：
> 1. **字形表由定长数组改为码点哈希表**，使非 ASCII 码点（如中文）可被按需追加（原实现仅 `[32,126]` 有槽位）；
> 2. **记录保留字体文件字节与图集像素缓冲**，使惰性补烘可在绘制期重新定位字形头并原位改写图集；原「不保留字体文件字节」的取舍已被取代（见 §6.1.1）；
> 3. **图集高度在加载时即留出补烘余量且此后不变**，故已烘焙字形的 uv 恒稳定——这是「文字网格缓存跨补烘仍正确」的前提（见 §6.1.4 与 §7.7）。
>
> 常量 `FONT_CODEPOINT_FIRST` / `FONT_CODEPOINT_LAST` / `FONT_GLYPH_COUNT` 仍保留（`font_load_file` 加载期仍只烘焙该 ASCII 区间；`FONT_GLYPH_COUNT` 仅作区间长度常量，不再用作数组长度）。
>
> `Font_Record` 仍为**纯数据聚合体**（无成员函数）；对本层内部公开，供门面读取 `atlas_texture` 与把整条记录传给 `glyphs_ensure` / `text_geometry_build`。

### 3.4 对外类型三：`Font_Context`（字体上下文）

```cpp
class Font_Context
{

    Font_Context(void) = default;

    const Font_Record* font_get(uint64_t handle) const;
    uint64_t font_skipped_codepoints_get(uint64_t handle) const;         // 第十二轮新增（跳过码点诊断计数）
    Font_Record* font_get_mutable(uint64_t handle);                       // 本轮新增（惰性补烘需可写记录）

    static bool text_measure(const Font_Record& record, const std::string& text,
        uint32_t& width_out, uint32_t& height_out);                        // 第十三轮新增（单行度量）
    static bool text_geometry_build(Mesh_Data& data_out, const Font_Record& record, const std::string& text);
    static bool text_layout_build(Mesh_Data& data_out, const Font_Record& record, const std::string& text,
        const Text_Layout& layout);                                        // 第十三轮新增（按布局生成几何）
private:
    // 纹理模块（字形图集上传 / 销毁）
    Texture_Context* texture = nullptr;
    // 字体记录集合（下标 = 句柄 - 1）
    std::vector<Font_Record> records;

```

类级约定（来自头文件注释与实现）：

- **生命周期**：`build → font_load_file → 使用（含 text_draw 触发的 glyphs_ensure 惰性补烘）→ destroy`；`destroy` 幂等；析构兜底调用 `destroy`。
- **句柄规则**：句柄自 1 起（0 表示无效），下标 = 句柄 − 1，**空槽复用**（与纹理模块的「单调递增不复用」取舍**不同**，见 §6.1）。
- **所有权**：持有纹理模块裸指针引用与字体记录集合，故不可拷贝、不可移动。
- **不持 Vulkan 类型**：本类**不出现任何 `Vk*` 类型**（图集纹理只以 `uint64_t` 句柄表达），是渲染层内少见的「零 Vulkan 头依赖」子模块。
- **惰性补烘入口（本轮新增）**：`font_get_mutable` 取可写记录、`glyphs_ensure(record, text)` 按文本所需码点补烘、`text_codepoints(text, out)` 做 UTF-8 解码去重；门面 `text_draw` 先补烘再取几何 / 绑图集纹理（见 §7.7）。
- **布局与度量入口（第十三轮新增，第十四轮扩字距 / 缩进）**：`text_measure` 提供单行像素度量，`text_layout_build` 按 `Text_Layout` 生成换行 / 对齐 / 字距 / 首行缩进后的几何；`text_geometry_build` 退化为「默认布局薄封装」（见 §6.12）。两者均为**静态**、纯 CPU、无 Vulkan / stb 依赖。

### 3.5 接口逐条清单

#### （1）`Font_Context(void) = default`

- **功能**：构造，**不加载任何字体**。
- **行为**：`texture = nullptr`、`records` 为空；`valid()` 为假，任何加载 / 取用接口都会因前置检查失败而被拒。

#### （2）`~Font_Context(void)`

- **功能**：析构，内部调用 `destroy()`，**保证图集纹理不泄漏**。
- **约束**：即使未 `build` 或半构建，析构也安全（`destroy` 对空集合为空遍历、`texture` 为空时空转）。

#### （3）拷贝与赋值（`= delete`）

- **约束**：持有纹理模块引用与记录集合，**不可拷贝、不可移动**（未声明移动，故移动亦不可用）。

#### （4）`bool build(Texture_Context& texture)`

- **功能**：构建——**仅记录纹理模块**（供字形图集上传与销毁），不创建任何字体 / 纹理。
- **参数**：`texture`——纹理上下文引用。仅记录其地址（`Texture_Context*`），**不拷贝、不持有所有权**；调用方须保证该对象在本上下文整个使用期内存活。
- **返回值**：`bool`——记录成功返回真；前置不满足返回假。
- **前置**：`texture.valid()` 必须为真，否则记 `logger.error("字体:: 构建时纹理模块不可用")` 并返回假。
- **约定**：重复 `build` 会直接覆盖 `texture`（不清理既有 `records`），**约定「先 `destroy` 再 `build`」**，实现不做重入保护（与纹理模块 `Texture_Context::build` 同属隐式约定）。

#### （5）`void destroy(void)`

- **功能**：销毁——幂等，归还**全部**字体记录与其图集纹理。
- **行为**（按实现顺序）：
  1. 遍历 `records`：若 `texture != nullptr`，先归还当前图集（`record.atlas_texture != 0` 时 `texture->texture_destroy`），再遍历 `record.retired_atlas_textures` 逐个 `texture_destroy`（**本轮新增**）；随后 `record = Font_Record{}` 复位整条记录；
  2. `records.clear()`；
  3. `texture = nullptr`。
- **幂等性**：清空后 `records` 为空、`texture` 为空，再调用进入空遍历、无副作用。
- **约束**：销毁后需重新 `build` 才能再次使用；本函数**不销毁** `Texture_Context` 本身（只持引用）。

#### （6）`bool valid(void) const`

- **返回值**：`texture != nullptr`（即 `build` 是否成功记录纹理模块）。

#### （7）`bool font_load_file(uint64_t& handle_out, const std::string& path, uint32_t pixel_height)`

- **功能**：从 TTF 文件加载字体并构建 ASCII 字形图集；成功写出句柄（≥ 1）。
- **参数**：`handle_out`（出参，进入即置 0）；`path`（字体文件路径，以二进制读取）；`pixel_height`（字号 / 字形像素高度，须为正）。
- **返回值**：`bool`——成功返回真并写出句柄；**文件不存在 / 不可读 / 为空 / 解析失败 / 字形过宽 / 图集纹理创建失败**均返回假，句柄保持 0，**不留半初始化记录**。
- **前置**：`valid()` 为真（否则 `error("字体:: 加载字体时模块尚未构建")`）；`pixel_height != 0`（否则 `error("字体:: 字号必须为正")`）。
- **行为要点（详见 §7.2）**：
  1. 以二进制方式打开并定位到末尾取长度（`ios::binary | ios::ate`）；文件不存在 / 空 / 读失败即返回假；
  2. `stbtt_GetFontOffsetForIndex(bytes.data(), 0)`（**TTC 等多字体重文件取第 0 号**）→ `stbtt_InitFont`；
  3. `scale = stbtt_ScaleForPixelHeight(info, pixel_height)`；`stbtt_GetFontVMetrics` 取 `ascent`，`baseline = floor(ascent × scale + 0.5)`；
  4. 逐码点 ASCII 32..126：`stbtt_GetCodepointHMetrics` 取 `advance`（`× scale` 写 `glyph.advance`）；`stbtt_GetCodepointBitmap` 取 1 通道位图——**空白字符无位图，仅保留 advance 后跳过**；字形过宽（宽 + 2 > 图集宽）即回收全部位图并返回假；
  5. **行式（shelf）打包**：图集宽固定 `512`，字形左右各留 1 像素间隔、放不下则换行且行距 +1，行高取该行最高字形；
  6. **图集高度**（本轮改动）：`max(ASCII 占用高度 × 2, 256)` 并向 4 对齐（ASCII 占用高度 = 末行 y + 行高 + 1）；余量供惰性补烘，且此后不再变化（故已烘焙字形 uv 恒稳定）；
  7. 生成 RGBA8 像素：**RGB 恒 255、A 为覆盖率（零覆盖率跳过写入）、非字形区 A = 0**；
  8. 登记度量：`uv = 图集矩形 ÷ 图集尺寸`、`x0 = gx`、`y0 = gy + baseline`、`x1 = x0 + gw`、`y1 = y0 + gh`、`has_ink = true`；逐字形 `stbtt_FreeBitmap` 释放；
  9. `texture_create_from_memory(atlas_texture, atlas_pixels, atlas_width, atlas_height)` 上传（失败即返回假）；
  10. **填充记录（本轮改动）**：除 `pixel_height` / `baseline` / `atlas_texture` / `atlas_width` / `atlas_height` 外，还写入 `atlas_pixels`（图集像素缓冲）、`font_bytes`（字体文件字节）、`cursor_x` / `cursor_y` / `shelf_height`（打包游标），供惰性补烘使用；
  11. 分配句柄：**优先复用第一个空槽**，无空槽才追加。
- **本轮改动**：加载时**只烘焙 ASCII 32..126**；非 ASCII 码点（如中文）在绘制时由 `glyphs_ensure` 惰性补烘（见 §7.7）。
- **日志**：成功记 `info("字体:: 已加载 {}（字号 {}，图集 {}×{}，句柄 {}）")`。

#### （8）`void font_destroy(uint64_t handle)`

- **功能**：销毁单条字体（一并归还其图集纹理）。
- **约束/行为**：句柄无效（`handle == 0 || handle > records.size()`）直接返回；目标记录 `!valid` 亦直接返回（幂等）；否则 `texture != nullptr` 时先 `texture->texture_destroy(record.atlas_texture)`（句柄非 0 时）并遍历 `record.retired_atlas_textures` 逐个归还（**本轮新增**），随后 `record = Font_Record{}`（**标记槽为空**，供后续 `font_load_file` 复用）。
- **日志**：记 `info("字体:: 已销毁（句柄 {}）")`。

#### （9）`const Font_Record* font_get(uint64_t handle) const`

- **功能**：取字体记录。
- **返回值**：句柄无效 / 目标记录 `!valid` 时返回 `nullptr`；否则返回 `&records[handle - 1]`（**只读指针**）。

#### （10）`static const Font_Glyph* glyph_seek(const Font_Record& record, uint32_t codepoint)`

- **功能**：按码点取字形度量（**本轮改动**：在 `glyphs` 哈希表中 `find`）。
- **返回值**：`record.glyphs.find(codepoint)` 不命中（尚未烘焙，含非 ASCII 码点）时返回 `nullptr`；命中返回 `&it->second`。
- **用途**：`text_geometry_build` 内部据此判「是否已有该码点度量」，门面亦可用它做度量查询。

#### （11）`static bool text_geometry_build(Mesh_Data& data_out, const Font_Record& record, const std::string& text)`

- **功能**：生成字符串的文字几何，写入 `data_out`（顶层为 `Mesh_Data`：`vertices` ＋ `indices`）。
- **坐标系**：**像素坐标系，原点在文本左上角、Y 向下**；`position` 为像素坐标（`z = 0`），`uv` 为图集 uv（见 §6.6）。
- **返回值**：`bool`——至少产出一个可见字形返回真；**文本不含任何可见字形（空串 / 全空白 / 全为不支持码点）返回假且清空出参**。
- **行为要点（详见 §7.3）**：
  1. 进入即清空 `data_out.vertices` / `data_out.indices`（失败不留残几何）；
  2. `record.valid` 为假返回假；
  3. 循环：`utf8_decode` 取码点 → `glyph_seek` 取度量（**不支持码点跳过、不推笔位**）→ 若 `has_ink && x1 > x0 && y1 > y0` 则产出四边形 → 笔位 `pen_x += advance`；
  4. 四边形四角顺序为「左上 → 右上 → 右下 → 左下」，索引为 **`(0,2,1)` ＋ `(0,3,2)`**（见 §6.4）；
  5. 若始终无可见字形，清空出参并返回假。
- **第十三轮改动**：本接口改为 `text_layout_build(data_out, record, text, Text_Layout{})` 的**薄封装**（单行、左对齐、不换行），行为与旧实现**逐字节等价**；原实现已删除，几何规则统一由 §6.12 记载。
- **注**：本接口**不涉及 Vulkan、不涉及 stb**，可视为纯函数式变换（仅依赖传入的记录）。

#### （12）`Font_Record* font_get_mutable(uint64_t handle)`（本轮新增）

- **功能**：取**可写**字体记录（供惰性补烘修改记录）。
- **返回值**：句柄无效 / 目标记录 `!valid` 时返回 `nullptr`；否则返回 `&records[handle - 1]`。
- **用途**：门面 `text_draw` 取可写记录后调用 `glyphs_ensure`（见 §7.7）。

#### （13）`bool glyphs_ensure(Font_Record& record, const std::string& text)`（本轮新增）

- **功能**：**惰性按需光栅化**——把文本中出现而尚未烘焙的码点光栅化并追加进该字体图集。
- **参数**：`record`——可写字体记录（须 `valid`）；`text`——UTF-8 文本。
- **返回值**：`bool`——真表示文本所需字形已全部可用（或本就无需补烘）；假表示前置不满足 / 解析失败 / 图集纹理重建失败。
- **行为要点（详见 §7.7）**：
  1. 前置：`record.valid` 且 `texture != nullptr`；
  2. `text_codepoints(text, codepoints)` 解码去重（解码失败即返回真、无待补码点）；
  3. 收集 `glyphs.find` 不命中的码点（`missing`）；`missing` 为空即返回真；
  4. `record.font_bytes` 为空则记 error 返回假；否则 `stbtt_GetFontOffsetForIndex` + `stbtt_InitFont` 重新定位字形头、按 `record.pixel_height` 求 `scale`；
  5. 逐码点光栅化并按**行式打包**续写：本行放不下则换行（`cursor_x=0; cursor_y += shelf_height+1; shelf_height=0`）；**字体不含该码点 / 图集空间不足 / 字形过宽则跳过该码点**（记 warn、`++skipped_codepoints`）并**登记为无墨迹**（`glyphs[codepoint]` 置空度量，以免重复尝试）；
  6. **确有像素写入时**（`atlas_changed`）`texture_create_from_memory` 重建图集纹理，旧句柄 `push_back` 进 `retired_atlas_textures`（**不可立即销毁**：可能仍被在途帧描述符集引用），`atlas_texture = 新句柄`；
  7. 无像素写入则直接返回真（不重建纹理）。
- **日志**：跳过码点记 `warn`；补烘成功记 `info("字体:: 字形图集已补烘（现存 {} 个字形，图集 {}×{}）")`。

#### （14）`static bool text_codepoints(const std::string& text, std::vector<uint32_t>& codepoints_out)`（本轮新增）

- **功能**：把 UTF-8 文本解码为**去重**码点序列（实现于 `core/文字几何.cpp`，复用静态 `utf8_decode`）。
- **返回值**：至少解出一个码点返回真；空串 / 全为非法字节返回假（出参被清空）。
- **用途**：`glyphs_ensure` 据此收集待补码点。

#### （15）`uint64_t font_skipped_codepoints_get(uint64_t handle) const`（第十二轮新增）

- **功能**：取该字体**累计被跳过的码点数**（只读诊断入口）。
- **返回值**：`uint64_t`——句柄无效（`handle == 0 || handle > records.size()`）或目标记录 `!valid` 时返回 `0`；否则返回 `records[handle - 1].skipped_codepoints`。
- **口径**：与 `Font_Record::skipped_codepoints` 完全一致——只统计补烘阶段判定「无法呈现」的码点（字体不含该码点 / 字形过宽 / 图集空间不足），按码点去重、只增不减、跨多次绘制累加；UTF-8 解码失败的字节不计（见 §6.11）。
- **用途**：门面 `font_skipped_codepoints` 薄包装（见《渲染层-门面》§3.4.50 / §6.20）；`R-TEXT-01` 结案依据。

#### （16）`static bool text_measure(const Font_Record& record, const std::string& text, uint32_t& width_out, uint32_t& height_out)`（第十三轮新增）

- **功能**：度量**单行**文本的像素尺寸（不换行、不产几何）。
- **参数**：`record`——字体记录（须 `valid`）；`text`——UTF-8 文本；`width_out` / `height_out`——出参像素尺寸（进入即置 0）。
- **返回值**：`bool`——至少存在一个有墨迹字形返回真；`record.valid` 为假 / 空串 / 全空白 / 全为不支持码点（无任何有墨迹字形）返回假且两出参为 0。
- **口径**：
  1. **宽** = 逐个字形累加 `advance` 得到的笔位中，**末个有墨迹字形（`has_ink && x1 > x0`）的笔位右缘**四舍五入（`static_cast<uint32_t>(ink_right + 0.5f)`）——故**不含尾随空白**（尾随空白的 `advance` 只推笔位、不刷新右缘）；
  2. **高**恒为 `record.pixel_height`，与实际墨迹高度无关；
  3. **不做换行**、不识别 `'\n'` 的断行语义（`'\n'` 若字体不含 / 未烘焙，则按「不支持码点」跳过）；
  4. **不触发惰性补烘**：仅 `glyph_seek` 查已烘焙度量，故对尚未补烘的码点（如首次遇到的中文）不产出宽度，可能返回假或偏窄——调用方若要度量未烘焙文本，应先经 `glyphs_ensure`（或先绘制一次）。详见 §6.12。
  5. **无字距基线**：不接收 `Text_Layout`，故宽度**不含 `tracking`**；带字距布局的行宽须按 `advance + tracking` 另行累加（见 §6.12.2）。
- **用途**：门面 `Renderer::text_measure` 的直接实现依据（见《渲染层-门面》§3.4.51）。

#### （17）`static bool text_layout_build(Mesh_Data& data_out, const Font_Record& record, const std::string& text, const Text_Layout& layout)`（第十三轮新增）

- **功能**：按 `Text_Layout`（换行宽度上限 / 行高 / 行内对齐 / 字距 / 首行缩进）生成文字几何，写入 `data_out`。
- **参数**：`record`（须 `valid`）；`text`（UTF-8）；`layout`（`Text_Layout`，见 §6.12；默认值 `{0, 0, Left, 0, 0}` 等价于旧 `text_geometry_build`）。
- **返回值**：`bool`——至少产出一个可见字形返回真；`record.valid` 为假 / 无可见字形（空串 / 全空白 / 全不支持码点）返回假并**清空出参**（与原口径一致）。
- **行为要点（详见 §6.12 / §7.8）**：
  1. **阶段一：逐字符切行**——显式 `'\n'` 收束当前行并新起一行（空行保留，形成垂直间距）；`max_width > 0` 且当前行非空且 `line_advance + glyph.advance + tracking > max_width` 时断行；**单字形超宽不在此断行**（独占一行）；不支持码点跳过且不推笔位；
  2. **阶段二：逐行产出**——行顶偏移 = `line_index × line_height`（`line_height == 0` 取 `record.pixel_height`）；仅当 `max_width > 0` 时对齐生效：`Center → (max_width − 行宽) / 2`、`Right → max_width − 行宽`，**负偏移钳到 0**；**首行（`line_index == 0`）在对齐结果之上再叠加 `first_line_indent`**；行宽 = 该行 `advance` 之和 ＋ 每字形 `tracking`（含行尾）；`max_width == 0` 时单行、`align` 无效果；
  3. 四边形四角顺序与索引绕序与旧实现一致（`(0,2,1)` ＋ `(0,3,2)`，见 §6.4），顶点 `position = 像素坐标`（`z = 0`）。
- **注**：不涉及 Vulkan / stb；`text_geometry_build` 即本接口的 `Text_Layout{}` 薄封装。

### 3.6A 文字绘制子系统 `engine::Text_Renderer`（第四十七轮下沉；`src/render/Text/文字渲染.h`）

- **定位**：门面 `text_draw_layout` 的下沉承接者——负责「字形惰性补烘 → 管线懒登记 → （字体, 文本, 布局五项）网格缓存 → 图集绑定 → 像素→NDC 矩阵 → 绘制登记」六步；门面只保留一行转发。

- **依赖关系**：`文字渲染.cpp` 依赖 `字体.h`（记录 / 补烘 / 布局构几何）、`网格数据.h`（`Mesh_Data` / `Mesh_Handle`）与 `结果检查.h`（`logger`）；宿主侧依赖由 `Text_Host` 回调隔离。
- **缓存上限与延迟归还（第四十八轮）**：缓存条目上限 `MESH_CACHE_MAX = 64`；命中刷新 `last_used`（`++use_clock`），插入前若已满则把 `last_used` 最小项移入 `retired`（不立即销毁），并记 `retired_tick = frame_clock`。门面每帧调用 `frame_begin(overlap)`：`++frame_clock` 后，仅当 `retired_tick + overlap < frame_clock` 才真正 `mesh_destroy`——保证不销毁本帧已登记绘制项仍引用的网格。`font_meshes_destroy` 仍立即归还（字体卸载属帧间调用）；`shutdown` 清空缓存后统一归还并复位帧时钟 / 使用序号。

## 四、模块私有方法介绍

本模块类内**无私有成员函数**：`Font_Context` 的私有区仅有两条数据成员（纹理模块裸指针、字体记录集合），无任何私有成员函数。模块在 `core/文字几何.cpp` 的**匿名命名空间**内定义了一个自由函数 `utf8_decode`（UTF-8 单码点解码），它是模块内部实现细节，逐条如下。

### 4.1 `static bool utf8_decode(const std::string& text, size_t& offset, uint32_t& codepoint_out)`（`core/文字几何.cpp`，匿名命名空间）

- **签名**：`static bool utf8_decode(const std::string& text, size_t& offset, uint32_t& codepoint_out);`
- **功能**：自 `text[offset]` 起解出一个码点。
- **参数**：`text` 输入串；`offset` 读写位置（成功时推进、失败时按规则推进）；`codepoint_out` 出参码点。
- **返回**：解析成功返回真并推进 / 写出；失败返回假。
- **行为**：
  1. `offset >= text.size()` → 返回假（无剩余字节，**不推进**）；
  2. 首字节 `< 0x80` → 单字节 ASCII，推进 1、返回真；
  3. 首字节 `110xxxxx` / `1110xxxx` / `11110xxx` → 2 / 3 / 4 字节序列，取低位作码点累加起始值；
  4. **非法首字节**（含把续字节 `10xxxxxx` 当首字节）→ 推进 1、返回假；
  5. 后续字节数不足（`offset + continuation_count >= text.size()`，**尾部截断**）→ 推进 1、返回假；
  6. 逐续字节拼接，若某续字节不满足 `10xxxxxx`（**格式不符**）→ 推进 1、返回假；
  7. 全部通过 → 推进 `continuation_count + 1`、写出码点、返回真。
- **关键口径**：**失败一律「跳过 1 字节」而返回假，不中断整串**——调用方（`text_geometry_build`）据返回假直接 `continue`，从而对畸形 UTF-8 **容错**：坏字节被逐字节跳过，后续合法码点继续解码（见 §6.3）。
- **可见性**：匿名命名空间（内部链接），仅本编译单元可见。

> 注：本模块**类内无私有成员函数**；实现细节以文件内静态辅助函数承担（见 §4.2）。

### 4.2 `core/字体加载.cpp` 的文件内静态辅助函数（本轮复用说明）

`字体加载.cpp` 在 `namespace engine` 内定义了若干**文件内静态函数**，由 `font_load_file` 与 `glyphs_ensure`（本轮新增）**共用**，以保证补烘字形与加载字形口径一致：

- 临时结构 `Pending_Glyph`（待打包字形：码点 / 位图宽高 / 位图偏移 / 位图指针 / 打包后图集位置）；
- `glyph_bitmap_get`——光栅化单个码点（写出 advance，返回 1 通道位图，空白字符返回空指针）；
- `glyph_blit`——把覆盖率写入图集对应位置的 A 通道（零覆盖率跳过）；
- `glyph_metric_set`——登记字形度量（由图集矩形与图集尺寸推 uv，`y0 = 位图垂直偏移 + baseline`，`has_ink = true`）。

这些函数不对外可见；`font_load_file` 的加载期烘焙与 `glyphs_ensure` 的惰性补烘均在其基础上完成行式打包与度量登记。

### 5.6 数据流总览

- **加载期（`font_load_file`）**：`TTF 字节` →（stb）字形信息 →（stb）逐字形 1 通道位图 ＋ advance →（本模块）行式打包定位 →（本模块）RGBA8 图集像素 ＋ 逐字形度量 →（纹理模块）图集纹理 →（本模块）`Font_Record`（**含保留的字体字节 / 图集像素 / 打包游标**）。
- **补烘期（`glyphs_ensure`，本轮新增）**：`Font_Record`（`font_bytes` 重新 `stbtt_InitFont`）＋ 待补码点 →（stb）逐字形位图 →（本模块）续写打包游标 / 原位改写 `atlas_pixels` →（纹理模块）**重建图集纹理** → 旧句柄入 `retired_atlas_textures`。
- **绘制期（门面 `text_draw`）**：`Font_Record` ＋ `UTF-8 文本` →（`text_geometry_build`，或按布局经 `text_layout_build`，第十三轮）`Mesh_Data`（像素坐标顶点 ＋ uv ＋ 索引）→（网格模块）网格 →（门面）绑定文字管线与图集纹理、构造像素→NDC 矩阵、登记绘制项 →（帧模块）提交呈现。
- **销毁期**：`font_destroy` / `destroy` →（纹理模块）归还**当前图集与全部退役图集纹理** →（本模块）复位记录 / 清空集合。

## 六、模块设计/实现细节

### 6.1 关键设计取舍

#### 6.1.1 度量加载期烘焙 ＋ 运行期惰性补烘（本轮改造）

**原取舍（已被取代）**：加载时一次性完成解析、光栅化、打包与度量登记，`Font_Record` 因此可脱离字体文件存活，绘制路径零解析开销；代价是**仅 ASCII 可打印字符 32..126 可用**（记录不保留字体文件字节）。

**本轮取舍**：把「字体文件字节 ＋ 图集像素缓冲 ＋ 打包游标」保留在 `Font_Record` 中，加载时**只烘焙 ASCII 32..126**，其余码点（如中文）在首次绘制遇到时由 `glyphs_ensure` **惰性按需光栅化**并追加进同一张图集。理由：中文等大批汉字若在加载期全量烘焙，图集将远超单张贴图尺寸且大量字形从不被绘制（浪费内存与加载时间）；惰性补烘把「慢的一次性工作」推迟到真正用到时，且已烘焙字形 uv 因图集高度不变而恒稳定（见 §6.1.4）。保留字体字节的代价是每条记录多占一份字体文件内存（通常数百 KB～数 MB），换取运行期免重新读盘。

**共同点**：字号或字体变更仍须重新 `font_load_file`（`baseline` / `scale` 均为加载时快照）；换字号必然重建整张图集（`glyphs` / `atlas_pixels` 一并重来）。

#### 6.1.2 图集格式固定为 RGBA8（RGB 恒白、A 为覆盖率）

把字形覆盖率写进 **A 通道**、RGB 恒为白，使片元着色器可直接 `输出纹理色` 而不必做通道重排，且**半透明合成交给管线混合档**（见 §6.5）。概念上「单通道覆盖率图」也可行，但 RGBA8 与纹理模块既有的 `texture_create_from_memory`（固定 `VK_FORMAT_R8G8B8A8_SRGB`、4 字节 / 像素）**直接对齐**，无需为文字新增纹理格式分支。

#### 6.1.3 句柄「空槽复用」而非「单调递增不复用」

`font_destroy` 把记录复位为 `Font_Record{}`（`valid = false`）但不移除元素；`font_load_file` **优先复用第一个空槽**、无空槽才 `push_back`。这与同层纹理 / 网格模块的「句柄单调递增、永不复用」取舍**相反**（见《渲染层-纹理》§6.5）。取舍理由：字体是**低频、少数量**的资源（通常同一时刻只有 1~2 种字体），且重新加载同一字体是常见操作；复用空槽可使句柄数量与「同时存活字体数」一致，避免长跑下 `records` 无界增长。代价是句柄**不再稳定**：同一字体卸载后重新加载会得到**不同的句柄**（若空槽位置不同），调用方不得缓存旧句柄跨卸载使用。

#### 6.1.4 图集宽度固定 512

图集宽固定 `512` 使打包算法（行式 / shelf）与图集高度计算变成纯前缀式扫描，无需「寻找最小宽度」的箱装优化。代价是可能存在**行尾浪费**（一行放不下最后一个字形时换行，右侧留空），但对 ASCII 95 个字形、字号 16~48 的常见场景，宽度 512 的总高度仍在合理范围。字形**过宽**（`宽 + 2 > 512`）在加载期被显式拒绝（返回假）、在补烘期被跳过（登记为无墨迹）。

**图集高度同理固定（本轮改动）**：加载时按 `max(ASCII 占用高度 × 2, 256)` 并向 4 对齐确定，此后不变。这给惰性补烘留出余量，同时保证已烘焙字形 uv 恒稳定。代价是**补烘容量有限**——补烘越界（`cursor_y + 高 + 1 > atlas_height`）时该码点被跳过（登记为无墨迹），即存在**图集容量上限**（`512 × atlas_height`，登记为待确认项，见「待答疑清单.md」）。

### 6.2 关键算法：字形图集行式（shelf）打包

`core/字体加载.cpp` 的打包分两趟：

**第一趟**（逐码点）：取 advance（**无论有无位图都写**）；取 1 通道位图——空白字符（`mono == nullptr || 宽 <= 0 || 高 <= 0`）跳过、仅留 advance；字形过宽（`宽 + 2 > 512`）即回收已光栅化位图并整体失败。

**第二趟**（行式打包定位）：

```text
cursor_x = 0, cursor_y = 0, shelf_height = 0
for 每个待打包字形 item：
    若 cursor_x + item.width + 2 > 512：            // 本行放不下
        cursor_x = 0; cursor_y += shelf_height + 1;  // 换行，行距 +1
        shelf_height = 0
    item.atlas_x = cursor_x; item.atlas_y = cursor_y
    cursor_x += item.width + 2                        // 右侧留 1 像素 + 下个字形左侧 1 像素
    shelf_height = max(shelf_height, item.height)
atlas_height = 向上取整到 4 的倍数(cursor_y + shelf_height + 1)
atlas_height = max(atlas_height, 4)                  // 防御：至少 4 像素高
```

要点：

- **左右各留 1 像素间隔**：`cursor_x` 每次推进「字宽 + 2」，加上打包起点本身，使相邻字形在图集中**至少隔 2 像素**（左字形的右边界与右字形的左边界各让 1 像素），线性过滤采样时不会互相渗色。
- **行距 +1**：换行时 `cursor_y += shelf_height + 1`，行与行之间留 1 像素间隔，同理防渗色；图集高度再加 1，给末行底部留间隔。
- **向上取整到 4 的倍数**：图集高度对齐到 4 的倍数（`(h + 3) / 4 * 4`），是对上传路径的保守对齐（并非 Vulkan 强制要求，属实现保守取值）。
- **复杂度** `O(字形数)`，纯 CPU、无外部依赖（打包算法本身不依赖 stb）。
- **像素填充**：先把整张图集 RGBA 全部写为 `255,255,255,0`（RGB 恒白、A 透明），再把各字形位图的覆盖率**逐像素写入对应位置的 A 通道**（零覆盖率跳过写入，省去无谓写入）。

**惰性补烘的打包（本轮新增）**：`glyphs_ensure` 复用同一行式打包逻辑，但**游标来自 `record.cursor_x / cursor_y / shelf_height`**（加载结束时的状态），故补烘字形**续接在 ASCII 占用区之后**；越界换行规则与加载期一致。差异在于：**图集高度不变**，故放不下的码点被跳过（不同于加载期的整体失败）；且只有**确有像素写入**时才重建图集纹理（见 §7.7）。

### 6.3 关键算法：UTF-8 解码

`core/文字几何.cpp` 的 `utf8_decode`（见 §4.1）实现 1~4 字节 UTF-8 解码，失败策略为「**跳过 1 字节**」。这条口径有两个直接后果：

1. **畸形串容错**：非法首字节、续字节格式不符、尾部截断都不会中断整串，坏字节被逐字节跳过，后续合法码点继续解码；因此「半个汉字」「错位字节」只会丢掉少量字形，不会使整串几何为空。
2. **不推进笔位（针对越界码点）**：解码成功后若码点超出 `[32,126]`（`glyph_seek` 返回 `nullptr`），**跳过该码点且不推进笔位**——见 §7.3。注意「不支持码点」与「解码失败」是两条不同分支，但**都不产出几何、也都不推进笔位**。

> **本模块的实际支持面（本轮改动）**：加载时烘焙 ASCII 32..126；**非 ASCII 码点（含中文）在绘制时经 `glyphs_ensure` 惰性补烘**进图集，因而可正常产出字形。若补烘因**字体不含该码点 / 图集空间不足 / 字形过宽**而跳过，该码点在本次 `glyph_seek` 仍返回 `nullptr`（不产出字形），且后续不会重复尝试（已登记为无墨迹），同时累计进 `skipped_codepoints`（见 §6.11）。原 `R-TEXT-01`（图集仅 ASCII、超范围码点直接跳过）**已由 `36f6ac8` 解决**；**第十二轮**另补诊断计数接口，**该条已结案**（见 §6.11 与附录 C）。

### 6.4 关键实现结论一：文字四边形索引绕序

**结论**：文字四边形索引须用 **`(base+0, base+2, base+1)` ＋ `(base+0, base+3, base+2)`**（即「左上 → 右下 → 右上」＋「左上 → 左下 → 右下」），**与场景四边形的 `(0,1,2)` ＋ `(0,2,3)` 相反**。

**成因（务必与场景几何区分）**：

1. 文字顶点在**像素空间**（原点在文本左上角、Y 向下），而场景顶点在 NDC 空间（Y 向上）；
2. 门面在 `text_draw` 中构造的**像素→NDC 仿射矩阵不做 Y 翻转**（见 §6.6）：矩阵为 `m[0] = 2/W`、`m[5] = 2/H`、`m[10] = 1`、`m[12] = 2·pixel_x/W − 1`、`m[13] = 2·pixel_y/H − 1`、`m[15] = 1`，其 2×2 主块行列式 `= (2/W)·(2/H) > 0`；
3. 而 Vulkan 视口把 NDC `y` 映射为**向下递增的帧缓冲行号**，故「像素 Y 向下 ＋ 不翻转」的组合使屏幕空间映射的**定向为负**（相对场景的「NDC Y 向上 ＋ 不翻转」）。

**后果（实测）**：若文字沿用场景绕序 `(0,1,2)` / `(0,2,3)`，在「背面剔除」的默认状态下**文字的所有三角形都会被判为背面而剔除**，表现为**一个像素都不出现**。故必须采用与场景相反的绕序。

> 口径提醒：绕序与「坐标系翻转」是**成对**的约定，改其一必改其二。若将来改为「像素→NDC 矩阵翻转 Y」（`m[5] = −2/H`），则文字绕序应同时改回场景的 `(0,1,2)` / `(0,2,3)`。

### 6.5 关键实现结论二：片元不判 alpha 与管线混合档

**结论**：文字片元着色器（`assets/shaders/文字.frag`）**不判断 alpha 阈值、不做 discard**，输出「字形覆盖率 × 推送颜色」；半透明合成依靠**管线 Alpha 混合档**完成（文字管线登记时即指定 `Blend_Mode::Alpha`，见 §7.6）。**第十六轮**：文字颜色由推送常量（offset 64 的 `vec4`）给出，覆盖率同时乘到 RGB 与 alpha；未设置时门面默认白色，输出与旧版逐像素一致（见《渲染层-门面》§3.4.35）。

**成因**：图集 RGB 恒为白、A 为覆盖率（见 §6.1.2）。若片元把「A 低于阈值」判为透明并 `discard`，则字形边缘的抗锯齿覆盖率会被整块丢弃，边缘出现硬锯齿；而**交给混合档**则使覆盖率直接作为混合因子参与 `src·A + dst·(1−A)`，边缘自然过渡，同时**保留字形内部的完整不透明度**。

**边界**：混合档是**管线级**属性。文字管线与默认场景管线共享同一管线布局与描述符集布局，仅「着色器对 ＋ 混合档」不同（见《渲染层-门面》§3.4.25）；文字项与场景项**共享同一实例缓冲与描述符集**（见附录 C 的 `R-TEXT-02` 相关备注与《渲染层-门面》§6.13）。

### 6.6 坐标系口径与像素→NDC 矩阵

**本模块产出的几何口径**（`text_geometry_build`）：

- 原点：**文本左上角**；Y 轴**向下**。
- 顶点 `position`：像素坐标（`z = 0`）。
- 单字形四角：`左上 = (pen_x + x0, y0)`、`右上 = (pen_x + x1, y0)`、`右下 = (pen_x + x1, y1)`、`左下 = (pen_x + x0, y1)`；`uv` 取该字形图集 uv（左上 `(u0,v0)` → 右上 `(u1,v0)` → 右下 `(u1,v1)` → 左下 `(u0,v1)`）。
- 笔位推进：每字形按 `advance` 前移 `pen_x`（**空白字符与不支持码点是否推进见 §6.3 / §7.3**）。

**门面侧的换算**（`text_draw`，非本模块，此处仅记口径以便理解几何的去向）：门面取交换链宽高 `W`、`H`，构造**列主序**仿射矩阵：

```text
m[0] = 2 / W, m[5] = 2 / H, m[10] = 1,
m[12] = 2 * pixel_x / W - 1, m[13] = 2 * pixel_y / H - 1, m[15] = 1
```

它把「像素 (px, py)」映射到 NDC，且**不做 Y 翻转**（成因与绕序对应见 §6.4）。故「像素 (x, y) 与屏幕帧缓冲行列一一对应」，`pixel_x` / `pixel_y` 即文本左上角在窗口内的像素位置。

### 6.7 内存所有权与销毁约定

| 资源 | 创建方 | 销毁方 | 依据 |
| --- | --- | --- | --- |
| `Texture_Context*`（引用） | 门面（值成员 `texture`） | 门面（`shutdown`） | 本模块只记录地址、**不拥有** |
| 字形图集纹理（`atlas_texture` 句柄） | 本模块经 `texture.texture_create_from_memory` | 本模块经 `texture.texture_destroy`（`font_destroy` / `destroy`） | 「创建与销毁同属一个模块」的推广：图集由本模块发起创建，亦由本模块发起归还 |
| 保留的字体文件字节 / 图集像素（`font_bytes` / `atlas_pixels`） | 本模块（加载时写入 / 补烘时改写） | 本模块（记录复位 / 清空即释放） | 纯数据（`std::vector`），随 `Font_Record` 生灭（**本轮新增**） |
| 已退役旧图集纹理（`retired_atlas_textures`） | 本模块经 `texture.texture_create_from_memory`（各次重建） | 本模块经 `texture.texture_destroy`（`font_destroy` / `destroy` 统一归还） | 旧纹理**不可立即销毁**——可能仍被在途帧描述符集引用；故累积至字体销毁（**本轮新增**） |
| `records` 中的 `Font_Record` | 本模块（`font_load_file` 写入 / 复用空槽） | 本模块（`font_destroy` / `destroy` 复位 / 清空） | 纯数据结构 |
| stb 位图（`unsigned char* mono`） | stb（`stbtt_GetCodepointBitmap`） | 本模块（`stbtt_FreeBitmap`，逐字形释放 / 失败回收） | stb 约定「调用方负责释放」 |

**关键约定**：

- 本模块**只销毁自己直接创建的对象**（图集纹理、位图）；`texture` 指向的对象由门面销毁。
- 加载失败路径必须**先回收再返回**：任一环节失败时，已光栅化位图逐一 `stbtt_FreeBitmap`、图集纹理**不创建**，且**不向 `records` 写入任何记录**（半初始化记录会破坏 `valid` 语义）。
- `destroy` / `font_destroy` 幂等：重复调用进入空遍历 / 早返回，无副作用。

### 6.8 线程 / 并发约定

本模块与渲染层其余子模块一致：**非线程安全**，`build` / `font_load_file` / `font_destroy` / `destroy` 与门面的文字绘制调用均须来自**同一线程**。本模块**未引入任何互斥量、原子量或同步原语**，成员均为普通标量与容器。`font_get` / `glyph_seek` 为只读查询，但本模块亦未承诺「可在其它线程安全读取」。

### 6.10 易错点清单

1. **`STB_TRUETYPE_IMPLEMENTATION` 只能定义一次**：本层唯一定义点为 `core/字体加载.cpp`；若在别处再定义会重复定义 stb 实现符号（链接冲突）。使用接口的文件只包含头、**不带**该宏。
2. **`core/文字几何.cpp` 不得包含 stb / 纹理头**：几何只消费「已烘焙度量」，引入 stb 会把第三方告警与实现体重带进来，也会破坏「几何与图集无关」的分层。
3. **文字绕序必须与场景相反**（见 §6.4）：沿用场景绕序会导致文字**全部被背面剔除**（一个像素不出现），是排查「文字明明登记了却看不见」的第一顺位检查点。
4. **像素→NDC 矩阵不做 Y 翻转**（见 §6.6）：`m[5] = 2/H`（正）而非 `−2/H`；与第 3 条成对，改其一必改其二。
5. **图集固定 `512` 宽、字形左右各留 1 像素**（见 §6.2）：改图集宽或间隔会同时影响 uv 与 `x0/x1` 的登记；间隔过小会在放大时出现邻字渗色。
6. **`baseline` 是「相对文本原点的像素偏移」而非「相对基线的偏移」**：`y0 = 位图垂直偏移 + baseline`，使 `y = 0` 对应文本顶端；写成「位图垂直偏移」会让文字整体上移 `baseline` 像素。
7. **含空白字符的串仍可能「无可见字形」**：空串、全空白、全为不支持码点都会使 `text_geometry_build` 返回假并清空出参；调用方（门面）必须据此拒绝登记绘制项。
8. **不支持码点既不产出几何、也不推进笔位**（见 §6.3 / §7.3）：若期望「用占位字形（豆腐块）代替」，当前实现**没有**该行为；但**非 ASCII 码点在绘制时会先被惰性补烘**（本轮起），故「不支持」实际只在补烘被跳过（**字体不含该码点** / 图集满 / 字形过宽）时成立；每次跳过均累加 `skipped_codepoints`（第十二轮起，见 §6.11）。
9. **`font_destroy` 后句柄可能被复用**（见 §6.1.3）：卸载后重新加载的字体**未必**拿到同一句柄；调用方不得跨卸载缓存旧句柄。同时门面侧还有一层「文本网格缓存」，须在 `font_unload` 中**一并归还**，否则网格会泄漏（见 §7.6）。
10. **重复 `build` 不清旧记录**：`build` 直接覆盖 `texture` 而不清理既有 `records`；约定「先 `destroy` 再 `build`」，实现不做重入保护（与纹理模块同）。
11. **图集高度对齐与最小高度对 uv 有影响**：`atlas_height` 向上取整到 4 的倍数且不小于 4，故 `v1` 的分母可能与「角落实际像素高度」不同；图集上传使用**对齐后**的高度，二者必须一致。

**本轮 / 第十二轮新增易错点**：

12. **惰性补烘会重建图集纹理、旧纹理退役累积**：`glyphs_ensure` 每次确有新字形写入都会新建图集纹理并把旧句柄压入 `retired_atlas_textures`；这些旧纹理在本字体销毁前不释放（防在途帧描述符集引用悬垂），故**同一字体长跑下退役纹理数会随补烘次数累积**（登记为待确认项）。
13. **`glyphs_ensure` 跳过的码点登记为无墨迹**：字体不含该码点、图集空间不足或字形过宽时，该码点以空度量登记进 `glyphs`，故不再重复尝试；当前实现**不支持扩充图集 / 换新图集**（登记为待确认项）。
14. **门面 `text_draw` 必须先补烘再取几何 / 绑纹理**：`glyphs_ensure` 会**替换 `atlas_texture`**，故须在 `text_geometry_build` 与 `texture_bind_set(record->atlas_texture)` **之前**调用（见 §7.7）。
15. **`skipped_codepoints` 是累计诊断量而非「本次跳过数」**：按码点去重、只增不减、跨绘制累加，字体销毁时随记录复位；且它只统计补烘阶段，**不含** UTF-8 解码失败的字节（见 §6.11）。

**第十三轮新增易错点**：

16. **对齐基准是「该行 `advance` 之和 ＋ `tracking`」**（见 §6.12）：行尾空白与行尾字距也计入行宽，故 `Center` / `Right` 在行尾含空白 / 字距时会**略偏左**（行宽被高估 → 起始笔位 `max_width − 行宽` 变小）；若需严格按墨迹对齐，须先裁掉行尾空白再交给布局。
17. **`max_width == 0` 时 `align` 无效果**：此时整段为单行、原点即锚点；`Center` / `Right` 不会产生任何位移（见 §6.12）。
18. **`text_measure` 不做换行、也不触发惰性补烘**：它只累加已烘焙字形的 `advance`，对尚未补烘的码点（如首次遇到的中文）不产出宽度；对含 `'\n'` 的文本不做断行（`'\n'` 若字体不含 / 未烘焙则按不支持码点跳过）。需要度量多行文本或未烘焙文本时，应先在门面侧补烘 / 按行切分（见 §3.5(16)）。

**第十四轮新增易错点**：

19. **`tracking` 计入行宽，`text_measure` 却不含字距**：`text_layout_build` 的换行判据与行宽均为 `advance + tracking` 累加（含行尾字距）；而 `text_measure` 只累加 `advance`（无字距基线）。用 `text_measure` 的结果预测带字距布局的换行 / 对齐会偏窄，必须自行补 `tracking`（见 §6.12.1 / §6.12.2）。
20. **`first_line_indent` 仅首行、且不计入换行判据**：它叠加在**对齐后的起始笔位**上，只影响第 0 行；不改变行宽、不参与 `max_width` 断行，故右对齐 / 居中时首行可超出 `max_width`（有意口径，不是溢出 bug）。同时它会改变首行字形位置，门面网格缓存键必须含该字段，否则换缩进仍命中旧网格（见《渲染层-门面》§3.4.52）。

### 6.11 跳过码点诊断计数口径（第十二轮新增）

**用途**：`R-TEXT-01`（超范围码点静默跳过）的结案产物——此前「码点被跳过」只能从 `text_draw` 返回假间接察觉；本轮起改为可查询的**累计诊断计数**，定位「文字缺字」不再只依赖日志。

**字段与接口**：
- `Font_Record::skipped_codepoints`（`字体.h`，`uint64_t`，默认 0），口径见 §3.3 字段表；
- `Font_Context::font_skipped_codepoints_get(handle)`（§3.5(15)）——句柄无效 / 空槽返回 0，否则读该字段；
- 门面 `font_skipped_codepoints(font)` 为**薄包装**（见《渲染层-门面》§3.4.50 / §6.20），门面不自行计数。

**三处递增点（`glyphs_ensure`，`core/字体加载.cpp`）**：

| 判据 | 源码条件 | 递增位置 | 备注 |
| --- | --- | --- | --- |
| 字体不含该码点 | `stbtt_FindGlyphIndex(&info, static_cast<int>(codepoint)) == 0` | `logger.warn("字体:: 字体不含码点 {}，已跳过", codepoint)` 之后、`record.glyphs[codepoint] = Font_Glyph{}` 与 `continue` 之前 | **第十二轮新增的前置判据** |
| 字形过宽 | `glyph_width + 2 > record.atlas_width` | 原有 warn 之后、`continue` 之前 | 原有分支，本轮仅补递增 |
| 图集高度不足 | `record.cursor_y + glyph_height + 1 > record.atlas_height` | 原有 warn 之后、`continue` 之前 | 同上 |

**为何以 `FindGlyphIndex` 判「字体不含该码点」**：空白字符（空格）的位图为空（`stbtt_GetCodepointBitmap` 返回 `mono == nullptr` 或宽高为 0），但其 `stbtt_FindGlyphIndex` **非 0**；故以「字形索引为 0」判定字体确实没有该字形，**不会把空格等空白字符误计为跳过**。该判据位于取位图之前，否则无法区分「字体无此字」与「有字但无墨迹」。

**去重、只增不减与累计口径**：
- 跳过时该码点以空 `Font_Glyph{}`（或已填 advance 的空度量）**登记进 `glyphs`**，故下次 `glyphs_ensure` 收集 `missing` 时不再命中——同一码点**至多计一次**；
- 计数跨多次绘制累加，**不随绘制结束复位**；
- `text_codepoints` 只产出**成功解码**的码点，UTF-8 解码失败的字节不进入补烘流程，故不计；
- 清零只发生在记录复位：`font_destroy` / `destroy` 均执行 `record = Font_Record{}`，该字段随之归 0（**无新增代码**）。

**与绘制信号的关系**：`text_draw` 返回假仍是「本次文本无任何可见字形」的唯一绘制侧信号；`skipped_codepoints` **不**替代它，而是回答「为什么缺字、累计缺了多少种字」——用于诊断而非流程控制，故不可把计数增量当作「本次绘制跳过的码点数」。

### 6.12 文字布局（度量 / 换行 / 对齐 / 字距与首行缩进）（第十三轮新增，第十四轮扩展）

**归属**：布局语义（做什么）落在本模块的 `文字布局数据.h` ＋ `text_measure` / `text_layout_build`；绘制（怎么画）仍全在门面（网格缓存、管线绑定、像素→NDC 矩阵、绘制登记，见《渲染层-门面》§6.21）。本模块**不新增任何 Vulkan / 状态字段**，布局是 `text_layout_build` 的**入参**而非 `Font_Record` 的成员。

#### 6.12.1 `Text_Layout` 五个字段的口径

| 字段 | 类型 / 默认值 | 口径 |
| --- | --- | --- |
| `max_width` | `float` / `0.0f` | 换行宽度上限（像素）。**`0` 表示不换行**：整段单行，此时 `align` 无效果、文本原点即锚点。对齐位移也以该值为基准。 |
| `line_height` | `float` / `0.0f` | 行距（像素）。**`0` 取 `Font_Record::pixel_height`**；行顶偏移 = `line_index × line_height`。 |
| `align` | `Text_Align` / `Left` | 行内对齐：`Left`（行起始笔位落在原点）、`Center`（按自身宽度居中于 `[原点, 原点 + max_width)`）、`Right`（行右端对齐到 `原点 + max_width`）。仅在 `max_width > 0` 时生效。 |
| `tracking` | `float` / `0.0f` | 字距（像素）。**计入行宽**：每收容一个字形，行推进量累加 `advance + tracking`，故同时影响**换行判定**与**对齐结果**；行宽含行尾字形的 `tracking`。**`text_measure` 是无字距基线**，不包含 `tracking`（见 §6.12.2）。 |
| `first_line_indent` | `float` / `0.0f` | 首行缩进（像素）。**只作用于第 0 行**，在算好的对齐起始笔位上**再叠加**（`pen_x += first_line_indent`）；**不计入行宽、不影响换行判定**。右对齐 / 居中 + 缩进时首行可能超出 `max_width`（有意口径）。 |

前三个字段为第十三轮引入，后两个为第十四轮新增；五项全为零时与旧布局逐字节等价（见 §6.12.5）。

该头为 **Vulkan-free**，可被上层与门面公共面直接包含（门面 `渲染器.h` 已包含，见《渲染层-门面》附录 B）。

#### 6.12.2 度量口径（`text_measure`）

- **宽**：按 `advance` 累加笔位，取**末个有墨迹字形（`has_ink && x1 > x0`）的笔位右缘**四舍五入 ⇒ **不含尾随空白**；
- **高**：恒为 `record.pixel_height`（不反映实际墨迹高度）；
- **无墨迹**（空串 / 全空白 / 全不支持码点）⇒ 两出参 0 ＋ 返回假；
- **无字距基线**：只累加 `glyph.advance`，**不含 `tracking`**，故其宽度不能直接用于预测带字距布局的换行 / 对齐；需要带字距的度量时按 `advance + tracking` 自行累加（或按布局生成几何后取包围盒）；
- **不换行**、不识别 `'\n'` 的断行语义、**不触发惰性补烘**（见 §3.5(16) / §6.10 第 18 条）。

#### 6.12.3 换行口径（`text_layout_build` 阶段一）

- **显式断行**：码点 `'\n'` 收束当前行并新起一行；**空行保留**（连续 `'\n'` 形成垂直间距）。
- **自动断行**：`max_width > 0` 且**当前行非空**且 `line_advance + glyph.advance + tracking > max_width` 时，先收束当前行再收容该字形。
- **行宽累加**：收容字形后 `line_advance += glyph.advance + tracking`，故断行判据与对齐用的行宽**同源**（均含 `tracking`）。
- **逐字符、不识别单词边界**：切行只按单字形 `advance`（＋ `tracking`）累加，英文长单词会被直接拆开。
- **单字形超宽**：因断行判据要求「当前行非空」，超宽字形**独占一行**（不在其前反复断行），随后不产生负溢出（对齐阶段钳 0）。
- **不支持码点**：跳过且不推笔位（与 `text_geometry_build` 一致）。

#### 6.12.4 对齐、首行缩进与行顶口径（`text_layout_build` 阶段二）

- 行顶偏移：`line_index × line_height`（`line_height` 已在阶段一按 `0 → pixel_height` 归一）。
- 起始笔位：仅 `max_width > 0` 时按 `align` 平移——`Center` 取 `(max_width − 行宽) / 2`、`Right` 取 `max_width − 行宽`；**负偏移钳到 0**（行宽超过上限时不自左溢出）。
- **首行缩进**：`line_index == 0` 时，在**上述对齐结果之后**叠加 `first_line_indent`（即 `pen_x += first_line_indent`）；它不参与行宽计算、也不回写行宽，其余行为 0。故右对齐 / 居中 + 缩进时首行右端可能超出 `max_width`，属有意口径。
- 行宽取「该行 `advance` 之和 **＋ 每字形 `tracking`**」，**含行尾空白与行尾 `tracking`**，故带尾随空白的行对齐会略偏（见 §6.10 第 16 条）。
- 四边形顶点与索引绕序不变（`(0,2,1)` ＋ `(0,3,2)`，见 §6.4）；`position = 像素坐标`、`z = 0`；逐字形推进为 `pen_x += glyph.advance + tracking`。

#### 6.12.5 `text_geometry_build` 的等价性

`text_geometry_build(data_out, record, text)` 现为 `text_layout_build(data_out, record, text, Text_Layout{})` 的**薄封装**（`max_width = 0`、`line_height = 0`、`align = Left`、`tracking = 0`、`first_line_indent = 0`）：单行、左对齐、行高不参与产出，故与原实现**逐字节等价**；原独立实现已删除，避免「同一几何规则两处实现」。

**与门面的分界**：布局**参与门面网格缓存键**（`(字体, 文本, 布局五项)`：`max_width` / `line_height` / `align` / `tracking` / `first_line_indent`，见《渲染层-门面》§3.4.52），否则同文本换布局 / 换字距 / 换缩进会命中旧网格；本模块不持有任何缓存。

## 七、模块运行链路详例

本章以「调用方 → 本模块 → 被调方」时序描述典型链路，覆盖主流程与关键异常 / 边界分支。

### 7.1 链路一：构建字体上下文

1. **调用方（门面）** 在 `init` ⑰ 调 `Texture_Context` 已就绪后调用 `font.build(impl->texture)`。
2. **`build`** 前置检查：`texture.valid()` 为假 → `logger.error("字体:: 构建时纹理模块不可用")`，返回假。
3. 否则记 `texture = &texture`，`logger.info("字体:: 上下文构建完成")`，返回真。
4. 此后 `valid()` 为真，可接受 `font_load_file`。

### 7.2 链路二：从 TTF 加载字体（主流程）

1. **调用方** 调 `font_load_file(handle_out, path, pixel_height)`（经门面 `Renderer::font_load_file`，见《渲染层-门面》§3.4.32）。
2. **前置**：`handle_out = 0`；`!valid()` → `error` 返回假；`pixel_height == 0` → `error` 返回假。
3. **读文件**：`std::ifstream file(path, binary | ate)`；`!file` → `error("字体:: 打不开字体文件 {}")` 返回假；`byte_count <= 0` → `error("字体:: 字体文件为空 {}")` 返回假；`seekg(0)` 后整块读入 `vector<uint8_t> bytes`，读失败 → `error` 返回假；`file.close()`。
4. **定位字体头**：`stbtt_GetFontOffsetForIndex(bytes.data(), 0)`（TTC 取第 0 号）；`font_offset < 0 || !stbtt_InitFont(&info, bytes.data(), font_offset)` → `error("字体:: 字体解析失败 {}")` 返回假。
5. **求缩放与基线**：`scale = stbtt_ScaleForPixelHeight(info, pixel_height)`；`stbtt_GetFontVMetrics` 取 `ascent`/`descent`/`line_gap`；`baseline = floor(ascent × scale + 0.5)`。
6. **逐码点光栅化**（`codepoint = 32..126`）：
   - `stbtt_GetCodepointHMetrics` 取 `advance`，写 `glyph.advance = advance × scale`（**无论有无位图都写**）；
   - `stbtt_GetCodepointBitmap(info, 0.0f, scale, codepoint, &w, &h, &xo, &yo)`；
   - 空白 / 空位图（`mono == nullptr || w <= 0 || h <= 0`）→ `continue`（仅留 advance）；
   - 字形过宽（`w + 2 > 512`）→ `error("字体:: 字形 {} 过宽（{} 像素），超出图集宽度 {}")`，**回收本字形与全部已光栅化位图**后返回假；
   - 否则登记待打包项（码点、宽高、偏移、位图指针）。
7. **行式打包定位**（见 §6.2），算出各字形 `atlas_x` / `atlas_y` 与 ASCII 占用高度；**图集高度** = `max(ASCII 占用高度 × 2, 256)` 并向 4 对齐（本轮改动）。
8. **构造图集像素**：`vector<uint8_t> pixels(512 × atlas_height × 4, 0)`，逐像素写 `RGB = 255, A = 0`；再逐字形把覆盖率写入 A 通道（零覆盖率跳过）、并登记该字形度量（`uv` / `x0` / `y0 = 偏移 + baseline` / `x1` / `y1` / `has_ink = true`）、随后 `stbtt_FreeBitmap(item.bitmap, nullptr)`。
9. **上传图集**：`texture->texture_create_from_memory(atlas_texture, pixels.data(), 512, atlas_height)`；失败 → `error("字体:: 字形图集纹理创建失败 {}")` 返回假。
10. **登记记录**：填 `pixel_height` / `baseline` / `atlas_texture` / `atlas_width` / `atlas_height` / `valid = true`；**本轮起另保留** `atlas_pixels`（图集像素）、`font_bytes`（字体文件字节）、`cursor_x` / `cursor_y` / `shelf_height`（打包游标），供惰性补烘。
11. **分配句柄**：扫描 `records` **复用第一个空槽**（写记录、`handle = index + 1`、`break`）；无空槽则 `push_back` 并 `handle = records.size()`。
12. 写出 `handle_out = handle`，记 `info("字体:: 已加载 {}（字号 {}，图集 {}×{}，句柄 {}）")`，返回真。

**异常 / 边界分支**：文件不存在 / 为空 / 读失败 / 解析失败 / 字形过宽 / 图集纹理创建失败 → 均返回假且句柄 0、无半初始化记录；空白字符不占图集空间、仅留 advance。

### 7.3 链路三：生成字符串文字几何

1. **调用方（门面 `text_draw`）** 先 `font_get_mutable(font)` 得 `Font_Record*`，调 `Font_Context::glyphs_ensure(*record, text)` 惰性补烘（见 §7.7），再调 `Font_Context::text_geometry_build(data, *record, text)`（第十三轮起即 `text_layout_build(..., Text_Layout{})` 的默认布局特例；带布局的链路见 §7.8）。
2. **进入**：清空 `data_out.vertices` / `data_out.indices`。
3. **前置**：`record.valid` 为假 → 返回假。
4. **循环**（`offset < text.size()`）：
   - **解码**：`utf8_decode(text, offset, codepoint)`；失败 → 已跳过 1 字节，`continue`；
   - **取度量**：`glyph_seek(record, codepoint)`；`nullptr`（码点越界）→ `continue`（**不推笔位**）；
   - **产出四边形**：若 `glyph.has_ink && x1 > x0 && y1 > y0` → 置 `any_ink = true`；按「左上 / 右上 / 右下 / 左下」写 4 顶点（`position = 像素坐标, z = 0`；`uv` = 图集 uv）；追加索引 `(base+0, base+2, base+1)` ＋ `(base+0, base+3, base+2)`；
   - **推进笔位**：`pen_x += glyph.advance`（**无论本字形是否有位图**——空白字符也推进）。
5. **收尾**：`!any_ink`（无任何可见字形）→ 清空出参并返回假；否则返回真。

**异常 / 边界分支**：空串 → 循环直接不执行 → 无可见字形 → 返回假；全空白 → 只推笔位、`any_ink` 恒假 → 返回假；畸形 UTF-8 → 逐字节跳过、其余码点继续；不支持码点 → 跳过且不推笔位。

### 7.4 链路四：单条字体销毁

1. **调用方（门面 `font_unload`）** 先清除该字体的**文本网格缓存**并归还网格（门面侧），再调 `font.font_destroy(handle)`。
2. **`font_destroy`**：句柄无效（`0` 或超界）→ 直接返回；目标记录 `!valid` → 直接返回（幂等）。
3. 否则：`texture != nullptr` → 先 `texture->texture_destroy(atlas_texture)`（句柄非 0 时）、**再遍历 `retired_atlas_textures` 逐个归还**（本轮新增）；`record = Font_Record{}`（标记槽为空）。
4. 记 `info("字体:: 已销毁（句柄 {}）")`。

### 7.5 链路五：整体销毁

1. **调用方（门面 `shutdown`）** 在归还文本网格、销毁网格模块**之后**、销毁纹理模块**之前**调 `font.destroy()`。
2. **`destroy`**：遍历 `records`，逐条归还**当前图集与全部退役图集**（`texture` 非空时 `texture->texture_destroy(atlas_texture)` ＋ 遍历 `retired_atlas_textures`，本轮新增）并 `record = Font_Record{}`；`records.clear()`；`texture = nullptr`。
3. **析构兜底**：`~Font_Context` 再调一次 `destroy`（此时集合已空、`texture` 已空，为无操作）。

### 7.6 与门面 / 网格 / 纹理 / 管线对接

本模块**不自行绘制**，其产出经门面接向网格、纹理与管线三模块（门面侧细节见《渲染层-门面》§6.13，此处只记交接点）：

1. **图集 → 纹理模块**：`font_load_file` 内 `texture_create_from_memory` 上传；销毁时 `texture_destroy` 归还。
2. **几何 → 网格模块**：门面 `text_draw` 调 `text_geometry_build`（或按布局经 `text_layout_build`，第十三轮）得 `Mesh_Data`，随后 `mesh.mesh_create` 上传为网格，并以「(字体句柄, 文本, 布局) → 网格句柄」缓存（`Impl::text_meshes`）；`font_unload` 时按字体句柄**清除缓存并归还网格**。
3. **图集 → 管线描述符集**：门面 `text_draw` 以 `texture_bind_set(record->atlas_texture)` 把字形图集绑为「当前纹理」（覆盖此前纹理绑定），使 `set1` 采到图集。
4. **几何 → 管线管线**：门面懒登记 `pipeline_load("文字.vert.spv", "文字.frag.spv", Blend_Mode::Alpha)`，并以 `pipeline_bind_set(text_pipeline)` 激活；随后构造像素→NDC 矩阵、`mesh_draw(mesh, 矩阵)`。

### 7.7 链路六：文字绘制中的惰性补烘（本轮新增）

以「门面 `text_draw` 绘制含非 ASCII 码点（如中文）的文本、而该字体加载时未烘焙这些码点」为背景：

1. **调用方（门面 `text_draw`）**：`font_get_mutable(font)` 取可写记录；
2. → `font.glyphs_ensure(*record, text)`：
   a. 前置 `record.valid && texture != nullptr`；
   b. `text_codepoints(text, codepoints)`（UTF-8 解码去重，见 §3.5(14)）；
   c. 收集 `glyphs.find` 不命中的码点（`missing`）；
   d. `stbtt_GetFontOffsetForIndex(record.font_bytes.data(), 0)` ＋ `stbtt_InitFont` 重新定位字形头，按 `record.pixel_height` 求 scale；
   e. 逐码点光栅化 → 行式打包续写（游标接在 ASCII 占用区后）→ 字体不含该码点 / 过宽 / 图集空间不足则跳过、登记无墨迹并 `++record.skipped_codepoints`（第十二轮起，见 §6.11）；
   f. 确有像素写入 → `texture_create_from_memory` 重建图集纹理、旧句柄入 `retired_atlas_textures`、更新 `atlas_texture`；
3. 返回后门面据几何 / 图集纹理绘制：`text_geometry_build(data, *record, text)` → `mesh.mesh_create` →（缓存）→ `texture_bind_set(record->atlas_texture)` → 登记绘制项。

**要点**：`glyphs_ensure` **必须在**取几何与绑纹理**之前**调用（否则 `atlas_texture` 未更新、`glyph_seek` 取不到新码点度量）；因图集高度固定，补烘重建后**已烘焙字形的 uv 仍不变**，故门面侧「(字体, 文本, 布局) → 网格」缓存中的**旧文本网格仍正确**（其 uv 指向同一位置）。

### 7.8 链路七：按布局生成文字几何（第十三轮新增，第十四轮扩字距 / 缩进）

以「门面 `text_draw_layout(font, text, pixel_x, pixel_y, layout)` 绘制一段需要自动换行 / 居中对齐 / 字距 / 首行缩进的文本」为背景（门面侧见《渲染层-门面》§3.4.52 / §6.21）：

1. **调用方（门面 `text_draw_layout`）**：`font_get_mutable(font)` 判活 → 空文本直接返回真（不登记）；
2. → `font.glyphs_ensure(*record, text)` 惰性补烘（同 §7.7）；
3. → 懒登记文字管线（`text_pipeline == 0` 时 `pipeline_load("文字.vert.spv","文字.frag.spv", Blend_Mode::Alpha)`）；
4. → 在 `text_meshes` 中按 **(字体, 文本, 布局五项)** 查找：布局的 `max_width` / `line_height` / `align` / `tracking` / `first_line_indent` **逐项比较**，任一不同即视为未命中；
5. → 未命中则 `Font_Context::text_layout_build(data, *record, text, layout)`：
   a. 阶段一：逐字符切行（显式 `'\n'` ／ `max_width` 超限，断行判据含 `tracking`；空行保留；单字形超宽独占一行）；
   b. 阶段二：逐行按 `line_index × line_height` 置行顶，按 `align` 平移起始笔位（`Center` ／ `Right`，负偏移钳 0），**首行再叠加 `first_line_indent`**，字形推进含 `tracking`，产出四边形与索引；
   c. 无可见字形 → 清空出参并返回假（门面记 `error("渲染器:: 文字几何生成失败（文本无可见字形）")` 并返回假）；
6. → `mesh.mesh_create(data)` 上传，并以 `Text_Mesh_Record{font, text, layout, mesh}` 记入缓存；
7. → `pipeline_bind_set(text_pipeline)` ＋ `texture_bind_set(record->atlas_texture)` → 构造像素→NDC 矩阵（原点仍为 `pixel_x / pixel_y`，即**首行左上角**）→ `mesh_draw(mesh, 矩阵)` 登记绘制项。

**要点**：① `max_width == 0` 时与 §7.3 / §7.7 的单行链路**几何等价**（`align` 无效果）；② 布局不写入 `Font_Record`，仅作 `text_layout_build` 入参与门面缓存键，故同一字体 / 文本可在不同布局下并存多个网格；③ 度量与布局互不影响图集（布局不触发补烘之外的任何光栅化）。
