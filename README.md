# 白银纪元 · 测试层

测试层是「白银纪元」四层工程（引擎层 → 系统层 → 游戏层，测试层横跨各层）中的**验证与启动层**。工程按依赖方向分层，每一层都是一个独立的 git 仓库，各推各的分支；本层对应的分支是 `test`，向远端 `sliverera/test` 推送。工程根目录另有一个 `main` 分支仓库，以「快照」形式收录四层源码，只作总览与合并线。

本层在依赖链中处于**横跨**位置：它与引擎层、系统层之间没有上下游的单向关系，而是同时接入两层——只链接两层**已经构建好的静态库**（`EngineCore.lib`、`SystemCore.lib`），绝不通过 `add_subdirectory` 把下层源码拉进本构建树重复编译，也没有任何源码回退路径。这条「层间一律链接已构建静态库」的契约由每层的 `cmake/对外接口.cmake` 与 `cmake/接入下层.cmake` 共同保证。

本层是**全项目唯一产出可执行文件的层**：`EngineTests.exe` 既是单元测试入口，也是整套工程的启动项。「宿主机制」（把下层组件按由浅到深的范围接在一起、各自产出启动项）已经取消，各层不再各自维护运行入口，可执行文件只由本层产生。

本层承载两件事：一是 **googletest 单元测试体系**（22 个套件 / 338 个用例，覆盖引擎层与系统层的核心模块，以及本层主调自身的逻辑）；二是**测试模块选择器**（图形窗口 / 控制台菜单 / 命令行开关三种交互形态），让同一份可执行文件同时服务「开发期按模块精准复跑」与「CI 一键全量回归」两类场景。

## 一、分支与仓库信息

### 1.1 仓库与分支

| 项 | 值 |
| --- | --- |
| 远端仓库地址 | `https://github.com/yuxingyuzhong/SilverEra.git` |
| 远端名（remote） | `sliverera` |
| 本地分支名 | `test` |
| 目标推送分支 | `test`（本地与远端同名） |
| 上游跟踪关系 | `test` → `sliverera/test` |

说明：

- 四层共用同一个远端仓库，各自推自己的分支（引擎层 `engine`、系统层 `system`、测试层 `test`、游戏层 `game`）。本层本地分支就叫 `test`，因此推送时本地名与远端名一致，无需像引擎层那样做 `main:engine` 的改名推送。
- 顶层 `main` 分支仓库是独立的一层仓库，与本层的 git 历史互不包含；它只做「四层源码快照 + 总览」，不会自动跟随本层更新。

### 1.2 本层在依赖链中的位置

```
引擎层 EngineCore.lib ──▶ 系统层 SystemCore.lib
        （已构建）              （已构建）
              ▲                      ▲
              └────── 测试层 ────────┘
                        │
                        ▼
              EngineTests.exe（全项目唯一可执行产物）
```

- 本层不产出供上层链接的库（对外面里的 `BYJY_TEST_OUT_LIB` 仅声明 `TestCore`，而 `TestCore` 当前无源文件、不产出）；`EngineTests.exe` 是运行产物，不写进对外面。
- 本层对下层只做「消费」：拿到两层的静态库与公共头文件路径，编译用例并链接。

### 1.3 仓库内布局与产物

| 项 | 值 |

### 1.4 许可证

本层**不单独维护许可证文件**，许可见工程根目录的 `LICENSE`。

### 1.5 与其余三层的关系

| 层 | 与测试层的关系 |
| --- | --- |
| 引擎层 | 本层链接其已构建的 `EngineCore.lib`；用例直接 include 引擎层头文件（事件、对象、空间分区、碰撞、工具集）验证真实现 |

| 顶层 `main` | 只做四层快照与总览，不参与本层构建 |

## 二、本层职责与核心特性

| 特性 | 说明 |
| --- | --- |
| 唯一可执行入口 | 全项目只此一份 `EngineTests.exe`；`main` 由本层主调提供，不链接 googletest 自带的 `gtest_main` |

## 三、技术栈

### 3.1 语言与标准

| 项 | 值 |
| --- | --- |
| 语言 | C++20（`CMAKE_CXX_STANDARD 20` + `REQUIRED ON`，`CMAKE_CXX_EXTENSIONS OFF`） |
| 命名空间 | `engine` |
| 源码风格 | 中文注释 + 中文用例名/文件名；MSVC 编译选项含 `/utf-8` 与 `/MP` |

### 3.2 第三方依赖

全部以**源码副本**形式入库在本层 `external/` 下，由本层自行编译（不改动下层构建脚本与对外接口）：

| 库 | 用途 | 引入方式 |
| --- | --- | --- |
| googletest | 单元测试框架 | `external/googletest/` 源码副本；`EXCLUDE_FROM_ALL` 接入，`INSTALL_GTEST OFF`、`BUILD_GMOCK OFF`、`gtest_force_shared_crt ON`（强制共享运行时库，避免与下层 CRT 设置冲突产生 LNK2038）；不使用 `GTest::gtest_main` |
| Dear ImGui | 图形选择窗口的即时模式界面 | `external/Dear_ImGui/` 源码副本；编 imgui 核心 4 文件（`imgui.cpp`/`imgui_draw.cpp`/`imgui_tables.cpp`/`imgui_widgets.cpp`）+ 后端（`imgui_impl_glfw.cpp`/`imgui_impl_opengl3.cpp`）；**不编 `imgui_demo.cpp`**（示例窗口用不到） |
| glad | OpenGL 函数加载器 | `external/glad/` 源码副本；编 `src/gl.c`，供图形窗口自身的 `glViewport`/`glClearColor`/`glClear` 调用 |

引擎层/系统层的第三方库（GLFW、nlohmann::json、bullet3、glm 等）**不在本层重复**，随下层的导入目标与对外面一并传递。

## 五、核心架构与运行链路

### 5.1 分层与依赖方向

```
         ┌───────────────── 测试层（本层） ─────────────────┐
         │  EngineTests.exe                                 │
         │   ├── main()            分流 / 过滤串 / 收尾等待  │
         │   ├── 测试选择模型        反射 gtest 注册表建树    │
         │   ├── 控制台选择菜单      编号菜单（回退入口）      │
         │   ├── 图形选择窗口        GLFW + ImGui 勾选界面    │
         │   └── RUN_ALL_TESTS()    执行选中的用例           │
         └───────┬──────────────────────────────┬───────────┘
                 │ 链接已构建静态库               │ 反射 / 过滤
        ┌────────▼────────┐              ┌───────▼────────┐
        │ EngineCore.lib  │              │  googletest    │
        │ SystemCore.lib  │              │ (GTest::gtest) │
        └─────────────────┘              └───────┬────────┘
                                                 │ 注册 TEST
                                        ┌────────▼────────┐
                                        │ src/单元测试/    │
                                        │ EngineTestObjects│
                                        └─────────────────┘
```

### 5.2 启动流程（`src/主调/主程序.cpp`）

主程序 `main()` 是全工程的进程入口，流程分六步：

1. 控制台切换 UTF-8 代码页（保证中文用例名可读）；
2. 摘出自定义开关 `--selector=`，其余参数原样保留，重建 `argv` 交给 googletest；
3. 调用 `InitGoogleTest()` 解析 googletest 参数（必须在建立选择模型之前完成）；
4. 四步分流——透传 / `off` / `console` / `window`（详见第六节）；
5. 选择结果落地为 `--gtest_filter` 过滤串，调用 `RUN_ALL_TESTS()`；
6. 交互运行结束后停住等待按键，自动化路径直接返回退出码。

一体化引擎时期，这份入口还兼管「核心对象构造 + 依赖注入装配」（即旧「启动流程」，文件为 `主调文件/主调文件.cpp`）；分层重构后该职责已移出本层，本层入口只保留**进程启动、参数分流、测试调度**，来龙去脉见第十三节。

### 5.3 一次完整运行的链路

```
[构建] 引擎层 EngineCore.lib → 系统层 SystemCore.lib → 本层 EngineTests.exe
[启动] EngineTests.exe（可带 --selector=... / --gtest_*）
   ├─ 交互路径（默认 window / console）：
   │     建立选择模型 → 反射 22 套件 / 338 用例 → 用户勾选 → 生成过滤串
   └─ 自动化路径（--gtest_* 透传 / --selector=off）：不建模型、不开窗
[执行] GTEST_FLAG(filter) = 过滤串 → RUN_ALL_TESTS() → 逐用例 SetUp / 用例体 / TearDown
[收尾] 交互运行打印提示并等待按键；自动化运行立即返回退出码（0 全过 / 非 0 有失败）
```

## 六、主调与测试模块选择器详解

主调模块位于 `src/主调/`，由六个源文件组成。

### 6.1 主程序（`src/主调/主程序.cpp`）

- **功能**：提供全工程唯一可执行入口 `main()`，完成参数摘取、googletest 初始化、四步分流、过滤串落地与收尾等待。
- **对外接口**：`int main(int argc, char** argv);`
- **实现要点**：
  - 参数摘取循环：凡以 `--selector=` 开头的参数被摘出为选择模式并标记「显式选择器」，不进入保留参数（否则 gtest 会报未知 flag）；凡以 `--gtest_` 开头的参数只做「命令行带过滤」标记，**原样保留**给 gtest；其余参数原样保留。`argv[0]` 做空指针兜底。
  - 四步分流：① 未显式指定选择器且带 `--gtest_*` → 直接透传执行；② `--selector=off` → 不开窗全量运行；③ `--selector=console` → 控制台菜单；④ 默认或 `--selector=window` → 图形窗口，窗口创建失败则打印提示并降级为控制台菜单。
  - 过滤串落地：执行前打印实际过滤串与 `--gtest_filter=` 复跑命令，再写入 `GTEST_FLAG(filter)`，只调用一次 `RUN_ALL_TESTS()`。
  - 收尾：`return 测试结果` 直接透传 `RUN_ALL_TESTS()` 的退出码供 CI 判级。
- **涉及文件**：`主程序.cpp`；依赖 `测试选择模型.h`、`控制台选择菜单.h`、`图形选择窗口.h`、`退出等待判定.h`。

### 6.2 测试选择模型（`src/主调/测试选择模型.h` / `.cpp`）

- **功能**：纯逻辑层，不依赖任何图形库。通过 googletest 反射枚举当前已注册的套件与用例，建立两层选择树；维护勾选态（全选 / 半选 / 单条）；生成 `--gtest_filter` 过滤串；解析控制台编号输入。图形窗口、控制台菜单与单元测试共用同一模型。
- **对外接口**：

```cpp
namespace engine
{
    // 选择树的两级条目
    struct 用例条目 { std::string 名称; bool 已勾选 = true; };
    struct 套件条目 { std::string 名称; std::vector<用例条目> 用例表; bool 已展开 = false; };

    class 测试选择模型
    {
    public:
        void 建立套件树();                              // 反射建树（默认全部勾选）
        const std::vector<套件条目>& 套件表() const;
        std::size_t 套件数() const;                     // 另有 用例总数 / 已勾选用例数
        bool 套件全选(std::size_t 套件序号) const;       // 另有 套件半选 / 套件已展开
        void 设置套件勾选(std::size_t 套件序号, bool 勾选);  // 另有 设置用例勾选 / 设置套件展开
        void 全部勾选();                                // 另有 全部清空 / 反向勾选
        std::string 生成过滤串() const;                  // 三态压缩（见实现要点）
    };

    bool 解析控制台选择(const std::string& 输入, std::size_t 套件数, std::vector<bool>& 勾选表);
}
```

- **实现要点**：
  - 反射建树：取 `::testing::UnitTest::GetInstance()` 单例，遍历 `total_test_suite_count()` 个套件、每个套件 `total_test_count()` 个用例，登记条目并默认勾选。
  - 过滤串三态压缩：**全不选**退化为 `"*"`（与 gtest 通配语义一致，即全跑）；**整套件全选**压缩为 `套件.*`；**部分勾选**逐条列 `套件.用例`；多条片段以 `':'` 连接。
  - 控制台输入解析：编号从 1 开始；支持 `1,3-5` 区间（左闭右闭且左值不大于右值）；支持 `all`/`ALL`/`a`/`*` 全选；空段、非法字符、越界编号一律整体判非法；数字解析设上限防御溢出。
- **涉及文件**：`测试选择模型.h` / `.cpp`。

### 6.3 控制台选择菜单（`src/主调/控制台选择菜单.h` / `.cpp`）

- **功能**：无图形环境（或用户显式指定）时的文本交互入口：打印套件编号列表，读取用户输入，把选择结果应用到模型并输出过滤串。
- **对外接口**：`void engine::控制台选择菜单_运行(测试选择模型& 模型, std::string& 过滤串);`
- **实现要点**：
  - 打印标题与逐条编号列表（`N) 套件名（M 个用例）`）。
  - 最多接受三次非法输入，其后兜底全跑；输入流结束（管道/重定向）与空输入（直接回车）均按全选处理。
  - 控制台菜单按**套件粒度**勾选；用例粒度是图形窗口的专属能力。
- **涉及文件**：`控制台选择菜单.h` / `.cpp`。

### 6.4 图形选择窗口（`src/主调/图形选择窗口.h` / `.cpp`）

- **功能**：默认交互入口，GLFW + OpenGL3 + Dear ImGui 的树形勾选窗口：展示套件与用例、支持搜索过滤与批量勾选、Esc / 关窗视为全跑。
- **对外接口**：`bool engine::图形选择窗口_运行(测试选择模型& 模型, std::string& 过滤串);`（窗口创建失败返回 `false`，调用方退控制台菜单）
- **实现要点**：
  - 初始化时序：`glfwInit` → 请求 OpenGL 3.3 核心上下文建窗 → `gladLoadGL` → 创建 ImGui 上下文 → 应用蓝色渐变主题 → 加载中文字体 → 主循环；三处失败点（GLFW 初始化、建窗、glad 加载）均返回 `false` 触发降级。
  - 界面：铺满视口的无标题面板；工具条含全选 / 清空 / 反选、搜索框与「已选 N / M」计数；选择树为「套件节点 + 用例复选」；底部为「开始测试」（或 Enter）与「取消（全跑）」（或 Esc）。
  - 细节：不写 `imgui.ini`（保持工作区整洁）；套件展开态由模型持有，避免每帧复位；搜索是「隐藏」而非「删除」，隐藏项勾选态保留；中文字体按候选链（微软雅黑 → 等线 → 黑体 → 宋体 → 楷体；非 Windows 另有一组）逐个探测，全部失败时界面仍可运行（中文显示为方块）。
- **涉及文件**：`图形选择窗口.h` / `.cpp`；第三方 `external/Dear_ImGui`、`external/glad`；GLFW 头文件与 `glfw3.lib` 由引擎层对外面传递。

### 6.5 退出等待判定（`src/主调/退出等待判定.h`）

- **功能**：判断本次运行结束后是否要停住等待用户按键。交互运行（默认 / `window` / `console`）需要停住，避免控制台一闪而过；自动化运行（透传 / `off`）必须跑完即走，否则 CI 会被挂住。
- **对外接口**：`bool engine::需要等待退出(const std::string& 选择模式, bool 命令行带过滤, bool 显式选择器);`
- **实现要点**：
  - 判定表（实现为两个早退 `return false` + 一个兜底 `return true`）：

    | 选择模式 | 命令行带过滤 | 显式选择器 | 结果 | 场景 |
    | --- | --- | --- | --- | --- |
    | window | 否 | 否 | 停 | 默认双击运行 |
    | window / console | 否 | 是 | 停 | 显式指定选择器 |
    | window / console | 是 | 否 | 不停 | gtest 参数透传（自动化） |
    | window / console | 是 | 是 | 停 | 显式选择器优先于透传约定 |
    | off | 任意 | 任意 | 不停 | ctest / 一键全量回归 |
    | 未知模式 | 任意 | 是 | 停 | 兜底：宁可多等一次 |

  - 头文件只放声明，**实现位于 `主程序.cpp`**：用例直接链接可执行文件里的同名符号，保证「用例验证的判定」与「主程序实际使用的判定」是同一份逻辑。
  - 停住动作（文件内部工具 `等待用户关闭窗口()`）：无控制台窗口时直接跳过；否则打印提示、清空控制台残留按键（避免确认用的回车被立刻吃掉）、阻塞等待任意键。
- **涉及文件**：`退出等待判定.h`（声明）+ `主程序.cpp`（实现）。

| 目标 | 类型 | 说明 |
| --- | --- | --- |
| `TestCore` | STATIC | `src/` 下功能测试代码（排除 `单元测试/`、`主调/`）；当前为空，跳过产出 |
| `TestGui` | STATIC | Dear ImGui 核心 4 文件 + glfw/opengl3 后端 + glad，仅供图形窗口使用 |
| `TestLauncher` | STATIC | 纯逻辑的测试选择模型 + 控制台菜单，供主程序与用例共用 |
| `EngineTestObjects` | OBJECT | 全部用例 `.obj`；用 OBJECT 库而非 STATIC，避免未引用 `.obj` 被链接器丢弃导致用例静默不跑 |
| `EngineTests` | 可执行文件 | 用例 `.obj` + 主程序 + 图形窗口，链接下层静态库与 gtest，输出到层根目录 |

设计要点：

- `TestLauncher` 与 `TestGui` 按**依赖方向**切开：图形窗口依赖 ImGui，单独编进 `EngineTests`，使用例不必拖上图形库；纯逻辑部分则被用例目标直接链接，用例可 include `测试选择模型.h` 验证选择逻辑。
- `EngineTestObjects` 用 OBJECT 库是本体系的关键决策：静态库里未被引用的 `.obj` 会被链接器丢弃，`TEST_F` 宏的静态注册随之丢失，用例便**静默不跑**（不报错，只是数量变少）。改回 STATIC 库是最危险的「优化」。
- 不链接 `GTest::gtest_main`：`main` 由本层 `主程序.cpp` 提供。

## 八、对外接口契约

### 8.1 本层对外面（`cmake/对外接口.cmake`）

本层对外面遵循统一契约，导出五个变量（前缀 `BYJY_TEST`）：

| 变量 | 值 / 含义 |
| --- | --- |
| `BYJY_TEST_OUT_LIB` | `TestCore`（本层静态库文件名，不含扩展名） |
| `BYJY_TEST_OUT_INC` | 本层根目录 + 系统层对外包含目录 |
| `BYJY_TEST_OUT_DEF` | 接系统层对外编译定义 |
| `BYJY_TEST_OUT_LINK` | 接系统层对外第三方库 |
| `BYJY_TEST_OUT_SYS` | 接系统层对外系统库 |

- 「本层对外面 = 本层自有面 + 下层对外面」的并入动作，由本层对外接口文件**直接 include 系统层对外接口**完成（纯数据赋值，重复 include 无副作用）；系统层又并入了引擎层对外面，因此接入系统层即同时取得两层公共路径。
- 备注：`TestCore` 当前只在 `src/` 下有源文件时才产出（`src/` 暂无功能测试源码，尚未产出库）；`EngineTests.exe` 不写进对外面——它是本层运行产物，不是供上层链接的东西。

### 8.2 接入下层（`cmake/接入下层.cmake`）

本层通过 `cmake/接入下层.cmake` 提供的 `byjy_jieru_xiaceng()` 接入引擎层与系统层。该文件在系统层 / 测试层 / 游戏层三份**逐字节相同**，改动须同步三层。函数签名：

```cmake
byjy_jieru_xiaceng(<下层对外接口文件> <对外接口变量前缀> <覆盖库路径变量名>)
```

调用方式（本层接两层）：

```cmake
byjy_jieru_xiaceng("${PROJECT_ROOT_DIR}/../引擎层/cmake/对外接口.cmake" "BYJY_ENGINE" "BYJY_ENGINE_LIB_PATH")
byjy_jieru_xiaceng("${PROJECT_ROOT_DIR}/../系统层/cmake/对外接口.cmake" "BYJY_SYSTEM" "BYJY_SYSTEM_LIB_PATH")
```

**三级库定位顺序**（任何情况下都不回退编译下层源码）：

1. **覆盖变量优先**：`BYJY_ENGINE_LIB_PATH` / `BYJY_SYSTEM_LIB_PATH` 非空且指向已存在的文件 → 直接使用；非空但文件不存在 → 直接 `FATAL_ERROR`，不静默降级。
2. **自动探测**：覆盖变量留空 → 扫 `<下层>/out/build/*/lib/<库名>.lib`，多个候选取**时间戳最新**的一份。
3. **硬失败**：仍找不到 → `FATAL_ERROR`，并给出构建下层的命令。

定位成功后，以下层声明库名为目标名建立 `IMPORTED STATIC GLOBAL` 静态库，把包含目录 / 编译定义 / 链接库挂到其 `INTERFACE` 上，供本层继续传递。

### 8.3 分层契约的硬约束

- 上层**只链接下层已构建的 `.lib`**，绝不通过 `add_subdirectory` 把下层源码拉进本层构建树重复编译。
- 包含路径沿依赖方向叠加：本层接入两层后自动获得引擎层全部包含路径（`common/` 预编译头、`src/` 头文件、`external/Json`、`external/glfw`、`external/bullet3/src` 等），无需重复声明。

## 九、构建与运行

### 9.1 前置条件

本层在配置阶段就会定位下层的**已构建静态库**，找不到即硬失败。因此必须**逐层构建**，顺序不能颠倒：

1. 构建引擎层，产出 `引擎层/out/build/<配置>/lib/EngineCore.lib`；
2. 构建系统层，产出 `系统层/out/build/<配置>/lib/SystemCore.lib`；
3. 再配置并构建本层。

### 9.2 构建命令

```bash
# 配置（CMake ≥ 3.20，Ninja 生成器，C++20）
cmake -S . -B out/build/x64-Debug -G Ninja

# 构建（产物：层根目录 EngineTests.exe）
cmake --build out/build/x64-Debug
```

如需跳过自动探测、显式指定下层库路径：

```bash
cmake -S . -B out/build/x64-Debug -G Ninja \
      -DBYJY_ENGINE_LIB_PATH=<EngineCore.lib 路径> \
      -DBYJY_SYSTEM_LIB_PATH=<SystemCore.lib 路径>
```

在 Visual Studio 中，用「打开本地文件夹」选中层目录，会读取本层 `CMakeSettings.json` 自动生成 `x64-Debug（Ninja）` 配置。

### 9.3 命令行参数

| 命令 | 行为 | 是否开窗 | 结束后是否停住 |
| --- | --- | --- | --- |
| `EngineTests.exe` | 默认 `window`：图形窗口树形勾选；窗口不可用时自动降级为控制台菜单 | 是 | 是 |
| `EngineTests.exe --selector=window` | 显式指定图形窗口（同样支持失败降级） | 是 | 是 |
| `EngineTests.exe --selector=console` | 控制台编号菜单，支持 `1,3-5` 区间与 `all` 全选，直接回车表示全跑 | 否 | 是 |
| `EngineTests.exe --selector=off` | 不开窗、不建模型，直接全量运行（ctest 使用） | 否 | 否 |
| `EngineTests.exe --gtest_filter=套件.用例` | 命令行已带 `--gtest_*` 且未显式指定选择器时直接透传，不弹窗 | 否 | 否 |
| `EngineTests.exe --gtest_list_tests` | 列出全部套件与用例（走透传分支） | 否 | 否 |

- 交互运行（window / console）跑完会打印提示并停住等待按键；自动化路径（透传 / off）不等按键，退出码不受影响。
- **显式 `--selector=` 优先于「带 gtest 参数即透传」的约定**：`--selector=console --gtest_filter=...` 会走控制台菜单，且菜单结果会覆盖命令行过滤串。
- 未知选择模式（如 `--selector=xxx`）会落到图形窗口分支，窗口失败再退控制台菜单；退出等待判定对未知模式兜底为「停住」。

### 9.4 ctest

在构建目录执行 `ctest`。注册策略分两路：

- 工程路径为**纯 ASCII** 时，用 `gtest_discover_tests` 逐用例注册；
- 工程路径含**非 ASCII**（本仓库路径含中文）时，退化为整体注册一个用例，命令等价于 `EngineTests --selector=off`。

退化的原因：`gtest_discover_tests` 会在构建期以 `--gtest_output=json:<文件>` 枚举用例，而 googletest 写该报告文件时按 ANSI 代码页解析路径，中文路径必然失败，构建会被判失败。退化分支用 `--selector=off` 不开窗直接全跑，无参数的 `ctest` 不会阻塞在图形窗口上。

## 十一、开发指南

### 11.1 如何新增一条用例

1. 在 `src/单元测试/<主调|工具|核心>/` 下打开或新建 `被测模块测试.cpp`；
2. 用例文件通用骨架：文件头一句话说明覆盖范围 → `#include <gtest/gtest.h>` → include 被测头文件（直接 include 真实源码头验证真实现）→ 夹具类（`class Xxx_Test : public ::testing::Test`）→ `TEST_F(套件名, 中文用例名)`；
3. 夹具三形态：空夹具（纯函数）、`protected` 成员被测对象（每用例独立构造）、静态辅助函数夹具（复用建树/写临时文件等公共逻辑）；
4. 重新构建，`file(GLOB_RECURSE ... CONFIGURE_DEPENDS)` 会自动收编新文件，**无需手改构建脚本**（除非新用例需要额外链接库）；
5. 运行验证：`EngineTests.exe --gtest_filter=新套件.*` 或 `--selector=off` 全量回归。

### 11.2 如何新增一个测试套件

- 若只是新增一个夹具类，直接在新建的 `*测试.cpp` 里 `class 新套件名_Test : public ::testing::Test` 并写 `TEST_F` 即可，套件名即夹具类名。
- 同一个 `.cpp` 文件可以注册多个套件（如 `碰撞测试.cpp` 含三个套件）。
- 新增后**反射驱动自动可见**：图形窗口与控制台菜单会直接出现新套件，无需改主调代码。

### 11.3 代码风格约定

- 命名空间统一为 `engine`；文件名 / 类名 / 注释 / 用例名用中文；英文标识符单词间用 `_` 分隔且首字母不大写（类名首字母大写）；
- 注释：汉字注释优先；不足三行用 `//` 且 `//` 后不留空格，三行及以上用 `/* */`；采用换行注释；函数头注释翻译函数名，函数体内为变量声明、`if` 条件、函数调用加注释；
- 源码统一 UTF-8，MSVC 编译选项必须带 `/utf-8`（中文源码、中文 include 路径、中文用例名都依赖它）；
- 临时文件（如网格加载用例写出的 `.obj`）必须在用例末尾删除，并用 `std::error_code` 容错；日志系统用例的落盘探针已纳入 `.gitignore`。

## 十三、历史沿革

本工程曾是一体化引擎（不分层），当时工程根有一份题名《游戏引擎》的长篇 README（733 行，对应版次 `0b8dbd27`）。分层重构后，那份 README 被删去，内容各归其位。与本层相关的对应关系如下：

| 旧（一体化引擎时期） | 现（分层后） | 说明 |
| --- | --- | --- |
| `主调文件/主调文件.cpp`（唯一入口，负责构造核心对象 + 依赖注入装配 + 事件中枢接入） | `测试层/src/主调/主程序.cpp` 等六个文件 | 入口职责被拆到测试层主调；旧文件承担的对象装配职责已移出本层，本层入口只保留进程启动与测试调度 |
| 旧「启动流程」：构造四个核心对象并注入 `attach_entry` / `event_entry` / `event_set_entry` / `prop_bind_entry` 通道 | 已取消，不再属于本层 | 「依赖注入装配」随分层重构移出测试层 |
| 旧「宿主组合根」与分层宿主（引擎宿主 / 系统宿主 / 全栈宿主） | 已取消 | 宿主把下层源码拉进本层构建树重复编译，与「层间一律链接已构建静态库」的契约冲突；且与测试入口职责重叠，故只保留一个入口 |
| `TestEngine.exe`（旧引擎测试入口） | `EngineTests.exe` | 改名并升级为全工程唯一可执行文件 |
| 引擎层 `EngineCore.lib` 与旧测试入口同树构建 | 各自产出静态库，本层只消费 | 层间契约由此确立 |

构建脚本中留有明确的旁证注释：本层「过去是宿主产地」，宿主机制取消后，可执行文件只在测试层产生。
