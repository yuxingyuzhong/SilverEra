# 聚光灯阴影上限评估（> 4 盏）

> 轮次：第 512 轮（文档轮，代码零改动）
> 基线哈希：Renderer `12560a3`、Test `a88a2bd`
> 关联：`深研预研_聚光灯阴影多盏.md`（第五百零七轮落地 4 瓦片）、`性能基线_方向七.md`

## 一、现状事实（以源码为准）

| 项 | 当前值 | 位置 |
| --- | --- | --- |
| 阴影瓦片数 | **4**（瓦片 0 常驻，1..3 首次开启多盏时按需创建） | `渲染器实现.h` `spot_shadow_targets[4]` |
| 采样数组 | set 1 `binding 9`，`sampler2D spot_shadow_map[4]`，`descriptorCount = 4` | `描述符布局.cpp` L89–91、`场景.frag` L62 |
| 矩阵入口 | `mat4 spot_view_proj_tiles[4]`（304..367） | `场景.frag` L133、`渲染器.cpp` L2916 |
| 深度跨度 | `vec4 spot_shadow_spans`（368..371） | `场景.frag` L134、`渲染器.cpp` L2919 |
| 槽位映射 | `vec4 spot_shadow_slots[2]`（372..379，8 个前向槽位，-1 = 不投影） | `场景.frag` L135、`渲染器.cpp` L2921 |
| 场景 UBO | `SCENE_BLOCK_FLOATS = 384`（1536 B；380..383 未用） | `渲染器实现.h` L977 |
| 阴影签名 | `spot_view_proj_tiles` 以 **64 浮点**参与 `shadow_signature_build` | `渲染器.cpp` L2441 |
| 描述符池采样器 | 每帧槽 `(1 + POST_SET_PER_SLOT + DRAW_SET_PER_SLOT) * 13` | `管线.cpp` L115–116 |
| 前向点光槽位 | 8（聚光与点光共用） | `point_spot_dir[8]` 等 |

结论：**槽位映射本身已支持 8 盏，限制只来自「瓦片数 4」**（矩阵 / 跨度 / 采样数组都按 4 写死）。
单遍聚光阴影耗时实测 **≈ 0.024 ms**（1/2/4 盏基本恒定），总成本随遍数线性增长。

## 二、候选方案

### 方案 1：沿用独立瓦片，把数组从 4 扩到 8（推荐）

思路：不换采样模型，仅把所有「4」扩成「8」，瓦片 4..7 同样按需创建。

改动点（共 8 处）：

1. `渲染器实现.h`：`spot_shadow_targets[8]`、`spot_view_proj_tiles[8][16]`、`spot_shadow_spans[8]`；`SCENE_BLOCK_FLOATS 384 → 448`；
2. `渲染器.cpp`：矩阵循环 `tile < 4 → 8`、候选表 `candidates[4] → [8]`、槽位映射写满 8、UBO 偏移改为
   304..431（矩阵）/ 432..439（跨度）/ 440..447（槽位）、阴影签名参数 `[64] → [128]`；
3. `spot_shadow_tiles_ensure()`：`tile < 4 → tile < 8`（运行期开关自动补齐 4..7）；
4. `渲染器.cpp` 释放路径：瓦片循环同步 `8`；
5. `描述符布局.cpp`：`sampler_bindings[9].descriptorCount 4 → 8`；
6. `管线.cpp`：采样描述符计数 `13 → 17`（8 个单张 ＋ 8 个数组元素 ＋ 1 余量）；
7. `场景.frag`：`sampler2D spot_shadow_map[8]`、`mat4 spot_view_proj_tiles[8]`、`vec4 spot_shadow_spans[2]`、
   `spot_shadow_factor` 增 5..8 分支（与本文件现有「显式四分支」风格一致）；
8. 关卡文本无需改（`light spot_shadow_all <0|1>` 语义不变，前 8 盏聚光各自投影）。

代价：

- 显存：每瓦片 1024² RGBA8 = **4 MB**，8 瓦片 = **32 MB**（比 4 瓦片多 16 MB）；
- 阴影 pass：最多 8 遍 × 0.024 ms ≈ **0.19 ms / 帧**（静态场景签名不变时仍跳过重绘）；
- 其余开销与盏数无关（前向着色仍按「每盏查一次映射」）。

风险：

- UBO 扩到 1792 B 仍在设备 `maxUniformBufferRange` 常见下限（64 KB）内，无兼容问题；
- 描述符池采样器上限按集数 × 17 计，帧槽 2 时 2×(1+POST+DRAW)×17，远低于常见 4000 上限；
- 阴影签名数组扩容后 `mix_float` 调用点同步改长度，漏改会导致「聚光移动不重绘」类缺陷。

### 方案 2：`sampler2DArray`（单绑定分层采样）

思路：把 8 张瓦片做成一张 `VK_IMAGE_VIEW_TYPE_2D_ARRAY` 的 8 层图，绑定 `sampler2DArray`，着色器按层号采样。

收益：绑定只占 1 个描述符、UBO 可省掉数组维度。
代价：需新增「数组颜色图 ＋ 逐层视图 ＋ 逐层渲染目标」的创建链路；阴影 pass 需按层设置视图 / 层号；
      现有 `render_target` 的单层目标接口不直接支持，改动面大于方案 1，且同样要跑 N 遍 pass。
结论：**8 盏以内不划算**，留作 16 盏以上的备选。

### 方案 3：单纹理图集（3×3 / 4×2 子视口）

思路：一张大图按网格切瓦片，阴影 pass 用 viewport/scissor 限定到子区域，采样时按 uv 偏移。
收益：绑定数量与显存占用最省（一张 2048² ≈ 16 MB 可容 4×4 瓦片，每瓦片 512² 等效精度）。
代价：每瓦片分辨率下降（4×4 时 512²）；采样需 uv 偏移 ＋ 边界 clamp；阴影 pass 需逐区域 viewport；
      `render_target` 需支持「子视口目标」，与现有「整图目标」模型冲突。
结论：**以画质换容量**，仅在需要 9 盏以上且显存受限时考虑。

### 方案 4：上限外降级 —— 只有前 4 / 8 盏投影

思路：超出容量的聚光灯照常照明但不投影（`spot_shadow_slots` 保持 -1）。
收益：零代码改动即可支持任意盏数照明。
代价：超过容量的灯会出现「亮但没有影子」的不一致观感。
结论：作为兜底策略保留，需在文档与展区说明中写明。

## 三、结论与实施顺序

1. **8 盏上限采用方案 1**：改动集中、语义不变、可复用现有按需建瓦片与运行期开关；
2. 若未来需要 9–16 盏，优先方案 3（图集）而非 `sampler2DArray`（后者改动最大而收益仅限绑定数）；
3. 超过容量一律按方案 4 降级（不投影但照明），禁止静默裁掉照明。

建议实施顺序（每步可单独验证）：

1. 数据结构与 UBO 扩容（`384 → 448`、矩阵 / 跨度 / 槽位偏移、签名 128）——画面不变；
2. 描述符布局 / 池计数 `4 → 8`、`13 → 17`——画面不变；
3. 着色器数组与 8 分支——画面不变（瓦片 4..7 仍为空）；
4. 瓦片 4..7 建目标 ＋ 绑定 ＋ 释放路径——8 盏用例出现独立阴影；
5. 关卡 / 展区接入 8 盏 ＋ 用例（差异像素、切回一致、开销基线复测）。

## 四、验收口径（供实施轮使用）

- 8 盏聚光场景：全部投影与单盏画面差异 > 100 像素；切回单盏差异 < 50 像素；
- 运行期开关在 8 盏下仍可切换，重复切换不新建瓦片；
- 阴影 pass 单遍耗时保持 ≈ 0.024 ms，8 遍总耗时 ≈ 8 × 单遍（容差 0.1 ms）；
- 全量回归 0 失败；显存增量与 4 张 1024² RGBA8 相符（约 +16 MB）。
