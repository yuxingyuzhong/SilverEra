# 深研方向二 · 阶段 C 常驻推进设计（第 326 轮定稿）

> 文件索引：[报告汇总索引](../渲染器自主迭代_执行报告汇总/索引.md) ｜ [计划汇总索引](../渲染器自主迭代_执行计划汇总/索引.md) ｜ [方向二规划](深研规划_方向二_粒子系统GPU模拟.md)

## 一、问题与依据

第 325 轮基线（1080p MSAA4、1 万粒子、容量 65 536）：

| 路径 | 单步耗时 |
| --- | --- |
| CPU 参考（`Particle_System::step`） | **0.374 ms** |
| GPU 同步链（上传镜像 → 调度 → 回读 → 镜像同步） | **20.777 ms** |

GPU 同步链的耗时几乎全部来自每步「2 MB × 2 上传 ＋ 2 MB 回读」，而非计算本身。
因此阶段 C 的核心是**粒子状态常驻显存**：每帧只下发模拟参数（推送常量）与少量计数回读。

## 二、目标数据布局

| 资源 | 布局 | 说明 |
| --- | --- | --- |
| 状态双缓冲 | `front` / `back`：容量 × 32 B（已有） | 每步 ping-pong，常驻显存 |
| 活跃位图 | 每 32 粒子 1 个 `uint32_t`（容量/32 字） | bit = 槽位是否活跃；GPU 发射置位、死亡压缩清位 |
| 活跃计数 | 1 × `uint32_t` | 每步结束后由 GPU 写；CPU 仅回读 4 B |
| 环形写指针 | 1 × `uint32_t` | GPU 发射时自增取槽；满则按容量回绕 |
| 力场数组 | 8 × 40 B（已有） | 每帧可更新（仅 force_count × 40 B） |
| 发射参数 | 推送常量扩展（发射位置 / 速度区间 / 寿命区间 / 形状 / RNG 种子） | 每帧 1 次小常量下发 |

所有「位图 / 计数 / 指针」与状态缓冲同容量，容量变化时与现有规则一致：等尽在途帧 → 释放 → 重建。

## 三、同步点（CPU 与 GPU 之间）

1. **初始化 / 容量变化**：CPU 全量上传一次（沿用 `particle_gpu_ensure`），位图清零、计数置 0。
2. **发射**：CPU 只写发射参数（推送常量 ＋ 可选种子），GPU 着色器按环形指针写状态、置位图、累加计数。
3. **推进**：每步只调度（无上传 / 无回读）。
4. **活跃数查询**：`particle_active_count` 在常驻模式下回读 4 B 计数（一次性命令缓冲或映射读数）。
5. **对照 / 调试**：显式 `particle_gpu_sync_readback` 全量回读（测试与展廊诊断用，常规帧不调用）。
6. **绘制**：默认从 GPU 位图 / 活跃列表取实例；CPU 镜像仅用于 CPU 参考与「关闭常驻」路径。

## 四、门面 API 草案（默认关闭，开关 `particle_resident_enable`）

| API | 语义 |
| --- | --- |
| `bool particle_resident_set(bool)` | 常驻模式开关；切换时等尽在途帧并按当前容量重建资源 |
| `uint32_t particle_active_count(void)` | 常驻模式下回读 GPU 计数（4 B），否则沿用 CPU 池 |
| `bool particle_gpu_emit(uint32_t count)` | GPU 发射（环形指针 ＋ 内建 RNG）；CPU 侧不写状态 |
| `bool particle_gpu_step_resident(float dt)` | 常驻推进：仅调度（含死亡标记与压缩），不读回 |
| `bool particle_gpu_sync_readback(void)` | 调试 / 对照：全量回读状态与位图到 CPU 镜像 |
| `bool particle_draw(float size)` | 常驻时活跃集合取 GPU 位图；否则沿用 CPU 活跃标记 |

## 五、间接绘制契约

- 常驻模式下粒子绘制项固定为**一条** `vkCmdDrawIndexedIndirect`（复用方向一间接命令缓冲）；
- 实例数由 GPU 在压缩 pass 末尾写入间接命令（`instanceCount`），CPU 不参与；
- 关闭常驻 / 设备不支持时回落到现有「CPU 活跃集合 + `mesh_draw_instanced`」路径，画面语义一致。

## 七、风险与回退

| 风险 | 预案 |
| --- | --- |
| 位图与状态不一致（发射 / 死亡竞争） | 同一步内「发射 → 死亡压缩」两 pass 严格顺序 ＋ 存储屏障；用例逐位比对 |
| GPU RNG 与 CPU LCG 分布差异 | 只要求统计同口径（数量 / 区间），逐粒子一致性由 CPU 参考路径保留 |
| 驱动对间接命令写入顺序差异 | 间接命令缓冲加 `INDIRECT` 用法＋计算→间接绘制屏障；失败回落 CPU 活跃路径 |
| 常驻模式引入画面变化 | 默认关闭；关闭态与现有路径逐字节一致（第 323 轮矩阵用例继续守护） |
