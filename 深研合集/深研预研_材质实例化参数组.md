# 深研预研 · 方向七候选：材质实例化参数组

> 预研轮：439（文档轮）｜状态：**候选定案（方案 A，排入下一窗口）**
> 相关：[方向六收口复盘](深研规划_方向六_收口复盘.md)、[方向五收口复盘](深研规划_方向五_收口复盘.md)

## 一、问题

当前 `Material_Data` 是**全局材质**：一组参数（tint / 粗糙度 / 金属度 / 卡通覆盖等）绑给一个绘制项。
关卡里的多个 `place` 若想同网格、同材质模板、但**不同颜色**，只能为每个配色复制整份材质（句柄翻倍），
无法在关卡文本里表达「用模板 + 覆盖参数」。

方向五的 `Asset_Object.materials` 是「材质句柄数组」（按 OBJ 段对齐）——它承载的是**引用**，不是参数。

## 二、目标形态

「**材质模板 ＋ 逐实例覆盖**」：

```
模板：Material_Data（tint / roughness / metallic / 卡通 / 自发光 …）
实例：Material_Instance = { 模板句柄, tint, emissive_tint, 卡通覆盖四项 }
```

- 一个模板可派生任意多个实例，GPU 侧只有**一份**材质 UBO / 推送数据（模板），实例只携带**覆盖参数**；
- 绘制时把实例覆盖参数合入材质（走既有逐绘制项 set1 / 推送路径），不新建管线；
- 关卡文本：`material <ID> <模板ID> <覆盖参数…>`，装载时产出「模板句柄 ＋ 覆盖参数」而**不复制材质**。

## 三、落地形态评估

| 方案 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| A. 实例参数进现有材质槽 | `Material_Instance` 持有模板句柄 ＋ 覆盖浮点组；绘制时临时改写材质记录再 `material_bind_set`（不改管线） | 改动最小，可逐实例覆盖 tint / 卡通 | 覆盖范围受「材质记录可改字段」限制；需防与共享缓存冲突 |
| B. 逐实例推送块 | 在实例缓冲（112 字节）追加一段覆盖参数（仿逐物体卡通 location 8/9 的套路） | 真正逐实例、无句柄复制 | 实例步长再加 16–32 字节；需补属性槽与着色器读取 |
| C. 材质句柄池 | 模板 × 覆盖参数组 → 生成独立 `Material_Handle`（内部复用同一管线） | 对外无新概念，关卡 `place` 直接引用材质句柄 | 句柄仍会随参数组增长；语义仍是「材质」不是「实例」 |

## 四、取舍建议

**优先方案 A**：范围最小、最贴合「数据化优先」——`Material_Instance` 作为关卡 / 场景的**中间层**，
只覆盖「tint（含 alpha）、自发光、卡通四项」这些**高频视觉差异**；模板句柄与覆盖参数在绘制时合成，
不复制资源。方案 B 留给「真正逐实例材质」的后续大件；方案 C 与现有缓存语义冲突，弃。

## 五、验收口径（若立项为方向七阶段 A）

| 项 | 口径 |
| --- | --- |
| 数据 | `Material_Instance { Material_Handle 模板; float tint[4]; float emissive_tint[3]; 卡通四项 }` |
| 装配 | 关卡 `material <ID> <模板ID> <覆盖…>` → `Asset_Scene` 输出实例而非句柄数组 |
| 绘制 | `scene_draw` 对带实例的对象把覆盖参数合成到材质记录后绘制 |
| 等价 | 覆盖参数等于模板默认值 → 画面与旧材质完全一致 |
| 生效 | 同模板两实例不同 tint → 画面差异 > 200 像素 |
| 边界 | 未知模板 ID / 覆盖字段数不符 → 整份拒绝 |
| 回归 | 关卡 15 ＋ 资产 19 ＋ 展示巡查 3 全过 |

## 六、定案建议（自主决策，留痕）

**建议按方案 A 立项为方向七**：以 `Material_Instance` 作为关卡 / 场景与绘制之间的中间层，只覆盖
tint（含 alpha）、自发光与卡通四项；模板句柄不复制资源。理由：与方向五 / 方向六的数据化口径一致、
改动面最小、可直接在关卡文本表达「同模板不同配色」。

若后续发现覆盖范围不足（例如需要逐实例粗糙度 / 金属度），再把实例参数挪进实例缓冲（方案 B）作为方向七阶段 B。
本窗口不再新增代码；方向七排入下一窗口开工。
