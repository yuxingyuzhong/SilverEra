# 深研预研 · 清单文件版材质实例（第 608 轮）

> 背景：方向七把材质实例做进**关卡文本**（`Level_Data.materials`），但 `scene_load`（独立场景清单文件）
> 仍只能引用「关卡传入的实例名表」，清单自身无法声明实例。收口复盘 §四 限制 2 记为未做项。

---

## 一、现状（2026-11-03，Renderer `10f1693`）

| 环节 | 现状 |
| --- | --- |
| `Scene_Manifest` | 仅 `meshes / materials / places` 三个 vector（`资产加载.h` L114–122） |
| 清单解析 | `scene_manifest_parse(_lines)` 只认 `mesh` / `mtl` / `place`；`place` 材质列可命中「实例名表」（默认为空） |
| 实例来源 | 仅 `level_load`：`Level_Data.materials` → 实例名表 ＋ `asset_scene_build(…, 实例声明, …)` |
| `scene_load` | `渲染器.h` L1109；内部走清单解析 → `asset_scene_build`，实例声明传空 → 清单不能声明实例 |

## 二、目标语法（与关卡文本同形）

```
material <实例名> <模板材质名> [tint r g b a] [emissive v] [toon steps rim specular] [pbr roughness metallic] [clearcoat strength roughness]
```

- 覆盖项顺序固定：tint → emissive → toon → pbr → clearcoat（与关卡解析一致）；
- 未启用项不落盘、读回默认；实例上限 256；重名 / 缺名 / 缺模板 → 整份拒绝；
- `place` 材质列优先命中实例名，其次材质库 ID（沿用 467 轮口径）。

## 三、方案对比

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A（推荐）** | `Scene_Manifest` 增 `std::vector<Scene_Material_Instance>`；结构字段与 `Level_Material` 一一对应；`scene_load` 组装时转成 `Level_Material` 后交给 `asset_scene_build` | Asset 层不反向依赖 Level 层；解析 / 校验可复用关卡侧规则（抽公共函数） | 结构字段两份（需同步维护） |
| B | `资产加载.h` 直接 `#include 关卡文件.h`，`Scene_Manifest` 直接存 `Level_Material` | 零转换、字段唯一 | Asset 依赖 Level（层次倒置）；后续 Level 演进会牵动 Asset 头 |
| C | 清单只允许「引用」，实例仍在关卡声明 | 改动最小 | 未解决限制 2 |

**结论**：选 A；把「material 行解析 + 域校验」抽到 `关卡文本.cpp` 的公共小函数（`material_line_parse`），
清单解析复用同一实现，避免两套规则漂移。

## 五、风险

1. **两套来源冲突**：关卡内嵌资产段落也能写 `material`（关卡文本已结构化进 `materials`，资产行只保留 `mesh/mtl/place`），
   故 manifest 解析仅对独立清单文件生效，不改变关卡路径；
2. **结构重复**：A 方案的 `Scene_Material_Instance` 与 `Level_Material` 需逐字段同步——建议加静态断言（sizeof/字段对照）或用转换函数集中维护；
3. **上限与额度**：实例 256 与资产行 20 000 互不占用（沿用关卡口径）；
4. **兼容**：旧清单无 `material` 行 → `instances` 为空，`asset_scene_build` 行为逐字节不变。
