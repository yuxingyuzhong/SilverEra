> 日志系统流输出设置对日志输出方法屏蔽(Log::info,Log::warn,Log::error,Log::debug)，
> 同时取消哈希流存储容器，改为如下机制，当日志输出方法被调用时，
> 默认参数自动获取调用处文件路径信息，
> 并根据文件信息建立链表树，链表树结构如下：
> 若两处调用文件路径存在相同部分则以相同路径为父节点建立链表结构，
> 若两处调用文件路径不同则各自单独成为父节点，每节点存在两个输出流容器并互斥存储，
> 当子节点未被设置单独输出流时，则激活weak_ptr容器，共享父节点输出流，
> 当子节点被设置单独输出流，则激活shared_ptr容器，单独流输出，
> 每容器可存储多个输出流，在打印日志信息时，所有流均会输出日志信息。
> 流设置无权限保护机制，但存在多线程保护机制。

## 二、用户定夺口径（提问卡片答复汇总，共 8 项，必须遵守）

1. **「屏蔽」语义**：四个日志方法（`info` / `warn` / `error` / `debug`）的签名与函数体**都不出现流参数**，也不再读取 `active_file_stream` 一类全局活跃流状态；流设置只经新增接口，与日志方法完全解耦。
2. **节点粒度**：以两处调用路径的**公共前缀**为父节点建立链表结构，且允许公共前缀互相成为对方的父子节点（即**嵌套链**，不逐级建节点）。路径不同则各自单独成为父节点。
3. **设置接口形态**：路径 + 文件名、路径 + 流对象、清空某节点自有流；未设置文件流时默认使用 `std::cout`。
4. **路径基准**：剥离到项目根「白银纪元」的**相对路径**。
5. **测试层**：更新兼容并补新用例。
6. **编译验证**：需要编译验证。
7. **接口命名**：`stream_bind`（清空为 `stream_clear`），**均 static**。
8. **目录节点**：目录节点可设流，且其后代继承。

## 四、实现方案（实际落地）

### 4.1 与执行计划的偏差（重要）

| 项 | 执行计划设想 | 实际落地 | 原因 |
| --- | --- | --- | --- |
| 调用处路径捕获 | 直接把 `std::source_location` 作为日志方法的默认参数 | 引入 `template<typename... Args> class Format` 包装类型，以其 `consteval` 构造的默认参数在调用点求值捕获 | **MSVC 限制**：非末位的变参包属非推导上下文，`static void info(Args&&... args, std::source_location = current())` 形式无法通过重载/实参推导；改用 `Format<std::type_identity_t<Args>...>` 首参 + 尾随 `Args&&...` 变参，并用 `std::type_identity_t` 阻断推导 |

该偏差已在阶段一（签名可行性最小样例编译验证）中发现并定案，后续阶段按此实现，用户未提出异议。

### 4.2 数据结构（`日志系统.h` 私有）

```cpp
//输出流别名（public）
using Stream = std::shared_ptr<std::ostream>;
//输出流容器别名：容器可存储多个输出流，打印日志时全部输出
using Stream_Group = std::shared_ptr<std::vector<Stream>>;
//输出流容器弱引用别名：共享父节点输出流时使用，不持有容器
using Stream_Group_Weak = std::weak_ptr<std::vector<Stream>>;

//流节点（链表树节点）
struct Stream_Node
{
    std::string key;                    //节点路径键（规范化后，到该节点为止的路径段）
    Stream_Node* parent;                //父节点指针
    std::list<Stream_Node> children;    //子节点链表（std::list，元素地址稳定）
    Stream_Group own_group;             //自有输出流容器（shared_ptr，被设置过则激活）
    Stream_Group_Weak shared_group;     //共享输出流容器（weak_ptr，未设自有流时激活）
};
```

`std::list` 保证节点地址稳定（插入/拆分不使已有节点指针失效）；根节点路径键为空串。

### 4.3 路径规范化 `path_normalize`

1. `\` → `/` 统一分隔符；
2. `rfind("白银纪元/")` 定位项目根锚点并剥离至相对路径（实现口径 4）；
3. 去除前导 `/` 与 `./`；
4. 末尾补 `/`（使「同段前缀」判定按路径段对齐，避免 `abc` 误配 `abcd`）。

### 4.4 链表树插入（最长公共前缀合并）`node_ensure`

- `prefix_common(left, right)`：求原始公共前缀长度；**若公共部分不足一个路径段，则回退到最近的 `/` 边界**，保证按段对齐。
- `node_ensure(key)`：自根向下，在 `children` 中挑选与目标键公共前缀最长者进行合并；两键公共前缀长于该子节点键时**拆分中间节点**，形成嵌套链（口径 2：公共前缀互为父子，不逐级建节点）。空键即根节点。

### 4.5 双容器与生效解析

- `group_resolve(node)`：**自有优先**——`node.own_group` 非空则直接返回（单独流输出）；否则取 `node.shared_group` 弱引用缓存，锁定成功即返回；再否则递归父节点；最终回落 `group_console()`（`std::cout` 兜底，口径 3）。
- `group_append(node, stream)`：必要时创建 `node.own_group`（激活 `shared_ptr` 容器）；**新建容器时调用 `group_shared_reset()` 刷新后代共享缓存**。
- `group_shared_reset(node)`：逐子节点重置 `shared_group` 并递归，使后代在父节点新设流后按父链重新解析。
- `stream_console()`：函数局部 `static Stream`（`&std::cout` + 空删除器，不持有 `std::cout` 生命周期）；`group_console()` / `group_create_console()` 同法构造控制台兜底容器。

### 4.6 对外接口（全部 static、public、无权限校验、全部持 `tree_mtx`）

| 接口 | 行为 |
| --- | --- |
| `static bool stream_bind(const std::string& path, const std::string& file_name)` | 定位或创建路径节点；**空文件名 → 绑定控制台流**；`new(std::nothrow) std::ofstream` 失败 → 控制台提示 `[FATAL]内存不足\n已切换至控制台输出\n` 并返回 false；`is_open()` 失败 → `[ERROR]文件打开失败\n已切换至控制台输出\n` 并返回 false；成功则追加进节点自有容器 |
| `static bool stream_bind(const std::string& path, const Stream& stream)` | 空流直接返回 false；否则定位或创建节点并追加 |
| `static bool stream_clear(const std::string& path)` | 按规范化键**查找（不新建）**节点；不存在返回 false；否则重置 `own_group` 与 `shared_group`，使该节点及其后代回落共享父节点流 |

目录节点设流后后代继承（口径 8）由 4.4 + 4.5 的父链解析自然实现。

### 4.7 日志方法（方法不感知流）

```cpp
template<typename... Args>
static void info(Format<std::type_identity_t<Args>...> fmt, Args&&... args)
{
    output(fmt.site.file_name(), std::format(fmt.pattern, std::forward<Args>(args)...), "INFO");
}
```

`warn` / `error` / `debug` 同构（类型前缀分别为 `WARN` / `ERROR` / `DEBUG`）。四方法仅做「取调用处文件名 → 格式化 → 交 `output` 路由」，**不出现任何流参数与流状态读取**（口径 1）。

`output(file_name, text, type)`：规范化键 → 定位/创建节点 → `group_resolve` → **逐流全部输出**（口径：每容器多流全量输出）。

```cpp
//调用处信息（并承担占位符与实参的编译期校验）
template<typename... Args>
class Format
{
public:
    template<typename Text>
    consteval Format(const Text& text, std::source_location place = std::source_location::current())
        : pattern(text), site(place){}
    std::format_string<Args...> pattern;
    std::source_location site;
};
```

### 4.8 线程保护（口径：无权限保护，有多线程保护）

- 单把 `inline static std::mutex tree_mtx{}`，**建节点 / 设流 / 清流 / 输出共用**；
- `stream_bind` ×2、`stream_clear`、`output` 入口均 `std::lock_guard<std::mutex> lock(tree_mtx);`；
- 无任何权限/密钥校验。

### 4.9 保留项

- 文件尾部保留全局实例 `inline Log logger;` 与 `std::formatter<std::error_code>` 特化（后者为既有依赖，`Data_Validator::error_out` 等经 `Log::info("{}", ec)` 使用）。
- 内存分配全面 `std::nothrow` 形式（无异常）。
