## 一、任务目标

为测试层开发主调文件，使 `EngineTests.exe` 具备交互式模块选择能力：

1. 运行测试时可**实时输入**（控制台菜单）挑选要执行的模块；
2. 或以 **ImGui 临时窗口**（树形勾选）挑选模块；
3. 选完**关闭窗口、恢复控制台输出**，再运行 googletest；
4. 不破坏原有「无交互全量跑」语义（ctest 与既有命令行用法必须继续可用）。

## 三、方案设计

### 3.1 分层结构

- **模型层**（纯逻辑、可单测）：`测试选择模型`
  - 反射枚举全部套件/用例并建树；勾选状态维护（套件与用例父子联动）；生成 gtest 过滤串。
- **视图层**（两个视图共用同一模型）：
  - `控制台选择菜单`：编号列表 + `1,3-5` / `all` 输入解析，非法输入最多重试三次后兜底全跑。
  - `图形选择窗口`：GLFW + ImGui 临时窗口，树形勾选 + 全选/清空/反选 + 开始测试/取消。
- **主调层**：`主程序.cpp` 负责选择模式解析、分发，最后调用 `RUN_ALL_TESTS()`。

### 3.2 选择模式与兼容策略

| 模式 | 行为 |
| --- | --- |
| `--selector=window`（默认） | 图形窗口；窗口创建失败或环境不支持时**自动退回**控制台菜单 |
| `--selector=console` | 强制控制台菜单 |
| `--selector=off` | 不选择、不等待输入，原样全量跑（**ctest 与既有脚本走这条**） |
| 命令行已带 `--gtest_filter` 且未显式指定选择器 | 透传该过滤串，不弹选择器 |

过滤串生成规则：全部勾选 → 列出每个套件的 `套件名.*`；部分勾选 → 只列所选套件。DISABLED 用例由 gtest 自行跳过。

### 3.3 窗口与输出的交接

窗口存在期间由 ImGui 独占前台；用户确认后销毁窗口、恢复标准输出，再执行 googletest——即任务要求里的「选完关闭窗口、恢复控制台输出再跑」。

## 五、验收标准

1. 全量路径：`EngineTests.exe --gtest_filter=* --gtest_brief=1` 全部通过、退出码 0；
2. 关选择器路径：`--selector=off` 全量通过；
3. 控制台路径：给定编号输入后**只跑所选套件**，过滤串打印正确；
4. 图形路径：窗口正常显示中文，确认后按窗口所选过滤串运行，随后退出；
5. `ctest` 1/1 通过（不弹窗、不等待输入）。

## 六、风险与规避

| 风险 | 规避 |
| --- | --- |
| GUI 交互无法自动点击 | 后台启动 + 窗口句柄精确抓图 + 像素统计核验渲染；再用键盘事件驱动确认路径，最终鼠标点选验收交给用户在本机完成 |
| 下层重命名破坏上层 | 构建时若暴露（引擎层 `Config_Checker` → `Data_Validator`），按用户选择「立即跟进」处理 |
| 第三方源码入库体积大 | 按既有 googletest 惯例入库，提交信息中显式说明 |
| 选择器抢占 ctest 语义 | ctest 显式加 `--selector=off` |
| 未提交改动误入库 | 提交前逐项核对；`out/` 已被忽略，构建产物不入库 |
