## 一、目标

1. 把 ImGui 测试选择窗口的背景改为**蓝色渐变**（按用户选择：整体转蓝，标题栏 / 按钮 / 勾选框 / 滚动条一并换色系；布局、尺寸、交互逻辑一律不动）。
2. 修复「测试跑完后控制台窗口自动关闭」：交互运行下，测试结束后**停住等用户手动关闭**，以便观察输出；自动化调用（ctest / `--gtest_filter`）保持原样，绝不被挂住。

## 三、实现方式

### 段一：窗口配色改蓝（仅颜色）

- `图形选择窗口.cpp` 新增文件内部函数 `绘制蓝色渐变背景()`：用 `ImGui::GetBackgroundDrawList()` + `AddRectFilledMultiColor()` 画**两段连续垂直渐变**（深蓝 → 中蓝 → 亮蓝），在 `ImGui::NewFrame()` 之后调用。
- `应用粉色主题()` 更名 `应用蓝色主题()`，色板整体换蓝系：
  - `WindowBg` 的 alpha 归零（否则会盖住渐变），改由渐变层充当窗口底色；
  - `ChildBg` 用半透明深蓝，让选择树区域透出部分渐变；按钮 / 勾选框 / 高亮 / 滚动条转蓝；
  - `Text` 保持高亮度白，保证中文用例名可读。
- `glClearColor` 同步改为蓝色系的兜底色。
- **不动**：窗口尺寸、字体加载、树结构、按钮文案与位置、Esc/Enter 行为。

### 段二：测试结束不自动关窗

- `主程序.cpp` 新增两个函数：
  - `需要等待退出(选择模式, 命令行带过滤, 显式选择器)` —— 纯逻辑判定：**透传分支（带 `--gtest_*` 且未显式指定 `--selector`）与 `--selector=off` 返回 false**，其余（默认 / `window` / `console`）返回 true。
  - `等待用户关闭窗口()` —— 打印「测试已结束，按任意键关闭窗口…」，用 `FlushConsoleInputBuffer` 清掉历史按键后 `_getch()` 等待；`GetConsoleWindow()` 为空的自动化环境直接跳过，不阻塞。
- 接入点：交互分支的 `return RUN_ALL_TESTS();` 改为「取返回值 → 按需等待 → 返回」；透传/关闭分支保持原样。
- 行为矩阵：

| 调用方式 | 结果 |
| --- | --- |
| 双击 `EngineTests.exe`（默认 window） | 测试跑完停住，按键 / 关窗才退出 ✓ 用户要的效果 |
| `--selector=console` | 同上 |
| `--selector=off`、ctest、`--gtest_filter=…` | 跑完立即结束，不等待 ✓ 自动化不受影响 |

### 段三：验证

- 新增用例 `src/单元测试/主调/退出暂停判定测试.cpp`，覆盖 `需要等待退出()` 的全部组合（默认、显式 window、console、off、透传、显式+透传并存）。等待动作本身是阻塞式控制台交互，不做自动化单测，改用真实运行验证。
- 构建 `EngineTests` → 全量用例回归（基线 279 例 / 20 套件，期望「无回归 + 新增用例全绿」）→ `ctest` 全绿。
- 视觉验证：后台启动 `--selector=window` → PowerShell 截屏 → `read_image` 核对背景确为蓝色渐变（上深下浅）。
- 行为验证：交互路径确认测试输出后进程仍存活（未自动退出）；`--selector=off` / `--gtest_filter` 确认进程正常结束（不挂）。

## 五、风险与回退

| 风险 | 应对 |
| --- | --- |
| 渐变层被窗口底色遮住 | `WindowBg` alpha 归零，渐变放背景绘制列表；截屏验证兜底 |
| `_getch()` 在无控制台环境（CI / 重定向）异常 | `GetConsoleWindow()` 判空后跳过等待；该路径本就不该停 |
| ctest 被等待挂住 | `--selector=off` 与 `--gtest_filter` 显式不等待，并单独跑一次 ctest 确认 |
| 截屏依赖图形环境 | 若无法截屏，如实报告并请用户双击验收 |
| 鼠标交互验收 | Agent 无法点击鼠标，最终勾选手感与配色观感仍需用户双击确认 |

**回退**：改动集中在 2 个既有文件 + 2 个新增文件，未触及层级契约与构建脚本；如需回退，直接还原这几个文件即可（无数据 / 接口迁移代价）。
