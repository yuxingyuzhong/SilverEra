# 执行计划：四叉树合并移除 copy 回调依赖

> 任务性质：对上一版次「四叉树 shared_ptr 改造」的收尾补全。
> 起因：review 中确认 `Quadtree_Manager::quadtree_merge` 的数据迁移仍依赖外界注册的
> `copy(const Tree_Chunk_Data<T>&, Tree_Chunk_Data<T>&)` 回调，`T` 仍必须可拷贝，
> shared_ptr 所有权模型在合并路径上未生效。用户拍板**方案 A：彻底移除该回调依赖**。

## 二、实现方式（分段）

1. **移除回调**：删 `copy` 成员、setter 与合并总开关；`quadtree_merge` 无条件执行。
2. **叶子收养**：`Quadtree::block_seek` 新增默认空形参
   `std::shared_ptr<T> adopt`；命中叶子（常规路径与退化树根区块两处）在产出 receiver 前
   执行 `std::get<1>(node.data) = adopt`，使**叶子本体**接管旧区块所有权；
   合并调用处把旧区块 shared_ptr 经该形参传入。旧树卸载后新树独占，`T` 地址不变、无需可拷贝。
3. **既有缺陷修复（新增真实用例后暴露）**：`largest_tree_size` 此前仅在「扩大审批」路径更新，
   智能建树后恒 0，导致相邻树矩形筛选半径塌缩（半径 128 < 邻居根距 256），真实合并不可能发生。
   于 `quadtree_build` 维护最大值、两个 `quadtree_unload` 重载末尾按剩余树重算（`clear` 随之归零）。
4. **测试**：
   - 删「未注册迁移方法时合并不生效」「树数量不足时合并不生效（计数 lambda）」，
     替换为「不足四棵同级树时合并不改变序列」「单棵树合并不改变序列」；
   - 「合并拷贝前检查区块指针」替换为「四棵相邻树合并后区块数据共享迁移」
     （2×2 四棵 256 树 → 一棵 512 树；断言数据值与 `T` 对象地址均不变）；
   - 「智能创建后最大规模仍为零」固化的是缺陷行为，改写为建树后 256、卸载后归零。
5. **验证**：引擎层重建 `error C=0`；测试层重建；全量回归 349 例。
6. **提交**：引擎层、测试层各一笔，顶层快照一笔；直推对应分支，不走 PR。
