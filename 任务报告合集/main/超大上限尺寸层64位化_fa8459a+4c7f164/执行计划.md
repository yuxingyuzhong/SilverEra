# 修复「超大边长上限整数除零」——四叉树链路尺寸层 64 位化

> 本文件为用户已批准计划的工作站存档副本，对应工作区 `.cyrene/docs/plan-20260925-203528.md`（2026-09-25 批准）。
> 执行结果、实测证据与偏差说明见同目录 `执行报告.md`。
> 对应版次：`引擎层 fa8459a`（`main` → `engine`）＋ `测试层 4c7f164`（`test` → `test`）。

## 一、目标

让四叉树在边长上限配置到 `INT_MAX` 以上（用例取 `1ull << 33`）时，**建树与单点检索真正可用**，而不是抛 `SEH 0xC0000094`；同时清掉同一类零尺寸除零隐患。

路线：**A 局部升级**（四叉树两模块内部尺寸·范围改用 64 位，对外公开接口不动）＋ **一并补零尺寸防御** ＋ **直接推送到 `engine` / `test`（不提 PR）**。

## 二、背景：缺陷的完整机制

### 2.1 崩溃链条（按代码链路推演，执行阶段会实测钉死落点）

`set_max_size(1ull << 33)` → `qurdtree_build_smart({ (0,0) })` → `prepare_smart_create_params`：

```cpp
int father_block_size = settings.max_tree_size;        // 2^33 按模 2^32 截断 → 0
int width = recta_range.right - recta_range.left + 1;  // = 1
if (width % father_block_size != 0)                    // 1 % 0 → SEH 0xC0000094
```

`int` 装不下 2^33（C++20 起无符号转有符号为模 2^N 截断），结果就是 0，紧跟的取模立刻崩。**上一版次注释里写的崩点 `excel_element_to_coord` 应更正**：那是范围查询路径上的另一站同类崩点（范围宽度不足一个 `block_size` 时 `(right-left+1)/block_size` 同样得 0）。

### 2.2 单点补不住的溢出面

即使堵掉上面这一处，后面仍有一串 int 承载不了的量：

| 位置 | 表达式 | 溢出量级 |
| --- | --- | --- |
| `prepare_smart_create_params` | 往 `Rect2i` 写补齐后的 `recta_range.right/up` | ±2^33 |
| `manage_range_calcu` | `(root.X ± 0.5) ± (tree_size / 2 - 1)` | ±(2^32−1) |
| `child_node_range_calcu` | `mid_x = left + (right - left) / 2` | ±2^32 |
| `range_seek` | `total_num` 乘法 | 超 int |
| 管理器侧 | `width` / `height` / `father_block_num_*` | 超 int |

所以上一版次「需架构层调整，非局部防御可解」的判断成立，但**架构调整可以收敛**：超标的量集中在「树尺寸」与「由它推导的范围边界」这一层，查询点本身（游戏世界坐标）int 完全够用。

### 2.3 引用面（已实测统计）

- `Rect2i` 在 `引擎层/src/core/spatial/partition/` 下共 **55 处**，`Point2i` 共 **32 处**，全部落在 `Quadtree` 与 `Quadtree_Manager` 两模块（含各自 `函数预声明.h`）
- 系统层、游戏层零引用（沿用上一版次结论）
- `set_callback_manage` 调用方：引擎层 1 处（管理器）＋ 测试层 **4 处**
- `point_to_int` 使用方：引擎层 2 处、测试层 4 处

## 三、设计要点

### 3.1 新增 64 位坐标类型（`引擎层/src/core/spatial/common/core/坐标类型.h`）

```cpp
//二维点 —— 64 位整数精度
using Point2l = Point2<int64_t>;
//二维矩形范围 —— 64 位整数精度
using Rect2l = Rect2<int64_t>;

//精度转换 —— 浮点转 64 位整数
inline Point2l point_to_l(const Point2d& p) noexcept;   // 取整口径同 point_to_int（std::llround）
```

`Point2i` / `Rect2i` / `point_to_int` / `point_to_double` 一并保留，语义不动。命名沿项目既有的单字母后缀风格（`i` / `d` → `l`）。

### 3.2 分层原则（唯一判据）

| 层 | 类型 | 说明 |
| --- | --- | --- |
| **对外公开接口** | `Point2i` / `Rect2i` 不变 | `Quadtree_Manager::seek`（单点 / 范围）、`qurdtree_build_smart`、`set_max_size` 等 |
| **模块内部** | `Point2l` / `Rect2l` | 树边界范围、由尺寸推导的坐标、待查询区块坐标、树间范围计算 |
| **回调契约** | `Point2l` | `callback` 的 `target` 参数是「申请扩大的目标坐标」，在超大树上会超 int，随之升级 |

### 3.3 零尺寸防御

- `excel_element_to_coord`：补 `width <= 0 || block_size <= 0` 直接返回（本版次主崩点的同类隐患）
- `prepare_smart_create_params`：补 `father_block_size <= 0` 直接返回（防 `max_size` 配成 0）
- `target_range_amend`：已含 `block_size <= 0` 与 `width <= 0 || height <= 0` 两道防御（上一版次 `16d74df` 所为），本版次只做类型同步，不重复添加

## 五、风险与回退

| 风险 | 应对 |
| --- | --- |
| 改造点遗漏导致静默截断（不报错但结果错） | 每一处 int64 → int 的落脚点逐条核对；靠全量回归与「边界值 2^33 建树」用例兜底 |
| `range_seek` 超大范围下 `total_num` 溢出或内存爆炸 | 乘法前做溢出检查，越界直接返回；本版次用例只覆盖单点检索，不触发超大范围分配 |
| `callback` 契约变更波及调用方 | 已知引擎层 1 处 + 测试层 4 处，一并同步；其余在编译期即可全数暴露 |
| 超大树上的**范围查询**仍可能不可用（内存物理受限） | 本版次只承诺建树与单点检索；范围查询的大尺寸行为作为已知限制写入报告与导航 |
| 退回 | 两仓各为本版次独立提交，`git revert <哈希>` 可整体回退，不影响既有版次 |
