## 一、背景与目标

引擎层 `src/core/spatial/collision/` 下的碰撞模块此前只有骨架：类型与接口已经定型，但成员函数为空实现（或返回占位值），且缺少网格（OBJ）加载能力，导致碰撞空间与碰撞代理器无法真正工作、也无法被事件系统驱动。

本次任务把三件骨架补齐为可用实现，并新增 OBJ 网格加载器与事件接入：

| 对象 | 现状 | 目标 |
| --- | --- | --- |
| `Collider`（碰撞体） | 只有基本字段与反查接口 | 持有碰撞形状与网格数据源，移动后可反查 |
| `Collision_Region`（碰撞空间） | 成员函数空实现 | 边界/碰撞体全生命周期 + 包含性与离散检测 |
| `Collision_Proxy`（碰撞代理器） | 成员函数空实现，未接入事件 | 空间与碰撞体管理、编号分发、事件驱动全链路 |
| OBJ 网格加载 | 无 | 新增 `src/tools/Mesh_Loader/`，供碰撞空间构建网格形状 |

## 三、关键决策（已与用户确认）

1. **几何描述统一为 JSON 规范**，字段固定为：
   `collider_ID`、`type`、`half_extent`、`radius`、`height`、`mesh_path`、`margin`、`position`、`rotation`。
   形状类型由 `type` 决定：盒体取 `half_extent`（三元数组）、球体取 `radius`、
   胶囊与圆柱与圆锥取 `radius`/`height`、网格取 `mesh_path`；`margin`、`position`、`rotation` 为通用可选项。
2. **OBJ 解析器放在引擎层 tools**（`src/tools/Mesh_Loader/`），不依赖外部库，直接解析文本 OBJ。
3. **事件完整接入**：`Collision` 与 `Config` 两个分类都接，指令与结果事件成套。
   碰撞体设置统一走「编号 → 所属空间」分发，代理器不直接暴露碰撞空间指针。
4. **编号归属登记**：`collider_mapping` 记录「碰撞体编号 → 持有该编号的碰撞空间名」，
   因此同一编号可被多个空间分别持有（使用多重映射），设置类指令对全部持有者生效。
5. **转移与镜像语义**：`transfer` 把碰撞体从原空间摘出并挂到目标空间（编号不变）；
   `mirror` 在目标空间复制一份并分配新编号。

## 四、计划中被纠正的假设

执行前逐条核对源码后，以下四处原始假设与实际不符，已按实际修正：

| # | 原假设 | 实际做法 |
| --- | --- | --- |
| 1 | `collider_set(json)` 按调用顺序定位碰撞体 | 以配置内的 `collider_ID` 字段定位；缺失即判配置非法 |
| 2 | `region_boundary_set(path)` 读取单份边界配置 | 读取 **边界配置 JSON 数组**，逐项构建并统一编号 |
| 3 | `transfer` 与 `mirror` 同义 | `transfer` = 摘出挂到目标空间；`mirror` = 复制新编号 |
| 4 | `collider_mapping` 是「编号 → 编号」 | 是「编号 → 所属空间登记」，值为空间名 |

## 七、风险与应对

| 风险 | 应对 |
| --- | --- |
| 引擎层存在用户自身未提交改动 | 全程不改动、不回退这些改动；提交范围另行向用户确认 |
| 碰撞世界记录的是碰撞对象地址，析构顺序错误会解引用已释放对象 | 在 `Collision_Region` 析构中先把碰撞对象移出碰撞世界 |
| 依赖库形状类只有抛异常的 `operator new` | 以 try/catch 包装普通 `new`，失败统一返回 `false` |
| 事件发送重载选择错误会导致事件发不出去 | 结果事件统一走单事件重载（多事件重载只认多事件发送者） |
| 中文路径与文件名 | 源码统一 CRLF + UTF-8，新建文件补 CRLF 规范化 |
