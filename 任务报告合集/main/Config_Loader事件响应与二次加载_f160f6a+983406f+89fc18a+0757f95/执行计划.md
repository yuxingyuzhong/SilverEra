## 三、脏标记方案（"具体格式你定"）

### 3.1 哈希与盐
- 盐：进程内**唯一且只生成一次**（函数局部 `static`），用 `Random_Generator<int64_t>` 生成；**运行内不变、跨运行随机** ⇒ 跨运行遗留标记自动失效，无需收尾。
- 标记值 = `hash_combine(盐, hash(对象名), hash(路径字符串))` → 64 位无符号整数。
  - **路由文件自身标记** = `hash_combine(盐, hash(路由文件路径))`（无对象维度）。
  - **路由条目标记** = `hash_combine(盐, hash(object), hash(config_path))`。

### 3.2 承载点（G1=B + G2=A）
- **路由文件**（顶层对象）：
  ```json
  {
    "dirty_mark": 12345678901234567890,
    "routes": [ { "object": "…", "config_path": "…", "dirty_mark": 987654321 } ]
  }
  ```
  - 顶层 `dirty_mark`：该路由文件是否已被本轮解析。
  - 条目 `dirty_mark`：该「对象 × 配置文件」是否已被本轮加载。
- **配置文件本体不写标记**（避免一文件多对象时单值无法表达、也避免污染配置数据）。

### 3.3 读写时机
1. 读路由文件 → 解析 `dirty_mark`（顶层）与 `routes` 数组；
2. 逐条目：`Subscriber/Check` 确认 `object` 存在性；
3. `object` 不存在 ⇒ **跳过该条目**（不读配置文件、不写标记）；
4. `object` 存在 ⇒ 比对条目 `dirty_mark`：相等则跳过读取；不等则读配置文件 → 投递 → 更新该条目标记；
5. 本轮有标记更新时，回写路由文件（顶层标记同步刷新）。

### 3.4 为什么去掉 `file_hashs`
盘上标记是唯一权威。若保留内存集合并让它先行短路，第三方重置标记就**永远无效**，直接违反口径 4；况且标记写在文件里，判定时本就要读文件，内存集合也省不掉 I/O。故去掉 `file_hashs`，单轮去重完全由盘上标记承担。

### 3.5 投递净化
`Config/Load` 的 `config` 只放**配置正文**；若正文自带同名标记字段则投递前剔除。路由解析循环必须显式跳过 `dirty_mark` 字段，否则会被 `field_check` 判为非法条目并刷日志。

## 四、四项任务的实现方案

### 4.1 任务 <1>：事件响应机制
`event_process(std::shared_ptr<Event>)` 按 `category/tag` 分派（订阅清单收敛为 2 条）：

| 事件 | 载荷（我定，待确认） | 行为 |
| --- | --- | --- |
| `Route/Reload` | `{"route":"<路由目录>","config":"<配置根目录>"}` | 见 4.4(b) |
| `Config/Reload` | `{"object":"<对象名>","files":["<配置相对路径>", …]}` | 见 4.4(a) |
| `Subscriber/Call`（中转站直接转发，无需订阅） | 以 `sender_object` 为对象名 | 见 4.2 后段 |

### 4.2 任务 <2>：接收者检查机制
- **检查**：读完路由并写入 `routes` 缓存后，对每个 `object` 发 `Event("Config_Loader", object, "Subscriber", "Check")`，经 `event_terminal.interact(evt, acl_key)` 取回 `Subscriber/Response`，读 `config["object_existence"]`；为 `false` ⇒ 取消该对象配置信息传递（不读配置、不写标记）。
- **补投**：Config_Loader 作为目标收到 `Subscriber/Call`（`category="Subscriber"`）后，以 `sender_object` 为对象名，从 `routes` 取全部路径并**全量定向投递**（`Config/Load`），用于"接收者后接入"的补投。

### 4.3 任务 <3>：对象配置文件路径缓存
`routes`（`unordered_map<string, unordered_set<string>>`）：`object → {config_path}`。
- 路由解析时**无论对象是否存在都记录**（它是路由数据，不依赖存在性）；
- 供 `config_load(object, paths)`、`Subscriber/Call` 补投、`Route/Reload` 更新使用。

### 4.4 任务 <4>：二次加载机制
**(a) `Config/Reload`**：读**配置文件头**（= 路由条目 `dirty_mark`）排除事件指定但无需重载的文件 → 对每条被排除项 `logger.warn` 告警 → 对需重载者：读文件 → 投递 `Config/Load` → 更新该条目标记 → 回写路由文件。
**(b) `Route/Reload`**：查阅**路由文件头**（顶层 `dirty_mark`）排除无需重载的路由文件 → 被排除项 `logger.warn` 告警 → 重新解析其余路由文件 → 更新 `routes`。
**口径**：标记匹配即排除，**无强制重载通道**（用户：不需要重载的就不重载，没得商量）；强制重载只能由第三方重置标记达成（口径 4）。

## 四、实现方案

### 4.1 唯一必须触碰共享函数的点：对象自身目录对的推导

`route_file_process` 目前往 `config_routes[object]` 写的是"传入的 `content`"（扫描根）。按口径 1 必须改为**按条目推导**：

```cpp
// 推导对象自身目录对：route = 路由文件所在目录（相对基目录），config = config_path 的父目录
path object_route_dir = std::filesystem::relative(file_path, base_dir_get());
Config_Content object_content(object_route_dir, detail::string_to_path(config_path).parent_path());
// 记录对象配置目录（唯一写入口：仅 Belived_Root 扫描链路与已登记缓存的加载链路会走到）
config_routes[object].insert(object_content);
```

- 对 `Route/load` **无行为改变**：其事件 `content` 即对象自身目录对，且 `insert` 幂等。
- `path_safety_check` 仍以**扫描根** `content` 为边界（Belived_Root = 可信根，Route/load = 对象目录），安全检查强度不变。

### 4.2 路径规范化（新增，必须）

事件侧目录对来自 UTF-8 字符串（`/` 分隔），磁盘侧来自 `std::filesystem::relative`（Windows 为 `\`）。二者直接比较/哈希**不相等** ⇒ `config_routes[object].count(content)` 永不命中。
**方案**：在 `Config_Content` 构造时对两路径统一 `lexically_normal()`（平台统一为 preferred separator）。仅影响**整路径**的比较与哈希；`path_safety_check` 的**逐节**比较不受影响。

### 4.3 三个事件分支

**（1）`Belived_Root/Add`**
1. 解析 `{route, config}` → `Config_Content root`；字段缺失 `logger.error` 驳回；
2. `believed_roots.count(root)` 命中 → `logger.warn` 跳过；
3. 登记 `believed_roots.insert(root)`；`content_scan(root.route)` 扫描 → 逐路由文件 `route_file_process(root, file, "", {}, /*deliver=*/false)`；
4. 不做 `receiver_check`、不投递。

**（2）`Belived_Root/Load`**
1. 解析同上；未登记则先登记；
2. **重建**：先 `root_cache_clear(root)`（按前缀清除该根旧缓存），再走与 Add 相同的扫描填充链路。

**（3）`Belived_Root/Unload`**
1. 解析同上；未登记则 `logger.warn` 跳过；
2. `root_cache_clear(root)` → `believed_roots.erase(root)`。

### 4.4 `root_cache_clear(root)`（新增私有）

- `config_routes`：逐对象，删除满足「`root.route` 为其前缀 **且** `root.config` 为其前缀」的元素；清空后移除该对象键。
- `config_files`：逐对象，删除键（`config_path` 转 path）以 `root.config` 为前缀的条目；清空后移除该对象键。
- 前缀判定按 `path` **逐节**比较（分隔符无关）。

### 4.5 `route_file_process` 增加投递开关

末位新增参数 `bool deliver = true`；`deliver=false` 时跳过 `receiver_check` 与 `config_file_process`（`delivered` 恒假 ⇒ **不回写磁盘路由文件**）。仅 Belived_Root 扫描链路传 `false`。

### 4.6 顺带修复的两处硬错误（上一阶段遗留）

| 位置 | 现状 | 修复 |
