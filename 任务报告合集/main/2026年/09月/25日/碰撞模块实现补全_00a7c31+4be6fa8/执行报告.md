## 二、执行记录

### s1 框架缺口

- `Collider`：新增 `std::unique_ptr<Triangle_Mesh> mesh` 与 `std::unique_ptr<Collision_Shape> shape`。
  网格声明在形状之前，按成员逆序析构即「形状先释放、网格后释放」，与「网格形状只持有网格指针而不接管所有权」的要求一致；碰撞对象只挂载形状指针。
- `Collider` 显式实现移动构造与移动赋值：默认移动会把封装结构一并搬走，而其中挂载的自指针仍指向被搬空的源对象，导致 `Collider::recover` 反查失效。
  搬移后重新挂载 `setUserPointer(this)`，并把源对象自指针清空。
- `Collision_Region`：新增 `Collision_Result`、`Number_Allocator ID_allocator`、含名构造、`collider_adopt` / `collider_geometry`，以及私有字段读取与形状构建辅助函数。
- `Collision_Region` 新增析构函数声明与实现（见「三、过程问题」第 1 条）。

### s2 OBJ 网格加载器

- 新增 `src/tools/Mesh_Loader/`：逐行解析 `v` 与 `f`，支持 `v`、`v/vt`、`v/vt/vn`、`v//vn` 四种面顶点写法；索引按 OBJ 规范支持负值（自末尾起算）；多边形面按扇形三角化。
- 失败路径统一返回失败：路径为空、路径不可读、顶点行分量不足、面顶点不足三个、面索引越界、未包含有效三角面。
- 构建网格形状时按依赖库实际接口调用：先 `preallocateVertices` / `preallocateIndices` 预留容量，顶点经 `findOrAddVertex(..., false)` 加入，面按 `addTriangleIndices` 成组添加。

### s3 碰撞空间

实现 `Collision_Region` 全部成员：`valid` / `state_set` / `state_check`、`boundary_build` / `boundary_unload`、
`collider_build`（自分配器取号，编号自 1 起） / `collider_unload` / 四个 `collider_set` 重载 /
`collider_find` / `colliders` / `collider_adopt` / `collider_geometry`、`contains`、`detect`。

- 几何配置先做「是否为对象」与必需字段检查，再按 `type` 分派到盒体/球体/胶囊/圆柱/圆锥/网格分支；
  未知类型、字段缺失或数组长度不符一律判非法并拒绝（碰撞体不被登记）。
- `detect` 使用离散检测：先按位移向量推进碰撞对象，再遍历碰撞世界取出接触对，
  经 `pair_normalize`（小号在前）与 `pair_unique`（去重、稳定排序）后返回。
- 空间未激活（`is_active == false`）时 `detect` 直接返回，不执行检测。

### s4 碰撞代理器与事件接入

- 构造函数调用 `event_terminal.acl_key_gen()` 取得发送权限密钥——该调用是密钥的唯一来源。
- `attach` 顺序固定为：检查接入入口是否已注册 → 注册单事件接收包装 → 以模块名登记 11 条订阅清单（`Collision` 与 `Config` 两个分类）。
- 空间与碰撞体管理：`region_build` / `region_unload` / `region_detect` / `region_boundary_set` / `region_state_set`、
  `collider_build` / `collider_unload` / `collider_transfer` / `collider_mirror`、三个 `collider_set` 重载。
- 碰撞空间以 `unique_ptr` 持有（按指针搬移不受析构顺序问题影响）。
- 碰撞体归属登记于 `collider_mapping`（编号 → 所属空间名，多重映射）；
  设置类指令经 `collider_set_dispatch` 对**所有**持有该编号的空间生效；转移为摘出挂入（编号不变），镜像为复制并分配新编号。
- 事件处理路由：`Config` / `Load` 走 `config_apply`（含边界配置文件读取），`Collision` 系列按指令标签分派；
  结果事件经 `event_publish` 发出——**检测结果事件**与**碰撞体构建结果事件**。

## 三、过程问题与解决

1. **夹具析构期访问违例（3 例 SEH 崩溃 0xc0000005）**
   碰撞体映射与空间边界都直接持有碰撞对象，而碰撞世界内部记录的是这些对象的地址；
   映射先于世界析构，世界析构时会解引用已释放的碰撞对象。
   **解决**：为 `Collision_Region` 实现析构函数——在世界有效时先把空间边界与映射中的全部碰撞对象移出碰撞世界。

2. **依赖库形状类无法用 `new (std::nothrow)` 构造**
   形状类带有对齐分配器声明，显式带 `nothrow` 的构造调用不匹配（C2661 / C2664）。
   **解决**：新增模板 `memory_malloc`，以 try/catch 包装普通 `new`，失败统一返回 `false`，保持「失败即返回 false」的契约。
   该模板同时修正过一次实参推导问题（接收者类型改为独立模板参数后编译通过）。

3. **`btTriangleMesh` 无 `addVertex` 接口**
   该版本依赖库的三角形网格不提供 `addVertex`。
   **解决**：改用 `findOrAddVertex` 加顶点、`addTriangleIndices` 按索引组面，并在构建前预留顶点与索引容量。

4. **事件发送不出去（`sent.size() == 0`）**
   事件终端的单事件发送重载只检查单事件发送者，多事件重载只检查多事件发送者；
   测试注册的是单事件通道，而结果事件原先走多事件重载，因此事件无人接收。
   **解决**：`event_publish` 统一改为单事件发送重载。

5. **一处既定契约需要修正**：`collider_set(json)` 以配置内 `collider_ID` 字段定位碰撞体（而非按调用顺序），
   缺失该字段即判非法——与「几何配置自带编号」的规范保持一致。

## 六、遗留与风险

1. **事件系统既有缺陷（本次未修，不在范围内）**
   - `acl_key_gen` 仅在密钥为 0 时成功，模块只能取得一次密钥；
   - 密钥错误分支直接返回空结果（属已知缺陷，对应用例处于 DISABLED）；
   - 接入流程中 `interact` 分支未返回成功标记（已知缺陷）。
   → 这些行为已被本次的碰撞代理器实现所适配（构造函数一次性取密钥、接入顺序固定），但缺陷本身仍在。
2. **碰撞体编号是空间内编号**：不同空间可各自持有相同编号，跨空间唯一定位需要「空间 + 编号」两个信息；
   若上层需要全局唯一编号，需在实体系统对接时另行约定。
3. **静态对象标记**：当前所有碰撞对象按静态登记，动态化（与动力学、位移驱动的扫掠检测）留待后续。
4. **网格加载仅支持 OBJ**：不支持材质、法线归一化与顶点去重，仅满足碰撞网格的最小需求。
5. **游戏层旧构建产物**：`TestEngine.exe` 及其 `.ilk` / `.pdb` 仍在测试层目录内（构建产物，未纳入版本管理，未清理）。
6. 顶层仓库（`白银纪元`）本次无改动，四层子仓库中本次只涉及引擎层与测试层。
