## 六、遇到的问题与处置

### 6.1 下层重命名破坏上层（阻塞构建）

- **现象**：首次全量构建报 `src/tools/Config_Checker/配置检查器.h` 找不到（C1083）。
- **根因**：引擎层 `src/tools/Config_Checker/` 已整体改名为 `Data_Validator`；旧测试文件在 `1f3e0ef` 时可用，此前一直靠**增量构建的旧 `.obj`** 蒙混，本次改动触发全量重编才暴露。`Config_Checker` 全工作区共 44 处，全部落在测试层那一个文件里。
- **处置**（经用户选择「立即跟进」）：PowerShell 精确替换 44 处（保留原编码、无 BOM）→ `str_replace` 修正 include 中文头文件名与注释 5 处 → `git mv` 重命名测试文件以保留历史。最终 `Config_Checker` 与「配置检查器」在测试层均为 0 命中。

### 6.2 自身缺陷一：模型用例污染过滤串

- **现象**：用例「过滤串单用例逐条列出」失败——断言里混入了其他套件的 `套件.*`。
- **根因**：该用例未先清空勾选，模型默认全选，导致其他套件仍处于勾选状态。
- **处置**：用例先 `模型.全部清空()` 再勾选首条，语义更明确。

### 6.3 自身缺陷二：透传条件压掉显式选择器

- **现象**：`--selector=console --gtest_brief=1` 被走成全量 279，而非控制台菜单。
- **根因**：主程序原先「出现 `--gtest_*` 即透传」的判断过于宽泛，把显式指定的选择器也吞掉了。
- **处置**：新增「显式选择器」标志，条件改为 `(命令行带过滤 && !显式选择器) || 选择模式 == "off"`；修复后控制台路径按预期只跑所选套件。

### 6.4 工具与环境问题（均不涉及产品代码）

| 问题 | 处置 |
| --- | --- |
| `cmake` / `ninja` / `ctest` 不在 PATH | 记录并改用绝对路径调用 |
| `run_verification` 只识别 `package.json`，本项目不可用 | 验证统一走 `run_shell`（vcvars64 + cmake --build + 直接运行 exe/ctest） |
| cmd 中 `&` 串联多段探测只回第一段 | 改为单条命令或 `&&` 串联 |
| git 命令传中文路径被 shell 吞（`fatal: pathspec 'src/主调' did not match`） | 改用 `git add --pathspec-from-file=<UTF-8 文件>` 传路径、`git commit -F <UTF-8 消息文件>` 传提交信息 |
| `git_push` 工具在工作区根仓库执行，测试层无该远端 | 在 `测试层/` 目录内以 `git push sliverera test` 追加推送 |
| 全屏截屏被前台窗口遮挡，无法判定窗口是否渲染 | 改为按进程主窗口句柄 `GetWindowRect` 精确抓图 + 像素统计（颜色数/均值）交叉核验 |
