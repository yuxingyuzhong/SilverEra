# 坐标类型更换后的四叉树侧跟进替换

## 一、目标

引擎层 `坐标类型.h` 已由你改写为新的模板实现（`Point2<T>` / `Rect2<T>` 及别名），现把**四叉树**与**四叉树管理器**中残留的旧类型引用全部替换为新类型，并连带更新测试层两个回归用例文件，使全仓恢复可编译、全量用例通过。

## 二、现状事实（已核实）

### 新旧类型映射

| 旧实现（HEAD 版） | 新实现（工作区版） | 语义差异 |
| --- | --- | --- |
| `coord2D_int` | `Point2i` = `Point2<int>` | 无 |
| `coord2D_double` | `Point2d` = `Point2<double>` | 无（浮点相等仍为 ULP ≤ 4） |
| `coord2D_range`（四边界为 `int`） | `Rect2i` = `Rect2<int>` | 无（边界仍为 `int`，与旧一致） |

- 命名空间：新实现已收敛为**单层 `engine`**（`detail` 嵌在其内），四叉树文件本身就在 `namespace engine` 内，可直接用短名。
- 新增能力：`point_to_int(Point2d) -> Point2i`、`point_to_double(Point2i) -> Point2d`。
- **关键差异**：旧类型之间可**隐式互转**（`coord2D_int` 收 `coord2D_double`、`coord2D_double` 收 `coord2D_int`）；新实现**取消了隐式跨精度转换**，需要显式调用转换函数。这是本次唯一可能触发编译错误的点。

## 五、风险与回退

| 风险 | 应对 |
| --- | --- |
| 隐式跨精度转换消失导致编译失败 | 按编译器报错逐点显式化（`point_to_int` / `point_to_double`），语义与旧实现逐条比对 |
| `Rect2i` 边界为 `int`，混算 `double` 时的截断行为 | 与旧 `coord2D_range` 完全一致，属等价改写；若有代码依赖旧隐式转换则单独确认 |
| 模板具名实例化漏改致链接错误 | `Quadtree<int>` / `Quadtree_Manager<int>` 实例化文件已在编译范围内，构建即可暴露 |
| 测试层替换引入断言偏差 | 只改类型名，断言数值与用例结构不动；以全量回归结果为准 |
| 提交混入你的其他未提交改动 | `git_commit` 显式指定路径清单，仅含四叉树/管理器/`坐标类型.h` |
| 需要撤回 | 每仓一笔提交，可用 `git revert` 单笔回退 |
