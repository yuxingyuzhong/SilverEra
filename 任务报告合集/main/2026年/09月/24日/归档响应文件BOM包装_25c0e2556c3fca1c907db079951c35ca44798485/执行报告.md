## 三、实现细节

### 3.1 接线点（本次最关键的结论）

真正生效的变量是 **`CMAKE_CXX_CREATE_STATIC_LIBRARY`**，且必须满足两个条件：

1. 在 `project()` **之后**设置 —— 否则会被 `Modules/Platform/Windows-MSVC.cmake:427` 的默认值覆盖回去；
2. 其模板中的 `<OBJECTS>` 占位符，在 Ninja 下正好展开为 `@$RSP_FILE`，即需要拦截的那个参数。

平台模板原文（CMake 4.3.1-msvc1）：

```cmake
set(CMAKE_${lang}_CREATE_STATIC_LIBRARY "<CMAKE_AR> ${CMAKE_CL_NOLOGO}${_PLATFORM_ARCHIVE_FLAGS} <LINK_FLAGS> /out:<TARGET> <OBJECTS> ")
```

**实测「压不动」归档规则的变量（勿重复尝试，浪费轮次）**：

| 变量 | 从项目侧设置 | 从 `-D` 传入 | 结果 |
| --- | --- | --- | --- |
| `CMAKE_AR` | 无效 | 无效 | 被平台模块用普通变量覆盖回默认 `lib.exe` |
| `CMAKE_CXX_ARCHIVE_CREATE` | 无效 | 无效 | 不在 Ninja 归档规则展开路径上 |
| `CMAKE_CXX_COMPILER_AR` | 无效 | 无效 | 同上 |
| `CMAKE_NINJA_FORCE_RESPONSE_FILE` | 无效 | 无效 | 开关语义为「强制用响应文件」，不改变归档器解读方式 |

**排查手法备忘**：把 `CMAKE_CXX_CREATE_STATIC_LIBRARY` 临时替换为哨兵值（如 `MARKER_CSL`），重新配置后看 `rules.ninja` 归档规则首词是否随之改写 —— 一次配置即可判定某变量是否真的接上了。

### 3.2 最终生效的归档命令（`CMakeFiles/rules.ninja` 实况，节选）

```
cmd.exe /C "$PRE_LINK && C:/Windows/System32/WindowsPowerShell/v1.0/powershell.exe
  -NoProfile -ExecutionPolicy Bypass -File <引擎层>/cmake/ar_rsp_bom.ps1
  <MSVC>/bin/Hostx64/x64/lib.exe /nologo $LINK_FLAGS /out:$TARGET_FILE @$RSP_FILE
  && $POST_BUILD"
```

### 3.3 包装脚本行为

1. 从参数中识别以 `@` 开头的响应文件参数；
2. 读取其前 3 字节：**已是 UTF-8 BOM 或全 ASCII 则原样不动**；
3. 否则在字节流前写入 `EF BB BF`（只补头，不重新编码内容，避免二次破坏）；
4. 以真实归档器 + 其余参数执行，**原样透传退出码**；
5. 诊断开关：环境变量 `BYJY_AR_WRAPPER_DISABLE_BOM=1` 时跳过补 BOM（仅用于对照实验，不参与正常构建）。

## 七、重开发指引（在干净工作区复刻本修复）

1. 新建 `引擎层/cmake/ar_rsp_bom.ps1`，**保存为 UTF-8 带 BOM**：取 `@` 响应文件参数 → 无 BOM 且含非 ASCII 时补 `EF BB BF` → 其余参数原样转交真实归档器 → 退出码透传。
2. 在 `引擎层/CMakeLists.txt` 中 `project(...)` **之后**插入：

```cmake
if(MSVC AND CMAKE_GENERATOR MATCHES "Ninja")
    # 此处 PROJECT_ROOT_DIR 尚未赋值，故用 CMAKE_CURRENT_SOURCE_DIR
    set(BYJY_AR_WRAPPER "${CMAKE_CURRENT_SOURCE_DIR}/cmake/ar_rsp_bom.ps1")
    find_program(BYJY_POWERSHELL_EXECUTABLE NAMES powershell powershell.exe)
    if(EXISTS "${BYJY_AR_WRAPPER}" AND BYJY_POWERSHELL_EXECUTABLE)
        set(CMAKE_CXX_CREATE_STATIC_LIBRARY
            "${BYJY_POWERSHELL_EXECUTABLE} -NoProfile -ExecutionPolicy Bypass -File ${BYJY_AR_WRAPPER} <CMAKE_AR> /nologo <LINK_FLAGS> /out:<TARGET> <OBJECTS> ")
    endif()
endif()
```

3. 重新配置，检查 `引擎层/out/build/x64-Debug/CMakeFiles/rules.ninja` 中归档规则首词是否为包装器调用；再构建，确认 `lib/EngineCore.lib` 产出。
4. 反向验证：`BYJY_AR_WRAPPER_DISABLE_BOM=1` 重跑归档，应复现 `LNK1181`。
