# 执行计划 · 第 656 轮（GUI 跑测试改为主线程执行）

> 轮次：第 656 轮（2026-11-05，用户选定修复方向①）
> 背景：图形界面里跑测试时弹出 `SDL_IsMainThread_REAL()` 断言（SDL3 要求事件泵在主线程）；
> 原因：`Test_Runner` 在工作线程执行 gtest，而渲染用例会创建 SDL 窗口并逐帧 `SDL_PollEvent`。
> 方案：**测试改由界面主循环在进程主线程执行**（逐轮阻塞，跑完再绘制结果）。

## 一、实现

| 文件 | 变更 |
| --- | --- |
| `src/主调/测试运行器.h` | 去掉工作线程与 `<thread>`；新增 `poll_on_caller()`；注释改写为「主线程执行」 |
| `src/主调/测试运行器.cpp` | `request_run` 仅入队并置 Running；`poll_on_caller` 在主线程取队列 → `RUN_ALL_TESTS()` → `round_end`；`shutdown` 不再 join |
| `src/主调/图形操作界面.cpp` | 主循环每帧先调 `运行器.poll_on_caller()`，再取统计并出一帧 |

## 二、语义与代价

- 一轮测试执行期间界面冻结（不再有工作线程后台跑），跑完立即刷新结果；
- 多轮排队仍受支持：每帧处理一个排队轮，轮与轮之间界面可交互；
- `request_stop` 仍为「清空后续排队」，当前轮不可中途取消（gtest 无此能力）。

## 三、验证

1. Test Debug 构建零错误；
2. 全量回归（命令行路径）零失败，确认无头/自动化行为未变；
3. 图形界面路径需人工验证一次（打开界面 → 运行渲染类套件 → 不再出现 SDL 断言弹窗）。
