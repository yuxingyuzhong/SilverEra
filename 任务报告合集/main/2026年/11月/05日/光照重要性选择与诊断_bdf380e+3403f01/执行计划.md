## 二、本轮实现（分两段）

### 段 A · 光源重要性选择（A1）

1. **数据字段**（`Scene/场景数据.h`）
   - `Light_Data::light_select_mode`（int，0 = 声明顺序（默认，旧口径）、1 = 重要性选择）。
   - `Light_Data::light_budget`（uint32_t，0 = 跟随路径上限（旧前向 8 / 簇路径全量）、>0 = 前向光照光源预算）。
   - `Scene_Data` 同步两字段并透传（数据化规约）。
2. **门面方法**（`渲染器.h` / `渲染器.cpp`）
   - `void light_select_set(uint32_t mode, uint32_t budget)`：mode 仅 0 / 1（其它按 0），budget 钳到 `[0, POINT_LIGHT_MAX]`。
3. **选择算法**（`scene_apply` 内，仅 mode = 1 且候选数 > 预算时生效）
   - 候选 = 点光（先）＋ 聚光（后）的声明序列表，各最多 8 条。
   - 评分 `score = intensity × radius/(radius + 相机距离) × 锥角可见性`
     - 锥角可见性：点光恒 1；聚光按 `clamp((cos − outer)/(inner − outer), 0, 1)`（相机位于锥内为 1）。
     - 非法 / 退化（半径非正、NaN、方向退化）评分为 0，仍可被选中（保持「非法即拒绝」的既有语义）。
   - 择优取前 `预算` 条；**同分同序**（评分降序、同分按声明序号升序）。
   - 命中集合确定后，按**声明顺序**登记（点光段在前、聚光段在后），保证槽位顺序与旧口径同构（聚光瓦片按槽位映射的 644 口径不受影响）。
4. **默认路径不变**：mode = 0 且 budget = 0 → 与旧实现逐条等价（前向 8 盏、超出 `break`）。

### 段 B · 光照诊断（A4）

1. `Frame_Stats` 增：
   - `lights_active`：最近一次场景应用后参与光照的光源数；
   - `lights_dropped`：同一次应用中因预算 / 选择而未登记的光源数；
   - `light_select_mode`：生效模式（0 / 1）。
2. `Impl` 增 `light_dropped` / `light_select_mode` / `light_budget`；`scene_apply` 每次重算。
3. `light_truncated` 语义保持：仅「簇关闭且确有光源未登记」时为 1。

### 段 C · 验证

1. 新增用例（`Application/Test/src/单元测试/Renderer/渲染光照选择测试.cpp`，套件 `Renderer_Light_Select_Test`）：
   - 默认模式：12 盏超限 → 前 8 盏生效、`lights_dropped = 4`、`light_truncated = 1`、选灯与旧口径一致；
   - 重要性模式：后声明的近距离强光入选、远弱光淘汰；连续两次 `scene_apply` 结果逐字段一致（同分同序、不抖动）；
   - 预算：`light_budget = 4` 时生效 4 盏、淘汰数正确；
   - 关闭对比：mode = 0 时与基线灯序一致（逐字段比对）。
2. 三树构建（Renderer Debug / Release、Test Debug）零错误；渲染套件 ＋ 光照分组回归；本轮为第 645 轮，**不触发全量**（每 3 轮一次）。

## 四、风险与回退

| 风险 | 处置 |
| --- | --- |
| 选择改变灯集合 → 画面变化 | 默认关闭（mode = 0）；用例锁定旧口径 |
| 评分裂化导致选灯抖动 | 同分同序（声明序号决胜）；评分公式只用相机距离 / 强度 / 半径 / 锥角，输入不变则结果不变 |
| 聚光瓦片按槽位映射（644）受影响 | 命中后仍按声明顺序登记，槽位顺序与旧口径一致 |
| UBO 8 槽限制 | 本轮不改着色器与 UBO 布局（16/32 槽扩展列入阶段 C 前的独立轮次，记录于下轮方向） |
