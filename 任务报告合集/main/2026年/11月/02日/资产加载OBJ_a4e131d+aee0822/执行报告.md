## 三、实现要点

1. **属性数组**：`v` / `vt` / `vn` 分别解析；`f` 的每个标记按 `/` 拆三段（`v`、`v/vt`、`v//vn`、`v/vt/vn`），正索引自 1 起算、负索引自末尾起算，越界即整次失败。
2. **去重**：以 `(v, vt, vn)` 三元组为键做哈希去重 → 顶点下标稳定、后接的多边形三角化不产生重复顶点。
3. **三角化**：多边形按扇形展开（`0-1-2`、`0-2-3`…），与「索引数为 3 的倍数」的网格模块校验自洽。
4. **分段**：`usemtl` 切换时收尾上一段（仅当该段确实吃到面），段序号即材质槽；无 `usemtl` 时全文件一段 `material 0`、名字为空。
5. **法线补全**：缺 `vn` 的顶点按相邻三角形叉积累加（模长即两倍面积 → 天然面积加权），零长度回落 `+Z`；已有法线一律保持。
6. **缺 `vt`**：纹理坐标填 `(0,0)`。
7. **限制**：文件 ≤ 64 MiB、属性 ≤ 400 万、索引 ≤ 1200 万；空文件 / 无有效三角面 / 语法非法一律拒绝并清空输出。
8. **门面**：`mesh_load_obj(handle, path)` 解析后直接 `mesh_create(handle, data, sections)`，分段随网格保存供 `mesh_draw_sections` 使用。

## 四、踩坑记录（复开发必读）

1. **公共头包含路径**：`资产加载.h` 首次写成 `#include "src/render/Mesh/网格数据.h"`，Test 报 `C1083`。
   Test 通过「渲染层快照」包含公共头，包含根是项目根，故公共头内必须写 `Application/Renderer/src/...` 全路径；`src/...` 只在渲染层 cpp 内部可用。
2. **渲染层构建需要 VS 开发环境**：直接 `cmake --build Application/Renderer/out/build/x64-Debug` 会报
   `无法打开包括文件: "stdio.h"`（缺 INCLUDE 环境变量）。须 `Enter-VsDevShell` 后再构建。
3. **快照刷新顺序**：渲染层构建树 → 重配 Test（刷新头文件快照 ＋ 拷贝 spv）→ 构建 `EngineTests`。
4. **门面没有 `mesh_sections_get`**：分段查询只在网格模块内部（`Mesh_Context`）；端到端用例改为只验证绘制覆盖。
