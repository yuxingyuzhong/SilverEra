## 一、目标

当前 `mesh_load_obj` / `texture_load_file` 每次调用都新建 GPU 资源：同一 OBJ 在场景清单里被多个 place 引用时仍只建一次（清单内去重），
但**跨清单 / 跨调用**重复加载会各建一份。本轮加入路径级缓存 ＋ 引用计数：

- 同一路径只创建一次资源，后续请求只把引用计数加一；
- 释放时引用计数先减一，归零才真正卸载；
- 新入口独立成 API，既有 `mesh_load_obj` / `texture_load_file` 行为不变（默认关闭原则）。

## 三、语义约定

1. **键归一化**：`类型前缀 + ':' + 路径`；路径分隔符统一为 `'/'`、ASCII 字母转小写（Windows 路径不区分大小写）。
2. **首次加载**：`refs = 1`，句柄写入输出；**命中**：`refs += 1`，返回同一句柄。
3. **释放**：`mesh_release` / `texture_release` 找到条目则 `refs -= 1`，归零时调用 `mesh_unload` / `texture_unload` 并删条目；
   未登记的句柄按「非共享资源」直接卸载（兼容混用）。
4. **诊断**：`asset_cache_count()` 返回两张表的条目总数（测试与报告用）。
5. **生命周期**：`shutdown` 清空两张表（模块销毁本身已释放资源），避免悬空句柄。

## 四、验收口径

| 项 | 口径 |
| --- | --- |
| 复用 | 同路径两次共享加载 → 句柄相等、缓存条目 = 1、第二次不新建 |
| 引用计数 | 释放一次后仍可绘制；释放归零后绘制失败、缓存条目 = 0 |
| 隔离 | 不同路径 → 不同句柄、条目 = 2 |
| 失败不入缓存 | 不存在路径 → 加载失败且条目数不变 |
| 纹理 | 同 BMP 两次共享加载 → 同一句柄；释放归零后条目清零 |
