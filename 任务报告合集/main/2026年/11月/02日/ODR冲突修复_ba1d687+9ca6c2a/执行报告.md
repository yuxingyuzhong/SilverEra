# 执行计划 / 执行报告 · 第 417 轮　修复 Mesh_Data 的 ODR 冲突

- 起点：Renderer `bd63562`、Test `42f77cb`；**终态：Renderer `ba1d687`、Test `9ca6c2a`**
- 回归：`Renderer_*` **592 / 592**；**非渲染 650 / 650（恢复通过）**
- 外部库变更：**无**

## 一、问题现象

收口做非渲染全量时，`--gtest_filter=-Renderer_*` 两次在 `Mesh_Loader_Test.三角形网格解析` 处卡住 / 退出（`0x80000003`）；
首次全量该用例耗时 64770 ms。此前第 413 轮同一套件 650 / 650 通过（第 414–416 轮之间未再跑非渲染套件）。

## 二、根因

- `Application/Renderer` 与 `Engine/EngineCore` **都定义了 `engine::Mesh_Data`**（同名不同定义：前者顶点是 `Vertex`，后者是 `float` 平铺）。
- 第 414 轮给 Renderer 的 `Mesh_Data` 增加了 `sections` 字段 → 结构体大小 48 → 72 字节；
- Test 层同时链接两层，`Mesh_Loader::load_obj` 按 EngineCore 布局写、测试按 Renderer 布局读（或反之）→ **越界写堆** → 卡住 / 崩溃。
- 渲染层用例不经过 `Mesh_Loader`，故 `Renderer_*` 一直全过，问题只在非渲染套件暴露。

## 三、修复

| 文件 | 改动 |
| --- | --- |
| `Application/Renderer/src/render/Mesh/网格数据.h` | `sections` 从 `Mesh_Data` 移除（保留 `Mesh_Section` 类型）；注释说明 ODR 原因 |
| `Application/Renderer/src/render/Mesh/网格.h` / `core/网格缓冲.cpp` | `mesh_create` 增可选 `sections` 形参（默认空）；校验与保存改用形参 |
| `Application/Renderer/src/render/Renderer/渲染器.h` / `.cpp` | 新增 `mesh_load_sections(handle, data, sections, count)`：段数组为空 / 数量 0 拒绝；转发网格模块 |
| `Application/Test/src/单元测试/Renderer/渲染物体多材质测试.cpp` | 3 个分段用例改用 `mesh_load_sections` |
| `Application/Test/src/主调/能力展示/资源构建.cpp` | 展廊「分段平面」改用 `mesh_load_sections` |

## 五、长期隐患

两层同名 `engine::Mesh_Data` 仍是 ODR 违规，只是布局恢复相同而「碰巧可用」。建议后续把渲染层类型改名（`Render_Mesh_Data`）或移入不同命名空间；
在此之前，**任何对 Renderer `Mesh_Data` 的字段增删都必须同步评估 Test 层**。
