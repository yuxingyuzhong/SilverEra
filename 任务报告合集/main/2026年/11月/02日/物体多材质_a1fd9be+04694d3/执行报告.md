## 二、实现要点（复开发必读）

1. **零复制**：`mesh_draw` 的 170 行登记逻辑（剔除 / 实例追加 / 推送块 / 描边项 / 合批）全部保留在 `mesh_draw_range` 内，
   公开 `mesh_draw` 只转发 (0, 0)；避免「整段 / 区间」两套实现漂移。
2. **区间语义**：`first_index == 0 && index_count == 0` 表示整段（既有行为）；否则
   `index_offset += first_index × 4`、`index_count = range_count`；越界（`first_index ≥ 总数` 或 `first_index + count > 总数`）整次拒绝并告警。
3. **多材质均分**：`mesh_draw_sections` 取网格索引总数，按 3 对齐得到每段长度 `((total / count) / 3) × 3`，
   最后一段吞掉余数；段数多于三角形数（每段为 0）整次拒绝。逐段 `material_bind_set` → `mesh_draw_range`，末尾恢复 `material_bind_set(0)`。
4. **合批影响**：区间项与整段项 `index_offset` / `index_count` 不同，不会被错误合并（合批条件已要求两者相等）。

## 四、排查留痕（重要）

1. **`frame_render` 首帧内容不可信**：初期用「通道和 > 200 视为亮」判断覆盖，结果整帧 2304 像素全部计为亮——
   隐藏窗口清屏色本身较亮；改用「同 renderer 的空场景基线 ＋ 逐像素差 ≥ 20」后覆盖数变为 400 / 210（真实值）。
2. **四边形覆盖面积**：`quad_data` 在 NDC ±1、相机 +Z 3 处，实际只覆盖视口中央约 400 像素（不是全屏），
   故断言阈值必须按实测（400 / 210）而非理论（2304 / 1152）。
3. **诊断手段**：临时在 `mesh_draw_range` 与项组装处加 `printf`，确认 `offset 128 / count 3`、`offset 140 / count 3` 正确后移除。

## 五、边界与后续

- 分段是「按索引均分」，不按子网格语义切分；真正的「物体多材质」若需要「每个子网格独立材质表」，应后续把分段描述放入 `Mesh_Data`（新增 `sections` 字段）。
