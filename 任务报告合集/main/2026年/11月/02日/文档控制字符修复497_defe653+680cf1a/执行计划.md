# 执行计划 · 第 497 轮　文档控制字符修复

## 一、问题

工作站 Markdown 中存在**不可见控制字符**（`0x00` / `0x07` / `0x08` / `0x0B` / `0x0C`），
来源是历史脚本用双引号字符串写文档时，反引号转义吞掉了紧随其后的字母：

| 控制字符 | 被吞掉的原文 | 典型现场 |
| --- | --- | --- |
| `0x00` | `` `0 `` | `…0xC0000005` → `…<NUL>xC0000005` |
| `0x07` | `` `a `` | `Test af3827a` → `Test <BEL>f3827a` |
| `0x08` | `` `b `` | `base_level` → `<BS>ase_level` |
| `0x0B` | `` `v `` | `vkCmdCopyBufferToImage` → `<VT>kCmdCopyBufferToImage` |
| `0x0C` | `` `f `` | `顶点/片元` 等 f 开头的代码名 |

后果：正文出现「断字」（`ase_level`、`f3827a`），且 `ripgrep` 等工具把文件误判为二进制。

## 二、修复方案

按「控制字符 → 原字母」一一回填：`0x00→0`、`0x07→a`、`0x08→b`、`0x0B→v`、`0x0C→f`；
不做其它改动（不臆造反引号，保留原文语义即可读）。扫描范围：工作站全部 `.md` / `.ps1`。
