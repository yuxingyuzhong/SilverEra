# 导航新鲜度体检 · 执行计划

## 一、背景与目标

项目导航当前只有“版次目录级哈希”，模块文档没有自描述版本，也没有“多久没更新”的记录。并行任务下，目录名与实际内容会脱节（例如 `底本重建_465703f` 中的碰撞模块已按当前源码重写）。

本次目标：

1. 建立一份**模块级清单**，记录每个模块文档的依据版次、源码范围与更新日期；
2. 提供**体检脚本**，自动列出过期、源已变更、有未提交改动与路径缺失的模块；
3. 给每个模块文档加**文件头版本标记**，让单文件可自证新鲜度。

不涉及并行任务流程改造与生成式导航（本次未选）。

## 二、设计决议

### 2.1 新鲜度以“源码变更”为主、“层版次”为辅

层版次哈希按整层头文件聚合，任一模块改动都会改变整层哈希。若只看层版次，世界/输入等未改模块会被误判为过期。

因此脚本判定顺序：

1. **源码范围**内是否存在未提交/未入库改动；
2. 源码范围内最后一次 git 提交日期是否晚于文档 `更新` 日期；
3. 清单路径是否存在；
4. 层版次是否与当前构建树锚点不同（仅作提示，不单独判过期）。

### 2.2 清单是唯一数据源

新增 `项目导航合集/main/底本重建_465703f/导航清单.md`，用 Markdown 表格记录 23 份模块文档的映射。脚本读清单，文件头由清单生成。

### 2.3 文件头格式

在每个模块文档 H1 标题之后插入一行引用块：

```markdown
> 依据版次：EngineSystem c00bda6 ｜ 依据：工作区 ｜ 更新：2026-11-08
```

- 跨层模块（构建系统）可写多个层版次，用 `、` 分隔；
- Application 模块没有独立锚点，`依据版次` 写 `工作区 465703f（冻结快照）` 或 `Test 7e368a1`；
- 更新日期只在人工确认文档已核对后修改，脚本不自动刷新。

## 三、清单格式

文件：`项目导航合集/main/底本重建_465703f/导航清单.md`

```markdown
# 导航清单（底本重建 465703f）

| 模块 | 源码范围 | 依据层 | 依据版次 | 更新日期 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 碰撞 | `Engine/EngineSystem/src/collision` | EngineSystem | c00bda6 | 2026-11-08 | 已按当前源码重写 |
| 世界 | `Engine/EngineSystem/src/world`;`Engine/EngineSystem/common/runtime/逻辑帧.h` | EngineSystem | d62229b | 2026-11-08 | 基于冻结快照 |
```

- `源码范围` 用分号分隔多个路径，路径相对项目根；
- `依据层` 取值：`EngineFoundation` / `EngineSystem` / `EngineRenderer` / `Test` / `工作区` / `构建系统`；
- `备注` 可选，写“基于冻结快照”“已按当前源码重写”“待复核”等。

## 四、体检脚本

新增：`导航体检.ps1`（工作站根目录，与 `构建双配置.ps1` 同级）。

### 4.1 参数

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `-NavDir` | 自动探测 | 版次导航目录；缺省时取 `项目导航合集/main/*/导航清单.md` 中最近修改的一份 |
| `-Config` | `Debug` | 读取层版次锚点所用配置 |
| `-NoFail` | 关 | 有落后项也返回 0，仅用于查看 |
| `-StampHeaders` | 关 | 按清单重写各模块文档的文件头 |

### 4.2 判定与输出

逐模块输出一行：

| 状态 | 条件 |
| --- | --- |
| `新鲜` | 路径都存在；无未提交/未入库改动；源码最后提交日期不晚于 `更新日期` |
| `源已变更` | 源码范围内存在晚于 `更新日期` 的 git 提交 |
| `有未提交改动` | `git status --porcelain` 在源码范围内非空（含未入库文件） |
| `路径缺失` | 清单中的路径不存在 |
| `无法比对` | 源码不在任何 git 仓库内，且无可靠时间依据 |

层版次不同只在行尾追加 `[层版次已变]`，不改变状态。

输出末尾汇总：`新鲜 N ｜ 源已变更 N ｜ 有未提交改动 N ｜ 路径缺失 N ｜ 无法比对 N`；存在非新鲜项且未加 `-NoFail` 时退出码为 1。

### 4.3 仓库定位

源码路径按前缀映射到独立仓库根：

- `Engine/EngineFoundation/…` → 该层仓库；
- `Engine/EngineSystem/…` → 该层仓库；
- `Engine/EngineRenderer/…` → 该层仓库；
- `Application/Test/…`、`Application/Game/…`、`Application/Editor/…` → 对应仓库；
- `Engine/cmake`、`Engine/版本锁.cmake` → 顶层仓库。

对每个仓库执行 `git log -1 --format=%cs -- <路径>` 与 `git status --porcelain -- <路径>`；未入库路径回退到文件修改时间并标注。

### 4.4 编码与行尾

- 读取与写回统一用 .NET `UTF8Encoding`，保留原 BOM 状态与行尾（不做 LF/CRLF 转换）；
- 清单解析按 `|` 分列并去空白，忽略分隔行；
- 路径中的反引号在比较前剥除。

## 五、文件头写入

`-StampHeaders` 行为：

1. 读清单；
2. 对每份模块文档定位 H1（第一行 `# `）；
3. 若 H1 后已存在以 `> 依据版次：` 开头的行则替换，否则在 H1 后插入一行（保留一个空行）；
4. 不修改文档其余内容，不修改清单。

写入前会打印将改动的文件列表，便于核对。

## 七、执行阶段

1. 生成 `导航清单.md`（23 行映射，按上表）；
2. 写 `导航体检.ps1` 并先用 `-NoFail` 跑通解析与仓库定位；
3. 用 `-StampHeaders` 写入 23 份文件头；
4. 再跑一次体检，核对状态分布；
5. 把体检结果记入执行报告，提交并推送文档仓库。

## 八、验证

- 脚本能在不传 `-NavDir` 时自动找到 `底本重建_465703f`；
- 清单 23 行全部被解析，无遗漏；
- `碰撞` 应显示 `新鲜`（源码今日已提交、更新日期为今日）；
- `世界` / `输入` 应显示 `有未提交改动` 或 `无法比对`（源码尚未入库），与实际情况一致；
- 文件头写入后，模块文档除新增一行外无其他 diff；
- `-NoFail` 与默认模式的退出码符合预期。

## 九、风险与边界

1. 现有 6 个渲染模块的源码路径较长，清单必须写全路径，避免脚本按省略号匹配失败。
2. `Application/Game/星屑弹幕` 是独立仓库/快照，git 定位可能失败，脚本按“无法比对”处理并提示。
3. 更新日期需要人工维护；脚本只负责发现“源码晚于更新日期”，不判断文档内容是否真的写对。
4. 层版次提示会因任一模块改动而抖动，故只作提示，不参与过期判定。
5. 本次不处理并行任务合并流程；后续可在此清单基础上增加“模块负责人/任务号”列。
