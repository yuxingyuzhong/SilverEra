## 四、判定口径

1. **源码范围**：清单中的路径逐项检查存在性。
2. **未提交/未入库**：对源码路径执行 `git status --porcelain`，非空即判“有未提交改动”；未入库目录会显示为 `??`。
3. **源码变更**：执行 `git log -1 --format=%cs -- <路径>`，最后提交日期晚于文档“更新日期”即判“源已变更”。
4. **无法比对**：源码不在任何 git 仓库内，或既无提交记录也无未提交标记。
5. **层版次提示**：读取对应仓库 `git rev-parse --short=7 HEAD`，与清单记录不同时追加“层版次已变”，但不单独判过期。
6. **构建锚点**：对三层引擎模块额外读取 `out/build/x64-<配置>/include/Engine/<层>/版本锚点.h` 中的 12 位符号哈希，仅作展示。

判定优先级：路径缺失 > 有未提交改动 > 源已变更 > 无法比对 > 新鲜。

## 八、已知限制

1. “有未提交改动”包含未入库文件；在并行重构未提交前，多数模块会长期处于该状态。这是事实暴露，不是脚本缺陷。
2. 更新日期需人工维护；脚本只发现“源码晚于更新日期”，不判断文档内容是否写对。
3. `配置编辑器` 的源码目录未被 Editor 仓库跟踪，只能标“无法比对”。
4. 层版次提示会随任一模块改动而抖动，因此只作提示。
5. 星屑弹幕使用独立仓库哈希；若其仓库切换分支，清单需同步更新。
