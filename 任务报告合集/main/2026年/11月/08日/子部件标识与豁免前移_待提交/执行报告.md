# 执行报告：子部件标识 + 碰撞豁免前移

## 一、任务结论

1. 公共 API 仍是一角色一碰撞体：上层只管理 `collider_ID`，几何配置仍是一个 `geometries` 列表。
2. 后端把每个子部件做成独立 `btCollisionObject`；复合形状退出多部件场景，自碰由 Bullet 正常检测。
3. 碰撞信息精确到子部件：`Collision_Contact` 与 `Collision_Result` 均携带 `part_A/part_B`，`DetectResult` 条目同样携带。
4. 豁免前移到宽阶段：跨碰撞体按同组对称互免，同一碰撞体内按对称子部件忽略对；后置过滤删除。
5. 豁免语义只保留对称规则，无任何单向豁免。

## 三、关键契约

### 3.1 子部件编号

- 类型 `uint16_t`，`0xFFFF` 为“无子部件”哨兵，不作为合法编号。
- 几何配置每个元素可选 `part_ID`；缺省按未占用最小值依次分配。
- 同一碰撞体内必须唯一，重复或越界整条几何配置拒绝。
- 忽略对 `part_ignore` 必须引用已存在的编号，不允许自忽略对，内部按排序键归一化。

### 3.2 运动

- 整体运动：改根变换，随后重算全部子部件世界变换。
- 部件运动：按子部件编号改该部件局部变换并重算其世界变换。
- 单部件碰撞体的部件运动仍退化为整体运动（保持旧语义）。
- 运动事件中 `parts[].part` 即子部件编号；编号不存在整条事件拒绝。

### 3.3 豁免

- 不同碰撞体：两侧 `exemption_flag` 非零且相等即互免。
- 同一碰撞体：`part_ignore` 命中对称忽略对即互免。
- 判定位于 `btOverlappingPairCache::setOverlapFilterCallback` 的 `needBroadphaseCollision`，保留内置过滤组与掩码检查。
- 豁免标记变更后重挂碰撞体以强制重建宽阶段配对。

### 3.4 结果

- `Collision_Contact::part_A/part_B` 由流形两侧子部件对象反查得到。
- `Collision_Result` 与 `DetectResult` 条目按子部件对去重输出。
- 同一碰撞体自碰允许 `collider_A == collider_B`，两侧子部件编号不同；此时法线不做方向约定。

## 五、重开发提示

1. 子部件对象必须 `unique_ptr` 堆分配，`userPointer` 才稳定；严禁放入可扩容容器。
2. 所有反查点统一走 `Collider_Backend_Access::part_recover`（返回 `Geometry_Part_Object*`），不要再按碰撞体实现体反查。
3. 宽阶段过滤替换了内置过滤，务必保留过滤组与掩码检查，否则自定义过滤组会失效。
4. 豁免配置变更必须重挂或清理配对，否则旧配对继续参与窄阶段。
5. 子部件编号在几何重建时按编号保留运动登记；新增几何配置路径需保持该清理规则。
6. 扫掠路径不经过宽阶段，命中后的豁免判定需在提取处单独做（已实现）。
