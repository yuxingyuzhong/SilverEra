# 执行计划：碰撞运动通道扩展（旋转 + 部件级运动）

## 一、目标

1. 把现有「位移向量」升级为「运动量」：同时携带平移与旋转。
2. 支持碰撞体内每个几何部件单独配置运动量（部件相对运动）。
3. **删除碰撞响应协议**：碰撞系统不再主动索要裁决；外界拿到碰撞数据后自行决定是否更新 motion，更新就投递 `ColliderMotion`，不更新则保持现状。
4. 保留唯一的 motion 更新事件协议，替换旧的 `ColliderDisplacement` 语义。
5. 保持后端封装边界：Bullet 仍只出现在 `*/backend/**` 与 `数学转换.h`。

## 二、命名与语义

### 2.1 统一改名

`displacement` → `motion`（中文注释统一为「运动量」）：

| 旧 | 新 |
| --- | --- |
| `Collider::displacement_vector` | `Collider::motion` |
| `Collider::displacement_invalid` | 删除（外部投递零运动即可停止） |
| `Collider::displacement_frequency` | `Collider::motion_frequency` |
| `Collider::displacement_frame` | `Collider::motion_frame` |
| `Collider::displacement_step` | `Collider::motion_step` |
| `Collision_Proxy::displacement_register` | `motion_register` |
| `Collision_Proxy::displacement_seek` | `motion_seek` |
| `Collision_Proxy::displacement_events` | `motion_events` |
| `Proxy_Backend::reader_bind` | `motion_reader_bind` |
| 事件 `Collision/ColliderDisplacement` | `Collision/ColliderMotion` |
| `Collision/ColliderCollision` | 删除 |
| `Collision/ColliderCollisionResponse` | 删除 |
| 回复信箱 `collision_responses` | 删除 |

旧事件 tag 不再保留（当前无生产消费方，测试同步改写）。

### 2.2 运动量定义

新增 `Common/运动类型.h`：

```cpp
//单通道运动量（周期总量，不是每帧增量）
struct Motion
{
    Vector3 translation{ 0.0f, 0.0f, 0.0f };
    Quaternion rotation{}; //默认单位四元数
    bool empty(void) const;           //平移为零且旋转为单位
    Motion operator/(Scalar factor) const; //平移除以因数，旋转按轴角等分
};

//部件运动量（part 为几何部件下标，从零开始）
struct Part_Motion
{
    uint32_t part = 0;
    Motion motion;
};
```

语义约定：

- **整体运动**：绕碰撞体自身原点旋转，再按世界轴平移。
  即 `new_origin = old_origin + translation`，`new_rotation = old_rotation * delta_rotation`。
- **部件运动**：在碰撞体局部空间内绕该部件原点旋转，再按局部轴平移：
  `new_local = old_local * delta_transform`（只改部件局部变换，不动碰撞体世界变换）。
- **执行顺序**：先整体运动，再逐部件应用；同一步内先平移后旋转。
- **频率**：仍按碰撞体粒度；`motion_frequency` 同时约束整体与全部部件，不引入部件级频率。
- **离散拆分**：旋转与部件运动一律走离散分段；每段的旋转按轴角 `angle / step_count` 等分，平移按 `translation / step_count` 等分。
- **步数必须显式提供**：`step_count` 取自该碰撞体的 `detection_mode.step_length`，旋转或部件运动要求 `step_length >= 1`；缺失或为零时**拒绝该运动事件并告警**，不做默认步数兜底。

### 2.3 旋转工具

`Common/几何类型.h` 的 `Quaternion` 增加：

- `bool identity_check(Scalar epsilon = 1e-6f) const`
- `Quaternion normalized(void) const`（零四元数返回单位）
- `bool axis_angle_get(Vector3& axis, Scalar& angle) const`
- `static Quaternion from_axis_angle(const Vector3& axis, Scalar angle)`

不引入 slerp；分段旋转用轴角等分，避免四元数除法歧义。

## 三、事件协议

### 3.1 投递事件：`Collision/ColliderMotion`

```json
{
  "collider_ID": 12,
  "frequency": 60,
  "motion": {
    "translation": [1.0, 0.0, 0.0],
    "rotation": [0.0, 0.0, 0.0, 1.0]
  },
  "parts": [
    {
      "part": 1,
      "translation": [0.0, 0.0, 0.5],
      "rotation": [0.0, 0.0, 0.0, 1.0]
    }
  ]
}
```

规则：

- `motion` 与 `parts` 至少出现一个；可同时出现。
- `translation` 为三元数组，缺省为零向量。
- `rotation` 为四元数 `[x,y,z,w]`，缺省为单位四元数；零长度四元数判为非法。
- `part` 从零开始，必须小于该碰撞体几何部件数；越界整条事件拒绝并告警。
- 同一 `part` 重复出现时后者覆盖前者。
- `frequency` 可选：缺省沿用旧值；`0` 表示每次检测都施加周期总量（沿用现有语义）。
- `frequency` 必须整除逻辑帧率，沿用现有校验。
- 运动包含旋转或 `parts` 时，该碰撞体的 `detection_mode.step_length` 必须大于零；否则整条事件拒绝并告警（不兜底步数）。
- 几何重建（`ColliderSet`）会清空已登记的部件运动，避免部件下标漂移；若重建后 `step_length` 变为零且仍存在旋转/部件运动，则同时清空该运动。

### 3.2 碰撞响应协议：删除

碰撞系统不再主动索要裁决，以下内容整体移除：

- 事件订阅：`Collision/ColliderCollisionResponse`。
- 事件发布：`Collision/ColliderCollision`（按碰撞体分发的裁决请求）。
- Proxy 回复信箱 `collision_responses`、登记/施加/两轮重发逻辑（`collision_protocol`）。
- `Collider::motion_invalid` 及检测时的作废判断：外部要停止运动，直接投递零运动即可。

外界处理碰撞数据的推荐链路：

```
region_detect 返回详细结果（或订阅 DetectResult 通知）
  → 外部运动控制器计算新 motion
  → 投递 ColliderMotion
```

不再有“碰撞 → 外界 → 碰撞”的回程。

## 四、数据结构与接口变更

### 4.1 前端 `Collider`

```cpp
Motion motion;                       //整体运动（周期总量）
std::vector<Part_Motion> part_motions; //部件运动（周期总量）
uint64_t motion_frequency = 0;
uint64_t motion_frame = 0;
Motion motion_step;                  //本帧实际施加量
std::vector<Part_Motion> part_motion_steps; //本帧部件施加量
```

### 4.2 后端 `Collider_Backend`

新增公开方法：

- `uint32_t part_count(void) const;`
- `bool motion_advance(const Motion& motion);`（整体：改世界变换的平移与旋转）
- `bool part_motion_advance(uint32_t part, const Motion& motion);`（部件：改局部变换）

部件运动实现：

- 多部件：`btCompoundShape::updateChildTransform(part, new_local, true)`，随后更新对象 AABB。
- 单部件：`part == 0` 时退化为整体运动（单部件局部变换恒为单位）。

### 4.3 `Collider_Move`

```cpp
struct Collider_Move
{
    uint64_t ID = 0;
    Collider_Backend* backend = nullptr;
    Motion body_step;                    //本帧整体运动
    std::vector<Part_Motion> part_steps; //本帧部件运动
    uint32_t step_count = 0;
};
```

检测策略：

- 仅整体纯平移：沿用扫掠路径，`step_count` 可为零（视作一段）。
- 出现旋转或任一部件运动：强制离散路径，且要求 `step_count >= 1`；事件登记阶段即校验，不满足则拒绝。
- 扫掠清单只收「纯平移且无部件运动」的碰撞体；其余只进离散清单。

## 五、分段执行

### 段 0：删除响应协议（先做，行为可观察）

1. 删除事件 `ColliderCollision` / `ColliderCollisionResponse` 的订阅、发布与分发分支。
2. 删除 Proxy 的回复信箱、登记/施加/两轮重发逻辑（`collision_protocol` 及 `collision_response_*`）。
3. 删除 `Collider::motion_invalid` 与检测时的作废判断（此时字段仍名 `displacement_invalid`）。
4. 删除 `碰撞响应测试.cpp`；其余测试改为“API 检测 + DetectResult 通知”，不再断言裁决事件。
5. 验收：碰撞套件全绿，`region_detect` 行为与响应协议删除前一致（除不再发裁决事件）。

### 段 A：类型与改名（行为不变）

1. 新增 `Common/运动类型.h`；`几何类型.h` 补四元数工具。
2. `Collider` 字段与方法改名，`Collider_Move` 改为 `body_step` + `part_steps`。
3. Proxy 方法/成员改名；事件 tag 改为 `ColliderMotion`，载荷先只支持 `motion.translation`（旋转字段解析但暂不生效）。
4. 测试同步改名，平移行为必须与改造前完全一致。
5. 验收：EngineSystem + TestSystem 构建，碰撞套件全绿。

### 段 B：整体旋转通道

1. `Collider_Backend::motion_advance` 实现旋转（世界变换原地旋转 + 世界平移）。
2. `Region_Backend` 离散推进改为按 `Motion` 逐步应用；扫掠清单排除带旋转者。
3. `Collision_Region::detect_detail` 的生效门控按「平移 ÷ 频率、旋转轴角 ÷ 频率」计算。
4. 测试：整体旋转改变 AABB/朝向；旋转时走离散；频率门控对旋转生效；`step_length == 0` 时旋转事件被拒绝。

### 段 C：部件级运动

1. `Collider_Backend::part_count` / `part_motion_advance`，复合形状子变换更新与 AABB 刷新。
2. `Collider` 存储 `part_motions` / `part_motion_steps`；`ColliderSet` 清空部件运动。
3. 事件解析 `parts` 数组、下标校验、重复覆盖。
4. 检测：任一部件运动存在时强制离散；单部件下标 0 退化为整体运动。
5. 测试：多部件单动一件、部件旋转、越界下标拒绝、单部件退化、几何重建清空、`step_length == 0` 时部件事件被拒绝。

### 段 D：收口

1. 删除旧 `ColliderDisplacement` 残留、旧字段名、`motion_invalid` 残留与旧测试断言。
2. 全量 Debug/Release 构建与测试；Bullet 泄漏门禁。
3. 更新执行报告与项目导航（提交后按版次内更新口径）。

## 七、风险与待确认

1. **旋转扫地机**：旋转无法扫掠，统一退化为离散分段；旋转或部件运动要求 `detection_mode.step_length >= 1`，缺失则拒绝事件，不做兜底。
2. **单部件退化**：单部件碰撞体的 `part=0` 运动按整体运动处理；若希望部件运动严格独立，需要把单部件也包装成复合形状（会增加开销）。
3. **响应协议已删除**：不再有“碰撞主动索要裁决”的回程；`ColliderCollision` / `ColliderCollisionResponse` / 回复信箱全部移除。外部要停止运动就投递零运动。
4. **部件下标稳定性**：下标依赖几何配置顺序；重建几何即清空部件运动，避免旧下标落到新部件上。

## 八、影响面

- 公开 API 破坏性变更：`ColliderDisplacement` → `ColliderMotion`，`Collider` 字段改名；
  `ColliderCollision` / `ColliderCollisionResponse` 事件删除，回复信箱与两轮重发逻辑删除。
- 无生产消费方；测试与报告同步更新（`碰撞响应测试.cpp` 删除）。
- 后端新增两条运动方法；子弹库依赖仍锁在 `*/backend/**`。

## 九、执行顺序

`段 0`（删除响应协议）→ `段 A` → `段 B` → `段 C` → `段 D`，每段结束先跑碰撞套件，再进入下一段。
