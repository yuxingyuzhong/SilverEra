# 执行报告：碰撞运动通道扩展（旋转 + 部件级运动）

## 一、任务结论

1. 位移通道升级为运动通道：一条运动量同时携带平移与旋转。
2. 支持碰撞体内每个几何部件单独配置运动量。
3. 碰撞响应协议彻底删除：碰撞系统不再主动索要裁决，只留唯一的 `Collision/ColliderMotion` 更新事件。
4. 含旋转或部件运动时必须显式提供离散步长，缺失即拒绝事件，不做兜底。
5. Bullet 依赖仍锁死在 `*/backend/**` 与 `Common/数学转换.h`。

## 三、关键契约

### 3.1 运动量语义

- 整体运动：`new_rotation = old_rotation * delta_rotation`，`new_origin = old_origin + translation`（先旋转后平移）。
- 部件运动：只改该部件局部变换，碰撞体世界变换不变。
- 单部件碰撞体的 `part = 0` 退化为整体运动。
- 运动等分：平移按段数/频率等分，旋转按轴角等分（`Motion::operator/`）。

### 3.2 事件协议

```json
{
  "collider_ID": 12,
  "frequency": 60,
  "motion": {
    "translation": [1.0, 0.0, 0.0],
    "rotation": [0.0, 0.0, 0.0, 1.0]
  },
  "parts": [
    { "part": 1, "translation": [0.0, 0.0, 0.5], "rotation": [0.0, 0.0, 0.0, 1.0] }
  ]
}
```

校验规则：

1. `motion` 与 `parts` 至少一个，可同时出现。
2. `rotation` 为零四元数即非法。
3. `frequency` 可选，缺省零；必须整除逻辑帧率，否则退回零。
4. 含旋转或 `parts` 时，目标碰撞体的 `detection_mode.step_length` 必须大于零，否则整条拒绝。
5. `part` 必须小于几何部件数，越界整条拒绝；同下标后者覆盖前者。
6. 几何重建（`ColliderSet`）清空已登记部件运动。
7. `detection_mode.step_length` 归零时，清空含旋转或部件运动的登记。
8. 运动读取回调返回 false（无登记）时，碰撞体运动清零，不沿用旧值。

### 3.3 检测路径

- 纯平移且启用扫掠：走 `swept_collect`，段数可为零（视作一段）。
- 含旋转或任一部件运动：强制走 `discrete_run`，逐段应用后逐段求交。
- 结果仍为 `Collision_Detail`，含接触点、法线、深度、扫掠比例。

## 五、重开发提示

1. 运动推进入口在 `Collider_Backend::motion_advance` 与 `part_motion_advance`；后者依赖 `btCompoundShape::updateChildTransform` 并刷新 AABB。
2. 分段循环归属后端：`Region_Backend::swept_collect` / `discrete_run`，前端只组织 `Collider_Move` 清单。
3. 事件解析集中在 `Collision_Proxy/core/运动管理.cpp`；校验失败一律整条拒绝，不修改旧登记。
4. 频率门控在 `Collision_Region/core/检测执行.cpp`，未到帧间隔时连运动事件都不重读。
5. 运动登记与几何/步长联动清理位于 `Collision_Proxy/core/碰撞体配置.cpp`，新增几何配置路径时须同步保持该清理。
6. 测试辅助沿用 `碰撞测试辅助.h`；旋转方向统一为右手系绕 +Z。
