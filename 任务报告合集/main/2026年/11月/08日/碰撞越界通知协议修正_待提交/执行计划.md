## 二、现状结论

当前实现位于 `Engine/EngineSystem/src/collision`，越界通知链路为：

1. `Collision_Region::detect_detail` 末尾调用 `cross_state_update`；
2. `cross_state_update` 以“是否与边界接触”和“包围盒中心射线奇偶”判定 `inside / crossing / outside`；
3. `region_detect` 取走通知并发布事件 `Collision/RegionCrossNotice`（单向、无回执、载荷仅 region/collider_ID/state）。

已确认的问题：

| 编号 | 问题 | 位置 |
| --- | --- | --- |
| P0-1 | 与边界接触即判 `crossing`，站在地形上或空间内贴墙会误报 `cross`，离开后再报 `return` | `Collision_Region/core/跨越通知.cpp` |
| P0-2 | 扫掠路径命中边界被直接丢弃，快速穿越只报 `exit`，穿内部薄壁时完全无通知 | `Collision_Region/backend/core/空间后端.cpp`、`Collision_Region/core/检测执行.cpp` |
| P0-3 | 边界重建不清 `cross_states`，重建后可能误报一次 | `Collision_Region/core/空间与边界.cpp` |
| P0-4 | 无去抖/迟滞，贴边抖动反复推送 | `Collision_Region/core/跨越通知.cpp` |
| P1-1 | 通知载荷缺前一状态、位置、帧号，外部无法判断方向与回推位置 | `Collision_Proxy/core/空间管理.cpp` |
| P1-2 | 碰撞体卸载/转移时状态被静默擦除，无状态消失通知 | `Collision_Region/core/碰撞体管理.cpp` |
| P1-3 | 通知顺序依赖 unordered_map，且与 DetectResult 无关联字段 | `Collision_Region/core/跨越通知.cpp`、`Collision_Proxy/core/空间管理.cpp` |
| P2-1 | 未移动的碰撞体每帧仍做射线判定 | `Collision_Region/core/跨越通知.cpp` |
| P2-2 | 空间停用期间通知滞留，重新激活后发出过期通知 | `Collision_Region/core/空间与边界.cpp`、`Collision_Proxy/backend/core/空间编排.cpp` |
| P2-3 | 无当前跨越状态查询入口 | `Collision_Region/碰撞空间.h` |

## 三、设计决议（已确认）

1. **部分跨越判定**：采用“接触时多探针”。
   - 未与边界接触：沿用包围盒中心的单次射线奇偶判定，结果只可能是 `inside` 或 `outside`。
   - 与边界接触：对包围盒中心 + 八个顶点共九个探针做 `point_inside`；内外混合判 `crossing`，全内判 `inside`，全外判 `outside`。
   - 因此“空间内贴墙/站地形”不会再被判为 `crossing`。
2. **快速穿越补报**：采用“补发 cross + exit”。
   - 扫掠路径命中边界时登记为穿越；本帧最终状态为 `outside` 时，同一检测帧依次发出 `cross`、`exit` 两条通知。
3. **查询走事件协议**：不新增公开同步 C++ 查询接口；新增请求事件与结果事件，依赖事件中转站的同步派发实现“调用即得到结果”的使用效果。

## 四、详细设计

### 4.1 跨越状态判定

`cross_state_update` 改为接收三类输入：

- 离散检测登记的边界接触编号集合；
- 扫掠检测登记的边界穿越编号集合；
- 本帧移动过的碰撞体编号集合。

单个碰撞体的判定流程：

1. 未挂载几何 → 跳过；
2. 若本帧未移动、且已存在状态记录、且缓存未失效 → 直接沿用旧状态，不做任何射线；
3. 若在边界接触集合中：
   - 取世界包围盒，生成中心 + 八顶点共 9 个探针；
   - 记录逐探针 `point_inside` 结果；
   - 同时存在内、外探针 → `crossing`；全部在内 → `inside`；全部在外 → `outside`；
4. 否则取包围盒中心单探针，奇偶判定 `inside / outside`。

九个探针全部用现有 `Region_Backend::point_inside`，不新增后端判定入口。

### 4.2 通知生成规则

记旧状态为 `previous`、本帧判定状态为 `current`、是否发生扫掠穿越为 `traversed`：

- 若 `traversed` 或 `current == crossing` → 生成一条 `cross`；
- 若 `current != crossing`：
  - `current != previous` → 生成一条最终状态通知（`return` / `exit`）；
  - 或 `traversed && current == outside` → 生成一条 `exit`（覆盖“内外都在空间外但一帧内穿了个来回”的情形）；
- 相邻重复类型去重；
- 首次判定只建立基准，不产生通知（沿用现有约定）；
- 更新状态记录为 `current`。

通知类型与状态映射保持：`crossing → "cross"`、`inside → "return"`、`outside → "exit"`。

### 4.3 通知载荷扩展

`Cross_Notice` 增加：

- `previous`（前一状态）；
- `position`（判定时世界包围盒中心）；
- `frame`（逻辑帧号）；
- `sequence`（本空间单调递增序号）。

事件载荷对应增加 `previous_state`、`position`、`frame`、`sequence` 字段；`DetectResult` 载荷增加 `frame`，用于与跨越通知对齐。

### 4.4 生命周期与缓存

- `boundary_build` 成功后清空 `cross_states` 与 `cross_notices`（重建即重新建立基准，不产生跨越通知）。
- `state_set(false)` 时清空 `cross_states` 与 `cross_notices`（停用期间不保留旧基准与过期通知）。
- `collider_set(geometry)` 成功时擦除该碰撞体的状态记录（几何重建/瞬移不算真实跨越，下次检测静默重建基准）。
- `collider_unload` 维持现有擦除逻辑；转移经由卸载路径自然清理。
- 缓存失效来源：边界重建、空间停用、几何重建；其余情况仅对“本帧移动过”的碰撞体重算。

### 4.5 查询事件协议

新增事件（类别仍为 `Collision`）：

| 方向 | 标签 | 载荷 |
| --- | --- | --- |
| 外部 → 本模块 | `RegionCrossStateQuery` | `region`（必填）、`collider_ID`（可选，缺省查全空间）、`request_ID`（可选） |
| 本模块 → 外部 | `RegionCrossStateResult` | `region`、`found`、`request_ID`（原样回传）、`states`（`[{collider_ID, state}]`） |

- `state` 取值：`inside` / `crossing` / `outside` / `unknown`（尚未建立基准或几何未挂载）。
- 空间不存在时回 `found = false` 与空 `states`。
- 代理器在 `event_process` 内处理查询并同步 `event_publish` 结果事件。
- 事件中转站按订阅者同步调用回调，故请求方在 `send` 返回前即可收到结果；请求方需自行订阅 `RegionCrossStateResult`。
- 注意：中转站不向发送者自身回投事件，请求方必须是独立模块（不得与 `Collision_Proxy` 同名）。

新增 `Collision_Region::cross_state_snapshot` 作为内部快照出口，仅供代理器调用。

### 4.6 性能

- 未移动且状态有效的碰撞体不再做射线；
- 多探针只对“本帧与边界接触”的碰撞体执行，通常数量很少；
- 最坏情况成本为“接触碰撞体数 × 9 次射线”，非接触碰撞体仍为 1 次（且仅移动时）。

## 七、验证方式

- 构建：使用工作站 `构建双配置.ps1 -Configs Debug`（自动进入 VS 开发人员环境，按层顺序构建）。
- 测试：运行 System 层测试可执行文件，过滤新增跨越用例（`*跨越*`）。
- 手工核对点：
  1. 碰撞体在空间内贴墙移动，不产生 `cross`；
  2. 碰撞体半嵌入边界，产生 `cross`；
  3. 大位移扫掠直接穿出，同帧依次产生 `cross` 与 `exit`；
  4. 边界重建后首次检测无通知；
  5. 空间停用再激活，不补发停用前的通知；
  6. 查询事件返回 `inside / crossing / outside / unknown` 与请求编号。

## 八、已知限制与风险

1. 多探针基于世界包围盒顶点，旋转或球形碰撞体在凹角处仍可能出现极小概率误判；属于可接受的近似。
2. 同一检测帧可能产生两条通知（`cross` + `exit` 或 `cross` + `return`），外部需按序列处理，不能假设“一帧一条”。
3. 查询“同步”依赖事件中转站的同步派发实现；若未来改为异步入队，查询将退化为异步请求/应答。
4. 事件中转站默认不向发送者回投，查询结果只能由独立模块接收。
5. 首次判定静默建基准的约定保持不变，越界玩法若需“初始即在外”的事件，需外部在初始化后自行查询一次。
