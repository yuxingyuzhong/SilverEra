## 二、行为变更摘要

1. **部分跨越判定**：与边界接触时由“接触即 `crossing`”改为“中心 + 八顶点九探针”，内外混合才判 `crossing`；未接触时仍用包围盒中心射线奇偶。空间内贴墙/站地形不再误报 `cross`。
2. **扫掠穿越补报**：扫掠路径命中边界时登记移动体编号；最终状态为 `outside` 时同一检测帧依次发出 `cross`、`exit`；最终为 `inside` 时至少发出 `cross`（旧状态在外还会补 `return`）。
3. **生命周期清理**：
   - 空间停用（`state_set(false)`）清空跨越状态、脏标记与待发通知；
   - 边界构建/重建成功后清空同样三项；
   - 几何设置（`collider_set(geometry)`）成功后把该碰撞体标脏，强制重算但保留旧基准。
4. **载荷补全**：`RegionCrossNotice` 增加 `previous_state`、`position`、`frame`、`sequence`；`DetectResult` 增加 `frame`。
5. **事件化查询**：新增入站 `RegionCrossStateQuery` 与出站 `RegionCrossStateResult`，支持按空间或按编号查询当前跨越状态快照，`request_ID` 原样回传。
6. **缓存**：未移动、未穿越、未标脏且已有基准的碰撞体不再做射线判定。

## 四、关键实现细节

### 4.1 判定分支

- 接触（离散末位置与边界有流形）：`probe_points_build` 生成中心 + 八顶点，逐点 `Region_Backend::point_inside`；计数为 0 → `outside`，等于 9 → `inside`，其余 → `crossing`。
- 未接触：包围盒中心单点奇偶。
- 未移动、未穿越、未标脏且已有基准：直接跳过，不产生射线。

### 4.2 通知生成

记旧状态 `previous`、当前状态 `current`、扫掠穿越标记 `traversed`：

- `traversed` 或 `current == crossing && previous != crossing` → 追加 `cross`；
- `current != crossing` 且（`current != previous` 或 `traversed && current == outside`）→ 追加 `return`（`inside`）或 `exit`（`outside`）；
- 其余情况不产生通知；
- 每条通知写入同一 `previous`、当前包围盒中心、`Logics::frame_count_get()` 与本空间递增 `sequence`。

### 4.3 查询事件

请求：

```json
{ "region": "空间名", "collider_ID": 3, "request_ID": 77 }
```

`collider_ID` 与 `request_ID` 均为可选。结果：

```json
{
  "region": "空间名",
  "found": true,
  "request_ID": 77,
  "states": [ { "collider_ID": 3, "state": "inside" } ]
}
```

- 空间不存在：`found = false`，`states` 为空数组。
- 状态未建立基准或几何未挂载：`state = "unknown"`。
- 事件中转站同步派发，请求方在 `send` 返回前收到结果；中转站不向发送者自身回投，请求方必须是独立模块。

## 七、已知限制

1. 九探针使用世界包围盒顶点；旋转盒体或球形碰撞体在凹角处仍可能出现极小概率误判。
2. 同一检测帧可能出现两条通知（`cross` + `exit` / `cross` + `return`），外部不得假设“一帧一条”。
3. 首次判定仍静默建立基准；若需要“初始即在外”的事件，外部应在初始化后主动查询一次。
4. 查询的“同步”语义依赖事件中转站的同步派发实现；若未来改为异步入队，查询会退化为异步请求/应答。
5. 项目导航 `底本重建_465703f` 存在本次任务之前遗留的运动/响应协议章节漂移；本次仅更新与跨越通知相关的章节，未改动其余遗留内容。
