## 三、关键决策

1. **类型唯一化**：`Mesh_Data` 的唯一定义落在 EngineCore `网格加载器.h`；渲染层与碰撞区域都转包含，彻底消除「同名不同定义」的 ODR 隐患（此前的规避手段是「不改布局 + 不混包含」，本轮不再需要）。
2. **解析器随类型迁移**：仅搬类型会造成「渲染层解析器产出 EngineCore 类型」的反向依赖叙事，故把 OBJ 解析器一并下沉；渲染层仅保留薄包装以稳定 `obj_mesh_load` 调用面。
3. **顶点去重语义**：沿用渲染层解析器（按 `(v, vt, vn)` 组合），而不是旧 EngineCore 的纯位置去重——因为 GPU 顶点布局要求属性组合独立。测试期望值据此修正。
4. **碰撞消费点同步**：`mesh_shape_build` 从浮点平铺改为 `Vertex.position`，行为（顶点顺序、索引）不变。

## 五、已知问题与后续建议

1. **VS 多配置生成器下快照选择缺陷（已修，同轮补提交）**：原 `CMakeLists.txt` 由 `CMAKE_BUILD_TYPE` 推导下层树，而 VS 多配置下该变量为空 → 恒落 `x64-Release` 快照，Debug 构建树实际编译的是 Release 版 EngineCore 头。
   修法（Renderer `d144abe`）：配置期同时算出 Debug / Release 两份快照根与库；导入目标补 `IMPORTED_LOCATION_DEBUG / RELEASE / RELWITHDEBINFO / MINSIZEREL`（多配置按 `$<CONFIG>` 取库），包含根改为 `$<IF:$<CONFIG:Debug>, x64-Debug/include, x64-Release/include>`；单配置（Ninja）仍按 `CMAKE_BUILD_TYPE` 挑 `IMPORTED_LOCATION`。快照缺失时按配置回退 `Engine/EngineCore/out/build/x64-<Debug|Release>`。手工覆盖 `BYJY_ENGINE_CORE_LIB_PATH` 时两配置共用该库，快照根由库所在构建树反推。
   验证：Debug 树重新配置后打印「DEBUG 使用冻结下层快照 → …/x64-Debug」与「RELEASE → …/x64-Release」，生成工程里 Debug 段包含根为 `x64-Debug/include`、Release 段为 `x64-Release/include`；Debug 构建成功，EngineTests 重建后全量 **1364 例 / 78 套件 / 0 失败**（297.155 s）。
2. 上层选库问题（已修，同轮补提交，详见第六节）：EngineSystem `7798162` 与 Test `22ca754` 接入下层时改为按构建配置取库与头快照；渲染层 `x64-Release` 树已补齐并完成 Release 全量验证。
3. `项目架构.md` 中多处 `Application/Renderer` 版次表行（`31d0cec`）为历史遗留，目录已迁至 `Engine/EngineSystem/src/core/Renderer`，本轮未逐条改写。
4. 渲染层 `core/网格加载器.cpp`（过程式生成）与下沉后的 `Mesh_Loader` 同名不同物，属命名遗留，未改名。

## 六、Release 构建树与上层按配置选库（同轮补修）

1. **渲染层 Release 树**：`cmake -S Engine/EngineSystem/src/core/Renderer -B .../out/build/x64-Release`（VS 多配置生成器）→ `cmake --build ... --config Release`。产物 `out/build/x64-Release/{lib/RendererCore.lib, include/, shaders/}`，库 78.8 MB、`MultiThreadedDLL`（/MD），工程 Release 段包含根全部指向 `下层依赖/EngineCore/x64-Release/include`。
2. **EngineSystem `7798162`**：`BYJY_RENDERER_LIB_PATH` 留空时按配置取 `src/core/Renderer/out/build/x64-<Debug|Release>/lib/RendererCore.lib`，并补 `IMPORTED_LOCATION_DEBUG/RELEASE/RELWITHDEBINFO/MINSIZEREL`；渲染层头快照同样按配置取（`$<IF:$<CONFIG:Debug>,…,…>`），缺一份回退另一份并告警，两份都缺才 `FATAL_ERROR`。
3. **Test `22ca754`**：对 `EngineSystem`、`EngineCore`、`RendererCore` 三库都按配置取（列表顺序须与 Engine 对外面 `OUT_LIB` 一致：`EngineSystem;EngineCore`）；三库头快照同样按配置取。
4. **同轮发现的附带缺陷**：VS 多配置生成器会给 `RUNTIME_OUTPUT_DIRECTORY` 追加 `Debug/`、`Release/` 子目录，而用例按「可执行文件目录」解析 `assets/` 与 `shaders/`，Release 产物落到 `Release/` 时 619 例失败（Debug 树此前靠缓存里的 `CMAKE_RUNTIME_OUTPUT_DIRECTORY_DEBUG` 恰好落在根目录，掩盖了该问题）。修法：`RUNTIME_OUTPUT_DIRECTORY` 改为 `"${PROJECT_ROOT_DIR}/$<0:>"`（含生成器表达式即不追加配置子目录），两配置按顺序构建时覆盖同名产物。
5. **验证**：Release 全量 1364 例 / 78 套件 / 0 失败（255.622 s，无 LNK4098）；随后重建 Debug 产物并冒烟（网格 / 资产 / 粒子 60 例通过）。
