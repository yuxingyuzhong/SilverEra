# 执行计划（修订版）· 渲染层职责下沉（三批一次落地）

- 版次：EngineCore `294f549` / EngineSystem `55cad65` / Renderer `28d045b` / Test `1e3c38e`
- 目标：最大化渲染层纯粹性——渲染层只保留「纯数据消费 ＋ 资源门面 ＋ 绘制登记 ＋ GPU 执行机制」。
- 与首版计划的差异（重定）：
  1. 首版「轮 2 双链对照」无法成立：`渲染器.h` 直接包含渲染层 `Level/关卡文件.h`，`engine::Level_Data` 由渲染层公共头拥有，与 EngineSystem 同名类型无法共存于同一翻译单元。故改为「先删后用」：一次性删除渲染层对应门面与实现，再迁用例；行为等价以迁移后 84 例关卡断言原样通过作为证据。
  2. 粒子数据类型（`Particle_State / Emitter / Params / Force_Field`）必须同时被渲染层（GPU 上传/绘制）与引擎层（模拟）引用，唯一可行落点是 **EngineCore**（两层的共同祖先）；`Particle_System` 与校验函数随类型同置 EngineCore（模拟语义完全离开渲染层）。
  3. 渲染层粒子门面改为「绑定应用层状态数组」：`particle_source_bind`；CPU 模拟门面删除，GPU 常驻推进保留为 GPU 执行机制。

## 四、风险与处置

1. 类型共存（见重定第 1 条）：先删后用，避免 ODR 冲突。
2. 粒子 GPU 推进需 CPU 镜像可写：`particle_source_bind` 的 `alive` 采用可变指针；GPU 回读只置活跃标记，空闲栈记账归应用层。
3. 静态宿主跨渲染器：`Particle_Host` 析构不解绑，展示层按渲染器实例重建宿主。
4. 用例统计口径：CPU 模拟的出生/死亡不再由渲染层内部累加，改由 `particle_stats_add` 上报，保持帧统计语义。
