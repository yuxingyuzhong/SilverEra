# 执行计划 · 渲染层职责下沉（第一批：Level ＋ 场景清单 ＋ 装配）

- 决策（用户拍板）：落点 **EngineSystem**；形态 **A 纯逻辑下沉**（Renderer 删除对应 API，应用层桥接）；节奏 **分三批**。
- 层方向：`EngineCore → EngineSystem → Renderer → 应用层`；Renderer 不依赖 EngineSystem，故被下沉的代码**不得**引用 Renderer 类型。
- `Camera_Data / Light_Data / Fog_Data / Scene_Data ＋ scene_apply` **留在渲染层**（只作为纯数据消费接口）；EngineSystem 关卡数据自带中立字段，应用层做映射。

## 一、第一批范围

1. Renderer `Level/` 整模块（`关卡文件.h` ＋ `core/关卡文本.cpp`，4 文件 / 1655 行）迁到 EngineSystem；
2. 场景清单解析与装配（`Asset/` 的 `scene_manifest_parse(_lines)` / `Scene_Manifest` / `Scene_Place` / `asset_scene_build`）；
3. Renderer 门面 `level_save / level_load / level_unload / scene_load / scene_unload / scene_draw` 删除；
4. `Level_Data / Level_Material / Asset_Object / Scene_Place / Asset_Scene` 类型随模块走；
5. 关卡材质实例 CRUD（find / update / add / remove）与全部关卡语法行解析随迁；
6. `Level_Test`（84 例）整体迁到 EngineSystem 侧测试套件。

## 二、EngineSystem 新模块布局

```
Engine/EngineSystem/src/scene/
├── Level/
│   ├── 关卡数据.h            # Level_Camera / Level_Light / Level_Fog / Level_Material / Level_Data
│   ├── 关卡文本.h            # read / write / 材质 CRUD / transform_build
│   └── core/关卡文本.cpp
├── Manifest/
│   ├── 场景清单.h            # Scene_Manifest / Scene_Place / 解析（mesh / mtl / place）
│   └── core/场景清单解析.cpp
└── 装配.h                     # Scene_Asset_Plan / 装配计划（句柄由调用方注入，不建 GPU 资源）
```

要点：
- `关卡数据.h` 的相机 / 光照 / 雾字段**逐字段对齐**渲染层 `Camera_Data / Light_Data / Fog_Data`（默认值一致），
  应用层只做逐字段拷贝，**不做语义换算**，保证往返与既有用例数值一致；
- 装配只产出「计划」（网格路径、材质路径、摆放变换矩阵、实例覆盖参数），
  实际 `mesh_load_obj` / `material_load_mtl` / `mesh_draw_sections` 由应用层调渲染层完成；
- `level_transform_build`（T·R·S）下沉后可被应用层直接用来填 `mesh_draw_sections` 的 transform。

## 三、API 破坏清单（渲染层删除）

| 删除项 | 替代 |
| --- | --- |
| `level_text_read / level_text_write` | EngineSystem `关卡文本.h` |
| `level_material_find / _update / _add / _remove` | EngineSystem 同名函数 |
| `level_transform_build` | EngineSystem 同名函数 |
| `level_save / level_load / level_unload` | 应用层：EngineSystem 读文本 → 建资源 → 填 `Camera_Data/Light_Data/Fog_Data` → `scene_apply` |
| `scene_manifest_parse / _parse_lines` | EngineSystem `场景清单.h` |
| `scene_load / scene_unload` | 应用层装配桥（缓存 ＋ 建资源 ＋ 摆放表） |
| `scene_draw` | 应用层按摆放表逐项 `mesh_draw_sections(transform, materials, instances)` |
| `apply_scene` 开关 | 随 `level_load` 一起消失（拆分后无双重职责） |
| `Asset_Async_Task / *_shared / *_release / asset_cache_count` | 第二批之后处理（第三批：资源缓存与异步） |

保留（渲染层）：`mesh_load_obj`、`material_load_mtl`、`texture_*`、`scene_apply`、`mesh_draw*`、OBJ/MTL 解析器（格式 → `Mesh_Data` / `Material_Data`）。

## 四、分轮推进（第一批内部）

| 轮 | 内容 | 验收 |
| --- | --- | --- |
| 1 | EngineSystem 新增 `scene/Level`（中立数据 ＋ 文本读写 ＋ CRUD ＋ transform） | EngineSystem 构建通过；新增 EngineSystem 关卡用例（往返 / 非法 / CRUD，数值与旧实现一致） |
| 2 | 应用层关卡桥（Test 侧 `关卡装配桥`）；Renderer 保留旧 API 作对照 | 同一关卡经新链路与旧链路出帧逐字节一致（端到端 1764 像素量级用例） |
| 3 | 删除 Renderer `Level/` 与 `level_*` 门面；`Level_Test` 迁至 EngineSystem 套件 | 全量回归通过（用例数 = 1351 − 84 ＋ 迁移后用例数） |
| 4 | `Manifest` 迁出 ＋ `scene_load/unload/draw` 删除；应用层装配桥接管 | 清单 / 装配 / 展区㉔ 用例改造后全绿；展示层关卡区改走新链路 |

## 五、风险与口径

1. **光照字段映射**：`Light_Data` 有 8 盏点光 / 8 盏聚光 × 多属性，映射表须逐字段对齐并加静态断言（`static_assert(sizeof)` 不可行，改单测逐字段比对默认值）。
2. **关卡往返逐位一致**：沿用 `%.9g` 写出；中立字段与渲染层默认值必须完全一致，否则迁移用例的逐位比较会失败。
3. **测试重建成本**：84 例中大量断言依赖 `level_load` 端到端出帧，迁移后需在新桥接层重写这一段。
4. **回滚边界**：每轮独立可构建、可回滚；第 3 轮删除 Renderer API 前，旧实现必须仍可编译。
