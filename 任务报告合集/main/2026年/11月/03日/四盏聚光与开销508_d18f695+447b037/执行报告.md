## 一、四盏聚光用例

`关卡四盏聚光阴影`：4 盏聚光（x = −6 / −2 / 2 / 6）各照一块地面与遮挡体，共 8 个绘制项。

## 二、开销基线（阴影 pass 单遍 GPU 耗时）

`关卡多盏聚光开销`：同一场景分别登记 1 / 2 / 4 盏，全部投影，预热 6 帧后读 `gpu_shadow_ms`。

| 盏数 | 单遍阴影耗时 |
| --- | --- |
| 1 | **0.0252 ms** |
| 2 | **0.0244 ms** |
| 4 | **0.0231 ms** |

结论：`gpu_shadow_ms` 记录的是**最后一次聚光提交的单遍耗时**，三者基本恒定（≈ 0.023–0.025 ms，噪声内），
说明单遍成本与盏数无关；**总成本随遍数线性增长**（4 盏 ≈ 4 × 0.023 ≈ 0.09 ms，仅阴影 pass，未含主 pass 采样）。

## 三、重复 BOM 清理

构建 Test 时 `展区_*.cpp` / `能力展示场景.cpp` / `资源构建.cpp` 等报 `C4430`：这些文件开头有 **4 个 BOM**（`EF BB BF` ×4），
MSVC 把第二个 BOM 当成非法记号。已清除重复 BOM（保留 UTF-8 无 BOM 口径），共 **9 份**：

| 仓库 | 文件 |
| --- | --- |
| Test | `展区_光照几何.cpp`、`展区_后处理.cpp`、`展区_基础网格材质.cpp`、`展区_粒子文字.cpp`、`展区_系统.cpp`、`展区_纹理风格.cpp`、`能力展示场景.cpp`、`资源构建.cpp` |
| Renderer | `渲染器.h` |

> 影响：仅字节层面的 BOM 变化，源码语义无关；清除后两仓可正常全量重编。
