## 一、交付内容

1. `Particle_Params`（`粒子数据.h`）末尾新增：
   `float color_start[3];` / `float color_end[3];` / `uint32_t color_enabled;`（结构由 372 B → 400 B；不参与 GPU 缓冲布局，仅 CPU 侧与推送块）。
2. `particle_params_valid`（`粒子数据.cpp`）：`color_enabled != 0` 时两端颜色各通道须落在 [0,1]（复用 `unit_interval`，含非有限拒绝）；未启用时不校验。
3. 推送块口径（三条路径一致）：`offset 64` = 新生色 rgb、`offset 80` = 衰老色 rgb、`offset 96.x` = 启用标志 0/1。
   - 门面新增私有接口 `Renderer::particle_color_push_fill(std::array<float, 32>&)`（`渲染器.h` 声明、`渲染器.cpp` 定义于 `particle_draw` 之前）。
   - CPU 参考路径：实例化登记前记录 `pending_items` / `pending_push_constants` 计数，登记后仅在「确实新增绘制项」时改写 `back()` 块（整批被视锥剔除时不误改他项）；分桶模式每桶各写一次。
   - GPU 直接（`particle_gpu_draw`）与 GPU 间接（`particle_indirect_draw`）在写入相机位置 / 尺寸后直接调用同一填充函数。
4. `粒子.frag`：新增 `layout(offset = 64/80/96)` 推送块 `Push_Particle_Color`；`particle_color_flags.x > 0.5` 时 `mix(color_start, color_end, age)`，否则维持第三百一十五轮内置暖白 → 暗红曲线。
   - 未启用时标志恒写 0，故 CPU 路径占位块里的 `material_alpha_cutoff` / UV 变换不会再被误当作启用标志。
