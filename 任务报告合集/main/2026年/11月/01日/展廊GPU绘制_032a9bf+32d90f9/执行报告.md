## 一、交付内容

1. **展廊第九区改走 GPU 绘制**：`能力展示场景::frame_draw` 在 `particle_enable_get()` 为真时，
   优先按 `particle_resident_get()` 分支——常驻 → `particle_gpu_draw(0.16f)`（紧凑索引 ＋ `粒子GPU.vert` 着色器内 billboard，
   主机不回读状态缓冲）；非常驻 → 原 `particle_draw(0.16f)` CPU 参考路径。
2. **预配置注释同步**：init 处说明补「常驻路径优先走 GPU 绘制（第三百四十三轮）」。
3. **用例** `展廊粒子GPU绘制接入`：场景 init（容量 4096）→ 开粒子 ＋ 切常驻 → 三轮 `particle_gpu_emit(64)` ＋ 常驻推进（活跃 192）→
   `frame_draw` 后 `particle_compact_count_get()` = 192（仅 GPU 绘制路径会产生紧凑，作为路径判别）→ `frame_render` 绘制项非零；
   关闭常驻后紧凑口径归 0（回落 CPU 路径）。

## 二、设计取舍

- 分支依据取门面状态 `particle_resident_get()`（而非场景私有 `粒子常驻_`），
  使「直接对渲染器开常驻」的调用方（含用例）也能命中 GPU 绘制路径。
- 未改动 `粒子GPU.vert` / 间接绘制；间接路径（`particle_indirect_draw`）保留供大容量场景按需接入（展廊当前 4096 容量用直接 GPU 绘制即可）。
