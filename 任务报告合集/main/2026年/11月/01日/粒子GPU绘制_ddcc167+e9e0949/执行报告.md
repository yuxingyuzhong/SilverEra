## 一、交付内容

1. **管线**：新增粒子专用 set0 描述符集（`particle_sets`，按帧槽独立分配；池扩为 UBO ×2、STORAGE ×8、maxSets ＋1 每槽），
   API `particle_set_get(slot)` / `particle_buffers_bind(slot, ubo, state, index)`（binding 0 UBO、1 状态、2 紧凑索引、3/4 占位）。
2. **帧模块**：`Frame_Render_Item` 增 `instance_input`（默认真）与 `particle_scene_set`（默认假）；
   `instance_input = 假` 时录制只绑定 binding 0、允许实例缓冲为空；间接合并与静态合批跳过此类项；
   帧渲染阶段按 `particle_scene_set` 选粒子集、按 `instance_input` 决定是否填实例缓冲。
3. **着色器** `粒子GPU.vert`：`gl_InstanceIndex → 紧凑索引 → 粒子状态`，着色器内构造 billboard（右 / 上基向量、年龄收缩 35%），
   相机位置与尺寸经推送常量（offset 0 的 `vec4`）下发；输出与 `粒子.frag` 兼容。
4. **门面** `particle_gpu_draw(float size)`：紧凑 → 逐帧槽刷新粒子集（front 随推进交换）→ 登记 1 个「无实例属性 ＋ 粒子集」绘制项。
5. **修正 set0 存储绑定的阶段可见性**：`描述符布局.cpp` 中 binding 1..4 由「仅片元」改为「顶点 ＋ 片元」。
6. 用例 `粒子GPU绘制`：未开常驻拒绝；常驻发射 256 → 五步推进 → GPU 绘制出帧，`drawn_instances = 256` 且有可见像素。

## 二、根因定位（本轮主要排障）

初版用例出帧全零（`drawn_items = 1`、`drawn_instances = 256` 但 `visible = 0`）。逐步探针：
固定几何 → 可见 148；推送常量探针 → 可见 152；索引缓冲探针 → 可见 12；
`states[0]` 探针 → 可见 14（近似「原点单个四边形」面积）。
据此判定：顶点阶段读取 binding 1 / 2 **恒为 0**，而缓冲内容经主机回读确认有效（紧凑索引 128,129,130,131…共 256 项）。
最终定位到 `场景` set0 布局的 binding 1..4 `stageFlags` 仅含 `FRAGMENT`；改为 `VERTEX | FRAGMENT` 后用例通过（可见 39 px）。
