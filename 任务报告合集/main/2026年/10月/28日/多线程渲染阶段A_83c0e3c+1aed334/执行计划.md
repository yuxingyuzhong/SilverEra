## 一、现状与约束

1. 逐帧 CPU 热点集中在两处：`mesh_draw_instanced` 的逐实例包围盒判可见、`frame_render` 的实例缓冲差异扫描（逐实例 20 浮点比较）。两者都不触碰 Vulkan，可在任意线程执行。
2. 分派必须满足「结果与单线程逐字节一致」：并行只写各自的槽位，压缩 / 连续段扫描仍单线程按原顺序执行。
3. 实例上限原为固定 256，达不到任何有意义的并行粒度，故同时把容量数据化（`Renderer_Config::instance_capacity`，默认 256 不变）。
4. 本层无既有线程基础设施（EngineCore 内亦无线程池），故新增独立 Thread 模块。

## 三、分段执行

1. 线程池：持久工作线程 ＋ 每轮任务代号 ＋ 原子块领取 ＋ 调用线程参与执行 ＋ 收尾等待。
2. 渲染器接入：`instance_capacity` 归一（[16, 1048576]）→ 掩码缓冲预留 → 线程池启动（失败回落 0）。
3. 两处热点改为「掩码并行判定 + 单线程按原序处理」。
4. 用例：1000 实例下比较线程 0 与 4 的剔除数 / 绘制实例数 / 像素；容量钳制与大批量登记。
5. 三树构建 → 全量回归 → 收口文档。

## 四、风险与口径

- 同步语义：`ranges_run` 为阻塞调用，返回即全部块完成；故不存在跨帧任务残留，`shutdown` 停线程安全。
- 块之间有共享写入即失去确定性，因此两处实现都只写「自己的掩码槽」，压缩与连续段判定保持单线程。
- 线程创建失败（`std::thread` 构造抛 `std::system_error`）仅告警并回落单线程，不影响正确性。
- 默认 `render_threads = 0`：`ranges_run` 退化为调用线程整段执行，与引入并行前逐字节一致。
