# 执行计划 · 描边色可配（第一百八十一轮）

- 代码版次：Renderer `5767018 → 5d7dd40`；Test `f3ed1f4 → 8a49af6`
- 日期：2026-10-28
- 目标：让二次元风格化的深度描边不再固定「压暗到黑」，而可按级配置描边色（如白描边、彩色描边）。

## 一、现状与约束

1. `深度描边.frag` 现按 `source.rgb × (1 − edge × strength)` 压暗轮廓，描边色恒为黑。
2. 后处理各级的推送常量只覆盖 offset 80..111（源 / 宿尺寸 ＋ 泛光参数），`post_params` 4 分量已全部占用，无法再塞 RGB。
3. 管线布局的推送常量范围为 **112 字节**，需要扩到 128 才能容纳新 vec4。
4. 扩张后必须保证默认值（黑）下画面与旧版**逐字节一致** —— 用 `mix(source, black, w)` 代替乘法可严格等价。

## 三、分段执行

1. 推送范围与帧侧字段：128 字节、`post_color`、12 浮点推送块。
2. 门面逐级描边色：设置 / 清除 / 写入绘制项；合批等价判据补色比较。
3. 着色器：`mix` 语义（默认黑与旧版逐字节等价）。
4. 用例：红描边使一批轮廓像素「外通道」抬升 ≥ 20。
5. 三树构建（Test 重配以刷新 `.spv`）→ 全量回归 → 收口文档。

## 四、风险与口径

- 推送常量范围扩大不影响既有场景 / 文字管线（它们只推 112 字节以内的块）。
- `mix` 与乘法在 color = 0 时严格等价：`mix(a, 0, t) = a × (1 − t)`，故默认路径逐字节不变。
- 用例只断言「外通道抬升像素数」，不依赖回读通道序。
