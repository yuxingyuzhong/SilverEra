# 执行计划 · 帧内缓冲复用（优化；第一百八十二轮）

- 代码版次：Renderer `5d7dd40 → eeed7d3`；Test 无变更（仍 `8a49af6`）
- 日期：2026-10-28
- 目标：消除 `frame_render` 内两处逐帧 `std::vector` 堆分配（阴影列表、后处理绘制项），行为与画面完全不变。

## 一、现状与约束

1. 阴影 pass 每帧在函数内新建 `std::vector<Frame_Render_Item> shadow_items` 并 `reserve(shadow_item_count)`，帧末析构释放。
2. 后处理链路径（含 SSAA 两级路径）同样每帧新建 `post_items` 并逐级 `push_back`。
3. 两处向量的生命周期都在单帧内（`render_to_target` / `render_chain_present` 均为同步调用），可安全改为 `Impl` 成员复用。
4. 复用缓冲每帧先 `clear()` 再 `push_back`；`reserve` 保留，避免再次扩容。

## 二、拟修改文件（相对项目根）

| 文件 | 计划改动 |
| --- | --- |
| `Application/Renderer/src/render/Renderer/core/渲染器实现.h` | 新增 `shadow_items_scratch` / `post_items_scratch` 两个复用缓冲 |
| `Application/Renderer/src/render/Renderer/core/渲染器.cpp` | 初始化预留容量；阴影 pass 与两条后处理路径改用复用缓冲 |

## 三、分段执行

1. 新增成员并注释复用前提（同步调用、单帧内使用）。
2. 三处 `std::vector` → 成员引用 ＋ `clear()`。
3. 三树构建 → 全量回归（行为等价，只验回归）。

## 四、风险与口径

- `batch_adjacent_items(shadow_items, batch_scratch)` 会交换两个向量内容；复用后 `shadow_items` 在帧末持有合并结果，下一帧 `clear()` 后重新填充，语义不变。
- SSAA 路径与链路径互斥，可共用同一 `post_items_scratch`。
- 该优化不改变任何绘制顺序、合批结果或统计口径，验收只看全量回归。
