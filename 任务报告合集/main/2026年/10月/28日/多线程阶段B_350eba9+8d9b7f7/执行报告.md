## 一、实现（相对项目根）
1. `Frame_Slot` 增 `std::vector<VkCommandBuffer> secondary_buffers`；`secondary_buffers_ensure` 经该帧槽命令池
   按 SECONDARY 级别追加分配（不足才分配，失败整次返回假）；帧槽销毁时清空数组（命令池销毁连带回收）。
2. `Frame_Context::thread_pool_set(Thread_Pool*)`：门面 init 在启动线程池后传入；空 / 0 线程即单线程。
3. `render_chain_present` 录制前判定：
   - 线程池已启动且 `thread_count > 1`、`item_count ≥ 32`、`active()`；
   - 段数 = `min(线程数, 8, item_count / 16)`，需 ≥ 2 且次级缓冲分配成功；
   - 填充 `active_secondary / active_secondary_count / active_color_format / active_depth_format / active_sample_count`，
     `parallel_counts.assign(段数, {})`；录制后清空。
4. `command_record_chain_present` 场景 pass：
   - 并行分支：`thread_pool->ranges_run(段数, 1, ...)`，每段完整录制一个渲染实例
     （首段 CLEAR、其余 LOAD；`resolveMode = NONE` 除末段；viewport / scissor 每段重设；`items_record` 只写本段统计槽）；
   - 主缓冲逐段 `vkCmdExecuteCommands`；统计汇总到 `frame_recorded`；
   - 单线程分支保留原逻辑（含 `frame_recorded` 清零）。
5. 次级缓冲 begin 时挂 `VkCommandBufferInheritanceRenderingInfo`（颜色格式 = 交换链格式、深度格式 = 交换链深度格式、采样数 = 场景目标采样数）。

## 二、验证
- 新用例 `Renderer_Thread_Test.并行录制场景通道与单线程一致`：
  - 64 个独立绘制项（**关闭静态合批**，否则会被并成 1 项）、单级「后处理」链、64×36 隐藏窗口；
  - 单线程 vs 四线程：`last_draw_items` / `last_instances` 一致、像素最大通道差 ≤ 2、四线程 `parallel_dispatches > 0`；
- 多线程夹具 6/6；全量 1046 例中 1043 通过（3 项并行会话在建用例，与前几轮完全一致）；
- 校验层运行期间无 VUID 输出（若被日志屏蔽，至少无失败 / 崩溃）。

## 三、回退口径
- `Renderer_Config::render_threads = 0`（默认）或线程池无工作线程 → `active_secondary_count = 0` → 原单线程录制，逐字节不变；
- 绘制项 < 32 或段数 < 2 同样回退。

## 四、重开发指引
1. 次级缓冲必须**每帧槽**持有（命令池按帧槽重置）；
2. 段内统计写入 `parallel_counts[段号]`（各元素独立写，线程安全）；`frame_recorded` 只由调用线程汇总；
3. 解析只能在末段；中间段必须显式把 `resolveMode / resolveImageView` 置空；
4. 该路径（`render_chain_present`）无 UI 回调，故无需考虑 UI 分段。
