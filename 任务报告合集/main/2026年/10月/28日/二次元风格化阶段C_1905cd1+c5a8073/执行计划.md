# 执行计划 · 二次元风格化阶段 C：暗部色调化（第一百七十八轮）

- 代码版次：Renderer `83c0e3c → 1905cd1`；Test `1aed334 → c5a8073`
- 日期：2026-10-28
- 目标：让卡通阴影的暗部带上统一色调（常见做法如偏蓝 / 偏紫的阴影），继续由数据字段驱动，默认关闭。

## 一、现状与约束

1. 阶段 A 已交付色阶量化（`toon_steps`）与菲涅尔边缘光（`toon_rim`），分别占用 `pbr_params.w` 与 `sky_params.w`。
2. 场景 UBO 剩余保留分量只有 `camera_range.zw`（266 / 267）与 `cascade_params2.w`（291），合计 3 个浮点 —— 恰好容纳一个 RGB 色调。
3. 量化后无光照面常常已是纯黑（乘任何色调仍为黑），故色调需作用在**含环境光基底**的合成结果上，且只在「主方向光量化受光系数 < 0.5」处生效。

## 三、分段执行

1. 数据与门面：字段 ＋ setter（逐分量钳 [0,1]，非有限值按 1）＋ getter。
2. UBO：三个保留分量拼接 RGB；默认值 (1,1,1) 保持既有画面逐字节不变。
3. 着色器：主方向光处记录 `toon_primary_shade`；合成 `lit` 后按 `1 − smoothstep(0, 0.5, shade)` 混入色调。
4. 用例：受光面不受影响（差 ≤ 2）、暗部整体压暗（≤ 70% 基准）、钳制与两条数据路径。
5. 三树构建 → 全量回归 → 收口文档。

## 四、风险与口径

- 色调作用在合成前的 `lit`（含环境光），而非仅方向光项 —— 否则环境光下的暗部无法被染色。
- 未提供法线 / 方向光关闭时 `toon_primary_shade` 保持 1，等价于不染色（既有「无法线网格」画面不变）。
- 回读为 sRGB 编码值，线性乘 0.25 在像素上约折半，故断言按「≤ 70% 基准」而非「≤ 50%」。
