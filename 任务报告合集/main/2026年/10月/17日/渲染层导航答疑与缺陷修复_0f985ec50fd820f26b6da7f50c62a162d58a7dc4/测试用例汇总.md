## 二、上轮计划用例（渲染层 Phase 2~9）

### 2.1 分级口径（承设计文档 §8.1）

| 级别 | 形态 | 可验证内容 | 是否弹窗 | 默认是否跑 |
| --- | --- | --- | --- | --- |
| **L1 无窗口** | 只测实例 / 物理设备枚举 / 逻辑设备创建与销毁 | 设备链路、校验层接线、失败回退 | 否 | 是 |
| **L2 隐藏窗口** | `Renderer_Config::hidden = true`（真实窗口 + 真实表面，不显示） | 交换链创建 / 重建、帧槽、命令录制、`frame_render` 全链路、网格与纹理 | 否 | 是 |
| **L3 可见窗口** | `hidden = false` | 真实呈现（肉眼：清屏色 / 三角形 / 立方体 / 纹理） | 是 | 否（须能被 GTest 过滤单独选择） |

### 2.2 逐 Phase 验收判据 → 用例映射

| 用例编号 | 级别 | 目标（Phase / 验收判据原文） | 关键断言 | 依赖接口 |
| --- | --- | --- | --- | --- |
| L1-01 实例创建 / 销毁 | L1 | Phase 2：无窗口创建 / 销毁实例与设备 | `Renderer` 构造→`init`（`hidden=true`）→`valid()==true`→`shutdown()` 后校验层无报错 | `Renderer::init/shutdown/valid` |
| L1-02 物理设备枚举 / 逻辑设备创建 | L1 | Phase 2：设备链路 | 校验层消息不含实例 / 设备创建失败 | 同上（内部链路） |
| L1-03 非法参数 `init` 返回假 | L1 | Phase 2：非法参数 `init` 返回 `false` 且无泄漏 | `width=0` / `height=0` / `frame_overlap=0` / `frame_overlap=4` 各返回 `false`，且 `valid()==false`；校验层无资源泄漏报错 | `Renderer::init` |
| L1-04 `init` 失败即无痕 | L1 | 设计 §5.1「失败即无痕」 | 故意让某一步失败（如非法 `width`）后，对象处于「`valid()==false` 且无半初始化资源」状态 | `Renderer::init/valid` |
| L2-01 表面创建 / 销毁 | L2 | Phase 4：隐藏窗口能创建表面并正常销毁 | `init`（`hidden=true`）成功，`shutdown` 后校验层无「surface destroyed after instance」类报错 | `Renderer::init/shutdown` |
| L2-02 交换链创建 / 重建 | L2 | Phase 5：交换链创建与重建 | 持续 `frame_render` 期间触发 resize（改窗口尺寸）→ 交换链重建成功、无校验层报错 | `Renderer::frame_render`、`extent_width/height` |
| L2-03 连续 60 帧 | L2 | Phase 5：隐藏窗口下 `frame_render` 连续 60 帧不报错；`frame_count()` 与调用次数一致 | 循环 60 次 `frame_render`，每次返回真；`frame_count()` 单调递增且等于成功调用次数 | `Renderer::frame_render/frame_count` |
| L2-04 最小化挂起 | L2 | Phase 5 / K7：`0×0` 交换链须挂起不重建 | 置窗口最小化后 `frame_render` 返回真且不重建、无报错；恢复后正常 | `Renderer::frame_render` |
| L2-05 缓冲写入 / 读回 | L2 | Phase 3：创建 / 写入 / 读回一块缓冲，读回值与写入值一致 | 主机可见缓冲写入已知序列，读回逐字节比对一致 | `Memory_Context::buffer_create/buffer_write/buffer_read`（经 Test 可用公共面间接验证） |
| L2-06 网格上传 / 绘制 | L2 | Phase 7：网格提交接口 | `mesh_load(triangle/cube)` 返回真、句柄有效；`mesh_draw` 后 `frame_render` 无报错 | `Renderer::mesh_load/mesh_unload/mesh_draw` |
| L2-07 纹理与采样 | L2 | Phase 9：纹理正确采样 | `texture_load(RGBA8)` / `texture_load_checkerboard` 返回真；`texture_bind_set` 后 `frame_render` 无报错 | `Renderer::texture_load/texture_load_checkerboard/texture_bind_set` |
| L2-08 相机参数 | L2 | Phase 8：投影正确（K1 不踩） | 设 `camera_position/target/fov/near_far` 后 `frame_render` 无报错；矩阵 Z ∈ [0,1] 语义正确（可用渲染结果旁证） | `Renderer::camera_position_set/camera_target_set/camera_fov_set/camera_near_far_set` |
| L3-01 可见窗口纯色 | L3 | Phase 6：可见窗口能稳定呈现纯色 | 肉眼确认清屏色稳定，无闪烁 / 黑屏 | `Renderer::init`（`hidden=false`） |

## 三、本轮计划用例（渲染层导航答疑与缺陷修复 · 15 项修复的回归用例）

本轮 15 项修复（见本轮《执行计划》第三节）中，除纯注释 / 编译期断言项外，均应有对应回归用例：

| 用例编号 | 对应修复 | 级别 | 目标接口 / 落点 | 关键断言 |
| --- | --- | --- | --- | --- |
| R-01 | R-PLAT-06（销毁顺序：先平台后设备） | L1 | `Renderer::init` → `shutdown` | `init` 成功（`hidden=true`）后 `shutdown`，校验层**不得**出现「`vkDestroySurfaceKHR` 在实例销毁之后」类报错；重复 `shutdown` 幂等无副作用 |
| R-02 | R-PLAT-03（补 `SDL_EVENT_WINDOW_PIXEL_SIZE_CHANGED`） | L2 | 事件泵 → 交换链重建 | 制造「像素尺寸变化但客户区尺寸不变」的 HiDPI 场景（或直接投递该事件），断言下一帧触发交换链重建、`extent` 更新 |
| R-03a | R-PIPE-02（格式未变时空操作） | L2 | `Pipeline_Context::pipeline_rebuild` | 以「当前相同格式」调用，返回真且**不重建**（不新增 `vkDeviceWaitIdle` 开销） |
| R-03b | R-PIPE-02（格式变化时重建） | L2 | `Pipeline_Context::pipeline_rebuild` + 门面重建路径 | 构造交换链格式变化（如 vsync 切换导致呈现模式 / 格式变化）→ 断言管线按新格式重建成功、后续 `frame_render` 无校验层「附件格式不匹配」报错 |
| R-04 | R-PIPE-03（顶点布局静态断言） | 编译期 | `Pipeline/core/图形管线.cpp` | `sizeof(Vertex)==20`、`offsetof(Vertex,position)==0`、`offsetof(Vertex,uv)==12` 三条 `static_assert` 通过即**双树构建成功**，无需运行用例 |
| R-05 | R-FRAME-02（合并 `frame_serial` 入 `frame_count`） | L2 | `Frame_Context` 槽号 / 释放判据 | 连续 60 帧内，帧槽号恒为 `frame_count % frame_overlap`，延迟销毁释放判据与槽号同源；`frame_count()` 单调递增 |
| R-06 | R-FRAME-05（`frame_overlap` 钳制到 ≤ 图像可用信号量数） | L2 | `Renderer::init` | 构造「图像可用信号量数 < `frame_overlap`」的场景（可临时抬高 `frame_overlap`），断言门面把 `frame_overlap` 下调并告警；下调后连续多帧无 K13 死锁 / 校验层「信号量仍在使用」报错 |
| R-07 | R-MEM-01（上传暂存改 `SEQUENTIAL_WRITE`） | L2 | `Memory/core/上传批次.cpp` 经 `upload_buffer` / `upload_image` | 上传一段已知数据到设备缓冲 / 图像后读回（或经绘制旁证）内容正确；断言不再走 `HOST_ACCESS_RANDOM` |
| R-08 | R-SHADER-01（`gcount()` 短读校验） | L1 | `Shader_Context::file_bytes_read` / `module_load` | 提供**被截断**的 `.spv`（声明长度 > 实际字节），断言 `module_load` 返回假并记录错误，不产生半初始化模块 |
| R-09 | R-SHADER-02（SPIR-V 魔数 + 4 字节倍数） | L1 | `Shader_Context::module_load` | ① 长度非 4 倍数 → 返回假；② 首 4 字节魔数 ≠ `0x07230203` → 返回假；各记一条错误日志 |
| R-10 | R-TEX-03（注释修正，行为不变） | L2 | `Texture_Context::destroy` | 创建 N 条独立纹理后 `destroy`，断言全部归还、无残留；顺序无关（正 / 逆序等价） |
| R-11 | R-TEX-04（模块共享单一采样器） | L2 | `Texture_Context` 采样器 | 创建 N 条纹理，断言各 `Texture_Record.sampler` 句柄**一致**（共享）；`destroy` 后共享采样器被归还且无泄漏 |
| R-12 | R-SCENE-05（`orbit` 内 up 轴归一化） | L1 | `Camera::orbit` | 传入**非单位** up（如 `(0,2,0)`）与单位 up（`(0,1,0)`）分别 `orbit(θ)`，断言两次结果一致；传入零长度 up 不除零、退化为默认上方向 |
| R-13 | R-FACADE-03（同帧多网格） | L2 + L3 | `Renderer::mesh_draw` | L2：同一帧内 `mesh_draw` × 2 后 `frame_render` 无报错、两网格均被消费；L3：肉眼可见两个各自带独立模型矩阵的物体 |
| R-14 | R-FACADE-04（删 `current_texture`、补 `texture_unload`） | L2 | `Renderer::texture_unload` | `texture_load` → `texture_unload` 后，再次 `texture_bind_set(该句柄)` 的绘制回落默认白纹理 / 或断言句柄失效；`texture_unload` 幂等 |
| R-15 | R-DEV-02 / R-PIPE-01 / R-FRAME-01 / R-FACADE-02（私有包含根） | 编译期（负向） | `cmake/对外接口.cmake`、`CMakeLists.txt` PRIVATE 段 | 从 `Application/Test` 侧 `#include "Application/Renderer/src/render/Pipeline/管线.h"` **应当编译失败**（层外不可见 Vulkan 类型）；属负向编译测试，可作为可选项 |

> 说明：R-15 属「构建系统与层间契约」的隔离验证，若不便做负向编译测试，可由「Test 层编译通过且不含任何 Vulkan 类型」间接旁证。

## 四、运行口径与环境前提（务必遵守）

1. **运行载体**：`Application/Test` 的 `EngineTests.exe`（全项目唯一可执行文件）。
2. **必须带 gtest 参数**：无参数启动会进入「退出暂停」等待按键；自动化运行须带任意 gtest 参数。
3. **工作目录**：必须是 `Application/Test` 层目录（`Path_Check_Test` 相对路径基准）。
4. **工具不在 PATH**：`cmake` / `ninja` / `ctest` 需用 VS 自带绝对路径（本机 `D:\ViusalStudioCommunity2026\...`）。
5. **L3 过滤**：L3 用例须能被 GTest 过滤标签单独选择，默认运行只跑 L1 + L2，避免默认退出即弹窗。
6. **双树**：用例应能在 `out/build/x64-Debug`（/MDd）与 `out/build/x64-Release`（/MD）两棵树各跑一遍。
7. **环境三坑（构建 / 运行前）**：`TMP`/`TEMP` 指向纯 ASCII 目录（本机 `D:\agent\_byjy_tmp`，否则 `cl /Zi` 报 `D8050`）；`chcp 65001` 须在进入 VS 开发人员环境**之后**执行；`cmake`/`ninja` 用绝对路径。
8. **着色器**：Phase 6 起 Test 输出目录须含 `shaders/`（由 CMake 从渲染层构建树拷贝）；渲染层以 exe 目录锚定着色器路径。
