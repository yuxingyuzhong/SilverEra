## 二、计划用例

### 2.1 P-A 绘制项录制状态缓存

| 用例编号 | 级别 | 目标 | 关键断言 |
| --- | --- | --- | --- |
| REC-01 | L2 | 单网格绘制回归 | `mesh_load` + `mesh_draw` 后连续 60 帧 `frame_render` 为真；校验层无报错（缓存不得影响首项绑定） |
| REC-02 | L2 | **同帧多网格各自模型矩阵**（核心回归点） | 同帧 `mesh_draw` ×2 后 `frame_render` 为真；两网格的 push constants 与顶点 / 索引缓冲仍逐项绑定——缓存跳过的是管线与描述符集，**不得**连带跳过逐项状态 |
| REC-03 | L3（默认跳过） | 同帧多网格目视 | 可见窗口内两物体各按自身模型矩阵呈现（缓存后画面与优化前一致） |
| REC-04 | L2 | 缓存变量不跨帧残留 | 连续多帧（≥60）每帧重新录制；缓存变量为 `command_record` 内局部量，不得跨帧沿用上一帧的绑定态导致错绘 / 漏绑 |

> 等价性判据：绘制结果与优化前**逐像素一致**（L3 目视 + L2 无校验层报错共同旁证）。优化仅减少 GPU 状态切换，不改绘制内容。

### 2.2 P-B 上传命令池复用

| 用例编号 | 级别 | 目标 | 关键断言 |
| --- | --- | --- | --- |
| UPL-01 | L2 | 多次网格上传 | 连续 `mesh_load` 多个网格均成功、句柄有效；校验层无「命令池仍在使用」「栅栏未复位」报错 |
| UPL-02 | L2 | 多次纹理上传 | 连续 `texture_load` / `texture_load_checkerboard` 多次均成功；上传内容正确（绘制旁证 / 读回比对） |
| UPL-03 | L2 | 网格 + 纹理混合多轮上传 | 同一会话内多轮「网格 + 纹理」上传后跑帧，无报错、无资源泄漏（池 / 栅栏跨次复用正确） |
| UPL-04 | L2 | 上传失败后再上传 | 构造一次失败上传（如非法参数）后再次正常上传仍成功（池 / 栅栏状态可自恢复） |
| UPL-05 | L2 | 会话结束归还 | `shutdown` 后校验层无「命令池 / 栅栏未销毁」报错（destroy 归还路径） |

> 语义判据：上传结果字节级不变（暂存 → 目标的拷贝内容与布局转换终态与优化前一致）。

### 2.3 P-E 帧栅栏等待快速路径

| 用例编号 | 级别 | 目标 | 关键断言 |
| --- | --- | --- | --- |
| FEN-01 | L2 | 连续 60 帧推进 | 每次 `frame_render` 为真；`frame_count()` 等于成功帧数（快速路径与阻塞路径混用无死锁） |
| FEN-02 | L2 | 交换链重建后仍正确 | 触发 resize 重建后继续跑帧无报错（重建路径的栅栏等待不走错槽） |
| FEN-03 | L2 | 重复 init / shutdown | 多次会话（≥2）各自跑帧无残留未完成帧；无「fence 未发出即等待」类校验层报错 |
| FEN-04 | L2 | 在途帧数 1 / 2 / 3 | 三种在途帧数下均能连续跑帧（快速路径在单缓冲下最易命中「未就绪」分支） |

> 语义判据：帧推进顺序与结果不变，仅省去已完成栅栏上的阻塞等待调用。

## 三、运行口径（沿用测试层既有约定）

1. 运行载体：`Application/Test` 的 `EngineTests.exe`（全项目唯一可执行文件）。
2. 必须带 gtest 参数（无参数启动会进入退出暂停等待按键）；自动化用 `--gtest_filter=Renderer_*` 或 `--gtest_filter=-*Quadtree*`。
3. 工作目录须为 `Application/Test` 层目录（着色器按可执行文件目录锚定 `shaders/`）。
4. L3 用例由环境变量 `BYJY_RUN_L3=1` 开启，默认跳过（避免无人值守弹窗）。
5. 构建 / 运行前置：`TMP` / `TEMP` 指向纯 ASCII 目录；`chcp 65001` 须在进入 VS 开发人员环境之后；`cmake` / `ninja` 用绝对路径。
