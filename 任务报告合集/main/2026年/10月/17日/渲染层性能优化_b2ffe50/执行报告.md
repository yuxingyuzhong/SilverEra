## 一、优化项与实现

### P-A 绘制项录制状态缓存（`命令录制.cpp`）

- **原状**：渲染项循环对每项都执行 `vkCmdBindPipeline` + `vkCmdBindDescriptorSets`，逐项 4 次状态调用。
- **事实依据**：① 本层只有一条场景管线，全部渲染项 `pipeline` 相同；② 同一帧内所有项的 set0 / set1 是**同一帧槽**的同一组值（门面按 `slot` 统一填装）→ 描述符集绑定也是重复的；③ push constants（各网格模型矩阵）与顶点 / 索引缓冲各网格不同，**必须**逐项绑定。
- **实现**：循环外置缓存变量（已绑定管线 / 管线布局 / 描述符集数量 / 描述符集内容）；管线变化即复位描述符缓存；管线与描述符集仅在与缓存不同时才重绑。
- **效果**：每帧状态调用由 `4N` 降为 `2 + 3N`（1 管线 + 1 描述符集 + N 推送 + N 顶点/索引 + N draw）。
- **接口影响**：无。输出逐像素不变。

### P-B 上传命令池复用（`内存上下文.h` / `上传批次.cpp` / `分配器创建.cpp`）

- **原状**：`upload_buffer` / `upload_image` 每次上传各自创建并销毁一个临时命令池 + 命令缓冲 + 栅栏。
- **实现**：
  - `Memory_Context` 新增常驻成员 `upload_pool` / `upload_fence`，由私有方法 `upload_resources_ensure()` 首次调用时创建（幂等）；
  - `upload_submit_once` 改为复用传入的池与栅栏：`vkResetCommandPool`（连带回收上次命令缓冲）→ 分配 → 录制 → `vkResetFences` → 提交 → `vkWaitForFences`；
  - 两处调用点先 `upload_resources_ensure()` 再提交；
  - `destroy()` 先于分配器销毁归还上传栅栏与命令池。
- **效果**：消除「每资源一次」的命令池 / 栅栏创建与销毁开销。
- **接口影响**：无（`upload_buffer` / `upload_image` 签名与语义不变）。
- **风险控制**：上传发生在 init / 资源加载期，不与 `frame_render` 并发提交（队列串行安全）；`vkResetFences` 对未发出栅栏为无操作，故首次使用亦安全。

### P-E 帧栅栏等待快速路径（`帧上下文.h` / `帧槽创建.cpp` / `提交呈现.cpp`）

- **原状**：`slot_wait` 与 `render` 内部各自 `vkWaitForFences` 阻塞等待同一栅栏。
- **实现**：新增私有方法 `slot_fence_wait(Frame_Slot&)`：先 `vkGetFenceStatus`，`VK_SUCCESS` 直接返回（免阻塞调用），`VK_NOT_READY` 才落 `vkWaitForFences`，其他码按统一出口判错；`slot_wait` 与 `render` 均改走该方法。
- **效果**：多数帧省去一次阻塞等待系统调用。
- **接口影响**：无。
