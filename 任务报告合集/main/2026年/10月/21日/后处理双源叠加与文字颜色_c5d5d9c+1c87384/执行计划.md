## 二、A · 后处理双源叠加

**动机**：第 15 轮的「亮部提取 → 模糊」只能得到**孤立亮部层**；每个后处理级只有 `set 1 binding 0` 一个 `sampler2D`，无法把亮部叠回原画面。

**实现**：
1. `sampler_set_layout` 增 **binding 1**（`COMBINED_IMAGE_SAMPLER`，片元可见）；描述符池 `COMBINED_IMAGE_SAMPLER` 容量 ×2（`maxSets` 不变）。
2. `texture_bind` 同时写 binding 0 与 binding 1（同视图，保证场景采样集无未写描述符）；新增 `post_scene_bind(slot, sampler, view, index)` 只写 binding 1。
3. 门面在组装后处理链时，把**目标组首项**（`targets[0]` 场景目标）视图按同一 index 写入 binding 1 —— 即「双源片元只能读场景目标」。
4. 新增 `assets/shaders/泛光叠加.frag`：`out = clamp(scene.rgb + bloom.rgb, 0, 1)`，binding 0 = 上一级（模糊亮部）、binding 1 = 场景目标。
5. 用例：中灰亮四边形（222 灰纹理）＋ 三级链「亮部提取 → 模糊 → 泛光叠加」：中心被叠加提亮（≥ 245，参考帧约 222）、角落与单级参考帧一致（差值 ≤ 容差，暗部不变）。

## 三、B · 文字颜色

**实现**：
1. 管线布局推送常量范围由 `VERTEX/64` 扩为 `VERTEX|FRAGMENT/80`（前 64 字节仍为矩阵，后 16 字节为 `vec4` 颜色）。
2. `文字.frag` 以 `layout(push_constant) uniform Push { layout(offset = 64) vec4 color; }` 读颜色，字形覆盖率乘该色。
3. `mesh_draw` 增可空 `const float* color`：非空时把「矩阵 ＋ 颜色」写入帧模块的推送常量存储（`std::deque<std::array<float,20>>`，引用稳定）。
4. 门面新增 `text_color_set(const float color[4])`（记录颜色，下一次 `text_draw*` 生效；未设置时白色）。
5. 用例：同文本红 / 绿两帧，字形像素通道比值符合设定色；白色默认与旧帧逐字节一致。

## 五、风险与预案

| 风险 | 预案 |
| --- | --- |
| 给 `sampler_set_layout` 加 binding 1 后，既有采样器集若有未写描述符会触发校验错 | `texture_bind` 同时写 binding 0/1；后处理集由门面写 binding 1；全量跑校验层复核 |
| 推送常量扩到 80 字节影响既有场景 / 后处理管线 | 仅文字管线推送 80 字节，其余保持不推送；`vkCmdPushConstants` 只按 `item.push_constant_size` 推送 |

| 泛光叠加用例依赖中间亮度 | 自建 222 灰纹理（线性 ≈0.7，高于亮部提取阈值 0.6），端点断言（≥245 vs ≤235） |
