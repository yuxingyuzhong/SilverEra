## 二、A · 文字布局能力

**动机**：`text_draw` 只能单行左对齐，调用方无法预知文本占宽（居中 / 右对齐 / 换行都得自己算），这是对外最常被用的能力缺口。

**实现**：
1. 新增 Vulkan-free 语义头 `Application/Renderer/src/render/Text/文字布局数据.h`：
   - `enum class Text_Align { Left, Center, Right };`
   - `struct Text_Layout { float max_width = 0.0f; float line_height = 0.0f; Text_Align align = Text_Align::Left; };`
   - 口径：`max_width == 0` 不换行（此时 align 无效果，单行以原点为锚）；`line_height == 0` 取字体像素高度；换行**逐字符**按字形 `advance` 累加判定（不识别单词边界）；支持 `'\n'` 显式换行；单个字形超过 `max_width` 时独占一行。
2. `Font_Context`（`Text/字体.h`）新增：
   - `static bool text_measure(const Font_Record&, const std::string&, uint32_t& width_out, uint32_t& height_out)` —— 单行宽度（按 advance 累加取整，**不含尾随空白**）与高度（= `pixel_height`）；无可见字形时两出参 0 并返回假。
   - `static bool text_layout_build(Mesh_Data&, const Font_Record&, const std::string&, const Text_Layout&)` —— 按布局生成几何；保留原 `text_geometry_build`（单行左对齐，等价于默认布局）。
3. 门面 `Renderer` 新增：
   - `bool text_measure(uint64_t font, const std::string&, float* width_out, float* height_out) const;`
   - `bool text_draw_layout(uint64_t font, const std::string&, float pixel_x, float pixel_y, const Text_Layout& layout);`
   - `text_draw` 语义不变，内部转调 `text_draw_layout(..., Text_Layout{})`。
4. **网格缓存键**从「(字体, 文本)」扩为「(字体, 文本, 布局三项)」，否则同文本不同布局会命中旧网格（**必须处理**）。
5. `渲染器.h` 新增包含 `Text/文字布局数据.h`。

**验收**：度量（宽度随字符数单调、空/全不支持文本为 0）、单行默认布局等价既有、窄宽度换行出两行、右对齐墨迹靠右、不同布局不串缓存；既有文字 / 中文用例不回归。

**风险**：`text_meshes` 结构变更牵动 `font_unload` 清理逻辑（只按 `font` 字段过滤，无需改动）；对齐基准取「行 advance 之和」而非「末字形右缘」，会在行尾有空格时略偏（文档写明）。

## 六、风险与预案

| 风险 | 预案 |
| --- | --- |
| 换行后行高 ≠ 字体像素高度导致两行重叠 | `line_height` 默认取 `pixel_height`，用例断言两行墨迹分处上下半区 |
| 右对齐基准取 advance 之和，行尾空格造成偏移 | 文档写明；用例用无尾随空格的文本 |
| 网格缓存键比较遗漏字段导致串味 | 用例「不同布局不串缓存」直接钉住（同一文本两种布局各画一次并比对像素） |
| 各向异性在部分驱动下两帧可能无差异 | 不支持能力时走结构性分支；支持时若差异为 0 则如实失败（说明状态未生效，正是要抓的问题） |
| 窗口内时间不足 | 按 A → B 顺序交付，B 顺延（A 为能力缺口，优先级更高） |
