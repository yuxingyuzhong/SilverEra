## 三、关键实现

### 3.1 度量口径
```cpp
//文字几何.cpp · text_measure
pen_x += glyph->advance;
//有墨迹的字形才刷新右缘（尾随空白因此不计入宽度）
if (glyph->has_ink && glyph->x1 > glyph->x0)
    ink_right = pen_x;
```
- 宽 = `round(ink_right)`，高 = `record.pixel_height`；
- 无任何有墨迹字形（空串 / 全空白 / 全不支持）→ 返回假且两出参 0。

### 3.2 换行与对齐
| 环节 | 口径 |
| --- | --- |
| 断行判据 | `max_width > 0` 且「当前行非空」且 `line_advance + glyph.advance > max_width` |
| 单字形超宽 | 不在此断行 → 独占一行（避免死循环），对齐时负偏移**钳到 0** |
| 显式换行 | `'\n'` 收束当前行并新起一行（空行保留，形成垂直间距） |
| 行距 | `line_height > 0 ? line_height : pixel_height` |
| 对齐基准 | 行宽 = 该行 `advance` 之和；`Center → (max_width − w)/2`；`Right → max_width − w` |
| 无换行时的对齐 | `max_width == 0` → 单行，`align` 无效果（原点即锚点） |

### 3.3 缓存键（易错点）
- 原键 `(font, text)` → 新键 `(font, text, layout.max_width, layout.line_height, layout.align)`；
- 浮点字段按**逐值 `!=`** 比较（同一调用方传同一常量即可命中）；
- 用例「右对齐使墨迹靠右」的第 2 段（改回左对齐）即为该键的回归护栏 —— 若键漏项，墨迹仍会在右侧。

### 3.4 各向异性诊断（B 方向定案）
- 场景：256×256 **垂直条纹**（条宽 2 px）＋ 绕 Y 轴 60° 四边形 → 屏幕 x 方向强压缩，`du/dx ≫ dv/dy`；
- 纹理细节必须落在**被压缩的 u 方向**：首版用水平条纹（细节在 v）时两帧必然相同（多采样采到常量），已改正并写入注释；
- **本机实测两帧逐字节相同（差异 0）** → 把「差异 > 0」写成硬断言会在换机 / 换驱动时假失败；
- 定案口径：`R-SAMPLE-01` = **结构性断言（两帧均正常出图）＋ 差异诊断记录**（`RecordProperty`），不判方向、不强制差异；「采样器状态确实作用于像素」由同文件 `mip过滤开关产生像素级差异` 钉住。

## 七、重开发指引

1. **布局语义头**：新增 `Text/文字布局数据.h`（`Text_Align` / `Text_Layout`），并在 `字体.h` 与 `渲染器.h` 中包含它（门面公共面需暴露 `Text_Layout`）。
2. **度量**：`text_measure` 用「末个有墨迹字形的右缘」而非「advance 总和」——否则尾随空白会算进宽度。
3. **布局几何**：两阶段实现（先切行、再逐行产出）；`text_geometry_build` 转调 `Text_Layout{}` 保持既有语义。
4. **缓存键**：`Text_Mesh_Record` 必须带布局三项，否则同一文本换布局后会画旧网格。
5. **各向异性用例**：纹理细节要落在**被压缩的方向**；诊断口径不要改成硬断言（本机差异为 0）。
6. **测试运行**：`EngineTests.exe` 位于 `Application/Test/` 根，工作目录必须是该目录；`--gtest_filter` 传中文用例名时 PowerShell 可能乱码，故用套件通配 `Suite.*`。
