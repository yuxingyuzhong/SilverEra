## 二、A · 多中间目标后处理链

**动机**：现有链只有「场景目标 ＋ 1 个第二目标」，只能做**同尺寸两级** ping-pong；真泛光（亮部提取 → 模糊 → 叠加）以及任何多级滤镜都需要 ≥ 3 个中间目标。

**接口改造**（统一为一条入口，**删除** `render_target_present_secondary_set`）：
1. 门面新增 `render_target_present_chain_set(const uint64_t* handles, uint32_t count)`：
   `handles[0]` = 场景目标（等同原 present 目标），`handles[1..count-1]` = 其余中间目标；
   `count == 0` 清除；任一句柄未登记 / `count > 4`（= `POST_SET_PER_SLOT`）时整组拒绝、保持原设置。
2. `render_target_present_set(handle)` 语义收窄为「只设一个场景目标」：同时清空额外目标组（链路目标数回归 1）。
3. 帧模块 `render_chain_present` 的目标参数由「scene_target ＋ second_target」改为
   `const Frame_Render_Target* targets, uint32_t target_count`；录制函数同步。目标轮转规则：
   **第 i 级源 = `targets[i % target_count]`，非末级宿 = `targets[(i + 1) % target_count]`**（N = 2 时与原 ping-pong 逐字等价）。
4. 后处理采样集下标由 `级序 % POST_SET_PER_SLOT(2)` 改为 **`级序 % target_count`**；
   `POST_SET_PER_SLOT` 由 2 扩为 **4**（描述符池容量随常量自动放大）。
5. 前置校验：`post_count ≥ 2` 要求 `target_count ≥ 2`；`target_count ≤ 4`；目标范围仍须与交换链 1:1 一致。

**新增着色器**：
- `assets/shaders/亮部提取.frag`：Rec.709 亮度过阈值（阈值 0.6、软膝 0.1，`smoothstep` 权重）后乘回原色，暗部归零。
- `assets/shaders/模糊.frag`：3×3 高斯近似（权重 1/16、2/16、1/16…）9 抽样 `texelFetch` 偏移 ＋ 越界钳边。

**用例**（`渲染后处理链测试.cpp`，3 例）：
1. **三级链「亮部提取 → 模糊 → 灰度」**（3 个中间目标）：中心（白四边形）仍为亮灰、角落（清屏色）近黑；
   中心三通道趋同证明确实执行到第 3 级；且三目标轮转下链正常出帧。
2. **二级链「亮部提取 → 模糊」与单级「亮部提取」画面必须不同**（有像素差 > 0）→ 证明第 2 级与第 2 目标真实参与。
3. **目标数不足回落**：链长 2 但只设 1 个目标 → 本帧回落单级默认路径并正常出帧（不硬失败）。

## 三、B · 预设库补两项

1. `assets/shaders/对比度.frag`：`rgb = clamp((rgb − 0.5) × 1.5 + 0.5, 0, 1)`；空白处（暗清屏色）被压到近黑，白四边形保持饱和。
2. `assets/shaders/饱和度.frag`：按 Rec.709 亮度 `mix(vec3(luma), rgb, 1.5)`，清屏色（b > r）通道差被放大。
3. 用例（2 例，端点方向断言，不依赖具体曲线数值）：对比度 → 角落明显变暗且中心仍饱和；饱和度 → 角落 b−r 差较参考帧增大。

## 五、风险与预案

| 风险 | 预案 |
| --- | --- |
| 目标轮转改变既有 ping-pong 行为 | N = 2 时 `i % 2` / `(i+1) % 2` 与原奇偶规则逐字等价；既有 12 例链用例必须全绿 |
