## 二、A1 · `R-TEXT-01` 诊断计数接口

**动机**：超出字体支持的码点目前被静默跳过（不推进笔位、无任何信号）；整串无可见字形时只靠 `text_draw` 返回假。用户指定「补诊断计数接口」。

**实现**：
1. `Text/字体.h` — `Font_Record` 增 `uint64_t skipped_codepoints = 0;`（累计「补烘阶段判定为无法呈现」的码点数；去重计，每码点至多计一次，解码失败字节不计）。
2. `Text/core/字体加载.cpp` — `glyphs_ensure` 三处递增：
   - `stbtt_FindGlyphIndex(&info, codepoint) == 0`（字体不含该码点 → 直接登记空度量并入计数）；
   - 字形过宽（`glyph_width + 2 > atlas_width`）；
   - 图集高度空间不足。
3. `Font_Context` 增只读 `uint64_t font_skipped_codepoints_get(uint64_t handle) const`（句柄无效返回 0）。
4. 门面 `Renderer` 增 `uint64_t font_skipped_codepoints(uint64_t font) const`（未初始化 / 句柄无效返回 0）。
5. `font_destroy` 通过 `record = Font_Record{}` 自动归零（无需额外代码）。

**口径**：计数为**累计值**，跨多次 `text_draw` 累加，不清零；「同一码点重复出现」只计第一次（因为补烘只做一次）。用例断言此口径。

**风险**：`stbtt_FindGlyphIndex` 对空白字符（如 U+0020）返回非 0，故不会误计；需确认测试字体确实不含所用私有区码点。

## 三、A2 · `R-FRAME-11` 链路径 GPU 旁证

**动机**：GPU 耗时口径（环形读回、滞后 = 在途帧数、多 pass 之和、掩高位、降级）只在注释里，缺链路径的结构旁证。**不做**「两级 ≥ 一级」的耗时单调断言（换机 / 驱动波动易假失败）。

**实现**（仅测试）：
- `渲染GPU耗时测试.cpp` 增 1 例：以链长 2 走 3 帧，断言 ①能力支持时 `gpu_samples == 帧数 − 在途帧数` 且链路径 `gpu_frame_ms > 0`；②能力不支持时三字段恒 0。任一分支都必须构造与实跑（不跳过）。

**结案口径**：`R-FRAME-11` 标记**结案**——「多 pass 之和」由终点时间戳位于收尾转换之后保证（源码已如此），本轮补链路径的样本计数旁证。

## 五、B · 后处理链状态可观测

**动机**：`post_chain_set` 只写不读；`pipeline_unload` 静默摘除链中失效句柄，调用方无法得知链现状。

**实现**：
1. `渲染器.h` 增 `uint32_t post_chain_count(void) const;` 与 `uint32_t post_chain_get(uint64_t* out, uint32_t capacity) const;`（返回实际写入数；`capacity` 不足按容量截断；`out` 为空返回 0）。
2. `渲染器.cpp` 实现（只读，不改渲染行为）。
3. 文档口径：**下标即当前级序**（`pipeline_unload` 摘除后级序压缩），非设置时的原始下标。

**用例**（`渲染后处理链测试.cpp`）：
- 设 3 级 → `post_chain_count() == 3`，`post_chain_get` 逐级句柄与设置顺序一致；
- 卸载中间一级 → 计数 2、顺序保持（原第 1、3 级前移）；
- `capacity = 1` → 返回 1，仅写出第 0 级；`out = nullptr` → 返回 0。
