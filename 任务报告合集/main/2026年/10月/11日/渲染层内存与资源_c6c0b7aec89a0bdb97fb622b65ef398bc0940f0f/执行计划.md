## 三、接口设计

### 3.1 `engine::Memory_Context`

```cpp
class Memory_Context
{
public:
    Memory_Context(void) = default;
    ~Memory_Context(void);
    Memory_Context(const Memory_Context&) = delete;
    Memory_Context& operator=(const Memory_Context&) = delete;

    // 构建：创建 VMA 分配器，并记下上传所需的图形队列
    bool build(VkInstance instance, VkPhysicalDevice physical_device, VkDevice device,
               uint32_t graphics_family, VkQueue graphics_queue);
    void destroy(void);
    bool valid(void) const;

    // 缓冲：host_visible 为真时按「主机可见 + 可随机访问」分配（本轮要用例读回校验）
    bool buffer_create(VkBuffer& buffer_out, VmaAllocation& alloc_out,
                       VkDeviceSize size, VkBufferUsageFlags usage, bool host_visible);
    void buffer_destroy(VkBuffer buffer, VmaAllocation alloc);
    bool buffer_write(VkBuffer buffer, VmaAllocation alloc,
                      const void* data, VkDeviceSize size, VkDeviceSize offset);
    bool buffer_read(VkBuffer buffer, VmaAllocation alloc,
                     void* data, VkDeviceSize size, VkDeviceSize offset);

    // 图像与视图
    bool image_create(VkImage& image_out, VmaAllocation& alloc_out,
                      uint32_t width, uint32_t height, VkFormat format, VkImageUsageFlags usage);
    void image_destroy(VkImage image, VmaAllocation alloc);
    bool image_view_create(VkImageView& view_out, VkImage image, VkFormat format, VkImageAspectFlags aspect);
    void image_view_destroy(VkImageView view);

    // 一次性同步上传
    bool upload_buffer(VkBuffer dst_buffer, const void* data, VkDeviceSize size, VkDeviceSize offset);
    bool upload_image(VkImage dst_image, const void* data,
                      uint32_t width, uint32_t height, uint32_t row_pixels);

    VmaAllocator allocator_get(void) const;
    VkDevice device_get(void) const;
private:
    bool build_allocator(VkInstance, VkPhysicalDevice, VkDevice);   // 实现见 core/分配器创建.cpp
private:
    VmaAllocator     allocator       = VK_NULL_HANDLE;
    VkDevice         device          = VK_NULL_HANDLE;
    VkPhysicalDevice physical_device = VK_NULL_HANDLE;
    VkInstance       instance        = VK_NULL_HANDLE;
    uint32_t         graphics_family = 0;
    VkQueue          graphics_queue  = VK_NULL_HANDLE;
};
```

### 3.2 关键口径

| 项 | 口径 | 依据 |
| --- | --- | --- |
| 设备本地缓冲 | `VMA_MEMORY_USAGE_AUTO` ＋ `VMA_ALLOCATION_CREATE_DEDICATED_MEMORY_BIT` | §6.1 |
| 主机可见缓冲 | `VMA_MEMORY_USAGE_AUTO` ＋ `VMA_ALLOCATION_CREATE_HOST_ACCESS_RANDOM_BIT` ＋ `VMA_ALLOCATION_CREATE_MAPPED_BIT` | §6.1（把「统一缓冲」的持久映射一并落实）；因本轮需要读回校验，取 RANDOM 而非 SEQUENTIAL_WRITE |
| 图像 | `VMA_MEMORY_USAGE_AUTO`，`VK_IMAGE_TILING_OPTIMAL` | §6.1 |
| 暂存缓冲 | 每次上传临时创建、用完立即销毁 | §6.1 |
| 写入后同步 | `vmaFlushAllocation`；读取前 `vmaInvalidateAllocation` | 非 HOST_COHERENT 内存类型必需 |
| 图像上传布局 | `UNDEFINED → TRANSFER_DST_OPTIMAL → SHADER_READ_ONLY_OPTIMAL` | 采样纹理的默认终态，Phase 9 复用 |
| 上传提交 | 临时 `VkCommandPool`（图形队列族）＋ 命令缓冲 ＋ `vkQueueSubmit` ＋ 栅栏等待 ＋ 销毁命令池 | 一次性同步；Phase 5 换成帧槽命令池 |
| 错误处理 | 一律 `bool` 返回 ＋ `Log`；Vulkan 调用经 `Renderer/core/结果检查.h` 的 `vk_result_check` | §4.4 |
| VMA 自身调用 | 无 `VkResult`，失败记 `Log::error` 并返回 `false` | §4.4 |
| VMA 加载函数 | 不定义 `VK_NO_PROTOTYPES`（默认静态链接 `vulkan-1.lib`） | §6.1 |

### 3.3 头文件可见性

`内存上下文.h` 会包含 `<vulkan/vulkan.h>` 与 `<vk_mem_alloc.h>`。这与 Device 模块同一口径：模块对外头属**层内可见**，其第三方包含根在 CMake 中是 PRIVATE，快照虽镜像该头，层外仍无法解析这两份第三方头 —— 即「层外拿不到 Vulkan/VMA 头」这条边界依然由构建系统强制成立。

## 五、风险与应对

| # | 风险 | 应对 |
| --- | --- | --- |
| 1 | `vmaCreateBuffer` / `vmaCreateImage` 无返回值 → 无法用 `vk_result_check` | 直接判 `VK_SUCCESS`，失败记 `Log::error`（该出口仍是「唯一检查点」的例外，会在执行报告中记录） |
| 2 | 临时命令池每次上传都创建，开销偏大 | 本轮 6 次以内的上传量下无实际影响；Phase 5 换帧槽命令池（设计已如此规划） |
| 3 | `VMA_ALLOCATION_CREATE_MAPPED_BIT` 与 `vmaMapMemory` 并用 | VMA 允许；持久映射下 `vmaMapMemory` 返回同一指针，`vmaUnmapMemory` 不解除持久映射 |
| 4 | 上传图像的目标布局假设为「采样用」 | 在 `上传批次.cpp` 顶部注明终态布局及其适用范围，Phase 9 若需其他终态再扩参 |
| 5 | 新目录未被 GLOB 收编 | 已实测：`GLOB_RECURSE CONFIGURE_DEPENDS` ＋ 目录级 `CMAKE_CONFIGURE_DEPENDS` 会收编新目录；构建前核对配置输出的「本层源文件」列表 |
