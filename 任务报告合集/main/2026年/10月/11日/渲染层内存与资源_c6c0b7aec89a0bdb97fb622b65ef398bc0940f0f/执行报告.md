### 2.1 `Application/Renderer/src/render/Memory/内存上下文.h`（110 行）

内存模块**对外头**。内含 `#include <vulkan/vulkan.h>` 与 `#include <vk_mem_alloc.h>`——**合法**：该头位于 `src/`，属层内私有实现细节，层外经头快照虽能拿到该头路径，但拿不到 Vulkan／VMA 私有包含根，包含即在层外编译失败（与 `Device/设备上下文.h` 同一口径，见 §3.3）。

`engine::Memory_Context` 完整接口（**重开发时按此还原即可**）：

```cpp
class Memory_Context
{
public:
    Memory_Context(void) = default;
    ~Memory_Context(void);                                    // 内部调 destroy()
    Memory_Context(const Memory_Context&) = delete;           // 不可拷贝/移动
    Memory_Context& operator=(const Memory_Context&) = delete;

    // 设备侧句柄：来自 Device_Context；图形队列用于一次性上传提交
    bool build(VkInstance instance, VkPhysicalDevice physical_device, VkDevice device,
               uint32_t graphics_family, VkQueue graphics_queue);
    void destroy(void);                                       // 幂等
    bool valid(void) const;                                   // allocator && device

    // 缓冲（host_visible 为真 → 主机可见可随机访问 ＋ 持久映射）
    bool buffer_create(VkBuffer& buffer_out, VmaAllocation& alloc_out,
                       VkDeviceSize size, VkBufferUsageFlags usage, bool host_visible);
    void buffer_destroy(VkBuffer buffer, VmaAllocation alloc);
    bool buffer_write(VkBuffer buffer, VmaAllocation alloc,
                      const void* data, VkDeviceSize size, VkDeviceSize offset);
    bool buffer_read(VkBuffer buffer, VmaAllocation alloc,
                     void* data, VkDeviceSize size, VkDeviceSize offset);

    // 图像与视图
    bool image_create(VkImage& image_out, VmaAllocation& alloc_out,
                      uint32_t width, uint32_t height, VkFormat format, VkImageUsageFlags usage);
    void image_destroy(VkImage image, VmaAllocation alloc);
    bool image_view_create(VkImageView& view_out, VkImage image, VkFormat format, VkImageAspectFlags aspect);
    void image_view_destroy(VkImageView view);

    // 一次性同步上传
    bool upload_buffer(VkBuffer dst_buffer, const void* data, VkDeviceSize size, VkDeviceSize offset);
    bool upload_image(VkImage dst_image, const void* data, VkDeviceSize data_size,
                      uint32_t width, uint32_t height, uint32_t row_pixels);

    VmaAllocator allocator_get(void) const;   // 供上层创建自有资源时复用
    VkDevice     device_get(void) const;
private:
    bool build_allocator(VkInstance, VkPhysicalDevice, VkDevice);   // 实现见 core/分配器创建.cpp
private:
    VmaAllocator     allocator       = VK_NULL_HANDLE;
    VkDevice         device          = VK_NULL_HANDLE;
    VkPhysicalDevice physical_device = VK_NULL_HANDLE;
    VkInstance       instance        = VK_NULL_HANDLE;
    uint32_t         graphics_family = 0;
    VkQueue          graphics_queue  = VK_NULL_HANDLE;
};
```

> **销毁口径（务必照抄）**：`destroy()` 只销毁 VMA 分配器，**不**连带销毁其下的缓冲／图像 —— 那些必须由调用方先行销毁，否则 VMA 会在销毁分配器时报「仍有存活分配」。类的头注释已写明此约定。

### 2.4 `Application/Renderer/src/render/Memory/core/分配器创建.cpp`（106 行）

实现 `~Memory_Context` / `build_allocator` / `build` / `destroy` / `valid` / 两个 getter。

- **`build_allocator(VkInstance, VkPhysicalDevice, VkDevice)`**：

```cpp
VmaAllocatorCreateInfo create_info{};
create_info.vulkanApiVersion = VK_API_VERSION_1_0;   // 不启用 1.1+ 特性
create_info.instance         = instance;
create_info.physicalDevice   = physical_device;
create_info.device           = device;
VkResult result = vmaCreateAllocator(&create_info, &allocator);
if (!vk_result_check(result, "分配器创建:: 创建 VMA 分配器")) { allocator = VK_NULL_HANDLE; return false; }
```

  不填 `pVulkanFunctions`：VMA 默认 `VMA_STATIC_VULKAN_FUNCTIONS=1` 直接走已静态链接的 `vulkan-1` 入口。**第一版不启用任何 VMA 特性开关**（不做内存预算／环形上传缓冲／延迟分配）。

- **`build(...)`**：先 `this->instance = instance;` 等 **逐个 `this->` 消歧**记录 5 个设备侧句柄（形参与成员同名），再调 `build_allocator`；失败即 `destroy()` 回退，不留半初始化。
- **`destroy()`**：幂等。分配器非空 → `vmaDestroyAllocator` 并置空；尾部清空 5 个句柄（`graphics_queue` / `graphics_family=0` / `device` / `physical_device` / `instance`）。
- **`valid()`**：`allocator != VK_NULL_HANDLE && device != VK_NULL_HANDLE`。

### 2.5 `Application/Renderer/src/render/Memory/core/缓冲创建.cpp`（118 行）

实现 `buffer_create` / `buffer_destroy` / `buffer_write` / `buffer_read`。

- **`buffer_create`**：`VkBufferCreateInfo{ size, usage, sharingMode = VK_SHARING_MODE_EXCLUSIVE }`；分配标志按 `host_visible` 二选一 ——

| `host_visible` | `alloc_info.flags` | 落点 |
| --- | --- | --- |
| `true` | `VMA_ALLOCATION_CREATE_HOST_ACCESS_RANDOM_BIT \| VMA_ALLOCATION_CREATE_MAPPED_BIT` | 主机可见、可随机读写、**持久映射**（读写取回同一指针） |
| `false` | `VMA_ALLOCATION_CREATE_DEDICATED_MEMORY_BIT` | 设备本地、专用内存（长命且体积大，不做子分配复用） |

  两者 `usage` 恒为 `VMA_MEMORY_USAGE_AUTO`；`vmaCreateBuffer` 经 `vk_result_check` 收口（**见 §一 偏离 2**），失败即双句柄置空并 `false`。

- **`buffer_destroy`**：三句柄（`buffer`/`alloc`/`allocator`）任一为空即直接返回（幂等）；否则 `vmaDestroyBuffer`。
- **`buffer_write`**：前置校验（含 `data != nullptr`）→ `vmaMapMemory`（经 `vk_result_check`）→ `memcpy(static_cast<uint8_t*>(mapped) + offset, data, size)` → `vmaFlushAllocation(allocator, alloc, offset, size)` → `vmaUnmapMemory`。
- **`buffer_read`**：同样映射 → 先 `vmaInvalidateAllocation(allocator, alloc, offset, size)` 使设备侧写入对主机可见 → `memcpy(data, static_cast<const uint8_t*>(mapped) + offset, size)` → 解除映射。

> `memcpy` 为**全局**函数（`EngineCore` 预编译头含 `<string.h>`，**不含** `<cstring>`，故不能写 `std::memcpy`）；字节偏移用全局 `uint8_t`（`<stdint.h>` 已含，**不含 `<cstdint>`**，故不能写 `std::uint8_t`）。`vmaFlushAllocation` / `vmaInvalidateAllocation` 返回 `void`（对主机一致内存类型为无操作，可无条件调用）。

### 2.6 `Application/Renderer/src/render/Memory/core/图像创建.cpp`（109 行）

实现 `image_create` / `image_destroy` / `image_view_create` / `image_view_destroy`。

- **`image_create`**：`VkImageCreateInfo` 按第一版最小口径固定 —— `imageType = 2D` / `mipLevels = 1` / `arrayLayers = 1` / `samples = VK_SAMPLE_COUNT_1_BIT` / `tiling = VK_IMAGE_TILING_OPTIMAL` / `sharingMode = EXCLUSIVE` / `initialLayout = VK_IMAGE_LAYOUT_UNDEFINED`；`extent = { width, height, 1 }`。分配恒为 `VMA_ALLOCATION_CREATE_DEDICATED_MEMORY_BIT`（图像一律设备本地）。`vmaCreateImage` 经 `vk_result_check`。
- **`image_destroy`**：三句柄任一为空即返回（幂等）；否则 `vmaDestroyImage`。
- **`image_view_create`**：`vkCreateImageView`；`VK_IMAGE_VIEW_TYPE_2D`、`subresourceRange{ aspectMask = aspect, baseMipLevel = 0, levelCount = 1, baseArrayLayer = 0, layerCount = 1 }`。经 `vk_result_check`。
- **`image_view_destroy`**：`view` 或 `device` 为空即返回；否则 `vkDestroyImageView`（**只销毁视图，图像由 `image_destroy` 负责**）。

### 2.7 `Application/Renderer/src/render/Memory/core/上传批次.cpp`（217 行）

本轮最大文件。匿名命名空间内定义**文件内模板** `upload_submit_once`，供 `upload_buffer` / `upload_image` 共用。

**`upload_submit_once(VkDevice, uint32_t graphics_family, VkQueue, Record_Fn record)`** —— 一次性同步提交路径：

```
临时 VkCommandPool（VK_COMMAND_POOL_CREATE_TRANSIENT_BIT，图形队列族）
  → vkAllocateCommandBuffers（PRIMARY × 1）
  → vkBeginCommandBuffer（VK_COMMAND_BUFFER_USAGE_ONE_TIME_SUBMIT_BIT）
  → record(command_buffer)          // 由调用方 lambda 录制拷贝与布局转换
  → vkEndCommandBuffer
  → vkCreateFence（未触发态）
  → vkQueueSubmit（同步完成，不设信号量）
  → vkWaitForFences（VK_TRUE, UINT64_MAX）
  → vkDestroyFence ＋ vkDestroyCommandPool（命令缓冲随池一并销毁）
```

每一步失败分支均**先回收已建出的对象**（命令池）再返回 `false`，无泄漏。所有 Vulkan 调用经 `vk_result_check`。

- **`upload_buffer(dst_buffer, data, size, offset)`**：前置校验（`valid()` ＋ 目标句柄 ＋ `data` ＋ `graphics_queue`）→ 建主机可见 `VK_BUFFER_USAGE_TRANSFER_SRC_BIT` 暂存缓冲 → `buffer_write` 写入 → `upload_submit_once` 内 `vkCmdCopyBuffer`（`srcOffset = 0, dstOffset = offset, size = size`）→ **无论成败回收暂存缓冲**。
- **`upload_image(dst_image, data, data_size, width, height, row_pixels)`**：前置校验 → 暂存缓冲（大小 = `data_size`）→ `buffer_write` → `upload_submit_once` 内**三步**：

  1. `VkImageMemoryBarrier`：`UNDEFINED → TRANSFER_DST_OPTIMAL`（`TOP_OF_PIPE → TRANSFER`，`dstAccessMask = VK_ACCESS_TRANSFER_WRITE_BIT`，旧内容不保留）；
  2. `vkCmdCopyBufferToImage`：`bufferRowLength = row_pixels`（传 0 表示按 `width` 紧排）、`imageExtent = { width, height, 1 }`、`imageSubresource = { VK_IMAGE_ASPECT_COLOR_BIT, 0, 0, 1 }`；
  3. `VkImageMemoryBarrier`：`TRANSFER_DST_OPTIMAL → SHADER_READ_ONLY_OPTIMAL`（`TRANSFER → FRAGMENT_SHADER`，`dstAccessMask = VK_ACCESS_SHADER_READ_BIT`）。

  → 无论成败回收暂存缓冲。**终态布局固定为采样用途**（`SHADER_READ_ONLY_OPTIMAL`），Phase 9 若需其他终态再扩参。
