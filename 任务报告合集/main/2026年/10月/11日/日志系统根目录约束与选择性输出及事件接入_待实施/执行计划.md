## 1. 需求拆解（原文 → 释义）

### <2> 根目录设置与绑定门禁

原文：
> 日志系统新增方法允许设置日志系统根目录，若根目录未设置则不允许绑定输出流；
> 则检查是否存在其他可用接口，若有则切换为其他接口(并打印警告日志)，若没有则打印错误日志；

释义（**已确认**）：「根目录」＝**调用处路径作用域**。

设计：
- 新增 `root_set` / `root_clear` / `root_get` 三个接口。
- 未设根目录时，**所有** `stream_bind` 重载一律拒绝。
- 拒绝后的「其他可用接口」判定（**待确认，见 §6**）：后备通道＝控制台兜底输出；可切换则切换并打 `WARN`，无后备则打 `ERROR`。

### <6> 路径越界截断

原文：
> 日志系统新增路径越界检查机制，对于未包含于根目录的输出日志直接截断；

设计：调用处规范化键（`detail::path_key_normalize` 结果）**不以根目录键为前缀**时，直接丢弃该条日志（不路由、不落盘）。

### <7> 选择性输出（读配置实现）

原文：
> <1> 允许设置特定文件可输出/不可输出；
> <2> 允许设置特定目录可输出/不可输出；
> <3> 允许设置特定分类日志可输出/不可输出；
> <4> 以上机制均通过读取配置文件实现；

释义（**已确认**）：「分类」＝**四级日志级别**（`INFO` / `WARN` / `ERROR` / `DEBUG`）。

设计：
- 7.1 文件：按**调用处文件路径**精确匹配。
- 7.2 目录：按**调用处目录路径**前缀匹配（作用于其后代）。
- 7.3 级别：按级别匹配。
- 7.4 三张许可表均由配置驱动（配置经事件中转站下发，见 <11>）。
- 求值顺序与优先级（**待确认，见 §6**）：级别 → 文件精确 → 目录最长前缀 → 全未命中默认**允许**。

### <11> 事件中转站接入

原文：
> 日志系统接入事件中转站，支持通过配置文件设置文件流，日志信息输出白/黑名单；

设计（配置来源**已确认**：经事件中转站下发）：
- 「通过配置文件设置文件流」＝ 配置可声明「路径节点 → 输出文件」绑定。
- 「白/黑名单」＝ §<7> 的三张许可表。
- 「接入事件中转站」＝ 由上层桥接模块以订阅者身份 `attach` 进 `Event_Broker`，订阅配置投递事件（`Config` / `Load`），收到后把配置解析为纯数据并调用日志系统的设置接口。

## 2. 架构约束与关键决策

### 2.1 依赖方向（关键）

- `Logging` 位于 `Engine/EngineCore/src/tools/`（底层工具），`Event_Broker` 位于 `Engine/EngineCore/src/core/event/`（上层）。
- `Event_Broker` 的 `.cpp` 已包含日志运行包；`Config_Loader` 的六个 `.cpp` 亦然。
- **决策：`Logging` 自身不包含事件系统／配置系统的任何头**，只暴露「纯数据」设置接口（字符串、`bool`、级别枚举），由上层桥接模块完成「订阅 → 解析 → 下发」，从而**彻底避免反向依赖与头文件循环**。
- 桥接模块落位（**待确认，见 §6**）：新建 `Engine/EngineCore/src/core/log/日志配置桥接/`。

依赖走向：

```
Config_Loader ──投递配置事件──▶ Event_Broker ──转发──▶ 日志配置桥接 ──调用设置接口──▶ logger(Logging)
                                                              （单一方向，无环）
```

### 2.2 规则载体与归属

- 新增 `Log_Rules`（日志规则）类，承载：根目录键 ＋ 三张许可表 ＋ 求值逻辑。
- 置于新文件 `Engine/EngineCore/src/tools/Logging/Rule/日志规则.h`，由 `Log` 持有（`has-a`），避免继续膨胀 `流节点树.h`（已 503 行 / 22.7 KB）。
- 路径键与作用域比较**复用** `detail::path_key_normalize`（尾部补 `/`，使前缀比较落在路径段边界）。

### 2.3 过滤求值位置（热路径）

- **级别过滤**在 `Log::output` 最前完成（无需路径，最省）。
- **作用域检查（<6>）＋ 文件/目录过滤（<7.1/7.2>）**在 `Stream_Tree::stream_output` 内、`node_locate` 之后按**节点已规范化的键**判定。
- 任一判定不通过即 `return`，**不进入 `group_resolve` 与输出热路径**。

### 2.4 规则变更的缓存失效

- 复用既有 `tree_epoch` 版本号：根目录或规则变更即 `epoch_bump()`。
- 节点上的「作用域/许可」缓存以版本号登记，变更后自动失效并惰性重算（与现有 `shared_epoch` 同机制）。

## 3. 接口设计（拟）

### 3.1 `Log`（`Log/日志系统.h`）新增公开接口

```cpp
//日志根目录设置（调用处路径作用域；未设置则禁止任何输出流绑定）
bool root_set(const std::string& dir);
//日志根目录清除
void root_clear();
//日志根目录查询（未设置返回空串）
std::string root_get() const;

//文件输出许可设置（file → 是否允许输出）
bool file_rule_set(const std::string& file, bool allowed);
//目录输出许可设置（dir → 是否允许输出；作用于其后代调用处）
bool dir_rule_set(const std::string& dir, bool allowed);
//级别输出许可设置（"INFO" / "WARN" / "ERROR" / "DEBUG"）
bool level_rule_set(const std::string& level, bool allowed);
//全部输出许可清空
void rule_clear();

//原有接口语义调整：未设根目录时一律返回 false（并走后备通道）
bool stream_bind(const std::string& path, const std::string& file_name);
bool stream_bind(const std::string& path, const Stream& stream);
```

## 5. 配置文件草案（JSON）

```json
{
    "root": "Engine/EngineCore/src",
    "streams": [
        { "path": "Engine/EngineCore/src", "file": "out/引擎核心日志.txt" },
        { "path": "Engine/EngineSystem",    "file": "out/引擎系统日志.txt" }
    ],
    "files":  { "Engine/EngineCore/src/tools/Logging/Log/日志系统.h": false },
    "dirs":   { "Engine/EngineCore/src/core/spatial": false },
    "levels": { "DEBUG": false, "INFO": true }
}
```

字段含义：
- `root`：日志根目录（调用处路径作用域，项目根相对路径）。
- `streams`：路径节点 → 输出文件绑定清单。
- `files` / `dirs` / `levels`：三张许可表，`true` 可输出 / `false` 不可输出。
