### 2.1 `Application/Renderer/src/render/Renderer/core/结果检查.h`（T1）

本层**唯一**的 `VkResult` 检查/日志出口。header-only（全 `inline`），不配 `.cpp`。

| 函数 | 签名 | 语义 |
| --- | --- | --- |
| `engine::vk_result_name_get` | `std::string vk_result_name_get(VkResult)` | `VkResult` → 可读名。收录 22 个常用码；`default` 回退 `std::format("VkResult({})", (int32_t)result)`。**刻意未收录 `VK_ERROR_FRAGMENTED_POOL`**（与 `VK_ERROR_OUT_OF_POOL_MEMORY` 是别名同值，收录会造成重复 `case` 编译错误） |
| `engine::vk_result_acceptable` | `bool vk_result_acceptable(VkResult)` | 可接受返回值：`VK_ERROR_OUT_OF_DATE_KHR` / `VK_SUBOPTIMAL_KHR` / `VK_TIMEOUT`。不算失败，但调用方必须自行分支，不能当成功用 |
| `engine::vk_result_check` | `bool vk_result_check(VkResult, const char* operation)` | 硬错误检查。`VK_SUCCESS` → `true`；可接受码 → `logger.debug` 并 `false`；硬错误 → `logger.error` 并 `false` |

包含关系：`前置头文件包含.h` ＋ `Engine/EngineCore/src/tools/Logging/日志系统运行包.h`（取 `logger`）＋ `<vulkan/vulkan.h>`。

### 2.2 `Application/Renderer/src/render/Device/设备上下文.h`（T2）

设备模块**对外头**。内含 `#include <vulkan/vulkan.h>`——**这是合法的**：该头位于 `src/`，属层内私有实现细节，层外经头快照虽能拿到该头路径，但拿不到 Vulkan 私有包含根，包含即在层外编译失败（与设计 §4.1 的公共面边界一致）。

`engine::Device_Context` 完整接口（**重开发时按此还原即可**）：

```cpp
class Device_Context
{
public:
    Device_Context(void) = default;
    ~Device_Context(void);                                    // 内部调 destroy()
    Device_Context(const Device_Context&) = delete;           // 不可拷贝/移动
    Device_Context& operator=(const Device_Context&) = delete;

    bool build(const std::vector<const char*>& instance_extensions, bool enable_validation);
    void destroy(void);                                       // 幂等，严格逆序
    bool valid(void) const;                                   // 三句柄齐备

    VkInstance       instance_get(void) const;
    VkPhysicalDevice physical_device_get(void) const;
    VkDevice         device_get(void) const;
    uint32_t         graphics_family_get(void) const;
    VkQueue          graphics_queue_get(void) const;
    bool             validation_get(void) const;
private:
    bool build_instance(const std::vector<const char*>& instance_extensions, bool enable_validation);
    bool build_physical_device(void);
    bool build_device(void);
private:
    VkInstance                   instance            = VK_NULL_HANDLE;
    VkDebugUtilsMessengerEXT     debug_messenger     = VK_NULL_HANDLE;
    VkPhysicalDevice             physical_device     = VK_NULL_HANDLE;
    VkDevice                     device              = VK_NULL_HANDLE;
    uint32_t                     graphics_family     = 0;
    VkQueue                      graphics_queue      = VK_NULL_HANDLE;
    bool                         validation_enabled  = false;
};
```

> **关键设计点（Phase 4 零返工的根因）**：`build()` 把「所需实例扩展清单」作为**入参**，而非自己去调 SDL3。Phase 4 只需由 `Platform::instance_extensions_get()` 填这个清单，`Device` 的签名与实现一行都不用改。
>
> 私有方法 `build_instance` / `build_physical_device` / `build_device` **分别落在三个不同 `.cpp`**，是靠 C++「同一类的成员函数可分散在多个 TU 定义」实现的，不额外引入接口类。

`#pragma once` ＋ `#include "设备上下文.h"` ＋ `using std::string;` ＋ `using std::vector;`。模块内 `.cpp` 一律首行包含它，之后免写命名空间前缀（与 `Engine/EngineCore/src/tools/Timer` 同构）。

### 2.4 `Application/Renderer/src/render/Device/core/设备上下文.cpp`（T2）

- `~Device_Context()` → 调 `destroy()`。
- `build()`：**三步编排**，任一步失败即 `logger.error` ＋ `destroy()` 回退 ＋ `return false`（失败即无痕，不留半初始化态）。

```
build_instance → build_physical_device → build_device
   任一步 false → destroy() → false
   全通过      → logger.info("设备上下文:: 设备基础设施构建完成") → true
```

- `destroy()`：**严格逆序** `device → debug_messenger → instance`，每步判句柄非空、销毁后置空；尾部另清 `physical_device` / `validation_enabled`。幂等（二次调用时三句柄均为 `VK_NULL_HANDLE`，全部跳过）。
- `valid()`：`instance && physical_device && device` 三者齐备。
- 其余 6 个 getter 为一行返回。

### 2.5 `Application/Renderer/src/render/Device/core/实例创建.cpp`（T3）

实现 `Device_Context::build_instance`。要点：

1. `use_validation = enable_validation && validation_layer_available();`——**先探测再决定**。请求不存在的层会让 `vkCreateInstance` 直接失败，故探测不中时 `logger.warn` 降级关闭（K19）。
2. 写入成员 `validation_enabled = use_validation;`。
3. `vkEnumerateInstanceVersion` 取运行时版本；失败则回退 `VK_API_VERSION_1_0`（此处**不用** `vk_result_check`，因为「取不到版本」属预期分支而非硬错误，且回退后仍继续）。
4. `VkApplicationInfo`：`pApplicationName="白银纪元"`、`pEngineName="SilverEra Renderer"`、版本均 `VK_MAKE_VERSION(0,1,0)`。
5. `extensions = instance_extensions_assemble(instance_extensions, use_validation);`
6. **`const char* layer_name` 声明在函数作用域**：`create_info.ppEnabledLayerNames = &layer_name;`——若写成临时量会悬垂（这是本文件最易踩的坑）。
7. 校验层开启时，`debug_info = debug_messenger_info_create(); create_info.pNext = &debug_info;`——使「实例创建/销毁本身」的校验消息也能被捕获。
8. `vkCreateInstance` 失败 → `vk_result_check` 记 error → `return false`。
9. 实例建成功后**再补建**调试信使；失败仅告警、**不回退实例**（K19）。

### 2.7 `Application/Renderer/src/render/Device/core/校验层配置.cpp`（T4）

- `validation_layer_available()`：两次 `vkEnumerateInstanceLayerProperties`（先取数量、再取清单），逐项比对 `layerName`；两次均经 `vk_result_check`。
- `instance_extensions_assemble()`：先拷贝 `required`（保序），`enable_validation` 为真时追加 `VK_EXT_DEBUG_UTILS_EXTENSION_NAME`。
- `debug_message_callback()`：按 severity 分派——`ERROR` → `logger.error`、`WARNING` → `logger.warn`、其余 → `logger.info`，前缀 `"[Vulkan 校验] "`；**返回值恒 `VK_FALSE`**（返回真会中止触发该消息的调用）。`callback_data` 作空指针兜底。
- `debug_messenger_info_create()`：`messageSeverity` **只订阅 `WARNING|ERROR`**（信息级噪音大，会淹没引擎日志）；`messageType` 三类全开；`pfnUserCallback = debug_message_callback`。
- `debug_messenger_create()`：**函数开头先 `*messenger_out = VK_NULL_HANDLE`**；经 `vkGetInstanceProcAddr(instance, "vkCreateDebugUtilsMessengerEXT")` 取入口，取不到则 `logger.warn` 降级返回 `false`（K19）。
- `debug_messenger_destroy()`：同法取 `vkDestroyDebugUtilsMessengerEXT`，取不到静默跳过。

### 2.8 `Application/Renderer/src/render/Device/core/物理设备选择.cpp`（T5）

实现 `Device_Context::build_physical_device`，另含两个**文件内 static** 助手（`graphics_family_query` / `device_score`）。

- 枚举：`vkEnumeratePhysicalDevices` 两次；数量为 0 → `logger.error`。
- 逐个候选：先 `graphics_family_query` 求图形队列族，**不具备则跳过**；再 `device_score` 打分；取最高分。
- 全无合格设备 → `logger.error("…所有物理设备均不具备图形队列族")` → `false`。
- 选中后写成员 `physical_device` / `graphics_family`，并 `logger.info` 打印 `deviceName`、`deviceType`（整型）、得分、队列族索引。
- **打分公式（重开发务必照抄）**：

```
score = 类型权重 + min(本地堆总字节 / 1MB, 9999)
类型权重：DISCRETE_GPU 30000 / INTEGRATED_GPU 20000 / VIRTUAL_GPU 10000 / CPU 1000 / 其它 500
```

  `min(…, 9999)` 的封顶值 **必须小于最小类型权重差 10000**，否则「大显存的核显/CPU 设备会反超独显」（这是本文件唯一的算法陷阱）。
- **Phase 2 不做表面支持查询**（尚无表面）；呈现队列族留待 Phase 4。

### 2.9 `Application/Renderer/src/render/Device/core/逻辑设备创建.cpp`（T6）

实现 `Device_Context::build_device`。

- **队列族集合去重**：Phase 2 只有图形族（`unique_families = {graphics_family}`）；Phase 4 起图形与呈现同族只建一份、异族建两份，去重骨架本轮已按集合写法备好（注释标出登记位置）。
- `VkDeviceQueueCreateInfo` 每族一份，`queueCount = 1`，`pQueuePriorities` 指向共享的 `float queue_priority = 1.0f;`。
- `VkPhysicalDeviceFeatures features{}` **全关**；不启用任何设备扩展（`enabledExtensionCount = 0`）。
- `vkCreateDevice` 经 `vk_result_check`；成功后再 `vkGetDeviceQueue(device, graphics_family, 0, &graphics_queue)`。

## 五、构建复现（可凭此快速重跑）

环境三坑（K22/K23 与中文用户名路径）沿用既有口径，命令为单条内联 PowerShell（不落脚本）：

```powershell
$env:TMP="C:\Temp"; $env:TEMP="C:\Temp"
Import-Module "D:\ViusalStudioCommunity2026\Common7\Tools\Microsoft.VisualStudio.DevShell.dll"
Enter-VsDevShell -VsInstallPath "D:\ViusalStudioCommunity2026" -SkipAutomaticLocation -DevCmdArguments "-arch=x64 -host_arch=x64" | Out-Null
chcp 65001 | Out-Null      # 必须在进入 VS 开发人员环境之后，顺序颠倒不生效
$cmake = "D:\ViusalStudioCommunity2026\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe"
# 树 = x64-Debug 时 CMAKE_BUILD_TYPE=Debug；树 = x64-Release 时 = Release
& $cmake -S "d:\代码存储\代码仓库\白银纪元\Application\Renderer" -B "d:\代码存储\代码仓库\白银纪元\Application\Renderer\out\build\x64-Debug"   -G Ninja -DCMAKE_BUILD_TYPE=Debug
& $cmake --build "d:\代码存储\代码仓库\白银纪元\Application\Renderer\out\build\x64-Debug"
```

要点：
1. `TMP`/`TEMP` 必须为纯 ASCII 目录，否则 `cl /Zi` 报 `D8050`（本机用户名含中文）。
2. `chcp 65001` **必须**在 `Enter-VsDevShell` 之后。
3. `cmake`/`ninja` 不在 PATH，需用 VS 自带绝对路径（如上）。
4. 本层 Debug 树映射 `Engine/EngineCore/out/build/x64-Debug/lib/EngineCore.lib`，Release 树映射 `…/x64-Release/…`（`CMakeLists.txt` §1 按 `CMAKE_BUILD_TYPE` 显式映射，避免 CRT 混链）。
