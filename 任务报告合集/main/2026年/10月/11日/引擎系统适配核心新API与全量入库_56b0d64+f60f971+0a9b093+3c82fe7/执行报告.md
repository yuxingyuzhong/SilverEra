## 一、根因（一句话）

并行会话改了 EngineCore 的对外 API（事件终端端口化、`Object_Pool` 整份重写、`Event` 字段改名），EngineSystem 只做了**半套适配**（`acl_key_gen()` → `key()`、`Prop_Effect` 只移改造做了，但**注册口与遍历口没改**），于是：

1. `C2039`：`event_receiver_register / event_sender_register` 不是 `Terminal_Port` 成员（已统一为 `bind(const Port_ID&, T callback)`）；`data` 不是 `Object_Pool` 成员（已删 `data()`，改走 `begin()/end()`）。
2. 更深一层：`Object_Pool::build(const T& object = {})` 内部 `push_back(object)` / `std::construct_at(&objects[i], object)` **要求 T 可拷贝**，而 `Entity`（含 `Event_Terminal`、`LuaState`）与 `Prop_Effect`（用户定义了移动构造 → 拷贝隐式删除）都是**只移类型**，故池无法服务它们。

构建系统本身完好：五层 `CMakeLists.txt` 与各自 HEAD 逐字节一致、共享脚本在位、GLOB 清单机制正常、五层 configure 全过。
