## 二、契约变更（最终形态）

### 2.1 路由条目（T1）

条目由 `{object, config_path, dirty_mark}` 扩展为可携带事件名：

```json
{
  "object": "Entity_Manager",
  "config_path": "config/entities/史莱姆 (Slime).json",
  "event_category": "Property",
  "event_tag": "Push",
  "dirty_mark": 12345678901234567890
}
```

- `event_category` / `event_tag` 均可选；缺失、非字符串或空串时回落 `Config` / `Load`。
- 二者只是**条目字段**，不进入投递载荷（载荷仍只剔除 `dirty_mark`）。

### 2.2 订阅事件表（4 → 6 条）

| 事件 | 语义 | 载荷 |
| --- | --- | --- |
| `Believed_Root` / `Load` | 登记可信根（已有） | `route` ＋ `config` |
| `Believed_Root` / `Unload` | 撤销可信根（已有） | `route` ＋ `config` |
| `Route` / `load` | 加载对象某目录对（已有） | `object` ＋ `route` ＋ `config` |
| `Config` / `load` | 加载对象配置（已有） | `object` ＋ 可选 `files` |
| **`Route` / `Unload`** | **卸载对象某目录对（新增）** | `object` ＋ `route` ＋ `config` |
| **`Config` / `Unload`** | **卸载对象配置（新增）** | `object` ＋ 可选 `files` |

### 2.3 卸载层级职责（最终）

| 事件 | `config_routes` | `config_files` | 路由文件标记 |
| --- | --- | --- | --- |
| `Believed_Root` / `Unload` | 前缀命中全清（既有 `root_cache_clear`） | 前缀命中全清 | 不清（既有行为） |
| `Route` / `Unload` | **保留** | 该目录对下全部清 | 清（条目标记 ＋ 顶层标记） |
| `Config` / `Unload` | **保留** | 指定文件（无 `files` 即全部） | 清（对应条目标记 ＋ 顶层标记） |

### 3.3 `Engine/EngineCore/src/core/config/Config_Loader/core/路由文件操作.cpp`（T4 ＋ `route_file_unload`，+97 行内改动）

- `route_file_write` 改为「顶层标记非空才写」：

  ```cpp
  json route_file;
  //若顶层脏标记非空则写入（空值表示本轮不写顶层标记）
  if (!mark.is_null())
      route_file["dirty_mark"] = mark;
  route_file["config_routes"] = entries;
  ```

  唯一既有调用点 `route_file_process` 尾部的 `route_file_write(file_path, mark_make(...), entries)` 无需改动（`uint64_t` 隐式转 `json`）。

- 文件末尾（`route_file_process` 之后）新增 `route_file_unload`，与 `route_file_process` 严格对称：
  1. `route_file_read` 取出 `mark` / `entries`；`entries` 非数组即报错返回 `false`。
  2. 逐条：字段检查 `object` / `config_path` → `only_object` 过滤 → `only_files` 过滤（`json` 非 `null` 时逐项字符串比对）→ `path_prefix_check(content.config, 配置路径父目录)`（**不用** `path_safety_check`，因其要求文件存在）。
  3. 从 `config_files[object]` 移除 `config_path`，该对象条目空则 `erase`。
  4. `entry.erase("dirty_mark")` 并置 `changed`（**不触碰 `config_routes`**）。
  5. 仅 `changed` 时 `route_file_write(file_path, json(), entries)` —— 以空顶层标记抹除文件头脏标记。

### 3.4 `Engine/EngineCore/src/core/config/Config_Loader/core/缓存清除.cpp`（T2 / T3，+84 行）

- `route_unload(content, object)`：`content_scan(content.route)` 扫该路由目录下全部路由文件，空则报错返回；逐份调 `route_file_unload(content, file_path, object, json())`（`only_files` 传空 `json` 表示不过滤文件）。
- `config_unload(object, request)`：
  1. `config_files.find(object)` 未命中即报错返回。
  2. `detail::field_check<vector<string>>(request, "files")` 成立时取 `request["files"]` 作 `only_files`，否则保持空 `json`。
  3. `only_files` 为空即 `config_files.erase(object 条目)`；否则按清单逐项 `erase`，条目空则删对象。
  4. 若 `config_routes` 无该对象或为空 → warn「仅清除内存缓存」返回。
  5. 逐个 `content` 扫描其 `route` 目录并调 `route_file_unload(content, file, object, only_files)` 抹除条目标记。

### 3.5 `Engine/EngineCore/src/core/config/Config_Loader/core/事件处理.cpp`（+60 行）

- 新增 7 条 `TEST_F`：
  1. `条目自定义事件名生效` —— 条目写 `Property/Push`、订阅 `Property/Push`，投递 1 次且事件名为 `Property/Push`；
  2. `条目自定义事件名无订阅者被丢弃` —— 条目写 `Property/Push` 但只订阅 `Config/Load`，`acl_set` 无该项 → 0 次；

  6. `配置卸载空载荷全卸载` —— `Config/Unload` 不带 `files` → 该对象全部配置文件缓存被清；
  7. `非法卸载目标被驳回` —— 未缓存对象 / 未缓存目录对 / 缺字段载荷：告警且投递计数不变。
