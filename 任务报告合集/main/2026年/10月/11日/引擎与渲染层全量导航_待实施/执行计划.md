## 一、任务定位

工作站 `项目导航合集/main/` 当前为**空目录**（无任何物理存在的版次导航），需要**完全从零**、以「一个模块一个模块通读源码」的方式，为**当前 HEAD 版次代码**重建一份完整的项目导航。

本轮的硬性取向（用户明确要求，优先级最高）：

1. **绝不参考工作站 git 历史中的任何旧版次导航内容**（不在 HEAD/历史中取出、不阅读、不比对、不复制）。旧导航仅作为「已存在的历史记录」保留其存在事实，不作为本轮知识来源。
2. 所有结论**只以当前工作区源码为准**，逐模块阅读源码后书写。
3. **一次只读一个模块**，读完立即写入对应文件，杜绝一次性读多模块导致上下文膨胀。
4. **本轮全程不向用户提问**（用户将长期离线）。遇「设计意图」「为何如此取舍」「边界行为预期」等源码无法确证的问题时：
   - 统一记录到 `待答疑清单.md`（置于新版次导航目录内，与导航同版次归档）；
   - 正文中在对应位置**就地标记 `【待确认】`** 并附一句成因，先按最佳推断书写；
   - 待用户回归并逐条答疑后，**下一轮对话依据其回答修正导航**并撤除 `【待确认】` 标记。

## 六、每份模块文件的固定章节骨架

依据《agent开发指南·「项目导航」内部文件结构》第 <2> 条，每个模块须含五要素。功能域聚合文件采用「**域概览 + 域内逐模块五节**」组织：

```
# <功能域/模块名>

## 一、模块功能           # 该域/模块的职责定位、在系统中的位置
## 二、模块提供接口       # 对外头文件中的类型、函数签名、语义（按对外/内部区分）
## 三、模块内部架构       # 目录结构、编译单元划分、类与数据结构关系
## 四、模块设计/实现细节  # 关键算法、隐式约定、坑位、错误处理、资源与生命周期策略
## 五、模块运行链路       # 典型调用序列（从入口到出口的分步链路）
```

`项目架构.md` 骨架（依同条第 <1> 项）：

```
## 一、项目目录架构图        # 层级目录树
## 二、项目各模块功能          # 逐模块一句话职责 + 所在文件索引
## 三、项目各模块间交互关系    # 依赖方向图 + 典型跨模块调用链
```

**存疑标注约定**：凡出现「设计意图／取舍理由／边界行为预期」等无法从当前源码百分百确证之处，一律：
1. 正文该处就地书写 `【待确认】<一句话成因>`，并给出最佳推断结论（保证正文可读、不残缺）；
2. 同时在 `待答疑清单.md` 中登记同一条目（编号 + 所在文件 + 上下文 + 待答问题）；
3. 下一轮依据用户回答修正正文并撤除标记。

`待答疑清单.md` 骨架：
```
# 待答疑清单 · 引擎与渲染层全量导航

> 本清单收录本轮导航构建中无法从源码确证的问题。用户逐条答疑后，下一轮据此修正导航正文并撤除【待确认】标记。
```

## 七、执行方式与上下文控制

1. **每模块闭环**：`Read/Glob/Grep 单个模块目录 → 分析 → 写入对应 .md`，单模块完成后再进入下一模块。
2. **禁止跨模块预读**：不提前批量读取下一模块源码。
3. **写入策略**：聚合文件（如工具集、空间系统）先落骨架，再随模块阅读逐节追加，避免一次性重写整份大文件。
4. **提问转记录**：涉及「设计意图」「为何如此取舍」「边界行为预期」等源码无法直接回答的问题，**不向用户提问**（用户长期离线），一律按第六节「存疑标注约定」写入 `待答疑清单.md` 并在正文就地标 `【待确认】`。
5. **临时文件**：如需临时脚本/中间产物，一律放工作站 `_临时/`，任务收尾时清理（不清理可复用的构建入口脚本）。
