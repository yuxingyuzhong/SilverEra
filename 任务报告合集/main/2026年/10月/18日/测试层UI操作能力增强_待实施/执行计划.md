## 一、任务与目标

把测试层「选完就跑、窗口随即销毁」的一次性选择窗，改为**常驻操作界面**：同进程内可反复跑多轮测试、实时看进度与结果、按结果再决策，并**在界面内直接看到 gtest 输出**（不再需要切回控制台）。

已由用户裁定的四项能力（全做）：

| 能力 | 内容 |
| --- | --- |
| 运行控制 + 进度 | 运行选中 / 重跑失败 / 清空结果；进度条 + 实时计数（通过 / 失败 / 跳过 / 耗时） |
| 结果表 + 失败详情 | 每用例状态与耗时列表、失败消息展开、「只看失败」过滤 |
| 多轮 + 轮次历史 | 同界面内连续跑 N 轮或逐轮手动触发；每轮汇总入轮次历史 |
| 引擎日志面板 | 界面内显示引擎日志尾部（读日志屏蔽输出的文件） |

用户追加要求：**gtest 输出入界面** —— 界面模式下把 gtest 的 `[==========] / [----------] / [ RUN ] / [ OK ] / [ FAILED ] / [ PASSED ]` 流与失败详情**镜像**到界面内滚动面板。

## 五、关键实现方式

1. **结果采集**：自实现 `TestEventListener`，覆写 `OnTestStart` / `OnTestEnd` / `OnTestPartResult` / `OnTestIterationStart` / `OnTestIterationEnd`；结果与输出分别写入两个互斥保护的容器。
2. **输出镜像**：同监听器内按 gtest 控制台风格格式化（`[ RUN ] 套件.用例`、`[ OK ] … (N ms)`、`[ FAILED ] …`、轮次起止与总计），失败详情取自 `TestPartResult`。界面模式启动时 `Release` 默认打印器（并销毁），使控制台不再重复输出；**无头模式不做任何此类改动**。
3. **多轮**：每轮前设 `GTEST_FLAG(filter) = 本轮过滤串`、`GTEST_FLAG(repeat) = 1`，然后调一次 `RUN_ALL_TESTS()`（与 gtest 自身 `--gtest_repeat` 同法）；轮次汇总由 `OnTestIterationEnd` 落表。
4. **线程与不冻结**：一轮在工作线程执行；界面线程每帧加锁取**最小快照**（状态枚举 / 计数 / 输出新增行数 / 轮次尾巴），不做拷贝大对象。「停止」置"本轮结束后不再排队"标志。
5. **引擎日志面板**：增量读 `Application/Test/out/引擎运行日志.txt`（记录已读偏移），只读不写。
6. **串味防护**（详见风险）：每轮开始前由界面侧显式复位的项目（如过滤串、`break_on_failure`、`shuffle` 等 flag）统一在"新一轮准备"函数里设置，避免轮间残留。

## 七、风险与限制（须用户知悉）

1. **无中途取消**：gtest 不提供运行中取消能力 → 「停止」只保证"本轮跑完、不再排队下一轮"；强杀会破坏 gtest 状态，不做。
2. **轮间状态残留**：引擎全局（日志系统、事件系统、对象池）与 gtest 静态量在多次 `RUN_ALL_TESTS` 之间可能残留（例如日志规则、事件端口绑定）。阶段 3 需逐项实测；若发现确凿残留，按"每轮显式复位"处理，必要时单列问题清单交用户裁定。
3. **工作线程与引擎全局的交互**：测试逻辑仍在**单线程**内跑；界面线程只读快照、不触碰引擎对象，故不引入引擎侧多线程访问。日志系统本身带锁，可安全地被工作线程写入。
4. **输出镜像的风格差异**：自实现格式化与 gtest 默认打印器可能有细微差异（例如着色、百分比格式）；界面模式下控制台将不再打印，属预期。
5. **非 ASCII 路径**：不使用 gtest 的文件型输出，规避其在该路径下写文件失败的问题。
6. **前置阻塞**：本任务依赖引擎 WIP 收口与测试层对齐，若引擎接口再次变动，阶段 0 需重做。
