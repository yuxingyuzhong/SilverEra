## 三、新增用例与断言口径

| 用例 | 步骤与断言 |
| --- | --- |
| `不透明档忽略源alpha` | 2×2 全 `(255,255,255,128)` 纹理 + 覆盖视口中央的四边形 → 中心**颜色三通道 ≥ 250**（源 alpha 未参与混合，颜色仍为实白）；**alpha 原样写出**（第 4 字节 ∈ [120,136]）；角落仍为清屏色 |
| `alpha档产生半透明叠加` | `blend_mode_set(Alpha)` → 中心**颜色三通道 ∈ [100,240]**（严格介于清屏色与纹理白之间，证混合真实发生）；混合后 alpha ∈ [180,205]（≈0.75 → 191）；角落仍为清屏色 |
| `切回不透明档后恢复实白` | 第一帧 alpha 档中心 ≤ 240 → `blend_mode_set(Opaque)` → 第二帧中心颜色三通道 ≥ 250（**档位可往返**，重建后不留残档） |

**格式无关性**：混合在 sRGB 附件下于**线性空间**进行再编码回 sRGB，故半透明期望值随附件传输函数不同（sRGB 附件 ≈ `192/192/196`、非 sRGB ≈ `134/134/141`）——用例用**区间**判定；颜色三通道与 alpha **分离断言**（`color_min` 只看前三通道），因为不透明档下写出的 alpha 是 128、并非 255。

## 六、本轮踩坑与可供重开发的关键细节

1. **`std::min({...})` 在本层不可用**：测试层包含链里存在 `min` 宏（Windows 头），`std::min({a,b,c})` 被宏展开后产生 `C2589: "(": "::" 右边的非法标记` 与随后的连锁语法错误；改用显式比较（或 `(std::min)(...)` 形式）。
2. **alpha 断言不能取「四通道最大值」**：不透明档下写出的 alpha = 源 alpha（128），取四通道最大值得到的是颜色 255，断言会误判；alpha 在 BGRA 与 RGBA 下**均恒为第 4 字节**，直接取下标 3。
3. **混合档必须在交换链重建处一并传递**：`pipeline_rebuild` 重建时会以传入档位为准，若重建调用处不传当前档位，交换链重建（如窗口缩放）会把已切好的混合档静默退回 `Opaque`——本轮已把两处调用改为带 `impl->blend_mode`。
4. **切档代价**：`pipeline_rebuild` 内部先 `vkDeviceWaitIdle`，故应在**帧与帧之间**调用；同档重复设置为空操作。
5. **公共面类型落点**：新增公共枚举不放在 `管线.h`（含 Vulkan），而放在 Vulkan-free 的 `Pipeline/管线数据.h`，由门面公共头包含 —— 保持「层外看不到 Vulkan 类型」。
