## 三、测试用例（Test 层，像素回读验收）

夹具 `Renderer_Blend_Test`（隐藏窗口 64×36 + 复用上一轮回读范式）：

| 用例 | 步骤与断言 |
| --- | --- |
| `不透明档忽略源 alpha` | 生成 2×2 全 `(255,255,255,128)` 纹理并绑定 → 不设档（默认不透明）→ 四边形覆盖视口中央 → 回读：**中心四通道均 ≥ 250**（alpha 被忽略，画成实白） |
| `alpha 档产生半透明叠加` | `blend_mode_set(Alpha)` → 同纹理同四边形 → 回读：**中心四通道最小值落在 [100, 240]**（严格介于「清屏色」与「纹理白」之间，证混合真实发生；对 sRGB 与非 sRGB 附件均成立） |
| `切回不透明档恢复` | `blend_mode_set(Opaque)` → 同帧重跑 → 中心四通道回到 **≥ 250**（档位可往返，且重建后不留残档） |

口径说明：断言仍为「通道序无关 ＋ 容差」，不依赖表面格式；半透明期望值在 sRGB 附件下约 `192/192/196`、非 sRGB 附件下约 `134/134/141`，故用区间判定。

## 四、EXT-02 显式检查（用户本轮要求）

**问题**：引擎层改公共 API 后，测试层不重配就发现不了断裂（上一轮 `order_set` 断裂即潜伏至重配才暴露）。

**方案（本轮落地）**：新增工作站脚本 `检查/下层与测试层同步检查.ps1`，把「引擎层源码版本 ↔ 测试层能否编译」变为**一条显式命令**：
1. 设置 `TMP`/`TEMP` 为纯 ASCII 目录、进入 VS 开发人员环境、`chcp 65001`（沿本机既有口径）；
2. **重建下层 `Engine/EngineCore`**（刷新其对外头快照）；
3. **重配 + 构建 `Application/Test`**；
4. 任一步失败即以非零退出码结束并输出「引擎层 API 与测试层不同步，请迁移测试层」的明确结论。
每轮开发任务收尾必跑一次（本轮即以它替代常规测试层构建步骤），使同类断裂**当轮即被捕获**。

## 六、风险与申报

1. **sRGB 附件下混合在「线性空间」进行**：期望值随附件传输函数不同，故用例用区间断言而非定值；不依赖格式。
