### 2.2 关键设计
1. **只有一条绘制路径**：管线恒定声明实例属性，故**任何**合法绘制项都必须绑定有效实例缓冲；`mesh_draw` 即以 `instanceCount = 1` 的实例化绘制呈现（模型矩阵等价于原来的推送常量）。这消除了「非实例 / 实例」两套语义并存的不变量风险。
2. **实例缓冲归属**：放在门面实现体、**按帧槽**主机可见缓冲（与场景 UBO 同构），容量 256 个矩阵；本帧全部实例矩阵按登记顺序连续存放，**一次 `buffer_write`** 即完成，各渲染项只携带「句柄 ＋ 字节偏移 ＋ 实例数」。
3. **容量语义**：超过容量**整体拒绝**（`mesh_draw_instanced` 返回假且不登记半截绘制项），不静默截断。
4. **推送常量**：管线布局仍保留推送常量范围（未用），`Frame_Render_Item` 的 `push_constants` / `push_constant_size` 字段保留但现由门面置零（不再推送）。

## 六、可供重开发的关键实现细节

1. **实例路径不变量**：管线恒定声明 `binding 1`，任何绘制项都须给实例缓冲；`command_record` 的缺失判据已含「实例缓冲为空或实例数 0 → 跳过」。
2. **实例矩阵写入时机**：`frame_render` 在填装描述符集之前一次性写入该帧槽实例缓冲（`buffer_write` 一块连续数据），故各渲染项偏移在登记时即确定，写入顺序与帧槽无关。
3. **mip 生成的布局账**：`UNDEFINED → TRANSFER_DST`（上传）→ `SHADER_READ`；生成时逐级 `SHADER_READ → TRANSFER_SRC`（源）与 `UNDEFINED → TRANSFER_DST`（目标）→ blit → 目标回 `SHADER_READ`；循环末第 0 级 `TRANSFER_SRC → SHADER_READ`。视图必须覆盖全部级，否则采样器取不到低级别。
4. **采样器与描述符集的耦合**：采样器句柄被烘焙进各帧槽 `set1`，故状态切换必须重新绑定纹理；门面用 `bound_texture_request` 复现最后一次绑定。
5. **外部库落地口径**：`STB_IMAGE_IMPLEMENTATION` 只在 `纹理解码.cpp` 定义，且以 `#pragma warning(push/pop)` 抑制第三方头告警（本层要求零本层新增警告）。
6. **测试层两个易错点（沿用）**：`std::min({...})` 会被包含链中的 `min` 宏破坏（C2589）；颜色断言须与 alpha 分离且通道序无关（alpha 恒为第 4 字节）。
