## 一、本轮方向（由 agent 自主择取）

**帧颜色附件像素回读**——把每帧最终颜色附件拷回主机内存，形成「截图 / 像素级验收」能力。

择取理由：

1. **前置性**：渲染层此前所有图形特性（纹理、网格、深度、动态渲染、UI 通道）只能靠「跑帧不崩」间接验证，**无法断言任何像素**。后续候选方向（实例化绘制、alpha 混合、多材质/多管线、离屏目标与后处理、文字渲染、纹理解码、mipmap）**全部只能在有像素断言的前提下才谈得上验收**。故本轮先补验收底座，再谈特性扩张。
2. **自身即能力**：回读同时是「运行时截图 / 逐帧像素回归」的正式接口，非一次性测试脚手架。
3. **边界可控**：不改渲染流程时序（拷贝插在同一命令缓冲内、提交前），不引入新线程、不引入外部库。

## 四、实现方式（分段）

### 阶段 A：交换链图像用法
`usage = (COLOR_ATTACHMENT | TRANSFER_SRC) & supportedUsageFlags`；若求交后不含 `TRANSFER_SRC`，仍按原样建链并置能力标志为假、`logger.warn`（回读不可用时上层优雅失败，不影响原有渲染）。

### 阶段 B：帧模块回读链路
1. `Frame_Context` 增 `Memory_Context* memory`（`build` 入参，新增一条 Frame → Memory 依赖边）。
2. 回读缓冲：主机可见（随机读写，非顺序写优化）、`TRANSFER_DST` 用途；尺寸 = `extent.width × extent.height × 4`；按需创建，交换链重建导致尺寸变化时先销毁再重建。
3. `Frame_Readback_Request`：`pixels` / `capacity` / `width_out` / `height_out` / `bytes_out`；空指针表示本帧不回读。
4. `render(...)`：录制前按请求让缓冲就绪并把它交给 `command_record`；提交并呈现成功后 `vkWaitForFences` 本帧槽栅栏（拷贝与渲染同在一个命令缓冲，栅栏发出即数据就绪）→ `memory->buffer_read` → 回填宽高字节数。
5. 命令录制：UI 阶段结束后，若有回读缓冲，则
   - 屏障 `COLOR_ATTACHMENT_OPTIMAL → TRANSFER_SRC_OPTIMAL`（src: `COLOR_ATTACHMENT_OUTPUT`/`COLOR_ATTACHMENT_WRITE`；dst: `TRANSFER`/`TRANSFER_READ`）
   - `vkCmdCopyImageToBuffer`（aspect=COLOR、mip 0 / layer 0、紧排、`imageExtent` = 交换链范围）
   - 末段呈现转换 `oldLayout` 取 `TRANSFER_SRC_OPTIMAL`（src: `TRANSFER`/`TRANSFER_READ`）
   - 无回读时保持原 `COLOR_ATTACHMENT_OPTIMAL → PRESENT_SRC_KHR`（行为与 `b2ffe50` 逐字节一致）
6. `destroy()`：先等设备空闲（沿用既有次序），再销毁回读缓冲。

### 阶段 C：门面公共面
```cpp
//每帧推进（可选：把本帧颜色附件回读到 readback_pixels；capacity 不足则报错返回假，不推进帧）
bool frame_render(uint8_t* readback_pixels = nullptr, uint32_t readback_capacity = 0,
                  uint32_t* readback_width = nullptr, uint32_t* readback_height = nullptr);
//是否支持像素回读（交换链图像具备 TRANSFER_SRC 用法）
bool readback_supported(void) const;
```
Vulkan-free：只出现 `uint8_t*` 与 `uint32_t*`。

### 阶段 D：测试用例（`Application/Test/src/单元测试/渲染/渲染像素回读测试.cpp`）

| 用例 | 断言要点 |
| --- | --- |
| 未初始化回读失败 | `init` 前调用返回假；`readback_supported()` 假 |
| 容量不足被拒 | 传入小于 `宽×高×4` 的缓冲 → 返回假，且 `frame_count()` 未推进 |
| 清屏色回读正确 | 320×180 隐藏窗口推进一帧，回读中心像素四字节**排序后** ≈{13,13,26,255}（对 BGRA/RGBA 通道序与 UNORM 取整均鲁棒），宽高回填正确 |
| 白纹理四边形回读 | 默认相机（+Z 3 单位、60°）+ NDC 四边形覆盖视口中央，中心像素近白（≥250），角落为清屏色 |
| 棋盘格纹理回读 | 绑棋盘格，回读中同时存在近白与近黑像素（≥2 种颜色），证纹理采样与网格绘制真实发生 |

说明：断言一律按「通道序无关 + 容差」编写，避免依赖具体表面格式；`readback_supported()` 为假时用例 `GTEST_SKIP`（不掩盖失败，仅适配无 `TRANSFER_SRC` 的极端驱动）。

## 六、风险与申报

1. **交换链 `TRANSFER_SRC` 可能不受支持**（个别驱动能力位不含它）：已在阶段 A 置能力标志 + 门面暴露查询，用例以 `GTEST_SKIP` 兜底，不影响原有渲染路径。
2. **回读引入帧内同步点**（等本帧栅栏）：只发生在**显式传缓冲**的帧，未传的帧路径零改动、零额外等待。
3. **新增依赖边 Frame → Memory**：仅为回读缓冲的创建 / 销毁；导航须同步记录该边。
4. **像素断言依赖表面格式通道序**：一律用「排序 + 容差」规避。
5. 渲染层仓库**无远程配置**（存量外部问题），本轮提交仍只落本地，登记入「渲染层外部问题汇总.md」。
