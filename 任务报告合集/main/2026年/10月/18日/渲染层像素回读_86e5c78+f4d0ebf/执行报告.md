## 三、新增用例与断言口径

| 用例 | 断言 |
| --- | --- |
| 未初始化回读失败 | 未 `init` 时带回读参数推进返回假；`readback_supported()` 假 |
| 容量不足被拒且不推进帧 | 传入 16 字节缓冲 → 返假、`frame_count()==0`、尺寸出参为零 |
| 回读清屏色正确 | 尺寸回填 = 64×36；左上 / 右下 / 中心三点为清屏色且**整帧三色一致**（清屏为纯填充） |
| 白纹理四边形中心覆盖角落留空 | 中心四通道 ≥ 250（纹理白落地）；左上角仍为清屏色 |
| 棋盘格纹理回读呈现多色调 | 去重颜色数 ≥ 3；存在四通道最小值 ≥ 60 的像素（纹理亮色，明显亮于清屏色） |

**格式无关性**（本轮踩坑与修正）：

- 首轮断言按「UNORM 清屏色 ≈ 13/13/26/255」硬编码 → 两条用例失败。实测本机交换链为 **sRGB 附件**，清屏色 `0.05/0.05/0.10` 经 sRGB 传输函数编码后为 **≈63/63/89**。
- 修正为**双候选 + 容差 ±4 + 通道排序**：`CLEAR_CANDIDATES = { {13,13,26} , {63,63,89} }`，逐候选比对排序后的前三个通道并校验 alpha ≥ 250。据此对 **B8G8R8A8 / R8G8B8A8、sRGB / UNORM 四种组合**均成立（断言与表面格式解耦）。
- 棋盘格用例同时说明：非 sRGB 附件下深色（0x40 → 线性 0.0509 → 130 附近）与清屏色高通道（26）可能接近，故用「去重颜色数」而非「与清屏色取色比对」判定。

## 五、可供重开发的关键实现细节

1. **回读时机**：拷贝与渲染录在**同一命令缓冲**内（`vkCmdEndRendering` 之后、呈现转换之前），故本帧槽栅栏发出即代表像素已落入回读缓冲——不需要额外信号量或第二次提交；`readback_read` 里的 `vkWaitForFences` 是**显式请求回读的帧才付**的同步代价，未请求的帧路径零额外等待。
2. **布局账**：引入回读后颜色附件的布局链为 `UNDEFINED → COLOR_ATTACHMENT_OPTIMAL → TRANSFER_SRC_OPTIMAL → PRESENT_SRC_KHR`；无回读时保持 `UNDEFINED → COLOR_ATTACHMENT_OPTIMAL → PRESENT_SRC_KHR`。
3. **缓冲归属**：回读缓冲由**帧模块**持有（`Frame_Context::readback_buffer/alloc/size`），尺寸 = `宽 × 高 × 4`，容量不足即销毁重建（交换链放大时自然生效），`destroy` 时归还；此设计新增一条依赖边 **Frame → Memory**（此前帧模块不认识内存模块）。
4. **能力降级**：交换链图像若不含 `TRANSFER_SRC`（极端驱动），建链照常进行、`readback_supported()` 返假、`frame_render(...回读)` 返假并告警；用例以 `GTEST_SKIP` 兜底。
5. **门面语义**：`frame_render` 回读参数**全为默认参数**，既有 35 例渲染用例与 Test 层其余调用点**零改动**即通过。
