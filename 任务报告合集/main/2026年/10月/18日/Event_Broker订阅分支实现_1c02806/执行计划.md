## 四、设计依据（现状核对）

1. 上一版（`af3c077`）中，订阅清单由 `attach(subscriber, needed_events, receiver)` 一次性灌入
   `acl_set`；本版 `attach` 已改为 `(subscriber, acl_key, receiver)`，只登记「订阅者名 ↔ 权限密钥」
   （`mapping`）与接收入口（`receivers`），**订阅清单的登记职责改由 `Add` / `Remove` 事件承担** ——
   这两个空分支正是该职责的落点，故本次补全属该重构的必要收尾。
2. 分支上下文已具备，无需另建校验：
   - `config["object"]`：目标订阅者名，已由 `detail::field_check<string>` 校验；
   - `config["acl_key"]`：目标权限密钥，已由 `detail::field_check<string>` 校验；
   - 目标订阅者存在性（`mapping` 查表）与密钥比对（`suscriber_key == config["acl_key"]`），
     且不匹配时已 `logger.error` 驳回。
3. 订阅清单字段（用户指定）：`config["subscribed_events"]`，**数组形式**。
   本计划按「每项为 `{"category": ..., "tag": ...}` 对象」实现；若元素结构另有约定，请在验收时指出。
4. 字段校验工具：`engine::detail::field_check<T>`（`tools/Detail/json字段可用性校验.h`，
   经 `数据校验工具.h` 聚合；该头已在本版被 `事件中转器.h` 引入）。

## 五、实现方式

### Add 分支（订阅事件添加）

1. 校验 `config["subscribed_events"]` 字段存在且为数组，否则 `logger.warn` 并返回。
2. 逐项校验元素的 `category` / `tag` 为非空字符串，不合格项 `logger.warn` 后跳过（不影响其余项）。
3. 以 `(category, tag)` 构造 `Event_Identity`，向 `acl_set[identity]` 追加本订阅者权限密钥；
   **先查重**，已授权即跳过（与旧 `attach` 的去重口径一致）。
4. 全部项处理完毕后打印一条 `logger.info`。

### Remove 分支（订阅事件移除）

1. 同 Add 的第 1、2 步。
2. 以 `Event_Identity` 在 `acl_set` 中查找；该标识未登记任何订阅者时 `logger.warn` 并跳过该项。
3. 在该标识所辖权限密钥列表中定位本订阅者并移除；未授权则不做处理。
4. 全部项处理完毕后打印一条 `logger.info`。

### 边界与取舍

- `(分类, "All")` **允许**经 `Add` 登记，作为「整分类满订」入口，与 `receive` 满订广播口径一致。
- `Remove` 后若列表清空，**不删除** `acl_set` 的键，与既有 `Detach` 分支口径一致
  （避免改变 `receive` 的「事件标识未注册」判定语义）。
- 不改动 `process` 其余分支，包括既有 `if (!evt)` 只告警未 return 的疏漏（不在本次范围）。
