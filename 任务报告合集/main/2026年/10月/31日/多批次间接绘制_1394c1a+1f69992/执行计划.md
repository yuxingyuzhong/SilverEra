# 执行计划 · 第 252 轮　多批次间接绘制（间接命令录制 ＋ 连续项合批）

- 日期：2026-10-31　方向一（Compute 管线 ＋ GPU 驱动渲染）阶段 B 收尾轮
- 目标：把「逐项 `vkCmdDrawIndexed`」升级为「连续兼容项合并成一条间接绘制命令」，为阶段 C 的 GPU 写 count（`drawIndirectCount`）预留接口；默认关闭，关闭时画面逐字节不变。

## 分段

### A 帧模块：间接录制上下文（约 8 分钟）

1. `Frame/帧上下文.h` 新增 `Indirect_Record_Context`（映射指针、命令容量、命令游标、命令缓冲、本帧命令数、实例缓冲步长 80）与 `indirect_context_set` / `indirect_draws_get` / `indirect_commands_get`。
2. 关闭 / 容量不足 / 非连续兼容段时回落逐项直接绘制，行为与现状完全一致。

### B 帧模块：`items_record` 合批（约 12 分钟）

1. 相邻项满足「同管线、同布局、同描述符集、同推送常量、同顶点 / 索引缓冲与索引区、同实例缓冲、实例区字节连续」时合并为一条 `VkDrawIndexedIndirectCommand`：
   `index_count / 合并后的 instance_count / first_index=0 / vertex_offset=0 / first_instance=首项实例偏移 ÷ 80`。
2. 合并段以实例缓冲偏移 0 绑定顶点缓冲（`first_instance` 承担偏移语义），逐字节等价于逐项绑定 `instance_offset` 后 `firstInstance=0`。
3. 每个合并段以 `vkCmdDrawIndexedIndirect(cb, buffer, 命令偏移, 1, 20)` 下达；单一 Vulkan 1.0 命令，无需 `multiDrawIndirect` 特性。
4. 统计：`indirect_draws` 累计实际间接调用数，`Recorded_Counts` 口径不变（仍按项数与实例数计）。

### C 门面与资源（约 12 分钟）

1. `Renderer_Config` 增 `gpu_indirect_enable`（默认 false）。
2. 每帧槽一条主机可见间接缓冲（容量 4096 条 × 20 字节），初始化创建、shutdown 回收；`Memory_Context` 增 `buffer_map` / `buffer_unmap`。
3. 录制前设置间接上下文（启用且特性可用）；`Frame_Stats.indirect_draws` 回填；并行分段录制时禁用间接（避免多线程争用同一映射区），自动回落逐项绘制。
4. `Renderer::gpu_indirect_supported()` 返回 `multiDrawIndirect` / `drawIndirectCount` 两项探测结果（供 253 之后的 GPU count 路径使用）。

### D 验证与文档（约 8 分钟）

1. 用例：间接开关开 / 关两帧像素逐字节一致；`indirect_draws > 0`；批次内实例数守恒；非法容量回落。
2. 三树构建零错误；分组回归（计算 / GPU 驱动 / 帧 / 渲染核心）。
3. 1 万实例场景对照 `性能基线_方向一.md` 记录 GPU 帧耗时差值与主机录制耗时差值（无性能面则写明原因）。
4. 执行报告、两份汇总、能力汇总、下轮方向、导航、两份历史、源码统计、工作站提交推送。
