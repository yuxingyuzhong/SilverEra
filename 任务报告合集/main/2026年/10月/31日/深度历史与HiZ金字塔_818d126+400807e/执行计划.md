# 执行计划 · 第 253 轮　深度历史 ＋ Hi-Z 金字塔资源

- 日期：2026-10-31　方向一（Compute 管线 ＋ GPU 驱动渲染）阶段 C 首轮
- 目标：核查现有深度附件的帧槽归属，落地「每帧槽一份深度历史 ＋ 单通道浮点金字塔」资源与深度拷贝录制辅助，为 254（金字塔生成 compute）/ 255（遮挡测试）提供数据底座。
- 口径：新增能力默认关闭，未开启时不分配任何资源、不改动任何既有录制路径，画面逐字节不变。

## 前置核查（§2.4）

1. 交换链路径：`Swapchain_Context` 持 `depth_images / depth_views`（每交换链图像一份），随图像轮转，**不是**每在途帧槽一份；离屏路径的深度归渲染目标自身。
2. 结论：不存在可直接复用的「上一帧深度」。按 §2.4 落地方案二：**每帧槽一份 R32 深度历史纹理 ＋ 每帧槽一份 mip 金字塔**，场景 pass 末尾由帧链路经 `vkCmdCopyImage` 写入历史。

## 分段

### A HiZ 模块与资源（约 15 分钟）

1. 新模块 `src/render/HiZ/`：`HiZ.h` ＋ `局部命名空间使用.h` ＋ `core/HiZ.cpp`。
2. `HiZ_Context`：`build / destroy / valid / extent_set / level_count / level_extent_get`。
3. 每帧槽记录：深度历史图像（格式 = 交换链深度格式，用途 = `TRANSFER_DST | SAMPLED`）＋ 视图；
   金字塔图像（`R32_SFLOAT`，用途 = `SAMPLED | STORAGE`，级数 = ⌊log2(max(w,h))⌋+1，上限 12）＋ 逐级视图（`baseMipLevel = level`）。
4. `history_valid` 逐槽标记（重建 / 尺寸变化即失效，供首帧跳过遮挡）；`history_copy_record` 录制「源深度 → 历史」的屏障 ＋ 拷贝 ＋ 回位，要求源 / 历史格式一致，否则拒绝（降级）。
5. `Memory_Context::image_view_create` 增 `base_mip_level`（默认 0，既有调用逐字节不变），供逐级视图。

### B 门面与生命周期（约 12 分钟）

1. `Renderer_Config` 增 `hiz_enable`（默认 false）。
2. `Impl`：`HiZ_Context hiz` ＋ `hiz_enabled` ＋ `hiz_capable`（初始化时探测 `R32_SFLOAT` 的 `STORAGE_IMAGE | SAMPLED` 格式特性）。
3. 惰性创建：首次 `hiz_enable_set(true)` 调用 `hiz_ensure()`（build 失败仅告警、开关保持关闭）；关闭只置标志，保留资源。
4. 交换链重建后 `hiz.extent_set(...)`；失败则销毁上下文并降级（底层原因见执行报告）。
5. 门面：`hiz_enable_set/get`、`hiz_supported`、`hiz_state_get`、`hiz_level_extent`；shutdown 先于内存模块销毁 HiZ。

### C 用例与验证（约 10 分钟）

1. 新套件 `Renderer_HiZ_Test`（4 例）：
   - 默认关闭且资源惰性（未开启时状态全 0）；
   - 开启后层次 / 尺寸（64×36 → 7 级，逐级尺寸表）；
   - `compute_enable = false` 时 `hiz_supported` 为假且开启失败；
   - 开关切换前后两帧均正常出帧且绘制实例数守恒。
2. 三树构建零错误；分组回归（HiZ ＋ GPU 驱动 ＋ 计算 ＋ 渲染核心）；本轮为阶段 C 首轮，按规则每 3 轮全量（254 后补全量）。
3. 执行报告、两份汇总、能力汇总、下轮方向、导航增量、两份历史、性能基线（本轮无性能面，写明原因）、源码统计、工作站推送。
