## 一、任务概况

- **任务类型**：接口修饰符补全（成员函数尾置 `const`）；**纯签名标注，不改函数体逻辑、不改算法与控制流**。
- **任务原文**：「搜索全项目，给每一个可以加上 const 后缀标签的方法加入 const 标签。这次不需要建立项目导航」。
- **涉及层**：引擎层（47 项）、系统层（20 项）；测试层扫描 **0 项**零改动；游戏层无源码跳过。
- **判定口径（经用户确认）**：只做**零风险 const**——加 const 后无需任何连带调整；需改签名 / 返回类型 / 调用方的**跳过**。
  - 三条判据：(a) 不改非 `mutable` 成员；(b) 不调用仍非 const 的成员函数；(c) 不改变虚函数 / 重载 / 接口。
  - **级联提升**：某函数唯一阻碍是「调用了本批将被 const 化的函数」时一并加（引擎层共 8 项级联：`Quadtree_Manager` 5 项 + `Config_Loader` 3 项）。
- **副作用口径（经用户确认）**：对「不修改本对象、但有副作用」的成员函数（写盘 / 只写出参 / 修改入参）**一并加入**。
- **在建改动口径（经用户确认）**：引擎层 `Event_Terminal/终端接口.h`、`core/终端接口.cpp` 含用户在建改动，**照常加 const，并连同在建改动一起提交**。
