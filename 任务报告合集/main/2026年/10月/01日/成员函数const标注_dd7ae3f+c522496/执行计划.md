## 一、任务目标与边界

- **任务原文**：「搜索全项目，给每一个可以加上 const 后缀标签的方法加入 const 标签。这次不需要建立项目导航」。
- **工作间**：全项目四层（引擎层 / 系统层 / 测试层 / 游戏层）；游戏层当前无源码，自动跳过。
- **不做 PR**：各层在本地 `main` / `test` 分支直接开发，完成后推送对应远端分支。
- **不做项目导航**（用户明确指示：此类小任务不建导航，避免浪费时间）；仅落盘「执行计划 / 执行报告」并更新报告提交历史。
- **判定口径（经用户确认）**：只做**零风险 const**——仅给「加上 const 后无需任何连带调整」的成员函数加尾置 const；需改签名 / 返回类型 / 调用方的**跳过**并单列。
  - 判定三条：(a) 不改非 `mutable` 成员；(b) 不调用仍非 const 的成员函数；(c) 不改变虚函数 / 重载 / 接口。
  - **级联提升**：某函数唯一阻碍是「调用了本批将被 const 化的函数」时，可一并加。
- **副作用口径（经用户确认）**：对「不修改本对象、但有副作用」的成员函数（写盘 / 只写出参 / 修改入参）**一并加入**。
- **在建改动口径（经用户确认）**：引擎层 `Event_Terminal/终端接口.h`、`core/终端接口.cpp` 含用户在建改动，**照常加 const，并连同在建改动一起提交**。

## 三、执行分段

1. **扫描**：逐层扫描自定义类的成员函数，筛出零风险项（引擎 / 系统 / 测试三层并行）。
2. **呈递计划**：以「计划书」形式列清单 + 跳过清单，经用户确认（含 Q1 在建改动、Q2 副作用口径两项提问卡片）。
3. **实施**：按模块声明（对外头 / 函数预声明）与定义（core 下 cpp/hpp）成对加 `const`，逐层构建验证 `error C` = 0。
4. **回归**：测试层重建后跑 `EngineTests.exe`，对比基线。
5. **提交推送**：引擎层 / 系统层 / 顶层快照各一笔提交，显式 refspec 推送；测试层无改动不提交。
6. **收尾**：落盘本报告，更新报告提交历史。（**不建项目导航**）
