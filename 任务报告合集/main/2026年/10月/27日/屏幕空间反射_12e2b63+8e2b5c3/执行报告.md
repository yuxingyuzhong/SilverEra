## 二、根因与修正（本轮最重要结论）

1. **引擎无缺陷**：UBO 的 `view_proj` 由 `camera.view_proj_get`（glm 列主序）直接写入 64 字节，着色器 `inverse()` 与 `scene.view_proj * vec4(...)` 同源。
2. **诊断读数误导**：上一轮把 `abs(normal)` 写入 SRGB 附件后按 R/G/B 顺序解码，得到 `(0.86, 0.51, 0)`；
   实际字节为 `(239,188,0)`，而 sRGB(0.866)=239、sRGB(0.5)=188 → 真实法线 `(0, 0.50, 0.87)`，与 −30° 斜面理论值一致。
   因此「反投影错误」的结论**不成立**，问题在布景与通道序解读。
3. **布景修正**：镜面绕 X 轴 −30°（法线朝相机上方），目标立方体沿反射方向 `(0, 0.8, 0.6)` 放在镜面上方；
   射线在屏幕内命中立方体，取样其明暗不同的颜色。

## 三、着色器要点

| 步骤 | 说明 |
| --- | --- |
| 反投影 | `world = inverse(view_proj) · (ndc, depth, 1)`，NDC 按 [0,1] 深度与 Y 翻转约定线性映射 |
| 法线 | `normalize(cross(dFdx(world), dFdy(world)))`，按「朝向相机」校正符号；导数在统一控制流内求值 |
| 早退 | 强度 0、天空（深度 ≥ 0.9999）、反射进入表面内部 |
| 步进 | 世界空间 8..48 步（`w` 控制），探针投影后比较「探针视深」与「该像素表面视深」，差值 ≤ `y` 判命中 |
| 输出 | 命中即按强度 × 屏幕边缘淡出混合，未命中保持直通 |
