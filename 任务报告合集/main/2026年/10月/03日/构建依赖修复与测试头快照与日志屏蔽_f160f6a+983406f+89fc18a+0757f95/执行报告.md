## 二、任务 1：构建系统问题（增量构建对头文件完全盲区）

### 2.1 根因（全部实测取证）

| 取证项 | 实测结果 |
| --- | --- |
| `引擎层/out/build/x64-Debug/CMakeFiles/rules.ninja` 的 `msvc_deps_prefix` | **GBK 字节**（按 CP936 可解为「注意: 包含文件: 」，按 UTF-8 不可解） |
| `build.ninja` 中的中文路径 | **UTF-8**（按 UTF-8 可解） |
| cl 实际输出的 `/showIncludes` 行 | **UTF-8 字节**（`Start-Process -RedirectStandardOutput` 原始字节捕获单 TU 构建输出，按 UTF-8 可解） |
| 依赖落库情况 | `ninja -t deps <obj>` → **`#deps 0`** |
| 改头重编情况 | 改动两个头后 `cmake --build` 重编 TU 数 = **0**（exit=0） |

**机理**：CMake 探测 `/showIncludes` 前缀时**不带 `/utf-8`**（编译器按系统本地码页输出），而本工程编译**带 `/utf-8`**（编译器输出 UTF-8 字节）。两侧逐字节不等 ⇒ ninja 匹配不到前缀 ⇒ 该对象只记录 `.cpp` 自身 ⇒ 头文件依赖全部丢失。

### 2.2 候选实测结果

| 序 | 候选 | 实测结论 |
| --- | --- | --- |
| A1v3 | `project()` **之后**覆盖 `CMAKE_CXX_CL_SHOWINCLUDES_PREFIX` | **无效**（936 代码页下仍为 GBK）：生成器在 `project()` 内的语言启用阶段已取定前缀 |
| A1v4 | `project()` **之前**把 `/utf-8` 写入 `CMAKE_CXX_FLAGS` 缓存 | **无效**：探测阶段不读 `CMAKE_CXX_FLAGS` |
| A3 | `VSLANG=1033` | **无效**：前缀仍为 GBK（cl 的消息语言不由该变量决定） |
| A6 | 在 CMakeLists 内 `execute_process(cmd /c chcp 65001)` | **无效**：必须在**启动 CMake 之前**设定，进程内切换影响不到子进程 |
| **A2** | **配置阶段本身处于 UTF-8 代码页** | **✅ 生效** |

**A2 验收数据**（`chcp 65001` 后重新配置引擎层）：
- `rules.ninja` 的 `msvc_deps_prefix` 变为 **UTF-8**，与 cl 输出一致；
- `ninja -t deps <obj>` → **`#deps 12`**（依赖列表含 `.h`）；
- touch 底层头 `external/bullet3/src/LinearMath/btScalar.h` → 重编 **119** TU；
- touch 项目头 `src/tools/Detail/文件路径规范化.h` → 重编 **18** TU（精确子集）。

> 注：本 Shell 会话的代码页本身为 UTF-8，曾一度混淆 A2 与 A1v3 的判定；已强制 `chcp 936` 复测，结论如上表。

### 2.3 采用方案与固化

采用 **A2**，并以文字固化（不新建文档）：
- 顶层 `README.md`「五、构建」：新增 `> 配置期必须处于 UTF-8 代码页` 的说明块（含机理、已排除方案、VS 集成未实测的声明）；

**已知限制（如实记录）**：`Visual Studio` 内建 CMake 集成若在非 UTF-8 代码页下配置，仍会丢失头依赖（未实测其行为）；使用该集成时须先 `chcp 65001` 再从该控制台启动，并以 `ninja -t deps` 复核。

## 四、任务 3：屏蔽引擎内置日志

### 4.1 机制

用日志系统既有的**路径节点绑定**：把**根节点 `""`** 绑到一个日志文件流 ⇒ 全部调用处的日志沿父链继承该流，不再落到控制台兜底输出目标（`std::cout`），googletest 的 stdout 因此干净。

### 4.2 实现

| 文件 | 改动 |
| --- | --- |
| `测试层/src/主调/引擎日志屏蔽.h`／`.cpp`（新增） | 对外：`日志屏蔽_开启()`（幂等）、`日志屏蔽_关闭()`、`日志屏蔽_落盘()`、`日志屏蔽_文件路径获取()` |
| `测试层/src/主调/主程序.cpp` | `main` 早期（`SetConsole*` 之后、`InitGoogleTest` 之前）开启屏蔽；两条返回路径（自动化透传／交互）执行后各调一次 `日志屏蔽_落盘()` |
| `测试层/src/单元测试/工具/日志系统测试.cpp` | 夹具 `SetUp` 首行 `日志屏蔽_关闭()`（保证「未绑定 → 走控制台」等 15 个 `Console_Capture` 用例成立）；`TearDown` 末行 `日志屏蔽_开启()`（恢复屏蔽，替代原先裸 `stream_clear("")` 的收尾） |
| `测试层/CMakeLists.txt` | `引擎日志屏蔽.cpp` 编入 `EngineTests`（与 `主程序.cpp` 同法；用例经可执行文件同名符号解析，与 `需要等待退出` 一致） |

日志文件：`测试层/out/引擎运行日志.txt`（可执行文件目录下的构建产物区，不污染层根；每次运行覆盖）。

### 4.3 实现中踩到的两个坑（已修，供后续复用）

1. **不能用日志系统「按文件名绑定」的重载**：`stream_bind(path, file_name)` 内部以**窄字符** `std::ofstream(file_name)` 打开，本机工程路径含中文 ⇒ 打不开 ⇒ 静默回落控制台，屏蔽完全失效（实测 stdout 仍有 244 条引擎日志、日志文件不存在）。改为**自行以 `std::filesystem::path` 打开文件流**（宽字符 API），再走「外部输出流」绑定重载。
2. **`filesystem::path::operator/(const char*)` 按系统本地码页解读**：`exe_dir / "out/引擎运行日志.txt"` 把 UTF-8 中文字节当 GBK 处理，生成了乱码文件名 `寮曟搸杩愯鏃ュ織.txt`。改为 `exe_dir / detail::string_to_path("out/引擎运行日志.txt")`。这与项目须知「UTF-8 中文路径与 `std::filesystem::path` 不兼容」一致。

### 4.4 验收数据

| 验收项 | 结果 |
| --- | --- |
| stdout 中 `[INFO]`/`[WARN]`/`[ERROR]` 行数 | **0**（变更前同一命令为 244 行） |
| 日志文件 | `测试层/out/引擎运行日志.txt` 生成，**10336** 字节，文件名正确 |
