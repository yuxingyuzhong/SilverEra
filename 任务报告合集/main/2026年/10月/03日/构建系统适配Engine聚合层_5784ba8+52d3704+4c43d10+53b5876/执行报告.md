│       ├── cmake/{对外接口,接入下层}.cmake

    ├── Test/                                独立仓库 → 分支 test

## 四、四项任务的实现要点

### 4.1 任务<1>：增删文件与配置同步

保留 `file(GLOB_RECURSE ... CONFIGURE_DEPENDS)`，并在各层 GLOB 之后登记**基点目录**：

```cmake
set_property(DIRECTORY APPEND PROPERTY CMAKE_CONFIGURE_DEPENDS
    "${PROJECT_ROOT_DIR}/src" ...)
```

原理：目录 mtime 变化（增删文件）被 ninja 记为 `build.ninja` 的依赖，构建前自动重跑配置并重扫 GLOB。实测见 §五。

### 4.2 任务<2>：包含前缀

统一「项目根相对全路径」；各层包含根收敛为项目根（`EngineCore` 私有根亦改为项目根，与对外面同写法）。第三方头不受影响。

### 4.3 任务<4>：层间契约扩展（最小必要）

在原有五变量上扩展两个：

| 变量 | 含义 |
| --- | --- |
| `OUT_LIB` | 由单库名改为**分号列表**（聚合层转发 `EngineSystem;EngineCore`；非聚合层仍为单元素） |
| `OUT_LIBDIR` | 与 `OUT_LIB` 一一对应的「该库所在层目录」，供自动探测；可选，缺省为本层目录 |

`byjy_jieru_xiaceng()` 相应改为**逐库**定位并建立 `IMPORTED STATIC GLOBAL` 目标；覆盖变量按元素下标逐项对应（元素个数须与 `OUT_LIB` 等长，否则硬失败）。三级策略（覆盖优先 → 自动探测最新 → 硬失败）与「绝不回退编下层源码」保持不变。

### 4.4 头快照：把「快照根」作为消费层自身包含目录（关键修正）

初版把「导入目标对外面里的项目根」换成快照根，结果 `-I` 次序成了 **项目根 → 快照根**；实测 `compile_commands.json` 证实快照被源码树**旁路**。

原因：MSVC 下目标自身的包含目录（`-I`）恒在导入目标传递来的 `/external:I` **之前**；一旦项目根只剩「自身包含目录」一个来源，它反而排到了快照之前。

修正后的做法：**不动导入目标对外面**，而是由消费层把下层快照根解析出来、作为**自身包含目录**列出，并排在项目根之前：

```cmake
byjy_tou_kuaizhao_gen(BYJY_CORE_SNAPSHOT   EngineCore)     # 解析并硬失败校验
byjy_tou_kuaizhao_gen(BYJY_SYSTEM_SNAPSHOT EngineSystem)
set(BYJY_APP_INC "${BYJY_CORE_SNAPSHOT}" "${BYJY_SYSTEM_SNAPSHOT}" "${BYJY_PROJECT_ROOT}")
```

由此 `接入下层.cmake` 的辅助函数由「两个映射函数」简化为一个 `byjy_tou_kuaizhao_gen(out_var, imported_target)`。

快照镜像范围同时收窄为各层自有头（`common`、`src`）：第三方在外对面上是独立的绝对路径条目、不经过快照解析，无需逐头复制（省掉 bullet3/glfw 上千个头的复制）。

### 6.1 顶层仓库模型的既成事实（重要）

git **不会收录「目录内含自身 `.git`」的文件**。四层各自成为独立仓库后，顶层 `main` 再也不能收录各层源码——此前能收录，是因为那些文件在层内出现 `.git` 之前就已入库（本次尝试补录时，`git add Engine/EngineCore/src` 等路径被静默跳过，`git ls-files --cached -- Engine/EngineCore` 为 0）。

用户裁定后，顶层定为**总览线**：顶层 `main` 现只跟踪

```
.gitignore
Engine/CMakeLists.txt            （Engine/ 无嵌套 .git，可正常跟踪）
Engine/cmake/对外接口.cmake
Engine/cmake/接入下层.cmake
LICENSE
README.md
```

各层源码由 `engine` / `system` / `test` / `game` 四分支承载；顶层的工作区会持续显示 `?? Engine/EngineCore/` 等三条未跟踪项——这是 git 对「内嵌仓库」的正常报告，不是遗漏。**注意：顶层 `main` 的这次推送会从远端 main 上移除 `引擎层/…` 等旧路径**，故已按「先推四层分支、再推顶层」的顺序执行，保证远端先拿到新源码。
