## 二、与《执行计划》的偏离（共 6 处，均已落地）

> 本《执行计划》见同目录 `执行计划.md`；下列偏离以「计划原文 → 实际做法」记录，便于回溯。

### 偏离 1（用户指示）：层拓扑由「接 Engine 聚合面」改为「只接 EngineCore 单层」

- 计划原文：§二.7「只接一次 Engine 聚合面（转发 `EngineSystem.lib` ＋ `EngineCore.lib`）」。
- 用户原话：`话说你现在也用不到EngineSystem吧？为什么要编译它？直接拿EngineCore已经生成好的静态库不好吗？`
- 实际做法：本层对外面 = 本层自有面 ＋ **EngineCore 单层**对外面。
  - `Application/Renderer/cmake/对外接口.cmake` 的 include 目标由 `Engine/cmake/对外接口.cmake` 改为 `Engine/EngineCore/cmake/对外接口.cmake`；全部 `${BYJY_ENGINE_OUT_*}` → `${BYJY_ENGINE_CORE_OUT_*}`。
  - `Application/Renderer/CMakeLists.txt` 的接入调用改为 `byjy_jieru_xiaceng(<项目根>/Engine/EngineCore/cmake/对外接口.cmake BYJY_ENGINE_CORE BYJY_ENGINE_CORE_LIB_PATH)`；头快照只解析 `EngineCore`；`target_link_libraries` 去掉 `EngineSystem`。
- 理由：渲染层与实体/属性/效应无关，公共头不出现 `EngineSystem` 类型；接聚合面只会把 `EngineSystem.lib` 拖成链接依赖，并让「`EngineSystem` 未跟上 `EngineCore` 重构」直接堵死渲染层构建。
- 可逆性：以后真需要用 `EngineSystem` 时，把 include 目标换回 `Engine/cmake/对外接口.cmake`、同步 CMakeLists 第 1、1.5、3 三处即可（代码注释中已标明）。

### 偏离 2：取消「先补建 `EngineSystem` 的 `x64-Release` 树」

- 计划原文：§十.7 与 §九「前置：先补建 `Engine/EngineSystem` 的 `x64-Release` 树」。
- 实际做法：**不建**。既然只接 `EngineCore`，渲染层 Release 树只需 `EngineCore` 的 `x64-Release/lib/EngineCore.lib`（已存在）。
- 附带结果：`Engine/EngineSystem` 至今仍只有 `x64-Debug` 树，本轮未产出其 Release 库。

### 偏离 3（重要修复）：SDL3 裁剪口径由「vcxproj 并集」改为「并集 ＋ 全量头 ＋ 引号包含闭包」

- 计划原文：§五「保留 `src/` 中 `VisualC/SDL/SDL.vcxproj` 文件清单（`ClCompile` ＋ `ClInclude`）所列的全部文件」，并称「裁剪后 `external/SDL3/src` 恰好只余该集合，`CMakeLists.txt` 直接 `file(GLOB_RECURSE)` 即可」。
- 问题：该口径**漏掉了大量被 `#include` 相对引入、但未列在 vcxproj 里的头文件**，构建以两种方式连爆：
  1. `src/SDL_internal.h(260): fatal error C1083: 无法打开包括文件 "SDL_utils_c.h"`（235 个 C 文件几乎全灭）；
  2. `src/hidapi/SDL_hidapi_windows.h(70): fatal error C1083: 无法打开包括文件 "windows/hid.c"`（**非头文件**也能被 `#include` 引入）。
- 实际做法（工作站的 `临时/SDL3_trim_v2.ps1`，从原始源码 `D:\rely\SDL-release-3.4.18` 重建目标目录）：
  - 保留 `include/**` 全部；
  - 保留 `src/**` 下**全部头文件**（`.h/.hpp/.hxx/.inc`）；
  - 保留 vcxproj 枚举的全部路径（并按存在性过滤：官方工程里有 3 条路径在发布包中不存在——`src/haptic/SDL_hidapihaptic.h`、`src/video/khronos/vulkan/vk_sdk_platform.h`、`src/video/windows/SDL_surface_utils.h`）；
  - 再对**引号 `#include` 做闭包**（相对 includer 目录、并回退 `src/`），把被引入的实现体也补回；
  - 其余删除；顶层只留 `include/ src/ LICENSE.txt`。

### 偏离 4（重要修复）：SDL3 编译集合由 GLOB 改为**显式清单**

- 原因：`src/` 下并非每个 `.c` 都是独立编译单元。SDL3 把 6 个平台实现体当作「被 `#include` 的头」使用：
  `src/hidapi/{libusb,linux,mac,netbsd,windows}/hid.c`、`src/hidapi/windows/hidapi_descriptor_reconstruct.c`。
  GLOB 会把它们同时编成独立 TU，与「被包含进去的那份」**符号重复定义**。
- 实际做法：新增生成物 [`Application/Renderer/cmake/SDL3源文件列表.cmake`](../../../../代码存储/代码仓库/白银纪元/Application/Renderer/cmake/SDL3源文件列表.cmake)（变量 `BYJY_SDL3_SOURCES`，236 条，相对本层根目录），`CMakeLists.txt` 第 2 节 `include` 它并补成绝对路径；`SDL3/src` 也不再登记 `CMAKE_CONFIGURE_DEPENDS`。
- 附带结果：`external/SDL3/src` 下同时存在「已编译的 236 个 TU」与「6 个仅作被包含负载的文件」，后者留树不编译。

### 偏离 5：新增归档响应文件 BOM 包装器接线（计划 §七.9 的具体落地）

- 现象：SDL3 全部编完后，归档阶段 `LINK : fatal error LNK1181: 无法打开输入文件 "CMakeFiles\RendererCore.dir\src\render\Renderer\core\VMA瀹炵幇.cpp.obj"`（乱码即 UTF-8 字节被当 GBK 读，`瀹炵幇` = `实现`）。
- 根因：Ninja 生成的归档响应文件 `CMakeFiles/RendererCore.rsp` 是 **UTF-8 无 BOM**，MSVC `lib.exe` 无 BOM 时按系统 ANSI 代码页解读，中文对象名解成乱码。**EngineCore 早已用 `Engine/EngineCore/cmake/ar_rsp_bom.ps1` 解决过同一问题**（其链接命令里能看到该包装器），渲染层当时缺这段接线。
- 实际做法：在 `Application/Renderer/CMakeLists.txt` 中 `project()` 之后加入同款块，复用 **EngineCore 的那一份脚本**（构建工具、非层间契约，共用避免两份漂移）：
  `set(CMAKE_CXX_CREATE_STATIC_LIBRARY "<powershell> -NoProfile -ExecutionPolicy Bypass -File <EngineCore>/cmake/ar_rsp_bom.ps1 <CMAKE_AR> /nologo <LINK_FLAGS> /out:<TARGET> <OBJECTS> ")`，仅在 `MSVC AND CMAKE_GENERATOR MATCHES "Ninja"` 时生效。
- 注：该块内**不能**用 `BYJY_PROJECT_ROOT`（那时尚未 `get_filename_component`），须用 `${CMAKE_CURRENT_SOURCE_DIR}/../../Engine/EngineCore/cmake/ar_rsp_bom.ps1`。

### 偏离 6：头快照与对外面只含 `EngineCore`

- 计划原文：§七.5「`byjy_tou_kuaizhao_gen(... EngineCore)` / `(... EngineSystem)`」，包含根 `[EngineCore 快照根, EngineSystem 快照根, 项目根]`。
- 实际做法：只解析 `EngineCore`，包含根 `[EngineCore 快照根, 项目根]`（次序不可颠倒：目标自身 `-I` 恒早于导入目标传递的 `/external:I`，快照必须排在项目根之前）。

## 七、重开发指引（凭本报告可不读源码重建）
