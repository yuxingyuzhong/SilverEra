## 四、实现方案

### 4.1 `Stream_Sink`（新增私有嵌套类）

- 持 `Stream owner`（`shared_ptr<ostream>`，共享所有权保证生命周期）+ 内部 `std::mutex` + `std::string buffer`。
- `write(text)`：锁内 `buffer += text`；`buffer.size() >= flush_size` 时落盘。
- `flush()`：锁内落盘。`~Stream_Sink()` 落盘残余缓冲。
- 落盘即 `*owner << buffer`，`flush_target` 为真时再 `owner->flush()`（文件流需刷新才可被外部读取）。
- 三档配置：
  | 用途 | flush_size | flush_target | 说明 |
  | --- | --- | --- | --- |
  | 控制台 | 0 | false | 逐条写出、不强制刷新（落实 <1>） |
  | 外部流（`stream_bind(path, Stream)`） | 0 | true | 逐条写出并刷新，保持既有外部流即时语义 |
  | 内部文件（`stream_bind(path, file_name)`） | 4096 | true | 批量落盘，性能优先 |

容器元素类型由 `shared_ptr<ostream>` 改为 `shared_ptr<Stream_Sink>`（`Sink` / `Sink_Group` / `Sink_Group_Weak`）。

### 4.2 调用点缓存（落实 <2>）

- 新增 `std::unordered_map<const char*, Stream_Node*> node_cache`（`cache_mtx` 保护），键为 `source_location::file_name()` 指针。
- 同一调用处文件指针恒定 → 首次未命中才做 `path_normalize` + `node_ensure`，此后 O(1) 直取节点，**不再做任何规范化**。
- 节点由 `std::list` 承载且从不销毁，地址稳定，故缓存指针长期有效（拆分节点只改 `key`/`parent`，不搬移元素）。

### 4.3 节点级锁（落实 <4>）

- `Stream_Node` 增 `std::mutex mtx`（保护本节点 `own_group` / `shared_group` / `shared_epoch` / `parent`）。
- `node_root` 的子链表插入由 `push_back(Stream_Node{})` 改 `emplace_back()`（含互斥量后不可搬移）。
- 锁职责与顺序（严格单向，绝不反向、绝不嵌套两个节点锁）：
  - `tree_mtx`：树结构变更（建节点/拆分/清流/落盘收集）——**不用于日志输出热路径**
  - `node.mtx`：单节点容器与缓存（逐级获取、即取即放）
  - `cache_mtx`：调用点缓存（顺序：`tree_mtx` → `cache_mtx`）
  - `Stream_Sink::mtx`：底层流（在无任何树锁时获取）
- `output()` 流程：构造消息 → `node_locate`（缓存 O(1)）→ `group_resolve`（节点锁内解析，取到容器即解锁）→ **逐流写出时不再持任何树锁**（落实「拿到 Stream_Group 拷贝后立刻解锁」）。

### 4.4 `group_resolve` 与共享缓存（落实 <5>）

- 保留 `shared_group`（`weak_ptr`）共享语义，但新增 `shared_epoch` + 全局 `tree_epoch` 校验，取代原 `group_shared_reset` 的子树遍历（消除父→子锁序风险）。
- 解析顺序：起点自有容器 → 起点未过期共享缓存 → 沿父链逐级（每级单锁）→ 兜底控制台容器。
- **返回值仍为 `Sink_Group`（按值）**：用户已指出返回 `const&` 需持锁至生命周期结束，等于回到「持锁做 I/O」；故保留一次 `shared_ptr` 拷贝（一次原子自增，相对格式化与 I/O 可忽略）。
- 命中后以「解析开始时的版本号」登记起点共享缓存：期间若发生设流/清流/建节点则版本号变化 → 缓存自动判过期 → 下次重新解析（避免陈旧结果）。

### 4.5 `std::endl` → `"\n"`（落实 <1>）

- `日志系统.h` 内 4 处 `std::endl` 全部去除；消息行改为 `[TYPE]正文\n`。
- 控制台目标逐条写出但不强制刷新底层流；文件目标按阈值批量落盘。

### 4.6 新增 `stream_flush()`（阈值缓冲的必要配套）

- 语义：把整棵树内所有输出目标的缓冲内容写出并刷新。
- 实现：先在 `tree_mtx` 内收集全部 `Sink`（`group_collect` 递归），**释放锁后**逐个 `flush()`（不在锁内做 I/O）。
- 命名遵循既有 `stream_*` 风格（动词后置）。

## 六、风险与遗留

1. **无编译验证**（用户约束）：改动量大且含并发原语，静态自查不能替代编译；编译问题由用户在并发任务收口时统一处理。
2. **`Log::`→`logger.` 不能无脑全文替换**：`engine::Log::Stream()` 是嵌套类型引用，替换为 `engine::logger.Stream()` 为非法语法，故 `Log::Stream` 保留。
3. **文件型用例可见性**：去掉 `std::endl` 后 ofstream 不再自动落盘，故文件型用例在读取前必须 `stream_flush()`；内存流/控制台仍即时可见。
4. **外部流不代为刷新缓冲**：`stream_bind(path, Stream)` 逐条写出并 `flush()`，但调用方自建流的内存缓冲语义仍由调用方负责。
5. **`stream_flush` 为新增公开接口**：系阈值缓冲的必要配套，命名沿用 `stream_*` 族。
