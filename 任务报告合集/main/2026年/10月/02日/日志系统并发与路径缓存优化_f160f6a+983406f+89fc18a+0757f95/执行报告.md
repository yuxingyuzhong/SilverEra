## 四、实现要点

### 4.1 `Stream_Sink`（新增私有嵌套类）

内部 `std::mutex` + `std::string buffer`，单次 `write()` 在锁内整体入缓冲，保证多线程不交错；缓冲达阈值才落盘，并把「是否刷新底层流」独立为 `flush_target`。

| 用途 | flush_size | flush_target | 语义 |
| --- | --- | --- | --- |
| 控制台 | 0 | false | 逐条写出、**不强制刷新**（落实 <1>：不再有 `std::endl` 语义） |
| 外部流（`stream_bind(path, Stream)`） | 0 | true | 逐条写出并刷新，保持既有外部流即时可读语义（向后兼容） |
| 内部文件（`stream_bind(path, file_name)`） | 4096 | true | 批量落盘，性能优先 |

- `owner` 以 `Stream`（`shared_ptr<ostream>`）共享所有权持有，**输出流生命周期不短于 Sink**（避免悬垂引用）。
- `~Stream_Sink()` 落盘残余缓冲；`flush()` 线程安全。
- 容器元素类型由 `shared_ptr<ostream>` 改为 `shared_ptr<Stream_Sink>`（`Sink` / `Sink_Group` / `Sink_Group_Weak`）；**公开别名 `Stream` 保持不变**，`stream_bind` 两重载签名不变。

### 4.2 调用点缓存（落实 <2>）

- 新增 `std::unordered_map<const char*, Stream_Node*> node_cache`（`cache_mtx` 保护），键取 `std::source_location::file_name()` 指针。
- 同一调用处文件的 `file_name()` 指针恒定（同一 TU 同一静态字面量），故首次未命中才执行 `path_normalize` + `node_ensure`，此后 **O(1) 直取节点、零路径规范化**。
- 节点由 `std::list` 承载且从不销毁（拆分只改 `key`/`parent`，元素不搬移），**节点地址永久稳定**，缓存指针长期有效。

### 4.3 节点级锁与锁序（落实 <4>）

- `Stream_Node` 新增 `std::mutex mtx`；因含互斥量不可搬移，三处 `push_back(Stream_Node{})` 改为 `emplace_back()`。
- 四把锁的职责与**严格单向**顺序（绝不反向、绝不嵌套两个节点锁）：

| 锁 | 保护对象 | 使用场合 |
| --- | --- | --- |
| `tree_mtx` | 树结构（`children`/`key`/`parent` 的创建与拆分） | 建节点 / 清流 / 落盘收集——**不在输出热路径** |
| `node.mtx` | 单节点 `own_group` / `shared_group` / `shared_epoch` / `parent` | 解析与设流，**逐级获取、即取即放** |
| `cache_mtx` | `node_cache` | 调用点缓存（顺序：`tree_mtx` → `cache_mtx`） |
| `Stream_Sink::mtx` | 底层输出流 | 在无任何树锁时获取 |

- `output()` 流程：构造消息 → `node_locate`（缓存 O(1)）→ `group_resolve`（节点锁内解析，**取到 `Sink_Group` 拷贝即已解锁**）→ 逐流写出（**不持任何树锁**）。I/O 全程在锁外。
- 死锁论证：全局不存在「父节点锁 → 子节点锁」或「节点锁 → `tree_mtx`」的获取方向；`group_resolve` 只沿父链向上、每级单锁；`group_collect` 沿子链向下但仅在 `tree_mtx` 内、且每级单锁。

### 4.4 `group_resolve` 与共享缓存（落实 <5>）

- 解析顺序：起点自有容器 → 起点**未过期**共享缓存 → 沿父链逐级（每级单锁）→ 兜底控制台容器。
- 新增 `tree_epoch`（`std::atomic<uint64_t>`）与节点 `shared_epoch`，取代原 `group_shared_reset()` 的子树遍历（消除「父→子」锁序风险）；`node_ensure` 结构变更、新建自有容器、`stream_clear` 均 `epoch_bump()`。
- **返回值仍为 `Sink_Group`（按值）**：用户已指出返回 `const&` 需持锁至生命周期结束，等于回到「持锁做 I/O」；故保留一次 `shared_ptr` 拷贝（一次原子自增），并以「解析开始时的版本号」登记缓存，期间任何结构/流设置变更都会使缓存自动判过期，避免陈旧结果。
- 起点命中自有容器为最常见路径：**仅一次原子自增**，无父链遍历。

### 4.5 `std::endl` → `"\n"`（落实 <1>）

- 原 4 处 `std::endl`（2 处绑定失败提示、1 处控制台兜底、1 处逐流写出）全部去除；消息行统一为 `[TYPE]正文\n`。
- 控制台目标逐条写出但不刷新底层流；文件目标按 4KB 阈值批量落盘。

### 4.6 新增 `stream_flush()`（阈值缓冲的必要配套）

- 语义：把整棵树内所有输出目标的缓冲内容写出并刷新。
- 实现：先在 `tree_mtx` 内用 `group_collect` 递归收集全部 `Sink`（含控制台），**释放锁后**逐个 `flush()`——不在锁内做 I/O。
- 命名沿用既有 `stream_*` 族（动词后置）。

按用户约束**未执行任何构建/测试**。已做的静态核对：

1. **锁序**：确认不存在反向/嵌套节点锁获取路径（见 4.3）。
2. **锁外 I/O**：`output` 与 `stream_flush` 的写出均在任何树锁释放之后。
3. **指针稳定性**：`std::list` + `emplace_back` + `splice`，节点地址稳定 → `node_cache` 与 `parent` 链不失效。

6. **非搬移类型**：`Stream_Node` 含 `std::mutex`，已确认全部构造点改用 `emplace_back()`，无拷贝/搬移。
7. **符号可见性**：`file_flush_size`（`static constexpr size_t`）为类作用域常量，成员函数内可见；`<atomic>` 由预编译头提供，无新增 include。
8. **调用形式**：`engine::logger` 为头文件 `inline` 变量，跨 TU 唯一定义，测试层/系统层均可直接引用。

## 七、遗留与风险

1. **无编译验证**（用户约束）：本版次为源码级交付，改动含并发原语与类型改造，**不能替代编译**。建议用户收口时优先编译引擎层 + 测试层。
2. **可见性变更（需留意）**：
   - 文件输出目标改为阈值（4KB）批量落盘：**写后立即读文件必须 `stream_flush()`**（测试层已在 `log_read()` 内统一补 flush）；进程正常退出时由 `Stream_Sink` 析构落盘；异常终止可能丢最后不足 4KB 的日志。
   - 控制台不再逐条强制刷新（落实 <1>），交互式实时性交给 `std::cout` 自身缓冲；如需强制刷新可调用 `stream_flush()`。
3. **外部流不代为刷新内存缓冲**：`stream_bind(path, Stream)` 逐条写出并 `flush()`，调用方自建流自身的缓冲语义仍由调用方负责。
4. **`stream_flush()` 为新增公开接口**：系阈值缓冲的必要配套，未被用户任务清单显式要求，如需更名/去除请指示。
5. **共享缓存为「弱一致性」**：并发设流与输出交错时，个别输出可能沿用解析瞬间的旧容器（一次 `Sink_Group` 拷贝的生命周期内），属预期（无权限保护、允许短暂过渡）。
6. **`node_ensure` 拆分中间节点时的 `key` 改写**：`parent` 已在 `moved.mtx` 内改写（输出路径会并发读取 `parent`）；`key` 仅由持有 `tree_mtx` 的遍历读取，未加节点锁。
7. 未建立项目导航、未提交 git（用户定夺）；后续如需入库，须待用户 `Config_Loader` 并发改动收口后统一处理。
