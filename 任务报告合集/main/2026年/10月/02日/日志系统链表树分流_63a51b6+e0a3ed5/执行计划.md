## 四、实现方案

### 4.1 数据结构（`日志系统.h` 内私有）

```cpp
//输出流别名
using Stream = std::shared_ptr<std::ostream>;
//输出流容器别名（容器可存多个流，打印时全部输出）
using Stream_Group = std::shared_ptr<std::vector<Stream>>;
//输出流容器弱引用别名（共享父节点输出流时使用，不拥有）
using Stream_Group_Weak = std::weak_ptr<std::vector<Stream>>;

//流节点（链表树节点）
struct Stream_Node
{
    //节点路径键（规范化后，恒以 '/' 结尾，保证前缀比较落在路径段边界）
    std::string key{};
    //父节点（生命周期由父节点子链表持有，链表 splice 不搬移元素，指针稳定）
    Stream_Node* parent = nullptr;
    //子节点链表
    std::list<Stream_Node> children{};
    //自有输出流容器（该节点被设置单独输出流时激活）
    Stream_Group own_group{};
    //共享输出流容器（该节点未被设置单独输出流时激活，弱引用最近祖先的自有容器）
    Stream_Group_Weak shared_group{};
};
```

静态成员（`inline static`，header-only 合法）：

```cpp
//流节点树根（键为空串）
inline static Stream_Node node_root{};
//控制台兜底输出流容器（未设置任何文件流时默认使用 std::cout）
inline static Stream_Group console_group{};
//整树互斥锁（建节点 / 设流 / 清流 / 输出共用；设置接口无权限校验但一律持锁）
inline static std::mutex tree_mtx{};
```

**两容器互斥语义**：`own_group` 非空 ⇒ 节点激活 shared_ptr 容器（单独输出）；`own_group` 为空 ⇒ 节点激活 weak_ptr 容器（共享父节点输出流）。二者同一时刻只可能有一个处于生效路径上。

### 4.2 路径规范化

```cpp
//调用路径规范化（分隔符统一 + 剥离到项目根相对路径 + 末尾补 '/'）
static std::string path_normalize(const std::string& raw)
```

规则：
1. 反斜杠 `\` 统一为 `/`；
2. 以 **项目根目录名 `白银纪元/`** 为锚点剥离（取**最后一次**出现位置之后的剩余部分，兼容构建目录等含同名片段的情形）；剥离后去除开头的 `./` 与多余的 `/`；
3. **未找到锚点时原样使用**（仅保留步骤 1 的规范化）；
4. 末尾补 `/`（若尚未以 `/` 结尾）。

产出示例：编译期绝对路径 `D:/代码存储/代码仓库/白银纪元/引擎层/src/tools/Logging/日志系统.h` → 规范化为 `引擎层/src/tools/Logging/日志系统.h/`。

**末尾补 `/` 的作用**：使目录节点与文件叶子节点共用同一套「字符串前缀 = 路径段前缀」比较，杜绝 `spatial` 误吞 `spatialX` 之类跨段前缀误匹配。

### 4.3 链表树插入（最长公共前缀合并）

```cpp
//节点查找或创建（按规范化路径键在树中定位，沿途按需建节点）
static Stream_Node& node_ensure(const std::string& key)
```

算法（自根向下，`rest` 为待插入剩余键；节点间递归下降）：
1. 在 **当前节点的子链表中**寻找与 `rest` 有非空公共前缀的子节点；
2. **无**公共前缀 ⇒ 以 `rest` 为键新建子节点，返回之（「路径不同则各自单独成为父节点」）；
3. 公共前缀长度 `l` **等于**该子节点键长 ⇒ 该子节点是 `rest` 的前缀 ⇒ 下降（`rest` 去掉 `l` 个字符），`rest` 为空则返回该子节点，否则继续第 1 步；
4. 公共前缀长度 `l` **小于**该子节点键长 ⇒ **拆分**：新建中间节点（键为公共前缀），用 `std::list::splice` 把原子节点（元素地址不变，故其子树与 `parent` 指针全部保持有效）移入中间节点子链表并截短其键，中间节点插入当前节点子链表，再以 `rest` 剩余部分作为中间节点的新子节点返回。
5. `l` 的取值必须**回退到最近的 `/` 边界**（否则回退到 0）——即「公共部分」以路径段为单位。

由此自然得到：
- 两处调用路径存在相同部分 ⇒ 相同部分成为父节点（且是**压缩**的：不为每级目录都建节点）；
- 公共前缀之间可互为父子（中间节点被插入后，原节点成为其子）；
- 插入保持不变量「同一父节点下任意两个子节点的键互不为前缀」，故第 1 步至多命中一个子节点。

### 4.4 双容器与生效解析

```cpp
//节点生效输出流容器获取（自有优先，否则经 weak_ptr 共享，失效则向父节点递归重建）
static Stream_Group group_resolve(Stream_Node& node)
{
    //自有容器已激活则直接使用（单独流输出）
    if (node.own_group)
        return node.own_group;
    //未设自有流：优先使用已激活的共享容器（weak_ptr，共享父节点输出流）
    if (Stream_Group shared = node.shared_group.lock())
        return shared;
    //共享容器缺失或已失效：向父节点重新取用并刷新共享容器
    if (node.parent)
    {
        Stream_Group parent_group = group_resolve(*node.parent);
        node.shared_group = parent_group;
        return parent_group;
    }
    //根部兜底：未设置任何文件流时默认使用 std::cout
    return console_group;
}
```

- 叶/中途节点（无自有流）⇒ 走 `weak_ptr` 取最近祖先的自有容器 ⇒ 「共享父节点输出流」；
- 任一节点 `stream_bind` 后 `own_group` 非空 ⇒ 其自身与后代改走该容器 ⇒ 「单独流输出」；
- 祖先容器被 `stream_clear` 置空 / 被替换 ⇒ 子的 `weak_ptr` 失效 ⇒ 递归上溯并刷新，不会悬空；
- 打印时遍历生效容器内的**全部**流逐个写出 ⇒ 「所有流均会输出日志信息」。

### 4.5 对外接口（全部 static、public、无权限校验、全部持 `tree_mtx`）

```cpp
//输出流绑定 —— 文件名重载（目录节点或文件节点均可绑定，节点按需创建）
static bool stream_bind(const std::string& path, const std::string& file_name);
//输出流绑定 —— 流对象重载（可挂控制台、自定义流、内存流等外部流）
static bool stream_bind(const std::string& path, const Stream& stream);
//输出流清空（清除该节点自有容器，使该节点及其后代回落为共享父节点输出流）
static bool stream_clear(const std::string& path);
```

`stream_bind(path, file_name)` 行为：
1. `path_normalize(path)` → `node_ensure` 取得/创建节点；
2. 按 `file_name` 创建 `std::ofstream`（`new(std::nothrow)`，遵守「内存分配全面禁用异常」约束），创建前判空文件名（空串口径同旧实现：**回落控制台流**）；
3. 分配失败 / `is_open()` 失败 ⇒ 回落控制台并输出 `[FATAL]`/`[ERROR]` 提示（沿用旧语义）；
4. 成功 ⇒ 把该流**追加**进节点的 `own_group`（必要时创建容器），使该节点激活 shared_ptr 容器；
5. 返回是否绑定了文件流。

`stream_bind(path, stream)` 行为：取得/创建节点，把外部流追加进 `own_group`，返回 true（空指针拒绝并返回 false）。

`stream_clear(path)` 行为：按规范化键找到节点（不新建），`reset` 其 `own_group` 并 `reset` 其 `shared_group`（下次解析时按父链重建）；节点不存在则返回 false。

### 4.6 日志方法（方法不感知流）

```cpp
//信息输出
template<typename... Args>
static void info(std::format_string<Args...> fmt, Args&&... args,
    std::source_location loc = std::source_location::current())
{
    //构建正文并交给树路由输出（方法体内不出现任何流参数与活跃流状态）
    output(loc.file_name(), std::format(fmt, std::forward<Args>(args)...), "INFO");
}
```

`warn` / `error` / `debug` 同构（仅级别标签不同）。

```cpp
//树路由输出（规范化调用路径 → 定位节点 → 解析生效容器 → 逐流输出）
static void output(const char* file_name, const std::string& text, const std::string& type)
{
    //规范化调用处路径键
    std::string key = path_normalize(file_name);
    //消息行（保持既有 [级别]正文 + std::endl 语义）
    const std::string msg = std::format("[{}]{}", type, text);
    //整树加锁：节点查找/创建与多流写出串行化
    std::lock_guard<std::mutex> lock(tree_mtx);
    //定位或创建节点
    Stream_Node& node = node_ensure(key);
    //取生效输出流容器（自有 → 共享 → 控制台兜底）
    Stream_Group group = group_resolve(node);
    //逐个流输出（容器内所有流均输出）
    for (const Stream& stream : *group)
        *stream << msg << std::endl;
}
```

### 4.7 线程保护

- 一把 `inline static std::mutex tree_mtx` 保护整棵树：日志输出的「查节点/建节点/解析容器/多流写出」与 `stream_bind`/`stream_clear` 的「建节点/改容器」全部持锁；
- 设置接口 public 且不做任何权限校验（对应「无权限保护机制」）；
- 持锁期间会串行化 I/O 写出（多线程下日志顺序稳定、不混行），符合「存在多线程保护机制」。

## 七、风险与待确认细节

### 7.1 需你确认的 3 个细节（我已按「推荐项」拟定，若不同意请直接指出）

1. **同一（路径, 文件名）重复绑定** —— 哈希容器按要求取消后不再有文件名级缓存。拟定：**不做同名去重**，每次 `stream_bind` 都新建并追加一个流（同一文件被绑定两次会产生两个 `ofstream` 指向同一文件，由调用方保证只绑一次）。备选：在**节点内**按文件名去重（同一节点同一文件名复用同一流）——这不是全局哈希容器，且可避免重复打开/截断。
2. **日志正文是否附带调用处信息** —— 拟定：**不改变输出格式**，仍为 `[级别]正文`（`source_location` 仅用于路由，不写入正文）。备选：正文追加 `文件:行`。
3. **项目根锚点剥离失效时的回落** —— 拟定：**原样使用**（仅统一分隔符），即树键退化为编译期给出的完整路径；因此换目录名/相对路径构建下仍能自洽运行（同一工程内左右一致），只是树键更长。

### 7.2 风险

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 变参包后置默认参数 | 「`Args&&... args` 之后 + 带默认值的 `std::source_location`」若被编译器拒绝 | 阶段一先做最小样例验证；被拒则改用 `Call_Site` 代理类型（默认参数 `{}` 在调用点求值），对外调用方式不变 |
| 锚点硬编码 | `白银纪元` 为项目根目录名，换名后剥离失效 | 仅回落为「原样使用」，功能不受影响；已在 7.1-3 明示 |
| 树的节点增长 | 每个调用文件路径与其公共前缀都会成为节点，仅增不减 | 节点数 = 调用文件数 + 目录前缀数，量级很小；不提供删除接口（如后续需要可另立任务） |
| 构建耗时 | 引擎层 Debug 全量重建耗时较长；本次仅改头文件，增量编译规模取决于包含该头的翻译单元数 | 使用增量构建；先建引擎层再建测试层 |
| 测试层被并行修改 | 若你并行编码测试层，构建可能失败 | 出现失败即向你反馈，不擅自改写无关代码 |
