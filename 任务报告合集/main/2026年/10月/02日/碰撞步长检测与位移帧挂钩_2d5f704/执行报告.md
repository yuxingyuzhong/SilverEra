## 二、任务要求与定夺口径

用户任务原文：

- `<1>` 碰撞系统添加步长检测，步长可通过事件进行配置；
- `<2>` 碰撞系统位移向量作用与逻辑帧挂钩，可通过事件配置位移向量的触发频率（建议直接合并到原位移向量事件中）。

用户答复的语义定夺：

| 项 | 定夺 |
|---|---|
| 帧计数器 | 由本任务在引擎环境中新增 |
| 门控对象 | 「从事件更新位移向量」与「用位移向量修改碰撞体位置」两处同受门控；未达帧间隔则对位移向量**不做任何操作**（含不响应外界更新请求） |
| 作用频率 | 必须为逻辑帧率的因数（保证整除）；帧间隔 = `逻辑帧率 ÷ 作用频率` |
| 单次施加量 | **位移向量 ÷ 频率**（一个逻辑帧周期内共生效 F 次，累计恰为一个位移向量） |
| 生效判定 | **全局帧序号差值**：`当前帧序号 − 上次生效帧序号 ≥ 帧间隔` |
| 频率粒度 | **碰撞体级**，数据存放在碰撞空间（即 `Collider` 记录内） |
| 窗口外更新 | **暂存待下次生效**（代理器保留最新事件，生效帧才重读） |
| 步长 | 一段（本次施加的）位移向量被拆分的**段数** |

用户另行确认的四条假设（均成立，本版次即按此实现）：

1. 频率缺省或非法 → 回退旧行为（每次检测重读并施加全量位移）；
2. 碰撞响应通道（`stop` / `keep` / `change`）不受帧门控，作废立即生效，`change` 改写后的向量仍按频率分帧；
3. 新位移事件登记时生效计时重新起算；
4. 帧计数由外部主循环驱动，本任务只提供接口。

## 四、新增接口与字段（重开发依据）

### 1. 引擎环境 `Engine_Env`（`引擎环境.h`，全部 `static`）

```cpp
static void frame_tick(void);                          //逻辑帧计数自增（外部主循环每逻辑帧调用一次）
static uint64_t frame_count_get(void);                 //逻辑帧计数读取
static void frame_count_set(const uint64_t& count);    //逻辑帧计数设定（测试/复位用）
```

- 新成员：`inline static uint64_t frame_count = 0;`
- 三接口与既有 `logic_frames_set/get` **共用 `frame_mtx`**，均以 `std::lock_guard` 加阻塞锁。
- 与既有成员的区别：`logic_frames` 是**帧率**（一个周期含多少帧），`frame_count` 是**帧序号**（只增的逻辑帧流逝计数）。

### 2. 碰撞体 `Collider`（`碰撞体.h`）

```cpp
uint64_t displacement_frequency = 0;              //位移作用频率（0 = 未配置 → 回退旧行为）
uint64_t displacement_frame = 0;                  //位移上次生效的逻辑帧序号
Vector3  displacement_step{ 0.0f,0.0f,0.0f };     //本帧实际施加的位移
```

- 三个字段紧随既有 `displacement_vector` / `displacement_invalid` 之后声明。
- **移动构造与移动赋值均已同步搬移**这三个字段（该类为手工搬移并重挂 `object` 自指针，漏搬会导致搬移后位移状态丢失）。

### 3. 碰撞空间 `Collision_Region`

```cpp
bool collider_frequency_set(uint64_t collider_ID, uint64_t frequency);
```

实现（`core/碰撞体管理.cpp`）：查找碰撞体 → 写入 `displacement_frequency` → `displacement_frame = Engine_Env::frame_count_get()`（**生效计时重新起算**）→ `displacement_step` 清零；编号不存在时 `Log::warn` 并返回 `false`。

### 4. 位移事件协议（`Collision/ColliderDisplacement`）

```json
{
  "collider_ID": 12,
  "displacement": [0.0, 1.0, 0.0],
  "frequency": 10
}
```

- `frequency` 为**新增可选字段**（旧事件不带该字段仍可用）。
- 校验规则（`位移管理.cpp`）：`frequency != 0 && (逻辑帧率 == 0 || 逻辑帧率 % frequency != 0)` → `Log::warn` 告警并把频率按 0 处理（回退每次检测全量位移）。
- 登记流程：保存事件（同编号新事件覆盖旧事件，**暂存**）→ 下发频率至持有该编号的各空间（`collider_frequency_set`）→ 保留 `collider_displacement_replace` 调用（其作用变为「解除碰撞响应产生的作废 + 写入目标位移」，实际位移量只来自生效帧的 `displacement_step`，故不会提前移动）。

## 五、行为矩阵（相对旧实现的差异）

| 项 | 旧实现 | 新实现（F 未配置 / 帧率 0） | 新实现（F 合法） |
|---|---|---|---|
| 位移事件重读 | 每次检测重读 | 每次检测重读（不变） | **仅生效帧重读**（其余帧不重读） |
| 单帧施加量 | 全量位移向量 | 全量位移向量（不变） | **位移向量 ÷ F** |
| 施加节奏 | 每帧 | 每帧（不变） | 每 `帧率 ÷ F` 帧一次 |
| 一周期累计位移 | 帧率 × 位移向量 | 同左 | **恰为一个位移向量** |
| `step_length` | **被解析但从不使用**（死字段） | **生效**：把本帧施加位移拆成 N 段 | 同左 |

检测流程（`detect()`）现状：

1. `updateAabbs()`；
2. **位移生效门控**：读 `frame_count_get()` / `logic_frames_get()`，逐碰撞体算出 `displacement_step`；
3. **扫掠检测**：启用扫掠的碰撞体，逐部件把本帧施加位移按段拆开，分段执行 `convexSweepTest` 并逐段收集命中；
4. **离散检测**：段数取全空间最大值，**外层按段循环**、内层逐碰撞体平移该段位移，每段后执行一次 `performDiscreteCollisionDetection()` 并提取流形（碰撞对与边界接触累计收集）；
5. `pair_unique` 去重 → `cross_state_update`（以最终位置与累计边界接触判定跨越状态，判定侧按集合成员处理，重复编号无碍）。

辅助设施：`检测执行.cpp` 新增匿名命名空间函数 `step_count_get(const Collider&)`，`step_length == 0` 时返回 1（不拆分，等价旧行为）。

## 七、风险与遗留

1. **帧计数必须由外部驱动**：未接入 `Engine_Env::frame_tick()` 时帧序号恒为初值，配了 `frequency` 的碰撞体将**永不施加位移**（差值永远不达帧间隔）。接入点（主循环）由用户后续处理。
2. **分段带来额外开销与额外接触**：离散检测由「1 次」变为「N 次」（N = 空间内最大 `step_length`），性能随 N 线性增长；中间段位置产生的接触也会进入碰撞对与边界接触集合，跨越判定可能因此在中间段触发状态转移（这正是分段检测的目的，但相比旧实现属行为差异）。
3. **帧率变更不重新校验**：`logic_frames_set` 改变帧率后，已下发频率不再校验整除性，生效判定按整数除法向下取整（行为已在本版次固化，未加运行期重校验）。
4. **回退路径下 `step_length` 同样生效**：旧配置中「配了 `step_length` 但未配频率」的碰撞体现在会真的分段推进（旧实现忽略该字段）。经检索常用例不受影响，但外部存量配置需留意。
5. 沿用既有遗留：`Quadtree/core/区块信息检索.hpp(72)` 与 `Event_Broker/core/事件中转器.cpp(221)` 的 `warning C4715` 未处理。
