## 二、方向 A 实现方式（详述）

### A-1 窗口尺寸公共入口
- 平台层 `window_size_set`：前置窗口非空且宽高非零；调 `SDL_SetWindowSize`；**成功后置 `resize_flag = true`**，使「尺寸变化 → 交换链重建」在隐藏窗口下亦能被驱动（SDL 对隐藏窗口不一定派发 `SDL_EVENT_WINDOW_RESIZED`）。
- 门面 `window_size_set`：未初始化返回假；转交平台层；返回平台结果。使重建路径可被上层驱动、可被用例构造。

### A-2 交换链重建延迟销毁（无整帧停顿）
- 新增 `Swapchain_Old_Resources`：承载旧交换链 ＋ 旧图像视图 ＋ 两类旧信号量 ＋ 旧深度图像 / 内存 / 视图。
- `rebuild(width, height, old_out)`：
  1. 校验设备 / 表面、宽高非零；
  2. `swapchain_resources_extract(old)`：把成员资源**整体移出**到局部（不销毁），并复位 `depth_initialized / format / depth_format / extent / color_transfer_src` 等状态到「资源已抽出」的待建态；
  3. `swapchain_create(width, height, old.swapchain)`：传入旧交换链作 `oldSwapchain` 建新链；
  4. 成功 → `old_out = std::move(old)`；失败 → `swapchain_resources_destroy()`（清理可能已建的半成品）＋ `swapchain_resources_restore(old)`（旧资源原样恢复，保持可用），返回假。
- 门面两处重建调用点：重建成功后把 `old_out` 组装为 `Deferred_Entry` 压入 `frame.deferred_push(entry, frame.in_flight_count_get() + 1)`（延迟 = 在途帧数 + 1）。
- `deferred_flush`：到达释放帧号后，先经 `memory->image_view_destroy / image_destroy` 归还旧深度视图与图像，再 `vkDestroyImageView`（旧图像视图与两类信号量）＋ `vkDestroySwapchainKHR`（旧交换链）。
- 帧模块 `in_flight_count_get` 返回 `frame_overlap`。

### A-3 顺手修（R-DEV-04）
- `Device_Context::destroy` 复位 `anisotropy_enabled = false`、`max_sampler_anisotropy = 1.0f`。

### 验收（校验层全开实跑）
连续 3 次「`window_size_set` 改尺寸 → 重建 → `frame_render` 出帧」后：帧计数继续推进、回读尺寸随新尺寸变化、回读内容正确、校验层无错误。

## 四、风险与关注点

- 时序敏感：旧资源销毁与在途帧错配会崩溃或花屏 —— **必须校验层全开实跑**并如实记录结论。
- 交换链重建中「析出旧资源 → 建新链失败」的回滚必须保证旧链仍可用，否则后续帧硬失败。
- `Swapchain_Old_Resources` 抽出 / 恢复须同时覆盖 `depth_initialized` 等**非句柄状态**，否则新深度图像会漏掉首帧布局转换。
- 旧交换链呈现可能在途：延迟 = 在途帧数 + 1 提供余量，仍以校验层验证。
- 改渲染层着色器后须重配测试层或手动拷 `.spv`（第 5 轮实测坑），方向 B 涉及后处理着色器，务必留意。
