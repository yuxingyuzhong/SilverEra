## 二、方向 A · 多材质/多管线（优先，可独立交付）

### A.1 目标
`Pipeline_Context` 由「持有单条图形管线」改为「持有若干条按 `（顶点着色器模块 + 片元着色器模块 + 混合档）` 缓存/工厂化的图形管线」，格式（颜色/深度）由配置统一烘焙；门面提供具名管线登记/卸载/选择入口；`Frame_Render_Item` 已带 `pipeline` 字段，命令录制的状态缓存天然支持「同帧多项挂不同管线」。

### A.2 设计要点（关键不变量）
1. **管线布局（`pipeline_layout`）与描述符集布局（set0 场景 UBO / set1 采样器）全管线共享**：所有管线共用同一 `VkPipelineLayout`，因此 `Frame_Render_Item::layout` 不变、描述符集绑定不变、推送常量范围不变。具名管线仅允许「着色器对 + 混合档」不同，不允许布局不同（避免描述符集与管线布局错配）。
2. **句柄语义**：句柄 `0` 保留给**默认场景管线**（`init` 时登记，承担 `frame_render` 的常规绘制路径）；具名管线句柄自 `1` 起由管线模块分配。`pipeline_bind_set(0)` ＝ 选回默认。
3. **着色器模块所有权仍在门面**：默认管线的 `vert_module/frag_module` 由门面持有（现状不变）；具名管线的着色器模块也由门面加载并持有、随 `pipeline_unload`/`shutdown` 销毁（与默认一致，保持单一所有权）。
4. **`blend_mode_set` 语义收敛为「重建默认场景管线」**：既有的 `渲染混合测试` 依赖该行为（默认管线切档），故保留；具名管线的混合档在登记时确定、不受 `blend_mode_set` 影响。
5. **交换链格式变化 → 重建全部已登记管线**：所有管线都把颜色/深度格式烘焙在 `VkPipelineRenderingCreateInfo` 中，故 `pipeline_rebuild` 走「按新格式重建全部条目（着色器与各自混合档保留）」。

### A.4 `Pipeline_Context` 目标接口
```
bool pipeline_build(vert, frag, blend);                 // 登记/替换并激活「句柄 0 默认管线」（init 调用，语义不变）
bool pipeline_register(uint64_t& handle_out, vert, frag, blend);   // 登记具名管线（句柄自 1 起递增；不激活）
bool pipeline_activate(uint64_t handle);                // 切换激活管线（不存在则失败、激活不变）
void pipeline_release(uint64_t handle);                 // 注销具名管线（句柄 0 忽略）
bool pipeline_rebuild(VkFormat color, VkFormat depth);  // 按新格式重建全部条目（着色器/混合档保留）
bool pipeline_default_blend_set(Blend_Mode blend);      // 重建句柄 0 默认管线的混合档（供 blend_mode_set）
VkPipeline pipeline_get(void) const;                    // 当前激活管线的 VkPipeline
VkPipelineLayout layout_get(void) const;                // 共享管线布局（不变）
bool pipeline_has(uint64_t handle) const;               // 句柄是否已登记
```
（其余描述符集 API 完全不变。）

| 用例 | 断言 |

## 三、方向 B · 离屏渲染目标与后处理闭环

### B.1 目标
新增 `Render_Target` 模块：创建「颜色图像 + 深度图像 + 视图」，颜色图像具备 `COLOR_ATTACHMENT | SAMPLED | TRANSFER_SRC` 用法，可作渲染附件、可作纹理采样、可作像素回读来源；帧链路增「渲染到目标」路径；门面提供目标的创建/销毁与「本帧渲染到目标」；**以目标作纹理采样**完成一次「离屏渲染 → 采样合成」闭环。

### B.2 设计要点（关键不变量与语义取舍）
1. **离屏路径本帧不呈现到窗口**：`render_to_target` 不取交换链图像、不提交呈现、不使用信号量（仅以帧槽完成栅栏同步）。离屏结果**经「以目标为纹理」的正常绘制路径显示**，这正是本方向要建立的后处理闭环。该取舍在《执行报告》中写明。
2. **布局不变量**：目标颜色图像在创建时一次性转为 `SHADER_READ_ONLY_OPTIMAL`，深度图像一次性转为 `DEPTH_ATTACHMENT_OPTIMAL`；此后每次「渲染到目标」在进入时把颜色 `SHADER_READ_ONLY → COLOR_ATTACHMENT_OPTIMAL`、结束时（回读则经 `TRANSFER_SRC`）回到 `SHADER_READ_ONLY`；深度以 `loadOp = CLEAR` 逐帧清空。于是目标在帧间恒处于「可采样 / 可作附件」的确定布局。
3. **目标模块自持一次性转换命令**：创建时的布局转换在目标模块内用「临时命令池 + 栅栏」完成（复用交换链深度图像的同款做法，不依赖帧模块）。
4. **帧槽复用**：离屏渲染复用同一批帧槽（命令池 / 命令缓冲 / 栅栏），与交换链路径共用 `frame_count` 轮转。

## 五、风险与申报

1. **管线布局共享是硬约束**：具名管线不得有不同描述符集布局，否则「已绑定描述符集」与管线布局错配会被校验层判错；本轮统一共享布局以规避。
2. **着色器模块所有权**：具名管线的 `.spv` 由门面加载并销毁；若加载成功而管线登记失败，须即时销毁模块，避免泄漏。
3. **离屏路径不呈现**：窗口在离屏帧不更新，属设计取舍（见 B.2.1），须在报告与「下轮方向」中写明。
4. **布局屏障口径**：目标颜色的进入/退出布局须严格配对，否则校验层报 `VUID` 布局不符；深度沿用「帧间恒 `DEPTH_ATTACHMENT_OPTIMAL`、逐帧 `CLEAR`」口径。
5. **新模块入列**：`RenderTarget/` 新源文件由 CMake 的 `GLOB_RECURSE` 自动纳入（勿手改 `源文件列表.cmake`）；新 `纯色.frag` 由着色器 GLOB 自动编译。
6. **外部问题汇总**：本轮不预期新增外部问题；仍按既有口径维护工作站根 `渲染层外部问题汇总.md` 与 `渲染层下轮方向.md`。
