### 2.4 关键接口与坐标系口径

```cpp
// 门面
bool font_load_file(uint64_t& handle_out, const std::string& path, uint32_t pixel_height);
void font_unload(uint64_t handle);
bool text_draw(uint64_t font, const std::string& text, float pixel_x, float pixel_y);

// 文字几何（Font_Context）
static bool text_geometry_build(Mesh_Data& data_out, const Font_Record& record, const std::string& text);

// 像素坐标 → NDC 仿射矩阵（列主序；**不做 Y 翻转**）
//   x' = 2/W * px + (2*pixel_x/W - 1)
//   y' = 2/H * py + (2*pixel_y/H - 1)
```

**两条必须保留的结论（本轮实测得到）**：

1. **像素→NDC 不需要 Y 翻转**：Vulkan 视口把 NDC y 映射为「向下递增」的帧缓冲行号，故直接 `y' = 2/H*py + (2*pixel_y/H − 1)` 即让「像素行号 = 帧缓冲行号」。**首版误加了 `y' = 1 − 2/H*py`（Y 翻转），导致文字被上下颠倒并落到窗口下半部**。
2. **文字四边形绕序须与场景四边形相反**：像素空间为 Y 向下且 `model` 不作 Y 翻转（行列式 > 0），此时索引须取 `(0,2,1)` ＋ `(0,3,2)`（即 `左上 → 右下 → 右上` 与 `左上 → 左下 → 右下`）。**首版沿用场景四边形的 `(0,1,2)` ＋ `(0,2,3)`，全部三角形被判背面剔除，表现为「一个像素都不出现」**（用「不透明纯绿片元」诊断确认属光栅化问题而非图集 alpha 问题）。

## 四、方向 C 为何顺延至下轮（**事实登记**）

方向 C（交换链重建延迟销毁启用）经评估后**本轮未实施**，理由如下（均已核实）：

1. **缺可验证入口**：渲染层当前**没有任何「请求改变窗口尺寸」的公共入口**（`Platform` 只有 `window_size_get` / `resized_consume`，无 `window_size_set`），而交换链重建只由「窗口尺寸变化」或「交换链过期 / 次优」触发。**在没有该入口的前提下，C 的用例无法构造**（既有渲染层用例也从未覆盖重建路径）。
2. **时序敏感且有崩溃风险**：延迟销毁若与在途帧错配，会销毁仍被 GPU 引用的对象（崩溃或花屏）；实施它需要同时扩展 `Deferred_Entry`（当前**不含深度图像 / 内存字段**，而深度图像同样被在途帧引用，必须一并延迟）、`deferred_flush`（深度归还须经内存模块）、`Swapchain_Context::rebuild`（须传 `oldSwapchain` 且不得再 `vkDeviceWaitIdle`）与门面两处重建调用点。
3. **不影响已交付价值**：A ＋ B 两个方向彼此独立且均已验证通过；按《执行计划》「任一方向完成即可独立交付」，本轮以 A ＋ B 交付。

**下轮首要方向即为「C ＋ 其前置的窗口尺寸公共入口」**（见 `渲染层下轮方向.md`），并须以**校验层全开**实跑。
