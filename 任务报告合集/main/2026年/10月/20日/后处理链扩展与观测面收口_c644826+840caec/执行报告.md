## 三、方向 A · 后处理链扩展（关键实现）

### 3.1 门面公共接口（新增）

- `bool post_chain_set(const uint64_t* handles, uint32_t count)`：`count == 0` 清除链（回落既有单级默认后处理）；`handles == nullptr` 且 `count != 0` 或任一句柄未登记 → **整链拒绝**（保持原链不变）；成功则按下标顺序复制为链。
- `void render_target_present_secondary_set(uint64_t handle)`：设置 ping-pong 第二目标；`0` 清除；句柄未登记则清除并告警。

### 3.2 帧模块公共接口（新增）

- `render_chain_present(swapchain, scene_target, second_target, items, item_count, post_items, post_count, clear_color, rebuild_needed_out, readback)`。
  - `post_count == 1` 时行为等价于 `render_to_target_present`（`second_target` 不被使用）。
  - `post_count >= 2` 时必须给出 `second_target`，否则报错返回假。
  - 与既有路径共用同一批帧槽与 `acquire_cursor` 轮转，故可与交换链路径交替调用。

### 3.3 ping-pong 映射（stage 自 0 起）

| 项 | 规则 |
| --- | --- |
| 源 | `stage % 2 == 0` → `scene_target`；`== 1` → `second_target` |
| 宿 | 末级（`stage + 1 == post_count`）→ 交换链图像；否则 `stage % 2 == 0` → `second_target`、`== 1` → `scene_target` |
| 中间目标布局不变量 | 每级写完后立即 `COLOR_ATTACHMENT_OPTIMAL → SHADER_READ_ONLY_OPTIMAL`，故帧间恒保持该布局；下一级可直接采样 |
| 交换链收尾 | 回读：`COLOR_ATTACHMENT → TRANSFER_SRC → PRESENT_SRC`；不回读：`COLOR_ATTACHMENT → PRESENT_SRC` |

### 3.4 描述符集分配

`post_sets` 由「每帧槽 1 个」扩为「每帧槽 `POST_SET_PER_SLOT`（= 2）个」，下标 `slot × 2 + index`：`index 0` 恒绑场景目标颜色视图（单级与链均用），`index 1` 仅在链长 ≥ 2 时绑第二目标颜色视图。门面每帧把两个视图写入**全部帧槽**（长命资源，值跨帧不变，故与既有单级路径同样安全）。

### 3.5 分派优先级（`frame_render`）

```
present_target != 0 且 post_chain 非空   → 链路径（post_mesh_ensure；链长 ≥ 2 须 present_secondary）
present_target != 0 且 post_chain 为空   → 既有单级默认路径（post_resources_ensure ＋ render_to_target_present）
!offscreen 且 active_target != 0        → 离屏路径
否则                                    → 交换链路径
```

任一前置不完整（目标 / 全屏网格 / 采样器 / 链中管线已失效）→ 记录告警并回落原路径，不中断帧循环。

### 3.6 遗留取舍

- 未新增 `post_pipeline_load`（见 §5.1 设计决策）。
- 链中各管线**不随链复制**：链仅存句柄；`pipeline_unload` 会同步摘除链中该句柄（避免整帧回落）。
- 链长上限未设：级数由调用方决定，仅受「级数 ≥ 2 须第二目标」与实例存储（每帧 1 个实例位）约束。

## 五、方向 C · 待确认项清扫（关键实现与结案）

### 5.1 设计决策（已记录，供复核）
1. **未新增 `post_pipeline_load`**：现有 `pipeline_load(handle_out, vert, frag, blend)` 已提供完全等价的「按文件名登记具名管线（共享同一管线布局与顶点输入）」能力，后处理 pass 的顶点输入（position + uv ＋ 实例 mat4）与之同构；新增独立接口属同一事实两处实现，故沿用之。链的「按文件名热登记」即由 `pipeline_load("后处理.vert.spv", "反色.frag.spv")` 表达。

### 5.2 结案项

| 编号 | 处置 | 结案依据 |
| --- | --- | --- |
| `R-FACADE-10`（`scene_apply` 不校验取值范围） | `scene_apply` 增校验：`fov ∈ (0, π)`、`near_plane > 0`、`far_plane > near_plane`；任一非法 → `logger.warn` 并**整次拒绝**（相机与清屏色均不变）。`clear_color_set` 分量钳制到 `[0,1]`（负 / 非数 → 0、大于 1 → 1）；`scene_apply` 内部统一走 `clear_color_set` | 用例 `非法场景描述整次拒绝`（画面与拒绝前逐字节相同）、`清屏色越界分量被钳制` |
| `R-SCENE-07`（`Scene_Data` 默认值与本层 `Camera` 私有默认两处同步） | `Camera::Camera(void)` 改由 `const Scene_Data defaults{}` 逐项设置位置 / 注视点 / 视场角 / 近远平面，删除 `Camera` 内重复的成员初始化器（`up` / `aspect` 仍为本层自有默认）→ **单一来源** | 用例 `默认场景描述与原默认画面一致`（应用默认 `Scene_Data` 与原默认状态画面逐字节相同） |
| `TEST-68`（GPU 用例在不支持设备上跳过） | 两例改为**不跳过**：支持分支断言 `gpu_frame_ms > 0` 且 `gpu_samples == 帧数 − 在途帧数`；不支持分支断言 `gpu_frame_ms == gpu_total_ms == 0` 且 `gpu_samples == 0` | 用例 `绘制帧GPU耗时随能力分支断言`、`空帧GPU耗时随能力分支断言`（两分支均可构造、均实跑） |
| `R-TEXT-02` / `R-SAMPLE-01`（各向异性未做像素级断言） | 补一条**像素级旁证**：自建「纯黑 / 纯白」棋格（256×256、格边 4 像素，`texture_load` 生成完整 mip 链）× 小四边形制造强缩小；断言 (a) mip 过滤开 / 关两帧画面**必须不同**（采样器状态确实作用于像素输出），(b) 开启侧极端亮度像素数**不多于**关闭侧。本机实测 `0` 对 `154`（关闭侧大量混叠） | 用例 `mip过滤开关产生像素级差异`（附 `RecordProperty` 记录两个计数，便于跨机复核） |

### 5.3 仍保留的说明（`R-TEXT-02` / `R-SAMPLE-01` 未完全沉降为像素级）
各向异性过滤的**具体像素效果依赖硬件与驱动**（各向异性质量、采样图案、驱动实现对同一状态的实现差异），且本层无「显式 LOD 控制 / 各向异性倍率逐绘制可配」的公共入口，故缺少可比的确定性基线；强行断言方向会在换机 / 换驱动时产生假失败。故：各向异性相关断言维持「状态可设、采样器有效、绘制与回读正常」的**结构性**口径，另以 mip 过滤（规范确定性行为）提供像素级旁证。该结论写入答疑清单与 `渲染层外部问题汇总.md`。

### 6.1 过程中修正（供重开发参考）
- 「两级反色恒等于原画面」的容差由 2 调为 **4**：反色每级都要经历一次「附件编码 → 采样解码」取整，两级累积实测最大通道差 3（若只执行一级则差达 200 以上，故容差 4 仍具决定性）。
- mip 差异用例最初用**内置棋盘格**（两种灰度），极端亮度计数恒为 0（指标无意义）；改为**自建纯黑/白棋格**后该指标变为 0 vs 154。

## 七、重开发指引（凭本文件即可复原本轮改动）

1. **管线模块**：`POST_SET_PER_SLOT = 2`；池 `maxSets` = `frame_overlap × (2 + POST_SET_PER_SLOT)`、`COMBINED_IMAGE_SAMPLER` = `frame_overlap × (1 + POST_SET_PER_SLOT)`；`post_sets` 长度 = `frame_overlap × POST_SET_PER_SLOT`，下标 `slot × 2 + index`。
2. **帧模块**：按 §3.3 的奇偶映射实现 `command_record_chain_present`；`render_chain_present` 照抄 `render_to_target_present` 的取图像 / 提交 / 呈现 / 回读骨架，仅把「1 个后处理项」换成「`post_count` 个」。
3. **门面**：`post_chain_set` 逐句柄校验；`frame_render` 按 §3.5 分派；链路径与单级路径**各自独立**（不合并为一条路径——保持既有单级路径的回归覆盖）。
4. **着色器**：`反色.frag` / `亮度阈值.frag` 均为「`texelFetch` ＋ 帧缓冲坐标 1:1 取源」写法，顶点复用 `后处理.vert`；届时须重配 Renderer（`assets/shaders/*.frag` 由 `GLOB CONFIGURE_DEPENDS` 纳编）。
5. **方向 B**：`total_frame_ms` 累加点 = 四条渲染路径写 `last_frame_ms` 之后；`total_gpu_frame_ms` / `gpu_sample_count` 累加点 = `gpu_timestamp_read` 中 `vkGetQueryPoolResults` 返回 `VK_SUCCESS` 之后。
6. **方向 C**：`scene_apply` 校验用「正向比较」写法（`scene.fov > 0.0f && scene.fov < 3.14159265f && ...`，NaN 亦被拒）；`clear_color_set` 用 `!(value >= 0.0f)` 归一负 / 非数；`Camera` 构造以 `Scene_Data{}` 为默认源。
