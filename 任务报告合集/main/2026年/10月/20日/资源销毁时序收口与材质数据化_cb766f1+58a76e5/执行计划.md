## 1. 方向 A：资源销毁时序收口（优先级最高）

### 1.1 目标
全量运行后校验层消息由 **6 条降至 0 条**，既有 634 例全部通过。

### 1.2 根因
平行四边形地推广第 6 轮的「交换链重建延迟销毁」：其余「可能仍被在途帧引用」的销毁仍是**立即销毁**。显式运行时 `mesh_unload` / `texture_unload` / `render_target_destroy` 与「写满全部帧槽 set1」的描述符更新，均在命令缓冲仍在途时发生。

### 1.3 实现方式

**(1) 帧模块扩展延迟条目承载「内存资源」**

- `帧上下文.h` 新增 `Deferred_Memory_Resource`（只持裸 Vulkan / VMA 句柄：`VkBuffer` ＋ `VmaAllocation` ＋ `VkImage` ＋ `VmaAllocation` ＋ `VkImageView`），`Deferred_Entry` 增 `std::vector<Deferred_Memory_Resource> memory_resources`。
- `core/延迟销毁.cpp` 的 `deferred_entry_release` 增：逐条经 `memory` 归还缓冲 / 图像视图 / 图像与内存（与既有旧交换链深度资源归并同一出口）。

**(2) 三个模块各增「分离」方法（摘出资源不销毁，责任移交调用方）**

- `Mesh/网格.h` ＋ `core/网格缓冲.cpp`：`bool mesh_detach(Mesh_Handle, Mesh_Record& record_out)`。
- `Texture/纹理.h` ＋ `core/纹理创建.cpp`：`bool texture_detach(uint64_t, Texture_Record& record_out)`。
- `RenderTarget/渲染目标.h` ＋ `core/目标创建.cpp`：`bool target_detach(uint64_t, Render_Target_Record& record_out)`。

三者的既有 `*_destroy` / `destroy()` 一律保留（关闭期与模块自身析构仍需立即释放；此时 `Frame_Context::destroy` 已先 `vkDeviceWaitIdle`，安全）。

**(3) 门面三处卸载改走帧延迟队列**

- `Renderer::mesh_unload`：`mesh_detach` → 组装 `Deferred_Entry` → `frame.deferred_push(entry, in_flight_count_get() + 1)`。
- `Renderer::texture_unload`：同上（图像 ＋ 内存 ＋ 视图）。
- `Renderer::render_target_destroy`：同上（颜色 / 深度各一条 `Deferred_Memory_Resource`）；保留既有的 `active_target` / `present_target` 回落逻辑。

**(4) 描述符集更新前等全部在途帧完成**

- `帧上下文.h` ＋ `core/帧槽创建.cpp`：新增 `bool frames_wait(void)`（逐槽 `slot_fence_wait`）。
- `Renderer::texture_bind_set` / `Renderer::texture_bind_target`：写满全部帧槽 set1 之前调用 `frame.frames_wait()`。
- `Renderer::texture_sampler_state_set`：`sampler_state_set`（销毁并重建共享采样器）之前调用 `frames_wait()`，避免销毁仍被在途描述符集引用的旧采样器。

### 1.4 预修改文件
- `Application/Renderer/src/render/Frame/帧上下文.h`
- `Application/Renderer/src/render/Frame/core/延迟销毁.cpp`
- `Application/Renderer/src/render/Frame/core/帧槽创建.cpp`
- `Application/Renderer/src/render/Mesh/网格.h`、`core/网格缓冲.cpp`
- `Application/Renderer/src/render/Texture/纹理.h`、`core/纹理创建.cpp`
- `Application/Renderer/src/render/RenderTarget/渲染目标.h`、`core/目标创建.cpp`

### 1.5 风险
延迟量若算错会退化为「销毁仍在用的资源」（第 6 轮交换链已踩过一次）；`延迟 = 在途帧数 + 1`，**校验层全开**实跑验证。

## 2. 方向 B：材质与场景描述数据化

### 2.1 目标
把「管线 ＋ 纹理 ＋ 混合档」从散装调用收敛为**材质**这一数据结构，验收＝「同一网格以不同材质绘制产生可区分像素」。

### 2.2 前置：先处置 `R-FACADE-06`
`texture_bind_target` 不改写 `bound_texture_request`，事后 `texture_sampler_state_set` 会以旧纹理句柄覆盖目标绑定。**改法**：门面以「当前绑定视图」（`VkImageView bound_view`）替代「绑定请求句柄」——
- `texture_bind_set` / `texture_bind_target`：解析出视图后记录 `bound_view`，再写满全部帧槽 set1；
- `texture_sampler_state_set`：重建采样器后，以 `{新采样器, bound_view}` 重写全部帧槽 set1（不再回落按句柄重绑）。

### 2.3 实现方式
- 新增 Vulkan-free 公共头 `Application/Renderer/src/render/Pipeline/材质数据.h`：
  `struct Material_Data { uint64_t pipeline = 0; uint64_t texture = 0; Blend_Mode blend = Blend_Mode::Opaque; }`
  （`Blend_Mode` 取自既有 `管线数据.h`；`texture` 亦允许为渲染目标句柄）。
- 门面新增：`material_load(Material_Handle& out, Material_Data)` / `material_unload(Material_Handle)` / `material_bind_set(Material_Handle)`。
  - `material_load`：若 `pipeline == 0` 则用默认场景管线（并按 `blend` 落一条具名管线句柄），否则沿用给句柄；记录 `{管线句柄, 纹理句柄}`。
  - `material_bind_set`：等价 `pipeline_bind_set(pipeline)` ＋ 「按纹理句柄绑定（纹理模块查询，失败/为零回落默认白纹理）」。
- **不引入每项独立 set1**：沿用现有「帧内 set1 共享」架构（材质绑定在帧之间切换），验收按「同网格、跨两帧、两材质 → 两帧像素可区分」判定。

### 2.4 预修改 / 新增文件
- 新增 `Application/Renderer/src/render/Pipeline/材质数据.h`
- `Application/Renderer/src/render/Renderer/渲染器.h`（公共面：`Material_Handle`、`material_*`）
- `Application/Renderer/src/render/Renderer/core/渲染器.cpp`
- `Application/Renderer/src/render/Renderer/core/渲染器实现.h`（材质记录集合）
- Test 层新增 `Application/Test/src/单元测试/渲染/渲染材质测试.cpp`

### 2.5 验收
新增用例「同一网格以不同材质绘制产生可区分像素」（像素回读）。

## 3. 方向 C：帧性能统计

### 3.1 目标
帧模块累计「主机侧录制 ＋ 提交耗时」（`std::chrono`）与「绘制项数 / 实例数」，门面暴露只读查询。**不引入 GPU 时间戳查询**。

### 3.2 实现方式
- `帧上下文.h`：帧上下文增计数成员（`last_frame_ms`、`total_draw_items`、`total_instances`）与只读访问器；`render` / `render_to_target` / `render_to_target_present` 三路均在录制前后以 `std::chrono::steady_clock` 计时，并按 `item_count` / 各 `instance_count` 累加。
- `渲染器.h`：新增公共 `struct Frame_Stats { uint64_t frames; double frame_ms; uint64_t draw_items; uint64_t instances; }` 与只读 `Frame_Stats frame_stats_get(void) const`。
- 门面把帧模块内部计数与自身 `frame_count` 组装为 `Frame_Stats`。

### 3.3 预修改文件
- `Application/Renderer/src/render/Frame/帧上下文.h`、`core/提交呈现.cpp`（计时与计数落点）
- `Application/Renderer/src/render/Renderer/渲染器.h`、`core/渲染器.cpp`
- Test 层新增 `Application/Test/src/单元测试/渲染/渲染帧统计测试.cpp`

### 3.4 验收
用例断言「绘制计数与登记项一致」且「帧时间 > 0」（不断言具体数值，避免机器相关）。
