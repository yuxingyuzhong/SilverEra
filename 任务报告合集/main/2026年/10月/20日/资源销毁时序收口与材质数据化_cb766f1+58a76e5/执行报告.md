## 1. 方向 A：资源销毁时序收口

### 1.1 根因
第 6 轮已把「交换链重建」改为延迟销毁，但其余**运行时卸载路径仍是立即销毁**：显式 `mesh_unload` / `texture_unload` / `render_target_destroy` 在命令缓冲/描述符集仍在途时销毁其引用的资源；`texture_bind_set` / `texture_bind_target` 在命令缓冲仍在途时更新其引用的描述符集。开工前基线 6 条校验消息逐套件实测为：

| 套件 | 条数 | 消息 |
| --- | --- | --- |
| `Renderer_Visible_Test` | 2 | `vkDestroyBuffer`（网格缓冲）／ `vkDestroyImageView`（棋盘格纹理视图，经描述符集被在途命令缓冲引用） |
| `Renderer_Offscreen_Test` | 1 | `vkUpdateDescriptorSets`（`texture_bind_target` 在第 2 帧前写满各帧槽 set1） |
| `Renderer_Mesh_Test` | 3 | `vkDestroyBuffer` × 3（`mesh_unload`） |

（`Renderer_Texture_Test` 为 0：其卸载发生在 `shutdown`，而 `Frame_Context::destroy` 已先 `vkDeviceWaitIdle`。）

### 1.2 修改文件清单（相对 Renderer 层根 `Application/Renderer`）

| 文件 | 改动 |
| --- | --- |
| `src/render/Frame/帧上下文.h` | 新增 `struct Deferred_Memory_Resource`（裸句柄：`VkBuffer`＋`VmaAllocation`＋`VkImage`＋`VmaAllocation`＋`VkImageView`）；`Deferred_Entry` 增 `std::vector<Deferred_Memory_Resource> memory_resources`；公开 `bool frames_wait(void)`；私有 `void frame_stats_accumulate(...)`；私有成员 `last_frame_ms` / `total_draw_items` / `total_instances` |
| `src/render/Frame/core/延迟销毁.cpp` | `deferred_entry_release` 增：逐条经 `memory->buffer_destroy` / `image_view_destroy` / `image_destroy` 归还内存资源 |
| `src/render/Frame/core/帧槽创建.cpp` | 新增 `Frame_Context::frames_wait`（逐槽 `slot_fence_wait`）；新增三个统计 getter；`destroy` 复位三个统计成员 |
| `src/render/Mesh/网格.h` ＋ `core/网格缓冲.cpp` | 新增 `bool mesh_detach(Mesh_Handle, Mesh_Record&)`（摘出记录、复位原记录、不销毁） |
| `src/render/Texture/纹理.h` ＋ `core/纹理创建.cpp` | 新增 `bool texture_detach(uint64_t, Texture_Record&)` |
| `src/render/RenderTarget/渲染目标.h` ＋ `core/目标创建.cpp` | 新增 `bool target_detach(uint64_t, Render_Target_Record&)` |
| `src/render/Renderer/core/渲染器.cpp` | `mesh_unload` / `texture_unload` / `render_target_destroy` 改为「分离 → 组装 `Deferred_Entry` → `frame.deferred_push(..., in_flight_count_get() + 1)`」；`texture_bind_set` / `texture_bind_target` 写满各帧槽 set1 前调用 `frame.frames_wait()`；`texture_sampler_state_set` 在重建共享采样器前调用 `frame.frames_wait()`；`pipeline_unload` 在注销图形管线前调用 `frame.frames_wait()`；`render_target_destroy` 顺带复位 `present_target` |

模块既有 `*_destroy` / `destroy()` **全部保留**（关闭期与模块自身析构仍立即释放；此时 `Frame_Context::destroy` 已 `vkDeviceWaitIdle`，安全）。

### 1.3 关键不变量
- 延迟量 = **在途帧数 + 1**（与第 6 轮交换链重建同口径），保证在途帧用尽后才释放。
- 卸载后记录被复位（`record = Xxx_Record{}`），故关闭期 `module.destroy()` 不会二次释放。
- 帧模块 `deferred_release_all` 在 `Frame_Context::destroy` 中先于内存模块销毁执行，且覆盖上述新资源。

## 2. 方向 B：材质与场景描述数据化

### 2.1 新增文件（相对 Renderer 层根）
| 文件 | 内容 |
| --- | --- |
| `src/render/Pipeline/材质数据.h` | Vulkan-free 公共头：`using Material_Handle = uint64_t`；`struct Material_Data { uint64_t pipeline; uint64_t texture; Blend_Mode blend; }`。**不携带采样器状态**（采样器为纹理模块共享并烘焙进各帧槽 set1，故仍由 `texture_sampler_state_set` 全局控制） |

### 2.2 公共面改动（`src/render/Renderer/渲染器.h`）
- 增 `#include "…/Pipeline/材质数据.h"`。
- 新增 `bool material_load(Material_Handle&, const Material_Data&)` / `void material_unload(Material_Handle)` / `void material_bind_set(Material_Handle)`。

### 2.3 实现要点（`src/render/Renderer/core/渲染器.cpp` ＋ `渲染器实现.h`）
- `Impl` 增 `struct Material_Record { uint64_t pipeline; uint64_t texture; bool owns_pipeline; bool valid; }` ＋ `std::vector<Material_Record> materials`（句柄 = 下标 + 1，空槽复用；`materials.clear()` 已加入 `shutdown`）。
- `material_load`：`pipeline != 0` 沿用；`pipeline == 0 && blend == Opaque` 用默认场景管线（句柄 0，不持有）；`pipeline == 0 && blend != Opaque` 调 `pipeline_load(handle, "场景.vert.spv", "场景.frag.spv", blend)` 登记具名管线并标记 `owns_pipeline`。
- `material_unload`：`owns_pipeline` 时 `pipeline_unload`（其内部现已等全部在途帧）。
- `material_bind_set`：`pipeline_bind_set(record.pipeline)` ＋ `texture_bind_set(record.texture)`；句柄 0 / 无效回落默认管线 ＋ 默认白纹理。

### 2.4 前置处置 `R-FACADE-06`（本次结案）
- `渲染器实现.h`：删除 `uint64_t bound_texture_request`，改设 `VkImageView bound_view`。
- `texture_bind_set`：解析出视图后记 `bound_view`。
- `texture_bind_target`：记 `bound_view = 目标颜色视图`（**由此不再被后续采样器切换覆盖**）。
- `texture_sampler_state_set`：重建采样器后，以 `{新采样器, bound_view}` 重写全部帧槽 set1（不再按句柄回落重绑）。
- `texture_unload`：若卸载的正是 `bound_view`，先 `texture_bind_set(0)` 回落默认白纹理，避免后续采样器切换写入失效视图。

### 2.5 新增用例（Test 层，相对 Test 层根 `Application/Test`）
`src/单元测试/渲染/渲染材质测试.cpp`（5 例）：
1. 未初始化登记材质失败；2. 登记卸载材质幂等（含槽复用）；3. 混合档材质登记并绘制（走具名管线路径）；4. 无效材质句柄回落默认；5. **核心验收：同一网格以不同材质（红/蓝纹理）绘制两帧 → 两帧像素可区分**（断言：两帧绿通道均低＝确被纹理着色而非默认白；外通道均饱和；首字节不同；整帧数据不同）。

## 3. 方向 C：帧性能统计

### 3.1 帧模块（`帧上下文.h` ＋ `core/提交呈现.cpp` ＋ `core/帧槽创建.cpp`）
- 新增私有成员 `last_frame_ms` / `total_draw_items` / `total_instances` 与三个公开只读 getter。
- 新增私有 `frame_stats_accumulate(items, item_count)`：累加绘制项数与实例数（`instance_count` 之和）。
- `render` / `render_to_target` / `render_to_target_present` 三路：在录制前取 `std::chrono::steady_clock::now()`，提交后（`render` / `present` 为 `submit_present` 返回后；离屏为 `vkQueueSubmit2` 后）计算毫秒耗时写入 `last_frame_ms`，并 `frame_stats_accumulate`；同帧多 pass 路径额外计入后处理绘制项（`total_draw_items += 1; total_instances += post_item.instance_count`）。
- `提交呈现.cpp` 增 `#include <chrono>`。

### 3.2 公共面（`渲染器.h` ＋ `core/渲染器.cpp`）
- 新增 `struct Frame_Stats { uint64_t frames; double frame_ms; uint64_t draw_items; uint64_t instances; }` ＋ 只读 `Frame_Stats frame_stats_get(void) const`。
- `frame_stats_get`：`frames` 取门面 `frame_count`（与既有 `frame_count()` 同口径）；其余取帧模块 getter。未初始化全零。
- **不引入 GPU 时间戳查询**（留作候选方向）。

### 3.3 新增用例

## 4. 构建坑与注意事项（本轮实测）
- 新增 Test 层用例文件后，Test 树因 `CONFIGURE_DEPENDS` 自动重配并纳入（无需手动改清单）；新增 Renderer 头文件会触发头快照导出（本轮 35 个）。
- 方向 B 首次实跑曾引入**新**校验消息 `vkDestroyPipeline`（材质的具名管线在命令缓冲在途时被卸载）——已通过「`pipeline_unload` 前 `frames_wait`」修复；**教训**：凡销毁「可能被在途命令缓冲引用的对象」（缓冲 / 图像 / 视图 / 管线 / 采样器）或更新其描述符集，均须先等全部在途帧。
- 构建命令三要素顺序不可颠倒：先设 `TMP`/`TEMP` 为纯 ASCII 目录 → 进 VS 开发环境 → 最后 `chcp 65001`。

- `R-TEXT-02`、`R-SAMPLE-01`（各向异性未做像素级断言）仍在。
