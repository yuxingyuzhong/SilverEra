## 三、关键实现

### 3.1 实际绘制量的采集点
```cpp
// 命令录制.cpp · items_record（末尾）
vkCmdDrawIndexed(command_buffer, item.index_count, item.instance_count, 0, 0, 0);
++counts.items;
counts.instances += item.instance_count;
```
- 采集点**紧跟绘制命令**，故「实际绘制量」与 GPU 真正收到的绘制一一对应；
- 被 `continue` 跳过的不完整项（管线 / 顶点 / 索引 / 实例缓冲缺失、`index_count == 0`、`instance_count == 0`）不计入。

### 3.2 单帧与累计的分层
| 层级 | 字段 | 清零时机 | 累计方式 |
| --- | --- | --- | --- |
| 单帧录制 | `frame_recorded` | 每次进入 `command_record` / `command_record_target` / `command_record_chain_present` 时 | 链路径各级另加 |
| 累计 | `total_drawn_items` / `total_drawn_instances` | `destroy` | `frame_stats_accumulate` 中加上 `frame_recorded` |

### 3.3 口径对照（写入 `Frame_Stats` 注释）
| 字段 | 含义 | 被跳过项 |
| --- | --- | --- |
| `draw_items` / `instances` | **登记量**（上层登记的渲染项与实例） | **计入** |
| `drawn_items` / `drawn_instances` | **实际绘制量**（真正下达绘制命令） | **不计入** |
| 相等性 | 两量相等 ⇒ 所有登记项都真正下达了绘制 | —— |

### 3.4 GPU 耗时口径定案
维持「按帧槽环形读回」：第 N 帧读回该槽上一轮（第 N − 在途帧数 帧）的耗时。**不改为同帧读回**——同帧读回需在提交后同步等待，代价大于收益；该滞后关系已写入 `Frame_Stats::gpu_total_ms` / `gpu_samples` 注释，并由既有用例 `GPU样本数与帧数关系符合口径` 钉住。

## 七、重开发指引

1. 在 `帧上下文.h` 的 public 区（`render_chain_present` 声明之后）加 `struct Recorded_Counts { uint32_t items = 0; uint64_t instances = 0; };`，把 `items_record` 的声明与定义返回类型一并改掉；
2. `items_record` 末尾在 `vkCmdDrawIndexed` 之后累加 `counts`，函数末尾 `return counts;`；
3. 三条录制路径的调用点统一改为两行：`frame_recorded = Recorded_Counts{};` ＋ `frame_recorded = items_record(...);`；链路径后处理循环内单独取 `stage_counts` 并累加到 `frame_recorded`；
4. `frame_stats_accumulate` 末尾加两行取 `frame_recorded` 的累计；`destroy` 复位三字段；
5. 门面 `Frame_Stats` 加两字段并在 `frame_stats_get` 填充；
6. 用例只依赖公共 API（`frame_stats_get`），不要直接构造不完整 `Frame_Render_Item`（门面不会登记这类项）。
