## 四、实施过程与关键决策

1. **先量后改**：先用 `coord2D` 全仓清点引用面 —— 3 个 token、**179 处 / 15 文件**（引擎层 13 文件 107 行 + 测试层 2 文件 46 行）；`系统层`、`游戏层` 零引用，碰撞模块零引用。改动面因此被限定在空间分区的两个模块内，不需要跨层联动。
2. **替换方式**：脚本化字面替换（PowerShell 内联），逐文件 `git diff --numstat` 校验 insertions == deletions，以此证明是纯字面替换而非重写。
3. **命名空间收敛**：新实现把 `coord2D_*` 收敛为单层 `namespace engine`，四叉树各文件本身就在 `namespace engine` 内，短名 `Point2i` 等可直接解析 —— 除测试文件外无需加限定名，这是替换面没有外溢的原因。
4. **关键决策：不新增兼容别名、不引入隐式转换**。新实现刻意取消了跨精度隐式转换（`Point2d → Point2i`），本次**不**为省事补回隐式构造，而是把依赖旧隐式转换的两处改为显式 `point_to_int`，保持新实现的类型安全与显式语义。
5. **等价性论证（改法依据）**：读 `HEAD` 版 `坐标类型.h` 第 122–125 行，确认旧转换构造函数定义为 `X = static_cast<int>(std::lround(coord.X)); Y = static_cast<int>(std::lround(coord.Y));` —— 与 `point_to_int` 的 `static_cast<int>(std::lround(...))` **逐字一致**，因此两处显式化在取整规则（四舍五入、远离零）上与原行为等价，不存在静默的行为漂移。
6. **验证策略**：第一次增量构建（默认 `-k`）在 2 处 `error C2664` 处停下；修正后第二次构建改用 `-- -k 0` 让编译全量续跑，确认「再无后续连带错误」这一点本身有证据，而不是靠错误数归零反推。

## 六、遇到的问题与处置

1. **首次构建 2 处 `error C2664`（`Point2d` → `const Point2i&` 跨精度实参）**
   - `Quadtree/core/区块信息检索.hpp:93`：`callback(state.root, expand_register)` — 回调形参声明为 `const Point2i&`，实参 `expand_register` 为 `Point2d`。
   - `Quadtree_Manager/core/四叉树合并.hpp:323`：`block_seek(ptr_data, buffer[copy_time]->node, true)` — `node` 为 `Point2d`，`block_seek` 形参为 `const Point2i&`。
   - 处置：各包一层 `point_to_int(...)`，等价性依据见第四节第 5 条。
2. **工具限制**：`ast_grep_replace` 在本部署不支持 Cpp（napi 报 `pattern 无效：Cpp is not supported`），语法级批量改写不可用 → 回退为 PowerShell 字面替换。
3. **编码坑（自伤一次）**：用 `write_file` 落盘的 `.ps1` 被 Windows PowerShell 按 ANSI 读取，脚本内的中文路径变乱码，脚本报告 `TOTAL REPLACED: 0`（无副作用）→ 改为不落盘、直接内联 `-Command` 传中文串完成替换。
4. **中文路径提交**：cmd 直传中文路径给 `git add` 有乱码风险 → 采用 `git add --pathspec-from-file=<UTF-8 路径清单>` + `git commit -F <UTF-8 提交信息文件>`，提交信息随后用 UTF-8 控制台回读校验，确认中文与标点无损。
5. **`git push` 被 `push.default=simple` 拦下**：引擎层本地分支名为 `main`、上游为 `sliverera/engine`，名字不一致导致 `git push` 报 fatal → 按 git 自身提示改用显式 refspec `git push sliverera HEAD:engine`（非强制推送），推送后 `00a7c31..9758826 HEAD -> engine`。
6. **一次工具误判**：用 `search_text` 想把搜索限定在 `out/_tools/` 下的单个 diff 文件上，被工具按依赖目录跳过而退化为全仓搜索（结果已收敛，无副作用）。后续改为 `read_file` 直接读该文件。
