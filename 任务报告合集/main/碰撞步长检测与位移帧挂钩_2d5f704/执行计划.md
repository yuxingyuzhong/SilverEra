## 二、语义定夺（用户已答复）

| 项 | 定夺 |
|---|---|
| 帧计数器 | 由本任务在引擎环境中新增 |
| 门控对象 | 作用于「从事件更新位移向量」与「用位移向量修改碰撞体位置」两处：计数未达帧间隔则对位移向量**不做任何操作** |
| 作用频率 | 必须为逻辑帧率的因数（保证整除）；帧间隔 = `逻辑帧率 ÷ 作用频率` |
| 单次施加量 | **位移向量 ÷ 频率**（一个逻辑帧周期内共生效 F 次，累计恰为一个位移向量） |
| 生效判定 | **全局帧序号差值**：`当前帧序号 − 上次生效帧序号 ≥ 帧间隔` |
| 频率粒度 | **碰撞体级**，数据存放在碰撞空间（即 `Collider` 记录内） |
| 窗口外更新请求 | **暂存待下次生效**（代理器保留最新事件配置，生效窗口才重读） |
| 步长 | 一段（本次施加的）位移向量被拆分的**段数** |

### 未获明确答复、本计划按下列假设执行（如与预期不符请在开工前指出）

1. 频率缺省或非法（缺 `frequency` 字段、F = 0、F 不整除逻辑帧率、逻辑帧率为 0）→ **回退旧行为**：每次检测重读事件并施加全量位移（保证既有用例语义不变）。
2. 碰撞响应通道（`stop` / `keep` / `change`）**不受帧门控**：作废立即生效；`change` 改写后的位移向量仍按频率分帧施加（视为新的一个周期总量）。
3. 新位移事件登记时，该碰撞体的生效计时**重新起算**（等待一个完整帧间隔后才生效），符合「暂存待下次生效」。
4. 逻辑帧计数器默认 0，由外部主循环经 `frame_tick()` 自增；本任务只提供接口，不接入主循环。

## 四、分阶段执行

### 阶段一：引擎环境帧计数器

- 新增 `frame_tick()`（自增）、`frame_count_get()`（读取）、`frame_count_set()`（设定，便于测试与复位），复用既有 `frame_mtx` 互斥锁与 `logic_frames` 的加锁风格。
- 与 `logic_frames` 的差别：`logic_frames` 是**帧率**（一周期多少帧），新计数器是**帧序号**（逻辑帧流逝计数）。

### 阶段二：碰撞空间与碰撞体的频率状态

- `Collider` 新增：
  - `displacement_frequency`（作用频率，0 表示未配置 → 回退旧行为）；
  - `displacement_frame`（上次生效的全局帧序号）；
  - `displacement_step`（本帧实际施加的位移，未生效帧为零向量）。
  - 三个字段纳入现有移动构造 / 移动赋值（该类已手工搬移全部成员并重挂自指针）。
- `Collision_Region::collider_frequency_set(collider_ID, frequency)`：写入频率、把 `displacement_frame` 置为当前全局帧序号（重新起算）、清零 `displacement_step`。
- `collider_displacement_void` / `collider_displacement_replace` 语义不变（响应通道立即生效）。

### 阶段三：检测执行的生效门控与分帧施加

- 每次检测读取 `frame_now`、`frame_rate`；逐碰撞体判定：
  - 回退路径（F = 0 或帧率为 0）：重读事件并令 `displacement_step = 事件位移`（等价旧行为）；
  - 正常路径：`帧间隔 = frame_rate / F`；差值 ≥ 帧间隔 → 生效（更新 `displacement_frame`、重读事件、`displacement_step = 事件位移 / F`）；否则 `displacement_step = 零向量`（不重读、不动作）。
- 扫掠段与离散段一律改用 `displacement_step`（不再直接使用 `displacement_vector` 作为单帧推进量）。

### 阶段四：步长检测（分段推进）

- 段数取 `detection_mode.step_length`，为 0 时取 1 段（旧行为）。
- 扫掠：把本帧施加位移按段拆开，逐段执行凸包扫掠并逐段收集命中，汇总碰撞对。
- 离散：外层按段循环，内层逐碰撞体平移该段位移，每段平移后执行一次离散检测并收集流形与边界接触，最后汇总（既有 `pair_unique` 去重继续生效）。
- 跨越状态在全部段执行完毕、以最终位置与累计边界接触统一判定（保持既有判定口径）。

### 阶段五：事件侧（代理器）

- `displacement_register` 新增解析可选字段 `frequency`，校验「F ≥ 1 且逻辑帧率 > 0 且逻辑帧率 % F == 0」；非法则告警并按未配置处理（回退）。
- 登记后除保存事件（暂存最新）外，向持有该编号的空间下发频率；保留既有 `collider_displacement_replace` 调用，其作用改为「解除作废 + 写入目标位移」，实际位移量仍只来自生效帧的 `displacement_step`。

## 五、验收与风险

本次按用户约束**不做编译验证**，故以「改动清单 + 源码级核对」作为交付口径；执行报告将如实记录未编译验证这一点。

**必须提醒的风险（因不编译，无法用测试兜底）**：

1. 生效门控依赖外部调用 `frame_tick()`；若主循环未接入，则**配置了作用频率的碰撞体永远不会施加位移**（帧序号恒为初值，差值永远不达帧间隔）。
2. 既有碰撞用例（位移空间 / 响应空间 / 保持空间 / 变化空间）均未配置频率，走回退路径，预期语义不变；但若其中有用例配置过 `detection_mode.step_length`，分段推进会使离散检测从「1 次」变为「N 次」，其中间段位置可能产生额外的边界接触，进而影响跨越状态判定的中间结果——此点无法在本次验证，需在集成时留意。
3. 逻辑帧率运行中变更后 F 不再重新校验，生效判定按整数除法向下取整。
