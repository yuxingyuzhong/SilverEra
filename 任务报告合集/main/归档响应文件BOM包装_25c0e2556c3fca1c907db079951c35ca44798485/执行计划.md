# 执行计划：引擎层归档响应文件 BOM 包装

> **任务性质**：修复「引擎层 CMake 构建在归档阶段报 `LNK1181`」的缺陷
> **书写时点**：方案已由用户在对话中确认并授权「全权处理此项」（2026-09-24），本文件为事后补记落盘，供后续「重开发」有据可依
> **路径约定**：本文件内路径均为相对工作区（`白银纪元/`）的相对路径

---

## 一、任务目标

让引擎层在「MSVC + Ninja」组合下正常归档出 `EngineCore` 静态库，并且：

1. **保留源码的中文文件名**（符合项目「文件名默认中文」的既有约定）；
2. **不把 `external/bullet3` 移出 `EngineCore` 目标**（不靠削减归档输入绕开问题）。

---

## 二、根因（承接前序排查任务结论）

| 环节 | 事实 |
| --- | --- |
| 生成器 | Ninja 在对象数量较大时，把归档输入写入响应文件 `CMakeFiles/EngineCore.rsp` |
| 编码 | 该响应文件是 UTF-8 **无 BOM** |
| 归档器 | `lib.exe` 在文件无 BOM 时按系统 ANSI（本机 936 / GBK）解读其内容 |
| 结果 | 含中文的成员路径被解成乱码（`事件终端` → `浜嬩欢缁堢`）→ `LNK1181: 无法打开输入文件` |

---

## 三、方案选定（附被否决方案）

采用「**包装器补 BOM**」：把归档命令替换为「先给响应文件补 UTF-8 BOM，再调用真实 `lib.exe`」的包装脚本。

被否决方案与原因：

1. **把中文源文件名改为英文** —— 违反项目文件命名约定，且波及 122 个对象对应的全部源码。
2. **把 bullet3 移出 `EngineCore` / 拆为独立目标** —— 只是把对象数压到响应文件阈值以下，根因仍在，规模增长后必然复现；并引入额外的目标与依赖编排。
3. **生成器改用 Visual Studio** —— 归档由 MSBuild 的 `Lib` 任务完成，问题确实不存在，但改变了既有构建流程与构建目录布局，代价超出缺陷本身。
4. **改 `CMAKE_AR` / `CMAKE_CXX_ARCHIVE_CREATE` / `CMAKE_CXX_COMPILER_AR` / `CMAKE_NINJA_FORCE_RESPONSE_FILE`** —— 实测从项目侧或 `-D` 传入**均压不动**归档规则（`CMAKE_AR` 会被平台模块用普通变量覆盖回默认值）。

---

## 四、预修改文件清单

| 文件（相对工作区） | 动作 | 内容 |
| --- | --- | --- |
| `引擎层/cmake/ar_rsp_bom.ps1` | **新增** | 归档包装脚本：补 BOM 后转交真实归档器，退出码透传 |
| `引擎层/CMakeLists.txt` | **修改** | 在 `project()` **之后**改写 `CMAKE_CXX_CREATE_STATIC_LIBRARY`（条件：MSVC + Ninja） |

---

## 五、分段执行

1. 编写包装脚本，先以 `-File` 方式单独跑通（脚本自身以 UTF-8 **带 BOM** 保存，避免 PowerShell 5.1 误读中文）。
2. 在 `引擎层/CMakeLists.txt` 的 `project()` 之后接入；重新配置，确认 `CMakeFiles/rules.ninja` 中归档规则已改道包装器。
3. 实跑归档，确认 `引擎层/out/build/x64-Debug/lib/EngineCore.lib` 产出。
4. 对照组：用脚本内置诊断开关 `BYJY_AR_WRAPPER_DISABLE_BOM=1` 关掉补 BOM，确认 `LNK1181` 复现。
5. 恢复干净构建，核对产物成员完整。
6. 清理本次产生的临时文件，写执行报告，更新「报告提交历史」。

---

## 六、验证方式

* **配置侧**：读 `引擎层/out/build/x64-Debug/CMakeFiles/rules.ninja`，归档规则首词应为包装器调用，而非裸 `lib.exe`。
* **构建侧**：`ninja` 退出码为 0；`lib/EngineCore.lib` 存在，且 `lib.exe -list` 能列出全部成员（含中文对象名）。
* **因果侧**：对照组必须复现 `LNK1181`（exit 1181）；否则「补 BOM 是起作用的那一环」不成立，需回头重查。

---

## 七、风险与回退

| 风险 | 应对 |
| --- | --- |
| PowerShell 不可用或执行策略受限 | 接线处已探测：包装脚本或 PowerShell 缺失时 `message(WARNING)` 降级，不改写归档命令 |
| 影响 Visual Studio 生成器 | 接线条件限定 `CMAKE_GENERATOR MATCHES "Ninja"`，VS 生成器分支不进入 |
| 包装脚本成为新的失败点 | 脚本只做「补 BOM + 转交」一件事，并原样透传归档器退出码；诊断开关可旁路补 BOM |
| 需要整体回退 | 删除接线块与脚本即可回到原始状态，不触碰任何源码与产物语义 |
| 中文路径下脚本定位失败 | 接线处使用 `${CMAKE_CURRENT_SOURCE_DIR}`（该位置 `PROJECT_ROOT_DIR` 尚未赋值） |
