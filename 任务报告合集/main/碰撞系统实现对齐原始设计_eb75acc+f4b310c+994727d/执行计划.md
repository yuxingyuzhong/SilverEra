## 一、任务目标

按用户提供的碰撞系统**原始设计文档**，把当前实现向设计对齐。改造集中在引擎层碰撞系统三模块（碰撞体 / 碰撞空间 / 碰撞代理器）与事件交互层，不涉及系统层、游戏层。

## 二、偏离核查结论（已完成）

以源码为准（`089b070` 版次）对 15 个核查点逐条比对，结果：**完全符合 4 / 部分符合 6 / 不符合 5 / 实现方式不同 1**（`项目导航` 记载与源码一致，无滞后）。

整体判断：三层骨架、事件化指令通道、豁免标记、BVH 后端、两种检测入口均已落地；缺口集中在**位移语义、碰撞响应、跨越通知、几何体集合**四处。

用户裁决后，本次实际纳入改造的是其中 5 项（见第三节）。

### 阶段三　三种碰撞响应（事件应答）（对应 C）

**目标**：碰撞发生后向外界发碰撞事件，由外界三选一响应；按用户指定流程处理**响应缺失**的情况。

**用户指定的响应时序（据此实现）**

1. 检测到碰撞 → 发布碰撞事件；
2. **立即**查阅事件终端是否收到回复事件；
3. 收到 → 按回复处理（停止运动位移作废 / 继续运动位移保持 / 继续运动位移变化）；
4. 未收到 → 该碰撞体**暂时搁置**，先继续处理其余正常碰撞体；
5. 其余碰撞体处理完毕后，**再检查一次**事件终端是否收到响应事件；
6. 仍未收到 → **再次发送碰撞事件**并检查事件终端是否存在响应；
7. 仍无响应 → **日志报错并搁置处理**。

**预修改文件**

| 文件 | 改动要点 |
| --- | --- |
| `引擎层/src/core/spatial/collision/Collision_Proxy/碰撞代理器.h` | 新增碰撞事件/响应事件订阅声明与响应查询接口 |
| `引擎层/src/core/spatial/collision/Collision_Proxy/core/事件交互.cpp` | 新增响应事件解析与登记 |
| `引擎层/src/core/spatial/collision/Collision_Region/core/检测执行.cpp` | 接入"发出—回查—搁置—重发—报错"时序；位移应用改由响应结果决定 |
| `引擎层/src/core/spatial/collision/Collision_Region/碰撞空间.h` | 承载"待响应碰撞体"暂存与作废标记 |
| `引擎层/src/core/spatial/collision/Collision_Proxy/core/空间管理.cpp` | 碰撞结果发布改为应答式流程 |

**前置核实（阶段三开始前先做）**：确认 `Event_Terminal` / `Event_Broker` 的**应答查询**能力与既有 `query` 语义是否足以支撑"查是否收到回复"，不足以则需在事件系统侧做最小适配。**该点若需改动事件系统，会先向你反馈。**

**验证**：引擎层构建；测试层新增三态响应用例 + 无响应时的搁置与重发用例。

### 阶段四　三类跨越通知事件（对应 B）

**目标**：碰撞体相对某碰撞空间发生「首次部分跨越 / 完全回归 / 完全超出跨越」状态转移时，向外界发通知事件。

**判定（拟定，可在检查中调整）**：以碰撞体几何体集合与空间边界（现有静态网格边界）的关系划分三态——完全在内 / 部分在内 / 完全在外；状态发生转移时发事件，仅**转移**发一次，稳态不发。

**预修改文件**

| 文件 | 改动要点 |
| --- | --- |
| `引擎层/src/core/spatial/collision/Collision_Region/碰撞空间.h` | 新增 per-collider 跨越状态记录 |
| `引擎层/src/core/spatial/collision/Collision_Region/core/检测执行.cpp` | 位置更新后计算当前态、比对旧态、转移则发通知 |
| `引擎层/src/core/spatial/collision/Collision_Proxy/core/事件交互.cpp` | 通知事件发布接线 |
| `引擎层/src/core/spatial/collision/Collision_Region/core/碰撞体管理.cpp` | 转移/卸载时跨越状态的清理口径 |

**待你确认的边界语义**：碰撞体被 `collider_transfer` 转移到另一空间时，原空间的跨越状态是否清零并视作在新空间"首次跨越"。**拟定：清零，按新空间重新判定。**

**验证**：引擎层构建；测试层新增三态转移用例（进入、越出、回归、稳态不重复发事件）。
