## 阶段二　碰撞体几何体集合（已完成）

### 目标

碰撞体由「单形状」改为「几何体集合」：一个碰撞体可容纳多个几何体，各几何体带**相对变换**，且共用同一个碰撞对象与同一个位移向量——故整体具有相同的移动方向与速度。对应设计文档「碰撞体是一组具有空间位置关系的几何体的集合，属于同一碰撞体的所有几何体具有相同的移动方向和速度」。

### 数据模型

| 项 | 说明 |
| --- | --- |
| 新增 `Geometry_Part` | 一个几何体部件：`mesh`（网格数据源）、`shape`（几何形状）、`local_transform`（相对碰撞体原点的变换） |
| `Collider::parts` | `std::vector<Geometry_Part>`，替换原先的 `mesh` / `shape` 两个 `unique_ptr`；成员声明**先于**复合形状，保证复合形状先析构、部件后析构 |
| `Collider::compound` | `std::unique_ptr<Collision_Shape>`，**仅当部件数大于一时**持有（`btCompoundShape`），各部件形状作为其子形状 |
| `Collider::mounted_shape()` | 新增；返回实际挂载到碰撞对象的形状：多部件返回复合形状，单部件返回该部件形状本体，无部件返回空指针 |

**单部件不套复合形状**是刻意设计：既保住「凸包判断 + 扫掠检测」，也使旧配置的挂载对象与改动前逐字节等价。

### 配置协议（向后兼容）

`Collision/ColliderSet` 事件的 `config["geometry"]` 现有两种形态：

- **对象形式（旧，不变）**：`config["geometry"]` 即单个几何体，`position` / `rotation` 写在几何对象内，作为该碰撞体的世界变换。
- **数组形式（新）**：`config["geometry"]` 为几何体数组，每个元素描述一个几何体，元素内的 `position` / `rotation` 为**相对本体的局部变换**；碰撞体基准位置与基准朝向改由配置**顶层**的 `position` / `rotation`（可选）给出，缺省时沿用当前变换。

`Collision_Region::collider_set` 侧以「是否含 `geometries` 数组字段」判定形态；数组形式由 `Collision_Proxy::collider_config_apply` 自动包装（写入 `geometries` 并合并顶层基准变换）。

## 阶段三　三种碰撞响应（事件应答）（已完成）

### 目标

碰撞发生后向外界发布碰撞事件，由外界三选一响应（停止运动位移作废 / 继续运动位移保持 / 继续运动位移变化）；并按用户指定时序处理**响应缺失**：发出 → 立即回查 → 未收到则搁置 → 其余碰撞体处理完毕后再查 → 仍未收到则重发 → 再查 → 仍无则日志报错并搁置。对应设计文档「碰撞体 3：三种碰撞响应」。

### 前置核实（事件系统应答能力）与用户裁决

| 核查点 | 结论 |
| --- | --- |
| `Event_Terminal::query` | 返回的是**原生事件集合** `event_set`，而该集合仅在**未注册** `event_receiver` 时才被填充 |
| `Collision_Proxy::attach` | 已注册 `event_receiver`（指向 `event_process`），故回送给代理器的回复事件落入 `event_process`，`event_set` 恒空 —— **`query()` 看不到回复** |
| `Event_Broker::process` | 仅对 `Subscriber/Check\|Call` 产生回复，**无通用应答通道** |
| `Event_Terminal::interact` | 依赖 `event_interactor`，全仓**无人注册**，不可用 |

结论：既有能力不足以"直接查阅事件终端"判定回复，但**无需改动事件系统** —— 中转站分发是同步的，`event_terminal.send(碰撞事件)` 内部即完成对外派发，外部即时回发的回复会在 `send()` 返回前送达代理器的事件入口。

**用户裁决**：复用 `event_receiver_register` 这一"终端持有者可改接收事件去向"的接口，在**碰撞代理器本地**设回复信箱，检测流程据此判定；事件系统零改动。

### 事件协议

| 方向 | tag | config |
| --- | --- | --- |
| 代理器 → 外界（发布） | `Collision/ColliderCollision` | `{ "region": <空间名>, "collider_ID": <编号>, "collisions": [ { "collider_A": <编号>, "collider_B": <编号> }, ... ] }` |
| 外界 → 代理器（回复） | `Collision/ColliderCollisionResponse` | `{ "collider_ID": <编号>, "response": "stop" \| "keep" \| "change", "displacement": [x,y,z]（仅 change 必需） }` |

订阅清单由 **12 条增至 13 条**（新增 `ColliderCollisionResponse`）；碰撞事件为**每个参与碰撞的碰撞体各发一条**（载荷含该碰撞体参与的全部碰撞对）。

### 响应时序（按用户裁决实现）

1. **第一轮**：逐个碰撞体发布 `ColliderCollision` → **立即回查**回复信箱 → 命中则施加响应，未命中则计入搁置集合；
2. **第二轮**：其余碰撞体处理完毕后，逐个回查搁置集合 → 命中则施加响应；
3. 仍未命中则**重发** `ColliderCollision` → 再次回查 → 命中则施加响应；
4. 仍无响应则 `Log::error("碰撞体(N)未收到碰撞响应，事件搁置处理")` 并搁置（不改动其位移）。

### 响应语义（三种）

| 回复 | 施加方式 |
| --- | --- |
| `stop`（停止运动，位移向量作废） | 对持有该编号的空间置位 `Collider::displacement_invalid`；检测的扫掠与离散两处**均跳过**已作废的碰撞体，故其自下一帧起不再推进 |
| `keep`（继续运动，位移向量保持） | 不施加任何改动，位移事件继续生效（沿用阶段一的持续位移语义） |
| `change`（继续运动，位移向量变化） | 改写 `Collider::displacement_vector` 并解除作废；**同时改写代理器已保存的位移事件** `config["displacement"]`，使后续重读取得新向量 |

**解除作废**：新 `ColliderDisplacement` 事件到达时，`displacement_register` 会向持有该编号的空间施加 `collider_displacement_replace`，从而解除作废、恢复运动。

## 阶段四　三类跨越通知事件（已完成）

### 目标

碰撞体相对某碰撞空间发生「首次部分跨越 / 完全回归 / 完全超出跨越」状态转移时，碰撞代理器向外界发布**通知事件**，供外界做碰撞体迁移到其余空间等操作。对应设计文档「碰撞空间 7」。

### 用户裁决（本阶段开工前四项）

| 项 | 裁决 |
| --- | --- |
| 三态判定口径 | **接触 + 奇偶混合**：以「是否与边界网格接触」判部分跨越；无接触时以**射线奇偶**判完全在内 / 完全在外 |
| 状态转移语义 | **任意三态转移均发**，含「完全在内 ↔ 完全在外」的直接跳变（按目标态命名）；仅转移发一次，稳态不重复发 |
| 转移 / 卸载后的状态 | **清零并重新判定**：在新空间按「首次」重新建立基准，不误报跨越 |
| 通知事件形态 | tag = `Collision/RegionCrossNotice`，config = `{ region, collider_ID, state }` |

### 三态状态机

状态定义 `enum class cross_state { inside, crossing, outside }`（完全在内 / 部分在内 / 完全在外）。

每次 `detect()` 在**位置更新完毕**（离散平移 + `performDiscreteCollisionDetection` 之后）逐碰撞体判定当前态：

1. 该碰撞体与空间边界**存在接触**（离散流形两侧之一为 `region_boundary`）→ `crossing`；
2. 无接触 → 取碰撞体**世界包围盒中心**为探针点，对空间边界做**射线奇偶**判定（交点数为奇数即在内）→ `inside` / `outside`。

与上一帧记录比对后转移：

| 转移后状态 | 通知 `state` | 含义 |
| --- | --- | --- |
| `crossing` | `"cross"` | 首次部分跨越（含由外直入） |
| `inside` | `"return"` | 完全回归 |
| `outside` | `"exit"` | 完全超出跨越 |

**首次判定仅建立基准、不发通知**（新挂载、转移入本空间、编号回收后再用均如此），故不会把「初始就位于空间外」误报为一次跨越。

### 判定实现细节

- **射线奇偶**：用 `btCollisionWorld::AllHitsRayResultCallback` 沿固定方向（`(1, 0.37, 0.19)` 归一化，三轴均非零以避免与面片共面漏检）自探针点射至「包围盒对角线两倍」处，统计命中对象为 `region_boundary.object` 的交点数。已核对子弹库源码：`AllHitsRayResultCallback::addSingleResult` 返回不变的 `m_closestHitFraction`（初值 1.0），使 `btTriangleRaycastCallback::processTriangle` 不对后续三角面片做分数剪枝，**全交点均被收集**，奇偶判定成立。
- **接触判定**：直接复用 `detect()` 已执行的离散检测流形，不额外发起查询。
- **不记录状态的情形**：空间边界未构建时不判定也不记录（待边界构建后重新建立基准）；空间未激活时 `detect()` 提前返回，同样不判定。

### 事件协议

| 方向 | tag | config |
| --- | --- | --- |
| 代理器 → 外界（发布） | `Collision/RegionCrossNotice` | `{ "region": <空间名>, "collider_ID": <编号>, "state": "cross" \| "return" \| "exit" }` |

发布时机：`region_detect` 内，**碰撞响应流程之后、`DetectResult` 之前**（故 `DetectResult` 恒为该次检测的最后一条事件）；每个发生转移的碰撞体各发一条。

**与计划书的偏差（1 处）**：计划书拟「订阅清单 13 → 14 条」，实施时未增加订阅——本事件为**代理器自身的出站事件**，若订阅则会**自收自处理**。订阅清单维持 **13 条**，既有订阅清单断言用例无需改动。

### 连带修复：空间边界不再作为碰撞对

`region_boundary` 是 `Collider` 类型且已挂入碰撞世界，改动前若碰撞体与边界接触，离散流形会反查出编号 **0** 的边界碰撞体，从而把 `(0, <编号>)` 当作正常碰撞对写入 `DetectResult`，并进一步触发 `collision_protocol` 对编号 0 发布碰撞事件、等待必定不会到来的响应（产生误导性报错）。此前无用例同时构建边界与触发接触，故该缺陷一直潜伏；本阶段引入接触判定后必然触发，故一并修复：

- 扫掠命中与离散流形两处，反查对象为 `&region_boundary` 时**跳过碰撞对**；
- 离散流形处**同时登记该碰撞体与边界的接触**，供跨越状态判定使用。
